## Inventario de instrucciones

| Grupo | Instrucción | Invocable por |
|-------|-------------|-------------|
| Configuración global | `CreateConfig` / `UpdateConfig` | Administrador del programa; la autoridad delegada de crear-configuración también puede llamar a `CreateConfig` |
| Ciclo de vida del lanzamiento | `Initialize` / `InitializeV2` | Cualquiera (creador) — base mint SPL Token; V2 registra `amm_creator_fee_on` para la eventual graduación CPMM. Solo V2 acepta un quote mint Token-2022. |
| Ciclo de vida del lanzamiento | `InitializeWithToken2022` | Cualquiera (creador) — base mint Token-2022, `TransferFeeConfig` opcional; acepta cualquier programa de token de quote |
| Comercio | `BuyExactIn` / `BuyExactOut` | Cualquiera — compra de entrada exacta / salida exacta en la curva de vinculación |
| Comercio | `SellExactIn` / `SellExactOut` | Cualquiera — venta de entrada exacta / salida exacta en la curva de vinculación |
| Graduación | `MigrateToAmm` | Cartera de migración — graduación heredada de AMM v4 para pools inicializados antes de que se aplicara la creación exclusiva de CPMM. |
| Graduación | `MigrateToCpswap` | Cartera de migración — graduación a CPMM. Todos los lanzamientos recién inicializados usan esta ruta. Envuelve `InitializeWithPermission` en CPMM. |
| Tarifas | `CollectFee` | Administrador — recopilar tarifas de protocolo de un lanzamiento |
| Tarifas | `CollectMigrateFee` | Administrador — recopilar tarifas de migración acumuladas |
| Tarifas | `ClaimCreatorFee` | Creador — reclamar tarifas de creador acumuladas durante la fase de curva |
| Vesting | `CreateVestingAccount` | Creador — asignar tokens bloqueados a un beneficiario, desbloqueados después de la graduación |
| Vesting | `CreatePlatformVestingAccount` | Administrador de plataforma — asignar tokens bloqueados a beneficiarios del lado de la plataforma |
| Vesting | `ClaimVestedToken` | Beneficiario — reclamar tokens desbloqueados después del acantilado |
| Configuración de plataforma | `CreatePlatformConfig` / `UpdatePlatformConfig` | Administrador de plataforma |
| Configuración de plataforma | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Administrador de plataforma — gestionar la lista por plataforma de formas de curva permitidas |
| Tarifas de plataforma | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Administrador de plataforma |
| Acceso a plataforma | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Administrador de plataforma — mantener la lista de permitidos de `GlobalConfig` utilizada cuando esa plataforma habilita la restricción |

La división "ExactIn/ExactOut" refleja `SwapBaseInput` / `SwapBaseOutput` de CPMM — en cadena son discriminadores de instrucción separados con redondeo ligeramente diferente.

**Selección de ruta de graduación.** Cada nueva llamada a `Initialize`, `InitializeV2` e `InitializeWithToken2022` debe establecer `migrate_type = 1` (`CPSWAP`). Cualquier intento de inicializar un nuevo pool vinculado a AMM v4 devuelve `MigrateTypeNotMatch`. `amm_creator_fee_on` solo selecciona si la tarifa de creador CPMM resultante se aplica al token de quote o a ambos tokens; no selecciona el programa de destino.

`MigrateToAmm` sigue siendo invocable para un `PoolState` existente que fue inicializado con `migrate_type = 0` antes de esta restricción. La versión no reescribe el estado del pool existente ni elimina la instrucción heredada.

**Programa de token del lado de quote.** El quote mint puede ser propiedad del programa SPL Token o Token-2022. Cada instrucción que lo toca — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, las cuatro instrucciones de comercio, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee` y `ClaimPlatformFeeFromVault` — toma el programa propietario en su ranura de cuenta de programa de quote. Las posiciones de cuenta no cambiaron; solo el valor aceptado cambió. Pasa el programa que realmente posee `GlobalConfig.quote_mint`, que puedes leer de `PoolState.token_program_flag` bit1 para un lanzamiento existente (ver [`accounts`](/es/products/launchlab/accounts#poolstate)) o de la propiedad de la cuenta mint de otra manera.

El `Initialize` deprecado es la excepción: su cuenta de programa de quote sigue siendo tipificada a SPL Token, por lo que una configuración cuyo quote mint es Token-2022 debe lanzarse a través de `InitializeV2` o `InitializeWithToken2022`.

`MigrateToCpswap` es la otra excepción, en la dirección opuesta — toma **ambos** programas incondicionalmente en lugar de uno por mint. Ver [las cuentas de migración a continuación](#cpmm-migration-token-programs).

## `Initialize`

Crear un nuevo lanzamiento.

**Argumentos**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // o initial_virtual_quote_reserve para curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // nombre/símbolo/uri en línea; programa CPI a Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Cuentas** (abreviado)

| # | Nombre | W | S | Notas |
|---|--------|---|---|-------|
| 1 | `creator` | W | S | Paga renta + creación de base mint. |
| 2 | `launch_config` |   |   | Vinculación de configuración de protocolo. |
| 3 | `launch_state` | W |   | Nueva cuenta. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Keypair fresco (o PDA) — esta instrucción lo inicializa. |
| 6 | `base_vault` | W |   | ATA de `launch_authority` en `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA de `launch_authority` en `quote_mint`. |
| 9 | `metadata` | W |   | PDA de metadatos de Metaplex. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token para el base mint. `InitializeV2` e `InitializeWithToken2022` toman una cuenta de programa de quote separada que puede ser cualquiera de los dos programas. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Precondiciones**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Los parámetros de tarifa pasan las comprobaciones `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK aplica `≥ now`; programa tolera un ligero antedatado).
- `curve_type` es reconocido.

**Postcondiciones**

- `base_mint` tiene `supply = base_supply_max`, todo en `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` inicializado con `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` calculado a partir de parámetros de curva + `base_supply_graduation` + `buy_numerator` (aproximadamente).
- Para `InitializeWithToken2022` con un `TransferFeeConfig` adjunto: `transfer_fee_config_authority = launch_authority`, y `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` cuando ese campo está establecido, de lo contrario `launch_authority`. El lado de retiro se escribe en la creación de mint precisamente para que la plataforma pueda barrer tarifas retenidas antes de la graduación. Ver [`platform-config`](/es/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**Errores comunes** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (variante canónica: `BuyExactIn`)

El usuario proporciona un `quote_in` fijo; la curva calcula `base_out`.

**Argumentos**

```
quote_in:          u64
minimum_base_out:  u64
```

**Cuentas**

| # | Nombre | W | S |
|---|--------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Precondiciones**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Efecto**

1. Dividir `quote_in` en `quote_in_after_fee` y las partes de tarifa.
2. Resolver Newton la curva para `base_out` dado el quote post-tarifa.
3. `require(base_out ≥ minimum_base_out)` de lo contrario revertir `ExceededSlippage`.
4. Mover `quote_in` usuario → bóveda. Mover `base_out` bóveda → usuario.
5. Actualizar `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Actualizar contadores de tarifa (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Si `quote_reserve_real ≥ quote_reserve_target` después de la actualización, el SDK típicamente encadena una ix `Graduate` en la misma transacción. El programa no se gradúa automáticamente dentro de `Buy` — se requiere un `Graduate` posterior.

## `BuyExactOut`

El usuario especifica el `base_out` exacto; el programa calcula `quote_in`.

**Argumentos**

```
base_out:      u64
maximum_quote_in: u64
```

Las mismas cuentas que `BuyExactIn`. Usa la integral cuadrática de forma cerrada (o CPMM inverso, para curve_type 1) en lugar de iteración Newton.

## `Sell` / `SellExactIn` / `SellExactOut`

Espejo de `Buy`. El usuario devuelve `base_in` a la curva y recibe `quote_out`. La tarifa se deduce de `quote_out`, por lo que el usuario recibe menos que los ingresos integrados brutos.

**Precondiciones** —

- `user_base_ata.balance ≥ base_in`.
- La venta no puede empujar `base_sold` por debajo de 0 (redundante con lo anterior dado que la contabilidad es consistente).
- El lanzamiento es `Active`.

**Efecto** — simétrico a `Buy`. `base_sold` disminuye, `quote_reserve_real` disminuye. Las tarifas aún se acumulan.

### Tarifas de transferencia del lado de quote

Cuando el quote mint lleva un `TransferFeeConfig`, la cantidad que la bóveda mueve y la cantidad que el pagador es debitado o acreditado difieren, y el límite de slippage se verifica contra el lado del pagador. En un quote mint sin la extensión cada caso a continuación es idéntico a un mint heredado simple.

| Instrucción | Argumento | Verificado contra |
|---|---|---|
| `BuyExactIn` | `amount_in` | La curva tiene precio en `amount_in − transfer_fee(amount_in)` — lo que llega a la bóveda. Un llenado completo debita exactamente `amount_in`; un llenado parcial debita la cantidad de bóveda consumida más su tarifa inversa. |
| `BuyExactOut` | `maximum_amount_in` | La cantidad de bóveda **más** la tarifa de transferencia inversa — el débito real. |
| `SellExactIn` | `minimum_amount_out` | Lo que el vendedor mantiene después de que el mint retiene su tarifa, no la cantidad bruta que sale de la bóveda. |
| `SellExactOut` | `amount_out` | Entregado exactamente. La curva apunta a `amount_out` más la tarifa de transferencia inversa. |

Dos consecuencias para cotizar:

- Un límite calculado como si el mint fuera sin tarifa es rechazado. Pasar el costo sin tarifa como `maximum_amount_in`, o los ingresos sin tarifa como `minimum_amount_out`, revierte con `ExceededSlippage`.
- `real_quote` avanza solo por lo que llegó a la bóveda. Un `BuyExactIn` de `amount_in` en un quote mint del 5% mueve `real_quote` por `amount_in × 0.95`.

Un quote mint con tarifa del 100% (`10000` puntos base) no puede ser invertido y revierte con `CalculateOverflow` en las rutas exactas de salida.

Ambos mints del lado de comercio también están restringidos al programa pasado en su ranura coincidente, por lo que un `base_token_program` no coincidente ahora falla en lugar de ser ignorado. Ver [`algorithms/token-2022-transfer-fees`](/es/algorithms/token-2022-transfer-fees) para las matemáticas de tarifa subyacentes.

## `MigrateToAmm` / `MigrateToCpswap`

Graduar un lanzamiento en un pool comercializable una vez que la curva ha alcanzado `total_quote_fund_raising`. Los nuevos lanzamientos son solo CPMM. `MigrateToAmm` se retiene para pools existentes cuyo `migrate_type` almacenado es `0`.

**Quién firma**

- `MigrateToAmm` — la `migrate_to_amm_wallet` registrada en el `GlobalConfig` vinculante.
- `MigrateToCpswap` — la `migrate_to_cpswap_wallet` registrada en el `GlobalConfig` vinculante.

Estas carteras típicamente son mantenidas por el crank de graduación operado por Raydium; en la práctica la graduación ocurre segundos después de que se cruza el umbral, independientemente de quién activó la compra final.

**Argumentos**

`MigrateToAmm` toma tres (principalmente parámetros del mercado OpenBook que el programa reenvía a AMM v4):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` no toma ninguno.

**Efecto (común a ambos)**

1. Verificar `pool_state.status == Migrate` (es decir, `quote_reserve_target` ha sido alcanzado). De lo contrario revertir con `PoolMigrated` (el estado ya era `Migrated`) o `PoolFunding` (aún en financiación).
2. Verificar que `pool_state.migrate_type` coincida con la instrucción (`0` para AMM, `1` para CPMM). De lo contrario revertir con `MigrateTypeNotMatch`.
3. Calcular las reservas post-graduación:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI en el programa de destino (`AMM v4 Initialize2` o `CPMM InitializeWithPermission`) con esas reservas para crear el pool post-graduación.
5. Para migraciones CPMM ejecutadas después de la actualización del 2026-08-17, combinar `platform_scale + creator_scale` en una participación de LP bloqueada de propiedad de plataforma y acuñar como máximo una NFT de Fee Key a `platform_nft_wallet`. Quemar el resto de `burn_scale`. Antes de la actualización, `creator_scale` estaba bloqueado por separado y su Fee Key iba al creador del token. Las migraciones históricas completadas no se modifican. Para la graduación heredada de AMM v4, la disposición de LP sigue el flujo existente de esa instrucción.
6. Revocar `base_mint.mint_authority` (establecer a `None`).
7. Voltear `pool_state.status = Migrated`, establecer `vesting_schedule.start_time = block_time + cliff_period`.

**Transferencia de autoridad de extensión de tarifa Token-2022** — cuando el base mint es un mint Token-2022 que lleva `TransferFeeConfig` **y** `PlatformConfig.transfer_fee_extension_auth` es no predeterminado, la migración también reasigna las autoridades de esa extensión a la clave de plataforma:

- `transfer_fee_config_authority` siempre es reasignado. El PDA de lanzamiento `authority` lo mantiene durante toda la fase pre-graduación, por lo que siempre hay algo que mover.
- `WithheldWithdraw` es reasignado **solo cuando el PDA `authority` aún lo mantiene**. Los lanzamientos creados a partir del 2026-08-27 en adelante ya llevan `transfer_fee_extension_auth` en esa autoridad desde la creación de mint, por lo que el paso se omite. La guardia es lo que evita que la migración revierta en esos mints — el PDA no puede renunciar a una autoridad que ya no mantiene.

Si `transfer_fee_extension_auth` es `Pubkey::default()` en el momento de la migración, ninguna autoridad se mueve y ambas permanecen con el PDA `authority` permanentemente. Ver [`platform-config`](/es/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**Postcondiciones** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` rechazarán a partir de este punto con `PoolMigrated`. El pool AMM resultante es canónico y comercia como cualquier otro pool AMM v4 / CPMM.

**Errores comunes** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### Cuentas restantes de migración CPMM

Los clientes que construyen `MigrateToCpswap` deben usar estos índices de `remaining_accounts` fijos:

| Índice | Cuenta |
|---|---|
| 0–4 | Propietario de Fee Key de plataforma, mint, cuenta de token, PDA de liquidez bloqueada y cuenta de metadatos |
| 5 | Creador de lanzamiento original; utilizado cuando `platform_cp_creator` no está establecido |
| 6 | PDA de permiso CPMM derivado de `[b"permission", launch_authority]` |
| 7 | `platform_cp_creator` configurado; utilizado cuando el campo es no predeterminado |
| 8 | PDA de mint de soporte CPMM para `mint0` ordenado, derivado de `[b"support_mint", mint0]` |
| 9 | PDA de mint de soporte CPMM para `mint1` ordenado, derivado de `[b"support_mint", mint1]` |

La instrucción requiere al menos diez cuentas restantes en la ruta actualizada. Las cuentas de mint de soporte son entradas CPI de solo lectura. Deriva ambas direcciones incluso cuando el mint no tiene un registro de soporte inicializado. Los constructores más antiguos que aún adjuntan cuentas de bloqueo de creador u omiten los índices 8–9 deben ser actualizados.

### Programas de token de migración CPMM

`MigrateToCpswap` toma ambos programas de token incondicionalmente y determina cuál posee cada mint. Sus dos cuentas de programa de token fueron renombradas en consecuencia:

| Posición | Cuenta | Valor |
|---|---|---|
| primera | `token_program` | Siempre el programa SPL Token heredado |
| segunda | `token_program_2022` | Siempre el programa Token-2022 |

Reemplazan el anterior `base_token_program` (cualquier programa que poseyera el base mint) y `quote_token_program` (siempre heredado). Las posiciones no cambiaron, por lo que esto es un cambio de valor en lugar de un cambio de diseño — pero los dos valores están cerca de invertirse, y un constructor que sigue pasando su par anterior suministrará Token-2022 donde se requiere el programa heredado tan pronto como cualquiera de los mints sea un mint Token-2022.

El programa heredado es requerido incluso cuando ninguno de los mints lo usa, porque el mint de LP de CPMM y la NFT de Fee Key de liquidez bloqueada siempre viven en él.

## Lista de permitidos de `GlobalConfig` de plataforma

`PlatformConfig.restrict_global_config` controla la comprobación:

- `0`: la plataforma acepta cualquier `GlobalConfig` válido de otra manera; no se requiere cuenta de permitidos.
- `1`: `Initialize`, `InitializeV2` e `InitializeWithToken2022` deben incluir el `PlatformAllowConfig` coincidente en cualquier lugar en `remaining_accounts`.

El administrador de plataforma crea o cierra el PDA con `CreatePlatformAllowConfig` y `ClosePlatformAllowConfig`. Sus semillas son `[b"platform_allow_config", platform_config, global_config]`. Las antiguas instrucciones `PlatformGlobalAccess` administradas por administrador y PDA se retiran.

## `CollectMigrateFee`

Barrido administrativo de la tarifa de migración acumulada en la graduación. La misma forma de cuenta que `CollectFee` con `migrate_fee_owner` como el firmante (en lugar de `protocol_fee_owner`) y `pool_state.migrate_fee` como el contador drenado.

**Efecto** — transferir `pool_state.platform_fee` de `quote_vault` a `recipient_token_account`, poner a cero el contador.

## `ClaimPlatformFeeFromVault`
