Cuando un token de LaunchLab migra a CPMM, el pool acuña tokens LP. Antes de la actualización del 2026-08-14, `creatorScale` se bloqueaba por separado para el creador del token. Para migraciones ejecutadas después de la actualización, `migrateCpLockNftScale` sigue almacenando tres campos que suman `1_000_000`, pero el runtime produce solo dos destinos.

## División efectiva

| Campo | Comportamiento actualizado |
|---|---|
| `platformScale` | Incluido en la cuota de LP bloqueado propiedad de la plataforma. |
| `creatorScale` | Antes de la actualización, acuñaba una Fee Key propiedad del creador. Después de la actualización, se incluye en la cuota de LP bloqueado propiedad de la plataforma. |
| `burnScale` | Se quema permanentemente. Ninguna Fee Key representa esta cuota. |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

Cuando `burnScale` es cero, la plataforma recibe todas las unidades de LP. Cuando `effectivePlatformScale` es cero, todo el LP se quema y no se crea ninguna Fee Key de plataforma.

## Ejemplos

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% LP bloqueado propiedad de la plataforma, 10% quemado.
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// Bajo el programa actualizado, esto produce 100% LP bloqueado propiedad de la plataforma.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% quemado; sin Fee Key.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## Relación con las comisiones de creador de CPMM

Los campos de escala controlan solo la propiedad de LP. No establecen tasas de comisión de swap ni identifican al beneficiario de la comisión de creador de CPMM. `cpConfigId` selecciona la `AmmConfig` de CPMM; `platformCpCreator` determina si el pool de CPMM registra el creador del lanzamiento original o una dirección seleccionada por la plataforma.

## Actualizar la división

Antes de actualizar una plataforma:

- Confirma que los tres valores sumen exactamente `1_000_000`.
- Presenta `platformScale + creatorScale` como la cuota efectiva de la plataforma.
- No prometas una Fee Key de creador basada en `creatorScale`.
- Preserva la propiedad de Fee Key del creador mostrada por migraciones completadas antes de la actualización; esos registros no se reescriben.
- Explica el cambio antes de que futuros lanzamientos usen la configuración actualizada.
