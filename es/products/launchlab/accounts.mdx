## Inventario de cuentas

| Cuenta | Propietario | Propósito |
|---------|-------|---------|
| [`GlobalConfig`](/es/products/launchlab/global-config) | Programa LaunchLab | Reglas a nivel de protocolo: comisiones, pisos de suministro, carteras de migración. Una por `(curve_type, index)`. |
| [`PlatformConfig`](/es/products/launchlab/platform-config) | Programa LaunchLab | Superposición por plataforma: marca, comisión de plataforma, división de NFT en graduación, lista blanca de forma de curva. |
| `PoolState` | Programa LaunchLab | Estado raíz por lanzamiento: mints, vaults, parámetros de curva, contadores vendidos, contadores de comisiones, cronograma de vesting, estado de graduación. |
| `authority` | Programa LaunchLab | PDA único con semilla `[b"vault_auth_seed"]` que posee vaults en todos los lanzamientos y firma el CPI posterior a la graduación. |
| `base_vault` | SPL Token / Token-2022 | Vault por lanzamiento que contiene los tokens base no vendidos. |
| `quote_vault` | SPL Token | Vault por lanzamiento que contiene los tokens quote acumulados. |
| [`VestingRecord`](/es/products/launchlab/vesting) | Programa LaunchLab | Registro por beneficiario de acantilado + desbloqueo lineal. Opcional. |
| `creator_fee_vault` | SPL Token | Vault por creador + por mint de quote que contiene comisiones de creador acumuladas, barridas por `ClaimCreatorFee`. |
| `platform_fee_vault` | SPL Token | Vault por plataforma + por mint de quote que contiene comisiones de plataforma acumuladas, barridas por `ClaimPlatformFeeFromVault`. |
| [`PlatformAllowConfig`](/es/products/launchlab/platform-config) | Programa LaunchLab | Permiso opcional gestionado por plataforma para un par `(PlatformConfig, GlobalConfig)`. Se verifica solo cuando la plataforma habilita la restricción. |
| (post-graduación) `cpmm_pool_state` | Programa CPMM | Pool creado por `MigrateToCpswap` para cada nuevo lanzamiento. El estado heredado aún puede hacer referencia a una graduación de AMM v4. |
| (post-graduación) Fee Key NFT | Programa LP-Lock | Antes de la actualización del 2026-08-14, las escalas de plataforma y creador podían producir Fee Keys separadas. Las migraciones ejecutadas después combinan ambas escalas en una única Fee Key de plataforma. |

El método `raydium.launchpad.getLaunchById` del SDK devuelve `PoolState` más una bandera indicando si el lanzamiento se ha graduado; si es así, se incluye el ID del pool posterior a la migración.

## `PoolState`

El estado raíz por lanzamiento. Los nombres de campo a continuación coinciden con la estructura Rust en cadena (`states/pool.rs`); algunos valores se simplifican para legibilidad — consulta la fuente para el diseño exacto de memoria.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit flags for SPL Token vs Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Valores de `PoolStatus` (del IDL de Anchor):

```
0 = Funding         — aceptando compras / ventas; por debajo de quote_reserve_target
1 = Migrate         — quote_reserve_target alcanzado; esperando MigrateTo*
2 = Migrated        — MigrateTo* ya ejecutado; reloj de vesting en marcha
```

Campos orientados al integrador:

- **`status`** — tres valores, monótonos (Funding → Migrate → Migrated). Las lecturas siempre son seguras; las escrituras están controladas.
- **`real_base`**, **`real_quote`** — estado actual de la curva. Combinados con `virtual_base` / `virtual_quote` son suficientes para calcular el precio spot sin tocar los vaults. Consulta [`bonding-curve`](/es/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — relación de "progreso hacia graduación" para interfaces de usuario.
- **`migrate_type`** — la nueva inicialización requiere `1` (`CPSWAP`). Un `0` almacenado sigue siendo significativo solo para un lanzamiento existente creado antes de la aplicación exclusiva de CPMM.
- **`amm_creator_fee_on`** — elige `creator_fee_on = OnlyQuoteToken` (`0`) o `BothToken` (`1`) en el pool CPMM posterior a la graduación. No elige el destino de migración. Consulta [`creator-fees`](/es/products/launchlab/creator-fees).
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — tres contadores de comisiones independientes. Cada uno tiene su propia instrucción de reclamación; consulta [`instructions`](/es/products/launchlab/instructions).
- **`vesting_schedule`** — presente en cada `PoolState` pero inactivo cuando `total_locked_amount == 0`. Consulta [`vesting`](/es/products/launchlab/vesting) para el ciclo de vida completo.

## El PDA de autoridad

LaunchLab utiliza un **único** PDA de autoridad en todos los lanzamientos, derivado sin semilla por lanzamiento:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Ese PDA único es:

- La autoridad en cada `base_vault` y `quote_vault` del lanzamiento.
- El `mint_authority` en cada `base_mint` del lanzamiento (pre-graduación).
- El firmante en el CPI de graduación de CPMM, y en la graduación heredada de AMM v4 para estado existente.
- El firmante en las transferencias de `ClaimVestedToken` fuera del vault base.

El `mint_authority` se revoca inmediatamente después de `MigrateToCpswap` o una llamada heredada de `MigrateToAmm`, por lo que el suministro se fija permanentemente.

Dos PDAs adicionales controlan los vaults de comisiones:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Estos firman la transferencia fuera de los vaults de comisiones correspondientes durante `ClaimCreatorFee` y `ClaimPlatformFeeFromVault`.

## Mint base

Creado en línea por `Initialize` con:

- `mint_authority = authority` (revocado en graduación).
- `freeze_authority = None`.
- `supply = supply`, completamente acuñado en `base_vault`.
- `decimals` elegido por el creador en `Initialize` (comúnmente 6).

Debido a que el suministro completo se acuña previamente, `base_mint.supply` es constante durante la vida del lanzamiento. Las compras de curva mueven tokens de `base_vault` al comprador, pero no llaman a `mint_to`.

`Initialize` / `InitializeV2` crean lanzamientos de SPL Token. La instrucción dedicada `InitializeWithToken2022` permite que el mint base sea un mint de Token-2022 (con `TransferFeeConfig` opcional); el mint quote sigue siendo SPL Token. Las tres rutas de inicialización requieren graduación de CPMM.

## Vaults

Tanto `base_vault` como `quote_vault` son cuentas estándar de SPL Token propiedad del PDA `authority` de LaunchLab. Las direcciones se almacenan en `PoolState` y también se pueden derivar:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Verifica los prefijos de semilla exactos de la estructura de cuentas `Initialize` de la fuente antes de confiar en una derivación en producción.)

## Vaults de comisiones

Dos PDAs agregan comisiones en todos los lanzamientos:

- **Vault de comisión del creador** — PDA con semillas `[creator, quote_mint]`. Cada lanzamiento que gana las mismas comisiones de creador en el mismo mint de quote vierte en el mismo vault. El creador lo barre a través de `ClaimCreatorFee`.
- **Vault de comisión de plataforma** — PDA con semillas `[platform_config, quote_mint]`. Cada lanzamiento enrutado a través de la misma plataforma que usa el mismo mint de quote vierte en el mismo vault. La `platform_fee_wallet` de la plataforma lo barre a través de `ClaimPlatformFeeFromVault`. También hay una variante de barrido por lanzamiento (`ClaimPlatformFee`) que extrae del `quote_vault` del lanzamiento directamente sin pasar por el vault agregado.

El patrón de vault agregado es lo que permite que un creador o plataforma de alto volumen amortice el costo de renta de acumulación de comisiones en muchos lanzamientos.

## Quote vault ↔ `real_quote`

`quote_vault.balance` y `PoolState.real_quote` deben mantenerse sincronizados. Pueden desviarse como máximo por la suma de los tres contadores de comisiones pendientes (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), que se encuentran en el vault pero pertenecen a los contadores de comisiones y no a la reserva de curva. Las matemáticas de la curva siempre usan `real_quote`, nunca el saldo bruto del vault.

Invariante pre-graduación:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## Transiciones de cuentas del ciclo de vida

| Evento | Estado | `real_base` | `real_quote` | Pool posterior a graduación |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (o heredado `MigrateToAmm`) | Funding → Migrate → Migrated | (congelado) | (congelado) | creado; LP de CPMM se divide en LP bloqueado propiedad de plataforma y LP quemado |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | cualquiera | — | — | drena un vault de comisiones |
| `CreateVestingAccount` | Funding | — | — | incrementa `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Solo Migrated | — | — | drena `base_vault` |
