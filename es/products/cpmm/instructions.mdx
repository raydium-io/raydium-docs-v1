## Resumen de instrucciones

| Nombre del discriminador | Quién firma | Qué hace |
|-------|-----------|--------------|
| `Initialize` | creador del pool | Crear un nuevo pool CPMM a partir de dos mints y una `AmmConfig`. Sin permisos; cualquiera puede llamarla. Codifica `enable_creator_fee = false` en el nuevo pool. La cuenta `pool_state` puede ser el PDA canónico o una keypair aleatoria nueva (ver cuentas de Initialize). |
| `InitializeWithPermission` | pagador + titular de un PDA `Permission` | Variante con permisos de `Initialize`. El llamador (`payer`) debe poseer un PDA `Permission` derivado de su propia clave pública. Utilizado por plataformas que necesitan creación de pools controlada (p. ej. graduaciones de LaunchLab). Permite al llamador fijar `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) y fuerza `enable_creator_fee = true` en el nuevo pool. El campo `creator` en `pool_state` se establece en una cuenta `creator` pasada por separado, no en el pagador. La misma flexibilidad PDA-canónico-o-keypair-aleatorio para `pool_state` que en `Initialize`. |
| `Deposit` | LP | Añadir liquidez en ambos tokens; recibir tokens LP. |
| `Withdraw` | LP | Quemar tokens LP; recibir ambos tokens subyacentes pro-rata. |
| `SwapBaseInput` | intercambiador | Swap de entrada exacta (`amount_in` dentro, ≥ `minimum_amount_out` fuera). |
| `SwapBaseOutput` | intercambiador | Swap de salida exacta (≤ `maximum_amount_in` dentro, `amount_out` fuera). |
| `CollectProtocolFee` | `protocol_owner` (de `AmmConfig`) | Recopilar comisiones de protocolo acumuladas de los vaults. |
| `CollectFundFee` | `fund_owner` (de `AmmConfig`) | Recopilar comisiones de fondo acumuladas de los vaults. |
| `CollectCreatorFee` | `pool_creator` | Recopilar comisiones de creador acumuladas (si la comisión de creador estaba habilitada). |
| `CollectCreatorFeePermissionless` | cualquier pagador | Recopilar todas las comisiones de creador acumuladas a las cuentas de token canónicas del `pool_creator`. El pagador puede crear ATAs de destinatario faltantes pero no puede redirigir la transferencia. |
| `UpdatePoolStatus` | `admin` | Pausar / reanudar operaciones específicas en un pool mediante una máscara de bits. |
| `UpdateAmmConfig` | `admin` | Cambiar tasas de comisión o el propietario de protocolo/fondo en una `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Crear un nuevo nivel de comisión (nueva cuenta `AmmConfig`). |
| `CreatePermissionPda` | `admin` o creador de PDA de permisos delegado | Acuñar un PDA `Permission` que permite a una autoridad específica llamar a `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` | Revocar un PDA `Permission` emitido previamente. |

Máscara de estado: el `status` de cada pool es un `u8` donde el bit 0 = depósito deshabilitado, bit 1 = retiro deshabilitado, bit 2 = swap deshabilitado (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` en el programa). Un bit claro significa que la operación está permitida; un bit establecido significa que está pausada. `UpdatePoolStatus` toma un `u8` sin procesar y sobrescribe el valor existente.

Las siguientes secciones detallan cada una. El orden de cuentas sigue el IDL de CPMM; el SDK y el cliente Rust en `raydium-cp-swap/programs/cp-swap/src/instructions` coinciden con este orden.

## `Initialize`

Crear un nuevo pool CPMM.

**Argumentos**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Marca de tiempo Unix; swaps rechazados antes de esto
```

**Cuentas** (W = escribible, S = firmante)

| # | Nombre | W | S | Notas |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Paga la renta; registrado como `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | El nivel de comisión elegido. |
| 3 | `authority` |   |   | PDA de autoridad global de CPMM. |
| 4 | `pool_state` | W | S* | `init`ializado aquí. **O bien** el PDA canónico `["pool", amm_config, token_0_mint, token_1_mint]` **o** una keypair aleatoria nueva — cuando no es el PDA canónico, el programa requiere que `pool_state` firme (`require_eq!(pool_account_info.is_signer, true)`). La ruta de keypair aleatoria permite a un creador evadir intentos de front-running en el PDA canónico. Los PDAs posteriores (`lp_mint`, `vaults`, `observation_state`) se derivan de `pool_state.key()` de cualquier forma. |
| 5 | `token_0_mint` |   |   | Ordenado: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | `init`ializado aquí. Autoridad establecida en `authority`. |
| 8 | `creator_token_0` | W |   | ATA de origen para `init_amount_0`. |
| 9 | `creator_token_1` | W |   | ATA de origen para `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | Destino para LP (creado si falta). |
| 11 | `token_0_vault` | W |   | `init`ializado aquí. Propiedad de `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | ATA de destino para la `create_pool_fee` pagada por el creador. |
| 14 | `observation_state` | W |   | `init`ializado aquí. |
| 15 | `token_program` |   |   | SPL Token (para LP mint). |
| 16 | `token_0_program` |   |   | SPL Token o Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token o Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` firma solo en la ruta de keypair aleatoria; la ruta de PDA canónico se ejecuta sin que `pool_state` firme.

**Precondiciones**

- Los mints están ordenados (`token_0_mint < token_1_mint` por orden de bytes).
- Ningún mint utiliza una extensión fuera de la lista de permitidos de CPMM (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — ver [`products/cpmm/accounts`](/es/products/cpmm/accounts#vaults-and-token-2022). Una pequeña lista de permitidos por mint dentro del programa evita la verificación para incorporación caso por caso.
- `creator` tiene al menos `init_amount_0` e `init_amount_1` en los ATAs respectivos.
- `amm_config.disable_create_pool == false`.

**Postcondiciones**

- `pool_state` existe con `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- El iniciador de LP de `LOCKED_LP` (`100` láminas de token LP) está permanentemente bloqueado en el pool — `pool_state.lp_supply` registra `liquidity − 100` mientras que `100` unidades de LP permanecen fuera de circulación, evitando que el pool se drene completamente y se divida por cero.
- `observation_state` se inicializa; `observation_index = 0` y `pool_id = pool_state.key()`.
- Las láminas de `create_pool_fee` se transfieren del creador al receptor y se sincronizan como SOL nativo (es un ATA wSOL).
- La máscara de estado del pool es `0` (depósito / retiro / swap todos habilitados).
- `enable_creator_fee = false` y `creator_fee_on = BothToken`. `Initialize` **no** admite habilitar la comisión de creador — esa ruta es `InitializeWithPermission`.
- `open_time` se incrementa a `block_timestamp + 1` si el llamador pasó un valor `<= block_timestamp`. Los swaps se rechazan antes de `open_time`; los depósitos y retiros funcionan inmediatamente.

**Errores comunes** (lista completa en [`reference/error-codes`](/es/reference/error-codes))

- `InvalidInput` — mints sin ordenar o mints idénticos.
- `NotSupportMint` — extensión de Token-2022 bloqueada.
- `ExceededSlippage` — raramente; si `init_amount_0/1` resultan en LP cero debido a desajuste de decimales.

## `Deposit`

Añadir liquidez en ambos tokens proporcional al pool.

**Argumentos**

```
lp_token_amount:   u64   // cuántos tokens LP acuñar para el LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Matemáticas**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

Sin cambios en la proporcionalidad de `k` — ambos vaults y `lp_supply` se escalan por el mismo factor.

**Postcondiciones**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (neto de cualquier comisión de transferencia de Token-2022 en la entrada).
- `vault_1 += needed_token_1` (neto de cualquier comisión de transferencia de Token-2022 en la entrada).

**Errores comunes** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus` si el depósito está pausado.

## `Withdraw`

Quemar tokens LP y recibir ambos tokens subyacentes pro-rata.

**Argumentos**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(Idéntico a `Deposit`; `lp_mint` es escribible porque los tokens LP se queman.)

**Matemáticas**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**Postcondiciones**

- `lp_supply -= lp_token_amount`.
- Los vaults envían `out_token_0` / `out_token_1` (bruto; el usuario recibe neto de cualquier comisión de transferencia de Token-2022).

## `SwapBaseInput`

Swap de entrada exacta.

**Argumentos**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

El orden **entrada → salida** es por la dirección del usuario, no por el `token_0 / token_1` canónico del pool. El programa determina qué vault es cuál haciendo coincidir los mints.

**Matemáticas** — ver [`products/cpmm/math`](/es/products/cpmm/math).

**Precondiciones**

- `open_time <= now`.
- `pool_status` permite swap.
- Ningún mint pausado o congelado para esta autoridad.
- `amount_in > 0`.

**Errores comunes**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — la operación se redondea a cero.
- `NotApproved` — el pool está pausado para swaps mediante `UpdatePoolStatus`.
- `InvalidInput` — los mints no coinciden con ninguno de los mints del vault del pool.

## `SwapBaseOutput`

Swap de salida exacta.

**Argumentos**

```
max_amount_in:  u64
amount_out:     u64
```

**Cuentas** — igual que `SwapBaseInput`.

**Matemáticas** — curva inversa con techo, ver [`products/cpmm/math`](/es/products/cpmm/math).

**Errores comunes** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

## `CollectProtocolFee`

Recopilar comisiones de protocolo acumuladas de los vaults al destino del protocolo.

**Argumentos** — ninguno.

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `owner` |   | S | Debe coincidir con `amm_config.protocol_owner`. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**Efecto**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

Sin cambios en los saldos efectivos de la curva (las comisiones acumuladas ya estaban excluidas).

**Error común** — `NotApproved` si el firmante no es `protocol_owner`.

## `CollectFundFee`

Misma forma que `CollectProtocolFee` pero firmado por `fund_owner` y poniendo a cero los contadores `fund_fees_*`.

## `CollectCreatorFee`

Firmado por `pool_state.pool_creator`. Transfiere los saldos completos de `creator_fees_token_0` y `creator_fees_token_1` a las cuentas de token del creador, luego pone a cero ambos contadores. Devuelve `NoFeeCollect` cuando ambos contadores son cero.

## `CollectCreatorFeePermissionless`

Cualquiera puede activar la recopilación de comisiones de creador. La instrucción siempre envía los saldos acumulados completos a las cuentas de token asociadas canónicas propiedad de `pool_state.pool_creator`; el llamador no puede elegir otro creador o destino. Si falta algún ATA, el pagador financia su creación.

El `CollectCreatorFee` original sigue siendo invocable, por lo que los clientes existentes permanecen compatibles.

**Argumentos** — ninguno.

**Cuentas**

| # | Nombre | W | S | Notas |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Cualquier firmante; financia ATAs de creador faltantes. |
| 2 | `creator` |   |   | Debe ser igual a `pool_state.pool_creator`; no firma. |
| 3 | `authority` |   |   | PDA de autoridad de vault global de CPMM. |
| 4 | `pool_state` | W |   | Contiene los contadores de comisión de creador acumulados. |
| 5 | `token_0_vault` | W |   | Debe coincidir con el vault de token 0 del pool. |
| 6 | `token_1_vault` | W |   | Debe coincidir con el vault de token 1 del pool. |
| 7 | `vault_0_mint` |   |   | Debe coincidir con `token_0_vault.mint`. |
| 8 | `vault_1_mint` |   |   | Debe coincidir con `token_1_vault.mint`. |
| 9 | `creator_token_0` | W |   | ATA canónico del creador para `vault_0_mint`; creado si falta. |
| 10 | `creator_token_1` | W |   | ATA canónico del creador para `vault_1_mint`; creado si falta. |
| 11 | `token_0_program` |   |   | SPL Token o Token-2022, coincidiendo con token 0. |
| 12 | `token_1_program` |   |   | SPL Token o Token-2022, coincidiendo con token 1. |
| 13 | `associated_token_program` |   |   | Crea un ATA de destinatario faltante. |
| 14 | `system_program` |   |   | Financia la creación de cuentas desde `payer`. |

**Efecto**

- Transfiere todo `creator_fees_token_0` y `creator_fees_token_1` de los vaults del pool a los ATAs del creador.
- Pone a cero ambos contadores de comisión de creador y actualiza `pool_state.recent_epoch`.
- Devuelve `NoFeeCollect` cuando ambos contadores son cero.

## `UpdatePoolStatus`

Pausar o reanudar operaciones individuales en un pool. El campo `status` es una máscara de bits:

| Bit | Bandera | Efecto cuando está establecido |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` rechaza con `NotApproved`. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` rechaza. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` rechazan. |

**Argumentos**

```
status: u8      // nueva máscara de bits
```

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `authority` |   | S | Debe coincidir con la clave de administrador en el programa CPMM. |
| 2 | `pool_state` | W |   |

La clave de administrador es la autoridad de actualización en el programa CPMM — en la práctica, el multisig de Raydium. Ver [`security/admin-and-multisig`](/es/security/admin-and-multisig).

Crear un nuevo nivel de comisión.

**Argumentos**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
```

**Cuentas**

| # | Nombre | W | S |
|---|------|---|---|
| 1 | `owner` | W | S | Administrador. |
| 2 | `amm_config` | W |   | `init`ializado aquí. |
| 3 | `system_program` |   |   |

**Precondiciones**

- No existe `AmmConfig` con el mismo `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

## `UpdateAmmConfig`

Cambiar tasas de comisión u propiedad en una `AmmConfig` existente. Toma un `param: u8` (discriminador para qué campo actualizar) y un `value: u64`. La semántica de valor por parámetro está en la fuente; comúnmente:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (pasar bytes `Pubkey` como reinterpretación)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

Los cambios se firman por el administrador y afectan a **cada pool vinculado a esta `AmmConfig`** en el próximo swap. Sin migración; los pools simplemente leen los nuevos valores.

## Matriz de cambio de estado

| Instrucción | `lp_supply` | Saldos de vault | Campos de comisión acumulada | `observation` |
|-------------|------------|---------------|-------------------|---------------|
| `Initialize` | + init LP | + `init_amount_{0,1}` | 0 | init |
| `InitializeWithPermission` | + init LP | + `init_amount_{0,1}` | 0 | init |
| `Deposit` | + | + ambos | — | — |
| `Withdraw` | − | − ambos | — | — |
| `SwapBaseInput` | — | + entrada, − salida | + `trade_fee` dividido en protocolo/fondo; + `creator_fee` si está habilitado | + (si transcurrió el intervalo) |
| `SwapBaseOutput` | — | + entrada, − salida | + `trade_fee` dividido en protocolo/fondo; + `creator_fee` si está habilitado | + (si transcurrió el intervalo) |
| `CollectProtocolFee` | — | − (por buckets de protocolo) | `protocol_*` → 0 | — |
| `CollectFundFee` | — | − (por buckets de fondo) | `fund_*` → 0 | — |
| `CollectCreatorFee` | — | − (por buckets de creador) | `creator_*` → 0 | — |
| `CollectCreatorFeePermissionless` | — | − (por buckets de creador) | `creator_*` → 0 | — |
| `UpdatePoolStatus` | — | — | — | — |
