## Requisitos previos

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

Cada demostración en esta página refleja un archivo en [`raydium-sdk-V2-demo/src/cpmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/cpmm); el enlace de GitHub se encuentra junto a cada sección. El arranque sigue el `config.ts.template` del repositorio de demostración ([fuente](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template)):

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

La instancia `Raydium` es la fachada del SDK — cada demostración a continuación la utiliza. `Raydium.load` es asincrónica porque carga la lista de tokens de forma predeterminada; pasa `disableLoadToken: true` para omitir esa búsqueda. La verificación de características de disponibilidad ya se omite a menos que pases `disableFeatureCheck: false`. Las configuraciones de comisiones se obtienen de forma perezosa en el primer uso a través de `raydium.api.getCpmmConfigs()`.

## Crear un pool CPMM

Fuente: [`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (Si necesitas cada PDA de pool a la vez, el ayudante exportado es `getCreatePoolKeys`.
//  No hay `getCpmmPdas`.)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. Elige una configuración de comisión. index=0 es el nivel 0.25%.
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. Extrae metadatos de mint para que el SDK pueda manejar extensiones de Token-2022.
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. Construye la transacción.
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL (asumiendo 9 decimales)
  mintBAmount:     new BN(   160_000_000),  // 160 USDC (a 160/SOL)
  startTime:       new BN(0),               // abierto inmediatamente
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool creado en", extInfo.address.poolId.toBase58());
console.log("Tx:", txId);
```

Algunas cosas que el SDK maneja silenciosamente:

- Ordenar los mints en orden token0/token1 antes de derivar el PDA.
- Pagar la `create_pool_fee` única a `poolFeeAccount`.
- Crear las cuentas de token asociadas del llamador si faltan.
- Elegir el programa de token correcto (SPL Token vs Token-2022) por lado.

Después de la confirmación, puedes obtener el estado del pool en vivo con:

```ts
// getPoolInfoFromRpc toma una cadena base58 posicional, no una PublicKey ni un objeto.
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## Swap (entrada base)

Fuente: [`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // cadena base58

// 1. Carga el estado actual del pool directamente desde un RPC (no desde la API).
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // swap A → B
const amountIn   = new BN(100_000_000);                   // 0.1 SOL
const slippage   = 0.005;                                 // 0.5%

// 2. Cotiza localmente. CurveCalculator refleja la matemática en cadena, incluyendo
//    comisiones de transferencia de Token-2022 en ambos lados. Los ocho argumentos son obligatorios.
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// Los campos de swapResult son inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount.
// No hay destinationAmountSwapped ni sourceAmountSwapped.

// 3. Construye y envía. Pasar `slippage` aquí es lo que aplica el límite —
//    no se necesita aritmética manual de salida mínima.
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Tx de swap:", txId);
```

Nota: el SDK **siempre** vuelve a obtener el estado del pool desde un RPC dentro de `getPoolInfoFromRpc`. No cites de `api-v3.raydium.io` para una transacción que estés a punto de firmar — una cotización que está un bloque desactualizada puede deslizarse en `ExceededSlippage` en el momento de la ejecución.

## Swap (salida base)

Fuente: [`src/cpmm/swapBaseOut.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swapBaseOut.ts)

```ts
const amountOutWanted = new BN(15_000_000);        // 15 USDC
const slippage        = 0.005;

const baseIn = false; // false → mintB es el lado de entrada
const swapResult = CurveCalculator.swapBaseOutput(
  amountOutWanted,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult.inputAmount es la entrada requerida; no hay sourceAmountSwapped.

const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: new BN(0),   // no utilizado cuando fixedOut — la cantidad viene de swapResult
  fixedOut:    true,
  swapResult,               // obligatorio, y lleva la cantidad de salida objetivo
  baseIn,
  slippage,
  txVersion:   TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

## Depositar liquidez

Fuente: [`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity se impulsa por una cantidad de ENTRADA, no por una cantidad de LP.
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // un Percent, no un número

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount está denominado en mintA
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

El SDK deriva la cantidad emparejada de las reservas actuales del pool, infla cada lado por el slippage para los argumentos `maximum_*` de la instrucción, y construye las creaciones de ATA si es necesario. `raydium.cpmm.computePairAmount({ ... })` devuelve los mismos números si los quieres para una vista previa de la interfaz de usuario.

## Cobrar comisiones de protocolo/fondo/creador

Fuente: [`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts), [`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

La recopilación de protocolo y fondo sigue siendo controlada por autoridad. Las comisiones del creador tienen dos caminos: el `CollectCreatorFee` firmado por el creador, y el aditivo `CollectCreatorFeePermissionless`, que cualquier pagador puede invocar pero que solo puede transferir a los ATA canónicos del creador. `0.2.64-alpha` envía constructores a nivel de módulo para ambas rutas del creador:

```ts
// firmado por el creador
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// sin permisos — cualquier pagador; los ingresos van a los ATA canónicos del creador
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// varios pools a la vez, firmado por el creador
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Note>
  Las dos instrucciones del creador tienen **discriminadores y diseños de cuenta diferentes** — la
  sin permisos reemplaza las posiciones del firmante del creador / `amm_config` con un `payer`
  separado y un `creator` que no firma. Usa el constructor coincidente en lugar de intercambiar
  manualmente cuentas en el otro.

  No hay constructor de comisión de protocolo o fondo en el SDK (`makeCollectProtocolFeeInstruction` y
  `makeCollectFundFeeInstruction` no existen bajo ningún nombre) — esos son caminos de administrador. Los
  constructores de instrucciones de bajo nivel que *sí* existen son `collectCpFeeInstruction`,
  `makeCollectCreatorFeeInstruction` e `collectCreatorFeePermissionlessInInstruction`.
</Note>

Fuera de la cadena, puedes leer las comisiones acumuladas directamente desde `PoolState`:

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // cadena base58
console.log("Comisión de protocolo acumulada mintA:", pool.protocolFeesMintA.toString());
console.log("Comisión de protocolo acumulada mintB:", pool.protocolFeesMintB.toString());
// Los campos de CpmmPoolInfoLayout son protocolFeesMintA/B, fundFeesMintA/B y
// creatorFeesMintA/B — no hay campos ...Token0/...Token1.
```

## Esqueleto de Rust CPI

Si quieres invocar CPMM desde tu propio programa Anchor — por ejemplo, una bóveda que intercambia en nombre de sus depositantes — el contexto de CPI se ve así. El orden de cuentas sigue [`products/cpmm/instructions`](/es/products/cpmm/instructions).

```rust
// Cargo.toml — la rama importa: `master` aún fija anchor-lang 0.32.1.
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "chore/upgrade-anchor", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // debe coincidir con lo que raydium-cp-swap fija
// anchor-spl       = "=1.0.2"
//
// La característica `cpi` es obligatoria — el módulo `raydium_cp_swap::cpi` solo existe
// bajo ella. Ten en cuenta que este crate no puede compartir un programa con la muestra CLMM en
// products/clmm/code-demos, que fija anchor-lang =0.32.1.

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: validado por el programa CPMM
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: búfer de anillo
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0 toma la Pubkey del programa aquí, no su AccountInfo.
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

Si tu CPI firma como un PDA (por ejemplo, administras una bóveda en nombre de los depositantes), intercambia `CpiContext::new` por `CpiContext::new_with_signer` y pasa tus semillas.

## Errores comunes

Una lista de verificación breve antes de abrir un ticket de soporte:

- **Mints ordenados.** Si tu PDA `poolState` derivado no coincide con el pool en cadena, probablemente olvidaste ordenar los mints.
- **Cotización de API desactualizada.** Nunca pases un valor de reserva de `api-v3.raydium.io` a `CurveCalculator.swap`. Obtén desde un RPC.
- **Programa de token incorrecto.** El vault de un mint de Token-2022 es propiedad del programa Token-2022, no de SPL Token. Siempre usa los campos `token_0_program` / `token_1_program` del pool.
- **Slippage sub-denominado para mints de comisión de transferencia.** Si cualquiera de los lados del pool es un mint de comisión de transferencia de Token-2022, tu `minimum_amount_out` debe estar denominado en lo que el usuario realmente recibe, no en lo que el vault envía.
- **`NotApproved` en un swap.** Verifica `PoolState.status` — el administrador puede haber pausado los swaps en ese pool. Consulta [`products/cpmm/instructions`](/es/products/cpmm/instructions) para la máscara de estado.
