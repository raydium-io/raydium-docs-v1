## Herramientas principales

### Solana CLI

La interfaz de línea de comandos canónica para interactuar con clústeres Solana — gestión de billeteras, llamadas RPC, despliegue de programas.

Instalar:

```bash
# La versión contra la que se construyen y prueban los programas de Raydium
sh -c "$(curl -sSfL https://release.anza.xyz/v3.1.10/install)"

# O seguir un canal en lugar de una etiqueta
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"
```

Verificar:

```bash
solana --version   # → solana-cli 3.1.10 (... client:Agave)
```

<Note>
  **El host de instalación se movió.** `release.solana.com` pertenecía a Solana Labs; el cliente ahora es mantenido por Anza como **Agave**, y los lanzamientos se sirven desde `release.anza.xyz`. El binario de auto-actualización es `agave-install` (`solana-install` se mantiene como un alias heredado), así que `agave-install update` y `agave-install init <version>` son los nombres actuales. La propia documentación de Solana también ofrece un instalador de un comando que extrae CLI, Rust y Anchor juntos:

  ```bash
  curl --proto '=https' --tlsv1.2 -sSfL https://solana-install.solana.workers.dev | bash
  ```

  Ese instalador sigue su propia idea de lo actual y puede entregarte un Anchor diferente del que fijan los programas de Raydium — verifica `anchor --version` después.
</Note>

Configurar para mainnet:

```bash
solana config set --url https://api.mainnet-beta.solana.com
solana config set --keypair ~/.config/solana/id.json
solana-keygen new                           # crear una billetera si no tienes una
solana address                              # tu clave pública
```

Para pruebas de Raydium, casi siempre querrás una billetera devnet financiada:

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2                            # 2 SOL para pruebas
```

### SPL Token CLI

La CLI oficial para operaciones SPL Token / Token-2022 — crear mints, acuñar tokens, transferir.

Instalar (incluido con Solana CLI):

```bash
spl-token --version
```

Operaciones comunes:

```bash
spl-token create-token                                  # crear un mint SPL Token
spl-token create-token --program-id TOKEN_2022 ...      # crear un mint Token-2022
spl-token create-account <MINT>                         # crear un ATA
spl-token mint <MINT> 1000                              # acuñar 1000 tokens en tu ATA
spl-token transfer <MINT> 100 <RECIPIENT>               # transferir 100
spl-token display <ACCOUNT_OR_MINT>                     # inspeccionar
```

### Anchor CLI

Necesario para obtener IDLs de Raydium, construir clientes y verificar programas.

Instalar:

```bash
cargo install --git https://github.com/solana-foundation/anchor avm --locked --force
avm install 1.0.2
avm use 1.0.2
anchor --version   # → anchor-cli 1.0.2
```

<Note>
  **Anchor cambió de repositorio y versión mayor.** El repositorio canónico es ahora `github.com/solana-foundation/anchor` (era `coral-xyz/anchor`), y Anchor 1.0 es la primera línea de lanzamiento que usan los programas de Raydium — CPMM y LaunchLab ambos fijan `anchor-lang`/`anchor-spl` `=1.0.2` a partir de la actualización 2026-09-09, subiendo desde `0.32.1`. `avm` puede mantener varias versiones; `avm use 1.0.2` es lo que hace que `anchor build` reproduzca los artefactos de Raydium. Anchor 1.1 y 1.2 existen y se construyen bien para tus propios programas, pero un crate CPI compilado contra un `anchor-lang` menor diferente del que fija el programa objetivo no se vinculará — ver [`sdk-api/rust-cpi`](/es/sdk-api/rust-cpi).
</Note>

Operaciones comunes:

```bash
anchor idl fetch <PROGRAM_ID> -o program.idl.json       # obtener el IDL en cadena
anchor idl init -f idl.json <PROGRAM_ID>                # subir un IDL
anchor build                                             # construir un programa desde fuente
```

## Configuración de TypeScript

La ruta de integración principal para Raydium.

### Paquetes

```bash
npm install \
  @solana/web3.js \
  @solana/spl-token \
  @anchor-lang/core \
  @raydium-io/raydium-sdk-v2 \
  bn.js \
  decimal.js
```

Versiones que se sabe funcionan juntas a partir de septiembre de 2026:

| Paquete | Versión | Nota |
|---------|---------|------|
| `@solana/web3.js` | `^1.95` | La API 1.x. `2.x` / `3.x` son una superficie de API diferente e incompatible; el SDK de Raydium apunta a 1.x. |
| `@solana/spl-token` | `^0.4.15` | 0.4.15 es lo que expone `createUnwrapLamportsInstruction` — ver [renta reclamable](/es/solana-fundamentals/rent-and-reclaimable-rent). |
| `@anchor-lang/core` | `^1.0` | El cliente TypeScript de Anchor 1.x. |
| `@raydium-io/raydium-sdk-v2` | `0.2.64-alpha` | El pin que usa cada demostración de código en estos documentos. |

<Note>
  **`@anchor-lang/core` está congelado; el paquete es ahora `@anchor-lang/core`.** `@anchor-lang/core` se detuvo en `0.32.1` cuando Anchor se movió a la Fundación Solana. Anchor 1.x se publica como `@anchor-lang/core`, y los propios repositorios de programas de Raydium cambiaron sus suites de prueba a él en la actualización 2026-09-09. Las importaciones que realmente usas no cambian — `import { Program, BN, AnchorProvider } from "@anchor-lang/core"` — así que migrar es un cambio de nombre de paquete más una actualización de lockfile.

  Dos notas de comportamiento si te estás moviendo desde `0.3x`: `.accounts({...})` ahora solo acepta cuentas que Anchor no puede resolver por sí mismo, así que un constructor que pasa el conjunto completo debe llamar a `.accountsPartial({...})` en su lugar; y `@anchor-lang/core/dist/cjs/utils/token` es donde se movieron ayudantes como `ASSOCIATED_PROGRAM_ID`.
</Note>

### Script mínimo

```ts
import { Connection, Keypair } from "@solana/web3.js";
import { Raydium } from "@raydium-io/raydium-sdk-v2";

const connection = new Connection("https://api.mainnet-beta.solana.com", "confirmed");
const owner      = Keypair.fromSecretKey(/* your key */);

const raydium = await Raydium.load({
  connection,
  owner,
  cluster:      "mainnet",
  disableFeatureCheck: true,
});

// `ids` es una lista separada por comas, y la llamada devuelve un array
const [poolInfo] = await raydium.api.fetchPoolById({ ids: "..." });
console.log(poolInfo);
```

Ver [`sdk-api/typescript-sdk`](/es/sdk-api/typescript-sdk) para la referencia completa del SDK.

## Configuración de Rust

Para integración CPI y programas en cadena.

### Cadena de herramientas

```bash
rustup install 1.91.0           # lo que fijan los programas de Raydium
rustup default 1.91.0
rustup component add rustfmt clippy
agave-install init 3.1.10       # cadena de herramientas SBF incluida
```

Construye los programas con `cargo build-sbf` (la antigua ortografía `cargo build-bpf` se ha ido).

### Program Cargo.toml para una integración CPI de Raydium

```toml
# Integración CPMM (Anchor 1.0)
[dependencies]
anchor-lang        = "=1.0.2"
anchor-spl         = "=1.0.2"
raydium-cp-swap    = { version = "0.2", features = ["cpi"] }
```

```toml
# Integración CLMM — aún Anchor 0.32, así que necesita su propio crate
[dependencies]
anchor-lang        = "=0.32.1"
anchor-spl         = "=0.32.1"
raydium-clmm       = { version = "0.1", features = ["cpi"] }
```

Fija `anchor-lang` y `anchor-spl` con `=` a la versión que fija el programa objetivo. A partir de 2026-09 CPMM fija `=1.0.2` y CLMM aún fija `=0.32.1`, así que **un único crate no puede hacer CPI en ambos** — ver [`sdk-api/rust-cpi`](/es/sdk-api/rust-cpi#cargo-dependencies).

La característica `"cpi"` importa el módulo `cpi` con ayudantes CPI (así que puedes `raydium_cp_swap::cpi::swap_base_input(...)`). Ver [`sdk-api/rust-cpi`](/es/sdk-api/rust-cpi).

## Configuración de Python

Ruta de integración secundaria — común para desarrolladores de bots.

### Paquetes

```bash
pip install solders solana anchorpy
```

Versiones:

| Paquete | Nombre PyPI | Versión |
|---------|-------------|---------|
| `solders` | `solders` | ≥0.29 |
| solana-py | `solana` | ≥0.40 |
| `anchorpy` | `anchorpy` | ≥0.21 |

<Note>
  Dos trampas de nomenclatura. El cliente RPC se importa como `solana` pero el proyecto se llama **solana-py** — `pip install solana-py` no instala nada útil. Y no hay **paquete `raydium-py` en PyPI**: el ayudante comunitario de Raydium es un repositorio que clonas, [`AL-THE-BOT-FATHER/raydium_py`](https://github.com/AL-THE-BOT-FATHER/raydium_py), no una distribución publicada. Las revisiones anteriores de esta página listaban una línea `pip install raydium-py` que nunca funcionó.
</Note>

### Script mínimo

```python
from solana.rpc.async_api import AsyncClient
from solders.keypair import Keypair
from anchorpy import Provider, Wallet, Program

async def main():
    conn = AsyncClient("https://api.mainnet-beta.solana.com")
    owner = Keypair()
    wallet = Wallet(owner)
    provider = Provider(conn, wallet)

    # Cargar IDL y programa
    with open("cpmm.idl.json") as f:
        idl = json.load(f)
    program = Program(idl, CPMM_PROGRAM_ID, provider)

    pool = await program.account["PoolState"].fetch(pool_id)
    print(pool)
```

Ver [`sdk-api/python-integration`](/es/sdk-api/python-integration).

## Puntos finales RPC

El RPC público de mainnet (`api.mainnet-beta.solana.com`) tiene límite de velocidad muy restrictivo y se ralentiza bajo cualquier carga. Para uso no trivial, obtén un punto final privado:

| Proveedor | Notas |
|-----------|-------|
| Helius | El más popular; nivel gratuito generoso. |
| Triton | Empresarial; precios premium, estable. |
| QuickNode | Sólido; latencia sub-por-segundo. |
| Tu propio nodo RPC | Cuesta ~\$500/mes en hardware; control total. |

Configurar:

```ts
const connection = new Connection("https://mainnet.helius-rpc.com/?api-key=...");
```

Algunas operaciones RPC necesitan capacidades extendidas:

- `getProgramAccounts` — los escaneos sin restricciones son costosos; algunos proveedores cierran o cobran por escaneo.
- `getPriorityFeeEstimate` — punto final específico de Helius; otros tienen equivalentes.
- `geyser` / transmisión WebSocket — necesario para bots de baja latencia; no todos los proveedores lo exponen.

## Devnet y localnet

### Devnet

Clúster de prueba público de Solana. Raydium tiene un despliegue parcial en devnet:

- Algunos pools CPMM existen para pruebas.
- AMM v4 tiene pools históricos de devnet.
- CLMM tiene algunos pools de demostración.
- Farm v6 está desplegado.

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2
```

El SDK soporta devnet a través de `cluster: "devnet"`:

```ts
const raydium = await Raydium.load({ connection, owner, cluster: "devnet" });
```

**Advertencia**: los pools de devnet tienen liquidez delgada y pueden tener estado obsoleto. No confíes en devnet para descubrimiento de precios; úsalo solo para construir y probar flujos de instrucciones.

### Localnet con estado de mainnet bifurcado

Para pruebas realistas, bifurca el estado de mainnet en un validador local:

```bash
solana-test-validator \
  --url https://api.mainnet-beta.solana.com \
  --clone CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C \
  --clone CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK \
  --clone <SOME_POOL_ID> \
  --clone <SOME_MINT_ID>
```

Esto clona el estado específico del programa/cuenta a localhost, donde puedes transaccionar libremente. Ideal para:

- Pruebas unitarias de tu integración CPI contra un programa Raydium real.
- Reproducir una transacción con un parámetro modificado para depurar.
- Pruebas de estrés con grandes volúmenes sintéticos.

El equipo de Raydium usa localnet bifurcado extensamente para pruebas de regresión antes del despliegue en mainnet.

## Plantillas de proyecto

### Iniciador de integración TypeScript

```
my-raydium-app/
├── package.json
├── tsconfig.json
├── src/
│   ├── swap.ts           # ejemplo de swap
│   ├── add-liquidity.ts
│   └── read-pool.ts

```

`package.json` mínimo:

```json
{
  "name": "my-raydium-app",
  "type": "module",
  "scripts": { "swap": "tsx src/swap.ts" },
  "dependencies": {
    "@raydium-io/raydium-sdk-v2": "0.2.64-alpha",
    "@solana/web3.js": "^1.95",
    "@solana/spl-token": "^0.4.15"
  },
  "devDependencies": {
    "@types/node": "^20",
    "tsx": "^4",
    "typescript": "^5"
  }
}
```

### Iniciador de programa Anchor CPI

```
my-raydium-cpi/
├── Anchor.toml
├── Cargo.toml
├── programs/
│   └── my-cpi/
│       ├── Cargo.toml
│       └── src/lib.rs
└── tests/
    └── my-cpi.ts
```

Con Anchor 1.0:

```bash
anchor init my-raydium-cpi
cd my-raydium-cpi

anchor build

```

## Higiene del entorno

### Billeteras separadas por propósito

- **Billetera de desarrollo**: contiene SOL de testnet, se usa para construir.
- **Billetera de producción**: contiene SOL real, se usa solo para despliegues / envíos multisig.
- **Billetera activa para bots**: saldo pequeño, permisos limitados.

Las claves nunca deben estar codificadas. Usa variables de entorno o gestores de secretos.

### Patrón `.env`

```
# .env (no comprometido)
SOLANA_RPC_URL=https://mainnet.helius-rpc.com/?api-key=...
WALLET_PATH=/Users/you/.config/solana/id.json
```

```ts
import { config } from "dotenv";
config();

const connection = new Connection(process.env.SOLANA_RPC_URL!);
```

### Fijación de versiones

Bloquea todas las dependencias del ecosistema Solana. El ecosistema se mueve rápido; un bump de versión menor de `@solana/web3.js` ha introducido previamente cambios disruptivos. Usa `package-lock.json` / `Cargo.lock` religiosamente.
