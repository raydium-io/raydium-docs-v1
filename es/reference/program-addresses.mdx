### Convenciones de configuración compartida / PDA

Varios programas de Raydium exponen **cuentas de configuración** cuyas claves públicas son estables y se enumeran en la API pública. Prefiere la búsqueda de API sobre codificar:

```
# Configuraciones de comisión de CPMM (devuelve un array de {id, index, tradeFeeRate, ...})
GET https://api-v3.raydium.io/main/cpmm-config

# Configuraciones de comisión de CLMM
GET https://api-v3.raydium.io/main/clmm-config
```

El receptor de comisión de creación de pool de CPMM es una cuenta fija, no derivada o buscada a través de la API: `create_pool_fee_reveiver::ID` en `lib.rs` de `raydium-cp-swap`, actualmente `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`. La instrucción `initialize` de CPMM la valida por dirección exacta, por lo que ya debe existir en cualquier cluster en el que estés probando.

Parámetros de comisión de índice de `AmmConfig` predeterminado de CPMM `0` (pool estándar de 0.25%), como referencia:

| Campo | Valor | Significado |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 0.25% del volumen de operaciones |
| `protocol_fee_rate` | `120000` | 12% **de la comisión de operación** (no volumen) enrutada al protocolo |
| `fund_fee_rate` | `40000` | 4% **de la comisión de operación** enrutada al multisig del fondo |
| `creator_fee_rate` | `500` | 0.05% del volumen de operaciones al creador del pool (opcional) |

Consulta [`products/cpmm/fees`](/es/products/cpmm/fees) para ver cómo se componen las divisiones y [`reference/fee-comparison`](/es/reference/fee-comparison) para la matriz entre productos.

### Semillas de PDA

Las semillas a continuación son **canónicas** y se utilizan tanto en el SDK como en CPIs en cadena. Siempre calcula PDAs; no codifiques direcciones derivadas.

```ts
// CPMM — todas las semillas son cadenas ASCII estáticas a menos que se indique lo contrario.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` están **ordenados por orden de bytes de clave pública** (token0 < token1) antes de hacer hash. Hacerlo mal produce un PDA válido para un pool inexistente.

Las semillas equivalentes de CLMM siguen el mismo estilo; consulta [`products/clmm/accounts`](/es/products/clmm/accounts).

## Cómo verificar una dirección en cadena

1. **Solana Explorer.** Pega la dirección en [explorer.solana.com](https://explorer.solana.com) y confirma que está marcada como `Program` con una autoridad de actualización actual. Mainnet-beta debe mostrar implementaciones firmadas por la autoridad de actualización de Raydium.
2. **CLI.** Usa `solana program show <PROGRAM_ID> -u mainnet-beta` para inspeccionar el slot de implementación, el cargador BPF, la autoridad de actualización y la longitud de datos. Registra estos en tu manual de procedimientos.
3. **Adjunto de IDL.** Consulta el IDL en cadena con `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet`. El campo `address` del IDL debe coincidir. Los mismos IDLs se reflejan en [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — compara el IDL en cadena contra el repositorio antes de confiar en él.
4. **Autoridades de configuración/administrador.** Para cuentas de configuración de CPMM/CLMM, lee el campo `owner`/`protocol_owner` y confirma que coincida con el multisig actual de Raydium publicado en [`security/admin-and-multisig`](/es/security/admin-and-multisig).

Si cualquiera de las cuatro comprobaciones anteriores no está de acuerdo con esta página, trata esta página como incorrecta y abre un problema antes de escribir código nuevo contra las direcciones.
