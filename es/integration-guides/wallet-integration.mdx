## Detectar posiciones de Raydium

### Tokens LP clásicos (CPMM, AMM v4)

Se ven como cualquier otro token SPL: la ATA del usuario contiene un saldo. Una billetera lo muestra como otro token por defecto. Para revelarlo como una posición LP de Raydium:

1. Enumera las cuentas de token del usuario: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Para cada mint, verifica la lista de mints de Raydium: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (agrupa hasta ~50 mints LP por llamada).
3. Para los mints que coincidan, la API devuelve la referencia del pool. Úsala para calcular el valor de la posición denominado en tokens:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Muestra tanto el saldo LP como los montos desenvueltos — los usuarios piensan en tokens subyacentes, no en unidades LP.

### NFTs de posición CLMM

Las posiciones CLMM son NFTs. El PDA `PersonalPositionState` de cada posición se deriva del mint del NFT. Para detectar:

1. Enumera los NFTs del usuario. Para NFTs Metaplex heredados: filtra cuentas de token a aquellas con suministro 1 y decimales 0.
2. Para cada mint de NFT, intenta derivar el PDA de PersonalPositionState:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Es una posición CLMM de Raydium — decodifica.
```

3. Enumera las posiciones de la billetera con `raydium.clmm.getOwnerPositionInfo({ programId })` y coincide en `nftMint` (no hay `getPositionInfo`). Cada entrada te proporciona:
   - `poolId` → obtén el pool para resolver mints
   - `tickLower`, `tickUpper` → muestra el rango
   - `liquidity`, `tokensOwedA/B` → calcula el valor de la posición + comisiones pendientes
   - `rewardInfos` → recompensas pendientes por stream

4. Para NFTs de posición emitidos bajo Token-2022 (`OpenPositionWithToken22Nft`), el programa del mint del NFT es Token-2022 en lugar de SPL Token. Enumera ambos al escanear.

### Apuestas en granjas

Farm v3 / v5 / v6 cada una tiene un PDA de libro mayor por usuario. Derivaciones:

```ts
// Intenta las tres versiones de granja para cada una de las posibles interacciones de granja del usuario.
// Enfoque más económico: pregunta primero a la API, que ha indexado todas las posiciones del usuario.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Para billeteras que prefieren detección completamente en cadena: itera PDAs posibles de `UserLedger` hasheando el usuario con una lista curada de IDs de granja "probables". Enumerar todos los IDs de granja exhaustivamente es impracticable (existen miles); usa la API.

## Calcular el valor de la posición

### LP CPMM / AMM v4

Los tres módulos **no** comparten una firma: `liquidity.getPoolInfoFromRpc` toma `{ poolId }`, mientras que `cpmm.getPoolInfoFromRpc` y `clmm.getPoolInfoFromRpc` toman una cadena base58 posicional.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` es un ApiV3Token y no tiene campo `supply`. Lee el
// suministro del mint LP de la cadena, o usa el espejo propio del pool:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Luego multiplica cada uno por el precio USD del mint (de `raydium.token` u un oráculo de precios).

### Posición CLMM

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // cadena base58
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity es asincrónica, toma epochInfo + poolInfo + add,
// y devuelve montos envueltos en comisiones.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // para visualización, sin slippage
  add:        false,
});
// amountA.amount / amountB.amount son los BNs; .fee es la comisión de transferencia de Token-2022.

// Comisiones pendientes — muestra por separado como "no cobradas"
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Recompensas pendientes — un pool CLMM tiene 0–3 streams de recompensas. Las entradas
// rewardInfos de la posición son solo { growthInsideLastX64, rewardAmountOwed }, así que el
// mint tiene que venir de rewardInfos del POOL en el mismo índice.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Renderiza como:

- Valor de liquidez (precio actual)
- Comisiones no cobradas
- Recompensas pendientes por stream
- Rango: `[tickLower_price, tickUpper_price]` con una barra visual mostrando si el precio actual está dentro del rango

### Apuesta en granja

```ts
// La respuesta de la API ya incluye recompensas pendientes; úsala directamente.
const apr       = stakingFarm.apr;               // %, anualizado
const staked    = stakingFarm.stakedAmount;      // unidades más pequeñas del mint de apuesta
const rewards   = stakingFarm.pendingRewards;    // array de { mint, amount }
```

Para cálculo en cadena, refleja la contabilidad de la granja:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Asegúrate de actualizar `reward_per_share_x64` con la fórmula de actualización perezosa antes de calcular (tiempo transcurrido × tasa de emisión ÷ total_staked).

## Simulación de transacción para vista previa

Antes de que un usuario firme, las billeteras generalmente previsualizan los cambios de saldo. Usa `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Decodifica el saldo de cada cuenta devuelta y compara con los saldos previos a la tx.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // compara con el saldo previo a la tx, muestra Δ
}
```

El parámetro `accounts` le pide al validador que devuelva el estado de la cuenta posterior a la simulación para las direcciones listadas. Mucho más preciso que intentar predecir el cambio de saldo solo desde la forma de la instrucción.

### Trampas de simulación

- **Los swaps CLMM necesitan arrays de tick válidos.** Si el tamaño de entrada del usuario cruzaría un array de tick no inicializado, la simulación se revierte (igual que la ejecución). Muestra esto claramente en la interfaz.
- **Comisión de prioridad.** La simulación se ejecuta sin las instrucciones de presupuesto de cómputo aplicadas. Para una transacción grande que excedería los 200k CU por defecto, la simulación falla pero la ejecución real con un límite de CU explícito tiene éxito. Siempre establece el límite de CU en la tx simulada también.
- **Blockhash fresco.** La simulación usa el blockhash actual; si la firma toma >60s la tx se vuelve inválida. Re-simula si el usuario duda.

## Visualización de Token-2022

Los tokens bajo el programa Token-2022 deben etiquetarse como tales en la lista de tokens de la billetera, ya que tienen superficies de riesgo diferentes:

- **Mints con comisión de transferencia**: muestra los `transferFeeBasisPoints` actuales como "Comisión de transferencia: X%" junto al saldo. Advierte al recibir — los usuarios pueden no darse cuenta de que recibirán menos de lo que el remitente envió.
- **Mints con gancho de transferencia**: muestra el ID del programa del gancho. Un gancho malicioso puede bloquear transferencias salientes; los usuarios deben verificar que el gancho sea el que esperan.
- **Mints no transferibles**: muestra "No transferible" y desactiva swap/envío. Estos son típicamente tokens vinculados al alma o credenciales.
- **Mints que generan interés**: el saldo de la interfaz derivado de `TokenAccount.amount` **no** refleja el interés acumulado. Usa `amountToUiAmount` de `@solana/spl-token` (que aplica el factor de escala) para el valor mostrado.

## Visualización de APR de granja

El APR mostrado a los usuarios debe combinar todos los streams de recompensas activos, convertidos a USD, y anualizados:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // salta los que no están en ejecución
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

Muestra como `APR: X.Y%`. Si el mint de apuesta es un token LP, también calcula el APR de comisión base del LP subyacente y etiqueta la suma como "APR Total" o "APR + comisiones".
