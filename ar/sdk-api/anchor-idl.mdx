## ما هو IDL

برامج Anchor على Solana تنشر ملف **IDL** (لغة تعريف الواجهة) يصف تعليماتها وتخطيطات الحسابات وتعداد الأخطاء وأنماط الهياكل. يعتبر IDL مصدر الحقيقة لإنشاء كود العميل — حيث يتم إنشاء TS SDK وصندوق Rust CPI والعملاء من جهات خارجية من (أو كتابتها يدويًا ضد) IDL.

تنشر Raydium IDLs لـ CPMM و CLMM و LaunchLab. AMM v4 و Stable AMM و Farm (v3 / v5 / v6) سابقة لـ Anchor أو غير موزعة عبر Anchor — تُحتفظ بهياكل حساباتها يدويًا في SDK.

## حيث تجدها

تعيش IDLs في مستودع مخصص:

```
https://github.com/raydium-io/raydium-idl
```

الملفات الدقيقة:

| البرنامج | ملف IDL |
|---------|----------|
| CPMM | [`raydium_cpmm/raydium_cp_swap.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_cpmm/raydium_cp_swap.json) |
| CLMM | [`raydium_clmm/raydium_clmm.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_clmm/raydium_clmm.json) |
| LaunchLab | [`raydium_launchpad/raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json) |
| AMM v4 | لا يوجد IDL رسمي — انظر [`raydium-sdk-V2/src/raydium/liquidity/layout.ts`](https://github.com/raydium-io/raydium-sdk-V2/blob/master/src/raydium/liquidity/layout.ts) للتخطيطات المكتوبة يدويًا |
| Stable AMM | لا يوجد IDL رسمي — التخطيطات في SDK |
| Farm | لا يوجد IDL رسمي — التخطيطات في SDK |

يتم إصدار ملفات IDL في سجل git للمستودع؛ ثبّت على commit معين إذا كنت بحاجة إلى قابلية إعادة الإنتاج بالبايت الكامل.

يمكن أيضًا سحب بعض IDLs مباشرة من mainnet:

```bash
anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet
```

هناك الآن **آليتان** على السلسلة لـ IDL، وتنقسم برامج Raydium عبرهما — وهذا مهم لأن إصدار Anchor CLI معين قد يعرف واحدة فقط:

| البرنامج | حيث يعيش IDL الخاص به | الحساب | التقارير |
|---------|--------------------|---------|---------|
| CLMM | حساب Anchor القديم `anchor:idl` | `FbDNAPsgm8Y5jWXQkXjpfN6Bp8xHeRkhMmsstAooPyY9` | `raydium_clmm` 0.1.0 — 38 تعليمة، 52 خطأ |
| LaunchLab | حساب Anchor القديم `anchor:idl` | `E6wT2uNeoWUvDrwdch1R8ETsyewR1ZM4WAwsa5hLJK5Z` | `raydium_launchpad` 0.2.0 — 27 تعليمة |
| Lock (Burn \& Earn) | حساب Anchor القديم `anchor:idl` | `HzLkUWn57cdtyQNQLJpyu2EPF8qQAiGt4iuiEo1XnEFK` | 4 تعليمات (IDL spec سابق للـ `metadata`) |
| **CPMM** | **برنامج Program Metadata** `ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S` | `FHuJXL7cEttfHk4sXdTAXVaRymBdKfVs7ZH6cMgA1ihk` (canonical، seed `idl`) | `raydium_cp_swap` 0.2.0 |
| AMM v4، Stable AMM، AMM Routing، Farm v3 / v5 / v6 | لا مكان | — | برامج غير Anchor؛ لا يتم نشر IDL |

<Warning>
  **CPMM ليس لديه حساب `anchor:idl` قديم.** تم ترحيل IDL الخاص به إلى برنامج Program Metadata، لذا فإن `anchor idl fetch CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C` يفشل على أي Anchor CLI يتحقق فقط من PDA القديم. استخدم IDL المرسل مع SDK، أو اقرأ حساب البيانات الوصفية أعلاه، حتى يدعم CLI الخاص بك برنامج البيانات الوصفية.
</Warning>

جميع حسابات IDL الثلاثة القديمة قابلة للكتابة بواسطة سلطة IDL `2XVnob28A5Qnpcy95UVeHWNT6G8Poy3tpA3AFyAMoZDt`، وهي منفصلة عن سلطة ترقية BPF للبرامج — لذا يمكن تحديث IDL دون إعادة نشر، ويمكن أيضًا أن يتأخر عن إعادة النشر. تعامل مع IDL على السلسلة كمسألة راحة، وليس كإثبات لشكل bytecode المنشور.

## إعادة إنشاء عميل TypeScript

ينتج عن codegen الخاص بـ Anchor عميل مكتوب من IDL:

```bash
# استخدام anchor CLI
anchor build
anchor idl parse \
  --file target/idl/cpmm.json \
  --out target/types/cpmm.ts

# أو مع مساعدات TS `@anchor-lang/core` في وقت التشغيل:
```

```ts
import { Program, AnchorProvider } from "@anchor-lang/core";
// اسحب IDL مباشرة من مستودع raydium-idl (أو ضعه في مشروعك).
import cpmmIdl from "./idls/raydium_cp_swap.json";

const provider = new AnchorProvider(connection, wallet, {});
// Anchor >= 0.30 يقرأ معرف البرنامج من `idl.address` — هذه IDLs هي spec 0.1.0
// وتحمله. نموذج الثلاث حجج `new Program(idl, programId, provider)` هو
// pre-0.30 ويرمي.
const program  = new Program(cpmmIdl as any, provider);

// منشئو الطرق المكتوبة التي تم إنشاؤها تلقائيًا:
await program.methods
  .swapBaseInput(new BN(amountIn), new BN(minAmountOut))
  .accounts({ ... })
  .rpc();
```

معظم المدمجين **لا** يفعلون هذا — يستخدمون مساعد `raydium.cpmm.swap(...)` ذو المستوى الأعلى الذي يلف طرق Anchor بالإضافة إلى جميع الحفظيات (إنشاء ATA، تعديل رسوم النقل، ميزانية الحساب، توجيه برنامج Token-2022). أعد الإنشاء فقط عندما تحتاج إلى طبقة أسفل SDK.

## إعادة إنشاء عميل Rust (صندوق CPI)

تنشر Raydium صناديق Anchor للبرامج التي لديها IDLs:

```toml
# Cargo.toml — يجب أن يكون مفتاح الاعتماد هو اسم PACKAGE للصندوق.
[dependencies]
raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap", branch = "chore/upgrade-anchor", features = ["cpi"] }
raydium-clmm    = { git = "https://github.com/raydium-io/raydium-clmm",    branch = "master",              features = ["cpi"] }
```

في الكود، أشر إليها باستخدام أسماء **lib** الخاصة بها، `raydium_cp_swap` و `raydium_clmm`. لا يوجد صندوق يسمى `raydium_amm_v3` تحت أي تهجئة. لاحظ أن الفروع تختلف: `raydium-cp-swap` الخاص بـ `master` لا يزال يثبت `anchor-lang 0.32.1`، لذا فإن تكامل Anchor-1.0 يحتاج إلى `chore/upgrade-anchor`؛ CLMM على `0.32.1` على أي حال، وهذا هو السبب في عدم تمكن الاثنين من مشاركة صندوق.

تكشف ميزة `cpi` عن هياكل حسابات `cpi::accounts::<Ix>` و invokers `cpi::<ix>()` — غلافات CPI جاهزة للاستخدام. انظر [`sdk-api/rust-cpi`](/ar/sdk-api/rust-cpi) لأنماط الاستخدام.

إذا كنت تفضل إنشاء ربطات جديدة:

```bash
# من IDL، باستخدام anchor-client
anchor idl parse \
  --file raydium_cpmm/raydium_cp_swap.json \
  --out src/generated/cpmm_bindings.rs
```

## إعادة إنشاء عميل Python

لا يوجد SDK Python رسمي لـ Raydium. تتضمن المولدات من جهات خارجية:

- **`anchorpy`** — منفذ Python لعميل Anchor TypeScript. ينشئ منشئي طرق مكتوبة من IDLs.
- **`solders`** — بدائيات Solana منخفضة المستوى (المعاملات، المفاتيح، pubkeys) في ربطات Rust؛ تُستخدم تحت `anchorpy`.

```bash
pip install anchorpy solders solana
```

```python
from anchorpy import Program, Provider
from solana.rpc.async_api import AsyncClient
from pathlib import Path
import json

idl = json.loads(Path("cpmm.json").read_text())
provider = Provider(AsyncClient("https://api.mainnet-beta.solana.com"), wallet)
program  = Program(idl, CPMM_PROGRAM_ID, provider)

await program.rpc["swap_base_input"](amount_in, min_amount_out, ctx=Context(accounts={...}))
```

انظر [`sdk-api/python-integration`](/ar/sdk-api/python-integration) للحصول على شرح أكثر اكتمالاً.

## سياسة تغيير IDL

تتبع Raydium هذه القواعد لاستقرار IDL:

1. **لا تتغير مميزات التعليمات أبدًا.** إضافة تعليمات جديدة تمدد التعداد في النهاية؛ تبقى المميزات الموجودة مستقرة.
2. **أحجام الحسابات مستقرة؛ الحقول الجديدة تأتي من الحشو المحجوز.** كل هيكل حالة Raydium يحمل منطقة حشو زائدة بحجم الإنشاء، والحقل الجديد يتم نحته من هذا الحشو بدلاً من إضافته — لذا يبقى طول الحساب بالبايت وإزاحات جميع الحقول *الموجودة مسبقًا* ثابتة. النتيجة الطبيعية هي أن البايتات التي كنت تقرأها سابقًا كحشو يمكن أن تصبح ذات معنى، وقد يتم إيقاف حقل مرة أخرى في الحشو (كما حدث مع `PlatformConfig.curve_params` في إصدار 2026-08-31). أعد قراءة تعريف الهيكل بعد الترقية؛ لا تفترض أن الحشو يبقى صفرًا.
3. **أكواد تعداد الأخطاء قابلة للإضافة فقط.** كود خطأ موجود يعني دائمًا نفس الشيء.
4. **التغييرات الجذرية تُشحن في برامج جديدة.** عندما تكون هناك حاجة لإعادة تصميم، يقوم الفريق بنشر معرف برنامج جديد (مثل CPMM كبرنامج جديد بدلاً من ترقية AMM v4). تستمر المجموعات القديمة في التشغيل على البرنامج القديم؛ تذهب المجموعات الجديدة إلى الجديد.

تحافظ هذه السياسة على توافق العملاء المُعاد إنشاؤهم بشكل أساسي: يحتفظ العميل الذي تم إنشاؤه مقابل IDL أقدم بفك تشفير الحقول التي يعرفها، بالإزاحات التي يعرفها. ما لن يراه هو حقل تم نحته من ما يعتبره لا يزال حشوًا — وفي حالة الإيقاف النادرة، قد لا يتم كتابة حقل يفك تشفيره. لا يرى "بايتات زائدة زائدة": لا يتغير طول الحساب.

## ماذا تفعل عندما يتغير IDL

1. **حدّث SDK.** `npm update @raydium-io/raydium-sdk-v2`.
2. **أعد إنشاء كود العميل الخاص بك** إذا كنت تستخدم Anchor codegen مباشرة.
3. **قارن تخطيط الحساب.** الحقول الزائدة للتخطيط الجديد هي الشيء الوحيد الذي لم يره الكود الخاص بك؛ تأكد مما إذا كنت بحاجة إليها.
4. **لا تفترض أن مميزات التعليمات القديمة غير صالحة.** وفقًا للقاعدة 1، لا تزال تعمل.
5. **أعد تشغيل اختبارات التكامل** مقابل devnet قبل الانتقال إلى mainnet.

## استكشاف أخطاء IDL

### أخطاء "Invalid discriminator"

عادة ما يعني أن عميلاً تم بناؤه مقابل الإصدار N من IDL يحاول استدعاء تعليمة كانت موجودة فقط في نسخة ما قبل النشر من البرنامج. أعد سحب IDL من البرنامج المباشر:

```bash
anchor idl fetch <PROGRAM_ID>
```

بالنسبة لـ CPMM، هذا لن ينجح — انظر جدول موقع IDL أعلاه؛ اسحب IDL المرسل مع SDK بدلاً من ذلك.

### فشل فك تشفير الحساب

إذا رمى `program.account.<Name>.fetch(pubkey)` مع "Invalid account discriminator"، تم إنشاء الحساب بواسطة إصدار برنامج سابق ويرفضه Anchor مميز 8 بايت الخاص به. الحل هو استخدام محلل التخطيط الخام من SDK (`PoolInfoLayout.decode(accountData)`) الذي لا يفرض مميزات Anchor.

### تعليمات مفقودة في العميل المُنشأ

يولد Anchor TS codegen فقط طرقًا للتعليمات التي يحتوي إدخال IDL الخاص بها على `name` يتحلل كمعرف صالح. جميع تعليمات Raydium تستوفي هذا، لكن إذا رأيت عدم تطابق، تحقق مما إذا كان ملف IDL من إصدار SDK الحالي.
