## ما هو ملف IDL

برامج Anchor على Solana تنشر ملف **IDL** (لغة تعريف الواجهة) يصف التعليمات والتخطيطات الحسابية والتعداد الخطأ وأنماط الهياكل. يعتبر IDL مصدر الحقيقة لإنشاء كود العميل — حيث يتم إنشاء TS SDK وصندوق Rust CPI والعملاء من جهات خارجية من (أو كتابتها يدويًا ضد) ملف IDL.

ينشر Raydium ملفات IDL لـ CPMM و CLMM و LaunchLab. AMM v4 و Stable AMM و Farm (v3 / v5 / v6) سابقة لـ Anchor أو لا يتم توزيعها عبر Anchor — حيث يتم الحفاظ على هياكل حساباتها يدويًا في SDK.

## حيث تجدها

تعيش ملفات IDL في مستودع مخصص:

```
https://github.com/raydium-io/raydium-idl
```

الملفات الدقيقة:

| البرنامج | ملف IDL |
|---------|----------|
| CPMM | [`raydium_cpmm/raydium_cp_swap.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_cpmm/raydium_cp_swap.json) |
| CLMM | [`raydium_clmm/raydium_clmm.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_clmm/raydium_clmm.json) |
| LaunchLab | [`raydium_launchpad/raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json) |
| AMM v4 | لا يوجد IDL رسمي — انظر [`raydium-sdk-V2/src/raydium/liquidity/layout.ts`](https://github.com/raydium-io/raydium-sdk-V2/blob/master/src/raydium/liquidity/layout.ts) للتخطيطات المكتوبة يدويًا |
| Stable AMM | لا يوجد IDL رسمي — التخطيطات في SDK |
| Farm | لا يوجد IDL رسمي — التخطيطات في SDK |

يتم إصدار ملفات IDL في سجل git للمستودع؛ قم بالتثبيت على commit محدد إذا كنت بحاجة إلى قابلية إعادة الإنتاج بالبايت الكامل.

يمكن أيضًا سحب ملفات IDL مباشرة من البرامج المنشورة عبر ميزة **on-chain IDL** الخاصة بـ Anchor (إذا اختار ناشر البرنامج الاشتراك):

```bash
anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet
```

CPMM و CLMM و LaunchLab جميعها لديها IDLs على السلسلة. AMM v4 و Stable AMM و Farm لا تملكها (برامج سابقة لـ Anchor).

## إعادة إنشاء عميل TypeScript

يُنتج codegen الخاص بـ Anchor عميلاً مكتوبًا من IDL:

```bash
# استخدام Anchor CLI
anchor build
anchor idl parse \
  --file target/idl/cpmm.json \
  --out target/types/cpmm.ts

# أو باستخدام مساعدات TS `@anchor-lang/core` في وقت التشغيل:
```

```ts
import { Program, AnchorProvider } from "@anchor-lang/core";
// اسحب IDL مباشرة من مستودع raydium-idl (أو ضعه في مشروعك).
import cpmmIdl from "./idls/raydium_cp_swap.json";

const provider = new AnchorProvider(connection, wallet, {});
const program  = new Program(cpmmIdl as any, CPMM_PROGRAM_ID, provider);

// منشئات الطرق المكتوبة التي تم إنشاؤها تلقائيًا:
await program.methods
  .swapBaseInput(new BN(amountIn), new BN(minAmountOut))
  .accounts({ ... })
  .rpc();
```

معظم المدمجين **لا** يفعلون هذا — فهم يستخدمون مساعد `raydium.cpmm.swap(...)` ذو المستوى الأعلى الذي يلف طرق Anchor بالإضافة إلى جميع الحفظيات (إنشاء ATA وتعديل رسوم النقل وميزانية الحساب وتوجيه برنامج Token-2022). أعد الإنشاء فقط عندما تحتاج إلى طبقة أسفل SDK.

## إعادة إنشاء عميل Rust (صندوق CPI)

ينشر Raydium صناديق Anchor للبرامج التي لديها IDLs:

```toml
# Cargo.toml
[dependencies]
raydium_cp_swap = { git = "https://github.com/raydium-io/raydium-cp-swap", branch = "master", features = ["cpi"] }
raydium_amm_v3 = { git = "https://github.com/raydium-io/raydium-clmm",    branch = "master", features = ["cpi"] }
```

تكشف ميزة `cpi` عن هياكل حساب `cpi::accounts::<Ix>` و invokers `cpi::<ix>()` — مغلفات CPI جاهزة للاستخدام. انظر [`sdk-api/rust-cpi`](/ar/sdk-api/rust-cpi) لأنماط الاستخدام.

إذا كنت تفضل إنشاء ربطات جديدة:

```bash
# من IDL، باستخدام anchor-client
anchor idl parse \
  --file raydium_cpmm/raydium_cp_swap.json \
  --out src/generated/cpmm_bindings.rs
```

## إعادة إنشاء عميل Python

لا يوجد SDK Python رسمي لـ Raydium. تتضمن المولدات من جهات خارجية:

- **`anchorpy`** — نسخة Python من عميل Anchor الخاص بـ TypeScript. ينشئ منشئات طرق مكتوبة من IDLs.
- **`solders`** — بدائيات Solana منخفضة المستوى (المعاملات والمفاتيح والمفاتيح العامة) في ربطات Rust؛ تُستخدم تحت `anchorpy`.

```bash
pip install anchorpy solders solana
```

```python
from anchorpy import Program, Provider
from solana.rpc.async_api import AsyncClient
from pathlib import Path
import json

idl = json.loads(Path("cpmm.json").read_text())
provider = Provider(AsyncClient("https://api.mainnet-beta.solana.com"), wallet)
program  = Program(idl, CPMM_PROGRAM_ID, provider)

await program.rpc["swap_base_input"](amount_in, min_amount_out, ctx=Context(accounts={...}))
```

انظر [`sdk-api/python-integration`](/ar/sdk-api/python-integration) للحصول على شرح أكثر اكتمالاً.

## سياسة تغيير IDL

يتبع Raydium هذه القواعد لاستقرار IDL:

1. **لا تتغير مميزات التعليمات أبدًا.** إضافة تعليمات جديدة تمدد التعداد في النهاية؛ تبقى المميزات الموجودة مستقرة.
2. **تتطور تخطيطات هياكل الحساب بشكل إضافي فقط.** تذهب الحقول الجديدة في النهاية، مسبوقة بزيادة الحجم في المخطط على السلسلة. تحتفظ الحقول الموجودة بإزاحاتها.
3. **رموز تعداد الأخطاء قابلة للإضافة فقط.** رمز خطأ موجود يعني دائمًا نفس الشيء.
4. **التغييرات الجذرية تُشحن في برامج جديدة.** عندما تكون هناك حاجة لإعادة تصميم، يقوم الفريق بنشر معرف برنامج جديد (على سبيل المثال CPMM كبرنامج جديد بدلاً من ترقية AMM v4). تستمر المجموعات القديمة في التشغيل على البرنامج القديم؛ تذهب المجموعات الجديدة إلى الجديد.

تجعل هذه السياسة العملاء المُعاد إنشاؤهم متوافقين للخلف: عميل تم إنشاؤه مقابل IDL قديم بإصدارين سيظل قادرًا على فك تشفير الحالة الحالية بشكل صحيح (يرى البايتات الزائدة الزائدة كحشو).

## ماذا تفعل عندما يتغير IDL

1. **حدّث SDK.** `npm update @raydium-io/raydium-sdk-v2`.
2. **أعد إنشاء كود العميل الخاص بك** إذا كنت تستخدم Anchor codegen مباشرة.
3. **قارن تخطيط الحساب.** الحقول الزائدة في التخطيط الجديد هي الشيء الوحيد الذي لم يرَه الكود الخاص بك؛ تأكد مما إذا كنت بحاجة إليها.
4. **لا تفترض أن مميزات التعليمات القديمة غير صالحة.** وفقًا للقاعدة 1، فهي لا تزال تعمل.
5. **أعد تشغيل اختبارات التكامل** مقابل devnet قبل الانتقال إلى mainnet.

## استكشاف أخطاء IDL

### أخطاء "Invalid discriminator"

عادة ما يعني أن عميلاً تم بناؤه مقابل الإصدار N من IDL يحاول استدعاء تعليمة كانت موجودة فقط في نسخة ما قبل النشر من البرنامج. أعد سحب IDL من البرنامج المباشر:

```bash
anchor idl fetch <PROGRAM_ID>
```

### فشل فك تشفير الحساب

إذا رمى `program.account.<Name>.fetch(pubkey)` مع "Invalid account discriminator"، فقد تم إنشاء الحساب بواسطة نسخة برنامج سابقة ويرفضها Anchor مع مميز 8 بايت. الحل هو استخدام محلل التخطيط الخام من SDK (`PoolInfoLayout.decode(accountData)`) الذي لا يفرض مميزات Anchor.

### تعليمات مفقودة في العميل المُنشأ

يُنشئ Anchor's TS codegen طرقًا فقط للتعليمات التي يحتوي إدخال IDL الخاص بها على `name` يُحلل كمعرّف صالح. تفي جميع تعليمات Raydium بهذا، لكن إذا رأيت عدم تطابق، تحقق مما إذا كان ملف IDL من إصدار SDK الحالي.
