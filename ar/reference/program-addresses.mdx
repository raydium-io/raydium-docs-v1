### سلطة المسؤول المشتركة

جميع البرامج المستندة إلى Anchor (CLMM و CPMM و LaunchLab و Lock) تشترك في `Pubkey` مسؤول واحد مرمّز بشكل ثابت للتحكم في الوصول على مستوى التعليمات إلى مسارات المسؤول (مثل `CreateAmmConfig` أو `UpdatePoolStatus`):

| المجموعة | المسؤول |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

السلطات التشغيلية على مستوى الحساب (مثل `protocol_owner` و `fund_owner` على CPMM/CLMM `AmmConfig` أو محافظ الهجرة على LaunchLab `GlobalConfig`) يتم تخزينها على السلسلة وقد تختلف عن مسؤول البرنامج. اقرأها مباشرة من حساب الإعدادات ذي الصلة قبل إرسال معاملات عالية المخاطر.

### سلطات التجميد المقيدة لمُصدر CLMM

عندما يكون لأحد mint الخزان في مجموعة CLMM إحدى سلطات التجميد أدناه، المراكز الجديدة المفتوحة من خلال مسار V2 لها حساب token حساب موضع NFT مجمّد. الإدخال الأولي هو السلطة المستخدمة من قبل كشف أصول Superstate الخاص بـ CLMM. هذه **سلطات مُصدر الأصول الأساسية المستخدمة فقط كمفاتيح مطابقة**. PDA مجموعة CLMM وليس مفتاح المُصدر يصبح سلطة التجميد لـ mint موضع NFT.

### اتفاقيات الإعدادات المشتركة / PDA

عدة برامج Raydium تعرّض **حسابات الإعدادات** التي تكون مفاتيحها العامة مستقرة ومدرجة في API العام. فضّل البحث عبر API على الترميز الثابت:

```
# إعدادات رسوم CPMM (تُرجع مصفوفة من {id, index, tradeFeeRate, ...})
GET https://api-v3.raydium.io/main/cpmm-config

# إعدادات رسوم CLMM
GET https://api-v3.raydium.io/main/clmm-config
```

معاملات رسوم `AmmConfig` الافتراضية لـ CPMM بفهرس `0` (مجموعة 0.25% القياسية)، للمرجعية:

| الحقل | القيمة | المعنى |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 0.25% من حجم التداول |
| `protocol_fee_rate` | `120000` | 12% **من رسوم التداول** (وليس الحجم) موجّهة للبروتوكول |
| `fund_fee_rate` | `40000` | 4% **من رسوم التداول** موجّهة لمحفظة الصندوق |
| `creator_fee_rate` | `500` | 0.05% من حجم التداول لمنشئ المجموعة (اختياري) |

انظر [`products/cpmm/fees`](/ar/products/cpmm/fees) لكيفية تكوين التقسيمات، و [`reference/fee-comparison`](/ar/reference/fee-comparison) لمصفوفة المنتجات المتقاطعة.

### بذور PDA

البذور أدناه **رسمية** وتُستخدم من قبل SDK و CPIs على السلسلة. احسب PDAs دائماً؛ لا ترمّز العناوين المشتقة.

```ts
// CPMM — جميع البذور عبارة عن سلاسل ASCII ثابتة ما لم يُذكر خلاف ذلك.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` يتم **ترتيبهما حسب ترتيب بايت المفتاح العام** (token0 < token1) قبل التجزئة. الخطأ في هذا ينتج عنه PDA صحيح لمجموعة غير موجودة.

بذور CLMM المكافئة تتبع نفس الأسلوب؛ انظر [`products/clmm/accounts`](/ar/products/clmm/accounts).

## كيفية التحقق من عنوان على السلسلة

1. **Solana Explorer.** الصق العنوان في [explorer.solana.com](https://explorer.solana.com) وتأكد من أنه مُشار إليه كـ `Program` مع سلطة ترقية حالية. يجب أن يُظهر mainnet-beta عمليات نشر موقّعة من قبل سلطة ترقية Raydium.
2. **CLI.** استخدم `solana program show <PROGRAM_ID> -u mainnet-beta` لفحص فتحة النشر و BPF loader وسلطة الترقية وطول البيانات. سجّل هذه في دليل التشغيل الخاص بك.
3. **إرفاق IDL.** استعلم عن IDL على السلسلة باستخدام `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet`. حقل `address` في IDL يجب أن يطابق. نفس IDLs يتم نسخها في [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — قارن IDL على السلسلة مقابل المستودع قبل الثقة به.
4. **سلطات الإعدادات/المسؤول.** لحسابات إعدادات CPMM/CLMM، اقرأ حقل `owner`/`protocol_owner` وتأكد من أنه يطابق multisig Raydium الحالي المنشور في [`security/admin-and-multisig`](/ar/security/admin-and-multisig).

إذا اختلف أي من الفحوصات الأربعة أعلاه مع هذه الصفحة، اعتبر هذه الصفحة خاطئة وافتح مشكلة قبل كتابة كود جديد مقابل العناوين.

## تحديث هذه الصفحة

- التغييرات على معرّفات البرامج حساسة للسلامة. **لا** تشحن تغيير معرّف برنامج دون (أ) الربط بإعلان Raydium، (ب) إضافة إدخال في [`reference/changelog`](/ar/reference/changelog)، و (ج) تشغيل فحص الروابط على التوثيق للتأكد من عدم وجود صفحة تشير إلى القيمة القديمة.
- الإيقافات تبقى في الجدول مع ملاحظة الحالة بدلاً من حذفها — المجموعات الموجودة لا تزال تُحل عبر البرنامج القديم.
