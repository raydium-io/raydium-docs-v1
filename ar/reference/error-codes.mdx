## كيفية عمل رموز أخطاء Anchor

يعين Anchor لكل متغير من متغيرات enum `ErrorCode` في البرنامج رمزًا رقميًا يبدأ من `6000`. تعرض المعاملة الفاشلة:

- **رمز الخطأ الرقمي** (مثل `0x1771` = 6001) في سجلات المعاملة.
- **اسم الخطأ** (مثل `InvalidOwner`) من IDL.
- **سلسلة `#[msg(...)]`** التي أصدرها Anchor في `log_messages`.

يجب على المدمجين المطابقة على **الرمز الرقمي**، وليس سلسلة الرسالة (يمكن إعادة صياغة السلسلة دون زيادة الإصدار).

```ts
// مثال: كشف خطأ الانزلاق في CPMM وعرض رسالة واجهة نظيفة.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

يتم توثيق هذه البرامج في فصولها الخاصة (انظر [`products/amm-v4/instructions`](/ar/products/amm-v4/instructions)، [`products/farm-staking/instructions`](/ar/products/farm-staking/instructions)، [`products/launchlab/instructions`](/ar/products/launchlab/instructions)). لأن هذه البرامج تستخدم مزيجًا من سطوح أخطاء Anchor والـ Solana العادية، تعيش جداول الأخطاء الخاصة بها بجانب مرجع التعليمات بدلاً من هنا. الرموز أدناه محجوزة من قبل هذه الفصول:

| البرنامج | نطاق الرمز (Anchor فقط) | المرجع |
|---------|--------------------------|-----------|
| AMM v4 | رموز u32 مخصصة، وليس نمط Anchor | [`products/amm-v4/instructions`](/ar/products/amm-v4/instructions) |
| Farm v3 / v5 | رموز u32 مخصصة | [`products/farm-staking/instructions`](/ar/products/farm-staking/instructions) |
| Farm v6 | 6000+ (Anchor) | [`products/farm-staking/instructions`](/ar/products/farm-staking/instructions) |
| LaunchLab | 6000+ (Anchor) | [`products/launchlab/instructions`](/ar/products/launchlab/instructions) |

تحافظ إصدارات LaunchLab الأخيرة على الرموز `6000`–`6021` دون تغيير. أزال إصدار 2026-08-17 أخطاء الوصول العام للمنصة السابقة وعيّن `6022` لخطأ التحقق من حساب السماح؛ يضيف إصدار 2026-08-24 `6023`؛ يضيف إصدار 2026-08-31 `6024`–`6030`:

| الرمز | الاسم | المعنى |
|---|---|---|
| 6018 | `NotEnoughRemainingAccounts` | حساب متبقي مطلوب مفقود. يتضمن ذلك `PlatformAllowConfig` مطلوب، `PlatformCurveRule` مطلوب، ومجموعة حسابات هجرة CPMM الموسعة. |
| 6020 | `CurveParamIsNotExist` | متقاعد. تم الاحتفاظ به كعنصر نائب حتى لا تتحول الرموز بعده؛ أزال إصدار 2026-08-31 آخر مستدعي له. |
| 6022 | `InvalidPlatformAllowConfig` | حساب السماح المُمرر لا يرمز إلى زوج المنصة والتكوين العام المتوقع. |
| 6023 | `CalculateOverflow` | لم يتمكن حساب رسوم نقل Token-2022 أو حساب رسوم النقل العكسي من التمثيل. يمكن الوصول إليه على مسارات التجارة الدقيقة عندما لا يمكن عكس رسوم mint الاقتباس (على سبيل المثال mint برسوم 100%). |
| 6024 | `InvalidPlatformCurveRule` | حساب القاعدة المُمرر ليس PDA لزوج المنصة والتكوين الذي يتم الإطلاق تحته. |
| 6025 | `CurveParamNotMatchPlatformRule` | معاملات الإطلاق لا تلبي أي مجموعة فحص من قاعدة المنصة. الخطأ الوحيد الذي يمكن لمنشئ أن يصطدم به فعلاً — عرضه كـ "شكل الإطلاق هذا غير مسموح به على هذه المنصة". |
| 6026 | `CurveRuleGroupNotExist` | تم استدعاء `RemovePlatformCurveRule` مع `group_id` لا تحتفظ به القاعدة. |
| 6027 | `CurveRuleGroupsExceeded` | لا يمكن لقاعدة أن تحتفظ بأكثر من 10 مجموعات فحص. |
| 6028 | `InvalidCurveRuleConstraint` | قيد له حقل أو عامل غير معروف، مجموعة بها أكثر من 25 قيد، أو نفس زوج `(field, op)` يظهر مرتين في مجموعة واحدة. |
| 6029 | `InvalidCurveRuleAuthority` | الموقّع ليس `PlatformConfig.curve_rule_manager` ولا مسؤول المنصة. |
| 6030 | `CurveRuleFieldNotSupportedByCurve` | قيد يقرأ `total_base_sell` على تكوين منحنى مشتق منه — المنحنيات ذات السعر الثابت والسعر الخطي. يتم رفعه عند كتابة القاعدة، وليس عند تشغيل الإطلاق. |

تم حذف المتغيرات القديمة `PlatformGlobalAccessDenied` (`6022`) و `InvalidPlatformGlobalAccess` (`6023`). لا تفك تشفير `6022` باستخدام IDL السابق، ولاحظ أن `6023` — الذي تم إخلاؤه من قبل إصدار 2026-08-17 — يتم إعادة استخدامه من قبل إصدار 2026-08-24 لخطأ غير ذي صلة، لذا يجب عدم فك تشفيره باستخدام IDL من أي إصدار سابق.

يتم الاحتفاظ بـ `6020` عن قصد. يرقّم Anchor المتغيرات حسب الموضع، لذا حذفه سيحول كل رمز بعده وسيكسر كل عميل يفك تشفير `6021`–`6030`.

## ربط أخطاء SDK بأخطاء البرنامج

يلف SDK TypeScript الرسمي أخطاء على السلسلة إلى `SendTransactionError` وللبرامج Anchor، `AnchorError`:

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — افحص err.logs للسطر "custom program error: 0x...".
  }
}
```

إذا لم تكن تستخدم عميل Anchor، حلّل سجلات المعاملة:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

النمط `Error Number: (\d+)` مستقر عبر إصدارات Anchor وآمن للمطابقة.

عند ترقية برنامج وإضافة خطأ جديد، أعد الاستخراج من المصدر:

```bash
# استنسخ و grep enum الخطأ بالترتيب.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# استبدل 6000+++ برموز متزايدة بشكل رتيب 6000,6001,... أضف صفوفًا جديدة إلى الجدول أعلاه.
```
