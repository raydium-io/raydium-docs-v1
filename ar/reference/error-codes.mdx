## كيفية عمل رموز أخطاء Anchor

يعين Anchor لكل متغير في تعريف `ErrorCode` للبرنامج رمز رقمي يبدأ من `6000`. تعرض المعاملة الفاشلة:

- **رمز الخطأ الرقمي** (مثل `0x1771` = 6001) في سجلات المعاملة.
- **اسم الخطأ** (مثل `InvalidOwner`) من IDL.
- **سلسلة `#[msg(...)]`** التي أصدرها Anchor في `log_messages`.

يجب على المدمجين المطابقة على **الرمز الرقمي**، وليس سلسلة الرسالة (يمكن إعادة صياغة السلسلة دون زيادة الإصدار).

```ts
// مثال: كشف خطأ الانزلاق في CPMM وعرض رسالة واجهة نظيفة.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

| 6052 | `LamportsCalculateError` | Lamports calculate error | كنس `CollectExcessLamports` لخزينة SOL ملفوفة، والرحلة ذهاباً وإياباً `SyncNative` → `UnwrapLamports` لم تترك رصيد الرمز الملفوف حيث بدأ. تمت الإضافة بواسطة ترقية 2026-09-30؛ الأكواد `6000`–`6051` لم تتغيّر. | غير متاح — مسار مخصص للمسؤول فقط. |

> **ملاحظة حول إعادة الترقيم.** تمت إعادة ترقيم enum `ErrorCode` الخاص بـ CLMM في هذا الإصدار: تمت إزالة/إصلاح خمسة متغيّرات قديمة (`LOK`، `ZeroMintAmount`، `InvalidLiquidity`، `TransactionTooOld`، `InvalidRewardDesiredAmount`) وعدة أخطاء إملائية (`Liquitity`، `enought`، `emissiones`)، وتمت إضافة أحد عشر متغيّراً جديداً (`6040`–`6050`) بواسطة إصدار الأوامر المحدودة؛ جاء `6051` (`InvalidTickArrayBitmapExtensionAccount`) من تغيير منفصل لاحق. هذا جعل 52 متغيّراً، `6000`–`6051`، وهو العدد الذي يُبلّغ عنه IDL على السلسلة الخاص بالبرنامج المنتشر حالياً. تضيف [ترقية 2026-09-30](/ar/reference/changelog/2026-09-30-clmm-anchor-1-and-excess-lamports) `6052` دون تحويل أي شيء، لإجمالي 53. لأن Anchor يرقّم الأخطاء حسب ترتيب المصدر، فإن كل كود عند أو بعد `6000` قد تحوّل بالنسبة إلى الإصدارات السابقة. يحتاج العملاء الذين رمّزوا الأكواد الرقمية مقابل نسخة سابقة إلى إعادة تعيين.

مصدر إعادة الإنشاء: [github.com/raydium-io/raydium-clmm — error.rs](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/error.rs).

### AMM v4: `AmmError` ليس مرقماً بأسلوب Anchor

يسبق AMM v4 Anchor. `AmmError` هو enum `thiserror` عادي مع `FromPrimitive`، محول عبر `ProgramError::Custom(e as u32)`، لذا تبدأ أكواده من **`0`**، وليس `6000` — وكما هو الحال مع Anchor، يتم تعيينها حسب ترتيب المصدر. يضيف ترقية 2026-09 متغيراً واحداً:

| الكود | المتغير | سلسلة `#[error]` | السبب |
|---|---|---|---|
| 60 | `LamportsCalculateError` | خطأ حساب Lamports. | كنس `WithdrawExcessLamports` حساب SOL المغلف والرحلة ذهاباً وإياباً `SyncNative` → `UnwrapLamports` لم تترك رصيد الرمز المغلف حيث بدأ بالضبط. مسار مخصص للمسؤول فقط. |

الأكواد `0`–`59` لم تتغير، لذا لا شيء يتحول. في سجلات المعاملات يظهر هذا كـ `custom program error: 0x3c`. مصدر إعادة الإنشاء: [github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs).

## ربط أخطاء SDK بأخطاء البرنامج

يلف SDK TypeScript الرسمي الأخطاء على السلسلة إلى `SendTransactionError` وللبرامج Anchor، `AnchorError`:

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

إذا لم تكن تستخدم Anchor على جانب العميل، حلّل سجلات المعاملات:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

النمط `Error Number: (\d+)` مستقر عبر إصدارات Anchor وآمن للمطابقة.
