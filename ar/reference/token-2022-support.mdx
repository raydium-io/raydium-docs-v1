لا تقبل Raydium عملات Token-2022 عشوائية. يعمل كل من CPMM و CLMM في **وضع قائمة سماح صارم**: فقط مجموعة صغيرة من الامتدادات تمر بشكل افتراضي؛ كل شيء آخر يُرفض عند إنشاء Pool. يتم قبول حفنة من العملات الموثوقة بواسطة عناوين مشفرة بشكل ثابت؛ يدعم CLMM بالإضافة إلى ذلك سجل إداري لكل عملة وكشف رموز Superstate في وقت التشغيل. هذه الصفحة هي المرجع الشامل لما يتم فرضه وأين، مع استشهادات بالملف والسطر في مصدر البرنامج.

## دعم مستوى البرنامج

| البرنامج | عملات Token-2022 الأساسية/المقتبسة؟ | الوضع |
|---|---|---|
| **CPMM** | نعم — مقيد | قائمة سماح امتدادات صارمة + قائمة بيضاء ثابتة من 4 عملات. |
| **CLMM** | نعم — مقيد | قائمة سماح امتدادات صارمة + قائمة بيضاء ثابتة من 6 عملات + سجل إداري لكل عملة + كشف Superstate. |
| **AMM v4** | لا | البرنامج سابق لـ Token-2022؛ يجب أن تكون كلا العملتين من SPL Token الكلاسيكي. |
| **Stable AMM** | لا | نفس القيود مثل AMM v4. |
| **Farm v6** | نعم، جزئي | يمكن أن تكون عملة المكافأة Token-2022 (تخضع لنفس قائمة السماح عند التفاف مزرعة حول LP من CPMM/CLMM)؛ ترث عملات LP المراهنة من Pool المغلفة. |
| **LaunchLab** | نعم — إدارة البرنامج الأساسي، المقتبس بدون بوابة | يمكن أن تكون العملة الأساسية Token-2022، لكن فقط عبر تعليمات `initialize_with_token_2022` المخصصة؛ ينشئ البرنامج نفسه العملة باستخدام `MetadataPointer` (دائماً) و`TransferFeeConfig` اختياري (معدل ≤ 5%). لا يمكن استخدام عملات Token-2022 الموجودة مسبقاً مع امتدادات عشوائية كأساس. قد تكون عملة **المقتبس** أي عملة Token-2022 يربطها مسؤول بـ `GlobalConfig`، بدون فحص امتداد — انظر [أدناه](#launchlab-quote-mints). |
| **Burn & Earn** | يعكس برنامج Pool | يرث بوابة CPMM / CLMM. |

فحوصات قائمة السماح موجودة في:

- **CPMM**: `is_supported_mint` في [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap)، يُستدعى من `Initialize`.
- **CLMM**: `is_supported_mint` في [`raydium-clmm/programs/amm/src/util/token.rs:280`](https://github.com/raydium-io/raydium-clmm)، يُستدعى من `CreatePool`.
- **LaunchLab**: `initialize_with_token_2022` في `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs` (المصدر غير متاح للعموم).

**لا يوجد** فحص عملة في وقت المبادلة على CPMM أو CLMM — تعمل البوابة فقط عند إنشاء Pool. بمجرد وجود Pool، تثق المبادلات بأن العملات لم تتغير، وهو صحيح للأجزاء غير القابلة للتغيير من حالة عملة Token-2022.

## تجميد NFT موضع CLMM للمُصدرين المقيدين

تبقى حسابات NFT الموضع غير مجمدة بشكل افتراضي. يجمد CLMM واحداً فقط عندما يستخدم الموضع مسار V2 مفتوح **و** يطابق `freeze_authority` الحالي لعملة vault واحدة على الأقل قائمة المُصدرين المقيدين المشفرة بشكل ثابت. تحتوي القائمة الأولية على نفس السلطة المستخدمة بواسطة مسار كشف Superstate أدناه. تعيين Pool PDA كسلطة تجميد عملة NFT الموضع ليس بحد ذاته تجميداً. هذه قاعدة حراسة موضع، وليست قائمة سماح إنشاء Pool أخرى:

- يمكن أن يكون Pool موجوداً بالفعل ويبقى قابلاً للمبادلة.
- تستخدم عملة NFT الموضع Pool PDA كسلطة تجميد خاصة بها؛ المُصدر الأساسي لا يتحكم في NFT الموضع.
- `OpenPositionV2` يغطي NFTs موضع SPL Token الكلاسيكي على أصول Pool من Token-2022. `OpenPositionWithToken22Nft` يغطي NFTs موضع Token-2022.
- `OpenPosition` V1 لا يفتش عملات vault ولا يمكنه خدمة أصول Token-2022 المقيدة المستهدفة بالقائمة المرسلة.
- المواضع الموجودة لم تتغير.

تبقى المواضع المجمدة قابلة للإدارة من قبل مالكها لكن لا يمكن نقلها. `ClosePosition` يذيب ويحرق بشكل ذري عندما يمرر العميل Pool كأول حساب متبقي. انظر [`products/clmm/ticks-and-positions`](/ar/products/clmm/ticks-and-positions#restricted-issuer-positions).

## عملات المقتبس في LaunchLab

يتم تقييد عملتي LaunchLab بطرق مختلفة جداً، والعدم التماثل سهل الفقدان.

- **العملة الأساسية** — ينشئها LaunchLab. عملة أساسية من Token-2022 قابلة للوصول فقط عبر `initialize_with_token_2022`، وسيرفق البرنامج فقط `MetadataPointer` و`TransferFeeConfig` (اختياري). أي شيء آخر يعيد `NoSupportExtension`. لا يمكن توفير عملة Token-2022 موجودة مسبقاً كأساس على الإطلاق.
- **عملة المقتبس** — لا ينشئها LaunchLab ولا يفحصها. `CreateConfig` يقبل حساب العملة كما هو، لذا **لا يوجد ما يعادل `is_supported_mint` على جانب المقتبس**. البوابة الوحيدة هي العملات التي يختار مسؤول ربطها بـ `GlobalConfig`.

هذا يجعل ربط عملة مقتبس من Token-2022 إجراءً عالي الثقة، بنفس المنطق الذي يقف وراء قوائم البيضاء الثابتة CPMM و CLMM أدناه: عملة مقتبس `TransferHook` ستشغل hook على كل عملية شراء وبيع ومطالبة رسوم في كل Pool مقتبس فيها، وعملة مقتبس `PermanentDelegate` ستسمح للمفوض بمسح vaults المقتبس لتلك Pools. لا يتم حظر أي منهما من قبل البرنامج.

ما يتعامل معه LaunchLab بشكل صحيح بمجرد ربط عملة مقتبس:

- vault المقتبس، كلا vaults الرسوم، وحساب رمز مستقبل رسوم المشاركة يتم إنشاؤها على برنامج عملة المقتبس الخاص به.
- `TransferFeeConfig` على جانب المقتبس يتم تسعيره في جميع تعليمات التجارة الأربعة، وتم فحص حد الانزلاق مقابل المبلغ الصافي للدافع بدلاً من حركة vault الإجمالية. انظر [`products/launchlab/instructions`](/ar/products/launchlab/instructions#quote-side-transfer-fees).
- `PoolState.token_program_flag` يسجل برامج كلا العملتين — bit0 للعملة الأساسية، bit1 للعملة المقتبس. فك تشفير حسب البت؛ البايت ليس قيمة منطقية. انظر [`products/launchlab/accounts`](/ar/products/launchlab/accounts#poolstate).

تعليمات `Initialize` المهجورة لا تزال تأخذ برنامج مقتبس وراثي فقط، لذا يمكن الوصول إلى config مع عملة مقتبس من Token-2022 فقط عبر `InitializeV2` و `InitializeWithToken2022`.

## قائمة سماح امتدادات CPMM و CLMM

بعد اختصارات قائمة البيضاء الثابتة (المغطاة أدناه)، يكرر البرنامج امتدادات العملة ويرفض العملة إذا كانت تحمل **أي** امتداد بخلاف هذه الخمسة:

| الامتداد | السبب في السماح به |
|---|---|
| `TransferFeeConfig` | تطرح رياضيات Pool الرسوم الداخلة؛ يتعامل برنامج Token-2022 مع الرسوم الخارجة. انظر [`algorithms/token-2022-transfer-fees`](/ar/algorithms/token-2022-transfer-fees). |
| `MetadataPointer` | زخرفي — يشير إلى البيانات الوصفية على السلسلة. |
| `TokenMetadata` | زخرفي — البيانات الوصفية المضمنة. |
| `InterestBearingConfig` | يرى Pool المبلغ الأساسي؛ مضاعف واجهة المستخدم زخرفي فقط والرصيد الأساسي محفوظ. |
| `ScaledUiAmount` | نفس الشكل مثل الفائدة — عامل المقياس ينطبق على عرض واجهة المستخدم فقط. |

أي شيء ليس في هذه القائمة — `TransferHook`، `NonTransferable`، `ConfidentialTransferMint`، `PermanentDelegate`، `MintCloseAuthority`، `DefaultAccountState`، `GroupPointer`، `GroupMemberPointer`، `MemberPointer`، `Pausable`، إلخ. — يسبب `is_supported_mint` للعودة `false` وإنشاء Pool للعودة.

الأسطر ذات الصلة (CPMM، نفس الشكل في CLMM):

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## طرق التجاوز

عملة Token-2022 التي لا تناسب قائمة السماح يمكن أن تُقبل عبر أحد التجاوزات الثلاثة الصريحة. يتم محاولتها بالترتيب، قبل تشغيل تكرار الامتداد.

### 1. قائمة العملات الثابتة

مصفوفة ثابتة `MINT_WHITELIST` من سلاسل base58 مشفرة بشكل ثابت في كل برنامج. إذا طابق عنوان العملة، تعيد الدالة `true` فوراً ولا يتم إجراء فحص امتداد.

| البرنامج | العملات المدرجة في القائمة البيضاء |
|---|---|
| CPMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`, `Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`, `FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`, `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM | الأربعة نفسها، بالإضافة إلى `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`, `AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

هذه العناوين مدمجة في البرنامج؛ تحديث القائمة يتطلب ترقية برنامج عبر multisig الترقية 3/4.

### 2. سجل لكل عملة — CLMM فقط

يستشير CLMM بالإضافة إلى ذلك PDA `SupportMintAssociated` بـ seed `[b"support_mint", mint]`. إذا كان هذا PDA موجوداً للعملة، يتم قبولها بغض النظر عن مجموعة امتدادها.

يتم إنشاء PDA بواسطة `CreateSupportMintAssociated` ([`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)). التعليمات مقيدة بموقعين:

- `crate::admin::ID` — سلطة مسؤول Raydium القياسية.
- `crate::create_support_mint_associated_owner::ID` — سلطة مخصصة لهذا الغرض: `RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY` (mainnet), `rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5` (devnet).

التأثير: يمكن لفريق CLMM اختيار عملة Token-2022 محددة لإنشاء Pool بدون ترقية برنامج. CPMM لا يملك ما يعادل — قائمة السماح الخاصة به مشفرة بشكل صارم في المصدر.

### 3. كشف Superstate — CLMM فقط

لدى CLMM مسار ثالث محدد لأصول Superstate المرمزة، التي تستخدم امتداد `ScaledUiConfig` الذي لا يمكن لإصدار `spl-token-2022` المرتبط ببرنامج CLMM فك تشفيره. بدلاً من ترقية الاعتماد، يكتشف CLMM رموز Superstate من خلال شكل سلطتها:

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

تمر عملة عبر هذا الفرع إذا **كانت جميع الأربعة** صحيحة:

- برنامجها المالك هو برنامج Token-2022.
- `freeze_authority` الخاص بها يساوي `superstate_allowlist::ID`. انظر [`reference/program-addresses`](/ar/reference/program-addresses#clmm-restricted-issuer-freeze-authorities) للقيم mainnet-beta و devnet.
- امتداد `DefaultAccountState` الخاص بها مضبوط على `Frozen`.
- المفوض الدائم الخاص بها هو أيضاً `superstate_allowlist::ID`.

هذا اكتشاف، وليس سجل — أي عملة مستقبلية تصدرها Superstate بنفس شكل السلطة ستُقبل تلقائياً.

## ما لا تتنازل عنه التجاوزات

تتخطى التجاوزات قائمة سماح الامتدادات، لكن البرنامج لا يزال يفرض:

- العملة مملوكة إما بـ `Token` أو `Token-2022`. يتم رفض برنامج رمز مخصص في المنبع.
- يتم إنشاء vaults Pool مع امتدادات ATA الصحيحة لـ Pools من Token-2022 (`ImmutableOwner`، إلخ).
- جميع التحويلات تمر عبر `transfer_checked` — تهبط العملات التي تحمل رسوم المبلغ الصحيح في vault.

عملة مدرجة في القائمة البيضاء أو مسجلة في PDA التي تضيف، على سبيل المثال، `TransferHook` لاحقاً لا تكتسب فحص وقت المبادلة؛ سيعمل hook ببساطة على كل تحويل ويمكن أن يوقف المبادلات. لذلك فإن إدراج العملة في القائمة البيضاء إجراء عالي الثقة.

## دلالات "محظور"

عندما تعيد `is_supported_mint` `false`، يعود إنشاء Pool مع `ErrorCode::NotSupportMint` (CPMM) / `ErrorCode::NotSupportMint` (CLMM). انظر [`reference/error-codes`](/ar/reference/error-codes) للأكواد الرقمية.

لا يمكن للـ Pools الموجودة أن تفشل هذا الفحص بأثر رجعي — تعمل البوابة فقط عند الإنشاء. امتدادات العملة غير قابلة للتغيير للفئات التي ترفضها Raydium (transfer hook، non-transferable، confidential transfer لا يمكن إضافتها بعد الإنشاء)، لذا فإن الفحص الثابت كافي.

## لماذا يتم استبعاد كل امتداد مستبعد

- **TransferHook** — يستدعي برنامج مخصص على كل تحويل، مع استهلاك CU عشوائي، شروط فشل عشوائية، والقدرة على إعادة الدخول إلى البرنامج الاستدعاء. لا يوجد sandbox آمن. تحتفظ بعض DEXes بقوائم سماح hook؛ Raydium لا تفعل.
- **NonTransferable** — `Transfer` يفشل دائماً. لا يمكن لـ Pool أن تأخذ الحراسة.
- **ConfidentialTransfer** — مبالغ التحويل مشفرة؛ لا يمكن للمنحنى تسعير المبادلة.
- **PermanentDelegate** — يمكن لحامل المفوض مسح أي حساب رمز، بما في ذلك vault Pool. مسموح فقط عبر قائمة البيضاء الثابتة للمُصدرين الموثوقين (مثل العملات المستقرة المنظمة).
- **MintCloseAuthority** — يمكن إغلاق العملة؛ تصبح Pools الموجودة غير قابلة للاستخدام. محظور بشكل افتراضي.
- **DefaultAccountState (Frozen)** — ستهبط ATAs Pool في حالة `Frozen` وتتطلب إذابة لكل حساب. مسموح فقط عبر كشف Superstate، الذي يفترض أن المُصدر يذيب الحسابات المؤسسية عند التسجيل.
- **Group/Member pointers** — ليست ضارة بنشاط، لكن لم تتم مراجعتها. محظور بشكل افتراضي للحفاظ على السطح ضيقاً.

## محاسبة رسوم التحويل

بالنسبة للعملات التي تحمل `TransferFeeConfig`، تنقل كل مبادلة وإيداع وسحب أقل من المبلغ الاسمي. تسطح SDK كلا نصفي الحساب:

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

تعرض واجهة مستخدم صحيحة:

- `amountIn + token2022FeeIn` كـ "أنت ترسل"
- `amountOut - token2022FeeOut` كـ "أنت تستقبل"
- `feeAmount` كرسوم Pool (LP + بروتوكول)، وهي منفصلة عن رسوم تحويل Token-2022

واجهة مستخدم ساذجة تعرض فقط `amountIn → amountOut` تقلل من التكاليف.

### حد `maximumFee`

يتم تحديد رسوم تحويل Token-2022 لكل تحويل. بالنسبة لعملة بنسبة 1% مع حد 10,000 رمز، يدفع تحويل 100,000,000 رمز فقط 10,000 في الرسوم. تطبق SDK `computeSwapAmount` الحد؛ يجب على المتصلين المباشرين للبرنامج تكراره.

### انتقال الحقبة

يمكن لسلطة العملة جدولة تغيير معدل الرسوم الذي يتم تفعيله في الحقبة التالية. أثناء نافذة الانتقال، يعيش تكويناً (`older`, `newer`) على العملة في نفس الوقت و`TransferChecked` يختار حسب الحقبة الحالية. يمرر كل من CPMM `SwapV2` و CLMM `SwapV2` حساب العملة الكامل في `accounts`، لذا يقرأ البرنامج التكوين الصحيح بدون بحث إضافي.

إذا اقتبست أكثر من حقبة واحدة مقدماً عبر Trade API أو SDK، قد تختلف الرسوم المنفذة عن الرسوم المقتبسة — محدودة بـ `maximum_fee_basis_points` للتكوين الأقدم.

## الفائدة والمبلغ المقياس

يحتفظ Pool بالمبلغ الأساسي؛ "مبلغ واجهة المستخدم" هو المبلغ الأساسي مضروباً بعامل مقياس يعتمد على الوقت أو يحدده المسؤول. تعمل رياضيات المبادلة على الأساسي:

```
principal_in = ui_amount_in / ui_multiplier(now)
```

تحول SDK تلقائياً. يجب على قارئي RPC المباشرين معاملة `pool.token0Vault.amount` كأساسي.

## تعريف "Pool من Token-2022"

يكون Pool من Token-2022 إذا **كانت أي من العملتين** لديها `programId == TokenzQdB...`. تسطح API هذا:

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

استخدم `programId` للتوزيع، و`hasTransferFee` لعرض تحذير واجهة المستخدم.

## مساعدات SDK

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## أخطاء التكامل الشائعة

- **التحقق المسبق من معرف البرنامج فقط.** يمكن أن تكون عملة Token-2022 *و* غير مدعومة. امشِ قائمة الامتدادات مقابل قائمة السماح (وقائمة البيضاء الثابتة) قبل السماح بإنشاء Pool.
- **الثقة في اقتباس SDK عندما لا تُقبل العملة على الإطلاق.** لا ترفض API الاقتباس — إنشاء Pool هو ما يعود. أكد دلالات `is_supported_mint` خارج السلسلة قبل عرض إنشاء Pool في واجهة المستخدم الخاصة بك.
- **الاقتباس بدون قص رسوم التحويل.** عملة برسوم تحويل 1% على كلا جانبي Pool CPMM بنسبة 0.25% لديها رسوم فعالة حول 2.25%، وليس 0.25%. استخدم اقتباس SDK أو اقتباس Trade API — لا تحسب الرسوم يدوياً من مستوى رسوم Pool وحده.
- **استدعاء تعليمات `Swap` الوراثية على Pool من Token-2022.** `Swap` سابق لـ Token-2022. استخدم `SwapV2` كلما كانت أي من العملتين Token-2022.
- **إدراج عملات Token-2022 الجديدة تلقائياً.** يجب على المحافظ والمجمعات التحقق من `TransferHook` و`NonTransferable` قبل عرض عملة للمستخدمين؛ كلاهما معادي لـ Raydium.

## العمل المستقبلي

عناصر خارطة الطريق للنظام البيئي Solana والبروتوكول التي ستغير هذه المصفوفة:

- برامج transfer-hook مدرجة في قائمة السماح على مستوى Solana (اتفاقية النظام البيئي تتطور).
- AMMs متوافقة مع confidential-transfer (مرحلة البحث).
- سجل CPMM لكل عملة أوسع (التكافؤ مع CLMM).
- ترقية الاعتماد بحيث يعمل فك تشفير `ScaledUiConfig` في CLMM بدون اكتشاف Superstate الاستدلالي.

سيتم تحديث هذه الصفحة عند هبوط أي منها.
