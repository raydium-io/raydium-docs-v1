لا تقبل Raydium نعناعات Token-2022 عشوائية. يعمل كل من CPMM و CLMM في **وضع قائمة سماح صارم**: فقط مجموعة صغيرة من الامتدادات تمر بشكل افتراضي؛ كل شيء آخر يُرفض عند إنشاء المجمع. يقبل كل برنامج نعناعًا فرديًا من خلال آلية واحدة — سجل نعناع مُدار من قبل المسؤول لكل نعناع. كلا البرنامجين حملا أيضًا التفافات مشفرة في نقاط مختلفة؛ تم حذف كل تلك الآن. هذه الصفحة هي المرجع الموحد لما يُفرض وأين، مع استشهادات في مصدر البرنامج.

## دعم على مستوى البرنامج

| البرنامج | نعناعات Token-2022 الأساسية/المقتبسة؟ | الوضع |
|---|---|---|
| **CPMM** | نعم — مقيد | قائمة سماح امتدادات صارمة + سجل نعناع مُدار من قبل المسؤول. تم حذف قائمة البيض الثابتة المكونة من 4 نعناعات في ترقية 2026-09. |
| **CLMM** | نعم — مقيد | قائمة سماح امتدادات صارمة + سجل نعناع مُدار من قبل المسؤول. تم حذف قائمة البيض الثابتة المكونة من 6 نعناعات واكتشاف Superstate في يوليو 2026. |
| **AMM v4** | لا | البرنامج يسبق Token-2022؛ يجب أن يكون كلا النعناعين من SPL Token الكلاسيكي. |
| **Stable AMM** | لا | نفس القيود مثل AMM v4. |
| **Farm v6** | نعم، جزئي | يمكن أن يكون نعناع المكافأة Token-2022 (يخضع لنفس قائمة السماح عند التفاف مزرعة حول CPMM/CLMM LP)؛ نعناعات LP للحصة من قبل المستخدم ترث من المجمع المُلتف. |
| **LaunchLab** | نعم — البرنامج الأساسي مُدار، المقتبس غير مقيد | يمكن أن يكون النعناع الأساسي Token-2022، لكن فقط عبر تعليمات `initialize_with_token_2022` المخصصة؛ ينشئ البرنامج النعناع بـ `MetadataPointer` (دائمًا) و`TransferFeeConfig` اختياري (معدل ≤ 5%). لا يمكن استخدام نعناعات Token-2022 الموجودة مسبقًا مع امتدادات عشوائية كأساس. قد يكون نعناع **المقتبس** أي نعناع Token-2022 يربطه مسؤول بـ `GlobalConfig`، بدون فحص امتداد — انظر [أدناه](#launchlab-quote-mints). |
| **Burn & Earn** | يعكس برنامج المجمع | يرث بوابات CPMM / CLMM. |

فحوصات قائمة السماح تعيش في:

- **CPMM**: `is_supported_mint` في [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs)، يُستدعى من `Initialize` و `InitializeWithPermission`.
- **CLMM**: `is_supported_mint` في [`raydium-clmm/programs/amm/src/util/token.rs`](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/util/token.rs)، يُستدعى من `CreatePool`.
- **LaunchLab**: `initialize_with_token_2022` في `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs` (المصدر غير متاح للعموم).

لا يوجد فحص نعناع في وقت المبادلة على CPMM أو CLMM — البوابة تُطلق فقط عند إنشاء المجمع. بمجرد وجود مجمع، تثق المبادلات فقط بأن النعناعات لم تتغير، وهو صحيح للأجزاء غير القابلة للتغيير من حالة نعناع Token-2022.

## تجميد NFT موضع CLMM للمُصدرين المقيدين

تبقى حسابات NFT الموضع غير مجمدة بشكل افتراضي. يجمد CLMM واحدًا فقط عندما يستخدم الموضع مسار V2 مفتوح **و** يظهر `freeze_authority` الحالي لنعناع الخزان الواحد على الأقل في قائمة `frozen_position_nft_authorities::IDS` المشفرة. هذه القائمة هي ما حل محل كشف رمز Superstate السابق في CLMM، وتحمل نفس سلطة المُصدر التي طابقتها الكشف الاستدلالي القديم. تعيين PDA المجمع كسلطة تجميد نعناع NFT الموضع ليس بحد ذاته تجميدًا. هذه قاعدة حراسة موضع، وليست قائمة سماح إنشاء مجمع:

- يمكن أن يكون المجمع موجودًا بالفعل ويبقى قابلاً للمبادلة.
- يستخدم نعناع NFT الموضع PDA مجمع CLMM كسلطة تجميد خاصة به؛ المُصدر الأساسي لا يتحكم في NFT الموضع.
- `OpenPositionV2` يغطي NFTs موضع SPL الكلاسيكي على أصول مجمع Token-2022. `OpenPositionWithToken22Nft` يغطي NFTs موضع Token-2022.
- `OpenPosition` V1 لا يفتش نعناعات الخزان ولا يمكنه خدمة أصول Token-2022 المقيدة المستهدفة بالقائمة المُرسلة.
- المواضع الموجودة لم تتغير.

تبقى المواضع المجمدة قابلة للإدارة من قبل مالكها لكن لا يمكن نقلها. `ClosePosition` يذيب ويحرق بشكل ذري عندما يمرر العميل المجمع كأول حساب متبقٍ. انظر [`products/clmm/ticks-and-positions`](/ar/products/clmm/ticks-and-positions#restricted-issuer-positions).

## نعناعات المقتبس في LaunchLab

يتم تقييد نعناعات LaunchLab الاثنين بطرق مختلفة جدًا، والعدم التماثل سهل الفقدان.

- **النعناع الأساسي** — ينشئه LaunchLab. يمكن الوصول إلى نعناع أساسي Token-2022 فقط من خلال `initialize_with_token_2022`، وسيرفق البرنامج فقط `MetadataPointer` و (اختياري) `TransferFeeConfig`. أي شيء آخر يُرجع `NoSupportExtension`. لا يمكن توفير نعناع Token-2022 موجود مسبقًا كأساس على الإطلاق. عند إرفاق `TransferFeeConfig`، يكون `transfer_fee_config_authority` للنعناع هو PDA سلطة الإطلاق حتى التخرج، بينما يكون `withdraw_withheld_authority` هو `transfer_fee_extension_auth` المُكوّن للمنصة من إنشاء النعناع فصاعدًا — برنامج الإطلاق نفسه ليس لديه تعليمات سحب محتفظ به. انظر [`products/launchlab/platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).
- **النعناع المقتبس** — لا ينشئه LaunchLab ولا يفحصه. `CreateConfig` يقبل حساب النعناع كما هو، لذا **لا يوجد ما يعادل `is_supported_mint` على جانب المقتبس**. البوابة الوحيدة هي النعناعات التي يختار المسؤول ربطها بـ `GlobalConfig`.

هذا يجعل ربط نعناع مقتبس Token-2022 إجراءً عالي الثقة، للسبب نفسه تسجيل نعناع أدناه: نعناع مقتبس `TransferHook` سيشغل خطافه على كل عملية شراء وبيع ومطالبة رسوم في كل مجمع مقتبس فيه، ونعناع مقتبس `PermanentDelegate` سيسمح للمندوب بمسح خزانات المقتبس لتلك المجمعات. لا يتم حظر أي منهما من قبل البرنامج.

ما يتعامل معه LaunchLab بشكل صحيح بمجرد ربط نعناع مقتبس:

- خزان المقتبس، وكلا خزاني الرسوم، وحساب رمز مستقبل رسوم المشاركة يتم إنشاؤها على برنامج النعناع المقتبس الخاص به.
- `TransferFeeConfig` على جانب المقتبس يتم تسعيره في جميع تعليمات التجارة الأربعة، وتُفحص حدود الانزلاق مقابل المبلغ الصافي للدافع بدلاً من حركة الخزان الإجمالية. انظر [`products/launchlab/instructions`](/ar/products/launchlab/instructions#quote-side-transfer-fees).
- `PoolState.token_program_flag` يسجل برامج كلا النعناعين — bit0 للنعناع الأساسي، bit1 للنعناع المقتبس. فك تشفيره لكل بت؛ البايت ليس قيمة منطقية. انظر [`products/launchlab/accounts`](/ar/products/launchlab/accounts#poolstate).

تعليمات `Initialize` المهجورة لا تزال تأخذ برنامج مقتبس وراثي فقط، لذا فإن التكوين الذي يحتوي على نعناع مقتبس Token-2022 يمكن الوصول إليه فقط من خلال `InitializeV2` و `InitializeWithToken2022`.

## قائمة سماح امتدادات CPMM و CLMM

بعد الاختصارات القصيرة المغطاة [أدناه](#the-one-bypass-the-per-mint-registry)، يكرر البرنامج امتدادات النعناع ويرفض النعناع إذا كان يحمل **أي** امتداد بخلاف هذه الخمسة:

| الامتداد | السبب في السماح به |
|---|---|
| `TransferFeeConfig` | تطرح رياضيات المجمع رسوم الإدخال؛ يتعامل برنامج Token-2022 مع رسوم الإخراج. انظر [`algorithms/token-2022-transfer-fees`](/ar/algorithms/token-2022-transfer-fees). |
| `MetadataPointer` | زخرفي — يشير إلى البيانات الوصفية على السلسلة. |
| `TokenMetadata` | زخرفي — البيانات الوصفية المضمنة. |
| `InterestBearingConfig` | يرى المجمع المبلغ الأساسي؛ مضاعف واجهة المستخدم هو مزخرف فقط والرصيد الأساسي محفوظ. |
| `ScaledUiAmount` | نفس الشكل مثل الفائدة — عامل القياس ينطبق على عرض واجهة المستخدم فقط. |

أي شيء ليس في هذه القائمة — `TransferHook`، `NonTransferable`، `ConfidentialTransferMint`، `PermanentDelegate`، `MintCloseAuthority`، `DefaultAccountState`، `GroupPointer`، `GroupMemberPointer`، `MemberPointer`، `Pausable`، إلخ. — يسبب `is_supported_mint` في إرجاع `false` وإنشاء المجمع في الارتداد.

الأسطر ذات الصلة (CPMM، نفس الشكل في CLMM):

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs)

## مسارات الالتفاف

يمكن قبول نعناع Token-2022 لا يناسب قائمة السماح، من خلال آلية واحدة في كل برنامج. كان لكلا البرنامجين أيضًا التفافات مشفرة في الماضي؛ لا يبقى أي منها.

| الالتفاف | CPMM | CLMM |
|---|---|---|
| سجل نعناع لكل نعناع PDA | نعم — الالتفاف الوحيد | نعم — الالتفاف الوحيد |
| `MINT_WHITELIST` الثابت | تم الحذف 2026-09 (4 عناوين) | تم الحذف 2026-07 (6 عناوين) |
| كشف شكل سلطة Superstate | لم يكن لديه أبدًا | تم الحذف 2026-07 |

`is_supported_mint` الآن بايت مقابل بايت نفس الدالة في كلا البرنامجين: نعناعات SPL Token الوراثية تمر، نعناع مع سجل PDA يمر، وكل شيء آخر يجب أن يحمل فقط امتدادات مسموحة.

## الالتفاف الوحيد: سجل النعناع لكل نعناع

يستشير كلا البرنامجين PDA `SupportMintAssociated` في البذرة `[b"support_mint", mint]`. إذا كان هذا PDA موجودًا للنعناع، يتم قبول النعناع بغض النظر عن مجموعة امتداده.

لكل برنامج نسخته الخاصة من PDA (يشتقان تحت معرفات برامج مختلفة)، وزوجه الخاص من `CreateSupportMintAssociated` / `CloseSupportMintAssociated`، وسلطته المخصصة إلى جانب المسؤول المشترك:

| البرنامج | سلطة دعم النعناع المخصصة (mainnet) | سلطة دعم النعناع المخصصة (devnet) |
|---|---|---|
| CPMM | `Rayv2LG4tFSMizZhMP8aSUYxDPjV8qJtx2NQY9RKYZy` | `DRaypyeDL6y1dUusMgwyeDM5JebjhsSi8aRXobKQ9DcQ` |
| CLMM | `RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY` | `rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5` |

في كلا البرنامجين تقبل التعليمات إما `crate::admin::ID` أو سلطة دعم النعناع المخصصة لذلك البرنامج، وتتطلب أن يكون النعناع مملوكًا بواسطة Token-2022. التأثير: يمكن اختيار نعناع Token-2022 محدد لإنشاء المجمع دون ترقية برنامج — وهذا هو السبب في أن القوائم المشفرة يمكن أن تذهب.

يستشير كل برنامج السجل من **كل** مسار إنشاء مجمع لديه: CPMM من `Initialize` و `InitializeWithPermission` (الأخير هو ما تستخدمه تخرجات LaunchLab، لذا يتخرج نعناع مسجل وكذلك ينشئ)، CLMM من `CreatePool`، `CreateCustomizablePool` و `CreatePermissionedPool`.

## الالتفافات المحذوفة

كلا الآليتين المشفرتين اختفتا من البرامج المنشورة. يتم توثيقها هنا فقط لأن التكاملات المكتوبة ضد السلوك الأقدم قد لا تزال تفترضها.

### `MINT_WHITELIST` الثابت — تم الحذف

كانت مصفوفة ثابتة من عناوين النعناع base58 تختصر `is_supported_mint` قبل تكرار الامتداد. احتفظت CLMM بستة عناوين وتم حذفها في 2026-07-24؛ احتفظت CPMM بأول أربعة من نفس المجموعة وتم حذفها في [ترقية 2026-09-09](/ar/reference/changelog/2026-09-09-cpmm-anchor-1-and-excess-lamports).

| كانت مسموحة سابقًا في | النعناعات |
|---|---|
| CPMM و CLMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`, `Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`, `FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`, `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM فقط | `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`, `AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

**مجمع موجود بالفعل لأحد هذه النعناعات يستمر في التداول** — فحص النعناع يعمل فقط عند إنشاء المجمع. إنشاء مجمع *جديد* لأحدها الآن يتطلب سجل PDA له بدلاً من ذلك.

### كشف شكل سلطة Superstate — تم الحذف

حدد CLMM بإيجاز أصول Superstate المرمزة بشكل رمزي من خلال شكل سلطتها بدلاً من العنوان: نعناع Token-2022 الذي `freeze_authority` **و** المندوب الدائم كلاهما يساوي `superstate_allowlist::ID`، مع تعيين `DefaultAccountState` إلى `Frozen`، تم قبوله. كان استدلالاً، لذا أي نعناع مستقبلي بنفس الشكل كان سيتم قبوله تلقائيًا.

تم حذفه في 2026-07-31، جنبًا إلى جنب مع وحدة `superstate_allowlist`. ما حل محله أضيق وخدم غرضًا مختلفًا: `frozen_position_nft_authorities::IDS`، الذي لا يقبل أي شيء — يقرر ما إذا كان **NFT موضع** يتم تجميده، وموصوف [أعلاه](#clmm-position-nft-freezing-for-restricted-issuers). سلطة المُصدر الوحيدة التي طابقها الكشف القديم هي الإدخال الوحيد في تلك القائمة.

## ما لا تتنازل عنه الالتفافات

تتخطى الالتفافات قائمة سماح الامتداد، لكن البرنامج لا يزال يفرض:

- النعناع مملوك بواسطة إما `Token` أو `Token-2022`. يتم رفض برنامج رمز مخصص في المنطقة العليا.
- يتم إنشاء خزانات المجمع مع امتدادات ATA الصحيحة لمجمعات Token-2022 (`ImmutableOwner`، إلخ).
- جميع التحويلات تمر عبر `transfer_checked` — نعناعات تحمل الرسوم تهبط المبلغ الصحيح في الخزان.

نعناع مسموح به أو مسجل PDA يضيف لاحقًا `TransferHook` لا يكتسب فحص وقت المبادلة؛ سيعمل الخطاف ببساطة على كل تحويل ويمكن أن يوقف المبادلات. تسجيل نعناع هو بالتالي إجراء عالي الثقة.

## دلالات "محظور"

عندما يُرجع `is_supported_mint` `false`، يرتد إنشاء المجمع مع `ErrorCode::NotSupportMint` (CPMM) / `ErrorCode::NotSupportMint` (CLMM). انظر [`reference/error-codes`](/ar/reference/error-codes) للأكواد الرقمية.

لا يمكن للمجمعات الموجودة أن تفشل هذا الفحص بأثر رجعي — البوابة تعمل فقط عند الإنشاء. امتدادات النعناع غير قابلة للتغيير للفئات التي ترفضها Raydium (لا يمكن إضافة خطاف نقل، غير قابل للنقل، نقل سري بعد الإنشاء)، لذا فإن الفحص الثابت كافٍ.

## لماذا يتم استبعاد كل امتداد

- **TransferHook** — يستدعي برنامجًا مخصصًا على كل نقل، مع استهلاك CU عشوائي، شروط فشل عشوائية، والقدرة على إعادة الدخول إلى البرنامج الاستدعاء. لا يوجد صندوق رمل آمن. تحتفظ بعض DEXes بقوائم سماح خطاف؛ Raydium لا.
- **NonTransferable** — `Transfer` يفشل دائمًا. لا يمكن للمجمع أن يأخذ الحراسة.
- **ConfidentialTransfer** — مبالغ النقل مشفرة؛ المنحنى لا يمكنه تسعير المبادلة.
- **PermanentDelegate** — حامل المندوب يمكنه مسح أي حساب رمز، بما في ذلك خزان المجمع. مقبول فقط بتسجيل النعناع، وهو كيفية إدراج مُصدر موثوق (مثل عملة مستقرة منظمة) حالة تلو الأخرى.
- **MintCloseAuthority** — يمكن إغلاق النعناع؛ المجمعات الموجودة تصبح غير قابلة للاستخدام. محظور بشكل افتراضي.
- **DefaultAccountState (Frozen)** — ستهبط ATAs المجمع في حالة `Frozen` وتتطلب إذابة لكل حساب. مقبول فقط بتسجيل النعناع، الذي يفترض أن المُصدر يذيب الحسابات المؤسسية عند التسجيل.
- **مؤشرات المجموعة/العضو** — ليست ضارة بنشاط، لكن لم تُراجع. محظور بشكل افتراضي للحفاظ على السطح ضيقًا.

## محاسبة رسوم النقل

بالنسبة للنعناعات التي تحمل `TransferFeeConfig`، تنقل كل مبادلة وإيداع وسحب أقل من المبلغ الاسمي. يتم تضمين رقمان منفصلان، و SDK يبقيهما منفصلين:

- **رسوم المجمع** (LP + بروتوكول + صندوق + منشئ) تأتي من المنحنى. `raydium.cpmm.computeSwapAmount({ ... })` يُرجعها كـ `fee`، إلى جانب `amountIn`، `amountOut`، `minAmountOut`، `executionPrice`، `priceImpact` والنتيجة الخام `swapResult`.
- **رسوم نقل Token-2022** تأتي من النعناع، وليس المجمع. يتم حسابها بواسطة مساعدات `getTransferAmountFee` في `@raydium-io/raydium-sdk-v2`، التي تُرجع `GetTransferAmountFee`:

```ts
export interface GetTransferAmountFee {
  amount: BN;                  // المبلغ الذي يتحرك فعليًا
  fee: BN | undefined;         // محتفظ به من قبل النعناع؛ غير محدد عندما لا يحتوي النعناع على TransferFeeConfig
  expirationTime: number | undefined;  // تعيين أثناء انتظار تغيير رسوم مجدول
}
```

الإيداع والسحب يسطحانها مباشرة: `computePairAmount` يُرجع `inputAmountFee` و `anotherAmount` كقيم `GetTransferAmountFee`.

واجهة مستخدم صحيحة تعرض:

- مبلغ الإدخال **زائد** رسوم النقل الخاصة به كـ "أنت ترسل"
- مبلغ الإخراج **ناقص** رسوم النقل الخاصة به كـ "أنت تستقبل"
- رسوم المجمع كسطر منفصل — إنها ليست رسوم Token-2022

واجهة مستخدم ساذجة تعرض فقط `amountIn → amountOut` تقلل من التكاليف. مرر `epochInfo` من المجموعة إلى هذه المساعدات بدلاً من تخزينها مؤقتًا؛ الحقبة هي ما يختار بين تكوين الرسوم `older` و `newer` للنعناع.

### حد `maximumFee`

يتم تحديد رسوم نقل Token-2022 لكل نقل. بالنسبة لنعناع 1% مع حد 10,000 رمز، يدفع نقل 100,000,000 رمز فقط 10,000 في الرسوم. يطبق SDK `computeSwapAmount` الحد؛ يجب على مستدعي البرنامج المباشر تكراره.

### انتقال الحقبة

يمكن لسلطة النعناع جدولة تغيير معدل الرسوم الذي ينشط في الحقبة التالية. أثناء نافذة الانتقال، يعيش تكويناتان (`older`، `newer`) على النعناع في نفس الوقت و `TransferChecked` يختار حسب الحقبة الحالية. كل من CPMM `SwapV2` و CLMM `SwapV2` يمرران حساب النعناع الكامل في `accounts`، لذا يقرأ البرنامج التكوين الصحيح بدون بحث إضافي.

إذا اقتبست أكثر من حقبة واحدة مقدمًا عبر Trade API أو SDK، قد تختلف الرسوم المنفذة عن الرسوم المقتبسة — محدودة بـ `maximum_fee_basis_points` للتكوين الأقدم.

## الفائدة والمبلغ المقياس في واجهة المستخدم

يحتفظ المجمع بالمبلغ الأساسي؛ "مبلغ واجهة المستخدم" هو المبلغ الأساسي مضروبًا في عامل قياس يعتمد على الوقت أو يعينه المسؤول. تعمل رياضيات المبادلة على الأساسي:

```
principal_in = ui_amount_in / ui_multiplier(now)
```

يحول SDK تلقائيًا. يجب على قارئي RPC المباشرين معاملة `pool.token0Vault.amount` كأساسي.

## تعريف "مجمع Token-2022"

مجمع هو مجمع Token-2022 إذا **كان** أي نعناع له `programId == TokenzQdB...`. تسطح API هذا:

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

استخدم `programId` للإرسال، و `hasTransferFee` لسطح تحذير واجهة المستخدم.

## مساعدات SDK

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## أخطاء التكامل الشائعة

- **التحقق المسبق من معرف البرنامج فقط.** يمكن أن يكون النعناع Token-2022 *و* غير مدعوم. امشِ قائمة الامتداد مقابل قائمة السماح، وتحقق من سجل PDA للنعناع، قبل السماح بإنشاء المجمع.
- **الثقة في اقتباس SDK عندما لا يتم قبول النعناع على الإطلاق.** API الاقتباس لا ترفض الاقتباس — إنشاء المجمع هو ما يرتد. أكد دلالات `is_supported_mint` خارج السلسلة قبل فضح إنشاء المجمع في واجهة المستخدم الخاصة بك.
- **الاقتباس بدون خصم رسوم النقل.** نعناع برسوم نقل 1% على كلا جانبي مجمع CPMM بنسبة 0.25% له رسوم فعالة حول 2.25%، وليس 0.25%. استخدم اقتباس SDK أو اقتباس Trade API — لا تحسب الرسوم يدويًا من مستوى رسوم المجمع وحده.
- **استدعاء تعليمات `Swap` الوراثية على مجمع Token-2022.** `Swap` يسبق Token-2022. استخدم `SwapV2` كلما كان أي نعناع Token-2022.
- **إدراج نعناعات Token-2022 الجديدة تلقائيًا.** يجب على المحافظ والمجمعات التحقق من `TransferHook` و `NonTransferable` قبل سطح نعناع للمستخدمين؛ كلاهما معادٍ لـ Raydium.
