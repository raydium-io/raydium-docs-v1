## الكشف عن مراكز Raydium

### رموز السيولة الكلاسيكية (CPMM و AMM v4)

تبدو مثل أي رمز SPL آخر: حساب ATA الخاص بالمستخدم يحتفظ برصيد. تعرض المحفظة هذا كرمز عادي افتراضيًا. لكشفه كمركز Raydium LP:

1. عدّد حسابات الرموز الخاصة بالمستخدم: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. لكل رمز، تحقق من قائمة Raydium: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (جمّع حتى ~50 رمز LP لكل استدعاء).
3. بالنسبة للرموز المطابقة، تعيد API مرجع التجمع. استخدمه لحساب قيمة المركز بالرموز:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

اعرض كلاً من رصيد LP والمبالغ المفكوكة — يفكر المستخدمون بالرموز الأساسية وليس بوحدات LP.

### NFTs مراكز CLMM

مراكز CLMM هي NFTs. يتم اشتقاق `PersonalPositionState` PDA لكل مركز من رمز NFT. للكشف:

1. عدّد NFTs الخاصة بالمستخدم. بالنسبة لـ NFTs من Metaplex القديمة: صفّ حسابات الرموز إلى تلك التي تحتوي على supply 1 و decimals 0.
2. لكل رمز NFT، حاول اشتقاق PersonalPositionState PDA:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// It's a Raydium CLMM position — decode.
```

3. عدّد مراكز المحفظة باستخدام `raydium.clmm.getOwnerPositionInfo({ programId })` وطابق على `nftMint` (لا توجد دالة `getPositionInfo`). كل إدخال يعطيك:
   - `poolId` → جلب التجمع لحل الرموز
   - `tickLower`, `tickUpper` → نطاق العرض
   - `liquidity`, `tokensOwedA/B` → حساب قيمة المركز + الرسوم المعلقة
   - `rewardInfos` → المكافآت المعلقة لكل تدفق

4. بالنسبة لـ NFTs المراكز الصادرة بموجب Token-2022 (`OpenPositionWithToken22Nft`)، يكون برنامج رمز NFT هو Token-2022 بدلاً من SPL Token. عدّد كليهما عند المسح.

### مراهنات المزرعة

لا تُرجع نقطة نهاية مراكز التخزين مبالغ المكافآت المعلّقة أو عناوين mint لرموز المكافآت. استخدم `raydium.farm.fetchFarmBalances()` لقراءة الحسابات على السلسلة عبر Solana RPC وحساب المكافآت.

`raydium.api.fetchFarmPositions(user.toBase58())` · [Owner API](/api-reference/owner-api-v1-endpoints/position/get-stake-positions-for-a-wallet) · [SDK v2 0.2.64-alpha](/integration-guides/wallet-integration#farm-stake)

## حساب قيمة المركز

### CPMM و AMM v4 LP

الوحدات الثلاث **لا** تشترك في توقيع: `liquidity.getPoolInfoFromRpc` يأخذ `{ poolId }`، بينما `cpmm.getPoolInfoFromRpc` و `clmm.getPoolInfoFromRpc` يأخذان سلسلة base58 موضعية.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` هو ApiV3Token وليس له حقل `supply`. اقرأ
// supply رمز LP من السلسلة، أو استخدم مرآة التجمع الخاصة به:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

ثم اضرب كل واحد بسعر USD للرمز (من `raydium.token` أو oracle سعر).

### مركز CLMM

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // base58 string
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity غير متزامن، يأخذ epochInfo + poolInfo + add،
// ويعيد المبالغ المغلفة برسوم.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // للعرض، بدون انزلاق
  add:        false,
});
// amountA.amount / amountB.amount هي BNs؛ .fee هي رسوم نقل Token-2022.

// الرسوم المعلقة — اعرضها بشكل منفصل كـ "غير مجمعة"
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// المكافآت المعلقة — تجمع CLMM له 0–3 تدفقات مكافآت. إدخالات
// rewardInfos الخاصة بالمركز هي { growthInsideLastX64, rewardAmountOwed } فقط، لذا يجب أن يأتي
// الرمز من rewardInfos الخاص بـ POOL بنفس الفهرس.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

اعرض كـ:

- قيمة السيولة (السعر الحالي)
- الرسوم غير المجمعة
- المكافآت المعلقة لكل تدفق
- النطاق: `[tickLower_price, tickUpper_price]` مع شريط بصري يوضح ما إذا كان السعر الحالي ضمن النطاق

## محاكاة المعاملة لمعاينة

قبل أن يوقّع المستخدم، عادة ما تعاين المحافظ تغييرات الرصيد. استخدم `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// فكّك رصيد كل حساب مُعاد وقارنه برصيد ما قبل المعاملة.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // قارن برصيد ما قبل المعاملة، اعرض Δ
}
```

معامل `accounts` يطلب من المدقق إعادة حالة الحساب بعد المحاكاة للعناوين المدرجة. أكثر دقة بكثير من محاولة التنبؤ بتغيير الرصيد من شكل التعليمات وحده.

### مزالق المحاكاة

- **مبادلات CLMM تحتاج إلى مصفوفات tick صحيحة.** إذا كان حجم إدخال المستخدم سيعبر إلى مصفوفة tick غير مهيأة، تعود المحاكاة (مثل التنفيذ). اعرض هذا بوضوح في الواجهة.
- **رسوم الأولوية.** تعمل المحاكاة بدون تطبيق تعليمات compute-budget. بالنسبة لمعاملة كبيرة تتجاوز 200k CU الافتراضي، تفشل المحاكاة لكن التنفيذ الفعلي مع حد CU صريح ينجح. اضبط حد CU على المعاملة المحاكاة أيضًا.
- **blockhash طازج.** تستخدم المحاكاة blockhash الحالي؛ إذا استغرق التوقيع >60 ثانية تصبح المعاملة غير صحيحة. أعد المحاكاة إذا تردد المستخدم.

## عرض Token-2022

يجب تسمية الرموز ضمن برنامج Token-2022 كما هي في قائمة الرموز الخاصة بالمحفظة، لأن لديها سطوح مخاطر مختلفة:

- **رموز رسوم النقل**: اعرض `transferFeeBasisPoints` الحالي كـ "رسوم النقل: X%" بجانب الرصيد. حذّر عند الاستقبال — قد لا يدرك المستخدمون أنهم سيستقبلون أقل مما أرسله المرسل.
- **رموز transfer-hook**: اعرض معرف برنامج الخطاف. يمكن لخطاف خبيث أن يحظر النقل الخارج؛ يجب على المستخدمين التحقق من أن الخطاف هو ما يتوقعونه.
- **رموز غير قابلة للنقل**: اعرض "غير قابل للنقل" وعطّل swap/send. عادة ما تكون هذه رموز مرتبطة بالروح أو بيانات اعتماد.
- **رموز تحمل الفائدة**: رصيد الواجهة المشتق من `TokenAccount.amount` **لا** يعكس الفائدة المتراكمة. استخدم `amountToUiAmount` من `@solana/spl-token` (الذي يطبق عامل التحجيم) للقيمة المعروضة.

## عرض APR للمزرعة

يجب أن يجمع APR المعروض للمستخدمين جميع تدفقات المكافآت المباشرة، محولة إلى USD، وسنوية:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // تخطّ غير المشغّل
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

اعرض كـ `APR: X.Y%`. إذا كان رمز المراهنة رمز LP، احسب أيضًا APR رسوم القاعدة الخاصة بـ LP الأساسي وسمّ المجموع كـ "إجمالي APR" أو "APR + الرسوم".
