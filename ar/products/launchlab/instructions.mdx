| دورة حياة الإطلاق | `Initialize` | **لا أحد — تفشل دائمًا مع `NotApproved`.** محتفظ بها فقط حتى يبقى المميز مشغولاً ويبقى IDL مستقرًا. استخدم `InitializeV2`. |
| دورة حياة الإطلاق | `InitializeV2` | أي شخص (المنشئ) — قاعدة SPL Token mint؛ يسجل `amm_creator_fee_on` للتخرج CPMM المستقبلي، ويقبل Token-2022 quote mint. |
| دورة حياة الإطلاق | `InitializeWithToken2022` | أي شخص (المنشئ) — Token-2022 base mint، `TransferFeeConfig` اختياري؛ يقبل برنامج رمز الاقتباس |

| التخرج | `MigrateToCpswap` | محفظة الهجرة — التخرج إلى CPMM. تستخدم جميع الإطلاقات المهيأة حديثًا هذا المسار. يغلف `InitializeWithPermission` على CPMM. |

| الرسوم | `CollectMigrateFee` | المسؤول — كنس رسوم الهجرة المتراكمة |
| الرسوم | `ClaimCreatorFee` | المنشئ — المطالبة برسوم المنشئ المتراكمة أثناء مرحلة المنحنى |
| الاستحقاق | `CreateVestingAccount` | المنشئ — تخصيص الرموز المقفلة للمستفيد، مفتوحة بعد التخرج |
| الاستحقاق | `CreatePlatformVestingAccount` | مسؤول المنصة — تخصيص الرموز المقفلة للمستفيدين من جانب المنصة |
| الاستحقاق | `ClaimVestedToken` | المستفيد — المطالبة برموز مفتوحة بعد الجرف |
| إعدادات المنصة | `CreatePlatformConfig` / `UpdatePlatformConfig` | مسؤول المنصة |
| إعدادات المنصة | `CreatePlatformCurveRule` / `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` / `ClosePlatformCurveRule` | `PlatformConfig.curve_rule_manager` أو مسؤول المنصة — إدارة قاعدة معاملات الإطلاق لـ `GlobalConfig` واحد |
| رسوم المنصة | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | مسؤول المنصة |
| وصول المنصة | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | مسؤول المنصة — الحفاظ على قائمة السماح `GlobalConfig` المستخدمة عندما تمكّن تلك المنصة التقييد |
| الإيجار | `CollectExcessLamports` | مسؤول البرنامج أو محفظة جمع lamports المخصصة — كنس lamports فوق الحد الأدنى المعفي من الإيجار من الأقبية والـ PDAs التي يتحكم فيها LaunchLab. تمت الإضافة 2026-09. |

ينعكس الانقسام "ExactIn/ExactOut" على `SwapBaseInput` / `SwapBaseOutput` الخاص بـ CPMM — على السلسلة يكونان مميزات تعليمات منفصلة برقم تقريبي مختلف قليلاً.

**اختيار مسار التخرج.** يجب على كل استدعاء `InitializeV2` و `InitializeWithToken2022` جديد تعيين `migrate_type = 1` (`CPSWAP`). أي محاولة لتهيئة مجموعة جديدة مرتبطة بـ AMM v4 تُرجع `MigrateTypeNotMatch`. `amm_creator_fee_on` يختار فقط ما إذا كانت رسوم منشئ CPMM الناتجة تنطبق على رمز الاقتباس أو كلا الرمزين؛ لا يختار برنامج الهدف. لا يمكن لـ `Initialize` القديم إنشاء إطلاق على الإطلاق بعد الآن (انظر أدناه).

يبقى `MigrateToAmm` قابلاً للاستدعاء لـ `PoolState` موجود تم تهيئته مع `migrate_type = 0` قبل هذا التقييد. لا تعيد الإصدار كتابة حالة المجموعة الموجودة أو تزيل التعليمة القديمة.

**برنامج الرمز من جانب الاقتباس.** قد تكون quote mint مملوكة لبرنامج SPL Token أو Token-2022. كل تعليمة تلمسها — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`، جميع التعليمات التجارية الأربع، `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee`, و `ClaimPlatformFeeFromVault` — تأخذ البرنامج المالك في فتحة حسابها للبرنامج المقتبس. لم تتغير مواضع الحسابات؛ فقط القيمة المقبولة. مرر البرنامج الذي يمتلك فعلاً `GlobalConfig.quote_mint`، والذي يمكنك قراءته من بت `PoolState.token_program_flag` bit1 لإطلاق موجود (انظر [`accounts`](/ar/products/launchlab/accounts#poolstate)) أو من مالك حساب mint بخلاف ذلك.

`Initialize` المهجورة غير ذات صلة هنا: حساب برنامج الاقتباس الخاص بها لا يزال مكتوبًا إلى SPL Token، ومنذ ترقية 2026-09 تفشل التعليمة قبل قراءة أي حساب. قم بالإطلاق من خلال `InitializeV2` أو `InitializeWithToken2022`.

`MigrateToCpswap` هو الاستثناء الآخر، في الاتجاه المعاكس — يأخذ **كلا** البرنامجين بدون شرط بدلاً من واحد لكل mint. انظر [حسابات الهجرة أدناه](#cpmm-migration-token-programs).

## `Initialize`

<Warning>
  **تم حذفها فعليًا اعتبارًا من ترقية 2026-09 — هذه التعليمة تفشل دائمًا.** معالج `initialize` الآن مجرد سجل يقول `Not supported. Please use initialize_v2 instruction` و `NotApproved` (`6000`). يتم الاحتفاظ بها فقط لكي يبقى المميز الخاص بها محتلاً والـ IDL يحافظ على شكل مستقر. (هيكل `Accounts` لم يتغير، لذا التحقق المُنشأ من Anchor يعمل أولاً؛ المعاملة تنعكس على أي حال.)

  في السابق، كانت مقيدة بالساعة: كانت تعمل حتى ثلاثة أيام بعد قطع `get_upgrade_timestamp` وفشلت بعد ذلك. مساعد الطابع الزمني هذا اختفى، لذا الفشل الآن غير مشروط. الإطلاقات الموجودة التي تم إنشاؤها من خلالها لم تتأثر — فهي تتداول وتتخرج بشكل طبيعي عبر `MigrateToAmm` أو `MigrateToCpswap` حسب `migrate_type` المخزن لديهم.

  الحجج وقائمة الحسابات أدناه خاصة بـ `InitializeV2`. الـ `Initialize` المهجور يأخذ نفس 18 حسابًا بنفس الترتيب والحجج الثلاث الأولى فقط — ليس لديه `amm_fee_on` — وفتحة `quote_token_program` الخاصة به مكتوبة بـ SPL Token بدلاً من `Interface<TokenInterface>`.
</Warning>

إنشاء إطلاق جديد. `InitializeV2` يضيف فقط حجة `amm_fee_on` على `Initialize` المهجور؛ عدد الحسابات والترتيب **متطابقان تمامًا**، والفرق الوحيد على مستوى الحسابات هو أن `quote_token_program` مكتوب `Interface<TokenInterface>` بحيث يتم قبول mint اقتباس Token-2022.

**الحجج**

أربع حجج موضعية، وليست هيكلاً واحدًا. (`InitializeWithToken2022` يضيف خامسة، `transfer_fee_extension_param: Option<TransferFeeExtensionParams>`؛ الـ `Initialize` المهجور يحذف `amm_fee_on`.)

```rust
base_mint_param: MintParams {
    decimals: u8,                 // must equal the program's BASE_MINT_DECIMALS
    name:     String,
    symbol:   String,
    uri:      String,
}

curve_param: CurveParams {        // Borsh enum — one leading variant-tag byte
    Constant { data: ConstantCurve { supply: u64, total_base_sell: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Fixed    { data: FixedCurve    { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Linear   { data: LinearCurve   { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
}

vesting_param: VestingParams {
    total_locked_amount: u64,     // 0 requires cliff_period == unlock_period == 0
    cliff_period:        u64,     // seconds after fundraising ends
    unlock_period:       u64,     // seconds
}

amm_fee_on: AmmCreatorFeeOn       // 0 = QuoteToken, 1 = BothToken (CPMM migrations only)
```

يجب أن يطابق المتغير `global_config.curve_type` أو ستنعكس التعليمة مع `InputNotMatchCurveConfig` (`6003`). لا يوجد `open_time`، لا حجة `quote_mint` (تأتي من `global_config`)، لا هيكل `fees` ولا `post_graduation_lp_policy` — يتم تعيين التخلص من LP على `PlatformConfig`، وليس لكل إطلاق.

**الحسابات** — 18 في المجموع (16 معلنة بالإضافة إلى إضافات `#[event_cpi]` الاثنتان)

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` | W | S | يدفع كل الإيجار. لا يحتاج إلى أن يكون المُنشئ. |
| 2 | `creator` |   |   | مسجل كـ `pool_state.creator`؛ ليس موقّعًا. |
| 3 | `global_config` |   |   | يوفر mint الاقتباس ونوع المنحنى وكل حد أدنى/أقصى. |
| 4 | `platform_config` |   |   | يوفر معدل رسوم المنصة وسياسة التخلص من LP. |

**الشروط المسبقة**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- معاملات الرسوم تمر فحوصات `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK يفرض `≥ now`؛ البرنامج يتسامح مع التأخير الطفيف).
- `curve_type` معروف.

**الشروط اللاحقة**

- `base_mint` له `supply = curve_param.supply`، كل شيء في `base_vault`.
- سلطة الـ mint تكون **ملغاة** في نفس التعليمة (`set_authority(MintTokens, None)`) مباشرة بعد سك الإمداد — وليس عند التخرج. mint الأساسي بالتالي ذو إمداد ثابت دائمًا، ولا يمكن لأي تعليمة لاحقة أن تسك المزيد.
- `PoolState` مهيأ مع `status = Fund` (`0`)، `real_a = 0`، `real_b = 0`.
- `total_fund_raising_b` يأتي مباشرة من `curve_param.total_quote_fund_raising`.
- لـ `InitializeWithToken2022` مع `TransferFeeConfig` مرفق: `transfer_fee_config_authority = launch_authority`، و `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` عندما يتم تعيين هذا الحقل، وإلا `launch_authority`. يتم كتابة جانب السحب عند إنشاء mint بالضبط حتى تتمكن المنصة من مسح الرسوم المحتفظ بها قبل التخرج. انظر [`platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**الأخطاء الشائعة** — `NotApproved` (`6000`، بدون شروط، لـ `Initialize` المهجور)، `InvalidInput` (`6002`، انتهاك إمداد / معدل / حد أدنى لجمع الأموال من `GlobalConfig`)، `InputNotMatchCurveConfig` (`6003`، متغير `curve_param` لا يطابق `global_config.curve_type`)، `MigrateTypeNotMatch` (`6007`، `migrate_type != 1`)، `MathOverflow` (`6008`)، `VestingRatioTooHigh` (`6010`)، `NoSupportExtension` (`6017`)، `NotEnoughRemainingAccounts` (`6018`)، `InvalidPlatformAllowConfig` (`6022`)، `CurveParamNotMatchPlatformRule` (`6025`). فشل فحص Anchor `address =` / `constraint =` يظهر كرمز 2xxx، وليس أحد هذه — لا يوجد `InvalidQuoteMint` أو `FeeRateTooHigh` أو `InvalidCurveParams` في تعداد الأخطاء في البرنامج.

## `Buy` (المتغير الأساسي: `BuyExactIn`)

يوفر المستخدم مبلغ إدخال ثابت؛ المنحنى يحسب الإخراج.

**الحجج**

```
amount_in:           u64
minimum_amount_out:  u64
share_fee_rate:      u64   // referral fee on a 1_000_000 denominator; must be
                           // <= global_config.max_share_fee_rate. Pass 0 for no
                           // referral. Any non-zero value requires the share-fee
                           // receiver as remaining_accounts[0].
```

<Warning>
  جميع تعليمات التداول الأربع تأخذ **ثلاث** حجج، وليس اثنتين. تعليمة مبنية بحجتين فقط تكون 8 بايتات قصيرة وتفشل في فك التسلسل.
</Warning>

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` | W | S | المتداول. |
| 2 | `authority` |   |   | PDA `["vault_auth_seed"]` — PDA عام واحد، بدون بذرة لكل إطلاق. |
| 3 | `global_config` |   |   | `address = pool_state.global_config`. |
| 4 | `platform_config` |   |   | `address = pool_state.platform_config`. |
| 5 | `pool_state` | W |   | |
| 6 | `user_base_token` | W |   | `token::mint = base_token_mint`. |
| 7 | `user_quote_token` | W |   | `token::mint = quote_token_mint`. |
| 8 | `base_vault` | W |   | `address = pool_state.base_vault`. |
| 9 | `quote_vault` | W |   | `address = pool_state.quote_vault`. |
| 10 | `base_token_mint` |   |   | |
| 11 | `quote_token_mint` |   |   | |
| 12 | `base_token_program` |   |   | البرنامج الذي يمتلك mint الأساسي — SPL Token أو Token-2022. |
| 13 | `quote_token_program` |   |   | البرنامج الذي يمتلك mint الاقتباس. |
| 14 | `event_authority` |   |   | PDA `["__event_authority"]`؛ مُضافة بواسطة `#[event_cpi]`. |
| 15 | `program` |   |   | معرّف برنامج LaunchLab؛ مُضافة بواسطة `#[event_cpi]`. |

**الحسابات المتبقية** — أنابيب الرسوم، تُقرأ بهذا الترتيب الدقيق:

1. `share_fee_receiver` — **فقط** عندما `share_fee_rate > 0`.
2. `system_program` — دائمًا؛ يتم التحقق من `== System::id()`، وإلا `InvalidInput`.
3. `platform_fee_vault` — PDA `[platform_config, quote_token_mint]`؛ تُنشأ عند الاستخدام الأول.
4. `creator_fee_vault` — PDA `[creator, quote_token_mint]`؛ تُنشأ عند الاستخدام الأول.

النقص يُرجع `NotEnoughRemainingAccounts` (`6018`). لا توجد فتحة `associated_token_program`، و `system_program` حساب *متبقي* وليس معلن.

**الشروط المسبقة**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**التأثير**

1. تقسيم `quote_in` إلى `quote_in_after_fee` وأجزاء الرسوم.
2. حل Newton للمنحنى لـ `base_out` بناءً على الاقتباس بعد الرسوم.
3. `require(base_out ≥ minimum_base_out)` وإلا انعكس `ExceededSlippage`.
4. نقل `quote_in` من المستخدم → الخزان. نقل `base_out` من الخزان → المستخدم.
5. تحديث `base_sold += base_out`، `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. تحديث عدادات الرسوم (`protocol_fees_quote`، `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. إذا كان `quote_reserve_real ≥ quote_reserve_target` بعد التحديث، عادة ما يربط SDK تعليمة `Graduate` في نفس المعاملة. البرنامج لا يتخرج تلقائيًا داخل `Buy` — يلزم `Graduate` لاحق.

## `BuyExactOut`

يحدد المستخدم `base_out` الدقيق؛ البرنامج يحسب `quote_in`.

**الحجج**

```
amount_out:         u64
maximum_amount_in:  u64
share_fee_rate:     u64   // as for BuyExactIn
```

نفس الحسابات ونفس عقد الحسابات المتبقية كـ `BuyExactIn`. يستخدم التكامل التربيعي الشكل المغلق (أو معكوس CPMM، لـ curve_type 1) بدلاً من تكرار Newton.

## `Sell` / `SellExactIn` / `SellExactOut`

نسخة معكوسة من `Buy`. يعيد المستخدم `base_in` إلى المنحنى ويستقبل `quote_out`. يتم خصم الرسم من `quote_out`، لذا يستقبل المستخدم أقل من العائد المتكامل الخام.

**الشروط المسبقة** —

- `user_base_ata.balance ≥ base_in`.
- البيع لا يمكن أن يدفع `base_sold` تحت 0 (زائد مع ما سبق نظراً لأن المحاسبة متسقة).
- Launch في حالة `Active`.

**التأثير** — متماثل مع `Buy`. ينخفض `base_sold`، ينخفض `quote_reserve_real`. تستمر الرسوم في التراكم.

### رسوم التحويل من جانب الاقتباس

عندما يحمل mint الاقتباس `TransferFeeConfig`، يختلف المبلغ الذي تنقله الخزانة عن المبلغ الذي يتم خصمه أو إضافته للدافع، ويتم فحص حد الانزلاق مقابل جانب الدافع. على mint اقتباس بدون الامتداد، كل حالة أدناه متطابقة مع mint موروث عادي.

| التعليمة | الحجة | يتم الفحص مقابل |
|---|---|---|
| `BuyExactIn` | `amount_in` | يتم تسعير المنحنى على `amount_in − transfer_fee(amount_in)` — ما يصل إلى الخزانة. يخصم الملء الكامل بالضبط `amount_in`؛ الملء الجزئي يخصم مبلغ الخزانة المستهلك بالإضافة إلى رسم معكوس. |
| `BuyExactOut` | `maximum_amount_in` | مبلغ الخزانة **بالإضافة إلى** رسم التحويل المعكوس — الخصم الفعلي. |
| `SellExactIn` | `minimum_amount_out` | ما يحتفظ به البائع بعد أن تحتفظ mint برسمها، وليس المبلغ الإجمالي الذي يغادر الخزانة. |
| `SellExactOut` | `amount_out` | يتم التسليم بالضبط. يستهدف المنحنى `amount_out` بالإضافة إلى رسم التحويل المعكوس. |

نتيجتان للاقتباس:

- حد محسوب كما لو كانت mint خالية من الرسوم يتم رفضه. تمرير التكلفة الخالية من الرسوم كـ `maximum_amount_in`، أو العائد الخالي من الرسوم كـ `minimum_amount_out`، يعود مع `ExceededSlippage`.
- `real_quote` يتقدم فقط بما وصل إلى الخزانة. `BuyExactIn` من `amount_in` على mint اقتباس بنسبة 5% يحرك `real_quote` بمقدار `amount_in × 0.95`.

لا يمكن عكس mint اقتباس برسم 100% (`10000` نقطة أساس) ويعود مع `CalculateOverflow` على مسارات exact-out.

كلا mint جانب التجارة مقيدة أيضاً ببرنامج تم تمريره في فتحتهما المطابقة، لذا فإن عدم تطابق `base_token_program` الآن يفشل بدلاً من تجاهله. انظر [`algorithms/token-2022-transfer-fees`](/ar/algorithms/token-2022-transfer-fees) للحصول على رياضيات الرسم الأساسية.

### حسابات التجارة المتبقية

تأخذ جميع التعليمات التجارية الأربع أنابيب الرسوم الخاصة بها من خلال `remaining_accounts`، بهذا الترتيب:

| الفهرس | الحساب | متى |

| التالي | `creator_fee_vault` | دائماً. PDA في البذور `[creator, quote_token_mint]`، تم الإنشاء عند الاستخدام الأول. |

<Note>

</Note>

## `MigrateToAmm` / `MigrateToCpswap`

تخريج إطلاق إلى مجموعة قابلة للتداول بمجرد وصول المنحنى إلى `total_quote_fund_raising`. الإطلاقات الجديدة تكون CPMM فقط. يتم الاحتفاظ بـ `MigrateToAmm` للمجموعات الموجودة التي يكون `migrate_type` المخزن فيها هو `0`.

**من يوقّع**

- `MigrateToAmm` — محفظة `migrate_to_amm_wallet` المسجلة على `GlobalConfig` المرتبط.
- `MigrateToCpswap` — محفظة `migrate_to_cpswap_wallet` المسجلة على `GlobalConfig` المرتبط.

عادة ما تكون هذه المحافظ مملوكة لآلية التخريج التي تديرها Raydium؛ في الممارسة العملية، يحدث التخريج بعد ثوانٍ من تجاوز الحد الأدنى، بغض النظر عمن أطلق عملية الشراء الأخيرة.

**المعاملات**

لا يأخذ أي منهما أي معاملات.

<Warning>
  **تغيير جذري (محفظة الهجرة فقط، 2026-09).** أسقط `MigrateToAmm` جميع المعاملات الثلاثة — `base_lot_size`، `quote_lot_size`، `market_vault_signer_nonce` — **وتسعة حسابات**. بيانات التعليمات الخاصة به الآن هي المميز الفارغ فقط، لذا فإن المُنشئ القديم يرسل 17 بايت معاملات غير متوقعة ويوفر قائمة حسابات لا تتوافق بعد الآن.

  يتبع هذا [إزالة OpenBook](/ar/reference/changelog/2026-07-22-amm-v4-openbook-removal) الخاصة بـ AMM v4: لا يأخذ `Initialize2` الخاص بـ AMM v4 `market_program` أو `amm_open_orders` بعد الآن، لذا لم يكن لدى LaunchLab شيء متبقٍ للإرسال. توقف البرنامج أيضًا عن CPI-ing `initialize_openbook_market`، وهو ما كانت المعاملات الثلاثة تُعدّه.

  الحسابات المحذوفة: `openbook_program`، `request_queue`، `event_queue`، `bids`، `asks`، `market_vault_signer`، `market_base_vault`، `market_quote_vault`، و `amm_open_orders`. حساب `market` **يبقى** في موضعه — AMM v4 لا يزال يسجله كحقل مرجعي — لكنه الآن معلن كـ `#[account(mut)]` فارغ: بدون قيد مالك أو عنوان أو بذور. إنه غير مُتحقق منه تماماً، يتم إرساله مباشرة إلى CPI الخاص بـ `Initialize2` في AMM v4، والبرنامج لم يعد يهيئه. يجب على المتصل الذي يريد أن يكون حساب السوق سوقاً حقيقياً مهيأً أن ينشئه بنفسه مسبقاً.

  قائمة الـ 23 حساب المتبقية، بالترتيب: `payer`، `base_mint`، `quote_mint`، `market`، `amm_program`، `amm_pool`، `amm_authority`، `amm_lp_mint`، `amm_base_vault`، `amm_quote_vault`، `amm_target_orders`، `amm_config`، `amm_create_fee_destination`، `authority`، `pool_state`، `global_config`، `base_vault`، `quote_vault`، `pool_lp_token`، `spl_token_program`، `associated_token_program`، `system_program`، `rent_program`.

  `MigrateToCpswap` لم يتأثر — لم يكن لديه معاملات قط.
</Warning>

**التأثير (مشترك بين الاثنين)**

1. تحقق من `pool_state.status == Migrate` (أي تم الوصول إلى `quote_reserve_target`). وإلا فارجع مع `PoolMigrated` (كان الحالة بالفعل `Migrated`) أو `PoolFunding` (لا يزال في التمويل).
2. تحقق من أن `pool_state.migrate_type` يطابق التعليمات (`0` لـ AMM، `1` لـ CPMM). وإلا فارجع مع `MigrateTypeNotMatch`.
3. احسب الاحتياطيات بعد التخريج:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. قم بـ CPI إلى البرنامج المستهدف (`AMM v4 Initialize2` أو `CPMM InitializeWithPermission`) بتلك الاحتياطيات لإنشاء مجموعة ما بعد التخريج.
5. بالنسبة لهجرات CPMM المنفذة بعد ترقية 2026-08-17، دمج `platform_scale + creator_scale` في حصة LP مقفولة واحدة مملوكة للمنصة وصك على الأكثر مفتاح رسوم NFT واحد إلى `platform_nft_wallet`. احرق باقي `burn_scale`. قبل الترقية، كان `creator_scale` مقفولاً بشكل منفصل وكان مفتاح الرسوم الخاص به يذهب إلى منشئ الرمز. لا يتم تعديل الهجرات التاريخية المكتملة. بالنسبة لتخريج AMM v4 القديم، يتبع توزيع LP تدفق التعليمات الموجود.
6. (لا توجد خطوة سلطة صك. تم بالفعل تعيين `base_mint.mint_authority` إلى `None` عند إنشاء الإطلاق — انظر الملاحظة أدناه.)
7. اقلب `pool_state.status = Migrated`، اضبط `vesting_schedule.start_time = block_time + cliff_period`.

**تسليم سلطة رسوم النقل Token-2022** — عندما يكون base mint عبارة عن Token-2022 mint يحمل `TransferFeeConfig` **و** `PlatformConfig.transfer_fee_extension_auth` غير افتراضي، تقوم الهجرة أيضاً بإعادة تعيين سلطات هذا الامتداد إلى مفتاح المنصة:

- يتم إعادة تعيين `transfer_fee_config_authority` دائماً. يحتفظ بها PDA `authority` الخاص بالإطلاق طوال مرحلة ما قبل التخريج، لذا هناك دائماً شيء يجب نقله.
- يتم إعادة تعيين `WithheldWithdraw` **فقط عندما يحتفظ بها PDA `authority` لا تزال**. الإطلاقات المنشأة من 2026-08-27 فما بعده تحمل بالفعل `transfer_fee_extension_auth` على تلك السلطة من إنشاء الرمز، لذا يتم تخطي الخطوة. الحراسة هي ما يمنع الهجرة من الرجوع على تلك الرموز — لا يمكن لـ PDA أن توقع سلطة لم تعد تحتفظ بها.

إذا كان `transfer_fee_extension_auth` هو `Pubkey::default()` في وقت الهجرة، فلا تتحرك أي سلطة وكلاهما يبقى مع `authority` PDA بشكل دائم. انظر [`platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

<Note>
  **عرض base mint ثابت من الإنشاء، وليس من التخريج.** `InitializeV2` و `InitializeWithToken2022` يصكان العرض الكامل في base vault ثم يلغيان فوراً `MintTokens` في نفس التعليمات، لذا `base_mint.mint_authority` هو `None` طوال حياة الإطلاق. الهجرة لا تلمسه. (الإصدارات السابقة من هذه الصفحة وضعت الإلغاء عند التخريج؛ كان ذلك خطأ.) السلطات الوحيدة التي يمكن للهجرة نقلها هي سلطات Token-2022 transfer-fee الموصوفة أدناه.
</Note>

**الشروط اللاحقة** — `BuyExactIn`، `BuyExactOut`، `SellExactIn`، `SellExactOut` سترفض من هذه النقطة فصاعداً مع `PoolMigrated`. مجموعة AMM الناتجة قانونية وتتداول مثل أي مجموعة AMM v4 / CPMM أخرى.

**الأخطاء الشائعة** — `PoolFunding`، `PoolMigrated`، `MigrateTypeNotMatch`، `InvalidCpSwapConfig`، `MathOverflow`.

### حسابات CPMM migration المتبقية

يجب على العملاء الذين ينشئون `MigrateToCpswap` استخدام مؤشرات `remaining_accounts` الثابتة هذه:

| الفهرس | الحساب |
|---|---|
| 0–4 | مالك مفتاح رسوم المنصة، والرمز، وحساب الرمز، و PDA السيولة المقفولة، وحساب البيانات الوصفية |
| 5 | منشئ الإطلاق الأصلي؛ يُستخدم عندما يكون `platform_cp_creator` غير محدد |
| 6 | CPMM permission PDA مشتق من `[b"permission", launch_authority]` |
| 7 | `platform_cp_creator` المُعد؛ يُستخدم عندما يكون الحقل غير افتراضي |
| 8 | CPMM support-mint PDA لـ `mint0` المرتب، مشتق من `[b"support_mint", mint0]` |
| 9 | CPMM support-mint PDA لـ `mint1` المرتب، مشتق من `[b"support_mint", mint1]` |

تتطلب التعليمات على الأقل عشرة حسابات متبقية. حسابات support-mint هي مدخلات CPI للقراءة فقط. اشتق كلا العنوانين حتى عندما لا يكون للرمز سجل دعم مهيأ. يجب تحديث المُنشئين الأقدم الذين لا يزالون يضيفون حسابات creator-lock أو يحذفون المؤشرات 8–9.

<Note>
  **تم التغيير في 2026-09.** تنظيفان، لا أحدهما يغير المُنشئ الصحيح:

  - **مسار CPMM المرخص هو الآن المسار الوحيد.** اعتاد `MigrateToCpswap` على الاختيار بين `InitializeCpSwap` و `InitializeCpSwapWithPermission` بناءً على `unix_timestamp >= get_upgrade_timestamp()`. مساعد الطابع الزمني والـ CPI القديم كلاهما اختفى، لذا ينطبق المسار المرخص — وبالتالي الحد الأدنى من عشرة حسابات — بدون شروط.
  - **تم نقل ثلاثة قيود عنوان من هيكل الحساب إلى جسم التعليمات.** `platform_config`، `base_vault`، و `quote_vault` لا تزال مطلوبة لمطابقة القيم المخزنة على `PoolState`، لكن عدم التطابق الآن يتم رفعه بواسطة `require_keys_eq!` بدلاً من قيد Anchor `address =`. الفحص معادل؛ فقط السطح الخطأ يختلف — تحصل على `RequireKeysEqViolated` (`2502`) العام من Anchor بدلاً من `ConstraintAddress` (`2012`)، ويتم الإبلاغ عنه بدون اسم حساب. حدّث أي معالجة خطأ طابقت على `2012` لهذه الحسابات الثلاثة.
</Note>

### برامج رموز هجرة CPMM

يأخذ `MigrateToCpswap` كلا برنامج الرموز بدون شروط ويعرف أي برنامج يمتلك كل رمز بنفسه. تمت إعادة تسمية حسابات برنامج الرموز الخاصة به وفقاً لذلك:

| الموضع | الحساب | القيمة |
|---|---|---|
| الأول | `token_program` | دائماً برنامج SPL Token القديم |
| الثاني | `token_program_2022` | دائماً برنامج Token-2022 |

يحلان محل `base_token_program` السابق (أي برنامج امتلك base mint) و `quote_token_program` (دائماً قديم). المواضع لم تتغير، لذا هذا تغيير قيمة وليس تغيير تخطيط — لكن القيمتين قريبتان من الانعكاس، والمُنشئ الذي يستمر في تمرير زوجه القديم سيوفر Token-2022 حيث يكون البرنامج القديم مطلوباً بمجرد أن يكون أي رمز Token-2022 mint.

البرنامج القديم مطلوب حتى عندما لا يستخدمه أي رمز، لأن CPMM LP mint و Fee Key NFT السيولة المقفولة يعيشان دائماً عليه.

## قائمة السماح `GlobalConfig` للمنصة

يتحكم `PlatformConfig.restrict_global_config` في الفحص:

- `0`: تقبل المنصة أي `GlobalConfig` صحيح بخلاف ذلك؛ لا يلزم حساب السماح.
- `1`: يجب أن تتضمن `Initialize`، `InitializeV2`، و `InitializeWithToken2022` `PlatformAllowConfig` المطابق في أي مكان في `remaining_accounts`.

ينشئ مسؤول المنصة أو يغلق PDA باستخدام `CreatePlatformAllowConfig` و `ClosePlatformAllowConfig`. بذوره هي `[b"platform_allow_config", platform_config, global_config]`. تم إيقاف تعليمات `PlatformGlobalAccess` و PDA المُدارة من قبل المسؤول السابق.

## قواعد معاملات الإطلاق للمنصة

أربع تعليمات تدير حساب `PlatformCurveRule` واحد. جميع الأربعة موقعة من قبل `PlatformConfig.curve_rule_manager` أو من قبل مسؤول المنصة — يقبل البرنامج المسؤول بإعادة اشتقاق PDA `PlatformConfig` من الموقّع، لذا لا حساب منفصل يثبته. الموقّع الذي ليس أياً منهما يعيد `InvalidCurveRuleAuthority`.

| التعليمات | الحسابات | المعاملات |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority` (موقّع، mut)، `platform_config`، `global_config`، `platform_curve_rule` (mut)، `system_program` | لا شيء |
| `UpdatePlatformCurveRule` | نفس الخمسة | `group_id: u16`، `constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | نفس الخمسة | `group_id: u16` |
| `ClosePlatformCurveRule` | الأربعة الأولى | لا شيء |

`platform_curve_rule` هو PDA في `[b"platform_curve_rule", platform_config, global_config]`.

- **`Create`** يخصص الحساب الذي لا يحتوي على مجموعة. تلك الحالة لا تقيد أي شيء.
- **`Update`** يدرج أو يحدّث المجموعة بـ `group_id` ذلك، مستبدلاً بالكامل إذا كانت موجودة. يغيّر حجم الحساب ليناسب، لذا يضيف الموقّع الإيجار الذي ينمو به ويستقبل الإيجار الذي ينكمش به. مجموعة جديدة تتجاوز العاشرة تعيد `CurveRuleGroupsExceeded`؛ أكثر من 25 قيد، حقل غير معروف أو عامل، أو نفس زوج `(field, op)` مرتين في مجموعة واحدة يعيد `InvalidCurveRuleConstraint`؛ الحقول الأربعة المشتقة من `TotalSellA` على تكوين غير ثابت الناتج يعيد `CurveRuleFieldNotSupportedByCurve`.
- **`Remove`** يسقط مجموعة واحدة حسب المعرّف، ينكمش الحساب ويسترجع الفرق. معرّف غير معروف يعيد `CurveRuleGroupNotExist`.
- **`Close`** يعيد الإيجار بالكامل إلى الموقّع. التكوين غير مقيد بعد ذلك حتى عندما يبقى `restrict_curve_param` على `1`.

لا يغير أي من الأربعة ما إذا كانت القواعس مفروضة. هذا هو `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`، والذي يمكن فقط لمسؤول المنصة استدعاؤه.

**على مسار الإطلاق.** بينما `restrict_curve_param` هو `1`، تتطلب `InitializeV2` و `InitializeWithToken2022` PDA القاعدة في `remaining_accounts` — بما في ذلك عندما لا توجد، بحيث لا يمكن حذفها تخطي الفحص. حساب مفقود هو `NotEnoughRemainingAccounts`؛ إطلاق لا يرضي أي مجموعة هو `CurveParamNotMatchPlatformRule`. يعمل الفحص قبل حدود `GlobalConfig` الخاصة به ويمكن فقط تضييقها. النموذج والكتيبات: [`products/launchlab/curve-rules`](/ar/products/launchlab/curve-rules). كلا الخطأين قابلان للتجنب من جانب العميل — يعكس SDK هذا الفحص كدالة نقية، انظر [تحقق قبل الإرسال](/ar/products/launchlab/curve-rules#check-before-you-send).

**الحسابات**

<Warning>
  `quote_mint` يأتي **قبل** `recipient_token_account` هنا — عكس `ClaimCreatorFee` و `ClaimPlatformFee` و `ClaimPlatformFeeFromVault`، التي تضع المستقبِل أولاً. الفتحتان لهما أنواع Anchor مختلفة (`Mint` مقابل `TokenAccount`)، لذا تبديلهما يفشل في فك التسلسل في وقت التشغيل ويبدو وكأنه خطأ حساب خاطئ. `CollectMigrateFee` له نفس الترتيب مثل `CollectFee`.
</Warning>

**التأثير** — نقل `pool_state.quote_protocol_fee` من `quote_vault` إلى `recipient_token_account`، ثم تصفير العداد. يمكن استدعاؤه في أي وقت بعد الشراء الأول.

## `CollectExcessLamports`

عملية مسح إداري لـ lamports الموجودة فوق الحد الأدنى المعفي من الإيجار على الحسابات التي يتحكم فيها LaunchLab. تمت إضافتها في ترقية 2026-09 بحيث يمكن للبروتوكول استرجاع التمويل الزائد الذي يتركه [SIMD-0437 rent reduction](/ar/solana-fundamentals/rent-and-reclaimable-rent) على الحسابات المُنشأة قبل كل خطوة.

فقط الزيادة تتحرك. أرصدة الرموز وبيانات الحساب والمالكون وحالة المنحنى والاستحقاق لا تتأثر، والتعليمات هي عملية بدون تأثير على حساب بالفعل عند الحد الأدنى — لذا من الآمن إعادة التشغيل بعد كل خطوة نشر.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | الوجهة لكل lamport مُكتسح. يجب أن يكون إما مسؤول برنامج LaunchLab أو محفظة collect-lamports المخصصة — انظر [`reference/program-addresses`](/ar/reference/program-addresses#excess-lamports-collection-wallets). أي موقّع آخر يفشل مع `InvalidOwner` (`6001`). |
| 2 | `authority` |   |   | **واحد** من ثلاث PDAs سلطة خزينة LaunchLab (انظر أدناه). يوقّع CPIs برنامج الرموز لكل حساب رموز في هذا الاستدعاء. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. كلاهما مطلوب بدون شروط؛ يختار البرنامج لكل حساب مصدر. |
| 5.. | `remaining_accounts` | W |   | `M` حساب مصدر للمسح، أي عدد، أي ترتيب. |

**اختيار `authority`**

يتم تمرير الحساب بدون فحص ويتم حله بواسطة البرنامج، الذي يعيد اشتقاق جميع ثلاث PDAs سلطة LaunchLab ومطابقة:

| البذرة | تمتلك |
|---|---|
| `[b"vault_auth_seed"]` | خزينة المجموعة الأساسية والاقتباس لكل إطلاق |
| `[b"platform_fee_vault_auth_seed"]` | كل خزينة رسوم منصة |
| `[b"creator_fee_vault_auth_seed"]` | كل خزينة رسوم منشئ |

مفتاح لا يطابق أيًا من الثلاثة يفشل التعليمات بالكامل مع `InvalidOwner` (`6001`).

<Warning>
  **جمّع حسابات المصدر حسب السلطة.** استدعاء واحد يحمل `authority` واحد، وبرنامج الرموز يتطلب من المالك الفعلي للحساب التوقيع. حساب رموز مملوك لـ PDA مختلف من الثلاثة عن `authority` الذي مررته يجعل CPI يفشل ويأخذ المعاملة بأكملها معه. قم بمسح خزائن المجموعة وخزائن رسوم المنصة وخزائن رسوم المنشئ في معاملات منفصلة.

  PDAs المملوكة للبرنامج هي الاستثناء — يتم خصمها مباشرة، لذا يمكنها الركوب مع أي سلطة.
</Warning>

**كيفية التعامل مع كل حساب مصدر**

| مالك حساب المصدر | المعالجة |
|---|---|
| SPL Token أو Token-2022، حساب رموز غير أصلي | CPI `WithdrawExcessLamports` (discriminant برنامج الرموز `38`)، موقّع بواسطة `authority`. |
| SPL Token أو Token-2022، **أصلي** (wSOL) حساب رموز | `WithdrawExcessLamports` يرفض الحسابات الأصلية. يقوم البرنامج بـ CPI `SyncNative`، يقيس كم نما `amount` المُغلّف، `UnwrapLamports` (discriminant `45`) لهذا الفرق بالضبط، ثم يتطلب أن يساوي الرصيد المُغلّف قيمته قبل المزامنة — وإلا `LamportsCalculateError` (`6031`). إطلاق مقتبس بـ SOL بالتالي يحتفظ باحتياطي الاقتباس الكامل. |
| برنامج LaunchLab نفسه — `PoolState`، `GlobalConfig`، `PlatformConfig`، `VestingRecord`، `PlatformCurveRule`، `PlatformAllowConfig` | يقوم البرنامج بخصم الحساب مباشرة إلى `rent.minimum_balance(data_len)`. |
| أي شيء آخر | **يتم تخطيه بصمت.** لا خطأ، لا lamports مُنقول. |

**لا يمكن مسح العملات الأساسية.** `InitializeV2` و `InitializeWithToken2022` يلغيان `MintTokens` على العملة الأساسية في نفس التعليمات التي تصك الإمداد، لذا لا يمكن لأي مفتاح توقيع `WithdrawExcessLamports` لها — يبقى إيجار العملة حيث هو بشكل دائم.

**الأخطاء الشائعة** — `InvalidOwner` (`6001`، موقّع خاطئ أو `authority` ليس أحد ثلاث PDAs)، `LamportsCalculateError` (`6031`، رحلة wSOL ذهاباً وإياباً لم تصل إلى صفر)، و `InsufficientFunds` من مسار البرنامج المملوك عندما يحتفظ حساب برصيد أقل من حد الإيجار الخاص به.

**لا منشئ SDK.** `@raydium-io/raydium-sdk-v2` لا يشحن منشئ لهذه التعليمات، وكذلك مستودع `raydium-sdk-V2-demo` — إنها مسار إداري. قم بترميزها يدويًا، بالطريقة التي يفعلها مسح جانب المحفظة في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) لتعليمات برنامج الرموز.
