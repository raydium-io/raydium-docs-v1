## جرد التعليمات

| المجموعة | التعليمة | قابلة للاستدعاء من قبل |
|-------|-------------|-------------|
| الإعدادات العامة | `CreateConfig` / `UpdateConfig` | مسؤول البرنامج؛ قد تستدعي سلطة إنشاء الإعدادات المفوضة أيضًا `CreateConfig` |
| دورة الإطلاق | `Initialize` / `InitializeV2` | أي شخص (المنشئ) — قاعدة رمز SPL Token؛ يسجل V2 `amm_creator_fee_on` للتخرج النهائي من CPMM. يقبل V2 فقط رمز اقتباس Token-2022. |
| دورة الإطلاق | `InitializeWithToken2022` | أي شخص (المنشئ) — قاعدة رمز Token-2022، `TransferFeeConfig` اختياري؛ يقبل برنامج رمز الاقتباس |
| التداول | `BuyExactIn` / `BuyExactOut` | أي شخص — شراء بمدخل دقيق / مخرج دقيق على منحنى الربط |
| التداول | `SellExactIn` / `SellExactOut` | أي شخص — بيع بمدخل دقيق / مخرج دقيق على منحنى الربط |
| التخرج | `MigrateToAmm` | محفظة الهجرة — تخرج AMM v4 القديم للمجموعات المهيأة قبل فرض إنشاء CPMM فقط. |
| التخرج | `MigrateToCpswap` | محفظة الهجرة — التخرج إلى CPMM. تستخدم جميع الإطلاقات المهيأة حديثًا هذا المسار. يغلّف `InitializeWithPermission` على CPMM. |
| الرسوم | `CollectFee` | المسؤول — مسح رسوم البروتوكول من إطلاق |
| الرسوم | `CollectMigrateFee` | المسؤول — مسح رسوم الهجرة المتراكمة |
| الرسوم | `ClaimCreatorFee` | المنشئ — المطالبة برسوم المنشئ المتراكمة أثناء مرحلة المنحنى |
| الاستحقاق | `CreateVestingAccount` | المنشئ — تخصيص الرموز المقفلة لمستفيد، مفتوحة بعد التخرج |
| الاستحقاق | `CreatePlatformVestingAccount` | مسؤول المنصة — تخصيص الرموز المقفلة لمستفيدي جانب المنصة |
| الاستحقاق | `ClaimVestedToken` | المستفيد — المطالبة برموز مفتوحة بعد الجرف |
| إعدادات المنصة | `CreatePlatformConfig` / `UpdatePlatformConfig` | مسؤول المنصة |
| إعدادات المنصة | `CreatePlatformCurveRule` / `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` / `ClosePlatformCurveRule` | `PlatformConfig.curve_rule_manager` أو مسؤول المنصة — إدارة قاعدة معاملات الإطلاق لـ `GlobalConfig` واحد |
| رسوم المنصة | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | مسؤول المنصة |
| وصول المنصة | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | مسؤول المنصة — الحفاظ على قائمة السماح `GlobalConfig` المستخدمة عندما تفعّل تلك المنصة التقييد |

ينعكس الانقسام "ExactIn/ExactOut" في CPMM `SwapBaseInput` / `SwapBaseOutput` — على السلسلة يكونان محددات تعليمات منفصلة برقم تقريبي مختلف قليلاً.

**اختيار مسار التخرج.** يجب أن تعيّن كل استدعاء `Initialize` و `InitializeV2` و `InitializeWithToken2022` جديد `migrate_type = 1` (`CPSWAP`). أي محاولة لتهيئة مجموعة مرتبطة بـ AMM v4 جديدة تُرجع `MigrateTypeNotMatch`. `amm_creator_fee_on` يختار فقط ما إذا كانت رسوم منشئ CPMM الناتجة تنطبق على رمز الاقتباس أو كلا الرمزين؛ لا يختار برنامج الهدف.

يبقى `MigrateToAmm` قابلاً للاستدعاء لـ `PoolState` موجود تمت تهيئته باستخدام `migrate_type = 0` قبل هذا التقييد. الإصدار لا يعيد كتابة حالة المجموعة الموجودة أو يزيل التعليمة القديمة.

**برنامج رمز الاقتباس.** قد يكون رمز الاقتباس مملوكًا لبرنامج SPL Token أو Token-2022. كل تعليمة تلمسه — `CreateConfig` و `InitializeV2` و `InitializeWithToken2022` وجميع التعليمات التجارية الأربع و `CollectFee` و `CollectMigrateFee` و `ClaimCreatorFee` و `ClaimPlatformFee` و `ClaimPlatformFeeFromVault` — تأخذ البرنامج المالك في فتحة حسابها. لم تتغير مواضع الحسابات؛ فقط القيمة المقبولة تغيرت. مرّر البرنامج الذي يملك فعلاً `GlobalConfig.quote_mint`، والذي يمكنك قراءته من بت `PoolState.token_program_flag` bit1 لإطلاق موجود (انظر [`accounts`](/ar/products/launchlab/accounts#poolstate)) أو من مالك حساب الرمز بخلاف ذلك.

`Initialize` المهجور هو الاستثناء: حسابه برنامج الاقتباس لا يزال مكتوبًا لـ SPL Token، لذا يجب إطلاق إعداد رمز اقتباس Token-2022 من خلال `InitializeV2` أو `InitializeWithToken2022`.

`MigrateToCpswap` هو الاستثناء الآخر، في الاتجاه المعاكس — يأخذ **كلا البرنامجين** بدون شروط بدلاً من واحد لكل رمز. انظر [حسابات الهجرة أدناه](#cpmm-migration-token-programs).

## `Initialize`

إنشاء إطلاق جديد.

**الوسائط**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // or initial_virtual_quote_reserve for curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // inline name/symbol/uri; program CPIs to Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**الحسابات** (مختصرة)

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `creator` | W | S | يدفع الإيجار + إنشاء قاعدة الرمز. |
| 2 | `launch_config` |   |   | ربط إعدادات البروتوكول. |
| 3 | `launch_state` | W |   | حساب جديد. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Keypair جديد (أو PDA) — تهيّئ هذه التعليمة له. |
| 6 | `base_vault` | W |   | ATA من `launch_authority` على `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA من `launch_authority` على `quote_mint`. |
| 9 | `metadata` | W |   | PDA بيانات Metaplex. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token لقاعدة الرمز. `InitializeV2` و `InitializeWithToken2022` يأخذان حساب برنامج اقتباس منفصل قد يكون أي برنامج. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**الشروط السابقة**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- معاملات الرسوم تمرّ فحوصات `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK يفرض `≥ now`؛ البرنامج يتسامح مع التأخير البسيط).
- `curve_type` معروف.

**الشروط اللاحقة**

- `base_mint` له `supply = base_supply_max`، الكل في `base_vault`.
- `base_mint.mint_authority = launch_authority`، `freeze_authority = None`.
- `LaunchState` مهيأ مع `status = Active`، `base_sold = 0`، `quote_reserve_real = 0`.
- `quote_reserve_target` محسوب من معاملات المنحنى + `base_supply_graduation` + `buy_numerator` (تقريبًا).
- لـ `InitializeWithToken2022` مع `TransferFeeConfig` مرفق: `transfer_fee_config_authority = launch_authority`، و `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` عندما يكون هذا الحقل معيّنًا، وإلا `launch_authority`. يُكتب جانب السحب عند إنشاء الرمز بالضبط حتى تتمكن المنصة من مسح الرسوم المحتفظ بها قبل التخرج. انظر [`platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**الأخطاء الشائعة** — `InvalidQuoteMint`، `FeeRateTooHigh`، `InvalidCurveParams`، `MathOverflow`.

## `Buy` (المتغير الكنسي: `BuyExactIn`)

يوفر المستخدم `quote_in` ثابت؛ يحسب المنحنى `base_out`.

**الوسائط**

```
quote_in:          u64
minimum_base_out:  u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**الشروط السابقة**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**التأثير**

1. قسّم `quote_in` إلى `quote_in_after_fee` وأجزاء الرسوم.
2. حل المنحنى بـ Newton للحصول على `base_out` من الاقتباس بعد الرسوم.
3. `require(base_out ≥ minimum_base_out)` وإلا عكّس `ExceededSlippage`.
4. انقل `quote_in` من المستخدم → الخزينة. انقل `base_out` من الخزينة → المستخدم.
5. حدّث `base_sold += base_out`، `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. حدّث عدادات الرسوم (`protocol_fees_quote`، `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. إذا كان `quote_reserve_real ≥ quote_reserve_target` بعد التحديث، يسلسل SDK عادةً تعليمة `Graduate` في نفس المعاملة. البرنامج لا يتخرج تلقائيًا داخل `Buy` — يلزم `Graduate` لاحق.

## `BuyExactOut`

يحدد المستخدم `base_out` الدقيق؛ يحسب البرنامج `quote_in`.

**الوسائط**

```
base_out:      u64
maximum_quote_in: u64
```

نفس الحسابات مثل `BuyExactIn`. يستخدم التكامل التربيعي الشكل المغلق (أو معكوس CPMM، لـ curve_type 1) بدلاً من تكرار Newton.

## `Sell` / `SellExactIn` / `SellExactOut`

مرآة `Buy`. يعيد المستخدم `base_in` إلى المنحنى ويستقبل `quote_out`. يُخصم الرسم من `quote_out`، لذا يستقبل المستخدم أقل من العائدات المتكاملة الخام.

**الشروط السابقة** —

- `user_base_ata.balance ≥ base_in`.
- البيع لا يمكن أن يدفع `base_sold` تحت 0 (زائد مع المحاسبة المتسقة).
- الإطلاق هو `Active`.

**التأثير** — متماثل مع `Buy`. `base_sold` ينخفض، `quote_reserve_real` ينخفض. الرسوم لا تزال تتراكم.

### رسوم نقل جانب الاقتباس

عندما يحمل رمز الاقتباس `TransferFeeConfig`، المبلغ الذي تنقله الخزينة والمبلغ الذي يُخصم أو يُرصد للدافع يختلفان، والحد الأدنى للانزلاق يُفحص مقابل جانب الدافع. على رمز اقتباس بدون الامتداد كل حالة أدناه متطابقة مع رمز قديم عادي.

| التعليمة | الوسيط | مفحوص مقابل |
|---|---|---|
| `BuyExactIn` | `amount_in` | يُسعّر المنحنى على `amount_in − transfer_fee(amount_in)` — ما يصل إلى الخزينة. يخصم الملء الكامل بالضبط `amount_in`؛ يخصم الملء الجزئي المبلغ المستهلك من الخزينة بالإضافة إلى رسم معكوس. |
| `BuyExactOut` | `maximum_amount_in` | مبلغ الخزينة **بالإضافة إلى** رسم النقل المعكوس — الخصم الحقيقي. |
| `SellExactIn` | `minimum_amount_out` | ما يحتفظ به البائع بعد احتفاظ الرمز برسمه، وليس المبلغ الإجمالي الذي يترك الخزينة. |
| `SellExactOut` | `amount_out` | مُسلّم بالضبط. يستهدف المنحنى `amount_out` بالإضافة إلى رسم النقل المعكوس. |

نتيجتان للاقتباس:

- حد محسوب كما لو كان الرمز خالي من الرسوم مرفوض. تمرير التكلفة الخالية من الرسوم كـ `maximum_amount_in`، أو العائدات الخالية من الرسوم كـ `minimum_amount_out`، يعكّس مع `ExceededSlippage`.
- `real_quote` يتقدم فقط بما وصل إلى الخزينة. `BuyExactIn` من `amount_in` على رمز اقتباس 5% يحرك `real_quote` بـ `amount_in × 0.95`.

رمز اقتباس برسم 100% (`10000` نقطة أساس) لا يمكن عكسه ويعكّس مع `CalculateOverflow` على مسارات الإخراج الدقيق.

كلا رموز جانب التداول مقيدة أيضًا ببرنامج مرّر في فتحتها المطابقة، لذا `base_token_program` غير متطابق الآن يفشل بدلاً من تجاهله. انظر [`algorithms/token-2022-transfer-fees`](/ar/algorithms/token-2022-transfer-fees) لرياضيات الرسوم الأساسية.

## `MigrateToAmm` / `MigrateToCpswap`

تخرج إطلاق إلى مجموعة قابلة للتداول بمجرد أن يصل المنحنى إلى `total_quote_fund_raising`. الإطلاقات الجديدة هي CPMM فقط. يُحتفظ بـ `MigrateToAmm` للمجموعات الموجودة التي يكون `migrate_type` المخزن فيها `0`.

**من يوقّع**

- `MigrateToAmm` — `migrate_to_amm_wallet` المسجل على `GlobalConfig` الملزم.
- `MigrateToCpswap` — `migrate_to_cpswap_wallet` المسجل على `GlobalConfig` الملزم.

تُحتفظ بهذه المحافظ عادةً بواسطة كرنك التخرج الذي تشغله Raydium؛ عمليًا يهبط التخرج ثوانٍ بعد تجاوز الحد الأدنى، بغض النظر عمن أطلق الشراء النهائي.

**الوسائط**

يأخذ `MigrateToAmm` ثلاثة (بشكل أساسي معاملات سوق OpenBook التي يمرّرها البرنامج إلى AMM v4):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` لا يأخذ أي شيء.

**التأثير (مشترك بين الاثنين)**

1. تحقق من `pool_state.status == Migrate` (أي تم الوصول إلى `quote_reserve_target`). وإلا عكّس مع `PoolMigrated` (كانت الحالة بالفعل `Migrated`) أو `PoolFunding` (لا تزال في التمويل).
2. تحقق من أن `pool_state.migrate_type` يطابق التعليمة (`0` لـ AMM، `1` لـ CPMM). وإلا عكّس مع `MigrateTypeNotMatch`.
3. احسب الاحتياطيات بعد التخرج:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI إلى برنامج الهدف (`AMM v4 Initialize2` أو `CPMM InitializeWithPermission`) مع تلك الاحتياطيات لإنشاء مجموعة ما بعد التخرج.
5. لهجرات CPMM المنفذة بعد ترقية 2026-08-17، دمج `platform_scale + creator_scale` في حصة LP مقفلة مملوكة للمنصة واحدة وأصدر على الأكثر مفتاح رسوم NFT واحد إلى `platform_nft_wallet`. احرق بقية `burn_scale`. قبل الترقية، كانت `creator_scale` مقفلة بشكل منفصل وذهب مفتاح الرسوم الخاص بها إلى منشئ الرمز. الهجرات التاريخية المكتملة لم تُعدّل. لتخرج AMM v4 القديم، يتبع توزيع LP تدفق التعليمة الموجود.
6. اسحب `base_mint.mint_authority` (عيّن إلى `None`).
7. اقلب `pool_state.status = Migrated`، عيّن `vesting_schedule.start_time = block_time + cliff_period`.

**سلطة نقل رسوم Token-2022** — عندما تكون قاعدة الرمز رمز Token-2022 يحمل `TransferFeeConfig` **و** `PlatformConfig.transfer_fee_extension_auth` غير افتراضي، الهجرة تعيد أيضًا سلطات هذا الامتداد إلى مفتاح المنصة:

- `transfer_fee_config_authority` يُعاد تعيينه دائمًا. PDA سلطة الإطلاق يحتفظ به لمرحلة ما قبل التخرج بأكملها، لذا هناك دائمًا شيء للنقل.
- `WithheldWithdraw` يُعاد تعيينه **فقط عندما يحتفظ به PDA السلطة**. الإطلاقات المنشأة من 2026-08-27 فما بعده تحمل بالفعل `transfer_fee_extension_auth` على تلك السلطة من إنشاء الرمز، لذا يُتخطى الخطوة. الحراسة هي ما يمنع الهجرة من الانعكاس على تلك الرموز — لا يمكن لـ PDA التوقيع على سلطة لم تعد تحتفظ بها.

إذا كان `transfer_fee_extension_auth` هو `Pubkey::default()` في وقت الهجرة، لا تتحرك السلطات ولا تبقى كلاهما مع `authority` PDA بشكل دائم. انظر [`platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**الشروط اللاحقة** — `BuyExactIn`، `BuyExactOut`، `SellExactIn`، `SellExactOut` سترفض من هذه النقطة فصاعدًا مع `PoolMigrated`. مجموعة AMM الناتجة كنسية وتتداول مثل أي مجموعة AMM v4 / CPMM أخرى.

**الأخطاء الشائعة** — `PoolFunding`، `PoolMigrated`، `MigrateTypeNotMatch`، `InvalidCpSwapConfig`، `MathOverflow`.

### حسابات هجرة CPMM المتبقية

يجب على العملاء الذين يبنون `MigrateToCpswap` استخدام فهارس `remaining_accounts` الثابتة هذه:

| الفهرس | الحساب |
|---|---|
| 0–4 | مالك مفتاح الرسوم، الرمز، حساب الرمز، PDA السيولة المقفلة، وحساب البيانات الوصفية |
| 5 | منشئ الإطلاق الأصلي؛ يُستخدم عندما يكون `platform_cp_creator` غير معيّن |
| 6 | PDA إذن CPMM مشتق من `[b"permission", launch_authority]` |
| 7 | `platform_cp_creator` المكوّن؛ يُستخدم عندما يكون الحقل غير افتراضي |
| 8 | PDA دعم رمز CPMM لـ `mint0` المرتب، مشتق من `[b"support_mint", mint0]` |
| 9 | PDA دعم رمز CPMM لـ `mint1` المرتب، مشتق من `[b"support_mint", mint1]` |

تتطلب التعليمة على الأقل عشرة حسابات متبقية على المسار المحدّث. حسابات دعم الرمز هي مدخلات CPI للقراءة فقط. اشتق كلا العنوانين حتى عندما لا يكون للرمز سجل دعم مهيأ. يجب تحديث المنشئين الأقدم الذين لا يزالون يضيفون حسابات قفل المنشئ أو يحذفون الفهارس 8–9.

### برامج هجرة رموز CPMM

يأخذ `MigrateToCpswap` كلا برنامجي الرموز بدون شروط ويعرّف أي برنامج يملك كل رمز بنفسه. أُعيدت تسمية حسابات برنامجي الرموز الخاصة به وفقًا لذلك:

| الموضع | الحساب | القيمة |
|---|---|---|
| الأول | `token_program` | دائمًا برنامج SPL Token القديم |
| الثاني | `token_program_2022` | دائمًا برنامج Token-2022 |

يحلان محل `base_token_program` السابق (أي برنامج يملك قاعدة الرمز) و `quote_token_program` (دائمًا قديم). المواضع لم تتغير، لذا هذا تغيير قيمة وليس تغيير تخطيط — لكن القيمتين قريبتان من الانعكاس، والمنشئ الذي يستمر في تمرير زوجه القديم سيوفر Token-2022 حيث يُطلب البرنامج القديم بمجرد أن يكون أي رمز رمز Token-2022.

البرنامج القديم مطلوب حتى عندما لا يستخدم أي رمز، لأن رمز LP من CPMM ومفتاح الرسوم NFT للسيولة المقفلة يعيشان دائمًا عليه.

## قائمة السماح `GlobalConfig` للمنصة

`PlatformConfig.restrict_global_config` يتحكم في الفحص:

- `0`: تقبل المنصة أي `GlobalConfig` صحيح بخلاف ذلك؛ لا يُطلب حساب سماح.
- `1`: يجب أن تتضمن `Initialize` و `InitializeV2` و `InitializeWithToken2022` `PlatformAllowConfig` المطابق في أي مكان في `remaining_accounts`.

ينشئ مسؤول المنصة أو يغلق PDA باستخدام `CreatePlatformAllowConfig` و `ClosePlatformAllowConfig`. بذوره هي `[b"platform_allow_config", platform_config, global_config]`. تعليمات `PlatformGlobalAccess` المدارة من قبل المسؤول السابقة و PDA متقاعدة.

## قواعد معاملات الإطلاق للمنصة

أربع تعليمات تدير حساب `PlatformCurveRule` واحد. جميعها موقعة بواسطة `PlatformConfig.curve_rule_manager` أو مسؤول المنصة — يقبل البرنامج المسؤول بإعادة اشتقاق PDA `PlatformConfig` من الموقّع، لذا لا حساب منفصل يثبته. الموقّع الذي ليس أحدهما يُرجع `InvalidCurveRuleAuthority`.

| التعليمة | الحسابات | الوسائط |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority` (موقّع، mut)، `platform_config`، `global_config`، `platform_curve_rule` (mut)، `system_program` | لا شيء |
| `UpdatePlatformCurveRule` | نفس الخمسة | `group_id: u16`، `constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | نفس الخمسة | `group_id: u16` |
| `ClosePlatformCurveRule` | الأربعة الأولى | لا شيء |

`platform_curve_rule` هو PDA في `[b"platform_curve_rule", platform_config, global_config]`.

- **`Create`** يخصص الحساب الذي لا يحتفظ بأي مجموعة. تلك الحالة لا تقيد أي شيء.
- **`Update`** يدرج المجموعة مع `group_id` ذلك، يستبدلها بالكامل إذا كانت موجودة. يعيد حجم الحساب ليناسب، لذا يضيف الموقّع الإيجار الذي ينمو به ويستقبل الإيجار الذي ينكمش به. مجموعة جديدة تتجاوز العاشرة تُرجع `CurveRuleGroupsExceeded`؛ أكثر من 25 قيد، حقل غير معروف أو عامل، أو نفس زوج `(field, op)` مرتين في مجموعة واحدة تُرجع `InvalidCurveRuleConstraint`؛ الحقول الأربعة المشتقة من `TotalSellA` على إعداد غير ثابت الناتج تُرجع `CurveRuleFieldNotSupportedByCurve`.
- **`Remove`** يسقط مجموعة واحدة بـ id، ينكمش الحساب ويسترد الفرق. معرّف غير معروف يُرجع `CurveRuleGroupNotExist`.
- **`Close`** يعيد الإيجار بأكمله إلى الموقّع. الإعداد غير مقيد بعد ذلك حتى عندما يبقى `restrict_curve_param` `1`.

لا يغيّر أي من الأربعة ما إذا كانت القواعد مفروضة. هذا هو `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`، الذي يمكن فقط لمسؤول المنصة استدعاؤه.

**على مسار الإطلاق.** بينما `restrict_curve_param` هو `1`، تتطلب `InitializeV2` و `InitializeWithToken2022` PDA القاعدة في `remaining_accounts` — بما في ذلك عندما لا توجد، حتى لا يمكن حذفها لتخطي الفحص. حساب مفقود هو `NotEnoughRemainingAccounts`؛ إطلاق لا يرضي أي مجموعة هو `CurveParamNotMatchPlatformRule`. يعمل الفحص قبل حدود `GlobalConfig` الخاصة به ويمكن فقط تضييقها. نموذج وكتيبات: [`products/launchlab/curve-rules`](/ar/products/launchlab/curve-rules). كلا الخطأين قابلان للتجنب من جانب العميل — يعكس SDK هذا الفحص كدالة نقية، انظر [تحقق قبل الإرسال](/ar/products/launchlab/curve-rules#check-before-you-send).
