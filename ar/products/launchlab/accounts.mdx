| `platform_fee_vault` | SPL Token / Token-2022 | خزانة لكل منصة + لكل نعناع اقتباس تحتفظ برسوم المنصة المتراكمة، يتم مسحها بواسطة `ClaimPlatformFeeFromVault`. تتبع برنامج نعناع الاقتباس. |

| (بعد التخرج) `cpmm_pool_state` | برنامج CPMM | تجمع تم إنشاؤه بواسطة `MigrateToCpswap` لكل إطلاق جديد. يمكن للحالة القديمة أن تشير إلى تخرج AMM v4 القديم. |
| (بعد التخرج) Fee Key NFT | برنامج LP-Lock | قبل ترقية 2026-08-17، يمكن لمقاييس المنصة والمنشئ أن تنتج مفاتيح رسوم منفصلة. الهجرات المنفذة بعد ذلك تجمع كلا المقياسين في مفتاح رسوم منصة واحد. |

يعيد `raydium.launchpad.getLaunchById` من SDK `PoolState` بالإضافة إلى علم يشير إلى ما إذا كان الإطلاق قد تخرج؛ إذا كان الأمر كذلك، يتم تضمين معرف التجمع بعد الهجرة.

## `PoolState`

حالة جذر الإطلاق. أسماء الحقول أدناه تطابق بنية Rust على السلسلة (`states/pool.rs`)؛ تم تبسيط بعض القيم لسهولة القراءة — استشر المصدر للحصول على تخطيط الذاكرة الدقيق.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

قيم `PoolStatus` (من Anchor IDL):

```
0 = Funding         — accepting buys / sells; below quote_reserve_target
1 = Migrate         — quote_reserve_target reached; awaiting MigrateTo*
2 = Migrated        — MigrateTo* already executed; vesting clock running
```

الحقول الموجهة للمدمج:

- **`status`** — ثلاث قيم، رتيبة (Funding → Migrate → Migrated). القراءات آمنة دائماً؛ الكتابات مبوابة.
- **`real_base`**, **`real_quote`** — حالة المنحنى الحالية. مع `virtual_base` / `virtual_quote` فهي كافية لحساب سعر البقعة دون لمس الخزائن. انظر [`bonding-curve`](/ar/products/launchlab/bonding-curve).
- **`total_base_sell`** مقابل `real_base` — نسبة "التقدم نحو التخرج" لواجهات المستخدم.
- **`migrate_type`** — يتطلب التهيئة الجديدة `1` (`CPSWAP`). يبقى `0` المخزن ذا معنى فقط لإطلاق موجود تم إنشاؤه قبل فرض CPMM فقط.
- **`amm_creator_fee_on`** — يختار `creator_fee_on = OnlyQuoteToken` (`0`) أو `BothToken` (`1`) على تجمع CPMM بعد التخرج. لا يختار هدف الهجرة. انظر [`creator-fees`](/ar/products/launchlab/creator-fees).
- **`token_program_flag`** — حقل بت، وليس منطقي. Bit0 هو نعناع الأساس و bit1 هو نعناع الاقتباس، كل منهما `0` لـ SPL Token و `1` لـ Token-2022، لذا يأخذ البايت أربع قيم: `0` (كلاهما قديم)، `1` (Token-2022 base)، `2` (Token-2022 quote)، `3` (كلاهما Token-2022). اقرأ نعناع واحد مع `(token_program_flag >> bit) & 1`. مقارنة البايت بالكامل مقابل `0` لتصنيف نعناع الأساس يحل `2` إلى البرنامج الخاطئ. كان Bit1 ثابتاً `0` حتى تم دعم نعناعات اقتباس Token-2022.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — ثلاثة عدادات رسوم مستقلة. لكل منها تعليمة مطالبة خاصة بها؛ انظر [`instructions`](/ar/products/launchlab/instructions).
- **`vesting_schedule`** — موجود على كل `PoolState` لكن غير نشط عندما `total_locked_amount == 0`. انظر [`vesting`](/ar/products/launchlab/vesting) للدورة الحياة الكاملة.

## سلطة PDA

يستخدم LaunchLab سلطة PDA **واحدة** عبر جميع الإطلاقات، مشتقة بدون بذرة لكل إطلاق:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

هذا PDA الواحد هو:

- السلطة على `base_vault` و `quote_vault` لكل إطلاق.
- `mint_authority` على `base_mint` لكل إطلاق (قبل التخرج).
- الموقّع على CPI تخرج CPMM، وعلى تخرج AMM v4 القديم للحالة الموجودة.
- الموقّع على تحويلات `ClaimVestedToken` خارج الخزانة الأساسية.
- `transfer_fee_config_authority` على `TransferFeeConfig` لنعناع أساس Token-2022، للمرحلة الكاملة قبل التخرج — و `withdraw_withheld_authority` أيضاً، لكن فقط عندما تترك المنصة `PlatformConfig.transfer_fee_extension_auth` غير محددة.

يتم إلغاء `mint_authority` فوراً بعد استدعاء `MigrateToCpswap` أو `MigrateToAmm` القديم، لذا يتم إصلاح العرض بشكل دائم.

يحرس PDA إضافيان خزائن الرسوم:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

يوقعان التحويل خارج خزانة الرسوم المقابلة أثناء `ClaimCreatorFee` و `ClaimPlatformFeeFromVault`.

## نعناع الأساس

تم إنشاؤه بشكل مضمن بواسطة `Initialize` مع:

- `mint_authority = authority` (تم إلغاؤه عند التخرج).
- `freeze_authority = None`.
- `supply = supply`، مصكوك بالكامل في `base_vault`.
- `decimals` اختاره المنشئ في `Initialize` (عادة 6).

نظراً لأن العرض الكامل مصكوك مسبقاً، فإن `base_mint.supply` ثابت طوال حياة الإطلاق. تحريكات المنحنى تنقل الرموز من `base_vault` إلى المشتري، لكنها لا تستدعي `mint_to`.

ينشئ `Initialize` / `InitializeV2` نعناعات أساس SPL Token. تسمح التعليمة المخصصة `InitializeWithToken2022` بأن يكون نعناع الأساس نعناع Token-2022 (مع `TransferFeeConfig` اختياري). تتطلب جميع مسارات التهيئة الثلاثة تخرج CPMM.

عندما يرفق `InitializeWithToken2022` `TransferFeeConfig`، يتم إنشاء النعناع مع `transfer_fee_config_authority = authority` و `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`، مع الرجوع إلى `authority` عندما لم تحدد المنصة هذا الحقل. يتم إعادة تعيين كلا السلطتين إلى مفتاح المنصة عند التخرج، الجانب الانسحاب فقط إذا كان PDA لا يزال يحتفظ به. انظر [`platform-config`](/ar/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

نعناع الاقتباس مستقل عن نعناع الأساس وقد يكون بنفسه نعناع Token-2022 — يقبل `InitializeV2` و `InitializeWithToken2022` أي برنامج في فتحة برنامج الاقتباس الخاصة بهما. لا يفعل `Initialize` المهجور: حساب برنامج الاقتباس الخاص به لا يزال مكتوباً إلى SPL Token، لذا يمكن فقط إطلاق إعدادات نعناع الاقتباس Token-2022 من خلال الاثنين الآخرين. لا يتم إنشاء نعناع الاقتباس بواسطة LaunchLab؛ إنه ما يسميه `GlobalConfig.quote_mint`. انظر [`global-config`](/ar/products/launchlab/global-config#token-2022-quote-mints) و [`reference/token-2022-support`](/ar/reference/token-2022-support#launchlab-quote-mints).

## الخزائن

كل من `base_vault` و `quote_vault` عبارة عن حسابات رموز يملكها LaunchLab `authority` PDA، تم إنشاء كل منها على البرنامج الذي يمتلك نعناعه الخاص — لذا يمكن لإطلاق أن يكون لديه خزانة أساس قديمة وخزانة اقتباس Token-2022، أو أي مزيج آخر. يسجل `token_program_flag` أي منها. يتم تخزين العناوين على `PoolState` ويمكن أيضاً اشتقاقها:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(تحقق من بادئات البذور الدقيقة من بنية حسابات `Initialize` في المصدر قبل الاعتماد على الاشتقاق في الإنتاج.)

## خزائن الرسوم

يجمع PDA اثنان الرسوم عبر الإطلاقات:

- **خزانة رسوم المنشئ** — PDA في البذور `[creator, quote_mint]`. كل إطلاق يكسب رسوم منشئ على نفس نعناع الاقتباس يصب في نفس الخزانة. يكتسحها المنشئ عبر `ClaimCreatorFee`.
- **خزانة رسوم المنصة** — PDA في البذور `[platform_config, quote_mint]`. كل إطلاق يتم توجيهه عبر نفس المنصة التي تستخدم نفس نعناع الاقتباس يصب في نفس الخزانة. يكتسح `platform_fee_wallet` للمنصة عبر `ClaimPlatformFeeFromVault`. هناك أيضاً متغير كنس لكل إطلاق (`ClaimPlatformFee`) يسحب من `quote_vault` للإطلاق مباشرة دون المرور عبر الخزانة المجمعة.

يتم إنشاء كلاهما بكسل على أول مبادلة تتراكم رسوماً، على أي برنامج يمتلك نعناع الاقتباس. ينتهي المنشئ أو المنصة التي تشغل إطلاقات ضد كل من نعناع اقتباس قديم و Token-2022 بخزانة واحدة لكل نعناع، كما فعلت بالفعل لنعناعين قديمين مختلفين.

نمط الخزانة المجمعة هو ما يسمح لمنشئ أو منصة عالية الحجم بإطفاء تكلفة الإيجار لتراكم الرسوم عبر العديد من الإطلاقات.

## Quote vault ↔ `real_quote`

يجب أن يبقى `quote_vault.balance` و `PoolState.real_quote` متزامنين. يمكنهما الانجراف بحد أقصى مجموع عدادات الرسوم الثلاثة المعلقة (`quote_protocol_fee`، `platform_fee`، `migrate_fee`)، التي تجلس في الخزانة لكنها تنتمي إلى عدادات الرسوم وليس احتياطي المنحنى. تستخدم رياضيات المنحنى دائماً `real_quote`، أبداً رصيد الخزانة الخام.

ثابت قبل التخرج:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## انتقالات دورة حياة الحساب

| الحدث | الحالة | `real_base` | `real_quote` | تجمع ما بعد التخرج |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (أو `MigrateToAmm` القديم) | Funding → Migrate → Migrated | (مجمد) | (مجمد) | تم الإنشاء؛ يتم تقسيم LP من CPMM إلى LP مقفول مملوك للمنصة و LP محروق |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | أي | — | — | يستنزف خزانة رسوم |
| `CreateVestingAccount` | Funding | — | — | يرفع `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated فقط | — | — | يستنزف `base_vault` |
