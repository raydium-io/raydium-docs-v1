<Info>
  `PlatformConfig` هو **طبقة التراكب على مستوى المنصة** التي تقع فوق [`GlobalConfig`](/ar/products/launchlab/global-config). بينما يحدد `GlobalConfig` القواعد على مستوى البروتوكول ("رسم التداول 1%، يجب أن يكون الإمداد 10 مليون على الأقل، فقط هذا المحفظة يمكنها التخرج")، `PlatformConfig` هو ما تستخدمه كل منصة إطلاق — pump.fun، واجهة Raydium الخاصة، منصات الإطلاق من جهات خارجية — لإضافة رسمها، والمطالبة بحصتها من LP بعد التخرج، وتقييد أشكال المنحنيات التي يمكن لعمليات الإطلاق الخاصة بها أن تختارها، وعرض علامتها التجارية (الاسم، الموقع الإلكتروني، الصورة) على السلسلة.
</Info>

## ما هو

حساب `PlatformConfig` يمتلك خمس مخاوف متقاطعة لمنصة:

1. **العلامة التجارية** — الاسم، الموقع الإلكتروني، رابط الصورة، كل شيء مخزن بشكل مضمن بحيث يمكن لأي مستكشف أو معالج بيانات عرض المنصة التي أطلقت رمزًا.
2. **رسم المنصة** — رسم تداول إضافي (`fee_rate`) بالإضافة إلى `trade_fee_rate` الخاص بالبروتوكول. يتراكم في `platform_fee_wallet` الخاص بالمنصة. محدود بـ 500 bps (`50000`) على كل من مسار الإنشاء والتحديث، تم رفعه من 100 bps (`10000`) في 2026-08-26 — انظر [حدود الأسعار](#rate-caps).
3. **تقسيم هجرة LP** — ثلاثة أعداد صحيحة مخزنة (`platform_scale`, `creator_scale`, `burn_scale`) تجمع إلى `1_000_000`. قبل ترقية 2026-08-17، كان مقياس المنشئ ينتج مفتاح رسم منفصل للمنشئ. الهجرات المنفذة بعد الترقية تجمع الاثنين الأولين في حصة LP مقفلة مملوكة للمنصة؛ الباقي يتم حرقه.
4. **قائمة بيضاء لمعاملات المنحنى** — `Vec<PlatformCurveParam>` يسرد بالضبط أي مجموعات `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)` مسموحة على هذه المنصة. إذا كان المتجه فارغًا أو جميع الإدخالات غير صالحة، **أي** مجموعة مسموحة؛ وإلا يجب أن تطابق عمليات الإطلاق أحد الإدخالات بالضبط.
5. **قائمة بيضاء للتكوين العام** — تقييد اختياري يتطلب `PlatformAllowConfig` تم إنشاؤه بواسطة المنصة للـ `GlobalConfig` المختار.

اشتقاق PDA:

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // platform's owning pubkey
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

(انظر `create_platform_config` في المصدر للحصول على قائمة البذور الموثوقة.)

## التخطيط

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (denominator 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (denominator 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // signs ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // receives the platform NFT slice at CPMM graduation
    pub platform_scale:              u64,               // share of LP minted to platform NFT
    pub creator_scale:               u64,               // creator share before upgrade; added to platform share afterward
    pub burn_scale:                  u64,               // share of LP burned permanently
    pub fee_rate:                    u64,               // platform's trade fee (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 padded with zeros
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig that the post-grad pool will bind to
    pub creator_fee_rate:            u64,               // creator-side fee taken pre-graduation
    pub transfer_fee_extension_auth: Pubkey,            // for Token-2022 launches: withdraw-withheld authority from mint creation, fee-config authority from graduation
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // platform's slice of total_locked_amount
    pub platform_cp_creator:         Pubkey,            // optional creator-of-record on the post-graduation CPMM pool
    pub restrict_global_config:      u8,                // 0 = unrestricted, 1 = require allow PDA
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // whitelist of permitted curve shapes
}
```

يجب أن يساوي `platform_scale + creator_scale + burn_scale` قيمة `1_000_000`. قبل ترقية 2026-08-17، كان `creator_scale` مقفولًا بشكل منفصل وذهب مفتاح الرسم الخاص به إلى منشئ الرمز. بالنسبة للهجرات المنفذة بعد الترقية، يتم إضافته إلى `platform_scale` وتذهب حقوق LP المقفلة إلى المنصة بدلاً من ذلك. أمثلة على النتائج بموجب المنطق المحدث:

- `(0, 100_000, 900_000)` — 90% LP محروق، 10% مقفول للمنصة.
- `(50_000, 100_000, 850_000)` — 85% محروق، 15% مقفول للمنصة.
- `(0, 0, 1_000_000)` — حرق كامل، لا توجد عملات NFT. عمليات إطلاق صارمة "بدون مطلعين".

## حقول العلامة التجارية

`name` و `web` و `img` عبارة عن مصفوفات بايت مضمنة مملوءة بأصفار حتى ثوابتها. لقراءتها كسلاسل، قم بالتقطيع حتى أول `\0`:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

الثوابت متحفظة عن قصد (`name: 64`, `web: 256`, `img: 256`) بحيث يمكن للمنصات تضمين بيانات وصفية كافية للمستكشفات ومعالجات البيانات دون لمس التخزين خارج السلسلة. أي شيء يتجاوز هذه الأحجام سيعود عند `CreatePlatformConfig` مع `InvalidInput`.

## ميكانيكا الرسوم

يفرض التبديل على منحنى مرتبط بـ `PlatformConfig` ثلاث رسوم متعددة الطبقات:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` يتراكم في `protocol_fee_owner` الخاص بالبروتوكول (يتم المطالبة به عبر `CollectFee`).
- `platform_fee` يتراكم في خزينة لكل منصة (يتم المطالبة به عبر `ClaimPlatformFee` أو `ClaimPlatformFeeFromVault`؛ انظر [`instructions`](/ar/products/launchlab/instructions)).
- `creator_fee` يتراكم في خزينة لكل منشئ مفتاح بواسطة المفتاح العام للمنشئ + عملة الاقتباس (يتم المطالبة به عبر `ClaimCreatorFee`).

### حدود الأسعار

كلا المعدلين مقومان بـ `1/1_000_000`، لذا `5000` هو 50 bps و `50000` هو 500 bps.

| المعدل | الحد | مفروض في |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` عند الإنشاء — يعود مع `InvalidInput`. `update_platform_fee_rate` عند كل متغير تحديث يلمسه (`FeeRate` و `AllInfo`) — يعود مع `InvalidPlatformInfo`. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` عند الإنشاء و `update_creator_fee_rate` عند التحديث — كلاهما يعود مع `InvalidPlatformInfo`. |

نقطتا الإنفاذ لـ `fee_rate` عبارة عن استدعاءات `require!` منفصلة في ملفات مختلفة، لذا تحمل رموز خطأ مختلفة، لكنها تطبق نفس السقف. يمكن تحرير منصة تم إنشاؤها بأي معدل مسموح به لاحقًا، بما في ذلك من خلال متغير `AllInfo` الشامل الذي يعيد كتابة كل حقل في وقت واحد.

كانت حدود `fee_rate` الأصلية 100 bps (`10000`). تم نقل حد التحديث إلى `25000` (250 bps) في 2026-01-27؛ في 2026-08-26 انتقل كلاهما إلى `50000` (500 bps) — انظر [إدخال السجل](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` **لا** يحد أي من المعدلين. يحد معدل `share_fee_rate` لكل معاملة الذي تأخذه تعليمات المبادلة الأربع — رسم الإحالة — وليس شيء آخر. انظر [`global-config`](/ar/products/launchlab/global-config#fees).

## سلطات نقل Token-2022

`transfer_fee_extension_auth` يسمي مفتاح المنصة الذي ينتهي به الحال بحيازة سلطات `TransferFeeConfig` الخاصة بـ mint الأساسي عند إنشاء إطلاق من خلال `InitializeWithToken2022` مع رسم نقل مرفق. يحمل الامتداد سلطتين، ويتم تسليمهما في **نقاط مختلفة في دورة حياة الإطلاق**:

| السلطة | الحامل عند إنشاء mint | الحامل بعد `MigrateToCpswap` |
|---|---|---|
| `withdraw_withheld_authority` — تسحب الرسوم التي يحتفظ بها Token-2022 على حسابات الرموز | `transfer_fee_extension_auth`، مكتوب مباشرة في mint. يعود إلى PDA `authority` الإطلاق عندما يكون الحقل `Pubkey::default()`. | بالفعل مفتاح المنصة، لذا لا شيء يتحرك. يعيد التخصيص فقط عندما يحتفظ PDA `authority` به. |
| `transfer_fee_config_authority` — يغير معدل الرسم والحد الأقصى للرسم | دائمًا PDA `authority` الإطلاق. | `transfer_fee_extension_auth`، بشرط أن يكون هذا الحقل غير افتراضي. |

قبل 2026-08-27 تم إنشاء mint مع PDA `authority` على كلا السلطتين، وانتقل كلاهما إلى المنصة عند التخرج. البرنامج لا يعرض أي تعليمات سحب محتفظ به أو حصاد، لذا كانت الرسوم المحتفظ بها أثناء مرحلة منحنى الترابط غير قابلة للوصول حتى تخرج الإطلاق. كتابة جانب السحب عند إنشاء mint يجعلها قابلة للمطالبة من أول تداول — انظر [إدخال السجل](/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority).

هناك عاقبتان تستحقان التخطيط:

- **اضبط الحقل قبل الإطلاق، وليس بعده.** إطلاق تم إنشاؤه بينما `transfer_fee_extension_auth` هو `Pubkey::default()` يضع PDA `authority` على جانب السحب. تعيين الحقل لاحقًا لا يزال يعمل — التخرج يجد PDA في المكان ويسلم السلطة — لكن لا شيء يمكنه سحب الرصيد المحتفظ به في الوقت الفاصل.
- **تدوير الحقل في منتصف الإطلاق يقسم السلطتين.** غير `transfer_fee_extension_auth` بين إنشاء الإطلاق وتخرجه وسلطة السحب المحتفظ بها في mint تبقى مع المفتاح المكون عند الإنشاء (PDA لم يعد يحتفظ به، لذا يتخطى الهجرة هذا التسليم) بينما تذهب سلطة تكوين الرسم إلى المفتاح الجديد. قم بالتدوير بين عمليات الإطلاق، أو خطط للتوفيق بين المفتاحين بنفسك من خلال Token-2022 مباشرة.

منصة تترك الحقل في `Pubkey::default()` لحياة الإطلاق بأكملها تحتفظ بكلا السلطتين على PDA `authority` بشكل دائم: لا يمكن تغيير معدل الرسم ولا يمكن سحب الرصيد المحتفظ به. قم فقط بإرفاق رسم نقل بإطلاق إذا كانت المنصة تنوي الاحتفاظ بهذه المفاتيح.

## تقسيم هجرة NFT (CPMM فقط)

عندما يتخرج إطلاق إلى CPMM، تقسم تعليمات الهجرة رموز LP التي تم سكها بواسطة `CPMM::InitializeWithPermission` بطريقتين:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

إذا كان `lp_to_platform` غير صفري، يقوم برنامج LP-Lock بلفه إلى رمز NFT مفتاح رسم واحد مملوك لـ `platform_nft_wallet`. هذا يحل محل السلوك السابق للترقية الذي أنشأ مفاتيح رسم منفصلة للمنصة والمنشئ. تبقى مفاتيح الرسم التي تم إنشاؤها بواسطة الهجرات المكتملة قبل الترقية دون تغيير. هذا الحق في رسم LP منفصل عن رسوم منشئ CPMM التي يتحكم فيها `platform_cp_creator`.

يتم حرق شريحة الحرق مباشرة، لذا لا يمكن لأي حساب سحبها أو المطالبة برسوم LP التي تمثلها تلك الحصة.

عمليات الإطلاق الموجودة مع `migrate_type = 0` المخزنة يمكنها لا تزال استخدام مسار AMM v4 القديم. يرفض الإنشاء الجديد نوع الهجرة هذا.

## قائمة بيضاء لمعاملات المنحنى

`curve_params: Vec<PlatformCurveParam>` هي آلية المنصة لتقييد أشكال المنحنيات التي يمكن لعمليات الإطلاق الخاصة بها أن تختارها. إذا كان المتجه غير فارغ وكان هناك إدخال واحد على الأقل صالحًا، يفرض البرنامج عند `Initialize` أن معاملات الإطلاق تطابق إدخالاً واحدًا على الأقل بالضبط.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // ordinal within this platform's whitelist
    pub global_config:        Pubkey,       // which GlobalConfig this entry applies to
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // new launches require 1 = CPMM; u8::MAX = wildcard
    pub migrate_cpmm_fee_on:        u8,    // 0 = quote-only, 1 = both. u8::MAX = wildcard
    pub supply:                     u64,   // 0 = wildcard
    pub total_base_sell:            u64,   // 0 = wildcard
    pub total_quote_fund_raising:   u64,   // 0 = wildcard
    pub total_locked_amount:        u64,   // u64::MAX = wildcard
    pub cliff_period:               u64,   // u64::MAX = wildcard
    pub unlock_period:              u64,   // u64::MAX = wildcard
}
```

كل حقل له قيمة حارسة تعني **wildcard** (أي قيمة تطابق): `u64::MAX` للحقول `u64`، `u8::MAX` للحقول `u8`، `0` لحقول الإمداد / البيع / جمع التمويل. `BondingCurveParam` مع جميع الحراس هو "السماح بأي شيء" — مكافئ لسلوك القائمة البيضاء الفارغة.

خوارزمية المطابقة عند `Initialize`:

1. تصفية `curve_params` إلى الإدخالات التي يطابق `global_config` فيها `GlobalConfig` المختار للإطلاق.
2. إذا كانت القائمة المصفاة فارغة، السماح بأي معاملات (لم تقم المنصة بإدراج أي شيء في القائمة البيضاء لهذا `GlobalConfig`).
3. إذا كان كل إدخال في القائمة المصفاة يحتوي على `all_is_invalid()` (كل حقل هو wildcard)، السماح بأي معاملات.
4. وإلا كرر الإدخالات؛ لكل إدخال، تحقق من معاملات الإطلاق مقابل كل حقل غير wildcard. إذا طابقت جميع الحقول غير wildcard، اقبل وعد.
5. إذا لم يطابق أي إدخال، عد مع `InvalidInput`.

هذا يسمح لمنصة بالقول "نحن نسمح فقط بشكل الإمداد القياسي 1B / 800M-sold / 30k-USDC-raise / no-vesting" بكتابة إدخال واحد بقيم ملموسة لتلك الحقول الأربعة و wildcards في كل مكان آخر. أو قد تقوم منصة أكثر صرامة بتعداد ثلاثة أو أربعة أشكال منفصلة، واحد لكل مستوى إطلاق مدعوم.

`MAX_CURVE_PARAMS = 10` يحد حجم القائمة البيضاء.

## `PlatformAllowConfig` — تقييد منصة

تقرر كل منصة ما إذا كانت ستقيد أي حسابات `GlobalConfig` قد تستخدمها عمليات الإطلاق الخاصة بها. اضبط `restrict_global_config` مع `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)`.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

بذور PDA: `[b"platform_allow_config", platform_config, global_config]`.

يقوم مسؤول المنصة بإنشاء أو إغلاق حساب واحد لكل زوج مسموح به عبر `CreatePlatformAllowConfig` و `ClosePlatformAllowConfig`. عندما يكون التقييد `1`، يبحث الإنشاء في `remaining_accounts` عن PDA المتوقع ويرفض حساب مفقود مع `NotEnoughRemainingAccounts`. عندما يكون التقييد `0`، لا يلزم حساب السماح.

حساب `PlatformGlobalAccess` المُدار من قبل مسؤول البروتوكول السابق وتعليمات الإنشاء / الإغلاق الخاصة به متقاعدة. أحجام `PlatformConfig` و `GlobalConfig` الموجودة لا تتغير، لكن يجب على فك التشفير استبدال العلم العام القديم بالعلم الجديد للمنصة. لا يتم استهلاك PDAs الوصول القديمة بواسطة الفحص الجديد.

## مسار القراءة

```ts
const platformConfig = await raydium.launchpad.getPlatformConfig(platformConfigPda);

console.log("Platform:", readString(platformConfig.name));
console.log("Fee rate:", platformConfig.feeRate, "(/1M)");
console.log("NFT split:",
  platformConfig.platformScale,
  platformConfig.creatorScale,
  platformConfig.burnScale,
);
console.log("Curve whitelist size:", platformConfig.curveParams.length);
```

بالنسبة لواجهة مستخدم تعرض "من أين تم إطلاق هذا الرمز"، `PoolState.platform_config` يشير إلى `PlatformConfig` الأصلي مباشرة — قم بجلبه مرة واحدة وخزن العلامة التجارية.

## مسار التحديث

| التعليمة | من يوقع | ما يتغير |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | مسؤول المنصة (مرة واحدة) | يهيئ الحساب مع `PlatformParams`. |
| `UpdatePlatformConfig` | مسؤول المنصة | إرسال عام مفتاح بـ `param: u8`؛ يغير حقل واحد لكل استدعاء، أو كل حقل في وقت واحد عبر `AllInfo`. حقول العلامة التجارية ومعدلات الرسوم ومحفظة التوزيع المرحلي والمحافظ المختلفة كلها قابلة للتعيين من خلال هذا. يتم إعادة التحقق من كلا معدلات الرسوم مقابل الحدود في [حدود الأسعار](#rate-caps) عند كل متغير يلمسهما. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | مسؤول المنصة | إضافة أو إزالة `GlobalConfig` واحد مسموح به لهذه المنصة. |
| `UpdatePlatformCurveParam` | مسؤول المنصة | إضافة أو استبدال إدخال `PlatformCurveParam` واحد بـ `(global_config, index)`. |
| `RemovePlatformCurveParam` | مسؤول المنصة | مسح إدخال واحد (تعيينه إلى جميع الحراس = wildcard). |
| `ClaimPlatformFee` | `platform_fee_wallet` | كنس رسم المنصة لكل مجموعة من `PoolState.quote_vault`. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | كنس خزينة رسم المنصة لكل منصة (PDA في `[platform_config, quote_mint]`). |

تدويرات المحفظة (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) كلها تمر عبر `UpdatePlatformConfig`. اقرأ جدول إرسال `update_platform_config` في المصدر للحصول على رموز `param` الدقيقة.

## الأخطاء الشائعة

- **حراس القائمة البيضاء غير محددة بشكل صحيح.** `BondingCurveParam` مع `total_locked_amount = 0` **ليس** wildcard — يطابق عمليات الإطلاق التي تختار بشكل صريح عدم الاشتراك في التوزيع المرحلي. wildcard لهذا الحقل هو `u64::MAX`. نفس الفخ موجود لـ `cliff_period` و `unlock_period`. استخدم `clear()` (الذي يعرضه البرنامج) لتعيين الحراس بشكل صحيح.
- **تقريب تقسيم NFT.** يجب أن تجمع المقاييس الثلاثة إلى `1_000_000` بالضبط. أخطاء الفارق الواحد عند `CreatePlatformConfig` تعود؛ الفارق الواحد في وقت التشغيل سيسك أو يحرق وحدة LP إضافية واحدة، وهذا ما يوجد فحص المساواة الصارمة لمنعه.
- **تخصيص التوزيع المرحلي المزدوج للمنصة.** إذا كان `platform_vesting_scale > 0`، يجب على المنصة استدعاء `CreatePlatformVestingAccount` مرة واحدة بعد انتهاء جمع التمويل للإطلاق؛ إذا نسيت، تبقى تلك الحصة غير مخصصة وخاملة إلى الأبد (يتم استهلاك ميزانية `total_locked_amount` للإطلاق لكن المنصة لا تطالب أبدًا).
- **غموض `platform_cp_creator`.** عند التعيين إلى `Pubkey::default()`، يتم تسجيل منشئ الإطلاق كـ `pool_creator` لمجموعة CPMM بعد التخرج؛ عند التعيين إلى مفتاح حقيقي، يتم تسجيل هذا المفتاح بدلاً من ذلك. هذا يحدد المستفيد من رسوم منشئ CPMM بعد التخرج ومن يمكنه توقيع مسار `CPMM::CollectCreatorFee` الأصلي. مسار الجمع بدون إذن لا يزال يدفع ATAs الموثوقة لهذا المفتاح المسجل. قرر في وقت إنشاء تكوين المنصة أي نموذج تريد.
- **`transfer_fee_extension_auth` تم تعيينه في وقت متأخر أو تم تدويره.** يتم قراءة الحقل مرتين لكل إطلاق Token-2022 — مرة عند إنشاء mint لـ `withdraw_withheld_authority`، مرة عند التخرج لـ `transfer_fee_config_authority` — لذا قيمة تتغير بين تلك اللحظتين تترك السلطتين على مفاتيح مختلفة. انظر [سلطات نقل Token-2022](#token-2022-transfer-fee-authorities).
- **تقييد بدون حساب سماح.** تفعيل `restrict_global_config` قبل إنشاء `PlatformAllowConfig` المطلوب يحجب عمليات الإطلاق الجديدة التي تختار هذا التكوين.
