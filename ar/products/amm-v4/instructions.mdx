## `Initialize2`

بدء pool AMM v4 جديد مرتبط بسوق OpenBook موجود.

**المعاملات**

```
nonce:        u8
open_time:    u64
init_pc_amount:   u64
init_coin_amount: u64
```

**الحسابات** (قابلة للكتابة `W`، موقّع `S`)

| # | الاسم | W | S | ملاحظات |
|---|-------|---|---|---------|
| 1 | `token_program` |   |   | يُتحقق منه `== spl_token::id()`. |
| 2 | `associated_token_program` |   |   | يُستخدم لإنشاء ATA LP للمُنشئ. |
| 3 | `system_program` |   |   | |
| 4 | `rent` |   |   | لا يزال يُمرَّر إلى استدعاءات `initialize_account` / `initialize_mint` — لا تحذفه. |
| 5 | `amm` | W |   | PDA الخاص بـ `AmmInfo` وهو `[programId, market, "amm_associated_seed"]`؛ يُنشأ هنا. |
| 6 | `amm_authority` |   |   | PDA `["amm authority"]`؛ يجب أن تساوي وسيطة `nonce` قيمة bump الخاصة به. |
| 7 | `lp_mint` | W |   | PDA `[programId, market, "lp_mint_associated_seed"]`؛ يُنشأ هنا. |
| 8 | `coin_mint` |   |   | يجب أن يختلف عن `pc_mint` (`InvalidCoinMint`). |
| 9 | `pc_mint` |   |   | |
| 10 | `pool_coin_token_account` | W |   | PDA `[programId, market, "coin_vault_associated_seed"]`. |
| 11 | `pool_pc_token_account` | W |   | PDA `[programId, market, "pc_vault_associated_seed"]`. |

| 13 | `amm_config` |   |   | PDA التكوين على مستوى البرنامج `["amm_config_account_seed"]`؛ `InvalidConfigAccount` عند عدم التطابق. |
| 14 | `create_fee_destination` | W |   | يجب أن يساوي `config_feature::create_pool_fee_address`؛ وإلا `InvalidFee`. |
| 15 | `market` |   |   | لا يُتحقق منه — يُستخدم فقط كبذرة متغيرة لكل PDA أعلاه، ويُخزَّن كحقل مرجعي. |
| 16 | `user_wallet` | W | S | المُنشئ. يدفع الإيجار ورسم إنشاء التجمع والإيداع الأولي. |
| 17 | `user_token_coin` | W |   | |
| 18 | `user_token_pc` | W |   | |
| 19 | `user_token_lp` | W |   | ATA LP للمُنشئ؛ يُنشئه البرنامج. |

<Note>
  **تخطيطان مقبولان.** قائمة الـ 19 حسابًا أعلاه هي الموصى بها. من أجل التوافق مع الإصدارات
  السابقة يقرأ البرنامج أيضًا تخطيطًا قديمًا من 21 حسابًا، يُدرج `amm_open_orders` مُتجاهلًا في
  الموضع 7 و `market_program` مُتجاهلًا في الموضع 16 — وهذا ما لا يزال بانِي تعليمة `initialize2`
  الموجود في المستودع يُصدره. أي طول آخر يُحلَّل موضعيًا مقابل التخطيط القديم وسيفشل.
</Note>

**الشروط اللاحقة**

- LP المُصدَر للمُنشئ = `sqrt(init_coin_amount × init_pc_amount) − 10^coin_mint.decimals`. تساوي منازل LP العشرية `coin_mint.decimals`، لذا فالمقدار المطروح هو رمز LP كامل واحد بالضبط؛ لا يُصدر أبدًا ويبقى خارج التداول بشكل دائم. إذا كان `sqrt(...)` أقل من ذلك، تُرجع التعليمة الخطأ `InitLpAmountTooLess`.
- يخزّن `AmmInfo.lp_amount` قيمة `sqrt(...)` الكاملة، **وليس** المقدار المُصدَر — لذا فإن `lp_mint.supply` أقل بشكل دائم بمقدار رمز LP كامل واحد من `amm.lp_amount`. كل الحسابات التناسبية تستخدم `amm.lp_amount`.
- لا يتم نشر أوامر OpenBook (تم إزالة شبكة دفتر الطلبات). يسجّل `AmmInfo.market` الحساب المُمرَّر في الخانة 15، لكن يُكتب كل من `AmmInfo.open_orders` و `AmmInfo.market_program` بالقيمة `Pubkey::default()`، ويتم تهيئة `coin_lot_size` / `pc_lot_size` / `min_size` إلى `0`. في التخطيط القديم المكوّن من 21 حسابًا يُقرأ الحسابان الإضافيان `amm_open_orders` و `market_program` ثم يُهملان.

**الأخطاء الشائعة** — `InvalidCoinMint` (عملة coin و pc متطابقتان)، `InvalidConfigAccount` (PDA خاطئ لـ `amm_config`)، `InvalidFee` (وجهة خاطئة لرسم إنشاء التجمع)، `InvalidProgramAddress` (`amm_authority` خاطئ أو `nonce` خاطئ)، `RepeatCreateAmm` (يوجد تجمع لهذا السوق بالفعل)، `InitLpAmountTooLess`، `InvalidSupply` (أحد مقداري التهيئة `0`، أو أن عملة LP لديها عرض بالفعل)، `AlreadyInUse`.

## `SwapBaseIn`

مبادلة بمدخل دقيق. دائمًا مبادلة **مسار AMM** (لا تسير عبر مطابقة OpenBook).

<Note>
  **استخدم متغيرات V2 للكود الجديد.** نظرًا لأنه تم إزالة اعتماد AMM v4 على OpenBook، لا تزال نقاط الدخول V1 (`SwapBaseIn`، `SwapBaseOut`) تتوقع قائمة الحسابات الكاملة المكونة من 17 حسابًا (أو 18 مع حساب target-orders الاختياري)، لكن حسابات OpenBook/market الآن **مقبولة بشكل موضعي ومُتجاهلة** — لا يتم التحقق منها ولا يتم إصدار CPI. لا يزال تمرير عدد حسابات خاطئ يعود مع `WrongAccountsNumber`، لكن محتويات حساب السوق لم تعد يتم التحقق منها. يجب على التكاملات الجديدة استخدام [`SwapBaseInV2` / `SwapBaseOutV2`](#swapbaseinv2-/-swapbaseoutv2)، التي تأخذ قائمة حسابات أصغر بكثير وتمثل مسار التنفيذ الكنسي اليوم. يتم توثيق النماذج V1 هنا للاكتمال وللقراءة من المعاملات على السلسلة الموجودة.
</Note>

**المعاملات**

```
amount_in:            u64
minimum_amount_out:   u64
```

**الحسابات** (مختصرة)

| # | الاسم | W | S |
|---|-------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `amm_open_orders` | W |   |
| 5 | `amm_target_orders` | W |   |
| 6 | `pool_coin_token_account` | W |   |
| 7 | `pool_pc_token_account` | W |   |
| 8 | `market_program` |   |   |
| 9 | `market` | W |   |
| 10 | `market_bids` | W |   |
| 11 | `market_asks` | W |   |
| 12 | `market_event_queue` | W |   |
| 13 | `market_coin_vault` | W |   |
| 14 | `market_pc_vault` | W |   |
| 15 | `market_vault_signer` |   |   |
| 16 | `user_source_token_account` | W |   |
| 17 | `user_dest_token_account` | W |   |
| 18 | `user_owner` |   | S |

**الرياضيات** — انظر [`products/amm-v4/math`](/ar/products/amm-v4/math).

**الشروط السابقة**

- `AmmStatus::from_u64(amm.status).swap_permission()` صحيحة — أي أن `status` هي `1` (`Initialized`) أو `6` (`SwapOnly`) أو `7` (`WaitingTrade`). فـ `status` قيمة تعدادية وليست bitmask؛ انظر [`products/amm-v4/accounts`](/ar/products/amm-v4/accounts#status).
- `amm.state_data.pool_open_time <= now`.
- `amount_in > 0`.
- `user_source_token_account` يحتفظ بـ `amount_in` على الأقل.

**الشروط اللاحقة**

- يفقد المستخدم `amount_in` من الرمز المصدر، ويكسب `amount_out ≥ minimum_amount_out` من رمز الوجهة.
- يبقى رسم المبادلة في الخزائن، مما يرفع الثابت `k`. وعدادات `need_take_pnl_*` **لا** تتأثر بالمبادلات — يُعاد حساب PnL البروتوكول من دلتا `k` عند أول `Deposit` أو `Withdraw` أو `WithdrawPnl` تالية (`Processor::calc_take_pnl`).
- ملاحظة: عدادات التحليلات `state_data.swap_*_in_amount` / `swap_*_out_amount` **لم تعد يتم تحديثها** — قيمها مجمدة. استخدم سجلات التداول لتحليلات الحجم.

**الأخطاء الشائعة** — `ExceededSlippage`، `InvalidInput`، `InvalidStatus`، `NotAllowed` (رمز coin/pc متطابق).

## `SwapBaseInV2` / `SwapBaseOutV2`

نقاط دخول مبادلة متغيرة (الوسوم **16** / **17**) التي **تتخطى حسابات OpenBook بالكامل**. الرياضيات متطابقة مع مسار V1، لكن قائمة الحسابات تنكمش إلى جانب AMM والمستخدم فقط — **8 حسابات، و `amm_open_orders` لا يتم تمريره**:

| # | الاسم | W | S |
|---|-------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `pool_coin_token_account` | W |   |
| 5 | `pool_pc_token_account` | W |   |
| 6 | `user_source_token_account` | W |   |
| 7 | `user_dest_token_account` | W |   |
| 8 | `user_owner` |   | S |

احتياطيات Pool الآن هي أرصدة الأقبية (ناقص PnL المعلق)، لذا فإن رياضيات الاقتباس مباشرة ومتطابقة مع مسار v1. استخدم V2 لتوفير الحساب وتجنب تمرير حسابات السوق (المُتجاهلة الآن). يستخدم موجه Raydium دائمًا نموذج V2 عند التوجيه عبر AMM v4.

المعاملات هي نفسها نماذج V1 (`amount_in / minimum_amount_out` لـ `SwapBaseInV2`؛ `max_amount_in / amount_out` لـ `SwapBaseOutV2`).

## `MonitorStep` والتعليمات المحذوفة الأخرى

<Warning>
  **تم إزالتها — لم تعد قابلة للاستدعاء.** اعتبارًا من ترقية 2026-07، تم إزالة `MonitorStep` (الوسم 2) من البرنامج والآن **يعود** (`unimplemented!`) إذا تم استدعاؤه. تم حذف منشئ العميل الخاص به أيضًا. ينطبق الشيء نفسه على `MigrateToOpenBook` (5)، `WithdrawSrm` (8)، `SimulateInfo` (12)، `AdminCancelOrders` (13)، ونقاط دخول إنشاء pool القديمة `Initialize` (0) / `PreInitialize` (10) — استخدم `Initialize2` بدلاً من ذلك.
</Warning>

تاريخيًا، كان `MonitorStep` يدير تفاعل pool مع OpenBook: كان يسوي الأوامر المملوءة (نقل العائدات من أقبية السوق إلى أقبية pool عبر OpenBook CPI)، وإلغاء الأوامر القديمة، ونشر أوامر جديدة لإغلاق الفجوة بين `target_orders` و `amm_open_orders`. مع إزالة اعتماد OpenBook، لا يوجد شيء للإدارة والتعليمة اختفت. يجب على أي حارس أو تكامل لا يزال يستدعيه إزالة الاستدعاء.

## `WithdrawPnl` / `TakePnl`

تجميع إداري لرسوم البروتوكول المتراكمة.

**المعاملات**

- `WithdrawPnl` لا تأخذ أي معاملات؛ تقرأ `need_take_pnl_*` وتنقل تلك المبالغ بالضبط.

<Warning>
  **كسر التوافقية (إدارة فقط).** انخفضت قائمة الحسابات من 17 (+1 اختياري) إلى **10** — تم إزالة `amm_open_orders` وجميع حسابات السوق الستة — **بدون تحليل توافقية**. التخطيط القديم لا يتطابق (كان #5 القديم `amm_open_orders`، الآن `pool_coin_token_account`) ويفشل مع أخطاء مثل `InvalidCoinVault`. يجب تحديث أدوات الإدارة.
</Warning>

## `SetParams`

تغييرات معاملات الإدارة، يستدعيها multisig Raydium. المعاملات هي وسم `param: u8` + حمولة.

<Warning>
  **كسر التوافقية (إدارة فقط).** تم تقليل قائمة الحسابات إلى مجرد `[amm (W)، admin (S)]` (تم إزالة السلطة، open-orders، target-orders، vault، وجميع حسابات السوق). تم **إعادة ترقيم واختصار** enum `param`: `Status` = 0، `State` = 1، `Fees` = **2** (كان 9)، `SetOpenTime` = **3** (كان 11). تم إزالة جميع معاملات شبكة دفتر الطلبات و `AmmOwner`، `LastOrderDistance`، `UpdateOpenOrder`، وأسقطت struct `SetParamsInstruction` `new_pubkey` و `last_order_distance`. يجب تحديث أدوات الإدارة.
</Warning>

## `CreateConfigAccount` / `UpdateConfigAccount`

إدارة إدارية لـ `AmmConfig` PDA على مستوى البرنامج (البذرة `["amm_config_account_seed"]`). يحتفظ الحساب بثلاثة حقول ذات معنى فقط — `pnl_owner` و `cancel_owner` و `create_pool_fee` — بالإضافة إلى منطقتَي حشو محجوزتين؛ ولا يوجد علم لإنشاء التجمعات. تعيّن `UpdateConfigAccount` الحقل `pnl_owner` بـ `param = 0`، و `cancel_owner` بـ `param = 1`، و `create_pool_fee` بـ `param = 2`.

<Note>
  **تغيرت في 2026-09، وتوافقية عكسية.** لم تعد `CreateConfigAccount` تقرأ sysvar الإيجار. قائمة حساباتها الآن **4 حسابات**، انخفاضًا من 5:

  | # | الاسم | W | S |
  |---|-------|---|---|
  | 1 | `admin` | W | S |
  | 2 | `amm_config` | W |   |
  | 3 | `pnl_owner` |   |   |
  | 4 | `system_program` |   |   |

  يقرأ البرنامج معاملات الإيجار من `Rent::get()` بدلاً من فك تسلسل حساب sysvar الذي تم تمريره — ما جعلته طبيعيًا اعتماد Solana 3.0.

  الحساب المحذوف كان **الأخير** في القائمة، والمعالج يقرأ حساباته بشكل موضعي عبر `next_account_info` بدون فحص الطول. لذلك فإن أداة إدارة موجودة لا تزال تمرر قائمة الحسابات القديمة المكونة من 5 حسابات تستمر في العمل: حساب الإيجار الزائد لا يتم قراءته أبدًا. حدثه عند الراحة، وليس بشكل عاجل. `UpdateConfigAccount` لم يتغير.
</Note>

تحتفظ `Initialize2` بـ sysvar الإيجار في الموضع 3، و**تستخدمه** بالفعل: توقف البرنامج عن استدعاء `Rent::from_account_info` عليه، لكن لا يزال يتم تمريره إلى CPIs `spl_token::initialize_account` و `initialize_mint` التي تنشئ أقبية pool و LP mint. لا تحذفه من قائمة الحسابات.

## `WithdrawExcessLamports`

تجميع إداري لـ lamports الجالسة فوق الحد الأدنى المعفي من الإيجار على الحسابات التي يتحكم فيها البرنامج. تمت الإضافة في ترقية 2026-09 لاسترجاع الإفراط في التمويل الذي يتركه [SIMD-0437 rent reduction](/ar/solana-fundamentals/rent-and-reclaimable-rent) خلفه على الحسابات المُنشأة قبل كل خطوة.

ينقل الفائض فقط. أرصدة الرموز، بيانات الحساب، المالكون، وحالة pool لم تتغير، والتعليمة هي no-op على حساب بالفعل في الحد الأدنى — لذا فمن الآمن إطلاقها بشكل متكرر وأيضًا بعد كل خطوة طرح.

**المعاملات** — لا شيء. الحمولة هي بايت الوسم الفردي `18`.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|-------|---|---|---------|
| 1 | `collect_lamports` | W | S | الوجهة لكل lamport مُجمّع. يجب أن تساوي محفظة collect-lamports للعنقود — انظر [`reference/program-addresses`](/ar/reference/program-addresses#excess-lamports-collection-wallets). أي موقّع آخر يفشل مع `InvalidSignAccount`. |
| 2 | `amm_authority` |   |   | PDA سلطة AMM v4 الفردية، معاد اشتقاقها بواسطة البرنامج من `["amm authority"]` مع nonce ثابت من `254`. يوقّع CPIs برنامج الرموز. |
| 3 | `token_program` |   |   | **SPL Token.** يتم التحقق منه مقابل `spl_token::id()`؛ قيمة خاطئة تفشل مع `InvalidSplTokenProgram`. |
| 4.. | حسابات المصدر | W |   | `M` حسابات للتجميع، أي عدد، أي ترتيب. |

**كيفية التعامل مع كل حساب مصدر**

يقوم البرنامج بالتوزيع على `owner` حساب المصدر:

| مالك حساب المصدر | المعالجة |
|---|---|
| SPL Token، `data_len == 165` (حساب رمز)، غير أصلي | CPI `WithdrawExcessLamports` (مميز برنامج الرموز `38`)، موقّع بواسطة `amm_authority`. |
| SPL Token، `data_len == 165`، أصلي (wSOL) | لا يمكن استخدام `WithdrawExcessLamports` على حساب أصلي. يقوم البرنامج بـ CPI `SyncNative`، يقيس كم نما `amount` المُغلّف، `UnwrapLamports` (مميز `45`) لتلك الدلتا بالضبط، ثم يؤكد أن الرصيد المُغلّف عاد إلى قيمته السابقة للمزامنة — وإلا `LamportsCalculateError`. لذا فإن سيولة SOL الجانبية للـ pool لا تتأثر أبدًا. |
| SPL Token، أي حجم آخر (LP mint) | CPI `WithdrawExcessLamports`، موقّع بواسطة `amm_authority`. |
| برنامج AMM v4 نفسه (`AmmInfo`، `TargetOrders`، `AmmConfig`) | يقوم البرنامج بخصم الحساب مباشرة إلى `rent.minimum_balance(data_len)`. |
| أي شيء آخر | **تم تخطيه بصمت.** لا خطأ، لا lamports مُنقولة. |

**الأخطاء الشائعة** — `InvalidSignAccount` (موقّع خاطئ)، `InvalidSplTokenProgram` (برنامج خاطئ في الفتحة 3)، `InvalidProgramAddress` (`amm_authority` خاطئ)، `LamportsCalculateError` (كود مخصص `60`؛ رحلة wSOL ذهابًا وإيابًا لم تصل إلى صفر)، و `InsufficientFunds` من مسار البرنامج المملوك عندما يحتفظ حساب بأقل من حد الإيجار الخاص به.

**لا منشئ SDK.** لا تشحن `@raydium-io/raydium-sdk-v2` منشئًا لهذه التعليمة، ولا يفعل مستودع `raydium-sdk-V2-demo` — إنه مسار إدارة. قم بترميزه يدويًا، بالطريقة التي يفعلها تجميع الجانب المحفظة في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) لتعليمة برنامج الرموز.
