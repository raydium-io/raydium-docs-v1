## ملخص التعليمات

| اسم المميز | من يوقّع | ما تفعله |
|-------|-----------|--------------|
| `Initialize` | منشئ المجموعة | إنشاء مجموعة CPMM جديدة من عملتين و`AmmConfig`. بدون إذن؛ يمكن لأي شخص استدعاؤها. تُرمّز `enable_creator_fee = false` على المجموعة الجديدة. يمكن أن يكون حساب `pool_state` إما PDA القانوني أو مفتاح عشوائي جديد (انظر حسابات Initialize). |
| `InitializeWithPermission` | الدافع + حامل PDA `Permission` | نسخة مرخصة من `Initialize`. يجب على المستدعي (الدافع) أن يمتلك PDA `Permission` مشتقة من مفتاحه العام. تُستخدم من قبل المنصات التي تحتاج إلى إنشاء مجموعات محدودة (مثل تخريجات LaunchLab). تسمح للمستدعي بتثبيت `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) وتفرض `enable_creator_fee = true` على المجموعة الجديدة. يتم تعيين حقل `creator` على `pool_state` إلى حساب `creator` منفصل تم تمريره، وليس الدافع. نفس مرونة PDA القانوني أو المفتاح العشوائي لـ `pool_state` كما في `Initialize`. |
| `Deposit` | مزود السيولة | إضافة السيولة في كلا الرمزين؛ استقبال رموز LP. |
| `Withdraw` | مزود السيولة | حرق رموز LP؛ استقبال كلا الرمزين الأساسيين بنسبة. |
| `SwapBaseInput` | المتداول | مبادلة بمدخل دقيق (`amount_in` داخل، ≥ `minimum_amount_out` خارج). |
| `SwapBaseOutput` | المتداول | مبادلة بمخرج دقيق (≤ `maximum_amount_in` داخل، `amount_out` خارج). |
| `CollectProtocolFee` | `protocol_owner` (من `AmmConfig`) | تجميع الرسوم البروتوكولية المتراكمة من الخزائن. |
| `CollectFundFee` | `fund_owner` (من `AmmConfig`) | تجميع رسوم الصندوق المتراكمة من الخزائن. |
| `CollectCreatorFee` | `pool_creator` | تجميع رسوم المنشئ المتراكمة (إذا كانت رسوم المنشئ مفعلة). |
| `CollectCreatorFeePermissionless` | أي دافع | تجميع جميع رسوم المنشئ المتراكمة إلى حسابات الرموز القانونية لـ `pool_creator`. لا يمكن للدافع إعادة توجيه التحويل. |
| `UpdatePoolStatus` | `admin` | إيقاف / استئناف عمليات محددة على مجموعة عبر قناع بت. |
| `UpdateAmmConfig` | `admin` | تغيير معدلات الرسوم أو مالك البروتوكول/الصندوق على `AmmConfig`. |
| `CreateAmmConfig` | `admin` | إنشاء فئة رسوم جديدة (حساب `AmmConfig` جديد). |
| `CreatePermissionPda` | `admin` أو منشئ PDA إذن مفوض | سك PDA `Permission` يسمح لسلطة محددة باستدعاء `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` أو منشئ PDA الإذن المخصص | إلغاء PDA `Permission` صادرة مسبقاً. منذ ترقية 2026-09، قد تغلق سلطة المنشئ المخصصة منحة أصدرتها؛ كانت حصرية للمسؤول قبل ذلك. |
| `CreateSupportMintAssociated` | `admin` أو مالك رمز الدعم المخصص | تسجيل رمز Token-2022 الذي قد يفشل في قائمة الامتدادات المسموحة، بإنشاء PDA `SupportMintAssociated` الخاص به. |
| `CloseSupportMintAssociated` | `admin` أو مالك رمز الدعم المخصص | إزالة تسجيل الرمز. |
| `CollectExcessLamports` | `admin` أو محفظة جمع lamports المخصصة | تجميع lamports فوق الحد الأدنى المعفي من الإيجار من الخزائن والرموز والـ PDAs التي يتحكم فيها CPMM. تمت الإضافة في 2026-09. |

قناع الحالة: `status` كل مجموعة هو `u8` حيث البت 0 = الإيداع معطل، البت 1 = السحب معطل، البت 2 = المبادلة معطلة (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` في البرنامج). البت الواضح يعني أن العملية مسموحة؛ البت المعين يعني أنها موقوفة. `UpdatePoolStatus` يأخذ `u8` خام ويستبدل القيمة الموجودة.

تتناول الأقسام التالية كل واحدة بالتفصيل. ترتيب الحسابات يتبع CPMM IDL؛ SDK وعميل Rust في `raydium-cp-swap/programs/cp-swap/src/instructions` يطابقان هذا الترتيب.

## `Initialize`

إنشاء مجموعة CPMM جديدة.

**المعاملات**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; swaps rejected before this
```

**الحسابات** (W = قابل للكتابة، S = موقّع)

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `creator` | W | S | يدفع الإيجار؛ مسجل كـ `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. |
| 3 | `authority` |   |   | PDA سلطة CPMM العامة. |
| 4 | `pool_state` | W | S* | تم `init` هنا. **إما** PDA القانوني `["pool", amm_config, token_0_mint, token_1_mint]` **أو** مفتاح عشوائي جديد — عندما لا يكون PDA القانوني، يتطلب البرنامج أن يوقّع `pool_state` (`require_eq!(pool_account_info.is_signer, true)`). يسمح مسار المفتاح العشوائي للمنشئ بتجنب محاولات الاستباق على PDA القانوني. يتم اشتقاق PDAs اللاحقة (`lp_mint`، `vaults`، `observation_state`) من `pool_state.key()` على أي حال. |
| 5 | `token_0_mint` |   |   | مرتب: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | تم `init` هنا. السلطة معينة إلى `authority`. |
| 8 | `creator_token_0` | W |   | ATA المصدر لـ `init_amount_0`. |
| 9 | `creator_token_1` | W |   | ATA المصدر لـ `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | الوجهة لـ LP (تم الإنشاء إذا كان مفقوداً). |
| 11 | `token_0_vault` | W |   | تم `init` هنا. مملوك بواسطة `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | ATA الوجهة لـ `create_pool_fee` المدفوعة من قبل المنشئ. |
| 14 | `observation_state` | W |   | تم `init` هنا. |
| 15 | `token_program` |   |   | SPL Token (لـ LP mint). |
| 16 | `token_0_program` |   |   | SPL Token أو Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token أو Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` يوقّع فقط على مسار المفتاح العشوائي؛ مسار PDA القانوني يعمل بدون توقيع `pool_state`.

**الشروط السابقة**

- الرموز مرتبة (`token_0_mint < token_1_mint` حسب ترتيب البايت).
- لا يستخدم أي رمز امتداداً خارج قائمة السماح بـ CPMM (`TransferFeeConfig`، `MetadataPointer`، `TokenMetadata`، `InterestBearingConfig`، `ScaledUiAmount`) — انظر [`products/cpmm/accounts`](/ar/products/cpmm/accounts#vaults-and-token-2022). الرمز الذي يحتوي على PDA `SupportMintAssociated` (البذرة `[b"support_mint", mint]`) يتخطى الفحص؛ هذا السجل هو الالتفاف الوحيد منذ أن أزالت ترقية 2026-09 قائمة الرموز الأربعة المرمزة.
- يمتلك `creator` على الأقل `init_amount_0` و `init_amount_1` في ATAs الخاصة.
- `amm_config.disable_create_pool == false`.

**الشروط اللاحقة**

- `pool_state` موجود مع `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- بداية LP لـ `LOCKED_LP` (`100` lamports من رمز LP) مقفلة بشكل دائم في المجموعة — `pool_state.lp_supply` يسجل `liquidity − 100` بينما تبقى `100` وحدة LP خارج التداول، مما يمنع المجموعة من تصريفها بالكامل والقسمة على صفر.
- تم تهيئة `observation_state`؛ `observation_index = 0` و `pool_id = pool_state.key()`.
- يتم نقل `create_pool_fee` lamports من المنشئ إلى المستقبل ومزامنتها كـ SOL أصلي (إنها ATA wSOL).
- قناع حالة المجموعة هو `0` (الإيداع / السحب / المبادلة جميعها مفعلة).
- `enable_creator_fee = false` و `creator_fee_on = BothToken`. `Initialize` **لا** يدعم تفعيل رسوم المنشئ — هذا المسار هو `InitializeWithPermission`.
- يتم رفع `open_time` إلى `block_timestamp + 1` إذا مرر المستدعي قيمة `<= block_timestamp`. يتم رفض المبادلات قبل `open_time`؛ الإيداعات والسحوبات تعمل فوراً.

**الأخطاء الشائعة** (القائمة الكاملة في [`reference/error-codes`](/ar/reference/error-codes))

- `InvalidInput` — رموز غير مرتبة، أو رموز متطابقة.
- `NotSupportMint` — امتداد Token-2022 محظور.
- `ExceededSlippage` — نادراً؛ إذا أسفرت `init_amount_0/1` عن صفر LP بسبب عدم تطابق الكسور العشرية.

## `Deposit`

إضافة السيولة في كلا الرمزين بما يتناسب مع المجموعة.

**المعاملات**

```
lp_token_amount:   u64   // how many LP tokens to mint to the LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**الرياضيات**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

لا يوجد تغيير في تناسب `k` — كل من الخزائن و `lp_supply` تتسع بنفس العامل.

**الشروط اللاحقة**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (صافي أي رسوم نقل Token-2022 على المدخل).
- `vault_1 += needed_token_1` (صافي أي رسوم نقل Token-2022 على المدخل).

**الأخطاء الشائعة** — `ExceededSlippage`، `ZeroTradingTokens`، `InvalidStatus` إذا كان الإيداع موقوفاً.

## `Withdraw`

حرق رموز LP واستقبال كلا الرمزين الأساسيين بنسبة.

**المعاملات**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(متطابق مع `Deposit`؛ `lp_mint` قابل للكتابة لأن رموز LP يتم حرقها.)

**الرياضيات**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**الشروط اللاحقة**

- `lp_supply -= lp_token_amount`.
- ترسل الخزائن `out_token_0` / `out_token_1` (إجمالي؛ يستقبل المستخدم صافي أي رسوم نقل Token-2022).

## `SwapBaseInput`

مبادلة بمدخل دقيق.

**المعاملات**

```
amount_in:            u64
minimum_amount_out:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

الترتيب **input → output** حسب اتجاه المستخدم، وليس حسب `token_0 / token_1` القانوني للمجموعة. يكتشف البرنامج أي خزان هو أي بمطابقة الرموز.

**الرياضيات** — انظر [`products/cpmm/math`](/ar/products/cpmm/math).

**الشروط السابقة**

- `open_time <= now`.
- `pool_status` يسمح بالمبادلة.
- لا يوجد رمز موقوف أو مجمد لهذه السلطة.
- `amount_in > 0`.

**الأخطاء الشائعة**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — التجارة تقرب إلى صفر.
- `NotApproved` — المجموعة موقوفة للمبادلات عبر `UpdatePoolStatus`.
- `InvalidInput` — الرموز لا تطابق أياً من رموز خزائن المجموعة.

## `SwapBaseOutput`

مبادلة بمخرج دقيق.

**المعاملات**

```
max_amount_in:  u64
amount_out:     u64
```

**الحسابات** — نفس `SwapBaseInput`.

**الرياضيات** — منحنى معكوس مع سقف، انظر [`products/cpmm/math`](/ar/products/cpmm/math).

**الأخطاء الشائعة** — `ExceededSlippage` (`gross_in > max_amount_in`)، `ZeroTradingTokens`، `InvalidInput`، `NotApproved`.

## `CollectProtocolFee`

تجميع الرسوم البروتوكولية المتراكمة من الخزائن إلى وجهة البروتوكول.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `owner` |   | S | يجب أن يطابق `amm_config.protocol_owner`. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**التأثير**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

لا يوجد تغيير في أرصدة المنحنى الفعالة (الرسوم المتراكمة تم استبعادها بالفعل).

**الخطأ الشائع** — `NotApproved` إذا لم يكن الموقّع هو `protocol_owner`.

## `CollectFundFee`

نفس شكل `CollectProtocolFee` لكن موقّع بواسطة `fund_owner` وتصفير عدادات `fund_fees_*`.

## `CollectCreatorFee`

موقّع بواسطة `pool_state.pool_creator`. ينقل أرصدة `creator_fees_token_0` و `creator_fees_token_1` الكاملة إلى حسابات الرموز للمنشئ، ثم يصفر كلا العدادين. يُرجع `NoFeeCollect` عندما يكون كلا العدادين صفراً.

## `CollectCreatorFeePermissionless`

يمكن لأي شخص تفعيل جمع رسوم المنشئ. التعليمة دائماً ترسل الأرصدة المتراكمة الكاملة إلى حسابات الرموز المرتبطة القانونية المملوكة بواسطة `pool_state.pool_creator`؛ لا يمكن للمستدعي اختيار منشئ أو وجهة أخرى. إذا كان أي ATA مفقوداً، يمول الدافع إنشاءه.

يبقى `CollectCreatorFee` الأصلي قابلاً للاستدعاء، لذا تبقى العملاء الموجودة متوافقة.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` | W | S | أي موقّع؛ يمول ATAs المفقودة للمنشئ. |
| 2 | `creator` |   |   | يجب أن يساوي `pool_state.pool_creator`؛ لا يوقّع. |
| 3 | `authority` |   |   | PDA سلطة الخزائن والرموز LP العامة لـ CPMM. |
| 4 | `pool_state` | W |   | يحتفظ بعدادات رسوم المنشئ المتراكمة. |
| 5 | `token_0_vault` | W |   | يجب أن يطابق خزان الرمز 0 للمجموعة. |
| 6 | `token_1_vault` | W |   | يجب أن يطابق خزان الرمز 1 للمجموعة. |
| 7 | `vault_0_mint` |   |   | يجب أن يطابق `token_0_vault.mint`. |
| 8 | `vault_1_mint` |   |   | يجب أن يطابق `token_1_vault.mint`. |
| 9 | `creator_token_0` | W |   | ATA القانوني للمنشئ لـ `vault_0_mint`؛ تم الإنشاء إذا كان مفقوداً. |
| 10 | `creator_token_1` | W |   | ATA القانوني للمنشئ لـ `vault_1_mint`؛ تم الإنشاء إذا كان مفقوداً. |
| 11 | `token_0_program` |   |   | SPL Token أو Token-2022، يطابق الرمز 0. |
| 12 | `token_1_program` |   |   | SPL Token أو Token-2022، يطابق الرمز 1. |
| 13 | `associated_token_program` |   |   | ينشئ ATA المستقبل المفقود. |
| 14 | `system_program` |   |   | يمول إنشاء الحساب من `payer`. |

**التأثير**

- ينقل كل `creator_fees_token_0` و `creator_fees_token_1` من خزائن المجموعة إلى ATAs المنشئ.
- يصفر كلا عدادات رسوم المنشئ ويحدّث `pool_state.recent_epoch`.
- يُرجع `NoFeeCollect` عندما يكون كلا العدادين صفراً.

## `UpdatePoolStatus`

إيقاف أو استئناف عمليات فردية على مجموعة. حقل `status` هو قناع بت:

| البت | العلم | التأثير عند التعيين |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` يرفض مع `NotApproved`. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` يرفض. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` يرفضان. |

**المعاملات**

```
status: u8      // new bitmask
```

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `authority` |   | S | يجب أن يطابق مفتاح المسؤول على برنامج CPMM. |
| 2 | `pool_state` | W |   |

مفتاح المسؤول هو سلطة الترقية على برنامج CPMM — في الممارسة العملية، متعدد التوقيع Raydium. انظر [`security/admin-and-multisig`](/ar/security/admin-and-multisig).

## `CreateAmmConfig`

إنشاء فئة رسوم جديدة.

**المعاملات**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `owner` | W | S | مسؤول. |
| 2 | `amm_config` | W |   | تم `init` هنا. |
| 3 | `system_program` |   |   |

**الشروط السابقة**

- لا يوجد `AmmConfig` موجود بنفس `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **تم التغيير في 2026-09: مالكو الرسوم للإعدادات الجديدة لم يعودوا يأتون من الموقّع.** `create_amm_config` الآن يكتب `protocol_fee_owner::ID` المرمّز في البرنامج إلى `protocol_owner` و `fund_fee_owner::ID` إلى `fund_owner`، بدلاً من نسخ مفتاح الموقّع المسؤول إلى كليهما. العناوين موجودة في [`reference/program-addresses`](/ar/reference/program-addresses#cpmm-fee-owner-wallets).

  النتائج: يتم تجميع `AmmConfig` المُنشأ حديثاً فوراً بواسطة محافظ الرسوم المخصصة بدلاً من مفتاح المسؤول، ولا يمكن للمسؤول جمع من إعداد أنشأه للتو بدون تدوير الحقل أولاً. **لم يتم إعادة كتابة حسابات `AmmConfig` الموجودة** — ما يتم تخزينه عليها لا يزال يحكم، لذا اقرأ دائماً `protocol_owner` / `fund_owner` من الحساب بدلاً من افتراض أي قيمة. معاملات `UpdateAmmConfig` `3` و `4` لا تزال تدورهما.
</Note>

## `UpdateAmmConfig`

تغيير معدلات الرسوم أو الملكية على `AmmConfig` موجود. يأخذ `param: u8` (مميز لأي حقل يتم تحديثه) و `value: u64`. دلالات القيمة لكل معامل موجودة في المصدر؛ عادة:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (مرر بايتات `Pubkey` كإعادة تفسير)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

التغييرات موقّعة من قبل المسؤول وتؤثر على **كل مجموعة مرتبطة بهذا `AmmConfig`** في المبادلة التالية. لا توجد هجرة؛ المجموعات ببساطة تقرأ القيم الجديدة.

## `CollectExcessLamports`

تجميع المسؤول لـ lamports الجالسة فوق الحد الأدنى المعفي من الإيجار على الحسابات التي يتحكم فيها CPMM. تمت الإضافة في ترقية 2026-09 حتى يتمكن البروتوكول من استرجاع الإفراط في التمويل الذي يتركه [SIMD-0437 rent reduction](/ar/solana-fundamentals/rent-and-reclaimable-rent) خلفه على الحسابات المُنشأة قبل كل خطوة.

فقط الزيادة تتحرك. أرصدة الرموز وبيانات الحساب والمالكون وحالة المجموعة والمنحنى لم تتغير، والتعليمة هي عدم عملية ضد حساب بالفعل في حده الأدنى — لذا من الآمن إعادة التشغيل بعد كل خطوة طرح.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | الوجهة لكل lamport تم تجميعه. يجب أن يكون إما مسؤول برنامج CPMM أو محفظة جمع lamports المخصصة — انظر [`reference/program-addresses`](/ar/reference/program-addresses#excess-lamports-collection-wallets). أي موقّع آخر يفشل مع `InvalidOwner`. |
| 2 | `authority` |   |   | PDA سلطة الخزائن ورموز LP لـ CPMM في البذرة `[b"vault_and_lp_mint_auth_seed"]`. يوقّع CPIs برنامج الرموز. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. كلاهما مطلوب بدون شرط؛ يختار البرنامج لكل حساب مصدر. |
| 5.. | `remaining_accounts` | W |   | `M` حسابات مصدر للتجميع، أي عدد، أي ترتيب. |

**كيفية التعامل مع كل حساب مصدر**

يقوم البرنامج بالتوزيع على `owner` حساب المصدر:

| مالك حساب المصدر | المعالجة |
|---|---|
| SPL Token أو Token-2022، حساب رمز غير أصلي أو رمز — خزائن المجموعة ورموز LP | CPI `WithdrawExcessLamports` (مميز برنامج الرموز `38`)، موقّع بواسطة `authority`. |
| SPL Token أو Token-2022، **أصلي** (wSOL) حساب رمز | `WithdrawExcessLamports` يرفض الحسابات الأصلية. يقوم البرنامج بـ CPI `SyncNative`، يقيس كم نما `amount` المغلف، `UnwrapLamports` (مميز `45`) لهذا الفرق بالضبط، ثم يتطلب أن يساوي الرصيد المغلف قيمته السابقة للمزامنة — وإلا `LamportsCalculateError` (`6015`). خزان مجموعة جانب SOL بالتالي يحتفظ بسيولته الكاملة. |
| برنامج CPMM نفسه — `PoolState`، `AmmConfig`، `ObservationState`، `Permission`، `SupportMintAssociated` | يقوم البرنامج بخصم الحساب مباشرة إلى `rent.minimum_balance(data_len)`. |
| أي شيء آخر | **تم التخطي بصمت.** لا خطأ، لا lamports تحركت. |

لأنها تأخذ قائمة `remaining_accounts` غير محدودة، حجم المعاملة هو الحد الحقيقي — نفس القيد كما في تجميع جانب المحفظة الموصوف في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**الأخطاء الشائعة** — `InvalidOwner` (`6001`، موقّع خاطئ)، `LamportsCalculateError` (`6015`، جولة wSOL لم تصل إلى صفر)، و `InsufficientFunds` من مسار البرنامج المملوك عندما يحتفظ حساب بأقل من حده الأدنى للإيجار.

**لا يوجد منشئ SDK.** `@raydium-io/raydium-sdk-v2` لا تشحن منشئاً لهذه التعليمة، ولا يفعل مستودع `raydium-sdk-V2-demo` — إنه مسار مسؤول. قم بترميزه يدويًا، بالطريقة التي يفعلها تجميع جانب المحفظة في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) لتعليمة برنامج الرموز.
