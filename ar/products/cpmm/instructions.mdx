## ملخص التعليمات

| اسم المميز | من يوقّع | ماذا تفعل |
|-------|-----------|--------------|
| `Initialize` | منشئ المجموعة | إنشاء مجموعة CPMM جديدة من عملتين و `AmmConfig`. بدون إذن؛ يمكن لأي شخص استدعاؤها. تشفّر `enable_creator_fee = false` على المجموعة الجديدة. يمكن أن يكون حساب `pool_state` إما PDA القانوني أو مفتاح عشوائي جديد (انظر حسابات Initialize). |
| `InitializeWithPermission` | الدافع + حامل PDA `Permission` | متغير مرخص من `Initialize`. يجب على المستدعي (الدافع) أن يمتلك PDA `Permission` مشتق من مفتاحه العام الخاص. يستخدمه المنصات التي تحتاج إلى إنشاء مجموعة محدود (مثل تخرجات LaunchLab). يسمح للمستدعي بتثبيت `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) ويفرض `enable_creator_fee = true` على المجموعة الجديدة. يتم تعيين حقل `creator` على `pool_state` إلى حساب `creator` منفصل تم تمريره، وليس الدافع. نفس مرونة PDA القانوني أو المفتاح العشوائي لـ `pool_state` كما في `Initialize`. |
| `Deposit` | مزود السيولة | إضافة السيولة في كلا الرمزين؛ استقبال رموز LP. |
| `Withdraw` | مزود السيولة | حرق رموز LP؛ استقبال كلا الرموز الأساسية بنسبة. |
| `SwapBaseInput` | المتداول | مبادلة بمدخل دقيق (`amount_in` داخل، ≥ `minimum_amount_out` خارج). |
| `SwapBaseOutput` | المتداول | مبادلة بمخرج دقيق (≤ `maximum_amount_in` داخل، `amount_out` خارج). |
| `CollectProtocolFee` | `protocol_owner` (من `AmmConfig`) | مسح الرسوم البروتوكول المتراكمة من الخزائن. |
| `CollectFundFee` | `fund_owner` (من `AmmConfig`) | مسح رسوم الصندوق المتراكمة من الخزائن. |
| `CollectCreatorFee` | `pool_creator` | مسح رسوم المنشئ المتراكمة (إذا كانت رسوم المنشئ مفعلة)، بعد خصم حصة البروتوكول، التي يتم حجزها في دلو البروتوكول للمجموعة. |
| `CollectCreatorFeePermissionless` | أي دافع | مسح رسوم المنشئ المتراكمة إلى حسابات الرموز القانونية لـ `pool_creator`، بعد خصم نفس حصة البروتوكول. لا يمكن للدافع إعادة توجيه التحويل. |
| `UpdatePoolStatus` | `admin` | إيقاف / استئناف عمليات محددة على مجموعة عبر قناع بت. |
| `UpdateAmmConfig` | `admin` | تغيير معدلات الرسوم أو مالك البروتوكول/الصندوق على `AmmConfig`. |
| `CreateAmmConfig` | `admin` | إنشاء فئة رسوم جديدة (حساب `AmmConfig` جديد). |
| `CreatePermissionPda` | `admin` أو منشئ PDA إذن مفوض | سك PDA `Permission` يسمح لسلطة محددة باستدعاء `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` أو منشئ PDA الإذن المخصص | إلغاء PDA `Permission` صادر مسبقًا. منذ ترقية 2026-09 قد تغلق سلطة المنشئ المخصصة أيضًا منحة أصدرتها؛ كانت حصرية للمسؤول قبل ذلك. |
| `CreateSupportMintAssociated` | `admin` أو مالك Token-2022 mint المخصص | تسجيل Token-2022 mint الذي قد يفشل بخلاف ذلك في قائمة الامتدادات المسموحة، بإنشاء PDA `SupportMintAssociated` الخاص به. |
| `CloseSupportMintAssociated` | `admin` أو مالك Token-2022 mint المخصص | إزالة تسجيل mint. |
| `CollectExcessLamports` | `admin` أو محفظة جمع lamports المخصصة | مسح lamports فوق الحد الأدنى المعفي من الإيجار من الخزائن والـ LP mints و PDAs التي يتحكم فيها CPMM. أضيفت 2026-09. |
| `CreateCreatorFeeShare` | `admin` أو مالك حصة رسوم المنشئ المخصص | تعيين حصة بروتوكول مخصصة من رسوم المنشئ لزوج واحد `(creator, amm_config)`، مع تجاوز `AmmConfig.creator_fee_share_rate`. أضيفت 2026-09-19. |
| `CloseCreatorFeeShare` | `admin` أو مالك حصة رسوم المنشئ المخصص | إزالة هذا التجاوز؛ يعود الزوج إلى الافتراضي للإعدادات. أضيفت 2026-09-19. |

قناع الحالة: `status` كل مجموعة هو `u8` حيث البت 0 = الإيداع معطل، البت 1 = السحب معطل، البت 2 = المبادلة معطلة (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` في البرنامج). البت الواضح يعني أن العملية مسموحة؛ البت المعين يعني أنها موقوفة. تأخذ `UpdatePoolStatus` `u8` خام وتستبدل القيمة الموجودة.

تمر الأقسام التالية عبر كل واحدة بالتفصيل. يتبع ترتيب الحساب IDL الخاص بـ CPMM؛ يطابق SDK وعميل Rust في `raydium-cp-swap/programs/cp-swap/src/instructions` هذا الترتيب.

## `Initialize`

إنشاء مجموعة CPMM جديدة.

**المعاملات**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; swaps rejected before this
```

**الحسابات** (W = قابل للكتابة، S = موقّع)

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `creator` | W | S | يدفع الإيجار؛ مسجل كـ `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. |
| 3 | `authority` |   |   | PDA سلطة CPMM العامة. |
| 4 | `pool_state` | W | S* | `init`ed هنا. **إما** PDA القانوني `["pool", amm_config, token_0_mint, token_1_mint]` **أو** مفتاح عشوائي جديد — عندما لا يكون PDA القانوني، يتطلب البرنامج `pool_state` للتوقيع (`require_eq!(pool_account_info.is_signer, true)`). يسمح مسار المفتاح العشوائي لمنشئ تجنب محاولات الجري الأمامي على PDA القانوني. يتم اشتقاق PDAs اللاحقة (`lp_mint`، `vaults`، `observation_state`) من `pool_state.key()` على أي حال. |
| 5 | `token_0_mint` |   |   | مرتب: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | `init`ed هنا. السلطة معينة إلى `authority`. |
| 8 | `creator_token_0` | W |   | ATA المصدر لـ `init_amount_0`. |
| 9 | `creator_token_1` | W |   | ATA المصدر لـ `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | ATA المنشئ على `lp_mint`. `init` (وليس `init_if_needed`) — يجب ألا يكون موجودًا بالفعل، وهو لا يمكن أن يكون، لأن `lp_mint` يتم إنشاؤه في نفس التعليمة. |
| 11 | `token_0_vault` | W |   | `init`ed هنا. مملوك بواسطة `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | ATA الوجهة لـ `create_pool_fee` المدفوعة من قبل المنشئ. |
| 14 | `observation_state` | W |   | `init`ed هنا. |
| 15 | `token_program` |   |   | SPL Token (لـ LP mint). |
| 16 | `token_0_program` |   |   | SPL Token أو Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token أو Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` يوقّع `pool_state` فقط على مسار المفتاح العشوائي؛ يعمل مسار PDA القانوني بدون توقيع `pool_state`.

**الشروط السابقة**

- يتم فرز الـ mints (`token_0_mint < token_1_mint` حسب ترتيب البايت).
- لا يستخدم أي mint امتدادًا خارج قائمة السماح بـ CPMM (`TransferFeeConfig`، `MetadataPointer`، `TokenMetadata`، `InterestBearingConfig`، `ScaledUiAmount`) — انظر [`products/cpmm/accounts`](/ar/products/cpmm/accounts#vaults-and-token-2022). يتخطى mint الذي يوجد PDA `SupportMintAssociated` الخاص به (البذرة `[b"support_mint", mint]`) فحص الامتداد — **لكن يجب عليك إضافة هذا PDA إلى `remaining_accounts`**. يقوم البرنامج فقط بمسح الحسابات التي تمررها ولا يحمل PDA بنفسه، لذا فإن الاعتماد على السجل بدون توفير الحساب لا يزال يفشل مع `NotSupportMint` (`6007`). الترتيب لا يهم (المطابقة حسب المفتاح)؛ مرر إدخالاً واحدًا لكل mint يحتاج إلى التجاوز. هذا السجل هو التجاوز الوحيد منذ أزالت ترقية 2026-09 قائمة الـ mint الأربعة المشفرة بشكل ثابت.
- يمتلك `creator` على الأقل `init_amount_0` و `init_amount_1` في ATAs الخاصة.
- `amm_config.disable_create_pool == false`.

**الشروط اللاحقة**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — الجذر التربيعي **الكامل**. يتم سك `lp_supply − 100` للمنشئ؛ يتم حساب 100 وحدة أساسية مقفلة في `lp_supply` لكن لا تُسك أبدًا.
- لذا `lp_mint.supply == pool_state.lp_supply − 100` لحياة المجموعة. تقسم كل رياضيات حصة LP (الإيداع، السحب) على `lp_supply`، لذا استخدم هذا الحقل ولا تستبدل إمداد mint على السلسلة. يعود مع `InitLpAmountTooLess` إذا كان `sqrt(...) < 100`.
- يتم تهيئة `observation_state`؛ `observation_index = 0` و `pool_id = pool_state.key()`.
- يتم نقل lamports `create_pool_fee` من المنشئ إلى المستقبل ومزامنتها كـ SOL أصلي (إنها ATA wSOL).
- قناع حالة المجموعة هو `0` (الإيداع / السحب / المبادلة جميعها مفعلة).
- `enable_creator_fee = false` و `creator_fee_on = BothToken`. لا تدعم `Initialize` تفعيل رسوم المنشئ — هذا المسار هو `InitializeWithPermission`.
- يتم رفع `open_time` إلى `block_timestamp + 1` إذا مرر المستدعي قيمة `<= block_timestamp`. يتم رفض المبادلات قبل `open_time`؛ تعمل الودائع والسحوبات فورًا.

**الأخطاء الشائعة** (القائمة الكاملة في [`reference/error-codes`](/ar/reference/error-codes))

- `InvalidInput` — mints غير مرتبة، أو mints متطابقة.
- `NotSupportMint` — امتداد Token-2022 محظور.
- `ExceededSlippage` — نادرًا؛ إذا أسفرت `init_amount_0/1` عن صفر LP بسبب عدم تطابق الكسور العشرية.

## `Deposit`

إضافة السيولة في كلا الرمزين بما يتناسب مع المجموعة.

**المعاملات**

```
lp_token_amount:   u64   // how many LP tokens to mint to the LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**الرياضيات**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // same for side 1
```

تفاصيل اثنتان تستحق التثبيت: القاعدة النسبية هي إجمالي الخزينة **المستثناة من الرسوم** (`vault_amount_without_fee`، أي الرصيد الخام مطروحًا منه عدادات البروتوكول والصندوق والمنشئ المتراكمة)، وليس رصيد الخزينة الخام؛ وتُفحص حد الانزلاق مقابل ما يحويله الدافع فعليًا، *بعد* إضافة رسوم نقل Token-2022، وليس مقابل حركة الخزينة الإجمالية.

لا تغيير في تناسب `k` — يتم قياس كلا الإجماليين و `lp_supply` بنفس العامل.

**الشروط اللاحقة**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (بعد خصم أي رسوم نقل Token-2022 على الإدخال).
- `vault_1 += needed_token_1` (بعد خصم أي رسوم نقل Token-2022 على الإدخال).

**الأخطاء الشائعة** — `ExceededSlippage`، `ZeroTradingTokens`، `InvalidStatus` إذا كان الإيداع موقوفًا.

## `Withdraw`

حرق رموز LP واستقبال كلا الرموز الأساسية بنسبة.

**المعاملات**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

الحسابات الـ 13 الأولى متطابقة مع `Deposit`، و `lp_mint` قابل للكتابة لأن رموز LP يتم حرقها. تأخذ `Withdraw` بالإضافة إلى ذلك حساب 14، `memo_program` (مقيد `address = memo::ID`) — لا تأخذ `Deposit`. يفشل `Withdraw` بـ 13 حساب في فك تسلسل Anchor، لذا لا يمكن لـ LP الخروج.

**الرياضيات**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // same for side 1

// As with Deposit: the base is the fee-excluded vault total, and the floor is
// checked against what the LP actually receives, after the transfer fee.
```

**الشروط اللاحقة**

- `lp_supply -= lp_token_amount`.
- ترسل الخزائن `out_token_0` / `out_token_1` (إجمالي؛ يستقبل المستخدم بعد خصم أي رسوم نقل Token-2022).

## `SwapBaseInput`

مبادلة بمدخل دقيق.

**المعاملات**

```
amount_in:            u64
minimum_amount_out:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

الترتيب **الإدخال → الإخراج** حسب اتجاه المستخدم، وليس حسب `token_0 / token_1` القانوني للمجموعة. يكتشف البرنامج أي خزينة هي أي بمطابقة الـ mints.

**الرياضيات** — انظر [`products/cpmm/math`](/ar/products/cpmm/math).

**الشروط السابقة**

- `open_time <= now`.
- تسمح `pool_status` بالمبادلة.
- لا يتم إيقاف أي mint أو تجميده لهذه السلطة.
- `amount_in > 0`.

**الأخطاء الشائعة**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — التجارة تقرب إلى صفر.
- `NotApproved` — المجموعة موقوفة للمبادلات عبر `UpdatePoolStatus`.
- `InvalidInput` — الـ mints لا تطابق أيًا من خزائن المجموعة.

## `SwapBaseOutput`

مبادلة بمخرج دقيق.

**المعاملات**

```
max_amount_in:  u64
amount_out:     u64
```

**الحسابات** — نفس `SwapBaseInput`.

**الرياضيات** — منحنى معكوس مع سقف، انظر [`products/cpmm/math`](/ar/products/cpmm/math).

**الأخطاء الشائعة** — `ExceededSlippage` (`gross_in > max_amount_in`)، `ZeroTradingTokens`، `InvalidInput`، `NotApproved`.

## `CollectProtocolFee`

مسح رسوم البروتوكول المتراكمة من الخزائن إلى وجهة البروتوكول.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `owner` |   | S | يجب أن يساوي `amm_config.protocol_owner` **أو** مفتاح المسؤول المشفر بشكل ثابت في البرنامج. |

</Note>

## `UpdateAmmConfig`

تغيير معدلات الرسوم أو الملكية على `AmmConfig` موجود. يأخذ `param: u8` (أي حقل لتحديثه) و `value: u64`. جدول الإرسال الكامل:

- `param = 0` → `trade_fee_rate` (يؤكد `trade_fee_rate + creator_fee_rate < 1_000_000`)
- `param = 1` → `protocol_fee_rate` (يؤكد `≤ 1_000_000` و `+ fund_fee_rate ≤ 1_000_000`)
- `param = 2` → `fund_fee_rate` (يؤكد `≤ 1_000_000` و `+ protocol_fee_rate ≤ 1_000_000`)
- `param = 3` → `protocol_owner`. المفتاح الجديد **ليس** في `value`: أضفه كـ `remaining_accounts[0]` (القراءة فقط بخير). يجب ألا يكون المفتاح الافتراضي، وحذف الحساب يرمي على `unwrap()`.
- `param = 4` → `fund_owner`. نفس الآلية كـ `3`.
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool` (أي `value` غير صفري يعطل)
- `param = 7` → `creator_fee_rate` (يؤكد `creator_fee_rate + trade_fee_rate < 1_000_000`)
- `param = 8` → `creator_fee_share_rate` (يؤكد `≤ 1_000_000`). أضيفت 2026-09-19. حصة البروتوكول الافتراضية **من رسوم المنشئ** على هذه الفئة؛ انظر [`products/cpmm/fees`](/ar/products/cpmm/fees#protocol-share-of-the-creator-fee). لا علاقة لها بـ `protocol_fee_rate`، الذي ينقسم رسوم التجارة.

أي `param` آخر يعود `InvalidInput`.

يتم توقيع التغييرات من قبل المسؤول وتؤثر على **كل مجموعة مرتبطة بهذا `AmmConfig`** على المبادلة التالية. لا هجرة؛ تقرأ المجموعات القيم الجديدة ببساطة.

## `CollectExcessLamports`

مسح المسؤول لـ lamports الجالسة فوق الحد الأدنى المعفي من الإيجار على الحسابات التي يتحكم فيها CPMM. أضيفت في ترقية 2026-09 حتى يتمكن البروتوكول من استرجاع الإفراط في التمويل الذي يتركه [SIMD-0437 rent reduction](/ar/solana-fundamentals/rent-and-reclaimable-rent) خلفه على الحسابات المُنشأة قبل كل خطوة.

يتحرك الفائض فقط. أرصدة الرموز وبيانات الحساب والمالكون وحالة المجموعة والمنحنى لم تتغير، والتعليمة هي عدم عملية ضد حساب بالفعل في الحد الأدنى — لذا من الآمن إعادة التشغيل بعد كل خطوة نشر.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | الوجهة لكل lamport مكتسح. يجب أن يكون إما مسؤول برنامج CPMM أو محفظة جمع lamports المخصصة — انظر [`reference/program-addresses`](/ar/reference/program-addresses#excess-lamports-collection-wallets). أي موقّع آخر يفشل مع `InvalidOwner`. |
| 2 | `authority` |   |   | PDA سلطة الخزينة و LP mint في البذرة `[b"vault_and_lp_mint_auth_seed"]`. يوقّع CPIs برنامج الرموز. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. كلاهما مطلوب بدون شروط؛ يختار البرنامج لكل حساب مصدر. |
| 5.. | `remaining_accounts` | W |   | `M` حساب مصدر للمسح، أي عدد، أي ترتيب. |

<Note>
  **إصلاح الترتيب، 2026-09-19.** يقوم البرنامج الآن بمسحتين على `remaining_accounts` — كل CPI برنامج رموز أولاً، ثم الخصومات المباشرة لـ PDAs المملوكة لـ CPMM. كان الفصل بينهما يُجهض مع `UnbalancedInstruction` ("مجموع أرصدة الحساب قبل وبعد التعليمة لا تتطابق") كلما تم خصم PDA قبل CPI، لأن التغييرات المعلقة lamport للمستدعي يتم تفريغها فقط في الحسابات التي تحملها CPI فعليًا. لا يتعين على المستدعين تجميع أو فرز القائمة بأنفسهم.
</Note>

**كيفية التعامل مع كل حساب مصدر**

يقوم البرنامج بالإرسال على مالك حساب المصدر:

| مالك حساب المصدر | المعالجة |
|---|---|
| SPL Token أو Token-2022، حساب رموز غير أصلي أو mint — خزائن المجموعة و LP mints | CPI `WithdrawExcessLamports` (مميز برنامج الرموز `38`)، موقّع بواسطة `authority`. |
| SPL Token أو Token-2022، **أصلي** (wSOL) حساب رموز | ترفض `WithdrawExcessLamports` الحسابات الأصلية. يقوم البرنامج بـ CPI `SyncNative`، يقيس كم نما `amount` المُغلف، `UnwrapLamports` (مميز `45`) لهذا الفرق بالضبط، ثم يتطلب أن يساوي الرصيد المُغلف قيمته السابقة للمزامنة — وإلا `LamportsCalculateError` (`6015`). لذا تحتفظ خزينة مجموعة جانب SOL بسيولتها الكاملة. |
| برنامج CPMM نفسه — `PoolState`، `AmmConfig`، `ObservationState`، `Permission`، `SupportMintAssociated` | يقوم البرنامج بخصم الحساب مباشرة إلى `rent.minimum_balance(data_len)`. |
| أي شيء آخر | **تم تخطيه بصمت.** لا خطأ، لا lamports تحركت. |

لأنها تأخذ قائمة `remaining_accounts` غير محدودة، حجم المعاملة هو الحد الحقيقي — نفس القيد كما في مسح جانب المحفظة الموصوف في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**الأخطاء الشائعة** — `InvalidOwner` (`6001`، موقّع خاطئ)، `LamportsCalculateError` (`6015`، لم تصل رحلة wSOL ذهابًا وإيابًا إلى صفر)، و `InsufficientFunds` من مسار المملوك للبرنامج عندما يحمل حساب أقل من الحد الأدنى للإيجار الخاص به.
