## ملخص التعليمات

| اسم المميز | من يوقّع | ما تفعله |
|-------|-----------|--------------|
| `Initialize` | منشئ المجموعة | إنشاء مجموعة CPMM جديدة من mint اثنين و `AmmConfig`. بدون إذن؛ يمكن لأي شخص استدعاؤها. تُرمّز `enable_creator_fee = false` على المجموعة الجديدة. يمكن أن يكون حساب `pool_state` إما PDA القانوني أو مفتاح عشوائي جديد (انظر حسابات Initialize). |
| `InitializeV2` | منشئ المجموعة | مثل `Initialize`، بالإضافة إلى معامل `creator_fee_on` اختياري. بدون إذن. `Some(...)` يخزّن `enable_creator_fee = true` مع الجانب المختار؛ `None` يخزّن نفس إعدادات رسوم المنشئ التي تخزّنها `Initialize`. نفس حسابات `Initialize` ناقص sysvar `rent` الأخير. أُضيفت في 2026-10-30. |
| `InitializeWithPermission` | الدافع + حامل PDA `Permission` | متغير مع إذن من `Initialize`. يجب على المستدعي (الدافع) أن يمتلك PDA `Permission` مشتق من مفتاحه العام الخاص. يستخدمه المنصات التي تحتاج إلى إنشاء مجموعة محدود (مثل تخرجات LaunchLab). يسمح للمستدعي بتثبيت `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) ويفرض `enable_creator_fee = true` على المجموعة الجديدة. يتم تعيين حقل `creator` على `pool_state` إلى حساب `creator` منفصل يتم تمريره، وليس الدافع. نفس مرونة PDA القانوني أو المفتاح العشوائي لـ `pool_state` كما في `Initialize`. |
| `Deposit` | مزود السيولة | إضافة السيولة في كلا الرمزين؛ استقبال رموز LP. |
| `Withdraw` | مزود السيولة | حرق رموز LP؛ استقبال كلا الرمزين الأساسيين بنسبة. |
| `SwapBaseInput` | المتبادل | مبادلة بمدخل دقيق (`amount_in` داخل، ≥ `minimum_amount_out` خارج). |
| `SwapBaseOutput` | المتبادل | مبادلة بمخرج دقيق (≤ `maximum_amount_in` داخل، `amount_out` خارج). |
| `CollectProtocolFee` | `protocol_owner` (من `AmmConfig`) | جمع رسوم البروتوكول المتراكمة من الخزائن. |
| `CollectFundFee` | `fund_owner` (من `AmmConfig`) | جمع رسوم الصندوق المتراكمة من الخزائن. |
| `CollectCreatorFee` | `pool_creator` | جمع رسوم المنشئ المتراكمة (إن كانت رسوم المنشئ مفعلة)، بعد خصم حصة البروتوكول، التي تُسجل في دلو البروتوكول للمجموعة. |
| `CollectCreatorFeePermissionless` | أي دافع | جمع رسوم المنشئ المتراكمة إلى حسابات الرموز القانونية لـ `pool_creator`، بعد خصم نفس حصة البروتوكول. يمكن للدافع إنشاء ATAs المستقبل المفقودة لكن لا يمكنه إعادة توجيه التحويل. |
| `UpdatePoolStatus` | `admin` | إيقاف / استئناف عمليات محددة على مجموعة عبر قناع بت. |
| `UpdateAmmConfig` | `admin` | تغيير معدلات الرسوم أو مالك البروتوكول/الصندوق على `AmmConfig`. |
| `CreateAmmConfig` | `admin` | إنشاء فئة رسوم جديدة (حساب `AmmConfig` جديد). |
| `CreatePermissionPda` | `admin` أو منشئ PDA إذن مفوض | صك PDA `Permission` يسمح لسلطة محددة باستدعاء `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` أو منشئ PDA الإذن المخصص | إلغاء PDA `Permission` صادر مسبقًا. منذ ترقية 2026-09 قد تغلق سلطة المنشئ المخصصة أيضًا منحة أصدرتها؛ كانت حصرية للمسؤول قبل ذلك. |
| `CreateSupportMintAssociated` | `admin` أو مالك mint الدعم المخصص | تسجيل mint Token-2022 الذي قد يفشل قائمة السماح بالامتداد، بإنشاء PDA `SupportMintAssociated` الخاص به. |
| `CloseSupportMintAssociated` | `admin` أو مالك mint الدعم المخصص | إزالة تسجيل mint. |
| `CollectExcessLamports` | `admin` أو محفظة جمع lamports المخصصة | جمع lamports فوق الحد الأدنى المعفي من الإيجار من الخزائن والـ LP mints و PDAs التي تتحكم فيها CPMM. أضيفت في 2026-09. |
| `CreateCreatorFeeShare` | `admin` أو مالك حصة رسوم المنشئ المخصص | تعيين حصة بروتوكول مخصصة من رسوم المنشئ لزوج واحد `(creator, amm_config)`، مع تجاوز `AmmConfig.creator_fee_share_rate`. أضيفت في 2026-09-19. |
| `CloseCreatorFeeShare` | `admin` أو مالك حصة رسوم المنشئ المخصص | إزالة هذا التجاوز؛ يعود الزوج إلى الافتراضي للإعدادات. أضيفت في 2026-09-19. |

قناع الحالة: `status` كل مجموعة هو `u8` حيث البت 0 = الإيداع معطل، البت 1 = السحب معطل، البت 2 = المبادلة معطلة (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` في البرنامج). البت الواضح يعني أن العملية مسموحة؛ البت المعين يعني أنها موقوفة. تأخذ `UpdatePoolStatus` `u8` خام وتستبدل القيمة الموجودة.

تمر الأقسام التالية عبر كل واحدة بالتفصيل. ترتيب الحسابات يتبع IDL الخاص بـ CPMM؛ SDK وعميل Rust في `raydium-cp-swap/programs/cp-swap/src/instructions` يطابقان هذا الترتيب.

## `Initialize`

إنشاء مجموعة CPMM جديدة.

**المعاملات**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; swaps rejected before this
```

**الحسابات** (W = قابل للكتابة، S = موقّع)

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `creator` | W | S | يدفع الإيجار؛ مسجل كـ `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. |
| 3 | `authority` |   |   | PDA سلطة CPMM العامة. |
| 4 | `pool_state` | W | S* | يتم `init` هنا. **إما** PDA القانوني `["pool", amm_config, token_0_mint, token_1_mint]` **أو** مفتاح عشوائي جديد — عندما لا يكون PDA القانوني، يتطلب البرنامج أن يوقّع `pool_state` (`require_eq!(pool_account_info.is_signer, true)`). يسمح مسار المفتاح العشوائي لمنشئ تجنب محاولات الجري الأمامي على PDA القانوني. يتم اشتقاق PDAs اللاحقة (`lp_mint`، `vaults`، `observation_state`) من `pool_state.key()` على أي حال. |
| 5 | `token_0_mint` |   |   | مرتب: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | يتم `init` هنا. السلطة معينة إلى `authority`. |
| 8 | `creator_token_0` | W |   | ATA المصدر لـ `init_amount_0`. |
| 9 | `creator_token_1` | W |   | ATA المصدر لـ `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | ATA المنشئ على `lp_mint`. `init` (وليس `init_if_needed`) — يجب ألا يكون موجودًا بالفعل، وهو لا يمكن أن يكون، لأن `lp_mint` يتم إنشاؤه في نفس التعليمة. |
| 11 | `token_0_vault` | W |   | يتم `init` هنا. مملوك بواسطة `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | ATA الوجهة لـ `create_pool_fee` المدفوعة من قبل المنشئ. |
| 14 | `observation_state` | W |   | يتم `init` هنا. |
| 15 | `token_program` |   |   | SPL Token (لـ LP mint). |
| 16 | `token_0_program` |   |   | SPL Token أو Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token أو Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` يوقّع `pool_state` فقط على مسار المفتاح العشوائي؛ مسار PDA القانوني يعمل بدون توقيع `pool_state`.

**الشروط السابقة**

- يتم ترتيب الـ mints (`token_0_mint < token_1_mint` حسب ترتيب البايت).
- لا يستخدم أي mint امتدادًا خارج قائمة السماح بـ CPMM (`TransferFeeConfig`، `MetadataPointer`، `TokenMetadata`، `InterestBearingConfig`، `ScaledUiAmount`) — انظر [`products/cpmm/accounts`](/ar/products/cpmm/accounts#vaults-and-token-2022). يتخطى mint الذي يوجد PDA `SupportMintAssociated` الخاص به (البذرة `[b"support_mint", mint]`) فحص الامتداد — **لكن يجب عليك إلحاق هذا PDA بـ `remaining_accounts`**. البرنامج يفحص فقط الحسابات التي تمررها ولا يحمل PDA بنفسه أبدًا، لذا الاعتماد على السجل بدون توفير الحساب يفشل مع `NotSupportMint` (`6007`). الترتيب لا يهم (المطابقة حسب المفتاح)؛ مرر إدخالاً واحدًا لكل mint يحتاج إلى التجاوز. هذا السجل هو التجاوز الوحيد منذ أن أزالت ترقية 2026-09 قائمة الـ mint الأربعة المرمزة بشكل ثابت.
- لدى `creator` على الأقل `init_amount_0` و `init_amount_1` في ATAs الخاصة.
- `amm_config.disable_create_pool == false`.

**الشروط اللاحقة**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — الجذر التربيعي **الكامل**. يتم صك المنشئ `lp_supply − 100`؛ وحدات 100 الأساسية المقفلة تُحسب في `lp_supply` لكن لا تُصك أبدًا.
- لذا `lp_mint.supply == pool_state.lp_supply − 100` لحياة المجموعة. كل رياضيات حصة LP (الإيداع، السحب) تقسم على `lp_supply`، لذا استخدم هذا الحقل ولا تستبدل بـ supply الـ mint على السلسلة. يعود مع `InitLpAmountTooLess` إذا كان `sqrt(...) < 100`.
- يتم تهيئة `observation_state`؛ `observation_index = 0` و `pool_id = pool_state.key()`.
- يتم نقل lamports `create_pool_fee` من المنشئ إلى المستقبل ومزامنتها كـ SOL أصلي (إنها ATA wSOL).
- قناع حالة المجموعة هو `0` (الإيداع / السحب / المبادلة كلها مفعلة).
- `enable_creator_fee = false` و `creator_fee_on = BothToken`. `Initialize` **لا** تدعم تفعيل رسوم المنشئ. استخدم [`InitializeV2`](#initializev2) لتفعيلها دون منح إذن.
- يتم رفع `open_time` إلى `block_timestamp + 1` إذا مرر المستدعي قيمة `<= block_timestamp`. يتم رفض المبادلات قبل `open_time`؛ الإيداعات والسحوبات تعمل فورًا.

**الأخطاء الشائعة** (القائمة الكاملة في [`reference/error-codes`](/ar/reference/error-codes))

- `InvalidInput` — mints غير مرتبة، أو mints متطابقة.
- `NotSupportMint` — امتداد Token-2022 محظور.
- `ExceededSlippage` — نادرًا؛ إذا أسفرت `init_amount_0/1` عن صفر LP بسبب عدم تطابق الكسور العشرية.

## `InitializeV2`

إنشاء مجموعة CPMM جديدة واختيار إعدادات رسوم المنشئ الخاصة بها. أُضيفت في ترقية 2026-10-30.

تنفّذ `InitializeV2` نفس مسار الإنشاء الذي تنفّذه `Initialize`. الفرق الوحيد هو ما تكتبه في `enable_creator_fee` و `creator_fee_on` على المجموعة الجديدة. قبل هذه التعليمة، كانت `InitializeWithPermission` وحدها قادرة على إنشاء مجموعة مع تفعيل رسوم المنشئ، وهذا المسار يتطلب `Permission` PDA يصدره المسؤول.

**المعاملات**

```
init_amount_0:  u64
init_amount_1:  u64
open_time:      u64                    // Unix timestamp; swaps rejected before this
creator_fee_on: Option<CreatorFeeOn>   // None = creator fee off
                                       // Some(BothToken | OnlyToken0 | OnlyToken1) = creator fee on
```

`CreatorFeeOn` هو تعداد Borsh، لذا يُرمَّز المعامل كبايت وسم واحد لـ `Option`، بالإضافة إلى بايت متغير واحد عندما يكون `Some`:

| القيمة | البايتات | المخزَّن على `pool_state` |
|-------|-------|------------------------|
| `None` | `00` | `enable_creator_fee = false`، `creator_fee_on = 0` (`BothToken`) |
| `Some(BothToken)` | `01 00` | `enable_creator_fee = true`، `creator_fee_on = 0` |
| `Some(OnlyToken0)` | `01 01` | `enable_creator_fee = true`، `creator_fee_on = 1` |
| `Some(OnlyToken1)` | `01 02` | `enable_creator_fee = true`، `creator_fee_on = 2` |

أي بايت آخر يفشل في إلغاء تسلسل المعاملات في Anchor قبل تشغيل المعالج.

المميز: `initialize_v2` → `[67, 153, 175, 39, 218, 16, 38, 32]`.

**الحسابات** (W = قابل للكتابة، S = موقّع)

أول 19 حسابًا مطابقة لـ [`Initialize`](#initialize)، وبنفس الترتيب. تحذف `InitializeV2` فقط sysvar `rent` الأخير.

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `creator` | W | S | يدفع الإيجار ورسوم إنشاء المجموعة والسيولة الأولية. مسجل كـ `pool_state.pool_creator`، لذا تذهب رسوم المنشئ إلى هذا الموقّع. |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. `creator_fee_rate` الخاص بها هو المعدل الذي تفرضه المجموعة. |
| 3 | `authority` |   |   | PDA السلطة العامة لـ CPMM. |
| 4 | `pool_state` | W | S* | PDA القانوني **أو** مفتاح عشوائي جديد، تمامًا كما في `Initialize`. |
| 5 | `token_0_mint` |   |   | مرتبة: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | يتم `init` هنا. |
| 8 | `creator_token_0` | W |   | الحساب المصدر لـ `init_amount_0`. |
| 9 | `creator_token_1` | W |   | الحساب المصدر لـ `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | ATA المنشئ على `lp_mint`. يتم `init` هنا. |
| 11 | `token_0_vault` | W |   | يتم `init` هنا. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | الوجهة لـ `create_pool_fee`. |
| 14 | `observation_state` | W |   | يتم `init` هنا. |
| 15 | `token_program` |   |   | SPL Token (لـ LP mint). |
| 16 | `token_0_program` |   |   | SPL Token أو Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token أو Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |

`*` يوقّع `pool_state` فقط على مسار المفتاح العشوائي.

تعمل `remaining_accounts` بنفس الطريقة كما في `Initialize`: ألحق PDA `SupportMintAssociated` لأي mint من Token-2022 يحتاج إلى تجاوز السجل.

<Note>
  لأن أول 19 حسابًا متطابقة، يمكنك تكييف منشئ `Initialize` موجود: غيّر المميز، وألحق بايتات `creator_fee_on`، واحذف `rent`. إذا أبقيت `rent`، يمرره Anchor كإدخال في `remaining_accounts`، ويتخطاه فحص support-mint لأنه ليس حسابًا مملوكًا لـ CPMM. احذفه على أي حال لتوفير خانة الحساب.
</Note>

**الشروط السابقة** — نفس شروط `Initialize`. لا يوجد فحص إذن ولا قيد جديد على `creator_fee_on`.

**الشروط اللاحقة** — نفس شروط `Initialize`، باستثناء:

- يتم تعيين `enable_creator_fee` و `creator_fee_on` من المعامل، كما في الجدول أعلاه.
- `pool_creator` هو دائمًا `creator` الموقّع. في `InitializeWithPermission` يكون المنشئ حسابًا منفصلًا غير موقّع؛ أما في `InitializeV2` فلا يمكن تعيينه لأي شخص آخر.

<Note>
  **تفعيل رسوم المنشئ لا يحدد معدلها.** تفرض المجموعة `AmmConfig.creator_fee_rate` الخاص بفئة الرسوم المرتبطة بها. على فئة يكون فيها هذا المعدل `0`، لا تراكم المجموعة المفعّلة شيئًا. اقرأ الإعدادات قبل اختيار الفئة. الاختيار دائم أيضًا: لا توجد تعليمة تغيّر `enable_creator_fee` أو `creator_fee_on` بعد الإنشاء. انظر [`products/cpmm/fees`](/ar/products/cpmm/fees#creator-fee).
</Note>

عندما تكون الرسوم مفعّلة، تراكمها المبادلات في `creator_fees_token_{0,1}`. يجمعها المنشئ عبر `CollectCreatorFee` أو `CollectCreatorFeePermissionless`، وتُطبَّق حصة البروتوكول من ترقية 2026-09-19 كالمعتاد.

**الأخطاء الشائعة** — نفس أخطاء `Initialize`.

## `Deposit`

إضافة السيولة في كلا الرمزين بنسبة متناسبة مع المجموعة.

**المعاملات**

```
lp_token_amount:   u64   // how many LP tokens to mint to the LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**الرياضيات**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // same for side 1
```

هناك تفصيلان جديران بالملاحظة: أساس النسبة المئوية هو إجمالي الخزان **المستثنى من الرسوم** (`vault_amount_without_fee`، أي الرصيد الخام مطروحاً منه عدادات البروتوكول والصندوق والمنشئ المتراكمة)، وليس رصيد الخزان الخام؛ وتُفحص حد الانزلاق مقابل ما يحوله الدافع فعلياً، *بعد* إضافة رسم نقل Token-2022، وليس مقابل حركة الخزان الإجمالية.

لا يوجد تغيير في تناسب `k` — يتم قياس كل من الإجماليات و`lp_supply` بنفس العامل.

**الشروط اللاحقة**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (صافي أي رسم نقل Token-2022 على الإدخال).
- `vault_1 += needed_token_1` (صافي أي رسم نقل Token-2022 على الإدخال).

**الأخطاء الشائعة** — `ExceededSlippage`، `ZeroTradingTokens`، `InvalidStatus` إذا كان الإيداع موقوفاً.

حرق رموز LP واستقبال كلا الرمزين الأساسيين بنسبة متناسبة.

**المعاملات**

```

minimum_token_1:   u64
```

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

الحسابات الثلاثة عشر الأولى متطابقة مع `Deposit`، و`lp_mint` قابل للكتابة لأن رموز LP يتم حرقها. يأخذ `Withdraw` بالإضافة إلى ذلك حساباً رابع عشر، `memo_program` (مقيد `address = memo::ID`) — `Deposit` لا يأخذه. يفشل `Withdraw` بـ 13 حساباً في فك تسلسل Anchor، لذا لا يمكن لصاحب LP الخروج.

**الرياضيات**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // same for side 1

// As with Deposit: the base is the fee-excluded vault total, and the floor is
// checked against what the LP actually receives, after the transfer fee.
```

**الشروط اللاحقة**

- `lp_supply -= lp_token_amount`.
- تُرسل الخزانات `out_token_0` / `out_token_1` (إجمالي؛ يستقبل المستخدم صافي أي رسم نقل Token-2022).

## `UpdateAmmConfig`

تغيير معدلات الرسوم أو الملكية على `AmmConfig` موجود. يأخذ `param: u8` (أي حقل لتحديثه) و `value: u64`. جدول الإرسال الكامل:

- `param = 0` → `trade_fee_rate` (يؤكد `trade_fee_rate + creator_fee_rate < 1_000_000`)
- `param = 1` → `protocol_fee_rate` (يؤكد `≤ 1_000_000` و `+ fund_fee_rate ≤ 1_000_000`)
- `param = 2` → `fund_fee_rate` (يؤكد `≤ 1_000_000` و `+ protocol_fee_rate ≤ 1_000_000`)
- `param = 3` → `protocol_owner`. المفتاح الجديد **ليس** في `value`: ألحقه كـ `remaining_accounts[0]` (القراءة فقط تمام). يجب ألا يكون المفتاح العام الافتراضي، وحذف الحساب يُحدث panic على `unwrap()`.
- `param = 4` → `fund_owner`. نفس الآلية كـ `3`.
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool` (أي `value` غير صفري يعطّل)
- `param = 7` → `creator_fee_rate` (يؤكد `creator_fee_rate + trade_fee_rate < 1_000_000`)
- `param = 8` → `creator_fee_share_rate` (يؤكد `≤ 1_000_000`). أضيف 2026-09-19. حصة البروتوكول الافتراضية **من رسوم المنشئ** على هذه الفئة؛ انظر [`products/cpmm/fees`](/ar/products/cpmm/fees#protocol-share-of-the-creator-fee). لا علاقة لها بـ `protocol_fee_rate`، الذي يقسم رسوم التداول.

أي `param` آخر يُرجع `InvalidInput`.

التغييرات موقّعة من قبل المسؤول وتؤثر على **كل مجموعة مرتبطة بهذا `AmmConfig`** عند المبادلة التالية. لا هجرة؛ المجموعات ببساطة تقرأ القيم الجديدة.

## `CreateCreatorFeeShare`

تعيين حصة بروتوكول مخصصة من رسوم المنشئ لزوج واحد `(creator, amm_config)`، مما يتجاوز `AmmConfig.creator_fee_share_rate` لكل مجموعة يملكها هذا المنشئ على فئة الرسوم تلك. أضيف في ترقية حصة رسوم المنشئ 2026-09-19.

**المعاملات**

```
share_rate: u64   // حصة البروتوكول من رسوم المنشئ، على FEE_RATE_DENOMINATOR = 1_000_000
```

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `owner` | W | S | يجب أن يكون مسؤول برنامج CPMM **أو** مالك حصة رسوم المنشئ المخصص — انظر [`reference/program-addresses`](/ar/reference/program-addresses#cpmm-creator-fee-share-authority). أي موقّع آخر يفشل برسالة `InvalidOwner` (`6001`). يدفع الإيجار. |
| 2 | `creator` |   |   | منشئ المجموعة الذي ينطبق عليه المعدل. غير مفحوص — لا يتعين أن يكون منشئ مجموعة موجود، ولا يوقّع. |
| 3 | `amm_config` |   |   | فئة الرسوم التي ينطبق عليها المعدل. |
| 4 | `creator_fee_share` | W |   | يتم `init` هنا في `["creator_fee_share", creator, amm_config]`، `space = 145`. |
| 5 | `system_program` |   |   | |

**الشروط المسبقة**

- `share_rate <= 1_000_000`، وإلا `InvalidInput` (`6003`).
- يجب ألا يكون PDA موجوداً بالفعل — `init` الخاص بـ Anchor يفشل عند استدعاء ثانٍ لنفس الزوج. لتغيير معدل، أغلق الحساب وأنشئه مرة أخرى.

**الشروط اللاحقة**

- `creator_fee_share` يخزن `bump`، `creator`، `amm_config` و `share_rate`.
- كل `CollectCreatorFee` / `CollectCreatorFeePermissionless` لاحق على مجموعة أنشأها `creator` تحت `amm_config` يحل الحصة من هذا الحساب بدلاً من الإعدادات.

<Note>
  منشئ المجموعة ليس طرفاً في هذه التعليمة ولا يوقّعها. يتم قراءة المعدل في وقت الجمع، لذا يتم تطبيق تجاوز تم إنشاؤه بعد تراكم الرسوم بالفعل على هذا الرصيد المتراكم أيضاً.
</Note>

## `CloseCreatorFeeShare`

إزالة التجاوز. يعود الزوج إلى `AmmConfig.creator_fee_share_rate`.

**المعاملات** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `owner` | W | S | نفس الموقّعين المقبولين كما في `CreateCreatorFeeShare`؛ يستقبل الإيجار. |
| 2 | `creator` |   |   | منشئ المجموعة الذي كان ينطبق عليه المعدل. |
| 3 | `amm_config` |   |   | فئة الرسوم التي كان ينطبق عليها المعدل. |
| 4 | `creator_fee_share` | W |   | مُغلق إلى `owner`. يجب أن يكون PDA الأساسي للزوج. |
| 5 | `system_program` |   |   | |

**الشروط اللاحقة**

- الحساب مُغلق وتذهب lamports الخاصة به إلى `owner`.
- الجمع لهذا الزوج يحل الحصة من `amm_config.creator_fee_share_rate` مرة أخرى — وهي `0` ما لم يقم المسؤول بتعيين معامل `UpdateAmmConfig` `8`.

## `CollectExcessLamports`

عملية مسح إداري لـ lamports المتراكمة فوق الحد الأدنى المعفي من الإيجار على الحسابات التي يتحكم بها CPMM. تمت إضافتها في ترقية 2026-09 بحيث يمكن للبروتوكول استرجاع الإفراط في التمويل الذي يتركه [تقليل الإيجار SIMD-0437](/ar/solana-fundamentals/rent-and-reclaimable-rent) على الحسابات المُنشأة قبل كل خطوة.

ينتقل الفائض فقط. أرصدة الرموز وبيانات الحساب والمالكون وحالة المجموعة والمنحنى تبقى دون تغيير، والتعليمة لا تفعل شيئًا ضد حساب بالفعل عند الحد الأدنى — لذا من الآمن إعادة تشغيلها بعد كل خطوة نشر.

**الوسائط** — لا توجد.

**الحسابات**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | الوجهة لكل lamport مُكتسح. يجب أن يكون إما مسؤول برنامج CPMM أو محفظة جمع lamports المخصصة — انظر [`reference/program-addresses`](/ar/reference/program-addresses#excess-lamports-collection-wallets). أي موقّع آخر يفشل مع `InvalidOwner`. |
| 2 | `authority` |   |   | PDA سلطة vault و LP mint في البذرة `[b"vault_and_lp_mint_auth_seed"]`. يوقّع CPIs برنامج الرموز. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. كلاهما مطلوب بشكل غير مشروط؛ يختار البرنامج لكل حساب مصدر. |
| 5.. | `remaining_accounts` | W |   | `M` حساب مصدر للمسح، أي عدد، أي ترتيب. |

<Note>
  **إصلاح الترتيب، 2026-09-19.** يقوم البرنامج الآن بمسحتين على `remaining_accounts` — كل CPIs برنامج الرموز أولاً، ثم الخصومات المباشرة لـ PDAs المملوكة لـ CPMM. كان الفصل بينها يؤدي إلى الإجهاض مع `UnbalancedInstruction` للوقت التشغيلي ("مجموع أرصدة الحساب قبل وبعد التعليمة لا تتطابق") كلما تم خصم PDA قبل CPI، لأن التغييرات المعلقة في lamports للمتصل يتم تفريغها فقط في الحسابات التي تحملها CPI فعلاً. لا يتعين على المتصلين تجميع أو فرز القائمة بأنفسهم.
</Note>

**كيفية التعامل مع كل حساب مصدر**

يقوم البرنامج بالتوزيع على `owner` حساب المصدر:

| مالك حساب المصدر | المعالجة |
|---|---|
| SPL Token أو Token-2022، حساب رمز غير أصلي أو mint — خزائن المجموعة و LP mints | CPI `WithdrawExcessLamports` (مميز برنامج الرموز `38`)، موقّع بواسطة `authority`. |
| SPL Token أو Token-2022، **أصلي** (wSOL) حساب رمز | `WithdrawExcessLamports` يرفض الحسابات الأصلية. يقوم البرنامج بـ CPI `SyncNative`، يقيس مقدار نمو `amount` المُغلّف، `UnwrapLamports` (مميز `45`) لهذا الفرق بالضبط، ثم يتطلب أن يساوي الرصيد المُغلّف قيمته قبل المزامنة — وإلا `LamportsCalculateError` (`6015`). وبالتالي تحتفظ خزانة المجموعة من جانب SOL بسيولتها الكاملة. |
| برنامج CPMM نفسه — `PoolState`، `AmmConfig`، `ObservationState`، `Permission`، `SupportMintAssociated` | يقوم البرنامج بخصم الحساب مباشرة إلى `rent.minimum_balance(data_len)`. |
| أي شيء آخر | **يتم تخطيه بصمت.** لا خطأ، لا lamports مُنقولة. |

لأنها تأخذ قائمة `remaining_accounts` غير محدودة، حجم المعاملة هو الحد الحقيقي — نفس القيد كما هو الحال في المسح من جانب المحفظة الموصوف في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**الأخطاء الشائعة** — `InvalidOwner` (`6001`، موقّع خاطئ)، `LamportsCalculateError` (`6015`، رحلة wSOL ذهابًا وإيابًا لم تصل إلى الصفر)، و `InsufficientFunds` من مسار المملوك للبرنامج عندما يحتفظ الحساب بأقل من الحد الأدنى للإيجار الخاص به.

**لا يوجد منشئ SDK.** `@raydium-io/raydium-sdk-v2` لا يشحن منشئًا لهذه التعليمة، وكذلك مستودع `raydium-sdk-V2-demo` — إنها مسار إداري. قم بترميزها يدويًا، بالطريقة التي يفعلها المسح من جانب المحفظة في [`solana-fundamentals/rent-and-reclaimable-rent`](/ar/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) لتعليمة برنامج الرموز.
