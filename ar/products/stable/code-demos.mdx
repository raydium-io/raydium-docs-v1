  - SDK: `@raydium-io/raydium-sdk-v2@0.2.64-alpha`
  - الكتلة: Solana `mainnet-beta`
  - معرّف برنامج Stable AMM: `5quBtoiQqxF9Jv6KYKctB59NT3gtJD2Y65kdnB1Uev3h` (انظر [`reference/program-addresses`](/ar/reference/program-addresses))

  وحدة `liquidity` في SDK تتعامل مع مجمعات Stable AMM بشكل أصلي. تظهر مجمعات الاستقرار كـ **`version: 5`** (أو `pooltype: "StablePool"`) على `ApiV3PoolInfoStandardItem`؛ نفس مساعدات `addLiquidity` / `removeLiquidity` / swap تعمل معها كما هو الحال مع مجمعات الناتج الثابت AMM v4 (`version: 4`) — يكتشف SDK المتغير ويصدر التعليمات الصحيحة تلقائيًا. رياضيات منحنى الاستقرار خارج السلسلة توجد في `src/raydium/liquidity/stable.ts`.
</Info>

## الإعداد

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
```

```ts
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import BN from "bn.js";
import bs58 from "bs58";

const connection = new Connection(clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(bs58.decode(process.env.PRIVATE_KEY!));

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });

// مطلوب قبل أي اقتباس لمجمع Stable. يجلب initLayout() جدول البحث
// ModelDataInfo على السلسلة إلى raydium.liquidity.stableLayout.
await raydium.liquidity.initLayout();
```

<Warning>
  **`initLayout()` ليس اختياريًا لمجمعات Stable.** يتفرع `liquidity.computeAmountOut` على `poolInfo.version`: بالنسبة للإصدار 4 يستخدم صيغة الناتج الثابت، وبالنسبة لأي شيء آخر يقرأ `this.stableLayout.stableModelData` ويقحم جدول البحث. هذا الذاكرة المؤقتة فارغة حتى يعمل `initLayout()`، لذا فإن اقتباس مجمع v5 بدونها ينتج عنه قمامة بدلاً من خطأ. إنه عملية متكررة وغير مكلفة — استدعه مرة واحدة عند بدء التشغيل.

  منشئو المعاملات (*builders*) (`swap`, `addLiquidity`, `removeLiquidity`) لا يحتاجون إليه: يتم الإرسال على `pooltype.includes("StablePool")` وإصدار تعليمات `AmmV5*`، وحدود المبلغ التي تمررها مُحسوبة بالفعل.
</Warning>

<Warning>
  **`liquidity.computeAmountIn` لا يدعم مجمعات Stable.** بخلاف `computeAmountOut`، لا يوجد فرع إصدار — يطبق دائمًا معكوس الناتج الثابت، لذا على مجمع v5 يعيد `maxAmountIn` خاطئ. لمبادلة ناتج دقيق مقابل مجمع Stable، اعكس باستخدام `getDxByDyBaseIn` بنفسك (انظر [مساعدات الاقتباس خارج السلسلة](#off-chain-quote-helpers-stablets) أدناه) ومرر النتيجة إلى `swap` مع `fixedSide: "out"`.
</Warning>

## تحديد مجمع Stable

إشارتان متكافئتان على `ApiV3PoolInfoStandardItem`:

```ts
const isStable =
  pool.version === 5 ||
  pool.pooltype.includes("StablePool"); // SDK يستخدم فحص السلسلة هذا داخليًا

// بدلاً من ذلك، حسب معرّف البرنامج:
const STABLE_AMM_PROGRAM_ID = "5quBtoiQqxF9Jv6KYKctB59NT3gtJD2Y65kdnB1Uev3h";
const isStableByProgram = pool.programId === STABLE_AMM_PROGRAM_ID;
```

يتدفق كل من AMM v4 (`version: 4`، الناتج الثابت) و Stable AMM (`version: 5`) عبر نفس واجهة برمجة تطبيقات `LiquidityModule` على SDK. داخليًا تتفرع الوحدة إلى:

- `InstructionType.AmmV4AddLiquidity` / `AmmV4RemoveLiquidity` لمجمعات v4
- `InstructionType.AmmV5AddLiquidity` / `AmmV5RemoveLiquidity` لمجمعات v5 (Stable)

يخبر `programId` للمجمع (المُرجع مع مفاتيح المجمع) SDK ببرنامج CPI؛ لا تحتاج إلى ترميزه بشكل ثابت.

## البحث عن مجمع حسب زوج العملات

```ts
import { PublicKey } from "@solana/web3.js";
import type { ApiV3PoolInfoStandardItem } from "@raydium-io/raydium-sdk-v2";

// عملتان شائعتان للاستخدام كمثال
const mintA = new PublicKey("Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB"); // USDT — انظر reference/program-addresses
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// fetchPoolByMints يعيد غلاف مرقّم: { count, data, hasNextPage }
const res = await raydium.api.fetchPoolByMints({
  mint1: mintA.toBase58(),
  mint2: mintB.toBase58(),
});

const stablePool = res.data.find(
  (p) => p.version === 5 || p.pooltype.includes("StablePool"),
) as ApiV3PoolInfoStandardItem | undefined;

if (!stablePool) {
  throw new Error("No Stable pool exists for this mint pair");
}

console.log("Stable pool id:", stablePool.id);
console.log("Stable pool programId:", stablePool.programId);
console.log("TVL:", stablePool.tvl);
```

إذا كان زوج العملات يحتوي على مجمع v4 (ناتج ثابت) ومجمع v5 (مستقر)، تتضمن الاستجابة كليهما — اختر الذي يحتاجه تدفقك، أو سلّمهما إلى برنامج [AMM Routing](/ar/products/routing) واترك له اختيار أفضل مسار.

## المبادلة عبر مجمع Stable

تدفق `LiquidityModule.swap` له نفس الشكل كما هو الحال مع مجمعات v4 — فقط سلّمه كائن v5. هناك تفصيلان من السهل الخطأ فيهما: `computeAmountOut` يحتاج إلى **الاحتياطيات الحية** للمجمع المدمجة في معلومات المجمع (عنصر واجهة برمجة التطبيقات وحده لا يحملها)، و `slippage` الخاص به هو **رقم** عادي، وليس `Percent`:

```ts
import BN from "bn.js";

const amountIn = new BN(1_000_000); // 1 USDT (6 عشريات)، وحدات خام

// الاحتياطيات الحية + الحالة. على mainnet يمكنك أيضًا أخذ poolKeys من
// getAmmPoolKeys(poolId) والاحتياطيات من getRpcPoolInfo(poolId).
const rpcData  = await raydium.liquidity.getRpcPoolInfo(stablePool.id);
const poolKeys = await raydium.liquidity.getAmmPoolKeys(stablePool.id);

const out = raydium.liquidity.computeAmountOut({
  poolInfo: {
    ...stablePool,
    baseReserve:  rpcData.baseReserve,
    quoteReserve: rpcData.quoteReserve,
    status:       rpcData.status.toNumber(),
    version:      5, // 5 = Stable؛ يتم اختيار فرع المنحنى على هذا
  },
  amountIn,
  mintIn:  stablePool.mintA.address,
  mintOut: stablePool.mintB.address,
  slippage: 0.005, // رقم عادي: 0.005 = 0.5% (النطاق 1 ~ 0.0001)
});

// amountOut / minAmountOut هي BN بوحدات خام، وليست TokenAmount.
console.log("Expected out:", out.amountOut.toString());
console.log("Minimum out:", out.minAmountOut.toString());

// بناء وتوقيع معاملة المبادلة. `inputMint` مطلوب — بدونه لا يستطيع
// SDK معرفة أي جانب من المجمع تبيع.
const { transaction, execute } = await raydium.liquidity.swap({
  poolInfo:  stablePool,
  poolKeys,
  amountIn,
  amountOut: out.minAmountOut, // out.amountOut هو الرقم قبل الانزلاق
  inputMint: stablePool.mintA.address,
  fixedSide: "in",
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Stable swap tx:", txId);
```

يقرأ SDK `programId` للمجمع من مفاتيح المجمع ويتفرع إلى برنامج Stable AMM. لا يلزم أي حجة `programId` خاصة.

## إضافة وإزالة السيولة

يعمل `addLiquidity` و `removeLiquidity` بشكل متطابق عبر مجمعات v4 و v5:

```ts
import { Percent, TokenAmount, toToken } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

const inputAmount = "100"; // 100 USDT، بوحدات بشرية — computePairAmount يأخذ سلسلة عشرية

// احسب مبلغ B المطابق الذي يتطلبه المنحنى لهذا الحجم من A.
// ملاحظة: slippage الخاص بـ computePairAmount هو Percent (بخلاف computeAmountOut).
const r = raydium.liquidity.computePairAmount({
  poolInfo: stablePool,
  amount:   inputAmount,
  baseIn:   true,
  slippage: new Percent(50, 10_000), // 0.5%
});

const { execute } = await raydium.liquidity.addLiquidity({
  poolInfo: stablePool,
  poolKeys,
  amountInA: new TokenAmount(
    toToken(stablePool.mintA),
    new Decimal(inputAmount).mul(10 ** stablePool.mintA.decimals).toFixed(0),
  ),
  amountInB: new TokenAmount(
    toToken(stablePool.mintB),
    new Decimal(r.maxAnotherAmount.toExact()).mul(10 ** stablePool.mintB.decimals).toFixed(0),
  ),
  otherAmountMin: r.minAnotherAmount,
  fixedSide:      "a",
  txVersion:      TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Add-liquidity tx:", txId);
```

داخليًا يصدر SDK `InstructionType.AmmV5AddLiquidity` لأن `pooltype.includes("StablePool")` صحيح. تدفق `removeLiquidity` المقابل متماثل — أدخل `lpAmount` والحد الأدنى من المبالغ التي ستقبلها على كل جانب.

## مساعدات الاقتباس خارج السلسلة (stable.ts)

للاقتباس من جانب الخادم أو الاختبار العكسي، يكشف SDK عن رياضيات منحنى الاستقرار الأساسية:

```ts
import {
  getStablePrice,
  getDxByDyBaseIn,
  getDyByDxBaseIn,
} from "@raydium-io/raydium-sdk-v2";

// يجب استدعاء initLayout() مرة واحدة قبل استخدام هذه (تحميل
// PDA `ModelDataInfo` على السلسلة إلى ذاكرة StableLayout المؤقتة للـ SDK).
await raydium.liquidity.initLayout();

// initLayout() يملأ مثيل StableLayout؛ كائن البيانات العادي الذي
// تتوقعه المساعدات الثلاث أدناه هو getter `stableModelData` الخاص به، وليس المثيل.
const modelData = raydium.liquidity.stableLayout.stableModelData;

// يتم تمرير الاحتياطيات كأرقام عادية بوحدات بشرية (وليست BN، وليست وحدات خام).
const coinReserve = 1_200_000; // احتياطي جانب العملة للمجمع
const pcReserve   = 1_150_000; // احتياطي جانب الكمبيوتر للمجمع

// السعر الفوري عند احتياطيات المجمع الحالية. الحجة الرابعة هي `baseCoin`:
// true يعيد عملة لكل كمبيوتر، false يعيد المعكوس.
const price = getStablePrice(modelData, coinReserve, pcReserve, true);
console.log("Spot price:", price);

// اقتباس: بالنظر إلى dx في، كم dy خارج (بدون رسوم مطبقة هنا)؟
const dyOut = getDyByDxBaseIn(modelData, coinReserve, pcReserve, 1_000);

// اقتباس: بالنظر إلى هدف dy خارج، كم dx في مطلوب؟
const dxIn  = getDxByDyBaseIn(modelData, coinReserve, pcReserve, 1_000);
```

هذه دوال نقية — لا RPC، لا توقيع. يتم جلب `ModelDataInfo` على السلسلة مرة واحدة بواسطة `initLayout()` وتخزينها مؤقتًا داخل `raydium.liquidity.stableLayout`، قابلة للقراءة كـ `.stableModelData`. `initStableModelLayout()` عملية متكررة: تعيد الجلب فقط بينما `validDataCount === 0`، لذا استدعاء `initLayout()` مرة أخرى مجاني. مرر الاحتياطيات الحالية (`x`, `y`) والمساعدات تحسب بالبحث الثنائي عن جدول البحث والاستيفاء الخطي بين صفي `DataElement` المحيطين. انظر [`products/stable/math`](/ar/products/stable/math) للخوارزمية الأساسية.

## التوجيه عبر AMM Routing (متعدد القفزات / أفضل سعر)

إذا كنت لا تريد اختيار مكان بنفسك، فسيأخذ برنامج [AMM Routing](/ar/products/routing) في الاعتبار كل Raydium AMM (v4 / CPMM / CLMM / Stable) والتوجيه عبر أي مزيج هو الأفضل:

الموجه عبارة عن خط أنابيب من خمس استدعاءات بدلاً من `swap()` واحد، وهو مكتوب بالكامل — مع نصيحة التخزين المؤقت التي تجعله قابلاً للاستخدام في الإنتاج — على [`products/routing/code-demos`](/ar/products/routing/code-demos). الشكل هو:

```ts
import { Router } from "@raydium-io/raydium-sdk-v2";

const poolData = await raydium.tradeV2.fetchRoutePoolBasicInfo(); // خزّن هذا مؤقتًا
const routes   = raydium.tradeV2.getAllRoute({ inputMint: mintA, outputMint: mintB, ...poolData });
const ctx      = await raydium.tradeV2.fetchSwapRoutesData({ routes, inputMint: mintA, outputMint: mintB });
const quotes   = raydium.tradeV2.getAllRouteComputeAmountOut({ /* ...ctx, amount, slippage, ... */ });

const best = quotes[0]; // مرتب الأفضل أولاً
if (!best) throw new Error("no swap routes were found");

// إدخالات best.poolInfoList تحمل `version` — 5 يشير إلى مجمع Stable في المسار.
console.log(best.routeType, best.poolInfoList.map((p) => p.version));

const poolKeys = await raydium.tradeV2.computePoolToPoolKeys({
  pools: best.poolInfoList,
  ammRpcData:  ctx.ammPoolsRpcInfo,
  clmmRpcData: ctx.clmmPoolsRpcInfo,
});

const { execute } = await raydium.tradeV2.swap({
  routeProgram: Router,
  swapInfo:     best,
  swapPoolKeys: poolKeys,
  ownerInfo:    { associatedOnly: true, checkCreateATAOwner: true },
  txVersion:    TxVersion.V0,
});

// tradeV2.swap قد يعيد عدة معاملات؛ الأولى تنشئ ATAs وسيطة.
const { txIds } = await execute({ sequentially: true });
```

<Warning>
  لا يوجد `raydium.tradeV2.fetchRoutes`، و `tradeV2.swap` **لا** يقبل `inputMint` / `outputMint` / `slippage` — يأخذ `swapInfo` محسوب بالفعل من `getAllRouteComputeAmountOut`. لمجمع **واحد** معروف، استخدم منشئ نوع المجمع الخاص به (`raydium.liquidity.swap` لـ AMM v4 و Stable، `raydium.cpmm.swap`، `raydium.clmm.swap`) كما هو موضح سابقًا على هذه الصفحة.
</Warning>

هذا هو المسار الموصى به لمبادلات الإنتاج والمجمعات — لا تحتاج أبدًا إلى تحديد ما إذا كان مجمع Stable موجودًا أو ما إذا كان أفضل مكان اليوم.

## التوصيات

1. **لمبادلات المستخدم النهائي**، فضّل تدفق التوجيه [`tradeV2`](/ar/products/routing). يتعامل مع كل نوع مجمع Raydium بما في ذلك Stable.
2. **للعمليات الخاصة بالمجمع** (إضافة / إزالة LP على مجمع Stable معروف)، استخدم `LiquidityModule` مباشرة — يكتشف تلقائيًا مجمعات v5.
3. **للاقتباس خارج السلسلة / التحليلات**، استدعِ `getStablePrice` / `getDyByDxBaseIn` / `getDxByDyBaseIn` بعد `initLayout()`. لا حركة RPC لكل اقتباس بعد تخزين بيانات النموذج مؤقتًا.
4. **لا تقم بترميز تعليمات `SwapBaseIn` الخام يدويًا.** أزالت [ترقية 2026-06-22](/ar/reference/changelog) حسابات OpenBook الميتة، لذا يأخذ تخطيط المبادلة الجديد **9 حسابات** (التخطيط القديم 18 حساب لا يزال يحلل للتوافق العكسي). `Deposit` الآن 12 حساب (القديم 14 متوافق)، `Withdraw` 12 (القديم 21/22 متوافق)، و `WithdrawPnl` 10 **بدون** مسار توافق. تختار مساعدات SDK المدمجة مسبقًا التخطيط والترتيب الصحيح لك؛ لف الخاص بك عرضة للخطأ. انظر [`products/stable/instructions`](/ar/products/stable/instructions) لجداول الحسابات الكاملة.
