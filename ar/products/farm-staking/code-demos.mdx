## الإعداد

الأمثلة هنا تعكس الملفات في [`raydium-sdk-V2-demo/src/farm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/farm). يتبع التمهيد [`config.ts.template`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template) من مستودع العرض التوضيحي:

```ts
import { Connection, Keypair, clusterApiUrl, PublicKey } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);
const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
export const txVersion = TxVersion.V0;
```

## جلب مزرعة حسب المعرّف

لا توجد `raydium.farm.getFarmById`. يبدأ كل عرض توضيحي للمزرعة من وحدة API، التي تُرجع شكل `FormatFarmInfoOut` المُطبّع الذي تأخذه `deposit` / `withdraw` / `harvestAllRewards`:

```ts
const farmId = "CHYrUBX2RKX8iBg7gYTkccoGNBzP44LdaazMHCLcdEgS"; // RAY-USDC farm

const farmInfo = (await raydium.api.fetchFarmInfoById({ ids: farmId }))[0];
if (!farmInfo) throw new Error("farm not found");

console.log("LP mint:", farmInfo.lpMint.address);
console.log("TVL:", farmInfo.tvl);
for (const r of farmInfo.rewardInfos) {
  console.log("  -", r.mint.address, r.mint.symbol);
}
```

تأخذ `fetchFarmInfoById` **سلسلة معرّفات مفصولة بفواصل** وتُرجع مصفوفة، لذا يمكن لاستدعاء واحد أن يملأ محفظة كاملة. إذا كنت بحاجة إلى مفاتيح الحساب الخام بدلاً من معلومات العرض، فإن `raydium.api.fetchFarmKeysById({ ids })` تُرجع الأقبية والسلطات PDAs؛ يستدعيها SDK داخليًا لك داخل كل منشئ أدناه.

## رهن رموز LP

المصدر: [`src/farm/stake.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/stake.ts)

```ts
// يرهن العرض التوضيحي رصيد LP الكامل للمحفظة؛ أي BN بالوحدات الخام يعمل.
const amount = raydium.account.tokenAccountRawInfos.find(
  (a) => a.accountInfo.mint.toBase58() === farmInfo.lpMint.address,
)?.accountInfo.amount;

if (!amount || amount.isZero()) throw new Error("user does not have an LP balance");

const { execute } = await raydium.farm.deposit({
  farmInfo,
  amount,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Deposit tx:", txId);
```

يتعامل SDK مع التسوية المسبقة لأي مكافآت معلقة، لذا إذا كانت هذه المحفظة بها رهن بالفعل في هذه المزرعة، فستدفع التعليمات المكافآت المتراكمة إلى ATAs المستخدم في نفس المعاملة.

## المطالبة فقط (الحصاد)

المصدر: [`src/farm/harvest.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/harvest.ts)

`farmInfoList` هو **`Record` مفهرس حسب معرّف المزرعة**، وليس مصفوفة، والمنشئ يُرجع **معاملات متعددة** — لذا يجب إعطاء `execute` `sequentially: true`:

```ts
const farmIds = [farmId, "<ANOTHER_FARM_ID>"];
const farmInfos = await raydium.api.fetchFarmInfoById({ ids: farmIds.join(",") });

const { execute } = await raydium.farm.harvestAllRewards({
  farmInfoList: Object.fromEntries(farmInfos.map((f) => [f.id, f])),
  txVersion: TxVersion.V0,
});

const { txIds } = await execute({ sequentially: true });
console.log("harvest txs:", txIds);
```

يضغط المنشئ على أكبر عدد ممكن من المزارع لكل معاملة حسب حد 1232 بايت ويقسم الباقي إلى معاملات متابعة، وهذا هو السبب في أنه يُرجع `txIds` بدلاً من `txId` واحد.

بالنسبة لمزرعة واحدة، قم بالحصاد باستخدام اصطلاح `amount: 0` — هذا ما يفعله [`src/farm/harvest.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/harvest.ts)، في كل إصدار بما في ذلك v6:

```ts
const { execute } = await raydium.farm.withdraw({
  farmInfo,
  amount: new BN(0),        // 0 = harvest-only path
  txVersion: TxVersion.V0,
});
await execute({ sendAndConfirm: true });
```

## إنشاء مزرعة v6

المصدر: [`src/farm/createAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/createAmmFarm.ts) و [`editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts)

تأخذ `create` **كائن معلومات المجمع** للمجمع الذي يتم رهن رموز LP الخاصة به (وليس رمز عاري)، وكل إدخال من `rewardInfos` هو `FarmRewardInfo`: `{ mint: PublicKey, perSecond: string, openTime: number, endTime: number, rewardType: "Standard SPL" | "Option tokens" }`. الأوقات هي **ثوانٍ عادية**، و `perSecond` هي **سلسلة**، وليست `BN`. يتم تعيين `programId` افتراضيًا إلى برنامج v6، لذا نادرًا ما تمرره.

```ts
import type { ApiV3PoolInfoStandardItem, FarmRewardInfo } from "@raydium-io/raydium-sdk-v2";
import { RAYMint } from "@raydium-io/raydium-sdk-v2";

// المجمع الذي تملكه والذي سيكون رمز LP الخاص به هو رمز الرهن.
const poolInfo = (
  await raydium.api.fetchPoolById({ ids: "<POOL_ID>" })
)[0] as ApiV3PoolInfoStandardItem;
if (!poolInfo) throw new Error("pool not found");

const rewardMint = await raydium.token.getTokenInfo(RAYMint);

// استخدم وقت السلسلة، وليس وقت الحائط — يتحقق البرنامج من الأول.
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);
const endTime  = openTime + 60 * 60 * 24 * 7; // 7 days

const rewardInfos: FarmRewardInfo[] = [
  {
    mint:       new PublicKey(rewardMint.address),
    perSecond:  "1",              // string, in raw units per second
    openTime,                      // seconds, not BN
    endTime,
    rewardType: "Standard SPL",   // "Option tokens" is the only other value
  },
];

const { execute, extInfo } = await raydium.farm.create({
  poolInfo,
  rewardInfos,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Farm:", extInfo.farmId.toBase58(), "createTx:", txId);
```

النقاط الرئيسية:

- `perSecond` هو معدل الانبعاث في الثانية بالوحدات **الخام** لرمز المكافأة، يتم تمريره كسلسلة عشرية. يقوم SDK بحزمه في تمثيل النقطة الثابتة على السلسلة قبل الإرسال.
- يجب أن تكون الميزانية الكاملة (`perSecond × (endTime − openTime)`) موجودة في ATA المكافأة الخاصة بك — `create` تنقلها إلى قبو المكافأة بشكل ذري.
- **لا يتم دعم رموز المكافآت Token-2022 من قبل منشئي المزرعة في SDK** في إصدار SDK هذا؛ استخدم رمز SPL عادي للمكافآت.
- يمكنك بذر ما يصل إلى 5 مكافآت في استدعاء `create` واحد. تنمو قائمة الحساب بمقدار `(reward_mint, reward_vault, sender_ata, token_program)` لكل تدفق إضافي؛ كن على دراية بحد حجم المعاملة 1232 بايت. بالنسبة لـ 4+ مكافآت، قم بالإنشاء بـ 1–2 واستخدم `addNewRewardsToken` في المعاملات اللاحقة.

## إضافة تدفق مكافأة جديد

لا توجد `raydium.farm.setRewards`. المنشئان اللذان يغيران مكافآت المزرعة هما `addNewRewardToken` / `addNewRewardsToken` (احتل فتحة حرة برمز **جديد**) و `restartReward` / `restartRewards` (أعد تسليح فتحة انتهى تدفقها). كلاهما يأخذ كائنات `FarmRewardInfo` بنفس الشكل الذي تستخدمه `create`.

```ts
import { USDCMint } from "@raydium-io/raydium-sdk-v2";

const added = await raydium.token.getTokenInfo(USDCMint);
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);

const { execute } = await raydium.farm.addNewRewardsToken({
  farmInfo,
  newRewardInfos: [
    {
      mint:       new PublicKey(added.address),
      perSecond:  "1",
      openTime,
      endTime:    openTime + 60 * 60 * 24 * 7,
      rewardType: "Standard SPL",
    },
  ],
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

يتم سحب ميزانية الفرق (`perSecond × duration`) من ATA الدافع كجزء من المعاملة. التعليمة الأساسية لا يمكنها تقصير التدفق، ولا يمكنها خفض `per_second` على تدفق مباشر، ولا يمكنها تغيير رمز المكافأة للفتحة — لتبديل الرموز، انتظر `end_time` واستخدم `addNewRewardsToken` على فتحة محررة، أو أنشئ مزرعة جديدة.

<Tip>
  `restartRewards` و `addNewRewardsToken` كل منهما يُرجع منشئًا، لذا يمكن لمعاملة واحدة أن تفعل كليهما. [`src/farm/editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts) يوضح النمط: `editFarmBuilder.builder.addInstruction(addNewRewardBuildData.builder.AllTxData)`، ثم `versionBuild({ txVersion })` واحد.
</Tip>

## إعادة تشغيل تدفق منتهٍ

المصدر: [`src/farm/editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts)

تأخذ `restartRewards` **`newRewardInfos`** (جمع، مصفوفة)؛ `restartReward` هي الشكل ذو العنصر الواحد وتأخذ `newRewardInfo`. حقل الرمز هو `mint`، وليس `rewardMint`، ويجب أن يطابق فتحة موجودة بالفعل على المزرعة — يبحث المنشئ عن الفتحة حسب الرمز ويرمي خطأ إذا كانت غائبة.

```ts
import type { FarmRewardInfo } from "@raydium-io/raydium-sdk-v2";

// أعد تسليح فتحة المكافأة الأولى الموجودة بالمزرعة.
const existing = await raydium.token.getTokenInfo(farmInfo.rewardInfos[0].mint.address);
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);

const newRewardInfos: FarmRewardInfo[] = [
  {
    mint:       new PublicKey(existing.address),
    perSecond:  "1",
    openTime,
    endTime:    openTime + 60 * 60 * 24 * 14,
    rewardType: "Standard SPL",
  },
];

const { execute } = await raydium.farm.restartRewards({
  farmInfo,
  newRewardInfos,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

`restartRewards` هي **v6 فقط** — يقرأ المنشئ معرّف برنامج المزرعة ويرمي خطأ لمزارع v3 / v5. صحيح فقط عندما يكون `reward_state == 2` للفتحة المستهدفة (انتهى)؛ يجب أن يكون المتصل هو `reward_sender` للفتحة. لاحظ أن `openTime >= endTime` يتم رفضه من جانب العميل قبل إجراء أي RPC.

## Rust CPI

<Warning>
  **لا توجد صندوق `raydium_farm_v6` Anchor.** لا يوجد صندوق بهذا الاسم على crates.io، لا ينشر برنامج Farm v6 أي IDL على السلسلة (لا حساب `anchor:idl` قديم ولا إدخال في برنامج Program Metadata)، ولا يوجد مستودع مصدر عام له. أظهر إصدار سابق من هذه الصفحة مثالاً على `raydium_farm_v6::cpi::deposit`؛ لم يتم تجميعه مقابل أي شيء وتم حذفه.
</Warning>

تم نشر Farm v6 آخر مرة في 2024-05-13 وليس برنامج Anchor من وجهة نظر المدمج. إذا كنت بحاجة إلى التكوين معه من برنامجك الخاص على السلسلة، فقم بإنشاء `Instruction` يدويًا — اشتق قائمة الحساب ومميزات التعليمات بشكل مستقل (من تخطيطات TypeScript في SDK تحت `raydium-sdk-V2/src/raydium/farm/`، أو بفك تشفير المعاملات الحقيقية)، و `invoke_signed` لها. انظر [`sdk-api/rust-cpi`](/ar/sdk-api/rust-cpi#farm-v6) لهذا الإجراء.

أيًا كان المسار الذي تسلكه، يجب أن تطابق ذيل `remaining_accounts` فتحات المكافآت النشطة للمزرعة 1-لـ-1 (أزواج من `reward_vault_i`، `user_reward_ata_i` بترتيب الفهرس). قد يؤدي حذف أو إساءة ترتيب هذه إلى سوء محاسبة صامت — سيقوم البرنامج بتحويل المبلغ الخاطئ.

## الأخطاء الشائعة

- **نسيان المطالبة قبل الانسحاب.** غير ضار — `Withdraw` تسوي المكافآت المعلقة أولاً. لكن إذا كان واجهة المستخدم الخاصة بك تعرض "مطالبة" بشكل منفصل عن "انسحاب"، قد يعتقد المستخدم أن هناك شيئًا آخر للمطالبة به بعد `Withdraw`. لا يوجد؛ تم دفع كل شيء متراكم حتى تلك النقطة.
- **`total_staked = 0` أثناء الانبعاثات.** يتم مصادرة الانبعاثات المتراكمة بينما لم يكن هناك شيء مرهون (تقسم صيغة تحديث `reward_per_share` على 0 ويتخطى البرنامج التحديث). بالنسبة للبرامج ذات `open_time` المجدول، قم بتشغيل "رهن البذور" في open_time لتجنب هذا.
- **رسوم نقل Token-2022.** على مزارع v6 برموز مكافآت Token-2022، تنطبق رسوم النقل عند الانبعاث (قبو → مستخدم). ضع هذا في الاعتبار في عروض APR.
- **`per_second` صغير على v5.** معدل `u64` في v5 يعني أن أي `per_second < 1` وحدة رمز في الثانية (على الرموز ذات ≥9 علامات عشرية هذا غالبًا ما يكون المعدل المطلوب) لا يمكن التعبير عنه — معدل التدفق يقرب إلى 0 والمزرعة لا تنبعث شيئًا. استخدم v6.
