## جرد التعليمات

| المجموعة | التعليمة | ملاحظات |
|-------|---------|--------|
| المسؤول | `CreateAmmConfig` | تحديد فئة رسوم جديدة. |
| المسؤول | `UpdateAmmConfig` | تغيير الأسعار على فئة موجودة. |
| المسؤول | `UpdatePoolStatus` | إيقاف/استئناف العمليات على مجمع. |
| المسؤول | `CreateSupportMintAssociated` | السماح بقائمة تكوين امتداد Token-2022 mint للاستخدام في مجمعات CLMM. |
| المسؤول | `CreateOperationAccount` | تهيئة حساب العملية على مستوى البرنامج (مرة واحدة). |
| المسؤول | `UpdateOperationAccount` | تعديل قائمة البيض الخاصة بحساب العملية. |
| المسؤول | `CreateDynamicFeeConfig` | إنشاء مجموعة معاملات رسوم ديناميكية قابلة لإعادة الاستخدام تحت فهرس u16. |
| المسؤول | `UpdateDynamicFeeConfig` | تعديل `DynamicFeeConfig` موجود. المجمعات التي التقطت لقطة منه بالفعل لا تتأثر. |
| المسؤول | `CreatePermissionPda` | منح سلطة الحق في استدعاء `CreatePermissionedPool` بتهيئة PDA `Permission` الخاص بها. |
| المسؤول | `ClosePermissionPda` | إلغاء إذن تم منحه مسبقًا بإغلاق PDA `Permission` الخاص به؛ يتم استرجاع الإيجار للمتصل. |
| المجمع | `CreatePool` | تهيئة مجمع CLMM مرتبط بـ `AmmConfig`. المسار القياسي، FromInput-fee. يتعايش مع `CreateCustomizablePool`. |
| المجمع | `CreateCustomizablePool` | موصى به للمجمعات الجديدة. نفس الشكل مثل `CreatePool` بالإضافة إلى `collect_fee_on` وعلم `enable_dynamic_fee` اختياري. |
| المجمع | `CreatePermissionedPool` | إنشاء مجمع **إضافي** لزوج لديه بالفعل واحد، باستخدام `seed_index` المزود من قبل العميل مطويًا في PDA المجمع. يجب أن يحتفظ الدافع بـ PDA `Permission`. |
| المركز | `OpenPosition` / `OpenPositionV2` / `OpenPositionWithToken22Nft` | صك NFT للمركز. `OpenPositionV2` يحل محل V1؛ `OpenPositionWithToken22Nft` يصدر NFT كـ Token-2022. تجمد مسارات V2 حساب NFT فقط عندما تطابق سلطة التجميد الأساسية لـ vault mint قائمة المُصدر المقيد. وإلا يبقى الحساب غير مجمد. |
| المركز | `IncreaseLiquidity` / `IncreaseLiquidityV2` | إضافة السيولة إلى مركز موجود. |
| المركز | `DecreaseLiquidity` / `DecreaseLiquidityV2` | إزالة السيولة؛ تجميع الرسوم المستحقة. |
| المركز | `ClosePosition` | حرق NFT وإغلاق `PersonalPositionState`. إذا كان حساب NFT مجمدًا، فقم أولاً بإذابته مع توفير PDA المجمع كحساب متبقي. |
| المركز | `CloseProtocolPosition` | كنس المسؤول للـ PDAs `ProtocolPositionState` القديمة. البرنامج الحالي لم يعد ينشئ أو يقرأ `ProtocolPositionState` — هذه التعليمة موجودة فقط لاسترجاع الإيجار على الحسابات التي أنشأتها إصدارات البرنامج الأقدم. |
| المبادلة | `Swap` / `SwapV2` | مبادلة السيولة الثابتة. كلا المتغيرين يطبقان الرسوم الديناميكية، وتوجيه الرسوم أحادي الجانب، ومطابقة أوامر الحد؛ الفرق الوحيد هو أن `SwapV2` يقبل Token-2022 mints (يتطلب المتغير V1 أن تكون كلا الأقبية SPL Token الكلاسيكية). |
| المبادلة | `SwapRouterBaseIn` | متعدد القفزات، يستخدمه الموجه. |
| أمر الحد | `OpenLimitOrder` | ضع أمر بيع عند علامة. الرموز غير المملوءة تجلس على العلامة؛ محرك المطابقة يملأها عندما يعبر السعر. |
| أمر الحد | `IncreaseLimitOrder` | إضافة إلى أمر مفتوح موجود. |
| أمر الحد | `DecreaseLimitOrder` | تقليل أو إلغاء أمر مفتوح؛ يدفع الباقي غير المملوء بالإضافة إلى أي مخرجات تم تسويتها بالفعل. |
| أمر الحد | `SettleLimitOrder` | دفع رموز الإخراج المملوءة إلى مالك الأمر. قابل للاستدعاء من قبل المالك أو حارس العمليات. |
| أمر الحد | `CloseLimitOrder` | إغلاق حساب أمر مستهلك بالكامل. يعود الإيجار دائمًا إلى `owner` الخاص بالأمر. قابل للاستدعاء من قبل المالك أو الحارس. |
| الرسوم | `CollectProtocolFee` | كنس المسؤول لرسوم البروتوكول. |
| الرسوم | `CollectFundFee` | كنس المسؤول لرسوم الصندوق. |
| المكافآت | `InitializeReward` | إرفاق تدفق مكافآت جديد بمجمع. |
| المكافآت | `SetRewardParams` | تغيير معدل الانبعاث/النهاية للمكافأة الموجودة. |
| المكافآت | `UpdateRewardInfos` | تسوية نمو المكافآت إلى الآن (يتم استدعاؤها بواسطة أي مبادلة / تغيير موضع). |
| المكافآت | `TransferRewardOwner` | نقل السلطة التي يمكنها تعيين أو تعبئة تدفق مكافآت. |
| المكافآت | `CollectRemainingRewards` | بعد `end_time` لتدفق المكافآت، كنس أي رموز غير مخصصة مرة أخرى إلى الممول. |
| المسؤول | `CloseSupportMintAssociated` | إزالة تسجيل `SupportMintAssociated` للـ mint واسترجاع إيجاره. |
| المسؤول | `CollectExcessLamports` | كنس lamports فوق الحد الأدنى المعفي من الإيجار من `PoolState` لمجمع واحد والأقبية، بالإضافة إلى أي PDAs مملوكة لـ CLMM تم تمريرها. `admin` أو محفظة جمع lamports المخصصة. تمت الإضافة 2026-09. |

<Note>
  **لا توجد تعليمة init-tick-array، ولا حاجة لها.** يتم إنشاء مصفوفة علامة *داخل*
  `OpenPosition*` / `IncreaseLiquidity*` بواسطة `TickArrayState::get_or_create_tick_array`، يتم دفعها بواسطة
  `payer`. مرر PDA مصفوفة العلامة (ربما لا تزال غير مهيأة، مملوكة للنظام) كـ
  `tick_array_lower` / `tick_array_upper` والبرنامج يخصصها إذا كانت مفقودة.
  `OpenLimitOrder` يفعل الشيء نفسه لـ `tick_array` الواحد الخاص به.
</Note>

معظم التعليمات الخاصة بالمسؤول (`CreateAmmConfig`، `UpdateAmmConfig`، `UpdatePoolStatus`، `CreateOperationAccount`، `UpdateOperationAccount`، `CloseProtocolPosition`) يتم التحكم فيها بواسطة مفتاح `admin` المشفر بقوة في البرنامج. `CreatePermissionPda` / `ClosePermissionPda` تقبل إما مفتاح `admin` **أو** مفتاح `permission_pda_admin` مخصص؛ `CreateSupportMintAssociated` / `CloseSupportMintAssociated` تقبل إما مفتاح `admin` **أو** مفتاح مالك support-mint مخصص؛ `CollectExcessLamports` تقبل إما مفتاح `admin` **أو** محفظة جمع lamports مخصصة. تعليمات مسؤول تدفق المكافآت (`TransferRewardOwner`، `CollectRemainingRewards`) يتم التحكم فيها بواسطة ممول المكافآت، وليس مسؤول البرنامج.

لاحقة V2 تعني "يدعم Token-2022 على الأقبية / NFT، يتطلب فتحة امتداد bitmap". يختار SDK V2 بشكل افتراضي للمجمعات الجديدة.

## `CreatePool`

**المعاملات**

```
sqrt_price_x64: u128           // السعر الأولي
open_time:      u64            // يتم رفض المبادلات قبل هذا الوقت
```

**الحسابات (مختصرة)**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|--------|
| 1 | `pool_creator` | W | S | |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. |
| 3 | `pool_state` | W |   | `init` هنا. |
| 4 | `token_mint_0` |   |   | مرتبة. |
| 5 | `token_mint_1` |   |   | |
| 6 | `token_vault_0` | W |   | `init` هنا، مملوكة بواسطة PDA سلطة المجمع. |
| 7 | `token_vault_1` | W |   | |
| 8 | `observation_state` | W |   | `init` هنا. |
| 9 | `tick_array_bitmap` | W |   | PDA `TickArrayBitmapExtension`؛ `init` هنا. |
| 10 | `token_program_0` |   |   | البرنامج الذي يمتلك `token_mint_0` — SPL Token **أو** Token-2022. |
| 11 | `token_program_1` |   |   | البرنامج الذي يمتلك `token_mint_1`. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

<Warning>
  الفتحات 10 و 11 هي **لكل mint**، وليس "SPL Token ثم Token-2022". كل واحد مقيد بـ
  `mint::token_program` على الـ mint المطابق، لذا بالنسبة لمجمع يكون `token_mint_0` فيه Token-2022 و
  `token_mint_1` هو SPL كلاسيكي يجب عليك تمرير Token-2022 في الفتحة 10 و SPL Token في الفتحة 11.
  `CreateCustomizablePool` و `CreatePermissionedPool` يستخدمان نفس الفتحتين.
</Warning>

**الشروط المسبقة**

- `token_mint_0 < token_mint_1` حسب ترتيب البايت.
- `amm_config.disable_create_pool == false`.
- لم يتم رفض الـ mints بواسطة قائمة السماح بامتداد Token-2022.

**الشروط اللاحقة**

- `pool_state.sqrt_price_x64 = sqrt_price_x64`، `tick_current = floor(log_{1.0001}(price))`.
- `pool_state.liquidity = 0` (لا توجد مراكز حتى الآن).
- `pool_state.fee_on = FromInput` (الافتراضي القديم).
- `pool_state.dynamic_fee_info` مصفر (الرسوم الديناميكية معطلة).

## `CreateCustomizablePool`

موصى به للمجمعات الجديدة. نفس تأثير `CreatePool` بالإضافة إلى وضع جمع الرسوم لكل مجمع واختيار رسوم ديناميكية اختياري.

**المعاملات**

```rust
pub struct CreateCustomizableParams {
    pub sqrt_price_x64:    u128,
    pub collect_fee_on:    CollectFeeOn,   // FromInput | Token0Only | Token1Only
    pub enable_dynamic_fee: bool,
}
```

**الحسابات** — بالضبط 13 حسابًا معلنًا من `CreatePool`. `dynamic_fee_config` **ليس** حسابًا معلنًا.

<Warning>
  عندما `enable_dynamic_fee = true`، يجب توفير `DynamicFeeConfig` للالتقاط كـ
  **آخر** `remaining_account` — يقرأ المعالج `ctx.remaining_accounts.last()`. أي
  PDAs تجاوز `SupportMintAssociated` يجب أن تأتي *قبله*، وإلا يلتقط البرنامج
  الحساب الخاطئ ويفشل في فك التسلسل. حذف الحساب بينما العلم مضبوط يفشل مع
  `AccountLack`.
</Warning>

**الشروط المسبقة** — نفس `CreatePool`. إذا كان `enable_dynamic_fee = false`، لا يلزم `remaining_account` وأي يتم تمريره يتم فحصه فقط للحصول على سجلات support-mint.

**الشروط اللاحقة**

- `pool_state.fee_on` مضبوط على متغير `CollectFeeOn` المختار.
- إذا تم تفعيل الرسوم الديناميكية: يتم تهيئة `pool_state.dynamic_fee_info` من `DynamicFeeConfig` المزود (خمسة معاملات معايرة مسخوخة؛ حقول الحالة مصفرة).
- وإلا: `pool_state.dynamic_fee_info` مصفر (= الرسوم الديناميكية غير نشطة إلى الأبد لهذا المجمع).

يتم تعيين `fee_on` وبت تفعيل الرسوم الديناميكية **فقط** عند إنشاء المجمع. لا توجد ترقية في المكان — لا يمكن للمجمعات التي تم إنشاؤها عبر `CreatePool` القديم أن تكتسب رسوم ديناميكية أو رسوم أحادية الجانب بأثر رجعي. يجب أن تستخدم النشرات الجديدة هذه التعليمة بشكل افتراضي.

## `CreatePermissionedPool`

كل من `CreatePool` و `CreateCustomizablePool` يشتقان PDA المجمع من `["pool", amm_config, token_mint_0, token_mint_1]`، لذا يوجد بالضبط **عنوان مجمع قانوني واحد** لكل ثلاثية `(config, mint0, mint1)` — محاولة `init` ثانية بنفس البذور تفشل. `CreatePermissionedPool` يرفع هذا التقييد بطي `seed_index: u16` المزود من قبل العميل في بذور PDA المجمع، مما يسمح بـ **مجمعات متعددة لنفس الزوج وفئة الرسوم** — كل واحد في عنوانه الخاص. لأن عنوان مجمع تعسفي هو قدرة مميزة، يجب أن يحتفظ الدافع بـ PDA `Permission` يفوضه.

كل شيء آخر عن المجمع متطابق مع `CreateCustomizablePool`: يأخذ نفس `CreateCustomizableParams` ويدعم الرسوم أحادية الجانب واختيار الرسوم الديناميكية.

**المعاملات**

```rust
customizable_params: CreateCustomizableParams   // نفس الهيكل مثل CreateCustomizablePool
seed_index:          u16                          // يجب أن يكون غير صفري؛ مطوي في بذور PDA المجمع
```

**الحسابات (مختصرة)** — نفس `CreateCustomizablePool` بالإضافة إلى، في الأمام:

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|--------|
| 1 | `payer` | W | S | يدفع الإيجار. يجب أن يكون سلطة PDA `permission` أدناه. |
| 2 | `pool_creator` |   |   | مسجل كـ `pool_state.owner`. قد يختلف عن `payer`. |
| 3 | `permission` |   |   | PDA `["permission", payer]`. يرفض Anchor الاستدعاء إذا لم يكن موجودًا / لا يملكه البرنامج. |
| … | (`amm_config`، `pool_state`، mints، vaults، `observation_state`، `tick_array_bitmap`، token/system programs) | | | كما في `CreateCustomizablePool`. |

يتم اشتقاق PDA `pool_state` من `["pool", amm_config, token_mint_0, token_mint_1, seed_index.to_le_bytes()]`.

**الشروط المسبقة**

- `seed_index != 0`. `seed_index` من `0` محجوز للمجمعات القديمة ويتم رفضه هنا؛ مكون البذرة `[0, 0]` هو ما يجعل عنوان المجمع القديم ينهار إلى الشكل الكلاسيكي ذي البذور الأربع.
- PDA `permission` لـ `payer` موجود (تم إنشاؤه بواسطة مسؤول عبر `CreatePermissionPda`).
- نفس قواعد mint / allow-list مثل `CreatePool`.

**الشروط اللاحقة**

- `pool_state` جديد موجود في عنوان مشتق من `seed_index`، مع `pool_state.seed_index = seed_index`.
- جميع حالات ما بعد الحالة الأخرى تطابق `CreateCustomizablePool` (وضع الرسوم، الرسوم الديناميكية الاختيارية).

<Note>
  هذه التعليمة **لا** توسع الوصول العام لإنشاء المجمع — الإنشاء بدون إذن يستمر عبر `CreatePool` / `CreateCustomizablePool`، والتي تبقى مجمع واحد لكل زوج. `CreatePermissionedPool` موجود للحالة المحددة حيث يحتاج مشغل مدرج في القائمة البيضاء إلى عدة مجمعات لنفس الزوج (على سبيل المثال، أسعار أولية مختلفة أو مجموعات إطلاق) ويحتفظ بـ PDA `Permission` منحه المسؤول.
</Note>

## `OpenPositionV2` / `OpenPositionWithToken22Nft`

إنشاء مركز جديد داخل مجمع موجود.

**المعاملات**

```
tick_lower_index: i32
tick_upper_index: i32
tick_array_lower_start_index: i32
tick_array_upper_start_index: i32
liquidity:  u128              // L المطلوب (أو 0 لاستخدام المبالغ أدناه)
amount_0_max: u64
amount_1_max: u64
with_metadata: bool           // كتابة بيانات وصفية NFT (Metaplex)
base_flag: Option<bool>       // true = ملاءمة لـ amount0؛ false = ملاءمة لـ amount1
```

**الحسابات** — المتغيران لهما *قوائم حسابات مختلفة*. `OpenPositionV2` يعلن 22؛ `OpenPositionWithToken22Nft` يعلن 20.

`OpenPositionV2`، بالترتيب:

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|--------|
| 1 | `payer` | W | S | |
| 2 | `position_nft_owner` |   |   | |
| 3 | `position_nft_mint` | W | S | keypair جديد. |
| 4 | `position_nft_account` | W |   | ATA المالك للـ NFT. |
| 5 | `metadata_account` | W |   | PDA بيانات وصفية Metaplex. معلن **بدون شروط**، حتى عندما `with_metadata = false`. |
| 6 | `pool_state` | W |   | |
| 7 | `protocol_position` |   |   | بقايا؛ `UncheckedAccount` للقراءة فقط. |
| 8 | `tick_array_lower` | W |   | تم الإنشاء هنا إذا لم تتم تهيئته. |
| 9 | `tick_array_upper` | W |   | نفس الشيء. |
| 10 | `personal_position` | W |   | تم الإنشاء هنا. |
| 11 | `token_account_0` | W |   | ATA مصدر المستخدم. |
| 12 | `token_account_1` | W |   | |
| 13 | `token_vault_0` | W |   | |
| 14 | `token_vault_1` | W |   | |
| 15 | `rent` |   |   | |
| 16 | `system_program` |   |   | |
| 17 | `token_program` |   |   | |
| 18 | `associated_token_program` |   |   | |
| 19 | `metadata_program` |   |   | Metaplex Token Metadata. |
| 20 | `token_program_2022` |   |   | |
| 21 | `vault_0_mint` |   |   | |
| 22 | `vault_1_mint` |   |   | |

`OpenPositionWithToken22Nft` هي نفس القائمة مع `metadata_account` (5) و `metadata_program` (19) **محذوفة** — تكتب بيانات وصفية المركز عبر امتداد البيانات الوصفية Token-2022 على NFT mint بدلاً من ذلك — مما يعطي 20 حسابًا. `position_nft_mint` الخاص به هو `Signer` عادي و `position_nft_account` هو `UncheckedAccount`.

<Warning>
  **`tick_array_bitmap_extension` ليس حسابًا معلنًا على أي متغير.** عندما يقع نطاق المركز خارج `tick_array_bitmap` المضمن للمجمع (±512 مصفوفة علامة)، أضف
  PDA `TickArrayBitmapExtension` في البذور `["pool_tick_array_bitmap_extension", pool_state]` كـ
  `remaining_accounts[0]`.
</Warning>

**الرياضيات** — انظر [`products/clmm/math`](/ar/products/clmm/math). بالنظر إلى `base_flag`، يحل البرنامج إما `liquidity` أو `(amount_0_max, amount_1_max)` إلى `L` الفعلي والمبالغ الفعلية للرموز المستهلكة.

**الشروط المسبقة**

- `tick_lower < tick_upper`، كلاهما مضاعفات `pool.tick_spacing`، ضمن `[MIN_TICK, MAX_TICK]`.
- يتم تمرير PDA مصفوفتي العلامة. لا يجب أن تكون موجودة بالفعل — `get_or_create_tick_array` يخصص واحدة مفقودة على حساب `payer` داخل هذه التعليمة. لا توجد تعليمة init-tick-array منفصلة.
- يحتوي المستخدم على ما لا يقل عن `amount_0_max` و `amount_1_max` في ATAs المصدر.

**الشروط اللاحقة**

- `personal_position` موجود، `liquidity` مضبوط، `fee_growth_inside_last` مأخوذ لقطة.
- تم تحديث إدخالات مصفوفة العلامة في `tick_lower` و `tick_upper` (`liquidity_gross += L`، `liquidity_net ± L`، لقطات نمو الرسوم المحفوظة).
- `pool_state.liquidity += L` إذا كان المركز في النطاق (`tick_lower ≤ tick_current < tick_upper`).
- يسجل NFT mint `pool_state` كسلطة تجميد. يتم إزالة سلطة الـ mint بعد صك NFT الواحد. تسجيل سلطة التجميد لا يغير حالة حساب رمز NFT.
- يبقى حساب رمز NFT غير مجمد ما لم تكن التعليمة `OpenPositionV2` أو `OpenPositionWithToken22Nft` **و** تطابق سلطة تجميد أي vault mint قائمة المُصدر المقيد لـ CLMM. فقط مسار V2 المطابق هذا يجمد الحساب. `OpenPosition` V1 لا يجمد.

**الأخطاء الشائعة** — `TickInvalidOrder` (`tick_lower >= tick_upper`)، `TickAndSpacingNotMatch` (نقطة نهاية ليست مضاعفة `tick_spacing`)، `InvalidTickIndex` (خارج `[MIN_TICK, MAX_TICK]`)، `MissingTickArrayBitmapExtensionAccount` (النطاق خارج bitmap المضمن والامتداد لم يتم إلحاقه)، `NotApproved` (`pool_state.status` يمنع الفتح)، `ZeroAmountSpecified`.

</Note>

**الأخطاء الشائعة** — `TooLittleOutputReceived` (انزلاق إدخال دقيق)، `TooMuchInputPaid` (انزلاق إخراج دقيق)، `SqrtPriceLimitOverflow`، `NotEnoughTickArrayAccount`، `InvalidFirstTickArrayAccount`، `MissingTickArrayBitmapExtensionAccount`، `LiquidityInsufficient`، `NotApproved` (بت المبادلة مضبوط على `pool_state.status`). **ما الذي يفعله `SwapV2` داخليًا والذي يجب أن يعرفه المتصلون** (بعد إصدار 2025):

1. **رسوم ديناميكية إضافية** — إذا كان `pool.dynamic_fee_info` غير صفري، يحدّث البرنامج مراكم التقلب باستخدام مسافة العلامة المقطوعة منذ آخر مبادلة (مع قواعد التصفية/الاضمحلال من [`products/clmm/fees`](/ar/products/clmm/fees)) ويضيف `dynamic_fee_component` على رأس `AmmConfig.trade_fee_rate`. إجمالي الرسوم مغطى بـ 10% (`MAX_FEE_RATE_NUMERATOR / 1_000_000`).
2. **مطابقة أوامر الحد** — عندما يعبر مشي السعر علامة تحتفظ بأوامر حد مفتوحة، يملأ البرنامج أولاً سيولة أوامر الحد المتاحة في تلك العلامة (FIFO حسب `order_phase`)، ثم يمضي على منحنى سيولة LP. تحدّث المبالغ المملوءة `tick.unfilled_ratio_x64` و `tick.part_filled_orders_remaining` للتسوية لاحقًا؛ تبقى الأوامر نفسها غير منفقة حتى يستدعي مالكها `SettleLimitOrder`.
3. **توجيه الرسوم أحادي الجانب** — عندما `pool.fee_on = Token0Only` أو `Token1Only`، تحسب خطوة المبادلة نفس إدخال-إخراج التجارة؛ يتم بعد ذلك توجيه الرسوم إلى الجانب المكون. بالنسبة للاتجاهات حيث جانب الرسوم المكون هو الإخراج، يتم خصم الرسوم من إخراج المبادلة (يتلقى المستخدم `out − fee`)؛ بالنسبة للاتجاهات حيث يكون الإدخال، السلوك يطابق `FromInput`. انظر `is_fee_on_input(zero_for_one)` و `is_fee_on_token0(zero_for_one)` على `PoolState`.

`Swap` (V1) ينفذ نفس الرسوم الديناميكية وتوجيه الرسوم أحادي الجانب ومطابقة أوامر الحد مثل `SwapV2`؛ الميزة الوحيدة التي ينقصها هي دعم Token-2022 — يجب أن تكون كلا الأقبية SPL Token كلاسيكية. يجب مبادلة المجمعات التي تحتوي على أي mint Token-2022 عبر `SwapV2`. يفضل المجمع والـ SDK بالفعل V2 لكل ساق CLMM لذا لا يضطر المتصلون إلى الفرع على نوع mint.
