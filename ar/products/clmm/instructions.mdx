| Limit order | `SettleLimitOrder` | دفع رموز الإخراج المملوءة إلى مالك الأمر. يمكن استدعاؤها من قبل المالك أو من قبل حارس العمليات. |
| Limit order | `CloseLimitOrder` | إغلاق حساب أمر تم استهلاكه بالكامل. يعود الإيجار دائمًا إلى `owner` الأمر. يمكن استدعاؤها من قبل المالك أو الحارس. |
| Fees | `CollectProtocolFee` | كنس إداري لرسوم البروتوكول. |
| Fees | `CollectFundFee` | كنس إداري لرسوم الصندوق. |
| Rewards | `InitializeReward` | إرفاق تدفق مكافآت جديد بمجمع. |
| Rewards | `SetRewardParams` | تغيير معدل الانبعاث/النهاية للمكافأة الموجودة. |
| Rewards | `UpdateRewardInfos` | تسوية نمو المكافآت إلى الآن (يتم استدعاؤها بواسطة أي مبادلة / تغيير موضع). |
| Rewards | `TransferRewardOwner` | نقل السلطة التي يمكنها تعيين أو تعبئة تدفق المكافآت. |
| Rewards | `CollectRemainingRewards` | بعد `end_time` لتدفق المكافآت، كنس أي رموز غير مخصصة مرة أخرى إلى الممول. |
| Utility | `InitTickArray` | تهيئة حساب tick-array (غالبًا ما يتم دمجه مع `OpenPosition`). |

معظم التعليمات الإدارية فقط (`CreateAmmConfig`, `UpdateAmmConfig`, `UpdatePoolStatus`, `CreateSupportMintAssociated`, `CreateOperationAccount`, `UpdateOperationAccount`, `CloseProtocolPosition`) يتم التحكم فيها بواسطة مفتاح `admin` المشفر في البرنامج. `CreatePermissionPda` / `ClosePermissionPda` تقبل إما مفتاح `admin` **أو** مفتاح `permission_pda_admin` مخصص. تعليمات إدارة تدفق المكافآت (`TransferRewardOwner`, `CollectRemainingRewards`) يتم التحكم فيها بواسطة ممول المكافآت، وليس إدارة البرنامج.

لاحقة V2 تعني "يدعم Token-2022 على الخزائن / NFT، يتطلب فتحة امتداد bitmap". يختار SDK V2 بشكل افتراضي للمجمعات الجديدة.

## `CreatePool`

**المعاملات**

```
sqrt_price_x64: u128           // السعر الأولي
open_time:      u64            // يتم رفض المبادلات قبل هذا الوقت
```

**الحسابات (مختصرة)**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `pool_creator` | W | S | |
| 2 | `amm_config` |   |   | فئة الرسوم المختارة. |
| 3 | `pool_state` | W |   | `init` هنا. |
| 4 | `token_mint_0` |   |   | مرتبة. |
| 5 | `token_mint_1` |   |   | |
| 6 | `token_vault_0` | W |   | `init` هنا، مملوكة بواسطة PDA سلطة المجمع. |
| 7 | `token_vault_1` | W |   | |
| 8 | `observation_state` | W |   | `init` هنا. |
| 9 | `tick_array_bitmap_extension` | W |   | `init` هنا (V2). |
| 10 | `token_program` |   |   | |
| 11 | `token_program_2022` |   |   | |
| 12 | `system_program`, `rent` |   |   | |

**الشروط المسبقة**

- `token_mint_0 < token_mint_1` حسب ترتيب البايت.
- `amm_config.disable_create_pool == false`.
- لا يتم رفض Mints بواسطة قائمة السماح بامتداد Token-2022.

**الشروط اللاحقة**

- `pool_state.sqrt_price_x64 = sqrt_price_x64`, `tick_current = floor(log_{1.0001}(price))`.
- `pool_state.liquidity = 0` (لا توجد مراكز حتى الآن).
- `pool_state.fee_on = FromInput` (الافتراضي القديم).
- `pool_state.dynamic_fee_info` مصفر (الرسوم الديناميكية معطلة).

## `CreateCustomizablePool`

موصى به للمجمعات الجديدة. نفس التأثير مثل `CreatePool` بالإضافة إلى وضع جمع الرسوم لكل مجمع وعلم اختياري لتفعيل الرسوم الديناميكية.

**المعاملات**

```rust
pub struct CreateCustomizableParams {
    pub sqrt_price_x64:    u128,
    pub collect_fee_on:    CollectFeeOn,   // FromInput | Token0Only | Token1Only
    pub enable_dynamic_fee: bool,
}
```

**الحسابات (مختصرة)** — نفس `CreatePool` بالإضافة إلى، عندما `enable_dynamic_fee = true`:

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| N | `dynamic_fee_config` |   |   | التكوين المشترك للالتقاط منه. يجب أن يكون موجودًا بالفعل. |

**الشروط المسبقة** — نفس `CreatePool`. إذا كان `enable_dynamic_fee = false`، يتم تجاهل `dynamic_fee_config`.

**الشروط اللاحقة**

- `pool_state.fee_on` تم تعيينها إلى متغير `CollectFeeOn` المختار.
- إذا تم تفعيل الرسوم الديناميكية: يتم تهيئة `pool_state.dynamic_fee_info` من `DynamicFeeConfig` المرسل (خمسة معاملات معايرة مسخوخة؛ حقول الحالة مصفرة).
- وإلا: `pool_state.dynamic_fee_info` مصفر (= الرسوم الديناميكية غير نشطة إلى الأبد لهذا المجمع).

يتم تعيين `fee_on` وبت تفعيل الرسوم الديناميكية **فقط** عند إنشاء المجمع. لا توجد ترقية في المكان — المجمعات التي تم إنشاؤها عبر `CreatePool` القديم لا يمكنها الحصول على رسوم ديناميكية أو رسوم أحادية الجانب بأثر رجعي. يجب أن تستخدم النشرات الجديدة هذه التعليمة بشكل افتراضي.

## `CreatePermissionedPool`

كل من `CreatePool` و `CreateCustomizablePool` يشتقان PDA المجمع من `["pool", amm_config, token_mint_0, token_mint_1]`، لذا يوجد بالضبط **مجمع قانوني واحد** لكل ثلاثية `(config, mint0, mint1)` — محاولة `init` ثانية بنفس البذور تفشل. `CreatePermissionedPool` يرفع هذا التقييد بطي `seed_index: u16` يوفره العميل في بذور PDA المجمع، مما يسمح بـ **مجمعات متعددة لنفس الزوج وفئة الرسوم** — كل واحد في عنوانه الخاص. لأن عنوان مجمع تعسفي هو قدرة مميزة، يجب أن يحتفظ الدافع بـ PDA `Permission` يفوضه.

كل شيء آخر عن المجمع متطابق مع `CreateCustomizablePool`: يأخذ نفس `CreateCustomizableParams` ويدعم الرسوم أحادية الجانب وخيار الرسوم الديناميكية.

**المعاملات**

```rust
customizable_params: CreateCustomizableParams   // نفس الهيكل مثل CreateCustomizablePool
seed_index:          u16                          // يجب أن يكون غير صفري؛ مطوي في بذور PDA المجمع
```

**الحسابات (مختصرة)** — نفس `CreateCustomizablePool` بالإضافة إلى، في الأمام:

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` | W | S | يدفع الإيجار. يجب أن يكون سلطة PDA `permission` أدناه. |
| 2 | `pool_creator` |   |   | مسجل كـ `pool_state.owner`. قد يختلف عن `payer`. |
| 3 | `permission` |   |   | PDA `["permission", payer]`. Anchor يرفض الاستدعاء إذا لم يكن موجودًا / لم يكن مملوكًا من قبل البرنامج. |
| … | (`amm_config`, `pool_state`, mints, vaults, `observation_state`, `tick_array_bitmap`, token/system programs) | | | كما في `CreateCustomizablePool`. |

يتم اشتقاق PDA `pool_state` من `["pool", amm_config, token_mint_0, token_mint_1, seed_index.to_le_bytes()]`.

**الشروط المسبقة**

- `seed_index != 0`. `seed_index` من `0` محجوز للمجمعات القديمة ويتم رفضه هنا؛ مكون البذرة `[0, 0]` هو ما يجعل عنوان المجمع القديم ينهار إلى الشكل الكلاسيكي ذي البذور الأربع.
- PDA `permission` لـ `payer` موجود (تم إنشاؤه بواسطة إدارة عبر `CreatePermissionPda`).
- نفس قواعد mint / allow-list مثل `CreatePool`.

**الشروط اللاحقة**

- `pool_state` جديد موجود في عنوان مشتق من `seed_index`، مع `pool_state.seed_index = seed_index`.
- جميع حالات ما بعد الأخرى تطابق `CreateCustomizablePool` (وضع الرسوم، الرسوم الديناميكية الاختيارية).

<Note>
  هذه التعليمة **لا** توسع الوصول العام لإنشاء المجمع — الإنشاء بدون إذن يستمر عبر `CreatePool` / `CreateCustomizablePool`، التي تبقى مجمع واحد لكل زوج. `CreatePermissionedPool` موجود للحالة المحددة حيث يحتاج مشغل مدرج في القائمة البيضاء إلى عدة مجمعات لنفس الزوج (مثل الأسعار الأولية المختلفة أو مجموعات الإطلاق) ويحتفظ بـ PDA `Permission` منحه الإدارة.
</Note>

## `OpenPositionV2` / `OpenPositionWithToken22Nft`

إنشاء موضع جديد داخل مجمع موجود.

**المعاملات**

```
tick_lower_index: i32
tick_upper_index: i32
tick_array_lower_start_index: i32
tick_array_upper_start_index: i32
liquidity:  u128              // L المطلوب (أو 0 لاستخدام المبالغ أدناه)
amount_0_max: u64
amount_1_max: u64
with_metadata: bool           // كتابة بيانات وصفية NFT (Metaplex)
base_flag: Option<bool>       // true = ملاءمة لـ amount0؛ false = ملاءمة لـ amount1
```

**الحسابات (مختصرة)**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `payer` | W | S |
| 2 | `position_nft_owner` |   |   |
| 3 | `position_nft_mint` | W | S (keypair) |
| 4 | `position_nft_account` | W |   | ATA المالك للـ NFT. |
| 5 | `metadata_account` | W |   | Metaplex (اختياري، إذا `with_metadata`). |
| 6 | `pool_state` | W |   |
| 7 | `protocol_position` |   |   |   |
| 8 | `tick_array_lower` | W |   | تم الإنشاء إذا لم يتم تهيئته. |
| 9 | `tick_array_upper` | W |   | نفس الشيء. |
| 10 | `personal_position` | W |   | تم الإنشاء هنا. |
| 11 | `token_account_0`, `token_account_1` | W |   | ATAs مصدر المستخدم. |
| 12 | `token_vault_0`, `token_vault_1` | W |   | |
| 13 | `rent`, `system_program`, `token_program` |   |   | |
| 14 | `associated_token_program` |   |   | |
| 15 | `metadata_program` |   |   | اختياري. |
| 16 | `token_program_2022` |   |   | V2. |
| 17 | `vault_0_mint`, `vault_1_mint` |   |   | V2. |
| 18 | `tick_array_bitmap_extension` | W |   | V2 (إذا تم لمسه). |

**الرياضيات** — انظر [`products/clmm/math`](/ar/products/clmm/math). بالنظر إلى `base_flag`، يحل البرنامج إما `liquidity` أو `(amount_0_max, amount_1_max)` إلى `L` الفعلي والمبالغ الفعلية للرموز المستهلكة.

**الشروط المسبقة**

- `tick_lower < tick_upper`، كلاهما مضاعفات `pool.tick_spacing`، ضمن `[MIN_TICK, MAX_TICK]`.
- مصفوفات tick المطلوبة تم تمريرها وتهيئتها (أو تم إنشاؤها هنا عبر `InitTickArray` CPI في المعاملة).
- المستخدم لديه على الأقل `amount_0_max` و `amount_1_max` في ATAs المصدر.

**الشروط اللاحقة**

- `personal_position` موجود، `liquidity` تم تعيينها، `fee_growth_inside_last` تم التقاطها.
- إدخالات مصفوفة tick في `tick_lower` و `tick_upper` تم تحديثها (`liquidity_gross += L`, `liquidity_net ± L`، لقطات نمو الرسوم يتم الحفاظ عليها).
- `pool_state.liquidity += L` إذا كان الموضع في النطاق (`tick_lower ≤ tick_current < tick_upper`).

**الأخطاء الشائعة** — `InvalidTickIndex`, `NotApproved`, `ZeroAmountSpecified`, `TransactionTooLarge` (إذا كان هناك الكثير من مصفوفات tick).

## `IncreaseLiquidityV2`

إضافة السيولة إلى موضع مفتوح بالفعل.

**المعاملات**

```
liquidity: u128
amount_0_max: u64
amount_1_max: u64
base_flag: Option<bool>
```

**الحسابات** — مثل `OpenPosition` ناقص صك NFT (الموضع موجود بالفعل؛ يتم تمرير NFT كـ ATA المالك الذي يحتفظ برمز واحد).

**التأثير**

- ينقل `amount_0_actual` / `amount_1_actual` من المستخدم → الخزائن.
- يزيد `personal_position.liquidity` و `pool_state.liquidity` (إذا كان في النطاق)، وإدخالات tick النهائية `liquidity_gross` / `liquidity_net` وفقًا لذلك.
- **يجمع الرسوم والمكافآت المستحقة منذ آخر لمسة** ويعتمدها على `tokens_fees_owed_{0,1}` / `reward_amount_owed`. يتم دفع هذه فقط على `DecreaseLiquidity` أو `CollectReward`، وليس على الزيادة.

## `DecreaseLiquidityV2`

إزالة السيولة من موضع.

**المعاملات**

```
liquidity: u128
amount_0_min: u64
amount_1_min: u64
```

**الحسابات** — نفس شكل `IncreaseLiquidity`.

**التأثير**

- يحسب `(amount_0, amount_1)` للـ `L` المزال بالنظر إلى `sqrt_price_x64` الحالي.
- يسوي الرسوم/المكافآت المتراكمة منذ آخر لمسة، نفس نمط `IncreaseLiquidity`.
- ينقل `amount_0 + fees_owed_0` و `amount_1 + fees_owed_1` خارج الخزائن إلى المستخدم.
- يقلل عدادات السيولة؛ إذا كان `personal_position.liquidity` الجديد == 0، يكون الموضع مؤهلاً لـ `ClosePosition`.

**الانزلاق** — `amount_0_min` و `amount_1_min` هي الحد الأدنى الذي يقبله المستخدم بعد خصم رسوم نقل Token-2022 على جانب الإخراج.

## `ClosePosition`

حرق موضع NFT وإغلاق `PersonalPositionState`.

**الشروط المسبقة**

- `personal_position.liquidity == 0`.
- `tokens_fees_owed_{0,1} == 0`.
- جميع عدادات المكافآت `reward_amount_owed == 0`.

(أي، جمع كل شيء وتقليل إلى صفر أولاً.)

**التأثير**

- يحرق NFT.
- يغلق حساب صك NFT وحساب `personal_position`، مما يسترجع الإيجار إلى `payer`.

## `SwapV2`

المشي على منحنى السيولة؛ إدخال دقيق **أو** إخراج دقيق حسب `is_base_input`.

**المعاملات**

```
amount: u64                  // إدخال إذا is_base_input=true، إخراج وإلا
other_amount_threshold: u64  // الحد الأدنى للإخراج أو الحد الأقصى للإدخال
sqrt_price_limit_x64: u128   // حد صارم؛ 0 ⇒ بدون حد
is_base_input: bool
```

**الحسابات (مختصرة)**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` |   | S | |
| 2 | `amm_config` |   |   | |
| 3 | `pool_state` | W |   | |
| 4 | `input_token_account` | W |   | |
| 5 | `output_token_account` | W |   | |
| 6 | `input_vault` | W |   | |
| 7 | `output_vault` | W |   | |
| 8 | `observation_state` | W |   | |
| 9 | `token_program` |   |   | |
| 10 | `token_program_2022` |   |   | V2. |
| 11 | `memo_program` |   |   | V2 (مطلوب لبعض مسارات Token-2022). |
| 12 | `input_vault_mint`, `output_vault_mint` |   |   | V2. |
| 13 | `tick_array_bitmap_extension` (اختياري) | W |   | إذا كانت المبادلة تدخل الامتداد. |
| 14+ | `tick_array` (الباقي) | W |   | مصفوفات كافية لتغطية نطاق المشي المتوقع. |

يمرر المستدعون قائمة مرتبة من مصفوفات tick تغطي مشي المبادلة المتوقع؛ يستخدم البرنامج ما يحتاجه. يحسب SDK هذه القائمة عبر `PoolUtils.computeAmountOutFormat` أو نقطة نهاية الاقتباس في API.

**الشروط المسبقة**

- `pool_state.status` يسمح بالمبادلة.
- `now >= open_time`.
- `sqrt_price_limit_x64` على الجانب الصحيح من `sqrt_price_x64` للاتجاه.

**الأخطاء الشائعة** — `ExceededSlippage`, `SqrtPriceLimitOverflow`, `TickArrayNotFound`, `LiquidityInsufficient`.

**ما يفعله `SwapV2` داخليًا يجب أن يعرفه المستدعون** (إصدار ما بعد 2025):

1. **رسوم ديناميكية إضافية** — إذا كان `pool.dynamic_fee_info` غير صفري، يحدث البرنامج مراكم التقلب باستخدام مسافة tick المقطوعة منذ آخر مبادلة (مع قواعد التصفية/الاضمحلال من [`products/clmm/fees`](/ar/products/clmm/fees)) ويضيف `dynamic_fee_component` على رأس `AmmConfig.trade_fee_rate`. إجمالي الرسوم مغطى بـ 10% (`MAX_FEE_RATE_NUMERATOR / 1_000_000`).
2. **مطابقة أوامر الحد** — عندما يعبر مشي السعر tick يحتفظ بأوامر حد مفتوحة، يملأ البرنامج أولاً سيولة أوامر الحد المتاحة في هذا tick (FIFO حسب `order_phase`)، ثم يتابع على منحنى سيولة LP. تحدث المبالغ المملوءة `tick.unfilled_ratio_x64` و `tick.part_filled_orders_remaining` للتسوية لاحقًا؛ تبقى الأوامر نفسها غير منفقة حتى يستدعي مالكها `SettleLimitOrder`.
3. **توجيه الرسوم أحادي الجانب** — عندما `pool.fee_on = Token0Only` أو `Token1Only`، خطوة المبادلة لا تزال تحسب نفس مخرجات الإدخال التجاري؛ يتم توجيه الرسوم بعد ذلك إلى الجانب المكون. للاتجاهات حيث جانب الرسوم المكون هو الإخراج، يتم خصم الرسوم من إخراج المبادلة (يتلقى المستخدم `out − fee`)؛ للاتجاهات حيث يكون الإدخال، السلوك يطابق `FromInput`. انظر `is_fee_on_input(zero_for_one)` و `is_fee_on_token0(zero_for_one)` على `PoolState`.

`Swap` (V1) ينفذ نفس الرسوم الديناميكية، توجيه الرسوم أحادي الجانب، ومطابقة أوامر الحد مثل `SwapV2`؛ الميزة الوحيدة التي ينقصها هي دعم Token-2022 — يجب أن تكون كلا الخزائن SPL Token كلاسيكي. المجمعات التي تحتوي على أي mint Token-2022 يجب أن يتم مبادلتها عبر `SwapV2`. المجمع والـ SDK بالفعل يفضلان V2 لكل ساق CLMM لذا لا يضطر المستدعون إلى الفرع على نوع mint.

## `OpenLimitOrder`

ضع أمر بيع عند tick محدد. يجلس الأمر في مجموعة FIFO لكل tick ويملأ عندما يعبر السعر.

**المعاملات**

```
nonce_index:    u8       // فهرس حساب nonce المختار من المستخدم (0..255 لكل محفظة)
zero_for_one:   bool     // true: بيع token0 مقابل token1؛ false: بيع token1 مقابل token0
tick_index:     i32      // يجب أن يكون مضاعفًا لـ pool.tick_spacing
amount:         u64      // مبلغ رمز الإدخال
```

**الحسابات (مختصرة)**

| # | الاسم | W | S | ملاحظات |
|---|------|---|---|-------|
| 1 | `payer` | W | S | مالك الأمر؛ يدفع الإيجار. |
| 2 | `pool_state` | W |   | |
| 3 | `tick_array` | W |   | مصفوفة tick التي تحتوي على `tick_index`. |
| 4 | `limit_order_nonce` | W |   | PDA. `init_if_needed` — تم الإنشاء في أول أمر للمستخدم تحت هذا `nonce_index`. |
| 5 | `limit_order` | W |   | PDA. `init` هنا. |
| 6 | `input_token_account` | W |   | ATA إدخال المستخدم. تم التحقق من `frozen`. |
| 7 | `output_token_account` | W |   | ATA **إخراج** المستخدم. لم يتم خصمه عند الفتح — مطلوب فقط حتى يتمكن البرنامج من تأكيد أنه ليس `frozen` (أي يمكن تسليم الملء لاحقًا). |
| 8 | `input_vault` | W |   | خزانة إدخال المجمع. |
| 9 | `output_vault` | W |   | خزانة إخراج المجمع. يحدد mint الإخراج لفحوصات `output_token_account` / `output_vault_mint`. |
| 10 | `input_vault_mint` |   |   | معالجة رسوم Token-2022. |
| 11 | `output_vault_mint` |   |   | mint جانب الإخراج (فحص frozen المقترن). |
| 12 | `input_token_program` |   |   | SPL أو Token-2022. |
| 13 | `system_program`, `rent` |   |   | |

<Note>
  **تغيير قائمة الحسابات (إصدار 2026-07).** `OpenLimitOrder` يأخذ الآن أيضًا حسابات **جانب الإخراج** — `output_token_account`, `output_vault`, و `output_vault_mint` — بالإضافة إلى جانب الإدخال. يتم استخدامها فقط للتحقق: يرفض البرنامج الأمر إذا كان حساب رمز الإدخال **أو** الإخراج للمالك مجمدًا. هذا يضمن أن الملء يمكن فعلاً أن يتم تسويته إلى ATA الإخراج للمالك، وهو مهم لـ allow-list / default-frozen Token-2022 mints (مثل الرموز المرخصة) حيث قد لا يكون الحساب قد تم إذابته بعد. يجب على العملاء المبنيين مقابل قائمة الحسابات أحادية الجانب الأقدم إضافة الحسابات الثلاثة للإخراج.
</Note>

**الشروط المسبقة**

- لا `input_token_account` ولا `output_token_account` مجمد (وإلا `NotApproved`).
- `pool_state.status` يسمح بكل من المبادلة (bit 4) وعمليات أوامر الحد (bit 5) (وإلا `NotApproved`).
- `tick_index % pool.tick_spacing == 0` وضمن `[MIN_TICK, MAX_TICK]`.
- `tick_index` على **الجانب الأيمن من `pool.tick_current`** للاتجاه المختار (بيع token0 → يجب أن يكون tick فوق الحالي، والعكس صحيح). البيع عند tick تم عبوره بالفعل سيتم مطابقته فورًا ويتم رفضه.

**الشروط اللاحقة**

- `limit_order` موجود، التقاط `tick.order_phase` و `tick.unfilled_ratio_x64` عند وقت الفتح.
- `tick.orders_amount += amount` (في المجموعة الحالية).
- `limit_order_nonce.order_nonce += 1`.
- `OpenLimitOrderEvent` مُصدر.

**الأخطاء الشائعة** — `NotApproved` (حساب رمز الإدخال أو الإخراج مجمد، أو المجمع لديه مبادلة / أوامر حد معطلة)، `InvalidLimitOrderAmount` (صفر أو أقل من الحد الأدنى للمجمع)، `InvalidTickIndex` (خارج `[MIN_TICK, MAX_TICK]`، أو على الجانب الخاطئ من `tick_current` للاتجاه المختار)، `TickAndSpacingNotMatch` (`tick_index % pool.tick_spacing != 0`)، `OrderPhaseSaturated`.

## `IncreaseLimitOrder`

إضافة إلى أمر مفتوح موجود. يمكن استدعاؤها فقط من قبل `owner` الأمر.

**المعاملات**

```
amount: u64    // مبلغ رمز إدخال إضافي
```

**الحسابات** — مثل `OpenLimitOrder` ناقص حساب nonce؛ يتم تمرير PDA `limit_order` مباشرة.

**الشروط المسبقة**

- `limit_order.owner == signer`.
- الأمر لا يزال في نفس المجموعة (`tick.order_phase == limit_order.order_phase`). إذا بدأت المجموعة بالفعل بالملء، يتم تسوية الأمر جزئيًا — يجب على المستدعي استدعاء `DecreaseLimitOrder` أو `SettleLimitOrder` أولاً للمتابعة.

**التأثير**

- ينقل `amount` من ATA المالك إلى `input_vault`.
- `limit_order.total_amount += amount`؛ `tick.orders_amount += amount`.

## `DecreaseLimitOrder`

تقليل أو إلغاء كامل أمر مفتوح. يدفع الباقي غير المملوء مرة أخرى إلى المالك، بالإضافة إلى أي إخراج تم تسويته بالفعل بواسطة ملء جزئي سابق.

**المعاملات**

```
amount:     u64    // مبلغ رمز الإدخال للسحب (الحد الأقصى = الباقي غير المملوء)
amount_min: u64    // حد الانزلاق على سحب جانب الإدخال
```

**الحسابات** — كلا جانبي رمز الإدخال والإخراج:

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `pool_state` | W |   |
| 3 | `tick_array` | W |   |
| 4 | `limit_order` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_vault_mint`, `output_vault_mint` |   |   |
| 10 | `token_program`, `token_program_2022` |   |   |

**التأثير**

- يعيد حساب مبلغ الملء للأمر من `unfilled_ratio_x64` المجموعة منذ الفتح.
- يرسل إخراج مملوء إلى `output_token_account`.
- يرسل `amount` من إدخال غير مملوء مرة أخرى إلى `input_token_account`.
- يحدث `limit_order` وفقًا لذلك. إذا كان الباقي غير المملوء الجديد صفرًا، يغلق البرنامج الحساب ويسترجع الإيجار إلى `owner`.

## `SettleLimitOrder`

دفع رموز إخراج مملوءة إلى المالك دون تغيير الباقي غير المملوء للأمر. مفيد عندما يريد حراس `auto_withdraw` تقطير الدفع لملء جزئي طويل الأمد.

**المستدعي** — إما `owner` الأمر، أو `limit_order_admin` البرنامج (محفظة ساخنة تشغيلية خارج السلسلة تشغل حلقة حارس آلية). الحارس ليس لديه سلطة أخرى — لا يمكنه نقل أموال المستخدم خارج دفع الإخراج المملوء إلى ATA `owner`.

**الحسابات**

| # | الاسم | W | S |
|---|------|---|---|
| 1 | `signer` |   | S | المالك **أو** `limit_order_admin` |
| 2 | `pool_state` |   |   | |
| 3 | `tick_array` |   |   | |
| 4 | `limit_order` | W |   | |
| 5 | `output_token_account` | W |   | ATA إخراج المالك. |
| 6 | `output_vault` | W |   | خزانة إخراج المجمع. |
| 7 | `output_vault_mint` |   |   | |
| 8 | `output_token_program` |   |   | |

**التأثير**

- يحسب الإخراج التراكمي المستحق باستخدام `(limit_order.unfilled_ratio_x64, tick.unfilled_ratio_x64)`.
- ينقل الفرق إلى `output_token_account`.
- يحدث `limit_order.settled_output`.
- **لا** يغلق الأمر؛ لا يزال مفتوحًا مقابل أي إدخال متبقي.

## `CloseLimitOrder`

إغلاق حساب أمر تم استهلاكه بالكامل. يتم إرجاع الإيجار دائمًا إلى `limit_order.owner` بغض النظر عمن يوقع.

**المستدعي** — إما `owner` أو `limit_order_admin`.

**الشروط المسبقة**

- الأمر لديه باقي غير مملوء صفري (إما `amount == total_amount` تم ملؤه وتسويته، أو قلل المالك الأمر إلى صفر ونسي الإغلاق).

**التأثير**

- يغلق `limit_order`؛ يتم إرسال الإيجار إلى `limit_order.owner`.

**المعاملات** — نفس خمسة حقول المعايرة مثل `CreateDynamicFeeConfig` (`filter_period`, `decay_period`, `reduction_factor`, `dynamic_fee_control`, `max_volatility_accumulator`)؛ `index` ثابت عند الإنشاء ولا يتم إعادة تمريره هنا.
