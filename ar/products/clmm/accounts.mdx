## جرد الحسابات

يتم وصف مجمع CLMM النشط بعائلات الحسابات التالية. جميعها مملوكة لبرنامج CLMM باستثناء النقودتين (Mints) وخزائنهما.

| الحساب | الغرض | العدد لكل مجمع |
|---------|---------|----------------|
| `AmmConfig` | فئة الرسوم: معدل رسوم التداول، حصة البروتوكول، حصة الصندوق، تباعد التكات الافتراضي. مشترك بين جميع المجمعات في هذه الفئة. | 1 (مشترك) |
| `PoolState` | `sqrt_price_x64` الحالي، التك الحالي، إجمالي السيولة، نمو الرسوم العام، معلومات المكافآت، مؤشر الملاحظة. | 1 |
| `TickArrayState` | كتلة من `TICK_ARRAY_SIZE` تكات متجاورة. يتم تهيئتها فقط عند الحاجة. | 0 ≤ N ≤ النطاق |
| `TickArrayBitmapExtension` | خريطة بت تتبع التكات التي توجد خارج خريطة البت المضمنة في `PoolState`. | 0 أو 1 |
| `PersonalPositionState` | واحد لكل مركز LP. يخزن النطاق والسيولة ونمو الرسوم/المكافآت الأخير المرئي. السلطة = مالك NFT. | 1 لكل مركز |
| NFT mint للمركز | نقود بإمداد 1، مرتبطة بـ `PersonalPositionState`. حسابها الرمزي غير مجمد بشكل افتراضي؛ V2 يجمده فقط عندما تطابق نقود أساسية مرشح المُصدر المقيد. | 1 لكل مركز |
| `ObservationState` | حلقة دائرية من ملاحظات الأسعار لـ TWAP. | 1 |
| `token_0_vault`, `token_1_vault` | حسابات رمزية تحتفظ برصيد المجمع. مملوكة لسلطة المجمع. | 2 |
| `DynamicFeeConfig` | مجموعة معاملات قابلة لإعادة الاستخدام لآلية الرسوم الديناميكية. يمكن للمجمعات المنشأة عبر `create_customizable_pool` الاشتراك فيها. مُدارة من قبل المسؤول. | مشترك (لكل فهرس) |
| `LimitOrderState` | واحد لكل أمر حد مفتوح. يسجل المالك والتك والجانب والمبلغ الإجمالي وصورة الإخراج المستقر. | 1 لكل أمر |
| `LimitOrderNonce` | عداد لكل `(wallet, nonce_index)` يشتق عناوين PDA فريدة للأوامر. | 1 لكل (محفظة، فهرس) |

## `PoolState`

الحالة الحية للمجمع، تُقرأ في كل مبادلة وكل تغيير موضع.

```rust
// programs/amm/src/states/pool.rs
pub struct PoolState {
    pub bump:           [u8; 1],
    pub amm_config:     Pubkey,            // fee tier binding
    pub owner:          Pubkey,            // admin (multisig)
    pub token_mint_0:   Pubkey,
    pub token_mint_1:   Pubkey,
    pub token_vault_0:  Pubkey,
    pub token_vault_1:  Pubkey,
    pub observation_key: Pubkey,

    pub mint_decimals_0: u8,
    pub mint_decimals_1: u8,
    pub tick_spacing:   u16,               // inherited from amm_config at init

    pub liquidity:      u128,              // total active (in-range) liquidity
    pub sqrt_price_x64: u128,              // Q64.64 of sqrt(price)
    pub tick_current:   i32,               // current tick index

    pub padding3:       u16,
    pub padding4:       u16,

    // Global fee growth per unit of liquidity, Q64.64.
    pub fee_growth_global_0_x64: u128,
    pub fee_growth_global_1_x64: u128,

    // Accrued-but-not-swept protocol fees (per mint).
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,

    // Reserved padding for future upgrades.
    pub padding5: [u128; 4],

    // Status bitmask. Bits 0-5: open-position, decrease-liquidity,
    // collect-fee, collect-reward, swap, limit-order. A set bit disables
    // the corresponding operation.
    pub status:  u8,

    // Fee-collection mode (CollectFeeOn).
    //   0 = FromInput (deduct fee from the swap input — Uniswap-V3 default)
    //   1 = Token0Only (always deduct fee from token0 vault)
    //   2 = Token1Only (always deduct fee from token1 vault)
    pub fee_on: u8,

    // Client-supplied index (u16 LE) folded into the pool PDA seeds by
    // create_customizable_pool_v2. [0, 0] for pools created via CreatePool /
    // CreateCustomizablePool (the seed component collapses to empty).
    pub seed_index: [u8; 2],
    pub padding: [u8; 4],

    // Live reward streams (up to REWARD_NUM = 3).
    pub reward_infos: [RewardInfo; 3],

    // Inline bitmap tracking initialized tick-arrays in the primary range.
    pub tick_array_bitmap: [u64; 16],

    // Reserved padding for future upgrades.
    pub padding6: [u64; 4],

    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time:    u64,                 // currently disabled by the program
    pub recent_epoch: u64,

    // Per-pool dynamic-fee state. Zero-valued unless the pool was
    // created with `enable_dynamic_fee = true` via create_customizable_pool.
    pub dynamic_fee_info: DynamicFeeInfo,

    // Reserved for future upgrades.
    pub padding1: [u64; 14],
    pub padding2: [u64; 32],
}
```

الحقول التي ستلمسها فعليًا:

- **`sqrt_price_x64`** و **`tick_current`** هما حالة سعر المجمع. يتم تحديثهما معًا في كل مبادلة. `tick_current` هو الحد الأدنى لـ `log_{1.0001}(price)`.
- **`liquidity`** هي السيولة **النشطة** — مجموع قيم `L` لجميع المراكز التي يحتوي نطاقها على `tick_current`. تتغير في كل مرة تعبر مبادلة تك وفي كل مرة يتم فتح/إغلاق/تغيير حجم مركز.
- **`fee_growth_global_{0,1}_x64`** هي الرسوم المتراكمة المكتسبة لكل وحدة سيولة عبر تاريخ المجمع بالكامل. تقرأ المراكز هذا لحساب ما يُستحق لهم.
- **`tick_spacing`** مقفل على `AmmConfig` عند التهيئة ولا يتغير أبدًا. يحدد أي مؤشرات تك يُسمح بها فقط أن تكون نقاط نهاية المركز.
- **`tick_array_bitmap`** هي خريطة بت **مضمنة** تغطي نطاق التكات المستخدم بشكل شائع حول سعر الفائدة. بالنسبة للمجمعات التي تصل مراكزها بعيدًا، يعيش تتبع الفائض في `TickArrayBitmapExtension` المنفصل.
- **`fee_on`** ثابت عند إنشاء المجمع. `0` (FromInput) يعيد إنتاج السلوك الكلاسيكي لـ Uniswap-V3. `1` و `2` يوجهان رسوم المبادلة إلى جانب واحد من الكتاب — انظر [`products/clmm/fees`](/ar/products/clmm/fees) للمقارنات.
- **`seed_index`** هو `[0, 0]` لكل مجمع تم إنشاؤه من خلال `CreatePool` / `CreateCustomizablePool` (مجمع قانوني واحد لكل زوج). قيمة **غير صفرية** تعني أن المجمع تم إنشاؤه عبر `CreateCustomizablePoolV2` (سُمي `CreatePermissionedPool` قبل 2026-10-22) والفهرس جزء من بذور PDA للمجمع، مما يسمح بعدة مجمعات للتعايش لنفس `(config, mint0, mint1)`. لإعادة اشتقاق عنوان مثل هذا المجمع يجب أن تعرف `seed_index` الخاص به.
- **`dynamic_fee_info`** يحمل حالة التقلب لرسوم الرسوم الديناميكية. عند التفعيل، تعيد كل مبادلة حساب `dynamic_fee_component` فوق `AmmConfig.trade_fee_rate`. التخطيط موثق تحت `DynamicFeeInfo` أدناه؛ المجمعات بدون رسوم ديناميكية تترك البنية بأكملها صفرية.

## `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub index: u16,                       // uses "amm_config"+u16 seed

    pub owner:             Pubkey,        // protocol-fee owner (CollectProtocolFee)
    pub protocol_fee_rate: u32,           // fraction of trade fee to protocol, denom 1e6
    pub trade_fee_rate:    u32,           // trade fee in 1e6ths of volume
    pub tick_spacing:      u16,           // default spacing for pools using this config
    pub fund_fee_rate:     u32,           // fraction of trade fee to fund, denom 1e6
    pub padding_u32: u32,

    pub fund_owner: Pubkey,               // fund-fee owner (CollectFundFee)
    pub padding: [u64; 3],
}
```

منذ ترقية 2026-09، يكتب `CreateAmmConfig` معرّف `protocol_fee_owner::ID` المشفر في البرنامج إلى `owner` و `fund_fee_owner::ID` إلى `fund_owner`. قبل ذلك، كان ينسخ مفتاح موقّع المسؤول إلى كليهما. تحتفظ التكوينات الموجودة بأي شيء تم إنشاؤها أو تدويره إليه، لذا اقرأ كلا الحقلين من الحساب. معاملات `UpdateAmmConfig` `3` / `4` لا تزال تدويرهما. العناوين موجودة في [`reference/program-addresses`](/ar/reference/program-addresses#clmm-fee-owner-wallets).

مجموعة نموذجية منشورة من فئات رسوم CLMM (تأكد مقابل `GET https://api-v3.raydium.io/main/clmm-config`):

| الفهرس | `trade_fee_rate` | تباعد التك | الاستخدام النموذجي |
|-------|------------------|--------------|-------------|
| 0 | `100` (0.01%) | 1 | أزواج مستقرة، USDC/USDT |
| 1 | `500` (0.05%) | 10 | الأزرق الكبير المترابط |
| 2 | `2_500` (0.25%) | 60 | الأزواج القياسية |
| 3 | `10_000` (1.00%) | 120 | متقلب أو طويل الذيل |

`protocol_fee_rate` و `fund_fee_rate` هما كسور من رسوم التداول؛ نفس الاتفاقية مثل CPMM. انظر [`products/clmm/fees`](/ar/products/clmm/fees).

## `TickArrayState`

لا يخزّن CLMM سجلاً واحداً لكل tick. هذا سيتطلب مليارات الحسابات. بدلاً من ذلك، يجمّع **`TICK_ARRAY_SIZE` من ticks المجاورة المهيأة أو غير المهيأة** (عادة 60 أو 88 حسب إصدار البرنامج) في `TickArrayState` يتم إنشاؤه بكسل عند الاستخدام الأول.

```rust
pub const TICK_ARRAY_SIZE: usize = 60;
pub const TICK_ARRAY_SIZE_USIZE: usize = 60;

pub struct TickArrayState {
    pub pool_id:                Pubkey,
    pub start_tick_index:       i32,                            // lowest tick in this array
    pub ticks:                  [TickState; TICK_ARRAY_SIZE],   // 60 entries
    pub initialized_tick_count: u8,
    pub recent_epoch:           u64,
    pub padding:                [u8; 107],
}

pub struct TickState {
    pub tick:                       i32,
    pub liquidity_net:              i128,                       // ΔL when crossing this tick upward
    pub liquidity_gross:            u128,                       // total L referencing this tick
    pub fee_growth_outside_0_x64:   u128,                       // see math.mdx
    pub fee_growth_outside_1_x64:   u128,
    pub reward_growths_outside_x64: [u128; 3],

    // Limit-order bookkeeping. All zero for ticks that have never carried
    // a limit order. See products/clmm/math for the matching algorithm.
    pub order_phase:                  u64,                      // monotonic FIFO cohort id
    pub orders_amount:                u64,                      // unfilled tokens in current cohort
    pub part_filled_orders_remaining: u64,                      // remaining tokens of partially-filled cohort
    pub unfilled_ratio_x64:           u128,                     // Q64.64; starts at 1.0 and shrinks as fills occur

    pub padding:                    [u32; 3],
}
```

الحقول الأربعة لأوامر الحد تكون صفراً على أي tick لم يُستخدم قط لأمر حد. عندما تُفتح أوامر على tick، يتتبع البرنامج سلسلة من المجموعات:

- `order_phase` هو معرّف المجموعة. يزداد في كل مرة تنتقل مجموعة من "غير مملوءة بالكامل" إلى "مملوءة جزئياً".
- `orders_amount` هو إجمالي رمز الإدخال للمجموعة الحالية (الأحدث).
- `part_filled_orders_remaining` يتتبع المجموعة السابقة التي يتم ملؤها حالياً بواسطة المبادلات الجارية.
- `unfilled_ratio_x64` هو مضروب Q64.64 يُحمل على المجموعة: عندما تملأ مبادلة X% من المجموعة، يُضرب النسبة في `(1 − X)`. كل أمر مفتوح يخزّن لقطة خاصة به من `(order_phase, unfilled_ratio_x64)` عند وقت الفتح، لذا تقليل رياضيات التسوية إلى مقارنة اللقطات.

القواعد:

- نقطة نهاية الموضع *t* يجب أن تحقق `t % tick_spacing == 0`. يرفض البرنامج المواضع غير المحاذاة.
- **مصفوفة** الـ tick موجودة في `floor(t / (TICK_ARRAY_SIZE * tick_spacing)) * (TICK_ARRAY_SIZE * tick_spacing)`.
- يتم تهيئة مصفوفة tick بكسل: أول موضع أو مبادلة تلمس مصفوفة غير مهيأة تنشئها، مع دفع الإيجار.
- مصفوفة tick **لا تُغلق أبداً** بواسطة البرنامج. بمجرد تخصيصها، تستمر طوال حياة المجموعة، حتى بعد عودة كل tick بداخلها إلى `liquidity_gross == 0`. تعيد المواضع والمبادلات اللاحقة استخدام الحساب الموجود بدون إيجار إضافي. لا توجد مسار تنظيف مدفوع بـ `ClosePosition` لمصفوفات tick.

### `TickArrayBitmapExtension`

`PoolState.tick_array_bitmap` (مضمّن) يغطي النطاق "القريب من السعر الفوري" — **±512** مصفوفة tick (`TICK_ARRAY_BITMAP_SIZE = 512`؛ الحقل `[u64; 16]` هو 1,024 بت مقسم بالتساوي بين مؤشرات البداية السالبة والموجبة، لذا مؤشرات المصفوفة −512 … +511). خارج هذا النطاق (لقيم tick القصوى)، يحتفظ البرنامج بحساب امتداد:

```rust
pub struct TickArrayBitmapExtension {
    pub pool_id: Pubkey,
    pub positive_tick_array_bitmap: [[u64; 8]; 14],
    pub negative_tick_array_bitmap: [[u64; 8]; 14],
}
```

إذا كان نطاق موضعك "عادياً"، فلن تفكر أبداً في حساب الامتداد. المواضع ذات النطاق الكامل (مثل `(MIN_TICK, MAX_TICK)`) تتطلبها؛ SDK يحلها لك.

## المواضع

موضع CLMM هو **حزمة** من ثلاثة حسابات بالإضافة إلى mint:

### موضع NFT mint

mint SPL Token أو Token-2022 بإمداد 1. موضع NFT في محفظة المالك هو ATA يحمل هذا الرمز الواحد. يربط البرنامج التفويض إلى **المالك الحالي لرصيد ATA الخاص بـ NFT**، وليس إلى Pubkey مخزّن في الحالة.

تعيين mints موضع NFT الجديدة `pool_state` كسلطة تجميد قبل صك الرمز الواحد وإزالة سلطة mint. **تعيين سلطة تجميد لا يجمّد حساب NFT بحد ذاته.** يبقى الحساب غير مجمّد وقابل للتحويل ما لم تتحقق كلا الشرطين: يستخدم المتصل `OpenPositionV2` أو `OpenPositionWithToken22Nft`، وتظهر سلطة تجميد mint الخزان الأساسي على الأقل على قائمة المُصدرين المقيدين في CLMM. فقط عندئذ يجمّد CLMM حساب NFT بعد الصك. هذا لا يغيّر أي بايتات `PersonalPositionState` أو `PoolState`.

### `PersonalPositionState`

واحد لكل موضع مفتوح. مفتاح من mint NFT.

```rust
pub struct PersonalPositionState {
    pub bump: [u8; 1],
    pub nft_mint: Pubkey,                 // this position's NFT mint
    pub pool_id:  Pubkey,

    pub tick_lower_index: i32,
    pub tick_upper_index: i32,

    pub liquidity: u128,                  // this position's L

    // Fee-growth snapshots at last time the position was touched.
    pub fee_growth_inside_0_last_x64: u128,
    pub fee_growth_inside_1_last_x64: u128,
    pub token_fees_owed_0: u64,           // accrued since last collect
    pub token_fees_owed_1: u64,

    pub reward_infos: [PositionRewardInfo; 3],
    pub recent_epoch: u64,
    pub padding: [u64; 7],
}

pub struct PositionRewardInfo {
    pub growth_inside_last_x64: u128,
    pub reward_amount_owed: u64,
}
```

### `ProtocolPositionState` (مُهمل)

<Note>
  خزّنت إصدارات CLMM الأقدم حسابات إجمالية لكل `(pool, tick_lower, tick_upper)` في `ProtocolPositionState` PDA. **الإصدارات الأحدث لا تعود تنشئ أو تقرأ هذا الحساب.** الفتحة لا تزال تظهر في قوائم حسابات `OpenPosition` / `IncreaseLiquidity` / `DecreaseLiquidity` كـ `UncheckedAccount` لتوافق ABI، لكن البرنامج لا يكتب إليها. الحسابات الموجودة على السلسلة هي بقايا؛ يمكن للمسؤول استدعاء `CloseProtocolPosition` لاسترجاع الإيجار لها.

  يتم اشتقاق حسابات النطاق الإجمالية الآن مباشرة من ticks النقطة النهائية (`liquidity_gross`، `liquidity_net`، و `fee_growth_outside_*` / `reward_growths_outside_x64` لكل tick) في `TickArrayState`. صيغة fee-growth-inside `fee_growth_inside = global − outside_lower − outside_upper` تستمر في العمل بدون حساب موضع إجمالي.
</Note>

## الملاحظة

```rust
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp: u32,
    pub tick_cumulative: i64,                            // Σ tick_current × Δt
    pub padding:         [u64; 4],
}

pub struct ObservationState {
    pub initialized:       bool,
    pub recent_epoch:      u64,
    pub observation_index: u16,
    pub pool_id:           Pubkey,
    pub observations:      [Observation; OBSERVATION_NUM], // 100 entries
    pub padding:           [u64; 4],
}
```

يخزّن مخزن مؤقت الملاحظة في CLMM **tick تراكمي**، وليس سعر تراكمي. يحسب المستهلكون الخارجيون السعر الهندسي المتوسط على فترة زمنية من `(tick_cumulative[t1] − tick_cumulative[t0]) / (t1 − t0)` ثم `price = 1.0001 ** tick`. انظر [`algorithms/clmm-math`](/ar/algorithms/clmm-math).

## `DynamicFeeConfig` و `DynamicFeeInfo`

معاملات الرسوم الديناميكية تعيش في مكانين. القالب القابل لإعادة الاستخدام — `DynamicFeeConfig` — يُدار من قبل المسؤول ومشترك بين المجموعات التي تختار الاشتراك. حالة وقت التشغيل لكل مجموعة — `DynamicFeeInfo` — مضمّنة في `PoolState` وتُحدّث بواسطة كل مبادلة.

### `DynamicFeeConfig`

```rust
// programs/amm/src/states/pool_fee.rs
pub struct DynamicFeeConfig {
    pub index:                       u16,    // identifier; PDA seed component
    pub filter_period:               u16,    // seconds — within this window the volatility reference is held
    pub decay_period:                u16,    // seconds — beyond this window the reference fully decays
    pub reduction_factor:            u16,    // fixed-point in [1, 10_000); applied at decay
    pub dynamic_fee_control:         u32,    // fixed-point in (0, 100_000); fee-rate gain
    pub max_volatility_accumulator:  u32,    // ceiling on the volatility accumulator
    pub padding:                     [u64; 8],
}
```

بذرة PDA: `["dynamic_fee_config", index.to_be_bytes()]`. يتم الإنشاء عبر `create_dynamic_fee_config` (محمي بالمسؤول) والتعديل عبر `update_dynamic_fee_config`. مجموعة تم إنشاؤها بـ `enable_dynamic_fee = true` تلتقط معاملات المعايرة الخمسة للإعدادات (`filter_period`، `decay_period`، `reduction_factor`، `dynamic_fee_control`، `max_volatility_accumulator`) في `DynamicFeeInfo` الخاص بها عند وقت الإنشاء؛ التعديلات اللاحقة على `DynamicFeeConfig` لا تؤثر بأثر رجعي على المجموعات الموجودة.

### `DynamicFeeInfo` (مضمّن في `PoolState`)

```rust
pub struct DynamicFeeInfo {
    pub filter_period:                u16,
    pub decay_period:                 u16,
    pub reduction_factor:             u16,
    pub dynamic_fee_control:          u32,
    pub max_volatility_accumulator:   u32,
    pub tick_spacing_index_reference: i32,    // tick-spacing-units; reference for next swap
    pub volatility_reference:         u32,    // running floor for the accumulator
    pub volatility_accumulator:       u32,    // current cumulative volatility (capped)
    pub last_update_timestamp:        u64,
    pub padding:                      [u8; 46],
}
```

الحقول الأربعة السفلية هي حالة؛ الخمسة العليا هي معايرة مُنسخة من `DynamicFeeConfig`. رياضيات الرسوم وقواعد الاضمحلال موثقة تحت [`products/clmm/math`](/ar/products/clmm/math) و [`products/clmm/fees`](/ar/products/clmm/fees).

الثوابت المستخدمة بواسطة الصيغة:

| الثابت | القيمة | المعنى |
|---|---|---|
| `VOLATILITY_ACCUMULATOR_SCALE` | `10_000` | دقة مراكم التقلب |
| `REDUCTION_FACTOR_DENOMINATOR` | `10_000` | المقسوم عليه لـ `reduction_factor` |
| `DYNAMIC_FEE_CONTROL_DENOMINATOR` | `100_000` | المقسوم عليه لـ `dynamic_fee_control` |
| `MAX_FEE_RATE_NUMERATOR` | `100_000` | حد أقصى صارم بنسبة 10% على معدل الرسوم الناتج |

## `LimitOrderState`

حساب واحد لكل أمر حد مفتوح.

```rust
// programs/amm/src/states/limit_order.rs
pub struct LimitOrderState {
    pub pool_id:            Pubkey,
    pub owner:              Pubkey,
    pub tick_index:         i32,
    pub zero_for_one:       bool,    // direction: true sells token0 for token1
    pub order_phase:        u64,     // snapshot of TickState.order_phase at open time
    pub total_amount:       u64,     // input-token amount placed
    pub filled_amount:      u64,     // informational; computed precisely on settle
    pub settle_base:        u64,     // unfilled remainder at last settle/decrease
    pub settled_output:     u64,     // cumulative output-token paid to owner
    pub open_time:          u64,
    pub unfilled_ratio_x64: u128,    // Q64.64 snapshot of TickState.unfilled_ratio_x64 at open
    pub padding:            [u64; 4],
}
```

دورة الحياة:

1. **الفتح** — يستدعي المستخدم `open_limit_order`، يودع `total_amount` من رمز الإدخال، يُربط الأمر بـ `TickState` cohort.
2. **(اختياري) الزيادة / الإنقاص** — `increase_limit_order` يضيف إلى `total_amount`؛ `decrease_limit_order` يعيد الرموز غير المملوءة (وأي مخرجات مستقرة حتى تلك النقطة).
3. **التسوية** — عندما تكون المجموعة مملوءة بالكامل أو جزئياً، يستدعي المالك *أو* حارس التشغيل `settle_limit_order` لدفع رموز الإخراج إلى ATA المالك.
4. **الإغلاق** — بمجرد `unfilled_amount == 0`، يكون الحساب قابلاً للإغلاق. الإيجار يعود دائماً إلى `owner`.

بذرة PDA: `[owner.as_ref(), limit_order_nonce.key().as_ref(), limit_order_nonce.order_nonce.to_be_bytes().as_ref()]`. ترتيب PDA فريد لكل `(owner, nonce_index, order_nonce)`.

## `LimitOrderNonce`

عداد لكل `(wallet, nonce_index)` يسمح لمستخدم واحد بتشغيل خطوط أنابيب متعددة متوازية من أوامر الحد الأدنى دون تضارب في عناوين PDA.

```rust
pub struct LimitOrderNonce {
    pub user_wallet: Pubkey,
    pub nonce_index: u8,             // user-chosen, 0..255
    pub order_nonce: u64,            // monotonic, incremented every time a new order is opened
    pub padding:     [u64; 4],
}
```

بذرة PDA: `[user_wallet.as_ref(), &[nonce_index]]`. تستخدم معظم العملاء `nonce_index = 0` وتترك `order_nonce` ليحمل العدد الأساسي.

## `Permission` (متقاعد)

تم إزالة حساب `Permission` في [ترقية 2026-10-22](/ar/reference/changelog/2026-10-22-clmm-customizable-pool-v2). كان يستخدم للتحكم في `CreatePermissionedPool`، وهي الآن `CreateCustomizablePoolV2` بدون إذن. لا يقرأ البرنامج هذه الحسابات أو يغلقها بعد الآن، والتعليمات `CreatePermissionPda` / `ClosePermissionPda` اختفت. تبقى عناوين PDA المُنشأة قبل الترقية (`["permission", authority]`، 280 بايت) على السلسلة كبيانات خاملة؛ تجاهلها عند مسح الحسابات المملوكة لـ CLMM.

## اشتقاق حسابات المفاتيح

```ts
import { PublicKey } from "@solana/web3.js";

const CLMM_PROGRAM_ID = new PublicKey(
  "CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK"
); // see reference/program-addresses

function i32ToBytes(n: number): Buffer {
  const b = Buffer.alloc(4);
  b.writeInt32BE(n);
  return b;
}

export function deriveClmmAccounts(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
) {
  const [poolState] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  // NOTE: pools created via CreateCustomizablePoolV2 append a non-zero u16
  // seed_index (LE) as a 5th seed — see deriveCustomizablePoolV2 below.
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  const [tickArrayBitmapExtension] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_tick_array_bitmap_extension"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return { poolState, observation, tickArrayBitmapExtension };
}

export function deriveTickArray(
  pool: PublicKey,
  startTickIndex: number,
) {
  const [tickArray] = PublicKey.findProgramAddressSync(
    [Buffer.from("tick_array"), pool.toBuffer(), i32ToBytes(startTickIndex)],
    CLMM_PROGRAM_ID,
  );
  return tickArray;
}

export function deriveDynamicFeeConfig(index: number) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16BE(index);
  const [pda] = PublicKey.findProgramAddressSync(
    [Buffer.from("dynamic_fee_config"), idx],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveCustomizablePoolV2(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
  seedIndex: number,               // non-zero u16
) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16LE(seedIndex);    // little-endian, unlike the u16 seeds above
  const [pool] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer(), idx],
    CLMM_PROGRAM_ID,
  );
  return pool;
}

export function deriveLimitOrderNonce(
  wallet: PublicKey,
  nonceIndex: number,
) {
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), Buffer.from([nonceIndex & 0xff])],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveLimitOrder(
  wallet: PublicKey,
  nonceAccount: PublicKey,
  orderNonce: bigint,
) {
  const nonceBytes = Buffer.alloc(8);
  nonceBytes.writeBigUInt64BE(orderNonce);
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), nonceAccount.toBuffer(), nonceBytes],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function derivePersonalPosition(nftMint: PublicKey) {
  const [personalPosition] = PublicKey.findProgramAddressSync(
    [Buffer.from("position"), nftMint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return personalPosition;
}
```

يجب التحقق دائماً من سلاسل البذور الدقيقة مقابل IDL على السلسلة و[`reference/program-addresses`](/ar/reference/program-addresses).

| الحدث | الحسابات المُنشأة | الحسابات المحذوفة |
|-------|------------------|---------------------|

| `IncreaseLiquidity` | ربما `tickArrayState`(s) جديد | — |

| `IncreaseLimitOrder` | — | — |

| `CreateDynamicFeeConfig` | `dynamicFeeConfig` | — |
