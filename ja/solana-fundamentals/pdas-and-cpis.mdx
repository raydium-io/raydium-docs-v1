<Info>
  **PDA**（プログラム派生アドレス）と **CPI**（クロスプログラム呼び出し）は、Raydium を可能にする 2 つのプリミティブです。PDA により、プログラムは秘密鍵なしで決定論的なアドレスを「所有」できます。これがプール権限とボールトの仕組みです。CPI により、あるプログラムが別のプログラムを呼び出せます。これが Raydium が SPL Token プログラム経由でトークンをスワップする方法であり、統合者が Raydium を独自のフローに合成する方法です。Raydium のソースコードを読む前に、両方を理解する価値があります。
</Info>

## PDA：鍵のないアドレス

**プログラム派生アドレス**は以下の特性を持つ公開鍵です：

- ed25519 曲線上にない（秘密鍵が存在しない）。
- プログラム ID とシードのセットから決定論的に導出される。
- `invoke_signed` を通じて、*導出プログラムのみ*で署名できる。

すべての Raydium プール権限、すべてのプール状態アカウント、すべてのボールト、すべてのファーム状態 — これらはすべて PDA です。

### 導出

PDA は、プログラム ID とシードをハッシュして計算され、その後、結果を曲線外に強制する「バンプ」バイトが見つかります。オフカーブアドレスを生成する最初のバンプ（通常は 255 から始まり減少）が勝ちます。これが**正規バンプ**です。

```ts
import { PublicKey } from "@solana/web3.js";

const [poolAuthority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("authority"), poolId.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

シードは何でもかまいません — 文字列、他の公開鍵、リトルエンディアンバイトとしての `u64` 値。Raydium の慣例は、人間が読める接頭辞の後に一意の識別子が続きます。

### Raydium の PDA パターン

Raydium のプログラムの一般的な PDA：

| PDA | シード | プログラム |
|-----|--------|-----------|
| AMM 権限（AMM v4） | `[b"amm authority"]` + バンプ | AMM v4 |
| プール状態（CPMM） | `[b"pool", amm_config, mint_a, mint_b]` | CPMM |
| プールボールト（CPMM） | `[b"pool_vault", pool, mint]` | CPMM |
| 権限（CPMM） | `[b"vault_and_lp_mint_auth_seed"]` | CPMM |
| プール状態（CLMM） | `[b"pool", amm_config, mint_0, mint_1]` | CLMM |
| ティック配列（CLMM） | `[b"tick_array", pool, start_tick_index]` | CLMM |
| オブザベーション（CLMM） | `[b"observation", pool]` | CLMM |
| パーソナルポジション（CLMM） | `[b"position", position_nft_mint]` | CLMM |
| ファーム状態（Farm v6） | `[b"pool_farm_state", farm_id]` | Farm v6 |
| ユーザーレジャー（Farm v6） | `[b"user_ledger", farm, user]` | Farm v6 |

ユーザーと統合者は、何も取得することなくこれらを計算できます。公開入力（プール ID、ファーム ID、ユーザーキー）が与えられれば、PDA は決定論的です。

### 正規バンプ

原則として複数のバンプがオフカーブアドレスを生成する可能性がありますが、Raydium のプログラムは常に**正規バンプ**を使用します（255 から減少させて見つかったもの）。これは PDA のアカウントデータに保存されるため、後続のトランザクションはそれを渡して（高コストな）導出ループをスキップできます：

```rust
// CPMM の実際のフィールド、AccountLoader 経由で読み込まれたゼロコピー PoolState：
#[account(zero_copy(unsafe))]
#[repr(C, packed)]
pub struct PoolState {
    pub auth_bump: u8,
    // ... プール状態の残り
}
```

（CLMM の `PoolState` は代わりに `bump: [u8; 1]` を保存するため、1 つの形状を想定するのではなく、特定のプログラムの構造体を確認してください。）

後続のトランザクションでは、バンプは再計算されるのではなく、プール状態から読み取られます。

## CPI：他のプログラムの呼び出し

**クロスプログラム呼び出し**により、プログラムは別のプログラムの命令を単一のトランザクション内でインラインで呼び出せます。Raydium は CPI を広範に使用します：

- スワップ命令は SPL Token プログラムを呼び出してトークンを移動します。
- CLMM は Metaplex を呼び出してポジション NFT をミントします。
- プール作成はシステムプログラムを呼び出してアカウントを割り当てます。
- Farm v6 は SPL Token を呼び出して報酬を転送します。

統合者も CPI を使用して Raydium *に*呼び出します。これがボールト戦略、レバレッジ LP プロトコル、自動複利プロトコルの仕組みです。[`integration-guides/cpi-integration`](/ja/integration-guides/cpi-integration) を参照してください。

### invoke と invoke_signed

Solana ランタイムは 2 つの CPI プリミティブを提供します：

- **`invoke`**：別のプログラムを呼び出します。呼び出されたプログラムは外側のトランザクションの署名者を継承します。
- **`invoke_signed`**：PDA の代わりに別のプログラムを呼び出します。ランタイムは PDA のシードを検証し、署名を認可します。

`invoke_signed` は、プログラムが秘密鍵を管理することなくアカウントに対する権限を保持できるようにする魔法です。

### 例：Raydium がプールボールトから転送する

プールボールトは、権限がプールプログラムの PDA であるトークンアカウントです。スワップ中にトークンを転送するには、プールプログラムはその PDA として署名する必要があります：

```rust
// プール権限のシード
let authority_seeds: &[&[u8]] = &[
    b"vault_and_lp_mint_auth_seed",
    &[authority_bump],
];
let signer_seeds: &[&[&[u8]]] = &[authority_seeds];

// CPI コンテキストを構築
let cpi_accounts = Transfer {
    from:      input_vault.to_account_info(),
    to:        user_ata.to_account_info(),
    authority: pool_authority.to_account_info(),
};
// Anchor 1.0 はここでプログラムの Pubkey を取ります。AccountInfo フォームは 0.3x のみです。
let cpi_ctx = CpiContext::new_with_signer(token_program.key(), cpi_accounts, signer_seeds);

// 実行
token::transfer(cpi_ctx, amount)?;
```

ランタイムは `invoke_signed` が CPMM プログラムによって呼び出されていることを確認し、`vault_and_lp_mint_auth_seed + バンプ` が CPMM プログラム ID でハッシュされたときに `pool_authority` のアドレスに導出されることを検証し、トークン転送の権限署名を許可します。秘密鍵は関係ありません。

### 例：統合者が Raydium CPMM を呼び出す

統合者プログラム（例：エスクロー）は CPI 経由で Raydium の `swap_base_input` を呼び出せます：

```rust
// クレートは `raydium-cp-swap` です。そのライブラリ名 — したがって `use` パス — は
// `raydium_cp_swap` です。`raydium_cpmm` はありません。
use raydium_cp_swap::cpi::{self, accounts::Swap};

let cpi_accounts = Swap {
    payer:                order.to_account_info(),      // PDA、署名します
    authority:            pool_authority_info,
    amm_config:           amm_config_info,
    pool_state:           pool_info,
    input_token_account:  order_input_ata,
    output_token_account: order_output_ata,
    input_vault:          input_vault_info,
    output_vault:         output_vault_info,
    input_token_program:  input_token_program_info,
    output_token_program: output_token_program_info,
    input_token_mint:     input_mint_info,
    output_token_mint:    output_mint_info,
    observation_state:    observation_info,
};

let seeds = &[b"order", user.key.as_ref(), &[order.bump]];
let cpi_ctx = CpiContext::new_with_signer(
    cpmm_program.key(),     // Anchor 1.0：AccountInfo ではなく Pubkey
    cpi_accounts,
    &[seeds],
);

cpi::swap_base_input(cpi_ctx, amount_in, min_out)?;
```

これは正規の統合パターンです。完全なエスクロー例については [`integration-guides/cpi-integration`](/ja/integration-guides/cpi-integration) を参照してください。

## CPI 深度制限

Solana は CPI 深度を **4 レベル**に制限します。トランザクションのトップレベル命令は深度 0 としてカウントされます。各 CPI 呼び出しは深度を増加させます。

実用的な影響：Raydium 自体のスワップは既に 1～2 レベルの CPI を使用します（Raydium → SPL Token）。統合者が Raydium を呼び出す場合は 2 です。その統合者が別の統合者によって呼び出される場合は 3 です。4 番目のレベルが制限です。

ほとんどの合成はこれを簡単に下回りますが、深いネスト（アグリゲーター → ルーター → Raydium → フック）はそれに達する可能性があります。深いのではなく平らに設計してください。

## 残りのアカウント

Raydium 命令が可変数のアカウントを必要とする場合（例：CLMM スワップが不明な数のティック配列を横切る場合）、追加のアカウントは**残りのアカウント**として渡されます — 固定アカウントリストに追加され、位置で解釈されます。

CPMM の `SwapV2` は、転送フックプログラムの追加の必須アカウント用に残りのアカウントを使用します。クライアントは必要なアカウントを取得して追加します：

```ts
const swapIx = await raydium.cpmm.swap({
  /* ... */
  // SDK は残りのアカウントを自動的に処理します
});
```

CPI レベルでは、統合者は独自の命令を通じて残りのアカウントを転送する必要があります：

```rust
pub struct Swap<'info> {
    // ... 固定アカウント
    // さらに ctx.remaining_accounts 経由で転送される残りのアカウント
}

// 残りのアカウントを CPI に転送
cpi::swap_base_input(
    cpi_ctx.with_remaining_accounts(ctx.remaining_accounts.to_vec()),
    amount_in,
    min_out,
)?;
```

## PDA の落とし穴

### 間違ったシード → 間違ったアドレス

シードが間違った順序、間違ったエンコーディング、または余分なバイトを含める/除外するバグは、静かに異なる PDA を生成します。トランザクションは曖昧に失敗します（プログラムは存在しないアカウントを読み取ろうとします）。常にシード導出を既知のゴールデン値に対してユニットテストしてください。

### バンプを保存しない

すべてのトランザクションでバンプを再導出する場合、導出ループの計算を支払います。正規バンプを PDA のデータに保存し、そこから読み取ります。

### 正規バンプと非正規バンプを混同する

非正規バンプ（オフカーブを生成するものが見つかった場合）は `invoke_signed` で許可されますが、Raydium のプログラムは `assert_eq!(bump, canonical_bump)` を通じて拒否します。誰かが非正規バンプで PDA を要求しようとする場合、トランザクションは失敗します。

### 所有プログラムでない場合に PDA を署名者として渡す

PDA の導出に ID が含まれるプログラムのみが、そのシードで `invoke_signed` できます。試みた場合、ランタイムは拒否します。

## CPI の落とし穴

### `remaining_accounts` を転送し忘れる

外側の命令が `remaining_accounts` に転送フックアカウントを渡しますが、Raydium への CPI がそれらを転送しない場合、Raydium はフックアカウントを見つけられないため失敗します。常に必要な CPI に `with_remaining_accounts` を含めてください。

### 書き込み可能フラグの不一致

外側の命令が書き込み可能としてマークするアカウントは、呼び出されたプログラムがそれを書き込む場合、CPI 呼び出しでも書き込み可能である必要があります。不一致 → ランタイム拒否。

### 家賃を考慮しない

アカウントを作成するプログラムへの CPI（例：ATA 作成）では、支払者が家賃用に十分な SOL を持つ必要があります。失敗した家賃チェックは不可解なエラーとして表示されます。

## 実例：Raydium CPMM PDA の計算

```ts
import { PublicKey } from "@solana/web3.js";

const CPMM_PROGRAM_ID = new PublicKey("CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C");

function computeCpmmPdas(ammConfig, mintA, mintB) {
  const [poolState, poolBump] = PublicKey.findProgramAddressSync(
    [
      Buffer.from("pool"),
      ammConfig.toBuffer(),
      mintA.toBuffer(),
      mintB.toBuffer(),
    ],
    CPMM_PROGRAM_ID,
  );

  const [authority] = PublicKey.findProgramAddressSync(
    [Buffer.from("vault_and_lp_mint_auth_seed")],
    CPMM_PROGRAM_ID,
  );

  const [vaultA] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), mintA.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  const [vaultB] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), mintB.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  return { poolState, authority, vaultA, vaultB, observation, poolBump };
}
```

これは、`getPoolInfoFromRpc({ poolId })` を呼び出すときに Raydium SDK が内部で行うことと全く同じです — ラウンドトリップなしで関連する PDA を導出します。
