## Raydiumポジションの検出

### クラシック LP トークン（CPMM、AMM v4）

これらは他のSPLトークンと同じように見えます。ユーザーのATAが残高を保有しています。ウォレットはデフォルトではこれを単なる別のトークンとして表示します。これをRaydium LPポジションとして表示するには：

1. ユーザーのトークン アカウントを列挙します：`connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`。
2. 各ミントについて、Raydiumのミント リストを確認します：`GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...`（1回の呼び出しで最大約50個のLPミントをバッチ処理）。
3. マッチするミントについて、APIはプール参照を返します。これを使用してポジションのトークン建て価値を計算します：

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

LP残高とアンラップされた金額の両方を表示します。ユーザーはLPユニットではなく、基礎となるトークンで考えます。

### CLMM ポジション NFT

CLMMポジションはNFTです。各ポジションの`PersonalPositionState` PDAはNFTミントから導出されます。検出するには：

1. ユーザーのNFTを列挙します。レガシーMetaplex NFTの場合：トークン アカウントをサプライが1で小数点以下が0のものにフィルタリングします。
2. 各NFTミントについて、PersonalPositionState PDAを導出してみます：

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Raydium CLMMポジションです — デコードします。
```

3. `raydium.clmm.getOwnerPositionInfo({ programId })`でウォレットのポジションを列挙し、`nftMint`でマッチングします（`getPositionInfo`はありません）。各エントリは以下を提供します：
   - `poolId` → プールをフェッチしてミントを解決
   - `tickLower`、`tickUpper` → 範囲を表示
   - `liquidity`、`tokensOwedA/B` → ポジション価値と保留中の手数料を計算
   - `rewardInfos` → ストリームごとの保留中報酬

4. Token-2022（`OpenPositionWithToken22Nft`）の下で発行されたポジション NFTの場合、NFTミントのプログラムはSPLトークンではなくToken-2022です。スキャン時に両方を列挙します。

### ファーム ステーク

Farm v3 / v5 / v6には、それぞれユーザーごとのレジャー PDAがあります。導出方法：

```ts
// ユーザーの潜在的なファーム インタラクションのそれぞれについて、3つのファーム バージョンをすべて試します。
// 最も安い方法：APIに最初に問い合わせます。APIはすべてのユーザー ポジションをインデックス化しています。

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

完全なオンチェーン検出を好むウォレットの場合：キュレーションされた「可能性の高い」ファームIDのリストでユーザーをハッシュして、可能な`UserLedger` PDAを反復処理します。すべてのファームIDを網羅的に列挙することは実用的ではありません（数千存在）。APIを使用してください。

## ポジション価値の計算

### CPMM / AMM v4 LP

3つのモジュールは署名を共有しません：`liquidity.getPoolInfoFromRpc`は`{ poolId }`を取り、`cpmm.getPoolInfoFromRpc`と`clmm.getPoolInfoFromRpc`は位置指定base58文字列を取ります。

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint`はApiV3Tokenで、`supply`フィールドがありません。LPミントの
// サプライをチェーンから読み取るか、プール自体のミラーを使用します：
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

次に、各ミントのUSD価格を掛けます（`raydium.token`または価格オラクルから）。

### CLMMポジション

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // base58文字列
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidityは非同期で、epochInfo + poolInfo + addを取り、
// 手数料でラップされた金額を返します。
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // 表示用、スリッページなし
  add:        false,
});
// amountA.amount / amountB.amountはBN；.feeはToken-2022転送手数料です。

// 保留中の手数料 — 「未収集」として別途表示
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// 保留中の報酬 — CLMMプールは0～3の報酬ストリームを持ちます。ポジションの
// rewardInfosエントリは{ growthInsideLastX64, rewardAmountOwed }のみなので、
// ミントはプールのrewardInfosの同じインデックスから取得する必要があります。
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

以下のようにレンダリングします：

- リクイディティ価値（現在の価格）
- 未収集の手数料
- ストリームごとの保留中報酬
- 範囲：`[tickLower_price, tickUpper_price]`。現在の価格が範囲内かどうかを示すビジュアル バーを表示

### ファーム ステーク

```ts
// APIレスポンスには既に保留中の報酬が含まれています。直接使用します。
const apr       = stakingFarm.apr;               // ％、年率
const staked    = stakingFarm.stakedAmount;      // ステーキング ミントの最小単位
const rewards   = stakingFarm.pendingRewards;    // { mint, amount }の配列
```

オンチェーン計算の場合、ファームの会計をミラーリングします：

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

計算する前に、遅延更新式で`reward_per_share_x64`を更新してください（経過時間×排出率÷総ステーク）。

## トランザクション シミュレーションでのプレビュー

ユーザーが署名する前に、ウォレットは通常、残高の変化をプレビューします。`simulateTransaction`を使用します：

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// 返された各アカウントの残高をデコードし、トランザクション前の残高と比較します。
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // トランザクション前の残高と比較し、Δを表示
}
```

`accounts`パラメータは、バリデータに対して、リストされたアドレスのシミュレーション後のアカウント状態を返すよう要求します。命令の形状だけから残高の変化を予測しようとするよりもはるかに正確です。

### シミュレーションの落とし穴

- **CLMMスワップは有効なティック配列が必要です。** ユーザーの入力サイズが初期化されていないティック配列に交差する場合、シミュレーションは戻ります（実行と同じ）。UIでこれを明確に表示します。
- **優先度手数料。** シミュレーションは、計算予算命令が適用されない状態で実行されます。デフォルトの200k CUを超える大規模なトランザクションの場合、シミュレーションは失敗しますが、明示的なCU制限での実際の実行は成功します。シミュレートされたトランザクションにもCU制限を常に設定してください。
- **新しいブロックハッシュ。** シミュレーションは現在のブロックハッシュを使用します。署名に60秒以上かかる場合、トランザクションは無効になります。ユーザーが躊躇した場合は再シミュレートしてください。

## Token-2022表示

Token-2022プログラムの下のトークンは、異なるリスク サーフェスを持つため、ウォレットのトークン リストで「Token-2022」とラベル付けする必要があります：

- **転送手数料ミント**：現在の`transferFeeBasisPoints`を「転送手数料：X%」として残高の横に表示します。受け取り時に警告します。ユーザーは送信者が送信した金額より少ない金額を受け取ることに気付かないかもしれません。
- **転送フック ミント**：フック プログラムIDを表示します。悪意のあるフックは送信トランザクションをブロックできます。ユーザーはフックが期待するものであることを確認する必要があります。
- **転送不可ミント**：「転送不可」を表示し、スワップ/送信を無効にします。これらは通常、ソウルバウンド トークンまたは認証情報です。
- **利息付きミント**：`TokenAccount.amount`から導出されたUI残高は、発生した利息を反映しません。表示値には`@solana/spl-token`の`amountToUiAmount`を使用します（スケーリング係数を適用）。

## ファーム APR表示

ユーザーに表示されるAPRは、すべてのライブ報酬ストリームを組み合わせ、USDに変換し、年率化する必要があります：

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // 実行中でないものをスキップ
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

`APR: X.Y%`として表示します。ステーキング ミントがLPトークンの場合、基礎となるLPの基本手数料APRも計算し、合計を「Total APR」または「APR + fees」とラベル付けします。
