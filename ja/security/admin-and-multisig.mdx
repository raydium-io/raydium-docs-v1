### CLMM

| ロール | 権限アドレス | 実行可能な操作 |
|------|-------------------|----------------|
| プログラムアップグレード | Squadsマルチシグ（3/4） | 新しいプログラムバイトコードをデプロイ |
| AmmConfig管理者 | Treasury マルチシグ（3/5） | AmmConfigを作成・変更 |
| DynamicFeeConfig管理者 | Treasury マルチシグ（3/5） | `CreateDynamicFeeConfig` / `UpdateDynamicFeeConfig` — `CreateCustomizablePool`呼び出しがオプトインできるダイナミック手数料ティアを調整 |
| `permission_pda_admin` | プログラム`admin`**または**専用の`permission_pda_admin`キー（メインネットとdevnetで異なる値） | `CreatePermissionPda` / `ClosePermissionPda` — `CreatePermissionedPool`を呼び出す権限を付与または取り消す。付与は`["permission", authority]` PDAの単なる存在であり、プール変更権は**付与しません**。 |
| `limit_order_admin`（プログラム全体） | **マルチシグではなく、オフチェーン運用ホットウォレット** | 所有者に代わってリミットオーダーを決済・クローズ。キーパーキーはプログラム全体の単一定数（メインネットとdevnetで異なる値）で、`SettleLimitOrder` / `CloseLimitOrder`で`signer == limit_order.owner \|\| signer == limit_order_admin::ID`経由でチェック。出力は常に元の所有者のATAに着地し、キーパーは資金をリダイレクト、オーダーを変更、または新しいものを開くことはできません。 |

`Permission` PDAを保有する権限は、`CreatePermissionedPool`を呼び出して、既に正規のプールを持つペアの追加プールを作成できます。各プールは異なる`seed_index`派生アドレスにあります。権限はプール作成のみにスコープされます。資金を移動、手数料を変更、または既存のプールに触れることはできません。権限を取り消す（`ClosePermissionPda`）と、権限は以降のプール作成を停止しますが、既に作成されたプールは変わりません。

`limit_order_admin`は意図的に狭い運用ロールです。オフチェーンキーパーが、オーダーの所有者がオンラインである必要なく、満たされたオーダーをスイープできるようにするために存在します。キーパーキーはホット（キーパーVM上に存在）で、上記のマルチシグとは独立して回転します。具体的には、キーパー権限は以下に限定されます：

- `SettleLimitOrder` — 満たされたオーダーの出力を**所有者の** ATAにオーダーのリミット価格で押し出す。
- `CloseLimitOrder` — 完全に決済されたオーダーのアカウントをクローズしてレント回収（レントは所有者に行く）。

`OpenLimitOrder`、`IncreaseLimitOrder`、`DecreaseLimitOrder`を呼び出したり、プールフィールドを変更したり、他の命令に署名することはできません。これらのチェックはオンチェーンで命令の`Accounts`構造体のシードと`has_one`制約によって強制されます。侵害されたキーパーは最悪の場合、利用不可（オーダーは所有者が自分で決済するまで駐車）または正当に満たされたオーダーを順序外で決済・クローズできます。所有者が既に認可した場所以外のユーザー資金を移動することはできません。

## プログラムアップグレード権限

Raydiumのプログラムは標準的なSolana **BPF Loader v3** アップグレードメカニズムを使用します。すべてのプログラムのアップグレード権限は3/4 Squadsマルチシグです。

なぜ3/4か：単一の侵害が不十分なほど十分な署名者がいます。正当なアップグレードの調整が扱いやすいほど十分です。4つの権限は独立した、コアチームメンバーが保有するエアギャップコールドデバイス署名者です。順序付き署名は同じトランザクションの並列承認を防ぎます。トランザクションは固定有効期限ウィンドウを持ちます。マルチシグ操作は**Solanaの STRIDE プログラム（Asymmetric Research）**とのパートナーシップで定期的にレビューされます。

### アップグレード権限の削除

Raydiumはプログラムのアップグレード権限をnullに設定していません。プロトコルはプログラムがアップグレード可能である必要があるという原則の下で動作します（バグを修正、Token-2022などの拡張機能を追加、統合ドリフトを修正するため）。トレードオフ：ユーザーは3/4マルチシグが十分にレビューされたアップグレードのみをデプロイすることを信頼します。

不変の代替案を望むユーザーのために、古いAMM v4プログラムは最後の監査以来安定しています。18ヶ月間ゼロアップグレード。そのコードパスは権限がまだ存在していても事実上凍結されています。

## AmmConfig権限

新しいAmmConfig作成はそれぞれ許可されています。3/5 treasury マルチシグが新しい手数料ティアとティックスペーシングを認可します。既存のプールはPDAでAmmConfigを参照します。プールの手数料ティアはAmmConfigが言うことです。

**管理者は既存のAmmConfigを変更できますか？** 技術的にはい。`updateAmmConfig`は管理者が呼び出せます。実際には、デプロイされたAmmConfigの変更は避けられます。なぜなら、そのコンフィグを使用するすべてのプールの経済学を静かに変更するからです。プロトコルポリシーは、変更のために新しいAmmConfigを作成し、移行することです。

**管理者はコンフィグ経由でプロトコル手数料を盗むことができますか？** いいえ。AmmConfigには手数料パラメータが含まれていますが、プロトコル手数料受取人は含まれていません。それはプールごとの別の不変アドレスです。

## プロトコル手数料請求

スワップ手数料の一部（通常、25 bpsスワップ手数料の3～12 bps、コンフィグによって異なる）がプロトコル手数料ボルトに蓄積されます。マルチシグはこれらの蓄積された手数料を引き出すことができます。ユーザーはこれからLPバランスが変わるのを見ることはありません。これはプロトコルの事前割り当てシェアであり、LPマネーではありません。

## ファーム作成者権限

Farms v6は作成者に以下の権限を与えます：

- リワードボルトに資金提供（トークンを追加）。
- スケジュール延長（終了時刻を後に押す）。
- 終了時刻後に`withdrawReward`を呼び出して、未使用のボルトバランスを回収。

ファーム作成者は**できません**：

- ステークされたユーザーLPを引き出す。
- ステーキングミントを変更する。
- 遡及的に排出レートを変更（`setRewards`経由の前向きのみ）。
- ユーザーハーベストをフリーズ。

悪意のあるファーム作成者は最悪の場合、ボルトに資金不足を与えてファームが枯渇するようにできます。ユーザーの元本ステークは常に安全です。

## Squadsマルチシグ設定

Raydiumは異なるリスク表面のために2つの別々のSquadsマルチシグを運用しています。どちらも[Squads Protocol](https://app.squads.so) UIを介してオンチェーンで検査できます。

| マルチシグ | 閾値 | タイムロック | スコープ |
|----------|-----------|----------|-------|
| **プログラムアップグレード** | **3/4** | **24時間** | AMM v4、CPMM、CLMM、LaunchLab、Lock、AMM Routing、Stable Swap、およびレガシーFarm/Stakingプログラムの新しいプログラムバイトコードをデプロイするための唯一の権限。[`app.squads.so/.../FytDr…ceZQK`](https://app.squads.so/squads/FytDrVzDybM1TwFQPGb8qaxZR7dBCzNeqT3vtQsceZQK/home)で表示。 |
| **Treasury** | **3/5** | なし | Treasury資産、プロトコル収益、運用費。また、当面の間、Raydiumの限定的なプログラム管理者権限（AmmConfigの作成、プロトコル手数料のスイープ、プールパラメータの設定）を保有しています。[`v3.squads.so/dashboard/RVha…dHdtYz09`](https://v3.squads.so/dashboard/RVhaWTdGUGNjTnVFdmdIWk1DTXB3dzJGZW44b0xXQlNKemRnQ3NYM0Rqd20=)で表示。 |

アップグレードマルチシグの運用プロパティ：

- **24時間タイムロック** 任意のトランザクション上。今日承認されたアップグレードは24時間以前に実行されず、ユーザーが応答する時間を与えます。
- **エアギャップコールドデバイス署名。** コールドデバイスはネットワークカードが物理的に削除されています。ハードウェアウォレットにのみ接続し、別のホットデバイスからQRコード経由でトランザクションデータを読み取ります。
- **順序付き署名。** 1つのコールドデバイスがトランザクションを生成して署名した後にのみ、次のコールドデバイスが署名プロセスを開始できます。同じトランザクションの競合または並列署名を防ぎます。
- **トランザクション有効期限。** すべてのトランザクションは固定有効期限ウィンドウを持つため、古いトランザクションは自動的に無効化されます。
- **TOTP + 物理キー強制** トランザクション開始とオンチェーン放送に使用されるホットデバイス上。
- **公開トランザクションキュー。** 誰でもSquads UIで保留中のアップグレードを監視できます。

Treasury マルチシグにはタイムロックがありません。スコープはより狭く、ルーチン操作（AmmConfigの作成、手数料のスイープ）は同日に着地する必要があります。Treasury マルチシグはまた、上記のプログラムごとのテーブルにリストされている限定的なプログラム管理者権限を保有しています。これは暫定的な取り決めであり、プロジェクトのセキュリティパートナーと定期的にレビューされます。

## オンチェーンで権限を検証

プログラムの現在のアップグレード権限を検証する最も簡単な方法：

```bash
solana program show <PROGRAM_ID>
```

出力には以下が含まれます：

```
Program Id:          CPMMoo8L3F4NbTegBCKVNunggL7H1Zpdmwpwh8KMoZ0F
Owner:               BPFLoaderUpgradeab1e11111111111111111111111
ProgramData Address: <ProgramDataPDA>
Authority:           <EXPECTED_MULTISIG_ADDRESS>
Last Deployed In Slot: <slot>
Data Length: <n> bytes
```

`Authority`が予想されるSquadsマルチシグアドレスでない場合、何か問題があります。Raydiumは予想される権限アドレスを[`reference/program-addresses`](/ja/reference/program-addresses)で公開しています。

AmmConfig / プール管理者ロールの場合、オンチェーンアカウントをフェッチしてデコード：

```ts
const config = await raydium.cpmm.getAmmConfig(configPda);
console.log("AmmConfig admin:", config.admin.toBase58());
// 予想：3/5 treasury マルチシグ。
```

## ユーザー側の考慮事項

ユーザー/LP/インテグレーターとしてあなたが何をすべきか？

1. **大きな割り当ての前にアップグレード権限を確認。** ドキュメント化されたマルチシグと一致することを確認。
2. **マルチシグアクティビティを監視。** [Squads UI](https://v4.squads.so)は保留中のトランザクションを表示します。スケジュールされたアップグレードは、変更に同意しない場合、アンワインドする24時間を与えます。
3. **タイムロック対応の償却戦略。** オートコンパウンダーを実行している場合、アンワインドパスが変更されている命令を必要としないことを確認。
4. **プログラムの不変性を仮定しないでください。** すべてのRaydiumプログラムはアップグレード可能です。それに対応してください。

## インテグレーターの落とし穴

### 1. 権限アドレスのキャッシング

コードにアップグレード権限または管理者マルチシグアドレスをハードコードし、後で回転する場合、検証が失敗します。[`reference/program-addresses`](/ja/reference/program-addresses)から実行時にフェッチするか、定期的に更新してください。

### 2. AmmConfigが安定していると仮定

新しいAmmConfigはいつでも作成できます。アグリゲーター/ルーターは定期的に（1時間ごとで問題ない）完全なコンフィグリストを再フェッチする必要があります。

### 3. ファーム作成者の悲しみベクトル

低い評判のファームに預金している場合、作成者はファームを早期に終了し、リワードボルトを回収できます（ユーザーがまだステークしていないと仮定）。ユーザーがステークすると、プロ・ラタ権利はプログラムによって強制されます。回収は合理的な終了後の残余のみを取得します。
