## Anchor エラーコードの仕組み

Anchor は、プログラムの `ErrorCode` 列挙型の各バリアントに `6000` から始まる数値コードを割り当てます。失敗したトランザクションは以下を表示します：

- **数値エラーコード**（例：`0x1771` = 6001）がトランザクションログに表示されます。
- **エラー名**（例：`InvalidOwner`）が IDL から取得されます。
- **`#[msg(...)]` 文字列**が Anchor によって `log_messages` に出力されます。

インテグレーターは、メッセージ文字列ではなく**数値コード**で照合する必要があります（文字列はバージョンをバンプせずに言い換えることができます）。

```ts
// 例：CPMM スリッページエラーを検出し、クリーンな UX メッセージを表示します。
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

| 6022 | `InvalidPlatformAllowConfig` | 提供された許可アカウントが予想されるプラットフォームとグローバル設定ペアをエンコードしていません。 |
| 6023 | `CalculateOverflow` | Token-2022 転送手数料または逆転送手数料の計算を表現できませんでした。クォートミントの手数料を反転できない場合（例えば 100% 手数料ミント）、正確な出力トレードパスで到達可能です。 |

古い `PlatformGlobalAccessDenied`（`6022`）および `InvalidPlatformGlobalAccess`（`6023`）バリアントは削除されました。以前の IDL を使用して `6022` をデコードしないでください。`6023` は 2026-08-17 リリースで空いており、2026-08-24 リリースで関連のないエラーに再利用されるため、どちらかの以前のバージョンの IDL でデコードしてはいけません。

## SDK エラーをプログラムエラーにマッピング

公式 TypeScript SDK はオンチェーンエラーを `SendTransactionError` にラップし、Anchor プログラムの場合は `AnchorError` にラップします：

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

クライアント側で Anchor を使用していない場合は、トランザクションログを解析します：

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

パターン `Error Number: (\d+)` は Anchor バージョン全体で安定しており、マッチするのは安全です。

## これらのテーブルを再生成する

プログラムがアップグレードされて新しいエラーが追加されたときは、ソースから再抽出します：

```bash
# リポジトリをクローンし、エラー列挙型を順序で grep します。
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# 6000+++ を単調増加する 6000,6001,... に置き換えます。新しい行を上記のテーブルに追加します。
```

プログラムバリアントが追加されたときは常に [`reference/changelog`](/ja/reference/changelog) を更新してください。SDK をアップグレードするインテグレーターがエラーハンドラーを更新する必要があることを知ることができます。
