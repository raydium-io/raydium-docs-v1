## Anchor エラーコードの仕組み

Anchor は、プログラムの `ErrorCode` 列挙型の各バリアントに `6000` から始まる数値コードを割り当てます。失敗したトランザクションは以下を表示します：

- **数値エラーコード**（例：`0x1771` = 6001）がトランザクション ログに表示されます。
- **エラー名**（例：`InvalidOwner`）が IDL から取得されます。
- **`#[msg(...)]` 文字列**が Anchor によって `log_messages` に出力されます。

インテグレーターは、メッセージ文字列ではなく**数値コード**で照合する必要があります（文字列はバージョンをバンプせずに言い換えることができます）。

```ts
// 例：CPMM スリッページ エラーを検出し、クリーンな UX メッセージを表示します。
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

`6020` は意図的に保持されています。Anchor はバリアントを位置で番号付けするため、削除すると後続のすべてのコードがシフトし、`6021`–`6031` をデコードするすべてのクライアントが破損します。

### AMM v4：`AmmError` は Anchor 番号付けではありません

AMM v4 は Anchor より前のものです。`AmmError` は `FromPrimitive` を備えたプレーン `thiserror` enum で、`ProgramError::Custom(e as u32)` を通じて変換されるため、そのコードは **`0`** から始まります。Anchor と同様に、ソース順序で割り当てられます。2026-09 アップグレードでは 1 つのバリアントが追加されます：

| コード | バリアント | `#[error]` 文字列 | 原因 |
|---|---|---|---|
| 60 | `LamportsCalculateError` | Lamports calculate error. | `WithdrawExcessLamports` がラップされた SOL アカウントをスイープし、`SyncNative` → `UnwrapLamports` ラウンドトリップがラップされたトークン残高を正確に開始位置に残しませんでした。管理者のみのパス。 |

コード `0`–`59` は変更されていないため、何もシフトしません。トランザクションログではこれは `custom program error: 0x3c` として表示されます。再生成ソース：[github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs)。

## SDK エラーをプログラムエラーにマッピングする

公式 TypeScript SDK はオンチェーンエラーを `SendTransactionError` にラップし、Anchor プログラムの場合は `AnchorError` にラップします：

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

クライアント側で Anchor を使用していない場合は、トランザクションログを解析してください：

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

パターン `Error Number: (\d+)` は Anchor バージョン全体で安定しており、マッチングに安全です。

## これらのテーブルを再生成する

プログラムがアップグレードされて新しいエラーが追加されたときは、ソースから再抽出してください：

```bash
# Clone and grep the error enum in order.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Replace 6000+++ with monotonically-increasing 6000,6001,... Append new rows to the table above.
```

新しいバリアントが追加されるたびに必ず [`reference/changelog`](/ja/reference/changelog) を更新してください。これにより、SDK をアップグレードするインテグレータはエラーハンドラーをリフレッシュする必要があることを知ることができます。
