### 共有管理者権限

| クラスター | 管理者 |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

アカウントレベルの運用権限（例：CPMM/CLMM `AmmConfig` の `protocol_owner`、`fund_owner`、または LaunchLab `GlobalConfig` のマイグレーションウォレット）はオンチェーンに保存され、プログラム管理者と異なる場合があります。高リスクのトランザクションを送信する前に、関連するコンフィグアカウントから直接読み取ってください。

### 共有コンフィグ / PDA 規約

複数の Raydium プログラムは、公開キーが安定している**コンフィグアカウント**を公開 API に記載しています。ハードコーディングよりも API ルックアップを優先してください：

```
# CPMM フィーコンフィグ（{id, index, tradeFeeRate, ...} の配列を返す）
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM フィーコンフィグ
GET https://api-v3.raydium.io/main/clmm-config
```

デフォルト CPMM `AmmConfig` インデックス `0`（標準 0.25% プール）フィーパラメーター（参考）：

| フィールド | 値 | 意味 |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | トレード量の 0.25% |
| `protocol_fee_rate` | `120000` | トレードフィーの 12%（ボリュームではなく）をプロトコルにルーティング |
| `fund_fee_rate` | `40000` | トレードフィーの 4% をファンドマルチシグにルーティング |
| `creator_fee_rate` | `500` | トレード量の 0.05% をプールクリエーターに（オプション） |

分割がどのように構成されるかについては [`products/cpmm/fees`](/ja/products/cpmm/fees) を参照し、クロスプロダクトマトリックスについては [`reference/fee-comparison`](/ja/reference/fee-comparison) を参照してください。

### PDA シード

以下のシードは**正規**であり、SDK とオンチェーン CPI の両方で使用されます。常に PDA を計算してください。派生アドレスをハードコードしないでください。

```ts
// CPMM — すべてのシードは特に記載がない限り、静的 ASCII 文字列です。
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` は、ハッシング前に**公開キーのバイト順でソート**されます（token0 < token1）。これを間違えると、存在しないプールの有効な PDA が生成されます。

同等の CLMM シードは同じスタイルに従います。詳細は [`products/clmm/accounts`](/ja/products/clmm/accounts) を参照してください。

## オンチェーンでアドレスを検証する方法

1. **Solana Explorer。** アドレスを [explorer.solana.com](https://explorer.solana.com) に貼り付けて、`Program` とマークされ、現在のアップグレード権限があることを確認します。Mainnet-beta は Raydium のアップグレード権限で署名されたデプロイを表示する必要があります。
2. **CLI。** `solana program show <PROGRAM_ID> -u mainnet-beta` を使用して、デプロイスロット、BPF ローダー、アップグレード権限、およびデータ長を検査します。これらをランブックに記録します。
3. **IDL 添付。** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` でオンチェーン IDL をクエリします。IDL の `address` フィールドが一致する必要があります。同じ IDL は [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) にミラーされています。信頼する前に、オンチェーン IDL をリポジトリと比較してください。
4. **コンフィグ/管理者権限。** CPMM/CLMM コンフィグアカウントの場合、`owner`/`protocol_owner` フィールドを読み取り、現在の Raydium マルチシグと一致することを確認します。詳細は [`security/admin-and-multisig`](/ja/security/admin-and-multisig) を参照してください。

上記の 4 つのチェックのいずれかがこのページと異なる場合は、このページが間違っていると見なし、新しいコードをアドレスに対して書く前に問題を開いてください。
