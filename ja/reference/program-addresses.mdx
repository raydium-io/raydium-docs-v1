### 共有管理者権限

すべての Raydium プログラム（AMM v4 を含む）は、管理者パスへのインストラクションレベルのアクセス制御のための単一のハードコードされた管理者 `Pubkey` を共有しています。AMM v4 では `config_feature::amm_owner::ID`（`SetParams`、`CreateConfigAccount`、`UpdateConfigAccount` をゲーティング、デフォルト `pnl_owner` として使用）で、Anchor プログラム（CLMM、CPMM、LaunchLab、Lock）では `admin::ID` です。`CreateAmmConfig` や `UpdatePoolStatus` などのパスをゲーティングします：

| クラスタ | 管理者 |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

アカウントレベルの運用権限（例：CPMM/CLMM `AmmConfig` の `protocol_owner`、`fund_owner`、または LaunchLab `GlobalConfig` のマイグレーションウォレット）はオンチェーンに保存され、プログラム管理者と異なる場合があります。高リスクのトランザクションを送信する前に、関連するコンフィグアカウントから直接読み取ってください。

### PDA シード

以下のシードは**正規**であり、SDK とオンチェーン CPI の両方で使用されます。常に PDA を計算してください。派生アドレスをハードコードしないでください。

```ts
// CPMM — すべてのシードは特に記載がない限り静的 ASCII 文字列です。
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` はハッシング前に**公開キーのバイト順でソート**されます（token0 < token1）。これを間違えると、存在しないプールの有効な PDA が生成されます。

同等の CLMM シードは同じスタイルに従います。詳細は [`products/clmm/accounts`](/ja/products/clmm/accounts) を参照してください。

## オンチェーンでアドレスを検証する方法

1. **Solana Explorer。** アドレスを [explorer.solana.com](https://explorer.solana.com) に貼り付けて、`Program` とマークされ、現在のアップグレード権限があることを確認します。Mainnet-beta は Raydium のアップグレード権限で署名された展開を表示する必要があります。
2. **CLI。** `solana program show <PROGRAM_ID> -u mainnet-beta` を使用して、展開スロット、BPF ローダー、アップグレード権限、データ長を検査します。これらをランブックに記録します。
3. **IDL 添付。** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` は **CLMM、LaunchLab、Lock** で機能します。これらはプログラム自体が所有するレガシー `anchor:idl` アカウントを保持しています。CPMM では**機能しません**。CPMM のオンチェーン IDL は 2026-09 アップグレードでプログラムメタデータプログラム（`ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S`）に移動したため、代わりにそこから取得してください。AMM v4、Stable AMM、Farm にはオンチェーン IDL がありません。IDL は [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) にミラーされています。信頼する前に、オンチェーン IDL をリポジトリと比較してください。
4. **コンフィグ/管理者権限。** CPMM/CLMM コンフィグアカウントの場合、`owner`/`protocol_owner` フィールドを読み取り、[`security/admin-and-multisig`](/ja/security/admin-and-multisig) で公開されている現在の Raydium マルチシグと一致することを確認します。

上記の 4 つのチェックのいずれかがこのページと異なる場合は、このページが間違っていると見なし、新しいコードをアドレスに対して記述する前に問題を開いてください。

- プログラム ID への変更は安全性が重要です。プログラム ID の変更を出荷する際は、(a) Raydium アナウンスへのリンク、(b) [`reference/changelog`](/ja/reference/changelog) へのエントリ追加、(c) ドキュメント全体のリンクチェックを実行して、古い値をまだ参照しているページがないことを確認してください。
