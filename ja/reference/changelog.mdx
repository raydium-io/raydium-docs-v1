## リリース

<Update label="2026-08-26" description="LaunchLab: プラットフォームフィーレート上限が 500 bps に引き上げられました">
  プラットフォーム `fee_rate` の上限が両方の検証パスで `50000`（500 bps）に移動します。`CreatePlatformConfig` はプログラムの最初のリリース以来 `10000`（100 bps）でキャップされていました。`UpdatePlatformConfig` は 2026-01-27 以来 `25000`（250 bps）でキャップされていました。これで 2 つのチェックが一致するため、許可されたレートで作成されたプラットフォームは、そのレートで更新することもできます。`AllInfo` バルク変種を含めて、他のすべてのフィールドを書き直しながら `fee_rate` を再検証します。2 つのパスは依然として異なるエラーを発生させます（作成時は `InvalidInput`、更新時は `InvalidPlatformInfo`）。アカウントレイアウト、命令、またはエラーコードは変更されず、既存のプラットフォームまたはローンチの価格変更はありません。`GlobalConfig.max_share_fee_rate` は 100 bps のままで、トランザクションごとのリファーラル `share_fee_rate` のみを制限します。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)
</Update>

<Update label="2026-08-24" description="LaunchLab: Token-2022 クォートミント">
  ローンチは Token-2022 ミントで見積もることができるようになりました。`CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、4 つのスワップ命令、およびすべてのフィー請求は、クォートプログラムスロットで両方のトークンプログラムを受け入れます。非推奨の `Initialize` はレガシーのみのままです。スワップスリッページ境界は、クォートミントの転送フィーを差し引いた、支払人が実際に支払うまたは受け取る金額と比較されるようになりました。`PoolState.token_program_flag` ビット 1 が意味を持つようになったため、バイト全体を `0` に対してテストするデコーダーはレガシーベースミントを Token-2022 として誤読します。`MigrateToCpswap` は 2 つのトークンプログラムアカウントを `token_program` / `token_program_2022` に名前変更し、`6023` は `CalculateOverflow` に再利用されます。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab: CPMM のみのローンチとプラットフォーム設定コントロール">
  新しいローンチ初期化は CPMM を必須とし、レガシー AMM v4 バウンド状態は移行可能なままです。このリリース前は、`creator_scale` はクリエイター所有のフィーキーを生成していました。アップグレード後に実行された CPMM 移行は、代わりに `platform_scale + creator_scale` を 1 つのプラットフォーム所有のフィーキーシェアに統合します。プラットフォームは独自の `PlatformAllowConfig` PDA でローンチを制限することもでき、移行ビルダーは両方の CPMM サポートミント PDA を追加する必要があります。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM: 制限発行者ポジション NFT フリーズ">
  新しい CLMM ポジション NFT ミントはプールをフリーズ権限として使用しますが、トークンアカウントはデフォルトではフリーズされたままです。フリーズは `OpenPositionV2` または `OpenPositionWithToken22Nft` でのみ発生し、基礎となるボルトミントのいずれかのフリーズ権限が制限発行者リストと一致する場合です。一致するポジションは転送または所有者変更はできませんが、流動性を管理することはできます。その `ClosePosition` 呼び出しはプールを追加する必要があり、CLMM はアトミックにフリーズ解除、バーン、クローズできます。既存のポジションは変更されません。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM: パーミッションレスクリエイターフィー収集">
  追加の `CollectCreatorFeePermissionless` 命令により、任意の支払人がすべての蓄積されたクリエイターフィーをスイープできますが、受益者と両方のトークン宛先を `PoolState.pool_creator` とクリエイターの正規 ATA に制限します。元のクリエイター署名パスは変更されません。`CreatePermissionPda` は専用の付与権限も受け入れますが、`ClosePermissionPda` は管理者のみのままです。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM: パーミッション付きマルチプールとリミットオーダーフリーズアカウントガード">
  2 つの追加の後方互換性のある CLMM プログラム更新。`CreatePermissionedPool` はクライアント提供の 0 以外の `seed_index` をプール PDA シードに折り込み、ホワイトリストに登録されたオペレーター（`Permission` PDA を保有している）が `(config, mint0, mint1)` ごとに複数のプールを作成できるようにします。これにより、プール ID はペアの正規ではなくなります。新しい管理命令 `CreatePermissionPda` / `ClosePermissionPda` はそれらの付与を管理し、`PoolState` は `seed_index` フィールドを取得します（パディングから削られ、サイズ変更なし）。別に、`OpenLimitOrder` は出力側アカウントを取得し、入力または出力トークンアカウントがフリーズされている注文を拒否します（`NotApproved`）。

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-22-amm-v4-openbook-removal)

## ドキュメンテーション規約

- **バージョニング**: このドキュメンテーションはカレンダーベースのバージョニング（YYYY-MM-DD）を使用します。各更新は新しいエントリページを追加し、上記のタイムラインに新しい行を追加します。
- **リリースごとに 1 ページ**: すべてのリリース概要は `reference/changelog/` の下の独自のページに存在するため、このインデックスは短く保たれ、各エントリは独立してリンク可能です。
- **検証日**: すべてのエントリは、コンテンツがオンチェーン / API 状態とプログラムソースに対して最後にクロスチェックされた時期を記録します。記載されていない場合は、エントリのメイン日付を想定してください。
- **破壊的変更**: 影響を受けるページのボックス化された警告で呼び出され、エントリでタグ付けされます。
- **カバレッジ**: この変更履歴はドキュメンテーションセット自体をカバーしています。プロトコル自体の歴史的タイムラインは [`introduction/history-and-milestones`](/ja/introduction/history-and-milestones) に存在し、「Raydium で X が発生したのはいつか」の真実の情報源です。
