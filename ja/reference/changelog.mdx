## リリース

<Update label="2026-08-24" description="LaunchLab: Token-2022 クォートミント">
  ローンチは Token-2022 ミントでクォートできるようになりました。`CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、4 つのスワップ命令、およびすべてのフィー請求は、クォートプログラムスロットで両方のトークンプログラムを受け入れます。非推奨の `Initialize` はレガシーのみのままです。スワップスリッページ境界は、支払者が実際に支払うまたは受け取る金額と比較されるようになり、クォートミントの転送フィーを差し引いた額になります。`PoolState.token_program_flag` ビット 1 が意味を持つようになったため、バイト全体を `0` に対してテストするデコーダーはレガシーベースミントを Token-2022 として誤読します。`MigrateToCpswap` は 2 つのトークンプログラムアカウントを `token_program` / `token_program_2022` に名前変更し、`6023` は `CalculateOverflow` に再利用されます。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab: CPMM のみのローンチとプラットフォーム設定コントロール">
  新しいローンチ初期化は CPMM を必須とし、レガシー AMM v4 バウンド状態は移行可能なままです。このリリース前は、`creator_scale` はクリエイター所有のフィーキーを生成していました。アップグレード後に実行される CPMM 移行は、代わりに `platform_scale + creator_scale` を 1 つのプラットフォーム所有のフィーキーシェアに統合します。プラットフォームは独自の `PlatformAllowConfig` PDA でローンチを制限することもでき、移行ビルダーは両方の CPMM サポートミント PDA を追加する必要があります。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM: 制限発行者ポジション NFT フリーズ">
  新しい CLMM ポジション NFT ミントはプールをフリーズ権限として使用しますが、トークンアカウントはデフォルトではフリーズされません。フリーズは `OpenPositionV2` または `OpenPositionWithToken22Nft` でのみ発生し、基礎となるボールトミントのいずれかのフリーズ権限が制限発行者リストと一致する場合です。一致するポジションは転送または所有者変更はできませんが、流動性管理は引き続き可能です。その `ClosePosition` 呼び出しはプールを追加する必要があり、CLMM はアトミックにフリーズ解除、バーン、クローズできます。既存のポジションは変更されません。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM: パーミッションレスクリエイターフィー収集">
  追加の `CollectCreatorFeePermissionless` 命令により、任意の支払者がすべての蓄積されたクリエイターフィーをスイープでき、受益者と両方のトークン宛先を `PoolState.pool_creator` とクリエイターの正規 ATA に制限します。元のクリエイター署名パスは変更されません。`CreatePermissionPda` は専用の付与権限も受け入れ、`ClosePermissionPda` は管理者のみのままです。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM: パーミッション付きマルチプールとリミットオーダーフリーズアカウントガード">
  2 つの追加で後方互換性のある CLMM プログラム更新。`CreatePermissionedPool` はクライアント提供の 0 以外の `seed_index` をプール PDA シードに折り込み、ホワイトリストに登録されたオペレーター（`Permission` PDA を保有している）が `(config, mint0, mint1)` ごとに複数のプールを作成できるようにします。これにより、プール ID はペアの正規ではなくなります。新しい管理命令 `CreatePermissionPda` / `ClosePermissionPda` はそれらの付与を管理し、`PoolState` は `seed_index` フィールドを取得します（パディングから削除、サイズ変更なし）。別途、`OpenLimitOrder` は出力側アカウントを取得し、入力または出力トークンアカウントがフリーズされている（`NotApproved`）オーダーを拒否するようになりました。

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4: OpenBook / Serum 依存関係の削除">
  AMM v4 は長く休止していた OpenBook/Serum 依存関係、すべてのオーダーブック CPI、および無効なマーケットメイキング命令を削除します。`SwapBaseIn` / `SwapBaseOut`、`Deposit`、`Withdraw` はレイアウトを保持します（削除されたマーケットアカウントは無視され、検証されません）。**ハード破壊** `WithdrawPnl`（17 → 10、互換性なし）と `SetParams`（アカウント削減 + `param` の番号変更）。`Initialize`、`PreInitialize`、`MonitorStep`、`MigrateToOpenBook`、`WithdrawSrm`、`SimulateInfo`、`AdminCancelOrders` は呼び出し不可になりました。オンチェーンアカウントレイアウトとエラーコードは安定したままです。スワップを V2 エントリポイントに移行してください。

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM: 無効な OpenBook（マーケット）コードの削除">

  [完全なエントリを読む →](/ja/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>

## ドキュメンテーション規約

- **バージョニング**：このドキュメンテーションはカレンダーベースのバージョニング（YYYY-MM-DD）を使用します。各更新は新しいエントリページを追加し、上記のタイムラインに新しい行を追加します。
- **リリースごとに 1 ページ**：すべてのリリース概要は `reference/changelog/` の下の独自のページに存在するため、このインデックスは短く保たれ、各エントリは独立してリンク可能です。
- **検証日**：すべてのエントリは、コンテンツがオンチェーン / API 状態とプログラムソースに対して最後に相互チェックされた時期を記録します。記載されていない場合は、エントリのメイン日付を想定してください。
- **破壊的変更**：影響を受けるページのボックス化された警告で呼び出され、エントリでタグ付けされます。
- **カバレッジ**：この変更履歴はドキュメンテーションセット自体をカバーしています。プロトコル自体の歴史的タイムラインは [`introduction/history-and-milestones`](/ja/introduction/history-and-milestones) に存在し、「Raydium で X が発生したのはいつか」の真実の源です。
