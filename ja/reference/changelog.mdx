## リリース

<Update label="2026-08-14" description="LaunchLab: CPMM専用ローンチとプラットフォーム設定コントロール">
  新しいローンチ初期化ではCPMMが必須になり、レガシーAMM v4バウンド状態は移行可能なままです。このリリース前は、`creator_scale`はクリエイター所有のFee Keyを生成していました。アップグレード後に実行されるCPMM移行では、`platform_scale + creator_scale`を1つのプラットフォーム所有のFee Keyシェアに統合します。プラットフォームは独自の`PlatformAllowConfig` PDAでローンチを制限することもでき、移行ビルダーはCPMMサポートミントPDAの両方を追加する必要があります。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-14-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-14" description="CLMM: 制限付き発行者ポジションNFTフリーズ">
  新しいCLMMポジションNFTミントはプールをフリーズ権限として使用しますが、トークンアカウントはデフォルトではフリーズされません。フリーズは`OpenPositionV2`または`OpenPositionWithToken22Nft`でのみ発生し、基礎となるボルトミントのいずれかのフリーズ権限が制限付き発行者リストと一致する場合です。一致するポジションは転送または所有者変更はできませんが、流動性の管理は可能です。その`ClosePosition`呼び出しはプールを追加する必要があり、CLMMは解凍、バーン、クローズをアトミックに実行できます。既存のポジションは変更されません。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-14-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-14" description="CPMM: パーミッションレスクリエイターフィー収集">
  追加の`CollectCreatorFeePermissionless`命令により、任意のペイヤーがすべての蓄積されたクリエイターフィーをスイープできます。受益者と両方のトークン宛先を`PoolState.pool_creator`とクリエイターの正規ATAに制限します。元のクリエイター署名パスは変更されません。`CreatePermissionPda`は専用の付与権限も受け入れ、`ClosePermissionPda`は管理者のみです。

  [完全なエントリを読む →](/ja/reference/changelog/2026-08-14-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM: パーミッション付きマルチプールとリミットオーダーフリーズアカウントガード">
  2つの追加的で後方互換性のあるCLMMプログラム更新。`CreatePermissionedPool`はクライアント提供の非ゼロ`seed_index`をプールPDAシードに折り込み、ホワイトリストに登録されたオペレーター（`Permission` PDAを保有する）が`(config, mint0, mint1)`ごとに複数のプールを作成できるようにします。これにより、プールIDはペアの正規ではなくなります。新しい管理命令`CreatePermissionPda` / `ClosePermissionPda`はそれらの付与を管理し、`PoolState`は`seed_index`フィールドを取得します（パディングから削除、サイズ変更なし）。別途、`OpenLimitOrder`は出力側アカウントを取得し、入力または出力トークンアカウントがフリーズされている（`NotApproved`）オーダーを拒否します。

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4: OpenBook / Serum依存関係の削除">
  AMM v4は長く休止していたOpenBook/Serum依存関係、すべてのオーダーブックCPI、および廃止されたマーケットメイキング命令を削除します。`SwapBaseIn` / `SwapBaseOut`、`Deposit`、`Withdraw`はレイアウトを保持します（削除されたマーケットアカウントは検証されず無視されます）。**ハード破壊的な**`WithdrawPnl`（17 → 10、互換性なし）と`SetParams`（アカウント削減 + `param`の番号付け直し）。`Initialize`、`PreInitialize`、`MonitorStep`、`MigrateToOpenBook`、`WithdrawSrm`、`SimulateInfo`、`AdminCancelOrders`は呼び出し不可になります。オンチェーンアカウントレイアウトとエラーコードは安定したままです。スワップをV2エントリポイントに移行してください。

  [完全なエントリを読む →](/ja/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM: 廃止されたOpenBook（マーケット）コードの削除">

  [完全なエントリを読む →](/ja/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>

## ドキュメンテーション規約

- **バージョニング**: このドキュメンテーションはカレンダーベースのバージョニング（YYYY-MM-DD）を使用します。各更新は新しいエントリページを追加し、上記のタイムラインに新しい行を追加します。
- **リリースごとに1ページ**: すべてのリリースサマリーは`reference/changelog/`の下の独自のページに存在するため、このインデックスは短く保たれ、各エントリは独立してリンク可能です。
- **検証日**: すべてのエントリは、コンテンツが最後にオンチェーン / API状態とプログラムソースに対して相互チェックされた時期を記録します。記載されていない場合は、エントリのメイン日付を想定してください。
- **破壊的変更**: 影響を受けるページのボックス警告で呼び出され、エントリでタグ付けされます。
- **カバレッジ**: この変更履歴はドキュメンテーションセット自体をカバーしています。プロトコル自体の歴史的タイムラインは[`introduction/history-and-milestones`](/ja/introduction/history-and-milestones)に存在し、「Raydiumで何がいつ起こったのか」の信頼できる情報源です。
