このリリースは、選定された KYC 制限発行者プールに対する条件付き非転送可能パスを追加します。すべての新しいポジションをフリーズしたり、プール資産をフリーズしたり、ポジション所有者がリクイディティを管理することを防いだりするものではありません。CLMM プール PDA はすべての新しいポジション NFT ミントのフリーズ権限になりますが、NFT トークンアカウントはデフォルトではフリーズされません。プログラムは、ポジションが `OpenPositionV2` または `OpenPositionWithToken22Nft` を使用し、かつ基礎となるボルトミントのいずれかがハードコードされた制限発行者リストからのフリーズ権限を持つ場合にのみ、それをフリーズします。

## インテグレーター向け TL;DR

- **新しいポジション NFT ミントはフリーズ権限を持ちますが、デフォルトではフリーズされません。** `OpenPosition`、`OpenPositionV2`、`OpenPositionWithToken22Nft` はポジションの `pool_state` をミントフリーズ権限として設定します。ミント権限は単一の NFT がミントされた後も削除されます。
- **フリーズには V2 パスと発行者マッチが必要です。** `OpenPositionV2` と `OpenPositionWithToken22Nft` は `vault_0_mint.freeze_authority` と `vault_1_mint.freeze_authority` を検査します。新しい NFT アカウントは、少なくとも 1 つがプログラムリストと一致する場合にのみフリーズされます。マッチがない場合、それはフリーズされたままで転送可能です。
- **フリーズは所有者にバインドされることを意味します。** SPL Token は、ネイティブ `AccountFrozen` エラーで NFT 転送とトークンアカウント所有者の変更を拒否します。NFT 所有者が署名する場合、リクイディティの増加・減少とフィー・報酬の収集は引き続き機能します。
- **クローズは利用可能なままです。** `ClosePosition` はフリーズされた NFT アカウントを検出し、プール PDA を使用してそれをシャーすると、NFT をバーンしてポジションをアトミックに閉じます。
- **フリーズされたクローズには 1 つの残りアカウントが必要です。** クライアントは `personal_position.pool_id` を最初の残りアカウントとして追加する必要があります。それがない場合は CLMM `AccountLack` を返します。間違ったプールを渡すと `NotApproved` を返します。
- **既存のポジションは影響を受けません。** このアップデートは、NFT ミント権限を遡及的に変更したり、既存のトークンアカウントをフリーズしたりしません。
- **CLMM 状態レイアウトまたは宣言された IDL アカウントリストの変更はありません。** `PoolState`、`PersonalPositionState`、命令引数はバイト互換のままです。クローズパス要件は `remaining_accounts` を通じて実行されます。

## トリガーロジック

プログラムはオープン時に 2 つのボルトミントを評価します：

```rust
must_freeze = restricted_ids.contains(vault_0_mint.freeze_authority)
           || restricted_ids.contains(vault_1_mint.freeze_authority)
```

フリーズ権限がない場合はマッチしません。一方の側がマッチすれば十分です。初期リストには、CLMM の Superstate アセット検出で使用される同じ発行者権限が含まれています。現在の mainnet-beta と devnet マッチキーは [`reference/program-addresses`](/ja/reference/program-addresses#clmm-restricted-issuer-freeze-authorities) にあります。

チェックは、ボルトミントアカウントが提供される場合にのみ、共有オープンポジションハンドラーで実行されます。これは以下を意味します：

| オープンパス | ポジション NFT プログラム | 制限発行者フリーズ動作 |
|-----------|----------------------|-----------------------------------|
| `OpenPosition` V1 | SPL Token | フリーズしません。V1 は出荷されたリストでターゲットにされた Token-2022 発行者アセットを提供できません。 |
| `OpenPositionV2` | SPL Token | 両方のボルトミントを検査し、マッチ時にフリーズします。 |
| `OpenPositionWithToken22Nft` | Token-2022 | 両方のボルトミントを検査し、マッチ時にフリーズします。 |

## ポジション NFT 権限の変更

このアップデート前は、新しく作成されたクラシック SPL ポジション NFT ミントはフリーズ権限を保持していませんでした。アップデート後、すべての新しいポジション NFT ミントは、通常のプール内のポジションを含め、そのプールをフリーズ権限として指定します。この権限設定だけでは NFT トークンアカウントをフリーズしません。通常のポジションとマッチしないポジションはフリーズされたままです。

グローバル管理者または発行者キーの代わりにプール PDA を使用すると、権限を 1 つのプールに限定します。外部パーティは PDA として署名できず、CLMM は任意のポジションアカウントをフリーズまたはシャーするための汎用命令を公開していません。新しいコードは権限を 2 つの場所でのみ使用します：

1. 基礎となる発行者チェックがマッチする場合、ミント直後にフリーズします。
2. バーン直前の `ClosePosition` 中にシャーします。

## `ClosePosition` マイグレーション

6 つの宣言されたアカウントは変わりません。フリーズされた NFT の場合、プールを最初の残りアカウントとして追加します：

```text
declared: nft_owner, position_nft_mint, position_nft_account,
          personal_position, system_program, token_program
remaining[0]: personal_position.pool_id   // read-only, non-signer
```

ハンドラーは `PoolState` をロードする前にキーを検証し、プール署名者シードを導出し、以下を実行します：

```text
NFT アカウントをシャー → NFT をバーン → NFT トークンアカウント / ポジション状態をクローズ
```

すべてのステップは 1 つの Solana 命令で実行されるため、一緒にコミットまたはロールバックされます。すべてのクローズでプールを渡すことは安全です。ハンドラーは NFT アカウントがフリーズされていない場合、残りアカウントを無視します。

<Warning>
  **条件付きクライアント破損。** 古いクライアントはアップグレード後にポジションを正常にオープンできます。これは V2 オープンアカウントレイアウトが変わらないためです。そのポジションがフリーズされている場合、同じクライアントは後でそれをクローズできない可能性があります。これは `ClosePosition` ビルダーがプール残りアカウントを省略するためです。影響を受けるプール内でポジションをオープンすることをユーザーに許可する前に、クローズビルダーを更新してください。
</Warning>
