## `CollectExcessLamports`

[SIMD-0437](/ja/solana-fundamentals/rent-and-reclaimable-rent)のステップ1は2026年9月3日にメインネットで有効化されました。ステップ前に作成されたすべてのCLMMアカウントは現在過剰資金化されており、CLMMプログラムのみがそれが所有するアカウントからラムポートを移動できます。これはプールボルト、報酬ボルト、`PoolState`、`AmmConfig`、`ObservationState`、`TickArrayBitmapExtension`などをカバーします。

命令は4つの固定アカウントを取り、その後`remaining_accounts`に任意の数のソースアカウントを取ります：

| # | アカウント | 役割 |
|---|---|---|
| 1 | `collect_lamports_wallet` (W, S) | 署名者と宛先。共有プログラム管理者または専用CLMM回収ラムポートウォレットである必要があります。そうでない場合、呼び出しは`NotApproved`（`6000`）で失敗します。 |
| 2 | `pool_state` (W) | PDAシードを通じてトークンプログラムCPIに署名し、常に自身もスイープされます。 |
| 3 | `token_program` | SPLトークン。 |
| 4 | `token_program_2022` | Token-2022。両方が必須です。プログラムはソースアカウントごとに1つを選択します。 |

**プールは署名権限であり、プログラム全体のPDAではありません。** CPMMは1つのグローバル`vault_and_lp_mint_auth_seed`権限で署名します。CLMMトークンボルトはそれらの`PoolState`によって所有されるため、単一の呼び出しはスロット2で渡されたプールに対してのみ署名できます。各トークンプログラムソースはそのプールを権限として持つ必要があります：`token_vault_0`、`token_vault_1`、またはプールの報酬ボルトの1つ。別のプールからのトークンアカウント、またはユーザーのトークンアカウントはトークンプログラムの所有者チェックに失敗し、命令全体を元に戻します。プログラムはそれをスキップしません。ポジションNFTミントもスイープできません。ポジションが開かれるとミント権限が取り消されるためです。プールごとにスイープしてください。

命令は2つのパスを実行し、その順序は固定されています：

1. **トークンプログラムCPIが最初。** SPLトークンまたはToken-2022によって所有されるすべてのソースについて、ネイティブ以外のアカウントは`WithdrawExcessLamports`（判別式`38`）を取得します。ネイティブwSOLボルトは`SyncNative` → `UnwrapLamports`（判別式`45`）ラウンドトリップを取得し、ラップされたバランスが同期前の値と等しいことを確認して終了します。そうでない場合、呼び出しは`LamportsCalculateError`で失敗します。**SOL側ボルトは完全なリクイディティを保持し**、スイープ全体でスワップクォートは変わりません。
2. **直接デビットが2番目。** パス2は`pool_state`を最初にデビットし、その後CLMMプログラムによって所有されるすべてのソースを`rent.minimum_balance(data_len)`までデビットします。

他のプログラムによって所有されるソースは静かにスキップされます。この2パス順序はCPMMが[2026-09-19](/ja/reference/changelog/2026-09-19-cpmm-creator-fee-protocol-share)で採用したものです。CLMMはその最初のリリースからこれを持っています。PDAがCPIの前にデビットされた場合、ランタイムは`UnbalancedInstruction`で中止するため、呼び出し元は任意の順序でソースを渡すことができます。

<Warning>
  **プログラム所有パスは、アカウントがどのプールまたはユーザーに属しているかをチェックしません。** CLMMプログラムによって所有されるすべてのアカウントが対象です。ユーザーがレントを支払った一部を含む：`PersonalPositionState`、`LimitOrderState`、`TickArrayState`。レント免除最小値を超える余剰のみが移動します。アカウントはそのデータを保持し、レント免除のままです。ポジションまたはオーダーが後で閉じられるとき、プログラムはアカウントがその時点で保持しているバランスをリファンドします。スイープ後、そのバランスは現在のレント最小値です。
</Warning>

ウォレットアドレスは[`reference/program-addresses`](/ja/reference/program-addresses#excess-lamports-collection-wallets)にリストされています。

## `CreateAmmConfig`は固定フィーオーナーを書き込みます

このリリース前、`create_amm_config`は両方のフィーオーナーフィールドを呼び出し署名者から設定していました：

```rust
amm_config.owner      = ctx.accounts.owner.key();
amm_config.fund_owner = ctx.accounts.owner.key();
```

現在はプログラム自身の定数を書き込みます：

```rust
amm_config.owner      = crate::protocol_fee_owner::ID;
amm_config.fund_owner = crate::fund_fee_owner::ID;
```

`CreateAmmConfig`は依然として`crate::admin::ID`にゲートされています。このリリース前、すべての新しいフィーティアは両方のフィールドに管理者で開始され、`UpdateAmmConfig`パラメータ`3` / `4`で回転する必要がありました。現在は運用ウォレットで開始されます。メインネットでは定数は既存の21個すべての設定に既に`owner` / `fund_owner`として保存されている同じキーです。プログラムは現在、運用が手動で設定するために使用した値を書き込みます。

回収署名者は変わりません。`CollectProtocolFee`は`amm_config.owner`**または**`crate::admin::ID`を受け入れ、`CollectFundFee`は`amm_config.fund_owner`**または**`crate::admin::ID`を受け入れます。このリリースの前後両方です。

デブネットでは、両方の定数は同じキーに解決されます。[`reference/program-addresses`](/ja/reference/program-addresses#clmm-fee-owner-wallets)を参照してください。

<Warning>
  **これはマイグレーションではありません。** すべての既存の`AmmConfig`は既に持っている`owner`と`fund_owner`を保持します。定数または管理者キーをハードコードするのではなく、フィールドを読み取ってください。
</Warning>

オンチェーン効果のないビルドシステムの詳細：

- **ローカルネット管理者。** `localnet`フィーチャーはコミットされたフィクスチャによってサポートされた固定テストキーをコンパイルしなくなります。代わりに、ビルド時に`CLMM_LOCALNET_ADMIN`環境変数から管理者を読み取ります。これは`yarn test:local-admin`がローカルウォレットから設定します。フィクスチャの`.gitignore`例外は削除されました。

- **Anchor.toml。** `seeds = false`は`resolution = true`プラス`skip-lint = false`になり、古い`[registry]` URLが削除されます。
- **リント。** `programs/amm/Cargo.toml`は、AnchorおよびSolanaマクロが出力するフィーチャcfgの`[lints.rust] unexpected_cfgs`許可リストを追加します。
- **README。** このブランチではREADMEは`coral-xyz/anchor`から`rustup default 1.86.0`と`avm install 0.32.1`を実行するよう指示しています。代わりに`Anchor.toml`と[`solana-fundamentals/toolchain`](/ja/solana-fundamentals/toolchain)に従ってください。
