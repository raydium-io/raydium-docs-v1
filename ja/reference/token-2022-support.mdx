Raydium は任意の Token-2022 ミントを受け入れません。CPMM と CLMM の両方は厳密な**許可リストモード**で動作します。デフォルトでは限定的な拡張機能セットのみが通過し、その他はすべてプール作成時に拒否されます。ハードコードされたアドレスで信頼できるミントが少数許可されており、CLMM はさらに管理者が管理するミント単位のレジストリと実行時の Superstate トークン検出をサポートしています。このページは、何が実施されているか、どこで実施されているかについての単一ページリファレンスで、プログラムソースへのファイルと行の引用が含まれています。

## プログラムレベルのサポート

| プログラム | Token-2022 ベース/クォートミント？ | モード |
|---|---|---|
| **CPMM** | はい — ゲート付き | 厳密な拡張機能許可リスト + 4 ミント静的許可リスト。 |
| **CLMM** | はい — ゲート付き | 厳密な拡張機能許可リスト + 6 ミント静的許可リスト + 管理者ミント単位レジストリ + Superstate 検出。 |
| **AMM v4** | いいえ | プログラムは Token-2022 より前のもの。両方のミントは従来の SPL Token である必要があります。 |
| **Stable AMM** | いいえ | AMM v4 と同じ制約。 |
| **Farm v6** | はい、部分的 | リワードミントは Token-2022 にできます（ファームが CPMM/CLMM LP をラップする場合、同じ許可リストの対象）。ユーザーステーク LP ミントはラップされたプールから継承します。 |
| **LaunchLab** | はい — ベースはプログラム管理、クォートはゲートなし | ベースミントは Token-2022 にできますが、専用の `initialize_with_token_2022` 命令を通じてのみ。プログラム自体は `MetadataPointer`（常に）とオプションで `TransferFeeConfig`（レート ≤ 5%）を使用してミントを作成します。任意の拡張機能を持つ既存の Token-2022 ミントはベースとして使用できません。**クォート**ミントは、管理者が `GlobalConfig` にバインドする任意の Token-2022 ミントにできます。拡張機能チェックはありません — [下記](#launchlab-quote-mints)を参照してください。 |
| **Burn & Earn** | プールプログラムをミラー | CPMM / CLMM ゲートを継承します。 |

許可リストチェックは以下の場所にあります：

- **CPMM**: [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap) の `is_supported_mint`、`Initialize` から呼び出し。

CPMM または CLMM にはスワップ時のミントチェックはありません — ゲートはプール作成時にのみ発火します。プールが存在すると、スワップは単にミントが変更されなかったことを信頼します。これは Token-2022 ミント状態の不変部分に対して正しいです。

## 制限付き発行者向けの CLMM ポジション NFT フリーズ

ポジション NFT アカウントはデフォルトではフリーズされません。CLMM は、ポジションが V2 オープンパスを使用**し、かつ**少なくとも 1 つのボルトミントの現在の `freeze_authority` がハードコードされた制限付き発行者リストと一致する場合にのみフリーズします。初期リストには、下記の Superstate 検出パスで使用される同じ権限が含まれています。プール PDA をポジション NFT ミントのフリーズ権限として設定することは、それ自体はフリーズではありません。これはプール作成許可リストではなく、ポジション保管ルールです：

- プールは既に存在でき、スワップ可能なままです。
- ポジション NFT ミントは CLMM プール PDA を独自のフリーズ権限として使用します。基礎となる発行者はポジション NFT を制御しません。
- `OpenPositionV2` は Token-2022 プール資産上の従来の SPL ポジション NFT をカバーします。`OpenPositionWithToken22Nft` は Token-2022 ポジション NFT をカバーします。
- `OpenPosition` V1 はボルトミントを検査せず、配布されたリストが対象とする Token-2022 制限資産に対応できません。
- 既存のポジションは変更されません。

フリーズされたポジションは所有者によって管理可能なままですが、転送できません。`ClosePosition` はクライアントが最初の残りアカウントとしてプールを渡すときに、アトミックにフリーズを解除して焼却します。[`products/clmm/ticks-and-positions`](/ja/products/clmm/ticks-and-positions#restricted-issuer-positions) を参照してください。

## LaunchLab クォートミント

LaunchLab の 2 つのミントは非常に異なる方法でゲートされており、非対称性は見落としやすいです。

- **ベースミント** — LaunchLab が作成します。Token-2022 ベースミントは `initialize_with_token_2022` を通じてのみ到達可能で、プログラムは `MetadataPointer` と（オプションで）`TransferFeeConfig` のみをアタッチします。その他は `NoSupportExtension` を返します。既存の Token-2022 ミントはベースとしてまったく供給できません。
- **クォートミント** — LaunchLab は作成せず、スクリーニングもしません。`CreateConfig` はミントアカウントをそのまま受け入れるため、**クォート側に `is_supported_mint` 相当のものはありません**。唯一のゲートは、管理者が `GlobalConfig` にバインドすることを選択するミントです。

これにより、Token-2022 クォートミントのバインドは高信頼アクションになります。理由は CPMM と CLMM 静的許可リストと同じです：`TransferHook` クォートミントはそれで引用されるすべてのプールのすべての買い、売り、手数料請求で独自のフックを実行し、`PermanentDelegate` クォートミントはデリゲートがそれらのプールのクォートボルトをスイープできるようにします。どちらもプログラムによってブロックされません。

クォートミントがバインドされると、LaunchLab が正しく処理するもの：

- クォートボルト、両方の手数料ボルト、およびシェア手数料受信者のトークンアカウントは、クォートミント独自のプログラムで作成されます。
- クォート側の `TransferFeeConfig` は 4 つのすべてのトレード命令に価格設定され、スリッページバウンドはボルトの総移動ではなく支払者の純額に対してチェックされます。[`products/launchlab/instructions`](/ja/products/launchlab/instructions#quote-side-transfer-fees) を参照してください。
- `PoolState.token_program_flag` は両方のミントのプログラムを記録します — ベースミント用の bit0、クォートミント用の bit1。ビットごとにデコードします。バイトはブール値ではありません。[`products/launchlab/accounts`](/ja/products/launchlab/accounts#poolstate) を参照してください。

非推奨の `Initialize` 命令は依然としてレガシーのみのクォートプログラムを取得するため、Token-2022 クォートミントを持つ設定は `InitializeV2` と `InitializeWithToken2022` を通じてのみ到達可能です。

## CPMM と CLMM 拡張機能許可リスト

静的許可リストショートサーキット（下記で説明）の後、プログラムはミントの拡張機能を反復処理し、これら 5 つ以外の**任意の**拡張機能を持つ場合、ミントを拒否します：

| 拡張機能 | 許可される理由 |
|---|---|
| `TransferFeeConfig` | プール数学は受信手数料を差し引きます。Token-2022 プログラムは送信手数料を処理します。[`algorithms/token-2022-transfer-fees`](/ja/algorithms/token-2022-transfer-fees) を参照してください。 |
| `MetadataPointer` | 装飾的 — オンチェーンメタデータを指します。 |
| `TokenMetadata` | 装飾的 — インラインメタデータ。 |
| `InterestBearingConfig` | プールは元本を見ます。UI 乗数は装飾のみで、基礎となる残高は保持されます。 |
| `ScaledUiAmount` | 利息ベアリングと同じ形状 — スケール係数は UI 表示にのみ適用されます。 |

このリストにないもの — `TransferHook`、`NonTransferable`、`ConfidentialTransferMint`、`PermanentDelegate`、`MintCloseAuthority`、`DefaultAccountState`、`GroupPointer`、`GroupMemberPointer`、`MemberPointer`、`Pausable` など — は `is_supported_mint` が `false` を返し、プール作成がリバートします。

関連する行（CPMM、CLMM で同じ形状）：

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## バイパスパス

許可リストに適合しない Token-2022 ミントは、3 つの明示的なバイパスの 1 つを通じて許可できます。拡張機能反復が実行される前に、順番に試行されます。

### 1. 静的ミント許可リスト

定数 `MINT_WHITELIST` 配列の base58 文字列が各プログラムにハードコードされています。ミントのアドレスが一致する場合、関数は `true` を直ちに返し、拡張機能チェックは実行されません。

| CLMM | 同じ 4 つ、プラス `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`、`AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

これらのアドレスはプログラムに焼き込まれています。リストを更新するには、3/4 アップグレードマルチシグを通じたプログラムアップグレードが必要です。

### 2. ミント単位レジストリ — CLMM のみ

CLMM はさらに、シード `[b"support_mint", mint]` で `SupportMintAssociated` PDA を参照します。そのミント用の PDA が存在する場合、その拡張機能セットに関係なく許可されます。

PDA は `CreateSupportMintAssociated`（[`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)）によって作成されます。命令は 2 つの署名者にゲートされています：

- `crate::admin::ID` — 標準 Raydium 管理者権限。
- `crate::create_support_mint_associated_owner::ID` — この目的専用の権限：`RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY`（メインネット）、`rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5`（デブネット）。

効果：CLMM チームはプログラムアップグレードなしで特定の Token-2022 ミントをプール作成にオプトインできます。CPMM には相当するものがありません — その許可リストは厳密にソースコード化されています。

### 3. Superstate 検出 — CLMM のみ

CLMM には、CLMM プログラムにリンクされた `spl-token-2022` のバージョンがアンパックできない `ScaledUiConfig` 拡張機能を使用する Superstate のトークン化資産専用の 3 番目のパスがあります。依存関係をアップグレードするのではなく、CLMM は権限形状で Superstate トークンを検出します：

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

ミントは**すべて 4 つ**が成立する場合、このブランチを通過します：

- その所有プログラムは Token-2022 プログラムです。
- そのフリーズ権限は `superstate_allowlist::ID` と等しい。メインネット-ベータとデブネット値については [`reference/program-addresses`](/ja/reference/program-addresses#clmm-restricted-issuer-freeze-authorities) を参照してください。
- その `DefaultAccountState` 拡張機能は `Frozen` に設定されています。
- その永続デリゲートも `superstate_allowlist::ID` です。

これはレジストリではなくヒューリスティックです — Superstate が同じ権限形状で発行する将来のミントは自動的に許可されます。

## バイパスが放棄しないもの

バイパスは拡張機能許可リストをスキップしますが、プログラムは依然として以下を実施します：

- ミントは `Token` または `Token-2022` のいずれかで所有されています。カスタムトークンプログラムは上流で拒否されます。
- プールボルトは Token-2022 プール用の正しい ATA 拡張機能（`ImmutableOwner` など）で作成されます。
- すべての転送は `transfer_checked` を通じて行われます — 手数料ベアリングミントはボルトに正しい金額を着地させます。

ホワイトリストまたは PDA 登録ミントが、例えば後で `TransferHook` を追加する場合、スワップ時チェックを取得しません。フックは単にすべての転送で実行され、スワップをブリックする可能性があります。したがって、ホワイトリストは高信頼アクションです。

## 「ブロック」セマンティクス

`is_supported_mint` が `false` を返すと、プール作成は `ErrorCode::NotSupportMint`（CPMM）/ `ErrorCode::NotSupportMint`（CLMM）でリバートします。数値コードについては [`reference/error-codes`](/ja/reference/error-codes) を参照してください。

既存のプールはこのチェックに遡及的に失敗することはできません — ゲートは作成時にのみ実行されます。ミント拡張機能は Raydium が拒否するカテゴリに対して不変です（転送フック、非転送可能、機密転送は作成後に追加できません）。したがって、静的チェックで十分です。

## 除外された各拡張機能が除外される理由

- **TransferHook** — すべての転送でカスタムプログラムを呼び出し、任意の CU 消費、任意の失敗条件、呼び出しプログラムに再入する能力があります。安全なサンドボックスは存在しません。一部の DEX はフック許可リストを維持しています。Raydium はそうしません。
- **NonTransferable** — `Transfer` は常に失敗します。プールは保管を取得できません。
- **ConfidentialTransfer** — 転送額は暗号化されています。曲線はスワップを価格設定できません。
- **PermanentDelegate** — デリゲートの保有者はプールボルトを含む任意のトークンアカウントをスイープできます。静的許可リストを通じてのみ信頼できる発行者（例：規制されたステーブルコイン）に許可されます。
- **MintCloseAuthority** — ミントを閉じることができます。既存のプールは使用不可になります。デフォルトで許可されません。
- **DefaultAccountState (Frozen)** — プール ATA は `Frozen` 状態で着地し、アカウントごとにフリーズを解除する必要があります。Superstate 検出を通じてのみ許可されます。これは発行者が登録時に機関アカウントをフリーズ解除することを前提としています。
- **グループ/メンバーポインタ** — 積極的に有害ではありませんが、未レビューです。表面を狭く保つためにデフォルトで許可されません。

## 転送手数料会計

`TransferFeeConfig` を持つミントの場合、すべてのスワップ、デポジット、および引き出しは名目額より少なく移動します。SDK は計算の両方の半分を表示します：

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

正しい UI は以下を表示します：

- `amountIn + token2022FeeIn` を「送信」として
- `amountOut - token2022FeeOut` を「受け取り」として
- `feeAmount` をプール手数料（LP + プロトコル）として。これは Token-2022 転送手数料とは別です

`amountIn → amountOut` のみを表示する素朴な UI はコストを過小評価します。

### `maximumFee` キャップ

Token-2022 転送手数料は転送ごとにキャップされます。1% ミントで 10,000 トークンキャップの場合、100,000,000 トークン転送は手数料で 10,000 のみを支払います。SDK の `computeSwapAmount` はキャップを適用します。直接プログラム呼び出し元はそれを複製する必要があります。

### エポック遷移

ミント権限は次のエポックで有効になる手数料レート変更をスケジュールできます。遷移ウィンドウ中、2 つの設定（`older`、`newer`）がミント上に同時に存在し、`TransferChecked` は現在のエポックで選択します。CPMM `SwapV2` と CLMM `SwapV2` の両方は `accounts` で完全なミントアカウントを渡すため、プログラムは追加ルックアップなしで正しい設定を読み取ります。

Trade API または SDK を通じて 1 エポック以上先に引用する場合、実行された手数料は引用された手数料と異なる可能性があります — 古い設定の `maximum_fee_basis_points` によってバウンドされます。

## 利息ベアリングと ScaledUiAmount

プールは元本を保有します。「UI 金額」は元本に時間依存またはアドミン設定スケール係数を乗じたものです。スワップ数学は元本で動作します：

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK は自動的に変換します。直接 RPC リーダーは `pool.token0Vault.amount` を元本として扱うべきです。

## 「Token-2022 プール」定義

プールは、**いずれかの**ミントが `programId == TokenzQdB...` を持つ場合、Token-2022 プールです。API はこれを表示します：

## SDK ヘルパー

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## 一般的な統合ミス

- **プログラム ID のみをプリフライトする。** ミントは Token-2022 *かつ*サポートされていない可能性があります。許可リスト（および静的許可リスト）に対して拡張機能リストを確認してから、プール作成を許可します。
- **ミントがまったく受け入れられていない場合、SDK の引用を信頼する。** 引用 API は引用を拒否しません — プール作成がリバートするものです。UI でプール作成を公開する前に、オフチェーンで `is_supported_mint` セマンティクスを確認します。
- **転送手数料ヘアカットなしで引用する。** 0.25% CPMM プールの両側に 1% 転送手数料ミントがある場合、実効手数料は約 2.25% で、0.25% ではありません。SDK 引用または Trade API 引用を使用します — プール手数料層のみから手数料を手動で計算しないでください。
- **Token-2022 プールで従来の `Swap` 命令を呼び出す。** `Swap` は Token-2022 より前のものです。いずれかのミントが Token-2022 の場合は常に `SwapV2` を使用します。
- **新しい Token-2022 ミントを自動リストする。** ウォレットとアグリゲーターは、ミントをユーザーに表示する前に `TransferHook` と `NonTransferable` をチェックする必要があります。両方とも Raydium に敵対的です。
