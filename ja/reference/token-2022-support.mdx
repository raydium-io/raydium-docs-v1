Raydium は任意の Token-2022 ミントを受け入れません。CPMM と CLMM の両方は厳密な**許可リストモード**で動作します。デフォルトでは限定的な拡張機能セットのみが通過し、その他はすべてプール作成時に拒否されます。各プログラムは 1 つのメカニズム（管理者が管理するミント単位のレジストリ PDA）を通じて個別のミントを認めます。両プログラムは過去のさまざまなポイントでハードコードされた回避方法を持っていましたが、それらはすべて削除されました。このページは、何が実施されているか、どこで実施されているかについての単一ページのリファレンスで、プログラムソースへの引用が含まれています。

## プログラムレベルのサポート

| **CLMM** | はい — ゲート付き | 厳密な拡張機能許可リスト + 管理者ミント単位レジストリ。6 ミント静的ホワイトリストと Superstate 検出は 2026 年 7 月に削除されました。 |

| **LaunchLab** | はい — ベースはプログラム管理、クォートはゲートなし | ベースミントは Token-2022 にできますが、専用の `initialize_with_token_2022` 命令を通じてのみ。プログラムは `MetadataPointer`（常に）と、オプションで `TransferFeeConfig`（レート ≤ 5%）を使用してミントを作成します。任意の拡張機能を持つ既存の Token-2022 ミントはベースとして使用できません。**クォート**ミントは、管理者が `GlobalConfig` にバインドする任意の Token-2022 ミントにできます。拡張機能チェックはありません — [下記](#launchlab-クォートミント)を参照してください。 |

許可リストチェックは以下の場所にあります：

- **CPMM**: [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs) の `is_supported_mint`。`Initialize` と `InitializeWithPermission` から呼び出されます。
- **CLMM**: [`raydium-clmm/programs/amm/src/util/token.rs`](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/util/token.rs) の `is_supported_mint`。`CreatePool` から呼び出されます。

CPMM または CLMM にはスワップ時のミントチェックは**ありません** — ゲートはプール作成時にのみ発火します。プールが存在すると、スワップは単にミントが変更されていないことを信頼します。これは Token-2022 ミント状態の不変部分に対して正しいです。

## CLMM ポジション NFT 制限発行者のフリーズ

ポジション NFT アカウントはデフォルトではフリーズされません。CLMM は、ポジションが V2 オープンパスを使用**し、かつ**少なくとも 1 つのボールトミントの現在の `freeze_authority` がハードコードされた `frozen_position_nft_authorities::IDS` リストに表示される場合にのみフリーズします。このリストは CLMM の以前の Superstate トークン検出に置き換わったもので、古いヒューリスティックが一致した発行者権限と同じものを持ちます。プール PDA をポジション NFT ミントのフリーズ権限として設定することは、それ自体はフリーズではありません。これはプール作成許可リストではなく、ポジション保管ルールです：

- プールは既に存在でき、スワップ可能なままです。
- ポジション NFT ミントは CLMM プール PDA をそれ自身のフリーズ権限として使用します。基礎となる発行者はポジション NFT を制御しません。
- `OpenPositionV2` は Token-2022 プール資産上の従来の SPL ポジション NFT をカバーします。`OpenPositionWithToken22Nft` は Token-2022 ポジション NFT をカバーします。
- `OpenPosition` V1 はボールトミントを検査せず、配布されたリストが対象とする Token-2022 制限資産に対応できません。
- 既存のポジションは変更されません。

フリーズされたポジションは所有者によって管理可能なままですが、転送できません。`ClosePosition` はクライアントがプールを最初の残りアカウントとして渡すときに、アトミックにフリーズを解除して焼却します。[`products/clmm/ticks-and-positions`](/ja/products/clmm/ticks-and-positions#restricted-issuer-positions) を参照してください。

## LaunchLab クォートミント

LaunchLab の 2 つのミントは非常に異なる方法でゲートされており、非対称性は見落としやすいです。

- **ベースミント** — LaunchLab が作成します。Token-2022 ベースミントは `initialize_with_token_2022` を通じてのみ到達可能で、プログラムは `MetadataPointer` と（オプションで）`TransferFeeConfig` のみをアタッチします。その他は `NoSupportExtension` を返します。既存の Token-2022 ミントはベースとして供給できません。`TransferFeeConfig` がアタッチされると、ミントの `transfer_fee_config_authority` は卒業まで起動権限 PDA であり、その `withdraw_withheld_authority` はミント作成時からプラットフォームの設定された `transfer_fee_extension_auth` です — ローンチパッドプログラム自体には引き出し保留命令がありません。[`products/launchlab/platform-config`](/ja/products/launchlab/platform-config#token-2022-transfer-fee-authorities) を参照してください。
- **クォートミント** — LaunchLab は作成せず、スクリーニングもしません。`CreateConfig` はミントアカウントをそのまま受け入れるため、**クォート側に `is_supported_mint` 相当のものはありません**。唯一のゲートは、管理者が `GlobalConfig` にバインドすることを選択するミントです。

これにより、Token-2022 クォートミントをバインドすることは高信頼アクションになります。理由は以下のミント登録と同じです：`TransferHook` クォートミントはそれが引用されるすべてのプール内のすべての買い、売り、手数料請求でそのフックを実行し、`PermanentDelegate` クォートミントはデリゲートがそれらのプールのクォートボールトをスイープできるようにします。どちらもプログラムによってブロックされません。

LaunchLab がクォートミントがバインドされると正しく処理するもの：

- クォートボールト、両方の手数料ボールト、およびシェア手数料受信者のトークンアカウントはクォートミント自身のプログラムで作成されます。
- クォート側の `TransferFeeConfig` はすべての 4 つのトレード命令に価格設定され、スリッページ境界はボールトの総移動ではなく支払者の純額に対してチェックされます。[`products/launchlab/instructions`](/ja/products/launchlab/instructions#quote-side-transfer-fees) を参照してください。
- `PoolState.token_program_flag` は両方のミントのプログラムを記録します — ベースミント用の bit0、クォートミント用の bit1。ビットごとにデコードします。バイトはブール値ではありません。[`products/launchlab/accounts`](/ja/products/launchlab/accounts#poolstate) を参照してください。

非推奨の `Initialize` 命令は依然としてレガシーのみのクォートプログラムを受け取るため、Token-2022 クォートミントを持つ設定は `InitializeV2` と `InitializeWithToken2022` を通じてのみ到達可能です。

## CPMM と CLMM 拡張機能許可リスト

[下記](#唯一の回避方法ミント単位レジストリ)でカバーされた 2 つのショートサーキットの後、プログラムはミントの拡張機能を反復処理し、これら 5 つ以外の拡張機能を持つミントを拒否します：

| 拡張機能 | 許可される理由 |
|---|---|
| `TransferFeeConfig` | プール数学は受信手数料を差し引きます。Token-2022 プログラムは送信手数料を処理します。[`algorithms/token-2022-transfer-fees`](/ja/algorithms/token-2022-transfer-fees) を参照してください。 |
| `MetadataPointer` | 装飾的 — オンチェーンメタデータを指します。 |
| `TokenMetadata` | 装飾的 — インラインメタデータ。 |
| `InterestBearingConfig` | プールは元本を見ます。UI 乗数は装飾のみで、基礎となる残高は保持されます。 |
| `ScaledUiAmount` | 利息ベアリングと同じ形状 — スケール係数は UI 表示にのみ適用されます。 |

このリストにない何か — `TransferHook`、`NonTransferable`、`ConfidentialTransferMint`、`PermanentDelegate`、`MintCloseAuthority`、`DefaultAccountState`、`GroupPointer`、`GroupMemberPointer`、`MemberPointer`、`Pausable` など — は `is_supported_mint` が `false` を返し、プール作成がリバートします。

関連する行（CPMM、CLMM で同じ形状）：

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs)

## 回避パス

許可リストに適合しない Token-2022 ミントは、各プログラムの 1 つのメカニズムを通じて認められることができます。両プログラムは過去にハードコードされた回避方法も持っていました。それらのどれも生き残っていません。

| 回避方法 | CPMM | CLMM |
|---|---|---|
| ミント単位レジストリ PDA | はい — 唯一の回避方法 | はい — 唯一の回避方法 |
| 静的 `MINT_WHITELIST` | 2026-09 に削除（4 アドレス） | 2026-07 に削除（6 アドレス） |
| Superstate 権限形状検出 | 持っていない | 2026-07 に削除 |

`is_supported_mint` は現在、両プログラムで完全に同じ関数です：レガシー SPL Token ミントは通過し、ミントがレジストリ PDA を持つと通過し、その他はすべて許可リストに登録された拡張機能のみを持つ必要があります。

## 唯一の回避方法：ミント単位レジストリ

両プログラムは、シード `[b"support_mint", mint]` で `SupportMintAssociated` PDA を参照します。そのミント用の PDA が存在する場合、ミントは拡張機能セットに関係なく認められます。

各プログラムは PDA の独自のコピー（異なるプログラム ID の下で派生）、独自の `CreateSupportMintAssociated` / `CloseSupportMintAssociated` ペア、および共有管理者と並んで独自の専用権限を持ちます：

| プログラム | 専用サポートミント権限（メインネット） | 専用サポートミント権限（デブネット） |
|---|---|---|
| CPMM | `Rayv2LG4tFSMizZhMP8aSUYxDPjV8qJtx2NQY9RKYZy` | `DRaypyeDL6y1dUusMgwyeDM5JebjhsSi8aRXobKQ9DcQ` |
| CLMM | `RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY` | `rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5` |

両プログラムで命令は `crate::admin::ID` またはそのプログラムの専用権限のいずれかを受け入れ、ミントが Token-2022 によって所有されていることを要求します。効果：特定の Token-2022 ミントはプログラムアップグレードなしでプール作成にオプトインできます — これが、ハードコードされたリストが削除できた理由です。

各プログラムは、それが持つ**すべての**プール作成パスからレジストリを参照します：CPMM は `Initialize` と `InitializeWithPermission` から（後者は LaunchLab 卒業が使用するため、登録されたミントは卒業と同様に作成されます）、CLMM は `CreatePool`、`CreateCustomizablePool` および `CreatePermissionedPool` から。

### Superstate 権限形状検出 — 削除

CLMM は、アドレスではなく権限形状によって Superstate のトークン化資産を簡潔に識別しました：`freeze_authority` **と** 永続デリゲートの両方が `superstate_allowlist::ID` に等しく、`DefaultAccountState` が `Frozen` に設定された Token-2022 ミントは認められました。これはヒューリスティックだったため、同じ形状を持つ将来のミントは自動的に認められていたでしょう。

2026-07-31 に `superstate_allowlist` モジュールと共に削除されました。それに置き換わったものはより狭く、異なる目的に役立ちます：`frozen_position_nft_authorities::IDS` は何も認めません — **ポジション NFT** がフリーズされるかどうかを決定し、[上記](#clmm-ポジション-nft-制限発行者のフリーズ)で説明されています。古いヒューリスティックが一致した 1 つの発行者権限がそのリストの 1 つのエントリです。

## 回避方法が放棄しないもの

回避方法は拡張機能許可リストをスキップしますが、プログラムは依然として実施します：

- ミントは `Token` または `Token-2022` によって所有されています。カスタムトークンプログラムは上流で拒否されます。
- プールボールトは Token-2022 プール用の正しい ATA 拡張機能で作成されます（`ImmutableOwner` など）。
- すべての転送は `transfer_checked` を通じて行われます — 手数料ベアリングミントはボールトに正しい金額を着地させます。

ホワイトリストまたは PDA 登録されたミントが、例えば後で `TransferHook` を追加しても、スワップ時チェックを取得しません。フックは単にすべての転送で実行され、スワップをブリックする可能性があります。ミントを登録することは、したがって高信頼アクションです。

## 「ブロック」セマンティクス

`is_supported_mint` が `false` を返すと、プール作成は `ErrorCode::NotSupportMint`（CPMM）/ `ErrorCode::NotSupportMint`（CLMM）でリバートします。数値コードについては [`reference/error-codes`](/ja/reference/error-codes) を参照してください。

既存のプールはこのチェックに遡及的に失敗することはできません — ゲートは作成時にのみ実行されます。ミント拡張機能は Raydium が拒否するカテゴリに対して不変です（転送フック、非転送可能、機密転送は作成後に追加できません）。したがって、静的チェックで十分です。

## 除外された各拡張機能が除外される理由

- **TransferHook** — すべての転送で任意の CU 消費、任意の失敗条件、および呼び出しプログラムを再入力する能力を持つカスタムプログラムを呼び出します。安全なサンドボックスは存在しません。一部の DEX はフック許可リストを維持します。Raydium はそうしません。
- **NonTransferable** — `Transfer` は常に失敗します。プールは保管を取得できません。
- **ConfidentialTransfer** — 転送額は暗号化されます。曲線はスワップを価格設定できません。
- **PermanentDelegate** — デリゲートの保有者はプールボールトを含む任意のトークンアカウントをスイープできます。ミント登録によってのみ認可可能です。これは信頼できる発行者（例えば規制されたステーブルコイン）がケースバイケースでオンボードされる方法です。
- **MintCloseAuthority** — ミントを閉じることができます。既存のプールは使用不可になります。デフォルトで許可されません。
- **DefaultAccountState (Frozen)** — プール ATA は `Frozen` 状態で着地し、アカウントごとにフリーズを解除する必要があります。ミント登録によってのみ認可可能です。これは発行者が登録時に機関アカウントをフリーズ解除することを想定しています。
- **Group/Member ポインター** — 積極的に有害ではありませんが、未レビューです。デフォルトで許可されず、表面を狭く保ちます。

## 転送手数料会計

`TransferFeeConfig` を持つミントの場合、すべてのスワップ、デポジット、および引き出しは名目額より少なく移動します。 2 つの別個の数値が関係し、SDK はそれらを分離します：

- **プール手数料**（LP + プロトコル + ファンド + クリエーター）は曲線から来ます。`raydium.cpmm.computeSwapAmount({ ... })` は `fee`、`amountIn`、`amountOut`、`minAmountOut`、`executionPrice`、`priceImpact` および生の `swapResult` と共にそれを返します。
- **Token-2022 転送手数料**はプールではなくミントから来ます。これは `@raydium-io/raydium-sdk-v2` の `getTransferAmountFee` ヘルパーによって計算され、`GetTransferAmountFee` を返します：

```ts
export interface GetTransferAmountFee {
  amount: BN;                  // 実際に移動する金額
  fee: BN | undefined;         // ミントによって保留。ミントに TransferFeeConfig がない場合は undefined
  expirationTime: number | undefined;  // スケジュールされた手数料変更が保留中の間に設定
}
```

デポジットと引き出しは直接それを表示します：`computePairAmount` は `inputAmountFee` と `anotherAmount` を `GetTransferAmountFee` 値として返します。

正しい UI は以下を表示します：

- 入力額**プラス**その転送 `fee` を「送信」として
- 出力額**マイナス**その転送 `fee` を「受け取る」として
- プール `fee` を別の行として — これは Token-2022 手数料ではありません

`amountIn → amountOut` のみを表示する素朴な UI はコストを過小評価します。これらのヘルパーにクラスタから `epochInfo` を渡します。キャッシュしないでください。エポックはミントの `older` と `newer` 手数料設定の間で選択するものです。

### `maximumFee` キャップ

Token-2022 転送手数料は転送ごとにキャップされます。1% ミントで 10,000 トークンキャップの場合、100,000,000 トークン転送は手数料で 10,000 のみを支払います。SDK の `computeSwapAmount` はキャップを適用します。直接プログラム呼び出し元はそれを複製する必要があります。

### エポック遷移

ミント権限は、次のエポックで有効になる手数料レート変更をスケジュールできます。遷移ウィンドウ中、 2 つの設定（`older`、`newer`）がミント上に同時に存在し、`TransferChecked` は現在のエポックで選択します。CPMM `SwapV2` と CLMM `SwapV2` の両方は `accounts` で完全なミントアカウントを渡すため、プログラムは追加のルックアップなしで正しい設定を読み取ります。

Trade API または SDK を通じて 1 エポック以上先に引用する場合、実行手数料は引用手数料と異なる可能性があります — 古い設定の `maximum_fee_basis_points` によってバウンドされます。

## 利息ベアリングと ScaledUiAmount

プールは元本を保有します。「UI 金額」は元本に時間依存またはアドミン設定スケール係数を掛けたものです。スワップ数学は元本で動作します：

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK は自動的に変換します。直接 RPC リーダーは `pool.token0Vault.amount` を元本として扱うべきです。

## 「Token-2022 プール」定義

プールは、**いずれかの**ミントが `programId == TokenzQdB...` を持つ場合、Token-2022 プールです。API はこれを表示します：

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

ディスパッチするには `programId` を使用し、UI 警告を表示するには `hasTransferFee` を使用します。

## SDK ヘルパー

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## 一般的な統合の間違い

- **プログラム ID のみをプリフライトする。** ミントは Token-2022 *かつ*サポートされていない可能性があります。プール作成を許可する前に、拡張機能リストを許可リストに対して確認し、ミントのレジストリ PDA を確認します。
- **ミントが完全にサポートされていない場合、SDK の引用を信頼する。** 引用 API は引用を拒否しません — プール作成がリバートするものです。UI でプール作成を公開する前に、オフチェーンで `is_supported_mint` セマンティクスを確認します。
- **転送手数料ヘアカットなしで引用する。** 両側に 1% 転送手数料ミントを持つ 0.25% CPMM プールは、約 2.25% の有効手数料を持ちます。0.25% ではなく。SDK 引用または Trade API 引用を使用します — プールの手数料層のみから手数料を手動で計算しないでください。
- **Token-2022 プールで従来の `Swap` 命令を呼び出す。** `Swap` は Token-2022 より前のもの。いずれかのミントが Token-2022 の場合は常に `SwapV2` を使用します。
- **新しい Token-2022 ミントを自動リストする。** ウォレットとアグリゲーターは、ミントをユーザーに表示する前に `TransferHook` と `NonTransferable` を確認する必要があります。両方とも Raydium に敵対的です。
