## フェーズ1：ボンディングカーブのクリエイターフィー

トークンがボンディングカーブで取引されている間、プラットフォームは買いと売りにクリエイターフィーコンポーネントを課すことができます。

- クォートトークン（通常はSOL）で発生します。
- レートはプラットフォームが設定します。
- LaunchLabクリエイターフィークレームフローを通じてクレームできます。
- 卒業によってボンディングカーブの新規発生は停止します。既存の残高はクレーム可能なままです。

## フェーズ2：CPMMクリエイターフィー

新しく初期化されたすべてのローンチはCPMMに卒業します。CPMMクリエイターフィーは、選択された `AmmConfig` がゼロ以外のクリエイターフィーレートを持つ場合にのみ発生します。

デフォルトでは、ローンチクリエイターがCPMMプールクリエイターになります。プラットフォームは代わりに `platform_cp_creator` を設定できます。その場合、そのアドレスがCPMMクリエイターフィー権を受け取ります。

記録されたCPMMクリエイターは直接クレームできます。別の支払者がパーミッションレス収集をトリガーすることもできますが、CPMMはクリエイターの正規トークンアカウントに宛先を固定します。

## LPトークンに何が起こるか

プラットフォーム設定は `platformScale`、`creatorScale`、および `burnScale` を保存します。2026-08-17アップグレード前は、`creatorScale` がクリエイター所有のFee Keyを作成していました。アップグレード後に実行されたマイグレーションでは、LaunchLabはそれを `platformScale` と組み合わせます：

```text
platform locked LP = platformScale + creatorScale
burned LP          = burnScale
```

ロックされたシェアがゼロ以外の場合、1つのFee Key NFTがプラットフォームの設定されたNFTウォレットに送られます。このNFTはLPフィー収集を制御します。CPMM クリエイターフィー収集は制御しません。アップグレード前に完了したマイグレーションからのクリエイターFee Keyは、既存の保有者に残ります。

## フィーフロー概要

```text
ボンディングカーブ
  クリエイターフィー → ローンチクリエイターボルト

CPMMへの卒業
  アップグレード前 → プラットフォームFee Key + クリエイターFee Key + バーンシェア
  アップグレード後  → 統合プラットフォームFee Keyシェア + バーンシェア

CPMM取引
  クリエイターフィー → 記録されたCPMMプールクリエイター
  LPフィー      → ロックされたシェアのプラットフォームFee Key保有者
```

## ローンチ前に確認すること

- ボンディングカーブの `creator_fee_rate` を確認します。
- `platform_cp_creator` があなたをCPMMクリエイター記録として置き換えるかどうかを確認します。
- アップグレード後に実行されたマイグレーションの場合、`creatorScale` を約束されたクリエイターFee Key割り当てとして扱わないでください。以前のマイグレーションの場合、既存のFee Keyレコードを確認します。
- CPMM設定のクリエイターフィーレートとフィーオン設定を確認します。
