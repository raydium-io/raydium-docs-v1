## セットアップ

ここのデモは [`raydium-sdk-V2-demo/src/farm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/farm) のファイルを反映しています。ブートストラップはデモリポジトリの [`config.ts.template`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template) に従います。

```ts
import { Connection, Keypair, clusterApiUrl, PublicKey } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);
const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
export const txVersion = TxVersion.V0;
```

## ID でファームをフェッチ

`raydium.farm.getFarmById` は存在しません。すべてのファームデモは API モジュールから始まります。API モジュールは、`deposit` / `withdraw` / `harvestAllRewards` がすべて受け取る正規化された `FormatFarmInfoOut` 形状を返します。

```ts
const farmId = "CHYrUBX2RKX8iBg7gYTkccoGNBzP44LdaazMHCLcdEgS"; // RAY-USDC ファーム

const farmInfo = (await raydium.api.fetchFarmInfoById({ ids: farmId }))[0];
if (!farmInfo) throw new Error("farm not found");

console.log("LP mint:", farmInfo.lpMint.address);
console.log("TVL:", farmInfo.tvl);
for (const r of farmInfo.rewardInfos) {
  console.log("  -", r.mint.address, r.mint.symbol);
}
```

`fetchFarmInfoById` は **カンマ区切りの ID 文字列** を受け取り、配列を返すため、1 回の呼び出しでポートフォリオ全体をハイドレートできます。表示情報ではなく生のアカウントキーが必要な場合、`raydium.api.fetchFarmKeysById({ ids })` はボルトと権限 PDA を返します。SDK は以下のすべてのビルダー内で内部的にこれを呼び出します。

## LP トークンをステーキング

ソース：[`src/farm/stake.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/stake.ts)

```ts
// デモはウォレットの LP 残高全体をステーキングします。生単位の任意の BN が機能します。
const amount = raydium.account.tokenAccountRawInfos.find(
  (a) => a.accountInfo.mint.toBase58() === farmInfo.lpMint.address,
)?.accountInfo.amount;

if (!amount || amount.isZero()) throw new Error("user does not have an LP balance");

const { execute } = await raydium.farm.deposit({
  farmInfo,
  amount,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Deposit tx:", txId);
```

SDK は保留中の報酬の事前決済を処理するため、このウォレットがこのファームにすでにステーキングを持っている場合、命令は同じトランザクション内でユーザーの ATA に蓄積された報酬を支払います。

## クレームのみ（ハーベスト）

ソース：[`src/farm/harvest.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/harvest.ts)

`farmInfoList` は配列ではなく **ファーム ID でキーされた `Record`** であり、ビルダーは **複数の** トランザクションを返すため、`execute` に `sequentially: true` を指定する必要があります。

```ts
const farmIds = [farmId, "<ANOTHER_FARM_ID>"];
const farmInfos = await raydium.api.fetchFarmInfoById({ ids: farmIds.join(",") });

const { execute } = await raydium.farm.harvestAllRewards({
  farmInfoList: Object.fromEntries(farmInfos.map((f) => [f.id, f])),
  txVersion: TxVersion.V0,
});

const { txIds } = await execute({ sequentially: true });
console.log("harvest txs:", txIds);
```

ビルダーは 1232 バイト制限が許す限り多くのファームをトランザクションごとにパックし、残りを後続トランザクションに分割します。そのため、単一の `txId` ではなく `txIds` を返します。

単一ファームの場合、`amount: 0` イディオムでハーベストします。これは v6 を含むすべてのバージョンで [`src/farm/harvest.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/harvest.ts) が行うことです。

```ts
const { execute } = await raydium.farm.withdraw({
  farmInfo,
  amount: new BN(0),        // 0 = ハーベストのみパス
  txVersion: TxVersion.V0,
});
await execute({ sendAndConfirm: true });
```

## v6 ファームを作成

ソース：[`src/farm/createAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/createAmmFarm.ts) および [`editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts)

`create` は、ステーキングされる LP ミントのプールのための **プール情報オブジェクト** を受け取ります（ミントだけではなく）。`rewardInfos` の各エントリは `FarmRewardInfo` です。`{ mint: PublicKey, perSecond: string, openTime: number, endTime: number, rewardType: "Standard SPL" | "Option tokens" }`。時間は **プレーン秒** であり、`perSecond` は `BN` ではなく **文字列** です。`programId` はデフォルトで v6 プログラムになるため、ほとんど渡す必要がありません。

```ts
import type { ApiV3PoolInfoStandardItem, FarmRewardInfo } from "@raydium-io/raydium-sdk-v2";
import { RAYMint } from "@raydium-io/raydium-sdk-v2";

// LP ミントがステーキングミントになるプール。
const poolInfo = (
  await raydium.api.fetchPoolById({ ids: "<POOL_ID>" })
)[0] as ApiV3PoolInfoStandardItem;
if (!poolInfo) throw new Error("pool not found");

const rewardMint = await raydium.token.getTokenInfo(RAYMint);

// ウォールクロック時間ではなくチェーン時間を使用します。プログラムは前者に対して検証します。
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);
const endTime  = openTime + 60 * 60 * 24 * 7; // 7 日

const rewardInfos: FarmRewardInfo[] = [
  {
    mint:       new PublicKey(rewardMint.address),
    perSecond:  "1",              // 文字列、秒あたりの生単位
    openTime,                      // 秒、BN ではない
    endTime,
    rewardType: "Standard SPL",   // "Option tokens" が唯一の他の値
  },
];

const { execute, extInfo } = await raydium.farm.create({
  poolInfo,
  rewardInfos,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Farm:", extInfo.farmId.toBase58(), "createTx:", txId);
```

重要なポイント：

- `perSecond` は報酬ミントの **生** 単位での秒あたりのエミッション率であり、10 進文字列として渡されます。SDK は送信前にオンチェーン固定小数点表現にパックします。
- 完全な予算（`perSecond × (endTime − openTime)`）は報酬 ATA に存在する必要があります。`create` はそれを報酬ボルトに原子的に移動します。
- **Token-2022 報酬ミントはこの SDK バージョンの SDK のファームビルダーではサポートされていません**。報酬にはプレーン SPL ミントを使用してください。
- 1 つの `create` 呼び出しで最大 5 つの報酬をシードできます。アカウントリストは追加ストリームごとに `(reward_mint, reward_vault, sender_ata, token_program)` だけ増加します。1232 バイトのトランザクションサイズ制限に注意してください。4 つ以上の報酬の場合、1～2 で作成し、後続トランザクションで `addNewRewardsToken` を使用します。

## 新しい報酬ストリームを追加

`raydium.farm.setRewards` は存在しません。ファームの報酬を変更する 2 つのビルダーは `addNewRewardToken` / `addNewRewardsToken`（**新しい** ミントで空きスロットを占有）および `restartReward` / `restartRewards`（ストリームが終了したスロットを再度有効化）です。どちらも `create` が使用するのと同じ形状の `FarmRewardInfo` オブジェクトを受け取ります。

```ts
import { USDCMint } from "@raydium-io/raydium-sdk-v2";

const added = await raydium.token.getTokenInfo(USDCMint);
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);

const { execute } = await raydium.farm.addNewRewardsToken({
  farmInfo,
  newRewardInfos: [
    {
      mint:       new PublicKey(added.address),
      perSecond:  "1",
      openTime,
      endTime:    openTime + 60 * 60 * 24 * 7,
      rewardType: "Standard SPL",
    },
  ],
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

デルタ予算（`perSecond × duration`）はトランザクションの一部として支払者の ATA から引き出されます。基礎となる命令はストリームを短縮することはできず、ライブストリームの `per_second` を低下させることはできず、スロットの報酬ミントを変更することはできません。ミントをスワップするには、`end_time` を待って解放されたスロットで `addNewRewardsToken` を使用するか、新しいファームを作成してください。

<Tip>
  `restartRewards` と `addNewRewardsToken` はそれぞれビルダーを返すため、単一トランザクションで両方を実行できます。[`src/farm/editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts) はパターンを示しています。`editFarmBuilder.builder.addInstruction(addNewRewardBuildData.builder.AllTxData)` の後、1 つの `versionBuild({ txVersion })` です。
</Tip>

## 終了したストリームを再開

ソース：[`src/farm/editAmmFarm.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/farm/editAmmFarm.ts)

`restartRewards` は **`newRewardInfos`**（複数、配列）を受け取ります。`restartReward` は単一項目形式で `newRewardInfo` を受け取ります。ミントフィールドは `rewardMint` ではなく `mint` であり、ファームに既に存在するスロットと一致する必要があります。ビルダーはミントでスロットを検索し、存在しない場合はエラーになります。

```ts
import type { FarmRewardInfo } from "@raydium-io/raydium-sdk-v2";

// ファームの既存の最初の報酬スロットを再度有効化します。
const existing = await raydium.token.getTokenInfo(farmInfo.rewardInfos[0].mint.address);
const openTime = Math.floor((await raydium.currentBlockChainTime()) / 1000);

const newRewardInfos: FarmRewardInfo[] = [
  {
    mint:       new PublicKey(existing.address),
    perSecond:  "1",
    openTime,
    endTime:    openTime + 60 * 60 * 24 * 14,
    rewardType: "Standard SPL",
  },
];

const { execute } = await raydium.farm.restartRewards({
  farmInfo,
  newRewardInfos,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

`restartRewards` は **v6 のみ** です。ビルダーはファームのプログラム ID を読み取り、v3 / v5 ファームに対してスローします。ターゲットスロットの `reward_state == 2`（終了）の場合のみ有効です。呼び出し元はスロットの `reward_sender` である必要があります。`openTime >= endTime` は RPC が行われる前にクライアント側で拒否されることに注意してください。

## Rust CPI

<Warning>
  **`raydium_farm_v6` Anchor クレートは存在しません。** crates.io にそのような名前のクレートは存在せず、Farm v6 プログラムはオンチェーン IDL を公開していません（レガシー `anchor:idl` アカウントも Program Metadata プログラムのエントリもありません）。また、公開ソースリポジトリも存在しません。このページの以前のリビジョンは `raydium_farm_v6::cpi::deposit` の例を示していました。それは何に対してもコンパイルされず、削除されました。
</Warning>

Farm v6 は 2024-05-13 に最後にデプロイされ、インテグレーターの観点からは Anchor プログラムではありません。独自のオンチェーンプログラムから構成する必要がある場合、`Instruction` を手動で構築してください。アカウントリストと命令ディスクリミネータを独立して導出します（SDK の TypeScript レイアウト（`raydium-sdk-V2/src/raydium/farm/` の下）から、または実際のトランザクションをデコードして）。その後、`invoke_signed` してください。その手順については [`sdk-api/rust-cpi`](/ja/sdk-api/rust-cpi#farm-v6) を参照してください。

どのルートを取るにせよ、`remaining_accounts` テールはファームのアクティブな報酬スロットと 1 対 1 で一致する必要があります（インデックス順の `reward_vault_i`、`user_reward_ata_i` のペア）。これらを省略または誤順序にすると、サイレント誤計算が発生します。プログラムは間違った金額を転送します。

## 落とし穴

- **引き出す前にクレームするのを忘れる。** 無害です。`Withdraw` は最初に保留中の報酬を決済します。ただし、UI が「クレーム」を「引き出す」とは別に表示する場合、ユーザーは `Withdraw` 後にまだクレームするものがあると思うかもしれません。ありません。その時点までに蓄積されたすべてが支払われました。
- **エミッション中に `total_staked = 0`。** 何もステーキングされていない間に蓄積されたエミッションは没収されます（`reward_per_share` 更新式は 0 で除算し、プログラムは更新をスキップします）。スケジュールされた `open_time` を持つプログラムの場合、open_time で「シードステーク」を実行してこれを回避してください。
- **Token-2022 転送手数料。** Token-2022 報酬ミントを持つ v6 ファームでは、転送手数料がエミット時に適用されます（ボルト → ユーザー）。これを APR 見積もりに考慮してください。
- **v5 での小さい `per_second`。** v5 の `u64` レートは、秒あたり 1 トークン単位未満の `per_second`（9 以上の小数点を持つミントでは、これはしばしば望ましいレート）を表現できないことを意味します。ストリームレートは 0 に丸められ、ファームは何も発行しません。v6 を使用してください。
