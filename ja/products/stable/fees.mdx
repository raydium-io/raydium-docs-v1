## フィーモデル

Stable AMM は AMM v4 の **`Fees` 構造体** を再利用していますが、AMM v4 の **数値** は再利用していません。Stable プールははるかに低い手数料を課します。これは同等価格の資産向けに設計されたプールに期待されることです。プールごとにフィーティアは 1 つだけ（初期化時に設定）で、プールをより高いティアに再構成することはできません。

| フィールド | オンチェーンの値 | 意味 |
|-------|----------------|---------|
| `swap_fee_numerator / swap_fee_denominator` | `2 / 10_000` | **総トレードフィー：0.02%** の入力量。実際に課される唯一の手数料です。 |
| `trade_fee_numerator / trade_fee_denominator` | `0 / 10_000` | **ゼロ。** かつて OpenBook の注文価格設定に使用されていたレガシーフィールド。レイアウト互換性のため保持されており、もう読み取られません。 |
| `pnl_numerator / pnl_denominator` | `12 / 100` | **プロトコルのフィー分配：12%** — つまり、取引量の `0.02% × 12% = 0.0024%`。 |
| `min_separate_numerator / min_separate_denominator` | `4 / 10_000` | 総手数料から PnL を分離する際に使用される最小分離しきい値。 |

<Note>
  これらは「デフォルト」ではありません — **すべての** 稼働中メインネット Stable プールに載っている値です。3 つすべて（USDT/USDC `2EXiumdi14E9b8Fy62QcA5Uh6WdHS2b38wtSxp72Mibj`、`9DTY3rv8xRa3CnoPoWJCMcQUSY7kUHZAoFKNsBhx8DDz`、`9f4FtV6ikxUZr8fAjKSGNPPnUHJEwi4jNk8d79twbyFf`）が上記と同一のセットを持ち、2026-06-22 のアップグレードで `SetParams` が削除されたため、これらを変更できる命令はもう存在しません。メインネットから `AmmInfo.fees` をデコードして検証済みです。
</Note>

**ファンドフィー** と **クリエイターフィー** のラインは **ありません** — これらは AMM v4 以降の発明です（CPMM/CLMM）。Stable AMM はその慣例より前のものです。

## 分割の計算方法

各スワップで：

```
gross_fee = ceil(amount_in * (swap_fee_numerator / swap_fee_denominator))    // amount_in の 0.02%
pnl_portion = gross_fee * (pnl_numerator / pnl_denominator)                  // gross_fee の 12%
lp_portion = gross_fee − pnl_portion                                          // gross_fee の 88%
```

- **`lp_portion`** はボールトに留まり、`k` を増加させ、LP償却時にLPに利益をもたらします。
- **`pnl_portion`** は `AmmInfo.out_put.need_take_pnl_coin` または `need_take_pnl_pc`（入力トークンに応じて）をインクリメントし、`WithdrawPnl` によってスイープされます。

CPMM と同じ **不変量保存トリック**：PnL 額はボールト内に物理的に存在しますが、曲線計算で使用される「有効準備金」から差し引かれるため、削除しても価格はシフトしません。

## OpenBook PnL（廃止）

初期段階では、プールは OpenBook に指値注文も投稿していました。それらが約定すると、マーケットメーカー/テイカースプレッドを獲得または喪失し、`MonitorStep` 中に決済され、結果は `out_put.total_pnl_{coin,pc}` カウンターで追跡されていました。**そのパスは数年間休止状態です** — プールはオープンオーダーを保有していないため、唯一のフィー発生は上記の0.0024%プロトコル分配です。`total_pnl_*` カウンターはレイアウトに残っていますが、もはやインクリメントされません。[2026-06-22 アップグレード](/ja/reference/changelog)は残りの OpenBook コード（`MonitorStep` を含む）を削除しました。CPMM が新しいプールのデフォルトになった理由の一部は、この OpenBook への以前の結合によるものです。Stable AMM はオーダーブック非依存です。

## 回収

Raydium マルチシグ（または `amm_admin` を制御する者）は `WithdrawPnl` を呼び出してスイープします：

1. `need_take_pnl_coin` と `need_take_pnl_pc` をボールトから管理者指定アカウントに転送します。
2. カウンターをゼロにします。

この操作は曲線を移動しません。LP は価格変化を見ません。

<Warning>
  `WithdrawPnl` は 2026-06-22 アップグレードで変更されました：**固定10アカウント、管理者のみのレイアウトで互換性パスなし**（古いレイアウトは `InvalidTokenCoin` などのエラーで失敗）、プールの利用可能資金が PnL をカバーするのに不十分な場合、プールを無効にする代わりに `TakePnlError` を直接返します。[`products/stable/instructions`](/ja/products/stable/instructions#withdrawpnl) を参照してください。
</Warning>

## LP フィー償却

専用の「フィー回収」命令はありません。LP フィーはボールトに蓄積され、準備金を増加させます。LP は `Withdraw` を通じて LP を焼却することで実現します。LP トークンの価値は準備金が増加するにつれて増加します。

## ビジュアライゼーション：\$10,000 の取引量がどこに行くか

稼働中の Stable プールに対する USDC ヘビーな `Swap` \$10,000 の場合：

```
総トレードフィー（0.02%）：      $2.0000
  LP 分配（0.0176%）：           $1.7600  → プールに留まり、k を上げる
  PnL 分配（0.0024%）：          $0.2400  → need_take_pnl_pc、WithdrawPnl でスイープ
ユーザーが受け取る（曲線を除く）：  $9,998.00
```

同じ \$10,000 を AMM v4 プールで通すと \$25.00、CPMM の `index=0` プールで通すと \$25.00 を支払います — **12.5 倍** です。そのギャップがこのプロダクトの要点です：ステーブルペアはほとんど動かないため、LP はインベントリリスクに対する補償をほとんど必要とせず、タイトなカーブと低い手数料が大口のステーブル間スワップを競争力あるものに保っています。

## インテグレーター向けメモ

- **クォート：** 常にチェーンから `AmmInfo` を読み取ります。フィーをハードコードしないでください。`SetParams` が削除されたため、既存プールのフィーパラメータは実質的に固定されています。
- **AMM v4 のレートを想定しないでください。** `Fees` 構造体は AMM v4 と共有されているため、AMM v4 の `25 / 10_000` を Stable の見積もりにコピーしてしまいがちです。Stable プールが課すのは `2 / 10_000` です。Stable プールを 0.25% で見積もると、手数料を 12.5 倍に過大評価します。
- **曲線 vs. フィー：** フィーの適用は、曲線が式（AMM v4 の x·y=k）であるか、ルックアップテーブル（Stable）であるかに関係なく独立しています。どちらも曲線に触れる前に入力額から手数料を差し引きます。
- **報酬なし：** Stable プールはオンプール報酬エミッションをサポートしていません。エコシステムファーム（Farm v3/v5/v6）は他の場所でステーキングを処理します。
