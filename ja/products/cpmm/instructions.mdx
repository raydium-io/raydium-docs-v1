## `Initialize`

新しい CPMM プールを作成します。

**引数**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix タイムスタンプ。この時刻前のスワップは拒否されます
```

**アカウント**（W = 書き込み可能、S = 署名者）

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 家賃を支払い、`pool_state.pool_creator` として記録されます。 |
| 2 | `amm_config` |   |   | 選択されたフィーティア。 |
| 3 | `authority` |   |   | CPMM グローバル権限 PDA。 |
| 4 | `pool_state` | W | S* | ここで `init` されます。**正規 PDA** `["pool", amm_config, token_0_mint, token_1_mint]` **または**新しいランダムキーペアのいずれか — 正規 PDA でない場合、プログラムは `pool_state` に署名を要求します（`require_eq!(pool_account_info.is_signer, true)`）。ランダムキーペアパスにより、作成者は正規 PDA 上のフロントランニング試行を回避できます。ダウンストリーム PDA（`lp_mint`、ボルト、`observation_state`）は `pool_state.key()` から派生します。 |
| 5 | `token_0_mint` |   |   | ソート済み：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | ここで `init` されます。権限は `authority` に設定されます。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` のソース ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` のソース ATA。 |
| 10 | `creator_lp_token` | W |   | `lp_mint` 上のクリエイターの ATA。`init`（`init_if_needed` ではない）— 既に存在してはいけません。`lp_mint` はこの同じインストラクションで作成されるため、存在できません。 |
| 11 | `token_0_vault` | W |   | ここで `init` されます。`authority` が所有します。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | クリエイターが支払う `create_pool_fee` の宛先 ATA。 |
| 14 | `observation_state` | W |   | ここで `init` されます。 |
| 15 | `token_program` |   |   | SPL Token（LP ミント用）。 |
| 16 | `token_0_program` |   |   | SPL Token または Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token または Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` はランダムキーペアパスでのみ署名します。正規 PDA パスは `pool_state` 署名なしで実行されます。

**前提条件**

- ミントはソート済み（バイト順で `token_0_mint < token_1_mint`）。
- どちらのミントも CPMM 許可リスト外の拡張機能を使用していません（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`）— [`products/cpmm/accounts`](/ja/products/cpmm/accounts#vaults-and-token-2022) を参照してください。`SupportMintAssociated` PDA（シード `[b"support_mint", mint]`）が存在するミントは拡張機能チェックをスキップします — **ただし、その PDA を `remaining_accounts` に追加する必要があります**。プログラムは渡されたアカウントのみをスキャンし、PDA 自体をロードしません。レジストリに依存しながらアカウントを提供しないと、`NotSupportMint`（`6007`）で失敗します。順序は重要ではありません（キーでマッチング）。バイパスが必要な各ミントに 1 つのエントリを渡します。そのレジストリは 2026-09 アップグレードがハードコードされた 4 ミント・ホワイトリストを削除した後の唯一のバイパスです。
- `creator` は各 ATA で少なくとも `init_amount_0` と `init_amount_1` を持っています。
- `amm_config.disable_create_pool == false`。

**事後条件**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — **完全な**平方根。クリエイターは `lp_supply − 100` をミントされます。100 ロック基本単位は `lp_supply` でカウントされますが、ミントされません。
- したがって、プールの存続期間中 `lp_mint.supply == pool_state.lp_supply − 100`。すべての LP シェア数学（デポジット、引き出し）は `lp_supply` で除算するため、そのフィールドを使用し、ミントのオンチェーン供給を代用しないでください。`sqrt(...) < 100` の場合、`InitLpAmountTooLess` で戻ります。
- `observation_state` が初期化されます。`observation_index = 0` で `pool_id = pool_state.key()`。
- `create_pool_fee` ラムポートはクリエイターから受取人に転送され、ネイティブ SOL として同期されます（wSOL ATA です）。
- プールのステータスビットマスクは `0`（デポジット / 引き出し / スワップすべて有効）。
- `enable_creator_fee = false` で `creator_fee_on = BothToken`。`Initialize` はクリエイターフィーの有効化をサポート**しません** — そのパスは `InitializeWithPermission` です。
- `open_time` は、呼び出し元が `<= block_timestamp` の値を渡した場合、`block_timestamp + 1` にバンプされます。スワップは `open_time` 前に拒否されます。デポジットと引き出しは直ちに機能します。

**一般的なエラー**（完全なリストは [`reference/error-codes`](/ja/reference/error-codes) を参照）

- `InvalidInput` — ミントがアンソート、または同一ミント。
- `NotSupportMint` — ブロックされた Token-2022 拡張機能。
- `ExceededSlippage` — まれに。`init_amount_0/1` が小数点の不一致により 0 LP になる場合。

## `Deposit`

プールに比例した両方のトークンでリクイディティを追加します。

**引数**

```
lp_token_amount:   u64   // LP にミントする LP トークン数
maximum_token_0:   u64
maximum_token_1:   u64
```

**アカウント**

| # | 名前 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**数学**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // サイド 1 も同じ

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // サイド 1 も同じ
```

ピンダウンする価値のある 2 つの詳細：按分ベースは**フィー除外**ボルト合計（`vault_amount_without_fee`、つまり生残高から蓄積されたプロトコル、ファンド、クリエイターカウンターを差し引いたもの）であり、生ボルト残高ではありません。スリッページキャップは、ペイヤーが実際に転送する内容に対してチェックされ、Token-2022 転送フィーが追加された後、生ボルト移動に対してではありません。

`k` の比例性に変更なし — 両方の合計と `lp_supply` は同じ係数でスケーリングされます。

**事後条件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（入力上の Token-2022 転送フィーを差し引いたネット）。
- `vault_1 += needed_token_1`（入力上の Token-2022 転送フィーを差し引いたネット）。

**一般的なエラー** — `ExceededSlippage`、`ZeroTradingTokens`、デポジットが一時停止されている場合は `InvalidStatus`。

| # | 名前 | W | S |

| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

最初の 13 アカウントは `Deposit` と同一で、`lp_mint` は LP トークンがバーンされるため書き込み可能です。`Withdraw` は追加で 14 番目のアカウント `memo_program`（制約 `address = memo::ID`）を取ります — `Deposit` は取りません。13 アカウント `Withdraw` は Anchor 逆シリアル化に失敗するため、LP は出口できません。

**数学**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // サイド 1 も同じ

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // サイド 1 も同じ

// Deposit と同様：ベースはフィー除外ボルト合計で、フロアは LP が実際に受け取る内容に対してチェックされます。
```

**事後条件**

- `lp_supply -= lp_token_amount`。
- ボルトは `out_token_0` / `out_token_1` を送信します（生。ユーザーは Token-2022 転送フィーを差し引いたネットを受け取ります）。

`CollectProtocolFee` と同じ形状ですが、`amm_config.fund_owner` — または再度、プログラム管理者 — によって署名され、`fund_fees_*` カウンターをゼロにします。間違った署名者に対して同じ `InvalidOwner`。

## `CollectCreatorFee`

**引数** — なし。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 制約 `address = pool_state.pool_creator`。 |
| 2 | `authority` |   |   | CPMM グローバルボルト権限 PDA。 |
| 3 | `pool_state` | W |   | 蓄積されたクリエイターフィーカウンターを保持します。 |
| 4 | `amm_config` |   |   | 制約 `address = pool_state.amm_config`。デフォルト `creator_fee_share_rate` を持ちます。 |
| 5 | `token_0_vault` | W |   | プールのトークン 0 ボルトと一致する必要があります。 |
| 6 | `token_1_vault` | W |   | プールのトークン 1 ボルトと一致する必要があります。 |
| 7 | `vault_0_mint` |   |   | `token_0_vault.mint` と一致する必要があります。 |
| 8 | `vault_1_mint` |   |   | `token_1_vault.mint` と一致する必要があります。 |
| 9 | `creator_token_0` | W |   | トークン 0 のクリエイター部分の宛先。 |
| 10 | `creator_token_1` | W |   | トークン 1 のクリエイター部分の宛先。 |
| 11 | `token_0_program` |   |   | SPL Token または Token-2022、トークン 0 に一致。 |
| 12 | `token_1_program` |   |   | SPL Token または Token-2022、トークン 1 に一致。 |
| 13 | `associated_token_program` |   |   | |
| 14 | `system_program` |   |   | |
| 15 | `creator_fee_share` |   |   | **2026-09-19 で追加**、`system_program` の後に追加されます。`["creator_fee_share", creator, amm_config]` の PDA。すべての呼び出しで渡す必要がありますが、**存在する必要はありません** — 空であるか CPMM が所有していない場合、プログラムは `amm_config.creator_fee_share_rate` にフォールバックします。シード制約は依然として適用されるため、アドレスは正規 PDA である必要があります。 |

**効果**

```
share_rate = creator_fee_share.share_rate   (アカウントが存在する場合)
           | amm_config.creator_fee_share_rate   (そうでない場合)

shared_i  = floor(creator_fees_token_i * share_rate / 1_000_000)
creator_i = creator_fees_token_i - shared_i

transfer creator_i from vault_i to creator_token_i
pool_state.protocol_fees_token_i += shared_i     // ボルトに留まります
pool_state.creator_fees_token_i   = 0
pool_state.recent_epoch = current epoch
```

プロトコルのシェアはここではボルトを離れません — プロトコルフィーとして再ラベル付けされ、`CollectProtocolFee` を待ちます。両方のカウンターは既にボルトのビューから除外されているため、プールの価格は移動しません。完全な導出は [`products/cpmm/fees`](/ja/products/cpmm/fees#protocol-share-of-the-creator-fee) を参照してください。

**一般的なエラー** — 両方のクリエイターカウンターがゼロの場合 `NoFeeCollect`（分割前にチェック）、解決された `share_rate` が `1_000_000` を超える場合 `InvalidInput`（`6003`）、シェアの記帳が `protocol_fees_token_*` をオーバーフローする場合 `MathOverflow`（`6011`）、`creator_fee_share` が正規 PDA でない場合 Anchor の `ConstraintSeeds` エラー。

## `CreateAmmConfig`

新しいフィーティアを作成します。

**引数**

```
index:             u16
trade_fee_rate:    u64

fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | 管理者。 |
| 2 | `amm_config` | W |   | ここで `init` されます。 |
| 3 | `system_program` |   |   |

**前提条件**

- 同じ `index` を持つ既存の `AmmConfig` はありません。
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`。

<Note>
  **2026-09 で変更：新しいコンフィグのフィー所有者は署名者から来なくなりました。** `create_amm_config` は現在、プログラムのハードコードされた `protocol_fee_owner::ID` を `protocol_owner` に、`fund_fee_owner::ID` を `fund_owner` に書き込みます。以前は管理者署名者のキーを両方にコピーしていました。アドレスは [`reference/program-addresses`](/ja/reference/program-addresses#cpmm-fee-owner-wallets) にあります。

  結果：新しく作成された `AmmConfig` 上のフィーは、管理者の代わりに専用フィーウォレットに着地します。管理者は収集の受け入れられた*署名者*のままです — `CollectProtocolFee` / `CollectFundFee` は `amm_config.protocol_owner` / `fund_owner` **または** `crate::admin::ID` を受け入れます — したがって、回収するために何もローテーションする必要はありません。変更されたのは、デフォルトで収益がどこに行くかだけです。**既存の `AmmConfig` アカウントは書き直されません** — それらに保存されているものは依然として支配するため、常にアカウントから `protocol_owner` / `fund_owner` を読み取り、どちらかの値を想定しないでください。`UpdateAmmConfig` パラメータ `3` と `4` は依然としてそれらをローテーションします。
</Note>

## `UpdateAmmConfig`

既存の `AmmConfig` のフィーレートまたは所有権を変更します。`param: u8`（更新するフィールド）と `value: u64` を取ります。完全なディスパッチテーブル：

- `param = 0` → `trade_fee_rate`（`trade_fee_rate + creator_fee_rate < 1_000_000` をアサート）
- `param = 1` → `protocol_fee_rate`（`≤ 1_000_000` および `+ fund_fee_rate ≤ 1_000_000` をアサート）
- `param = 2` → `fund_fee_rate`（`≤ 1_000_000` および `+ protocol_fee_rate ≤ 1_000_000` をアサート）
- `param = 3` → `protocol_owner`。新しいキーは `value` に**ありません**：`remaining_accounts[0]` として追加します（読み取り専用で問題ありません）。デフォルト pubkey であってはいけず、アカウントを省略すると `unwrap()` でパニックします。
- `param = 4` → `fund_owner`。`3` と同じメカニズム。
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`（ゼロ以外の `value` は無効化）
- `param = 7` → `creator_fee_rate`（`creator_fee_rate + trade_fee_rate < 1_000_000` をアサート）
- `param = 8` → `creator_fee_share_rate`（`≤ 1_000_000` をアサート）。2026-09-19 で追加。このティア上のクリエイターフィーのプロトコルのデフォルトシェア。[`products/cpmm/fees`](/ja/products/cpmm/fees#protocol-share-of-the-creator-fee) を参照してください。トレードフィーを分割する `protocol_fee_rate` とは関係ありません。

その他の `param` は `InvalidInput` を返します。

変更は管理者によって署名され、次のスワップでこの `AmmConfig` にバインドされた**すべてのプール**に影響します。マイグレーションなし。プールは単に新しい値を読み取ります。

1 つの `(creator, amm_config)` ペアのクリエイターフィーのカスタムプロトコルシェアを設定し、そのフィーティア上でそのクリエイターが所有するすべてのプールの `AmmConfig.creator_fee_share_rate` をオーバーライドします。2026-09-19 クリエイターフィーシェアアップグレードで追加。

**引数**

```
share_rate: u64   // クリエイターフィーの OF プロトコルのシェア、FEE_RATE_DENOMINATOR = 1_000_000 以上
```

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | CPMM プログラム管理者 **または**専用クリエイターフィーシェア所有者である必要があります — [`reference/program-addresses`](/ja/reference/program-addresses#cpmm-creator-fee-share-authority) を参照してください。その他の署名者は `InvalidOwner`（`6001`）で失敗します。家賃を支払います。 |
| 2 | `creator` |   |   | レートが適用されるプール作成者。チェックなし — 既存のプール作成者である必要はなく、署名しません。 |
| 3 | `amm_config` |   |   | レートが適用されるフィーティア。 |
| 4 | `creator_fee_share` | W |   | `["creator_fee_share", creator, amm_config]` で `space = 145` でここで `init` されます。 |
| 5 | `system_program` |   |   | |

**前提条件**

- `share_rate <= 1_000_000`、そうでない場合は `InvalidInput`（`6003`）。
- PDA は既に存在してはいけません — Anchor の `init` は同じペアの 2 番目の呼び出しで失敗します。レートを変更するには、アカウントを閉じて再度作成します。

**事後条件**

- `creator_fee_share` は `bump`、`creator`、`amm_config`、`share_rate` を保存します。
- その後のすべての `CollectCreatorFee` / `CollectCreatorFeePermissionless` は、`creator` によって `amm_config` の下で作成されたプール上で、コンフィグの代わりにこのアカウントからシェアを解決します。

<Note>
  プール作成者はこのインストラクションの当事者ではなく、署名しません。レートは収集時に読み取られるため、フィーが既に蓄積された後に作成されたオーバーライドはその蓄積残高にも適用されます。
</Note>

## `CollectExcessLamports`

CPMM が制御するアカウント上の家賃免除最小値を超えるラムポートの管理者スイープ。2026-09 アップグレードで追加されたため、プロトコルは [SIMD-0437 家賃削減](/ja/solana-fundamentals/rent-and-reclaimable-rent) が各ステップの前に作成されたアカウントに残す過剰資金を回収できます。

過剰分のみが移動します。トークン残高、アカウントデータ、所有者、プール状態、曲線は変更されず、インストラクションは既に最小値にあるアカウントに対して no-op です — したがって、各ロールアウトステップ後に再実行しても安全です。

**引数** — なし。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | すべてのスイープされたラムポートの宛先。CPMM プログラム管理者または専用 collect-lamports ウォレットのいずれかである必要があります — [`reference/program-addresses`](/ja/reference/program-addresses#excess-lamports-collection-wallets) を参照してください。その他の署名者は `InvalidOwner` で失敗します。 |
| 2 | `authority` |   |   | シード `[b"vault_and_lp_mint_auth_seed"]` の CPMM ボルト・LP ミント権限 PDA。トークンプログラム CPI に署名します。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。両方は無条件に必須。プログラムはソースアカウントごとに選択します。 |
| 5.. | `remaining_accounts` | W |   | スイープする `M` ソースアカウント、任意の数、任意の順序。 |

<Note>
  **順序付け修正、2026-09-19。** プログラムは `remaining_accounts` に対して 2 つのパスを実行します — すべてのトークンプログラム CPI 最初、次に CPMM 所有 PDA の直接デビット。CPI の前に PDA がデビットされるたびに、ランタイムの `UnbalancedInstruction`（「命令の前後のアカウント残高の合計が一致しない」）で中止されました。呼び出し元の保留中のラムポート変更は、CPI が実際に実行するアカウントにのみフラッシュされるためです。呼び出し元はリストを自分でグループ化またはソートする必要はありません。
</Note>

**各ソースアカウントの処理方法**

プログラムはソースアカウントの `owner` でディスパッチします：

| ソースアカウント所有者 | 処理 |
|---|---|
| SPL Token または Token-2022、非ネイティブトークンアカウントまたはミント — プールボルトと LP ミント | CPI `WithdrawExcessLamports`（トークンプログラムディスクリミナント `38`）、`authority` によって署名。 |
| SPL Token または Token-2022、**ネイティブ**（wSOL）トークンアカウント | `WithdrawExcessLamports` はネイティブアカウントを拒否します。プログラムは `SyncNative` を CPI し、ラップされた `amount` がどれだけ増加したかを測定し、`UnwrapLamports`（ディスクリミナント `45`）をその正確なデルタに対して実行し、ラップされた残高が事前同期値と等しいことを要求します — そうでない場合は `LamportsCalculateError`（`6015`）。SOL サイドプールボルトはその完全なリクイディティを保持します。 |
| CPMM プログラム自体 — `PoolState`、`AmmConfig`、`ObservationState`、`Permission`、`SupportMintAssociated` | プログラムはアカウントを直接 `rent.minimum_balance(data_len)` にデビットします。 |
| その他 | **サイレントにスキップされます。** エラーなし、ラムポート移動なし。 |

無制限の `remaining_accounts` リストを取るため、トランザクションサイズが実際の制限です — [`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) で説明されているウォレット側スイープと同じ制約。

**一般的なエラー** — `InvalidOwner`（`6001`、間違った署名者）、`LamportsCalculateError`（`6015`、wSOL ラウンドトリップがゼロにネットされなかった）、プログラム所有パスから `InsufficientFunds`（アカウントが独自の家賃最小値より少ない場合）。

**SDK ビルダーなし。** `@raydium-io/raydium-sdk-v2` はこのインストラクションのビルダーを出荷しません。`raydium-sdk-V2-demo` リポジトリも出荷しません — これは管理者パスです。手動でエンコードしてください。[`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) のウォレット側スイープがトークンプログラムインストラクションに対して行うのと同じ方法で。
