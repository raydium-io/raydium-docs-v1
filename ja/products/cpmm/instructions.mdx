## インストラクション一覧

| ディスクリミネータ名 | 署名者 | 機能 |
|-------|-----------|--------------|
| `Initialize` | プール作成者 | 2 つのミントと `AmmConfig` から新しい CPMM プールを作成します。パーミッションレス。誰でも呼び出せます。新しいプールに `enable_creator_fee = false` をハードコードします。`pool_state` アカウントは、正規の PDA またはランダムな新規キーペア（Initialize アカウントを参照）のいずれかです。 |

| `SwapBaseOutput` | スワッパー | 正確な出力スワップ（`maximum_amount_in` 以下入力、`amount_out` 出力）。 |
| `CollectProtocolFee` | `protocol_owner`（`AmmConfig` から） | ボールトから蓄積されたプロトコルフィーを回収します。 |
| `CollectFundFee` | `fund_owner`（`AmmConfig` から） | ボールトから蓄積されたファンドフィーを回収します。 |
| `CollectCreatorFee` | `pool_creator` | 蓄積されたクリエイターフィーを回収します（クリエイターフィーが有効な場合）。 |

ステータスビットマスク：各プールの `status` は `u8` で、ビット 0 = デポジット無効、ビット 1 = 引き出し無効、ビット 2 = スワップ無効（プログラムの `PoolStatusBitIndex { Deposit, Withdraw, Swap }`）です。クリアビットは操作が許可されていることを意味し、セットビットは一時停止されていることを意味します。`UpdatePoolStatus` は生の `u8` を取り、既存の値を上書きします。

次のセクションでは、それぞれについて詳しく説明します。アカウント順序は CPMM IDL に従います。SDK と `raydium-cp-swap/programs/cp-swap/src/instructions` の Rust クライアントがこの順序に一致します。

## `Initialize`

新しい CPMM プールを作成します。

**引数**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix タイムスタンプ。この時刻より前のスワップは拒否されます
```

**アカウント**（W = 書き込み可能、S = 署名者）

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | レント支払い。`pool_state.pool_creator` として記録されます。 |
| 2 | `amm_config` |   |   | 選択されたフィーティア。 |
| 3 | `authority` |   |   | CPMM グローバル権限 PDA。 |
| 4 | `pool_state` | W | S* | ここで `init` されます。**正規 PDA** `["pool", amm_config, token_0_mint, token_1_mint]` **または**新しいランダムキーペア。正規 PDA でない場合、プログラムは `pool_state` に署名を要求します（`require_eq!(pool_account_info.is_signer, true)`）。ランダムキーペアパスにより、作成者は正規 PDA への先制攻撃を回避できます。下流の PDA（`lp_mint`、ボールト、`observation_state`）は、どちらの場合でも `pool_state.key()` から派生します。 |
| 5 | `token_0_mint` |   |   | ソート済み：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | ここで `init` されます。権限は `authority` に設定されます。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` のソース ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` のソース ATA。 |
| 10 | `creator_lp_token` | W |   | LP の宛先（不足している場合は作成）。 |
| 11 | `token_0_vault` | W |   | ここで `init` されます。`authority` が所有します。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 作成者が支払う `create_pool_fee` の宛先 ATA。 |
| 14 | `observation_state` | W |   | ここで `init` されます。 |
| 15 | `token_program` |   |   | SPL Token（LP ミント用）。 |
| 16 | `token_0_program` |   |   | SPL Token または Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token または Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` はランダムキーペアパスでのみ署名します。正規 PDA パスは `pool_state` 署名なしで実行されます。

**前提条件**

- ミントはソート済み（バイト順で `token_0_mint < token_1_mint`）。
- どちらのミントも CPMM 許可リスト外の拡張機能を使用していません（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`）。[`products/cpmm/accounts`](/ja/products/cpmm/accounts#vaults-and-token-2022) を参照してください。プログラム内の小さいミント単位の許可リストは、ケースバイケースのオンボーディング用にチェックをバイパスします。
- `creator` は各 ATA に少なくとも `init_amount_0` と `init_amount_1` を保有しています。
- `amm_config.disable_create_pool == false`。

**事後条件**

- `pool_state` は `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP` で存在します。
- `LOCKED_LP`（100 ラムポートの LP トークン）の LP スターターは永久にプールにロックされます。`pool_state.lp_supply` は `liquidity − 100` を記録し、100 LP ユニットは流通外に留まり、プールが完全に排出されるのを防ぎ、ゼロで除算するのを防ぎます。
- `observation_state` は初期化されます。`observation_index = 0` および `pool_id = pool_state.key()`。
- `create_pool_fee` ラムポートは作成者から受取人に転送され、ネイティブ SOL として同期されます（wSOL ATA です）。
- プールのステータスビットマスクは `0`（デポジット・引き出し・スワップすべて有効）。
- `enable_creator_fee = false` および `creator_fee_on = BothToken`。`Initialize` はクリエイターフィーの有効化をサポート**していません**。そのパスは `InitializeWithPermission` です。
- `open_time` は、呼び出し元が `<= block_timestamp` の値を渡した場合、`block_timestamp + 1` にバンプされます。スワップは `open_time` より前に拒否されます。デポジットと引き出しはすぐに機能します。

**一般的なエラー**（完全なリストは [`reference/error-codes`](/ja/reference/error-codes) を参照）

- `InvalidInput` — ミントがソートされていない、または同一のミント。
- `NotSupportMint` — ブロックされた Token-2022 拡張機能。
- `ExceededSlippage` — まれに。`init_amount_0/1` が小数点の不一致により LP ゼロになる場合。

## `Deposit`

プールに比例したリクイディティを両方のトークンで追加します。

**引数**

```
lp_token_amount:   u64   // LP にミントする LP トークン数
maximum_token_0:   u64
maximum_token_1:   u64
```

**アカウント**

| # | 名前 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**計算**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

`k` の比例性に変化なし。両方のボールトと `lp_supply` は同じ係数でスケーリングされます。

**事後条件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（入力時の Token-2022 転送フィーを差し引いた額）。
- `vault_1 += needed_token_1`（入力時の Token-2022 転送フィーを差し引いた額）。

**一般的なエラー** — `ExceededSlippage`、`ZeroTradingTokens`、デポジットが一時停止されている場合は `InvalidStatus`。

**引数**


**アカウント**

| # | 名前 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

（`Deposit` と同一。LP トークンがバーンされるため、`lp_mint` は書き込み可能です。）

**計算**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**事後条件**

- `lp_supply -= lp_token_amount`。
- ボールトは `out_token_0` / `out_token_1` を送信します（総額。ユーザーは Token-2022 転送フィーを差し引いた額を受け取ります）。

順序は、プールの正規 `token_0 / token_1` ではなく、ユーザーの方向による**入力 → 出力**です。プログラムはミントをマッチングすることでどのボールトがどれであるかを判断します。

- `open_time <= now`。
- `pool_status` はスワップを許可します。

- `amount_in > 0`。

**一般的なエラー**

- `ExceededSlippage` — `amount_out < minimum_amount_out`。
- `ZeroTradingTokens` — トレードがゼロに丸められます。
- `NotApproved` — プールは `UpdatePoolStatus` 経由でスワップに対して一時停止されています。
- `InvalidInput` — ミントがプールのボールトミントのいずれとも一致しません。

## `UpdateAmmConfig`

既存の `AmmConfig` のフィー率または所有権を変更します。`param: u8`（更新するフィールドのディスクリミネータ）と `value: u64` を取ります。パラメータごとの値セマンティクスはソースにあります。一般的には：

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner`（`Pubkey` バイトを再解釈として渡す）
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

変更は管理者によって署名され、次のスワップで **この `AmmConfig` にバインドされたすべてのプール** に影響します。マイグレーションなし。プールは単に新しい値を読み取ります。
