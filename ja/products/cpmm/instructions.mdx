## `Initialize`

新しい CPMM プールを作成します。

**引数**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix タイムスタンプ。この前のスワップは拒否されます
```

**アカウント**（W = 書き込み可能、S = 署名者）

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 家賃を支払います。`pool_state.pool_creator` として記録されます。 |
| 2 | `amm_config` |   |   | 選択されたフィーティア。 |
| 3 | `authority` |   |   | CPMM グローバル権限 PDA。 |
| 4 | `pool_state` | W | S* | ここで `init` されます。**正規 PDA `["pool", amm_config, token_0_mint, token_1_mint]` **または** フレッシュなランダムキーペア — 正規 PDA でない場合、プログラムは `pool_state` に署名を要求します（`require_eq!(pool_account_info.is_signer, true)`）。ランダムキーペアパスにより、作成者は正規 PDA 上のフロントランニング試行を回避できます。ダウンストリーム PDA（`lp_mint`、ボールト、`observation_state`）は `pool_state.key()` から派生します。 |
| 5 | `token_0_mint` |   |   | ソート済み：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | ここで `init` されます。権限は `authority` に設定されます。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` のソース ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` のソース ATA。 |
| 10 | `creator_lp_token` | W |   | LP の宛先（不足している場合は作成）。 |
| 11 | `token_0_vault` | W |   | ここで `init` されます。`authority` が所有します。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 作成者が支払う `create_pool_fee` の宛先 ATA。 |
| 14 | `observation_state` | W |   | ここで `init` されます。 |
| 15 | `token_program` |   |   | SPL Token（LP ミント用）。 |
| 16 | `token_0_program` |   |   | SPL Token または Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token または Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` はランダムキーペアパスでのみ署名します。正規 PDA パスは `pool_state` 署名なしで実行されます。

**前提条件**

- ミントはソート済み（バイト順で `token_0_mint < token_1_mint`）。
- どちらのミントも CPMM 許可リスト外の拡張機能を使用していません（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`）— [`products/cpmm/accounts`](/ja/products/cpmm/accounts#vaults-and-token-2022) を参照してください。`SupportMintAssociated` PDA（シード `[b"support_mint", mint]`）を持つミントはチェックをスキップします。このレジストリは 2026-09 アップグレードがハードコードされた 4 ミントホワイトリストを削除した後の唯一のバイパスです。
- `creator` は各 ATA で少なくとも `init_amount_0` と `init_amount_1` を持っています。
- `amm_config.disable_create_pool == false`。

**事後条件**

- `pool_state` は `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP` で存在します。
- `LOCKED_LP`（100 ラムポートの LP トークン）の LP スターターはプールに永久にロックされます — `pool_state.lp_supply` は `liquidity − 100` を記録し、100 LP ユニットは流通外に留まり、プールが完全に排出されるのを防ぎ、ゼロで除算するのを防ぎます。
- `observation_state` は初期化されます。`observation_index = 0` および `pool_id = pool_state.key()`。
- `create_pool_fee` ラムポートは作成者から受取人に転送され、ネイティブ SOL として同期されます（wSOL ATA です）。
- プールのステータスビットマスクは `0`（デポジット / 引き出し / スワップすべて有効）です。
- `enable_creator_fee = false` および `creator_fee_on = BothToken`。`Initialize` はクリエイターフィーの有効化をサポート**していません** — そのパスは `InitializeWithPermission` です。
- `open_time` は、呼び出し元が `<= block_timestamp` の値を渡した場合、`block_timestamp + 1` にバンプされます。スワップは `open_time` の前に拒否されます。デポジットと引き出しはすぐに機能します。

**一般的なエラー**（完全なリストは [`reference/error-codes`](/ja/reference/error-codes) を参照）

- `InvalidInput` — ミントがソートされていない、または同一のミント。
- `NotSupportMint` — ブロックされた Token-2022 拡張機能。
- `ExceededSlippage` — まれに。`init_amount_0/1` が小数点の不一致により 0 LP になる場合。

## `Deposit`

プールに比例したリクイディティを両方のトークンで追加します。

**引数**

```
lp_token_amount:   u64   // LP にミントする LP トークンの数
maximum_token_0:   u64
maximum_token_1:   u64
```

**アカウント**

| # | 名前 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**数学**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

`k` の比例性に変更なし — ボールトと `lp_supply` は同じ係数でスケーリングされます。

**事後条件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（入力の Token-2022 転送フィーを差し引いた額）。
- `vault_1 += needed_token_1`（入力の Token-2022 転送フィーを差し引いた額）。

**一般的なエラー** — `ExceededSlippage`、`ZeroTradingTokens`、デポジットが一時停止されている場合は `InvalidStatus`。

| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |

**数学**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)

require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**事後条件**

- `lp_supply -= lp_token_amount`。
- ボールトは `out_token_0` / `out_token_1` を送信します（総額。ユーザーは Token-2022 転送フィーを差し引いた額を受け取ります）。

## `CollectCreatorFee`

## `UpdatePoolStatus`

プール上の個別の操作を一時停止または再開します。`status` フィールドはビットマスクです：

| ビット | フラグ | セット時の効果 |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` は `NotApproved` で拒否されます。 |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` は拒否されます。 |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` は拒否されます。 |

**引数**

```
status: u8      // 新しいビットマスク
```

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `authority` |   | S | CPMM プログラムの管理者キーと一致する必要があります。 |
| 2 | `pool_state` | W |   |

管理者キーは CPMM プログラムのアップグレード権限です — 実際には、Raydium マルチシグです。[`security/admin-and-multisig`](/ja/security/admin-and-multisig) を参照してください。

## `CreateAmmConfig`

新しいフィーティアを作成します。

**引数**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | 管理者。 |
| 2 | `amm_config` | W |   | ここで `init` されます。 |
| 3 | `system_program` |   |   |

**前提条件**

- 同じ `index` を持つ既存の `AmmConfig` がありません。
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`。

<Note>
  **2026-09 で変更：新しいコンフィグのフィー所有者は署名者から取得されなくなりました。** `create_amm_config` は、管理者署名者のキーを両方にコピーする代わりに、プログラムのハードコードされた `protocol_fee_owner::ID` を `protocol_owner` に、`fund_fee_owner::ID` を `fund_owner` に書き込むようになりました。アドレスは [`reference/program-addresses`](/ja/reference/program-addresses#cpmm-fee-owner-wallets) にあります。

  結果：新しく作成された `AmmConfig` は、管理者キーではなく専用フィーウォレットによって即座に回収され、管理者はフィールドを最初にローテーションせずに作成したばかりのコンフィグから回収することはできなくなりました。**既存の `AmmConfig` アカウントは書き直されません** — それらに保存されているものが引き続き支配するため、常にアカウントから `protocol_owner` / `fund_owner` を読み取り、どちらかの値を想定しないでください。`UpdateAmmConfig` パラメータ `3` と `4` は引き続きそれらをローテーションします。
</Note>

## `UpdateAmmConfig`

既存の `AmmConfig` のフィー率または所有権を変更します。`param: u8`（更新するフィールドの識別子）と `value: u64` を取ります。パラメータごとの値セマンティクスはソースにあります。一般的には：

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner`（`Pubkey` バイトを再解釈として渡す）
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

変更は管理者によって署名され、次のスワップで **このコンフィグにバインドされたすべてのプール** に影響します。マイグレーションなし。プールは単に新しい値を読み取ります。

## `CollectExcessLamports`

CPMM が制御するアカウント上の家賃免除最小値を超えるラムポートの管理者スイープ。2026-09 アップグレードで追加されたため、プロトコルは [SIMD-0437 家賃削減](/ja/solana-fundamentals/rent-and-reclaimable-rent) が各ステップの前に作成されたアカウントに残す過剰資金を回収できます。

超過分のみが移動します。トークン残高、アカウントデータ、所有者、プール状態、曲線は変更されず、命令は既に最小値にあるアカウントに対しては no-op です — したがって、各ロールアウトステップ後に再実行しても安全です。

**引数** — なし。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | すべての回収ラムポートの宛先。CPMM プログラム管理者または専用 collect-lamports ウォレットのいずれかである必要があります — [`reference/program-addresses`](/ja/reference/program-addresses#excess-lamports-collection-wallets) を参照してください。他の署名者は `InvalidOwner` で失敗します。 |
| 2 | `authority` |   |   | シード `[b"vault_and_lp_mint_auth_seed"]` の CPMM ボールトおよび LP ミント権限 PDA。トークンプログラム CPI に署名します。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。両方が無条件に必要です。プログラムはソースアカウントごとに選択します。 |
| 5.. | `remaining_accounts` | W |   | スイープする `M` ソースアカウント、任意の数、任意の順序。 |

**各ソースアカウントの処理方法**

プログラムはソースアカウントの `owner` でディスパッチします：

| ソースアカウント所有者 | 処理 |
|---|---|
| SPL Token または Token-2022、非ネイティブトークンアカウントまたはミント — プールボールトおよび LP ミント | CPI `WithdrawExcessLamports`（トークンプログラム識別子 `38`）、`authority` によって署名。 |
| SPL Token または Token-2022、**ネイティブ**（wSOL）トークンアカウント | `WithdrawExcessLamports` はネイティブアカウントを拒否します。プログラムは `SyncNative` を CPI し、ラップされた `amount` がどれだけ増加したかを測定し、正確にその差分に対して `UnwrapLamports`（識別子 `45`）を実行し、ラップされた残高が事前同期値と等しいことを要求します — そうでない場合は `LamportsCalculateError`（`6015`）。したがって、SOL 側プールボールトはその完全なリクイディティを保持します。 |
| CPMM プログラム自体 — `PoolState`、`AmmConfig`、`ObservationState`、`Permission`、`SupportMintAssociated` | プログラムはアカウントを直接 `rent.minimum_balance(data_len)` まで引き下げます。 |
| その他 | **サイレントにスキップされます。** エラーなし、ラムポート移動なし。 |

無制限の `remaining_accounts` リストを取るため、トランザクションサイズが実際の制限です — [`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) で説明されているウォレット側スイープと同じ制約です。

**一般的なエラー** — `InvalidOwner`（`6001`、間違った署名者）、`LamportsCalculateError`（`6015`、wSOL ラウンドトリップがゼロに正味化されなかった）、プログラム所有パスから `InsufficientFunds`（アカウントが独自の家賃最小値より少ない場合）。

**SDK ビルダーなし。** `@raydium-io/raydium-sdk-v2` はこの命令のビルダーを出荷していません。`raydium-sdk-V2-demo` リポジトリも同様です — これは管理者パスです。手動でエンコードしてください。[`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) のウォレット側スイープがトークンプログラム命令に対して行うのと同じ方法で。
