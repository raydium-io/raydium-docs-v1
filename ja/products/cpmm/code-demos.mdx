```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

`Raydium` インスタンスは SDK のファサードです。以下のすべてのデモはこれを使用します。`Raydium.load` は非同期です。デフォルトではトークンリストを読み込むためです。トークン読み込みをスキップするには `disableLoadToken: true` を渡してください。利用可能性機能チェックは、`disableFeatureCheck: false` を渡さない限り既にスキップされています。フィー設定は `raydium.api.getCpmmConfigs()` を通じて最初の使用時に遅延フェッチされます。

## CPMM プールの作成

ソース：[`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (すべてのプール PDA を一度に必要とする場合、エクスポートされたヘルパーは `getCreatePoolKeys` です。
//  `getCpmmPdas` はありません。)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. フィー設定を選択します。index=0 は 0.25% ティアです。
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. ミントメタデータを取得して、SDK が Token-2022 拡張機能を処理できるようにします。
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. トランザクションを構築します。
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL（9 デシマルを想定）
  mintBAmount:     new BN(   160_000_000),  // 160 USDC（160/SOL）
  startTime:       new BN(0),               // すぐに開く
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool created at", extInfo.address.poolId.toBase58());
console.log("Tx:", txId);
```

SDK が静かに処理するいくつかのこと：

- ミントを token0/token1 の順序にソートしてから PDA を導出します。
- 1 回限りの `create_pool_fee` を `poolFeeAccount` に支払います。
- 呼び出し元の関連トークンアカウントが不足している場合は作成します。
- 各側で正しいトークンプログラム（SPL Token vs Token-2022）を選択します。

<Note>
  **`createPool` は `Initialize` を構築するため、プールのクリエイターフィーはオフです。** クリエイターフィーを有効にしたプールを作成するには、`InitializeV2`（2026-10-30 プログラムアップグレードで追加）を使用してください。最初の 19 アカウントは `Initialize` と一致します。`rent` を除外し、引数を 1 つ追加で取ります：`creator_fee_on: Option<CreatorFeeOn>`。このページの `0.2.64-alpha` ピンはこのインストラクションより前のものです。お使いの SDK バージョンがビルダーを提供するまでは、更新された IDL からエンコードしてください。[`products/cpmm/instructions`](/ja/products/cpmm/instructions#initializev2) を参照してください。
</Note>

確認後、ライブプール状態を取得できます：

```ts
// getPoolInfoFromRpc は位置引数の base58 文字列を取ります。PublicKey ではなく、オブジェクトでもありません。
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## スワップ（ベース入力）

ソース：[`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // base58 文字列

// 1. RPC から直接現在のプール状態を読み込みます（API からではなく）。
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // A → B をスワップ
const amountIn   = new BN(100_000_000);                   // 0.1 SOL
const slippage   = 0.005;                                 // 0.5%

// 2. ローカルで見積もります。CurveCalculator はオンチェーン数学をミラーします。
//    どちらの側でも Token-2022 転送フィーを含みます。8 つの引数すべてが必要です。
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult フィールドは inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount です。
// destinationAmountSwapped や sourceAmountSwapped はありません。

// 3. 構築して送信します。ここで `slippage` を渡すことが、バウンドを適用するものです。
//    手動の最小出力計算は必要ありません。
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Swap tx:", txId);
```

注意：SDK は常に `getPoolInfoFromRpc` 内から RPC のプール状態を再フェッチします。署名しようとしているトランザクションの `api-v3.raydium.io` から見積もらないでください。1 ブロック古い見積もりは、ランド時に `ExceededSlippage` にスリップする可能性があります。

## リクイディティのデポジット

ソース：[`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity は入力金額によって駆動されます。LP 金額ではなく。
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // 数値ではなく Percent です

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount は mintA で表示されます
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

SDK はプールの現在のリザーブから対になった金額を導出し、各側をスリッページで膨らませて命令の `maximum_*` 引数にし、必要に応じて ATA 作成を構築します。`raydium.cpmm.computePairAmount({ ... })` は UI プレビュー用に同じ数値を返します。

## プロトコル/ファンド/クリエイターフィーの回収

ソース：[`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts)、[`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

プロトコルおよびファンドの回収は権限ゲートで保護されています。クリエイターフィーには 2 つのパスがあります：クリエイター署名の `CollectCreatorFee` と、任意のペイヤーが呼び出せるが、クリエイターの正規 ATA にのみ転送できる `CollectCreatorFeePermissionless` です。`0.2.64-alpha` では、両方のクリエイターパスに対するモジュールレベルのビルダーが提供されます：

```ts
// クリエイター署名
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// パーミッションレス — 任意のペイヤー；収益はクリエイターの正規 ATA に送付
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 複数のプール一度に、クリエイター署名
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Warning>
  **両方のクリエイター命令は 2026-09-19 のプログラムアップグレードでアカウントリストが変更されました。** 各命令は `["creator_fee_share", creator, ammConfig]` の `creator_fee_share` PDA を取得し、パーミッションレス版は `amm_config` も取得します — どちらも **`system_program` の後に追加** されるため、既存のアカウントは位置が変わりません。アップグレード前の SDK リリースにピン留めされたビルダーは短いリストを出力し、トランザクションはアカウント不足で拒否されます。これらのヘルパーをアップグレード済みプログラムに対して使用する前に、インストールするバージョンが新しいアカウントを含んでいることを確認し、IDL から生成する場合は IDL をリフレッシュしてください。

  PDA の渡却は、それが作成されたことがない場合でも必須です — PDA を導出して渡してください；プログラムはアカウントが空の場合、`AmmConfig.creator_fee_share_rate` にフォールバックします。
</Warning>

<Note>
  2 つのクリエイター命令は **異なるディスクリミネータとアカウントレイアウト** を持ちます — パーミッションレス版はクリエイター署名者を別の `payer` と署名しない `creator` に置き換えます。一方のアカウントを手動で入れ替えるのではなく、マッチングビルダーを使用してください。

  SDK にはプロトコルフィーまたはファンドフィーのビルダーがありません（`makeCollectProtocolFeeInstruction` と `makeCollectFundFeeInstruction` はどの名前でも存在しません）— これらは管理者パスであり、`CreateCreatorFeeShare` / `CloseCreatorFeeShare` も同様にビルダーがありません。存在する低レベル命令ビルダーは `collectCpFeeInstruction`、`makeCollectCreatorFeeInstruction`、`collectCreatorFeePermissionlessInInstruction` です。
</Note>

オフチェーンでは、`PoolState` から直接蓄積されたフィーを読み取ることができます：

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // base58 文字列
console.log("蓄積されたプロトコルフィー mintA:", pool.protocolFeesMintA.toString());
console.log("蓄積されたプロトコルフィー mintB:", pool.protocolFeesMintB.toString());
// CpmmPoolInfoLayout フィールドは protocolFeesMintA/B、fundFeesMintA/B、
// creatorFeesMintA/B です — ...Token0/...Token1 フィールドはありません。
//
// creatorFeesMintA/B は*総*蓄積です。クリエイターは回収時に解決されたプロトコル
// シェアを差し引いた額を受け取ります；protocolFeesMintA/B はそのシェアを受け取る
// ため、スワップだけでなくクリエイターフィー回収でも増加します。
// products/cpmm/fees#protocol-share-of-the-creator-fee を参照してください。
```

## Rust CPI スケルトン

独自の Anchor プログラムから CPMM を呼び出したい場合（例えば、デポジターの代わりにスワップを実行するボールト）、CPI コンテキストは次のようになります。アカウント順序は [`products/cpmm/instructions`](/ja/products/cpmm/instructions) に従います。

```rust
// Cargo.toml — `master` は anchor-lang =1.0.2 にピン留めされています。
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "master", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // raydium-cp-swap がピン留めしているものと一致する必要があります
// anchor-spl       = "=1.0.2"
//
// `cpi` フィーチャーが必須です — `raydium_cp_swap::cpi` モジュールはこれの下でのみ
// 存在します。products/clmm/code-demos の CLMM サンプルは独自の `master` で同じ
// =1.0.2 にピン留めされているため、2 つのプログラムで共有できます。

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: CPMM プログラムで検証
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: リングバッファ
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0 はここでプログラムの Pubkey を取得します。AccountInfo ではなく。
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

CPI が PDA として署名する場合（例えば、デポジターの代わりにボールトを管理する場合）、`CpiContext::new` を `CpiContext::new_with_signer` に置き換えてシードを渡してください。

## よくある落とし穴

サポートチケットを開く前の簡単なチェックリスト：

- **ソート済みミント。** 導出した `poolState` PDA がオンチェーンプールと一致しない場合、ミントのソートを忘れた可能性があります。
- **古い API クォート。** `api-v3.raydium.io` からのリザーブ値を `CurveCalculator.swap` に渡さないでください。RPC から取得してください。
- **間違ったトークンプログラム。** Token-2022 ミントのボールトは SPL Token ではなく Token-2022 プログラムが所有しています。常にプールの `token_0_program` / `token_1_program` フィールドを使用してください。
- **転送フィーミントに対して過小評価されたスリッページ。** プールのどちらかが Token-2022 転送フィーミントの場合、`minimum_amount_out` はボールトが送信する額ではなく、ユーザーが実際に受け取る額で評価される必要があります。
- **スワップで `NotApproved`。** `PoolState.status` を確認してください — 管理者がそのプールのスワップを一時停止している可能性があります。ステータスビットマスクについては [`products/cpmm/instructions`](/ja/products/cpmm/instructions) を参照してください。
