## インベントリ

AMM v4 プールは作成時に 1 つのバインドされたマーケットを `AmmInfo` に記録します。全体像は以下の通りです：

| カテゴリ | アカウント | オーナー | 役割 |
|----------|---------|-------|------|
| プール | `AmmInfo` | AMM v4 プログラム | プール状態：蓄積されたフィー、ステータス、ボルトへの参照（およびレガシー フィールドとしてマーケット）。 |
| プール | `amm_authority` | AMM v4 プログラム | プログラム所有の PDA。ボルト移動に署名します。すべての AMM v4 プール間で共有されます。 |
| プール | `amm_open_orders` | OpenBook | レガシー `OpenOrders` 参照。現在のプログラムによって作成も読み取りもされず、新規プールにはすべて `AmmInfo.open_orders = Pubkey::default()` が書き込まれます。実際の値を持つのは OpenBook 削除前に作成されたプールのみです。v1 レイアウトでは今も位置的に渡されます。 |
| プール | `amm_target_orders` | AMM v4 プログラム | レガシー ターゲット オーダー アカウント。`WithdrawPnl`（アカウント #10）から今も参照されていますが、グリッドは構築されません。 |
| プール | `pool_coin_token_account` | SPL Token | プールのコイン側ボルト（`amm_authority` の ATA）。 |
| プール | `pool_pc_token_account` | SPL Token | プールの pc 側ボルト。 |
| プール | `lp_mint` | SPL Token | ファンジブル LP ミント。 |
| レガシー（OpenBook） | `serum_market` | OpenBook | バインドされたマーケット。v1 レイアウトで渡されますが、もう検証も使用もされません。 |
| レガシー | `serum_bids`、`serum_asks` | OpenBook | ビッド/アスク キュー。無視されます。 |
| レガシー | `serum_event_queue` | OpenBook | 保留中のイベント。無視されます。 |
| レガシー | `serum_coin_vault`、`serum_pc_vault` | SPL Token | マーケット レベルのボルト。無視されます。 |
| レガシー | `serum_vault_signer` | OpenBook | マーケット レベルの PDA。無視されます。 |

注：「serum」プレフィックスは、後方互換性のため AMM v4 の IDL とフィールド名に保持されています。これらのアカウントは OpenBook 削除後、もう機能していません。

## `AmmInfo`

プールのルート状態アカウント。プールと OpenBook 参照の両方をインラインで保持するため、大きい（≈ 752 バイト）です。

```rust
// programs/amm/src/state.rs (abridged; field order / names follow the IDL)
pub struct AmmInfo {
    pub status: u64,           // bitmask: swap/deposit/withdraw/crank enabled
    pub nonce:  u64,           // bump used to derive amm_authority
    pub order_num: u64,
    pub depth: u64,
    pub coin_decimals: u64,
    pub pc_decimals:   u64,
    pub state:         u64,    // internal state machine
    pub reset_flag:    u64,
    pub min_size:      u64,
    pub vol_max_cut_ratio: u64,
    pub amount_wave: u64,
    pub coin_lot_size: u64,    // legacy (OpenBook lot size); now initialized to 0
    pub pc_lot_size:   u64,    // legacy; now initialized to 0
    pub min_price_multiplier: u64,
    pub max_price_multiplier: u64,
    pub sys_decimal_value: u64,

    pub fees: Fees,            // trade/protocol/fund fee rates
    pub state_data: StateData,

    // Pool-owned accounts:
    pub coin_vault: Pubkey,
    pub pc_vault:   Pubkey,
    pub coin_vault_mint: Pubkey,
    pub pc_vault_mint:   Pubkey,
    pub lp_mint:  Pubkey,
    pub open_orders: Pubkey,   // pool's OpenOrders on OpenBook
    pub market: Pubkey,        // OpenBook market
    pub market_program: Pubkey, // OpenBook program ID
    pub target_orders: Pubkey,
    pub padding1: [u64; 8],     // reserved — NOT withdraw_queue / lp_vault
    pub amm_owner: Pubkey,      // admin (multisig)
    pub lp_amount: u64,         // the pool's internal LP total; see the note below
    pub client_order_id: u64,
    pub recent_epoch: u64,
    pub padding2: u64,
}

pub struct Fees {
    pub min_separate_numerator:   u64,     // 5
    pub min_separate_denominator: u64,     // 10_000
    pub trade_fee_numerator:      u64,     // 25  → used by OpenBook integration
    pub trade_fee_denominator:    u64,     // 10_000
    pub pnl_numerator:            u64,     // 12  → protocol's share OF the swap fee
    pub pnl_denominator:          u64,     // 100 → so 12/100 = 12% of fee, = 0.03% of volume
    pub swap_fee_numerator:       u64,     // 25  → 0.25% gross swap fee
    pub swap_fee_denominator:     u64,     // 10_000
}

pub struct StateData {
    pub need_take_pnl_coin: u64,        // still updated — accrued protocol fee (coin side)
    pub need_take_pnl_pc:   u64,        // still updated — accrued protocol fee (pc side)
    pub total_pnl_pc:   u64,            // DEPRECATED — no longer updated
    pub total_pnl_coin: u64,            // DEPRECATED — no longer updated
    pub pool_open_time: u64,            // still used — pool open timestamp
    pub padding: [u64; 2],              // reserved
    pub orderbook_to_init_time: u64,    // DEPRECATED — no longer updated
    pub swap_coin_in_amount: u128,      // DEPRECATED — volume counters frozen
    pub swap_pc_out_amount:  u128,      // DEPRECATED
    pub swap_acc_pc_fee:    u64,        // DEPRECATED
    pub swap_pc_in_amount:  u128,       // DEPRECATED
    pub swap_coin_out_amount: u128,     // DEPRECATED
    pub swap_acc_coin_fee:  u64,        // DEPRECATED
}
```

<Note>
  構造体の **レイアウトは変更されていません**（バイト互換）ため、既存のデシリアライザーは動作し続けますが、OpenBook 削除後、上記の `DEPRECATED` とマークされたフィールドは **もう書き込まれません** — `swap_*` ボリューム カウンターは最後の値で凍結されます。ボリューム分析には、これらのフィールドではなくトレード ログを使用してください。`need_take_pnl_*` と `pool_open_time` のみがアクティブに保持されます。
</Note>

インテグレーター向けフィールド：

- **`coin_vault`**、**`pc_vault`** — プールの SPL Token ボルト。`coin` は Serum/OpenBook 規約により `token_0`（ベース）、`pc` は `token_1`（クォート）です。
- **`coin_decimals`**、**`pc_decimals`** — ミントに対応します。
- **`open_orders`**、**`target_orders`**、**`market`** — レガシー参照フィールド。`AmmInfo` には今も存在し、v1 命令レイアウトでは今も位置的に渡されますが、プログラムはもう読み取りも検証もしません。V2 スワップ エントリポイントはこれらを省略します。
- **`fees.swap_fee_numerator / swap_fee_denominator`** — 合計トレード フィー。デフォルト `25 / 10_000 = 0.25%`。
- **`status`** — 操作をゲートする単一の列挙された `u64` 状態であり、ビットマスクでは **ありません**。`SetParams` の `param = 0`（`Status`）経由で管理者が設定可能です。下記の[ステータス](#status)を参照してください。
- **`lp_amount`** — プール内部の LP 合計。これは `lp_mint.supply` と等しく **ありません**：ちょうど LP トークン 1 枚分（`10^coin_decimals` ベース単位）だけ大きい値です。その分は init 時に計上されるものの、実際にはミントされないためです。プログラム内のすべての比例計算は `lp_amount` を使用するため、あなたもこれを使用してください。
- **`amm_owner`** — 作成時に、クリエーターではなくプログラムにハードコードされた管理者キーから書き込まれます。
- **`state_data.need_take_pnl_*`** — 蓄積された総フィーと掃引されたもの間のデルタ。`TakePnl` はこれらをゼロにします。

## OpenBook 配線

<Note>
  **削除されました。** OpenBook / Serum 依存関係はプログラムから削除されました（2026-07 アップグレード）。このセクションで説明されているアカウントはもう検証または使用されません。`AmmInfo` の参照フィールドおよびレガシー v1 命令レイアウトの位置プレースホルダーとして残ります。**V2 スワップ エントリポイント**（[`SwapBaseInV2` / `SwapBaseOutV2`](/ja/products/amm-v4/instructions)）を使用してください。これらのアカウントを完全にスキップします。
</Note>

レガシー **v1** `SwapBaseIn` / `SwapBaseOut`、`Deposit`、または `Withdraw` 命令を呼び出すとき、アカウント **数** は古いレイアウトと一致する必要があります（マーケット アカウントは歴史的位置を占めます）が、その **内容はもう確認されません** — CPI は発行されません。新しいコードは V2 スワップ バリアントを使用する必要があります。これらはこれらのアカウントをまったく取りません。

```ts
const market = ...;  // OpenBook market PublicKey

// Fields OpenBook exposes on its market account:
const marketDecoded = OpenBookMarket.decode(marketAccountData);
const {
  bids:           serumBids,
  asks:           serumAsks,
  eventQueue:     serumEventQueue,
  requestQueue:   serumRequestQueue,
  baseVault:      serumCoinVault,
  quoteVault:     serumPcVault,
  vaultSignerNonce,
} = marketDecoded;

const serumVaultSigner = PublicKey.createProgramAddressSync(
  [market.toBuffer(), u64ToBytes(vaultSignerNonce)],
  OPENBOOK_PROGRAM_ID,
);
```

AMM の `amm_open_orders` は OpenBook 所有のアカウント。このマーケット上のプールのリミット オーダー状態を保持します：アクティブなオーダー、決済残高、リファラーなど。`amm_target_orders` は AMM 側：プログラムが現在ポストされているものと安価に比較でき、差分をプレイス / キャンセルできるように、AMM の *意図された* グリッド（各オーダー スロットの価格/サイズ）を保持します。

## オーソリティ PDA

AMM v4 プログラム全体に対して、正確に 1 つの `amm_authority` PDA があります。そのシードは単純です（`["amm authority"]`）。そのバンプはすべての `AmmInfo` に保存されます。このオーソリティはすべての AMM v4 プールのすべてのトークン移動に署名します。

```ts
const AMM_V4_PROGRAM_ID = new PublicKey(
  "675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8",
);
const [ammAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("amm authority")],
  AMM_V4_PROGRAM_ID,
);
```

2 つ目のプール スコープのオーソリティは存在しません：この 1 つの PDA が、プログラムが署名するすべてをカバーします。そのバンプはメインネットでは `254` で、すべての `AmmInfo` の `nonce` にミラーされます。`WithdrawExcessLamports` はその nonce をハードコードして再導出します。

## ボルト

プールの SPL Token ボルトは、`owner` が `amm_authority` である標準的なトークン アカウントです。ATA ではありません — それらのアドレスは `Initialize2` の時点で `[AMM_V4_PROGRAM_ID, market, "coin_vault_associated_seed"]` および `[AMM_V4_PROGRAM_ID, market, "pc_vault_associated_seed"]` から導出される PDA です。ミントはシードではなく、`amm_id` もシードではありません。アドレスは `AmmInfo` に保存されます。導出は 1 回限りの好奇心です。

Token-2022 は **サポートされていません**。プログラムはすべてのボルト移動に対して SPL Token のプログラム ID をハードコードします。AMM v4 プールを Token-2022 ミントにバインドしようとすると、`Initialize2` で `InvalidSplTokenProgram` により失敗します。

## LP ミント

オーソリティが `amm_authority` である古典的な SPL Token ミント。総供給はプールの LP 所有権を追跡します。LP を焼却すると、両方のボルトからトークンが比例的に返されます。

状態内のミラーは **存在します**：`AmmInfo.lp_amount` です。これはミントの供給とは等しくありません — ちょうど LP トークン 1 枚分（`10^coin_decimals` ベース単位）だけ大きい値です。その分は init 時に計上されるものの、実際にはミントされないためです。プログラム内のすべての比例計算は `lp_amount` で除算するため、ミントのオンチェーン供給ではなくこのフィールドを使用してください。

## ステータス

`AmmInfo.status` は単一の列挙された `u64` 状態であり、ビットマスクでは **ありません**。等価性でテストしてください — `status & 1` でテストするクライアントは、通常のトレード状態が `6` でビット 0 が立っているため、稼働中のプールをすべて誤分類します。

| 値 | `AmmStatus` | スワップ | デポジット | 引き出し |
|-------|-------------|------|---------|----------|
| 0 | `Uninitialized` | いいえ | いいえ | いいえ |
| 1 | `Initialized` | はい | はい | はい |
| 2 | `Disabled` | いいえ | いいえ | いいえ |
| 3 | `WithdrawOnly` | いいえ | いいえ | はい |
| 4 | `LiquidityOnly` | いいえ | はい | はい |
| 5 | `OrderBookOnly` | いいえ | はい | はい |
| 6 | `SwapOnly` | はい | はい | はい |
| 7 | `WaitingTrade` | はい（`pool_open_time` を過ぎてから） | はい | はい |

`Initialize2` は `open_time` が未来なら `7`、そうでなければ `6` を書き込みます。`7` のプールは `state_data.pool_open_time` 以降の最初のスワップで自身を `6` に切り替えます。`0..=7` の範囲外の値は `AmmStatus::from_u64` をパニックさせます。

Raydium マルチシグは `SetParams` の `param = 0`（`Status`）経由で状態を設定します。受け付けられる値は `1`〜`7` のみです。（`AdminCancelOrders` は削除されました。）

## オブザベーション / オラクル

**AMM v4 には専用のオブザベーション アカウントがありません**。また、OpenBook の削除以降、それを導出できるオーダーブックの状態も存在しません。プログラム サポート付きの Raydium TWAP が必要な場合は、CPMM または CLMM を使用してください — どちらも `ObservationState` リング バッファを維持しています。それ以外の場合は、スワップ ログをオフチェーンでインデックスしてください。

## スクラッチからプールのアカウントを導出する

AMM v4 のプール アカウントは、バインドされたマーケットをキーとする素の PDA です — シード キーペアでも、ペアごとの PDA でもありません。そのすべてが `AMM_V4_PROGRAM_ID` の下で同じ 3 シード構造 `[AMM_V4_PROGRAM_ID, market, <label>]` を使用します：

| Account | `<label>` |
|---------|-----------|
| `amm_id` (`AmmInfo`) | `"amm_associated_seed"` |
| `amm_target_orders` | `"target_associated_seed"` |
| `lp_mint` | `"lp_mint_associated_seed"` |
| `pool_coin_token_account` | `"coin_vault_associated_seed"` |
| `pool_pc_token_account` | `"pc_vault_associated_seed"` |

```ts
const [ammId] = PublicKey.findProgramAddressSync(
  [
    AMM_V4_PROGRAM_ID.toBuffer(),
    marketPubkey.toBuffer(),
    Buffer.from("amm_associated_seed"),
  ],
  AMM_V4_PROGRAM_ID,
);
```

バインドされたマーケットが唯一の可変シードであり、そのため 1 つのマーケットはちょうど 1 つの AMM v4 プールに対応します。SDK と API はこれらを事前計算します。`raydium-sdk-v2` の `Liquidity.getAssociatedPoolKeys` を参照してください。

実際には、インテグレーターは `GET https://api-v3.raydium.io/pools/info/ids?ids=<POOL_ID>` または SDK からプールの完全なアカウント セットを読み取ります。手動導出はめったに必要ありません。
