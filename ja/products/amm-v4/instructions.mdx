## `SwapBaseIn`

正確な入力スワップ。常に**AMM パス**スワップです（OpenBook マッチングを通じてルーティングされません）。

<Note>

**前提条件**

- `amm.status` はスワップを許可します（ステータスビットマスクのビット 0 が設定されていません）。
- `amm.state_data.pool_open_time <= now`。
- `amount_in > 0`。

**事後条件**

- ユーザーはソーストークンの `amount_in` を失い、デストトークンの `amount_out ≥ minimum_amount_out` を獲得します。

**一般的なエラー** — `ExceededSlippage`、`InvalidInput`、`InvalidStatus`、`NotAllowed`（coin/pc ミント同一）。

## `WithdrawExcessLamports`

プログラムが制御するアカウント上のレント免除最小値を超えるラムポートのスイープを管理します。[SIMD-0437 レント削減](/ja/solana-fundamentals/rent-and-reclaimable-rent)が各ステップの前に作成されたアカウントに残す過剰資金を回復するために、2026-09 アップグレードで追加されました。

過剰分のみを移動します。トークン残高、アカウントデータ、所有者、およびプール状態は変わりません。命令は既に最小値にあるアカウントでは no-op です — したがって、繰り返し実行し、各ロールアウトステップ後に再度実行するのは安全です。

**引数** — なし。ペイロードは単一のタグバイト `18` です。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|------|
| 1 | `collect_lamports` | W | S | すべてのスイープされたラムポートの宛先。クラスタの collect-lamports ウォレットと等しい必要があります — [`reference/program-addresses`](/ja/reference/program-addresses#excess-lamports-collection-wallets) を参照してください。他の署名者は `InvalidSignAccount` で失敗します。 |
| 2 | `amm_authority` |   |   | 単一の AMM v4 権限 PDA。プログラムによって `["amm authority"]` から固定ノンス 254 で再導出されます。トークンプログラム CPI に署名します。 |
| 3 | `token_program` |   |   | **SPL Token。** `spl_token::id()` に対してチェックされます。間違った値は `InvalidSplTokenProgram` で失敗します。 |
| 4.. | ソースアカウント | W |   | スイープする `M` アカウント、任意の数、任意の順序。 |

**各ソースアカウントの処理方法**

プログラムはソースアカウントの `owner` でディスパッチします：

| ソースアカウント所有者 | 処理 |
|---|---|
| SPL Token、`data_len == 165`（トークンアカウント）、非ネイティブ | CPI `WithdrawExcessLamports`（トークンプログラム判別式 `38`）、`amm_authority` で署名。 |
| SPL Token、`data_len == 165`、ネイティブ（wSOL） | `WithdrawExcessLamports` はネイティブアカウントでは使用できません。プログラムは CPI `SyncNative`、ラップされた `amount` がどれだけ増加したかを測定、`UnwrapLamports`（判別式 `45`）をその正確なデルタに対して実行し、ラップされた残高が同期前の値に戻ったことをアサートします — そうでなければ `LamportsCalculateError`。プールの SOL 側リクイディティは決して触れられません。 |
| SPL Token、その他のサイズ（LP ミント） | CPI `WithdrawExcessLamports`、`amm_authority` で署名。 |
| AMM v4 プログラム自体（`AmmInfo`、`TargetOrders`、`AmmConfig`、引き出しキュー） | プログラムはアカウントを `rent.minimum_balance(data_len)` まで直接デビットします。 |
| その他 | **サイレントにスキップ。** エラーなし、ラムポート移動なし。 |

**一般的なエラー** — `InvalidSignAccount`（間違った署名者）、`InvalidSplTokenProgram`（スロット 3 の間違ったプログラム）、`InvalidProgramAddress`（間違った `amm_authority`）、`LamportsCalculateError`（カスタムコード `60`；wSOL ラウンドトリップはゼロに正味化されませんでした）、およびプログラム所有パスからの `InsufficientFunds`（アカウントが独自のレント最小値より少ない場合）。

**SDK ビルダーなし。** `@raydium-io/raydium-sdk-v2` はこの命令のビルダーを出荷しません。`raydium-sdk-V2-demo` リポジトリも同様です — これは管理者パスです。手動でエンコードしてください。[`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) のウォレット側スイープが行うのと同じ方法で。
