LaunchLab トークンが CPMM に移行すると、プールは LP トークンをミントします。2026-08-14 アップグレード前は、`creatorScale` はトークンクリエイター向けに個別にロックされていました。アップグレード後に実行された移行では、`migrateCpLockNftScale` は依然として 3 つのフィールドを保持し、合計は `1_000_000` になりますが、ランタイムは 2 つの宛先のみを生成します。

## 実効的な分割

| フィールド | 更新後の動作 |
|---|---|
| `platformScale` | プラットフォーム所有のロック LP シェアに含まれます。 |
| `creatorScale` | アップグレード前は、クリエイター所有の Fee Key をミントしていました。アップグレード後は、プラットフォーム所有のロック LP シェアに含まれます。 |
| `burnScale` | 永続的にバーンされます。このシェアを表す Fee Key はありません。 |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

`burnScale` がゼロの場合、プラットフォームはすべての LP ユニットを受け取ります。`effectivePlatformScale` がゼロの場合、すべての LP がバーンされ、プラットフォーム Fee Key は作成されません。

## 例

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% プラットフォーム所有ロック LP、10% バーン。
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// 更新されたプログラムでは、これは 100% プラットフォーム所有ロック LP を生成します。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% バーン；Fee Key なし。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## CPMM クリエイターフィーとの関係

スケールフィールドは LP 所有権のみを制御します。スワップフィーレートを設定したり、CPMM クリエイターフィーの受取人を識別したりすることはありません。`cpConfigId` は CPMM `AmmConfig` を選択し、`platformCpCreator` は CPMM プールが元のローンチクリエイターを記録するか、プラットフォーム選択のアドレスを記録するかを決定します。

## 分割の更新

プラットフォームを更新する前に：

- 3 つの値の合計が正確に `1_000_000` であることを確認してください。
- `platformScale + creatorScale` を実効的なプラットフォームシェアとして提示してください。
- `creatorScale` に基づくクリエイター Fee Key を約束しないでください。
- アップグレード前に完了した移行によって示されるクリエイター Fee Key 所有権を保持してください。これらのレコードは書き直されません。
- 将来のローンチが更新されたコンフィグを使用する前に、変更を説明してください。
