## 概要

`PlatformConfig` アカウントはプラットフォームの 5 つの横断的な関心事を管理します：

1. **ブランディング** — 名前、ウェブサイト、画像リンク。すべてインラインで保存されるため、エクスプローラーやアグリゲーターはトークンをローンチしたプラットフォームを表示できます。
2. **プラットフォームフィー** — プロトコルの `trade_fee_rate` の上に追加されるトレードフィー（`fee_rate`）。プラットフォームの `platform_fee_wallet` に蓄積されます。作成と更新の両方で 500 bps（`50000`）に制限されており、2026-08-26 に 100 bps（`10000`）から引き上げられました。[レート上限](#レート上限)を参照してください。
3. **LP 移行分割** — 3 つの保存された整数（`platform_scale`、`creator_scale`、`burn_scale`）で合計 `1_000_000` になります。2026-08-17 アップグレード前は、クリエイター スケールが別のクリエイター Fee Key を生成していました。アップグレード後に実行された移行は、最初の 2 つをプラットフォーム所有のロック LP シェアに統合し、残りはバーンされます。
4. **カーブパラメータホワイトリスト** — `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)` の組み合わせのうち、このプラットフォームで許可されているものを正確にリストアップする `Vec<PlatformCurveParam>`。ベクトルが空であるか、すべてのエントリが無効な場合、**任意の**組み合わせが許可されます。それ以外の場合、ローンチはエントリの 1 つと正確に一致する必要があります。
5. **グローバルコンフィグ許可リスト** — 選択した `GlobalConfig` に対してプラットフォーム作成の `PlatformAllowConfig` を要求するオプトイン制限。

PDA 導出：

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // platform's owning pubkey
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

（正規のシードリストについては、ソースの `create_platform_config` を参照してください。）

## レイアウト

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (denominator 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (denominator 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // signs ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // receives the platform NFT slice at CPMM graduation
    pub platform_scale:              u64,               // share of LP minted to platform NFT
    pub creator_scale:               u64,               // creator share before upgrade; added to platform share afterward
    pub burn_scale:                  u64,               // share of LP burned permanently
    pub fee_rate:                    u64,               // platform's trade fee (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 padded with zeros
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig that the post-grad pool will bind to
    pub creator_fee_rate:            u64,               // creator-side fee taken pre-graduation
    pub transfer_fee_extension_auth: Pubkey,            // for Token-2022 launches: withdraw-withheld authority from mint creation, fee-config authority from graduation
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // platform's slice of total_locked_amount
    pub platform_cp_creator:         Pubkey,            // optional creator-of-record on the post-graduation CPMM pool
    pub restrict_global_config:      u8,                // 0 = unrestricted, 1 = require allow PDA
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // whitelist of permitted curve shapes
}
```

`platform_scale + creator_scale + burn_scale` は `1_000_000` に等しくなければなりません。2026-08-17 アップグレード前は、`creator_scale` は別にロックされ、その Fee Key はトークンクリエイターに送られました。アップグレード後に実行された移行では、`platform_scale` に追加され、ロック LP 権はプラットフォームに移ります。更新されたロジックの下での例：

- `(0, 100_000, 900_000)` — 90% LP バーン、10% プラットフォームにロック。
- `(50_000, 100_000, 850_000)` — 85% バーン、15% プラットフォームにロック。
- `(0, 0, 1_000_000)` — 完全バーン、NFT ミントなし。厳密な「インサイダーなし」ローンチ。

## ブランディングフィールド

`name`、`web`、`img` はインラインバイト配列で、サイズ定数までゼロでパディングされています。文字列として読み込むには、最初の `\0` までスライスします：

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

定数は意図的に寛容です（`name: 64`、`web: 256`、`img: 256`）。プラットフォームはオフチェーンストレージに触れることなく、エクスプローラーやアグリゲーター向けに十分なメタデータを含めることができます。これらのサイズを超えるものは `CreatePlatformConfig` で `InvalidInput` で戻ります。

## フィーメカニクス

`PlatformConfig` にバインドされたカーブ上のスワップは、3 層のフィーを請求します：

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` はプロトコルの `protocol_fee_owner` に蓄積されます（`CollectFee` で請求）。
- `platform_fee` はプラットフォームごとのボールトに蓄積されます（`ClaimPlatformFee` または `ClaimPlatformFeeFromVault` で請求。[`instructions`](/ja/products/launchlab/instructions)を参照）。
- `creator_fee` はクリエイターの公開鍵 + クォートミントでキーされたクリエイターごとのボールトに蓄積されます（`ClaimCreatorFee` で請求）。

### レート上限

両方のレートは `1/1_000_000` で表示されるため、`5000` は 50 bps、`50000` は 500 bps です。

| レート | 上限 | 適用場所 |
|---|---|---|
| `fee_rate` | `50000`（500 bps） | 作成時の `PlatformParams::check()` — `InvalidInput` で戻ります。更新時の `update_platform_fee_rate`（`FeeRate` と `AllInfo` など、これに触れるすべての更新バリアント） — `InvalidPlatformInfo` で戻ります。 |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000`（50 bps） | 作成時の `create_platform_config` と更新時の `update_creator_fee_rate` — 両方とも `InvalidPlatformInfo` で戻ります。 |

`fee_rate` の 2 つの適用ポイントは異なるファイル内の別の `require!` 呼び出しなので、異なるエラーコードを持ちますが、同じ上限を適用します。許可されたレートで作成されたプラットフォームは後で編集できます。これには、すべてのフィールドを一度に書き直す `AllInfo` バルク バリアントも含まれます。

両方の `fee_rate` 上限は元々 100 bps（`10000`）でした。更新上限は 2026-01-27 に `25000`（250 bps）に移動し、2026-08-26 に両方とも `50000`（500 bps）に移動しました。[チェンジログエントリ](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)を参照してください。

`GlobalConfig.max_share_fee_rate` はどちらのレートも制限**しません**。4 つのスワップ命令が取る per-transaction `share_fee_rate` 引数（リファラルフィー）を制限するだけです。[`global-config`](/ja/products/launchlab/global-config#fees)を参照してください。

## Token-2022 トランスファーフィー権限

`transfer_fee_extension_auth` は、トランスファーフィーが付加された `InitializeWithToken2022` を通じてローンチが作成されるときに、ベースミントの `TransferFeeConfig` 権限を保持することになるプラットフォームキーを指定します。拡張機能は 2 つの権限を持ち、ローンチライフサイクルの**異なるポイント**で引き渡されます：

| 権限 | ミント作成時の保有者 | `MigrateToCpswap` 後の保有者 |
|---|---|---|
| `withdraw_withheld_authority` — Token-2022 がトークンアカウントで保留するフィーを引き出します | `transfer_fee_extension_auth`。ミントに直接書き込まれます。フィールドが `Pubkey::default()` の場合、ローンチ `authority` PDA にフォールバックします。 | 既にプラットフォームキーなので、何も移動しません。移行は `authority` PDA がまだ保持している場合にのみ再割り当てします。 |
| `transfer_fee_config_authority` — フィーレートと最大フィーを変更します | 常にローンチ `authority` PDA。 | `transfer_fee_extension_auth`。ただし、そのフィールドがデフォルト以外の場合。 |

2026-08-27 前は、ミントは両方の権限で `authority` PDA を使用して作成され、両方とも卒業時にプラットフォームに移動しました。プログラムは withdraw-withheld または harvest 命令を公開していないため、ボンディングカーブフェーズ中に保留されたフィーは、ローンチが卒業するまでアクセスできませんでした。ミント作成時に withdraw 側を書き込むと、最初のトレードから請求可能になります。[チェンジログエントリ](/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority)を参照してください。

計画する価値のある 2 つの結果：

- **ローンチ後ではなく、前にフィールドを設定してください。** `transfer_fee_extension_auth` が `Pubkey::default()` の間に作成されたローンチは、`authority` PDA を withdraw 側に配置します。後でフィールドを設定することはまだ機能します — 卒業は PDA を所定の位置に見つけ、権限を引き渡します — しかし、その間、保留されたバランスを引き出すことはできません。
- **ローンチ中にフィールドを回転させると、2 つの権限が分割されます。** ローンチの作成と卒業の間で `transfer_fee_extension_auth` を変更すると、ミントの withdraw-withheld 権限は作成時に設定されたキーに留まり（PDA はそれを保持しなくなるため、移行はその引き渡しをスキップします）、フィー設定権限は新しいキーに移動します。ローンチ間で回転させるか、Token-2022 を直接使用して 2 つのキーを自分で調整する計画を立ててください。

フィールドを `Pubkey::default()` のままにしておくプラットフォームは、ローンチの全生涯にわたって両方の権限を `authority` PDA に永続的に保持します。フィーレートは変更できず、保留されたバランスは引き出せません。トランスファーフィーをローンチに付加するのは、プラットフォームがこれらのキーを保持する意図がある場合のみです。

## NFT 移行分割（CPMM のみ）

ローンチが CPMM に卒業すると、移行命令は `CPMM::InitializeWithPermission` によってミントされた LP トークンを 2 つの方法に分割します：

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

`lp_to_platform` がゼロ以外の場合、LP-Lock プログラムはそれを `platform_nft_wallet` が所有する 1 つの Fee Key NFT にラップします。これは、別のプラットフォームとクリエイター Fee Key を作成したアップグレード前の動作に置き換わります。アップグレード前に完了した移行によって作成された Fee Key は変更されません。この LP フィー権は `platform_cp_creator` によって制御される CPMM クリエイターフィーとは別です。

バーンスライスは直接バーンされるため、アカウントはそれを引き出したり、そのシェアで表されるLP フィーを請求したりすることはできません。

保存された `migrate_type = 0` を持つ既存のローンチは、レガシー AMM v4 パスを使用できます。新しい初期化はその移行タイプを拒否します。

## カーブパラメータホワイトリスト

`curve_params: Vec<PlatformCurveParam>` は、プラットフォームがそのローンチが選択できるカーブ形状を制限するメカニズムです。ベクトルが空でなく、少なくとも 1 つのエントリが有効な場合、プログラムは `Initialize` でローンチのパラメータが少なくとも 1 つのエントリと正確に一致することを強制します。

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // ordinal within this platform's whitelist
    pub global_config:        Pubkey,       // which GlobalConfig this entry applies to
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // new launches require 1 = CPMM; u8::MAX = wildcard
    pub migrate_cpmm_fee_on:        u8,    // 0 = quote-only, 1 = both. u8::MAX = wildcard
    pub supply:                     u64,   // 0 = wildcard
    pub total_base_sell:            u64,   // 0 = wildcard
    pub total_quote_fund_raising:   u64,   // 0 = wildcard
    pub total_locked_amount:        u64,   // u64::MAX = wildcard
    pub cliff_period:               u64,   // u64::MAX = wildcard
    pub unlock_period:              u64,   // u64::MAX = wildcard
}
```

各フィールドには**ワイルドカード**を意味するセンチネル値があります（任意の値が一致）：`u64` フィールドの場合は `u64::MAX`、`u8` フィールドの場合は `u8::MAX`、supply / sell / fund-raising フィールドの場合は `0`。すべてのセンチネルを持つ `BondingCurveParam` は「すべてを許可」です — 空のホワイトリスト動作と同等です。

`Initialize` でのマッチングアルゴリズム：

1. `curve_params` をフィルタリングして、`global_config` がローンチの選択した `GlobalConfig` と一致するエントリを取得します。
2. フィルタリングされたリストが空の場合、任意のパラメータを許可します（プラットフォームはこの `GlobalConfig` に対して何もホワイトリストに登録していません）。
3. フィルタリングされたリストのすべてのエントリが `all_is_invalid()`（すべてのフィールドがワイルドカード）の場合、任意のパラメータを許可します。
4. それ以外の場合、エントリを反復処理します。各エントリについて、ローンチのパラメータをすべての非ワイルドカードフィールドに対してチェックします。すべての非ワイルドカードフィールドが一致する場合、受け入れて戻ります。
5. エントリが一致しない場合、`InvalidInput` で戻ります。

これにより、プラットフォームは「標準的な 1B-supply / 800M-sold / 30k-USDC-raise / no-vesting 形状のみを許可する」と言うことができます。これらの 4 つのフィールドに具体的な値を書き込み、他の場所にワイルドカードを書き込むことで、単一のエントリを作成します。または、より厳密なプラットフォームは、サポートされているローンチティアごとに 3 つまたは 4 つの離散形状を列挙する場合があります。

`MAX_CURVE_PARAMS = 10` はホワイトリストサイズを制限します。

## `PlatformAllowConfig` — プラットフォームの制限

各プラットフォームは、そのローンチが使用できる `GlobalConfig` アカウントを制限するかどうかを決定します。`restrict_global_config` を `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)` で設定します。

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

PDA シード：`[b"platform_allow_config", platform_config, global_config]`。

プラットフォーム管理者は、`CreatePlatformAllowConfig` と `ClosePlatformAllowConfig` を使用して、許可されたペアごとに 1 つのアカウントを作成または閉じます。制限が `1` の場合、初期化は `remaining_accounts` で予期される PDA を検索し、不足しているアカウントで `NotEnoughRemainingAccounts` を拒否します。制限が `0` の場合、許可アカウントは不要です。

以前のプロトコル管理者が管理していた `PlatformGlobalAccess` アカウントとその作成/閉じる命令は廃止されました。既存の `PlatformConfig` と `GlobalConfig` のサイズは変わりませんが、デコーダーは古いグローバルフラグを新しいプラットフォームフラグに置き換える必要があります。古いアクセス PDA は新しいチェックでは使用されません。

## よくある落とし穴

- **ホワイトリストセンチネルの誤設定。** `total_locked_amount = 0` を持つ `BondingCurveParam` はワイルドカード**ではなく**、明示的にベスティングをオプトアウトするローンチと一致します。そのフィールドのワイルドカードは `u64::MAX` です。同じ罠は `cliff_period` と `unlock_period` に存在します。`clear()`（プログラムが公開）を使用してセンチネルを正しく設定します。
- **NFT 分割の丸め。** 3 つのスケールは正確に `1_000_000` に合計される必要があります。`CreatePlatformConfig` での 1 オフエラーは戻ります。実行時での 1 オフは 1 つの余分な LP ユニットをミントまたはバーンします。これが厳密な等価性チェックが存在する理由です。
- **プラットフォームベスティングの二重配分。** `platform_vesting_scale > 0` の場合、プラットフォームはローンチの資金調達終了後に `CreatePlatformVestingAccount` を 1 回呼び出す必要があります。忘れた場合、そのシェアは未割り当てで永遠に休止したままになります（ローンチの `total_locked_amount` 予算は消費されますが、プラットフォームは請求しません）。
- **`platform_cp_creator` の曖昧性。** `Pubkey::default()` に設定されている場合、ローンチクリエイターは卒業後の CPMM プールの `pool_creator` として記録されます。実際のキーに設定されている場合、そのキーが代わりに記録されます。これは卒業後の CPMM クリエイターフィーの受益者と、元の `CPMM::CollectCreatorFee` パスに署名できるユーザーを決定します。パーミッションレス収集パスは、このレコードされたキーの正規 ATA に支払います。プラットフォーム設定作成時にどのモデルを使用するかを決定します。
- **`transfer_fee_extension_auth` が遅く設定されるか回転される。** フィールドは Token-2022 ローンチごとに 2 回読み込まれます — ミント作成時に `withdraw_withheld_authority` 用、卒業時に `transfer_fee_config_authority` 用 — そのため、これら 2 つの瞬間の間に変わる値は、2 つの権限を異なるキーに残します。[Token-2022 トランスファーフィー権限](#token-2022-トランスファーフィー権限)を参照してください。
- **許可アカウントなしの制限。** 必要な `PlatformAllowConfig` を作成する前に `restrict_global_config` を有効にすると、そのコンフィグを選択する新しいローンチがブロックされます。
