## `PoolState`

ローンチごとのルート状態。以下のフィールド名はオンチェーン Rust 構造体（`states/pool.rs`）と一致します。一部の値は読みやすさのために簡略化されています。正確なメモリレイアウトについてはソースを参照してください。

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus` の値（Anchor IDL から）：

```
0 = Funding         — buys / sells を受け入れ中。quote_reserve_target 以下
1 = Migrate         — quote_reserve_target に到達。MigrateTo* を待機中
2 = Migrated        — MigrateTo* 既に実行済み。ベスティングクロック実行中
```

インテグレーター向けフィールド：

- **`status`** — 3 つの値、単調（Funding → Migrate → Migrated）。読み取りは常に安全。書き込みはゲート制御されます。
- **`real_base`**、**`real_quote`** — 現在のカーブ状態。`virtual_base` / `virtual_quote` と組み合わせると、ヴォルトにアクセスせずにスポット価格を計算するのに十分です。[`bonding-curve`](/ja/products/launchlab/bonding-curve) を参照してください。
- **`total_base_sell`** vs `real_base` — UI 用の「グラデュエーションへの進捗」比率。
- **`migrate_type`** — 新しい初期化には `1`（`CPSWAP`）が必要です。保存された `0` は、CPMM のみの強制が行われる前に作成された既存のローンチに対してのみ意味があります。
- **`amm_creator_fee_on`** — ポストグラデュエーション CPMM プールで `creator_fee_on = OnlyQuoteToken`（`0`）または `BothToken`（`1`）を選択します。マイグレーションターゲットを選択しません。[`creator-fees`](/ja/products/launchlab/creator-fees) を参照してください。
- **`token_program_flag`** — ブール値ではなくビットフィールド。Bit0 はベースミント、Bit1 はクォートミント。各々 SPL Token の場合は `0`、Token-2022 の場合は `1`。バイトは 4 つの値を取ります：`0`（両方レガシー）、`1`（Token-2022 ベース）、`2`（Token-2022 クォート）、`3`（両方 Token-2022）。1 つのミントを読み取るには `(token_program_flag >> bit) & 1` を使用します。バイト全体を `0` と比較してベースミントを分類すると、`2` が間違ったプログラムに解決されます。Bit1 は Token-2022 クォートミントがサポートされるまで常に `0` でした。
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — 3 つの独立したフィーカウンター。各々に独自のクレーム命令があります。[`instructions`](/ja/products/launchlab/instructions) を参照してください。
- **`vesting_schedule`** — すべての `PoolState` に存在しますが、`total_locked_amount == 0` の場合は非アクティブです。完全なライフサイクルについては [`vesting`](/ja/products/launchlab/vesting) を参照してください。

## オーソリティ PDA

LaunchLab は、ローンチごとのシードなしで、すべてのローンチ全体で **単一** のオーソリティ PDA を使用します：

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // reference/program-addresses を参照

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

その単一 PDA は：

- すべてのローンチの `base_vault` と `quote_vault` のオーソリティ。
- 各ローンチの `base_mint` の `mint_authority`（グラデュエーション前）。
- CPMM グラデュエーション CPI の署名者、および既存の状態のレガシー AMM v4 グラデュエーション。
- `ClaimVestedToken` がベースヴォルトから転送する際の署名者。
- Token-2022 ベースミントの `TransferFeeConfig` の `transfer_fee_config_authority`。プレグラデュエーション期間全体。および `withdraw_withheld_authority` も、ただしプラットフォームが `PlatformConfig.transfer_fee_extension_auth` を設定しなかった場合のみ。

`mint_authority` は `MigrateToCpswap` またはレガシー `MigrateToAmm` 呼び出しの直後に取り消されるため、供給は永久に固定されます。

2 つの追加 PDA がフィーヴォルトをゲート制御します：

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

これらは `ClaimCreatorFee` と `ClaimPlatformFeeFromVault` 中に対応するフィーヴォルトから転送する際に署名します。

## ベースミント

`Initialize` によってインラインで作成されます：

- `mint_authority = authority`（グラデュエーション時に取り消し）。
- `freeze_authority = None`。
- `supply = supply`。完全に `base_vault` にミントされます。
- `decimals` はクリエーターが `Initialize` で選択（通常 6）。

完全な供給がプレミントされるため、`base_mint.supply` はローンチの存続期間中は定数です。カーブの買いは `base_vault` からバイヤーにトークンを移動しますが、`mint_to` は呼び出しません。

`Initialize` / `InitializeV2` は SPL Token ベースミントを作成します。専用の `InitializeWithToken2022` 命令により、ベースミントを Token-2022 ミント（オプションの `TransferFeeConfig` 付き）にできます。3 つの初期化パスすべてが CPMM グラデュエーションを必要とします。

`InitializeWithToken2022` が `TransferFeeConfig` をアタッチする場合、ミントは `transfer_fee_config_authority = authority` と `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` で作成され、プラットフォームがそのフィールドを設定していない場合は `authority` にフォールバックします。両方のオーソリティはグラデュエーション時にプラットフォームキーに再割り当てされます。引き出し側は PDA がまだ保有している場合のみです。[`platform-config`](/ja/products/launchlab/platform-config#token-2022-transfer-fee-authorities) を参照してください。

クォートミントはベースミントから独立しており、それ自体が Token-2022 ミントである可能性があります。`InitializeV2` と `InitializeWithToken2022` はクォートプログラムスロットでどちらのプログラムも受け入れます。非推奨の `Initialize` はそうではありません。そのクォートプログラムアカウントは依然として SPL Token に型付けされているため、クォートミントが Token-2022 である設定は他の 2 つを通じてのみ起動できます。クォートミントは LaunchLab によって作成されることはありません。`GlobalConfig.quote_mint` が指定するものです。[`global-config`](/ja/products/launchlab/global-config#token-2022-quote-mints) と [`reference/token-2022-support`](/ja/reference/token-2022-support#launchlab-quote-mints) を参照してください。

## ヴォルト

`base_vault` と `quote_vault` の両方は LaunchLab `authority` PDA によって所有されるトークンアカウントで、各々は独自のミントを所有するプログラムで作成されます。したがって、ローンチはレガシーベースヴォルトと Token-2022 クォートヴォルト、または他の任意の組み合わせを持つことができます。`token_program_flag` はどちらがどちらかを記録します。アドレスは `PoolState` に保存され、また導出することもできます：

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

（本番環境での導出に依存する前に、ソースの `Initialize` アカウント構造体から正確なシードプレフィックスを確認してください。）

## フィーヴォルト

2 つの PDA がローンチ全体のフィーを集約します：

- **クリエーターフィーヴォルト** — シード `[creator, quote_mint]` の PDA。同じクォートミントで同じクリエーターフィーを獲得するすべてのローンチは同じヴォルトに流れ込みます。クリエーターは `ClaimCreatorFee` を通じてスイープします。
- **プラットフォームフィーヴォルト** — シード `[platform_config, quote_mint]` の PDA。同じプラットフォームを通じてルーティングされ、同じクォートミントを使用するすべてのローンチは同じヴォルトに流れ込みます。プラットフォームの `platform_fee_wallet` は `ClaimPlatformFeeFromVault` を通じてスイープします。また、ローンチごとのスイープバリアント（`ClaimPlatformFee`）もあり、集約ヴォルトを経由せずにローンチの `quote_vault` から直接プルします。

両方ともフィーを発生させる最初のスワップで遅延作成され、クォートミントを所有するプログラムで作成されます。クリエーターまたはプラットフォームがレガシーと Token-2022 クォートミントの両方に対してローンチを実行する場合、ミントごとに 1 つのヴォルトで終わります。これは 2 つの異なるレガシーミントの場合と同じです。

集約ヴォルトパターンにより、高ボリュームのクリエーターまたはプラットフォームは、多くのローンチ全体でフィー蓄積のレント コストを償却できます。

## クォートヴォルト ↔ `real_quote`

`quote_vault.balance` と `PoolState.real_quote` は同期を保つ必要があります。3 つの保留中のフィーカウンター（`quote_protocol_fee`、`platform_fee`、`migrate_fee`）の合計によって最大でドリフトする可能性があります。これらはヴォルトに存在しますが、フィーカウンターに属し、カーブリザーブには属しません。カーブ数学は常に `real_quote` を使用し、生のヴォルト残高は使用しません。

グラデュエーション前の不変式：

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## ライフサイクルアカウント遷移

| イベント | ステータス | `real_base` | `real_quote` | ポストグラデュエーションプール |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap`（またはレガシー `MigrateToAmm`） | Funding → Migrate → Migrated | （凍結） | （凍結） | 作成済み。CPMM LP はプラットフォーム所有のロック LP とバーン LP に分割 |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | any | — | — | フィーヴォルトをドレイン |
| `CreateVestingAccount` | Funding | — | — | `vesting_schedule.allocated_share_amount` をバンプ |
| `ClaimVestedToken` | Migrated only | — | — | `base_vault` をドレイン |
