## `PoolState`

ローンチごとのルート状態。以下のフィールド名はオンチェーン Rust 構造体（`states/pool.rs`）と一致します。一部の値は読みやすさのために簡略化されています。正確なメモリレイアウトについてはソースを参照してください。

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus` の値（Anchor IDL から）：

```
0 = Funding         — buys / sells を受け入れます。quote_reserve_target 未満
1 = Migrate         — quote_reserve_target に到達。MigrateTo* を待機中
2 = Migrated        — MigrateTo* は既に実行済み。ベスティングクロック実行中
```

インテグレーター向けフィールド：

- **`status`** — 3 つの値、単調（Funding → Migrate → Migrated）。読み取りは常に安全です。書き込みはゲートされます。
- **`real_base`**、**`real_quote`** — 現在のカーブ状態。`virtual_base` / `virtual_quote` と組み合わせると、ヴォルトに触れずにスポット価格を計算するのに十分です。[`bonding-curve`](/ja/products/launchlab/bonding-curve) を参照してください。
- **`total_base_sell`** vs `real_base` — UI の「グラデュエーションへの進捗」比率。
- **`migrate_type`** — 新しい初期化には `1`（`CPSWAP`）が必要です。保存された `0` は、CPMM のみの強制が適用される前に作成された既存のローンチに対してのみ意味があります。
- **`amm_creator_fee_on`** — ポストグラデュエーション CPMM プールで `creator_fee_on = OnlyQuoteToken`（`0`）または `BothToken`（`1`）を選択します。マイグレーションターゲットを選択しません。[`creator-fees`](/ja/products/launchlab/creator-fees) を参照してください。
- **`token_program_flag`** — ブール値ではなくビットフィールド。Bit0 はベースミント、Bit1 はクォートミント。各々 SPL Token の場合は `0`、Token-2022 の場合は `1` です。したがってバイトは 4 つの値を取ります：`0`（両方レガシー）、`1`（Token-2022 ベース）、`2`（Token-2022 クォート）、`3`（両方 Token-2022）。`(token_program_flag >> bit) & 1` で 1 つのミントを読み取ります。ベースミントを分類するために全バイトを `0` と比較すると、`2` が間違ったプログラムに解決されます。Bit1 は Token-2022 クォートミントがサポートされるまで定数 `0` でした。
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — 3 つの独立した手数料カウンター。各々に独自のクレーム命令があります。[`instructions`](/ja/products/launchlab/instructions) を参照してください。
- **`vesting_schedule`** — すべての `PoolState` に存在しますが、`total_locked_amount == 0` の場合は非アクティブです。完全なライフサイクルについては [`vesting`](/ja/products/launchlab/vesting) を参照してください。

## オーソリティ PDA

LaunchLab は、ローンチごとのシードなしで導出された、すべてのローンチ全体で**単一の**オーソリティ PDA を使用します：

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

その単一 PDA は：

- すべてのローンチの `base_vault` および `quote_vault` のオーソリティ。
- 各ローンチの `base_mint` の `mint_authority`（グラデュエーション前）。
- CPMM グラデュエーション CPI、および既存の状態のレガシー AMM v4 グラデュエーションの署名者。
- `ClaimVestedToken` がベースヴォルトから転送する際の署名者。
- Token-2022 ベースミントの `TransferFeeConfig` の `transfer_fee_config_authority`（グラデュエーション前フェーズ全体）。および `withdraw_withheld_authority` も、ただしプラットフォームが `PlatformConfig.transfer_fee_extension_auth` を設定していない場合のみ。

`mint_authority` は `MigrateToCpswap` またはレガシー `MigrateToAmm` 呼び出しの直後に取り消されるため、供給は永久に固定されます。

2 つの追加 PDA が手数料ヴォルトをゲートします：

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

これらは `ClaimCreatorFee` および `ClaimPlatformFeeFromVault` 中に対応する手数料ヴォルトから転送する際に署名します。

## ベースミント

`Initialize` によってインラインで作成されます：

- `mint_authority = authority`（グラデュエーション時に取り消し）。
- `freeze_authority = None`。
- `supply = supply`、完全に `base_vault` にミントされます。
- `decimals` はクリエーターが `Initialize` で選択（通常 6）。

完全な供給が事前にミントされるため、`base_mint.supply` はローンチの生涯を通じて定数です。カーブの買いはトークンを `base_vault` から買い手に移動しますが、`mint_to` を呼び出しません。

`Initialize` / `InitializeV2` は SPL Token ベースミントを作成します。専用の `InitializeWithToken2022` 命令により、ベースミントを Token-2022 ミント（オプションの `TransferFeeConfig` 付き）にできます。3 つの初期化パスすべてが CPMM グラデュエーションを必要とします。

`InitializeWithToken2022` が `TransferFeeConfig` をアタッチする場合、ミントは `transfer_fee_config_authority = authority` および `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` で作成され、プラットフォームがそのフィールドを設定していない場合は `authority` にフォールバックします。両方のオーソリティはグラデュエーション時にプラットフォームキーに再割り当てされます。引き出し側は PDA がまだ保有している場合のみです。[`platform-config`](/ja/products/launchlab/platform-config#token-2022-transfer-fee-authorities) を参照してください。

クォートミントはベースミントから独立しており、それ自体が Token-2022 ミントである可能性があります。`InitializeV2` および `InitializeWithToken2022` はクォートプログラムスロットでどちらのプログラムも受け入れます。非推奨の `Initialize` はそうではありません。そのクォートプログラムアカウントは依然として SPL Token に型付けされているため、クォートミントが Token-2022 である設定は他の 2 つを通じてのみ起動できます。クォートミントは LaunchLab によって作成されることはありません。`GlobalConfig.quote_mint` が指定するものです。[`global-config`](/ja/products/launchlab/global-config#token-2022-quote-mints) および [`reference/token-2022-support`](/ja/reference/token-2022-support#launchlab-quote-mints) を参照してください。

## ヴォルト

`base_vault` と `quote_vault` の両方は LaunchLab `authority` PDA によって所有されるトークンアカウントで、各々は独自のミントを所有するプログラムで作成されます。したがって、ローンチはレガシーベースヴォルトと Token-2022 クォートヴォルト、または他の任意の組み合わせを持つことができます。`token_program_flag` はどちらがどちらかを記録します。アドレスは `PoolState` に保存され、導出することもできます：

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

（本番環境での導出に依存する前に、ソースの `Initialize` アカウント構造体から正確なシードプレフィックスを確認してください。）

## 手数料ヴォルト

2 つの PDA がローンチ全体の手数料を集約します：

- **クリエーター手数料ヴォルト** — シード `[creator, quote_mint]` の PDA。同じクォートミントで同じクリエーター手数料を獲得するすべてのローンチが同じヴォルトに流れ込みます。クリエーターは `ClaimCreatorFee` を通じてスイープします。
- **プラットフォーム手数料ヴォルト** — シード `[platform_config, quote_mint]` の PDA。同じプラットフォームを通じてルーティングされ、同じクォートミントを使用するすべてのローンチが同じヴォルトに流れ込みます。プラットフォームの `platform_fee_wallet` は `ClaimPlatformFeeFromVault` を通じてスイープします。ローンチの `quote_vault` から直接引き出す、集約されたヴォルトを経由しないローンチごとのスイープバリアント（`ClaimPlatformFee`）もあります。

両方ともクォートミントを所有するプログラムで、手数料を発生させる最初のスワップで遅延作成されます。クリエーターまたはプラットフォームがレガシーと Token-2022 クォートミントの両方に対してローンチを実行する場合、2 つの異なるレガシーミントの場合と同様に、ミントごとに 1 つのヴォルトで終わります。

集約ヴォルトパターンにより、高ボリュームのクリエーターまたはプラットフォームは、多くのローンチ全体で手数料蓄積のレント コストを償却できます。

## クォートヴォルト ↔ `real_quote`

`quote_vault.balance` と `PoolState.real_quote` は同期を保つ必要があります。3 つの保留中の手数料カウンター（`quote_protocol_fee`、`platform_fee`、`migrate_fee`）の合計によって最大でドリフトする可能性があります。これらはヴォルトに存在しますが、手数料カウンターに属し、カーブリザーブには属しません。カーブ数学は常に `real_quote` を使用し、生のヴォルト残高は使用しません。

グラデュエーション前の不変式：

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## `PlatformCurveRule`

`(PlatformConfig, GlobalConfig)` ペアごとに 1 つのアカウント。そのプラットフォームがそのコンフィグで許可するローンチ形状を保有します。PDA シードは `[b"platform_curve_rule", platform_config, global_config]` です。

```rust
#[account]
pub struct PlatformCurveRule {
    pub bump:            u8,
    pub version:         u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub epoch:           u64,
    pub padding:         [u64; 8],
    pub groups:          Vec<CurveRuleGroup>,   // up to 10
}

pub struct CurveRuleGroup {
    pub group_id:    u16,                       // stable id, used to update or remove the group
    pub epoch:       u64,
    pub constraints: Vec<ParamConstraint>,      // up to 25, ANDed
}

pub struct ParamConstraint {
    pub field: u8,                              // which launch parameter
    pub op:    u8,                              // 0 Eq, 1 Gte, 2 Lte, 3 Neq
    pub value: u128,
}
```

アカウントはグループなしで作成され、グループ変更のたびにリサイズされるため、その長さは `150 + Σ(14 + 18 × constraints)` であり、デコーダーは固定サイズを想定してはいけません。グループは OR されます。1 つのグループの制約がすべて成立するとすぐに、ローンチが許可されます。ゼログループは制限がないことを意味します。

所有する `PlatformConfig.restrict_curve_param` が `1` の場合にのみ読み取ります。`0` の場合、プログラムはアカウントを無視し、古いルールがそこに存在する可能性があります。フィールド ID、オペレーター、およびプレイブックは [`products/launchlab/curve-rules`](/ja/products/launchlab/curve-rules) にあります。
