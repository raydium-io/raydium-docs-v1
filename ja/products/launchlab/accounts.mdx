## `PoolState`

ローンチごとのルート状態。以下のフィール名はオンチェーン Rust 構造体（`states/pool.rs`）と一致します。一部の値は読みやすさのために簡略化されています。正確なメモリレイアウトについてはソースを参照してください。

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit flags for SPL Token vs Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus` の値（Anchor IDL から）：

```
0 = Funding         — buys / sells を受け入れます。quote_reserve_target 未満
1 = Migrate         — quote_reserve_target に到達。MigrateTo* を待機中
2 = Migrated        — MigrateTo* は既に実行済み。ベスティングクロック実行中
```

インテグレーター向けフィール：

- **`status`** — 3 つの値、単調（Funding → Migrate → Migrated）。読み取りは常に安全です。書き込みはゲートされます。
- **`real_base`**、**`real_quote`** — 現在のカーブ状態。`virtual_base` / `virtual_quote` と組み合わせると、ヴォルトに触れずにスポット価格を計算するのに十分です。[`bonding-curve`](/ja/products/launchlab/bonding-curve) を参照してください。
- **`total_base_sell`** vs `real_base` — UI の「卒業への進捗」比率。
- **`migrate_type`** — 新しい初期化には `1`（`CPSWAP`）が必要です。保存された `0` は、CPMM のみの強制が適用される前に作成された既存のローンチに対してのみ意味があります。
- **`amm_creator_fee_on`** — ポスト卒業 CPMM プールで `creator_fee_on = OnlyQuoteToken`（`0`）または `BothToken`（`1`）を選択します。マイグレーションターゲットを選択しません。[`creator-fees`](/ja/products/launchlab/creator-fees) を参照してください。
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — 3 つの独立したフィーカウンター。それぞれ独自のクレーム命令があります。[`instructions`](/ja/products/launchlab/instructions) を参照してください。
- **`vesting_schedule`** — すべての `PoolState` に存在しますが、`total_locked_amount == 0` の場合は非アクティブです。完全なライフサイクルについては [`vesting`](/ja/products/launchlab/vesting) を参照してください。

## オーソリティ PDA

LaunchLab は、ローンチごとのシードなしで導出された、すべてのローンチ間で**単一の**オーソリティ PDA を使用します：

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

その単一 PDA は：

- すべてのローンチの `base_vault` と `quote_vault` のオーソリティ。
- 各ローンチの `base_mint` の `mint_authority`（卒業前）。
- CPMM 卒業 CPI、およびレガシー AMM v4 卒業の署名者。
- `ClaimVestedToken` がベースヴォルトから転送する際の署名者。

`mint_authority` は `MigrateToCpswap` またはレガシー `MigrateToAmm` 呼び出しの直後に取り消されるため、供給は永久に固定されます。

2 つの追加 PDA がフィーヴォルトをゲートします：

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

これらは `ClaimCreatorFee` と `ClaimPlatformFeeFromVault` 中に対応するフィーヴォルトから転送する際に署名します。

## ベースミント

`Initialize` によってインラインで作成されます：

- `mint_authority = authority`（卒業時に取り消し）。
- `freeze_authority = None`。
- `supply = supply`、完全に `base_vault` にミントされます。
- `decimals` は `Initialize` でクリエーターが選択（通常は 6）。

完全な供給が事前にミントされるため、`base_mint.supply` はローンチの存続期間中は定数です。カーブの買いは `base_vault` からバイヤーにトークンを移動しますが、`mint_to` を呼び出しません。

`Initialize` / `InitializeV2` は SPL Token ローンチを作成します。専用の `InitializeWithToken2022` 命令により、ベースミントを Token-2022 ミント（オプションの `TransferFeeConfig` 付き）にできます。クォートミントは依然として SPL Token です。3 つの初期化パスすべてが CPMM 卒業を必要とします。

## ヴォルト

`base_vault` と `quote_vault` の両方は、LaunchLab `authority` PDA が所有する標準 SPL Token アカウントです。アドレスは `PoolState` に保存され、導出することもできます：

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

（本番環境での導出に依存する前に、ソースの `Initialize` アカウント構造体から正確なシードプレフィックスを確認してください。）

## フィーヴォルト

2 つの PDA がローンチ間でフィーを集約します：

- **クリエーターフィーヴォルト** — シード `[creator, quote_mint]` の PDA。同じクリエーターが同じクォートミントで獲得したすべてのローンチは同じヴォルトに流れ込みます。クリエーターは `ClaimCreatorFee` を介してそれを回収します。
- **プラットフォームフィーヴォルト** — シード `[platform_config, quote_mint]` の PDA。同じプラットフォームを通じてルーティングされ、同じクォートミントを使用するすべてのローンチは同じヴォルトに流れ込みます。プラットフォームの `platform_fee_wallet` は `ClaimPlatformFeeFromVault` を介してそれを回収します。集約されたヴォルトを経由せずにローンチの `quote_vault` から直接引き出すローンチごとのスイープバリアント（`ClaimPlatformFee`）もあります。

集約ヴォルトパターンにより、高ボリュームのクリエーターまたはプラットフォームは、多くのローンチ間でフィー蓄積のレント コストを償却できます。

## クォートヴォルト ↔ `real_quote`

`quote_vault.balance` と `PoolState.real_quote` は同期を保つ必要があります。これらは 3 つの保留中のフィーカウンター（`quote_protocol_fee`、`platform_fee`、`migrate_fee`）の合計によって最大でドリフトする可能性があります。これらはヴォルトに存在しますが、フィーカウンターに属し、カーブリザーブには属しません。カーブ数学は常に `real_quote` を使用し、生のヴォルト残高は使用しません。

卒業前の不変式：

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## ライフサイクルアカウント遷移

| イベント | ステータス | `real_base` | `real_quote` | ポスト卒業プール |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap`（またはレガシー `MigrateToAmm`） | Funding → Migrate → Migrated | （凍結） | （凍結） | 作成済み。CPMM LP はプラットフォーム所有のロック LP とバーン LP に分割されます |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | any | — | — | フィーヴォルトをドレイン |
| `CreateVestingAccount` | Funding | — | — | `vesting_schedule.allocated_share_amount` をバンプ |
| `ClaimVestedToken` | Migrated のみ | — | — | `base_vault` をドレイン |
