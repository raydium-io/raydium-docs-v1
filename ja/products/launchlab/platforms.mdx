<Info>
  LaunchLabの**プラットフォーム**は、Raydiumの LaunchLab プログラムの上に構築されたサードパーティのローンチ環境です。プラットフォームは独自のブランディングを行い、独自の手数料を請求でき、独立したオンチェーンプログラムを実行することなく、プラットフォーム下で起動されるすべてのトークンのマイグレーション後のパラメータを構成できます。Raydium独自のローンチUIは、多くのプラットフォームの1つに過ぎません。
</Info>

## プラットフォームが存在する理由

Raydiumは LaunchLab を**共有プリミティブ**にしたいと考えていました。単一のブランド化された製品ではなく、プラットフォームPDAシステムにより、エコシステム、ツール提供者、コミュニティ、ミームチームが、すべて同じ基盤となるLaunchLabボンディングカーブプログラムとCPMM マイグレーション後プールに決済される、キュレーションされたまたはブランド化されたローンチ体験を提供できます。

実際に見かけるかもしれないプラットフォームの例：

- **Raydium独自のLaunchLab UI** (raydium.io/launchlab) — リファレンス実装。
- **パートナーローンチパッド** — 独自のプラットフォームPDAを登録してローンチ体験をブランド化したサードパーティ。
- **ニッチなプラットフォーム** — 例えば、特定のテーマに関連するミームコインのみを起動し、カスタム手数料シェアでトレジャリーに資金を提供するコミュニティ固有のプラットフォーム。

これらのトークンはすべて同じLaunchLabプログラムに存在し、同じCPMMプログラムに卒業し、同じアグリゲータでルーティングできます。

## プラットフォームPDA

各プラットフォームはLaunchLabプログラムに保存されたプラットフォームPDAで表されます。フィールドには以下が含まれます：

| フィールド | 説明 |
|---|---|
| `platform_key` | プラットフォームのシード/識別子。プラットフォームPDAの導出に使用されます。 |
| `platform_fee_destination` | マイグレーション前後の取引手数料のプラットフォーム分を受け取るアカウント。 |
| `platform_fee_bps` | マイグレーション前のスワップに対するプラットフォーム手数料シェア（プラットフォームによって異なります）。 |
| `creator_fee_rate` | ボンディングカーブ取引中のクリエイター手数料レート。 |
| `platform_scale`, `creator_scale`, `burn_scale` | 保存されたLPスケール。アップグレード前は、クリエイタースケールはクリエイターフィーキーに移動していました。その後に実行されたマイグレーションでは、最初の2つはプラットフォームのロック済みLP シェアに結合され、`burn_scale`はバーンされます。 |
| `cp_config_id` | マイグレーション後のターゲットがCPMMの場合、どの`AmmConfig`を使用するか — 手数料ティアを選択します。 |
| `restrict_global_config` | ローンチが選択された`GlobalConfig`のプラットフォーム作成許可PDAを提示する必要があるかどうか。 |
| `name`, `description`, `image_url` | ウォレットとプラットフォームブランディングをサポートするUIで使用される表示メタデータ。 |
| `tokens_launched` | このプラットフォーム下で作成されたトークンのカウンターまたはオンチェーンインデックス。 |

正確なフィールド名はLaunchLab IDL（[`sdk-api/anchor-idl`](/ja/sdk-api/anchor-idl)）にあります。上記の表は説明的な概要です。

## プラットフォームが制御できること

**手数料の取得：**

- マイグレーション前のすべての買い/売りに対する**プラットフォーム手数料シェア**。
- **マイグレーション後のシェア** — 2026-08-14アップグレード前は、クリエイタースケールは別のクリエイターフィーキーを生成していました。その後に実行されたマイグレーションでは、`platform_scale + creator_scale`が1つのプラットフォーム所有のロック済みLP ポジションになり、`burn_scale`はバーンされます。

**マイグレーション後の宛先：**

- `cp_config_id`で選択された`AmmConfig`を持つ**CPMM**。新しく初期化されたすべてのローンチはCPMMを使用します。
- **AMM v4** は、レガシーマイグレーションタイプで作成された既存のローンチ状態のマイグレーションパスとしてのみ残ります。

**ユーザー体験：**

- RaydiumアプリおよびラunchLabトークンをサーフェスするウォレット/エクスプローラーで使用される**ブランディングメタデータ**。
- **ローンチページのカスタマイズ** — 独自のフロントエンドをホストするプラットフォームは、トークンをフィルタリングして独自のプラットフォームのローンチのみを表示できます。

## プラットフォームが制御できないこと

- **ボンディングカーブの数学。** カーブの形状（ロジスティック、指数関数など）はLaunchLabプログラム自体の一部です。プラットフォームはサポートされているカーブから選択できます。任意のカスタムカーブを追加することはできません。
- **マイグレーション閾値ロジック。** CPMMへの卒業をトリガーする条件はプログラムで強制されます。
- **コアセキュリティ/監査体制。** すべてのプラットフォームはLaunchLabの監査履歴を継承します。悪意のあるプラットフォームはプログラムを変更することでそれをバイパスすることはできません。

## プラットフォームの登録

LaunchLabプログラムは`create_platform`命令を公開しています（IDLからの正確な名前）。呼び出し元は以下を渡します：

- プラットフォームPDAを導出するシード。
- 手数料宛先アカウント。
- 希望する手数料bps（プログラムレベルの上限の対象）。
- マイグレーション後の構成（該当する場合はCPMM `AmmConfig` ID）。
- ブランディングメタデータ。

プラットフォームPDAのレントは作成者によって支払われます。ブランディングと一部の手数料パラメータの更新は、プラットフォームの権限によって作成後に許可されます。構造パラメータ（マイグレーション宛先プログラム）は通常許可されません。

現在のLaunchLab IDLの正確な命令署名については、[`products/launchlab/instructions`](/ja/products/launchlab/instructions)を参照してください。

## 経済的相互作用

LaunchLabボンディングカーブの単一スワップは、大まかに次のように価値を分配します（正確な比率はプラットフォームによって設定されます）：

```
買い手が支払う：           100 SOL
プロトコル手数料（LaunchLab）: – 小さい %
プラットフォーム手数料：    – platform_fee_bps%
クリエイター手数料（マイグレーション前）: – creator_fee_bps%（有効な場合）
残り（カーブへ）：         ~ 残り
```

マイグレーション後、LPトークンには2つの有効な宛先があります：

```
卒業時に鋳造されたLPトークン：  100%
  → バーン：                      burnScale
  → プラットフォームフィーキー：  platformScale + creatorScale
```

プラットフォームフィーキーは、ロック済みリクイディティを引き出す能力なしに請求可能なLP手数料権を表します。バーンされたLPにはフィーキーホルダーがありません。

## グローバル構成の制限

プラットフォーム管理者は`restrict_global_config = 1`を設定し、受け入れられた各`GlobalConfig`に対して1つの`PlatformAllowConfig`を作成できます。新しいローンチトランザクションは、一致する許可PDAを追加する必要があります。制限が無効な場合、プラットフォームはプログラムの他の検証に合格するすべての構成を受け入れます。

## インテグレータ向けメモ

- **プラットフォーム別のトークンのリスト。** API プール情報/ミントエンドポイントを`platform`フィルタ（サポートされている場合）と共に使用して、特定のプラットフォームPDA下で起動されたトークンのみをリストします。
- **ブランディング表示。** LaunchLabトークンをサーフェスするウォレットまたはエクスプローラーを構築する場合、プラットフォームPDAからプラットフォームの名前/画像URLを読み取ることは、すべてのトークンに対して「LaunchLab」を表示するよりもはるかに優れたUXです。
- **手数料計算。** すべてのボンディングカーブクォートは、プロトコルおよびクリエイター手数料に加えてプラットフォーム手数料を考慮する必要があります。SDKのクォートヘルパーは、プラットフォームPDAが提供されるときにこれを自動的に行います。
