「ExactIn/ExactOut」の分割は CPMM の `SwapBaseInput` / `SwapBaseOutput` をミラーします — オンチェーンでは、わずかに異なるラウンディングを持つ別の命令ディスクリミネータです。

**卒業パス選択。** すべての新しい `InitializeV2` と `InitializeWithToken2022` 呼び出しは `migrate_type = 1`（`CPSWAP`）を設定する必要があります。新しい AMM v4 バウンドプールを初期化しようとすると `MigrateTypeNotMatch` が返されます。`amm_creator_fee_on` は、結果の CPMM 作成者手数料がクォートトークンに適用されるか両方のトークンに適用されるかのみを選択します。ターゲットプログラムを選択しません。従来の `Initialize` はもはやローンチを作成できません（下記を参照）。

`MigrateToAmm` は、この制限の前に `migrate_type = 0` で初期化された既存の `PoolState` に対して呼び出し可能なままです。このリリースは既存のプール状態を書き直したり、従来の命令を削除したりしません。

**クォート側トークンプログラム。** クォートミントは SPL Token プログラムまたは Token-2022 のいずれかが所有できます。それに触れるすべての命令 — `CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、4 つのトレード命令すべて、`CollectFee`、`CollectMigrateFee`、`ClaimCreatorFee`、`ClaimPlatformFee`、`ClaimPlatformFeeFromVault` — は、クォートプログラムアカウントスロットで所有プログラムを取ります。アカウント位置は変わりませんでした。受け入れられた値のみが変わりました。実際に `GlobalConfig.quote_mint` を所有するプログラムを渡してください。これは既存のローンチの場合 `PoolState.token_program_flag` ビット 1 から読み取ることができます（[`accounts`](/ja/products/launchlab/accounts#poolstate)を参照）。または、ミントアカウントの所有者から読み取ることができます。

非推奨の `Initialize` はここでは無関係です：そのクォートプログラムアカウントは依然として SPL Token に型付けされており、2026-09 アップグレード以降、命令はアカウントを読む前に失敗します。`InitializeV2` または `InitializeWithToken2022` を通じてローンチしてください。

`MigrateToCpswap` は反対方向の例外です — 1 つではなく両方のプログラムを無条件に取ります。[下記のマイグレーションアカウント](#cpmm-migration-token-programs)を参照してください。

## `Initialize`

<Warning>
  **2026-09 アップグレード以降、実質的に削除されました — この命令は常に失敗します。** `initialize` のハンドラは、`Not supported. Please use initialize_v2 instruction` と `NotApproved`（`6000`）のログだけです。ディスクリミネータを占有したままにして IDL が安定した形を保つためだけに保持されています。（`Accounts` 構造体は変わらないため、Anchor の生成された検証は最初に実行されます。トランザクションは関係なく戻ります。）

  以前は、クロックでゲートされていました：`get_upgrade_timestamp` カットオーバーの 3 日後まで機能し、その後失敗しました。そのタイムスタンプヘルパーはなくなったため、失敗は無条件になりました。それを通じて作成された既存のローンチは影響を受けません — それらは `MigrateToAmm` または `MigrateToCpswap` を通じて正常にトレードおよび卒業します。これは、保存された `migrate_type` に依存します。

  以下の引数とアカウントリストは `InitializeV2` のものです。非推奨の `Initialize` は同じ 18 個の
  アカウントを同じ順序で取り、最初の 3 つの引数のみを取ります — `amm_fee_on` はありません — そして
  その `quote_token_program` スロットは `Interface<TokenInterface>` ではなく SPL Token 型です。
</Warning>

新しいローンチを作成します。`InitializeV2` は非推奨の `Initialize` に対して `amm_fee_on` 引数のみを追加します。アカウントの **数と順序は同一** で、アカウント レベルでの唯一の違いは `quote_token_program` が `Interface<TokenInterface>` 型であり、Token-2022 のクォートミントが受け入れられることです。

**引数**

1 つの構造体ではなく、4 つの位置引数です。（`InitializeWithToken2022` は 5 つ目として `transfer_fee_extension_param: Option<TransferFeeExtensionParams>` を追加します。非推奨の `Initialize` は `amm_fee_on` を持ちません。）

```rust
base_mint_param: MintParams {
    decimals: u8,                 // must equal the program's BASE_MINT_DECIMALS
    name:     String,
    symbol:   String,
    uri:      String,
}

curve_param: CurveParams {        // Borsh enum — one leading variant-tag byte
    Constant { data: ConstantCurve { supply: u64, total_base_sell: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Fixed    { data: FixedCurve    { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Linear   { data: LinearCurve   { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
}

vesting_param: VestingParams {
    total_locked_amount: u64,     // 0 requires cliff_period == unlock_period == 0
    cliff_period:        u64,     // seconds after fundraising ends
    unlock_period:       u64,     // seconds
}

amm_fee_on: AmmCreatorFeeOn       // 0 = QuoteToken, 1 = BothToken (CPMM migrations only)
```

バリアントは `global_config.curve_type` と一致しなければならず、そうでなければ命令は `InputNotMatchCurveConfig`（`6003`）で失敗します。`open_time` はなく、`quote_mint` 引数もなく（それは `global_config` から来ます）、`fees` 構造体も `post_graduation_lp_policy` もありません — LP の処理はローンチごとではなく `PlatformConfig` で設定されます。

**アカウント** — 合計 18 個（宣言済み 16 個に加え、`#[event_cpi]` が追加する 2 個）

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | すべてのレントを支払います。クリエイターである必要はありません。 |
| 2 | `creator` |   |   | `pool_state.creator` として記録されます。署名者ではありません。 |
| 3 | `global_config` |   |   | クォートミント、カーブタイプ、およびすべての下限/上限を供給します。 |
| 4 | `platform_config` |   |   | プラットフォーム手数料率と LP 処理ポリシーを供給します。 |
| 5 | `authority` |   |   | PDA `["vault_auth_seed"]` — すべてのローンチで共有される 1 つのグローバル PDA。 |
| 6 | `pool_state` | W |   | 新しいアカウント。 |
| 7 | `base_mint` | W | S | 新しいキーペア — この命令がそれを初期化します。 |
| 8 | `quote_mint` |   |   | `global_config.quote_mint` と等しい必要があります。 |
| 9 | `base_vault` | W |   | PDA `["pool_vault", pool_state, base_mint]`。 |
| 10 | `quote_vault` | W |   | PDA `["pool_vault", pool_state, quote_mint]`。 |
| 11 | `metadata_account` | W |   | Metaplex メタデータ PDA。 |
| 12 | `base_token_program` |   |   | `InitializeV2` では SPL Token。`InitializeWithToken2022` では Token-2022。 |
| 13 | `quote_token_program` |   |   | `quote_mint` を所有するプログラム — SPL Token または Token-2022。 |
| 14 | `metadata_program` |   |   | Metaplex Token Metadata。 |
| 15 | `system_program` |   |   | |
| 16 | `rent_program` |   |   | Rent sysvar。 |
| 17 | `event_authority` |   |   | PDA `["__event_authority"]`。`#[event_cpi]` によって追加されます。 |
| 18 | `program` |   |   | LaunchLab プログラム ID。`#[event_cpi]` によって追加されます。 |

**前提条件**

- `quote_mint ∈ launch_config.allowed_quote_mints`。
- `base_supply_graduation ≤ base_supply_max`。
- 手数料パラメータは `launch_config.max_*_fee_rate` チェックに合格します。
- `open_time ≥ now − slop`（SDK は `≥ now` を強制します。プログラムはわずかなバックデートを許容します）。
- `curve_type` は認識されます。

**事後条件**

- `base_mint` は `supply = curve_param.supply` を持ち、すべて `base_vault` にあります。
- ミント権限は、供給がミントされた直後に、この同じ命令内で **取り消されます**（`set_authority(MintTokens, None)`） — 卒業時ではありません。したがってベースミントは恒久的に固定供給であり、後続のどの命令も追加でミントできません。
- `PoolState` は `status = Fund`（`0`）、`real_a = 0`、`real_b = 0` で初期化されます。
- `total_fund_raising_b` は `curve_param.total_quote_fund_raising` からそのまま来ます。
- `InitializeWithToken2022` が `TransferFeeConfig` を添付している場合：`transfer_fee_config_authority = launch_authority`、および `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`（そのフィールドが設定されている場合）、それ以外は `launch_authority`。引き出し側は、プラットフォームが卒業前に保留中の手数料をスイープできるように、ミント作成時に書き込まれます。[`platform-config`](/ja/products/launchlab/platform-config#token-2022-transfer-fee-authorities)を参照してください。

**一般的なエラー** — `NotApproved`（`6000`、非推奨の `Initialize` では無条件）、`InvalidInput`（`6002`、`GlobalConfig` の供給量 / レート / 資金調達の下限に違反）、`InputNotMatchCurveConfig`（`6003`、`curve_param` のバリアントが `global_config.curve_type` と一致しない）、`MigrateTypeNotMatch`（`6007`、`migrate_type != 1`）、`MathOverflow`（`6008`）、`VestingRatioTooHigh`（`6010`）、`NoSupportExtension`（`6017`）、`NotEnoughRemainingAccounts`（`6018`）、`InvalidPlatformAllowConfig`（`6022`）、`CurveParamNotMatchPlatformRule`（`6025`）。Anchor の `address =` / `constraint =` チェックの失敗は、これらではなく 2xxx コードとして現れます — `InvalidQuoteMint`、`FeeRateTooHigh`、`InvalidCurveParams` はいずれもプログラムのエラー列挙型に存在しません。

## `Buy`（正規バリアント：`BuyExactIn`）

ユーザーは固定の入力額を提供します。カーブが出力を計算します。

**引数**

```
amount_in:           u64
minimum_amount_out:  u64
share_fee_rate:      u64   // referral fee on a 1_000_000 denominator; must be
                           // <= global_config.max_share_fee_rate. Pass 0 for no
                           // referral. Any non-zero value requires the share-fee
                           // receiver as remaining_accounts[0].
```

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | トレーダー。 |
| 2 | `authority` |   |   | PDA `["vault_auth_seed"]` — 1 つのグローバル PDA で、ローンチごとのシードはありません。 |
| 3 | `global_config` |   |   | `address = pool_state.global_config`。 |
| 4 | `platform_config` |   |   | `address = pool_state.platform_config`。 |
| 5 | `pool_state` | W |   | |
| 6 | `user_base_token` | W |   | `token::mint = base_token_mint`。 |
| 7 | `user_quote_token` | W |   | `token::mint = quote_token_mint`。 |
| 8 | `base_vault` | W |   | `address = pool_state.base_vault`。 |
| 9 | `quote_vault` | W |   | `address = pool_state.quote_vault`。 |
| 10 | `base_token_mint` |   |   | |
| 11 | `quote_token_mint` |   |   | |
| 12 | `base_token_program` |   |   | ベースミントを所有するプログラム — SPL Token または Token-2022。 |
| 13 | `quote_token_program` |   |   | クォートミントを所有するプログラム。 |
| 14 | `event_authority` |   |   | PDA `["__event_authority"]`。`#[event_cpi]` によって追加されます。 |
| 15 | `program` |   |   | LaunchLab プログラム ID。`#[event_cpi]` によって追加されます。 |

**残りのアカウント** — 手数料の配管で、正確にこの順序で読み取られます：

1. `share_fee_receiver` — `share_fee_rate > 0` の場合 **のみ**。
2. `system_program` — 常に必要。`== System::id()` がチェックされ、そうでなければ `InvalidInput`。
3. `platform_fee_vault` — PDA `[platform_config, quote_token_mint]`。初回使用時に作成されます。
4. `creator_fee_vault` — PDA `[creator, quote_token_mint]`。初回使用時に作成されます。

不足すると `NotEnoughRemainingAccounts`（`6018`）が返ります。`associated_token_program` のスロットは
存在せず、`system_program` は宣言済みアカウントではなく *残りの* アカウントです。

**前提条件**

- `launch_state.status == Active`。
- `now ≥ open_time`。
- `user_quote_ata.balance ≥ quote_in`。
- `quote_in > 0`。

**効果**

1. `quote_in` を `quote_in_after_fee` と手数料部分に分割します。
2. ポストフィー クォートが与えられたカーブに対して Newton-solve で `base_out` を求めます。
3. `require(base_out ≥ minimum_base_out)` そうでなければ `ExceededSlippage` で戻ります。
4. `quote_in` ユーザー → ボルトを移動します。`base_out` ボルト → ユーザーを移動します。
5. `base_sold += base_out`、`quote_reserve_real += quote_in_after_fee × (lp_share / total_share)` を更新します。
6. 手数料カウンタ（`protocol_fees_quote`、`creator_fees_quote`）を更新します。
7. `state_data.num_buys += 1`。
8. 更新後に `quote_reserve_real ≥ quote_reserve_target` の場合、SDK は通常、同じトランザクション内で `Graduate` ix をチェーンします。プログラムは `Buy` 内で自動卒業しません — 後続の `Graduate` が必要です。

## `BuyExactOut`

ユーザーは正確な `base_out` を指定します。プログラムは `quote_in` を計算します。

**引数**

```
amount_out:         u64
maximum_amount_in:  u64
share_fee_rate:     u64   // as for BuyExactIn
```

`BuyExactIn` と同じアカウント、そして同じ残りアカウントの契約です。Newton 反復ではなく、閉じた形の二次積分（または curve_type 1 の場合は CPMM 逆）を使用します。

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy` のミラー。ユーザーは `base_in` をカーブに返し、`quote_out` を受け取ります。手数料は `quote_out` から差し引かれるため、ユーザーは生の統合収益より少なく受け取ります。

**前提条件** —

- `user_base_ata.balance ≥ base_in`。
- 売却は `base_sold` を 0 以下に押し下げることはできません（会計が一貫している場合、上記と冗長）。
- ローンチは `Active` です。

**効果** — `Buy` に対称的です。`base_sold` は減少し、`quote_reserve_real` は減少します。手数料は依然として発生します。

### クォート側転送手数料

クォートミントが `TransferFeeConfig` を持つ場合、ボルトが移動する金額と支払者が請求または貸方される金額は異なり、スリッページ境界は支払者側に対してチェックされます。転送手数料拡張なしのクォートミントでは、以下のすべてのケースは通常のレガシーミントと同じです。

| 命令 | 引数 | チェック対象 |
|---|---|---|
| `BuyExactIn` | `amount_in` | カーブは `amount_in − transfer_fee(amount_in)` で価格設定されます — ボルトに到達するもの。完全な充填は正確に `amount_in` を請求します。部分的な充填は消費されたボルト金額とその逆手数料を請求します。 |
| `BuyExactOut` | `maximum_amount_in` | ボルト金額**プラス**逆転送手数料 — 実際の請求。 |
| `SellExactIn` | `minimum_amount_out` | 売り手がミントの手数料を差し引いた後に保持するもの。ボルトを離れる総額ではありません。 |
| `SellExactOut` | `amount_out` | 正確に配信されます。カーブは `amount_out` プラス逆転送手数料をターゲットにします。 |

見積もりの 2 つの結果：

- 手数料がないかのように計算された境界は拒否されます。手数料なしのコストを `maximum_amount_in` として、または手数料なしの収益を `minimum_amount_out` として渡すと、`ExceededSlippage` で戻ります。
- `real_quote` はボルトに到達したもののみで進みます。5% クォートミント上の `BuyExactIn` の `amount_in` は、`amount_in × 0.95` で `real_quote` を移動します。

100% 手数料クォートミント（`10000` ベーシスポイント）は反転できず、正確出力パスで `CalculateOverflow` で戻ります。

両方のトレード側ミントも、マッチングスロットで渡されたプログラムに制限されるため、ミスマッチの `base_token_program` は無視されるのではなく失敗するようになりました。[`algorithms/token-2022-transfer-fees`](/ja/algorithms/token-2022-transfer-fees)を参照してください。基礎となる手数料数学については。

### トレード残りアカウント

4 つのトレード命令すべてが、`remaining_accounts` を通じて手数料配管を取ります。この順序で：

| インデックス | アカウント | 時期 |
|---|---|---|
| 0 | `share_fee_receiver` | `share_fee_rate > 0` の場合のみ。存在する場合、以下のすべてのインデックスを 1 つシフトします。 |
| 次 | `system_program` | 常に。手数料ボルト作成に資金を提供します。 |
| 次 | `platform_fee_vault` | 常に。シード `[platform_config, quote_token_mint]` の PDA。最初の使用時に作成されます。 |
| 次 | `creator_fee_vault` | 常に。シード `[creator, quote_token_mint]` の PDA。最初の使用時に作成されます。 |

<Note>
  **2026-09 で変更：最後の 3 つは無条件になり、`system_program` が検証されます。** このリリースの前に、プログラムは `unix_timestamp >= get_upgrade_timestamp()` の場合のみそれらを読み取り、その時点の前にプラットフォーム/作成者手数料分割をスキップしました。タイムスタンプは長く過ぎたため、メインネット上の動作は実際には変わりません — しかし、ブランチはコードから削除されており、3 つのアカウントを省略したままのビルダーは、カットオーバー後のみではなく常に `NotEnoughRemainingAccounts`（`6018`）で失敗するようになりました。`system_program` スロットは追加で `System::id()` に対して検証され、他のものを保持している場合は `InvalidInput`（`6002`）を返します。以前は、そのポジションで任意のアカウントが受け入れられていました。
</Note>

## `MigrateToAmm` / `MigrateToCpswap`

カーブが `total_quote_fund_raising` に達したら、ローンチを取引可能なプールに卒業させます。新しいローンチは CPMM のみです。`MigrateToAmm` は、保存された `migrate_type` が `0` である既存のプールのために保持されています。

**署名者**

- `MigrateToAmm` — バインディング `GlobalConfig` に記録された `migrate_to_amm_wallet`。
- `MigrateToCpswap` — バインディング `GlobalConfig` に記録された `migrate_to_cpswap_wallet`。

これらのウォレットは通常、Raydium が運営する卒業クランクによって保持されます。実際には、卒業は閾値を超えた数秒後に着地し、最終的な買いをトリガーした人に関係なく。

**引数**

どちらも取りません。

<Warning>
  **破壊的な変更（マイグレーションウォレットのみ、2026-09）。** `MigrateToAmm` は 3 つの引数すべてを削除しました — `base_lot_size`、`quote_lot_size`、`market_vault_signer_nonce` — **および 9 つのアカウント**。その命令データは現在、ベアディスクリミネータのみです。そのため、古いビルダーは 17 バイトの予期しない引数バイトを送信し、もはや整列しないアカウントリストを提供します。

  これは AMM v4 自体の [OpenBook 削除](/ja/reference/changelog/2026-07-22-amm-v4-openbook-removal)に従います：AMM v4 の `Initialize2` はもはや `market_program` または `amm_open_orders` を取らないため、LaunchLab は転送するものが何もありませんでした。プログラムも `initialize_openbook_market` への CPI を停止しました。これは 3 つの引数が設定したものです。

  削除されたアカウント：`openbook_program`、`request_queue`、`event_queue`、`bids`、`asks`、`market_vault_signer`、`market_base_vault`、`market_quote_vault`、および `amm_open_orders`。`market` アカウント**は位置に留まります** — AMM v4 はそれを参照フィールドとして記録します — しかし、それは現在、ベアの `#[account(mut)]` として宣言されています：所有者、アドレス、またはシード制約なし。それは完全に検証されず、AMM v4 の `Initialize2` CPI に直接転送され、プログラムはそれを初期化しません。市場アカウントが実際に初期化された市場であることを望むコーラーは、事前にそれ自体を作成する必要があります。

  残りの 23 アカウントリストは、順序で：`payer`、`base_mint`、`quote_mint`、`market`、`amm_program`、`amm_pool`、`amm_authority`、`amm_lp_mint`、`amm_base_vault`、`amm_quote_vault`、`amm_target_orders`、`amm_config`、`amm_create_fee_destination`、`authority`、`pool_state`、`global_config`、`base_vault`、`quote_vault`、`pool_lp_token`、`spl_token_program`、`associated_token_program`、`system_program`、`rent_program`。

  `MigrateToCpswap` は影響を受けません — それは引数を持ったことがありません。
</Warning>

**効果（両方に共通）**

1. `pool_state.status == Migrate` を確認します（つまり、`quote_reserve_target` に達しました）。そうでない場合は `PoolMigrated`（ステータスは既に `Migrated`）または `PoolFunding`（まだ資金調達中）で戻ります。
2. `pool_state.migrate_type` が命令と一致することを確認します（AMM の場合は `0`、CPMM の場合は `1`）。そうでない場合は `MigrateTypeNotMatch` で戻ります。
3. 卒業後の準備金を計算します：
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. ターゲットプログラム（`AMM v4 Initialize2` または `CPMM InitializeWithPermission`）に CPI して、それらの準備金を使用して卒業後のプールを作成します。
5. 2026-08-17 アップグレード後に実行された CPMM マイグレーションの場合、`platform_scale + creator_scale` を 1 つのプラットフォーム所有のロック LP シェアに結合し、最大 1 つの Fee Key NFT を `platform_nft_wallet` にミントします。`burn_scale` 残りを焼きます。アップグレード前は、`creator_scale` は別々にロックされ、その Fee Key は トークン作成者に行きました。完了した履歴マイグレーションは変更されません。従来の AMM v4 卒業の場合、LP 処分はその命令の既存のフローに従います。
6. （ミント権限ステップなし。`base_mint.mint_authority` は既にローンチ作成時に `None` に設定されていました — 下記の注記を参照してください。）
7. `pool_state.status = Migrated` をフリップし、`vesting_schedule.start_time = block_time + cliff_period` を設定します。

**Token-2022 転送手数料権限の引き渡し** — ベースミントが Token-2022 ミントで `TransferFeeConfig` を持つ**かつ** `PlatformConfig.transfer_fee_extension_auth` がデフォルト以外の場合、マイグレーションはその拡張の権限をプラットフォームキーに再割り当てします：

- `transfer_fee_config_authority` は常に再割り当てされます。ローンチ `authority` PDA は卒業前フェーズ全体でそれを保持するため、常に移動するものがあります。
- `WithheldWithdraw` は**`authority` PDA がそれを保持している場合のみ**再割り当てされます。2026-08-27 以降に作成されたローンチは、ミント作成時からその権限に既に `transfer_fee_extension_auth` を持っているため、ステップはスキップされます。ガードは、マイグレーションがそれらのミントで戻るのを防ぐものです — PDA はそれが保持していない権限を署名して譲ることはできません。

マイグレーション時に `transfer_fee_extension_auth` が `Pubkey::default()` の場合、どちらの権限も移動せず、両方は `authority` PDA に永続的に留まります。[`platform-config`](/ja/products/launchlab/platform-config#token-2022-transfer-fee-authorities)を参照してください。

<Note>
  **ベースミントの供給は卒業からではなく、作成から固定されます。** `InitializeV2` と `InitializeWithToken2022` は、ベースボルトに全供給をミントし、同じ命令で直ちに `MintTokens` を取り消すため、`base_mint.mint_authority` はローンチの全生涯で `None` です。マイグレーションはそれに触れません。（このページの以前のリビジョンは、卒業時に取り消しを配置していました。それは間違っていました。）マイグレーションが移動できる唯一の権限は、以下で説明する Token-2022 転送手数料のものです。
</Note>

**事後条件** — `BuyExactIn`、`BuyExactOut`、`SellExactIn`、`SellExactOut` はこの時点から `PoolMigrated` で拒否します。結果の AMM プールは正規であり、他の AMM v4 / CPMM プールのようにトレードします。

**一般的なエラー** — `PoolFunding`、`PoolMigrated`、`MigrateTypeNotMatch`、`InvalidCpSwapConfig`、`MathOverflow`。

### CPMM マイグレーション残りアカウント

`MigrateToCpswap` を構築するクライアントは、これらの固定 `remaining_accounts` インデックスを使用する必要があります：

| インデックス | アカウント |
|---|---|
| 0–4 | Platform Fee Key 所有者、ミント、トークンアカウント、ロック流動性 PDA、およびメタデータアカウント |
| 5 | 元のローンチ作成者。`platform_cp_creator` が設定されていない場合に使用されます |
| 6 | `[b"permission", launch_authority]` から派生した CPMM パーミッション PDA |
| 7 | 設定された `platform_cp_creator`。フィールドがデフォルト以外の場合に使用されます |
| 8 | ソート済み `mint0` の CPMM サポートミント PDA。`[b"support_mint", mint0]` から派生 |
| 9 | ソート済み `mint1` の CPMM サポートミント PDA。`[b"support_mint", mint1]` から派生 |

命令は最低 10 個の残りアカウントが必要です。サポートミントアカウントは読み取り専用 CPI 入力です。ミントが初期化されたサポートレコードを持たない場合でも、両方のアドレスを派生させます。作成者ロックアカウントを追加したり、インデックス 8–9 を省略したままの古いビルダーは更新する必要があります。

<Note>
  **2026-09 で変更。** 2 つのクリーンアップ。どちらも正しいビルダーを変更しません：

  - **パーミッション CPMM パスは現在唯一のパスです。** `MigrateToCpswap` は `unix_timestamp >= get_upgrade_timestamp()` に基づいて `InitializeCpSwap` と `InitializeCpSwapWithPermission` の間で選択するために使用されました。タイムスタンプヘルパーと従来の CPI の両方がなくなったため、パーミッション パス — したがって 10 アカウント最小 — は無条件に適用されます。
  - **3 つのアドレス制約がアカウント構造から命令本体に移動しました。** `platform_config`、`base_vault`、および `quote_vault` は依然として `PoolState` に保存された値と一致する必要がありますが、ミスマッチは Anchor の `address =` 制約ではなく `require_keys_eq!` によって発生します。チェックは同等です。エラーサーフェスのみが異なります — これらの 3 つのアカウントに対して `2012` にマッチしたエラー処理を更新してください。Anchor の汎用 `RequireKeysEqViolated`（`2502`）を取得し、アカウント名なしで報告されます。
</Note>

### CPMM マイグレーショントークンプログラム

`MigrateToCpswap` は両方のトークンプログラムを無条件に取り、どのプログラムが各ミントを所有するかを自分で計算します。その 2 つのトークンプログラムアカウントは相応に名前が変更されました：

| 位置 | アカウント | 値 |
|---|---|---|
| 最初 | `token_program` | 常にレガシー SPL Token プログラム |
| 2 番目 | `token_program_2022` | 常に Token-2022 プログラム |

これらは、以前の `base_token_program`（ベースミントを所有していたプログラム）と `quote_token_program`（常にレガシー）に置き換わります。位置は変わらないため、これはレイアウト変更ではなく値の変更です — しかし、2 つの値はほぼ反転しており、古いペアを渡し続けるビルダーは、どちらのミントが Token-2022 ミントになるとすぐに、レガシープログラムが必要な場所に Token-2022 を提供します。

レガシープログラムは、どちらのミントも使用しない場合でも必須です。CPMM LP ミントとロック流動性 Fee Key NFT は常にそれに存在するためです。

## プラットフォーム `GlobalConfig` アロウリスト

`PlatformConfig.restrict_global_config` はチェックを制御します：

- `0`：プラットフォームは、他の有効な `GlobalConfig` を受け入れます。アロウアカウントは必要ありません。
- `1`：`Initialize`、`InitializeV2`、および `InitializeWithToken2022` は、マッチング `PlatformAllowConfig` を `remaining_accounts` の任意の場所に含める必要があります。

プラットフォーム管理者は、`CreatePlatformAllowConfig` と `ClosePlatformAllowConfig` で PDA を作成または閉じます。そのシードは `[b"platform_allow_config", platform_config, global_config]` です。以前の管理者管理の `PlatformGlobalAccess` 命令と PDA は廃止されました。

## プラットフォームローンチパラメータルール

4 つの命令は 1 つの `PlatformCurveRule` アカウントを管理します。すべての 4 つは `PlatformConfig.curve_rule_manager` またはプラットフォーム管理者によって署名されます — プログラムは署名者から `PlatformConfig` PDA を再派生することで管理者を受け入れるため、それを証明する別のアカウントはありません。どちらでもない署名者は `InvalidCurveRuleAuthority` を返します。

| 命令 | アカウント | 引数 |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority`（署名者、mut）、`platform_config`、`global_config`、`platform_curve_rule`（mut）、`system_program` | なし |
| `UpdatePlatformCurveRule` | 同じ 5 つ | `group_id: u16`、`constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | 同じ 5 つ | `group_id: u16` |
| `ClosePlatformCurveRule` | 最初の 4 つ | なし |

`platform_curve_rule` は `[b"platform_curve_rule", platform_config, global_config]` の PDA です。

- **`Create`** はグループを保持しないアカウントを割り当てます。その状態は何も制限しません。
- **`Update`** はそのグループを `group_id` でアップサート（存在する場合は全体的に置き換え）します。アカウントをサイズ変更して適合させるため、署名者は成長するレントを補充し、縮小するレントを返します。10 番目を超える新しいグループは `CurveRuleGroupsExceeded` を返します。25 を超える制約、未知のフィールドまたはオペレータ、または 1 つのグループ内で同じ `(field, op)` ペアが 2 回は `InvalidCurveRuleConstraint` を返します。非定数積設定の 4 つの `TotalSellA` 派生フィールドは `CurveRuleFieldNotSupportedByCurve` を返します。
- **`Remove`** は id でグループを削除し、アカウントを縮小して差分を払い戻します。未知の id は `CurveRuleGroupNotExist` を返します。
- **`Close`** は全レントを署名者に返します。設定は、`restrict_curve_param` が `1` のままであっても、その後、制限されなくなります。

4 つのどれもルールが強制されるかどうかを変更しません。それは `UpdatePlatformConfig::RestrictCurveParam(0 | 1)` です。プラットフォーム管理者のみが呼び出すことができます。

**ローンチパス上。** `restrict_curve_param` が `1` の間、`InitializeV2` と `InitializeWithToken2022` は `remaining_accounts` のルール PDA を必要とします — それが存在しない場合でも、それを省略することでチェックをスキップできないようにするため。欠落しているアカウントは `NotEnoughRemainingAccounts`。ローンチがグループを満たさない場合は `CurveParamNotMatchPlatformRule`。チェックは `GlobalConfig` 独自の制限の前に実行され、それらのみを狭めることができます。モデルとプレイブック：[`products/launchlab/curve-rules`](/ja/products/launchlab/curve-rules)。両方のエラーはクライアント側で回避可能です — SDK はこのチェックを純粋な関数としてミラーします。[送信前にチェック](/ja/products/launchlab/curve-rules#check-before-you-send)を参照してください。

## `CollectExcessLamports`

LaunchLab が制御するアカウント上のレント免除最小値を超えて座っているラムポートの管理者スイープ。2026-09 アップグレードで追加されたため、プロトコルは [SIMD-0437 レント削減](/ja/solana-fundamentals/rent-and-reclaimable-rent)が各ステップの前に作成されたアカウントに残す過剰資金を回収できます。

過剰のみが移動します。トークン残高、アカウントデータ、所有者、カーブ状態、ベスティングは変更されず、命令は既に最小値にあるアカウントに対して no-op です — したがって、各ロールアウトステップ後に再実行するのは安全です。

**引数** — なし。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | すべてのスイープされたラムポートの宛先。LaunchLab プログラム管理者または専用の collect-lamports ウォレットのいずれかである必要があります — [`reference/program-addresses`](/ja/reference/program-addresses#excess-lamports-collection-wallets)を参照してください。他の署名者は `InvalidOwner`（`6001`）で失敗します。 |
| 2 | `authority` |   |   | LaunchLab の 3 つのボルト権限 PDA の**1 つ**（下記を参照）。このコール内のすべてのトークンアカウント転送に署名します。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。両方は無条件に必須。プログラムはソースアカウントごとに選択します。 |
| 5.. | `remaining_accounts` | W |   | スイープする `M` ソースアカウント。任意の数、任意の順序。 |

**`authority` を選択**

アカウントはチェックなしで渡され、プログラムによって解決されます。プログラムは LaunchLab の 3 つの権限 PDA をすべて再派生し、マッチします：

| シード | 所有 |
|---|---|
| `[b"vault_auth_seed"]` | すべてのローンチのベースおよびクォートプールボルト |
| `[b"platform_fee_vault_auth_seed"]` | すべてのプラットフォーム手数料ボルト |
| `[b"creator_fee_vault_auth_seed"]` | すべてのクリエイター手数料ボルト |

3 つのどれにも一致しないキーは、全命令を `InvalidOwner`（`6001`）で失敗させます。

<Warning>
  **ソースアカウントを権限でグループ化します。** 1 つの呼び出しは 1 つの `authority` を持ち、トークンプログラムはアカウントの実際の所有者に署名することを要求します。渡した `authority` とは異なる 3 つの PDA の 1 つが所有するトークンアカウントは CPI を失敗させ、トランザクション全体を持ち去ります。プールボルト、プラットフォーム手数料ボルト、クリエイター手数料ボルトを別々のトランザクションでスイープします。

  プログラム所有の PDA は例外です — それらは直接請求されるため、任意の権限と一緒に乗ることができます。
</Warning>

**各ソースアカウントの処理方法**

| ソースアカウント所有者 | 処理 |
|---|---|
| SPL Token または Token-2022、非ネイティブトークンアカウント | CPI `WithdrawExcessLamports`（トークンプログラムディスクリミナント `38`）。`authority` によって署名されます。 |
| SPL Token または Token-2022、**ネイティブ**（wSOL）トークンアカウント | `WithdrawExcessLamports` はネイティブアカウントを拒否します。プログラムは `SyncNative` に CPI し、ラップされた `amount` がどれだけ成長したかを測定し、`UnwrapLamports`（ディスクリミナント `45`）をその正確なデルタに対して実行し、ラップされた残高が事前同期値と等しいことを要求します — そうでない場合は `LamportsCalculateError`（`6031`）。SOL クォートローンチは、したがって、その全クォート準備金を保持します。 |
| LaunchLab プログラム自体 — `PoolState`、`GlobalConfig`、`PlatformConfig`、`VestingRecord`、`PlatformCurveRule`、`PlatformAllowConfig` | プログラムはアカウントを `rent.minimum_balance(data_len)` まで直接請求します。 |
| その他 | **サイレントにスキップされます。** エラーなし、ラムポート移動なし。 |

**ベースミントはスイープできません。** `InitializeV2` と `InitializeWithToken2022` は、供給をミントする同じ命令で `MintTokens` をベースミントで取り消すため、誰もそれに対して `WithdrawExcessLamports` に署名することはできません — ミントのレントは永続的にそこに留まります。

**一般的なエラー** — `InvalidOwner`（`6001`。間違った署名者または 3 つの PDA のどれでもない `authority`）、`LamportsCalculateError`（`6031`。wSOL ラウンドトリップがゼロに正味化されませんでした）、プログラム所有パスからの `InsufficientFunds`。アカウントが独自のレント最小値より少ない場合。

**SDK ビルダーなし。** `@raydium-io/raydium-sdk-v2` はこの命令のビルダーを出荷しません。`raydium-sdk-V2-demo` リポジトリも出荷しません — それは管理者パスです。手で符号化してください。[`solana-fundamentals/rent-and-reclaimable-rent`](/ja/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction)のウォレット側スイープが行うのと同じ方法で。
