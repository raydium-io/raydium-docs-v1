「ExactIn/ExactOut」の分割は CPMM の `SwapBaseInput` / `SwapBaseOutput` を反映しています — オンチェーンでは、わずかに異なるラウンディングを持つ別の命令ディスクリミネーターです。

**卒業パスの選択。** すべての新しい `Initialize`、`InitializeV2`、および `InitializeWithToken2022` 呼び出しは `migrate_type = 1`（`CPSWAP`）を設定する必要があります。新しい AMM v4 バウンドプールを初期化しようとすると、`MigrateTypeNotMatch` が返されます。`amm_creator_fee_on` は、結果の CPMM 作成者手数料がクォートトークンに適用されるか両方のトークンに適用されるかのみを選択します。ターゲットプログラムを選択しません。

`MigrateToAmm` は、この制限の前に `migrate_type = 0` で初期化された既存の `PoolState` に対して呼び出し可能なままです。このリリースは既存のプール状態を書き直したり、従来の命令を削除したりしません。

**クォート側トークンプログラム。** クォートミントは SPL Token プログラムまたは Token-2022 のいずれかが所有できます。それに触れるすべての命令 — `CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、4 つのトレード命令すべて、`CollectFee`、`CollectMigrateFee`、`ClaimCreatorFee`、`ClaimPlatformFee`、および `ClaimPlatformFeeFromVault` — は、クォートプログラムアカウントスロットで所有プログラムを取得します。アカウント位置は変わりませんでした。受け入れられた値のみが変わりました。実際に `GlobalConfig.quote_mint` を所有するプログラムを渡してください。これは、既存のローンチの場合は `PoolState.token_program_flag` ビット 1 から読み取ることができます（[`accounts`](/ja/products/launchlab/accounts#poolstate) を参照）。または、ミントアカウントの所有者から読み取ります。

非推奨の `Initialize` は例外です：そのクォートプログラムアカウントは依然として SPL Token に型付けされているため、クォートミントが Token-2022 である設定は `InitializeV2` または `InitializeWithToken2022` を通じて起動する必要があります。

`MigrateToCpswap` は反対方向の別の例外です — 1 つではなく、無条件に **両方の** プログラムを取得します。以下の [マイグレーションアカウント](#cpmm-migration-token-programs) を参照してください。

## `Initialize`

新しいローンチを作成します。

**引数**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // or initial_virtual_quote_reserve for curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // inline name/symbol/uri; program CPIs to Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**アカウント**（簡略版）

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | レント + ベースミント作成を支払います。 |
| 2 | `launch_config` |   |   | プロトコル設定バインディング。 |
| 3 | `launch_state` | W |   | 新しいアカウント。 |
| 4 | `launch_authority` |   |   | PDA。 |
| 5 | `base_mint` | W | S | 新しいキーペア（または PDA）— この命令がそれを初期化します。 |
| 6 | `base_vault` | W |   | `launch_authority` の `base_mint` 上の ATA。 |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | `launch_authority` の `quote_mint` 上の ATA。 |
| 9 | `metadata` | W |   | Metaplex メタデータ PDA。 |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | ベースミント用の SPL Token。`InitializeV2` と `InitializeWithToken2022` は、どちらのプログラムでもあり得る別のクォートプログラムアカウントを取得します。 |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**前提条件**

- `quote_mint ∈ launch_config.allowed_quote_mints`。
- `base_supply_graduation ≤ base_supply_max`。
- 手数料パラメーターは `launch_config.max_*_fee_rate` チェックに合格します。
- `open_time ≥ now − slop`（SDK は `≥ now` を強制します；プログラムはわずかなバックデーティングを許容します）。
- `curve_type` は認識されます。

**事後条件**

- `base_mint` は `supply = base_supply_max` を持ち、すべて `base_vault` にあります。
- `base_mint.mint_authority = launch_authority`、`freeze_authority = None`。
- `LaunchState` は `status = Active`、`base_sold = 0`、`quote_reserve_real = 0` で初期化されます。
- `quote_reserve_target` はカーブパラメーター + `base_supply_graduation` + `buy_numerator` から計算されます（おおよそ）。

**一般的なエラー** — `InvalidQuoteMint`、`FeeRateTooHigh`、`InvalidCurveParams`、`MathOverflow`。

## `Buy`（正規バリアント：`BuyExactIn`）

ユーザーは固定の `quote_in` を提供します；カーブは `base_out` を計算します。

**引数**

```
quote_in:          u64
minimum_base_out:  u64
```

**アカウント**

| # | 名前 | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**前提条件**

- `launch_state.status == Active`。
- `now ≥ open_time`。
- `user_quote_ata.balance ≥ quote_in`。
- `quote_in > 0`。

**効果**

1. `quote_in` を `quote_in_after_fee` と手数料部分に分割します。
2. ポストフィークォートが与えられたカーブに対して `base_out` を Newton 法で解きます。
3. `require(base_out ≥ minimum_base_out)` そうでなければ `ExceededSlippage` で戻ります。
4. `quote_in` ユーザー → ボルト。`base_out` ボルト → ユーザーを移動します。
5. `base_sold += base_out`、`quote_reserve_real += quote_in_after_fee × (lp_share / total_share)` を更新します。
6. 手数料カウンター（`protocol_fees_quote`、`creator_fees_quote`）を更新します。
7. `state_data.num_buys += 1`。
8. 更新後に `quote_reserve_real ≥ quote_reserve_target` の場合、SDK は通常、同じトランザクション内で `Graduate` ix をチェーンします。プログラムは `Buy` 内で自動卒業しません — 後続の `Graduate` が必要です。

## `BuyExactOut`

ユーザーは正確な `base_out` を指定します；プログラムは `quote_in` を計算します。

**引数**

```
base_out:      u64
maximum_quote_in: u64
```

`BuyExactIn` と同じアカウント。Newton 反復ではなく、閉じた形の二次積分（または curve_type 1 の場合は CPMM 逆関数）を使用します。

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy` のミラー。ユーザーは `base_in` をカーブに返し、`quote_out` を受け取ります。手数料は `quote_out` から差し引かれるため、ユーザーは生の統合収益より少なく受け取ります。

**前提条件** —

- `user_base_ata.balance ≥ base_in`。
- 売却は `base_sold` を 0 未満に押し下げることはできません（会計が一貫している場合、上記と冗長）。
- ローンチは `Active` です。

**効果** — `Buy` と対称。`base_sold` は減少し、`quote_reserve_real` は減少します。手数料は依然として蓄積されます。

### クォート側転送手数料

クォートミントが `TransferFeeConfig` を持つ場合、ボルトが移動する金額と支払者が請求または貸方される金額は異なり、スリッページ境界は支払者側に対してチェックされます。転送手数料拡張なしのクォートミントでは、以下のすべてのケースは通常のレガシーミントと同じです。

| 命令 | 引数 | チェック対象 |
|---|---|---|
| `BuyExactIn` | `amount_in` | カーブは `amount_in − transfer_fee(amount_in)` で価格設定されます — ボルトに到達するもの。完全な充填は正確に `amount_in` を請求します；部分的な充填は消費されたボルト金額とその逆手数料を請求します。 |
| `BuyExactOut` | `maximum_amount_in` | ボルト金額 **プラス** 逆転送手数料 — 実際の請求。 |
| `SellExactIn` | `minimum_amount_out` | 売り手がミントが手数料を差し引いた後に保持するもの、ボルトを離れる総額ではありません。 |
| `SellExactOut` | `amount_out` | 正確に配信されます。カーブは `amount_out` プラス逆転送手数料をターゲットにします。 |

見積もりの 2 つの結果：

- ミントが手数料なしであるかのように計算された境界は拒否されます。手数料なしのコストを `maximum_amount_in` として、または手数料なしの収益を `minimum_amount_out` として渡すと、`ExceededSlippage` で戻ります。
- `real_quote` はボルトに到達したもののみで進みます。5% クォートミント上の `BuyExactIn` の `amount_in` は `real_quote` を `amount_in × 0.95` で移動します。

100% 手数料クォートミント（`10000` ベーシスポイント）は反転できず、正確出力パスで `CalculateOverflow` で戻ります。

両方のトレード側ミントも、マッチングスロットで渡されたプログラムに制限されるため、ミスマッチの `base_token_program` は無視されるのではなく失敗するようになりました。基礎となる手数料計算については、[`algorithms/token-2022-transfer-fees`](/ja/algorithms/token-2022-transfer-fees) を参照してください。

## `MigrateToAmm` / `MigrateToCpswap`

カーブが `total_quote_fund_raising` に達したら、ローンチを取引可能なプールに卒業させます。新しいローンチは CPMM のみです。`MigrateToAmm` は、保存された `migrate_type` が `0` である既存のプールのために保持されます。

**署名者**

- `MigrateToAmm` — バインディング `GlobalConfig` に記録された `migrate_to_amm_wallet`。
- `MigrateToCpswap` — バインディング `GlobalConfig` に記録された `migrate_to_cpswap_wallet`。

これらのウォレットは通常、Raydium が運営する卒業クランクによって保持されます；実際には、卒業は最終的な買いをトリガーした人に関係なく、閾値を超えた数秒後に着地します。

**引数**

`MigrateToAmm` は 3 つを取ります（主に、プログラムが AMM v4 に転送する OpenBook マーケットパラメーター）：

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` は何も取りません。

**効果（両方に共通）**

1. `pool_state.status == Migrate` を確認します（つまり、`quote_reserve_target` に達しました）。そうでない場合は `PoolMigrated`（ステータスは既に `Migrated`）または `PoolFunding`（まだ資金調達中）で戻ります。
2. `pool_state.migrate_type` が命令と一致することを確認します（AMM の場合は `0`、CPMM の場合は `1`）。そうでない場合は `MigrateTypeNotMatch` で戻ります。
3. 卒業後の準備金を計算します：
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. ターゲットプログラム（`AMM v4 Initialize2` または `CPMM InitializeWithPermission`）に CPI して、それらの準備金を使用して卒業後のプールを作成します。
5. 2026-08-17 アップグレード後に実行された CPMM マイグレーションの場合、`platform_scale + creator_scale` を 1 つのプラットフォーム所有のロック LP シェアに結合し、最大 1 つの Fee Key NFT を `platform_nft_wallet` にミントします。`burn_scale` の残りを焼きます。アップグレード前は、`creator_scale` は別々にロックされ、その Fee Key は トークン作成者に行きました。完了した履歴マイグレーションは変更されません。従来の AMM v4 卒業の場合、LP 処分はその命令の既存のフローに従います。
6. `base_mint.mint_authority` を取り消します（`None` に設定）。
7. `pool_state.status = Migrated` をフリップし、`vesting_schedule.start_time = block_time + cliff_period` を設定します。

**事後条件** — `BuyExactIn`、`BuyExactOut`、`SellExactIn`、`SellExactOut` はこの時点から `PoolMigrated` で拒否されます。結果の AMM プールは正規であり、他の AMM v4 / CPMM プールのように取引されます。

**一般的なエラー** — `PoolFunding`、`PoolMigrated`、`MigrateTypeNotMatch`、`InvalidCpSwapConfig`、`MathOverflow`。

### CPMM マイグレーション残りアカウント

`MigrateToCpswap` を構築するクライアントは、これらの固定 `remaining_accounts` インデックスを使用する必要があります：

| インデックス | アカウント |
|---|---|
| 0–4 | プラットフォーム Fee Key 所有者、ミント、トークンアカウント、ロック流動性 PDA、およびメタデータアカウント |
| 5 | 元のローンチ作成者；`platform_cp_creator` が未設定の場合に使用 |
| 6 | `[b"permission", launch_authority]` から派生した CPMM パーミッション PDA |
| 7 | 設定された `platform_cp_creator`；フィールドがデフォルト以外の場合に使用 |
| 8 | ソート済み `mint0` の CPMM サポートミント PDA、`[b"support_mint", mint0]` から派生 |
| 9 | ソート済み `mint1` の CPMM サポートミント PDA、`[b"support_mint", mint1]` から派生 |

命令は、アップグレードされたパスで最低 10 個の残りアカウントが必要です。サポートミントアカウントは読み取り専用 CPI 入力です。ミントに初期化されたサポートレコードがない場合でも、両方のアドレスを派生させます。クリエーターロックアカウントを追加し続けるか、インデックス 8–9 を省略する古いビルダーは更新する必要があります。

### CPMM マイグレーショントークンプログラム

`MigrateToCpswap` は両方のトークンプログラムを無条件に取得し、どのプログラムが各ミントを所有しているかを自分で計算します。その 2 つのトークンプログラムアカウントは、それに応じて名前が変更されました：

| 位置 | アカウント | 値 |
|---|---|---|
| 最初 | `token_program` | 常にレガシー SPL Token プログラム |
| 2 番目 | `token_program_2022` | 常に Token-2022 プログラム |

これらは、以前の `base_token_program`（ベースミントを所有していたプログラム）と `quote_token_program`（常にレガシー）に置き換わります。位置は変わらないため、これはレイアウト変更ではなく値の変更です — しかし、2 つの値はほぼ反転しており、古いペアを渡し続けるビルダーは、いずれかのミントが Token-2022 ミントになるとすぐに Token-2022 を提供します。ここでレガシープログラムが必要です。

レガシープログラムは、どちらのミントも使用しない場合でも必須です。CPMM LP ミントとロック流動性 Fee Key NFT は常にそれに存在するためです。

## プラットフォーム `GlobalConfig` アロウリスト

`PlatformConfig.restrict_global_config` はチェックを制御します：

- `0`：プラットフォームは、その他の有効な `GlobalConfig` を受け入れます；アロウアカウントは必須ではありません。
- `1`：`Initialize`、`InitializeV2`、および `InitializeWithToken2022` は、マッチング `PlatformAllowConfig` を `remaining_accounts` の任意の場所に含める必要があります。

プラットフォーム管理者は、`CreatePlatformAllowConfig` と `ClosePlatformAllowConfig` で PDA を作成または閉じます。そのシードは `[b"platform_allow_config", platform_config, global_config]` です。以前の管理者管理の `PlatformGlobalAccess` 命令と PDA は廃止されました。

## `CollectFee`

単一のローンチでプロトコルの蓄積されたトレード手数料の管理者スイープ。

**引数** — なし。

**アカウント**

| # | 名前 | W | S | 注記 |
|---|------|---|---|-------|
| 1 | `protocol_fee_owner` |   | S | `global_config.protocol_fee_owner` と等しい必要があります。 |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`；ボルト転送に署名します。 |
| 3 | `pool_state` | W |   | `quote_protocol_fee` をゼロにするために変更されます。 |
| 4 | `global_config` |   |   | 署名者の真実の源。 |
| 5 | `quote_vault` | W |   | `quote_protocol_fee` によってドレインされます。 |
| 6 | `recipient_token_account` | W |   | `protocol_fee_owner` の `quote_mint` 上の ATA。 |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | クォートミントを所有するプログラム — SPL Token または Token-2022。 |

**効果** — `quote_vault` から `recipient_token_account` に `pool_state.quote_protocol_fee` を転送し、カウンターをゼロにします。最初の買い後いつでも呼び出し可能です。

## `CollectMigrateFee`

卒業時に蓄積されたマイグレーション手数料の管理者スイープ。`CollectFee` と同じアカウント形状で、`migrate_fee_owner` が署名者（`protocol_fee_owner` の代わり）であり、`pool_state.migrate_fee` がドレインされたカウンターです。

## `ClaimCreatorFee`

作成者が所有する **すべてのローンチ** にわたって蓄積された作成者手数料の作成者ごとのスイープ。同じクォートミントを使用します。プール単位ではなく、作成者単位の手数料ボルトをドレインします。

**引数** — なし。

**アカウント**

| 4 | `recipient_token_account` | W |   | `init_if_needed`；`creator` の `quote_mint` 上の ATA。 |
