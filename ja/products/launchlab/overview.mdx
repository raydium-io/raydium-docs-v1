## LaunchLab が解決する問題

LaunchLab 登場以前、Raydium で新しいトークンをローンチするには、クリエイターが AMM プールの両側（ペアの両方）に事前に流動性を供給する必要がありました。つまり、チームが自己資金でクォート側の流動性（SOL または USDC）を用意しなければならず、これは資金力のあるプロジェクトを優遇し、初期資本によってローンチパッド機能へのアクセスを制限していました。

LaunchLab はこの初期段階を**ボンディングカーブ**に置き換えます。トークンはクォートミント（通常は SOL または USDC）で価格設定されたカーブに対してデプロイされます。買い手はクォートをカーブに送信してトークンを取得し、カーブはカーブ公式と現在の供給量に基づいて決定された価格でベーストークンをアトミックにミントまたはリリースします。事前にシードされた流動性は不要です。

カーブが実際の AMM プールの流動性公式に合致するだけのクォートを集めると、**卒業**します。プログラムはカーブのベース準備金とクォート準備金でシードされた CPMM プールをメインネット上に作成し、その時点から取引は AMM に移行します。

すべてのローンチはこのシーケンスを正確に 1 回通過します。`Buy` と `Sell` は中間段階のユーザー向けインストラクションです。閾値を超えた後、`GlobalConfig` に保存されたマイグレーションウォレットが `MigrateToCpswap` に署名します。

## 2 つの固定パーティ

LaunchLab 状態には 2 つの区別されたアカウントがあります：

- **ベースミント** — ローンチされるトークン。そのミント権限は卒業まで LaunchLab プログラムが保有し、卒業後は取り消されます。
- **クォートミント** — 担保。常にメインストリームミント（SOL / USDC / RAY）です。ローンチ設定は `Initialize` で 1 つを選択します。変更することはできません。

さらに 2 つのボルト：

- **`base_vault`** — カーブに事前ミントされたがまだ売却されていないベース供給量の部分を保有します。ユーザーが買うにつれて減少します。
- **`quote_vault`** — 買い手から支払われたクォートを蓄積します。ユーザーが買うにつれて増加します。この残高が卒業閾値に対してチェックされます。

## 価格設定モデル

LaunchLab は複数のカーブ公式をサポートしています（[`bonding-curve`](/ja/products/launchlab/bonding-curve) を参照）。最も一般的なのは **二次** ボンディングカーブで、Pump.fun / Curve.fi / Bancor の系統に類似しています：

```
price(s) = k × (s / S_max)²     (または類似 — 正確な公式はカーブ設定に依存)
```

ここで `s` はユーザーに既に売却されたベースの量で、`S_max` はカーブの最大供給量です。価格は各買いで単調に上昇し、各売りで下降します。プログラムが AMM 統合コストを正確に計算するため、任意のサイズの買いは正しい統合量を返します。カーブの自然な凸性を超えた取引ごとのスリッページはありません。

## 卒業

ローンチは `quote_vault.balance ≥ graduation_threshold` のときに卒業します。閾値は `Initialize` で設定され、通常は卒業時にカーブの暗黙の価格が収集された準備金で開く AMM プールの価格と一致するように選択されます。具体的には：

```
threshold ≈ S_graduate × price(S_graduate) × f
```

ここで `S_graduate` は既に売却されたベースの量、`price(S_graduate)` はその時点でのカーブの限界価格、`f` はフィーラインを考慮した小さな係数（1～2%）です。

卒業時：

1. プログラムは `(base_vault_remaining, quote_vault)` をスナップショットします。
2. これら 2 つの準備金で CPMM `CreatePool` CPI を呼び出し、初期 LP をプログラム所有の権限にミントします（通常はポリシーに従いバーンまたはロック）。
3. ベースミントのミント権限を取り消します（これ以上ベーストークンをミントできなくなります）。
4. `LaunchState.status` が `Graduated` に切り替わります。

卒業後、`Buy` と `Sell` は拒否されます。取引は結果として生じた CPMM プール上で続行され、これは他の Raydium CPMM プールと区別できません。

## フィー

カーブ段階では、各 `Buy` と `Sell` は以下に分割されたフィーが発生します：

- **カーブ LP 側** — カーブの暗黙の `k` を増加させ、後の買い手に利益をもたらします（より厳しい価格）。
- **プロトコル** — LaunchLab 管理者に蓄積され、`CollectFees` を通じて収集されます。
- **クリエイター** — オプション、`Initialize` で設定可能。一部のローンチはクリエイターへの継続的な収益ストリームとしてシェアを指示します。

デフォルトレートは [`bonding-curve`](/ja/products/launchlab/bonding-curve) に記載されています。正確な分割は `LaunchState.fees` に保存され、ローンチごとに異なる場合があります。

卒業後のフィーは、プールが作成された CPMM 設定に従います（通常は `AmmConfig[0]`、0.25% ティア）。

## 卒業後の LP の保有者は誰ですか？

LaunchLab はプラットフォームの 3 つの保存されたスケールを使用して、2 つの有効な LP 宛先を生成します：

- **プラットフォームロック** — 2026-08-14 アップグレード後に実行されたマイグレーションの場合、`platform_scale + creator_scale` は LP-Lock を通じてロックされ、このシェアが 0 でない場合、1 つのフィーキーが `platform_nft_wallet` に送られます。アップグレード前は、`creator_scale` は別のクリエイターフィーキーを生成しました。
- **バーン** — `burn_scale` は永続的にバーンされ、フィーキーはありません。

スケールは `PlatformConfig` に存在し、`1_000_000` に合計する必要があります。アップグレードは将来のマイグレーション実行のみを変更します。以前のマイグレーションで作成されたクリエイターフィーキーは変更されません。

## 重要な不変量

- **ベースミントは卒業後、インフレーションフリーです。** その `mint_authority` は取り消されます。`freeze_authority` は設定されていません。
- **すべての新しいローンチは CPMM のみです。** `Initialize`、`InitializeV2`、`InitializeWithToken2022` は `migrate_type = CPSWAP` を必要とします。既存のレガシー状態は引き続き `MigrateToAmm` を使用できます。
- **カーブ状態は一方向で単調です。** `base_sold` は Buy 中にのみ上昇し、`quote_vault` は Buy 中にのみ上昇します（Sell 中に下降 — これは対称的に `base_sold` を減少させます）。プログラムはカーブを負にすることはありません。
- **卒業は一方向のゲートです。** 卒業後の取引が AMM プール価格を卒業価格以下に押し戻したとしても、ローンチはカーブに戻りません。

## LaunchLab を使用する場合

<Note>
  このページはプロトコルメカニクスのみを説明しています。ここに記載されている内容は、財務、法律、または投資アドバイスを構成しません。トークンローンチには重大な財務リスクが伴います。公開資金調達を伴うトークンをローンチする前に、適切な専門家に相談してください。
</Note>

- 既存市場のない新しいトークンをローンチしている。
- 市場が事前に宣言するのではなく、開始 CPMM 価格を決定することを望んでいる。
- チーム自体を含む誰もが、インサイダーに割引で事前割り当てするのではなく、同じカーブ決定価格で買うことを許可したい。

LaunchLab を**使用しないでください**：

- 確立された市場を持つ既存トークン（CPMM で直接 `CreatePool` を使用）。
- 開始 AMM 価格を正確に制御する必要があるローンチ（慎重なカーブ設定で近似できますが、メカニズムはまだカーブ駆動）。
- LaunchLab がホワイトリストに登録していない Token-2022 拡張機能を必要とするトークン（ローンチプログラムは Token-2022 パスでも `TransferHook` や `PermanentDelegate` などの拡張機能を拒否）。
