## Шесть аккаунтов пула CPMM

Каждый пул CPMM полностью описывается шестью программно-производными адресами (PDA) под программой CPMM, плюс один общий аккаунт `AmmConfig`, на который он ссылается. Имея два mint'а, вы можете детерминированно вывести всё остальное без обращения к сети.

| Аккаунт | Seed(s) | Владелец | Назначение |
|---------|---------|----------|-----------|
| `authority` | `"vault_and_lp_mint_auth_seed"` | CPMM | Подписант для каждого перемещения хранилища и каждого mint/burn LP. Общий для **всех** пулов CPMM. |
| `poolState` | `"pool"`, `ammConfig`, `token0Mint`, `token1Mint` **или** любая пара ключей, предоставленная подписантом | CPMM | Структура состояния пула — пара mint'ов, балансы хранилищ, предложение LP, начисление комиссий, указатель наблюдений. Инструкция CPMM `Initialize` принимает либо канонический PDA, полученный из четырёх seed'ов, **либо** произвольную пару ключей, подписанную создателем. Путь со случайной парой ключей существует для защиты от атаки фронт-раннинга, когда противник следит за mempool и спешит занять канонический PDA до того, как это сделает законный создатель. |
| `lpMint` | `"pool_lp_mint"`, `poolState` | SPL Token | LP токен пула. Предложение = всего выданных LP. Mint authority = PDA authority CPMM. |
| `vault0` | `"pool_vault"`, `poolState`, `token0Mint` | SPL Token / Token-2022 | Хранит баланс token0 пула. Принадлежит PDA authority. |
| `vault1` | `"pool_vault"`, `poolState`, `token1Mint` | SPL Token / Token-2022 | Хранит баланс token1 пула. Принадлежит PDA authority. |
| `observation` | `"observation"`, `poolState` | CPMM | Кольцевой буфер образцов цен, используемый для TWAP. Записывается при каждом swap'е. |

И общая конфигурация:

| Аккаунт | Seed(s) | Владелец | Назначение |
|---------|---------|----------|-----------|
| `ammConfig` | `"amm_config"`, `index: u16` | CPMM | Содержит ставки торговой/протокольной/фондовой/создательской комиссии, ставку по умолчанию для доли создателя и ключи администратора. По одному на «уровень комиссии». Poolstate привязывается к одному при создании и не может измениться позже. |

И один опциональный аккаунт на создателя:

| Аккаунт | Seed(s) | Владелец | Назначение |
|---------|---------|----------|-----------|
| `creatorFeeShare` | `"creator_fee_share"`, `creator`, `ammConfig` | CPMM | Переопределяет `AmmConfig.creator_fee_share_rate` для одного создателя пула на одном уровне комиссии. Опционально — когда его нет, применяется значение по умолчанию из конфига. Добавлено обновлением creator-fee-share от 2026-09-19. |

## Вывод пула из двух mint'ов

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";

const CPMM_PROGRAM_ID = new PublicKey(
  "CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C"
); // mainnet — см. reference/program-addresses

function u16ToBytes(n: number): Buffer {
  const b = Buffer.alloc(2);
  b.writeUInt16BE(n);
  return b;
}

// token0 < token1 по порядку байтов. Ошибка здесь приводит к валидному PDA
// который указывает на несуществующий пул.
function sortMints(a: PublicKey, b: PublicKey): [PublicKey, PublicKey] {
  return Buffer.compare(a.toBuffer(), b.toBuffer()) < 0 ? [a, b] : [b, a];
}

export function deriveCpmmAccounts(
  mintA: PublicKey,
  mintB: PublicKey,
  ammConfigIndex = 0,
) {
  const [token0Mint, token1Mint] = sortMints(mintA, mintB);

  const [ammConfig] = PublicKey.findProgramAddressSync(
    [Buffer.from("amm_config"), u16ToBytes(ammConfigIndex)],
    CPMM_PROGRAM_ID,
  );
  const [authority] = PublicKey.findProgramAddressSync(
    [Buffer.from("vault_and_lp_mint_auth_seed")],
    CPMM_PROGRAM_ID,
  );
  const [poolState] = PublicKey.findProgramAddressSync(
    [
      Buffer.from("pool"),
      ammConfig.toBuffer(),
      token0Mint.toBuffer(),
      token1Mint.toBuffer(),
    ],
    CPMM_PROGRAM_ID,
  );
  const [lpMint] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault0] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault1] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  return {
    ammConfig,
    authority,
    poolState,
    lpMint,
    token0Mint,
    token1Mint,
    vault0,
    vault1,
    observation,
  };
}
```

<Tip>
  **Всегда сортируйте mint'ы перед выводом PDA пула.** Seed хеширует два mint'а в порядке байтов, а не в порядке пользователя. Два пула с `(A, B)` и `(B, A)` столкнулись бы в цепи — сортировка — это то, как программа делает отображение каноническим.
</Tip>

<Note>
  **ID пула не всегда является каноническим PDA.** `Initialize` принимает произвольную пару ключей подписанта как `pool_state` в дополнение к PDA выше. Если переданный аккаунт не совпадает с каноническим PDA, программа требует, чтобы он был подписантом — то есть создатель передаёт свежую пару ключей, которую они подписывают. Это защита от фронт-раннинга: любая третья сторона, спешащая захватить канонический PDA, может быть обойдена законным создателем, использующим вместо этого случайную пару ключей. Нижестоящие PDA (`lpMint`, `vault0`, `vault1`, `observation`) по-прежнему выводятся из `poolState.key()`, поэтому они остаются уникальными для любого использованного адреса. При индексировании пулов всегда обнаруживайте ID пула из состояния в цепи (например, аккаунты `PoolState` под программой CPMM), а не путём вывода канонического PDA — последний пропустит пулы со случайными парами ключей.
</Note>

## Макеты аккаунтов

Полные определения на Rust находятся в исходном коде [`raydium-cp-swap`](https://github.com/raydium-io/raydium-cp-swap). Поля ниже — это те, которые вы будете читать при интеграции.

### `PoolState`

```rust
// programs/cp-swap/src/states/pool.rs
pub struct PoolState {
    pub amm_config: Pubkey,               // привязывает этот пул к AmmConfig
    pub pool_creator: Pubkey,             // кто запустил initialize
    pub token_0_vault: Pubkey,            // == vault0 PDA
    pub token_1_vault: Pubkey,            // == vault1 PDA

    pub lp_mint: Pubkey,
    pub token_0_mint: Pubkey,
    pub token_1_mint: Pubkey,

    pub token_0_program: Pubkey,          // программа SPL Token или Token-2022
    pub token_1_program: Pubkey,

    pub observation_key: Pubkey,          // == observation PDA
    pub auth_bump: u8,
    pub status: u8,                       // битовая маска: deposit | withdraw | swap
    pub lp_mint_decimals: u8,
    pub mint_0_decimals: u8,
    pub mint_1_decimals: u8,

    pub lp_supply: u64,                   // отражает предложение lp_mint
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,
    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time: u64,                   // unix; swap'ы отклоняются до этого времени
    pub recent_epoch: u64,

    // Состояние комиссии создателя (добавлено после исходного макета):
    pub creator_fee_on: u8,               // 0=BothToken, 1=OnlyToken0, 2=OnlyToken1
    pub enable_creator_fee: bool,
    pub padding1: [u8; 6],
    pub creator_fees_token_0: u64,
    pub creator_fees_token_1: u64,

    pub padding: [u64; 28],
}
```

Что на самом деле нужно читать:

- **`lp_supply`** — внутреннее общее количество LP пула. Оно **не** равно предложению LP mint'а: оно ровно на 100 базовых единиц выше, потому что 100 заблокированных единиц считаются здесь, но никогда не выпускаются. Вся математика доли LP (deposit, withdraw) делится на `lp_supply`, поэтому используйте это поле и не подставляйте предложение mint'а из цепи.
- **`protocol_fees_token{0,1}`**, **`fund_fees_token{0,1}`** — *накопленные* комиссии, ещё не собранные. Они не влияют на цену swap'а; они находятся в хранилищах до вызова `CollectProtocolFee` / `CollectFundFee`. `protocol_fees_token{0,1}` также получает долю протокола комиссии создателя при сборе комиссии создателя, поэтому растёт вне swap'ов — см. [`products/cpmm/fees`](/ru/products/cpmm/fees#protocol-share-of-the-creator-fee).
- **`status`** — битовая маска, контролирующая, разрешены ли `Swap`, `Deposit`, `Withdraw`. Обновляется администратором через `UpdatePoolStatus`. SDK проверяет это перед построением транзакции; если вы CPI'ите напрямую, проверьте это сами.
- **`token0_program` / `token1_program`** — программа токена для CPI в каждое хранилище. Один может быть классическим SPL Token, а другой Token-2022; они независимы.
- **`open_time`** — временная метка Unix. Swap'ы до этого времени не удаются. Deposit'ы разрешены до `open_time`, чтобы пул мог быть заполнен.
- **`creator_fee_on` / `enable_creator_fee`** — вместе контролируют, активна ли опциональная комиссия создателя для этого пула и с какой стороны swap'а она собирается. `enable_creator_fee == false` полностью обнуляет путь комиссии создателя. Когда включено, `creator_fee_on` выбирает: `0` = взять комиссию с любого токена, который является входом swap'а (`BothToken`); `1` = взять комиссию только из `token_0` (пропустить на swap'ах `token_1 → token_0`); `2` = взять комиссию только из `token_1`. Устанавливается при создании пула через `InitializeWithPermission`; не может измениться позже.
- **`creator_fees_token_{0,1}`** — накопленные комиссии создателя, собираемые через `CollectCreatorFee` или `CollectCreatorFeePermissionless`. Оба пути обнуляют полные счётчики, но с обновлением creator-fee-share от 2026-09-19 из пула уходит только часть баланса: доля протокола **добавляется к `protocol_fees_token_{0,1}`** и остаток передаётся создателю. Путь без разрешения фиксирует получателей на канонических ATA `pool_creator`. Сам `PoolState` не изменился — нет отдельного счётчика для общей суммы.

### `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub disable_create_pool: bool,
    pub index: u16,                       // совпадает с seed'ом
    pub trade_fee_rate: u64,              // например, 2500 = 0.25%
    pub protocol_fee_rate: u64,           // доля торговой комиссии протоколу
    pub fund_fee_rate: u64,               // доля торговой комиссии фонду
    pub create_pool_fee: u64,             // оплачивается один раз при инициализации (в SOL или токене)
    pub protocol_owner: Pubkey,           // может вызвать CollectProtocolFee
    pub fund_owner: Pubkey,               // может вызвать CollectFundFee
    pub creator_fee_rate: u64,            // опциональная ставка комиссии создателя пула (1/1_000_000 от объёма)
    pub creator_fee_share_rate: u64,      // доля протокола ОТ комиссии создателя по умолчанию
    pub padding: [u64; 14],
}
// AmmConfig::LEN == 236 байт — не изменилось.
```

Три вещи, на которые нужно обратить внимание:

1. **`trade_fee_rate` и `creator_fee_rate` — доли объёма**, обе обозначены в единицах `1/1_000_000`. `2500` означает 0.25% от объёма торговли. **`protocol_fee_rate` и `fund_fee_rate` — доли *торговой комиссии*** (не объёма), в том же знаменателе `1/1_000_000`. Комиссия создателя **не** является долей торговой комиссии — это её собственная независимая ставка. Полная арифметика находится в [`products/cpmm/fees`](/ru/products/cpmm/fees).
2. **`index` — это `u16`**, поэтому seed хеш использует 2 байта big-endian. Ошибка на один в порядке байтов — частая ошибка интеграции.
3. **`AmmConfig` неизменяем на уровне пула.** Пул указывает на один `AmmConfig` при создании и никогда не переключается. Изменения комиссий распространяются, потому что пул читает конфиг при каждом swap'е — но пул не может быть перемещён между уровнями комиссии.

Заметка о комиссиях создателя: сама **ставка** (`creator_fee_rate`) находится на `AmmConfig` и общая для уровня комиссии. Взимает ли конкретный пул её на самом деле (`enable_creator_fee`) и с какой стороны swap'а она приземляется (`creator_fee_on`) находятся на `PoolState`. Комиссия создателя **независима** от торговой комиссии — это её собственная ставка, накопленная на её собственные счётчики (`creator_fees_token_{0,1}`), и никогда не уменьшает доли LP / протокола / фонда торговой комиссии. Сборка происходит через `CollectCreatorFee` или ограниченный по назначению `CollectCreatorFeePermissionless`, и оба пути передают долю накопленного баланса протоколу на выходе — по `creator_fee_share_rate`, или по ставке на PDA [`CreatorFeeShare`](#creatorfeeshare) когда он существует для пары `(creator, amm_config)`. См. [`products/cpmm/fees`](/ru/products/cpmm/fees#protocol-share-of-the-creator-fee) для полной механики.

### `Permission`

Небольшой аккаунт контроля доступа, используемый `InitializeWithPermission`. Программа CPMM поддерживает путь создания пула с разрешением, чтобы другие программы (например, LaunchLab при переводе токена на CPMM) могли доказать, что они имеют право создать пул для данного `AmmConfig`.

```rust
pub struct Permission {
    pub authority: Pubkey,    // кому разрешено вызывать InitializeWithPermission
    pub padding: [u64; 30],
}
// Permission::LEN == 8 + 32 + 8 * 30 == 280 байт
```

PDA Permission создаётся через `CreatePermissionPda` либо администратором CPMM, либо выделенным создателем PDA разрешений. С обновлением 2026-09 `ClosePermissionPda` принимает тех же двух подписантов; раньше это было только администратором. Конечные пользователи не взаимодействуют с этим аккаунтом напрямую — это сантехника для кросс-программных потоков. См. [`security/admin-and-multisig`](/ru/security/admin-and-multisig) для границы роли и [`reference/program-addresses`](/ru/reference/program-addresses) для канонических адресов.

### `CreatorFeeShare`

Опциональный аккаунт, который переопределяет долю протокола в комиссии создателя для одной пары `(pool creator, AmmConfig)`. Добавлено обновлением creator-fee-share от 2026-09-19.

```rust
// programs/cp-swap/src/states/creator_fee_share.rs
pub const CREATOR_FEE_SHARE_SEED: &str = "creator_fee_share";

pub struct CreatorFeeShare {
    pub bump: u8,
    pub creator: Pubkey,       // создатель пула, к которому применяется эта ставка
    pub amm_config: Pubkey,    // уровень комиссии, к которому применяется эта ставка
    pub share_rate: u64,       // доля протокола ОТ комиссии создателя, 1/1_000_000
    pub padding: [u64; 8],
}
// CreatorFeeShare::LEN == 8 + 1 + 32 * 2 + 8 + 8 * 8 == 145 байт
```

```ts
const [creatorFeeShare] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_share"), creator.toBuffer(), ammConfig.toBuffer()],
  CPMM_PROGRAM_ID, // см. reference/program-addresses
);
```

Как это работает:

- **Это опционально, но аккаунт никогда не опционален в инструкции.** `CollectCreatorFee` и `CollectCreatorFeePermissionless` оба объявляют `creator_fee_share` с ограничением seed выше и берут его при каждом вызове. Программа затем проверяет, пуст ли аккаунт или принадлежит иностранцу; если так, она возвращается к `AmmConfig.creator_fee_share_rate`. Поэтому клиент должен всегда выводить и передавать адрес, независимо от того, существует ли аккаунт.
- **`share_rate` ограничен `FEE_RATE_DENOMINATOR_VALUE` (`1_000_000`)** при создании и снова при выполнении разделения. `1_000_000` маршрутизирует всю комиссию создателя протоколу; `0` не маршрутизирует ничего.
- **Создаётся и закрывается администратором или выделенным органом власти** через `CreateCreatorFeeShare` / `CloseCreatorFeeShare`. Закрытие возвращает ренту подписанту и возвращает пару к значению по умолчанию конфига; создатель пула не является подписантом ни на одном пути.
- **Это ключ по создателю, а не по пулу.** Один аккаунт управляет каждым пулом, который этот создатель имеет на этом `AmmConfig`. Создатель с пулами на двух уровнях комиссии нуждается в двух аккаунтах, чтобы быть охваченным на обоих.

Арифметика разделения, которую она управляет, находится в [`products/cpmm/fees`](/ru/products/cpmm/fees#protocol-share-of-the-creator-fee).

### Хранилища и Token-2022

`vault0` и `vault1` принадлежат PDA authority CPMM, и их владелец token-программы (`token_program`) — это либо SPL Token, либо Token-2022, определяемый при создании пула программой mint'а. Пул прозрачно обрабатывает оба случая — вы передаёте правильный ID token-программы для каждой стороны в аккаунты инструкции `Swap` / `Deposit` / `Withdraw`.

CPMM применяет строгий **список разрешений расширений** при создании пула (`is_supported_mint` в `utils/token.rs`). Mint Token-2022 может использоваться в пуле CPMM только если **каждое** расширение, которое он несёт, находится в этом списке:

- **`TransferFeeConfig`.** Применяется mint'ом при каждом переводе. Пул находится на принимающей стороне для deposit'ов `SwapBaseInput` и на отправляющей стороне для вывода. Программа вычисляет **чистую** сумму, попадающую в хранилище, и устанавливает кривую соответственно. См. [`algorithms/token-2022-transfer-fees`](/ru/algorithms/token-2022-transfer-fees).
- **`MetadataPointer`** и **`TokenMetadata`.** Стандартные метаданные на mint'е. Никакого влияния на математику swap'а.
- **`InterestBearingConfig`.** UI сумма mint'а начисляет проценты. Хранилище хранит сырые суммы; кривая работает только с сырыми суммами. UI'ы, которые показывают APR, должны вызывать помощников Token-2022 для отображения UI суммы.
- **`ScaledUiAmount`.** Расширение масштабирования отображения UI. Такая же обработка, как `InterestBearingConfig` — кривая использует сырые суммы.

Любое другое расширение — `PermanentDelegate`, `TransferHook`, `DefaultAccountState`, `NonTransferable`, `ConfidentialTransfer`, `Group`/`GroupMember`, `MintCloseAuthority` и т.д. — вызывает отклонение `Initialize` с `NotSupportMint`. Единственное исключение — это **реестр для каждого mint'а**: если PDA `SupportMintAssociated` существует с seed `[b"support_mint", mint]`, mint допускается независимо от его набора расширений. Этот PDA создаётся и удаляется администратором (или выделенным органом поддержки mint'ов) через `CreateSupportMintAssociated` / `CloseSupportMintAssociated`, поэтому подключение конкретного mint'а больше не требует обновления программы.

<Note>
  **Изменено в 2026-09.** CPMM ранее также содержал жестко закодированный четырёхадресный `MINT_WHITELIST`, который обходил проверку расширений. Этот массив был **удалён**; реестр PDA теперь является единственным обходом. Любой mint, который полагался на жестко закодированный список, нуждается в PDA `SupportMintAssociated` перед созданием нового пула для него — существующие пулы не затронуты, потому что проверка выполняется только при создании пула.
</Note>

Список проверенных расширений находится в исходном коде CP-Swap под `programs/cp-swap/src/utils/token.rs` и может измениться с будущими обновлениями программы. См. [`reference/token-2022-support`](/ru/reference/token-2022-support) для матрицы кросс-программ.

### Observation

Аккаунт observation — это кольцевой буфер записей `ObservationState`, каждая хранящая `block_timestamp` и **кумулятивную цену**. При каждом swap'е программа добавляет новое наблюдение, если прошло достаточно времени с последнего. TWAP'ы вычисляются путём чтения двух наблюдений и деления `Δcumulative / Δtime`.

```rust
// OBSERVATION_NUM жестко закодирован в программе как 100.
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp:              u64,
    pub cumulative_token_0_price_x32: u128,   // Q32.32, верхние 64 бита оставлены для переполнения
    pub cumulative_token_1_price_x32: u128,
}

pub struct ObservationState {
    pub initialized:           bool,
    pub observation_index:     u16,                            // циклический индекс
    pub pool_id:               Pubkey,
    pub observations:          [Observation; OBSERVATION_NUM], // 100 записей
    pub last_update_timestamp: u64,                            // временная метка самого последнего добавления
    pub padding:               [u64; 3],
}
```

Кольцевой буфер рассчитан на **100 наблюдений**. Каждое наблюдение — 40 байт (`8 + 16 + 16`), поэтому сам массив — 4,000 байт; `ObservationState::LEN` — ровно **4,075 байт** (`8 + 1 + 2 + 32 + 4,000 + 8 × 4`).

Два правила потребителя:

- **Не используйте одно наблюдение как цену.** Это *кумулятив*, а не спот-цена. Используйте два из них для вычисления TWAP.
- **Выбирайте наблюдения по крайней мере на один блок друг от друга.** Swap'ы в одном блоке могут не создать новое наблюдение; чтение подряд может вернуть одну и ту же запись.

Больше математики в [`products/clmm/accounts`](/ru/products/clmm/accounts).

## Жизненный цикл аккаунта

| Событие | Созданные аккаунты | Уничтоженные аккаунты |
|---------|-------------------|----------------------|
| `Initialize` | `poolState`, `lpMint`, `vault0`, `vault1`, `observation` | — |
| `Deposit` | — (может создать пользовательский LP ATA) | — |
| `Withdraw` | — | — |
| `Swap` | — (может создать пользовательский целевой ATA) | — |
| `CollectProtocolFee` | — | — |
| `CollectFundFee` | — | — |
| `CollectCreatorFee` / `CollectCreatorFeePermissionless` | — (путь без разрешения может создать ATA создателя) | — |
| `CreateCreatorFeeShare` | `creatorFeeShare` | — |
| `CloseCreatorFeeShare` | — | `creatorFeeShare` |
| `UpdatePoolStatus` | — | — |

Пулы CPMM и их PDA **никогда не закрываются**. `Permission`, `SupportMintAssociated` и `CreatorFeeShare` — исключения — это автономные управляемые администратором записи, а не состояние пула, и каждый имеет явную инструкцию закрытия. Даже при нулевой ликвидности `poolState` остаётся. Это намеренно: повторное заполнение того же пула позже сохраняет его исторический буфер наблюдений и его вывод PDA остаётся стабильным.
