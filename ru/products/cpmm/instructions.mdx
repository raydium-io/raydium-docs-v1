## Сводка инструкций

| Имя дискриминатора | Кто подписывает | Что делает |
|-------|-----------|--------------|
| `Initialize` | создатель пула | Создать новый пул CPMM из двух минтов и `AmmConfig`. Без ограничений; может вызвать кто угодно. Жёстко устанавливает `enable_creator_fee = false` на новом пуле. Счёт `pool_state` может быть либо каноническим PDA, либо свежей случайной парой ключей (см. счёты Initialize). |
| `InitializeWithPermission` | плательщик + владелец PDA `Permission` | Версия `Initialize` с ограничениями. Вызывающий (`payer`) должен владеть PDA `Permission`, производным от своего публичного ключа. Используется платформами, которым нужно контролировать создание пула (например, LaunchLab graduations). Позволяет вызывающему зафиксировать `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) и устанавливает `enable_creator_fee = true` на новом пуле. Поле `creator` на `pool_state` устанавливается в отдельно переданный счёт `creator`, а не плательщик. Та же гибкость канонического-PDA-или-случайной-пары для `pool_state`, что и в `Initialize`. |
| `Deposit` | LP | Добавить ликвидность в обоих токенах; получить LP-токены. |
| `Withdraw` | LP | Сжечь LP-токены; получить оба базовых токена пропорционально. |
| `SwapBaseInput` | трейдер | Своп с точным входом (`amount_in` входит, ≥ `minimum_amount_out` выходит). |
| `SwapBaseOutput` | трейдер | Своп с точным выходом (≤ `maximum_amount_in` входит, `amount_out` выходит). |
| `CollectProtocolFee` | `protocol_owner` (из `AmmConfig`) | Собрать накопленные комиссии протокола из хранилищ. |
| `CollectFundFee` | `fund_owner` (из `AmmConfig`) | Собрать накопленные комиссии фонда из хранилищ. |
| `CollectCreatorFee` | `pool_creator` | Собрать накопленные комиссии создателя (если комиссия создателя была включена). |
| `CollectCreatorFeePermissionless` | любой плательщик | Собрать все накопленные комиссии создателя на канонические токен-счёты `pool_creator`. Плательщик может создавать недостающие ATA получателя, но не может перенаправить перевод. |
| `UpdatePoolStatus` | `admin` | Приостановить / возобновить конкретные операции на пуле через битовую маску. |
| `UpdateAmmConfig` | `admin` | Изменить ставки комиссий или владельца протокола/фонда на `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Создать новый уровень комиссий (новый счёт `AmmConfig`). |
| `CreatePermissionPda` | `admin` или делегированный создатель permission-PDA | Выпустить PDA `Permission`, который позволяет конкретному органу вызывать `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` или выделенный создатель permission-PDA | Отозвать ранее выданный PDA `Permission`. С обновления 2026-09 выделенный орган-создатель может также закрыть выданное им разрешение; раньше это было только для админа. |
| `CreateSupportMintAssociated` | `admin` или выделенный владелец support-mint | Зарегистрировать минт Token-2022, который иначе не прошёл бы список разрешений расширений, создав его PDA `SupportMintAssociated`. |
| `CloseSupportMintAssociated` | `admin` или выделенный владелец support-mint | Удалить регистрацию минта. |
| `CollectExcessLamports` | `admin` или выделенный кошелёк collect-lamports | Собрать лампорты выше минимума для освобождения от ренты из хранилищ, контролируемых CPMM, LP-минтов и PDA. Добавлено в 2026-09. |

Битовая маска статуса: `status` каждого пула — это `u8`, где бит 0 = депозит отключен, бит 1 = вывод отключен, бит 2 = своп отключен (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` в программе). Нулевой бит означает, что операция разрешена; установленный бит означает, что она приостановлена. `UpdatePoolStatus` принимает сырой `u8` и перезаписывает существующее значение.

Следующие разделы подробно рассматривают каждую инструкцию. Порядок счётов соответствует IDL CPMM; SDK и Rust-клиент в `raydium-cp-swap/programs/cp-swap/src/instructions` соответствуют этому порядку.

## `Initialize`

Создать новый пул CPMM.

**Аргументы**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; своп отклоняется до этого времени
```

**Счёты** (W = записываемый, S = подписывающий)

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Платит ренту; записывается как `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | Выбранный уровень комиссий. |
| 3 | `authority` |   |   | PDA глобального органа CPMM. |
| 4 | `pool_state` | W | S* | `init`иализируется здесь. **Либо** канонический PDA `["pool", amm_config, token_0_mint, token_1_mint]` **либо** свежая случайная пара ключей — когда не канонический PDA, программа требует, чтобы `pool_state` подписал (`require_eq!(pool_account_info.is_signer, true)`). Путь со случайной парой ключей позволяет создателю избежать фронт-ранов на каноническом PDA. Нижестоящие PDA (`lp_mint`, `vaults`, `observation_state`) производны от `pool_state.key()` в любом случае. |
| 5 | `token_0_mint` |   |   | Отсортированы: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | `init`иализируется здесь. Орган установлен на `authority`. |
| 8 | `creator_token_0` | W |   | Исходный ATA для `init_amount_0`. |
| 9 | `creator_token_1` | W |   | Исходный ATA для `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | ATA создателя на `lp_mint`. `init` (а не `init_if_needed`) — он не должен уже существовать, что и невозможно, поскольку `lp_mint` создаётся в этой же инструкции. |
| 11 | `token_0_vault` | W |   | `init`иализируется здесь. Принадлежит `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Целевой ATA для `create_pool_fee`, уплачиваемой создателем. |
| 14 | `observation_state` | W |   | `init`иализируется здесь. |
| 15 | `token_program` |   |   | SPL Token (для LP-минта). |
| 16 | `token_0_program` |   |   | SPL Token или Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token или Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` подписывает только на пути со случайной парой ключей; канонический-PDA путь работает без подписи `pool_state`.

**Предусловия**

- Минты отсортированы (`token_0_mint < token_1_mint` по порядку байтов).
- Ни один минт не использует расширение вне списка разрешений CPMM (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — см. [`products/cpmm/accounts`](/ru/products/cpmm/accounts#vaults-and-token-2022). Минт, у которого существует PDA `SupportMintAssociated` (seed `[b"support_mint", mint]`), пропускает проверку расширений — **но вы обязаны добавить этот PDA в `remaining_accounts`**. Программа сканирует только переданные вами аккаунты и никогда не загружает PDA сама, поэтому расчёт на реестр без передачи аккаунта всё равно завершится ошибкой `NotSupportMint` (`6007`). Порядок не важен (сопоставление идёт по ключу); передайте по одной записи на каждый минт, которому нужен обход. Этот реестр — единственный обход с тех пор, как обновление 2026-09 удалило жёстко закодированный список четырёх минтов.
- `creator` имеет по крайней мере `init_amount_0` и `init_amount_1` в соответствующих ATA.
- `amm_config.disable_create_pool == false`.

**Постусловия**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — **полный** квадратный корень. Создателю минтится `lp_supply − 100`; 100 заблокированных базовых единиц учитываются в `lp_supply`, но никогда не минтятся.
- Поэтому `lp_mint.supply == pool_state.lp_supply − 100` на всё время жизни пула. Вся математика LP-доли (депозит, вывод) делит на `lp_supply`, поэтому используйте это поле и не подставляйте предложение минта в цепи. Откатывается с `InitLpAmountTooLess`, если `sqrt(...) < 100`.
- `observation_state` инициализирован; `observation_index = 0` и `pool_id = pool_state.key()`.
- `create_pool_fee` лампортов переводятся от создателя к получателю и синхронизируются как нативный SOL (это ATA wSOL).
- Битовая маска статуса пула — `0` (депозит / вывод / своп все включены).
- `enable_creator_fee = false` и `creator_fee_on = BothToken`. `Initialize` **не** поддерживает включение комиссии создателя — этот путь — `InitializeWithPermission`.
- `open_time` увеличивается до `block_timestamp + 1`, если вызывающий передал значение `<= block_timestamp`. Своп отклоняется до `open_time`; депозиты и выводы работают сразу.

**Частые ошибки** (полный список в [`reference/error-codes`](/ru/reference/error-codes))

- `InvalidInput` — минты не отсортированы или идентичны.
- `NotSupportMint` — заблокированное расширение Token-2022.
- `ExceededSlippage` — редко; если `init_amount_0/1` приводят к нулевому LP из-за несовпадения десятичных знаков.

## `Deposit`

Добавить ликвидность в обоих токенах пропорционально пулу.

**Аргументы**

```
lp_token_amount:   u64   // сколько LP-токенов выпустить LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Математика**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // same for side 1
```

Две детали, которые стоит зафиксировать: база для пропорционального расчёта — это итог хранилища **без учёта комиссий** (`vault_amount_without_fee`, то есть сырой баланс минус накопленные счётчики протокола, фонда и создателя), а не сырой баланс хранилища; и ограничение проскальзывания проверяется относительно того, что плательщик фактически переводит, *после* добавления transfer fee Token-2022, а не относительно валового движения хранилища.

Без изменения пропорциональности `k` — оба итога и `lp_supply` масштабируются на один и тот же коэффициент.

**Постусловия**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (нетто любой комиссии передачи Token-2022 на входе).
- `vault_1 += needed_token_1` (нетто любой комиссии передачи Token-2022 на входе).

**Частые ошибки** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus`, если депозит приостановлен.

## `Withdraw`

Сжечь LP-токены и получить оба базовых токена пропорционально.

**Аргументы**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

Первые 13 аккаунтов идентичны `Deposit`, а `lp_mint` записываемый, потому что LP-токены сжигаются. `Withdraw` дополнительно принимает 14-й аккаунт, `memo_program` (с ограничением `address = memo::ID`) — у `Deposit` его нет. `Withdraw` с 13 аккаунтами не проходит десериализацию Anchor, поэтому LP не может выйти.

**Математика**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // same for side 1

// As with Deposit: the base is the fee-excluded vault total, and the floor is
// checked against what the LP actually receives, after the transfer fee.
```

**Постусловия**

- `lp_supply -= lp_token_amount`.
- Хранилища отправляют `out_token_0` / `out_token_1` (валовой; пользователь получает нетто любой комиссии передачи Token-2022).

## `SwapBaseInput`

Своп с точным входом.

**Аргументы**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

Порядок **вход → выход** определяется направлением пользователя, а не каноническим `token_0 / token_1` пула. Программа определяет, какое хранилище какое, сопоставляя минты.

**Математика** — см. [`products/cpmm/math`](/ru/products/cpmm/math).

**Предусловия**

- `open_time <= now`.
- `pool_status` разрешает своп.
- Ни один минт не приостановлен или заморожен для этого органа.
- `amount_in > 0`.

**Частые ошибки**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — сделка округляется до нуля.
- `NotApproved` — пул приостановлен для свопов через `UpdatePoolStatus`.
- `InvalidInput` — минты не совпадают ни с одним из минтов хранилища пула.

## `SwapBaseOutput`

Своп с точным выходом.

**Аргументы**

```
max_amount_in:  u64
amount_out:     u64
```

**Счёты** — то же, что `SwapBaseInput`.

**Математика** — обратная кривая с потолком, см. [`products/cpmm/math`](/ru/products/cpmm/math).

**Частые ошибки** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

## `CollectProtocolFee`

Собрать накопленные комиссии протокола из хранилищ в назначение протокола.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `owner` |   | S | Должен совпадать с `amm_config.protocol_owner` **либо** с жёстко закодированным в программе ключом администратора. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**Эффект**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

Без изменения эффективных балансов кривой (накопленные комиссии уже были исключены).

**Частая ошибка** — `InvalidOwner` (`6001`), если подписывающий не является ни `amm_config.protocol_owner`, ни администратором программы. (На этом пути нет `NotApproved`.)

## `CollectFundFee`

Та же форма, что `CollectProtocolFee`, но подписана `amm_config.fund_owner` — или, опять же, администратором программы — и обнуляет счётчики `fund_fees_*`. Тот же `InvalidOwner` при неверном подписанте.

## `CollectCreatorFee`

Подписана `pool_state.pool_creator`. Она переводит полные балансы `creator_fees_token_0` и `creator_fees_token_1` на токен-счёты создателя, затем обнуляет оба счётчика. Возвращает `NoFeeCollect`, когда оба счётчика равны нулю.

## `CollectCreatorFeePermissionless`

Любой может запустить сбор комиссии создателя. Инструкция всегда отправляет полные накопленные балансы на канонические связанные токен-счёты, принадлежащие `pool_state.pool_creator`; вызывающий не может выбрать другого создателя или назначение. Если какой-либо ATA отсутствует, плательщик финансирует его создание.

Оригинальный `CollectCreatorFee` остаётся вызываемым, поэтому существующие клиенты остаются совместимыми.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Любой подписывающий; финансирует недостающие ATA создателя. |
| 2 | `creator` |   |   | Должен равняться `pool_state.pool_creator`; не подписывает. |
| 3 | `authority` |   |   | PDA органа хранилища и LP-минта CPMM с seed `[b"vault_and_lp_mint_auth_seed"]`. Подписывает CPI программы токенов. |
| 4 | `pool_state` | W |   | Содержит накопленные счётчики комиссии создателя. |
| 5 | `token_0_vault` | W |   | Должен совпадать с хранилищем токена 0 пула. |
| 6 | `token_1_vault` | W |   | Должен совпадать с хранилищем токена 1 пула. |
| 7 | `vault_0_mint` |   |   | Должен совпадать с `token_0_vault.mint`. |
| 8 | `vault_1_mint` |   |   | Должен совпадать с `token_1_vault.mint`. |
| 9 | `creator_token_0` | W |   | Канонический ATA создателя для `vault_0_mint`; создаётся, если отсутствует. |
| 10 | `creator_token_1` | W |   | Канонический ATA создателя для `vault_1_mint`; создаётся, если отсутствует. |
| 11 | `token_0_program` |   |   | SPL Token или Token-2022, соответствующий токену 0. |
| 12 | `token_1_program` |   |   | SPL Token или Token-2022, соответствующий токену 1. |
| 13 | `associated_token_program` |   |   | Создаёт недостающий ATA получателя. |
| 14 | `system_program` |   |   | Финансирует создание счёта из `payer`. |

**Эффект**

- Переводит все `creator_fees_token_0` и `creator_fees_token_1` из хранилищ пула на ATA создателя.
- Обнуляет оба счётчика комиссии создателя и обновляет `pool_state.recent_epoch`.
- Возвращает `NoFeeCollect`, когда оба счётчика равны нулю.


**Счёты**

| 1 | `authority` |   | S | Должен совпадать с ключом админа программы CPMM. |

Ключ администратора — это pubkey, **вкомпилированный в программу** (`crate::admin::ID`), а не полномочие обновления BPF — его изменение требует обновления программы. ## `CreateAmmConfig`

Создать новый уровень комиссий.

**Аргументы**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `owner` | W | S | Админ. |
| 2 | `amm_config` | W |   | `init`иализируется здесь. |
| 3 | `system_program` |   |   |

**Предусловия**

- Нет существующего `AmmConfig` с тем же `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **Изменено в 2026-09: владельцы комиссий новой конфигурации больше не берутся от подписывающего.** `create_amm_config` теперь записывает жёстко закодированный `protocol_fee_owner::ID` программы в `protocol_owner` и `fund_fee_owner::ID` в `fund_owner`, вместо копирования ключа подписывающего админа в оба. Адреса находятся в [`reference/program-addresses`](/ru/reference/program-addresses#cpmm-fee-owner-wallets).

  Последствия: комиссии по вновь созданному `AmmConfig` попадают в выделенные кошельки комиссий, а не в кошелёк администратора. Администратор при этом остаётся допустимым *подписантом* для сбора — `CollectProtocolFee` / `CollectFundFee` принимают `amm_config.protocol_owner` / `fund_owner` **либо** `crate::admin::ID` — поэтому для сбора ничего поворачивать не нужно; изменилось только то, куда по умолчанию идут поступления. **Существующие счёта `AmmConfig` не переписываются** — всё, что на них хранится, по-прежнему управляет, поэтому всегда читайте `protocol_owner` / `fund_owner` со счёта вместо предположения любого значения. Параметры `UpdateAmmConfig` `3` и `4` по-прежнему их поворачивают.
</Note>

## `UpdateAmmConfig`

Изменить ставки комиссий или владение на существующем `AmmConfig`. Принимает `param: u8` (какое поле обновить) и `value: u64`. Полная таблица диспетчеризации:

- `param = 0` → `trade_fee_rate` (проверяет `trade_fee_rate + creator_fee_rate < 1_000_000`)
- `param = 1` → `protocol_fee_rate` (проверяет `≤ 1_000_000` и `+ fund_fee_rate ≤ 1_000_000`)
- `param = 2` → `fund_fee_rate` (проверяет `≤ 1_000_000` и `+ protocol_fee_rate ≤ 1_000_000`)
- `param = 3` → `protocol_owner`. Новый ключ передаётся **не** в `value`: добавьте его как `remaining_accounts[0]` (только для чтения — нормально). Он не должен быть pubkey по умолчанию, а пропуск этого аккаунта вызывает панику на `unwrap()`.
- `param = 4` → `fund_owner`. Тот же механизм, что и у `3`.
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool` (любое ненулевое `value` отключает)
- `param = 7` → `creator_fee_rate` (проверяет `creator_fee_rate + trade_fee_rate < 1_000_000`)

Любой другой `param` возвращает `InvalidInput`.

Изменения подписаны админом и влияют на **каждый пул, привязанный к этому `AmmConfig`** при следующем своп. Без миграции; пулы просто читают новые значения.

## `CollectExcessLamports`

Административный сбор лампортов, сидящих выше минимума для освобождения от ренты на счётах, контролируемых CPMM. Добавлено в обновление 2026-09, чтобы протокол мог вернуть избыточное финансирование, которое [SIMD-0437 снижение ренты](/ru/solana-fundamentals/rent-and-reclaimable-rent) оставляет на счётах, созданных до каждого шага.

Движется только избыток. Балансы токенов, данные счёта, владельцы, состояние пула и кривая не трогаются, и инструкция — это холостой ход против счёта, уже находящегося на минимуме — поэтому безопасно переустанавливать после каждого развёртывания.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | Назначение для каждого собранного лампорта. Должен быть либо админом программы CPMM, либо выделенным кошельком collect-lamports — см. [`reference/program-addresses`](/ru/reference/program-addresses#excess-lamports-collection-wallets). Любой другой подписывающий не пройдёт с `InvalidOwner`. |
| 2 | `authority` |   |   | PDA органа хранилища и LP-минта CPMM с seed `[b"vault_and_lp_mint_auth_seed"]`. Подписывает CPI программы токенов. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. Оба требуются безусловно; программа выбирает по исходному счёту. |
| 5.. | `remaining_accounts` | W |   | `M` исходных счётов для сбора, любое количество, любой порядок. |

**Как обрабатывается каждый исходный счёт**

Программа распределяет по `owner` исходного счёта:

| Владелец исходного счёта | Обработка |
|---|---|
| SPL Token или Token-2022, не-нативный токен-счёт или минт — хранилища пула и LP-минты | CPI `WithdrawExcessLamports` (дискриминант программы токенов `38`), подписано `authority`. |
| SPL Token или Token-2022, **нативный** (wSOL) токен-счёт | `WithdrawExcessLamports` отклоняет нативные счёта. Программа CPI `SyncNative`, измеряет, насколько выросла обёрнутая `amount`, `UnwrapLamports` (дискриминант `45`) ровно на эту дельту, затем требует, чтобы обёрнутый баланс равнялся его значению до синхронизации — иначе `LamportsCalculateError` (`6015`). Хранилище пула на стороне SOL поэтому сохраняет полную ликвидность. |
| Сама программа CPMM — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | Программа дебетует счёт прямо до `rent.minimum_balance(data_len)`. |
| Что-либо ещё | **Пропускается молча.** Нет ошибки, лампорты не движутся. |

Поскольку она принимает неограниченный список `remaining_accounts`, размер транзакции — это реальный лимит — то же ограничение, что и сбор на стороне кошелька, описанный в [`solana-fundamentals/rent-and-reclaimable-rent`](/ru/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**Частые ошибки** — `InvalidOwner` (`6001`, неправильный подписывающий), `LamportsCalculateError` (`6015`, круговой оборот wSOL не нетто к нулю), и `InsufficientFunds` из пути, принадлежащего программе, когда счёт содержит меньше, чем его собственный минимум ренты.

**Нет SDK-построителя.** `@raydium-io/raydium-sdk-v2` не поставляет построитель для этой инструкции, и ни `raydium-sdk-V2-demo` репо — это административный путь. Кодируйте вручную, как сбор на стороне кошелька в [`solana-fundamentals/rent-and-reclaimable-rent`](/ru/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) делает для инструкции программы токенов.
