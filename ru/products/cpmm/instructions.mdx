## Обзор инструкций

| Имя дискриминатора | Кто подписывает | Что делает |
|-------|-----------|--------------|
| `Initialize` | создатель пула | Создаёт новый пул CPMM из двух монет и `AmmConfig`. Без ограничений; может вызвать кто угодно. Жёстко устанавливает `enable_creator_fee = false` для нового пула. Счёт `pool_state` может быть либо каноническим PDA, либо свежей случайной парой ключей (см. Initialize accounts). |
| `InitializeWithPermission` | плательщик + владелец PDA `Permission` | Версия `Initialize` с ограничениями. Вызывающий (`payer`) должен владеть PDA `Permission`, производным от своего публичного ключа. Используется платформами, требующими контролируемого создания пулов (например, LaunchLab graduations). Позволяет вызывающему установить `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) и принудительно устанавливает `enable_creator_fee = true` для нового пула. Поле `creator` в `pool_state` устанавливается на отдельно переданный счёт `creator`, а не на плательщика. Та же гибкость канонического PDA или случайной пары ключей для `pool_state`, что и в `Initialize`. |
| `Deposit` | LP | Добавляет ликвидность в обе монеты; получает LP-токены. |
| `Withdraw` | LP | Сжигает LP-токены; получает обе базовые монеты пропорционально. |
| `SwapBaseInput` | трейдер | Своп с точным входом (`amount_in` на входе, ≥ `minimum_amount_out` на выходе). |
| `SwapBaseOutput` | трейдер | Своп с точным выходом (≤ `maximum_amount_in` на входе, `amount_out` на выходе). |
| `CollectProtocolFee` | `protocol_owner` (из `AmmConfig`) | Собирает накопленные комиссии протокола из хранилищ. |
| `CollectFundFee` | `fund_owner` (из `AmmConfig`) | Собирает накопленные комиссии фонда из хранилищ. |
| `CollectCreatorFee` | `pool_creator` | Собирает накопленные комиссии создателя (если они были включены). |
| `CollectCreatorFeePermissionless` | любой плательщик | Собирает все накопленные комиссии создателя на канонические токен-счета `pool_creator`. Плательщик может создавать недостающие ATA получателя, но не может перенаправить перевод. |
| `UpdatePoolStatus` | `admin` | Приостанавливает / возобновляет определённые операции на пуле через битовую маску. |
| `UpdateAmmConfig` | `admin` | Изменяет ставки комиссий или владельца протокола/фонда в `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Создаёт новый уровень комиссий (новый счёт `AmmConfig`). |
| `CreatePermissionPda` | `admin` или делегированный создатель permission-PDA | Создаёт PDA `Permission`, позволяющий определённому органу вызывать `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` | Отзывает ранее выданный PDA `Permission`. |

Битовая маска статуса: `status` каждого пула — это `u8`, где бит 0 = депозит отключен, бит 1 = вывод отключен, бит 2 = своп отключен (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` в программе). Нулевой бит означает, что операция разрешена; установленный бит означает, что она приостановлена. `UpdatePoolStatus` принимает сырой `u8` и перезаписывает существующее значение.

В следующих разделах каждая инструкция рассматривается подробно. Порядок счётов соответствует IDL CPMM; SDK и Rust-клиент в `raydium-cp-swap/programs/cp-swap/src/instructions` соответствуют этому порядку.

## `Initialize`

Создаёт новый пул CPMM.

**Аргументы**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; своп отклоняется до этого времени
```

**Счёты** (W = записываемый, S = подписывающий)

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Платит за аренду; записывается как `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | Выбранный уровень комиссий. |
| 3 | `authority` |   |   | Глобальный PDA органа CPMM. |
| 4 | `pool_state` | W | S* | Инициализируется здесь. **Либо** канонический PDA `["pool", amm_config, token_0_mint, token_1_mint]` **либо** свежая случайная пара ключей — когда это не канонический PDA, программа требует, чтобы `pool_state` подписал (`require_eq!(pool_account_info.is_signer, true)`). Путь со случайной парой ключей позволяет создателю избежать фронт-раннинга на каноническом PDA. Нижестоящие PDA (`lp_mint`, `vaults`, `observation_state`) производны от `pool_state.key()` в любом случае. |
| 5 | `token_0_mint` |   |   | Отсортирована: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | Инициализируется здесь. Орган установлен на `authority`. |
| 8 | `creator_token_0` | W |   | Исходный ATA для `init_amount_0`. |
| 9 | `creator_token_1` | W |   | Исходный ATA для `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | Назначение для LP (создаётся, если отсутствует). |
| 11 | `token_0_vault` | W |   | Инициализируется здесь. Принадлежит `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Целевой ATA для `create_pool_fee`, уплачиваемой создателем. |
| 14 | `observation_state` | W |   | Инициализируется здесь. |
| 15 | `token_program` |   |   | SPL Token (для LP mint). |
| 16 | `token_0_program` |   |   | SPL Token или Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token или Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` подписывает только на пути со случайной парой ключей; путь с каноническим PDA работает без подписи `pool_state`.

**Предусловия**

- Монеты отсортированы (`token_0_mint < token_1_mint` по порядку байтов).
- Ни одна монета не использует расширение вне списка разрешённых CPMM (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — см. [`/ru/products/cpmm/accounts`](/ru/products/cpmm/accounts#vaults-and-token-2022). Небольшой список разрешённых расширений для каждой монеты внутри программы обходит проверку для поэтапного подключения.
- `creator` имеет как минимум `init_amount_0` и `init_amount_1` в соответствующих ATA.
- `amm_config.disable_create_pool == false`.

**Постусловия**

- `pool_state` существует с `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- Стартовый LP в размере `LOCKED_LP` (`100` ламортов LP-токена) навсегда заблокирован в пуле — `pool_state.lp_supply` записывает `liquidity − 100`, в то время как `100` LP-единиц остаются вне обращения, предотвращая полное осушение пула и деление на ноль.
- `observation_state` инициализирован; `observation_index = 0` и `pool_id = pool_state.key()`.
- `create_pool_fee` ламортов переводятся от создателя к получателю и синхронизируются как нативный SOL (это ATA wSOL).
- Битовая маска статуса пула — `0` (депозит / вывод / своп все включены).
- `enable_creator_fee = false` и `creator_fee_on = BothToken`. `Initialize` **не** поддерживает включение комиссии создателя — этот путь — `InitializeWithPermission`.
- `open_time` увеличивается до `block_timestamp + 1`, если вызывающий передал значение `<= block_timestamp`. Своп отклоняется до `open_time`; депозиты и выводы работают сразу.

**Частые ошибки** (полный список в [`/ru/reference/error-codes`](/ru/reference/error-codes))

- `InvalidInput` — монеты не отсортированы или идентичны.
- `NotSupportMint` — заблокированное расширение Token-2022.
- `ExceededSlippage` — редко; если `init_amount_0/1` приводят к нулевому LP из-за несовпадения десятичных знаков.

## `Deposit`

Добавляет ликвидность в обе монеты пропорционально пулу.

**Аргументы**

```
lp_token_amount:   u64   // сколько LP-токенов выпустить LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Математика**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

Без изменения пропорциональности `k` — оба хранилища и `lp_supply` масштабируются на один и тот же коэффициент.

**Постусловия**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (за вычетом любой комиссии за передачу Token-2022 на входе).
- `vault_1 += needed_token_1` (за вычетом любой комиссии за передачу Token-2022 на входе).

**Частые ошибки** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus`, если депозит приостановлен.

## `Withdraw`

Сжигает LP-токены и получает обе базовые монеты пропорционально.

**Аргументы**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(Идентично `Deposit`; `lp_mint` записываемый, потому что LP-токены сжигаются.)

**Математика**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**Постусловия**

- `lp_supply -= lp_token_amount`.
- Хранилища отправляют `out_token_0` / `out_token_1` (валовой; пользователь получает нетто за вычетом любой комиссии за передачу Token-2022).

## `SwapBaseInput`

Своп с точным входом.

**Аргументы**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

Порядок **вход → выход** определяется направлением пользователя, а не каноническим `token_0 / token_1` пула. Программа определяет, какое хранилище какое, сопоставляя монеты.

**Математика** — см. [`/ru/products/cpmm/math`](/ru/products/cpmm/math).

**Предусловия**

- `open_time <= now`.
- `pool_status` разрешает своп.
- Ни одна монета не приостановлена или заморожена для этого органа.
- `amount_in > 0`.

**Частые ошибки**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — сделка округляется до нуля.
- `NotApproved` — пул приостановлен для свопов через `UpdatePoolStatus`.
- `InvalidInput` — монеты не совпадают ни с одной из монет хранилища пула.

## `SwapBaseOutput`

Своп с точным выходом.

**Аргументы**

```
max_amount_in:  u64
amount_out:     u64
```

**Счёты** — то же, что и `SwapBaseInput`.

**Математика** — обратная кривая с потолком, см. [`/ru/products/cpmm/math`](/ru/products/cpmm/math).

**Частые ошибки** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

## `CollectProtocolFee`

Собирает накопленные комиссии протокола из хранилищ в назначение протокола.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S | Должен совпадать с `amm_config.protocol_owner`. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**Эффект**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

Без изменения эффективных балансов кривой (накопленные комиссии уже были исключены).

**Частая ошибка** — `NotApproved`, если подписывающий не является `protocol_owner`.

## `CollectFundFee`

Та же структура, что и `CollectProtocolFee`, но подписана `fund_owner` и обнуляет счётчики `fund_fees_*`.

## `CollectCreatorFee`

Подписана `pool_state.pool_creator`. Переводит полные балансы `creator_fees_token_0` и `creator_fees_token_1` на токен-счета создателя, затем обнуляет оба счётчика. Возвращает `NoFeeCollect`, когда оба счётчика равны нулю.

## `CollectCreatorFeePermissionless`

Любой может запустить сбор комиссии создателя. Инструкция всегда отправляет полные накопленные балансы на канонические связанные токен-счета, принадлежащие `pool_state.pool_creator`; вызывающий не может выбрать другого создателя или назначение. Если какой-либо ATA отсутствует, плательщик финансирует его создание.

Исходный `CollectCreatorFee` остаётся вызываемым, поэтому существующие клиенты остаются совместимыми.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Любой подписывающий; финансирует недостающие ATA создателя. |
| 2 | `creator` |   |   | Должен равняться `pool_state.pool_creator`; не подписывает. |
| 3 | `authority` |   |   | Глобальный PDA органа хранилища CPMM. |
| 4 | `pool_state` | W |   | Содержит накопленные счётчики комиссии создателя. |
| 5 | `token_0_vault` | W |   | Должен совпадать с хранилищем токена 0 пула. |
| 6 | `token_1_vault` | W |   | Должен совпадать с хранилищем токена 1 пула. |
| 7 | `vault_0_mint` |   |   | Должен совпадать с `token_0_vault.mint`. |
| 8 | `vault_1_mint` |   |   | Должен совпадать с `token_1_vault.mint`. |
| 9 | `creator_token_0` | W |   | Канонический ATA создателя для `vault_0_mint`; создаётся, если отсутствует. |
| 10 | `creator_token_1` | W |   | Канонический ATA создателя для `vault_1_mint`; создаётся, если отсутствует. |
| 11 | `token_0_program` |   |   | SPL Token или Token-2022, соответствующий токену 0. |
| 12 | `token_1_program` |   |   | SPL Token или Token-2022, соответствующий токену 1. |
| 13 | `associated_token_program` |   |   | Создаёт недостающий ATA получателя. |
| 14 | `system_program` |   |   | Финансирует создание счёта из `payer`. |

**Эффект**

- Переводит все `creator_fees_token_0` и `creator_fees_token_1` из хранилищ пула на ATA создателя.
- Обнуляет оба счётчика комиссии создателя и обновляет `pool_state.recent_epoch`.
- Возвращает `NoFeeCollect`, когда оба счётчика равны нулю.

## `UpdatePoolStatus`

Приостанавливает или возобновляет отдельные операции на пуле. Поле `status` — это битовая маска:

| Бит | Флаг | Эффект при установке |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` отклоняется с `NotApproved`. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` отклоняется. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` отклоняются. |

**Аргументы**

```
status: u8      // новая битовая маска
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `authority` |   | S | Должен совпадать с ключом администратора программы CPMM. |
| 2 | `pool_state` | W |   |

Ключ администратора — это орган обновления программы CPMM — на практике мультиподпись Raydium. См. [`/ru/security/admin-and-multisig`](/ru/security/admin-and-multisig).

## `CreateAmmConfig`

Создаёт новый уровень комиссий.

**Аргументы**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` | W | S | Администратор. |
| 2 | `amm_config` | W |   | Инициализируется здесь. |
| 3 | `system_program` |   |   |

**Предусловия**

- Нет существующего `AmmConfig` с тем же `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

## `UpdateAmmConfig`

Изменяет ставки комиссий или владение существующим `AmmConfig`. Принимает `param: u8` (дискриминатор для выбора обновляемого поля) и `value: u64`. Семантика значения для каждого параметра находится в исходном коде; обычно:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (передайте байты `Pubkey` как переинтерпретацию)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

Изменения подписаны администратором и влияют на **каждый пул, привязанный к этому `AmmConfig`** при следующем своп. Без миграции; пулы просто читают новые значения.
