## Сводка инструкций

| Имя дискриминатора | Кто подписывает | Что она делает |
|-------|-----------|--------------|
| `Initialize` | создатель пула | Создать новый пул CPMM из двух минтов и `AmmConfig`. Без разрешений; может вызвать кто угодно. Жёстко кодирует `enable_creator_fee = false` на новом пуле. Счёт `pool_state` может быть либо каноническим PDA, либо свежей случайной парой ключей (см. счёты Initialize). |
| `InitializeWithPermission` | плательщик + владелец PDA `Permission` | Вариант `Initialize` с разрешениями. Вызывающий (`payer`) должен владеть PDA `Permission`, производным от своего публичного ключа. Используется платформами, которым нужно контролируемое создание пула (например, LaunchLab graduations). Позволяет вызывающему закрепить `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) и принудительно устанавливает `enable_creator_fee = true` на новом пуле. Поле `creator` на `pool_state` устанавливается на отдельно переданный счёт `creator`, а не на плательщика. Та же гибкость канонического-PDA-или-случайной-пары для `pool_state`, что и в `Initialize`. |
| `Deposit` | LP | Добавить ликвидность в оба токена; получить LP-токены. |
| `Withdraw` | LP | Сжечь LP-токены; получить оба базовых токена пропорционально. |
| `SwapBaseInput` | трейдер | Своп с точным входом (`amount_in` входит, ≥ `minimum_amount_out` выходит). |
| `SwapBaseOutput` | трейдер | Своп с точным выходом (≤ `maximum_amount_in` входит, `amount_out` выходит). |
| `CollectProtocolFee` | `protocol_owner` (из `AmmConfig`) | Собрать накопленные комиссии протокола из хранилищ. |
| `CollectFundFee` | `fund_owner` (из `AmmConfig`) | Собрать накопленные комиссии фонда из хранилищ. |
| `CollectCreatorFee` | `pool_creator` | Собрать накопленные комиссии создателя (если комиссия создателя была включена), за вычетом доли протокола, которая учитывается в протокольном бакете пула. |
| `CollectCreatorFeePermissionless` | любой плательщик | Собрать накопленные комиссии создателя на канонические токен-счёты `pool_creator`, за вычетом той же доли протокола. Плательщик может создавать отсутствующие ATA получателя, но не может перенаправить перевод. |
| `UpdatePoolStatus` | `admin` | Приостановить / возобновить определённые операции на пуле через битовую маску. |
| `UpdateAmmConfig` | `admin` | Изменить ставки комиссий или владельца протокола/фонда на `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Создать новый уровень комиссий (новый счёт `AmmConfig`). |
| `CreatePermissionPda` | `admin` или делегированный создатель permission-PDA | Выпустить PDA `Permission`, который позволяет определённому органу власти вызывать `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` или выделенный создатель permission-PDA | Отозвать ранее выданный PDA `Permission`. С обновления 2026-09 выделенный орган-создатель может также закрыть выданное им разрешение; раньше это было только для админа. |
| `CreateSupportMintAssociated` | `admin` или выделенный владелец support-mint | Зарегистрировать минт Token-2022, который иначе не прошёл бы список расширений, создав его PDA `SupportMintAssociated`. |
| `CloseSupportMintAssociated` | `admin` или выделенный владелец support-mint | Удалить регистрацию минта. |
| `CollectExcessLamports` | `admin` или выделенный кошелёк collect-lamports | Собрать лампорты выше минимума для освобождения от аренды из хранилищ, LP-минтов и PDA, контролируемых CPMM. Добавлено 2026-09. |
| `CreateCreatorFeeShare` | `admin` или выделенный владелец creator-fee-share | Установить пользовательскую долю протокола комиссии создателя для одной пары `(creator, amm_config)`, переопределяя `AmmConfig.creator_fee_share_rate`. Добавлено 2026-09-13. |
| `CloseCreatorFeeShare` | `admin` или выделенный владелец creator-fee-share | Удалить это переопределение; пара возвращается к значению по умолчанию конфига. Добавлено 2026-09-13. |

Битовая маска статуса: `status` каждого пула — это `u8`, где бит 0 = депозит отключен, бит 1 = вывод отключен, бит 2 = своп отключен (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` в программе). Очищенный бит означает, что операция разрешена; установленный бит означает, что она приостановлена. `UpdatePoolStatus` принимает сырой `u8` и перезаписывает существующее значение.

Следующие разделы подробно рассматривают каждую инструкцию. Порядок счётов соответствует IDL CPMM; SDK и Rust-клиент в `raydium-cp-swap/programs/cp-swap/src/instructions` соответствуют этому порядку.

## `Initialize`

Создать новый пул CPMM.

**Аргументы**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix timestamp; своп отклоняется до этого времени
```

**Счёты** (W = записываемый, S = подписывающий)

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Платит аренду; записывается как `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | Выбранный уровень комиссий. |
| 3 | `authority` |   |   | PDA глобального органа власти CPMM. |
| 4 | `pool_state` | W | S* | `init`иализируется здесь. **Либо** канонический PDA `["pool", amm_config, token_0_mint, token_1_mint]` **либо** свежая случайная пара ключей — когда не канонический PDA, программа требует, чтобы `pool_state` подписал (`require_eq!(pool_account_info.is_signer, true)`). Путь со случайной парой ключей позволяет создателю избежать попыток фронт-раннинга на каноническом PDA. Нижестоящие PDA (`lp_mint`, `vaults`, `observation_state`) производны от `pool_state.key()` в любом случае. |
| 5 | `token_0_mint` |   |   | Отсортировано: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | `init`иализируется здесь. Орган власти установлен на `authority`. |
| 8 | `creator_token_0` | W |   | Исходный ATA для `init_amount_0`. |
| 9 | `creator_token_1` | W |   | Исходный ATA для `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | ATA создателя на `lp_mint`. `init` (не `init_if_needed`) — он не должен существовать, что невозможно, так как `lp_mint` создаётся в этой же инструкции. |
| 11 | `token_0_vault` | W |   | `init`иализируется здесь. Принадлежит `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Целевой ATA для `create_pool_fee`, уплачиваемой создателем. |
| 14 | `observation_state` | W |   | `init`иализируется здесь. |
| 15 | `token_program` |   |   | SPL Token (для LP-минта). |
| 16 | `token_0_program` |   |   | SPL Token или Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token или Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` подписывает только на пути со случайной парой ключей; путь с каноническим PDA работает без подписи `pool_state`.

**Предусловия**

- Минты отсортированы (`token_0_mint < token_1_mint` по порядку байтов).
- Ни один минт не использует расширение вне списка разрешений CPMM (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — см. [`products/cpmm/accounts`](/ru/products/cpmm/accounts#vaults-and-token-2022). Минт, для которого существует PDA `SupportMintAssociated` (seed `[b"support_mint", mint]`), пропускает проверку расширения — **но вы должны добавить этот PDA в `remaining_accounts`**. Программа сканирует только переданные вами счёты и никогда не загружает PDA самостоятельно, поэтому полагаться на реестр без предоставления счёта всё равно не удаётся с `NotSupportMint` (`6007`). Порядок не имеет значения (сопоставление по ключу); передайте одну запись на минт, которому нужен обход. Этот реестр — единственный обход с тех пор, как обновление 2026-09 удалило жёстко закодированный список четырёх минтов.
- `creator` имеет по крайней мере `init_amount_0` и `init_amount_1` в соответствующих ATA.
- `amm_config.disable_create_pool == false`.

**Постусловия**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — **полный** квадратный корень. Создателю выдаётся `lp_supply − 100`; 100 заблокированных базовых единиц учитываются в `lp_supply`, но никогда не выпускаются.
- Таким образом, `lp_mint.supply == pool_state.lp_supply − 100` на протяжении всей жизни пула. Вся математика LP-доли (депозит, вывод) делится на `lp_supply`, поэтому используйте это поле и не подставляйте предложение минта в цепи. Возвращает `InitLpAmountTooLess`, если `sqrt(...) < 100`.
- `observation_state` инициализируется; `observation_index = 0` и `pool_id = pool_state.key()`.
- Лампорты `create_pool_fee` передаются от создателя получателю и синхронизируются как нативный SOL (это ATA wSOL).
- Битовая маска статуса пула — `0` (депозит / вывод / своп все включены).
- `enable_creator_fee = false` и `creator_fee_on = BothToken`. `Initialize` **не** поддерживает включение комиссии создателя — этот путь — `InitializeWithPermission`.
- `open_time` увеличивается до `block_timestamp + 1`, если вызывающий передал значение `<= block_timestamp`. Своп отклоняется до `open_time`; депозиты и выводы работают немедленно.

**Распространённые ошибки** (полный список в [`reference/error-codes`](/ru/reference/error-codes))

- `InvalidInput` — минты не отсортированы или идентичны.
- `NotSupportMint` — заблокировано расширение Token-2022.
- `ExceededSlippage` — редко; если `init_amount_0/1` приводят к нулевому LP из-за несовпадения десятичных знаков.

## `Deposit`

Добавить ликвидность в оба токена пропорционально пулу.

**Аргументы**

```
lp_token_amount:   u64   // сколько LP-токенов выпустить LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Математика**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // то же для стороны 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // то же для стороны 1
```

Два момента, которые стоит уточнить: база пропорции — это **исключённое комиссии** хранилище (`vault_amount_without_fee`, т.е. сырой баланс минус накопленные счётчики протокола, фонда и создателя), а не сырой баланс хранилища; и крышка проскальзывания проверяется против того, что плательщик фактически передаёт, *после* добавления комиссии передачи Token-2022, а не против валового движения хранилища.

Нет изменения пропорциональности `k` — обе суммы и `lp_supply` масштабируются на один и тот же коэффициент.

**Постусловия**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (за вычетом любой комиссии передачи Token-2022 на входе).
- `vault_1 += needed_token_1` (за вычетом любой комиссии передачи Token-2022 на входе).

**Распространённые ошибки** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus`, если депозит приостановлен.

## `Withdraw`

Сжечь LP-токены и получить оба базовых токена пропорционально.

**Аргументы**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

Первые 13 счётов идентичны `Deposit`, и `lp_mint` записываемый, потому что LP-токены сжигаются. `Withdraw` дополнительно принимает 14-й счёт, `memo_program` (ограничение `address = memo::ID`) — `Deposit` не принимает. `Withdraw` с 13 счётами не проходит десериализацию Anchor, поэтому LP не может выйти.

**Математика**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // то же для стороны 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // то же для стороны 1

// Как и в Deposit: база — это исключённое комиссии хранилище, и пол проверяется
// против того, что LP фактически получает, после комиссии передачи.
```

**Постусловия**

- `lp_supply -= lp_token_amount`.
- Хранилища отправляют `out_token_0` / `out_token_1` (валовой; пользователь получает за вычетом любой комиссии передачи Token-2022).

## `SwapBaseInput`

Своп с точным входом.

**Аргументы**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Счёты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

Порядок **вход → выход** определяется направлением пользователя, а не каноническим `token_0 / token_1` пула. Программа определяет, какое хранилище какое, сопоставляя минты.

**Математика** — см. [`products/cpmm/math`](/ru/products/cpmm/math).

**Предусловия**

- `open_time <= now`.
- `pool_status` разрешает своп.
- Ни один минт не приостановлен или заморожен для этого органа власти.
- `amount_in > 0`.

**Распространённые ошибки**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — сделка округляется до нуля.
- `NotApproved` — пул приостановлен для своп через `UpdatePoolStatus`.
- `InvalidInput` — минты не совпадают ни с одним из минтов хранилища пула.

## `SwapBaseOutput`

Своп с точным выходом.

**Аргументы**

```
max_amount_in:  u64
amount_out:     u64
```

**Счёты** — то же, что `SwapBaseInput`.

**Математика** — обратная кривая с потолком, см. [`products/cpmm/math`](/ru/products/cpmm/math).

**Распространённые ошибки** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

## `CollectProtocolFee`

Собрать накопленные комиссии протокола из хранилищ на целевой адрес протокола.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `owner` |   | S | Должен равняться `amm_config.protocol_owner` **или** жёстко закодированному ключу админа программы. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**Эффект**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

Нет изменения эффективных балансов кривой (накопленные комиссии уже исключены).

**Распространённая ошибка** — `InvalidOwner` (`6001`), если подписывающий ни `amm_config.protocol_owner`, ни админ программы. (На этом пути нет `NotApproved`.)

## `CollectFundFee`

Та же форма, что `CollectProtocolFee`, но подписана `amm_config.fund_owner` — или, опять же, админом программы — и обнуляет счётчики `fund_fees_*`. Та же `InvalidOwner` при неправильном подписывающем.

## `CollectCreatorFee`

Подписана `pool_state.pool_creator`. Она рассчитывает накопленную комиссию создателя и передаёт часть создателя на токен-счёты создателя.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Ограничение `address = pool_state.pool_creator`. |
| 2 | `authority` |   |   | PDA глобального органа власти хранилища CPMM. |
| 3 | `pool_state` | W |   | Содержит накопленные счётчики комиссии создателя. |
| 4 | `amm_config` |   |   | Ограничение `address = pool_state.amm_config`. Несёт значение по умолчанию `creator_fee_share_rate`. |
| 5 | `creator_fee_share` |   |   | **Добавлено 2026-09-13.** PDA в `["creator_fee_share", creator, amm_config]`. Должен быть передан при каждом вызове, но **не требуется существовать** — когда он пуст или не принадлежит CPMM, программа возвращается к `amm_config.creator_fee_share_rate`. Ограничение seed всё ещё применяется, поэтому адрес должен быть каноническим PDA. |
| 6 | `token_0_vault` | W |   | Должен совпадать с хранилищем token 0 пула. |
| 7 | `token_1_vault` | W |   | Должен совпадать с хранилищем token 1 пула. |
| 8 | `vault_0_mint` |   |   | Должен совпадать с `token_0_vault.mint`. |
| 9 | `vault_1_mint` |   |   | Должен совпадать с `token_1_vault.mint`. |
| 10 | `creator_token_0` | W |   | Целевой адрес для части создателя token 0. |
| 11 | `creator_token_1` | W |   | Целевой адрес для части создателя token 1. |
| 12 | `token_0_program` |   |   | SPL Token или Token-2022, совпадающий с token 0. |
| 13 | `token_1_program` |   |   | SPL Token или Token-2022, совпадающий с token 1. |
| 14 | `associated_token_program` |   |   | |
| 15 | `system_program` |   |   | |

**Эффект**

```
share_rate = creator_fee_share.share_rate   (если счёт существует)
           | amm_config.creator_fee_share_rate   (иначе)

shared_i  = floor(creator_fees_token_i * share_rate / 1_000_000)
creator_i = creator_fees_token_i - shared_i

transfer creator_i from vault_i to creator_token_i
pool_state.protocol_fees_token_i += shared_i     // остаётся в хранилище
pool_state.creator_fees_token_i   = 0
pool_state.recent_epoch = current epoch
```

Доля протокола никогда не покидает хранилище здесь — она переклассифицируется как комиссия протокола и ждёт `CollectProtocolFee`. Оба счётчика уже исключены из представления кривой о хранилище, поэтому цена пула не движется. Полный вывод в [`products/cpmm/fees`](/ru/products/cpmm/fees#protocol-share-of-the-creator-fee).

**Распространённые ошибки** — `NoFeeCollect`, когда оба счётчика создателя равны нулю (проверяется перед разделением), `InvalidInput` (`6003`), если разрешённый `share_rate` превышает `1_000_000`, `MathOverflow` (`6011`), если бронирование доли переполнит `protocol_fees_token_*`, и ошибка Anchor `ConstraintSeeds`, если `creator_fee_share` не является каноническим PDA.

## `CollectCreatorFeePermissionless`

Кто угодно может запустить сбор комиссии создателя. Инструкция всегда отправляет часть создателя на канонические связанные токен-счёты, принадлежащие `pool_state.pool_creator`; вызывающий не может выбрать другого создателя или целевой адрес. Если какой-либо ATA отсутствует, плательщик финансирует его создание.

Оригинальный `CollectCreatorFee` остаётся вызываемым, поэтому создатель, который хочет подписать для своего собственного сбора, всё ещё может.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |

| 2 | `creator` |   |   | Должен равняться `pool_state.pool_creator`; не подписывает. |
| 3 | `authority` |   |   | PDA глобального органа власти хранилища CPMM. |
| 4 | `pool_state` | W |   | Содержит накопленные счётчики комиссии создателя. |
| 5 | `amm_config` |   |   | **Добавлено 2026-09-13.** Ограничение `address = pool_state.amm_config`. |
| 6 | `creator_fee_share` |   |   | **Добавлено 2026-09-13.** Тот же PDA и то же правило опционального существования, что и на `CollectCreatorFee`. |
| 7 | `token_0_vault` | W |   | Должен совпадать с хранилищем token 0 пула. |
| 8 | `token_1_vault` | W |   | Должен совпадать с хранилищем token 1 пула. |
| 9 | `vault_0_mint` |   |   | Должен совпадать с `token_0_vault.mint`. |
| 10 | `vault_1_mint` |   |   | Должен совпадать с `token_1_vault.mint`. |
| 11 | `creator_token_0` | W |   | Канонический ATA создателя для `vault_0_mint`; создаётся, если отсутствует. |
| 12 | `creator_token_1` | W |   | Канонический ATA создателя для `vault_1_mint`; создаётся, если отсутствует. |
| 13 | `token_0_program` |   |   | SPL Token или Token-2022, совпадающий с token 0. |
| 14 | `token_1_program` |   |   | SPL Token или Token-2022, совпадающий с token 1. |
| 15 | `associated_token_program` |   |   | Создаёт отсутствующий ATA получателя. |

  Два новых счёта вставлены в позиции 5 и 6, **перед** хранилищами. Каждый счёт от `token_0_vault` далее сместился на два. Транзакция, собранная для предыдущей схемы с четырнадцатью счётами от 2026-09, не проходит ограничение — она неправильно читает хранилища как счёты конфига и не проходит десериализацию. Перестройте её, не патчьте.
</Warning>

**Эффект** — идентичен `CollectCreatorFee` выше: доля разрешается из `creator_fee_share` или `amm_config`, часть протокола учитывается в `protocol_fees_token_{0,1}`, часть создателя передаётся на ATA создателя, оба счётчика создателя обнуляются и `recent_epoch` обновляется. Возвращает `NoFeeCollect`, когда оба счётчика равны нулю.


## `CreateAmmConfig`

Создать новый уровень комиссий.

**Аргументы**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `owner` | W | S | Админ. |
| 2 | `amm_config` | W |   | `init`иализируется здесь. |
| 3 | `system_program` |   |   |

**Предусловия**

- Нет существующего `AmmConfig` с тем же `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **Изменено в 2026-09: владельцы комиссий нового конфига больше не берутся из подписывающего.** `create_amm_config` теперь записывает жёстко закодированный `protocol_fee_owner::ID` программы в `protocol_owner` и `fund_fee_owner::ID` в `fund_owner`, вместо копирования ключа подписывающего админа в оба. Адреса находятся в [`reference/program-addresses`](/ru/reference/program-addresses#cpmm-fee-owner-wallets).

  Последствия: комиссии на вновь созданном `AmmConfig` попадают в выделенные кошельки комиссий, а не в кошелёк админа. Админ остаётся принятым *подписывающим* для сбора — `CollectProtocolFee` / `CollectFundFee` принимают `amm_config.protocol_owner` / `fund_owner` **или** `crate::admin::ID` — поэтому ничего не нужно ротировать для сбора; что изменилось, это только то, куда по умолчанию идут доходы. **Существующие счёты `AmmConfig` не переписываются** — всё, что на них хранится, всё ещё управляет, поэтому всегда читайте `protocol_owner` / `fund_owner` со счёта вместо предположения любого значения. Параметры `UpdateAmmConfig` `3` и `4` всё ещё их ротируют.
</Note>

## `UpdateAmmConfig`

Изменить ставки комиссий или владение на существующем `AmmConfig`. Принимает `param: u8` (какое поле обновить) и `value: u64`. Полная таблица диспетчеризации:

- `param = 0` → `trade_fee_rate` (утверждает `trade_fee_rate + creator_fee_rate < 1_000_000`)
- `param = 1` → `protocol_fee_rate` (утверждает `≤ 1_000_000` и `+ fund_fee_rate ≤ 1_000_000`)
- `param = 2` → `fund_fee_rate` (утверждает `≤ 1_000_000` и `+ protocol_fee_rate ≤ 1_000_000`)
- `param = 3` → `protocol_owner`. Новый ключ **не** в `value`: добавьте его как `remaining_accounts[0]` (только для чтения в порядке). Он не должен быть ключом по умолчанию, и пропуск счёта паникует на `unwrap()`.
- `param = 4` → `fund_owner`. Тот же механизм, что `3`.
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool` (любое ненулевое `value` отключает)
- `param = 7` → `creator_fee_rate` (утверждает `creator_fee_rate + trade_fee_rate < 1_000_000`)
- `param = 8` → `creator_fee_share_rate` (утверждает `≤ 1_000_000`). Добавлено 2026-09-13. Доля протокола по умолчанию **комиссии создателя** на этом уровне; см. [`products/cpmm/fees`](/ru/products/cpmm/fees#protocol-share-of-the-creator-fee). Это не связано с `protocol_fee_rate`, который разделяет комиссию торговли.

Любой другой `param` возвращает `InvalidInput`.

Изменения подписаны админом и влияют на **каждый пул, привязанный к этому `AmmConfig`** при следующем своп. Нет миграции; пулы просто читают новые значения.

Установить пользовательскую долю протокола комиссии создателя для одной пары `(creator, amm_config)`, переопределяя `AmmConfig.creator_fee_share_rate` для каждого пула, который этот создатель владеет на этом уровне комиссий. Добавлено в обновление creator-fee-share 2026-09-13.

**Аргументы**

```
share_rate: u64   // доля протокола ОТ комиссии создателя, над FEE_RATE_DENOMINATOR = 1_000_000
```

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `owner` | W | S | Должен быть админом программы CPMM **или** выделенным владельцем creator-fee-share — см. [`reference/program-addresses`](/ru/reference/program-addresses#cpmm-creator-fee-share-authority). Любой другой подписывающий не проходит с `InvalidOwner` (`6001`). Платит аренду. |
| 2 | `creator` |   |   | Создатель пула, к которому применяется ставка. Не проверяется — это не должен быть существующий создатель пула, и он не подписывает. |
| 3 | `amm_config` |   |   | Уровень комиссий, к которому применяется ставка. |
| 4 | `creator_fee_share` | W |   | `init`иализируется здесь в `["creator_fee_share", creator, amm_config]`, `space = 145`. |
| 5 | `system_program` |   |   | |

**Предусловия**

- `share_rate <= 1_000_000`, иначе `InvalidInput` (`6003`).
- PDA не должен уже существовать — Anchor `init` не проходит при втором вызове для одной пары. Чтобы изменить ставку, закройте счёт и создайте его снова.

**Постусловия**

- `creator_fee_share` хранит `bump`, `creator`, `amm_config` и `share_rate`.
- Каждый последующий `CollectCreatorFee` / `CollectCreatorFeePermissionless` на пуле, созданном `creator` под `amm_config`, разрешает долю из этого счёта вместо конфига.

<Note>
  Создатель пула не является стороной этой инструкции и не подписывает её. Ставка читается во время сбора, поэтому переопределение, созданное после того, как комиссии уже накопились, применяется к этому накопленному балансу тоже.
</Note>

## `CollectExcessLamports`

Админ-сбор лампортов, сидящих выше минимума для освобождения от аренды на счётах, контролируемых CPMM. Добавлено в обновление 2026-09, чтобы протокол мог вернуть избыточное финансирование, которое [SIMD-0437 rent reduction](/ru/solana-fundamentals/rent-and-reclaimable-rent) оставляет на счётах, созданных до каждого шага.

Движется только избыток. Балансы токенов, данные счёта, владельцы, состояние пула и кривая не трогаются, и инструкция — это no-op для счёта, уже находящегося на минимуме — поэтому безопасно переиспользовать после каждого развёртывания шага.

**Аргументы** — нет.

**Счёты**

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | Целевой адрес для каждого собранного лампорта. Должен быть либо админом программы CPMM, либо выделенным кошельком collect-lamports — см. [`reference/program-addresses`](/ru/reference/program-addresses#excess-lamports-collection-wallets). Любой другой подписывающий не проходит с `InvalidOwner`. |
| 2 | `authority` |   |   | PDA органа власти хранилища-и-LP-минта CPMM в seed `[b"vault_and_lp_mint_auth_seed"]`. Он подписывает CPI токен-программы. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. Оба требуются безусловно; программа выбирает по исходному счёту. |
| 5.. | `remaining_accounts` | W |   | `M` исходных счётов для сбора, любое количество, любой порядок. |

<Note>
  **Исправление порядка, 2026-09-13.** Программа теперь делает два прохода по `remaining_accounts` — каждый CPI токен-программы сначала, затем прямые дебеты CPMM-управляемых PDA. Чередование их прерывалось с `UnbalancedInstruction` рантайма ("сумма балансов счётов до и после инструкции не совпадают") всякий раз, когда PDA дебетовался перед CPI, потому что ожидающие изменения лампортов вызывающего только сбрасываются в счёта, которые CPI фактически несёт. Вызывающие не должны группировать или сортировать список сами.
</Note>

**Как каждый исходный счёт обрабатывается**

Программа диспетчеризует по `owner` исходного счёта:

| Владелец исходного счёта | Обработка |
|---|---|
| SPL Token или Token-2022, не-нативный токен-счёт или минт — пулы хранилищ и LP-минты | CPI `WithdrawExcessLamports` (дискриминант токен-программы `38`), подписано `authority`. |
| SPL Token или Token-2022, **нативный** (wSOL) токен-счёт | `WithdrawExcessLamports` отклоняет нативные счёта. Программа CPI `SyncNative`, измеряет, насколько выросла обёрнутая `amount`, `UnwrapLamports` (дискриминант `45`) ровно на эту дельту, затем требует, чтобы обёрнутый баланс равнялся его значению до синхронизации — иначе `LamportsCalculateError` (`6015`). Хранилище пула SOL-стороны поэтому сохраняет свою полную ликвидность. |
| Сама программа CPMM — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | Программа дебетует счёт напрямую вниз до `rent.minimum_balance(data_len)`. |
| Что-либо ещё | **Пропущено молча.** Нет ошибки, лампорты не движутся. |

Потому что он принимает неограниченный список `remaining_accounts`, размер транзакции — это реальный лимит — то же ограничение, что и сбор со стороны кошелька, описанный в [`solana-fundamentals/rent-and-reclaimable-rent`](/ru/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**Распространённые ошибки** — `InvalidOwner` (`6001`, неправильный подписывающий), `LamportsCalculateError` (`6015`, wSOL round-trip не нетировал до нуля) и `InsufficientFunds` из пути, управляемого программой, когда счёт держит меньше, чем его собственный минимум аренды.

**Нет SDK-построителя.** `@raydium-io/raydium-sdk-v2` не поставляет построитель для этой инструкции, и ни `raydium-sdk-V2-demo` репо — это админ-путь. Кодируйте вручную, как сбор со стороны кошелька в [`solana-fundamentals/rent-and-reclaimable-rent`](/ru/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) делает для инструкции токен-программы.
