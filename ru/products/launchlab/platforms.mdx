## Зачем нужны платформы

Raydium хотела, чтобы LaunchLab был **общим примитивом**, а не единственным фирменным продуктом. Система Platform PDA позволяет экосистемам, поставщикам инструментов, сообществам и мем-командам предлагать кураторский или фирменный опыт запуска, который все еще использует одну и ту же базовую программу bonding curve LaunchLab и пул CPMM после миграции.

Примеры платформ, которые вы можете встретить:

- **Собственный интерфейс LaunchLab компании Raydium** на raydium.io/launchlab — эталонная реализация.
- **Партнёрские лаунчпады** — третьи стороны, которые зарегистрировали собственный Platform PDA для фирменного опыта запуска.
- **Специализированные платформы** — например, платформа, специфичная для сообщества, которая запускает только мемкоины, связанные с определённой тематикой, с пользовательской долей комиссии, финансирующей казну.

Все эти токены по-прежнему находятся в одной программе LaunchLab, переходят в одну программу CPMM и могут маршрутизироваться одними и теми же агрегаторами.

## Platform PDA

Каждая платформа представлена Platform PDA, хранящейся в программе LaunchLab. Поля включают:

| Поле | Описание |
|---|---|
| `platform_key` | Seed / идентификатор платформы, используется для получения Platform PDA. |
| `platform_fee_destination` | Счёт, который получает долю платформы от торговых комиссий до и после миграции. |
| `platform_fee_bps` | Доля комиссии платформы на своп-операциях до миграции (варьируется по платформам). |
| `creator_fee_rate` | Ставка комиссии создателя во время торговли на bonding curve. |
| `platform_scale`, `creator_scale`, `burn_scale` | Сохранённые масштабы LP. До обновления масштаб создателя переходил на Fee Key создателя. Для миграций, выполненных после этого, первые два объединяются в долю заблокированного LP платформы; `burn_scale` сжигается. |
| `cp_config_id` | Если целевой пункт назначения после миграции — CPMM, какой `AmmConfig` использовать — выбирает уровень комиссии. |
| `restrict_global_config` | Должны ли запуски представлять allow PDA, созданный платформой, для выбранного `GlobalConfig`. |
| `name`, `description`, `image_url` | Метаданные отображения, используемые кошельками и интерфейсами, поддерживающими фирменность платформы. |
| `tokens_launched` | Счётчик или индекс в блокчейне токенов, созданных под этой платформой. |

Точные названия полей находятся в IDL LaunchLab ([`sdk-api/anchor-idl`](/ru/sdk-api/anchor-idl)). Таблица выше — это описательный обзор.

## Что может контролировать платформа

**Захват комиссий:**

- **Доля комиссии платформы** на каждой операции покупки/продажи до миграции.
- **Доля после миграции** — до обновления от 2026-08-14 масштаб создателя создавал отдельный Fee Key создателя. Для миграций, выполненных после этого, `platform_scale + creator_scale` становится одной позицией заблокированного LP, принадлежащей платформе, и `burn_scale` сжигается.

**Целевой пункт назначения после миграции:**

- **CPMM** с `AmmConfig`, выбранным через `cp_config_id`. Все вновь инициализированные запуски используют CPMM.
- **AMM v4** остаётся только как путь выпуска для существующего состояния запуска, созданного с устаревшим типом миграции.

**Пользовательский опыт:**

- **Метаданные фирменности**, используемые приложением Raydium и любым кошельком / обозревателем, который отображает токены LaunchLab.
- **Настройка страницы запуска** — платформы, которые размещают собственный интерфейс, могут фильтровать токены, чтобы показывать только запуски собственной платформы.

## Что платформа не может контролировать

- **Математику bonding curve.** Форма кривой (логистическая, экспоненциальная и т. д.) является частью самой программы LaunchLab. Платформы выбирают из поддерживаемых кривых; они не могут добавлять произвольные пользовательские кривые.
- **Логику порога миграции.** Условие, которое запускает выпуск в CPMM, обеспечивается программой.
- **Основную безопасность / статус аудита.** Каждая платформа наследует историю аудита LaunchLab; вредоносная платформа не может обойти её, изменяя программу.

## Регистрация платформы

Программа LaunchLab предоставляет инструкцию `create_platform` (точное название из IDL). Вызывающие стороны передают:

- Seed, который будет использоваться для получения Platform PDA.
- Счёт назначения комиссии.
- Желаемые bps комиссии (подлежат ограничениям на уровне программы).
- Конфигурацию после миграции (ID `AmmConfig` CPMM, если применимо).
- Метаданные фирменности.

Аренда для Platform PDA оплачивается создателем. Обновления фирменности и некоторых параметров комиссии разрешены после создания органом управления платформы; структурные параметры (программа назначения миграции) обычно нет.

Точную сигнатуру инструкции в текущем IDL LaunchLab см. в [`products/launchlab/instructions`](/ru/products/launchlab/instructions).

## Экономическое взаимодействие

Один своп на bonding curve LaunchLab распределяет стоимость примерно так (точные соотношения устанавливаются платформой):

```
Покупатель платит:           100 SOL
Комиссия протокола (LaunchLab): – небольшой %
Комиссия платформы:          – platform_fee_bps%
Комиссия создателя (до миграции): – creator_fee_bps% (если включена)
Остаток (на кривую):         ~ остальное
```

После миграции токены LP имеют два эффективных пункта назначения:

```
Токены LP, выпущенные при выпуске:  100%
  → Сожжены:                           burnScale
  → Fee Key платформы:                 platformScale + creatorScale
```

Fee Key платформы представляет требуемые права на комиссию LP без возможности вывести заблокированную ликвидность. Сожжённый LP не имеет держателя Fee Key.

## Ограничение глобальных конфигураций

Администратор платформы может установить `restrict_global_config = 1` и создать один `PlatformAllowConfig` для каждого принятого `GlobalConfig`. Новые транзакции запуска должны затем добавить соответствующий allow PDA. Если ограничение отключено, платформа принимает любую конфигурацию, которая проходит другую валидацию программы.

## Примечания для интеграторов

- **Список токенов по платформе.** Используйте API endpoints pool-info / mint с фильтром `platform` (если поддерживается) для отображения только токенов, запущенных под конкретным Platform PDA.
- **Отображение фирменности.** Если вы создаёте кошелёк или обозреватель, который отображает токены LaunchLab, чтение имени платформы / URL изображения из Platform PDA — это намного лучший UX, чем отображение «LaunchLab» для каждого токена.
- **Математика комиссий.** Каждое предложение цены на bonding curve должно учитывать комиссию платформы в дополнение к комиссиям протокола и создателя. Помощники по расчёту цены SDK делают это автоматически, когда предоставляется Platform PDA.
