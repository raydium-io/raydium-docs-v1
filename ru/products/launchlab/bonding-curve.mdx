<Info>
  LaunchLab поддерживает три формы кривых, выбираемые при `Initialize`: **constant-product** (наиболее распространённая, форма с виртуальными резервами стандартной кривой `x · y = k`), **linear-price** и **fixed-price**. Формула порога выпуска одинакова для всех трёх. На этой странице подробно разбирается математика constant-product; линейная и фиксированная формы кратко описаны в конце.
</Info>

## Параметры, хранящиеся в `LaunchState`

| Поле | Значение |
|-------|---------|
| `curve_type` | `0` = constant-product (виртуальные резервы), `1` = fixed-price, `2` = linear-price. |
| `base_supply_max` | Максимальное количество базовых токенов, которые может выпустить кривая. |
| `base_supply_graduation` | Количество базовых токенов, которое необходимо продать для достижения выпуска. Обычно `0.8 × base_supply_max`; оставшиеся 20% становятся начальной ликвидностью пула после выпуска. |
| `quote_reserve_target` | Количество quote, которое запускает выпуск. Вычисляется при `Initialize` из параметров кривой + `base_supply_graduation`. |
| `virtual_base` / `virtual_quote` | Начальные значения виртуальных резервов для кривой constant-product. |
| `migrate_type` | Должно быть `CPSWAP` для новой инициализации. Сохранённое значение AMM v4 — только устаревшее состояние. См. [`instructions`](/ru/products/launchlab/instructions). |
| `fees.buy_numerator / buy_denominator` | Комиссия на покупку, например `100 / 10_000 = 1.00%`. |
| `fees.sell_numerator / sell_denominator` | Комиссия на продажу. Часто совпадает с покупкой. |
| `fees.protocol_share`, `fees.creator_share`, `fees.lp_share` | Распределение вышеуказанного, в сумме равное знаменателю. |

Названия полей в структуре Rust совпадают с полями `PoolState`, описанными в [`accounts`](/ru/products/launchlab/accounts); единицы выше — концептуальные.

## Кривая constant-product с виртуальными резервами (`curve_type = 0`)

Кривая по умолчанию и наиболее используемая. Все запуски в стиле Pump используют эту форму. Кривая предполагает наличие **виртуального резерва quote** `V_q` и **виртуального резерва base** `V_b` с самого начала (хранятся как `virtual_quote` и `virtual_base` в `PoolState`), поэтому эффективный пул выглядит как CPMM с этими резервами. Покупки следуют математике `x · y = k`:

```
(V_q + real_quote_in_after_fee) × (V_b + real_base_remaining − base_out) = V_q × V_b
```

решено для `base_out`:

```
base_out = (V_b + real_base_remaining) × quote_in_after_fee / (V_q + real_quote_in_after_fee)
```

Эффективная цена при продано base `s`:

```
price(s) = (V_q + real_quote_in(s)) / (V_b + real_base_remaining(s))
```

Тот же инвариант `x · y = k`, который LaunchLab применяет до выпуска, затем становится кривой CPMM после выпуска, поэтому переход механически безупречен: предельная цена при `base_sold = base_supply_graduation` равна цене, по которой открывается пул после выпуска с `(quote_vault, base_vault_remaining)` в качестве резервов.

## Кривая fixed-price (`curve_type = 1`)

Кривая с плоской ценой. Каждая покупка/продажа происходит по постоянной цене, настраиваемой при `Initialize`:

```
price(s) = virtual_quote / virtual_base    (постоянна для всех s)
```

Полезна для честных запусков, когда команда хочет единую цену для всех участников независимо от времени покупки. Выпуск запускается, когда продано `base_supply_graduation` (линейная зависимость стоимости делает вывод `quote_reserve_target` простым).

## Кривая linear-price (`curve_type = 2`)

Цена растёт линейно с `base_sold`:

```
price(s) = a · s     (a = наклон, выведен из virtual_base / virtual_quote)
```

Интегрированная стоимость:

```
cost(s_0, s_1) = a · (s_1² − s_0²) / 2
```

Квадратична по `base_sold` — ранние покупатели платят близко к нулю, поздние платят значительно больше, при этом предельная цена всегда растёт с фиксированным наклоном. Реализация на цепи находится в `curve/linear_price.rs`.

## Сравнение форм кривых

```
price
  │   linear (крутой хвост)               linear (curve_type = 2)
  │       ╱
  │      ╱
  │     ╱            const-product (curve_type = 0)
  │    ╱            ╱
  │   ╱           ╱
  │  ╱         ╱
  │ ╱       ╱
  │╱_____╱_______________________  fixed-price (curve_type = 1)
  └──────────────────────────────── base_sold
  0                  S_grad         S_max
```

## Порог выпуска

`quote_reserve_target` вычисляется при `Initialize` как количество quote, необходимое для увеличения `base_sold` с 0 до `base_supply_graduation`:

```
quote_reserve_target = cost(0, base_supply_graduation) × (1 + buy_fee_rate)
                                                         ^^^^^^^^^^^^^^^^^
                                                         приблизительно; точная
                                                         форма совпадает с
                                                         округлением комиссии
                                                         при Buy.
```

Запуск выпускается, как только `quote_vault.balance ≥ quote_reserve_target`. Поскольку покупки происходят дискретными размерами, фактический баланс при выпуске может немного превышать целевой — избыток становится дополнительной ликвидностью на стороне quote в результирующем пуле CPMM.

## Пошаговый пример — квадратичный запуск

Параметры:

- `base_supply_max        = 1_000_000_000` (1 миллиард базовых токенов, 6 десятичных)
- `base_supply_graduation = 800_000_000`   (80% продано запускает выпуск)
- `k                      = 40` (масштаб цены)
- Комиссии: 1% покупка, 1% продажа, распределение `lp:creator:protocol = 60:20:20`.

**Начальная цена** (`s = 0`): `0` (чистая квадратика начинается с нуля).

**Цена при 50% продано** (`s = 500_000_000`):

```
price = 40 × (500e6 / 1e9)² = 40 × 0.25 = 10  (quote за base, 6 десятичных)
```

**Цена при выпуске** (`s = 800_000_000`):

```
price = 40 × (800e6 / 1e9)² = 40 × 0.64 = 25.6
```

**Quote, необходимый для достижения выпуска** (интегрированная стоимость):

```
cost(0, 800_000_000) = (40 / (3 × 1e18)) × ((800e6)³ − 0)
                     = (40 / 3e18) × 5.12e26
                     ≈ 6.827e9
```

Итак, ≈ 6.827 единиц quote в нативном виде (в любом 6-десятичном quote mint, например ~6,827 USDC, если quote — USDC).

**Комиссия сверху**:

```
quote_reserve_target ≈ 6.827e9 × 1.01 ≈ 6.895e9  (6,895 USDC)
```

**Первая покупка** на `10 USDC`:

- Виртуальное состояние: `s = 0`, `quote_vault = 0`.
- Вычесть комиссию: `quote_after_fee = 10 × 0.99 = 9.9`.
- Решить `(40 / (3e18)) × s³ = 9.9` ⇒ `s ≈ 6.22e6` базовых токенов куплено.
- Комиссия 1% (`0.1 USDC`) распределена: lp `0.06`, creator `0.02`, protocol `0.02`. Доля lp остаётся в `quote_vault`; остальные две маршрутизируются в соответствующие счётчики накопления.

**Покупка при 75% продано** (приближение к выпуску):

Те же 10 USDC теперь покупают намного меньше base, потому что кривая крутая. Решение Ньютона при `s₀ = 750e6` с `quote_in_after_fee = 9.9` даёт примерно `∆s ≈ 0.4e6` — сокращение в ~15 раз в base на USDC по сравнению с первой покупкой.

## Механика комиссий во время фазы кривой

При каждой `Buy`:

```
gross_fee      = ceil(quote_in_gross × buy_numerator / buy_denominator)
lp_share       = gross_fee × fees.lp_share / fees.total_share
protocol_share = gross_fee × fees.protocol_share / fees.total_share
creator_share  = gross_fee × fees.creator_share / fees.total_share
```

- `lp_share` остаётся в `quote_vault`. Это то, что делает эффективную кривую более узкой (больше резерва quote против того же предложения base).
- `protocol_share` увеличивает `LaunchState.state_data.protocol_fees_quote`.
- `creator_share` увеличивает `LaunchState.state_data.creator_fees_quote`.

При `Sell` то же распределение применяется, но комиссия берётся из исходящего `quote_out`.

Оба счётчика очищаются через `CollectFees` (администратор или создатель, каждый на свой счётчик).

## Точность

- Количества на стороне base: `u64`.
- Количества на стороне quote: `u64`.
- Промежуточные кубы / произведения: `u128`.
- Решения Ньютона для "купить точное количество quote" и "продать точное количество quote" итерируют в `u128` с фиксированной точкой с настраиваемым максимальным количеством итераций (по умолчанию 10). Режим отказа — `NotConverged` — редко встречается вне граничных случаев близко к выпуску.

## Передача в CPMM

Когда срабатывает `Graduate`:

```
cpmm_quote_reserve = quote_vault − swept_protocol_fees − swept_creator_fees
cpmm_base_reserve  = base_vault                       // т.е. base_supply_max − base_sold
cpmm_initial_price = cpmm_quote_reserve / cpmm_base_reserve
```

Для квадратичной кривой `cpmm_initial_price` механически равна `price(base_sold)` (это предельная цена кривой в момент передачи). Пул CPMM открывается ровно по этой цене, поэтому наблюдатель, переходящий от UI кривой к UI CPMM, не видит скачка.
