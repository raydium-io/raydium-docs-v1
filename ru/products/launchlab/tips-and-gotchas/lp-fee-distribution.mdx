Когда токен LaunchLab мигрирует на CPMM, пул выпускает токены LP. До обновления от 2026-08-17 `creatorScale` блокировался отдельно для создателя токена. Для миграций, выполненных после обновления, `migrateCpLockNftScale` по-прежнему хранит три поля, которые в сумме дают `1_000_000`, но во время выполнения создаются только два назначения.

## Эффективное распределение

| Поле | Обновленное поведение |
|---|---|
| `platformScale` | Включено в долю заблокированного LP, принадлежащую платформе. |
| `creatorScale` | До обновления выпускал Fee Key, принадлежащий создателю. После обновления включено в долю заблокированного LP, принадлежащую платформе. |
| `burnScale` | Сжигается навсегда. Никакой Fee Key не представляет эту долю. |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

Когда `burnScale` равен нулю, платформа получает все единицы LP. Когда `effectivePlatformScale` равен нулю, весь LP сжигается и Fee Key платформы не создается.

## Примеры

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% заблокированного LP, принадлежащего платформе, 10% сжигается.
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// В соответствии с обновленной программой это дает 100% заблокированного LP, принадлежащего платформе.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% сжигается; Fee Key не создается.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## Связь с комиссиями создателя CPMM

Поля масштаба контролируют только владение LP. Они не устанавливают ставки комиссий за своп и не определяют получателя комиссии создателя CPMM. `cpConfigId` выбирает `AmmConfig` CPMM; `platformCpCreator` определяет, записывает ли пул CPMM исходного создателя запуска или адрес, выбранный платформой.

## Обновление распределения

Перед обновлением платформы:

- Убедитесь, что три значения в сумме дают ровно `1_000_000`.
- Представьте `platformScale + creatorScale` как эффективную долю платформы.
- Не обещайте Fee Key создателю на основе `creatorScale`.
- Сохраняйте владение Fee Key создателя, показанное миграциями, завершенными до обновления; эти записи не переписываются.
- Объясните изменение перед будущими запусками с использованием обновленной конфигурации.
