## Инвентарь инструкций

| Группа | Инструкция | Может вызвать |
|-------|-------------|-------------|
| Глобальная конфигурация | `CreateConfig` / `UpdateConfig` | Администратор программы; делегированный орган создания конфигурации также может вызвать `CreateConfig` |
| Жизненный цикл запуска | `Initialize` / `InitializeV2` | Любой (создатель) — базовый минт SPL Token; V2 записывает `amm_creator_fee_on` для будущего выпуска CPMM. Только V2 принимает минт котировки Token-2022. |
| Жизненный цикл запуска | `InitializeWithToken2022` | Любой (создатель) — базовый минт Token-2022, опциональный `TransferFeeConfig`; принимает любую программу токена котировки |
| Торговля | `BuyExactIn` / `BuyExactOut` | Любой — точный ввод / точный вывод покупки на кривой связи |
| Торговля | `SellExactIn` / `SellExactOut` | Любой — точный ввод / точный вывод продажи на кривой связи |
| Выпуск | `MigrateToAmm` | Кошелек миграции — устаревший выпуск AMM v4 для пулов, инициализированных до того, как было принято создание только CPMM. |
| Выпуск | `MigrateToCpswap` | Кошелек миграции — выпуск в CPMM. Все вновь инициализированные запуски используют этот путь. Оборачивает `InitializeWithPermission` на CPMM. |
| Комиссии | `CollectFee` | Администратор — сбор комиссий протокола с запуска |
| Комиссии | `CollectMigrateFee` | Администратор — сбор накопленных комиссий миграции |
| Комиссии | `ClaimCreatorFee` | Создатель — получение накопленных комиссий создателя во время фазы кривой |
| Вестинг | `CreateVestingAccount` | Создатель — выделение заблокированных токенов бенефициару, разблокированных после выпуска |
| Вестинг | `CreatePlatformVestingAccount` | Администратор платформы — выделение заблокированных токенов бенефициарам со стороны платформы |
| Вестинг | `ClaimVestedToken` | Бенефициар — получение разблокированных токенов после cliff |
| Конфигурация платформы | `CreatePlatformConfig` / `UpdatePlatformConfig` | Администратор платформы |
| Конфигурация платформы | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Администратор платформы — управление списком разрешённых форм кривых для каждой платформы |
| Комиссии платформы | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Администратор платформы |
| Доступ платформы | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Администратор платформы — управление списком разрешений `GlobalConfig`, используемым при включении ограничения платформой |

Разделение "ExactIn/ExactOut" отражает `SwapBaseInput` / `SwapBaseOutput` CPMM — в цепи это отдельные дискриминаторы инструкций с немного отличающимся округлением.

**Выбор пути выпуска.** Каждый новый вызов `Initialize`, `InitializeV2` и `InitializeWithToken2022` должен установить `migrate_type = 1` (`CPSWAP`). Любая попытка инициализировать новый пул, привязанный к AMM v4, возвращает `MigrateTypeNotMatch`. `amm_creator_fee_on` только выбирает, применяется ли результирующая комиссия создателя CPMM к токену котировки или обоим токенам; это не выбирает целевую программу.

`MigrateToAmm` остаётся вызываемым для существующего `PoolState`, который был инициализирован с `migrate_type = 0` до этого ограничения. Выпуск не переписывает существующее состояние пула и не удаляет устаревшую инструкцию.

**Программа токена на стороне котировки.** Минт котировки может принадлежать либо программе SPL Token, либо Token-2022. Каждая инструкция, которая её касается — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, все четыре торговые инструкции, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee` и `ClaimPlatformFeeFromVault` — принимает владеющую программу в слот своего аккаунта quote-program. Позиции аккаунтов не изменились; изменилось только принимаемое значение. Передайте программу, которая действительно владеет `GlobalConfig.quote_mint`, которую вы можете прочитать из бита1 `PoolState.token_program_flag` для существующего запуска (см. [`accounts`](/ru/products/launchlab/accounts#poolstate)) или из владельца аккаунта минта в противном случае.

Устаревший `Initialize` — исключение: его аккаунт quote-program всё ещё типизирован как SPL Token, поэтому конфигурация, чей минт котировки — Token-2022, должна быть запущена через `InitializeV2` или `InitializeWithToken2022`.

`MigrateToCpswap` — другое исключение, в противоположном направлении — он принимает **обе** программы безусловно, а не одну на минт. См. [аккаунты миграции ниже](#cpmm-migration-token-programs).

## `Initialize`

Создание нового запуска.

**Аргументы**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // или initial_virtual_quote_reserve для curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // встроенные name/symbol/uri; программа CPI в Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Аккаунты** (сокращённо)

| # | Имя | W | S | Примечания |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Оплачивает ренту + создание базового минта. |
| 2 | `launch_config` |   |   | Привязка конфигурации протокола. |
| 3 | `launch_state` | W |   | Новый аккаунт. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Свежая Keypair (или PDA) — эта инструкция инициализирует её. |
| 6 | `base_vault` | W |   | ATA `launch_authority` на `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA `launch_authority` на `quote_mint`. |
| 9 | `metadata` | W |   | PDA метаданных Metaplex. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token для базового минта. `InitializeV2` и `InitializeWithToken2022` принимают отдельный аккаунт quote-program, который может быть любой программой. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Предусловия**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Параметры комиссии проходят проверки `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK требует `≥ now`; программа допускает небольшое отставание по времени).
- `curve_type` распознан.

**Постусловия**

- `base_mint` имеет `supply = base_supply_max`, всё в `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` инициализирован с `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` вычислен из параметров кривой + `base_supply_graduation` + `buy_numerator` (приблизительно).
- Для `InitializeWithToken2022` с прикреплённым `TransferFeeConfig`: `transfer_fee_config_authority = launch_authority`, и `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` когда это поле установлено, иначе `launch_authority`. Сторона вывода записывается при создании минта именно для того, чтобы платформа могла собрать удержанные комиссии перед выпуском. См. [`platform-config`](/ru/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**Частые ошибки** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (канонический вариант: `BuyExactIn`)

Пользователь предоставляет фиксированный `quote_in`; кривая вычисляет `base_out`.

**Аргументы**

```
quote_in:          u64
minimum_base_out:  u64
```

**Аккаунты**

| # | Имя | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Предусловия**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Эффект**

1. Разделить `quote_in` на `quote_in_after_fee` и части комиссии.
2. Решить кривую методом Ньютона для `base_out` с учётом пост-комиссионной котировки.
3. `require(base_out ≥ minimum_base_out)` иначе вернуть `ExceededSlippage`.
4. Переместить `quote_in` пользователь → хранилище. Переместить `base_out` хранилище → пользователь.
5. Обновить `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Обновить счётчики комиссий (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Если `quote_reserve_real ≥ quote_reserve_target` после обновления, SDK обычно цепляет инструкцию `Graduate` в той же транзакции. Программа не автоматически выпускает внутри `Buy` — требуется последующий `Graduate`.

## `BuyExactOut`

Пользователь указывает точный `base_out`; программа вычисляет `quote_in`.

**Аргументы**

```
base_out:      u64
maximum_quote_in: u64
```

Те же аккаунты, что и `BuyExactIn`. Использует замкнутую форму квадратичного интеграла (или обратный CPMM для curve_type 1) вместо итерации Ньютона.

## `Sell` / `SellExactIn` / `SellExactOut`

Зеркало `Buy`. Пользователь возвращает `base_in` кривой и получает `quote_out`. Комиссия вычитается из `quote_out`, поэтому пользователь получает меньше, чем сырые интегрированные доходы.

**Предусловия** —

- `user_base_ata.balance ≥ base_in`.
- Продажа не может опустить `base_sold` ниже 0 (избыточно с учётом согласованности учёта).
- Запуск — `Active`.

**Эффект** — симметричен `Buy`. `base_sold` уменьшается, `quote_reserve_real` уменьшается. Комиссии всё ещё начисляются.

### Комиссии передачи на стороне котировки

Когда минт котировки имеет `TransferFeeConfig`, сумма, которую перемещает хранилище, и сумма, на которую дебетуется или кредитуется плательщик, отличаются, и граница проскальзывания проверяется со стороны плательщика. На минте котировки без расширения каждый случай ниже идентичен простому устаревшему минту.

| Инструкция | Аргумент | Проверено против |
|---|---|---|
| `BuyExactIn` | `amount_in` | Кривая оценена на `amount_in − transfer_fee(amount_in)` — что достигает хранилища. Полное заполнение дебетует ровно `amount_in`; частичное заполнение дебетует потреблённую сумму хранилища плюс его обратную комиссию. |
| `BuyExactOut` | `maximum_amount_in` | Сумма хранилища **плюс** обратная комиссия передачи — реальный дебет. |
| `SellExactIn` | `minimum_amount_out` | Что продавец сохраняет после удержания минтом его комиссии, не валовая сумма, покидающая хранилище. |
| `SellExactOut` | `amount_out` | Доставлено точно. Кривая нацелена на `amount_out` плюс обратная комиссия передачи. |

Два следствия для котирования:

- Граница, вычисленная так, как если бы минт был без комиссии, отклоняется. Передача свободной от комиссии стоимости как `maximum_amount_in` или свободных от комиссии доходов как `minimum_amount_out` возвращает `ExceededSlippage`.
- `real_quote` продвигается только на то, что достигло хранилища. `BuyExactIn` на `amount_in` на 5% минте котировки перемещает `real_quote` на `amount_in × 0.95`.

Минт котировки со 100%-комиссией (`10000` базовых пункта) не может быть инвертирован и возвращает `CalculateOverflow` на путях точного вывода.

Оба минта на стороне торговли также ограничены программой, переданной в их соответствующий слот, поэтому несовпадающий `base_token_program` теперь не срабатывает, а не игнорируется. См. [`algorithms/token-2022-transfer-fees`](/ru/algorithms/token-2022-transfer-fees) для базовой математики комиссий.

## `MigrateToAmm` / `MigrateToCpswap`

Выпуск запуска в торгуемый пул после того, как кривая достигла `total_quote_fund_raising`. Новые запуски только CPMM. `MigrateToAmm` сохраняется для существующих пулов, чьё сохранённое `migrate_type` — `0`.

**Кто подписывает**

- `MigrateToAmm` — `migrate_to_amm_wallet`, записанный на привязке `GlobalConfig`.
- `MigrateToCpswap` — `migrate_to_cpswap_wallet`, записанный на привязке `GlobalConfig`.

Эти кошельки обычно удерживаются операционным механизмом выпуска Raydium; на практике выпуск происходит секунды после пересечения порога, независимо от того, кто инициировал финальную покупку.

**Аргументы**

`MigrateToAmm` принимает три (в основном параметры рынка OpenBook, которые программа передаёт в AMM v4):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` не принимает никаких.

**Эффект (общий для обоих)**

1. Проверить `pool_state.status == Migrate` (т.е. `quote_reserve_target` был достигнут). Иначе вернуть `PoolMigrated` (статус уже был `Migrated`) или `PoolFunding` (всё ещё в финансировании).
2. Проверить `pool_state.migrate_type` соответствует инструкции (`0` для AMM, `1` для CPMM). Иначе вернуть `MigrateTypeNotMatch`.
3. Вычислить пост-выпускные резервы:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI в целевую программу (`AMM v4 Initialize2` или `CPMM InitializeWithPermission`) с этими резервами для создания пост-выпускного пула.
5. Для миграций CPMM, выполненных после обновления 2026-08-17, объединить `platform_scale + creator_scale` в одну заблокированную платформой долю LP и выпустить максимум один Fee Key NFT в `platform_nft_wallet`. Сжечь остаток `burn_scale`. До обновления `creator_scale` был заблокирован отдельно и его Fee Key перешёл создателю токена. Завершённые исторические миграции не изменяются. Для устаревшего выпуска AMM v4 расположение LP следует существующему потоку этой инструкции.
6. Отозвать `base_mint.mint_authority` (установить на `None`).
7. Переключить `pool_state.status = Migrated`, установить `vesting_schedule.start_time = block_time + cliff_period`.

**Передача полномочия расширения Token-2022 transfer-fee** — когда базовый минт — это минт Token-2022, несущий `TransferFeeConfig` **и** `PlatformConfig.transfer_fee_extension_auth` не по умолчанию, миграция также переназначает полномочия этого расширения ключу платформы:

- `transfer_fee_config_authority` всегда переназначается. PDA запуска `authority` держит его на протяжении всей пред-выпускной фазы, поэтому всегда есть что переместить.
- `WithheldWithdraw` переназначается **только когда PDA `authority` всё ещё его держит**. Запуски, созданные с 2026-08-27 и позже, уже несут `transfer_fee_extension_auth` на этом полномочии от создания минта, поэтому шаг пропускается. Охрана — это то, что предотвращает возврат миграции на этих минтах — PDA не может подписать полномочие, которое оно больше не держит.

Если `transfer_fee_extension_auth` — `Pubkey::default()` во время миграции, ни одно полномочие не перемещается и оба остаются с PDA `authority` навсегда. См. [`platform-config`](/ru/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

**Постусловия** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` будут отклонены с этого момента с `PoolMigrated`. Результирующий пул AMM канонический и торгуется как любой другой пул AMM v4 / CPMM.

**Частые ошибки** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### Оставшиеся аккаунты миграции CPMM

Клиенты, строящие `MigrateToCpswap`, должны использовать эти фиксированные индексы `remaining_accounts`:

| Индекс | Аккаунт |
|---|---|
| 0–4 | Владелец Fee Key платформы, минт, аккаунт токена, PDA заблокированной ликвидности и аккаунт метаданных |
| 5 | Оригинальный создатель запуска; используется когда `platform_cp_creator` не установлен |
| 6 | PDA разрешения CPMM, полученный из `[b"permission", launch_authority]` |
| 7 | Настроенный `platform_cp_creator`; используется когда поле не по умолчанию |
| 8 | PDA поддержки-минта CPMM для отсортированного `mint0`, полученный из `[b"support_mint", mint0]` |
| 9 | PDA поддержки-минта CPMM для отсортированного `mint1`, полученный из `[b"support_mint", mint1]` |

Инструкция требует как минимум десять оставшихся аккаунтов на обновленном пути. Аккаунты поддержки-минта — входы CPI только для чтения. Получите оба адреса даже когда минт не имеет инициализированной записи поддержки. Старые построители, которые всё ещё добавляют аккаунты блокировки создателя или опускают индексы 8–9, должны быть обновлены.

### Программы токенов миграции CPMM

`MigrateToCpswap` принимает обе программы токенов безусловно и сам определяет, какая программа владеет каждым минтом. Его два аккаунта программы токенов были переименованы соответственно:

| Позиция | Аккаунт | Значение |
|---|---|---|
| первый | `token_program` | Всегда устаревшая программа SPL Token |
| второй | `token_program_2022` | Всегда программа Token-2022 |

Они заменяют бывший `base_token_program` (какая бы программа ни владела базовым минтом) и `quote_token_program` (всегда устаревший). Позиции не изменились, поэтому это изменение значения, а не изменение макета — но два значения близки к инвертированным, и построитель, который продолжает передавать свою старую пару, будет поставлять Token-2022 там, где требуется устаревшая программа, как только любой минт будет минтом Token-2022.

Устаревшая программа требуется даже когда ни один минт её не использует, потому что минт LP CPMM и заблокированный NFT Fee Key ликвидности всегда живут на нём.

## Список разрешений `GlobalConfig` платформы

`PlatformConfig.restrict_global_config` управляет проверкой:

- `0`: платформа принимает любой иначе действительный `GlobalConfig`; аккаунт разрешения не требуется.
- `1`: `Initialize`, `InitializeV2` и `InitializeWithToken2022` должны включать соответствующий `PlatformAllowConfig` где-нибудь в `remaining_accounts`.

Администратор платформы создаёт или закрывает PDA с помощью `CreatePlatformAllowConfig` и `ClosePlatformAllowConfig`. Его семена — `[b"platform_allow_config", platform_config, global_config]`. Бывшие управляемые администратором инструкции `PlatformGlobalAccess` и PDA сняты с производства.
