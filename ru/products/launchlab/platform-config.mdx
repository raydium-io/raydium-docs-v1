Если `GlobalConfig` определяет правила на уровне протокола («комиссия за торговлю 1%, предложение должно быть не менее 10M, только этот кошелёк может выпуститься»), то `PlatformConfig` — это то, что каждая платформа запуска — pump.fun, собственный интерфейс Raydium, сторонние лаунчпады — использует для добавления своей комиссии, получения своей доли LP после выпуска, ограничения форм кривых, которые могут выбирать их запуски, и отображения своего брендинга (имя, веб-сайт, изображение) в цепи.
</Info>

## Что это такое

Аккаунт `PlatformConfig` управляет пятью сквозными задачами платформы:

1. **Брендинг** — имя, веб-сайт, ссылка на изображение, всё хранится встроенным образом, чтобы любой обозреватель или агрегатор мог отобразить платформу, которая запустила токен.
2. **Комиссия платформы** — дополнительная комиссия за торговлю (`fee_rate`) поверх `trade_fee_rate` протокола. Начисляется на `platform_fee_wallet` платформы. Ограничена 500 bps (`50000`) как при создании, так и при обновлении, повышена с 100 bps (`10000`) 26 августа 2026 г. — см. [Ограничения ставок](#rate-caps).
3. **Распределение миграции LP** — три сохранённых целых числа (`platform_scale`, `creator_scale`, `burn_scale`), которые в сумме дают `1_000_000`. До обновления от 17 августа 2026 г. масштаб создателя создавал отдельный Fee Key создателя. Миграции, выполненные после обновления, объединяют первые два в одну долю LP, принадлежащую платформе; остаток сжигается.
4. **Список разрешённых параметров кривой** — `Vec<PlatformCurveParam>`, в котором перечислены ровно те комбинации `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)`, которые разрешены на этой платформе. Если вектор пуст или все записи недействительны, **любая** комбинация разрешена; в противном случае запуски должны точно совпадать с одной из записей.
5. **Список разрешённых глобальных конфигов** — дополнительное ограничение, требующее `PlatformAllowConfig`, созданный платформой, для выбранного `GlobalConfig`.

Вывод PDA:

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // публичный ключ владельца платформы
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

(См. `create_platform_config` в исходном коде для канонического списка seed'ов.)

## Макет

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (знаменатель 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (знаменатель 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // подписывает ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // получает долю платформы NFT при выпуске CPMM
    pub platform_scale:              u64,               // доля LP, отчеканенная на платформу NFT
    pub creator_scale:               u64,               // доля создателя до обновления; добавляется к доле платформы после
    pub burn_scale:                  u64,               // доля LP, сжигаемая навсегда
    pub fee_rate:                    u64,               // комиссия платформы за торговлю (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 дополнено нулями
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig, к которому привяжется пул после выпуска
    pub creator_fee_rate:            u64,               // комиссия создателя, взимаемая до выпуска
    pub transfer_fee_extension_auth: Pubkey,            // для запусков Token-2022: кто наследует полномочия трансфер-комиссии после выпуска
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // доля платформы от total_locked_amount
    pub platform_cp_creator:         Pubkey,            // дополнительный создатель записи в пуле CPMM после выпуска
    pub restrict_global_config:      u8,                // 0 = без ограничений, 1 = требовать разрешение PDA
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // список разрешённых форм кривых
}
```

`platform_scale + creator_scale + burn_scale` должны равняться `1_000_000`. До обновления от 17 августа 2026 г. `creator_scale` был заблокирован отдельно, и его Fee Key переходил создателю токена. Для миграций, выполненных после обновления, он добавляется к `platform_scale`, и его права на заблокированный LP переходят платформе. Примеры результатов при обновлённой логике:

- `(0, 100_000, 900_000)` — 90% LP сожжено, 10% заблокировано для платформы.
- `(50_000, 100_000, 850_000)` — 85% сожжено, 15% заблокировано для платформы.
- `(0, 0, 1_000_000)` — полное сжигание, без отчеканки NFT. Строгие запуски «без инсайдеров».

## Поля брендинга

`name`, `web` и `img` — это встроенные массивы байтов, дополненные нулями до размера констант. Чтобы прочитать их как строки, срежьте до первого `\0`:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

Константы намеренно щедрые (`name: 64`, `web: 256`, `img: 256`), чтобы платформы могли включить достаточно метаданных для обозревателей и агрегаторов без обращения к хранилищу вне цепи. Всё, что превышает эти размеры, откатывается при `CreatePlatformConfig` с `InvalidInput`.

## Механика комиссий

Своп на кривой, привязанной к `PlatformConfig`, взимает три уровня комиссий:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` начисляется на `protocol_fee_owner` протокола (взимается через `CollectFee`).
- `platform_fee` начисляется на хранилище платформы (взимается через `ClaimPlatformFee` или `ClaimPlatformFeeFromVault`; см. [`instructions`](/ru/products/launchlab/instructions)).
- `creator_fee` начисляется на хранилище создателя, ключ которого — публичный ключ создателя + quote mint (взимается через `ClaimCreatorFee`).

### Ограничения ставок

Обе ставки выражены в `1/1_000_000`, поэтому `5000` — это 50 bps, а `50000` — это 500 bps.

| Ставка | Ограничение | Применяется в |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` при создании — откатывается с `InvalidInput`. `update_platform_fee_rate` при каждом варианте обновления, который его касается (`FeeRate` и `AllInfo`) — откатывается с `InvalidPlatformInfo`. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` при создании и `update_creator_fee_rate` при обновлении — оба откатываются с `InvalidPlatformInfo`. |

Две точки применения для `fee_rate` — это отдельные вызовы `require!` в разных файлах, поэтому они несут разные коды ошибок, но применяют одинаковый потолок. Платформа, созданная с любой разрешённой ставкой, может быть отредактирована позже, включая через вариант `AllInfo`, который переписывает каждое поле сразу.

Оба ограничения `fee_rate` первоначально составляли 100 bps (`10000`). Ограничение обновления переместилось на `25000` (250 bps) 27 января 2026 г.; 26 августа 2026 г. оба переместились на `50000` (500 bps) — см. [запись в журнале изменений](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` **не** ограничивает ни одну из этих ставок. Он ограничивает аргумент `share_fee_rate` для каждой транзакции, который принимают четыре инструкции swap — реферальную комиссию — и ничего больше. См. [`global-config`](/ru/products/launchlab/global-config#fees).

## Распределение миграции NFT (только CPMM)

Когда запуск выпускается в CPMM, инструкция миграции разделяет токены LP, отчеканенные `CPMM::InitializeWithPermission`, двумя способами:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

Если `lp_to_platform` ненулевой, программа LP-Lock оборачивает его в один Fee Key NFT, принадлежащий `platform_nft_wallet`. Это заменяет поведение до обновления, которое создавало отдельные Fee Keys платформы и создателя. Fee Keys, созданные миграциями, завершёнными до обновления, остаются неизменными. Это право на LP-комиссию отделено от комиссий создателя CPMM, контролируемых `platform_cp_creator`.

Доля сжигания сжигается напрямую, поэтому ни один аккаунт не может её вывести или потребовать LP-комиссии, представленные этой долей.

Существующие запуски с сохранённым `migrate_type = 0` всё ещё могут использовать устаревший путь AMM v4. Новая инициализация отклоняет этот тип миграции.

## Список разрешённых параметров кривой

`curve_params: Vec<PlatformCurveParam>` — это механизм платформы для ограничения форм кривых, которые могут выбирать её запуски. Если вектор непуст и хотя бы одна запись действительна, программа применяет при `Initialize`, что параметры запуска точно совпадают с хотя бы одной записью.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // порядковый номер в списке разрешённых этой платформы
    pub global_config:        Pubkey,       // какой GlobalConfig применяется к этой записи
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // новые запуски требуют 1 = CPMM; u8::MAX = подстановочный знак
    pub migrate_cpmm_fee_on:        u8,    // 0 = только quote, 1 = оба. u8::MAX = подстановочный знак
    pub supply:                     u64,   // 0 = подстановочный знак
    pub total_base_sell:            u64,   // 0 = подстановочный знак
    pub total_quote_fund_raising:   u64,   // 0 = подстановочный знак
    pub total_locked_amount:        u64,   // u64::MAX = подстановочный знак
    pub cliff_period:               u64,   // u64::MAX = подстановочный знак
    pub unlock_period:              u64,   // u64::MAX = подстановочный знак
}
```

Каждое поле имеет значение-дозорное, которое означает **подстановочный знак** (любое значение совпадает): `u64::MAX` для полей `u64`, `u8::MAX` для полей `u8`, `0` для полей supply / sell / fund-raising. `BondingCurveParam` со всеми дозорными значениями — это «разрешить всё» — эквивалент поведения пустого списка разрешённых.

Алгоритм сопоставления при `Initialize`:

1. Отфильтруйте `curve_params` до записей, чей `global_config` совпадает с выбранным запуском `GlobalConfig`.
2. Если отфильтрованный список пуст, разрешите любые параметры (платформа не внесла в список разрешённых ничего для этого `GlobalConfig`).
3. Если каждая запись в отфильтрованном списке имеет `all_is_invalid()` (каждое поле — подстановочный знак), разрешите любые параметры.
4. В противном случае переберите записи; для каждой записи проверьте параметры запуска против каждого поля, не являющегося подстановочным знаком. Если все поля, не являющиеся подстановочными знаками, совпадают, примите и вернитесь.
5. Если ни одна запись не совпала, откатитесь с `InvalidInput`.

Это позволяет платформе сказать «мы разрешаем только стандартную форму 1B-supply / 800M-sold / 30k-USDC-raise / no-vesting», написав одну запись с конкретными значениями для этих четырёх полей и подстановочными знаками везде. Или более строгая платформа может перечислить три или четыре дискретные формы, по одной на поддерживаемый уровень запуска.

`MAX_CURVE_PARAMS = 10` ограничивает размер списка разрешённых.

## `PlatformAllowConfig` — ограничение платформы

Каждая платформа решает, ограничивать ли, какие аккаунты `GlobalConfig` могут использовать её запуски. Установите `restrict_global_config` с `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)`.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

Seeds PDA: `[b"platform_allow_config", platform_config, global_config]`.

Администратор платформы создаёт или закрывает один аккаунт на разрешённую пару через `CreatePlatformAllowConfig` и `ClosePlatformAllowConfig`. Когда ограничение равно `1`, инициализация ищет в `remaining_accounts` ожидаемый PDA и отклоняет отсутствующий аккаунт с `NotEnoughRemainingAccounts`. Когда ограничение равно `0`, аккаунт разрешения не требуется.

Управляемый администратором протокола аккаунт `PlatformGlobalAccess` и его инструкции создания/закрытия снимаются с производства. Размеры существующих `PlatformConfig` и `GlobalConfig` не меняются, но декодеры должны заменить старый глобальный флаг на новый флаг платформы. Старые PDA доступа не потребляются новой проверкой.

## Путь чтения

```ts
const platformConfig = await raydium.launchpad.getPlatformConfig(platformConfigPda);

console.log("Platform:", readString(platformConfig.name));
console.log("Fee rate:", platformConfig.feeRate, "(/1M)");
console.log("NFT split:",
  platformConfig.platformScale,
  platformConfig.creatorScale,
  platformConfig.burnScale,
);
console.log("Curve whitelist size:", platformConfig.curveParams.length);
```

Для интерфейса, показывающего «откуда был запущен этот токен», `PoolState.platform_config` указывает на исходящий `PlatformConfig` напрямую — получите его один раз и кэшируйте брендинг.

## Путь обновления

| Инструкция | Кто подписывает | Что меняется |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | администратор платформы (один раз) | Инициализирует аккаунт с `PlatformParams`. |
| `UpdatePlatformConfig` | администратор платформы | Универсальная диспетчеризация, ключ которой — `param: u8`; мутирует одно поле за вызов или каждое поле сразу через `AllInfo`. Поля брендинга, ставки комиссий, кошелёк вестинга и различные кошельки — всё устанавливается через это. Обе ставки переподтверждаются против ограничений в [Ограничения ставок](#rate-caps) при каждом варианте, который их касается. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | администратор платформы | Добавьте или удалите один разрешённый `GlobalConfig` для этой платформы. |
| `UpdatePlatformCurveParam` | администратор платформы | Добавьте или замените одну запись `PlatformCurveParam` по `(global_config, index)`. |
| `RemovePlatformCurveParam` | администратор платформы | Очистите одну запись (установите её на все-дозорные = подстановочный знак). |
| `ClaimPlatformFee` | `platform_fee_wallet` | Соберите комиссию платформы за пул из `PoolState.quote_vault`. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | Соберите хранилище комиссии платформы (PDA в `[platform_config, quote_mint]`). |

Ротации кошельков (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) — всё проходит через `UpdatePlatformConfig`. Прочитайте таблицу диспетчеризации `update_platform_config` в исходном коде для точных кодов `param`.

## Распространённые ошибки

- **Дозорные значения списка разрешённых неправильно установлены.** `BondingCurveParam` с `total_locked_amount = 0` *не* является подстановочным знаком — он совпадает с запусками, которые явно отказываются от вестинга. Подстановочный знак для этого поля — `u64::MAX`. Та же ловушка существует для `cliff_period` и `unlock_period`. Используйте `clear()` (который программа предоставляет) для правильной установки дозорных значений.
- **Округление NFT-разделения.** Три масштаба должны в сумме равняться ровно `1_000_000`. Ошибки на единицу при `CreatePlatformConfig` откатываются; ошибки на единицу во время выполнения отчеканили бы или сожгли бы один дополнительный LP-юнит, что и предотвращает проверка строгого равенства.
- **Двойное распределение вестинга платформы.** Если `platform_vesting_scale > 0`, платформа должна вызвать `CreatePlatformVestingAccount` один раз после окончания сбора средств запуска; если она забудет, эта доля остаётся невыделенной и неактивной навсегда (бюджет `total_locked_amount` запуска потребляется, но платформа никогда не требует).
- **Неоднозначность `platform_cp_creator`.** Когда установлено на `Pubkey::default()`, создатель запуска записывается как `pool_creator` пула CPMM после выпуска; когда установлено на реальный ключ, вместо этого записывается этот ключ. Это определяет получателя комиссий создателя CPMM после выпуска и кто может подписать исходный путь `CPMM::CollectCreatorFee`. Путь сбора без разрешения всё ещё платит канонические ATA этого записанного ключа. Решите при создании конфигурации платформы, какую модель вы хотите.
- **Ограничение без аккаунта разрешения.** Включение `restrict_global_config` перед созданием требуемого `PlatformAllowConfig` блокирует новые запуски, которые выбирают этот конфиг.
