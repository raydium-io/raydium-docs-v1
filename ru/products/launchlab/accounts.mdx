На этой странице описан граф аккаунтов **на запуск**: `PoolState` (корневой аккаунт состояния одного запуска), его два хранилища, PDA полномочий и ссылки после выпуска, которые он получает при завершении запуска.

Для конфигурации на уровне протокола, которая ограничивает каждый запуск, см. [`products/launchlab/global-config`](/ru/products/launchlab/global-config). Для наложения на уровне платформы см. [`products/launchlab/platform-config`](/ru/products/launchlab/platform-config). Для аккаунтов вестинга (`VestingSchedule` на `PoolState`, `VestingRecord` на бенефициара), см. [`products/launchlab/vesting`](/ru/products/launchlab/vesting).

## Инвентарь аккаунтов

| Аккаунт | Владелец | Назначение |
|---------|----------|-----------|
| [`GlobalConfig`](/ru/products/launchlab/global-config) | Программа LaunchLab | Правила на уровне протокола: комиссии, минимальные объемы, кошельки миграции. Один на `(curve_type, index)`. |
| [`PlatformConfig`](/ru/products/launchlab/platform-config) | Программа LaunchLab | Наложение на уровне платформы: брендинг, комиссия платформы, разделение NFT при выпуске, переключатель параметров запуска и менеджер правил. Фиксированный размер 944 байта. |
| `PoolState` | Программа LaunchLab | Корневое состояние на запуск: минты, хранилища, параметры кривой, счетчики продаж, счетчики комиссий, график вестинга, статус выпуска. |
| `authority` | Программа LaunchLab | Единственный PDA с seed `[b"vault_auth_seed"]`, который владеет хранилищами всех запусков и подписывает CPI после выпуска. |
| `base_vault` | SPL Token / Token-2022 | Хранилище на запуск, содержащее непроданные базовые токены. |
| `quote_vault` | SPL Token / Token-2022 | Хранилище на запуск, содержащее накопленные котировочные токены. Следует программе, которая владеет котировочным минтом. |
| [`VestingRecord`](/ru/products/launchlab/vesting) | Программа LaunchLab | Запись cliff + линейного разблокирования на бенефициара. Опционально. |
| `creator_fee_vault` | SPL Token / Token-2022 | Хранилище на создателя + на котировочный минт, содержащее накопленные комиссии создателя, очищаемое `ClaimCreatorFee`. Следует программе котировочного минта. |
| `platform_fee_vault` | SPL Token / Token-2022 | Хранилище на платформу + на котировочный минт, содержащее накопленные комиссии платформы, очищаемое `ClaimPlatformFeeFromVault`. Следует программе котировочного минта. |
| [`PlatformAllowConfig`](/ru/products/launchlab/platform-config) | Программа LaunchLab | Опциональное разрешение, управляемое платформой, для одной пары `(PlatformConfig, GlobalConfig)`. Проверяется только когда платформа включает ограничение. |
| [`PlatformCurveRule`](/ru/products/launchlab/curve-rules) | Программа LaunchLab | Опциональное правило параметров запуска, управляемое платформой, для одной пары `(PlatformConfig, GlobalConfig)`. Переменный размер, 150 байт пусто. |
| (после выпуска) `cpmm_pool_state` | Программа CPMM | Пул, созданный `MigrateToCpswap` для каждого нового запуска. Устаревшее состояние может по-прежнему ссылаться на выпуск AMM v4. |
| (после выпуска) Fee Key NFT | Программа LP-Lock | До обновления 2026-08-17 шкалы платформы и создателя могли создавать отдельные Fee Keys. Миграции, выполненные после этого, объединяют обе шкалы в один Fee Key платформы. |

Метод SDK `raydium.launchpad.getLaunchById` возвращает `PoolState` плюс флаг, указывающий, был ли запуск выпущен; если да, включается ID пула после миграции.

## `PoolState`

Корневое состояние на запуск. Названия полей ниже соответствуют структуре Rust на цепи (`states/pool.rs`); некоторые значения упрощены для читаемости — обратитесь к исходному коду для точного расположения в памяти.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Значения `PoolStatus` (из Anchor IDL):

```
0 = Funding         — принимает покупки / продажи; ниже quote_reserve_target
1 = Migrate         — достигнут quote_reserve_target; ожидание MigrateTo*
2 = Migrated        — MigrateTo* уже выполнен; часы вестинга работают
```

Поля, видимые интеграторам:

- **`status`** — три значения, монотонные (Funding → Migrate → Migrated). Чтение всегда безопасно; запись ограничена.
- **`real_base`**, **`real_quote`** — текущее состояние кривой. В сочетании с `virtual_base` / `virtual_quote` они достаточны для вычисления спотовой цены без обращения к хранилищам. См. [`bonding-curve`](/ru/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — соотношение «прогресс к выпуску» для UI.
- **`migrate_type`** — новая инициализация требует `1` (`CPSWAP`). Сохраненный `0` остается значимым только для существующего запуска, созданного до принудительного использования CPMM.
- **`amm_creator_fee_on`** — выбирает `creator_fee_on = OnlyQuoteToken` (`0`) или `BothToken` (`1`) на пуле CPMM после выпуска. Это не выбирает цель миграции. См. [`creator-fees`](/ru/products/launchlab/creator-fees).
- **`token_program_flag`** — битовое поле, не логическое значение. Bit0 — это базовый минт, а bit1 — котировочный минт, каждый `0` для SPL Token и `1` для Token-2022, поэтому байт принимает четыре значения: `0` (оба устаревшие), `1` (Token-2022 базовый), `2` (Token-2022 котировочный), `3` (оба Token-2022). Прочитайте один минт с помощью `(token_program_flag >> bit) & 1`. Сравнение всего байта с `0` для классификации базового минта разрешает `2` в неправильную программу. Bit1 был постоянно `0` до поддержки котировочных минтов Token-2022.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — три независимых счетчика комиссий. Каждый имеет свою инструкцию требования; см. [`instructions`](/ru/products/launchlab/instructions).
- **`vesting_schedule`** — присутствует на каждом `PoolState`, но неактивен, когда `total_locked_amount == 0`. См. [`vesting`](/ru/products/launchlab/vesting) для полного жизненного цикла.

## PDA полномочий

LaunchLab использует **единственный** PDA полномочий для всех запусков, полученный без seed на запуск:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // см. reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Этот единственный PDA:

- Полномочия на каждом хранилище `base_vault` и `quote_vault` запуска.
- `mint_authority` на каждом `base_mint` запуска (до выпуска).
- Подписант на CPI выпуска CPMM и на устаревший выпуск AMM v4 для существующего состояния.
- Подписант на передачи `ClaimVestedToken` из базового хранилища.
- `transfer_fee_config_authority` на `TransferFeeConfig` базового минта Token-2022, для всей фазы до выпуска — и его `withdraw_withheld_authority` тоже, но только когда платформа не установила `PlatformConfig.transfer_fee_extension_auth`.

`mint_authority` отзывается сразу после вызова `MigrateToCpswap` или устаревшего `MigrateToAmm`, поэтому предложение навсегда фиксируется.

Два дополнительных PDA ограничивают хранилища комиссий:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Они подписывают передачу из соответствующего хранилища комиссий во время `ClaimCreatorFee` и `ClaimPlatformFeeFromVault`.

## Базовый минт

Создается встроенно `Initialize` с:

- `mint_authority = authority` (отзывается при выпуске).
- `freeze_authority = None`.
- `supply = supply`, полностью отчеканено в `base_vault`.
- `decimals`, выбранные создателем при `Initialize` (обычно 6).

Поскольку полное предложение предварительно отчеканено, `base_mint.supply` постоянно на протяжении жизни запуска. Покупки по кривой перемещают токены из `base_vault` покупателю, но не вызывают `mint_to`.

`Initialize` / `InitializeV2` создают базовые минты SPL Token. Выделенная инструкция `InitializeWithToken2022` позволяет базовому минту быть минтом Token-2022 (с опциональным `TransferFeeConfig`). Все три пути инициализации требуют выпуска CPMM.

Когда `InitializeWithToken2022` присоединяет `TransferFeeConfig`, минт создается с `transfer_fee_config_authority = authority` и `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`, возвращаясь к `authority`, когда платформа не установила это поле. Обе полномочия переназначаются ключу платформы при выпуске, сторона вывода только если PDA все еще ее держит. См. [`platform-config`](/ru/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

Котировочный минт независим от базового минта и сам может быть минтом Token-2022 — `InitializeV2` и `InitializeWithToken2022` принимают любую программу в своем слоте котировочной программы. Устаревший `Initialize` не принимает: его аккаунт котировочной программы по-прежнему типизирован как SPL Token, поэтому конфиг, чей котировочный минт является Token-2022, может быть запущен только через два других. Котировочный минт никогда не создается LaunchLab; это то, что называет `GlobalConfig.quote_mint`. См. [`global-config`](/ru/products/launchlab/global-config#token-2022-quote-mints) и [`reference/token-2022-support`](/ru/reference/token-2022-support#launchlab-quote-mints).

## Хранилища

Оба `base_vault` и `quote_vault` — это аккаунты токенов, принадлежащие PDA LaunchLab `authority`, каждый созданный на программе, которая владеет своим собственным минтом — поэтому запуск может иметь устаревшее базовое хранилище и хранилище котировочного Token-2022, или любую другую комбинацию. `token_program_flag` записывает, какое это. Адреса хранятся на `PoolState` и также могут быть получены:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Проверьте точные префиксы seed из структуры аккаунтов `Initialize` исходного кода перед использованием вывода в production.)

## Хранилища комиссий

Два PDA агрегируют комиссии по запускам:

- **Хранилище комиссии создателя** — PDA с seeds `[creator, quote_mint]`. Каждый запуск, который зарабатывает одинаковые комиссии создателя на одном котировочном минте, выливается в одно хранилище. Создатель очищает его через `ClaimCreatorFee`.
- **Хранилище комиссии платформы** — PDA с seeds `[platform_config, quote_mint]`. Каждый запуск, направленный через одну платформу, которая использует один котировочный минт, выливается в одно хранилище. `platform_fee_wallet` платформы очищает его через `ClaimPlatformFeeFromVault`. Существует также вариант очистки на запуск (`ClaimPlatformFee`), который вытягивает из `quote_vault` запуска напрямую без прохождения через агрегированное хранилище.

Оба создаются лениво при первом своппе, который начисляет комиссию, на программе, которая владеет котировочным минтом. Создатель или платформа, которые запускают запуски как на устаревшем, так и на котировочном минте Token-2022, заканчиваются одним хранилищем на минт, как это уже было для двух разных устаревших минтов.

Паттерн агрегированного хранилища позволяет высокообъемному создателю или платформе амортизировать стоимость аренды накопления комиссий по многим запускам.

## Quote vault ↔ `real_quote`

`quote_vault.balance` и `PoolState.real_quote` должны оставаться синхронизированными. Они могут отличаться максимум на сумму трех счетчиков ожидающих комиссий (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), которые находятся в хранилище, но принадлежат счетчикам комиссий, а не резерву кривой. Математика кривой всегда использует `real_quote`, никогда не использует сырой баланс хранилища.

Инвариант до выпуска:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## `PlatformCurveRule`

Один аккаунт на пару `(PlatformConfig, GlobalConfig)`, содержащий формы запусков, которые эта платформа разрешает на этом конфиге. PDA seeds — это `[b"platform_curve_rule", platform_config, global_config]`.

```rust
#[account]
pub struct PlatformCurveRule {
    pub bump:            u8,
    pub version:         u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub epoch:           u64,
    pub padding:         [u64; 8],
    pub groups:          Vec<CurveRuleGroup>,   // до 10
}

pub struct CurveRuleGroup {
    pub group_id:    u16,                       // стабильный id, используется для обновления или удаления группы
    pub epoch:       u64,
    pub constraints: Vec<ParamConstraint>,      // до 25, ANDed
}

pub struct ParamConstraint {
    pub field: u8,                              // какой параметр запуска
    pub op:    u8,                              // 0 Eq, 1 Gte, 2 Lte, 3 Neq
    pub value: u128,
}
```

Аккаунт создается без группы и изменяется в размере при каждом изменении группы, поэтому его длина составляет `150 + Σ(14 + 18 × constraints)` и декодеры не должны предполагать фиксированный размер. Группы ORed: запуск разрешен, как только все ограничения одной группы выполняются. Нулевые группы означают отсутствие ограничений.

Читайте его только когда владеющий `PlatformConfig.restrict_curve_param` равен `1` — при `0` программа игнорирует аккаунт, и там может находиться устаревшее правило. ID полей, операторы и сборники находятся в [`products/launchlab/curve-rules`](/ru/products/launchlab/curve-rules).

## Переходы аккаунтов жизненного цикла

| Событие | Статус | `real_base` | `real_quote` | Пул после выпуска |
|---------|--------|-------------|--------------|-------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (или устаревший `MigrateToAmm`) | Funding → Migrate → Migrated | (заморожено) | (заморожено) | создано; LP CPMM разделен на заблокированный LP, принадлежащий платформе, и сожженный LP |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | любой | — | — | очищает хранилище комиссий |
| `CreateVestingAccount` | Funding | — | — | увеличивает `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated только | — | — | очищает `base_vault` |
