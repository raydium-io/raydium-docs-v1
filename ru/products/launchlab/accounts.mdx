Для аккаунтов вестинга (`VestingSchedule` на `PoolState`, `VestingRecord` для каждого бенефициара) см. [`products/launchlab/vesting`](/ru/products/launchlab/vesting).

## Инвентарь аккаунтов

| Аккаунт | Владелец | Назначение |
|---------|----------|-----------|
| [`GlobalConfig`](/ru/products/launchlab/global-config) | Программа LaunchLab | Правила на уровне протокола: комиссии, минимальные объемы предложения, кошельки миграции. Один на `(curve_type, index)`. |
| [`PlatformConfig`](/ru/products/launchlab/platform-config) | Программа LaunchLab | Наложение на уровне платформы: брендинг, комиссия платформы, разделение NFT при выпуске, белый список форм кривой. |
| `PoolState` | Программа LaunchLab | Корневое состояние для каждого запуска: монеты, хранилища, параметры кривой, счетчики продаж, счетчики комиссий, график вестинга, статус выпуска. |
| `authority` | Программа LaunchLab | Единственный PDA с seed `[b"vault_auth_seed"]`, который владеет хранилищами всех запусков и подписывает CPI после выпуска. |
| `base_vault` | SPL Token / Token-2022 | Хранилище для каждого запуска, содержащее непроданные базовые токены. |
| `quote_vault` | SPL Token | Хранилище для каждого запуска, содержащее накопленные котировочные токены. |
| [`VestingRecord`](/ru/products/launchlab/vesting) | Программа LaunchLab | Запись cliff + линейного разблокирования для каждого бенефициара. Опционально. |
| `creator_fee_vault` | SPL Token | Хранилище для каждого создателя + для каждой котировочной монеты, содержащее накопленные комиссии создателя, очищаемое `ClaimCreatorFee`. |
| `platform_fee_vault` | SPL Token | Хранилище для каждой платформы + для каждой котировочной монеты, содержащее накопленные комиссии платформы, очищаемое `ClaimPlatformFeeFromVault`. |
| [`PlatformAllowConfig`](/ru/products/launchlab/platform-config) | Программа LaunchLab | Опциональное разрешение, управляемое платформой, для одной пары `(PlatformConfig, GlobalConfig)`. Проверяется только если платформа включает ограничение. |
| (после выпуска) `cpmm_pool_state` | Программа CPMM | Пул, созданный `MigrateToCpswap` для каждого нового запуска. Устаревшее состояние может по-прежнему ссылаться на выпуск AMM v4. |
| (после выпуска) Fee Key NFT | Программа LP-Lock | До обновления 2026-08-14 шкалы платформы и создателя могли создавать отдельные Fee Keys. Миграции, выполненные после этого, объединяют обе шкалы в один Fee Key платформы. |

Метод SDK `raydium.launchpad.getLaunchById` возвращает `PoolState` плюс флаг, указывающий, был ли запуск выпущен; если да, включается ID пула после миграции.

## `PoolState`

Корневое состояние для каждого запуска. Названия полей ниже соответствуют структуре Rust на цепи (`states/pool.rs`); некоторые значения упрощены для читаемости — обратитесь к исходному коду для точного расположения в памяти.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit flags for SPL Token vs Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Значения `PoolStatus` (из Anchor IDL):

```
0 = Funding         — accepting buys / sells; below quote_reserve_target
1 = Migrate         — quote_reserve_target reached; awaiting MigrateTo*
2 = Migrated        — MigrateTo* already executed; vesting clock running
```

Поля, важные для интеграторов:

- **`status`** — три значения, монотонные (Funding → Migrate → Migrated). Чтение всегда безопасно; запись ограничена.
- **`real_base`**, **`real_quote`** — текущее состояние кривой. В сочетании с `virtual_base` / `virtual_quote` их достаточно для вычисления спотовой цены без обращения к хранилищам. См. [`bonding-curve`](/ru/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — соотношение «прогресс к выпуску» для пользовательских интерфейсов.
- **`migrate_type`** — новая инициализация требует `1` (`CPSWAP`). Сохраненный `0` остается значимым только для существующего запуска, созданного до принудительного использования CPMM.
- **`amm_creator_fee_on`** — выбирает `creator_fee_on = OnlyQuoteToken` (`0`) или `BothToken` (`1`) на пуле CPMM после выпуска. Это не выбирает целевую миграцию. См. [`creator-fees`](/ru/products/launchlab/creator-fees).
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — три независимых счетчика комиссий. Каждый имеет свою инструкцию требования; см. [`instructions`](/ru/products/launchlab/instructions).
- **`vesting_schedule`** — присутствует на каждом `PoolState`, но неактивен, когда `total_locked_amount == 0`. См. [`vesting`](/ru/products/launchlab/vesting) для полного жизненного цикла.

## PDA полномочий

LaunchLab использует **единственный** PDA полномочий для всех запусков, полученный без seed для каждого запуска:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Этот единственный PDA:

- Является полномочием на `base_vault` и `quote_vault` каждого запуска.
- Является `mint_authority` на `base_mint` каждого запуска (до выпуска).
- Подписывает CPI выпуска CPMM и выпуск AMM v4 для существующего состояния.
- Подписывает передачи `ClaimVestedToken` из базового хранилища.

`mint_authority` отзывается сразу после вызова `MigrateToCpswap` или устаревшего `MigrateToAmm`, поэтому предложение навсегда фиксируется.

Два дополнительных PDA ограничивают хранилища комиссий:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Они подписывают передачу из соответствующих хранилищ комиссий во время `ClaimCreatorFee` и `ClaimPlatformFeeFromVault`.

## Базовая монета

Создается встроенно `Initialize` с:

- `mint_authority = authority` (отзывается при выпуске).
- `freeze_authority = None`.
- `supply = supply`, полностью отчеканено в `base_vault`.
- `decimals`, выбранные создателем при `Initialize` (обычно 6).

Поскольку полное предложение предварительно отчеканено, `base_mint.supply` постоянно на протяжении жизни запуска. Покупки по кривой перемещают токены из `base_vault` покупателю, но не вызывают `mint_to`.

`Initialize` / `InitializeV2` создают запуски SPL Token. Специальная инструкция `InitializeWithToken2022` позволяет базовой монете быть монетой Token-2022 (с опциональным `TransferFeeConfig`); котировочная монета остается SPL Token. Все три пути инициализации требуют выпуска CPMM.

## Хранилища

Оба `base_vault` и `quote_vault` — это стандартные аккаунты SPL Token, принадлежащие PDA LaunchLab `authority`. Адреса хранятся на `PoolState` и также могут быть получены:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Перед использованием вывода в production проверьте точные префиксы seed в структуре аккаунтов `Initialize` исходного кода.)

## Хранилища комиссий

Два PDA агрегируют комиссии по всем запускам:

- **Хранилище комиссии создателя** — PDA с seeds `[creator, quote_mint]`. Каждый запуск, который зарабатывает одинаковые комиссии создателя на одной и той же котировочной монете, выливается в одно хранилище. Создатель очищает его через `ClaimCreatorFee`.
- **Хранилище комиссии платформы** — PDA с seeds `[platform_config, quote_mint]`. Каждый запуск, маршрутизированный через одну и ту же платформу, которая использует одну и ту же котировочную монету, выливается в одно хранилище. Кошелек `platform_fee_wallet` платформы очищает его через `ClaimPlatformFeeFromVault`. Существует также вариант очистки для каждого запуска (`ClaimPlatformFee`), который извлекает из `quote_vault` запуска напрямую без прохождения через агрегированное хранилище.

Паттерн агрегированного хранилища позволяет высокообъемному создателю или платформе амортизировать стоимость аренды накопления комиссий по многим запускам.

## Quote vault ↔ `real_quote`

`quote_vault.balance` и `PoolState.real_quote` должны оставаться синхронизированными. Они могут отличаться максимум на сумму трех ожидающих счетчиков комиссий (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), которые находятся в хранилище, но принадлежат счетчикам комиссий, а не резерву кривой. Математика кривой всегда использует `real_quote`, никогда не использует сырой баланс хранилища.

Инвариант до выпуска:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## Переходы аккаунтов жизненного цикла

| Событие | Статус | `real_base` | `real_quote` | Пул после выпуска |
|---------|--------|-------------|--------------|-------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (или устаревший `MigrateToAmm`) | Funding → Migrate → Migrated | (frozen) | (frozen) | создан; LP CPMM разделен на заблокированный LP, принадлежащий платформе, и сожженный LP |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | любой | — | — | очищает хранилище комиссий |
| `CreateVestingAccount` | Funding | — | — | увеличивает `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated только | — | — | очищает `base_vault` |
