## Установка

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

Каждый пример на этой странице соответствует файлу в [`raydium-sdk-V2-demo/src/clmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/clmm); ссылка на GitHub находится рядом с каждым разделом. Инициализация следует файлу `config.ts.template` репозитория демонстрации ([источник](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template)) — `disableFeatureCheck: true` — рекомендуемая настройка для любой нетривиальной интеграции:

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);
const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
export const txVersion = TxVersion.V0;
```

## Создание пула CLMM

Источник: [`src/clmm/createPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/createPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";
import Decimal from "decimal.js";

const mintA = await raydium.token.getTokenInfo(
  new PublicKey("So11111111111111111111111111111111111111112"));   // wSOL
const mintB = await raydium.token.getTokenInfo(
  new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"));   // USDC

// getClmmConfigs() возвращает ApiClmmConfigInfo (id — строка). createPool требует
// ClmmConfigInfo, которому нужен PublicKey id плюс fundOwner/description — преобразуем:
const clmmConfigs = await raydium.api.getClmmConfigs();
const picked = clmmConfigs.find((c) => c.index === 1)!;        // уровень 0.05%
const ammConfig = { ...picked, id: new PublicKey(picked.id), fundOwner: "", description: "" };

const initialPrice = new Decimal(160);        // 160 USDC за SOL
const { execute, extInfo } = await raydium.clmm.createPool({
  programId: CLMM_PROGRAM_ID,
  mint1:     mintA,
  mint2:     mintB,
  ammConfig,
  initialPrice,
  txVersion: TxVersion.V0,   // нет `startTime` — CreateConcentratedPool не имеет такого поля
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool:", extInfo.address.id, "tx:", txId);   // уже строка base58
```

SDK:

- Сортирует `mint1`/`mint2` по порядку байтов перед выведением.
- Вычисляет `sqrt_price_x64 = floor(sqrt(initialPrice × 10^(dB−dA)) × 2^64)`.
- Создаёт аккаунты `observation` и `tick_array_bitmap_extension`.
- Платит комиссию за создание пула, определённую `ammConfig`.

## Открытие позиции в выбранном диапазоне

Источник: [`src/clmm/createPosition.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/createPosition.ts)

```ts
import { PoolUtils, TickUtil } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // строка base58
// примечание: getPoolInfoFromRpc CLMM возвращает `rpcPoolInfo`, а не `rpcData` (как CPMM)
const { poolInfo, poolKeys, rpcPoolInfo } = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);

// Выберите диапазон цен. Здесь: ±10% от текущей.
const currentPrice = new Decimal(poolInfo.price);
const lowerPrice   = currentPrice.mul(0.9);
const upperPrice   = currentPrice.mul(1.1);

// Привяжите к допустимым тикам для tick_spacing этого пула.
// Класс — TickUtil (единственное число), и он принимает decimals + tickSpacing, а не poolInfo.
const { tick: tickLower } = TickUtil.getPriceAndTick({
  price: lowerPrice,
  mintADecimals: poolInfo.mintA.decimals,
  mintBDecimals: poolInfo.mintB.decimals,
  zeroForOne: true,
  tickSpacing: poolInfo.config.tickSpacing,
});
const { tick: tickUpper } = TickUtil.getPriceAndTick({
  price: upperPrice,
  mintADecimals: poolInfo.mintA.decimals,
  mintBDecimals: poolInfo.mintB.decimals,
  zeroForOne: true,
  tickSpacing: poolInfo.config.tickSpacing,
});

// Сколько каждого токена внести.
const inputAmount = new BN(10_000_000);  // 0.01 SOL

// getLiquidityAmountOutFromAmountIn асинхронна — ждите её.
const res = await PoolUtils.getLiquidityAmountOutFromAmountIn({
  poolInfo,
  slippage: 0.01,
  inputA: true,
  tickUpper,
  tickLower,
  amount: inputAmount,
  add: true,
  amountHasFee: true,
  epochInfo: await raydium.fetchEpochInfo(),
});

const { execute } = await raydium.clmm.openPositionFromBase({
  poolInfo,
  poolKeys,
  tickUpper,
  tickLower,
  base: "MintA",
  ownerInfo: { useSOLBalance: true },
  baseAmount: inputAmount,
  otherAmountMax: res.amountSlippageB.amount,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Position opened, tx:", txId);
```

SDK вычисляет, какие массивы тиков касается диапазон, и передаёт их как аккаунты. Ему не нужно включать инструкцию инициализации — нет инструкции init-tick-array; `OpenPosition*` сам выделяет недостающий массив тиков за счёт платящей стороны.

## Уменьшение ликвидности (и сбор комиссий одновременно)

Источник: [`src/clmm/decreaseLiquidity.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/decreaseLiquidity.ts) и [`src/clmm/closePosition.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/closePosition.ts)

```ts
const { execute } = await raydium.clmm.decreaseLiquidity({
  poolInfo,
  poolKeys,
  ownerPosition: positionAccount,
  ownerInfo: {                       // обязательно; closePosition находится здесь
    useSOLBalance: true,
    closePosition: false,
  },
  liquidity: positionAccount.liquidity.divn(2),   // уменьшить вдвое
  amountMinA: new BN(0),
  amountMinB: new BN(0),
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Чтобы **собрать только комиссии и вознаграждения**, вызовите `decreaseLiquidity` с `liquidity = new BN(0)`. Побочный эффект инструкции — урегулирование `token_fees_owed_{0,1}` и `reward_amount_owed` и их передача — это единственный способ собрать любое из них.

Чтобы полностью закрыть позицию после обнуления ликвидности и комиссий, передайте `ownerInfo: { closePosition: true }` в финальный вызов `decreaseLiquidity`. SDK добавляет `ClosePosition` и сжигает NFT.

<Warning>
  **Позиции с ограниченным эмитентом требуют совместимого построителя закрытия.** Эти позиции имеют замороженный аккаунт токена NFT. `ClosePosition` должен добавить ID пула позиции как первый оставшийся аккаунт, чтобы CLMM мог разморозить аккаунт перед сжиганием. Ветка исходного кода не включает изменение SDK. Убедитесь, что ваш выпуск SDK явно поддерживает путь замороженного закрытия перед включением создания позиций с ограниченным эмитентом.
</Warning>

Для прямого клиента Anchor оставьте объявленные аккаунты без изменений и добавьте пул:

```ts
// Программа CLMM: см. reference/program-addresses; источник ecb1577;
// Solana mainnet-beta; последняя проверка 13.08.2026.
await program.methods
  .closePosition()
  .accounts({
    nftOwner,
    positionNftMint,
    positionNftAccount,
    personalPosition,
    systemProgram: SystemProgram.programId,
    tokenProgram: positionNftTokenProgram,
  })
  .remainingAccounts([
    { pubkey: poolId, isWritable: false, isSigner: false },
  ])
  .rpc();
```

Вы можете передать `poolId` при каждом закрытии. CLMM читает его только когда `positionNftAccount` заморожен, что сохраняет один путь клиента совместимым со старыми и новыми позициями.

## Сбор вознаграждения(й)

Источник: [`src/clmm/harvestAllRewards.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/harvestAllRewards.ts)

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const { execute } = await raydium.clmm.harvestAllRewards({
  ownerInfo: { useSOLBalance: true },
  allPoolInfo: { [poolInfo.id]: poolInfo },
  allPositions: { [poolInfo.id]: [positionAccount] },
  programId: CLMM_PROGRAM_ID,
  txVersion: TxVersion.V0,
});

// harvestAllRewards — построитель НЕСКОЛЬКИХ транзакций: `sequentially` обязателен
// и результат — `txIds`, а не `txId`.

```

`harvestAllRewards` проходит по каждой позиции на каждом переданном пуле, группирует вызовы `DecreaseLiquidity` с нулевой ликвидностью, которые урегулируют комиссии и вознаграждения (плюс любые `UpdateRewardInfos`), и распределяет их по транзакциям при необходимости.

## Своп

Источник: [`src/clmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/clmm/swap.ts)

```ts
Это соответствует `src/clmm/swap.ts`, который моделирует с помощью `swapInternal` вместо
`PoolUtils.computeAmountOutFormat`.

```ts
import {
  swapInternal,
  getPdaExBitmapAccount,
  TickArrayBitmapExtensionLayout,
  CLMM_PROGRAM_ID,
} from "@raydium-io/raydium-sdk-v2";

const amountIn   = new BN(10_000_000);
const zeroForOne = true;             // своп A (SOL) → B (USDC)

const poolIdPub = new PublicKey(poolInfo.id);
const { rpcData, tickArrays, configInfo } =
  await raydium.clmm.getSwapPoolInfo(poolInfo.id, zeroForOne);

const exBitmap = getPdaExBitmapAccount(CLMM_PROGRAM_ID, poolIdPub).publicKey;
const exBitmapInfo = await raydium.connection.getAccountInfo(exBitmap);

const simulation = swapInternal({
  programId: CLMM_PROGRAM_ID,
  poolId: poolIdPub,
  poolInfo: rpcData,
  tickArrays,
  configInfo,
  tickarrayBitmapExtension: TickArrayBitmapExtensionLayout.decode(exBitmapInfo!.data),
  amountSpecified: amountIn,
  sqrtPriceLimitX64: new BN(0),
  zeroForOne,
  isBaseInput: true,               // false для точного выхода
  blockTimestamp: Math.floor(Date.now() / 1000),
  includeExtraTickArrays: true,
});

const { execute } = await raydium.clmm.swap({
  poolInfo,
  poolKeys,
  inputMint: poolInfo.mintA.address,
  amountIn,
  amountOutMin: simulation.amountCalculated,
  observationId: rpcData.observationId,
  ownerInfo: { useSOLBalance: true },   // обязательно
  remainingAccounts: simulation.accounts,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Моделирование проходит по карте тиков в автономном режиме с той же логикой, что и программа на цепи, и возвращает выходное количество (`amountCalculated`) плюс точный список аккаунтов, которые коснётся своп (`accounts`).

Всегда передавайте `remainingAccounts`, которые возвращает моделирование: слишком мало — своп откатится в середине прохода с `NotEnoughTickArrayAccount`; устаревшие просто тратят вычисления.

<Note>
  `PoolUtils.computeAmountOutFormat` всё ещё существует, но ему нужна `ComputeClmmPoolInfo` (
  `computePoolInfo` из `getPoolInfoFromRpc`, а не объект пула API) плюс два дополнительных обязательных
  аргумента — `tickarrayBitmapExtension` и `blockTimestamp` — и нет
  метода `raydium.clmm.fetchTickArrays` (`fetchTickArrays` — свободная функция; помощники уровня модуля —
  `PoolUtils.fetchMultiplePoolTickArrays` и `tickData` / `tickArrays`, возвращаемые
  `getPoolInfoFromRpc`).
</Note>

## Создание настраиваемого пула CLMM

`createCustomizablePool` — точка входа, которая раскрывает переключатели динамической комиссии и односторонней комиссии во время создания пула. Она принимает форму `createPool` плюс **два** дополнения:

```ts
import { CLMM_PROGRAM_ID, CollectFeeOn } from "@raydium-io/raydium-sdk-v2";

const dynamicFeeConfigs = await raydium.api.getClmmDynamicConfigs();    // GET /main/clmm-dynamic-config
const dynamicFeeConfig  = dynamicFeeConfigs.find((c) => c.index === 0); // выберите уровень калибровки

const { execute, extInfo } = await raydium.clmm.createCustomizablePool({
  programId: CLMM_PROGRAM_ID,
  mint1:     mintA,
  mint2:     mintB,
  ammConfig,
  initialPrice,
  // Два дополнения:
  collectFeeOn:      CollectFeeOn.TokenOnlyB,   // FromInput | TokenOnlyA | TokenOnlyB
  dynamicFeeConfig:  new PublicKey(dynamicFeeConfig!.id),
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
console.log("Customizable pool:", extInfo.address.id);   // строка base58
```

<Warning>
  Нет флага `enableDynamicFee` и нет параметра `dynamicFeeConfigId`, и нет `startTime`.
  **Передача `dynamicFeeConfig` — это то, что включает динамические комиссии** — опустите его и вы получите пул со статической комиссией, без ошибки. Также обратите внимание, что члены перечисления SDK — `TokenOnlyA` / `TokenOnlyB`, тогда как перечисление Rust на цепи пишет их как `Token0Only` / `Token1Only`; числовые значения совпадают
  (`FromInput` = 0).
</Warning>

`createPool` продолжает работать для пути с комиссией по умолчанию и без динамической комиссии. Используйте `createCustomizablePool` всякий раз, когда вам нужен любой из переключателей. См. [`products/clmm/instructions`](/ru/products/clmm/instructions) для списка аккаунтов на цепи.

## Лимитные ордера

Лимитный ордер припаркует пользовательский ввод на одном тике и будет заполнен FIFO, когда своп пересечёт этот тик. Выходы передаются в ATA владельца во время урегулирования; владельцу не нужно быть в сети, чтобы быть заполненным.

### Открытие лимитного ордера

```ts
Нет конфигурационного аккаунта лимитного ордера для каждого пула и нет помощника `getClmmLimitOrderConfigs()` — ордера ключены по тику.

```ts
import {
  getOrderTick,
  getPdaExBitmapAccount,
  CLMM_PROGRAM_ID,
} from "@raydium-io/raydium-sdk-v2";

const { poolInfo, rpcData } = await raydium.clmm.getSimplePoolInfo(POOL_ID);

// Лимитная цена ДОЛЖНА быть квантована к tick_spacing — getOrderTick это делает.
const targetPrice = new Decimal(180);                              // продать SOL за 180 USDC
const orderData = getOrderTick({
  baseIn: true,                                                    // продаём mintA
  mintADecimal: poolInfo.mintA.decimals,
  mintBDecimal: poolInfo.mintB.decimals,
  tickSpacing: poolInfo.config.tickSpacing,
  price: targetPrice,
});

// Ордер на продажу должен находиться выше текущего тика; ордер на покупку ниже.
if (orderData.tick < rpcData.tickCurrent) throw new Error("sell price must be > current price");

const { execute, extInfo } = await raydium.clmm.openLimitOrder({
  poolInfo,
  baseIn: true,
  orderTick: orderData.tick,
  amount: new BN(50_000_000),                // 0.05 SOL
  tickArrayBitmap: getPdaExBitmapAccount(
    CLMM_PROGRAM_ID,
    new PublicKey(poolInfo.id),
  ).publicKey,
  // noneIndex: 0,                           // опционально, по умолчанию 0
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Limit order opened:", extInfo.limitOrder.toBase58(), "tx:", txId);
```

SDK выводит PDA `LimitOrderState` из `(owner, nonce PDA, order nonce)`, увеличивает `LimitOrderNonce` для каждого кошелька и вставляет ордер в когорту FIFO на этом тике.

### Увеличение / уменьшение открытого ордера

```ts
const limitOrder = new PublicKey("<LIMIT_ORDER_PDA>");

await raydium.clmm.increaseLimitOrder({
  poolInfo,
  limitOrder,
  amount: new BN(20_000_000),
  txVersion: TxVersion.V0,
}).then((b) => b.execute({ sendAndConfirm: true }));

await raydium.clmm.decreaseLimitOrder({
  poolInfo,
  limitOrder,
  amount: new BN(10_000_000),
  slippage: 100,                 // опционально; DecreaseLimitOrder добавляет это над Increase
  txVersion: TxVersion.V0,
}).then((b) => b.execute({ sendAndConfirm: true }));
```

`decreaseLimitOrder` может удалять только из **незаполненной** части ордера; заполненная часть заблокирована до урегулирования. Обе инструкции откатываются с `InvalidOrderPhase`, если ордер уже полностью заполнен.

### Урегулирование заполненного ордера

```ts
// settleLimitOrder принимает ТОЛЬКО PDA ордера — нет poolInfo, нет poolKeys.
await raydium.clmm.settleLimitOrder({
  limitOrder,
  txVersion: TxVersion.V0,
}).then((b) => b.execute({ sendAndConfirm: true }));
```

`settleLimitOrder` читает `unfilled_ratio_x64` ордера против трекера когорты, вычисляет заполненный выход и передаёт его в ATA владельца. Владелец может вызвать это сам; `limit_order_admin` (автономный оперативный хранитель) также может вызвать это от имени владельца — выход всё равно идёт владельцу.

Для закрытия полностью урегулированных ордеров для восстановления ренты используйте `closeLimitOrder` (одиночный) или `closeAllLimitOrder` (пакетный). Для урегулирования многих одновременно `settleAllLimitOrder` упаковывает столько вызовов `SettleLimitOrder`, сколько поместится в v0 tx.

### Список припаркованных ордеров кошелька (в автономном режиме)

```ts
// Помощник API. См. api-reference/temp-api-v1.
const active = await fetch(
  `https://temp-api-v1.raydium.io/limit-order/order/list?wallet=<your-wallet-pubkey>`,
).then((r) => r.json());
```

Конечная точка активных ордеров возвращает как незаполненные, так и частично заполненные ордера в одном полезном грузе (`totalAmount` / `filledAmount` / `pendingSettle` различают фазы). Для истории закрытых ордеров используйте `/limit-order/history/order/list-by-user?wallet=…` (для каждого кошелька, разбито по страницам с помощью `nextPageId`); для полного журнала событий конкретного ордера используйте `/limit-order/history/event/list-by-pda?pda=…`.

## Скелет Rust CPI

```rust
// Cargo.toml — CLMM всё ещё на Anchor 0.32, поэтому не может делить крейт с
// образцом CPMM в products/cpmm/code-demos (который закрепляет =1.0.2).
// anchor-lang  = "=0.32.1"
// anchor-spl   = "=0.32.1"
// raydium-clmm = { git = "https://github.com/raydium-io/raydium-clmm",
//                  branch = "master", features = ["cpi"] }

use anchor_lang::prelude::*;
use raydium_clmm::cpi;
use raydium_clmm::program::RaydiumClmm;
use raydium_clmm::cpi::accounts::SwapSingleV2;   // `SwapV2` — имя инструкции,
                                                 // `SwapSingleV2` — структура аккаунтов

#[derive(Accounts)]
pub struct ProxyClmmSwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    /// CHECK:
    pub amm_config: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub input_token_account: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub output_token_account: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub input_vault: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub output_vault: UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub observation_state: UncheckedAccount<'info>,
    /// CHECK:
    pub token_program: UncheckedAccount<'info>,
    /// CHECK:
    pub token_program_2022: UncheckedAccount<'info>,
    /// CHECK:
    pub memo_program: UncheckedAccount<'info>,
    /// CHECK:
    pub input_vault_mint: UncheckedAccount<'info>,
    /// CHECK:
    pub output_vault_mint: UncheckedAccount<'info>,
    pub clmm_program: Program<'info, RaydiumClmm>,
    // `remaining_accounts` несёт аккаунты tick_array и bitmap_extension.
}

pub fn proxy_swap(
    ctx: Context<ProxyClmmSwap>,
    amount: u64,
    other_amount_threshold: u64,
    sqrt_price_limit_x64: u128,
    is_base_input: bool,
) -> Result<()> {
    let cpi_accounts = SwapSingleV2 {
        payer:                 ctx.accounts.payer.to_account_info(),
        amm_config:            ctx.accounts.amm_config.to_account_info(),
        pool_state:            ctx.accounts.pool_state.to_account_info(),
        input_token_account:   ctx.accounts.input_token_account.to_account_info(),
        output_token_account:  ctx.accounts.output_token_account.to_account_info(),
        input_vault:           ctx.accounts.input_vault.to_account_info(),
        output_vault:          ctx.accounts.output_vault.to_account_info(),
        observation_state:     ctx.accounts.observation_state.to_account_info(),
        token_program:         ctx.accounts.token_program.to_account_info(),
        token_program_2022:    ctx.accounts.token_program_2022.to_account_info(),
        memo_program:          ctx.accounts.memo_program.to_account_info(),
        input_vault_mint:      ctx.accounts.input_vault_mint.to_account_info(),
        output_vault_mint:     ctx.accounts.output_vault_mint.to_account_info(),
    };
    // Anchor 0.32 принимает AccountInfo программы здесь. НЕ меняйте это на
    // Pubkey — это форма Anchor 1.0, которую CLMM не использует.
    let cpi_ctx = CpiContext::new(ctx.accounts.clmm_program.to_account_info(), cpi_accounts)
        .with_remaining_accounts(ctx.remaining_accounts.to_vec());
    cpi::swap_v2(cpi_ctx, amount, other_amount_threshold, sqrt_price_limit_x64, is_base_input)
}
```

Порядок оставшихся аккаунтов для `SwapV2`:

```
[tick_array_bitmap_extension?, tick_array_0, tick_array_1, …]
```

Если своп никогда не нуждается в расширении, опустите его; в противном случае это первый оставшийся аккаунт.

## Распространённые ошибки

- **Конечные точки тика вне интервала** → `TickAndSpacingNotMatch`. Всегда привязывайте через `TickUtil.getPriceAndTick` (единственное число `TickUtil`).
- **Недостаточно массивов тиков в `SwapV2`** → `NotEnoughTickArrayAccount`. Возьмите список из `swapInternal(...).accounts`.
- **Позиция полного диапазона без расширения битовой карты** → расширение PDA должно быть записываемым; SDK обрабатывает это автоматически.
- **Путаница `sqrt_price_x64` с `price`** → ошибка в коэффициенте 2 здесь особенно болезненна. Если сомневаетесь, позвольте SDK вычислить это из читаемой человеком цены.
- **Слишком ранний сбор вознаграждений** → каждый сбор — это `DecreaseLiquidity` с нулевой ликвидностью и стоит одну транзакцию. Группируйте через `harvestAllRewards` по многим позициям и помните, что его `execute` нуждается в `{ sequentially: true }`.
- **Самостоятельное закрытие аккаунтов NFT** → `ClosePosition` сжигает NFT и закрывает его ATA. Он также закрывает минт NFT Token-2022; классический минт SPL Token остаётся с нулевым предложением, потому что эта программа не может закрывать минты. Не закрывайте поддерживаемые аккаунты отдельно или инструкция откатится.
- **Открытие лимитного ордера на тике без интервала** → `TickAndSpacingNotMatch`. Всегда квантуйте через экспортированный помощник `getOrderTick`.
- **Вызов `decreaseLimitOrder` на полностью заполненном ордере** → `InvalidOrderPhase`. Вместо этого используйте `settleLimitOrder` затем `closeLimitOrder`.
- **Ожидание флага `enableDynamicFee`** → его нет. Опущение `dynamicFeeConfig` просто создаёт пул со статической комиссией, молча и без ошибки. Если вы хотели динамические комиссии, передайте `PublicKey` аккаунта конфигурации, выбранный из `/main/clmm-dynamic-config`.
