На этой странице описаны **структура и назначение** каждого аккаунта. Семена (seeds) канонические и перечислены в [`reference/program-addresses`](/ru/reference/program-addresses). Пул CLMM требует больше аккаунтов, чем пул CPMM, потому что ликвидность хранится разреженно по диапазону тиков; понимание этой разреженности — основная часть этой страницы.

## Инвентарь аккаунтов

Активный пул CLMM описывается следующими семействами аккаунтов. Все принадлежат программе CLMM, кроме двух минтов и их хранилищ.

| Аккаунт | Назначение | Количество на пул |
|---------|-----------|-------------------|
| `AmmConfig` | Уровень комиссии: ставка торговой комиссии, доля протокола, доля фонда, интервал тиков по умолчанию. Общий для всех пулов этого уровня. | 1 (общий) |
| `PoolState` | Текущие `sqrt_price_x64`, текущий тик, общая ликвидность, глобальный рост комиссий, информация о вознаграждениях, указатель наблюдений. | 1 |
| `TickArrayState` | Блок из `TICK_ARRAY_SIZE` соседних тиков. Инициализируется только по требованию. | 0 ≤ N ≤ диапазон |
| `TickArrayBitmapExtension` | Переполняющаяся битовая карта, отслеживающая, какие массивы тиков существуют за пределами встроенной битовой карты в `PoolState`. | 0 или 1 |
| `PersonalPositionState` | По одному на позицию LP. Хранит диапазон, ликвидность и последний видимый рост комиссий/вознаграждений. Authority = владелец NFT. | 1 на позицию |
| Минт позиции NFT | Минт с предложением 1, связанный с `PersonalPositionState`. Его токен-аккаунт разморожен по умолчанию; V2 замораживает его только при совпадении базового минта с фильтром restricted-issuer. | 1 на позицию |
| `ObservationState` | Кольцевой буфер ценовых наблюдений для TWAP. | 1 |
| `token_0_vault`, `token_1_vault` | Токен-аккаунты, хранящие балансы пула. Принадлежат authority пула. | 2 |
| `DynamicFeeConfig` | Переиспользуемый набор параметров для механизма динамической комиссии. Пулы, созданные через `create_customizable_pool`, могут подключиться. Управляется администратором. | общий (по индексу) |
| `LimitOrderState` | По одному на открытый лимитный ордер. Записывает владельца, тик, сторону, общую сумму, снимок выполненного выхода. | 1 на ордер |
| `LimitOrderNonce` | Счетчик на `(wallet, nonce_index)`, который выводит уникальные PDA ордеров. | 1 на (wallet, index) |

## `PoolState`

Текущее состояние пула, читается при каждом своппе и каждом изменении позиции.

```rust
// programs/amm/src/states/pool.rs
pub struct PoolState {
    pub bump:           [u8; 1],
    pub amm_config:     Pubkey,            // fee tier binding
    pub owner:          Pubkey,            // admin (multisig)
    pub token_mint_0:   Pubkey,
    pub token_mint_1:   Pubkey,
    pub token_vault_0:  Pubkey,
    pub token_vault_1:  Pubkey,
    pub observation_key: Pubkey,

    pub mint_decimals_0: u8,
    pub mint_decimals_1: u8,
    pub tick_spacing:   u16,               // inherited from amm_config at init

    pub liquidity:      u128,              // total active (in-range) liquidity
    pub sqrt_price_x64: u128,              // Q64.64 of sqrt(price)
    pub tick_current:   i32,               // current tick index

    pub padding3:       u16,
    pub padding4:       u16,

    // Global fee growth per unit of liquidity, Q64.64.
    pub fee_growth_global_0_x64: u128,
    pub fee_growth_global_1_x64: u128,

    // Accrued-but-not-swept protocol fees (per mint).
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,

    // Reserved padding for future upgrades.
    pub padding5: [u128; 4],

    // Status bitmask. Bits 0-5: open-position, decrease-liquidity,
    // collect-fee, collect-reward, swap, limit-order. A set bit disables
    // the corresponding operation.
    pub status:  u8,

    // Fee-collection mode (CollectFeeOn).
    //   0 = FromInput (deduct fee from the swap input — Uniswap-V3 default)
    //   1 = Token0Only (always deduct fee from token0 vault)
    //   2 = Token1Only (always deduct fee from token1 vault)
    pub fee_on: u8,

    // Client-supplied index (u16 LE) folded into the pool PDA seeds by
    // create_customizable_pool_v2. [0, 0] for pools created via CreatePool /
    // CreateCustomizablePool (the seed component collapses to empty).
    pub seed_index: [u8; 2],
    pub padding: [u8; 4],

    // Live reward streams (up to REWARD_NUM = 3).
    pub reward_infos: [RewardInfo; 3],

    // Inline bitmap tracking initialized tick-arrays in the primary range.
    pub tick_array_bitmap: [u64; 16],

    // Reserved padding for future upgrades.
    pub padding6: [u64; 4],

    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time:    u64,                 // currently disabled by the program
    pub recent_epoch: u64,

    // Per-pool dynamic-fee state. Zero-valued unless the pool was
    // created with `enable_dynamic_fee = true` via create_customizable_pool.
    pub dynamic_fee_info: DynamicFeeInfo,

    // Reserved for future upgrades.
    pub padding1: [u64; 14],
    pub padding2: [u64; 32],
}
```

Поля, с которыми вы будете работать:

- **`sqrt_price_x64`** и **`tick_current`** — состояние цены пула. Обновляются вместе при каждом своппе. `tick_current` — это пол от `log_{1.0001}(price)`.
- **`liquidity`** — это **активная** ликвидность — сумма значений `L` для всех позиций, диапазон которых содержит `tick_current`. Изменяется каждый раз, когда своп пересекает тик, и каждый раз, когда позиция открывается/закрывается/изменяется.
- **`fee_growth_global_{0,1}_x64`** — кумулятивные комиссии, заработанные на единицу ликвидности по всей истории пула. Позиции читают это, чтобы вычислить, что им причитается.
- **`tick_spacing`** привязан к `AmmConfig` при инициализации и никогда не меняется. Он определяет, какие индексы тиков могут быть конечными точками позиции.
- **`tick_array_bitmap`** — это **встроенная** битовая карта, охватывающая часто используемый диапазон тиков вокруг спотовой цены. Для пулов, позиции которых простираются далеко, отслеживание переполнения находится в отдельном `TickArrayBitmapExtension`.
- **`fee_on`** фиксируется при создании пула. `0` (FromInput) воспроизводит классическое поведение Uniswap-V3. `1` и `2` направляют комиссию своппа на одну сторону книги — см. [`products/clmm/fees`](/ru/products/clmm/fees) для анализа компромиссов.
- **`seed_index`** — это `[0, 0]` для каждого пула, созданного через `CreatePool` / `CreateCustomizablePool` (один канонический пул на пару). **Ненулевое** значение означает, что пул был создан через `CreateCustomizablePoolV2` (до 2026-10-22 назывался `CreatePermissionedPool`) и индекс является частью семян PDA пула, позволяя нескольким пулам сосуществовать для одной и той же `(config, mint0, mint1)`. Чтобы повторно вывести адрес такого пула, вы должны знать его `seed_index`.
- **`dynamic_fee_info`** содержит состояние волатильности для надбавки динамической комиссии. Когда включено, каждый своп пересчитывает `dynamic_fee_component` поверх `AmmConfig.trade_fee_rate`. Структура документирована под `DynamicFeeInfo` ниже; пулы без динамической комиссии оставляют всю структуру нулевой.

## `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub index: u16,                       // uses "amm_config"+u16 seed

    pub owner:             Pubkey,        // protocol-fee owner (CollectProtocolFee)
    pub protocol_fee_rate: u32,           // fraction of trade fee to protocol, denom 1e6
    pub trade_fee_rate:    u32,           // trade fee in 1e6ths of volume
    pub tick_spacing:      u16,           // default spacing for pools using this config
    pub fund_fee_rate:     u32,           // fraction of trade fee to fund, denom 1e6
    pub padding_u32: u32,

    pub fund_owner: Pubkey,               // fund-fee owner (CollectFundFee)
    pub padding: [u64; 3],
}
```

Начиная с обновления 2026-09, `CreateAmmConfig` записывает жестко закодированный `protocol_fee_owner::ID` программы в `owner` и `fund_fee_owner::ID` в `fund_owner`. До этого он копировал ключ подписавшего администратора в оба. Существующие конфиги сохраняют то, на что они были созданы или ротированы, поэтому читайте оба поля с аккаунта. Параметры `UpdateAmmConfig` `3` / `4` по-прежнему их ротируют. Адреса находятся в [`reference/program-addresses`](/ru/reference/program-addresses#clmm-fee-owner-wallets).

Типичный опубликованный набор уровней комиссий CLMM (подтвердите против `GET https://api-v3.raydium.io/main/clmm-config`):

| Индекс | `trade_fee_rate` | Интервал тиков | Типичное использование |
|--------|------------------|-----------------|------------------------|
| 0 | `100` (0.01%) | 1 | Стабильные пары, USDC/USDT |
| 1 | `500` (0.05%) | 10 | Коррелированные голубые фишки |
| 2 | `2_500` (0.25%) | 60 | Стандартные пары |
| 3 | `10_000` (1.00%) | 120 | Волатильные или длинные хвосты |

`protocol_fee_rate` и `fund_fee_rate` — это доли торговой комиссии; то же соглашение, что и в CPMM. См. [`products/clmm/fees`](/ru/products/clmm/fees).

## `TickArrayState`

CLMM не хранит отдельную запись для каждого тика. Это потребовало бы миллиарды аккаунтов. Вместо этого программа группирует **`TICK_ARRAY_SIZE` соседних инициализированных или неинициализированных тиков** (обычно 60 или 88 в зависимости от версии программы) в `TickArrayState`, который создаётся лениво при первом использовании.

```rust
pub const TICK_ARRAY_SIZE: usize = 60;
pub const TICK_ARRAY_SIZE_USIZE: usize = 60;

pub struct TickArrayState {
    pub pool_id:                Pubkey,
    pub start_tick_index:       i32,                            // lowest tick in this array
    pub ticks:                  [TickState; TICK_ARRAY_SIZE],   // 60 entries
    pub initialized_tick_count: u8,
    pub recent_epoch:           u64,
    pub padding:                [u8; 107],
}

pub struct TickState {
    pub tick:                       i32,
    pub liquidity_net:              i128,                       // ΔL when crossing this tick upward
    pub liquidity_gross:            u128,                       // total L referencing this tick
    pub fee_growth_outside_0_x64:   u128,                       // see math.mdx
    pub fee_growth_outside_1_x64:   u128,
    pub reward_growths_outside_x64: [u128; 3],

    // Limit-order bookkeeping. All zero for ticks that have never carried
    // a limit order. See products/clmm/math for the matching algorithm.
    pub order_phase:                  u64,                      // monotonic FIFO cohort id
    pub orders_amount:                u64,                      // unfilled tokens in current cohort
    pub part_filled_orders_remaining: u64,                      // remaining tokens of partially-filled cohort
    pub unfilled_ratio_x64:           u128,                     // Q64.64; starts at 1.0 and shrinks as fills occur

    pub padding:                    [u32; 3],
}
```

Четыре поля лимитных ордеров равны нулю для любого тика, который никогда не использовался для лимитного ордера. Когда ордера открываются на тике, программа отслеживает их как последовательность когорт:

- `order_phase` — это идентификатор когорты. Он увеличивается каждый раз, когда когорта переходит из состояния «полностью неисполненная» в «частично исполненная».
- `orders_amount` — это общее количество входного токена текущей (новейшей) когорты.
- `part_filled_orders_remaining` отслеживает предыдущую когорту, которая в настоящий момент исполняется текущими свопами.
- `unfilled_ratio_x64` — это множитель Q64.64, привязанный к когорте: когда своп исполняет X% когорты, коэффициент умножается на `(1 − X)`. Каждый открытый ордер хранит свой снимок `(order_phase, unfilled_ratio_x64)` в момент открытия, поэтому математика расчёта сводится к сравнению снимков.

Правила:

- Конечный тик позиции *t* должен удовлетворять условию `t % tick_spacing == 0`. Программа отклоняет позиции с неправильным интервалом.
- **Массив** тика расположен по адресу `floor(t / (TICK_ARRAY_SIZE * tick_spacing)) * (TICK_ARRAY_SIZE * tick_spacing)`.
- Массив тиков инициализируется лениво: первая позиция или своп, которые касаются неинициализированного массива, создают его и оплачивают ренту.
- Массив тиков **никогда не закрывается** программой. После выделения он сохраняется на протяжении всего времени существования пула, даже после того, как каждый тик внутри него вернётся к `liquidity_gross == 0`. Последующие позиции и свопы повторно используют существующий аккаунт без дополнительной ренты. Нет пути очистки массивов тиков, управляемого `ClosePosition`.

### `TickArrayBitmapExtension`

`PoolState.tick_array_bitmap` (встроенный) охватывает диапазон «близко к спот» — **±512** массива тиков (`TICK_ARRAY_BITMAP_SIZE = 512`; поле `[u64; 16]` содержит 1024 бита, поровну разделённые между отрицательными и положительными начальными индексами, поэтому индексы массива −512 … +511). За пределами этого диапазона (для экстремальных значений тиков) программа поддерживает аккаунт расширения:

```rust
pub struct TickArrayBitmapExtension {
    pub pool_id: Pubkey,
    pub positive_tick_array_bitmap: [[u64; 8]; 14],
    pub negative_tick_array_bitmap: [[u64; 8]; 14],
}
```

Если диапазон вашей позиции «нормальный», вы никогда не думаете об аккаунте расширения. Позиции полного диапазона (например, `(MIN_TICK, MAX_TICK)`) требуют его; SDK разрешает это за вас.

## Позиции

Позиция CLMM — это **набор** из трёх аккаунтов плюс минт:

### Минт NFT позиции

Минт SPL Token или Token-2022 с предложением 1. NFT позиции в кошельке владельца — это ATA, содержащий этот единственный токен. Программа привязывает авторизацию к **текущему держателю баланса ATA NFT**, а не к Pubkey, хранящемуся в состоянии.

Новые минты NFT позиции устанавливают `pool_state` как свой freeze authority перед минтингом единственного токена и удалением mint authority. **Установка freeze authority не замораживает сам аккаунт NFT.** Аккаунт остаётся разморозенным и передаваемым, если только не выполнены оба условия: вызывающий использует `OpenPositionV2` или `OpenPositionWithToken22Nft`, и freeze authority хотя бы одного базового минта хранилища появляется в списке ограниченных издателей CLMM. Только тогда CLMM замораживает аккаунт NFT после минтинга. Это не изменяет ни один байт `PersonalPositionState` или `PoolState`.

### `PersonalPositionState`

Один на открытую позицию. Привязан к минту NFT.

```rust
pub struct PersonalPositionState {
    pub bump: [u8; 1],
    pub nft_mint: Pubkey,                 // this position's NFT mint
    pub pool_id:  Pubkey,

    pub tick_lower_index: i32,
    pub tick_upper_index: i32,

    pub liquidity: u128,                  // this position's L

    // Fee-growth snapshots at last time the position was touched.
    pub fee_growth_inside_0_last_x64: u128,
    pub fee_growth_inside_1_last_x64: u128,
    pub token_fees_owed_0: u64,           // accrued since last collect
    pub token_fees_owed_1: u64,

    pub reward_infos: [PositionRewardInfo; 3],
    pub recent_epoch: u64,
    pub padding: [u64; 7],
}

pub struct PositionRewardInfo {
    pub growth_inside_last_x64: u128,
    pub reward_amount_owed: u64,
}
```

### `ProtocolPositionState` (устарело)

<Note>
  Более старые версии CLMM хранили агрегированную бухгалтерию по `(pool, tick_lower, tick_upper)` в PDA `ProtocolPositionState`. **Новые версии больше не создают и не читают этот аккаунт.** Слот по-прежнему появляется в списках аккаунтов `OpenPosition` / `IncreaseLiquidity` / `DecreaseLiquidity` как `UncheckedAccount` для совместимости ABI, но программа не записывает в него. Существующие аккаунты в цепи — это рудименты; администратор может вызвать `CloseProtocolPosition` для возврата ренты.

  Агрегированная бухгалтерия диапазона теперь выводится непосредственно из двух конечных тиков (`liquidity_gross`, `liquidity_net` и полей `fee_growth_outside_*` / `reward_growths_outside_x64` для каждого тика) в `TickArrayState`. Формула fee-growth-inside `fee_growth_inside = global − outside_lower − outside_upper` продолжает работать без аккаунта агрегированной позиции.
</Note>

## Observation

```rust
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp: u32,
    pub tick_cumulative: i64,                            // Σ tick_current × Δt
    pub padding:         [u64; 4],
}

pub struct ObservationState {
    pub initialized:       bool,
    pub recent_epoch:      u64,
    pub observation_index: u16,
    pub pool_id:           Pubkey,
    pub observations:      [Observation; OBSERVATION_NUM], // 100 entries
    pub padding:           [u64; 4],
}
```

Буфер наблюдений CLMM хранит **кумулятивный тик**, а не кумулятивную цену. Внешние потребители вычисляют геометрическую среднюю цену за интервал из `(tick_cumulative[t1] − tick_cumulative[t0]) / (t1 − t0)`, а затем `price = 1.0001 ** tick`. См. [`algorithms/clmm-math`](/ru/algorithms/clmm-math).

## `DynamicFeeConfig` и `DynamicFeeInfo`

Параметры динамической комиссии находятся в двух местах. Переиспользуемый шаблон — `DynamicFeeConfig` — управляется администратором и используется пулами, которые согласились. Состояние выполнения для каждого пула — `DynamicFeeInfo` — встроено в `PoolState` и обновляется каждым свопом.

### `DynamicFeeConfig`

```rust
// programs/amm/src/states/pool_fee.rs
pub struct DynamicFeeConfig {
    pub index:                       u16,    // identifier; PDA seed component
    pub filter_period:               u16,    // seconds — within this window the volatility reference is held
    pub decay_period:                u16,    // seconds — beyond this window the reference fully decays
    pub reduction_factor:            u16,    // fixed-point in [1, 10_000); applied at decay
    pub dynamic_fee_control:         u32,    // fixed-point in (0, 100_000); fee-rate gain
    pub max_volatility_accumulator:  u32,    // ceiling on the volatility accumulator
    pub padding:                     [u64; 8],
}
```

Seed PDA: `["dynamic_fee_config", index.to_be_bytes()]`. Создаётся через `create_dynamic_fee_config` (с ограничением администратора) и изменяется через `update_dynamic_fee_config`. Пул, созданный с `enable_dynamic_fee = true`, снимает пять параметров калибровки конфига (`filter_period`, `decay_period`, `reduction_factor`, `dynamic_fee_control`, `max_volatility_accumulator`) в свой собственный `DynamicFeeInfo` при создании; более поздние изменения `DynamicFeeConfig` не влияют ретроактивно на существующие пулы.

### `DynamicFeeInfo` (встроено в `PoolState`)

```rust
pub struct DynamicFeeInfo {
    pub filter_period:                u16,
    pub decay_period:                 u16,
    pub reduction_factor:             u16,
    pub dynamic_fee_control:          u32,
    pub max_volatility_accumulator:   u32,
    pub tick_spacing_index_reference: i32,    // tick-spacing-units; reference for next swap
    pub volatility_reference:         u32,    // running floor for the accumulator
    pub volatility_accumulator:       u32,    // current cumulative volatility (capped)
    pub last_update_timestamp:        u64,
    pub padding:                      [u8; 46],
}
```

Нижние четыре поля — это состояние; верхние пять — это калибровка, скопированная из `DynamicFeeConfig`. Математика комиссии и правила затухания задокументированы в [`products/clmm/math`](/ru/products/clmm/math) и [`products/clmm/fees`](/ru/products/clmm/fees).

Константы, используемые формулой:

| Константа | Значение | Смысл |
|---|---|---|
| `VOLATILITY_ACCUMULATOR_SCALE` | `10_000` | Гранулярность аккумулятора волатильности |
| `REDUCTION_FACTOR_DENOMINATOR` | `10_000` | Знаменатель для `reduction_factor` |
| `DYNAMIC_FEE_CONTROL_DENOMINATOR` | `100_000` | Знаменатель для `dynamic_fee_control` |
| `MAX_FEE_RATE_NUMERATOR` | `100_000` | Жёсткий лимит 10% на результирующую ставку комиссии |

## `LimitOrderState`

Один аккаунт на открытый лимитный ордер.

```rust
// programs/amm/src/states/limit_order.rs
pub struct LimitOrderState {
    pub pool_id:            Pubkey,
    pub owner:              Pubkey,
    pub tick_index:         i32,
    pub zero_for_one:       bool,    // direction: true sells token0 for token1
    pub order_phase:        u64,     // snapshot of TickState.order_phase at open time
    pub total_amount:       u64,     // input-token amount placed
    pub filled_amount:      u64,     // informational; computed precisely on settle
    pub settle_base:        u64,     // unfilled remainder at last settle/decrease
    pub settled_output:     u64,     // cumulative output-token paid to owner
    pub open_time:          u64,
    pub unfilled_ratio_x64: u128,    // Q64.64 snapshot of TickState.unfilled_ratio_x64 at open
    pub padding:            [u64; 4],
}
```

Жизненный цикл:

1. **Open** — пользователь вызывает `open_limit_order`, депонирует `total_amount` входного токена, ордер привязывается к когорте `TickState`.
2. **(опционально) Increase / Decrease** — `increase_limit_order` добавляет к `total_amount`; `decrease_limit_order` возвращает неисполненные токены (и любой исполненный выход до этого момента).
3. **Settle** — когда когорта полностью или частично исполнена, владелец *или* оперативный хранитель вызывает `settle_limit_order` для отправки выходных токенов на ATA владельца.
4. **Close** — как только `unfilled_amount == 0`, аккаунт можно закрыть. Рента всегда возвращается `owner`.

Seed PDA: `[owner.as_ref(), limit_order_nonce.key().as_ref(), limit_order_nonce.order_nonce.to_be_bytes().as_ref()]`. Таким образом, PDA ордера уникален для каждого `(owner, nonce_index, order_nonce)`.

## `LimitOrderNonce`

Счётчик для каждой пары `(wallet, nonce_index)`, позволяющий одному пользователю запускать несколько параллельных конвейеров лимитных ордеров без коллизий на PDA.

```rust
pub struct LimitOrderNonce {
    pub user_wallet: Pubkey,
    pub nonce_index: u8,             // user-chosen, 0..255
    pub order_nonce: u64,            // monotonic, incremented every time a new order is opened
    pub padding:     [u64; 4],
}
```

Seed PDA: `[user_wallet.as_ref(), &[nonce_index]]`. Большинство клиентов используют `nonce_index = 0` и позволяют `order_nonce` нести кардинальность.

## `Permission` (снято с производства)

Аккаунт `Permission` был удалён в [обновлении от 2026-10-22](/ru/reference/changelog/2026-10-22-clmm-customizable-pool-v2). Раньше он ограничивал доступ к `CreatePermissionedPool`, которая теперь является бесправовой `CreateCustomizablePoolV2`. Программа больше не читает и не закрывает эти аккаунты, а инструкции `CreatePermissionPda` / `ClosePermissionPda` удалены. PDA, созданные до обновления (`["permission", authority]`, 280 байт), остаются в цепи как инертные данные; игнорируйте их при сканировании аккаунтов, принадлежащих CLMM.

## Получение ключевых аккаунтов

```ts
import { PublicKey } from "@solana/web3.js";

const CLMM_PROGRAM_ID = new PublicKey(
  "CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK"
); // see reference/program-addresses

function i32ToBytes(n: number): Buffer {
  const b = Buffer.alloc(4);
  b.writeInt32BE(n);
  return b;
}

export function deriveClmmAccounts(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
) {
  const [poolState] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  // NOTE: pools created via CreateCustomizablePoolV2 append a non-zero u16
  // seed_index (LE) as a 5th seed — see deriveCustomizablePoolV2 below.
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  const [tickArrayBitmapExtension] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_tick_array_bitmap_extension"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return { poolState, observation, tickArrayBitmapExtension };
}

export function deriveTickArray(
  pool: PublicKey,
  startTickIndex: number,
) {
  const [tickArray] = PublicKey.findProgramAddressSync(
    [Buffer.from("tick_array"), pool.toBuffer(), i32ToBytes(startTickIndex)],
    CLMM_PROGRAM_ID,
  );
  return tickArray;
}

export function deriveDynamicFeeConfig(index: number) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16BE(index);
  const [pda] = PublicKey.findProgramAddressSync(
    [Buffer.from("dynamic_fee_config"), idx],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveCustomizablePoolV2(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
  seedIndex: number,               // non-zero u16
) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16LE(seedIndex);    // little-endian, unlike the u16 seeds above
  const [pool] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer(), idx],
    CLMM_PROGRAM_ID,
  );
  return pool;
}

export function deriveLimitOrderNonce(
  wallet: PublicKey,
  nonceIndex: number,
) {
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), Buffer.from([nonceIndex & 0xff])],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveLimitOrder(
  wallet: PublicKey,
  nonceAccount: PublicKey,
  orderNonce: bigint,
) {
  const nonceBytes = Buffer.alloc(8);
  nonceBytes.writeBigUInt64BE(orderNonce);
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), nonceAccount.toBuffer(), nonceBytes],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function derivePersonalPosition(nftMint: PublicKey) {
  const [personalPosition] = PublicKey.findProgramAddressSync(
    [Buffer.from("position"), nftMint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return personalPosition;
}
```

Точные строки seed всегда следует проверять по IDL в цепи и [`reference/program-addresses`](/ru/reference/program-addresses).

## Краткий справочник жизненного цикла

| Событие | Созданные аккаунты | Удалённые аккаунты |
|-------|------------------|---------------------|
| `CreatePool` | `poolState`, `observation`, `token_0_vault`, `token_1_vault` | — |
| `OpenPosition[V2]` / `OpenPositionWithToken22Nft` | NFT mint + ATA, `personalPosition`, возможно новые `tickArrayState`(s), `tickArrayBitmapExtension` если ещё не существует; может заморозить NFT ATA для пула с ограниченным издателем | — |
| `IncreaseLiquidity` | Возможно новые `tickArrayState`(s) | — |
| `DecreaseLiquidity` | — | Возможно очищает записи tick (но сам `tickArrayState` не закрывается) |
| `ClosePosition` | — | NFT ATA, `personalPosition` и Token-2022 NFT mint; классический SPL NFT mint остаётся с нулевым предложением. Замороженный путь сначала разморозится через пул, переданный в оставшихся аккаунтах. |
| `SwapV2` | Возможно новые `tickArrayState` | — |
| `OpenLimitOrder` | `limitOrderState`, возможно `limitOrderNonce` (init-if-needed), возможно новые `tickArrayState` | — |
| `IncreaseLimitOrder` | — | — |
| `DecreaseLimitOrder` | — | Закрывает `limitOrderState` если ордер полностью исполнен |
| `SettleLimitOrder` | — | — |
| `CloseLimitOrder` | — | `limitOrderState` (rent → `owner`) |
| `CreateDynamicFeeConfig` | `dynamicFeeConfig` | — |
| `CreateCustomizablePool` | `poolState`, `observation`, vaults — как в `CreatePool`. Снимает снимок `dynamicFeeConfig` если `enable_dynamic_fee = true`. | — |
| `CreateCustomizablePoolV2` | `poolState` (по адресу, полученному из `seed_index`), `observation`, vaults — как в `CreateCustomizablePool`. Бесправовая. | — |
| `CollectRewards` | — | — |
| `UpdateRewardInfos` | — | — |
| `CloseProtocolPosition` (admin) | — | Рудиментарный `protocolPositionState` (rent → admin) |

Аккаунты `TickArrayState` **никогда не закрываются программой** — они сохраняются на протяжении всей жизни пула. После инициализации tick array он остаётся в цепи даже когда каждый tick внутри него возвращается к `liquidity_gross == 0`. Повторное использование существующего tick array бесплатно; только первая позиция, касающаяся никогда не инициализированного массива, платит его rent.
