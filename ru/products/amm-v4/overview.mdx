## Краткое резюме

AMM v4 — это программа, с которой Raydium начинал. Она поддерживает инвариант constant-product (`x · y = k`). Изначально она была разработана как **гибридный AMM**: каждый пул находился поверх маркета лимитных ордеров OpenBook (ранее Serum) и отражал части своей кривой в виде лимитных ордеров на этом маркете, так что пользователи и агрегаторы могли совершать своп либо напрямую против пула (путь AMM), либо против лимитных ордеров, которыми владел пул на OpenBook (путь CLOB). **Зависимость от OpenBook была удалена из программы** — пулы больше не размещают и не поддерживают ордера на OpenBook, и весь текущий трафик своп-операций проходит через AMM-only V2 swap entrypoints. Token-2022 не поддерживается. AMM v4 **по-прежнему полностью функционален как constant-product AMM** — каждый пул продолжает торговаться, комиссии по-прежнему начисляются, LP по-прежнему зарабатывают — но UI и SDK по умолчанию создают новые пулы в [CPMM](/ru/products/cpmm), потому что CPMM дешевле и поддерживает больше типов монет.

## История гибридной архитектуры (контекст)

При запуске создание пула рядом с order-book Serum рисковало фрагментировать ликвидность. Гибридный дизайн публиковал кривую AMM на маркете в виде лимитных ордеров, так что маршрутизаторы order-book видели глубину пула бесплатно. После того как OpenBook отделился от Serum в конце 2022 года, программа продолжала работать с OpenBook с минимальными изменениями. По мере развития CPMM и on-chain агрегаторов преимущество order-book стало менее значимым, и интеграция AMM v4 с OpenBook была в итоге отключена — кривая теперь является единственной поверхностью исполнения пула.

## Что даёт AMM v4 (чего нет в CPMM)

- **Глубокая ликвидность для устаревших пар.** Основные пары (SOL-USDC, mSOL-USDC и т. д.) с большим TVL в AMM v4 остаются самым глубоким местом для этих торгов.

(Исторически AMM v4 также предлагал видимость на order-book через гибридный механизм OpenBook, но этот путь больше не активен. Любой интегратор, который ранее маршрутизировал через ордера AMM на OpenBook, должен теперь маршрутизировать напрямую через swap entrypoints AMM.)

## Чего AMM v4 не даёт

- **Token-2022.** Не поддерживается. AMM v4 был написан до появления Token-2022; его макеты аккаунтов предполагают классический SPL Token.
- **Низкое количество аккаунтов при v1 своп-операциях.** Макеты legacy `SwapBaseIn` / `SwapBaseOut` по-прежнему содержат аккаунты маркета OpenBook как позиционные заполнители (они принимаются, но больше не валидируются и не используются). Используйте `SwapBaseInV2` / `SwapBaseOutV2`, чтобы удалить их и уменьшить размер транзакции.
- **Низкое потребление вычислений.** Даже V2 своп стоит дороже, чем своп CPMM.
- **Поток создания новых пулов по умолчанию.** Новые пулы создаются с помощью `Initialize2` (legacy entrypoints `Initialize` / `PreInitialize` были удалены и теперь возвращают ошибку). Raydium UI, SDK и `api-v3.raydium.io` больше не предлагают кнопку "создать пул AMM v4" — путь по умолчанию для новых пулов — это CPMM.

## Как AMM v4 отличается от CPMM

| Аспект | AMM v4 | CPMM |
|-----------|--------|------|
| Кривая | Constant product | Constant product |
| Зависимость от OpenBook | Удалена (изначально была; теперь удалена из программы) | Нет |
| Token-2022 | Нет | Да |
| Количество аккаунтов на V2 своп | ~9 | ~11 |
| Compute units на своп | ~80k–120k (V2 путь) | ~60k–100k |
| LP комиссия | 0.22% от объёма | Варьируется по `AmmConfig` |
| Комиссия протокола | 0.03% от объёма (фиксированная) | Варьируется по `AmmConfig` |
| Fund комиссия | Нет | Да |
| TWAP oracle | Нет встроенного аккаунта наблюдений | Ring buffer `observation` |
| По умолчанию для новых пулов | Нет (по-прежнему принимается) | Да |

Подробнее о комиссиях: [`products/amm-v4/fees`](/ru/products/amm-v4/fees) и [`reference/fee-comparison`](/ru/reference/fee-comparison).

## Концептуальная модель

Пул AMM v4 сегодня — это constant-product `x · y = k` AMM. Оба хранилища полностью доступны для кривой — никакая часть не зарезервирована для ордеров OpenBook, потому что интеграция с OpenBook была удалена. Операции — это **своп** (пользователь ↔ пул, через `SwapBaseInV2` / `SwapBaseOutV2`) и **депозит** / **вывод** (LP операции). Старый **кран** (`MonitorStep`) был удалён и теперь возвращает ошибку при вызове.

*Историческая концептуальная модель (до деактивации):* часть каждого хранилища была зарезервирована как открытые ордера на маркете; расчёт заполненных ордеров происходил во время своп и LP операций; маршрутизированные своп-операции могли заполняться против собственных ордеров AMM на OpenBook. Ничего из этого сегодня не работает.

## Почему CPMM — рекомендуемый выбор по умолчанию

CPMM избавляется от зависимости OpenBook. Компромиссы:

- Транзакции CPMM в 2×–3× дешевле по вычислениям.
- CPMM поддерживает монеты Token-2022.
- Агрегаторы теперь интегрируют CPMM напрямую через Raydium SDK, поэтому преимущество видимости order-book в значительной степени утратило актуальность.
- Операционный риск: исторически сбои или паузы OpenBook могли ухудшить пулы AMM v4 (устаревшие ордера). Теперь, когда зависимость от OpenBook удалена из программы, эта связь разорвана — но CPMM остаётся рекомендуемым, менее затратным выбором по умолчанию.

См. [`protocol-overview/versions-and-migration`](/ru/protocol-overview/versions-and-migration) для руководства по миграции.

## Когда AMM v4 — правильный выбор

- Вы маршрутизируете своп и один из кандидатов — пул AMM v4 с лучшей ценой.
- Вы предоставляете или управляете ликвидностью в существующем пуле AMM v4 — миграция — это выбор, а не требование; пул продолжает функционировать как чистый AMM.
- Вы поддерживаете интеграцию, построенную на AMM v4, и у вас нет причин для миграции.

(Видимость на order-book OpenBook больше не является причиной выбирать AMM v4 — эта интеграция отключена.)

Для нового пула constant-product [CPMM](/ru/products/cpmm) — это более простой выбор по умолчанию.
