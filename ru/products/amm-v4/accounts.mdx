## Реестр

Пул AMM v4 записывает один привязанный маркет на `AmmInfo` при создании. Полная картина:

| Категория | Аккаунт | Владелец | Роль |
|----------|---------|----------|------|
| Пул | `AmmInfo` | Программа AMM v4 | Состояние пула: накопленные комиссии, статус, ссылки на хранилища (и, как устаревшие поля, маркет). |
| Пул | `amm_authority` | Программа AMM v4 | Принадлежащий программе PDA, подписывающий перемещения хранилищ. Общий для всех пулов AMM v4. |
| Пул | `amm_open_orders` | OpenBook | Устаревшая ссылка на `OpenOrders`. Никогда не создаётся и не читается текущей программой, которая записывает `AmmInfo.open_orders = Pubkey::default()` в каждом новом пуле; реальное значение есть только у пулов, созданных до удаления OpenBook. По-прежнему передаётся позиционно в макетах v1. |
| Пул | `amm_target_orders` | Программа AMM v4 | Устаревший аккаунт целевых ордеров. По-прежнему используется `WithdrawPnl` (как аккаунт #10), но сетка не строится. |
| Пул | `pool_coin_token_account` | SPL Token | Хранилище пула на стороне coin (ATA `amm_authority`). |
| Пул | `pool_pc_token_account` | SPL Token | Хранилище пула на стороне pc. |
| Пул | `lp_mint` | SPL Token | Fungible LP mint. |
| Устаревшие (OpenBook) | `serum_market` | OpenBook | Привязанный маркет. Передаётся в макетах v1, но больше не проверяется и не используется. |
| Устаревшие | `serum_bids`, `serum_asks` | OpenBook | Очереди бидов/асков. Игнорируются. |
| Устаревшие | `serum_event_queue` | OpenBook | Ожидающие события. Игнорируются. |
| Устаревшие | `serum_coin_vault`, `serum_pc_vault` | SPL Token | Хранилища уровня маркета. Игнорируются. |
| Устаревшие | `serum_vault_signer` | OpenBook | PDA уровня маркета. Игнорируется. |

Примечание: префикс «serum» сохранён в IDL и названиях полей AMM v4 для обратной совместимости. Эти аккаунты больше не функциональны после удаления OpenBook.

## `AmmInfo`

Корневой аккаунт состояния пула. Большой (≈ 752 байта), так как содержит ссылки на пул и OpenBook встроенными.

```rust
// programs/amm/src/state.rs (сокращённо; порядок полей / имена следуют IDL)
pub struct AmmInfo {
    pub status: u64,           // битовая маска: swap/deposit/withdraw/crank включены
    pub nonce:  u64,           // bump для получения amm_authority
    pub order_num: u64,
    pub depth: u64,
    pub coin_decimals: u64,
    pub pc_decimals:   u64,
    pub state:         u64,    // внутренний конечный автомат
    pub reset_flag:    u64,
    pub min_size:      u64,
    pub vol_max_cut_ratio: u64,
    pub amount_wave: u64,
    pub coin_lot_size: u64,    // устаревшее (размер лота OpenBook); теперь инициализируется в 0
    pub pc_lot_size:   u64,    // устаревшее; теперь инициализируется в 0
    pub min_price_multiplier: u64,
    pub max_price_multiplier: u64,
    pub sys_decimal_value: u64,

    pub fees: Fees,            // ставки комиссий за торговлю/протокол/фонд
    pub state_data: StateData,

    // Аккаунты, принадлежащие пулу:
    pub coin_vault: Pubkey,
    pub pc_vault:   Pubkey,
    pub coin_vault_mint: Pubkey,
    pub pc_vault_mint:   Pubkey,
    pub lp_mint:  Pubkey,
    pub open_orders: Pubkey,   // OpenOrders пула на OpenBook
    pub market: Pubkey,        // маркет OpenBook
    pub market_program: Pubkey, // ID программы OpenBook
    pub target_orders: Pubkey,
    pub padding1: [u64; 8],     // резерв — НЕ withdraw_queue / lp_vault
    pub amm_owner: Pubkey,      // администратор (multisig)
    pub lp_amount: u64,         // внутренний итог LP пула; см. примечание ниже
    pub client_order_id: u64,
    pub recent_epoch: u64,
    pub padding2: u64,
}

pub struct Fees {
    pub min_separate_numerator:   u64,     // 5
    pub min_separate_denominator: u64,     // 10_000
    pub trade_fee_numerator:      u64,     // 25  → используется интеграцией OpenBook
    pub trade_fee_denominator:    u64,     // 10_000
    pub pnl_numerator:            u64,     // 12  → доля протокола ОТ комиссии свопа
    pub pnl_denominator:          u64,     // 100 → итак 12/100 = 12% комиссии, = 0.03% объёма
    pub swap_fee_numerator:       u64,     // 25  → 0.25% валовая комиссия свопа
    pub swap_fee_denominator:     u64,     // 10_000
}

pub struct StateData {
    pub need_take_pnl_coin: u64,        // по-прежнему обновляется — накопленная комиссия протокола (сторона coin)
    pub need_take_pnl_pc:   u64,        // по-прежнему обновляется — накопленная комиссия протокола (сторона pc)
    pub total_pnl_pc:   u64,            // УСТАРЕВШЕЕ — больше не обновляется
    pub total_pnl_coin: u64,            // УСТАРЕВШЕЕ — больше не обновляется
    pub pool_open_time: u64,            // по-прежнему используется — временная метка открытия пула
    pub padding: [u64; 2],              // зарезервировано
    pub orderbook_to_init_time: u64,    // УСТАРЕВШЕЕ — больше не обновляется
    pub swap_coin_in_amount: u128,      // УСТАРЕВШЕЕ — счётчики объёма заморожены
    pub swap_pc_out_amount:  u128,      // УСТАРЕВШЕЕ
    pub swap_acc_pc_fee:    u64,        // УСТАРЕВШЕЕ
    pub swap_pc_in_amount:  u128,       // УСТАРЕВШЕЕ
    pub swap_coin_out_amount: u128,     // УСТАРЕВШЕЕ
    pub swap_acc_coin_fee:  u64,        // УСТАРЕВШЕЕ
}
```

<Note>
  Макет структуры **не изменился** (совместим по байтам), поэтому существующие десериализаторы продолжают работать, но после удаления OpenBook поля, отмеченные как `УСТАРЕВШЕЕ` выше, **больше не записываются** — счётчики объёма `swap_*` заморожены на последнем значении. Для аналитики объёма используйте логи торговли вместо этих полей. Только `need_take_pnl_*` и `pool_open_time` активно поддерживаются.
</Note>

Поля, видимые интеграторам:

- **`coin_vault`**, **`pc_vault`** — хранилища SPL Token пула. `coin` — это `token_0` по соглашению Serum/OpenBook (базовый), `pc` — это `token_1` (котировка).
- **`coin_decimals`**, **`pc_decimals`** — соответствующие минтам.
- **`open_orders`**, **`target_orders`**, **`market`** — устаревшие справочные поля. По-прежнему присутствуют на `AmmInfo` и по-прежнему передаются позиционно в макетах инструкций v1, но программа больше их не читает и не проверяет. Точки входа V2 для свопов их опускают.
- **`fees.swap_fee_numerator / swap_fee_denominator`** — объединённая комиссия торговли. По умолчанию `25 / 10_000 = 0.25%`.
- **`status`** — единственное перечислимое состояние типа `u64`, ограничивающее операции, а **не** битовая маска. Устанавливается администратором через `SetParams` с `param = 0` (`Status`). См. [Статус](#статус) ниже.
- **`lp_amount`** — внутренний итог LP пула. Он **не** равен `lp_mint.supply`: он ровно на один целый LP-токен (`10^coin_decimals` базовых единиц) больше, потому что эта сумма учитывается при инициализации, но никогда не минтится. Вся пропорциональная математика в программе использует `lp_amount`, поэтому используйте его и вы.
- **`amm_owner`** — записывается при создании из жёстко заданного в программе ключа администратора, а не из ключа создателя.
- **`state_data.need_take_pnl_*`** — дельта между валовыми накопленными комиссиями и тем, что было снято. `TakePnl` обнуляет эти значения.

## Проводка OpenBook

<Note>
  **Удалена.** Зависимость OpenBook / Serum была удалена из программы (обновление 2026-07). Аккаунты, описанные в этом разделе, больше не проверяются и не используются. Они остаются справочными полями на `AmmInfo` и позиционными заполнителями в старых макетах инструкций v1. Используйте **точки входа V2 для свопов** ([`SwapBaseInV2` / `SwapBaseOutV2`](/ru/products/amm-v4/instructions)), которые полностью пропускают эти аккаунты.
</Note>

Когда вы вызываете устаревшую инструкцию v1 `SwapBaseIn` / `SwapBaseOut`, `Deposit` или `Withdraw`, **количество** аккаунтов должно по-прежнему соответствовать старому макету (аккаунты маркета занимают свои исторические позиции), но их **содержимое больше не проверяется** — никакой CPI не выполняется против них. Новый код должен использовать варианты V2 для свопов, которые вообще не принимают эти аккаунты.

```ts
const market = ...;  // PublicKey маркета OpenBook

// Поля, которые OpenBook предоставляет на своём аккаунте маркета:
const marketDecoded = OpenBookMarket.decode(marketAccountData);
const {
  bids:           serumBids,
  asks:           serumAsks,
  eventQueue:     serumEventQueue,
  requestQueue:   serumRequestQueue,
  baseVault:      serumCoinVault,
  quoteVault:     serumPcVault,
  vaultSignerNonce,
} = marketDecoded;

const serumVaultSigner = PublicKey.createProgramAddressSync(
  [market.toBuffer(), u64ToBytes(vaultSignerNonce)],
  OPENBOOK_PROGRAM_ID,
);
```

`amm_open_orders` пула — это принадлежащий OpenBook аккаунт, содержащий состояние лимитных ордеров пула на этом маркете: активные ордеры, урегулированные балансы, рефереры и т. д. `amm_target_orders` — со стороны AMM: он содержит *предполагаемую* сетку AMM (цена/размер для каждого слота ордера), чтобы программа могла дёшево сравнить с тем, что в настоящий момент выставлено, и разместить / отменить разницу.

## Authority PDAs

Существует ровно один PDA `amm_authority` для всей программы AMM v4. Его seed тривиален (`["amm authority"]`), а его bump хранится на каждом `AmmInfo`. Эта authority подписывает все перемещения токенов для всех пулов AMM v4.

```ts
const AMM_V4_PROGRAM_ID = new PublicKey(
  "675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8",
);
const [ammAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("amm authority")],
  AMM_V4_PROGRAM_ID,
);
```

Второй, ограниченной пулом authority не существует: этот единственный PDA покрывает всё, что подписывает программа. Его bump равен `254` в mainnet и дублируется на каждом `AmmInfo` в поле `nonce`; `WithdrawExcessLamports` заново выводит его с жёстко заданным этим nonce.

## Хранилища

Хранилища SPL Token пула — это стандартные аккаунты токенов, чей `owner` — это `amm_authority`. Это не ATA — их адреса являются PDA, полученными при `Initialize2` из `[AMM_V4_PROGRAM_ID, market, "coin_vault_associated_seed"]` и `[AMM_V4_PROGRAM_ID, market, "pc_vault_associated_seed"]`. Минт в seeds не входит, как и `amm_id`. Адреса хранятся на `AmmInfo`; их вывод — одноразовое любопытство.

Token-2022 **не поддерживается**. Программа жёстко кодирует ID программы SPL Token для всех перемещений хранилищ. Попытка привязать пул AMM v4 к минту Token-2022 не удаётся при `Initialize2` с ошибкой `InvalidSplTokenProgram`.

## LP mint

Классический SPL Token mint, чья authority — это `amm_authority`. Общее предложение отслеживает владение LP пулом; сжигание LP возвращает токены из обоих хранилищ пропорционально.

Зеркало в состоянии всё же **есть**: `AmmInfo.lp_amount`. Оно не равно предложению минта — оно ровно на один целый LP-токен (`10^coin_decimals` базовых единиц) больше, потому что эта сумма учитывается при инициализации, но никогда не минтится. Каждое пропорциональное вычисление в программе делит на `lp_amount`, поэтому используйте это поле, а не предложение минта в цепи.

## Статус

`AmmInfo.status` — это единственное перечислимое состояние типа `u64`, а **не** битовая маска. Проверяйте его на равенство: клиент, проверяющий `status & 1`, неверно классифицирует каждый живой пул, потому что обычное торговое состояние — это `6`, у которого бит 0 установлен.

| Значение | `AmmStatus` | Swap | Deposit | Withdraw |
|-------|-------------|------|---------|----------|
| 0 | `Uninitialized` | нет | нет | нет |
| 1 | `Initialized` | да | да | да |
| 2 | `Disabled` | нет | нет | нет |
| 3 | `WithdrawOnly` | нет | нет | да |
| 4 | `LiquidityOnly` | нет | да | да |
| 5 | `OrderBookOnly` | нет | да | да |
| 6 | `SwapOnly` | да | да | да |
| 7 | `WaitingTrade` | да, после наступления `pool_open_time` | да | да |

`Initialize2` записывает `7`, если `open_time` в будущем, и `6` в противном случае; пул со значением `7` сам переключается на `6` при первом свопе в момент `state_data.pool_open_time` или позже. Значение вне диапазона `0..=7` вызывает панику в `AmmStatus::from_u64`.

Multisig Raydium устанавливает состояние через `SetParams` с `param = 0` (`Status`); принимаются только значения `1`–`7`. (`AdminCancelOrders` был удалён.)

## Наблюдение / оракул

**AMM v4 не имеет выделенного аккаунта наблюдения**, и после удаления OpenBook нет и состояния книги ордеров, из которого его можно было бы вывести. Если вам нужен TWAP Raydium с поддержкой программы, используйте CPMM или CLMM — оба поддерживают кольцевой буфер `ObservationState`. В противном случае индексируйте логи свопов вне цепи.

## Получение аккаунтов пула с нуля

Аккаунты пула AMM v4 — это обычные PDA, ключом для которых служит привязанный маркет: не seeded keypair и не PDA для каждой пары. Все они используют одну и ту же трёхсидовую форму `[AMM_V4_PROGRAM_ID, market, <label>]` под `AMM_V4_PROGRAM_ID`:

| Аккаунт | `<label>` |
|---------|-----------|
| `amm_id` (`AmmInfo`) | `"amm_associated_seed"` |
| `amm_target_orders` | `"target_associated_seed"` |
| `lp_mint` | `"lp_mint_associated_seed"` |
| `pool_coin_token_account` | `"coin_vault_associated_seed"` |
| `pool_pc_token_account` | `"pc_vault_associated_seed"` |

```ts
const [ammId] = PublicKey.findProgramAddressSync(
  [
    AMM_V4_PROGRAM_ID.toBuffer(),
    marketPubkey.toBuffer(),
    Buffer.from("amm_associated_seed"),
  ],
  AMM_V4_PROGRAM_ID,
);
```

Привязанный маркет — единственный переменный seed, поэтому один маркет соответствует ровно одному пулу AMM v4. SDK и API предварительно вычисляют эти значения для вас; см. `Liquidity.getAssociatedPoolKeys` в `raydium-sdk-v2`.

На практике интеграторы читают полный набор аккаунтов пула из `GET https://api-v3.raydium.io/pools/info/ids?ids=<POOL_ID>` или из SDK. Ручное получение редко требуется.

## Краткая справка по жизненному циклу

| Событие | Созданные аккаунты | Удалённые аккаунты |
|---------|-------------------|-------------------|
| `Initialize2` | `amm_info`, `amm_target_orders`, оба хранилища, `lp_mint` и LP ATA создателя | — |
| `Deposit` | — (может создать пользовательский LP ATA) | — |
| `Withdraw` | — | — |
| `SwapBaseIn` / `SwapBaseOut` (v1 / V2) | — (может создать пользовательский ATA) | — |
| `WithdrawPnl` | — | — |

Пулы и их аккаунты сохраняются неопределённо долго. Даже если ликвидность полностью выведена, `AmmInfo` остаётся.
