Примечания:

- AMM v4 и Farm v3/v5 **сохраняются для существующих пулов и позиций**. UI Raydium и SDK направляют создание новых пулов и новые экосистемные фермы на CPMM, CLMM и Farm v6 соответственно — см. [`protocol-overview/versions-and-migration`](/ru/protocol-overview/versions-and-migration).
- ID Farm v3 выше также служит программой стейкинга одного актива \$RAY. Поведение идентично Farm v3 для стейкинга LP.
- **Stable AMM** — это отдельная программа, на которую может ориентироваться программа AMM Routing наряду с AMM v4, CPMM и CLMM. Ликвидность тонкая по сравнению с тремя другими программами, и SDK не предоставляет для неё первоклассный API; интеграторы, маршрутизирующие через неё, обычно делают это через маршрутизатор.
- **Доступность исходного кода.** Из on-chain программ выше только `raydium-amm` (AMM v4), `raydium-cp-swap` (CPMM) и `raydium-clmm` (CLMM) поставляются с публичными репозиториями исходного кода под [`github.com/raydium-io`](https://github.com/raydium-io). Stable AMM, LaunchLab, AMM Routing, Burn & Earn / LP Lock и программы Farm недоступны публично — проверяйте их по живому API, on-chain байт-коду и опубликованным IDL в [`raydium-io/raydium-idl`](https://github.com/raydium-io/raydium-idl).

### Общий администратор

Каждая программа Raydium — включая AMM v4 — использует один жёстко закодированный администратор `Pubkey` для контроля доступа на уровне инструкций к путям администратора. Это `config_feature::amm_owner::ID` в AMM v4 (ограничивает `SetParams`, `CreateConfigAccount` и `UpdateConfigAccount`, используется как `pnl_owner` по умолчанию) и `admin::ID` в программах Anchor — CLMM, CPMM, LaunchLab, Lock — ограничивающие пути такие как `CreateAmmConfig` или `UpdatePoolStatus`:

| Кластер | Администратор |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Операционные полномочия на уровне аккаунта (например `protocol_owner`, `fund_owner` на CPMM/CLMM `AmmConfig`, или кошельки миграции на LaunchLab `GlobalConfig`) хранятся on-chain и могут отличаться от администратора программы. Читайте их непосредственно из соответствующего аккаунта конфигурации перед отправкой критичных транзакций.

Где накапливается доля протокола от торговых комиссий каждой программы. Это обычные кошельки, держащие токены, поэтому один адрес содержит смешанный набор SPL монет (wSOL и USDC из пулов SOL/USDC, wSOL и RAY из пулов SOL/RAY и так далее).

|---------|--------------------|-----------|
| CLMM | `projjosVCPQH49d5em7VYS7fJZzaqKixqKtus7yk416` | `AmmConfig.owner` на всех 21 конфигурациях |
| CPMM | `ProCXqRcXJjoUd1RNoo28bSizAA6EEqt9wURZYPDc5u` | `AmmConfig.protocol_owner` (см. [Кошельки владельца комиссии CPMM](#кошельки-владельца-комиссии-cpmm)) |

Доля протокола Stable AMM накапливается в хранилище как `out_put.need_take_pnl_*` и выводится `WithdrawPnl` вместо того, чтобы сидеть на постоянном кошельке. Для CPMM читайте `protocol_owner` с конкретного `AmmConfig` перед построением транзакции сбора — конфигурации, созданные до обновления 2026-09, могут содержать другой ключ.

### Семена PDA

Семена ниже **канонические** и используются как SDK, так и on-chain CPI. Всегда вычисляйте PDA; не жёстко кодируйте производные адреса.

```ts
// CPMM — все семена — это статические ASCII строки, если не указано иное.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` **отсортированы по порядку байтов открытого ключа** (token0 < token1) перед хешированием. Ошибка здесь даёт действительный PDA для несуществующего пула.

Эквивалентные семена CLMM следуют тому же стилю; см. [`products/clmm/accounts`](/ru/products/clmm/accounts).

## Орган обновления

Каждая программа Raydium на mainnet-beta развёрнута под BPF Upgradeable Loader с **одним и тем же** органом обновления — хранилищем мультиподписи программы обновления Squads:

## Как проверить адрес on-chain

1. **Solana Explorer.** Вставьте адрес в [explorer.solana.com](https://explorer.solana.com) и подтвердите, что он отмечен как `Program` с текущим органом обновления. Mainnet-beta должен показывать развёртывания, подписанные органом обновления Raydium.
2. **CLI.** Используйте `solana program show <PROGRAM_ID> -u mainnet-beta` для проверки слота развёртывания, загрузчика BPF, органа обновления и длины данных. Запишите это в вашу инструкцию.
3. **Присоединение IDL.** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` работает для **CLMM, LaunchLab и Lock**, которые всё ещё ведут устаревший аккаунт `anchor:idl`, принадлежащий самой программе. Это **не** работает для CPMM: IDL CPMM on-chain переместился в программу Program Metadata (`ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S`) при обновлении 2026-09, поэтому вместо этого получите его оттуда. AMM v4, Stable AMM и Farm не имеют on-chain IDL. IDL зеркалируются на [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — сравните on-chain IDL с репозиторием перед тем, как ему доверять.
4. **Органы конфигурации/администратора.** Для аккаунтов конфигурации CPMM/CLMM читайте поле `owner`/`protocol_owner` и подтвердите, что оно совпадает с текущей мультиподписью Raydium, опубликованной в [`security/admin-and-multisig`](/ru/security/admin-and-multisig).

Если какая-либо из четырёх проверок выше не совпадает с этой страницей, считайте эту страницу неправильной и откройте проблему перед написанием нового кода для адресов.

## Обновление этой страницы

- Изменения ID программ критичны для безопасности. **Не** отправляйте изменение ID программы без (a) ссылки на объявление Raydium, (b) добавления записи в [`reference/changelog`](/ru/reference/changelog) и (c) запуска проверки ссылок по документации, чтобы подтвердить, что ни одна страница всё ещё не ссылается на старое значение.
- Устаревшие версии остаются в таблице с примечанием о статусе вместо удаления — существующие пулы всё ещё разрешаются через старую программу.
