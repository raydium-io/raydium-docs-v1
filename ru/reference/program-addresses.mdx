- AMM v4 и Farm v3/v5 **сохраняются для существующих пулов и позиций**. Raydium UI и SDK направляют создание новых пулов и новые экосистемные фермы на CPMM, CLMM и Farm v6 соответственно — см. [`protocol-overview/versions-and-migration`](/ru/protocol-overview/versions-and-migration).

### Общий администраторский ключ

Каждая программа Raydium — включая AMM v4 — использует один жёстко закодированный администраторский `Pubkey` для контроля доступа на уровне инструкций к администраторским путям. Это `config_feature::amm_owner::ID` в AMM v4 (ограничивает `SetParams`, `CreateConfigAccount` и `UpdateConfigAccount`, и используется как `pnl_owner` по умолчанию) и `admin::ID` в Anchor-программах — CLMM, CPMM, LaunchLab, Lock — ограничивающий пути такие как `CreateAmmConfig` или `UpdatePoolStatus`:

| Кластер | Администратор |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Операционные ключи на уровне аккаунта (например `protocol_owner`, `fund_owner` на CPMM/CLMM `AmmConfig`, или кошельки миграции на LaunchLab `GlobalConfig`) хранятся on-chain и могут отличаться от администратора программы. Читайте их непосредственно из соответствующего аккаунта конфигурации перед отправкой критичных транзакций.

### Семена PDA

Семена ниже **канонические** и используются как SDK, так и on-chain CPI. Всегда вычисляйте PDA; не жёстко кодируйте производные адреса.

```ts
// CPMM — все семена — это статические ASCII строки, если не указано иное.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);

// Опциональное переопределение доли протокола в комиссии создателя для каждого создателя.
// Аккаунт может не существовать; оба пути CollectCreatorFee по-прежнему требуют адрес.
const [creatorFeeShare] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_share"), creator.toBuffer(), ammConfig.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` **отсортированы по порядку байтов открытого ключа** (token0 < token1) перед хешированием. Ошибка в этом даёт действительный PDA для несуществующего пула.

Эквивалентные семена CLMM следуют тому же стилю; см. [`products/clmm/accounts`](/ru/products/clmm/accounts).

## Как проверить адрес on-chain

1. **Solana Explorer.** Вставьте адрес в [explorer.solana.com](https://explorer.solana.com) и подтвердите, что он отмечен как `Program` с текущим администратором обновления. Mainnet-beta должен показывать развёртывания, подписанные администратором обновления Raydium.
2. **CLI.** Используйте `solana program show <PROGRAM_ID> -u mainnet-beta` для проверки слота развёртывания, BPF загрузчика, администратора обновления и длины данных. Запишите эти значения в вашу инструкцию.
3. **Присоединение IDL.** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` работает для **CLMM, LaunchLab и Lock**, которые по-прежнему ведут устаревший аккаунт `anchor:idl`, принадлежащий самой программе. Это **не** работает для CPMM: IDL CPMM on-chain переместился в программу Program Metadata (`ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S`) при обновлении 2026-09, поэтому вместо этого получите его оттуда. AMM v4, Stable AMM и Farm не имеют on-chain IDL. IDL зеркалируются на [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — сравните on-chain IDL с репозиторием перед тем, как доверять ему.
4. **Конфигурация/администраторские ключи.** Для конфигурационных аккаунтов CPMM/CLMM читайте поле `owner`/`protocol_owner` и подтвердите, что оно совпадает с текущей мультиподписью Raydium, опубликованной в [`security/admin-and-multisig`](/ru/security/admin-and-multisig).

Если любая из четырёх проверок выше не совпадает с этой страницей, считайте эту страницу неправильной и откройте issue перед написанием нового кода для этих адресов.

## Обновление этой страницы

- Изменения ID программ критичны для безопасности. **Не** отправляйте изменение ID программы без (a) ссылки на объявление Raydium, (b) добавления записи в [`reference/changelog`](/ru/reference/changelog) и (c) запуска проверки ссылок по документации для подтверждения того, что ни одна страница по-прежнему не ссылается на старое значение.
