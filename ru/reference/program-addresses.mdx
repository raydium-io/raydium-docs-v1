Примечания:

- AMM v4 и Farm v3/v5 **сохраняются для существующих пулов и позиций**. UI Raydium и SDK направляют создание новых пулов и новые экосистемные фермы на CPMM, CLMM и Farm v6 соответственно — см. [`protocol-overview/versions-and-migration`](/ru/protocol-overview/versions-and-migration).

- **Stable AMM** — отдельная программа, на которую может ориентироваться программа AMM Routing наряду с AMM v4, CPMM и CLMM. Ликвидность тонкая по сравнению с тремя другими программами, и SDK не предоставляет для неё первоклассный API; интеграторы, маршрутизирующие через неё, обычно делают это через маршрутизатор.
- **Доступность исходного кода.** Из on-chain программ выше только `raydium-amm` (AMM v4), `raydium-cp-swap` (CPMM) и `raydium-clmm` (CLMM) поставляются с публичными репозиториями исходного кода под [`github.com/raydium-io`](https://github.com/raydium-io). Stable AMM, LaunchLab, AMM Routing, Burn & Earn / LP Lock и программы Farm не опубликованы — проверяйте их по живому API, on-chain байт-коду и опубликованным IDL в [`raydium-io/raydium-idl`](https://github.com/raydium-io/raydium-idl).

### Общий администратор

Все программы на основе Anchor (CLMM, CPMM, LaunchLab, Lock) используют один жёстко закодированный администратор `Pubkey` для контроля доступа на уровне инструкций к путям администратора (таким как `CreateAmmConfig` или `UpdatePoolStatus`):

| Кластер | Администратор |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Операционные полномочия на уровне аккаунта (например, `protocol_owner`, `fund_owner` на CPMM/CLMM `AmmConfig` или кошельки миграции на LaunchLab `GlobalConfig`) хранятся on-chain и могут отличаться от администратора программы. Читайте их непосредственно из соответствующего аккаунта конфигурации перед отправкой критичных транзакций.

`CreatePermissionPda` принимает либо общего администратора программы выше, либо выделенного владельца. `ClosePermissionPda` остаётся ограничена общим администратором программы.

### Полномочия freeze CLMM restricted-issuer

Когда один из минтов хранилища в пуле CLMM имеет одно из полномочий freeze ниже, новые позиции, открытые через путь V2, имеют замороженный аккаунт токена NFT позиции. Начальная запись — это полномочие, используемое обнаружением активов Superstate CLMM. Это **полномочия издателя базового актива, используемые только как ключи сопоставления**. PDA пула CLMM, а не ключ издателя, становится полномочием freeze для минта NFT позиции.

### Общие соглашения конфигурации / PDA

Несколько программ Raydium предоставляют **аккаунты конфигурации**, чьи открытые ключи стабильны и перечислены в публичном API. Предпочитайте поиск по API вместо жёсткого кодирования:

```
# Конфигурации комиссий CPMM (возвращает массив {id, index, tradeFeeRate, ...})
GET https://api-v3.raydium.io/main/cpmm-config

# Конфигурации комиссий CLMM
GET https://api-v3.raydium.io/main/clmm-config
```

Параметры комиссии по умолчанию CPMM `AmmConfig` индекс `0` (стандартный пул 0.25%), для справки:

| Поле | Значение | Значение |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 0.25% объёма торговли |
| `protocol_fee_rate` | `120000` | 12% **комиссии за торговлю** (не объёма), направляемой протоколу |
| `fund_fee_rate` | `40000` | 4% **комиссии за торговлю**, направляемой фонду multisig |
| `creator_fee_rate` | `500` | 0.05% объёма торговли создателю пула (опционально) |

См. [`products/cpmm/fees`](/ru/products/cpmm/fees) для того, как составляются разделения, и [`reference/fee-comparison`](/ru/reference/fee-comparison) для матрицы кросс-продукта.

### Семена PDA

Семена ниже **канонические** и используются как SDK, так и on-chain CPI. Всегда вычисляйте PDA; не жёстко кодируйте производные адреса.

```ts
// CPMM — все семена — статические ASCII строки, если не указано иное.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` **отсортированы по порядку байтов открытого ключа** (token0 < token1) перед хешированием. Ошибка здесь даст валидный PDA для несуществующего пула.

Эквивалентные семена CLMM следуют тому же стилю; см. [`products/clmm/accounts`](/ru/products/clmm/accounts).

## Как проверить адрес on-chain

1. **Solana Explorer.** Вставьте адрес в [explorer.solana.com](https://explorer.solana.com) и подтвердите, что он отмечен как `Program` с текущим органом обновления. Mainnet-beta должен показывать развёртывания, подписанные органом обновления Raydium.
2. **CLI.** Используйте `solana program show <PROGRAM_ID> -u mainnet-beta` для проверки слота развёртывания, BPF загрузчика, органа обновления и длины данных. Запишите это в вашу инструкцию.
3. **Присоединение IDL.** Запросите on-chain IDL с помощью `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet`. Поле `address` IDL должно совпадать. Те же IDL зеркалируются на [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — сравните on-chain IDL с репозиторием перед доверием.
4. **Полномочия конфигурации/администратора.** Для аккаунтов конфигурации CPMM/CLMM прочитайте поле `owner`/`protocol_owner` и подтвердите, что оно совпадает с текущим multisig Raydium, опубликованным в [`security/admin-and-multisig`](/ru/security/admin-and-multisig).

Если какая-либо из четырёх проверок выше не совпадает с этой страницей, считайте эту страницу неправильной и откройте issue перед написанием нового кода для адресов.

## Обновление этой страницы

- Изменения ID программ критичны для безопасности. **Не** отправляйте изменение ID программы без (a) ссылки на объявление Raydium, (b) добавления записи в [`reference/changelog`](/ru/reference/changelog) и (c) запуска проверки ссылок по документации для подтверждения, что ни одна страница не ссылается на старое значение.
- Устаревшие версии остаются в таблице с примечанием о статусе, а не удаляются — существующие пулы по-прежнему разрешаются через старую программу.
