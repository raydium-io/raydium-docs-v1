Примечания:

- AMM v4 и Farm v3/v5 **сохраняются для существующих пулов и позиций**. UI Raydium и SDK маршрутизируют создание новых пулов и новые экосистемные фермы на CPMM, CLMM и Farm v6 соответственно — см. [`protocol-overview/versions-and-migration`](/ru/protocol-overview/versions-and-migration).

- **Stable AMM** — отдельная программа, на которую может ориентироваться программа AMM Routing наряду с AMM v4, CPMM и CLMM. Ликвидность тонкая по сравнению с тремя другими программами, и SDK не предоставляет для неё первоклассный API; интеграторы, маршрутизирующие через неё, обычно делают это через маршрутизатор.
- **Доступность исходного кода.** Из перечисленных выше on-chain программ только `raydium-amm` (AMM v4), `raydium-cp-swap` (CPMM) и `raydium-clmm` (CLMM) поставляются с публичными репозиториями исходного кода под [`github.com/raydium-io`](https://github.com/raydium-io). Stable AMM, LaunchLab, AMM Routing, Burn & Earn / LP Lock и программы Farm недоступны публично — проверяйте их по живому API, on-chain bytecode и опубликованным IDL в [`raydium-io/raydium-idl`](https://github.com/raydium-io/raydium-idl).

### Общая администраторская власть

Все программы на основе Anchor (CLMM, CPMM, LaunchLab, Lock) используют один жёстко закодированный администраторский `Pubkey` для контроля доступа на уровне инструкций к администраторским путям (таким как `CreateAmmConfig` или `UpdatePoolStatus`):

| Кластер | Администратор |
|---------|-------|
| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Операционные власти на уровне аккаунта (например, `protocol_owner`, `fund_owner` на CPMM/CLMM `AmmConfig` или кошельки миграции на LaunchLab `GlobalConfig`) хранятся on-chain и могут отличаться от администратора программы. Читайте их непосредственно с соответствующего аккаунта конфигурации перед отправкой критичных транзакций.

### Кошельки сбора избыточных lamports

Каждая из трёх программ, обновлённых 2026-09-09, получила администраторскую инструкцию, которая возвращает lamports, удерживаемые выше минимума, освобождённого от арендной платы на контролируемых программой аккаунтах, следуя [SIMD-0437 снижению арендной платы](/solana-fundamentals/rent-and-reclaimable-rent). Каждая программа жёстко кодирует свой собственный целевой кошелёк, и каждый — выделенный ключ, а не общий администратор программы.

| CPMM | `CollectExcessLamports` | `RayGkhY93thaTgCv98sx1pNLgBHhJDxWUeZXp4bjmnp` | `DRaydJNq54dSDHUqYCE3G8YySgaXfZucbh7dTXw9fBMs` |
| LaunchLab | `CollectExcessLamports` | `RayFqUZuGuG4Lt35YSEVX1TS12pKLbiqpB3fPzFG4Ag` | `DRayrZj22uaieAuGA8BnYUnK5zRMEiJM88A13dPrJDyB` |

CPMM и LaunchLab дополнительно принимают общего администратора программы в качестве подписанта. AMM v4 принимает **только** кошелёк выше — у него нет резервного администратора. Эти инструкции перемещают только lamports; они никогда не трогают баланс токена, не закрывают аккаунт и не изменяют состояние пула. См. ### Общие соглашения конфигурации / PDA

Несколько программ Raydium предоставляют **аккаунты конфигурации**, чьи открытые ключи стабильны и перечислены в публичном API. Предпочитайте поиск по API вместо жёсткого кодирования:

```
# CPMM fee configs (возвращает массив {id, index, tradeFeeRate, ...})
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM fee configs
GET https://api-v3.raydium.io/main/clmm-config
```

Получатель комиссии за создание пула CPMM — это фиксированный аккаунт, не производный и не ищущийся через API: `create_pool_fee_reveiver::ID` в `lib.rs` `raydium-cp-swap`, в настоящее время `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`. Инструкция `initialize` CPMM проверяет его по точному адресу, поэтому он должен уже существовать на любом кластере, на котором вы тестируете.

Параметры комиссии конфигурации CPMM по умолчанию с индексом `0` (стандартный пул 0,25%), для справки:

| Поле | Значение | Значение |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 0,25% объёма торговли |
| `protocol_fee_rate` | `120000` | 12% **комиссии за торговлю** (не объёма), направленной в протокол |
| `fund_fee_rate` | `40000` | 4% **комиссии за торговлю**, направленной в фонд multisig |
| `creator_fee_rate` | `500` | 0,05% объёма торговли создателю пула (опционально) |

См. [`products/cpmm/fees`](/ru/products/cpmm/fees) для того, как разделения составляются, и [`reference/fee-comparison`](/ru/reference/fee-comparison) для матрицы кросс-продукта.

### Seeds PDA

Seeds ниже **канонические** и используются как SDK, так и on-chain CPI. Всегда вычисляйте PDA; не жёстко кодируйте производные адреса.

```ts
// CPMM — все seeds — это статические ASCII строки, если не указано иное.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` **отсортированы по порядку байтов открытого ключа** (token0 < token1) перед хешированием. Ошибка здесь даёт валидный PDA для несуществующего пула.

Эквивалентные seeds CLMM следуют тому же стилю; см. [`products/clmm/accounts`](/ru/products/clmm/accounts).

## Как проверить адрес on-chain

1. **Solana Explorer.** Вставьте адрес в [explorer.solana.com](https://explorer.solana.com) и подтвердите, что он отмечен как `Program` с текущей upgrade authority. Mainnet-beta должен показывать развёртывания, подписанные upgrade authority Raydium.
2. **CLI.** Используйте `solana program show <PROGRAM_ID> -u mainnet-beta` для проверки слота развёртывания, BPF loader, upgrade authority и длины данных. Запишите это в вашу runbook.
3. **Присоединение IDL.** Запросите on-chain IDL с помощью `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet`. Поле `address` IDL должно совпадать. Те же IDL зеркалируются на [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — сравните on-chain IDL с репо перед доверием к нему.
4. **Конфигурация/администраторские власти.** Для аккаунтов конфигурации CPMM/CLMM прочитайте поле `owner`/`protocol_owner` и подтвердите, что оно совпадает с текущим multisig Raydium, опубликованным в [`security/admin-and-multisig`](/ru/security/admin-and-multisig).

Если любая из четырёх проверок выше не согласуется с этой страницей, считайте эту страницу неправильной и откройте issue перед написанием нового кода для адресов.

- Устаревания остаются в таблице с примечанием о статусе, а не удаляются — существующие пулы всё ещё разрешаются через старую программу.
