Этот релиз делает CPMM единственной целью выпуска для вновь инициализированных запусков. Он также изменяет, кто получает права на заблокированную LP, перемещает элементы управления выбором `GlobalConfig` администраторам платформы и расширяет входные данные CPI миграции CPMM.

## TL;DR для интеграторов

- **Новые запуски только CPMM.** `Initialize`, `InitializeV2` и `InitializeWithToken2022` требуют `migrate_type = 1`. Новый запуск, настроенный для AMM v4, возвращает `MigrateTypeNotMatch`.
- **Поддержка унаследованного состояния AMM v4 сохраняется.** `MigrateToAmm` не удаляется. Он по-прежнему может выпустить существующий пул, тип миграции которого хранится как `0`.
- **Заблокированная LP создателя переходит на платформу после этого обновления.** До этого релиза `creator_scale` создавал отдельный Fee Key, принадлежащий создателю. Миграции, выполненные после обновления, объединяют `platform_scale + creator_scale` в одну долю заблокированной LP, принадлежащую платформе. `burn_scale` сжигается.
- **Комиссии создателя остаются отдельными.** Комиссии создателя кривой связывания и комиссии создателя CPMM не являются правами Fee Key LP. `platform_cp_creator` по-прежнему определяет, становится ли исходный создатель запуска или выбранный платформой адрес создателем CPMM в записях.
- **Платформы управляют своими собственными списками разрешений конфигурации.** `PlatformConfig.restrict_global_config` и `PlatformAllowConfig` заменяют управляемую глобальным администратором модель `requires_platform_auth` / `PlatformGlobalAccess`.
- **Разработчики миграции CPMM должны внести изменения.** Обновленный путь требует десять фиксированных оставшихся учетных записей и добавляет PDA `support_mint` CPMM для обоих отсортированных монет.
- **Делегированный орган может создать `GlobalConfig`.** Он не может обновлять существующие конфигурации.

## Поведение новых запусков в сравнении с существующим состоянием

Проверка CPMM-only выполняется во время инициализации пула. Она не переписывает существующие учетные записи `PoolState`. Существующие запуски, привязанные к AMM v4, сохраняют свой сохраненный тип миграции и могут использовать сохраненную унаследованную инструкцию миграции.

`amm_creator_fee_on` теперь контролирует только сторону комиссии создателя CPMM (`QuoteToken` или `BothToken`). Клиенты не должны использовать его для определения целевой программы.

## Изменение владения LP

Три поля масштаба остаются в `PlatformConfig`, и их сумма по-прежнему должна равняться `1_000_000`. Распределение во время выполнения теперь:

```text
platform locked LP = floor(total LP × (platform_scale + creator_scale) / 1_000_000)
burned LP          = total LP − platform locked LP
```

До этого релиза LaunchLab блокировал `creator_scale` отдельно и выпускал его Fee Key создателю токена. Для миграций, выполненных после обновления, эта же масштаб добавляется к доле платформы. Если объединенная доля ненулевая, LaunchLab создает один Fee Key для `platform_nft_wallet` и не создает новый Fee Key создателя.

Изменение не изменяет Fee Keys или записи заблокированной ликвидности, созданные миграциями, завершенными до обновления. Запуск, созданный до обновления, но перенесенный после, следует новому распределению, потому что разделение применяется при выполнении `MigrateToCpswap`.

Поскольку макет учетной записи сохраняется, индексаторам не требуется миграция размера учетной записи, но пользовательские интерфейсы и системы учета должны интерпретировать `creator_scale` в соответствии с версией миграции.

## Миграция списка разрешений платформы

`GlobalConfig.requires_platform_auth` удаляется и его байт возвращается в заполнение. `PlatformConfig` повторно использует один байт заполнения для `restrict_global_config`, поэтому оба размера учетной записи остаются неизменными.

Когда `restrict_global_config = 1`, инициализация должна включать PDA, полученный из:

```text
["platform_allow_config", platform_config, global_config]
```

Администратор платформы создает и закрывает эти учетные записи. Бывшие инструкции `CreatePlatformGlobalAccess` и `ClosePlatformGlobalAccess` удаляются, и старые PDA `PlatformGlobalAccess` не удовлетворяют новой проверке. Пути автоматического преобразования нет.

## Изменение учетной записи миграции CPMM

`MigrateToCpswap` теперь ожидает эти индексы `remaining_accounts` с нулевой базой:

| Индекс | Назначение |
|---|---|
| 0–4 | Владелец Fee Key платформы, монета, ATA, PDA заблокированной ликвидности и метаданные |
| 5 | Резервный адрес исходного создателя |
| 6 | PDA разрешения CPMM |
| 7 | Опциональная учетная запись `platform_cp_creator`, настроенная платформой |
| 8–9 | PDA `support_mint` CPMM для отсортированных mint0 и mint1 |

Старые разработчики, которые добавляют отдельные учетные записи блокировки создателя или опускают индексы 8–9, несовместимы с обновленным путем. Получите оба адреса support-mint, используя `[b"support_mint", mint]` под программой CPMM.

## Влияние на ошибки и IDL

Коды `6000`–`6021` остаются стабильными. Бывшие варианты глобального доступа платформы удаляются. `6022` теперь означает `InvalidPlatformAllowConfig`, и старый `6023` больше не существует.

Обновите IDL LaunchLab перед построением инструкций `PlatformAllowConfig`, декодированием обновленных полей конфигурации или построением нового макета миграции CPMM.
