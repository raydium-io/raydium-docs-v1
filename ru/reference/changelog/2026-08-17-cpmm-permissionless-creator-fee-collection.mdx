Этот релиз добавляет путь без разрешения для сбора комиссий создателя. Любой может оплатить запуск сбора, но программа фиксирует получателя как `PoolState.pool_creator` и оба назначения как канонические associated token accounts этого создателя. Существующая инструкция, подписанная создателем, остаётся без изменений.

Также позволяет выделенному органу создавать CPMM `Permission` PDA. Это делегирование намеренно асимметрично: выделенный орган может предоставить доступ к `InitializeWithPermission`, в то время как только администратор программы может отозвать разрешение с помощью `ClosePermissionPda`.

## TL;DR для интеграторов

- **Новая дополнительная инструкция: `CollectCreatorFeePermissionless`.** Любой подписант может быть `payer`. Записанный создатель пула не подписывает.
- **Вызывающий не может перенаправить средства.** `creator` должен равняться `pool_state.pool_creator`. `creator_token_0` и `creator_token_1` должны быть каноническими ATA этого создателя для минтов хранилища пула и их соответствующих программ токенов.
- **Плательщик покрывает отсутствующие ATA.** Обе учётные записи получателя используют `init_if_needed`; плательщик финансирует аренду, когда любая учётная запись не существует.
- **Сбор — всё или ничего.** Инструкция переводит оба полностью накопленных счётчика комиссий создателя, обнуляет оба и обновляет `recent_epoch`. Возвращает существующую ошибку `NoFeeCollect`, когда оба счётчика равны нулю.
- **Существующие интеграции остаются совместимыми.** `CollectCreatorFee` не изменяется и не удаляется. Нет изменений макета `PoolState`, `AmmConfig`, `Permission`, событий или кодов ошибок.
- **Создание Permission имеет второго владельца.** `CreatePermissionPda` принимает администратора программы или выделенного владельца create-permission-PDA. `ClosePermissionPda` остаётся только для администратора.

## Новые учётные записи инструкции

`CollectCreatorFeePermissionless` принимает 14 учётных записей в этом порядке:

| # | Учётная запись | Ограничение или роль |
|---|---------|--------------------|
| 1 | `payer` | Записываемый подписант; финансирует отсутствующие ATA создателя. |
| 2 | `creator` | Должен равняться `pool_state.pool_creator`; не подписывает. |
| 3 | `authority` | CPMM глобальный PDA органа хранилища. |
| 4 | `pool_state` | Записываемый; содержит счётчики комиссий создателя. |
| 5–6 | `token_0_vault`, `token_1_vault` | Записываемые; должны совпадать с хранилищами, сохранёнными в пуле. |
| 7–8 | `vault_0_mint`, `vault_1_mint` | Должны совпадать с соответствующим минтом хранилища. |
| 9–10 | `creator_token_0`, `creator_token_1` | Записываемые канонические ATA создателя; инициализируются при необходимости. |
| 11–12 | `token_0_program`, `token_1_program` | SPL Token или Token-2022 для каждого минта. |
| 13 | `associated_token_program` | Создаёт отсутствующий ATA создателя. |
| 14 | `system_program` | Поддерживает создание учётной записи, финансируемое плательщиком. |

В отличие от `CollectCreatorFee`, новый макет имеет отдельные учётные записи `payer` и не подписывающего `creator` и не принимает `amm_config`. Поэтому требует собственный дискриминатор и построитель.

## Влияние на SDK и IDL

Ветка исходного кода программы не включает зафиксированное обновление SDK или IDL. Интеграторы должны обновить развёрнутый CPMM IDL или использовать выпуск клиента, который явно поддерживает `CollectCreatorFeePermissionless`. Зафиксированный в документации набор построителей `@raydium-io/raydium-sdk-v2@0.2.42-alpha` охватывает только исходный путь, подписанный создателем.

## Граница безопасности

Вызов без разрешения не означает хранение без разрешения. Вызывающий может выбрать, когда собирать, и может потратить SOL на создание отсутствующих ATA создателя. Вызывающий не может выбрать получателя, заменить произвольные учётные записи токенов, запросить частичную сумму или изменить конфигурацию комиссий создателя пула.

Новая роль создателя permission-PDA может создать разрешение для любого `permission_authority` и платит аренду новой учётной записи. Она не может закрыть этот PDA в соответствии с этим изменением. Рассматривайте это как делегированный орган выдачи разрешений, а не полного администратора разрешений.

## Примечания по миграции

- Оставьте существующие транзакции `CollectCreatorFee` без изменений.
- Добавляйте инструкцию без разрешения только после того, как целевое развёртывание CPMM и IDL клиента включат её.
- Автоматизация может сканировать пулы с ненулевыми `creator_fees_token_0` или `creator_fees_token_1` и запускать сбор без хранения ключей создателя.
- Обрабатывайте `NoFeeCollect` как доброкачественное состояние гонки, когда другой вызывающий сначала опустошает счётчики.
- Не передавайте произвольные учётные записи токенов получателя; выводите ATA создателя из `pool_state.pool_creator`, каждого минта хранилища и соответствующей программы токенов.
