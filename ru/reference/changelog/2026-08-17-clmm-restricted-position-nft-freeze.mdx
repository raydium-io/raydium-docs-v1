Этот релиз добавляет условный путь неперевод­имости для выбранных пулов с KYC-ограниченными эмитентами. Он не блокирует каждую новую позицию, не замораживает активы пула и не препятствует владельцам позиций управлять ликвидностью. PDA пула CLMM становится freeze authority для каждого нового mint позиционного NFT, но счёт токена NFT остаётся разморожен по умолчанию. Программа замораживает его только когда позиция использует `OpenPositionV2` или `OpenPositionWithToken22Nft` и хотя бы один базовый vault mint имеет freeze authority из жёстко закодированного списка ограниченных эмитентов.

## TL;DR для интеграторов

- **Новые mint позиционных NFT имеют freeze authority, но не заморожены по умолчанию.** `OpenPosition`, `OpenPositionV2` и `OpenPositionWithToken22Nft` устанавливают `pool_state` позиции как freeze authority mint. Mint authority всё ещё удаляется после создания единственного NFT.
- **Замораживание требует пути V2 и совпадения эмитента.** `OpenPositionV2` и `OpenPositionWithToken22Nft` проверяют `vault_0_mint.freeze_authority` и `vault_1_mint.freeze_authority`. Новый счёт NFT замораживается только если хотя бы один совпадает со списком программы. Без совпадения он остаётся разморожен и передаваем.
- **Заморозка означает привязку к владельцу.** SPL Token отклоняет передачу NFT и изменение владельца счёта с нативной ошибкой `AccountFrozen`. Увеличение/уменьшение ликвидности и сбор комиссий/вознаграждений продолжают работать, когда владелец NFT подписывает.
- **Закрытие остаётся доступным.** `ClosePosition` обнаруживает замороженный счёт NFT, использует PDA пула для его разморозки, затем сжигает NFT и закрывает позицию атомарно.
- **Закрытие замороженной позиции требует один дополнительный счёт.** Клиент должен добавить `personal_position.pool_id` как первый дополнительный счёт. Его отсутствие возвращает CLMM `AccountLack`; передача неправильного пула возвращает `NotApproved`.
- **Существующие позиции не затронуты.** Обновление не изменяет ретроактивно mint authorities NFT или не замораживает существующие счёта токенов.
- **Нет изменений в макете состояния CLMM или объявленном списке счётов IDL.** `PoolState`, `PersonalPositionState` и аргументы инструкций остаются совместимы по байтам. Требование пути закрытия передаётся через `remaining_accounts`.

## Логика срабатывания

Программа оценивает два vault mint при открытии:

```rust
must_freeze = restricted_ids.contains(vault_0_mint.freeze_authority)
           || restricted_ids.contains(vault_1_mint.freeze_authority)
```

Отсутствующий freeze authority не совпадает. Одного совпадающего стороны достаточно. Список — это `frozen_position_nft_authorities::IDS` и содержит одну запись. Текущие ключи mainnet-beta и devnet находятся в [`reference/program-addresses`](/ru/reference/program-addresses#clmm-restricted-issuer-freeze-authorities).

Проверка выполняется в общем обработчике открытия позиции только когда предоставлены счёта vault mint. Это означает:

| Путь открытия | Программа позиционного NFT | Поведение блокировки ограниченного эмитента |
|-----------|----------------------|-----------------------------------|
| `OpenPosition` V1 | SPL Token | Не замораживает. V1 не может обслуживать активы Token-2022 эмитента, на которые нацелен поставляемый список. |
| `OpenPositionV2` | SPL Token | Проверяет оба vault mint и замораживает при совпадении. |
| `OpenPositionWithToken22Nft` | Token-2022 | Проверяет оба vault mint и замораживает при совпадении. |

## Изменения authority позиционного NFT

До этого обновления вновь созданный классический SPL mint позиционного NFT не сохранял freeze authority. После обновления каждый новый mint позиционного NFT называет свой пул как freeze authority, включая позиции в обычных пулах. Это установление authority само по себе не замораживает счёт токена NFT; обычные и несовпадающие позиции остаются разморожены.

Использование PDA пула вместо глобального ключа администратора или эмитента сужает authority до одного пула. Внешняя сторона не может подписать как PDA, и CLMM не предоставляет инструкцию общего назначения для замораживания или разморозки произвольных счётов позиций. Новый код использует authority только в двух местах:

1. Заморозка сразу после создания mint когда проверка базового эмитента совпадает.
2. Разморозка во время `ClosePosition` непосредственно перед сжиганием.

## Миграция `ClosePosition`

Шесть объявленных счётов не изменяются. Для замороженного NFT добавьте пул как первый дополнительный счёт:

```text
declared: nft_owner, position_nft_mint, position_nft_account,
          personal_position, system_program, token_program
remaining[0]: personal_position.pool_id   // read-only, non-signer
```

Обработчик проверяет ключ перед загрузкой `PoolState`, выводит семена подписи пула и выполняет:

```text
разморозить счёт NFT → сжечь NFT → закрыть счёт токена NFT / состояние позиции
```

Все шаги выполняются в одной инструкции Solana и поэтому фиксируются или откатываются вместе. Передача пула при каждом закрытии безопасна: обработчик игнорирует дополнительные счёта когда счёт NFT не заморожен.

<Warning>
  **Условный разрыв клиента.** Старый клиент может успешно открыть позицию после обновления, потому что макеты счётов V2 открытия не изменились. Если эта позиция заморожена, тот же клиент может позже не закрыть её, потому что его построитель `ClosePosition` опускает дополнительный счёт пула. Обновите построитель закрытия перед тем как позволить пользователям открывать позиции в затронутых пулах.
</Warning>

## Матрица совместимости

| Сценарий | Передача NFT | Управление ликвидностью | Построитель закрытия Legacy | Обновленный построитель закрытия |
|----------|--------------|------------------|----------------------|-----------------------|
| Существующая позиция | без изменений | да | да | да |
| Новая позиция, обычный пул | да | да | да | да |
| Новая позиция V2, пул ограниченного эмитента | нет | да | ошибка `AccountLack` | да; атомарная разморозка и сжигание |

Нет новых вариантов пользовательских ошибок CLMM или числовых сдвигов. Нативная ошибка `AccountFrozen` SPL Token отклоняет попытки передачи или изменения владельца.
