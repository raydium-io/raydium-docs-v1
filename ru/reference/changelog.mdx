## Релизы

<Update label="2026-07-22" description="AMM v4: удаление зависимости OpenBook / Serum">
  AMM v4 удаляет давно неиспользуемую зависимость OpenBook/Serum, все CPI вызовы к order-book и мёртвые инструкции для создания рынков. `SwapBaseIn` / `SwapBaseOut`, `Deposit` и `Withdraw` сохраняют свои структуры (удалённые счета рынка теперь игнорируются, не валидируются); **критически несовместимые** изменения `WithdrawPnl` (17 → 10, без совместимости) и `SetParams` (сокращённые счета + переномерованный `param`); инструкции `Initialize`, `PreInitialize`, `MonitorStep`, `MigrateToOpenBook`, `WithdrawSrm`, `SimulateInfo`, `AdminCancelOrders` больше не вызываются. Структуры счетов на блокчейне и коды ошибок остаются стабильными; перенесите свопы на точки входа V2.

  [Читать полную запись →](/ru/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM: удаление мёртвого кода OpenBook (market)">
  Stable AMM удаляет давно неиспользуемые счета и код для создания рынков OpenBook. Меньшие структуры `SwapBaseIn` / `SwapBaseOut` (18 → 9), `Deposit` (14 → 12) и `Withdraw` (21/22 → 12) (старые структуры остаются совместимыми); **критически несовместимые** изменения `WithdrawPnl` (16 → 10, без совместимости); отмена комиссии реферала; и упрощённая формула активов пула только для хранилища. Большинство других инструкций Stable больше не вызываются.

  [Читать полную запись →](/ru/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>

<Update label="2026-05-18" description="CLMM: лимитные ордера, односторонняя комиссия, динамическая комиссия">
  Три опциональные, обратно совместимые возможности CLMM: лимитные ордера первого класса (с `limit_order_admin` keeper для расчётов), сбор комиссии в одну сторону (`CollectFeeOn`) и отслеживающая волатильность динамическая комиссия. Добавляет `CreateCustomizablePool`, переструктурирование `PoolState` (**критическое изменение для индексаторов**), новые поля `TickState`, одиннадцать новых кодов ошибок (с числовым сдвигом) и соответствующие добавления в SDK / API.

  [Читать полную запись →](/ru/reference/changelog/2026-05-18-clmm-limit-orders)
</Update>

<Update label="2026-04-26" description="Первоначальная публикация">

## Соглашения документации

- **Версионирование**: эта документация использует календарное версионирование (YYYY-MM-DD). Каждое обновление добавляет новую страницу записи и новую строку в начало временной шкалы выше.
- **Одна страница на релиз**: каждое резюме релиза находится на отдельной странице в `reference/changelog/`, поэтому этот индекс остаётся кратким и каждая запись независимо ссылаема.
- **Дата проверки**: каждая запись фиксирует, когда содержание было последний раз перепроверено на соответствие состоянию блокчейна / API и исходному коду программы. Если не указано, предполагайте основную дату записи.
- **Критические изменения**: выделены в боксе предупреждения на затронутых страницах и отмечены в записи.
- **Охват**: этот журнал изменений охватывает сам набор документации. Собственная историческая временная шкала протокола находится в [`introduction/history-and-milestones`](/ru/introduction/history-and-milestones) и является источником истины для «когда произошло X на Raydium».
