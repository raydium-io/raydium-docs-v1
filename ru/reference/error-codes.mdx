## Как работают коды ошибок Anchor

Anchor присваивает каждому варианту enum `ErrorCode` программы числовой код, начиная с `6000`. Неудачная транзакция выводит:

- **Числовой код ошибки** (например `0x1771` = 6001) в логах транзакции.
- **Имя ошибки** (например `InvalidOwner`) из IDL.
- **Строку `#[msg(...)]`**, которую Anchor вывел в `log_messages`.

Интеграторы должны сопоставлять по **числовому коду**, а не по строке сообщения (строка может быть переформулирована без изменения версии).

```ts
// Пример: обнаружить ошибку slippage в CPMM и вывести чистое сообщение UX.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Цена вышла за пределы вашей толерантности к slippage. Увеличьте slippage или повторите попытку.");
    return;
  }
  throw err;
}
```

> **Примечание о переномеровании.** Enum `ErrorCode` CLMM был переномерован в этом выпуске: пять устаревших вариантов (`LOK`, `ZeroMintAmount`, `InvalidLiquidity`, `TransactionTooOld`, `InvalidRewardDesiredAmount`) и несколько опечаток (`Liquitity`, `enought`, `emissiones`) были удалены/исправлены, и одиннадцать новых вариантов были добавлены (`6040`–`6050`) выпуском лимитных ордеров; `6051` (`InvalidTickArrayBitmapExtensionAccount`) пришёл из отдельного, более позднего изменения. Это дало 52 варианта, `6000`–`6051`, что является количеством, которое сообщает IDL развёрнутой программы. [Обновление 2026-09-30](/ru/reference/changelog/2026-09-30-clmm-anchor-1-and-excess-lamports) добавляет `6052` без сдвига чего-либо, всего 53. Поскольку Anchor нумерует ошибки по порядку источника, каждый код на или после `6000` сместился относительно более ранних сборок. Клиентам, которые жёстко кодировали числовые коды для более ранней версии, необходимо переделать отображение.

[`products/amm-v4/instructions`](/ru/products/amm-v4/instructions), [`products/farm-staking/instructions`](/ru/products/farm-staking/instructions), [`products/launchlab/instructions`](/ru/products/launchlab/instructions)). Поскольку эти программы используют смешанный набор поверхностей ошибок Anchor и обычного Solana, их таблицы ошибок находятся рядом со справочником инструкций, а не здесь. Коды, приведённые ниже, зарезервированы этими разделами:

| Программа | Диапазон кодов (только Anchor) | Справочник |
|---------|--------------------------|-----------|
| AMM v4 | Пользовательские коды u32 с `0`, не в стиле Anchor | [ниже](#amm-v4-ammerror-is-not-anchor-numbered) и [`products/amm-v4/instructions`](/ru/products/amm-v4/instructions) |
| Farm v3 / v5 | Пользовательские коды u32 | [`products/farm-staking/instructions`](/ru/products/farm-staking/instructions) |
| Farm v6 | 6000+ (Anchor) | [`products/farm-staking/instructions`](/ru/products/farm-staking/instructions) |
| LaunchLab | 6000+ (Anchor) | [`products/launchlab/instructions`](/ru/products/launchlab/instructions) |

Последние релизы LaunchLab сохраняют коды `6000`–`6021` без изменений. Релиз от 2026-08-17 удалил прежние ошибки глобального доступа платформы и назначил `6022` ошибке валидации allow-account; релиз от 2026-08-24 добавляет `6023`; релиз от 2026-08-31 добавляет `6024`–`6030`; релиз от 2026-09-09 добавляет `6031`:

| Код | Имя | Значение |
|---|---|---|
| 6018 | `NotEnoughRemainingAccounts` | Отсутствует требуемый оставшийся аккаунт. Это включает требуемый `PlatformAllowConfig`, требуемый `PlatformCurveRule` и расширенный набор аккаунтов миграции CPMM. |
| 6020 | `CurveParamIsNotExist` | Устарело. Сохранено как заполнитель, чтобы коды после него не сдвигались; релиз от 2026-08-31 удалил его последний вызов. |
| 6022 | `InvalidPlatformAllowConfig` | Предоставленный allow-аккаунт не кодирует ожидаемую пару конфигурации платформы и глобальной конфигурации. |
| 6023 | `CalculateOverflow` | Расчёт комиссии за передачу Token-2022 или обратной комиссии за передачу не может быть представлен. Достижимо на путях точного выхода при невозможности инвертировать комиссию mint котировки (например, mint со 100%-комиссией). |
| 6024 | `InvalidPlatformCurveRule` | Предоставленный аккаунт правила не является PDA пары платформы и конфигурации, под которой запускается. |
| 6025 | `CurveParamNotMatchPlatformRule` | Параметры запуска не удовлетворяют ни одной группе проверок правила платформы. Единственная ошибка, которую может получить создатель — представьте её как «эта форма запуска не разрешена на этой платформе». |
| 6026 | `CurveRuleGroupNotExist` | `RemovePlatformCurveRule` был вызван с `group_id`, который правило не содержит. |
| 6027 | `CurveRuleGroupsExceeded` | Правило не может содержать более 10 групп проверок. |
| 6028 | `InvalidCurveRuleConstraint` | Ограничение имеет неизвестное поле или оператор, группа имеет более 25 ограничений, или одна и та же пара `(field, op)` появляется дважды в одной группе. |
| 6029 | `InvalidCurveRuleAuthority` | Подписант — ни `PlatformConfig.curve_rule_manager`, ни администратор платформы. |
| 6030 | `CurveRuleFieldNotSupportedByCurve` | Ограничение читает одно из четырёх полей, специфичных для постоянного произведения — `TotalSellA` (`4`), `SellRateA` (`13`), `MigrateAmountA` (`15`), `MigrateRateA` (`16`) — на конфигурации, чья кривая выводит `total_base_sell` вместо того, чтобы брать его у создателя (кривые фиксированной цены и линейной цены). Возникает при записи правила, а не при запуске запуска. |
| 6031 | `LamportsCalculateError` | `CollectExcessLamports` очистил хранилище wrapped-SOL и цикл `SyncNative` → `UnwrapLamports` не оставил баланс wrapped-токена ровно там, где он был. Путь только для администратора. |

Старые варианты `PlatformGlobalAccessDenied` (`6022`) и `InvalidPlatformGlobalAccess` (`6023`) удалены. Не декодируйте `6022` с использованием предыдущего IDL, и учтите, что `6023` — освобождённый релизом от 2026-08-17 — переиспользуется релизом от 2026-08-24 для несвязанной ошибки, поэтому его нельзя декодировать с IDL из более ранней версии.

`6020` сохранён намеренно. Anchor нумерует варианты по позиции, поэтому удаление его сдвинуло бы каждый код после него и сломало бы каждый клиент, декодирующий `6021`–`6031`.

### AMM v4: `AmmError` не нумеруется в стиле Anchor

AMM v4 предшествует Anchor. `AmmError` — это обычный enum `thiserror` с `FromPrimitive`, преобразуемый через `ProgramError::Custom(e as u32)`, поэтому его коды начинаются с **`0`**, а не `6000` — и, как в Anchor, назначаются по порядку источника. Обновление 2026-09 добавляет один вариант:

| Код | Вариант | Строка `#[error]` | Причина |
|---|---|---|---|
| 60 | `LamportsCalculateError` | Lamports calculate error. | `WithdrawExcessLamports` очистил wrapped-SOL аккаунт и цикл `SyncNative` → `UnwrapLamports` не оставил баланс wrapped-токена ровно там, где он был. Путь только для администратора. |

Коды `0`–`59` не изменены, поэтому ничего не сдвигается. В логах транзакций это отображается как `custom program error: 0x3c`. Источник регенерации: [github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs).

## Сопоставление ошибок SDK с ошибками программы

Официальный TypeScript SDK оборачивает ошибки on-chain в `SendTransactionError` и, для программ Anchor, `AnchorError`:

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

Если вы не используете Anchor на клиентской стороне, разберите логи транзакции:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Паттерн `Error Number: (\d+)` стабилен во всех версиях Anchor и безопасен для сопоставления.

## Регенерация этих таблиц

Когда программа обновляется и добавляет новую ошибку, переизвлеките из источника:

```bash
# Clone and grep the error enum in order.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Replace 6000+++ with monotonically-increasing 6000,6001,... Append new rows to the table above.
```

Всегда обновляйте [`reference/changelog`](/ru/reference/changelog) при добавлении нового варианта, чтобы интеграторы, обновляющие SDK, знали о необходимости обновить обработчики ошибок.

- [raydium-clmm error.rs (mainnet CLMM)](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/error.rs)
