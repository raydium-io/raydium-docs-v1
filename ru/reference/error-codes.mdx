## Как работают коды ошибок Anchor

Anchor присваивает каждому варианту перечисления `ErrorCode` программы числовой код, начиная с `6000`. Неудачная транзакция выводит:

- **Числовой код ошибки** (например `0x1771` = 6001) в логах транзакции.
- **Имя ошибки** (например `InvalidOwner`) из IDL.
- **Строку `#[msg(...)]`**, которую выпустил Anchor в `log_messages`.

Интеграторы должны сопоставлять по **числовому коду**, а не по строке сообщения (строка может быть переформулирована без изменения версии).

```ts
// Пример: обнаружить ошибку проскальзывания CPMM и вывести чистое сообщение пользователю.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

| 6030 | `CurveRuleFieldNotSupportedByCurve` | Ограничение читает `total_base_sell` на конфигурации, чья кривая его получает — кривые с фиксированной ценой и линейной ценой. Возникает при написании правила, а не при запуске запуска. |
| 6031 | `LamportsCalculateError` | `CollectExcessLamports` очистил хранилище обёрнутого SOL, и цикл `SyncNative` → `UnwrapLamports` не оставил баланс обёрнутого токена ровно там, где он был. Путь только для администратора. |

Старые варианты `PlatformGlobalAccessDenied` (`6022`) и `InvalidPlatformGlobalAccess` (`6023`) удалены. Не декодируйте `6022` с использованием предыдущего IDL, и обратите внимание, что `6023` — освобождённый выпуском 2026-08-17 — переиспользуется выпуском 2026-08-24 для несвязанной ошибки, поэтому его не следует декодировать с IDL из любой более ранней версии.

`6020` сохранён намеренно. Anchor нумерует варианты по позиции, поэтому удаление его сместит каждый код после него и нарушит каждого клиента, который декодирует `6021`–`6031`.

### AMM v4: `AmmError` не нумеруется в стиле Anchor

AMM v4 предшествует Anchor. `AmmError` — это простое перечисление `thiserror` с `FromPrimitive`, преобразованное через `ProgramError::Custom(e as u32)`, поэтому его коды начинаются с **`0`**, а не `6000` — и, как у Anchor, назначаются по порядку в исходном коде. Обновление 2026-09 добавляет один вариант:

| Код | Вариант | Строка `#[error]` | Причина |
|---|---|---|---|
| 60 | `LamportsCalculateError` | Lamports calculate error. | `WithdrawExcessLamports` очистил счёт обёрнутого SOL, и цикл `SyncNative` → `UnwrapLamports` не оставил баланс обёрнутого токена ровно там, где он был. Путь только для администратора. |

Коды `0`–`59` не изменены, поэтому ничего не сместилось. В логах транзакции это выводится как `custom program error: 0x3c`. Источник регенерации: [github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs).

## Сопоставление ошибок SDK с ошибками программы

Официальный TypeScript SDK оборачивает ошибки в блокчейне в `SendTransactionError` и, для программ Anchor, `AnchorError`:

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

Если вы не используете Anchor на стороне клиента, разберите логи транзакции:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Паттерн `Error Number: (\d+)` стабилен во всех версиях Anchor и безопасен для сопоставления.

## Регенерация этих таблиц

Когда программа обновляется и добавляется новая ошибка, повторно извлеките из исходного кода:

```bash
# Клонируйте и grep перечисление ошибок по порядку.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Замените 6000+++ на монотонно возрастающие 6000,6001,... Добавьте новые строки в таблицу выше.
```

Всегда обновляйте [`reference/changelog`](/ru/reference/changelog) при добавлении нового варианта, чтобы интеграторы, обновляющие SDK, знали, что нужно обновить обработчики ошибок.
