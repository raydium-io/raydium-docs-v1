## Как работают коды ошибок Anchor

Anchor присваивает каждому варианту перечисления `ErrorCode` программы числовой код, начиная с `6000`. При ошибке транзакции выводятся:

- **Числовой код ошибки** (например `0x1771` = 6001) в логах транзакции.
- **Имя ошибки** (например `InvalidOwner`) из IDL.
- **Строка `#[msg(...)]`**, которую выдал Anchor в `log_messages`.

Интеграторы должны сравнивать по **числовому коду**, а не по строке сообщения (строка может быть переформулирована без изменения версии).

```ts
// Пример: обнаружить ошибку проскальзывания CPMM и показать понятное сообщение.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Цена изменилась больше допустимого проскальзывания. Увеличьте проскальзывание или повторите попытку.");
    return;
  }
  throw err;
}
```

Последние выпуски LaunchLab сохраняют коды `6000`–`6021` без изменений. Выпуск 2026-08-17 удалил прежние ошибки глобального доступа платформы и назначил `6022` ошибке валидации счёта разрешений; выпуск 2026-08-24 добавляет `6023`:

| Код | Имя | Значение |
|---|---|---|
| 6018 | `NotEnoughRemainingAccounts` | Отсутствует требуемый оставшийся счёт. Это включает требуемый `PlatformAllowConfig` и расширенный набор счётов миграции CPMM. |
| 6022 | `InvalidPlatformAllowConfig` | Предоставленный счёт разрешений не кодирует ожидаемую пару платформы и глобальной конфигурации. |
| 6023 | `CalculateOverflow` | Вычисление комиссии передачи Token-2022 или обратной комиссии передачи не может быть представлено. Достижимо на путях торговли с точным выходом, когда комиссия mint котировки не может быть инвертирована (например mint со 100%-комиссией). |

Старые варианты `PlatformGlobalAccessDenied` (`6022`) и `InvalidPlatformGlobalAccess` (`6023`) удалены. Не декодируйте `6022` с использованием предыдущего IDL, и обратите внимание, что `6023` — освобождённый выпуском 2026-08-17 — переиспользуется выпуском 2026-08-24 для несвязанной ошибки, поэтому его нельзя декодировать с IDL из любой более ранней версии.

## Сопоставление ошибок SDK с ошибками программы

Официальный TypeScript SDK оборачивает ошибки в блокчейне в `SendTransactionError` и для программ Anchor в `AnchorError`:

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — проверьте err.logs для строки "custom program error: 0x...".
  }
}
```

Если вы не используете Anchor на клиентской стороне, разберите логи транзакции:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Паттерн `Error Number: (\d+)` стабилен во всех версиях Anchor и безопасен для сопоставления.

## Регенерация этих таблиц

Когда программа обновляется и добавляется новая ошибка, повторно извлеките из исходного кода:

```bash
# Клонируйте и grep перечисление ошибок по порядку.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Замените 6000+++ на монотонно возрастающие 6000,6001,... Добавьте новые строки в таблицу выше.
```

Всегда обновляйте [`reference/changelog`](/ru/reference/changelog) при добавлении нового варианта, чтобы интеграторы, обновляющие SDK, знали о необходимости обновить обработчики ошибок.
