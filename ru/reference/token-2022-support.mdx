Raydium **не** принимает произвольные монеты Token-2022. CPMM и CLMM работают в строгом режиме **allow-list**: по умолчанию проходит только небольшой набор расширений; всё остальное отклоняется при создании пула. Несколько доверенных монет допускаются по жёстко закодированному адресу; CLMM дополнительно поддерживает управляемый администратором реестр для каждой монеты и обнаружение токенов Superstate во время выполнения. Эта страница — единственный справочник по тому, что применяется и где, с ссылками на файлы и строки исходного кода программы.

## Поддержка на уровне программы

| Программа | Монеты base/quote Token-2022? | Режим |
|---|---|---|
| **CPMM** | Да — с ограничениями | Строгий allow-list расширений + статический whitelist из 4 монет. |
| **CLMM** | Да — с ограничениями | Строгий allow-list расширений + статический whitelist из 6 монет + управляемый администратором реестр для каждой монеты + обнаружение Superstate. |
| **AMM v4** | Нет | Программа предшествует Token-2022; обе монеты должны быть классическим SPL Token. |
| **Stable AMM** | Нет | Те же ограничения, что и AMM v4. |
| **Farm v6** | Да, частично | Монета награды может быть Token-2022 (подчиняется тому же allow-list, когда ферма оборачивает LP CPMM/CLMM); монеты LP для ставок пользователя наследуются из обёрнутого пула. |
| **LaunchLab** | Да — base управляется программой, quote без ограничений | Монета base может быть Token-2022, но только через выделенную инструкцию `initialize_with_token_2022`; программа сама создаёт монету с `MetadataPointer` (всегда) и опционально `TransferFeeConfig` (ставка ≤ 5%). Предсуществующие монеты Token-2022 с произвольными расширениями не могут использоваться как base. Монета **quote** может быть любой монетой Token-2022, которую администратор привяжет к `GlobalConfig`, без проверки расширений — см. [ниже](#launchlab-quote-mints). |
| **Burn & Earn** | Зеркалирует программу пула | Наследует ограничения CPMM / CLMM. |

Проверки allow-list находятся в:

- **CPMM**: `is_supported_mint` в [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap), вызывается из `Initialize`.
- **CLMM**: `is_supported_mint` в [`raydium-clmm/programs/amm/src/util/token.rs:280`](https://github.com/raydium-io/raydium-clmm), вызывается из `CreatePool`.
- **LaunchLab**: `initialize_with_token_2022` в `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs` (исходный код не является общедоступным).

**Нет** проверки монеты во время swap на CPMM или CLMM — ограничение срабатывает только при создании пула. После создания пула swap просто доверяет, что монеты не изменились, что верно для неизменяемых частей состояния монеты Token-2022.

## Замораживание позиционных NFT в CLMM для ограниченных издателей

Счета позиционных NFT остаются разморожены по умолчанию. CLMM замораживает позицию только когда позиция использует V2 open path **и** текущий `freeze_authority` хотя бы одной монеты хранилища совпадает с жёстко закодированным списком ограниченных издателей. Начальный список содержит тот же authority, используемый путём обнаружения Superstate ниже. Установка PDA пула как freeze authority монеты позиционного NFT сама по себе не является замораживанием. Это правило хранения позиции, а не ещё один allow-list при создании пула:

- Пул может уже существовать и оставаться пригодным для swap.
- Монета позиционного NFT использует PDA пула CLMM как свой собственный freeze authority; базовый издатель не контролирует позиционный NFT.
- `OpenPositionV2` охватывает классические позиционные NFT SPL над активами пула Token-2022. `OpenPositionWithToken22Nft` охватывает позиционные NFT Token-2022.
- `OpenPosition` V1 не проверяет монеты хранилища и не может служить целевым активам Token-2022 из поставляемого списка.
- Существующие позиции не изменяются.

Замороженные позиции остаются управляемыми их владельцем, но не могут быть переданы. `ClosePosition` размораживает и сжигает атомарно, когда клиент передаёт пул как первый оставшийся счёт. См. [`products/clmm/ticks-and-positions`](/ru/products/clmm/ticks-and-positions#restricted-issuer-positions).

## Монеты quote в LaunchLab

Две монеты LaunchLab имеют очень разные ограничения, и асимметрия легко упустить.

- **Монета base** — LaunchLab её создаёт. Монета base Token-2022 доступна только через `initialize_with_token_2022`, и программа будет присоединять только `MetadataPointer` и (опционально) `TransferFeeConfig`. Всё остальное возвращает `NoSupportExtension`. Предсуществующая монета Token-2022 вообще не может быть предоставлена как base. Когда `TransferFeeConfig` присоединён, `transfer_fee_config_authority` монеты — это PDA authority запуска до выпуска, а `withdraw_withheld_authority` — это настроенный платформой `transfer_fee_extension_auth` с момента создания монеты — сама программа launchpad не имеет инструкции для вывода удержанных средств. См. [`products/launchlab/platform-config`](/ru/products/launchlab/platform-config#token-2022-transfer-fee-authorities).
- **Монета quote** — LaunchLab её не создаёт и не проверяет. `CreateConfig` принимает счёт монеты как есть, поэтому **нет эквивалента `is_supported_mint` на стороне quote**. Единственное ограничение — какие монеты администратор выбирает привязать к `GlobalConfig`.

Это делает привязку монеты quote Token-2022 действием высокого доверия, с той же логикой, что и статические whitelist CPMM и CLMM ниже: монета quote с `TransferHook` запустит свой hook при каждой покупке, продаже и требовании комиссии в каждом пуле, котируемом в ней, а монета quote с `PermanentDelegate` позволит делегату очистить хранилища quote этих пулов. Ни то, ни другое не блокируется программой.

Что LaunchLab правильно обрабатывает после привязки монеты quote:

- Хранилище quote, оба хранилища комиссий и счёт получателя комиссии за акции создаются в собственной программе монеты quote.
- `TransferFeeConfig` на стороне quote учитывается во всех четырёх инструкциях торговли, и граница slippage проверяется против чистой суммы плательщика, а не против валового движения хранилища. См. [`products/launchlab/instructions`](/ru/products/launchlab/instructions#quote-side-transfer-fees).
- `PoolState.token_program_flag` записывает программы обеих монет — бит0 для монеты base, бит1 для монеты quote. Декодируйте по битам; байт не является логическим значением. См. [`products/launchlab/accounts`](/ru/products/launchlab/accounts#poolstate).

Устаревшая инструкция `Initialize` по-прежнему принимает программу quote только для legacy, поэтому конфиг с монетой quote Token-2022 доступен только через `InitializeV2` и `InitializeWithToken2022`.

## Allow-list расширений CPMM и CLMM

После того как статический whitelist срабатывает (рассмотрено ниже), программа перебирает расширения монеты и отклоняет монету, если она содержит **любое** расширение, отличное от этих пяти:

| Расширение | Причина, по которой оно разрешено |
|---|---|
| `TransferFeeConfig` | Математика пула вычитает входящую комиссию; программа Token-2022 обрабатывает исходящую комиссию. См. [`algorithms/token-2022-transfer-fees`](/ru/algorithms/token-2022-transfer-fees). |
| `MetadataPointer` | Декоративное — указывает на on-chain метаданные. |
| `TokenMetadata` | Декоративное — встроенные метаданные. |
| `InterestBearingConfig` | Пул видит основную сумму; множитель UI — только декоратор, и базовый баланс сохраняется. |
| `ScaledUiAmount` | Та же форма, что и interest-bearing — коэффициент масштабирования применяется только к отображению UI. |

Всё остальное — `TransferHook`, `NonTransferable`, `ConfidentialTransferMint`, `PermanentDelegate`, `MintCloseAuthority`, `DefaultAccountState`, `GroupPointer`, `GroupMemberPointer`, `MemberPointer`, `Pausable` и т. д. — заставляет `is_supported_mint` вернуть `false` и откатывает создание пула.

Соответствующие строки (CPMM, идентичная форма в CLMM):

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## Пути обхода

Монета Token-2022, которая не соответствует allow-list, всё ещё может быть допущена через один из трёх явных путей обхода. Они пробуются по порядку, прежде чем запускается итерация расширений.

### 1. Статический whitelist монет

Константный массив `MINT_WHITELIST` строк base58 жёстко закодирован в каждой программе. Если адрес монеты совпадает, функция немедленно возвращает `true` и проверка расширения не выполняется.

| Программа | Монеты в whitelist |
|---|---|
| CPMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`, `Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`, `FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`, `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM | Те же четыре, плюс `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`, `AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

Эти адреса встроены в программу; обновление списка требует обновления программы через multisig 3/4.

### 2. Реестр для каждой монеты — только CLMM

CLMM дополнительно консультирует PDA `SupportMintAssociated` с seed `[b"support_mint", mint]`. Если этот PDA существует для монеты, она допускается независимо от её набора расширений.

PDA создаётся `CreateSupportMintAssociated` ([`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)). Инструкция ограничена двумя подписантами:

- `crate::admin::ID` — стандартный authority администратора Raydium.
- `crate::create_support_mint_associated_owner::ID` — выделенный authority для этой цели: `RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY` (mainnet), `rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5` (devnet).

Эффект: команда CLMM может включить конкретную монету Token-2022 в создание пула без обновления программы. CPMM не имеет эквивалента — его allow-list строго закодирован в исходном коде.

### 3. Обнаружение Superstate — только CLMM

CLMM имеет третий путь специально для токенизированных активов Superstate, которые используют расширение `ScaledUiConfig`, которое версия `spl-token-2022`, связанная с программой CLMM, не может распаковать. Вместо обновления зависимости CLMM обнаруживает токены Superstate по форме их authority:

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

Монета проходит эту ветвь, если **все четыре** условия выполнены:

- Её владеющая программа — это программа Token-2022.
- Её freeze authority равна `superstate_allowlist::ID`. См. [`reference/program-addresses`](/ru/reference/program-addresses#clmm-restricted-issuer-freeze-authorities) для значений mainnet-beta и devnet.
- Её расширение `DefaultAccountState` установлено на `Frozen`.
- Её permanent delegate также равен `superstate_allowlist::ID`.

Это эвристика, а не реестр — любая будущая монета, которую выпустит Superstate с той же формой authority, будет автоматически допущена.

## Что пути обхода не отменяют

Пути обхода пропускают allow-list расширений, но программа по-прежнему применяет:

- Монета принадлежит либо `Token`, либо `Token-2022`. Пользовательская программа токена отклоняется выше по потоку.
- Хранилища пула создаются с правильными расширениями ATA для пулов Token-2022 (`ImmutableOwner` и т. д.).
- Все передачи проходят через `transfer_checked` — монеты с комиссией попадают в хранилище в правильном количестве.

Монета в whitelist или зарегистрированная в PDA, которая, например, позже добавляет `TransferHook`, не получает проверку во время swap; hook просто запустится при каждой передаче и может заблокировать swap. Поэтому внесение в whitelist — это действие высокого доверия.

## Семантика "заблокировано"

Когда `is_supported_mint` возвращает `false`, создание пула откатывается с `ErrorCode::NotSupportMint` (CPMM) / `ErrorCode::NotSupportMint` (CLMM). См. [`reference/error-codes`](/ru/reference/error-codes) для числовых кодов.

Существующие пулы не могут ретроспективно не пройти эту проверку — ограничение срабатывает только при создании. Расширения монеты неизменяемы для категорий, которые Raydium отклоняет (transfer hook, non-transferable, confidential transfer не могут быть добавлены после создания), поэтому статической проверки достаточно.

## Почему каждое исключённое расширение исключено

- **TransferHook** — вызывает пользовательскую программу при каждой передаче с произвольным потреблением CU, произвольными условиями отказа и способностью повторно входить в вызывающую программу. Безопасной песочницы не существует. Некоторые DEX поддерживают allow-list hook; Raydium — нет.
- **NonTransferable** — `Transfer` всегда не удаётся. Пул не может взять под опеку.
- **ConfidentialTransfer** — суммы передачи зашифрованы; кривая не может оценить swap.
- **PermanentDelegate** — держатель делегата может очистить любой счёт токена, включая хранилище пула. Разрешено только через статический whitelist для доверенных издателей (например, регулируемые stablecoin).
- **MintCloseAuthority** — монета может быть закрыта; существующие пулы становятся непригодными. Запрещено по умолчанию.
- **DefaultAccountState (Frozen)** — ATA пула попадут в состояние `Frozen` и потребуют размораживания для каждого счёта. Разрешено только через обнаружение Superstate, которое предполагает, что издатель размораживает институциональные счета при регистрации.
- **Group/Member pointers** — не активно вредны, но не проверены. Запрещены по умолчанию, чтобы сохранить поверхность узкой.

## Учёт комиссий за передачу

Для монет с `TransferFeeConfig` каждый swap, депозит и вывод перемещают меньше номинальной суммы. SDK выводит обе половины расчёта:

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

Правильный UI показывает:

- `amountIn + token2022FeeIn` как "вы отправляете"
- `amountOut - token2022FeeOut` как "вы получаете"
- `feeAmount` как комиссию пула (LP + протокол), которая отделена от комиссии за передачу Token-2022

Наивный UI, который показывает только `amountIn → amountOut`, занижает затраты.

### Ограничение `maximumFee`

Комиссии за передачу Token-2022 ограничены за передачу. Для монеты с 1% и ограничением в 10 000 токенов передача 100 000 000 токенов платит только 10 000 в комиссии. `computeSwapAmount` SDK применяет ограничение; прямые вызывающие программу должны его воспроизвести.

### Переход эпохи

Authority монеты может запланировать изменение ставки комиссии, которое активируется в следующую эпоху. Во время окна переходов два конфига (`older`, `newer`) живут на монете одновременно и `TransferChecked` выбирает по текущей эпохе. CPMM `SwapV2` и CLMM `SwapV2` оба передают полный счёт монеты в `accounts`, поэтому программа читает правильный конфиг без дополнительного поиска.

Если вы котируете более чем на одну эпоху вперёд через Trade API или SDK, выполненная комиссия может отличаться от котируемой комиссии — ограничена `maximum_fee_basis_points` старого конфига.

## Interest-bearing и ScaledUiAmount

Пул держит основную сумму; "UI сумма" — это основная сумма, умноженная на зависящий от времени или установленный администратором коэффициент масштабирования. Математика swap работает с основной суммой:

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK конвертирует автоматически. Прямые читатели RPC должны рассматривать `pool.token0Vault.amount` как основную сумму.

## Определение "пула Token-2022"

Пул является пулом Token-2022, если **любая** монета имеет `programId == TokenzQdB...`. API выводит это:

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

Используйте `programId` для диспетчеризации и `hasTransferFee` для вывода предупреждения UI.

## Помощники SDK

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## Распространённые ошибки интеграции

- **Предварительная проверка только ID программы.** Монета может быть Token-2022 *и* неподдерживаемой. Пройдитесь по списку расширений против allow-list (и статического whitelist) перед разрешением создания пула.
- **Доверие к котировке SDK, когда монета вообще не принята.** API котировки не отказывает в котировке — создание пула — это то, что откатывается. Подтвердите семантику `is_supported_mint` off-chain перед тем, как выставить создание пула в вашем UI.
- **Котировка без вычета комиссии за передачу.** Монета с комиссией 1% с обеих сторон пула CPMM с комиссией 0,25% имеет эффективную комиссию около 2,25%, а не 0,25%. Используйте котировку SDK или котировку Trade API — никогда не вычисляйте комиссию вручную только из уровня комиссии пула.
- **Вызов устаревшей инструкции `Swap` на пуле Token-2022.** `Swap` предшествует Token-2022. Используйте `SwapV2` всякий раз, когда любая монета — Token-2022.
- **Автоматический листинг новых монет Token-2022.** Кошельки и агрегаторы должны проверять `TransferHook` и `NonTransferable` перед выставлением монеты пользователям; обе враждебны Raydium.

## Будущая работа

Элементы дорожной карты экосистемы Solana и протокола, которые изменили бы эту матрицу:
