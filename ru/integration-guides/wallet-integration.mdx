## Обнаружение позиций Raydium

### Классические LP-токены (CPMM, AMM v4)

Они выглядят как любой другой SPL Token: баланс пользователя хранится в его ATA. Кошелек по умолчанию показывает это как обычный токен. Чтобы раскрыть это как позицию Raydium:

1. Перечислите токен-аккаунты пользователя: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Для каждого минта проверьте список минтов Raydium: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (группируйте до ~50 LP-минтов за вызов).
3. Для совпадающих минтов API возвращает ссылку на пул. Используйте её для вычисления стоимости позиции в токенах:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Показывайте как баланс LP, так и развёрнутые суммы — пользователи думают в терминах базовых токенов, а не LP-единиц.

### CLMM позиции-NFT

CLMM позиции — это NFT. PDA `PersonalPositionState` каждой позиции производна от минта NFT. Для обнаружения:

1. Перечислите NFT пользователя. Для устаревших Metaplex NFT: отфильтруйте токен-аккаунты по тем, у которых supply 1 и decimals 0.
2. Для каждого NFT-минта попытайтесь вывести PDA PersonalPositionState:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Это позиция Raydium CLMM — декодируйте.
```

3. Перечислите позиции кошелька с помощью `raydium.clmm.getOwnerPositionInfo({ programId })` и сопоставьте по `nftMint` (метода `getPositionInfo` нет). Каждая запись даёт вам:
   - `poolId` → получите пул для разрешения минтов
   - `tickLower`, `tickUpper` → отобразите диапазон
   - `liquidity`, `tokensOwedA/B` → вычислите стоимость позиции + ожидающие комиссии
   - `rewardInfos` → ожидающие вознаграждения за поток

4. Для позиций-NFT, выпущенных под Token-2022 (`OpenPositionWithToken22Nft`), программа минта NFT — это Token-2022, а не SPL Token. Перечисляйте обе при сканировании.

### Ставки в фермах

Farm v3 / v5 / v6 каждая имеет PDA реестра для каждого пользователя. Выводы:

```ts
// Попробуйте все три версии фермы для каждого из возможных взаимодействий пользователя с фермой.
// Самый дешёвый подход: сначала спросите API, который индексировал все позиции пользователя.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Для кошельков, предпочитающих полностью on-chain обнаружение: перебирайте возможные PDA `UserLedger`, хешируя пользователя с курируемым списком «вероятных» ID ферм. Перечисление всех ID ферм исчерпывающе непрактично (существуют тысячи); используйте API.

## Вычисление стоимости позиции

### CPMM / AMM v4 LP

Три модуля **не** имеют одинаковой сигнатуры: `liquidity.getPoolInfoFromRpc` принимает `{ poolId }`, а `cpmm.getPoolInfoFromRpc` и `clmm.getPoolInfoFromRpc` принимают позиционную строку base58.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` — это ApiV3Token и не имеет поля `supply`. Прочитайте
// supply LP-минта из цепи или используйте зеркало самого пула:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Затем умножьте каждый на USD-цену минта (из `raydium.token` или ценового оракула).

### CLMM позиция

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // строка base58
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity асинхронна, принимает epochInfo + poolInfo + add,
// и возвращает суммы с обёрнутыми комиссиями.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // для отображения, без slippage
  add:        false,
});
// amountA.amount / amountB.amount — это BN; .fee — это комиссия передачи Token-2022.

// Ожидающие комиссии — отобразите отдельно как «невзятые»
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Ожидающие вознаграждения — пул CLMM имеет 0–3 потока вознаграждений. Записи
// rewardInfos позиции содержат только { growthInsideLastX64, rewardAmountOwed }, поэтому
// минт должен поступить из rewardInfos ПУЛА с тем же индексом.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Отобразите как:

- Стоимость ликвидности (текущая цена)
- Невзятые комиссии
- Ожидающие вознаграждения за каждый поток
- Диапазон: `[tickLower_price, tickUpper_price]` с визуальной полосой, показывающей, находится ли текущая цена в диапазоне

### Ставка в ферме

```ts
// Ответ API уже включает ожидающие вознаграждения; используйте его напрямую.
const apr       = stakingFarm.apr;               // %, годовой
const staked    = stakingFarm.stakedAmount;      // наименьшие единицы минта ставки
const rewards   = stakingFarm.pendingRewards;    // массив { mint, amount }
```

Для on-chain вычисления отразите учёт фермы:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Убедитесь, что вы обновили `reward_per_share_x64` с помощью формулы ленивого обновления перед вычислением (прошедшее время × скорость эмиссии ÷ total_staked).

## Симуляция транзакции для предпросмотра

Перед подписанием пользователем кошельки обычно показывают предпросмотр изменений баланса. Используйте `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Декодируйте баланс каждого возвращённого аккаунта и сравните с балансами до транзакции.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // сравните с балансом до транзакции, покажите Δ
}
```

Параметр `accounts` просит валидатор вернуть состояние аккаунта после симуляции для указанных адресов. Намного точнее, чем попытка предсказать изменение баланса только по форме инструкции.

### Подводные камни симуляции

- **CLMM свопы требуют валидные tick-массивы.** Если размер ввода пользователя пересекает неинициализированный tick-массив, симуляция откатывается (как и выполнение). Ясно отобразите это в интерфейсе.
- **Приоритетная комиссия.** Симуляция выполняется без применённых инструкций compute-budget. Для большой транзакции, которая превысит стандартные 200k CU, симуляция не удаётся, но фактическое выполнение с явным лимитом CU успешно. Всегда устанавливайте лимит CU и на симулируемую транзакцию.
- **Свежий блокхеш.** Симуляция использует текущий блокхеш; если подписание занимает >60s, транзакция становится недействительной. Пересимулируйте, если пользователь колеблется.

## Отображение Token-2022

Токены под программой Token-2022 должны быть помечены как таковые в списке токенов кошелька, так как они имеют разные поверхности риска:

- **Минты с комиссией передачи**: отобразите текущий `transferFeeBasisPoints` как «Комиссия передачи: X%» рядом с балансом. Предупредите при получении — пользователи могут не понять, что получат меньше, чем отправитель отправил.
- **Минты с хуком передачи**: отобразите ID программы хука. Вредоносный хук может заблокировать исходящие передачи; пользователи должны проверить, что хук — это тот, который они ожидают.
- **Непередаваемые минты**: отобразите «Непередаваемо» и отключите swap/send. Это обычно soulbound-токены или учётные данные.
- **Минты с начислением процентов**: баланс UI, полученный из `TokenAccount.amount`, **не** отражает начисленные проценты. Используйте `amountToUiAmount` из `@solana/spl-token` (который применяет коэффициент масштабирования) для отображаемого значения.

## Отображение APR фермы

APR, отображаемый пользователям, должен объединять все активные потоки вознаграждений, преобразованные в USD и годовые:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // пропустите не запущенные
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

Отобразите как `APR: X.Y%`. Если минт ставки — это LP-токен, также вычислите базовый APR комиссии базового LP и обозначьте сумму как «Total APR» или «APR + fees».
