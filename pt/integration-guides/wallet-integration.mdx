## Detectando posições Raydium

### Tokens LP clássicos (CPMM, AMM v4)

Eles parecem como qualquer outro Token SPL: a ATA do usuário mantém um saldo. Uma carteira mostra isso como apenas outro token por padrão. Para revelá-lo como uma posição Raydium LP:

1. Enumere as contas de token do usuário: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Para cada mint, verifique a lista de mints do Raydium: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (agrupe até ~50 LP mints por chamada).
3. Para mints que correspondem, a API retorna a referência do pool. Use-a para calcular o valor da posição denominado em tokens:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Mostre tanto o saldo de LP quanto os valores desembrulhados — usuários pensam em tokens subjacentes, não em unidades de LP.

### NFTs de posição CLMM

Posições CLMM são NFTs. O `PersonalPositionState` PDA de cada posição é derivado do mint do NFT. Para detectar:

1. Enumere os NFTs do usuário. Para NFTs Metaplex legados: filtre contas de token para aquelas com supply 1 e decimals 0.
2. Para cada mint de NFT, tente derivar o PDA PersonalPositionState:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// É uma posição CLMM Raydium — decodifique.
```

3. Enumere as posições da carteira com `raydium.clmm.getOwnerPositionInfo({ programId })` e faça correspondência em `nftMint` (não há `getPositionInfo`). Cada entrada fornece:
   - `poolId` → busque o pool para resolver mints
   - `tickLower`, `tickUpper` → exiba o intervalo
   - `liquidity`, `tokensOwedA/B` → calcule o valor da posição + taxas pendentes
   - `rewardInfos` → recompensas pendentes por stream

4. Para NFTs de posição emitidos sob Token-2022 (`OpenPositionWithToken22Nft`), o programa do mint do NFT é Token-2022 em vez de SPL Token. Enumere ambos ao fazer a varredura.

### Stakes em farms

Farm v3 / v5 / v6 cada um tem um PDA de ledger por usuário. Derivações:

```ts
// Tente todas as três versões de farm para cada uma das possíveis interações de farm do usuário.
// Abordagem mais barata: pergunte à API primeiro, que indexou todas as posições do usuário.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Para carteiras que preferem detecção totalmente on-chain: itere PDAs `UserLedger` possíveis fazendo hash do usuário com uma lista curada de IDs de farm "prováveis". Enumerar todos os IDs de farm exaustivamente é impraticável (milhares existem); use a API.

## Calculando o valor da posição

### CPMM / AMM v4 LP

Os três módulos **não** compartilham uma assinatura: `liquidity.getPoolInfoFromRpc` recebe `{ poolId }`, enquanto `cpmm.getPoolInfoFromRpc` e `clmm.getPoolInfoFromRpc` recebem uma string base58 posicional.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` é um ApiV3Token e não tem campo `supply`. Leia o
// supply do mint LP da chain, ou use o espelho do próprio pool:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Então multiplique cada um pelo preço USD do mint (de `raydium.token` ou um oráculo de preço).

### Posição CLMM

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // string base58
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity é assíncrono, recebe epochInfo + poolInfo + add,
// e retorna valores envolvidos em taxa.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // para exibição, sem slippage
  add:        false,
});
// amountA.amount / amountB.amount são os BNs; .fee é a taxa de transferência Token-2022.

// Taxas pendentes — exiba separadamente como "não coletadas"
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Recompensas pendentes — um pool CLMM tem 0–3 streams de recompensa. As entradas
// rewardInfos da posição são apenas { growthInsideLastX64, rewardAmountOwed }, então o
// mint tem que vir de rewardInfos do POOL no mesmo índice.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Renderize como:

- Valor de liquidez (preço atual)
- Taxas não coletadas
- Recompensas pendentes por stream
- Intervalo: `[tickLower_price, tickUpper_price]` com uma barra visual mostrando se o preço atual está dentro do intervalo

### Stake em farm

```ts
// A resposta da API já inclui recompensas pendentes; use-a diretamente.
const apr       = stakingFarm.apr;               // %, anualizado
const staked    = stakingFarm.stakedAmount;      // menores unidades do mint de staking
const rewards   = stakingFarm.pendingRewards;    // array de { mint, amount }
```

Para computação on-chain, espelhe a contabilidade do farm:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Certifique-se de atualizar `reward_per_share_x64` com a fórmula de atualização preguiçosa antes de calcular (tempo decorrido × taxa de emissão ÷ total_staked).

## Simulação de transação para visualização

Antes de um usuário assinar, carteiras geralmente visualizam as mudanças de saldo. Use `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Decodifique o saldo de cada conta retornada e compare com os saldos pré-tx.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // compare com o saldo pré-tx, mostre Δ
}
```

O parâmetro `accounts` pede ao validador para retornar o estado da conta pós-simulação para endereços listados. Muito mais preciso do que tentar prever a mudança de saldo apenas pela forma da instrução.

### Armadilhas de simulação

- **Swaps CLMM precisam de arrays de tick válidos.** Se o tamanho de entrada do usuário cruzaria em um array de tick não inicializado, a simulação reverte (igual à execução). Superfície isso claramente na UI.
- **Taxa de prioridade.** A simulação é executada sem as instruções de orçamento de computação aplicadas. Para uma transação grande que excederia o padrão de 200k CU, a simulação falha, mas a execução real com um limite de CU explícito funciona. Sempre defina o limite de CU na tx simulada também.
- **Blockhash fresco.** A simulação usa o blockhash atual; se a assinatura levar >60s a tx se torna inválida. Re-simule se o usuário hesitar.

## Exibição Token-2022

Tokens sob o programa Token-2022 devem ser rotulados como tal na lista de tokens da carteira, pois têm superfícies de risco diferentes:

- **Mints com taxa de transferência**: exiba o `transferFeeBasisPoints` atual como "Taxa de transferência: X%" ao lado do saldo. Avise ao receber — usuários podem não perceber que receberão menos do que o remetente enviou.
- **Mints com hook de transferência**: superfície o ID do programa do hook. Um hook malicioso pode bloquear transferências de saída; usuários devem verificar se o hook é o que esperam.
- **Mints não transferíveis**: exiba "Não transferível" e desabilite swap/envio. Estes são tipicamente tokens vinculados à alma ou credenciais.
- **Mints com juros**: o saldo da UI derivado de `TokenAccount.amount` **não** reflete juros acumulados. Use `amountToUiAmount` de `@solana/spl-token` (que aplica o fator de escala) para o valor exibido.

## Exibição de APR de Farm

O APR exibido aos usuários deve combinar todos os streams de recompensa ao vivo, convertidos para USD e anualizados:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // pule não-em-execução
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

Exiba como `APR: X.Y%`. Se o mint de staking for um token LP, também calcule o APR de taxa base do LP subjacente e rotule a soma como "APR Total" ou "APR + taxas".
