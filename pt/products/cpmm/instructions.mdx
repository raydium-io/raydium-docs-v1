## Resumo de instruções

| Nome do discriminador | Quem assina | O que faz |
|-------|-----------|--------------|
| `Initialize` | criador do pool | Cria um novo pool CPMM a partir de dois mints e uma `AmmConfig`. Sem permissão; qualquer um pode chamar. Hardcoda `enable_creator_fee = false` no novo pool. A conta `pool_state` pode ser tanto a PDA canônica quanto um keypair aleatório fresco (veja contas de Initialize). |
| `InitializeWithPermission` | pagador + detentor de uma PDA `Permission` | Variante com permissão de `Initialize`. O chamador (`payer`) deve possuir uma PDA `Permission` derivada de sua própria chave pública. Usado por plataformas que precisam de criação de pool controlada (ex: graduações do LaunchLab). Permite que o chamador fixe `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) e força `enable_creator_fee = true` no novo pool. O campo `creator` em `pool_state` é definido para uma conta `creator` passada separadamente, não o pagador. Mesma flexibilidade de PDA-canônica-ou-keypair-aleatório para `pool_state` como em `Initialize`. |
| `Deposit` | LP | Adiciona liquidez em ambos os tokens; recebe tokens LP. |
| `Withdraw` | LP | Queima tokens LP; recebe ambos os tokens subjacentes pro-rata. |
| `SwapBaseInput` | swapper | Swap de entrada exata (`amount_in` dentro, ≥ `minimum_amount_out` fora). |
| `SwapBaseOutput` | swapper | Swap de saída exata (≤ `maximum_amount_in` dentro, `amount_out` fora). |
| `CollectProtocolFee` | `protocol_owner` (de `AmmConfig`) | Coleta taxas de protocolo acumuladas dos vaults. |
| `CollectFundFee` | `fund_owner` (de `AmmConfig`) | Coleta taxas de fundo acumuladas dos vaults. |
| `CollectCreatorFee` | `pool_creator` | Coleta taxas de criador acumuladas (se taxa de criador foi habilitada). |
| `CollectCreatorFeePermissionless` | qualquer pagador | Coleta todas as taxas de criador acumuladas para as contas de token canônicas do `pool_creator`. O pagador pode criar ATAs de destinatário ausentes mas não pode redirecionar a transferência. |
| `UpdatePoolStatus` | `admin` | Pausa / retoma operações específicas em um pool via bitmask. |
| `UpdateAmmConfig` | `admin` | Altera taxas ou o proprietário de protocolo/fundo em uma `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Cria um novo nível de taxa (nova conta `AmmConfig`). |
| `CreatePermissionPda` | `admin` ou criador de PDA de permissão delegado | Emite uma PDA `Permission` que permite que uma autoridade específica chame `InitializeWithPermission`. |
| `ClosePermissionPda` | `admin` ou o criador dedicado de PDA de permissão | Revoga uma PDA `Permission` previamente emitida. Desde a atualização 2026-09, a autoridade criadora dedicada também pode fechar uma concessão que emitiu; era apenas admin antes. |
| `CreateSupportMintAssociated` | `admin` ou o proprietário dedicado de mint de suporte | Registra um mint Token-2022 que falharia na lista de permissões de extensão, criando sua PDA `SupportMintAssociated`. |
| `CloseSupportMintAssociated` | `admin` ou o proprietário dedicado de mint de suporte | Remove o registro de um mint. |
| `CollectExcessLamports` | `admin` ou a carteira dedicada de coleta de lamports | Coleta lamports acima do mínimo isento de aluguel dos vaults controlados pelo CPMM, mints LP e PDAs. Adicionado em 2026-09. |

Bitmask de status: o `status` de cada pool é um `u8` onde bit 0 = depósito desabilitado, bit 1 = saque desabilitado, bit 2 = swap desabilitado (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` no programa). Um bit limpo significa que a operação é permitida; um bit definido significa que está pausada. `UpdatePoolStatus` recebe um `u8` bruto e sobrescreve o valor existente.

As próximas seções detalham cada uma. A ordenação de contas segue o IDL do CPMM; o SDK e o cliente Rust em `raydium-cp-swap/programs/cp-swap/src/instructions` correspondem a essa ordem.

## `Initialize`

Cria um novo pool CPMM.

**Argumentos**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Timestamp Unix; swaps rejeitados antes disso
```

**Contas** (W = gravável, S = assinante)

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Paga aluguel; registrado como `pool_state.pool_creator`. |
| 2 | `amm_config` |   |   | O nível de taxa escolhido. |
| 3 | `authority` |   |   | PDA de autoridade global do CPMM. |
| 4 | `pool_state` | W | S* | `init`ializado aqui. **Ou** a PDA canônica `["pool", amm_config, token_0_mint, token_1_mint]` **ou** um keypair aleatório fresco — quando não é a PDA canônica, o programa requer que `pool_state` assine (`require_eq!(pool_account_info.is_signer, true)`). O caminho de keypair aleatório permite que um criador evite tentativas de front-running na PDA canônica. As PDAs a jusante (`lp_mint`, `vaults`, `observation_state`) são derivadas de `pool_state.key()` de qualquer forma. |
| 5 | `token_0_mint` |   |   | Ordenado: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | `init`ializado aqui. Autoridade definida como `authority`. |
| 8 | `creator_token_0` | W |   | ATA de origem para `init_amount_0`. |
| 9 | `creator_token_1` | W |   | ATA de origem para `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | Destino para LP (criado se ausente). |
| 11 | `token_0_vault` | W |   | `init`ializado aqui. Possuído por `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | ATA de destino para a `create_pool_fee` paga pelo criador. |
| 14 | `observation_state` | W |   | `init`ializado aqui. |
| 15 | `token_program` |   |   | SPL Token (para mint LP). |
| 16 | `token_0_program` |   |   | SPL Token ou Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token ou Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` assina apenas no caminho de keypair aleatório; o caminho de PDA canônica executa sem `pool_state` assinando.

**Pré-condições**

- Mints são ordenados (`token_0_mint < token_1_mint` por ordem de bytes).
- Nenhum mint usa uma extensão fora da lista de permissões do CPMM (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — veja [`products/cpmm/accounts`](/pt/products/cpmm/accounts#vaults-and-token-2022). Um mint com uma PDA `SupportMintAssociated` (seed `[b"support_mint", mint]`) pula a verificação; esse registro é o único bypass desde que a atualização 2026-09 removeu a whitelist hardcoded de quatro mints.
- `creator` tem pelo menos `init_amount_0` e `init_amount_1` nos respectivos ATAs.
- `amm_config.disable_create_pool == false`.

**Pós-condições**

- `pool_state` existe com `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- O iniciador de LP de `LOCKED_LP` (`100` lamports de token LP) é permanentemente bloqueado no pool — `pool_state.lp_supply` registra `liquidity − 100` enquanto `100` unidades LP permanecem fora de circulação, prevenindo que o pool seja totalmente drenado e dividindo por zero.
- `observation_state` é inicializado; `observation_index = 0` e `pool_id = pool_state.key()`.
- `create_pool_fee` lamports são transferidos do criador para o receptor e sincronizados como SOL nativo (é um ATA wSOL).
- O bitmask de status do pool é `0` (depósito / saque / swap todos habilitados).
- `enable_creator_fee = false` e `creator_fee_on = BothToken`. `Initialize` **não** suporta habilitar a taxa de criador — esse caminho é `InitializeWithPermission`.
- `open_time` é aumentado para `block_timestamp + 1` se o chamador passou um valor `<= block_timestamp`. Swaps são rejeitados antes de `open_time`; depósitos e saques funcionam imediatamente.

**Erros comuns** (lista completa em [`reference/error-codes`](/pt/reference/error-codes))

- `InvalidInput` — mints desordenados ou mints idênticos.
- `NotSupportMint` — extensão Token-2022 bloqueada.
- `ExceededSlippage` — raramente; se `init_amount_0/1` resultarem em zero LP devido a incompatibilidade de decimais.

## `Deposit`

Adiciona liquidez em ambos os tokens proporcionais ao pool.

**Argumentos**

```
lp_token_amount:   u64   // quantos tokens LP cunhar para o LP
maximum_token_0:   u64
maximum_token_1:   u64
```

**Contas**

| # | Nome | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Matemática**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

Sem alteração na proporcionalidade de `k` — ambos os vaults e `lp_supply` escalam pelo mesmo fator.

**Pós-condições**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (líquido de qualquer taxa de transferência Token-2022 na entrada).
- `vault_1 += needed_token_1` (líquido de qualquer taxa de transferência Token-2022 na entrada).

**Erros comuns** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus` se depósito está pausado.

## `Withdraw`

Queima tokens LP e recebe ambos os tokens subjacentes pro-rata.

**Argumentos**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Contas**

| # | Nome | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(Idêntico a `Deposit`; `lp_mint` é gravável porque os tokens LP são queimados.)

**Matemática**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**Pós-condições**

- `lp_supply -= lp_token_amount`.
- Vaults enviam `out_token_0` / `out_token_1` (bruto; o usuário recebe líquido de qualquer taxa de transferência Token-2022).

## `SwapBaseInput`

Swap de entrada exata.

**Argumentos**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Contas**

| # | Nome | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

A ordenação **entrada → saída** é pela direção do usuário, não pela `token_0 / token_1` canônica do pool. O programa descobre qual vault é qual combinando mints.

**Matemática** — veja [`products/cpmm/math`](/pt/products/cpmm/math).

**Pré-condições**

- `open_time <= now`.
- `pool_status` permite swap.
- Nenhum mint pausado ou congelado para essa autoridade.
- `amount_in > 0`.

**Erros comuns**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — a negociação arredonda para zero.
- `NotApproved` — pool está pausado para swaps via `UpdatePoolStatus`.
- `InvalidInput` — mints não correspondem a nenhum dos mints do vault do pool.

## `SwapBaseOutput`

Swap de saída exata.

**Argumentos**

```
max_amount_in:  u64
amount_out:     u64
```

**Contas** — mesmas que `SwapBaseInput`.

**Matemática** — curva inversa com teto, veja [`products/cpmm/math`](/pt/products/cpmm/math).

**Erros comuns** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `owner` |   | S | Deve corresponder a `amm_config.protocol_owner`. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |

**Efeito**

## `CollectFundFee`

Mesma forma que `CollectProtocolFee` mas assinado por `fund_owner` e zerando os contadores `fund_fees_*`.

## `CollectCreatorFee`

Assinado por `pool_state.pool_creator`. Transfere os saldos completos de `creator_fees_token_0` e `creator_fees_token_1` para as contas de token do criador, depois zera ambos os contadores. Retorna `NoFeeCollect` quando ambos os contadores são zero.

## `CollectCreatorFeePermissionless`

Qualquer um pode disparar a coleta de taxa de criador. A instrução sempre envia os saldos acumulados completos para as contas de token associadas canônicas possuídas por `pool_state.pool_creator`; o chamador não pode escolher outro criador ou destino. Se qualquer ATA estiver ausente, o pagador financia sua criação.

O `CollectCreatorFee` original permanece chamável, então clientes existentes permanecem compatíveis.

**Argumentos** — nenhum.

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Qualquer assinante; financia ATAs de criador ausentes. |
| 2 | `creator` |   |   | Deve ser igual a `pool_state.pool_creator`; não assina. |
| 3 | `authority` |   |   | PDA de autoridade de vault global do CPMM. |
| 4 | `pool_state` | W |   | Mantém os contadores de taxa de criador acumulados. |
| 5 | `token_0_vault` | W |   | Deve corresponder ao vault de token 0 do pool. |
| 6 | `token_1_vault` | W |   | Deve corresponder ao vault de token 1 do pool. |
| 7 | `vault_0_mint` |   |   | Deve corresponder a `token_0_vault.mint`. |
| 8 | `vault_1_mint` |   |   | Deve corresponder a `token_1_vault.mint`. |
| 9 | `creator_token_0` | W |   | ATA canônica do criador para `vault_0_mint`; criada se ausente. |
| 10 | `creator_token_1` | W |   | ATA canônica do criador para `vault_1_mint`; criada se ausente. |
| 11 | `token_0_program` |   |   | SPL Token ou Token-2022, correspondendo ao token 0. |
| 12 | `token_1_program` |   |   | SPL Token ou Token-2022, correspondendo ao token 1. |
| 13 | `associated_token_program` |   |   | Cria um ATA de destinatário ausente. |
| 14 | `system_program` |   |   | Financia criação de conta a partir de `payer`. |

**Efeito**

- Transfere todo `creator_fees_token_0` e `creator_fees_token_1` dos vaults do pool para os ATAs do criador.
- Zera ambos os contadores de taxa de criador e atualiza `pool_state.recent_epoch`.
- Retorna `NoFeeCollect` quando ambos os contadores são zero.

## `UpdatePoolStatus`

Pausa ou retoma operações individuais em um pool. O campo `status` é um bitmask:

| Bit | Flag | Efeito quando definido |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` rejeita com `NotApproved`. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` rejeita. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` rejeitam. |

**Argumentos**

```
status: u8      // novo bitmask
```

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `authority` |   | S | Deve corresponder à chave de admin no programa CPMM. |
| 2 | `pool_state` | W |   |

A chave de admin é a autoridade de upgrade no programa CPMM — na prática, o multisig Raydium. Veja [`security/admin-and-multisig`](/pt/security/admin-and-multisig).

## `CreateAmmConfig`

Cria um novo nível de taxa.

**Argumentos**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `owner` | W | S | Admin. |
| 2 | `amm_config` | W |   | `init`ializado aqui. |
| 3 | `system_program` |   |   |

**Pré-condições**

- Nenhuma `AmmConfig` existente com o mesmo `index`.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **Alterado em 2026-09: os proprietários de taxa da nova config não vêm mais do assinante.** `create_amm_config` agora escreve o `protocol_fee_owner::ID` hardcoded do programa em `protocol_owner` e `fund_fee_owner::ID` em `fund_owner`, em vez de copiar a chave do assinante de admin em ambos. Os endereços estão em [`reference/program-addresses`](/pt/reference/program-addresses#cpmm-fee-owner-wallets).

  Consequências: uma `AmmConfig` recém-criada é imediatamente varrida pelas carteiras de taxa dedicadas em vez da chave de admin, e o admin não pode mais coletar de uma config que acabou de criar sem primeiro rotacionar o campo. **Contas `AmmConfig` existentes não são reescritas** — o que quer que esteja armazenado nelas ainda governa, então sempre leia `protocol_owner` / `fund_owner` da conta em vez de assumir qualquer valor. Os parâmetros `3` e `4` de `UpdateAmmConfig` ainda os rotacionam.
</Note>

## `UpdateAmmConfig`

Altera taxas ou propriedade em uma `AmmConfig` existente. Recebe um `param: u8` (discriminador para qual campo atualizar) e um `value: u64`. A semântica de valor por param está na fonte; comumente:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (passe bytes `Pubkey` como reinterpretação)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

As alterações são assinadas pelo admin e afetam **cada pool vinculado a essa `AmmConfig`** no próximo swap. Sem migração; pools simplesmente leem os novos valores.

## `CollectExcessLamports`

Varredura de admin de lamports acima do mínimo isento de aluguel em contas que o CPMM controla. Adicionado na atualização 2026-09 para que o protocolo possa recuperar o excesso de financiamento que a [redução de aluguel SIMD-0437](/pt/solana-fundamentals/rent-and-reclaimable-rent) deixa em contas criadas antes de cada etapa.

Apenas o excesso se move. Saldos de token, dados de conta, proprietários, estado do pool e a curva permanecem intocados, e a instrução é uma no-op contra uma conta já em seu mínimo — então é seguro re-executar após cada etapa de rollout.

**Argumentos** — nenhum.

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | Destino para cada lamport varrido. Deve ser ou o admin do programa CPMM ou a carteira dedicada de coleta de lamports — veja [`reference/program-addresses`](/pt/reference/program-addresses#excess-lamports-collection-wallets). Qualquer outro assinante falha com `InvalidOwner`. |
| 2 | `authority` |   |   | A PDA de autoridade de vault e mint LP do CPMM com seed `[b"vault_and_lp_mint_auth_seed"]`. Assina os CPIs do programa de token. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. Ambos são necessários incondicionalmente; o programa escolhe por conta de origem. |
| 5.. | `remaining_accounts` | W |   | `M` contas de origem para varrer, qualquer número, qualquer ordem. |

**Como cada conta de origem é tratada**

O programa despacha no `owner` da conta de origem:

| Proprietário da conta de origem | Tratamento |
|---|---|
| SPL Token ou Token-2022, conta de token não-nativa ou mint — vaults de pool e mints LP | CPI `WithdrawExcessLamports` (discriminante do programa de token `38`), assinado por `authority`. |
| SPL Token ou Token-2022, conta de token **nativa** (wSOL) | `WithdrawExcessLamports` rejeita contas nativas. O programa CPIs `SyncNative`, mede quanto o `amount` envolvido cresceu, `UnwrapLamports` (discriminante `45`) para exatamente esse delta, depois requer que o saldo envolvido seja igual ao seu valor pré-sync — caso contrário `LamportsCalculateError` (`6015`). Um vault de pool do lado SOL portanto mantém sua liquidez completa. |
| O próprio programa CPMM — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | O programa debita a conta diretamente até `rent.minimum_balance(data_len)`. |
| Qualquer outra coisa | **Pulada silenciosamente.** Sem erro, sem lamports movidos. |

Como recebe uma lista `remaining_accounts` ilimitada, o tamanho da transação é o limite real — a mesma restrição que a varredura do lado da carteira descrita em [`solana-fundamentals/rent-and-reclaimable-rent`](/pt/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction).

**Erros comuns** — `InvalidOwner` (`6001`, assinante errado), `LamportsCalculateError` (`6015`, a volta wSOL não resultou em zero) e `InsufficientFunds` do caminho possuído pelo programa quando uma conta mantém menos que seu próprio mínimo de aluguel.

**Sem construtor SDK.** `@raydium-io/raydium-sdk-v2` não fornece um construtor para essa instrução, e nem o repositório `raydium-sdk-V2-demo` — é um caminho de admin. Codifique manualmente, da forma que a varredura do lado da carteira em [`solana-fundamentals/rent-and-reclaimable-rent`](/pt/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) faz para a instrução do programa de token.
