<Info>
  `GlobalConfig` é a conta de configuração **no nível do protocolo**. Pode haver muitas delas — indexadas por `(curve_type, index)` — e cada lançamento escolhe exatamente uma no momento de `Initialize`. Os valores no `GlobalConfig` escolhido então se tornam limites rígidos para os parâmetros daquele lançamento. Para personalização no nível da plataforma (taxa de taxa por plataforma, formas de curva permitidas, divisões de NFT na graduação), consulte [`products/launchlab/platform-config`](/pt/products/launchlab/platform-config).
</Info>

## O que é

Um `GlobalConfig` é um PDA singleton-por-`(curve_type, index)` que fixa as regras no nível do protocolo que todo lançamento deve obedecer:

- O tipo de curva de ligação permitida (`curve_type`).
- A taxa de negociação que a curva cobra em cada compra e venda.
- A taxa de migração cobrada na graduação.
- Pisos em fornecimento, taxa de bloqueio, taxa de venda e taxa de migração.
- O mint de cotação (tipicamente SOL envolvido ou USDC) — o ativo com o qual os usuários compram.
- Quatro carteiras no nível do protocolo: o proprietário da taxa de protocolo, o proprietário da taxa de migração e as duas carteiras de controle de migração retidas para graduação CPMM e AMM v4 legado.

Contas `GlobalConfig` podem ser criadas pelo administrador do programa LaunchLab ou pela autoridade delegada de criação de configuração. Apenas o administrador atualiza configurações existentes. Consulte [`reference/program-addresses`](/pt/reference/program-addresses) para as autoridades canônicas.

## Layout

```rust
// states/config.rs
pub const GLOBAL_CONFIG_SEED: &str = "global_config";

#[account]
pub struct GlobalConfig {
    pub epoch:                   u64,         // recent_epoch tracker
    pub curve_type:              u8,          // 0 = ConstantProduct, 1 = FixedPrice, 2 = LinearPrice
    pub index:                   u16,         // discriminator within a curve_type
    pub migrate_fee:             u64,         // SOL paid on graduation
    pub trade_fee_rate:          u64,         // 1/1_000_000 of volume
    pub max_share_fee_rate:      u64,         // 100 bps cap on platform share fee
    pub min_base_supply:         u64,         // floor on Initialize supply (no decimals)
    pub max_lock_rate:           u64,         // ceiling on vesting locked / supply
    pub min_base_sell_rate:      u64,         // floor on base_supply_graduation / supply
    pub min_base_migrate_rate:   u64,         // floor on tokens that seed the post-graduation pool
    pub min_quote_fund_raising:  u64,         // floor on quote_reserve_target (with decimals)
    pub quote_mint:              Pubkey,
    pub protocol_fee_owner:      Pubkey,      // claims protocol fees via CollectFee
    pub migrate_fee_owner:       Pubkey,      // claims migration fees via CollectMigrateFee
    pub migrate_to_amm_wallet:   Pubkey,      // can sign MigrateToAmm
    pub migrate_to_cpswap_wallet:Pubkey,      // can sign MigrateToCpswap
    pub padding_alignment:       [u8; 8],
    pub padding:                 [u64; 15],
}
```

Derivação de PDA:

```ts
const [globalConfig] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    Buffer.from(quoteMint.toBytes()),
    Buffer.from([curveType]),
    u16ToBytes(index),

);
```

## Semântica dos campos

### `curve_type` e `index`

Juntos, esses campos indexam um `GlobalConfig` de forma única. Há um `GlobalConfig` por par `(curve_type, index)`:

- `curve_type = 0` — Curva de reserva virtual de produto constante. Padrão e mais usado.
- `curve_type = 1` — Curva de preço fixo.
- `curve_type = 2` — Curva de preço linear.

`index` é um `u16` que permite ao administrador publicar múltiplas configurações por tipo de curva (por exemplo, uma com uma taxa mais apertada, outra com um mínimo de arrecadação de cotação mais alto). Em `Initialize`, o lançamento fornece um par `(curve_type, index)` e o programa carrega o `GlobalConfig` correspondente.

### Taxas

- `trade_fee_rate` — denominada em `1/1_000_000` do volume de negociação. Aplicada a cada compra e venda na curva. O `protocol_fee_owner` reivindica sua parte via `CollectFee`.
- `migrate_fee` — uma taxa fixa em lamports (ou unidades de cotação, dependendo da configuração) cobrada uma vez na graduação. Reivindicada por `migrate_fee_owner` via `CollectMigrateFee`.
- `max_share_fee_rate` — inicializada para `10_000` (100 bps). Limita a taxa de taxa de compartilhamento da **plataforma** do `PlatformConfig` vinculante (consulte [`platform-config`](/pt/products/launchlab/platform-config)). O programa garante `trade_fee_rate + max_share_fee_rate < RATE_DENOMINATOR_VALUE`.

### Pisos de fornecimento e taxa

Esses pisos limitam quais parâmetros de forma de curva um lançamento pode escolher em `Initialize`. Se o `CurveParams` do criador violar qualquer um deles, `Initialize` reverte com `InvalidInput`.

- `min_base_supply` — o mínimo `supply` (sem decimais) que a curva pode declarar. Padrão é `10_000_000`.
- `max_lock_rate` — denominada em `1/1_000_000`; padrão `300_000` (30%). Limita vesting via `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `min_base_sell_rate` — denominada em `1/1_000_000`; padrão `200_000` (20%). Limita `base_supply_graduation / supply` por baixo.
- `min_base_migrate_rate` — denominada em `1/1_000_000`; padrão `200_000` (20%). Limita o número de tokens deixados para semear o pool pós-graduação.
- `min_quote_fund_raising` — mínimo `quote_reserve_target` que um lançamento pode declarar (com decimais). Padrão é `30_000_000_000` unidades do mint de cotação.

### Mint de cotação e carteiras de protocolo

- `quote_mint` — o ativo com o qual os usuários compram. A maioria dos lançamentos usa SOL envolvido (`So111…112`) ou USDC (`EPjF…Dt1v`). Um `GlobalConfig` está vinculado a um mint de cotação; lançamentos que precisam de um alvo de cotação diferente visam um `(curve_type, index)` diferente.
- `protocol_fee_owner` — chave pública que assina `CollectFee` e reivindica as taxas de protocolo acumuladas em cada lançamento vinculado a essa configuração. Armazenada on-chain; o administrador pode rotacioná-la via `UpdateConfig`.
- `migrate_fee_owner` — chave pública que assina `CollectMigrateFee`.

### Carteiras de migração

As duas carteiras de graduação armazenadas requerem signatários diferentes:

- `migrate_to_amm_wallet` — assina `MigrateToAmm` para um lançamento legado existente cujo `migrate_type = 0` armazenado.
- `migrate_to_cpswap_wallet` — assina `MigrateToCpswap`. Todo lançamento recém-inicializado usa esse caminho.

Essas são tipicamente mantidas pela crank de graduação operada pela Raydium, para que a graduação ocorra logo após a curva atingir o limite, em vez de esperar o criador chamá-la.

### Listas de permissão no nível da plataforma

`GlobalConfig` não tem mais `requires_platform_auth`. Seu byte anterior é preenchimento, portanto o tamanho da conta não muda. O acesso agora é controlado por `PlatformConfig.restrict_global_config` e contas `PlatformAllowConfig` criadas pelo administrador dessa plataforma. Consulte [`platform-config`](/pt/products/launchlab/platform-config).

## Padrões na inicialização

Quando `CreateConfig` é chamado, o programa semeia muitos campos com padrões codificados:

```rust
self.max_share_fee_rate     = 10_000;                  // 100 bps
self.min_base_supply        = 10_000_000;              // no decimals
self.max_lock_rate          = 300_000;                 // 30%
self.min_base_migrate_rate  = 200_000;                 // 20%
self.min_base_sell_rate     = 200_000;                 // 20%
self.min_quote_fund_raising = 30_000_000_000;
```

O administrador define `curve_type`, `index`, `migrate_fee`, `trade_fee_rate`, `quote_mint` e as quatro chaves públicas de carteira explicitamente no momento da criação; valores subsequentes podem ser ajustados via `UpdateConfig`.

## Como um lançamento escolhe um `GlobalConfig`

Em `Initialize`, o criador passa:

- `(curve_type, index)` para selecionar qual PDA `GlobalConfig` carregar.
- `CurveParams` descrevendo a forma da curva (`supply`, `total_base_sell`, `total_quote_fund_raising`, `migrate_type`).
- `VestingParams` descrevendo fornecimento bloqueado.
- `MintParams` para o mint base.

O programa garante:

- `curve_type` corresponde a `global_config.curve_type`.
- `supply >= global_config.min_base_supply`.
- `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `total_base_sell >= supply * min_base_sell_rate / 1_000_000`.
- `(supply − total_base_sell − total_locked_amount) >= supply * min_base_migrate_rate / 1_000_000` — ou seja, tokens suficientes deixados para semear o pool pós-graduação.
- `total_quote_fund_raising >= min_quote_fund_raising`.
- `migrate_type == 1` (`CPSWAP`).
- Se a plataforma selecionada tem `restrict_global_config == 1`, o `PlatformAllowConfig` correspondente é incluído.

Após `Initialize`, o `PoolState` do lançamento armazena a chave pública `global_config` diretamente, portanto a vinculação é permanente.

## Caminho de atualização

`UpdateConfig` é apenas para administrador e recebe um par `(param: u8, value: u64)`. Cada valor `param` seleciona qual campo mutar:

| `param` | Campo alterado |
|---------|---------------|
| 0 | `migrate_fee` |
| 1 | `trade_fee_rate` |
| 2 | `max_share_fee_rate` |
| 3 | `min_base_supply` |
| 4 | `max_lock_rate` |
| 5 | `min_base_sell_rate` |
| 6 | `min_base_migrate_rate` |
| 7 | `min_quote_fund_raising` |

Rotações de carteira (`protocol_fee_owner`, `migrate_fee_owner`, `migrate_to_amm_wallet`, `migrate_to_cpswap_wallet`) recebem uma forma de argumento `Pubkey` separada; consulte a fonte `update_config` para a tabela de dispatch exata antes de compor uma transação de administrador.

O seletor anterior `UpdateConfig` `12` para autorização de plataforma foi removido. Administradores de plataforma agora gerenciam suas próprias listas de permissão.

## Lendo um `GlobalConfig` de um cliente

```ts
import { Raydium } from "@raydium-io/raydium-sdk-v2";

// Fetch by PDA derivation:
const [configPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    quoteMint.toBytes(),
    Buffer.from([curveType]),
    u16ToBytes(index),
  ],
  LAUNCHLAB_PROGRAM_ID,
);

const config = await raydium.launchpad.getGlobalConfig(configPda);
console.log(config.tradeFeeRate, config.minQuoteFundRaising);
```

Para uma interface listando todas as configurações disponíveis, percorra o auxiliar `getAllGlobalConfigs` do SDK ou consulte o endpoint da API LaunchLab que as espelha; a contagem de contas on-chain é pequena (alguns dígitos na prática).
