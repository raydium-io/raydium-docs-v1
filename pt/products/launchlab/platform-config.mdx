<Info>
  `PlatformConfig` é a **sobreposição em nível de plataforma** que fica sobre [`GlobalConfig`](/pt/products/launchlab/global-config). Enquanto `GlobalConfig` define as regras em todo o protocolo ("taxa de negociação é 1%, fornecimento deve ser pelo menos 10M, apenas esta carteira pode se formar"), `PlatformConfig` é o que cada plataforma de lançamento — pump.fun, a própria UI do Raydium, launchpads de terceiros — usa para adicionar sua taxa, reivindicar sua fatia do LP pós-graduação, restringir quais formas de curva seus lançamentos podem escolher e exibir sua marca (nome, site, imagem) on-chain.
</Info>

## O que é

Uma conta `PlatformConfig` possui cinco preocupações transversais para uma plataforma:

1. **Marca** — nome, site, link de imagem, todos armazenados inline para que qualquer explorador ou agregador possa exibir a plataforma que lançou um token.
2. **Taxa de plataforma** — uma taxa de negociação extra (`fee_rate`) além da `trade_fee_rate` do protocolo. Acumula na `platform_fee_wallet` da plataforma. Limitada a 500 bps (`50000`) tanto no caminho de criação quanto no de atualização, aumentada de 100 bps (`10000`) em 2026-08-26 — veja [Limites de taxa](#limites-de-taxa).
3. **Divisão de migração de LP** — três inteiros armazenados (`platform_scale`, `creator_scale`, `burn_scale`) que somam `1_000_000`. Antes da atualização de 2026-08-17, a escala do criador produzia uma Fee Key de criador separada. Migrações executadas após a atualização combinam os dois primeiros em uma compartilhamento de LP bloqueado de propriedade da plataforma; o restante é queimado.
4. **Lista de permissões de parâmetros de curva** — um `Vec<PlatformCurveParam>` listando exatamente quais combinações `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)` são permitidas nesta plataforma. Se o vetor estiver vazio ou todas as entradas forem inválidas, **qualquer** combinação é permitida; caso contrário, os lançamentos devem corresponder exatamente a uma das entradas.
5. **Lista de permissões de configuração global** — uma restrição opt-in que requer um `PlatformAllowConfig` criado pela plataforma para o `GlobalConfig` selecionado.

Derivação de PDA:

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // chave pública proprietária da plataforma
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Veja `create_platform_config` no código-fonte para a lista de seeds canônica.)

## Layout

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (denominador 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (denominador 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // assina ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // recebe a fatia de NFT da plataforma na graduação CPMM
    pub platform_scale:              u64,               // compartilhamento de LP cunhado para NFT da plataforma
    pub creator_scale:               u64,               // compartilhamento do criador antes da atualização; adicionado à compartilhamento da plataforma depois
    pub burn_scale:                  u64,               // compartilhamento de LP queimado permanentemente
    pub fee_rate:                    u64,               // taxa de negociação da plataforma (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 preenchido com zeros
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // AmmConfig CPMM que o pool pós-grad vinculará
    pub creator_fee_rate:            u64,               // taxa de taxa do lado do criador tomada pré-graduação
    pub transfer_fee_extension_auth: Pubkey,            // para lançamentos Token-2022: autoridade de retirada de withheld da criação de mint, autoridade de configuração de taxa da graduação
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // fatia da plataforma de total_locked_amount
    pub platform_cp_creator:         Pubkey,            // criador opcional de registro no pool CPMM pós-graduação
    pub restrict_global_config:      u8,                // 0 = irrestrito, 1 = requer PDA de permissão
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // lista de permissões de formas de curva permitidas
}
```

`platform_scale + creator_scale + burn_scale` deve ser igual a `1_000_000`. Antes da atualização de 2026-08-17, `creator_scale` era bloqueado separadamente e sua Fee Key ia para o criador do token. Para migrações executadas após a atualização, é adicionado a `platform_scale` e seus direitos de LP bloqueado vão para a plataforma. Exemplos de resultados sob a lógica atualizada:

- `(0, 100_000, 900_000)` — 90% LP queimado, 10% bloqueado para a plataforma.
- `(50_000, 100_000, 850_000)` — 85% queimado, 15% bloqueado para a plataforma.
- `(0, 0, 1_000_000)` — queima total, sem cunhagem de NFT. Lançamentos estritos "sem insiders".

## Campos de marca

`name`, `web` e `img` são matrizes de bytes inline preenchidas com zeros até suas constantes de tamanho. Para lê-las como strings, fatia até o primeiro `\0`:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

As constantes são deliberadamente generosas (`name: 64`, `web: 256`, `img: 256`) para que as plataformas possam incluir metadados suficientes para exploradores e agregadores sem tocar no armazenamento off-chain. Qualquer coisa que exceda esses tamanhos reverte em `CreatePlatformConfig` com `InvalidInput`.

## Mecânica de taxa

Um swap em uma curva vinculada a um `PlatformConfig` cobra três taxas em camadas:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` acumula no `protocol_fee_owner` do protocolo (reivindicado via `CollectFee`).
- `platform_fee` acumula em um cofre por plataforma (reivindicado via `ClaimPlatformFee` ou `ClaimPlatformFeeFromVault`; veja [`instructions`](/pt/products/launchlab/instructions)).
- `creator_fee` acumula em um cofre por criador com chave pela chave pública do criador + mint de cotação (reivindicado via `ClaimCreatorFee`).

### Limites de taxa

Ambas as taxas são denominadas em `1/1_000_000`, então `5000` é 50 bps e `50000` é 500 bps.

| Taxa | Limite | Aplicado em |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` na criação — reverte com `InvalidInput`. `update_platform_fee_rate` em cada variante de atualização que a toca (`FeeRate` e `AllInfo`) — reverte com `InvalidPlatformInfo`. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` na criação e `update_creator_fee_rate` na atualização — ambos revertam com `InvalidPlatformInfo`. |

Os dois pontos de aplicação para `fee_rate` são chamadas `require!` separadas em arquivos diferentes, então carregam códigos de erro diferentes, mas aplicam o mesmo limite. Uma plataforma criada em qualquer taxa permitida pode ser editada depois, incluindo através da variante `AllInfo` em massa que reescreve cada campo de uma vez.

Ambos os limites de `fee_rate` eram originalmente 100 bps (`10000`). O limite de atualização passou para `25000` (250 bps) em 2026-01-27; em 2026-08-26 ambos passaram para `50000` (500 bps) — veja [a entrada do changelog](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` **não** limita nenhuma das duas taxas. Limita o argumento `share_fee_rate` por transação que as quatro instruções de swap recebem — a taxa de referência — e nada mais. Veja [`global-config`](/pt/products/launchlab/global-config#fees).

## Autoridades de taxa de transferência Token-2022

`transfer_fee_extension_auth` nomeia a chave da plataforma que acaba segurando as autoridades `TransferFeeConfig` do mint base quando um lançamento é criado através de `InitializeWithToken2022` com uma taxa de transferência anexada. A extensão carrega duas autoridades, e são entregues em **pontos diferentes do ciclo de vida do lançamento**:

| Autoridade | Titular na criação do mint | Titular após `MigrateToCpswap` |
|---|---|---|
| `withdraw_withheld_authority` — retira as taxas que Token-2022 retém nas contas de token | `transfer_fee_extension_auth`, escrito direto no mint. Volta para o PDA `authority` do lançamento quando o campo é `Pubkey::default()`. | Já é a chave da plataforma, então nada se move. A migração a reatribui apenas quando o PDA `authority` ainda a mantém. |
| `transfer_fee_config_authority` — muda a taxa e a taxa máxima | Sempre o PDA `authority` do lançamento. | `transfer_fee_extension_auth`, desde que o campo seja não-padrão. |

Antes de 2026-08-27 o mint era criado com o PDA `authority` em ambas as autoridades, e ambas se moviam para a plataforma na graduação. O programa não expõe nenhuma instrução de retirada de withheld ou harvest, então as taxas retidas durante a fase de curva de ligação eram inacessíveis até o lançamento se formar. Escrever o lado de retirada na criação do mint as torna reivindicáveis desde o primeiro trade — veja [a entrada do changelog](/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority).

Duas consequências que valem a pena planejar:

- **Defina o campo antes de lançar, não depois.** Um lançamento criado enquanto `transfer_fee_extension_auth` é `Pubkey::default()` coloca o PDA `authority` no lado de retirada. Definir o campo depois ainda funciona — a graduação encontra o PDA no lugar e entrega a autoridade — mas nada pode retirar o saldo retido enquanto isso.
- **Girar o campo durante o lançamento divide as duas autoridades.** Mude `transfer_fee_extension_auth` entre a criação e a graduação de um lançamento e a autoridade de retirada de withheld do mint fica com a chave configurada na criação (o PDA não a mantém mais, então a migração pula essa entrega) enquanto a autoridade de configuração de taxa vai para a nova chave. Gire entre lançamentos, ou planeje reconciliar as duas chaves você mesmo através de Token-2022 diretamente.

Uma plataforma que deixa o campo em `Pubkey::default()` pela vida toda de um lançamento mantém ambas as autoridades no PDA `authority` permanentemente: a taxa nunca pode ser mudada e o saldo retido nunca pode ser retirado. Apenas anexe uma taxa de transferência a um lançamento se a plataforma pretender manter essas chaves.

## Divisão de migração de NFT (apenas CPMM)

Quando um lançamento se forma para CPMM, a instrução de migração divide os tokens LP cunhados por `CPMM::InitializeWithPermission` de duas maneiras:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

Se `lp_to_platform` for diferente de zero, o programa LP-Lock o envolve em um NFT Fee Key de propriedade de `platform_nft_wallet`. Isso substitui o comportamento pré-atualização que criava Fee Keys de plataforma e criador separadas. Fee Keys criadas por migrações concluídas antes da atualização permanecem inalteradas. Este direito de taxa de LP é separado das taxas de criador CPMM controladas por `platform_cp_creator`.

A fatia de queima é queimada diretamente, então nenhuma conta pode retirá-la ou reivindicar as taxas de LP representadas por esse compartilhamento.

Lançamentos existentes com `migrate_type = 0` armazenado ainda podem usar o caminho AMM v4 legado. A nova inicialização rejeita esse tipo de migração.

## Lista de permissões de parâmetros de curva

`curve_params: Vec<PlatformCurveParam>` é o mecanismo da plataforma para restringir quais formas de curva seus lançamentos podem escolher. Se o vetor for não-vazio e pelo menos uma entrada for válida, o programa aplica em `Initialize` que os parâmetros do lançamento correspondam exatamente a pelo menos uma entrada.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // ordinal dentro da lista de permissões desta plataforma
    pub global_config:        Pubkey,       // qual GlobalConfig esta entrada se aplica
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // novos lançamentos requerem 1 = CPMM; u8::MAX = curinga
    pub migrate_cpmm_fee_on:        u8,    // 0 = apenas cotação, 1 = ambos. u8::MAX = curinga
    pub supply:                     u64,   // 0 = curinga
    pub total_base_sell:            u64,   // 0 = curinga
    pub total_quote_fund_raising:   u64,   // 0 = curinga
    pub total_locked_amount:        u64,   // u64::MAX = curinga
    pub cliff_period:               u64,   // u64::MAX = curinga
    pub unlock_period:              u64,   // u64::MAX = curinga
}
```

Cada campo tem um valor sentinela que significa **curinga** (qualquer valor corresponde): `u64::MAX` para os campos `u64`, `u8::MAX` para os campos `u8`, `0` para os campos de fornecimento / venda / arrecadação de fundos. Um `BondingCurveParam` com todos os sentinelas é "permitir qualquer coisa" — equivalente ao comportamento de lista vazia.

O algoritmo de correspondência em `Initialize`:

1. Filtre `curve_params` para entradas cuja `global_config` corresponda ao `GlobalConfig` escolhido do lançamento.
2. Se a lista filtrada estiver vazia, permita qualquer parâmetro (a plataforma não colocou na lista de permissões nada para este `GlobalConfig`).
3. Se cada entrada na lista filtrada tiver `all_is_invalid()` (cada campo é o curinga), permita qualquer parâmetro.
4. Caso contrário, itere entradas; para cada entrada, verifique os parâmetros do lançamento contra cada campo não-curinga. Se todos os campos não-curinga corresponderem, aceite e retorne.
5. Se nenhuma entrada correspondeu, reverta com `InvalidInput`.

Isso permite que uma plataforma diga "nós apenas permitimos a forma padrão de 1B-fornecimento / 800M-vendido / 30k-USDC-arrecadação / sem-vesting" escrevendo uma única entrada com valores concretos para esses quatro campos e curingas em qualquer lugar. Ou uma plataforma mais rigorosa pode enumerar três ou quatro formas discretas, uma por nível de lançamento suportado.

`MAX_CURVE_PARAMS = 10` limita o tamanho da lista de permissões.

## `PlatformAllowConfig` — restringindo uma plataforma

Cada plataforma decide se restringe qual `GlobalConfig` contas seus lançamentos podem usar. Defina `restrict_global_config` com `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)`.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

Seeds de PDA: `[b"platform_allow_config", platform_config, global_config]`.

O admin da plataforma cria ou fecha uma conta por par permitido via `CreatePlatformAllowConfig` e `ClosePlatformAllowConfig`. Quando a restrição é `1`, a inicialização procura em `remaining_accounts` pelo PDA esperado e rejeita uma conta ausente com `NotEnoughRemainingAccounts`. Quando a restrição é `0`, nenhuma conta de permissão é necessária.

A conta `PlatformGlobalAccess` gerenciada pelo admin do protocolo anterior e suas instruções de criar/fechar são aposentadas. Os tamanhos existentes de `PlatformConfig` e `GlobalConfig` não mudam, mas decodificadores devem substituir o sinalizador global antigo pelo sinalizador de plataforma novo. PDAs de acesso antigos não são consumidos pela nova verificação.

## Caminho de atualização

| Instrução | Quem assina | O que muda |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | admin da plataforma (uma vez) | Inicializa a conta com `PlatformParams`. |
| `UpdatePlatformConfig` | admin da plataforma | Despacho genérico com chave por um `param: u8`; muta um campo por chamada, ou cada campo de uma vez via `AllInfo`. Campos de marca, taxas, carteira de vesting e as várias carteiras são todos configuráveis através disso. Ambas as taxas são re-validadas contra os limites em [Limites de taxa](#limites-de-taxa) em cada variante que as toca. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | admin da plataforma | Adicione ou remova um `GlobalConfig` permitido para esta plataforma. |
| `UpdatePlatformCurveParam` | admin da plataforma | Adicione ou substitua uma entrada `PlatformCurveParam` por `(global_config, index)`. |
| `RemovePlatformCurveParam` | admin da plataforma | Limpe uma entrada (defina como todos-sentinela = curinga). |
| `ClaimPlatformFee` | `platform_fee_wallet` | Limpe a taxa de plataforma por pool de `PoolState.quote_vault`. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | Limpe o cofre de taxa por plataforma (PDA em `[platform_config, quote_mint]`). |

Rotações de carteira (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) todas passam por `UpdatePlatformConfig`. Leia a tabela de despacho `update_platform_config` do código-fonte para os códigos `param` exatos.

## Armadilhas comuns

- **Sentinelas de lista de permissões mal definidas.** Um `BondingCurveParam` com `total_locked_amount = 0` *não é* um curinga — corresponde a lançamentos que explicitamente optam por não usar vesting. O curinga para esse campo é `u64::MAX`. A mesma armadilha existe para `cliff_period` e `unlock_period`. Use `clear()` (que o programa expõe) para definir sentinelas corretamente.
- **Arredondamento de divisão de NFT.** As três escalas devem somar exatamente `1_000_000`. Erros de um em `CreatePlatformConfig` revertam; erros de um em tempo de execução cunhariam ou queimariam uma unidade LP extra, que é o que a verificação de igualdade estrita está lá para prevenir.
- **Dupla alocação de vesting de plataforma.** Se `platform_vesting_scale > 0`, a plataforma deve chamar `CreatePlatformVestingAccount` uma vez após o término da arrecadação de fundos do lançamento; se esquecer, esse compartilhamento permanece não alocado e dormente para sempre (o orçamento `total_locked_amount` do lançamento é consumido mas a plataforma nunca reclama).
- **Ambiguidade de `platform_cp_creator`.** Quando definido como `Pubkey::default()`, o criador do lançamento é registrado como o `pool_creator` do pool CPMM pós-graduação; quando definido como uma chave real, essa chave é registrada. Isso determina o beneficiário das taxas de criador CPMM pós-graduação e quem pode assinar o caminho original `CPMM::CollectCreatorFee`. O caminho de coleta sem permissão ainda paga as ATAs canônicas dessa chave registrada. Decida no momento da criação da configuração da plataforma qual modelo você quer.
- **`transfer_fee_extension_auth` definido tarde ou girado.** O campo é lido duas vezes por lançamento Token-2022 — uma vez na criação do mint para `withdraw_withheld_authority`, uma vez na graduação para `transfer_fee_config_authority` — então um valor que muda entre esses dois momentos deixa as duas autoridades em chaves diferentes. Veja [Autoridades de taxa de transferência Token-2022](#autoridades-de-taxa-de-transferência-token-2022).
- **Restrição sem uma conta de permissão.** Habilitar `restrict_global_config` antes de criar o `PlatformAllowConfig` necessário bloqueia novos lançamentos que selecionam essa configuração.
