Quando um token do LaunchLab migra para CPMM, o pool cunha tokens LP. Antes da atualização de 2026-08-17, `creatorScale` era bloqueado separadamente para o criador do token. Para migrações executadas após a atualização, `migrateCpLockNftScale` ainda armazena três campos que somam `1_000_000`, mas o runtime produz apenas dois destinos.

## Divisão efetiva

| Campo | Comportamento atualizado |
|---|---|
| `platformScale` | Incluído na participação de LP bloqueado de propriedade da plataforma. |
| `creatorScale` | Antes da atualização, cunhava uma Fee Key de propriedade do criador. Após a atualização, é incluído na participação de LP bloqueado de propriedade da plataforma. |
| `burnScale` | Queimado permanentemente. Nenhuma Fee Key representa essa participação. |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

Quando `burnScale` é zero, a plataforma recebe todas as unidades de LP. Quando `effectivePlatformScale` é zero, todo o LP é queimado e nenhuma Fee Key de plataforma é criada.

## Exemplos

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% LP bloqueado de propriedade da plataforma, 10% queimado.
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// Sob o programa atualizado, isso produz 100% LP bloqueado de propriedade da plataforma.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% queimado; sem Fee Key.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## Relação com as taxas de criador do CPMM

Os campos de escala controlam apenas a propriedade do LP. Eles não definem as taxas de swap ou identificam o beneficiário da taxa de criador do CPMM. `cpConfigId` seleciona o `AmmConfig` do CPMM; `platformCpCreator` determina se o pool CPMM registra o criador de lançamento original ou um endereço selecionado pela plataforma.

## Atualizando a divisão

Antes de atualizar uma plataforma:

- Confirme que os três valores somam exatamente `1_000_000`.
- Apresente `platformScale + creatorScale` como a participação efetiva da plataforma.
- Não prometa uma Fee Key de criador com base em `creatorScale`.
- Preserve a propriedade da Fee Key do criador mostrada por migrações concluídas antes da atualização; esses registros não são reescritos.
- Explique a mudança antes que futuros lançamentos usem a configuração atualizada.
