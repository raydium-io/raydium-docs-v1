## Inventário de instruções

| Grupo | Instrução | Chamável por |
|-------|-----------|-------------|
| Configuração global | `CreateConfig` / `UpdateConfig` | Admin do programa; a autoridade delegada de criar-config também pode chamar `CreateConfig` |
| Ciclo de vida do lançamento | `Initialize` / `InitializeV2` | Qualquer um (criador) — lançamentos de SPL Token; V2 registra `amm_creator_fee_on` para a eventual graduação CPMM |
| Ciclo de vida do lançamento | `InitializeWithToken2022` | Qualquer um (criador) — lançamento Token-2022, `TransferFeeConfig` opcional |
| Negociação | `BuyExactIn` / `BuyExactOut` | Qualquer um — compra com entrada exata / saída exata na curva de ligação |
| Negociação | `SellExactIn` / `SellExactOut` | Qualquer um — venda com entrada exata / saída exata na curva de ligação |
| Graduação | `MigrateToAmm` | Carteira de migração — graduação legada AMM v4 para pools inicializados antes da criação exclusiva CPMM ser imposta. |
| Graduação | `MigrateToCpswap` | Carteira de migração — graduar para CPMM. Todos os lançamentos recém-inicializados usam este caminho. Envolve `InitializeWithPermission` no CPMM. |
| Taxas | `CollectFee` | Admin — varrer taxas de protocolo de um lançamento |
| Taxas | `CollectMigrateFee` | Admin — varrer taxas de migração acumuladas |
| Taxas | `ClaimCreatorFee` | Criador — reivindicar taxas de criador acumuladas durante a fase de curva |
| Vesting | `CreateVestingAccount` | Criador — alocar tokens bloqueados a um beneficiário, desbloqueados após graduação |
| Vesting | `CreatePlatformVestingAccount` | Admin da plataforma — alocar tokens bloqueados a beneficiários do lado da plataforma |
| Vesting | `ClaimVestedToken` | Beneficiário — reivindicar tokens desbloqueados após o cliff |
| Configuração de plataforma | `CreatePlatformConfig` / `UpdatePlatformConfig` | Admin da plataforma |
| Configuração de plataforma | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Admin da plataforma — gerenciar a lista por plataforma de formas de curva permitidas |
| Taxas de plataforma | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Admin da plataforma |
| Acesso à plataforma | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Admin da plataforma — manter a lista de permissões `GlobalConfig` usada quando essa plataforma ativa restrição |

A divisão "ExactIn/ExactOut" espelha `SwapBaseInput` / `SwapBaseOutput` do CPMM — na cadeia são discriminadores de instrução separados com arredondamento ligeiramente diferente.

**Seleção de caminho de graduação.** Cada chamada `Initialize`, `InitializeV2` e `InitializeWithToken2022` deve definir `migrate_type = 1` (`CPSWAP`). Qualquer tentativa de inicializar um novo pool vinculado a AMM v4 retorna `MigrateTypeNotMatch`. `amm_creator_fee_on` apenas seleciona se a taxa de criador CPMM resultante se aplica ao token de cotação ou a ambos os tokens; não seleciona o programa de destino.

`MigrateToAmm` permanece chamável para um `PoolState` existente que foi inicializado com `migrate_type = 0` antes dessa restrição. A versão não reescreve o estado do pool existente ou remove a instrução legada.

## `Initialize`

Criar um novo lançamento.

**Argumentos**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // ou initial_virtual_quote_reserve para curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // nome/símbolo/uri inline; programa faz CPI para Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Contas** (resumidas)

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Paga aluguel + criação de mint base. |
| 2 | `launch_config` |   |   | Vinculação de configuração de protocolo. |
| 3 | `launch_state` | W |   | Nova conta. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Keypair fresco (ou PDA) — esta instrução o inicializa. |
| 6 | `base_vault` | W |   | ATA de `launch_authority` em `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA de `launch_authority` em `quote_mint`. |
| 9 | `metadata` | W |   | PDA de metadados Metaplex. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | Apenas SPL Token. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Pré-condições**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Parâmetros de taxa passam nas verificações `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK impõe `≥ now`; programa tolera backdating leve).
- `curve_type` é reconhecido.

**Pós-condições**

- `base_mint` tem `supply = base_supply_max`, tudo em `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` inicializado com `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` computado a partir de parâmetros de curva + `base_supply_graduation` + `buy_numerator` (aproximadamente).

**Erros comuns** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (variante canônica: `BuyExactIn`)

Usuário fornece um `quote_in` fixo; a curva computa `base_out`.

**Argumentos**

```
quote_in:          u64
minimum_base_out:  u64
```

**Contas**

| # | Nome | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Pré-condições**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Efeito**

1. Dividir `quote_in` em `quote_in_after_fee` e as partes de taxa.
2. Resolver Newton a curva para `base_out` dado o quote pós-taxa.
3. `require(base_out ≥ minimum_base_out)` senão reverter `ExceededSlippage`.
4. Mover `quote_in` usuário → cofre. Mover `base_out` cofre → usuário.
5. Atualizar `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Atualizar contadores de taxa (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Se `quote_reserve_real ≥ quote_reserve_target` após a atualização, o SDK tipicamente encadeia uma ix `Graduate` na mesma transação. O programa não auto-gradua dentro de `Buy` — um `Graduate` subsequente é necessário.

## `BuyExactOut`

Usuário especifica o `base_out` exato; programa computa `quote_in`.

**Argumentos**

```
base_out:      u64
maximum_quote_in: u64
```

Mesmas contas que `BuyExactIn`. Usa a integral quadrática de forma fechada (ou inverso CPMM, para curve_type 1) em vez de iteração Newton.

## `Sell` / `SellExactIn` / `SellExactOut`

Espelho de `Buy`. Usuário retorna `base_in` à curva e recebe `quote_out`. A taxa é deduzida de `quote_out`, então o usuário recebe menos que os rendimentos integrados brutos.

**Pré-condições** —

- `user_base_ata.balance ≥ base_in`.
- Vender não pode empurrar `base_sold` abaixo de 0 (redundante com o acima dado que a contabilidade é consistente).
- Lançamento é `Active`.

**Efeito** — simétrico a `Buy`. `base_sold` diminui, `quote_reserve_real` diminui. Taxas ainda acumulam.

## `MigrateToAmm` / `MigrateToCpswap`

Graduar um lançamento em um pool negociável uma vez que a curva atingiu `total_quote_fund_raising`. Novos lançamentos são apenas CPMM. `MigrateToAmm` é retido para pools existentes cujo `migrate_type` armazenado é `0`.

**Quem assina**

- `MigrateToAmm` — a `migrate_to_amm_wallet` registrada na `GlobalConfig` vinculada.
- `MigrateToCpswap` — a `migrate_to_cpswap_wallet` registrada na `GlobalConfig` vinculada.

Essas carteiras são tipicamente mantidas pelo crank de graduação operado por Raydium; na prática a graduação ocorre segundos após o limite ser cruzado, independentemente de quem acionou a compra final.

**Argumentos**

`MigrateToAmm` leva três (principalmente parâmetros de mercado OpenBook que o programa encaminha para AMM v4):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` não leva nenhum.

**Efeito (comum a ambos)**

1. Verificar `pool_state.status == Migrate` (ou seja, `quote_reserve_target` foi atingido). Caso contrário, reverter com `PoolMigrated` (status já era `Migrated`) ou `PoolFunding` (ainda em financiamento).
2. Verificar `pool_state.migrate_type` corresponde à instrução (`0` para AMM, `1` para CPMM). Caso contrário, reverter com `MigrateTypeNotMatch`.
3. Computar as reservas pós-graduação:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI no programa de destino (`AMM v4 Initialize2` ou `CPMM InitializeWithPermission`) com essas reservas para criar o pool pós-graduação.
5. Para migrações CPMM executadas após a atualização de 2026-08-14, combinar `platform_scale + creator_scale` em uma participação de LP bloqueada de propriedade da plataforma e cunhar no máximo um NFT de Chave de Taxa para `platform_nft_wallet`. Queimar o restante `burn_scale`. Antes da atualização, `creator_scale` era bloqueado separadamente e sua Chave de Taxa ia para o criador do token. Migrações históricas concluídas não são modificadas. Para graduação legada AMM v4, a disposição de LP segue o fluxo existente dessa instrução.
6. Revogar `base_mint.mint_authority` (definir como `None`).
7. Virar `pool_state.status = Migrated`, definir `vesting_schedule.start_time = block_time + cliff_period`.

**Pós-condições** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` rejeitarão a partir deste ponto com `PoolMigrated`. O pool AMM resultante é canônico e negocia como qualquer outro pool AMM v4 / CPMM.

**Erros comuns** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### Contas restantes de migração CPMM

Clientes construindo `MigrateToCpswap` devem usar estes índices `remaining_accounts` fixos:

| Índice | Conta |
|---|---|
| 0–4 | Proprietário da Chave de Taxa de Plataforma, mint, conta de token, PDA de liquidez bloqueada e conta de metadados |
| 5 | Criador de lançamento original; usado quando `platform_cp_creator` não está definido |
| 6 | PDA de permissão CPMM derivado de `[b"permission", launch_authority]` |
| 7 | `platform_cp_creator` configurado; usado quando o campo não é padrão |
| 8 | PDA de mint de suporte CPMM para `mint0` ordenado, derivado de `[b"support_mint", mint0]` |
| 9 | PDA de mint de suporte CPMM para `mint1` ordenado, derivado de `[b"support_mint", mint1]` |

A instrução requer pelo menos dez contas restantes no caminho atualizado. As contas de mint de suporte são entradas CPI somente leitura. Derive ambos os endereços mesmo quando o mint não tem registro de suporte inicializado. Construtores mais antigos que ainda anexam contas de bloqueio de criador ou omitem índices 8–9 devem ser atualizados.

## Lista de permissões `GlobalConfig` de plataforma

`PlatformConfig.restrict_global_config` controla a verificação:

- `0`: a plataforma aceita qualquer `GlobalConfig` válido; nenhuma conta de permissão é necessária.
- `1`: `Initialize`, `InitializeV2` e `InitializeWithToken2022` devem incluir o `PlatformAllowConfig` correspondente em qualquer lugar em `remaining_accounts`.

O admin da plataforma cria ou fecha o PDA com `CreatePlatformAllowConfig` e `ClosePlatformAllowConfig`. Suas sementes são `[b"platform_allow_config", platform_config, global_config]`. As instruções `PlatformGlobalAccess` gerenciadas por admin anterior e PDA estão aposentadas.

## `CollectFee`

Varredura de admin das taxas de negociação acumuladas do protocolo em um único lançamento.

**Argumentos** — nenhum.

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `protocol_fee_owner` |   | S | Deve ser igual a `global_config.protocol_fee_owner`. |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`; assina a transferência do cofre. |
| 3 | `pool_state` | W |   | Mutado para zerar `quote_protocol_fee`. |
| 4 | `global_config` |   |   | Fonte de verdade para o signatário. |
| 5 | `quote_vault` | W |   | Drenado por `quote_protocol_fee`. |
| 6 | `recipient_token_account` | W |   | ATA de `protocol_fee_owner` em `quote_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | SPL Token (o mint de cotação é sempre SPL Token). |

**Efeito** — transferir `pool_state.quote_protocol_fee` de `quote_vault` para `recipient_token_account`, depois zerar o contador. Chamável a qualquer momento após a primeira compra.

## `CollectMigrateFee`

Varredura de admin da taxa de migração acumulada na graduação. Mesma forma de conta que `CollectFee` com `migrate_fee_owner` como signatário (em vez de `protocol_fee_owner`) e `pool_state.migrate_fee` como contador drenado.

## `ClaimCreatorFee`

Varredura por criador de taxas de criador acumuladas em **cada lançamento que o criador possui** que usa o mesmo mint de cotação. Drena o cofre de taxa por criador, não o por pool.

**Argumentos** — nenhum.

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `creator` | W | S | O criador do pool. |
| 2 | `fee_vault_authority` |   |   | PDA `[b"creator_fee_vault_auth_seed"]`. |
| 3 | `creator_fee_vault` | W |   | PDA em sementes `[creator, quote_mint]`; o cofre de criador agregado. |
| 4 | `recipient_token_account` | W |   | `init_if_needed`; ATA de `creator` em `quote_mint`. |
| 5 | `quote_mint` |   |   | |
| 6 | `token_program` |   |   | |
| 7 | `system_program` |   |   | Para criação de ATA se necessário. |
| 8 | `associated_token_program` |   |   | |

**Efeito** — transferir o saldo inteiro de `creator_fee_vault` para `recipient_token_account`. Reverte com uma verificação require-maior-que-zero se o cofre estiver vazio.

## `ClaimPlatformFee`

Varredura por plataforma que drena o cofre de cotação de um lançamento diretamente. Use isso quando uma plataforma quer reivindicar sua fatia para um lançamento específico sem passar pelo cofre de plataforma agregado.

**Argumentos** — nenhum.

**Contas**

| # | Nome | W | S | Notas |
|---|------|---|---|-------|
| 1 | `platform_fee_wallet` | W | S | Deve ser igual a `platform_config.platform_fee_wallet`. |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`. |
| 3 | `pool_state` | W |   | Drenado por `pool_state.platform_fee`. |
| 4 | `platform_config` |   |   | Fonte de verdade para o signatário. |
| 5 | `quote_vault` | W |   | Drenado. |
| 6 | `recipient_token_account` | W |   | `init_if_needed`; ATA de `platform_fee_wallet`. |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | |
| 9 | `system_program` |   |   | |
| 10 | `associated_token_program` |   |   | |

**Efeito** — transferir `pool_state.platform_fee` de `quote_vault` para `recipient_token_account`, zerar o contador.
