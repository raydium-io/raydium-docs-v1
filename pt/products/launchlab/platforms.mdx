<Info>
  Uma **Platform** no LaunchLab é um ambiente de lançamento de terceiros construído sobre o programa LaunchLab da Raydium. As plataformas podem se marcar, cobrar suas próprias taxas e configurar os parâmetros de migração pós-curva de ligação para cada token lançado sob elas — sem executar um programa separado na cadeia. A própria interface de lançamento da Raydium é apenas uma plataforma entre muitas.
</Info>

## Por que as plataformas existem

A Raydium queria que o LaunchLab fosse uma **primitiva compartilhada**, não um produto de marca única. O sistema Platform PDA permite que ecossistemas, provedores de ferramentas, comunidades e equipes de memes ofereçam experiências de lançamento curadas ou com marca própria que todas se resolvem no mesmo programa de curva de ligação LaunchLab subjacente e pool CPMM pós-migração.

Exemplos de plataformas que você pode encontrar:

- **Interface LaunchLab própria da Raydium** em raydium.io/launchlab — a implementação de referência.
- **Launchpads parceiros** — terceiros que registraram sua própria Platform PDA para marcar a experiência de lançamento.
- **Plataformas especializadas** — por exemplo, uma plataforma específica da comunidade que apenas lança memecoins vinculados a um tema particular, com uma divisão de taxa personalizada financiando seu tesouro.

Todos esses tokens ainda vivem no mesmo programa LaunchLab, se formam no mesmo programa CPMM e podem ser roteados pelos mesmos agregadores.

## A Platform PDA

Cada plataforma é representada por uma Platform PDA armazenada no programa LaunchLab. Os campos incluem:

| Campo | Descrição |
|---|---|
| `platform_key` | Seed / identificador da plataforma, usado para derivar a Platform PDA. |
| `platform_fee_destination` | Conta que recebe a parte da plataforma das taxas de negociação pré e pós-migração. |
| `platform_fee_bps` | Compartilhamento de taxa de plataforma em swaps pré-migração (varia por plataforma). |
| `creator_fee_rate` | Taxa de taxa do criador durante negociação em curva de ligação. |
| `platform_scale`, `creator_scale`, `burn_scale` | Escalas LP armazenadas. Antes da atualização, a escala do criador ia para uma Fee Key do criador. Para migrações executadas depois, as duas primeiras se combinam na participação de LP bloqueada da plataforma; `burn_scale` é queimado. |
| `cp_config_id` | Se o alvo pós-migração for CPMM, qual `AmmConfig` usar — escolhe o nível de taxa. |
| `restrict_global_config` | Se os lançamentos devem apresentar uma PDA de permissão criada pela plataforma para o `GlobalConfig` selecionado. |
| `name`, `description`, `image_url` | Metadados de exibição usados por carteiras e interfaces que suportam marca de plataforma. |
| `tokens_launched` | Contador ou índice na cadeia de tokens criados sob esta plataforma. |

Os nomes exatos dos campos estão no IDL do LaunchLab ([`sdk-api/anchor-idl`](/pt/sdk-api/anchor-idl)). A tabela acima é uma visão geral descritiva.

## O que uma plataforma pode controlar

**Captura de taxa:**

- **Compartilhamento de taxa de plataforma** em cada compra/venda pré-migração.
- **Compartilhamento pós-migração** — antes da atualização de 2026-08-17, a escala do criador produzia uma Fee Key de criador separada. Para migrações executadas depois, `platform_scale + creator_scale` se torna uma posição de LP bloqueada de propriedade da plataforma e `burn_scale` é queimado.

**Destino pós-migração:**

- **CPMM** com um `AmmConfig` escolhido via `cp_config_id`. Todos os lançamentos recém-inicializados usam CPMM.
- **AMM v4** permanece apenas como o caminho de formação para o estado de lançamento existente criado com o tipo de migração legado.

**Experiência do usuário:**

- **Metadados de marca** usados pelo aplicativo Raydium e por qualquer carteira / explorador que exiba tokens LaunchLab.
- **Personalização de página de lançamento** — plataformas que hospedam seu próprio frontend podem filtrar tokens para mostrar apenas os lançamentos de sua própria plataforma.

## O que uma plataforma não pode controlar

- **Matemática da curva de ligação.** A forma da curva (logística, exponencial, etc.) faz parte do próprio programa LaunchLab. As plataformas escolhem entre as curvas suportadas; elas não podem adicionar curvas personalizadas arbitrárias.
- **Lógica de limite de migração.** A condição que dispara a formação para CPMM é aplicada pelo programa.
- **Postura de segurança / auditoria principal.** Cada plataforma herda o histórico de auditoria do LaunchLab; uma plataforma maliciosa não pode contorná-lo alterando o programa.

## Registrando uma plataforma

O programa LaunchLab expõe uma instrução `create_platform` (nome exato do IDL). Os chamadores passam:

- A seed que derivará a Platform PDA.
- A conta de destino da taxa.
- Bps de taxa desejados (sujeito a limites de nível de programa).
- Configuração pós-migração (ID `AmmConfig` CPMM se aplicável).
- Metadados de marca.

O aluguel para a Platform PDA é pago pelo criador. Atualizações de marca e alguns parâmetros de taxa são permitidas pós-criação pela autoridade da plataforma; parâmetros estruturais (programa de destino de migração) normalmente não são.

Veja [`products/launchlab/instructions`](/pt/products/launchlab/instructions) para a assinatura exata da instrução no IDL atual do LaunchLab.

## Interação econômica

Um único swap em uma curva de ligação LaunchLab distribui valor aproximadamente assim (proporções exatas definidas pela plataforma):

```
Comprador paga:              100 SOL
Taxa de protocolo (LaunchLab): – pequeno %
Taxa de plataforma:          – platform_fee_bps%
Taxa do criador (pré-migração): – creator_fee_bps% (se habilitado)
Restante (para curva):       ~ resto
```

Pós-migração, tokens LP têm dois destinos efetivos:

```
Tokens LP cunhados na formação:  100%
  → Queimados:                      burnScale
  → Fee Key da plataforma:          platformScale + creatorScale
```

A Fee Key da plataforma representa direitos de taxa de LP reivindicáveis sem capacidade de sacar a liquidez bloqueada. LP queimado não tem titular de Fee Key.

## Restringindo configurações globais

Um administrador de plataforma pode definir `restrict_global_config = 1` e criar uma `PlatformAllowConfig` por `GlobalConfig` aceito. Novas transações de lançamento devem então anexar a PDA de permissão correspondente. Com restrição desabilitada, a plataforma aceita qualquer configuração que passe pela validação de outro programa.

## Notas para integradores

- **Listando tokens por plataforma.** Use os endpoints de informações de pool / mint da API com um filtro `platform` (quando suportado) para listar apenas tokens lançados sob uma Platform PDA específica.
- **Exibição de marca.** Se você construir uma carteira ou explorador que exiba tokens LaunchLab, ler o nome / URL de imagem da plataforma da Platform PDA é uma UX muito melhor do que mostrar "LaunchLab" para cada token.
- **Matemática de taxa.** Cada cotação de curva de ligação deve levar em conta a taxa de plataforma além das taxas de protocolo e criador. Os auxiliares de cotação do SDK fazem isso automaticamente quando a Platform PDA é fornecida.
