## Configuração

As demonstrações aqui espelham arquivos em [`raydium-sdk-V2-demo/src/launchpad`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/launchpad). O bootstrap segue o [`config.ts.template`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template) do repositório de demonstração:

```ts
import { Connection, Keypair, clusterApiUrl, PublicKey } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);
const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
export const txVersion = TxVersion.V0;
```

## Criar um lançamento

Fonte: [`src/launchpad/createMint.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/createMint.ts) (e [`createBonkMintApi.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/createBonkMintApi.ts) para a variante Bonk orientada por API)

A maioria dos parâmetros econômicos do lançamento **não** são argumentos — eles vêm da `GlobalConfig` que você vincula via `configId`, e o SDK preenche o resto com os parâmetros padrão da API. Você passa a identidade do mint, a configuração a vincular e (opcionalmente) uma primeira compra:

```ts
import {
  LAUNCHPAD_PROGRAM,
  DEVNET_PROGRAM_ID,
  LaunchpadConfig,
  getPdaLaunchpadConfigId,
} from "@raydium-io/raydium-sdk-v2";
import { Keypair, PublicKey } from "@solana/web3.js";
import { NATIVE_MINT } from "@solana/spl-token";

const programId = LAUNCHPAD_PROGRAM;          // devnet: DEVNET_PROGRAM_ID.LAUNCHPAD_PROGRAM

// O mint base é um keypair que você gera e assina.
const pair  = Keypair.generate();
const mintA = pair.publicKey;

// Vincule uma GlobalConfig: (quote mint, curve_type, index).
const configId = getPdaLaunchpadConfigId(programId, NATIVE_MINT, 0, 0).publicKey;
const configData = await raydium.connection.getAccountInfo(configId);
if (!configData) throw new Error("config not found");
const configInfo = LaunchpadConfig.decode(configData.data);
const mintBInfo = await raydium.token.getTokenInfo(configInfo.mintB);

const { execute, transactions, extInfo } = await raydium.launchpad.createLaunchpad({
  programId,
  mintA,
  decimals: 6,
  name:   "Example Token",
  symbol: "EXMPL",                 // deve ter 10 caracteres ou menos
  uri:    "https://example.com/metadata.json",   // deve ser não-vazio
  migrateType: "amm",              // "amm" | "cpmm"

  configId,
  configInfo,                      // opcional; o SDK relê configId quando omitido
  mintBDecimals: mintBInfo.decimals,
  mintBProgram:  new PublicKey(mintBInfo.programId),

  // Primeira compra opcional no mesmo bundle.
  createOnly: true,                // true = criar apenas o mint
  buyAmount:  new BN(1000),        // ignorado quando createOnly é true
  slippage:   new BN(100),         // 100 = 1%

  extraSigners: [pair],            // o keypair do mint base deve assinar
  txVersion: TxVersion.V0,

  // Os padrões vêm dos padrões da API da configuração vinculada; substitua apenas se necessário:
  // supply:            new BN(1_000_000_000_000_000),
  // totalSellA:        new BN(793_100_000_000_000),
  // totalFundRaisingB: new BN(85_000_000_000),   // 85 SOL quando mintB é SOL
  // totalLockedAmount: new BN(0),
  // cliffPeriod:       new BN(0),                // segundos
  // unlockPeriod:      new BN(0),                // segundos
  // platformId:        new PublicKey("4Bu96XjU84XjPDSpveTVf6LYGCkfW5FK7SNkREWcEfV4"), // padrão do Raydium
});

// createLaunchpad retorna MÚLTIPLAS transações - execute-as em ordem.
const { txIds } = await execute({ sequentially: true });
console.log("Pool:", extInfo.address.poolId.toBase58());
console.log("Base mint:", mintA.toBase58());
console.log("Create txs:", txIds);
```

Notas:

- **Não há** argumentos `curveType`, `graduationFractionBps`, `initialK`, `quoteMint`, `openTime`, `fees` ou `postGraduationLpPolicy`. A forma da curva e o quote mint são propriedades da `GlobalConfig` que você vincula; as taxas vivem em `GlobalConfig` e `PlatformConfig`; a disposição de LP na graduação é uma configuração de `PlatformConfig`. Veja [`products/launchlab/instructions`](/pt/products/launchlab/instructions#initialize) para exatamente o que `InitializeV2` aceita.
- `symbol` com mais de 10 caracteres e `uri` vazio são ambos rejeitados no lado do cliente antes de qualquer RPC.
- Passar `transferFeeExtensionParams` muda o builder para `InitializeWithToken2022` e força `migrateType` para `"cpmm"`.
- O builder retorna um array `transactions`; `createOnly: false` adiciona a transação de primeira compra. Sempre execute com `execute({ sequentially: true })` — o mint deve existir antes da compra chegar.

## Buscar estado do lançamento

Fonte: [`src/launchpad/poolInfo.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/poolInfo.ts)

Não há `getLaunchById`. O pool id é um PDA de `(programId, mintA, mintB)`, e `getRpcPoolInfo` retorna o `PoolState` decodificado com seu `configInfo` vinculado anexado:

```ts
import { getPdaLaunchpadPoolId, Curve } from "@raydium-io/raydium-sdk-v2";

const poolId = getPdaLaunchpadPoolId(programId, mintA, NATIVE_MINT).publicKey;
const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });

console.log("status:", poolInfo.status);
console.log("base sold:", poolInfo.realA.toString(), "/", poolInfo.totalSellA.toString());
console.log("quote raised:", poolInfo.realB.toString(), "/", poolInfo.totalFundRaisingB.toString());

// Preço spot atual na curva.
const price = Curve.getPrice({
  poolInfo,
  curveType: poolInfo.configInfo.curveType,
  decimalA: poolInfo.mintDecimalsA,
  decimalB: poolInfo.mintDecimalsB,
});
console.log("price:", price.toString());
```

`getRpcPoolsInfo({ poolIdList })` é a forma em lote e retorna um `poolInfoMap` indexado por pool id — use-o para visualizações de portfólio em vez de fazer loop. Se você quiser decodificar as contas brutas você mesmo, `LaunchpadPool.decode` e `LaunchpadConfig.decode` são exportados.

## Comprar — quote exato de entrada

Fonte: [`src/launchpad/buy.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/buy.ts)

O auxiliar de cotação off-chain é **`Curve.buyExactIn`**, um método estático na classe `Curve` exportada — não um método em `raydium.launchpad`. O builder de transação é **`buyToken`**. Ambos precisam das taxas de taxa da plataforma, que vivem em uma conta `PlatformConfig` separada:

```ts
import { Curve, PlatformConfig, toTransferFeeConfig } from "@raydium-io/raydium-sdk-v2";

const inAmount = new BN(1).mul(new BN(10).pow(new BN(9)));   // 1 SOL
const slippage = new BN(100);                                 // 100 = 1%

const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });
const platformData = await raydium.connection.getAccountInfo(poolInfo.platformId);
const platformInfo = PlatformConfig.decode(platformData!.data);

const mintInfo  = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(poolInfo.mintB);
const epochInfo = await raydium.connection.getEpochInfo();

// Visualização off-chain — espelha a matemática da curva on-chain.
const res = Curve.buyExactIn({
  poolInfo,
  amountB: inAmount,
  protocolFeeRate: poolInfo.configInfo.tradeFeeRate,
  platformFeeRate: platformInfo.feeRate,
  creatorFeeRate:  platformInfo.creatorFeeRate,
  curveType:       poolInfo.configInfo.curveType,
  shareFeeRate:    new BN(0),
  transferFeeConfigA: mintInfo.extensions.feeConfig  ? toTransferFeeConfig(mintInfo,  epochInfo.epoch) : undefined,
  transferFeeConfigB: mintBInfo.extensions.feeConfig ? toTransferFeeConfig(mintBInfo, epochInfo.epoch) : undefined,
  slot: await raydium.connection.getSlot(),
});
console.log("expected out:", res.amountA.amount.sub(res.amountA.fee ?? new BN(0)).toString());

const { execute, extInfo } = await raydium.launchpad.buyToken({
  programId,
  mintA,
  mintAProgram: new PublicKey(mintInfo.programId),
  mintB:        poolInfo.mintB,
  mintBProgram: new PublicKey(mintBInfo.programId),
  transferFeeConfigB: toTransferFeeConfig(mintBInfo, epochInfo.epoch),
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,
  buyAmount:       inAmount,
  slippage,                       // BN em bps; o SDK deriva minMintAAmount a partir dele
  txVersion: TxVersion.V0,
});

console.log("expected receive amount:", extInfo.decimalOutAmount.toString());
const { txId } = await execute({ sendAndConfirm: true });
console.log("Buy tx:", txId);
```

Você pode passar `minMintAAmount` explicitamente em vez de `slippage`; omita ambos e o SDK calcula o limite a partir de dados RPC ao vivo. `shareFeeRate` não deve exceder `poolInfo.configInfo.maxShareFeeRate`, e só se aplica quando você também passa um `shareFeeReceiver`.

## Comprar — base exata de saída

O builder é **`buyTokenExactOut`**, e os argumentos de quantidade são `outAmount` (base que você quer) e `maxBuyAmount` (quote que você gastará no máximo). `Curve.buyExactOut({ poolInfo, amountA, ... })` é a visualização off-chain correspondente.

```ts
const { execute, extInfo } = await raydium.launchpad.buyTokenExactOut({
  programId,
  mintA,
  mintAProgram: new PublicKey(mintInfo.programId),
  mintB:        poolInfo.mintB,
  mintBProgram: new PublicKey(mintBInfo.programId),
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,

  outAmount:    new BN(1_000_000).mul(new BN(10).pow(new BN(6))),  // 1M base
  maxBuyAmount: new BN(2).mul(new BN(10).pow(new BN(9))),          // limite em 2 SOL
  slippage:     new BN(100),

  txVersion: TxVersion.V0,
});

console.log("out:", extInfo.outAmount.toString(), "max spent:", extInfo.maxSpentAmount.toString());
await execute({ sendAndConfirm: true });
```

Útil para UIs "compre exatamente X tokens". O builder rejeita um `outAmount` de zero no lado do cliente, e o programa reverte se a curva se moveu o suficiente para que o requisito de quote exceda `maxBuyAmount`.

## Vender

Fonte: [`src/launchpad/sell.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/sell.ts)

O builder é **`sellToken`** (`sellTokenExactOut` para a variante de quote exato de saída), com `sellAmount` e um `minAmountB` opcional. `Curve.sellExactIn({ poolInfo, amountA, ... })` visualiza isso.

```ts
const inAmount = new BN(500_000).mul(new BN(10).pow(new BN(6)));  // 0.5M base

const res = Curve.sellExactIn({
  poolInfo,
  amountA: inAmount,
  protocolFeeRate: poolInfo.configInfo.tradeFeeRate,
  platformFeeRate: platformInfo.feeRate,
  creatorFeeRate:  platformInfo.creatorFeeRate,
  curveType:       poolInfo.configInfo.curveType,
  shareFeeRate:    new BN(0),
  transferFeeConfigA: mintInfo.extensions.feeConfig  ? toTransferFeeConfig(mintInfo,  epochInfo.epoch) : undefined,
  transferFeeConfigB: mintBInfo.extensions.feeConfig ? toTransferFeeConfig(mintBInfo, epochInfo.epoch) : undefined,
  slot: await raydium.connection.getSlot(),
});
console.log("expected quote out:", res.amountB.toString());

const { execute } = await raydium.launchpad.sellToken({
  programId,
  mintA,
  mintAProgram: new PublicKey(mintInfo.programId),
  mintB:        poolInfo.mintB,
  mintBProgram: new PublicKey(mintBInfo.programId),
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,
  sellAmount:      inAmount,
  slippage:        new BN(100),
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

O caminho de venda da curva é simétrico ao caminho de compra: reduzir `real_a` por `sellAmount` retorna `quote_out` igual à área integrada sob a curva entre `real_a − sellAmount` e `real_a`, menos a taxa de venda. `sellAmount` deve ser maior que zero — o builder rejeita zero antes de qualquer RPC.

## Graduação

<Warning>
  **Graduação não é algo que um integrador possa disparar.** Não há `raydium.launchpad.graduate`, nenhuma flag `autoGraduate` nos builders de compra, e nenhum campo `willGraduate` no valor de retorno deles. On-chain, graduação é `MigrateToCpswap` (ou o legado `MigrateToAmm`), e ambas as instruções restringem seu signatário a uma carteira registrada na `GlobalConfig` de ligação — `migrate_to_cpswap_wallet` e `migrate_to_amm_wallet` respectivamente. Uma chamada de qualquer outro signatário falha com `InvalidOwner`. **Não é** sem permissão, e nenhum bot de MEV pode corrê-la.
</Warning>

Essas carteiras são operadas pelo crank de graduação do Raydium, então na prática a migração chega segundos após o limite ser cruzado, independentemente de quem fez a compra final. Do lado do integrador, a única coisa a fazer é tratar a transição de status como um evento rápido: pesquise `getRpcPoolInfo` (ou inscreva-se via gRPC, abaixo) e mude sua UI da curva para o pool CPMM resultante quando `status` mudar.

Veja [`products/launchlab/instructions`](/pt/products/launchlab/instructions#migratetoamm-/-migratetocpswap) para as listas de contas, a taxa de migração e como o LP é dividido na graduação.

## Coletar taxas do criador

Fonte: [`src/launchpad/claimCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/claimCreatorFee.ts) (mint único) e [`collectAllCreatorFees.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/collectAllCreatorFees.ts) (em lote)

O método é **`claimCreatorFee`** (e `claimMultipleCreatorFee` para a forma em lote). É indexado pelo **quote mint**, não por um lançamento — uma chamada varre as taxas de criador acumuladas do signatário nesse mint em todos os seus lançamentos:

```ts
import { NATIVE_MINT } from "@solana/spl-token";

const { execute } = await raydium.launchpad.claimCreatorFee({
  programId,
  mintB: NATIVE_MINT,          // o quote mint para reivindicar
  // mintBProgram: TOKEN_PROGRAM_ID,   // ou TOKEN_2022_PROGRAM_ID
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Transfere o contador de taxa de criador acumulado para o ATA do criador no quote mint. Pode ser chamado pré ou pós-graduação; use-o periodicamente em vez de esperar um saldo enorme se acumular. Operadores de plataforma têm os builders paralelos `claimPlatformFee` / `claimAllPlatformFee` / `claimVaultPlatformFee`.

## Rastrear um lançamento através de seu ciclo de vida

Juntando tudo, um script de monitoramento pode parecer:

```ts
async function watch(poolId: PublicKey) {
  const startStatus = (await raydium.launchpad.getRpcPoolInfo({ poolId })).status;

  while (true) {
    const p = await raydium.launchpad.getRpcPoolInfo({ poolId });
    const progress = Number(p.realB.toString()) / Number(p.totalFundRaisingB.toString());

    console.log(`status=${p.status}`, `progress=${(progress * 100).toFixed(2)}%`);

    if (p.status !== startStatus) {
      console.log("status changed - the launch has migrated; switch to the pool page");
      break;
    }
    await new Promise((r) => setTimeout(r, 10_000));
  }
}
```

Pesquisar `getRpcPoolInfo` em um timer de 10 segundos é bom para um único lançamento. Para um indexador, use a inscrição gRPC abaixo — `getRpcPoolsInfo({ poolIdList })` faz lote, mas pesquisar centenas de pools ainda queima créditos RPC sem benefício.

## Assistir configs e pools via gRPC

Fonte: [`src/grpc/launchpadPoolInfo.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/grpc/launchpadPoolInfo.ts)

Inscreve-se no programa LaunchLab via Yellowstone gRPC e registra cada atualização de `GlobalConfig` e `PoolState` com o programa de token de cada mint. Dois filtros `datasize` em uma inscrição `accounts` separam os dois tipos de conta, então um único stream cobre ambos.

A demonstração é a referência mais curta e correta para classificar os mints de um lançamento, o que a [versão de quote mint Token-2022](/pt/reference/changelog/2026-08-24-launchlab-token2022-quote-mint) torna necessário:

- **Pools** são classificados diretamente de `PoolState.token_program_flag`, decodificando bit0 para o mint base e bit1 para o quote mint sem qualquer busca de mint. Testar o byte inteiro contra `0` — que era suficiente enquanto os quote mints eram apenas legados — malinterpreta um mint base legado como Token-2022 sempre que o quote mint é Token-2022.
- **Configs** não podem ser classificados dessa forma: um `GlobalConfig` armazena o endereço do seu quote mint e nenhuma flag de programa, então a demonstração lê o proprietário da conta de mint uma vez e o armazena em cache por mint.

Também faz verificação cruzada dos dois um contra o outro, o que é uma asserção útil para manter em seu próprio indexador. Note que `create` versus `update` é inferido dos próprios caches da demonstração, inicializados na inicialização a partir de `getProgramAccounts`; com essa inicialização desabilitada, leia "create" como "primeiro visto neste stream".

O acesso gRPC não faz parte da superfície RPC pública — veja o [`src/grpc/README.md`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/grpc/README.md) do repositório de demonstração.

## Rust CPI

Chamar LaunchLab a partir de seu próprio programa Anchor é raro (a maioria das integrações de lançamento são apenas do lado TS). Se você fizer:

- O crate é **`raydium-launchpad`** (nome da lib `raydium_launchpad`), versão `0.2.0`, e expõe um recurso `cpi`. **Não há** `raydium_launchlab`.
- **Não é publicado em crates.io** — dependa dele por revisão git, da mesma forma que os outros crates do programa Raydium.
- Os pontos de entrada CPI são nomeados após as instruções on-chain, não após os métodos TypeScript do SDK: `buy_exact_in`, `buy_exact_out`, `sell_exact_in`, `sell_exact_out`, `claim_creator_fee`, `create_vesting_account`, `claim_vested_token`. `migrate_to_amm` / `migrate_to_cpswap` são gated por signatário para as carteiras de migração `GlobalConfig` e não são chamáveis a partir de um programa integrador.

Veja [`sdk-api/rust-cpi`](/pt/sdk-api/rust-cpi) para as regras de fixação de crate — em particular a divisão de versão do Anchor, que decide se um crate pode fazer CPI tanto em LaunchLab quanto em CLMM.

## Armadilhas

- **Confundir nomes de instruções on-chain com nomes de métodos SDK.** O programa tem `buy_exact_in` / `sell_exact_in`; o SDK tem `buyToken` / `sellToken`. `buyExactIn` e `sellExactIn` existem apenas como **métodos estáticos em `Curve`**, e computam uma cotação — eles não constroem uma transação.
- **Esquecer `extraSigners`.** `createLaunchpad` cria o mint base a partir de um keypair que você gera, então esse keypair tem que assinar. Omita `extraSigners: [pair]` e a transação falha na verificação de assinatura.
- **Não escolher o quote mint.** Você não passa um. O quote mint é uma propriedade da `GlobalConfig` que você vincula através de `configId` — `getPdaLaunchpadConfigId(programId, quoteMint, curveType, index)`. Para lançar contra um quote mint diferente, vincule uma configuração diferente; `raydium.api.fetchLaunchConfigs()` lista as disponíveis com seus parâmetros padrão.
- **Tamanho de metadados.** Strings `uri` longas empurram o CPI do Metaplex sobre o orçamento. Mantenha `uri` sob ~200 caracteres — a maioria dos metadados JSON hospedados em CDN se encaixa facilmente. `symbol` é limitado a 10 caracteres.
- **Tratar graduação como uma corrida que você pode entrar.** Não é — veja o aviso acima. Sua UI ainda deve tratar transições de `status` como eventos rápidos, porque o crank do Raydium chega a migração dentro de segundos após o limite ser cruzado.
