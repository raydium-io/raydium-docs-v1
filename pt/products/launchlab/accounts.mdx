Esta página documenta o grafo de contas **por lançamento**: a `PoolState` (a conta de estado raiz para um lançamento), seus dois vaults, a PDA de autoridade e as referências pós-graduação que ela ganha quando o lançamento se liquida.

Para a configuração em nível de protocolo que limita cada lançamento, consulte [`products/launchlab/global-config`](/pt/products/launchlab/global-config). Para a sobreposição por plataforma, consulte [`products/launchlab/platform-config`](/pt/products/launchlab/platform-config). Para contas de vesting (`VestingSchedule` em `PoolState`, `VestingRecord` por beneficiário), consulte [`products/launchlab/vesting`](/pt/products/launchlab/vesting).

O método `raydium.launchpad.getLaunchById` do SDK retorna `PoolState` mais um sinalizador indicando se o lançamento foi graduado; se foi, o ID do pool pós-migração é incluído.

## `PoolState`

O estado raiz por lançamento. Os nomes de campo abaixo correspondem à struct Rust on-chain (`states/pool.rs`); alguns valores são simplificados para legibilidade — consulte a fonte para o layout exato de memória.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Valores de `PoolStatus` (do IDL Anchor):

```
0 = Funding         — accepting buys / sells; below quote_reserve_target
1 = Migrate         — quote_reserve_target reached; awaiting MigrateTo*
2 = Migrated        — MigrateTo* already executed; vesting clock running
```

Campos voltados para integradores:

- **`status`** — três valores, monotônicos (Funding → Migrate → Migrated). Leituras sempre seguras; escritas controladas.
- **`real_base`**, **`real_quote`** — estado atual da curva. Combinados com `virtual_base` / `virtual_quote` são suficientes para calcular o preço spot sem tocar nos vaults. Consulte [`bonding-curve`](/pt/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — razão de "progresso em direção à graduação" para UIs.
- **`migrate_type`** — nova inicialização requer `1` (`CPSWAP`). Um `0` armazenado permanece significativo apenas para um lançamento existente criado antes da aplicação exclusiva de CPMM.
- **`amm_creator_fee_on`** — escolhe `creator_fee_on = OnlyQuoteToken` (`0`) ou `BothToken` (`1`) no pool CPMM pós-graduação. Não escolhe o alvo de migração. Consulte [`creator-fees`](/pt/products/launchlab/creator-fees).
- **`token_program_flag`** — um campo de bits, não um booleano. Bit0 é o mint base e bit1 é o mint quote, cada um `0` para SPL Token e `1` para Token-2022, então o byte assume quatro valores: `0` (ambos legados), `1` (Token-2022 base), `2` (Token-2022 quote), `3` (ambos Token-2022). Leia um mint com `(token_program_flag >> bit) & 1`. Comparar o byte inteiro contra `0` para classificar o mint base resolve `2` para o programa errado. Bit1 era constante `0` até que mints quote Token-2022 fossem suportados.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — três contadores de taxa independentes. Cada um tem sua própria instrução de reivindicação; consulte [`instructions`](/pt/products/launchlab/instructions).
- **`vesting_schedule`** — presente em cada `PoolState` mas inativo quando `total_locked_amount == 0`. Consulte [`vesting`](/pt/products/launchlab/vesting) para o ciclo de vida completo.

## A PDA de autoridade

LaunchLab usa uma **única** PDA de autoridade em todos os lançamentos, derivada sem seed por lançamento:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Essa PDA única é:

- A autoridade em cada `base_vault` e `quote_vault` de lançamento.
- A `mint_authority` em cada mint base de lançamento (pré-graduação).
- O signatário no CPI de graduação CPMM e na graduação AMM v4 legada para estado existente.
- O signatário em transferências `ClaimVestedToken` para fora do vault base.
- A `transfer_fee_config_authority` em um `TransferFeeConfig` de mint base Token-2022, para toda a fase pré-graduação — e sua `withdraw_withheld_authority` também, mas apenas quando a plataforma deixou `PlatformConfig.transfer_fee_extension_auth` não definido.

A `mint_authority` é revogada imediatamente após `MigrateToCpswap` ou uma chamada legada `MigrateToAmm`, então o fornecimento é permanentemente fixo.

Duas PDAs adicionais controlam os vaults de taxa:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Estas assinam a transferência para fora dos vaults de taxa correspondentes durante `ClaimCreatorFee` e `ClaimPlatformFeeFromVault`.

## Mint base

Criado inline por `Initialize` com:

- `mint_authority = authority` (revogado na graduação).
- `freeze_authority = None`.
- `supply = supply`, totalmente cunhado em `base_vault`.
- `decimals` escolhido pelo criador em `Initialize` (comumente 6).

Como o fornecimento completo é pré-cunhado, `base_mint.supply` é constante durante a vida do lançamento. Compras de curva movem tokens de `base_vault` para o comprador, mas não chamam `mint_to`.

`Initialize` / `InitializeV2` criam mints base SPL Token. A instrução dedicada `InitializeWithToken2022` permite que o mint base seja um mint Token-2022 (com `TransferFeeConfig` opcional). Todos os três caminhos de inicialização requerem graduação CPMM.

Quando `InitializeWithToken2022` anexa um `TransferFeeConfig`, o mint é criado com `transfer_fee_config_authority = authority` e `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`, voltando para `authority` quando a plataforma não definiu esse campo. Ambas as autoridades são reatribuídas à chave de plataforma na graduação, o lado de retirada apenas se a PDA ainda a mantiver. Consulte [`platform-config`](/pt/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

O mint quote é independente do mint base e pode ser um mint Token-2022 — `InitializeV2` e `InitializeWithToken2022` aceitam qualquer programa em seu slot de programa quote. O `Initialize` descontinuado não: sua conta de programa quote ainda é tipada para SPL Token, então uma configuração cujo mint quote é Token-2022 só pode ser lançada através das outras duas. O mint quote nunca é criado por LaunchLab; é o que `GlobalConfig.quote_mint` nomeia. Consulte [`global-config`](/pt/products/launchlab/global-config#token-2022-quote-mints) e [`reference/token-2022-support`](/pt/reference/token-2022-support#launchlab-quote-mints).

## Vaults

Tanto `base_vault` quanto `quote_vault` são contas de token possuídas pela PDA `authority` do LaunchLab, cada uma criada no programa que possui seu próprio mint — então um lançamento pode ter um vault base legado e um vault quote Token-2022, ou qualquer outra combinação. `token_program_flag` registra qual é qual. Os endereços são armazenados em `PoolState` e também podem ser derivados:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Verifique os prefixos de seed exatos da struct de contas `Initialize` da fonte antes de confiar em uma derivação em produção.)

## Vaults de taxa

Duas PDAs agregam taxas em lançamentos:

- **Vault de taxa de criador** — PDA com seeds `[creator, quote_mint]`. Cada lançamento que ganha as mesmas taxas de criador no mesmo mint quote despeja no mesmo vault. O criador o varre via `ClaimCreatorFee`.
- **Vault de taxa de plataforma** — PDA com seeds `[platform_config, quote_mint]`. Cada lançamento roteado através da mesma plataforma que usa o mesmo mint quote despeja no mesmo vault. A `platform_fee_wallet` da plataforma o varre via `ClaimPlatformFeeFromVault`. Há também uma variante de varredura por lançamento (`ClaimPlatformFee`) que puxa do `quote_vault` do lançamento diretamente sem passar pelo vault agregado.

Ambos são criados preguiçosamente no primeiro swap que acumula uma taxa, no programa que possui o mint quote. Um criador ou plataforma que executa lançamentos contra um mint quote legado e um Token-2022 acaba com um vault por mint, como já fazia para dois mints legados diferentes.

O padrão de vault agregado é o que permite que um criador ou plataforma de alto volume amortize o custo de aluguel da acumulação de taxa em muitos lançamentos.

## Quote vault ↔ `real_quote`

`quote_vault.balance` e `PoolState.real_quote` devem permanecer sincronizados. Podem divergir no máximo pela soma dos três contadores de taxa pendentes (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), que ficam no vault mas pertencem aos contadores de taxa e não à reserva de curva. A matemática de curva sempre usa `real_quote`, nunca o saldo bruto do vault.

Invariante pré-graduação:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## `PlatformCurveRule`

Uma conta por par `(PlatformConfig, GlobalConfig)`, contendo as formas de lançamento que a plataforma permite nessa configuração. As seeds da PDA são `[b"platform_curve_rule", platform_config, global_config]`.

```rust
#[account]
pub struct PlatformCurveRule {
    pub bump:            u8,
    pub version:         u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub epoch:           u64,
    pub padding:         [u64; 8],
    pub groups:          Vec<CurveRuleGroup>,   // up to 10
}

pub struct CurveRuleGroup {
    pub group_id:    u16,                       // stable id, used to update or remove the group
    pub epoch:       u64,
    pub constraints: Vec<ParamConstraint>,      // up to 25, ANDed
}

pub struct ParamConstraint {
    pub field: u8,                              // which launch parameter
    pub op:    u8,                              // 0 Eq, 1 Gte, 2 Lte, 3 Neq
    pub value: u128,
}
```

A conta é criada sem grupo e redimensionada a cada mudança de grupo, então seu comprimento é `150 + Σ(14 + 18 × constraints)` e decodificadores não devem assumir um tamanho fixo. Grupos são ORados: um lançamento é permitido assim que as restrições de um grupo todas se mantêm. Zero grupos significa sem restrição.

Leia apenas quando o `PlatformConfig.restrict_curve_param` proprietário for `1` — em `0` o programa ignora a conta e uma regra obsoleta pode estar lá. IDs de campo, operadores e os playbooks estão em [`products/launchlab/curve-rules`](/pt/products/launchlab/curve-rules).

## Transições de contas do ciclo de vida

| Evento | Status | `real_base` | `real_quote` | Pool pós-graduação |
|--------|--------|-------------|--------------|-------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (ou legado `MigrateToAmm`) | Funding → Migrate → Migrated | (congelado) | (congelado) | criado; LP CPMM é dividido em LP bloqueado de propriedade de plataforma e LP queimado |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | qualquer | — | — | drena um vault de taxa |
| `CreateVestingAccount` | Funding | — | — | aumenta `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated apenas | — | — | drena `base_vault` |
