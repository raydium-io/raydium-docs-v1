## Inventário de contas

| Conta | Proprietário | Propósito |
|---------|-------|---------|
| [`GlobalConfig`](/pt/products/launchlab/global-config) | Programa LaunchLab | Regras em nível de protocolo: taxas, pisos de fornecimento, carteiras de migração. Uma por `(curve_type, index)`. |
| [`PlatformConfig`](/pt/products/launchlab/platform-config) | Programa LaunchLab | Sobreposição por plataforma: marca, taxa de plataforma, divisão de NFT na graduação, whitelist de forma de curva. |
| `PoolState` | Programa LaunchLab | Estado raiz por lançamento: mints, vaults, parâmetros de curva, contadores de vendas, contadores de taxas, cronograma de vesting, status de graduação. |
| `authority` | Programa LaunchLab | PDA única com seed `[b"vault_auth_seed"]` que possui vaults em todos os lançamentos e assina o CPI pós-graduação. |
| `base_vault` | SPL Token / Token-2022 | Vault por lançamento contendo os tokens base não vendidos. |
| `quote_vault` | SPL Token | Vault por lançamento contendo tokens quote acumulados. |
| [`VestingRecord`](/pt/products/launchlab/vesting) | Programa LaunchLab | Registro por beneficiário de cliff + desbloqueio linear. Opcional. |
| `creator_fee_vault` | SPL Token | Vault por criador + por mint de quote contendo taxas de criador acumuladas, limpas por `ClaimCreatorFee`. |
| `platform_fee_vault` | SPL Token | Vault por plataforma + por mint de quote contendo taxas de plataforma acumuladas, limpas por `ClaimPlatformFeeFromVault`. |
| [`PlatformAllowConfig`](/pt/products/launchlab/platform-config) | Programa LaunchLab | Permissão opcional gerenciada pela plataforma para um par `(PlatformConfig, GlobalConfig)`. Verificada apenas quando a plataforma ativa restrição. |
| (pós-graduação) `cpmm_pool_state` | Programa CPMM | Pool criado por `MigrateToCpswap` para cada novo lançamento. O estado legado ainda pode referenciar uma graduação AMM v4. |
| (pós-graduação) Fee Key NFT | Programa LP-Lock | Antes da atualização de 2026-08-14, escalas de plataforma e criador podiam produzir Fee Keys separadas. Migrações executadas depois combinam ambas as escalas em uma Fee Key de plataforma. |

O método `raydium.launchpad.getLaunchById` do SDK retorna `PoolState` mais um sinalizador indicando se o lançamento foi graduado; se foi, o ID do pool pós-migração é incluído.

## `PoolState`

O estado raiz por lançamento. Os nomes de campo abaixo correspondem ao struct Rust on-chain (`states/pool.rs`); alguns valores são simplificados para legibilidade — consulte a fonte para o layout exato de memória.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit flags for SPL Token vs Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Valores de `PoolStatus` (do IDL Anchor):

```
0 = Funding         — accepting buys / sells; below quote_reserve_target
1 = Migrate         — quote_reserve_target reached; awaiting MigrateTo*
2 = Migrated        — MigrateTo* already executed; vesting clock running
```

Campos voltados para integradores:

- **`status`** — três valores, monotônicos (Funding → Migrate → Migrated). Leituras sempre seguras; escritas controladas.
- **`real_base`**, **`real_quote`** — estado atual da curva. Combinados com `virtual_base` / `virtual_quote` são suficientes para calcular o preço spot sem acessar os vaults. Consulte [`bonding-curve`](/pt/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — razão de "progresso em direção à graduação" para UIs.
- **`migrate_type`** — nova inicialização requer `1` (`CPSWAP`). Um `0` armazenado permanece significativo apenas para um lançamento existente criado antes da aplicação exclusiva de CPMM.
- **`amm_creator_fee_on`** — escolhe `creator_fee_on = OnlyQuoteToken` (`0`) ou `BothToken` (`1`) no pool CPMM pós-graduação. Não escolhe o alvo de migração. Consulte [`creator-fees`](/pt/products/launchlab/creator-fees).
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — três contadores de taxa independentes. Cada um tem sua própria instrução de reivindicação; consulte [`instructions`](/pt/products/launchlab/instructions).
- **`vesting_schedule`** — presente em cada `PoolState` mas inativo quando `total_locked_amount == 0`. Consulte [`vesting`](/pt/products/launchlab/vesting) para o ciclo de vida completo.

## A PDA de autoridade

LaunchLab usa uma **única** PDA de autoridade em todos os lançamentos, derivada sem seed por lançamento:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Essa PDA única é:

- A autoridade em cada `base_vault` e `quote_vault` de lançamento.
- A `mint_authority` em cada `base_mint` de lançamento (pré-graduação).
- A signatária no CPI de graduação CPMM e na graduação AMM v4 legada para estado existente.
- A signatária em transferências `ClaimVestedToken` para fora do vault de base.

A `mint_authority` é revogada imediatamente após `MigrateToCpswap` ou uma chamada legada `MigrateToAmm`, então o fornecimento é permanentemente fixado.

Duas PDAs adicionais controlam os vaults de taxa:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Essas assinam a transferência para fora dos vaults de taxa correspondentes durante `ClaimCreatorFee` e `ClaimPlatformFeeFromVault`.

## Mint de base

Criado inline por `Initialize` com:

- `mint_authority = authority` (revogada na graduação).
- `freeze_authority = None`.
- `supply = supply`, totalmente cunhado em `base_vault`.
- `decimals` escolhido pelo criador em `Initialize` (comumente 6).

Como o fornecimento completo é pré-cunhado, `base_mint.supply` é constante durante a vida do lançamento. Compras de curva movem tokens de `base_vault` para o comprador, mas não chamam `mint_to`.

`Initialize` / `InitializeV2` criam lançamentos SPL Token. A instrução dedicada `InitializeWithToken2022` permite que o mint de base seja um mint Token-2022 (com `TransferFeeConfig` opcional); o mint de quote ainda é SPL Token. Todos os três caminhos de inicialização requerem graduação CPMM.

## Vaults

Tanto `base_vault` quanto `quote_vault` são contas SPL Token padrão possuídas pela PDA `authority` do LaunchLab. Os endereços são armazenados em `PoolState` e também podem ser derivados:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Verifique os prefixos exatos de seed da struct de contas `Initialize` da fonte antes de confiar em uma derivação em produção.)

## Vaults de taxa

Duas PDAs agregam taxas em lançamentos:

- **Vault de taxa de criador** — PDA com seeds `[creator, quote_mint]`. Cada lançamento que ganha as mesmas taxas de criador no mesmo mint de quote despeja no mesmo vault. O criador o limpa via `ClaimCreatorFee`.
- **Vault de taxa de plataforma** — PDA com seeds `[platform_config, quote_mint]`. Cada lançamento roteado através da mesma plataforma que usa o mesmo mint de quote despeja no mesmo vault. A `platform_fee_wallet` da plataforma o limpa via `ClaimPlatformFeeFromVault`. Há também uma variante de limpeza por lançamento (`ClaimPlatformFee`) que puxa do `quote_vault` do lançamento diretamente sem passar pelo vault agregado.

O padrão de vault agregado é o que permite que um criador ou plataforma de alto volume amortize o custo de aluguel da acumulação de taxas em muitos lançamentos.

## Quote vault ↔ `real_quote`

`quote_vault.balance` e `PoolState.real_quote` devem permanecer sincronizados. Podem divergir no máximo pela soma dos três contadores de taxa pendentes (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), que ficam no vault mas pertencem aos contadores de taxa e não à reserva de curva. A matemática da curva sempre usa `real_quote`, nunca o saldo bruto do vault.

Invariante pré-graduação:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## Transições de contas do ciclo de vida

| Evento | Status | `real_base` | `real_quote` | Pool pós-graduação |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (ou legado `MigrateToAmm`) | Funding → Migrate → Migrated | (congelado) | (congelado) | criado; LP CPMM é dividido em LP bloqueado de propriedade da plataforma e LP queimado |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | qualquer | — | — | drena um vault de taxa |
| `CreateVestingAccount` | Funding | — | — | aumenta `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated apenas | — | — | drena `base_vault` |
