### Autoridade de administrador compartilhada

Cada programa Raydium — incluindo AMM v4 — compartilha uma única `Pubkey` de administrador codificada para controle de acesso em nível de instrução para caminhos de administrador. É `config_feature::amm_owner::ID` no AMM v4 (controlando `SetParams`, `CreateConfigAccount` e `UpdateConfigAccount`, e usado como `pnl_owner` padrão) e `admin::ID` nos programas Anchor — CLMM, CPMM, LaunchLab, Lock — controlando caminhos como `CreateAmmConfig` ou `UpdatePoolStatus`:

| mainnet-beta | `GThUX1Atko4tqhN2NaiTazWSeFWMuiUvfFnyJyUghFMJ` |
| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

As autoridades operacionais em nível de conta (por exemplo, `protocol_owner`, `fund_owner` em `AmmConfig` CPMM/CLMM, ou as carteiras de migração em `GlobalConfig` LaunchLab) são armazenadas on-chain e podem diferir do administrador do programa. Leia-as diretamente da conta de configuração relevante antes de enviar transações de alto risco.

### Sementes de PDA

As sementes abaixo são **canônicas** e usadas tanto pelo SDK quanto por CPIs on-chain. Sempre calcule PDAs; não codifique endereços derivados.

```ts
// CPMM — todas as sementes são strings ASCII estáticas a menos que indicado.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` são **ordenados por ordem de byte de chave pública** (token0 < token1) antes de fazer hash. Fazer isso errado produz um PDA válido para um pool inexistente.

As sementes CLMM equivalentes seguem o mesmo estilo; veja [`products/clmm/accounts`](/pt/products/clmm/accounts).

## Como verificar um endereço on-chain

1. **Solana Explorer.** Cole o endereço em [explorer.solana.com](https://explorer.solana.com) e confirme que está marcado como `Program` com uma autoridade de atualização atual. Mainnet-beta deve mostrar implantações assinadas pela autoridade de atualização do Raydium.
2. **CLI.** Use `solana program show <PROGRAM_ID> -u mainnet-beta` para inspecionar slot de implantação, carregador BPF, autoridade de atualização e comprimento de dados. Registre estes em seu runbook.
3. **Anexo de IDL.** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` funciona para **CLMM, LaunchLab e Lock**, que ainda mantêm uma conta `anchor:idl` legada de propriedade do programa. **Não** funciona para CPMM: o IDL on-chain do CPMM foi movido para o programa Program Metadata (`ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S`) na atualização de 2026-09, então busque-o de lá. AMM v4, Stable AMM e Farm não têm IDL on-chain. Os IDLs são espelhados em [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — compare o IDL on-chain com o repositório antes de confiar nele.
4. **Autoridades de configuração/administrador.** Para contas de configuração CPMM/CLMM, leia o campo `owner`/`protocol_owner` e confirme que corresponde ao multisig Raydium atual publicado em [`security/admin-and-multisig`](/pt/security/admin-and-multisig).
