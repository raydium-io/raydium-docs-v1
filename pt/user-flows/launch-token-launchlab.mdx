<Info>
  LaunchLab é o principal local de lançamento de mercado primário da Raydium. Um projeto deposita seu suprimento de tokens em uma curva de ligação; compradores negociam contra a curva usando SOL (ou outro mint de cotação); quando um limite de graduação é atingido, os ativos da curva migram automaticamente para um pool CPMM, e o token se torna livremente negociável. Esta página orienta você por todo o fluxo do lado do projeto.
</Info>

## O que você precisa

- **Token mint** — o token que você quer vender. Deve ser recém-cunhado com:
  - Suprimento total cunhado em sua carteira (para que você possa depositar na curva).
  - Autoridade de cunhagem revogada antes do lançamento (caso contrário, o preço da curva pode ser manipulado por novas cunhagens).
- **Metadados** — nome, símbolo, imagem, links sociais. Metadados Metaplex ou similar.
- **Carteira** — ~1 SOL para aluguel de criação + financiamento de cofre + taxas de prioridade (a graduação em si é paga pelo graduador, não por você).
- **Decisão sobre**:
  - Tipo de curva (quadrática vs CPMM de reservas virtuais).
  - Limite de graduação.
  - Política de disposição de LP (Burn / Lock / ToCreator).
  - Preço inicial e limite.

## Escolha da curva

LaunchLab suporta duas famílias de curvas:

### Quadrática (`curve_type = 0`)

O preço cresce quadraticamente com o suprimento vendido. Sensação clássica de "lançamento justo" — compradores iniciais obtêm vantagem de preço, compradores posteriores pagam mais, o preço acelera suavemente.

```
price(s) = a * s^2 + b * s + c
```

onde `s` é o suprimento vendido. Tipicamente `a > 0` (convexo). O spread entre os preços inicial e de graduação é determinístico dado `a, b, c` e o limite.

Melhor para: lançamentos de novidade, memes, projetos orientados pela comunidade.

### CPMM de reservas virtuais (`curve_type = 1`)

Emula um AMM de produto constante usando reservas *virtuais* — a curva se comporta como um CPMM com `x * y = k`, mas o pool começa com tokens sintéticos que nunca são retirados.

```
price = virtual_quote_reserve / virtual_base_reserve
```

Conforme os compradores compram, `virtual_base_reserve` diminui e `virtual_quote_reserve` aumenta — a curva parece idêntica ao que o CPMM pós-graduação parecerá. Transição mais suave.

Melhor para: lançamentos que desejam continuidade de preço previsível pós-graduação.

## Passo a passo da interface

Em [raydium.io/launchpad/create](https://raydium.io/launchpad/create):

1. **Token.** Cole o endereço do mint. A interface busca metadados e os exibe.
2. **Tipo de curva.** Escolha quadrática ou CPMM virtual; a interface mostra uma visualização de gráfico de preço para cada uma.
3. **Limite de graduação.** Padrão: a curva termina após todo o `total_base_supply` ter sido vendido. Alternativa: terminar em um `graduation_quote_amount` específico (por exemplo, 85 SOL).
4. **Mint de cotação.** SOL (padrão), USDC ou qualquer outro mint. SOL é o padrão.
5. **Política de disposição de LP:**
   - **Burn** — tokens LP enviados para um endereço inutilizável na graduação. O criador não pode retirar liquidez; os usuários confiam no pool para sempre.
   - **Lock** — tokens LP enviados para um escrow com bloqueio de tempo por `lock_duration`.
   - **ToCreator** — tokens LP enviados para o criador. Mais flexível, menos confiável.

   Os lançamentos mais respeitados usam Burn.

6. **Revisão.** A interface resume: intervalo de preço esperado, arrecadação inicial se a curva se esgotar, configuração CPMM de graduação.
7. **Assinar.** Uma transação cria o estado de lançamento + cofre base + cofre de cotação, transfere `total_base_supply` de sua carteira para o cofre base.

## Passo a passo programático

A forma da curva, o mint de cotação, o alvo de arrecadação e a política de disposição de LP **não** são argumentos — eles vêm do `GlobalConfig` que você vincula e do `PlatformConfig` sob o qual seu lançamento é executado. O que você passa é a identidade do mint, a configuração a vincular e opcionalmente uma primeira compra:

```ts
import {
  Raydium,
  TxVersion,
  LAUNCHPAD_PROGRAM,
  LaunchpadConfig,
  getPdaLaunchpadConfigId,
} from "@raydium-io/raydium-sdk-v2";
import { Keypair, PublicKey } from "@solana/web3.js";
import { NATIVE_MINT } from "@solana/spl-token";
import BN from "bn.js";

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });
const programId = LAUNCHPAD_PROGRAM;

// Você gera o keypair do mint base e assina com ele.
const pair  = Keypair.generate();
const mintA = pair.publicKey;

// Vincule uma configuração: (mint de cotação, curve_type, índice). Isso é o que fixa a forma da curva,
// o mint de cotação e o alvo de arrecadação.
const configId   = getPdaLaunchpadConfigId(programId, NATIVE_MINT, 0, 0).publicKey;
const configData = await raydium.connection.getAccountInfo(configId);
const configInfo = LaunchpadConfig.decode(configData!.data);
const mintBInfo  = await raydium.token.getTokenInfo(configInfo.mintB);

const { execute, extInfo } = await raydium.launchpad.createLaunchpad({
  programId,
  mintA,
  decimals: 6,
  name:   "My New Token",
  symbol: "MYNEW",                    // 10 caracteres ou menos
  uri:    "https://example.com/metadata.json",
  migrateType: "amm",                 // "amm" | "cpmm"

  configId,
  configInfo,
  mintBDecimals: mintBInfo.decimals,
  mintBProgram:  new PublicKey(mintBInfo.programId),

  createOnly: true,                   // true = criar o mint sem uma primeira compra
  buyAmount:  new BN(1000),
  slippage:   new BN(100),            // 100 = 1%

  extraSigners: [pair],               // o keypair do mint base deve assinar
  txVersion: TxVersion.V0,
  computeBudgetConfig: { units: 400_000, microLamports: 50_000 },
});

// createLaunchpad retorna várias transações - execute-as em ordem.
const { txIds } = await execute({ sequentially: true });
console.log("Pool ID:", extInfo.address.poolId.toBase58());
console.log("Base mint:", mintA.toBase58());
```

`raydium.api.fetchLaunchConfigs()` lista as configurações disponíveis com seu suprimento padrão, quantidade de venda e alvo de arrecadação, para que você possa mostrar ao usuário o que uma determinada configuração implica antes de assinar. Versão totalmente anotada, incluindo a variante Token-2022: [`products/launchlab/code-demos`](/pt/products/launchlab/code-demos#create-a-launch).

## Monitoramento pré-graduação

Rastreie a atividade via API:

LaunchLab tem seus próprios hosts de API, separados de `api-v3.raydium.io`:

```ts
// Informações no nível do mint, indexadas por mint base (separadas por vírgula para um lote).
const r = await fetch(
  `https://launch-mint-v1.raydium.io/get/by/mints?ids=${mintA.toBase58()}`,
).then((r) => r.json());
console.log(r.data.rows[0]);

// Também disponível: /main/configs (lista de configuração) no mesmo host, e
// https://launch-history-v1.raydium.io/kline e /trade para preço e preenchimentos.
```

Ou leia o estado on-chain diretamente. O ID do pool é um PDA de `(programId, mintA, mintB)`:

```ts
import { getPdaLaunchpadPoolId, Curve } from "@raydium-io/raydium-sdk-v2";

const poolId = getPdaLaunchpadPoolId(programId, mintA, NATIVE_MINT).publicKey;
const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });

console.log({
  status:      poolInfo.status,
  baseSold:    poolInfo.realA.toString(),
  totalSellA:  poolInfo.totalSellA.toString(),
  quoteRaised: poolInfo.realB.toString(),
  raiseTarget: poolInfo.totalFundRaisingB.toString(),
});
```

O progresso é melhor expresso em termos de **preço** em vez de como uma fração da arrecadação, porque a curva é não-linear. O repositório de demonstração [`getFinishRate.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/getFinishRate.ts) faz isso com `Curve.getPrice`, `Curve.getPoolEndPriceReal` e `Curve.getPoolInitPriceByPool`:

```
finishRate = (currentPrice − initPrice) / (endPrice − initPrice)   // limitado a 1
```

### Métricas a monitorar

- **Taxa de venda**: percentual de base vendido. O limite de graduação é tipicamente em 80–100% vendido.
- **Preço atual**: derivado da curva no `baseSold` atual.
- **Compradores únicos**: contagem de pagadores distintos via indexador.
- **Proporção de compra vs venda**: lançamentos iniciais veem pressão de compra pesada que desacelera.

Se a venda for `<10%` após 24 horas, considere se o marketing é adequado. LaunchLab não resgata lançamentos sub-divulgados.

## Graduação

A graduação é uma transação separada, e **não** é chamável por ninguém: `MigrateToCpswap` e o legado `MigrateToAmm` cada um requer que seu signatário corresponda a uma carteira registrada no `GlobalConfig` de ligação (`migrate_to_cpswap_wallet` / `migrate_to_amm_wallet`), e qualquer outro signatário recebe `InvalidOwner`. Não há recompensa. Essas carteiras são executadas pelo crank de graduação da Raydium, que coloca a migração dentro de segundos do limite ser cruzado. Nenhuma ação necessária de você como criador além da configuração inicial.

### O que a graduação faz

1. Lê os saldos do cofre.
2. Fecha a curva (sem mais compras/vendas contra ela).
3. Cria um novo pool CPMM com os saldos do cofre como liquidez inicial.
4. Cunha tokens LP iniciais com base nos saldos do cofre.
5. Dispõe dos tokens LP de acordo com a política configurada (Burn / Lock / ToCreator).

Após a graduação, o pool CPMM está ativo e negocia através do roteamento normal da Raydium.

### Monitoramento para graduação

Observe `status` no estado do pool e mude sua interface quando mudar:

```ts
const before = (await raydium.launchpad.getRpcPoolInfo({ poolId })).status;

setInterval(async () => {
  const p = await raydium.launchpad.getRpcPoolInfo({ poolId });
  if (p.status !== before) console.log("migrado - mude para a página do pool CPMM");
}, 10_000);
```

O endereço do pool graduado é o PDA CPMM para `(cpswap config, token0, token1)`, então você pode derivá-lo em vez de esperar que seja relatado. Para um indexador, inscreva-se via gRPC em vez de fazer polling — veja [`products/launchlab/code-demos`](/pt/products/launchlab/code-demos#watch-configs-and-pools-over-grpc).

Não há caminho de "graduação manual" para um criador ou terceiro. Se um lançamento cruzou seu limite e não migrou, isso é uma questão operacional para a carteira de migração, não algo que você possa forçar de um cliente.

## Pós-graduação

### Verificar o pool CPMM

```ts
const pool = await raydium.cpmm.getPoolInfoFromRpc({ poolId: cpmmPoolId });
console.log("Preço CPMM:", pool.poolInfo.price);
console.log("TVL CPMM:  ", pool.poolInfo.tvl);
```

O pool CPMM deve ter (aproximadamente):

- Saldo de token base: `total_base_supply - baseSold` + resíduo de curva.
- Saldo de token de cotação: `quoteRaised - graduationFee`.
- Preço: corresponde ao último preço da curva.

### Verificar disposição de LP

- **Burn**: o suprimento do mint LP mostra enviado para 1nc1nerator11111111111111111111111111111111 ou similar.
- **Lock**: tokens LP no PDA de escrow com timestamp de desbloqueio.
- **ToCreator**: tokens LP na carteira do criador.

### Coletar taxas do criador

Se você configurou uma participação de taxa do criador, chame periodicamente:

O construtor é `claimCreatorFee`, e é indexado pelo **mint de cotação** em vez de por um lançamento — uma chamada varre suas taxas de criador acumuladas naquele mint:

```ts
import { NATIVE_MINT } from "@solana/spl-token";

await raydium.launchpad.claimCreatorFee({
  programId,
  mintB: NATIVE_MINT,      // o mint de cotação para reivindicar
  txVersion: TxVersion.V0,
});
```

Use `claimMultipleCreatorFee` para fazer lote entre mints. As taxas acumulam a partir de negociações de curva pré-graduação, e pós-graduação a partir do caminho de taxa do criador do pool CPMM quando o `platform_cp_creator` da plataforma o deixa como o criador do pool registrado — veja [`products/launchlab/platform-config`](/pt/products/launchlab/platform-config).

## Lista de verificação de anúncio

O anúncio pós-graduação deve incluir:

- [ ] Hash da transação de graduação.
- [ ] Novo ID do pool CPMM.
- [ ] Prova de disposição de LP (tx de burn / tx de lock / carteira do criador).
- [ ] ETA de cobertura do agregador (carteiras normalmente indexam dentro de 5 minutos).
- [ ] Verificação de contrato de token (corresponder endereço do mint em canais de anúncio).

## Armadilhas

### 1. Autoridade de cunhagem não revogada

Se `baseMint.mintAuthority` ainda for uma chave que você controla, você pode cunhar novo suprimento e vender para sua própria curva. Lançamentos que não revogaram são comumente sinalizados como alto risco ou não verificados por agregadores e sites de listagem. Revogue antes de lançar.

### 2. Parâmetros de curva incorretos

Curvas quadráticas com `a` muito alto tornam tokens iniciais gratuitos (preço ≈ 0) e tokens posteriores absurdos. Curvas com `a` muito baixo tornam a curva quase linear (perdem a sensação de "ligação"). Teste parâmetros em devnet primeiro.

### 3. Limite de graduação muito alto

Se a graduação exigir mais capital do que a demanda realista, a curva nunca se gradua e os compradores ficam presos com tokens que só podem vender de volta para a curva (a preços piores). Escolha um limite que você possa realmente atingir.

### 4. Scams de mint de cotação

Se seu mint de cotação for um token personalizado (não SOL/USDC), os usuários não confiarão nele. Fique com SOL ou USDC para cotação.

### 5. Esqueceu de financiar o cofre base

O SDK transfere `totalBaseSupply` de sua carteira na criação. Se sua carteira não tiver, a tx reverte. Confirme o saldo antes de assinar.

### 6. Disposição de LP = Burn é irreversível

Uma vez que LP é enviado para 1nc1nerator, ninguém pode retirar liquidez, *incluindo você*. Este é o ponto — minimização de confiança. Não escolha Burn se não tiver certeza.

### 7. Nível de taxa CPMM pós-graduação

O pool graduado usa a configuração CPMM padrão do LaunchLab (0,25%). Se você quisesse 1% ou 0,01%, você precisa criar um segundo pool CPMM você mesmo pós-graduação e migrar liquidez — desajeitado e fragmentando. Aceite o padrão, ou lance via criação direta de CPMM em vez de LaunchLab.
