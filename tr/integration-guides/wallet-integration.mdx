## Raydium pozisyonlarını algılama

### Klasik LP token'ları (CPMM, AMM v4)

Bunlar diğer SPL Token'lar gibi görünür: kullanıcının ATA'sı bir bakiye tutar. Bir cüzdan bunu varsayılan olarak başka bir token olarak gösterir. Bunu bir Raydium LP pozisyonu olarak ortaya çıkarmak için:

1. Kullanıcının token hesaplarını numaralandırın: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Her mint için Raydium'un mint listesini kontrol edin: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (çağrı başına ~50 LP mint'e kadar toplu işlem yapın).
3. Eşleşen mint'ler için API havuz referansını döndürür. Pozisyonun token cinsinden değerini hesaplamak için kullanın:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Hem LP bakiyesini hem de açılmış tutarları gösterin — kullanıcılar LP birimleri değil, temel token'lar cinsinden düşünürler.

### CLMM pozisyon NFT'leri

CLMM pozisyonları NFT'lerdir. Her pozisyonun `PersonalPositionState` PDA'sı NFT mint'inden türetilir. Algılamak için:

1. Kullanıcının NFT'lerini numaralandırın. Eski Metaplex NFT'leri için: token hesaplarını arz 1 ve ondalık 0 olanlarla filtreleyin.
2. Her NFT mint için PersonalPositionState PDA'sını türetmeyi deneyin:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Bu bir Raydium CLMM pozisyonudur — çöz.
```

3. Cüzdanın pozisyonlarını `raydium.clmm.getOwnerPositionInfo({ programId })` ile numaralandırın ve `nftMint` ile eşleştirin (bir `getPositionInfo` yoktur). Her giriş size şunları verir:
   - `poolId` → mint'leri çözmek için havuzu getir
   - `tickLower`, `tickUpper` → aralığı göster
   - `liquidity`, `tokensOwedA/B` → pozisyon değerini ve bekleyen ücretleri hesapla
   - `rewardInfos` → akış başına bekleyen ödüller

4. Token-2022 altında verilen pozisyon-NFT'leri için (`OpenPositionWithToken22Nft`), NFT mint'inin programı SPL Token yerine Token-2022'dir. Tarama yaparken her ikisini de numaralandırın.

### Farm stake'leri

Farm v3 / v5 / v6'nın her birinin kullanıcı başına bir defter PDA'sı vardır. Türetmeler:

```ts
// Her kullanıcı farm etkileşimi için üç farm sürümünü de deneyin.
// En ucuz yaklaşım: API'ye önce sorun, bu tüm kullanıcı pozisyonlarını indekslemişdir.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Tamamen zincir üstü algılamayı tercih eden cüzdanlar için: olası `UserLedger` PDA'larını, kullanıcıyı "muhtemel" farm ID'lerinin seçilmiş bir listesiyle karma hale getirerek yineleyin. Tüm farm ID'lerini kapsamlı olarak numaralandırmak pratik değildir (binlerce vardır); API'yi kullanın.

## Pozisyon değerini hesaplama

### CPMM / AMM v4 LP

Üç modül **aynı imzayı paylaşmaz**: `liquidity.getPoolInfoFromRpc` `{ poolId }` alırken, `cpmm.getPoolInfoFromRpc` ve `clmm.getPoolInfoFromRpc` konumsal base58 dizesi alır.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` bir ApiV3Token'dır ve `supply` alanı yoktur. LP mint'inin
// arzını zincirden okuyun veya havuzun kendi aynasını kullanın:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Ardından her birini mint'in USD fiyatıyla çarpın (`raydium.token` veya bir fiyat oracle'ından).

### CLMM pozisyonu

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // base58 dizesi
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity asenkrondur, epochInfo + poolInfo + add alır,
// ve ücret sarılı tutarları döndürür.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // görüntüleme için, kayma yok
  add:        false,
});
// amountA.amount / amountB.amount BN'lerdir; .fee Token-2022 transfer ücretidir.

// Bekleyen ücretler — "toplanmamış" olarak ayrı olarak gösterin
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Bekleyen ödüller — bir CLMM havuzunun 0–3 ödül akışı vardır. Pozisyonun
// rewardInfos girdileri yalnızca { growthInsideLastX64, rewardAmountOwed }'dir, bu nedenle
// mint HAVUZUN rewardInfos'undan aynı indekste gelmelidir.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Şu şekilde gösterin:

- Likidite değeri (mevcut fiyat)
- Toplanmamış ücretler
- Akış başına bekleyen ödüller
- Aralık: `[tickLower_price, tickUpper_price]` mevcut fiyatın aralık içinde olup olmadığını gösteren görsel bir çubukla

### Farm stake

```ts
// API yanıtı zaten bekleyen ödülleri içerir; doğrudan kullanın.
const apr       = stakingFarm.apr;               // %, yıllıklandırılmış
const staked    = stakingFarm.stakedAmount;      // stake mint'inin en küçük birimleri
const rewards   = stakingFarm.pendingRewards;    // { mint, amount } dizisi
```

Zincir üstü hesaplama için farm'ın muhasebesi yansıtın:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Hesaplamadan önce `reward_per_share_x64`'ü tembel güncelleme formülüyle yenileyin (geçen zaman × emisyon oranı ÷ toplam_stake).

## Önizleme için işlem simülasyonu

Kullanıcı imzalamadan önce, cüzdanlar genellikle bakiye değişikliklerini önizler. `simulateTransaction` kullanın:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Her döndürülen hesabın bakiyesini çöz ve işlem öncesi bakiyeye karşı farkı al.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // işlem öncesi bakiyeyle karşılaştır, Δ göster
}
```

`accounts` parametresi doğrulayıcıdan listelenen adresler için simülasyon sonrası hesap durumunu döndürmesini ister. Bakiye değişimini yalnızca talimat şeklinden tahmin etmeye çalışmaktan çok daha doğru.

### Simülasyon tuzakları

- **CLMM swap'leri geçerli tick dizileri gerektirir.** Kullanıcının giriş boyutu başlatılmamış bir tick dizisine geçerse, simülasyon geri döner (yürütme gibi). Bunu arayüzde açıkça gösterin.
- **Öncelik ücreti.** Simülasyon, hesaplama bütçesi talimatları uygulanmadan çalışır. Varsayılan 200k CU'yu aşacak büyük bir işlem için simülasyon başarısız olur ancak açık CU sınırı ile gerçek yürütme başarılı olur. Simüle edilen tx'e de CU sınırını ayarlayın.
- **Taze blockhash.** Simülasyon mevcut blockhash'i kullanır; imzalama 60 saniyeden fazla sürerse tx geçersiz hale gelir. Kullanıcı tereddüt ederse yeniden simüle edin.

## Token-2022 görüntüleme

Token-2022 programı altındaki token'lar cüzdanın token listesinde bu şekilde etiketlenmelidir, çünkü farklı risk yüzeylerine sahiptirler:

- **Transfer-fee mint'leri**: mevcut `transferFeeBasisPoints`'i bakiyenin yanında "Transfer ücreti: X%" olarak gösterin. Alırken uyarı verin — kullanıcılar gönderenin gönderdiğinden daha az alacaklarını fark etmeyebilir.
- **Transfer-hook mint'leri**: hook program ID'sini gösterin. Kötü niyetli bir hook giden transferleri engelleyebilir; kullanıcılar hook'un beklediği şey olduğunu doğrulamalıdır.
- **Aktarılamayan mint'ler**: "Aktarılamayan" gösterin ve swap/gönder'i devre dışı bırakın. Bunlar tipik olarak soulbound token'lar veya kimlik bilgileridir.
- **Faiz getiren mint'ler**: `TokenAccount.amount`'dan türetilen UI bakiyesi **tahakkuk eden faizi yansıtmaz. Görüntülenen değer için `@solana/spl-token`'dan `amountToUiAmount`'ı kullanın (ölçekleme faktörünü uygular).

## Farm APR görüntüleme

Kullanıcılara gösterilen APR, tüm canlı ödül akışlarını birleştirmeli, USD'ye dönüştürmeli ve yıllıklandırmalıdır:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // çalışmayan'ı atla
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

`APR: X.Y%` olarak gösterin. Stake mint'i bir LP token'ı ise, temel LP'nin temel ücret APR'sini de hesaplayın ve toplamı "Toplam APR" veya "APR + ücretler" olarak etiketleyin.
