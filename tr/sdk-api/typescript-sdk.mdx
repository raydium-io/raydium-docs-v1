## Kurulum

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
# veya
pnpm add @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
```

SDK TypeScript'te yazılmıştır ve JS yapıtının yanında `.d.ts` dosyalarını içerir. Minimum araç zinciri: Node 18+, TypeScript 5.0+, `moduleResolution: "bundler"` veya `"node16"`.

## Başlatma

Giriş noktası `Raydium.load` fonksiyonudur:

```ts
import { Raydium } from "@raydium-io/raydium-sdk-v2";
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner      = Keypair.fromSecretKey(/* ... */);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",           // "mainnet" | "devnet"
  disableFeatureCheck: true,    // SDK'nın başlangıç özellik-algılama API çağrısını atla
  blockhashCommitment: "confirmed",
});
```

`Raydium.load` asenkron olduğu için başlangıçta `api-v3.raydium.io`'dan küçük bir `/config` yükü getirir (mevcut `AmmConfig` hesaplarını, ücret katmanlarını vb. listeler). Çevrimdışı ortamlarda `disableFeatureCheck: true` ayarlayın; bu değerleri bazı oluşturuculara manuel olarak sağlamanız gerekecektir.

## Dört modül arayüzü

Yüklendikten sonra, `raydium` nesnesi dört modül arayüzünü ortaya çıkarır; her biri bir ürün yüzeyine karşılık gelir:

```ts
raydium.cpmm       // CPMM havuzları: createPool, addLiquidity, withdrawLiquidity, swap, ...
raydium.clmm       // CLMM havuzları: createPool, openPositionFromBase, increasePositionFromBase,
                   //                 decreaseLiquidity, harvestAllRewards, swap, ...
raydium.liquidity  // AMM v4 havuzları: computeAmountOut, swap, addLiquidity, removeLiquidity, ...
raydium.farm       // Farm v3/v5/v6: deposit, withdraw, harvestAllRewards, create, setRewards
raydium.launchpad  // LaunchLab: createLaunchpad, buyExactIn, sellExactIn, graduate, ...
raydium.trade      // Çok havuzlu yönlendirme: quotes, route-execution (0.2.41'de beta)
raydium.token      // Yardımcılar: token listesi al, metadata, ATA oluşturma
```

(Evet, toplamda beş arayüz — "dört" Raydium'un bunları herkese açık olarak gruplandırma şeklidir; `trade` ve `token` destekleyici yardımcılar olarak kullanılır.)

## İşlem oluşturucuları

Her değiştirici fonksiyon hemen yürütmek yerine bir oluşturucu döndürür:

```ts
const { execute, builder, transaction, innerTransactions, extInfo } =
  await raydium.cpmm.addLiquidity({
    poolInfo,
    amountInA,
    amountInB,
    slippage: 0.005,
    txVersion: TxVersion.V0,
  });
```

Döndürülen alanlar:

- **`execute`** — imzalayan ve gönderen bir kolaylık fonksiyonu. `builder.execute` ile eşdeğerdir.
- **`builder`** — tüm talimatlar ve imzalayanlar biriktirilmiş `TxBuilder` örneği. `.build()` çağrısı `VersionedTransaction[]` döndürür; kendi talimatlarınızı enjekte etmeniz veya harici imzalayanlarla imzalamanız gerektiğinde kullanışlıdır.
- **`transaction` / `innerTransactions`** — ham talimat dizileri. Birleştirilmiş çok programlı işlemler oluştururken kullanın.
- **`extInfo`** — ürüne özgü ekstralar. Örneğin, `createPool` `extInfo.poolId` döndürür; `createLaunchpad` yeni başlatma durumu PDA'sını döndürür.

`txVersion` eski ve V0 işlem biçimi arasında kontrol eder. V0 (adres arama tabloları) varsayılan tavsiyedir — daha büyük swapların tek bir işlemde sığmasını sağlar.

### Neden asenkron oluşturucular?

Neredeyse her oluşturucu dahili olarak zincir üstü durumu getirir: havuz bilgisi (teklifler için), token programı sahipliği (Token-2022 vs SPL yönlendirmesi için), hesap kira muafiyeti (ATA oluşturma için), vb. SDK agresif bir şekilde önbelleğe alır ancak yeni bir havuz için ilk çağrı RPC gidiş-dönüşleri içerir. Yeniden getirmeyi önlemek için uzun ömürlü bir `raydium` örneği tutun.

## CLMM modülü eklemeleri (en son sürüm)

CLMM arayüzü yeni dinamik ücret, tek taraflı ücret ve limit sipariş özellikleri için yüzeyler kazandı:

- **`raydium.clmm.createCustomizablePool`** — `collectFeeOn`, `enableDynamicFee` ve `dynamicFeeConfigId` kabul eden `createPool`'un üst kümesi. Yeni kontrollere ihtiyaç duyan herhangi bir yeni havuz için bunu kullanın; klasik `createPool` varsayılan ücret havuzları için çalışmaya devam eder.
- **`raydium.clmm.openLimitOrder`** — bunları destekleyen bir havuzda tek tick limit siparişi açın. `poolInfo`, `poolKeys`, `limitOrderConfig` (`/main/clmm-limit-order-config`'ten), `inputMint`, `inputAmount` ve hedef `tick` alır.
- **`raydium.clmm.increaseLimitOrder` / `decreaseLimitOrder`** — mevcut bir siparişin doldurulmamış kısmını ayarlayın. Azaltma, tamamen doldurulmuş bir siparişte `InvalidOrderPhase` ile geri döner.
- **`raydium.clmm.settleLimitOrder` / `settleAllLimitOrder`** — doldurulmuş çıktıyı sahibinin ATA'sına taşıyın. Siparişin sahibi veya havuzun `limit_order_admin` bekçisi bunları çağırabilir.
- **`raydium.clmm.closeLimitOrder` / `closeAllLimitOrder`** — tamamen kapatılmış siparişleri kapat ve kirayı geri al.
- **`raydium.api.getClmmDynamicConfigs()` / `getClmmLimitOrderConfigs()`** — yeni `/main/clmm-dynamic-config` ve `/main/clmm-limit-order-config` uç noktalarına isabet eden REST yardımcıları.

Küçük bir yeniden düzenleme ayrıca `utils/` öğesini `libraries/` öğesine taşıdı. `@raydium-io/raydium-sdk-v2/utils/...` öğesinden içe aktaran kod `@raydium-io/raydium-sdk-v2/libraries/...` öğesine geçmelidir. Üst düzey paket barili değişmemiştir, bu nedenle çoğu kullanıcı yeniden adlandırmayı hiç görmez.

Uçtan uca TypeScript kılavuzları [`products/clmm/code-demos`](/tr/products/clmm/code-demos) içinde bulunur.

## Yaygın tuzaklar

### 1. Küme uyuşmazlığı

SDK'nın başlangıç yapılandırması kümeye özgüdür. `cluster: "mainnet"` öğesini devnet `Connection` öğesiyle karıştırmak sessiz yanlış yönlendirmeye neden olur: SDK mainnet `AmmConfig` öğesine karşı teklif verir ancak devnet'e gönderir. Her zaman her ikisini de geçin.

### 2. ATA'ları önceden oluşturmayı unutmak

Bir mint ile ilk etkileşimde, kullanıcının İlişkili Token Hesabı mevcut olmayabilir. SDK, eksik bir ATA'yı algıladığında bir `AssociatedTokenAccount::create` talimatını otomatik olarak önceden ekler; bu küçük bir kira miktarına mal olur. Cüzdanınızda SOL azsa bu sessizce başarısız olur. Yeniden denemeden önce kontrol edin ve fon sağlayın.

### 3. Eski `poolInfo`

`poolInfo` önbelleğe alınmış bir anlık görüntüdür. Havuz durumu onu getirdikten sonra değişmişse (büyük bir işlem fiyatı hareket ettirdiyse, örneğin), swap'ın `minAmountOut` eski duruma karşı hesaplanabilir ve zincir üstü çıktı miktarının altında kalabilir, geri döner. Yüksek değerli işlemler oluşturmadan hemen önce `poolInfo` öğesini yeniden getirin veya zincir üstü rezervleri yeniden sorgulayan SDK'nın `computeAmountOut` öğesini kullanın.

### 4. Öncelik ücretleri

SDK varsayılan olarak işlem birimi fiyatları eklemez. Yüksek hacimli pencereler sırasında (yeni havuz başlatmaları, meme-coin olayları) bu, işleminizin diğerleriyle rekabet ettiği ve iniş yapmayabileceği anlamına gelir. Açık bir `computeBudgetConfig` sağlayın:

```ts
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  inputAmount: new BN(...),
  swapResult: ...,
  slippage: 0.005,
  txVersion: TxVersion.V0,
  computeBudgetConfig: {
    units: 250_000,          // CU sınırı
    microLamports: 50_000,   // CU başına öncelik ücreti
  },
});
```

Boyutlandırma rehberi için [`integration-guides/priority-fee-tuning`](/tr/integration-guides/priority-fee-tuning) öğesine bakın.

### 5. Slippage toleransı havuz türüyle eşleşmelidir

CPMM ve AMM v4 CPMM matematiğidir (normal işlemlerde düşük etki). CLMM parçalıdır (etki tick geçişlerinde atlar). CPMM örneğinden 0,5% slippage toleransını birkaç tick'i geçen bir CLMM swap'ına kopyalarsanız, işlem muhtemelen geri döner. SDK'nın `computeAmountOut` `priceImpact` döndürür; toleransınızı bunun üzerine boyutlandırın.

### 6. `BN` vs `number`

SDK'daki tüm miktar alanları `bn.js` `BN` örnekleridir — asla JavaScript `number` değil. Miktar değerlerini `.toNumber()` aracılığıyla dönüştürmek `2^53` konumunda sessizce kesilir; ~9 katrilyon üzerindeki herhangi bir değer için (9 ondalık mint'lerde nadir değildir), bu yanlış sonuç üretir. Son UI oluşturmaya kadar her şeyi `BN` içinde tutun.

## Sürüm oluşturma ilkesi

- `@raydium-io/raydium-sdk-v2` Raydium'un koruduğu tek SDK'dır. Tüm belgeler, demolar ve entegrasyon rehberleri bunu hedefler.
- Eski bir v1 paketi (`@raydium-io/raydium-sdk`) tarihsel nedenlerle npm'de bulunur. Bakım CPMM ve LaunchLab sevk edildikten sonra sona erdi (v1 hiçbir zaman her ikisini de desteklemedi) ve 2024'ten sonra v1 sürümü yayınlanmamıştır. v1'i yaşam sonu olarak değerlendirin: yeni kod için kullanmayın ve kalan v1 entegrasyonlarını v2'ye geçirin.
- SDK v2 ön-1.0'dır. 0.x küçük sürümleri arasında kırıcı değişiklikler mümkündür; doğruladığınız sürümü sabitleyin ve yükseltirken GitHub sürüm notlarını kontrol edin.

## Yükseltme

SDK küçük sürümleri arasında yükseltirken:

1. Her değiştirici çağrının dönüş türünü yeniden kontrol edin — şekil değişiklikleri (örn. `extInfo`) sık sık iniş yapar.
2. `poolInfo` getirme imzalarını yeniden oluşturun — bir alan yeniden adlandırılmış olabilir.
3. Slippage işlemenizi yeniden doğrulayın; SDK sürümler arasında otomatik sınırlı ve tercih edilen sınırlı davranışlar arasında kaymıştır.
4. `raydium.trade` (yönlendirme) kullanıyorsanız, rota şeklini yeniden doğrulayın — yüzeyin en kararsız kısmıdır.
