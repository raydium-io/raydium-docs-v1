## Talimat özeti

| Ayırıcı adı | Kim imzalar | Ne yapar |
|-------|-----------|--------------|
| `Initialize` | havuz oluşturucu | İki mint ve bir `AmmConfig` adresinden yeni bir CPMM havuzu oluşturun. İzinsiz; herkes çağırabilir. Yeni havuzda `enable_creator_fee = false` değerini sabit kodlar. `pool_state` hesabı kanonik PDA veya yeni rastgele bir anahtar olabilir (bkz. Initialize hesapları). |
| `InitializeWithPermission` | ödeyici + `Permission` PDA sahibi | `Initialize`'ın izinli varyantı. Çağıran (`payer`) kendi genel anahtarından türetilen bir `Permission` PDA'ya sahip olmalıdır. Havuz oluşturmayı kapılandıran platformlar tarafından kullanılır (örn. LaunchLab mezuniyetleri). Çağıranın `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) değerini sabitlemeye ve yeni havuzda `enable_creator_fee = true` değerini zorlamaya izin verir. `pool_state` üzerindeki `creator` alanı ödeyici değil, ayrı olarak geçirilen `creator` hesabına ayarlanır. `pool_state` için `Initialize` ile aynı kanonik-PDA-veya-rastgele-anahtar esnekliği. |
| `Deposit` | LP | Her iki token'de likidite ekleyin; LP token'leri alın. |
| `Withdraw` | LP | LP token'lerini yakın; her iki temel token'i orantılı olarak alın. |
| `SwapBaseInput` | takas yapan | Tam giriş takas (`amount_in` giriş, ≥ `minimum_amount_out` çıkış). |
| `SwapBaseOutput` | takas yapan | Tam çıkış takas (≤ `maximum_amount_in` giriş, `amount_out` çıkış). |
| `CollectProtocolFee` | `protocol_owner` (`AmmConfig`'den) | Kasalardan tahakkuk eden protokol ücretlerini temizleyin. |
| `CollectFundFee` | `fund_owner` (`AmmConfig`'den) | Kasalardan tahakkuk eden fon ücretlerini temizleyin. |
| `CollectCreatorFee` | `pool_creator` | Tahakkuk eden oluşturucu ücretlerini temizleyin (oluşturucu ücreti etkinleştirilmişse). |
| `CollectCreatorFeePermissionless` | herhangi bir ödeyici | Tüm tahakkuk eden oluşturucu ücretlerini `pool_creator`'ın kanonik token hesaplarına temizleyin. Ödeyici eksik alıcı ATA'larını oluşturabilir ancak transferi yeniden yönlendiremez. |
| `UpdatePoolStatus` | `admin` | Bir havuz üzerindeki belirli işlemleri bir bit maskesi aracılığıyla duraklatın / devam ettirin. |
| `UpdateAmmConfig` | `admin` | Bir `AmmConfig` üzerindeki ücret oranlarını veya protokol/fon sahibini değiştirin. |
| `CreateAmmConfig` | `admin` | Yeni bir ücret katmanı oluşturun (yeni `AmmConfig` hesabı). |
| `CreatePermissionPda` | `admin` veya temsilci izin-PDA oluşturucu | Belirli bir yetkilinin `InitializeWithPermission` çağırmasına izin veren bir `Permission` PDA'sı basın. |
| `ClosePermissionPda` | `admin` veya adanmış izin-PDA oluşturucu | Daha önce verilen bir `Permission` PDA'sını iptal edin. 2026-09 yükseltmesinden bu yana adanmış oluşturucu yetkilisi verdiği bir izni kapatabilir; bundan önce yalnızca admin tarafından yapılabiliyordu. |
| `CreateSupportMintAssociated` | `admin` veya adanmış destek-mint sahibi | Aksi takdirde uzantı izin listesinde başarısız olacak bir Token-2022 mint'i, `SupportMintAssociated` PDA'sını oluşturarak kaydedin. |
| `CloseSupportMintAssociated` | `admin` veya adanmış destek-mint sahibi | Bir mint'in kaydını kaldırın. |
| `CollectExcessLamports` | `admin` veya adanmış collect-lamports cüzdanı | CPMM tarafından kontrol edilen kasalardan, LP mint'lerinden ve PDA'larından kira-muaf minimumun üzerindeki lamport'ları temizleyin. 2026-09'da eklendi. |

Durum bit maskesi: her havuzun `status` değeri bir `u8` olup, bit 0 = depozito devre dışı, bit 1 = çekim devre dışı, bit 2 = takas devre dışı (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` programda). Temiz bir bit işlemin izin verildiği anlamına gelir; ayarlanmış bir bit duraklatıldığı anlamına gelir. `UpdatePoolStatus` ham bir `u8` alır ve mevcut değerin üzerine yazar.

Sonraki bölümler her birini ayrıntılı olarak açıklar. Hesap sıralaması CPMM IDL'sini takip eder; SDK ve `raydium-cp-swap/programs/cp-swap/src/instructions` içindeki Rust istemcisi bu sırayı eşleştirir.

## `Initialize`

Yeni bir CPMM havuzu oluşturun.

**Argümanlar**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix zaman damgası; bu tarihten önce takas reddedilir
```

**Hesaplar** (W = yazılabilir, S = imzalayan)

| # | Ad | W | S | Notlar |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Kirayı öder; `pool_state.pool_creator` olarak kaydedilir. |
| 2 | `amm_config` |   |   | Seçilen ücret katmanı. |
| 3 | `authority` |   |   | CPMM global yetki PDA'sı. |
| 4 | `pool_state` | W | S* | Burada `init` edilir. **Ya** kanonik PDA `["pool", amm_config, token_0_mint, token_1_mint]` **ya da** yeni rastgele bir anahtar — kanonik PDA olmadığında, program `pool_state`'in imzalamasını gerektirir (`require_eq!(pool_account_info.is_signer, true)`). Rastgele anahtar yolu, oluşturucunun kanonik PDA üzerindeki ön çalıştırma girişimlerinden kaçınmasını sağlar. Aşağı akış PDA'ları (`lp_mint`, `vaults`, `observation_state`) her iki durumda da `pool_state.key()` adresinden türetilir. |
| 5 | `token_0_mint` |   |   | Sıralanmış: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | Burada `init` edilir. Yetki `authority` olarak ayarlanır. |
| 8 | `creator_token_0` | W |   | `init_amount_0` için kaynak ATA. |
| 9 | `creator_token_1` | W |   | `init_amount_1` için kaynak ATA. |
| 10 | `creator_lp_token` | W |   | Yaratıcının `lp_mint` üzerindeki ATA'sı. `init` (`init_if_needed` değil) — önceden var olmamalıdır; `lp_mint` bu aynı talimatta oluşturulduğu için de var olamaz. |
| 11 | `token_0_vault` | W |   | Burada `init` edilir. `authority` tarafından sahiplenilir. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Oluşturucu tarafından ödenen `create_pool_fee` için hedef ATA. |
| 14 | `observation_state` | W |   | Burada `init` edilir. |
| 15 | `token_program` |   |   | SPL Token (LP mint için). |
| 16 | `token_0_program` |   |   | SPL Token veya Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token veya Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` yalnızca rastgele anahtar yolunda imzalar; kanonik PDA yolu `pool_state` imzalaması olmadan çalışır.

**Ön koşullar**

- Mint'ler sıralanmıştır (`token_0_mint < token_1_mint` bayt sırasına göre).
- Hiçbir mint, CPMM izin listesi dışında bir uzantı kullanmaz (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — bkz. [`products/cpmm/accounts`](/tr/products/cpmm/accounts#vaults-and-token-2022). `SupportMintAssociated` PDA'sı (seed `[b"support_mint", mint]`) var olan bir mint, uzantı kontrolünü atlar — **ancak bu PDA'yı `remaining_accounts`'a eklemeniz gerekir**. Program yalnızca geçirdiğiniz hesapları tarar ve PDA'yı hiçbir zaman kendisi yüklemez; bu nedenle hesabı sağlamadan kayda güvenmek yine `NotSupportMint` (`6007`) ile başarısız olur. Sıra önemli değildir (eşleştirme anahtara göre yapılır); geçişe ihtiyaç duyan her mint için bir girdi geçirin. Bu kayıt, 2026-09 yükseltmesinin sabit kodlanmış dört mint beyaz listesini kaldırmasından bu yana tek geçiş yoludur.
- `creator` ilgili ATA'larda en az `init_amount_0` ve `init_amount_1` değerine sahiptir.
- `amm_config.disable_create_pool == false`.

**Son koşullar**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — **tam** karekök. Oluşturucuya `lp_supply − 100` mint'lenir; kilitli 100 taban birimi `lp_supply` içinde sayılır ama hiçbir zaman mint'lenmez.
- Dolayısıyla havuzun ömrü boyunca `lp_mint.supply == pool_state.lp_supply − 100` olur. Tüm LP payı hesaplamaları (yatırma, çekme) `lp_supply`'a böler; bu nedenle mint'in zincir üstü arzını ikame etmeyin, bu alanı kullanın. `sqrt(...) < 100` ise `InitLpAmountTooLess` ile geri döner.
- `observation_state` başlatılır; `observation_index = 0` ve `pool_id = pool_state.key()`.
- `create_pool_fee` lamport'ları oluşturucudan alıcıya aktarılır ve yerel SOL olarak senkronize edilir (wSOL ATA'sıdır).
- Havuzun durum bit maskesi `0` (depozito / çekim / takas tümü etkindir).
- `enable_creator_fee = false` ve `creator_fee_on = BothToken`. `Initialize` oluşturucu ücretini etkinleştirmeyi desteklemez — bu yol `InitializeWithPermission` yoludur.
- `open_time`, çağıran `<= block_timestamp` değeri geçtiyse `block_timestamp + 1` olarak yükseltilir. Takas `open_time` öncesinde reddedilir; depozito ve çekimler hemen çalışır.

**Yaygın hatalar** (tam liste [`reference/error-codes`](/tr/reference/error-codes) içinde)

- `InvalidInput` — mint'ler sıralanmamış veya özdeş mint'ler.
- `NotSupportMint` — engellenen Token-2022 uzantısı.
- `ExceededSlippage` — nadiren; `init_amount_0/1` ondalık uyuşmazlığı nedeniyle sıfır LP ile sonuçlanırsa.

## `Deposit`

Havuza orantılı olarak her iki token'de likidite ekleyin.

**Argümanlar**

```
lp_token_amount:   u64   // LP'ye basılacak kaç LP token
maximum_token_0:   u64
maximum_token_1:   u64
```

**Hesaplar**

| # | Ad | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Matematik**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // same for side 1
```

Üzerinde durmaya değer iki ayrıntı: orantısal payın temeli, ham kasa bakiyesi değil, **ücret hariç** kasa toplamıdır (`vault_amount_without_fee`, yani ham bakiye eksi tahakkuk eden protokol, fon ve yaratıcı sayaçları); ve kayma üst sınırı, brüt kasa hareketine göre değil, Token-2022 transfer ücreti eklendikten *sonra* ödeyicinin gerçekten aktardığı tutara göre kontrol edilir.

`k`'nin orantılılığında değişiklik yok — hem toplamlar hem de `lp_supply` aynı faktörle ölçeklenir.

**Son koşullar**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (giriş üzerindeki herhangi bir Token-2022 transfer ücreti net).
- `vault_1 += needed_token_1` (giriş üzerindeki herhangi bir Token-2022 transfer ücreti net).

**Yaygın hatalar** — `ExceededSlippage`, `ZeroTradingTokens`, depozito duraklatılmışsa `InvalidStatus`.

## `Withdraw`

LP token'lerini yakın ve her iki temel token'i orantılı olarak alın.

**Argümanlar**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Hesaplar**

| # | Ad | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

İlk 13 hesap `Deposit` ile özdeştir ve `lp_mint` yazılabilirdir çünkü LP token'ları yakılır. `Withdraw` ek olarak 14. bir hesap alır: `memo_program` (`address = memo::ID` ile kısıtlanmış) — `Deposit` bunu almaz. 13 hesaplı bir `Withdraw`, Anchor seri açımında başarısız olur ve LP çıkış yapamaz.

**Matematik**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // same for side 1

// As with Deposit: the base is the fee-excluded vault total, and the floor is
// checked against what the LP actually receives, after the transfer fee.
```

**Son koşullar**

- `lp_supply -= lp_token_amount`.
- Kasalar `out_token_0` / `out_token_1` gönderir (brüt; kullanıcı herhangi bir Token-2022 transfer ücreti net alır).

**Argümanlar**

**Hesaplar**

| # | Ad | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |

| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |

| 12 | `output_token_mint` |   |   |

Sıralama **giriş → çıkış** kullanıcının yönüne göre, havuzun kanonik `token_0 / token_1` değerine göre değil. Program mint'leri eşleştirerek hangi kasanın hangisi olduğunu bulur.

**Matematik** — bkz. [`products/cpmm/math`](/tr/products/cpmm/math).

**Ön koşullar**

- `open_time <= now`.
- `pool_status` takas'a izin verir.
- Ne mint duraklatılmış ne de bu yetki için dondurulmuş.
- `amount_in > 0`.

**Yaygın hatalar**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — ticaret sıfıra yuvarlanır.
- `NotApproved` — havuz `UpdatePoolStatus` aracılığıyla takas için duraklatılmış.
- `InvalidInput` — mint'ler havuzun kasa mint'lerinden hiçbiriyle eşleşmez.

## `CollectFundFee`

`CollectProtocolFee` ile aynı şekil, ancak `amm_config.fund_owner` — ya da yine program yöneticisi — tarafından imzalanır ve `fund_fees_*` sayaçlarını sıfırlar. Yanlış bir imzalayanda aynı şekilde `InvalidOwner`.

## `CollectCreatorFee`

`pool_state.pool_creator` tarafından imzalanmış. Tam `creator_fees_token_0` ve `creator_fees_token_1` bakiyelerini oluşturucunun token hesaplarına aktarır, ardından her iki sayacı sıfırlar. Her iki sayaç sıfır olduğunda `NoFeeCollect` döndürür.

## `CollectCreatorFeePermissionless`

Herkes oluşturucu ücreti koleksiyonunu tetikleyebilir. Talimat her zaman tam tahakkuk eden bakiyeleri `pool_state.pool_creator` tarafından sahiplenilen kanonik ilişkili token hesaplarına gönderir; çağıran başka bir oluşturucu veya hedef seçemez. Her iki ATA eksikse, ödeyici oluşturulmasını finanse eder.

Orijinal `CollectCreatorFee` çağrılabilir kalır, bu nedenle mevcut istemciler uyumlu kalır.

**Argümanlar** — yok.

**Hesaplar**

| # | Ad | W | S | Notlar |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Herhangi bir imzalayan; eksik oluşturucu ATA'larını finanse eder. |
| 2 | `creator` |   |   | `pool_state.pool_creator` ile eşleşmelidir; imzalamaz. |
| 3 | `authority` |   |   | CPMM global kasa yetki PDA'sı. |
| 4 | `pool_state` | W |   | Tahakkuk eden oluşturucu ücreti sayaçlarını tutar. |
| 5 | `token_0_vault` | W |   | Havuzun token 0 kasası ile eşleşmelidir. |
| 6 | `token_1_vault` | W |   | Havuzun token 1 kasası ile eşleşmelidir. |
| 7 | `vault_0_mint` |   |   | `token_0_vault.mint` ile eşleşmelidir. |
| 8 | `vault_1_mint` |   |   | `token_1_vault.mint` ile eşleşmelidir. |
| 9 | `creator_token_0` | W |   | `vault_0_mint` için oluşturucunun kanonik ATA'sı; eksikse oluşturulur. |
| 10 | `creator_token_1` | W |   | `vault_1_mint` için oluşturucunun kanonik ATA'sı; eksikse oluşturulur. |
| 11 | `token_0_program` |   |   | SPL Token veya Token-2022, token 0 ile eşleşir. |
| 12 | `token_1_program` |   |   | SPL Token veya Token-2022, token 1 ile eşleşir. |
| 13 | `associated_token_program` |   |   | Eksik alıcı ATA'sını oluşturur. |
| 14 | `system_program` |   |   | `payer` adresinden hesap oluşturmayı finanse eder. |

**Etki**

- Tüm `creator_fees_token_0` ve `creator_fees_token_1` değerlerini havuz kasalarından oluşturucu ATA'larına aktarır.
- Her iki oluşturucu ücreti sayacını sıfırlar ve `pool_state.recent_epoch` değerini günceller.
- Her iki sayaç sıfır olduğunda `NoFeeCollect` döndürür.

## `UpdatePoolStatus`

Bir havuz üzerindeki bireysel işlemleri duraklatın veya devam ettirin. `status` alanı bir bit maskesidir:

| Bit | Bayrak | Ayarlandığında etki |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` `NotApproved` ile reddeder. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` reddeder. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` reddeder. |

**Argümanlar**

```
status: u8      // yeni bit maskesi
```

**Hesaplar**

| # | Ad | W | S | Notlar |
|---|------|---|---|-------|
| 1 | `authority` |   | S | CPMM programındaki admin anahtarı ile eşleşmelidir. |
| 2 | `pool_state` | W |   |

Admin anahtarı, BPF yükseltme yetkilisi değil, **programın içine derlenmiş** bir genel anahtardır (`crate::admin::ID`) — değiştirilmesi bir program yükseltmesi gerektirir. Değer için [`reference/program-addresses`](/tr/reference/program-addresses), anahtarı kimin tuttuğu için [`security/admin-and-multisig`](/tr/security/admin-and-multisig) sayfasına bakın.

## `CreateAmmConfig`

Yeni bir ücret katmanı oluşturun.

**Argümanlar**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**Hesaplar**

| # | Ad | W | S | Notlar |
|---|------|---|---|-------|
| 1 | `owner` | W | S | Admin. |
| 2 | `amm_config` | W |   | Burada `init` edilir. |
| 3 | `system_program` |   |   |

**Ön koşullar**

- Aynı `index` ile mevcut `AmmConfig` yok.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **2026-09'da değişti: yeni config'in ücret sahipleri artık imzalayıcıdan gelmez.** `create_amm_config` artık programın sabit kodlanmış `protocol_fee_owner::ID` değerini `protocol_owner` alanına ve `fund_fee_owner::ID` değerini `fund_owner` alanına yazar, admin imzalayıcısının anahtarını her ikisine de kopyalamak yerine. Adresler [`reference/program-addresses`](/tr/reference/program-addresses#cpmm-fee-owner-wallets) içindedir.

  Sonuçlar: yeni oluşturulan bir `AmmConfig` üzerindeki ücretler, admin'in cüzdanına değil adanmış ücret cüzdanlarına gider. Admin, toplama için kabul edilen bir *imzalayan* olarak kalır — `CollectProtocolFee` / `CollectFundFee`, `amm_config.protocol_owner` / `fund_owner` **veya** `crate::admin::ID` anahtarını kabul eder — dolayısıyla süpürme için hiçbir şeyin döndürülmesi gerekmez; değişen tek şey, gelirlerin varsayılan olarak nereye gittiğidir. **Mevcut `AmmConfig` hesapları yeniden yazılmaz** — bunlarda depolanan her şey geçerli olmaya devam eder; bu nedenle her iki değeri de varsaymak yerine `protocol_owner` / `fund_owner` değerini her zaman hesaptan okuyun. `UpdateAmmConfig` parametreleri `3` ve `4` yine de bunları döndürür.
</Note>

## `UpdateAmmConfig`

Mevcut bir `AmmConfig` üzerindeki ücret oranlarını veya sahipliği değiştirin. Bir `param: u8` (hangi alanın güncelleneceği) ve bir `value: u64` alır. Tam dağıtım tablosu:

- `param = 0` → `trade_fee_rate` (`trade_fee_rate + creator_fee_rate < 1_000_000` olduğunu doğrular)
- `param = 1` → `protocol_fee_rate` (`≤ 1_000_000` ve `+ fund_fee_rate ≤ 1_000_000` olduğunu doğrular)
- `param = 2` → `fund_fee_rate` (`≤ 1_000_000` ve `+ protocol_fee_rate ≤ 1_000_000` olduğunu doğrular)
- `param = 3` → `protocol_owner`. Yeni anahtar `value` içinde **değildir**: onu `remaining_accounts[0]` olarak ekleyin (salt okunur olması yeterlidir). Varsayılan genel anahtar olmamalıdır ve hesabın atlanması bir `unwrap()` üzerinde panik yaratır.
- `param = 4` → `fund_owner`. `3` ile aynı mekanizma.
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool` (sıfır olmayan herhangi bir `value` devre dışı bırakır)
- `param = 7` → `creator_fee_rate` (`creator_fee_rate + trade_fee_rate < 1_000_000` olduğunu doğrular)

Başka herhangi bir `param`, `InvalidInput` döndürür.

Değişiklikler admin tarafından imzalanır ve **bu `AmmConfig`'e bağlı her havuzu** sonraki takas üzerinde etkiler. Geçiş yok; havuzlar yeni değerleri okur.

## `CollectExcessLamports`

CPMM'nin kontrol ettiği hesaplarda kira-muaf minimumun üzerinde oturan lamport'ların admin taraması. 2026-09 yükseltmesinde eklendi, böylece protokol [SIMD-0437 kira azaltması](/tr/solana-fundamentals/rent-and-reclaimable-rent) tarafından her adımdan sonra oluşturulan hesaplarda bırakılan aşırı finansmanı geri alabilir.

Yalnızca fazla hareket eder. Token bakiyeleri, hesap verileri, sahipler, havuz durumu ve eğri dokunulmaz ve talimat zaten minimumda olan bir hesaba karşı bir no-op'tir — bu nedenle her dağıtım adımından sonra yeniden çalıştırmak güvenlidir.

**Argümanlar** — yok.

**Hesaplar**

| # | Ad | W | S | Notlar |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | Her temizlenen lamport için hedef. CPMM program admin'i veya adanmış collect-lamports cüzdanı olmalıdır — bkz. [`reference/program-addresses`](/tr/reference/program-addresses#excess-lamports-collection-wallets). Başka bir imzalayan `InvalidOwner` ile başarısız olur. |
| 2 | `authority` |   |   | Seed `[b"vault_and_lp_mint_auth_seed"]` adresindeki CPMM kasa-ve-LP-mint yetki PDA'sı. Token-program CPI'larını imzalar. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. Her ikisi koşulsuz olarak gereklidir; program kaynak hesaba göre seçer. |
| 5.. | `remaining_accounts` | W |   | Temizlenecek `M` kaynak hesabı, herhangi bir sayı, herhangi bir sıra. |

**Her kaynak hesabın nasıl işlendiği**

Program kaynak hesabın `owner` değerine göre gönderir:

| Kaynak hesap sahibi | İşleme |
|---|---|
| SPL Token veya Token-2022, yerel olmayan token hesabı veya mint — havuz kasaları ve LP mint'leri | CPI `WithdrawExcessLamports` (token-program ayırıcısı `38`), `authority` tarafından imzalanmış. |
| SPL Token veya Token-2022, **yerel** (wSOL) token hesabı | `WithdrawExcessLamports` yerel hesapları reddeder. Program `SyncNative` CPI'sı yapar, sarılı `amount` ne kadar büyüdüğünü ölçer, tam o delta için `UnwrapLamports` (ayırıcı `45`) yapar, ardından sarılı bakiyenin ön-senkronizasyon değerine eşit olmasını gerektirir — aksi takdirde `LamportsCalculateError` (`6015`). Bir SOL tarafı havuz kasası bu nedenle tam likidite tutar. |
| CPMM programının kendisi — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | Program hesabı doğrudan `rent.minimum_balance(data_len)` değerine kadar borçlandırır. |
| Başka bir şey | **Sessizce atlanır.** Hata yok, lamport hareket yok. |

Sınırsız bir `remaining_accounts` listesi aldığı için, işlem boyutu gerçek sınırdır — [`solana-fundamentals/rent-and-reclaimable-rent`](/tr/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) içinde açıklanan cüzdan tarafı tarama ile aynı kısıtlama.

**Yaygın hatalar** — `InvalidOwner` (`6001`, yanlış imzalayan), `LamportsCalculateError` (`6015`, wSOL gidiş-dönüş net sıfıra ulaşmadı) ve program tarafından sahiplenilen yol sıfırdan bir hesap kendi kira minimumundan daha az tuttuğunda `InsufficientFunds`.

**SDK oluşturucu yok.** `@raydium-io/raydium-sdk-v2` bu talimat için bir oluşturucu göndermez ve `raydium-sdk-V2-demo` repo da göndermez — bu bir admin yoludur. Elle kodlayın, [`solana-fundamentals/rent-and-reclaimable-rent`](/tr/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) içinde cüzdan tarafı tarama token-program talimatı için yaptığı gibi.
