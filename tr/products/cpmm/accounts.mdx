## Bir CPMM havuzunun altı hesabı

Her CPMM havuzu, CPMM programı altında altı program türetilmiş adres (PDA) ve referans verdiği bir paylaşılan `AmmConfig` hesabı tarafından tamamen tanımlanır. İki mint'e sahip olduğunuzda, ağa dokunmadan her şeyi deterministik olarak türetebilirsiniz.

| Hesap | Seed(ler) | Sahibi | Amaç |
|---------|---------|-------|---------|
| `authority` | `"vault_and_lp_mint_auth_seed"` | CPMM | Her vault hareketi ve her LP mint/burn işlemi için imzalayan. **Tüm** CPMM havuzları arasında paylaşılır. |
| `poolState` | `"pool"`, `ammConfig`, `token0Mint`, `token1Mint` **veya** herhangi bir imzalayan tarafından sağlanan rastgele keypair | CPMM | Havuzun state struct'ı — mint çifti, vault bakiyeleri, LP arzı, ücret birikimi, observation işaretçisi. CPMM `Initialize` talimatı, dört seed'den türetilen kanonik PDA'yı **veya** yaratıcı tarafından imzalanan rastgele bir keypair'i kabul eder. Rastgele keypair yolu, bir saldırganın mempool'u izleyip meşru yaratıcıdan önce kanonik PDA'yı işgal etmeye çalıştığı ön-çalıştırma saldırısını engellemeye yönelik bir savunmadır. |
| `lpMint` | `"pool_lp_mint"`, `poolState` | SPL Token | Havuzun LP token'ı. Arz = toplam LP ödenmemiş. Mint yetkisi = CPMM authority PDA. |
| `vault0` | `"pool_vault"`, `poolState`, `token0Mint` | SPL Token / Token-2022 | Havuzun token0 bakiyesini tutar. Authority PDA tarafından sahiplenilir. |
| `vault1` | `"pool_vault"`, `poolState`, `token1Mint` | SPL Token / Token-2022 | Havuzun token1 bakiyesini tutar. Authority PDA tarafından sahiplenilir. |
| `observation` | `"observation"`, `poolState` | CPMM | TWAP için kullanılan fiyat örneklerinin ring buffer'ı. Her swap'ta yazılır. |

Ve paylaşılan config:

| Hesap | Seed(ler) | Sahibi | Amaç |
|---------|---------|-------|---------|
| `ammConfig` | `"amm_config"`, `index: u16` | CPMM | İşlem/protokol/fon/yaratıcı ücret oranlarını ve admin anahtarlarını tutar. "Ücret seviyesi" başına bir tane. Poolstate oluşturma sırasında birine bağlanır ve daha sonra değişemez. |

## Sadece iki mint'ten bir havuz türetme

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";

const CPMM_PROGRAM_ID = new PublicKey(
  "CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C"
); // mainnet — reference/program-addresses sayfasına bakın

function u16ToBytes(n: number): Buffer {
  const b = Buffer.alloc(2);
  b.writeUInt16BE(n);
  return b;
}

// token0 < token1 byte sırasına göre. Bunu yanlış yapmak geçerli bir PDA
// verir ama var olmayan bir havuza işaret eder.
function sortMints(a: PublicKey, b: PublicKey): [PublicKey, PublicKey] {
  return Buffer.compare(a.toBuffer(), b.toBuffer()) < 0 ? [a, b] : [b, a];
}

export function deriveCpmmAccounts(
  mintA: PublicKey,
  mintB: PublicKey,
  ammConfigIndex = 0,
) {
  const [token0Mint, token1Mint] = sortMints(mintA, mintB);

  const [ammConfig] = PublicKey.findProgramAddressSync(
    [Buffer.from("amm_config"), u16ToBytes(ammConfigIndex)],
    CPMM_PROGRAM_ID,
  );
  const [authority] = PublicKey.findProgramAddressSync(
    [Buffer.from("vault_and_lp_mint_auth_seed")],
    CPMM_PROGRAM_ID,
  );
  const [poolState] = PublicKey.findProgramAddressSync(
    [
      Buffer.from("pool"),
      ammConfig.toBuffer(),
      token0Mint.toBuffer(),
      token1Mint.toBuffer(),
    ],
    CPMM_PROGRAM_ID,
  );
  const [lpMint] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault0] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault1] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  return {
    ammConfig,
    authority,
    poolState,
    lpMint,
    token0Mint,
    token1Mint,
    vault0,
    vault1,
    observation,
  };
}
```

<Tip>
  **Havuz PDA'sını türetmeden önce her zaman mint'leri sıralayın.** Seed, iki mint'i kullanıcı sırasına değil byte sırasına göre hash'ler. `(A, B)` ve `(B, A)` ile iki havuz zincirde çarpışırdı — sıralama, programın eşlemeyi kanonik hale getirme yöntemidir.
</Tip>

<Note>
  **Havuz ID'si her zaman kanonik PDA değildir.** `Initialize`, yukarıdaki PDA'ya ek olarak `pool_state` olarak rastgele bir imzalayan keypair'i kabul eder. Geçirilen hesap kanonik PDA'yla eşleşmiyorsa, program bunun bir imzalayan olmasını gerektirir — yani yaratıcı imzaladığı yeni bir keypair geçirir. Bu ön-çalıştırma savunmasıdır: kanonik PDA'yı ele geçirmeye çalışan herhangi bir üçüncü taraf, meşru yaratıcı tarafından bunun yerine rastgele bir keypair kullanılarak atlatılabilir. Aşağı akış PDA'ları (`lpMint`, `vault0`, `vault1`, `observation`) yine de `poolState.key()` öğesinden türetilir, bu nedenle kullanılan hangi adres olursa olsun benzersiz kalırlar. Havuzları indekslerken, kanonik PDA'yı türeterek değil, zincir üstü state'ten havuz ID'sini keşfedin (örn. CPMM programı altında `PoolState` hesapları) — ikincisi rastgele keypair havuzlarını kaçıracaktır.
</Note>

## Hesap düzenleri

Tam Rust tanımları [`raydium-cp-swap`](https://github.com/raydium-io/raydium-cp-swap) kaynağında bulunur. Aşağıdaki alanlar, bir entegrasyon sırasında okuduğunuz alanlardır.

### `PoolState`

```rust
// programs/cp-swap/src/states/pool.rs
pub struct PoolState {
    pub amm_config: Pubkey,               // bu havuzu bir AmmConfig'e bağlar
    pub pool_creator: Pubkey,             // initialize'ı çalıştıran kişi
    pub token_0_vault: Pubkey,            // == vault0 PDA
    pub token_1_vault: Pubkey,            // == vault1 PDA

    pub lp_mint: Pubkey,
    pub token_0_mint: Pubkey,
    pub token_1_mint: Pubkey,

    pub token_0_program: Pubkey,          // SPL Token veya Token-2022 programı
    pub token_1_program: Pubkey,

    pub observation_key: Pubkey,          // == observation PDA
    pub auth_bump: u8,
    pub status: u8,                       // bitmask: deposit | withdraw | swap
    pub lp_mint_decimals: u8,
    pub mint_0_decimals: u8,
    pub mint_1_decimals: u8,

    pub lp_supply: u64,                   // lp_mint arzını yansıtır
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,
    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time: u64,                   // unix; bu tarihten önce swap'lar reddedilir
    pub recent_epoch: u64,

    // Yaratıcı-ücret state'i (orijinal düzenden sonra eklendi):
    pub creator_fee_on: u8,               // 0=BothToken, 1=OnlyToken0, 2=OnlyToken1
    pub enable_creator_fee: bool,
    pub padding1: [u8; 6],
    pub creator_fees_token_0: u64,
    pub creator_fees_token_1: u64,

    pub padding: [u64; 28],
}
```

Gerçekten okumanız gerekenler:

- **`lp_supply`** — havuzun LP mint'inin toplam arzının iç yansıması. LP-share matematiği için kullanın; değer mint'in zincir üstü arzıyla eşleşmeli, ancak bunu `PoolState`'ten okumak ekstra bir hesap getirmesini önler.
- **`protocol_fees_token{0,1}`**, **`fund_fees_token{0,1}`** — henüz taranmamış *birikmiş* ücretler. Bunlar swap fiyatlandırmasını etkilemez; `CollectProtocolFee` / `CollectFundFee` çağrılana kadar vault'larda kalırlar.
- **`status`** — `Swap`, `Deposit`, `Withdraw`'ın izin verilip verilmediğini kontrol eden bir bitmask. Admin tarafından `UpdatePoolStatus` aracılığıyla güncellenir. SDK bunu bir işlem oluşturmadan önce kontrol eder; doğrudan CPI yapıyorsanız, kendiniz kontrol edin.
- **`token0_program` / `token1_program`** — her vault için CPI yapılacak token programı. Biri klasik SPL Token, diğeri Token-2022 olabilir; bağımsızdırlar.
- **`open_time`** — Unix zaman damgası. Bu tarihten önce swap'lar başarısız olur. Havuz tohumlanabilmesi için `open_time` öncesinde mevduatlar izin verilir.
- **`creator_fee_on` / `enable_creator_fee`** — birlikte bu havuz için isteğe bağlı yaratıcı ücretinin etkin olup olmadığını ve swap'ın hangi tarafından toplandığını kontrol eder. `enable_creator_fee == false` yaratıcı-ücret yolunu tamamen sıfırlar. Etkinleştirildiğinde, `creator_fee_on` seçer: `0` = swap girdisi olan token'dan ücret al (`BothToken`); `1` = sadece `token_0`'dan ücret al (`token_1 → token_0` swap'larını atla); `2` = sadece `token_1`'den ücret al. `InitializeWithPermission` aracılığıyla havuz oluşturmada ayarlanır; daha sonra değişemez.
- **`creator_fees_token_{0,1}`** — `CollectCreatorFee` veya `CollectCreatorFeePermissionless` tarafından taranmış birikmiş yaratıcı ücretleri. Her iki yol da tam sayaçları sıfırlar; izinsiz yol alıcıları `pool_creator`'ın kanonik ATA'larına sabitler.

### `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub disable_create_pool: bool,
    pub index: u16,                       // seed'le eşleşir
    pub trade_fee_rate: u64,              // örn. 2500 = %0.25
    pub protocol_fee_rate: u64,           // işlem ücretinin protokole giden kısmı
    pub fund_fee_rate: u64,               // işlem ücretinin fona giden kısmı
    pub create_pool_fee: u64,             // init'te bir kez ödenir (SOL veya token)
    pub protocol_owner: Pubkey,           // CollectProtocolFee'yi çağırabilir
    pub fund_owner: Pubkey,               // CollectFundFee'yi çağırabilir
    pub creator_fee_rate: u64,            // isteğe bağlı havuz-yaratıcı ücret oranı (hacmin 1/1_000_000'i)
    pub padding: [u64; 15],
}
```

Dikkat edilmesi gereken üç şey:

1. **`trade_fee_rate` ve `creator_fee_rate` hacmin kesirleridir**, her ikisi de `1/1_000_000` birimlerinde gösterilir. `2500` işlem hacminin %0.25'i anlamına gelir. **`protocol_fee_rate` ve `fund_fee_rate` *işlem ücretinin* kesirleridir** (hacmin değil), aynı `1/1_000_000` paydası ile. Yaratıcı ücreti işlem ücretinin bir kesri **değildir** — kendi bağımsız oranıdır. Tam aritmetik [`products/cpmm/fees`](/tr/products/cpmm/fees) sayfasındadır.
2. **`index` bir `u16`'dır**, bu nedenle seed hash'i 2 bayt big-endian kullanır. Byte sırasında bir hata entegrasyon hatasının yaygın nedenidir.
3. **`AmmConfig` havuz seviyesinde değişmezdir.** Bir havuz oluşturmada bir `AmmConfig`'e işaret eder ve asla değişmez. Ücret değişiklikleri yayılır çünkü havuz her swap'ta config'i okur — ancak havuz ücret seviyeleri arasında taşınamaz.

Yaratıcı ücretleri hakkında bir not: **oran** kendisi (`creator_fee_rate`) `AmmConfig`'te bulunur ve ücret seviyesi arasında paylaşılır. Belirli bir havuzun gerçekten bunu talep edip etmediği (`enable_creator_fee`) ve swap'ın hangi tarafında yer aldığı (`creator_fee_on`) `PoolState`'te bulunur. Yaratıcı ücreti işlem ücretinden **bağımsızdır** — kendi oranıdır, kendi sayaçlarına birikir (`creator_fees_token_{0,1}`), ve asla LP / protokol / fon paylarını işlem ücretinden azaltmaz. Tarama `CollectCreatorFee` veya hedef-kısıtlı `CollectCreatorFeePermissionless` aracılığıyla yapılır. Tam mekanik için [`products/cpmm/fees`](/tr/products/cpmm/fees) sayfasına bakın.

### `Permission`

`InitializeWithPermission` tarafından kullanılan küçük bir erişim-kontrol hesabı. CPMM programı, diğer programların (örn. bir token'ı CPMM'ye yükseltirken LaunchLab) belirli bir `AmmConfig`'e karşı havuz oluşturmaya yetkili olduklarını kanıtlayabilmeleri için izinli bir havuz-oluşturma yolunu destekler.

```rust
pub struct Permission {
    pub authority: Pubkey,    // InitializeWithPermission'ı çağırmaya izin verilen kişi
    pub padding: [u64; 8],
}
```

Permission PDA, CPMM admin'i veya özel bir permission-PDA yaratıcı yetkisi tarafından `CreatePermissionPda` aracılığıyla oluşturulur. Sadece CPMM admin'i `ClosePermissionPda` aracılığıyla iptal edebilir. Son kullanıcılar bu hesapla doğrudan etkileşime girmezler — bu, çapraz program akışları için altyapıdır. Rol sınırı için [`security/admin-and-multisig`](/tr/security/admin-and-multisig) sayfasına ve kanonik adresler için [`reference/program-addresses`](/tr/reference/program-addresses) sayfasına bakın.

### Vault'lar ve Token-2022

`vault0` ve `vault1` CPMM authority PDA tarafından sahiplenilir ve bunların token-program sahibi (`token_program`) havuz oluşturmada mint'in programı tarafından belirlenen SPL Token veya Token-2022'dir. Havuz iki durumu şeffaf bir şekilde işler — `Swap` / `Deposit` / `Withdraw` talimatı hesaplarında her taraf için doğru token-program ID'sini geçersiniz.

CPMM, havuz oluşturmada katı bir **extension allow-list** uygular (`is_supported_mint` in `utils/token.rs`). Bir Token-2022 mint, CPMM havuzunda kullanılabilir, ancak ve ancak taşıdığı **her** extension bu listedeyse:

- **`TransferFeeConfig`.** Mint tarafından her transferde uygulanır. Havuz `SwapBaseInput` mevduatları için alıcı taraf ve çekilişler için gönderen taraftır. Program vault'a inen **net** miktarı hesaplar ve eğriyi buna göre ayarlar. [`algorithms/token-2022-transfer-fees`](/tr/algorithms/token-2022-transfer-fees) sayfasına bakın.
- **`MetadataPointer`** ve **`TokenMetadata`.** Mint üzerinde standart meta veriler. Swap matematiğine hiçbir etkisi yoktur.
- **`InterestBearingConfig`.** Mint'in UI miktarı faiz biriktirir. Vault ham miktarları depolar; eğri sadece ham miktarlar üzerinde çalışır. APR gösteren UI'lar, UI miktarını render etmek için Token-2022 yardımcılarını çağırmalıdır.
- **`ScaledUiAmount`.** UI-görüntü ölçekleme extension'ı. `InterestBearingConfig` ile aynı işlem — eğri ham miktarları kullanır.

Diğer herhangi bir extension — `PermanentDelegate`, `TransferHook`, `DefaultAccountState`, `NonTransferable`, `ConfidentialTransfer`, `Group`/`GroupMember`, `MintCloseAuthority`, vb. — `Initialize`'ın `NotSupportMint` ile reddetmesine neden olur. İstisna, programda küçük bir hardcoded **mint whitelist**'i (bir avuç belirli pubkey) extension kontrolünü atlar; belirli mint'leri duruma göre entegre etmek için kullanılır.

Doğrulanmış-extension listesi ve mint whitelist'i CP-Swap kaynağında `programs/cp-swap/src/utils/token.rs` altında bulunur ve gelecekteki program yükseltmeleriyle değişebilir.

### Observation

Observation hesabı, her biri bir `block_timestamp` ve **kümülatif fiyat** depolayan `ObservationState` girdilerinin ring buffer'ıdır. Her swap'ta, son birinden yeterli zaman geçtiyse program yeni bir observation ekler. TWAP'lar iki observation okuyarak ve `Δcumulative / Δtime` bölerek hesaplanır.

```rust
// OBSERVATION_NUM programda 100 olarak hardcoded'dir.
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp:              u64,
    pub cumulative_token_0_price_x32: u128,   // Q32.32, taşma için üst 64 bit sol
    pub cumulative_token_1_price_x32: u128,
}

pub struct ObservationState {
    pub initialized:           bool,
    pub observation_index:     u16,                            // dairesel indeks
    pub pool_id:               Pubkey,
    pub observations:          [Observation; OBSERVATION_NUM], // 100 giriş
    pub last_update_timestamp: u64,                            // en son eklemenin zaman damgası
    pub padding:               [u64; 3],
}
```

Ring buffer **100 observation** için boyutlandırılmıştır. Her observation 40 bayttır, bu nedenle dizi tek başına 4.000 bayttır; tam `ObservationState` PDA'sı çevre alanları ve discriminator'dan sonra yaklaşık 4.100 bayttır.

İki tüketici kuralı:

- **Tek bir observation'ı fiyat olarak kullanmayın.** Bu bir *kümülatif*, spot fiyat değildir. TWAP hesaplamak için ikisini kullanın.
- **En az bir blok aralıklı observation'ları seçin.** Aynı blok içindeki swap'lar yeni bir observation üretmeyebilir; arka arkaya okumak aynı kaydı döndürebilir.

Daha fazla matematik [`products/clmm/accounts`](/tr/products/clmm/accounts) sayfasındadır.

## Hesap yaşam döngüsü

| Olay | Oluşturulan Hesaplar | Yok Edilen Hesaplar |
|-------|------------------|---------------------|
| `Initialize` | `poolState`, `lpMint`, `vault0`, `vault1`, `observation` | — |
| `Deposit` | — (kullanıcı LP ATA'sı oluşturabilir) | — |
| `Withdraw` | — | — |
| `Swap` | — (kullanıcı hedef ATA'sı oluşturabilir) | — |
| `CollectProtocolFee` | — | — |
| `CollectFundFee` | — | — |
| `UpdatePoolStatus` | — | — |

CPMM havuzları ve bunların PDA'ları **asla kapatılmaz**. Sıfır likidite olsa bile `poolState` kalır. Bu kasıtlıdır: aynı havuzu daha sonra yeniden tohumlamak, tarihsel observation buffer'ını korur ve PDA türetmesi istikrarlı kalır.
