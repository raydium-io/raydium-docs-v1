<Info>
  `PlatformConfig`, [`GlobalConfig`](/tr/products/launchlab/global-config) üzerine oturan **platform düzeyinde** bir katmandır. `GlobalConfig` protokol genelinde kuralları tanımlarken ("işlem ücreti %1, arz en az 10M olmalı, sadece bu cüzdan mezun olabilir"), `PlatformConfig` her başlatma platformunun — pump.fun, Raydium'un kendi arayüzü, üçüncü taraf launchpad'ler — kendi ücretini eklemek, mezuniyet sonrası LP'nin payını talep etmek, başlatmalarının hangi eğri şekillerini seçebileceğini kısıtlamak ve markalamalarını (ad, web sitesi, görüntü) zincir üzerinde göstermek için kullandığı araçtır.
</Info>

## Nedir

Bir `PlatformConfig` hesabı, bir platform için beş çapraz kesişen konuyu yönetir:

1. **Markalama** — ad, web sitesi, görüntü bağlantısı; hepsi satır içi depolanır, böylece herhangi bir explorer veya toplayıcı platformu görüntüleyebilir.
2. **Platform ücreti** — protokolün `trade_fee_rate` üzerine ek bir işlem ücreti (`fee_rate`). `platform_fee_wallet` adresine birikir. Her iki oluşturma ve güncelleme yolunda 500 bps (`50000`) ile sınırlandırılır; 2026-08-26'da 100 bps (`10000`) üzerinden yükseltildi — bkz. [Ücret sınırları](#ücret-sınırları).
3. **LP göçü bölüşümü** — üç depolanan tam sayı (`platform_scale`, `creator_scale`, `burn_scale`) toplamı `1_000_000` olur. 2026-08-17 yükseltmesinden önce, yaratıcı ölçeği ayrı bir yaratıcı Fee Key'i üretirdi. Yükseltmeden sonra gerçekleştirilen göçler ilk ikisini platform'a ait kilitli LP payına birleştirir; geri kalan yakılır.
4. **Eğri parametresi beyaz listesi** — tam olarak hangi `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)` kombinasyonlarının bu platformda izin verileceğini listeleyen bir `Vec<PlatformCurveParam>`. Vektör boşsa veya tüm girişler geçersizse, **herhangi bir** kombinasyon izin verilir; aksi takdirde başlatmalar tam olarak bir girişle eşleşmelidir.
5. **Global-config beyaz listesi** — seçilen `GlobalConfig` için platform tarafından oluşturulan bir `PlatformAllowConfig` gerektiren isteğe bağlı bir kısıtlama.

PDA türetme:

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // platform'un sahip pubkey'i
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Kanonik seed listesi için kaynakta `create_platform_config` bölümüne bakın.)

## Düzen

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (payda 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (payda 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // ClaimPlatformFee'yi imzalar
    pub platform_nft_wallet:         Pubkey,            // CPMM mezuniyetinde platform NFT payını alır
    pub platform_scale:              u64,               // platform NFT'ye basılan LP'nin payı
    pub creator_scale:               u64,               // yükseltmeden önce yaratıcı payı; sonrasında platform payına eklenir
    pub burn_scale:                  u64,               // kalıcı olarak yakılan LP'nin payı
    pub fee_rate:                    u64,               // platform'un işlem ücreti (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 sıfırlarla doldurulmuş
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // mezuniyet sonrası havuzun bağlanacağı CPMM AmmConfig
    pub creator_fee_rate:            u64,               // mezuniyet öncesi alınan yaratıcı tarafı ücreti
    pub transfer_fee_extension_auth: Pubkey,            // Token-2022 başlatmaları için: mint oluşturmadan çekme-tutma yetkisi, mezuniyetten ücret-yapılandırma yetkisi
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // toplam_kilitli_tutar'ın platform payı
    pub platform_cp_creator:         Pubkey,            // mezuniyet sonrası CPMM havuzunda isteğe bağlı yaratıcı-kayıt
    pub restrict_global_config:      u8,                // 0 = kısıtlanmamış, 1 = izin PDA'sı gerekli
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // izin verilen eğri şekillerinin beyaz listesi
}
```

`platform_scale + creator_scale + burn_scale` tam olarak `1_000_000` olmalıdır. 2026-08-17 yükseltmesinden önce, `creator_scale` ayrı olarak kilitliydi ve Fee Key'i token yaratıcısına giderdi. Yükseltmeden sonra gerçekleştirilen göçler için, `platform_scale`'e eklenir ve kilitli LP hakları platform'a gider. Güncellenmiş mantık altında örnek sonuçlar:

- `(0, 100_000, 900_000)` — %90 LP yakılır, %10 platform'a kilitlenir.
- `(50_000, 100_000, 850_000)` — %85 yakılır, %15 platform'a kilitlenir.
- `(0, 0, 1_000_000)` — tam yakma, NFT basımı yok. Katı "içeriden kimse yok" başlatmaları.

## Markalama alanları

`name`, `web` ve `img` satır içi bayt dizileridir, boyut sabitine kadar sıfırlarla doldurulmuştur. Bunları dizeler olarak okumak için ilk `\0`'a kadar dilimleyin:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

Sabitler kasıtlı olarak cömerttir (`name: 64`, `web: 256`, `img: 256`), böylece platformlar explorer'lar ve toplayıcılar için yeterli meta veri içerebilir ve zincir dışı depolamaya dokunmaz. Bu boyutları aşan herhangi bir şey `CreatePlatformConfig`'de `InvalidInput` ile geri döner.

## Ücret mekaniği

Bir `PlatformConfig`'e bağlı bir eğri üzerindeki swap üç katmanlı ücret alır:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` protokolün `protocol_fee_owner` adresine birikir (`CollectFee` aracılığıyla talep edilir).
- `platform_fee` platform başına bir kasaya birikir (`ClaimPlatformFee` veya `ClaimPlatformFeeFromVault` aracılığıyla talep edilir; bkz. [`instructions`](/tr/products/launchlab/instructions)).
- `creator_fee` yaratıcının pubkey'i + quote mint tarafından anahtarlanan platform başına bir kasaya birikir (`ClaimCreatorFee` aracılığıyla talep edilir).

### Ücret sınırları

Her iki oran da `1/1_000_000` cinsinden gösterilir, bu nedenle `5000` 50 bps ve `50000` 500 bps'dir.

| Oran | Sınır | Uygulandığı yer |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` oluşturmada — `InvalidInput` ile geri döner. `update_platform_fee_rate` bunu değiştiren her güncelleme varyantında (`FeeRate` ve `AllInfo`) — `InvalidPlatformInfo` ile geri döner. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` oluşturmada ve `update_creator_fee_rate` güncellemede — her ikisi de `InvalidPlatformInfo` ile geri döner. |

`fee_rate` için iki uygulama noktası farklı dosyalardaki ayrı `require!` çağrılarıdır, bu nedenle farklı hata kodları taşırlar, ancak aynı tavanı uygularlar. Herhangi bir izin verilen oranla oluşturulan bir platform daha sonra düzenlenebilir, `AllInfo` toplu varyantı da dahil olmak üzere tüm alanları bir kez yeniden yazar.

Her iki `fee_rate` sınırı da orijinal olarak 100 bps (`10000`) idi. Güncelleme sınırı 2026-01-27'de `25000` (250 bps) olarak taşındı; 2026-08-26'da her ikisi de `50000` (500 bps) olarak taşındı — bkz. [changelog girişi](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` her iki oranı da sınırlamaz. Dört swap talimatının aldığı işlem başına `share_fee_rate` argümanını — referral ücretini — sınırlar ve başka hiçbir şeyi değil. Bkz. [`global-config`](/tr/products/launchlab/global-config#fees).

## Token-2022 transfer-fee yetkileri

`transfer_fee_extension_auth`, bir başlatma `InitializeWithToken2022` aracılığıyla transfer ücreti eklenmiş olarak oluşturulduğunda, temel mint'in `TransferFeeConfig` yetkililerini tutacak platform anahtarını adlandırır. Uzantı iki yetkiliye sahiptir ve bunlar başlatma yaşam döngüsünün **farklı noktalarında** teslim edilir:

| Yetki | Mint oluşturmada sahibi | `MigrateToCpswap` sonrasında sahibi |
|---|---|---|
| `withdraw_withheld_authority` — Token-2022'nin token hesaplarında tuttuğu ücretleri çeker | `transfer_fee_extension_auth`, doğrudan mint'e yazılır. Alan `Pubkey::default()` olduğunda başlatma `authority` PDA'sına geri döner. | Zaten platform anahtarıdır, bu nedenle hiçbir şey hareket etmez. Göç, `authority` PDA hala tuttuğunda yalnızca yeniden atar. |
| `transfer_fee_config_authority` — ücret oranını ve maksimum ücreti değiştirir | Her zaman başlatma `authority` PDA'sı. | `transfer_fee_extension_auth`, bu alan varsayılan değilse. |

2026-08-27 öncesinde mint, her iki yetkilide `authority` PDA ile oluşturulurdu ve her ikisi de mezuniyet sırasında platform'a taşınırdı. Program hiçbir çekme-tutma veya hasat talimatı göstermez, bu nedenle bağlama eğrisi aşamasında tutulan ücretler başlatma mezun olana kadar erişilemezdi. Çekme tarafını mint oluşturmada yazmak, bunları ilk işlemden itibaren talep edilebilir hale getirir — bkz. [changelog girişi](/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority).

Planlama için değer olan iki sonuç:

- **Alanı başlatmadan sonra değil, öncesinde ayarlayın.** `transfer_fee_extension_auth` `Pubkey::default()` iken oluşturulan bir başlatma, çekme tarafına `authority` PDA'sını koyar. Alanı daha sonra ayarlamak hala çalışır — mezuniyet, PDA'yı yerinde bulur ve yetkileri teslim eder — ancak bu arada hiçbir şey tutulan bakiyeyi çekemez.
- **Alanı başlatma ortasında döndürmek iki yetkiliye ayırır.** Bir başlatmanın oluşturulması ile mezuniyeti arasında `transfer_fee_extension_auth` değiştirin ve mint'in çekme-tutma yetkilisi oluşturmada yapılandırılan anahtarda kalır (PDA artık tutmaz, bu nedenle göç bu teslimi atlar) ücret-yapılandırma yetkilisi yeni anahtara gider. Başlatmalar arasında döndürün veya iki anahtarı Token-2022 aracılığıyla doğrudan uzlaştırmayı planlayın.

Alanı başlatmanın tüm yaşamı boyunca `Pubkey::default()` konumunda bırakan bir platform, her iki yetkiliye de `authority` PDA'sında kalıcı olarak sahip olur: ücret oranı asla değiştirilemez ve tutulan bakiye asla çekilemez. Transfer ücreti ekli bir başlatmaya yalnızca platform bu anahtarları tutmayı amaçlıyorsa ekleyin.

## NFT göçü bölüşümü (yalnızca CPMM)

Bir başlatma CPMM'ye mezun olduğunda, göç talimatı `CPMM::InitializeWithPermission` tarafından basılan LP token'larını iki şekilde böler:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

`lp_to_platform` sıfır değilse, LP-Lock programı bunu `platform_nft_wallet` tarafından sahip olunan bir Fee Key NFT'sine sarar. Bu, ayrı platform ve yaratıcı Fee Key'leri oluşturan yükseltme öncesi davranışın yerini alır. Yükseltmeden önce tamamlanan göçler tarafından oluşturulan Fee Key'ler değişmeden kalır. Bu LP-fee hakkı, `platform_cp_creator` tarafından kontrol edilen CPMM yaratıcı ücretlerinden ayrıdır.

Yakma dilimi doğrudan yakılır, bu nedenle hiçbir hesap bunu çekemez veya bu payın temsil ettiği LP ücretlerini talep edemez.

Depolanan `migrate_type = 0` olan mevcut başlatmalar hala eski AMM v4 yolunu kullanabilir. Yeni başlatma bu göç türünü reddeder.

## Eğri parametresi beyaz listesi

`curve_params: Vec<PlatformCurveParam>`, platformun başlatmalarının hangi eğri şekillerini seçebileceğini kısıtlamak için mekanizmasıdır. Vektör boş değilse ve en az bir girişi geçerliyse, program `Initialize`'da başlatmanın parametrelerinin tam olarak bir girişle eşleşmesini uygular.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // bu platform'un beyaz listesi içinde sıra
    pub global_config:        Pubkey,       // bu girişin hangi GlobalConfig'e uygulandığı
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // yeni başlatmalar 1 = CPMM gerektirir; u8::MAX = joker
    pub migrate_cpmm_fee_on:        u8,    // 0 = yalnızca quote, 1 = her ikisi. u8::MAX = joker
    pub supply:                     u64,   // 0 = joker
    pub total_base_sell:            u64,   // 0 = joker
    pub total_quote_fund_raising:   u64,   // 0 = joker
    pub total_locked_amount:        u64,   // u64::MAX = joker
    pub cliff_period:               u64,   // u64::MAX = joker
    pub unlock_period:              u64,   // u64::MAX = joker
}
```

Her alanın **joker** anlamına gelen bir sentinel değeri vardır (herhangi bir değer eşleşir): `u64` alanları için `u64::MAX`, `u8` alanları için `u8::MAX`, arz / satış / fon toplama alanları için `0`. Tüm sentinel'leri olan bir `BondingCurveParam` "her şeye izin ver" — boş beyaz liste davranışına eşdeğer.

`Initialize`'daki eşleştirme algoritması:

1. `curve_params`'ı `global_config`'i başlatmanın seçilen `GlobalConfig`'i ile eşleşen girişlere filtreleyin.
2. Filtrelenmiş liste boşsa, herhangi bir parametreye izin verin (platform bu `GlobalConfig` için hiçbir şeyi beyaz listeye almadı).
3. Filtrelenmiş listedeki her girişin `all_is_invalid()` varsa (her alan joker), herhangi bir parametreye izin verin.
4. Aksi takdirde girişleri yineleyin; her girişi için başlatmanın parametrelerini her joker olmayan alana karşı kontrol edin. Tüm joker olmayan alanlar eşleşirse, kabul edin ve dönün.
5. Hiçbir girişi eşleşmezse, `InvalidInput` ile geri döner.

Bu, bir platformun "sadece standart 1B-arz / 800M-satılan / 30k-USDC-yükseltme / vesting yok şeklini izin veririz" demesini sağlar; bu dört alan için somut değerler ve başka yerlerde joker'ler yazarak. Veya daha katı bir platform, desteklenen başlatma katmanı başına bir veya dört ayrı şekli numaralandırabilir.

`MAX_CURVE_PARAMS = 10` beyaz liste boyutunu sınırlar.

## `PlatformAllowConfig` — bir platformu kısıtlama

Her platform, başlatmalarının hangi `GlobalConfig` hesaplarını kullanabileceğini kısıtlamayı seçer. `restrict_global_config`'i `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)` ile ayarlayın.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

PDA seed'leri: `[b"platform_allow_config", platform_config, global_config]`.

Platform yöneticisi `CreatePlatformAllowConfig` ve `ClosePlatformAllowConfig` aracılığıyla izin verilen çift başına bir hesap oluşturur veya kapatır. Kısıtlama `1` olduğunda, başlatma beklenen PDA için `remaining_accounts`'ı arar ve eksik hesabı `NotEnoughRemainingAccounts` ile reddeder. Kısıtlama `0` olduğunda, izin hesabı gerekli değildir.

Eski protokol-yönetici tarafından yönetilen `PlatformGlobalAccess` hesabı ve oluşturma/kapatma talimatları emekli olmuştur. Mevcut `PlatformConfig` ve `GlobalConfig` boyutları değişmez, ancak kod çözücüler eski genel bayrağı yeni platform bayrağı ile değiştirmelidir. Eski erişim PDA'ları yeni kontrol tarafından tüketilmez.

```ts
const platformConfig = await raydium.launchpad.getPlatformConfig(platformConfigPda);

console.log("Platform:", readString(platformConfig.name));
console.log("Ücret oranı:", platformConfig.feeRate, "(/1M)");
console.log("NFT bölüşümü:",
  platformConfig.platformScale,
  platformConfig.creatorScale,
  platformConfig.burnScale,
);
console.log("Eğri beyaz listesi boyutu:", platformConfig.curveParams.length);
```

"Bu token nereden başlatıldı" gösteren bir UI için, `PoolState.platform_config` orijinal `PlatformConfig`'i doğrudan gösterir — bir kez getirin ve markalamayı önbelleğe alın.

## Güncelleme yolu

| Talimat | İmzalayan | Ne değişir |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | platform yöneticisi (bir kez) | Hesabı `PlatformParams` ile başlatır. |
| `UpdatePlatformConfig` | platform yöneticisi | `param: u8` tarafından anahtarlanan genel gönderim; çağrı başına bir alanı değiştirir veya `AllInfo` aracılığıyla tüm alanları bir kez. Markalama alanları, ücret oranları, vesting cüzdanı ve çeşitli cüzdanlar hepsi bununla ayarlanabilir. Her iki ücret oranı da bunları değiştiren her varyant üzerinde [Ücret sınırları](#ücret-sınırları) içindeki sınırlara karşı yeniden doğrulanır. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | platform yöneticisi | Bu platform için izin verilen bir `GlobalConfig` ekleyin veya kaldırın. |
| `UpdatePlatformCurveParam` | platform yöneticisi | `(global_config, index)` tarafından bir `PlatformCurveParam` girişi ekleyin veya değiştirin. |
| `RemovePlatformCurveParam` | platform yöneticisi | Bir girişi temizleyin (tüm sentinel = joker olarak ayarlayın). |
| `ClaimPlatformFee` | `platform_fee_wallet` | Platform ücretini `PoolState.quote_vault`'tan temizleyin. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | Platform başına ücret kasasını temizleyin (PDA `[platform_config, quote_mint]`'de). |

Cüzdan döndürmeleri (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) hepsi `UpdatePlatformConfig` aracılığıyla gider. Tam `param` kodları için kaynağın `update_platform_config` gönderim tablosunu okuyun.

## Yaygın tuzaklar

- **Beyaz liste sentinel'leri yanlış ayarlanmış.** `total_locked_amount = 0` olan bir `BondingCurveParam` joker *değildir* — vesting'i açıkça devre dışı bırakan başlatmalarla eşleşir. Bu alan için joker `u64::MAX`'tır. Aynı tuzak `cliff_period` ve `unlock_period` için de vardır. Sentinel'leri doğru ayarlamak için `clear()` kullanın (program bunu gösterir).
- **NFT-bölüşümü yuvarlama.** Üç ölçek tam olarak `1_000_000`'e toplanmalıdır. `CreatePlatformConfig`'de bir hata geri döner; çalışma zamanında bir hata ekstra bir LP birimi basacak veya yakacak, bu da katı eşitlik kontrolünün orada olmasının nedenidir.
- **Platform vesting çift tahsisi.** `platform_vesting_scale > 0` ise, platform başlatmanın fon toplaması bittikten sonra bir kez `CreatePlatformVestingAccount` çağırmalıdır; unutursa, bu pay tahsis edilmemiş ve sonsuza kadar hareketsiz kalır (başlatmanın `total_locked_amount` bütçesi tüketilir ancak platform asla talep etmez).
- **`platform_cp_creator` belirsizliği.** `Pubkey::default()` olarak ayarlandığında, başlatma yaratıcısı mezuniyet sonrası CPMM havuzunun `pool_creator`'ı olarak kaydedilir; gerçek bir anahtara ayarlandığında, o anahtar kaydedilir. Bu, mezuniyet sonrası CPMM yaratıcı ücretlerinin yararlanıcısını ve orijinal `CPMM::CollectCreatorFee` yolunu imzalayabilecek kişiyi belirler. İzinsiz koleksiyon yolu hala bu kaydedilen anahtarın kanonik ATA'larını öder. Platform-yapılandırma oluşturma zamanında hangi modeli istediğinize karar verin.
- **`transfer_fee_extension_auth` geç ayarlanmış veya döndürülmüş.** Alan Token-2022 başlatması başına iki kez okunur — mint oluşturmada `withdraw_withheld_authority` için, mezuniyette `transfer_fee_config_authority` için — bu nedenle bu iki an arasında değişen bir değer iki yetkiliye farklı anahtarlarda bırakır. Bkz. [Token-2022 transfer-fee yetkileri](#token-2022-transfer-fee-yetkileri).
- **İzin hesabı olmadan kısıtlama.** `restrict_global_config`'i etkinleştirmeden önce gerekli `PlatformAllowConfig`'i oluşturmak, bu yapılandırmayı seçen yeni başlatmaları engeller.
