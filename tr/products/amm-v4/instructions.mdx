## `Initialize2`

Mevcut bir OpenBook market'e bağlı yeni bir AMM v4 pool'u başlat.

**Argümanlar**

```
nonce:        u8
open_time:    u64
init_pc_amount:   u64
init_coin_amount: u64
```

**Hesaplar** (yazılabilir `W`, imzalayan `S`)

| # | Ad | W | S | Notlar |
|---|-----|---|---|--------|
| 1 | `token_program` |   |   | `== spl_token::id()` olarak kontrol edilir. |
| 2 | `associated_token_program` |   |   | Yaratıcının LP ATA'sını oluşturmak için kullanılır. |
| 3 | `system_program` |   |   | |
| 4 | `rent` |   |   | Hâlâ `initialize_account` / `initialize_mint` CPI'lerine iletilir — kaldırmayın. |
| 5 | `amm` | W |   | `AmmInfo` PDA'sı `[programId, market, "amm_associated_seed"]`; burada oluşturulur. |
| 6 | `amm_authority` |   |   | PDA `["amm authority"]`; `nonce` argümanı bump değerine eşit olmalıdır. |
| 7 | `lp_mint` | W |   | PDA `[programId, market, "lp_mint_associated_seed"]`; burada oluşturulur. |
| 8 | `coin_mint` |   |   | `pc_mint`'ten farklı olmalıdır (`InvalidCoinMint`). |
| 9 | `pc_mint` |   |   | |
| 10 | `pool_coin_token_account` | W |   | PDA `[programId, market, "coin_vault_associated_seed"]`. |
| 11 | `pool_pc_token_account` | W |   | PDA `[programId, market, "pc_vault_associated_seed"]`. |
| 12 | `pool_target_orders_account` | W |   | PDA `[programId, market, "target_associated_seed"]`. |
| 13 | `amm_config` |   |   | Program düzeyinde yapılandırma PDA'sı `["amm_config_account_seed"]`; uyumsuzlukta `InvalidConfigAccount`. |

| 16 | `user_wallet` | W | S | Yaratıcı. Rent, havuz oluşturma ücretini ve ilk yatırımı öder. |
| 17 | `user_token_coin` | W |   | |
| 18 | `user_token_pc` | W |   | |
| 19 | `user_token_lp` | W |   | Yaratıcının LP ATA'sı; program tarafından oluşturulur. |

<Note>
  **Kabul edilen iki düzen.** Yukarıdaki 19 hesaplı liste önerilen olandır. Geriye dönük uyumluluk
  için program ayrıca 21 hesaplı eski bir düzeni de okur; bu düzen 7. konuma yoksayılan bir
  `amm_open_orders`, 16. konuma ise yoksayılan bir `market_program` ekler — depo içindeki
  `initialize2` komut oluşturucusunun hâlâ ürettiği düzen budur. Başka herhangi bir uzunluk eski
  düzene göre konumsal olarak ayrıştırılır ve başarısız olur.
</Note>

**Son koşullar**

- Yaratıcıya mint'lenen LP = `sqrt(init_coin_amount × init_pc_amount) − 10^coin_mint.decimals`. LP ondalıkları `coin_mint.decimals` ile eşittir, dolayısıyla çıkarılan miktar tam olarak bir bütün LP token'ıdır; hiçbir zaman mint'lenmez ve kalıcı olarak dolaşım dışıdır. `sqrt(...)` bunun altındaysa komut `InitLpAmountTooLess` ile geri döner.
- `AmmInfo.lp_amount`, mint'lenen miktarı **değil**, tam `sqrt(...)` değerini saklar — bu nedenle `lp_mint.supply`, `amm.lp_amount`'tan kalıcı olarak bir bütün LP token'ı kadar daha düşüktür. Tüm orantısal matematik `amm.lp_amount` kullanır.
- OpenBook emirleri yayınlanmaz (emir defteri ızgarası kaldırılmıştır). `AmmInfo.market`, 15. yuvada geçirilen hesabı kaydeder; ancak `AmmInfo.open_orders` ve `AmmInfo.market_program` ikisi de `Pubkey::default()` olarak yazılır ve `coin_lot_size` / `pc_lot_size` / `min_size` `0` olarak başlatılır. 21 hesaplı eski düzende fazladan gelen `amm_open_orders` ve `market_program` hesapları okunur ve atılır.

**Yaygın hatalar** — `InvalidCoinMint` (coin ve pc mint aynı), `InvalidConfigAccount` (yanlış `amm_config` PDA'sı), `InvalidFee` (yanlış havuz oluşturma ücreti hedefi), `InvalidProgramAddress` (yanlış `amm_authority` veya yanlış `nonce`), `RepeatCreateAmm` (bu market için bir havuz zaten mevcut), `InitLpAmountTooLess`, `InvalidSupply` (init miktarlarından biri `0` ya da LP mint'inin zaten arzı var), `AlreadyInUse`.

## `SwapBaseIn`

Tam giriş swap'ı. Her zaman bir **AMM yolu** swap'ıdır (OpenBook eşleştirmesi aracılığıyla yönlendirilmez).

<Note>
  **Yeni kod için V2 varyantlarını kullanın.** AMM v4'ün OpenBook bağımlılığı kaldırıldığından, V1 giriş noktaları (`SwapBaseIn`, `SwapBaseOut`) hala tam 17 hesap listesini (veya isteğe bağlı target-orders hesabı ile 18) bekler, ancak OpenBook/market hesapları şimdi **konumsal olarak kabul edilir ve yoksayılır** — doğrulanmaz ve CPI yayınlanmaz. Yanlış hesap *sayısı* geçirmek hala `WrongAccountsNumber` ile geri döner, ancak market hesabı *içeriği* artık kontrol edilmez. Yeni entegrasyonlar [`SwapBaseInV2` / `SwapBaseOutV2`](#swapbaseinv2-/-swapbaseoutv2) kullanmalıdır, bunlar çok daha küçük bir hesap listesi alır ve bugün kanonik yürütme yolunu temsil eder. V1 formları burada bütünlük için ve mevcut zincir üstü işlemleri okumak için belgelenmiştir.
</Note>

**Argümanlar**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Hesaplar** (kısaltılmış)

| # | Ad | W | S |
|---|-----|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `amm_open_orders` | W |   |
| 5 | `amm_target_orders` | W |   |
| 6 | `pool_coin_token_account` | W |   |
| 7 | `pool_pc_token_account` | W |   |
| 8 | `market_program` |   |   |
| 9 | `market` | W |   |
| 10 | `market_bids` | W |   |
| 11 | `market_asks` | W |   |
| 12 | `market_event_queue` | W |   |
| 13 | `market_coin_vault` | W |   |
| 14 | `market_pc_vault` | W |   |
| 15 | `market_vault_signer` |   |   |
| 16 | `user_source_token_account` | W |   |
| 17 | `user_dest_token_account` | W |   |
| 18 | `user_owner` |   | S |

**Matematik** — [`products/amm-v4/math`](/tr/products/amm-v4/math) bölümüne bakın.

**Ön koşullar**

- `AmmStatus::from_u64(amm.status).swap_permission()` doğrudur — yani `status` değeri `1` (`Initialized`), `6` (`SwapOnly`) veya `7` (`WaitingTrade`)'tür. `status` bir enum değeridir, bitmask değildir; bkz. [`products/amm-v4/accounts`](/tr/products/amm-v4/accounts#status).
- `amm.state_data.pool_open_time <= now`.
- `amount_in > 0`.
- `user_source_token_account` en az `amount_in` tutar.

**Son koşullar**

- Kullanıcı kaynak token'ın `amount_in`'ini kaybeder, hedef token'ın `amount_out ≥ minimum_amount_out`'unu kazanır.
- Swap ücreti vault'larda kalır ve `k` değişmezini yükseltir. `need_take_pnl_*` sayaçlarına swap'lar tarafından **dokunulmaz** — protokol PnL'si, bir sonraki `Deposit`, `Withdraw` veya `WithdrawPnl` işleminde `k` deltasından yeniden hesaplanır (`Processor::calc_take_pnl`).
- Not: `state_data.swap_*_in_amount` / `swap_*_out_amount` analitik sayaçları **artık güncellenmez** — değerleri dondurulmuştur. Hacim analitikleri için işlem günlüklerini kullanın.

**Yaygın hatalar** — `ExceededSlippage`, `InvalidInput`, `InvalidStatus`, `NotAllowed` (coin/pc mint özdeş).

## `SwapBaseInV2` / `SwapBaseOutV2`

Varyant swap giriş noktaları (etiketler **16** / **17**) **OpenBook hesaplarını tamamen atlar**. Matematik V1 yolu ile özdeştir, ancak hesap listesi sadece AMM tarafı ve kullanıcıya küçülür — **8 hesap, ve `amm_open_orders` geçirilmez**:

| # | Ad | W | S |
|---|-----|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `pool_coin_token_account` | W |   |
| 5 | `pool_pc_token_account` | W |   |
| 6 | `user_source_token_account` | W |   |
| 7 | `user_dest_token_account` | W |   |
| 8 | `user_owner` |   | S |

Pool rezervleri şimdi vault bakiyeleridir (bekleyen PnL eksi), bu nedenle fiyat teklifi matematik basittir ve v1 yolu ile özdeştir. Hesaplama tasarrufu yapmak ve (şimdi yoksayılan) market hesaplarını geçmekten kaçınmak için V2 kullanın. Raydium yönlendiricisi AMM v4 aracılığıyla yönlendirirken her zaman V2 formunu kullanır.

Argümanlar V1 formları ile aynıdır (`SwapBaseInV2` için `amount_in / minimum_amount_out`; `SwapBaseOutV2` için `max_amount_in / amount_out`).

## `MonitorStep` ve diğer kaldırılan talimatlar

<Warning>
  **Kaldırıldı — artık çağrılamaz.** 2026-07 güncellemesi itibarıyla, `MonitorStep` (tag 2) programdan kaldırılmış ve şimdi çağrılırsa **geri döner** (`unimplemented!`). İstemci oluşturucusu da silindi. Aynı durum `MigrateToOpenBook` (5), `WithdrawSrm` (8), `SimulateInfo` (12), `AdminCancelOrders` (13) ve eski `Initialize` (0) / `PreInitialize` (10) pool oluşturma giriş noktaları için geçerlidir — bunun yerine `Initialize2` kullanın.
</Warning>

Tarihsel olarak, `MonitorStep` pool'un OpenBook etkileşimini çalıştırdı: doldurulmuş siparişleri yerleştirdi (OpenBook CPI aracılığıyla market vault'larından pool vault'larına gelirleri taşıdı), eski siparişleri iptal etti ve `target_orders` ile `amm_open_orders` arasındaki boşluğu kapatmak için yeni siparişler yayınladı. OpenBook bağımlılığı kaldırıldığında, çalıştırılacak bir şey yoktur ve talimat gitmiştir. Hala çağıran herhangi bir keeper veya entegrasyon çağrıyı kaldırmalıdır.

## `SetParams`

Raydium multisig tarafından çağrılan yönetici param değişiklikleri. Argümanlar bir `param: u8` etiketi + yüküdür.

<Warning>
  **Kırıcı değişiklik (yalnızca yönetici).** Hesap listesi sadece `[amm (W), admin (S)]`'ye indirildi (otorite, açık siparişler, hedef siparişler, vault ve tüm market hesapları kaldırıldı). `param` enum'u **yeniden numaralandırıldı ve kırpıldı**: `Status` = 0, `State` = 1, `Fees` = **2** (9 idi), `SetOpenTime` = **3** (11 idi). Tüm sipariş defteri ızgarası parametreleri ve `AmmOwner`, `LastOrderDistance`, `UpdateOpenOrder` kaldırıldı ve `SetParamsInstruction` yapısı `new_pubkey` ve `last_order_distance`'ı bıraktı. Yönetici araçları güncellenmeli.
</Warning>

## `CreateConfigAccount` / `UpdateConfigAccount`

Program düzeyindeki `AmmConfig` PDA'sının (tohum `["amm_config_account_seed"]`) yönetici yönetimi. Hesap tam olarak üç anlamlı alan tutar — `pnl_owner`, `cancel_owner` ve `create_pool_fee` — ve buna ek olarak iki ayrılmış dolgu bölgesi; havuz oluşturma bayrağı yoktur. `UpdateConfigAccount`, `param = 0` ile `pnl_owner`'ı, `param = 1` ile `cancel_owner`'ı ve `param = 2` ile `create_pool_fee`'yi ayarlar.

<Note>
  **2026-09'da değişti ve geriye dönük uyumlu.** `CreateConfigAccount` artık rent sysvar'ı okumaz. Hesap listesi şimdi **4 hesap**, 5'ten aşağı:

  | # | Ad | W | S |
  |---|-----|---|---|
  | 1 | `admin` | W | S |
  | 2 | `amm_config` | W |   |
  | 3 | `pnl_owner` |   |   |
  | 4 | `system_program` |   |   |

  Program, geçirilen sysvar hesabını deserialize etmek yerine `Rent::get()` öğesinden rent parametrelerini okur — Solana 3.0 bağımlılığı bump'ının doğal kıldığı şey.

  Kaldırılan hesap listenin **sonunda** idi ve işleyici hesaplarını `next_account_info` aracılığıyla konumsal olarak uzunluk kontrolü olmadan okur. Eski 5 hesap listesini hala geçiren mevcut bir yönetici aracı bu nedenle çalışmaya devam eder: sondaki rent hesabı basitçe asla okunmaz. Acele etmeden uygun olduğunda güncelleyin. `UpdateConfigAccount` değişmez.
</Note>

`Initialize2` rent sysvar'ı 3. konumda tutar ve hala **kullanır**: program `Rent::from_account_info` öğesini çağırmayı bıraktı, ancak pool'un vault'larını ve LP mint'ini oluşturan `spl_token::initialize_account` ve `initialize_mint` CPI'lerine iletilir. Hesap listesinden bırakmayın.

## `WithdrawExcessLamports`

Program kontrollü hesaplardan rent-exempt minimumunun üzerinde oturan lamportların yönetici tarafından temizlenmesi. [SIMD-0437 rent azaltması](/tr/solana-fundamentals/rent-and-reclaimable-rent) her adımdan sonra hesaplar oluşturulduğunda bıraktığı aşırı finansmanı kurtarmak için 2026-09 güncellemesinde eklendi.

Yalnızca fazlalığı taşır. Token bakiyeleri, hesap verileri, sahipleri ve pool durumu dokunulmaz ve talimat zaten minimumda olan bir hesapta no-op'tır — bu nedenle tekrar tekrar ve her rollout adımından sonra tekrar ateşlemek güvenlidir.

**Argümanlar** — hiçbiri. Yük tek tag baytı `18`'dir.

**Hesaplar**

| # | Ad | W | S | Notlar |
|---|-----|---|---|--------|
| 1 | `collect_lamports` | W | S | Her süpürülen lamport için hedef. Kümenin collect-lamports cüzdanına eşit olmalıdır — [`reference/program-addresses`](/tr/reference/program-addresses#excess-lamports-collection-wallets) bölümüne bakın. Başka bir imzalayan `InvalidSignAccount` ile başarısız olur. |
| 2 | `amm_authority` |   |   | Tek AMM v4 otorite PDA'sı, program tarafından `["amm authority"]` öğesinden sabit `254` nonce'u ile yeniden türetilir. Token programı CPI'lerini imzalar. |
| 3 | `token_program` |   |   | **SPL Token.** `spl_token::id()` karşısında kontrol edilir; yanlış bir değer `InvalidSplTokenProgram` ile başarısız olur. |
| 4.. | kaynak hesapları | W |   | Süpürülecek `M` hesapları, herhangi bir sayı, herhangi bir sıra. |

**Her kaynak hesabı nasıl işlenir**

Program kaynak hesabının `owner` öğesine göre gönderir:

| Kaynak hesabı sahibi | İşleme |
|---|---|
| SPL Token, `data_len == 165` (bir token hesabı), yerel olmayan | CPI `WithdrawExcessLamports` (token programı discriminant `38`), `amm_authority` tarafından imzalanmış. |
| SPL Token, `data_len == 165`, yerel (wSOL) | `WithdrawExcessLamports` yerel bir hesapta kullanılamaz. Program `SyncNative` CPI'si yapar, sarılı `amount`'un ne kadar büyüdüğünü ölçer, tam o delta için `UnwrapLamports` (discriminant `45`) yapar, sonra sarılı bakiyenin ön senkronizasyon değerine geri döndüğünü iddia eder — aksi takdirde `LamportsCalculateError`. Havuzun SOL tarafı likiditesine bu nedenle asla dokunulmaz. |
| SPL Token, başka herhangi bir boyut (bir LP mint) | CPI `WithdrawExcessLamports`, `amm_authority` tarafından imzalanmış. |
| AMM v4 programının kendisi (`AmmInfo`, `TargetOrders`, `AmmConfig`) | Program hesabı doğrudan `rent.minimum_balance(data_len)` değerine kadar borçlandırır. |
| Başka herhangi bir şey | **Sessizce atlanır.** Hata yok, lamport taşınmaz. |

**Yaygın hatalar** — `InvalidSignAccount` (yanlış imzalayan), `InvalidSplTokenProgram` (slot 3'te yanlış program), `InvalidProgramAddress` (yanlış `amm_authority`), `LamportsCalculateError` (özel kod `60`; wSOL gidiş-dönüş sıfıra net olmadı) ve program sahibi yolundan `InsufficientFunds` bir hesap kendi rent minimumundan daha az tuttuğunda.

**SDK oluşturucusu yok.** `@raydium-io/raydium-sdk-v2` bu talimat için bir oluşturucu göndermez ve `raydium-sdk-V2-demo` repo da göndermez — bu bir yönetici yoludur. Elle kodlayın, [`solana-fundamentals/rent-and-reclaimable-rent`](/tr/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) içindeki cüzdan tarafı süpürmenin yaptığı şekilde token programı talimatı için.
