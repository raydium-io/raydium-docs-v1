## Hesap envanteri

Canlı bir CLMM havuzu aşağıdaki hesap aileleri tarafından tanımlanır. CLMM programına ait olanlar hariç tümü, iki mint ve bunların vault'ları program tarafından sahiplenilir.

| Hesap | Amaç | Havuz başına sayı |
|---------|---------|----------------|
| `AmmConfig` | Ücret katmanı: işlem ücreti oranı, protokol payı, fon payı, varsayılan tick-aralığı. Bu katmandaki tüm havuzlar arasında paylaşılır. | 1 (paylaşılan) |
| `PoolState` | Mevcut `sqrt_price_x64`, mevcut tick, toplam likidite, ücret büyümesi globalleri, ödül bilgisi, gözlem işaretçisi. | 1 |
| `TickArrayState` | `TICK_ARRAY_SIZE` bitişik tick'in bir bloğu. Yalnızca talep üzerine başlatılır. | 0 ≤ N ≤ aralık |
| `TickArrayBitmapExtension` | `PoolState` içindeki satır içi bitmap'in ötesinde hangi tick dizilerinin var olduğunu izleyen taşma bitmap'i. | 0 veya 1 |
| `PersonalPositionState` | Her LP pozisyonu için bir tane. Aralığı, likiditeyi ve son görülen ücret/ödül büyümesini depolar. Yetki = NFT sahibi. | pozisyon başına 1 |
| Pozisyon NFT mint'i | Arz 1 olan mint, `PersonalPositionState` ile ilişkili. Token hesabı varsayılan olarak dondurulmamıştır; V2, yalnızca temel bir mint kısıtlı-yayıncı filtresine uyduğunda onu dondurur. | pozisyon başına 1 |
| `ObservationState` | TWAP için fiyat gözlemlerinin halka tamponu. | 1 |
| `token_0_vault`, `token_1_vault` | Havuzun bakiyelerini tutan token hesapları. Havuz yetkilisi tarafından sahiplenilir. | 2 |
| `DynamicFeeConfig` | Dinamik ücret mekanizması için yeniden kullanılabilir parametre seti. `create_customizable_pool` aracılığıyla oluşturulan havuzlar katılabilir. Yönetici tarafından yönetilir. | paylaşılan (dizin başına) |
| `LimitOrderState` | Açık her limit emri için bir tane. Sahibi, tick'i, tarafı, toplam tutarı, kapatılan çıktı anlık görüntüsünü kaydeder. | emir başına 1 |
| `LimitOrderNonce` | Her `(wallet, nonce_index)` başına sayaç, benzersiz emir PDA'larını türetir. | (wallet, index) başına 1 |

## `PoolState`

Havuzun canlı durumu, her swap ve her pozisyon değişikliğinde okunur.

```rust
// programs/amm/src/states/pool.rs
pub struct PoolState {
    pub bump:           [u8; 1],
    pub amm_config:     Pubkey,            // fee tier binding
    pub owner:          Pubkey,            // admin (multisig)
    pub token_mint_0:   Pubkey,
    pub token_mint_1:   Pubkey,
    pub token_vault_0:  Pubkey,
    pub token_vault_1:  Pubkey,
    pub observation_key: Pubkey,

    pub mint_decimals_0: u8,
    pub mint_decimals_1: u8,
    pub tick_spacing:   u16,               // inherited from amm_config at init

    pub liquidity:      u128,              // total active (in-range) liquidity
    pub sqrt_price_x64: u128,              // Q64.64 of sqrt(price)
    pub tick_current:   i32,               // current tick index

    pub padding3:       u16,
    pub padding4:       u16,

    // Global fee growth per unit of liquidity, Q64.64.
    pub fee_growth_global_0_x64: u128,
    pub fee_growth_global_1_x64: u128,

    // Accrued-but-not-swept protocol fees (per mint).
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,

    // Reserved padding for future upgrades.
    pub padding5: [u128; 4],

    // Status bitmask. Bits 0-5: open-position, decrease-liquidity,
    // collect-fee, collect-reward, swap, limit-order. A set bit disables
    // the corresponding operation.
    pub status:  u8,

    // Fee-collection mode (CollectFeeOn).
    //   0 = FromInput (deduct fee from the swap input — Uniswap-V3 default)
    //   1 = Token0Only (always deduct fee from token0 vault)
    //   2 = Token1Only (always deduct fee from token1 vault)
    pub fee_on: u8,

    // Client-supplied index (u16 LE) folded into the pool PDA seeds by
    // create_customizable_pool_v2. [0, 0] for pools created via CreatePool /
    // CreateCustomizablePool (the seed component collapses to empty).
    pub seed_index: [u8; 2],
    pub padding: [u8; 4],

    // Live reward streams (up to REWARD_NUM = 3).
    pub reward_infos: [RewardInfo; 3],

    // Inline bitmap tracking initialized tick-arrays in the primary range.
    pub tick_array_bitmap: [u64; 16],

    // Reserved padding for future upgrades.
    pub padding6: [u64; 4],

    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time:    u64,                 // currently disabled by the program
    pub recent_epoch: u64,

    // Per-pool dynamic-fee state. Zero-valued unless the pool was
    // created with `enable_dynamic_fee = true` via create_customizable_pool.
    pub dynamic_fee_info: DynamicFeeInfo,

    // Reserved for future upgrades.
    pub padding1: [u64; 14],
    pub padding2: [u64; 32],
}
```

Gerçekten dokunacağınız alanlar:

- **`sqrt_price_x64`** ve **`tick_current`** havuzun fiyat durumudur. Her swap'ta birlikte güncellenir. `tick_current`, `log_{1.0001}(price)` tabanının tabanıdır.
- **`liquidity`** **aktif** likidite — aralığı `tick_current` içeren tüm pozisyonların `L` değerlerinin toplamıdır. Bir swap her tick'i geçtiğinde ve her pozisyon açıldığında/kapatıldığında/yeniden boyutlandırıldığında değişir.
- **`fee_growth_global_{0,1}_x64`** tüm havuz geçmişi boyunca likidite birimi başına kazanılan kümülatif ücretlerdir. Pozisyonlar kendilerine ne borçlu olduğunu hesaplamak için bunu okur.
- **`tick_spacing`** başlatmada `AmmConfig`'e kilitlenir ve asla değişmez. Hangi tick indekslerine pozisyon uç noktaları olarak izin verildiğini belirler.
- **`tick_array_bitmap`** spot fiyat etrafındaki yaygın olarak kullanılan tick aralığını kapsayan bir **satır içi** bitmap'tir. Pozisyonları uzağa ulaşan havuzlar için taşma izlemesi ayrı `TickArrayBitmapExtension` içinde yaşar.
- **`fee_on`** havuz oluşturmada sabitlenir. `0` (FromInput) klasik Uniswap-V3 davranışını yeniden üretir. `1` ve `2` swap ücretini kitabın tek bir tarafına yönlendirir — ödünleşmeler için [`products/clmm/fees`](/tr/products/clmm/fees) bölümüne bakınız.
- **`seed_index`** `CreatePool` / `CreateCustomizablePool` aracılığıyla oluşturulan her havuz için `[0, 0]` değerindedir (çift başına bir kanonik havuz). **Sıfır olmayan** bir değer, havuzun `CreateCustomizablePoolV2` (2026-10-22 öncesinde `CreatePermissionedPool` adında) aracılığıyla oluşturulduğu ve dizinin havuzun PDA seed'lerinin bir parçası olduğu anlamına gelir; bu da aynı `(config, mint0, mint1)` için birkaç havuzun bir arada bulunmasını sağlar. Böyle bir havuzun adresini yeniden türetmek için `seed_index` değerini bilmeniz gerekir.
- **`dynamic_fee_info`** dinamik ücret artışı için oynaklık durumunu taşır. Etkinleştirildiğinde, her swap `AmmConfig.trade_fee_rate` üzerine bir `dynamic_fee_component` yeniden hesaplar. Düzen `DynamicFeeInfo` altında belgelenmiştir; dinamik ücret olmayan havuzlar tüm yapıyı sıfır bırakır.

## `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub index: u16,                       // uses "amm_config"+u16 seed

    pub owner:             Pubkey,        // protocol-fee owner (CollectProtocolFee)
    pub protocol_fee_rate: u32,           // fraction of trade fee to protocol, denom 1e6
    pub trade_fee_rate:    u32,           // trade fee in 1e6ths of volume
    pub tick_spacing:      u16,           // default spacing for pools using this config
    pub fund_fee_rate:     u32,           // fraction of trade fee to fund, denom 1e6
    pub padding_u32: u32,

    pub fund_owner: Pubkey,               // fund-fee owner (CollectFundFee)
    pub padding: [u64; 3],
}
```

2026-09 güncellemesinden bu yana, `CreateAmmConfig` programın sabit kodlanmış `protocol_fee_owner::ID` değerini `owner` içine ve `fund_fee_owner::ID` değerini `fund_owner` içine yazar. Bundan önce, yönetici imzalayanın anahtarını her ikisine de kopyalardı. Mevcut konfigürasyonlar oluşturuldukları veya döndürüldükleri şeyi tutar, bu nedenle her iki alanı da hesaptan okuyun. `UpdateAmmConfig` parametreleri `3` / `4` yine de bunları döndürür. Adresler [`reference/program-addresses`](/tr/reference/program-addresses#clmm-fee-owner-wallets) içindedir.

Tipik bir yayınlanmış CLMM ücret katmanları seti (`GET https://api-v3.raydium.io/main/clmm-config` ile doğrulayın):

| Dizin | `trade_fee_rate` | Tick aralığı | Tipik kullanım |
|-------|------------------|--------------|-------------|
| 0 | `100` (0.01%) | 1 | Sabit çiftler, USDC/USDT |
| 1 | `500` (0.05%) | 10 | İlişkili mavi çipli |
| 2 | `2_500` (0.25%) | 60 | Standart çiftler |
| 3 | `10_000` (1.00%) | 120 | Değişken veya uzun kuyruk |

`protocol_fee_rate` ve `fund_fee_rate` işlem ücretinin kesintileridir; CPMM ile aynı kural. [`products/clmm/fees`](/tr/products/clmm/fees) bölümüne bakınız.

## `TickArrayState`

CLMM, tek bir tick için ayrı bir kayıt tutmaz. Bu milyarlarca hesap olurdu. Bunun yerine **`TICK_ARRAY_SIZE` bitişik başlatılmış-veya-başlatılmamış tick'leri** (program sürümüne bağlı olarak tipik olarak 60 veya 88) ilk kullanımda tembel olarak oluşturulan bir `TickArrayState` içinde gruplandırır.

```rust
pub const TICK_ARRAY_SIZE: usize = 60;
pub const TICK_ARRAY_SIZE_USIZE: usize = 60;

pub struct TickArrayState {
    pub pool_id:                Pubkey,
    pub start_tick_index:       i32,                            // lowest tick in this array
    pub ticks:                  [TickState; TICK_ARRAY_SIZE],   // 60 entries
    pub initialized_tick_count: u8,
    pub recent_epoch:           u64,
    pub padding:                [u8; 107],
}

pub struct TickState {
    pub tick:                       i32,
    pub liquidity_net:              i128,                       // ΔL when crossing this tick upward
    pub liquidity_gross:            u128,                       // total L referencing this tick
    pub fee_growth_outside_0_x64:   u128,                       // see math.mdx
    pub fee_growth_outside_1_x64:   u128,
    pub reward_growths_outside_x64: [u128; 3],

    // Limit-order bookkeeping. All zero for ticks that have never carried
    // a limit order. See products/clmm/math for the matching algorithm.
    pub order_phase:                  u64,                      // monotonic FIFO cohort id
    pub orders_amount:                u64,                      // unfilled tokens in current cohort
    pub part_filled_orders_remaining: u64,                      // remaining tokens of partially-filled cohort
    pub unfilled_ratio_x64:           u128,                     // Q64.64; starts at 1.0 and shrinks as fills occur

    pub padding:                    [u32; 3],
}
```

Dört limit-order alanı, hiçbir zaman limit order için kullanılmamış herhangi bir tick'te sıfırdır. Bir tick'te emirler açıldığında, program bunları bir kohort dizisi olarak izler:

- `order_phase` kohort kimliğidir. Bir kohort "tamamen doldurulmamış" durumundan "kısmen doldurulmuş" durumuna geçtiğinde her seferinde artar.
- `orders_amount`, mevcut (en yeni) kohortu giriş-token toplamıdır.
- `part_filled_orders_remaining`, devam eden swaplar tarafından doldurulmakta olan önceki kohortu izler.
- `unfilled_ratio_x64`, kohort üzerinde taşınan bir Q64.64 çarpanıdır: bir swap kohortu X% doldurduğunda, oran `(1 − X)` ile çarpılır. Her açık emir, açılış zamanında kendi `(order_phase, unfilled_ratio_x64)` anlık görüntüsünü depolar, bu nedenle kapatma matematiği anlık görüntüleri karşılaştırmaya indirgenir.

Kurallar:

- Bir pozisyon uç noktası tick'i *t*, `t % tick_spacing == 0` koşulunu sağlamalıdır. Program aralık dışı pozisyonları reddeder.
- Tick'in **dizisi** `floor(t / (TICK_ARRAY_SIZE * tick_spacing)) * (TICK_ARRAY_SIZE * tick_spacing)` konumunda bulunur.
- Bir tick dizisi tembel olarak başlatılır: bir pozisyon veya swap'ın başlatılmamış bir diziyi ilk kez dokunması onu oluşturur ve kirayı öder.
- Bir tick dizisi program tarafından **asla kapatılmaz**. Tahsis edildikten sonra, içindeki her tick `liquidity_gross == 0` durumuna döndükten sonra bile havuzun ömrü boyunca devam eder. Sonraki pozisyonlar ve swaplar mevcut hesabı ek kira ödemeden yeniden kullanır. Tick dizileri için `ClosePosition` tarafından yönlendirilen temizleme yolu yoktur.

### `TickArrayBitmapExtension`

`PoolState.tick_array_bitmap` (satır içi) "spot'a yakın" aralığını kapsar — **±512** tick dizileri (`TICK_ARRAY_BITMAP_SIZE = 512`; `[u64; 16]` alanı 1.024 bit olup negatif ve pozitif başlangıç indeksleri arasında eşit olarak bölünür, bu nedenle dizi indeksleri −512 … +511). Bu aralığın dışında (aşırı tick değerleri için), program bir uzantı hesabı tutar:

```rust
pub struct TickArrayBitmapExtension {
    pub pool_id: Pubkey,
    pub positive_tick_array_bitmap: [[u64; 8]; 14],
    pub negative_tick_array_bitmap: [[u64; 8]; 14],
}
```

Pozisyonunuzun aralığı "normal" ise, uzantı hesabı hakkında hiç düşünmezsiniz. Tam aralık pozisyonları (örn. `(MIN_TICK, MAX_TICK)`) bunu gerektirir; SDK bunu sizin için çözer.

## Pozisyonlar

Bir CLMM pozisyonu, üç hesap artı bir mint'in **bir paketidir**:

### Pozisyon NFT mint'i

Arz 1 olan bir SPL Token veya Token-2022 mint'i. Sahibinin cüzdanındaki pozisyon NFT'si, o tek token'ı tutan bir ATA'dır. Program yetkilendirmeyi durumda depolanan bir Pubkey'e değil, **NFT'nin ATA bakiyesinin mevcut sahibine** anahtarlar.

Yeni pozisyon NFT mint'leri, tek token'ı basmadan ve mint yetkilendirmesini kaldırmadan önce `pool_state`'i dondurma yetkilisi olarak ayarlar. **Bir dondurma yetkilisi ayarlamak, NFT hesabını kendiliğinden dondurmaz.** Hesap, her iki koşul da geçerli olmadığı sürece donmuş ve aktarılabilir kalır: çağıran `OpenPositionV2` veya `OpenPositionWithToken22Nft` kullanır ve en az bir temel kasa mint'inin dondurma yetkilisi CLMM'nin kısıtlı-yayıncı listesinde görünür. Yalnızca o zaman CLMM, basımdan sonra NFT hesabını dondurur. Bu, `PersonalPositionState` veya `PoolState` baytlarında hiçbir değişiklik yapmaz.

### `PersonalPositionState`

Açık her pozisyon için bir tane. NFT mint'i kapalı anahtarlanmış.

```rust
pub struct PersonalPositionState {
    pub bump: [u8; 1],
    pub nft_mint: Pubkey,                 // this position's NFT mint
    pub pool_id:  Pubkey,

    pub tick_lower_index: i32,
    pub tick_upper_index: i32,

    pub liquidity: u128,                  // this position's L

    // Fee-growth snapshots at last time the position was touched.
    pub fee_growth_inside_0_last_x64: u128,
    pub fee_growth_inside_1_last_x64: u128,
    pub token_fees_owed_0: u64,           // accrued since last collect
    pub token_fees_owed_1: u64,

    pub reward_infos: [PositionRewardInfo; 3],
    pub recent_epoch: u64,
    pub padding: [u64; 7],
}

pub struct PositionRewardInfo {
    pub growth_inside_last_x64: u128,
    pub reward_amount_owed: u64,
}
```

### `ProtocolPositionState` (kullanımdan kaldırılmış)

<Note>
  Eski CLMM sürümleri, `(pool, tick_lower, tick_upper)` başına toplam muhasebe bilgilerini bir `ProtocolPositionState` PDA'sında depoladı. **Yeni sürümler artık bu hesabı oluşturmaz veya okumaz.** Slot, ABI uyumluluğu için `OpenPosition` / `IncreaseLiquidity` / `DecreaseLiquidity` hesap listelerinde bir `UncheckedAccount` olarak görünmeye devam eder, ancak program buna yazmaz. Zincir üzerinde mevcut hesaplar kalıntıdır; yönetici, bunlar için kirayı geri almak üzere `CloseProtocolPosition`'ı çağırabilir.

  Toplam aralık muhasebesi artık doğrudan iki uç noktası tick'inden (`liquidity_gross`, `liquidity_net` ve tick başına `fee_growth_outside_*` / `reward_growths_outside_x64`) `TickArrayState` içinde türetilir. Ücret-büyüme-içi formülü `fee_growth_inside = global − outside_lower − outside_upper` toplam pozisyon hesabı olmadan çalışmaya devam eder.
</Note>

## Gözlem

```rust
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp: u32,
    pub tick_cumulative: i64,                            // Σ tick_current × Δt
    pub padding:         [u64; 4],
}

pub struct ObservationState {
    pub initialized:       bool,
    pub recent_epoch:      u64,
    pub observation_index: u16,
    pub pool_id:           Pubkey,
    pub observations:      [Observation; OBSERVATION_NUM], // 100 entries
    pub padding:           [u64; 4],
}
```

CLMM'nin gözlem arabelleği, kümülatif fiyat değil, **kümülatif tick** depolar. Harici tüketiciler, `(tick_cumulative[t1] − tick_cumulative[t0]) / (t1 − t0)` aralığından geometrik-ortalama fiyatı hesaplar ve ardından `price = 1.0001 ** tick` hesaplar. Bkz. [`algorithms/clmm-math`](/tr/algorithms/clmm-math).

## `DynamicFeeConfig` ve `DynamicFeeInfo`

Dinamik ücret parametreleri iki yerde yaşar. Yeniden kullanılabilir şablon — `DynamicFeeConfig` — yönetici tarafından yönetilir ve katılan havuzlar arasında paylaşılır. Havuz başına çalışma zamanı durumu — `DynamicFeeInfo` — `PoolState` içine gömülü ve her swap tarafından güncellenir.

### `DynamicFeeConfig`

```rust
// programs/amm/src/states/pool_fee.rs
pub struct DynamicFeeConfig {
    pub index:                       u16,    // identifier; PDA seed component
    pub filter_period:               u16,    // seconds — within this window the volatility reference is held
    pub decay_period:                u16,    // seconds — beyond this window the reference fully decays
    pub reduction_factor:            u16,    // fixed-point in [1, 10_000); applied at decay
    pub dynamic_fee_control:         u32,    // fixed-point in (0, 100_000); fee-rate gain
    pub max_volatility_accumulator:  u32,    // ceiling on the volatility accumulator
    pub padding:                     [u64; 8],
}
```

PDA seed: `["dynamic_fee_config", index.to_be_bytes()]`. `create_dynamic_fee_config` (yönetici-kapılı) aracılığıyla oluşturulur ve `update_dynamic_fee_config` aracılığıyla değiştirilir. `enable_dynamic_fee = true` ile oluşturulan bir havuz, yapılandırmanın beş kalibrasyon parametresini (`filter_period`, `decay_period`, `reduction_factor`, `dynamic_fee_control`, `max_volatility_accumulator`) oluşturma zamanında kendi `DynamicFeeInfo`'suna kaydeder; `DynamicFeeConfig`'e yapılan sonraki düzenlemeler mevcut havuzları geriye dönük olarak etkilemez.

### `DynamicFeeInfo` (`PoolState` içine gömülü)

```rust
pub struct DynamicFeeInfo {
    pub filter_period:                u16,
    pub decay_period:                 u16,
    pub reduction_factor:             u16,
    pub dynamic_fee_control:          u32,
    pub max_volatility_accumulator:   u32,
    pub tick_spacing_index_reference: i32,    // tick-spacing-units; reference for next swap
    pub volatility_reference:         u32,    // running floor for the accumulator
    pub volatility_accumulator:       u32,    // current cumulative volatility (capped)
    pub last_update_timestamp:        u64,
    pub padding:                      [u8; 46],
}
```

Alt dört alan durumdur; üst beş alan `DynamicFeeConfig`'ten kopyalanan kalibrasyon parametreleridir. Ücret matematiği ve bozunma kuralları [`products/clmm/math`](/tr/products/clmm/math) ve [`products/clmm/fees`](/tr/products/clmm/fees) altında belgelenmiştir.

Formül tarafından kullanılan sabitler:

| Sabit | Değer | Anlamı |
|---|---|---|
| `VOLATILITY_ACCUMULATOR_SCALE` | `10_000` | Volatilite biriktiricisinin granülarite |
| `REDUCTION_FACTOR_DENOMINATOR` | `10_000` | `reduction_factor` için payda |
| `DYNAMIC_FEE_CONTROL_DENOMINATOR` | `100_000` | `dynamic_fee_control` için payda |
| `MAX_FEE_RATE_NUMERATOR` | `100_000` | Sonuç ücret oranında %10'luk sabit üst sınır |

## `LimitOrderState`

Açık her limit emir için bir hesap.

```rust
// programs/amm/src/states/limit_order.rs
pub struct LimitOrderState {
    pub pool_id:            Pubkey,
    pub owner:              Pubkey,
    pub tick_index:         i32,
    pub zero_for_one:       bool,    // direction: true sells token0 for token1
    pub order_phase:        u64,     // snapshot of TickState.order_phase at open time
    pub total_amount:       u64,     // input-token amount placed
    pub filled_amount:      u64,     // informational; computed precisely on settle
    pub settle_base:        u64,     // unfilled remainder at last settle/decrease
    pub settled_output:     u64,     // cumulative output-token paid to owner
    pub open_time:          u64,
    pub unfilled_ratio_x64: u128,    // Q64.64 snapshot of TickState.unfilled_ratio_x64 at open
    pub padding:            [u64; 4],
}
```

Yaşam döngüsü:

1. **Aç** — kullanıcı `open_limit_order`'ı çağırır, giriş token'ının `total_amount`'ını yatırır, emir bir `TickState` kohortuna bağlanır.
2. **(isteğe bağlı) Artır / Azalt** — `increase_limit_order` `total_amount`'a ekler; `decrease_limit_order` doldurulmamış token'ları (ve o noktaya kadar herhangi bir kapatılmış çıktıyı) döndürür.
3. **Kapat** — kohort tamamen veya kısmen doldurulduğunda, sahip *veya* operasyonel bekçi çıktı token'larını sahibinin ATA'sına göndermek için `settle_limit_order`'ı çağırır.
4. **Kapat** — `unfilled_amount == 0` olduğunda, hesap kapatılabilir. Kira her zaman `owner`'a döner.

PDA seed: `[owner.as_ref(), limit_order_nonce.key().as_ref(), limit_order_nonce.order_nonce.to_be_bytes().as_ref()]`. Emir PDA'sı bu nedenle `(owner, nonce_index, order_nonce)` başına benzersizdir.

## `LimitOrderNonce`

Belirli bir `(wallet, nonce_index)` çifti için sayaç; tek bir kullanıcının limit order'ların birden fazla paralel pipeline'ını PDA çarpışması olmadan çalıştırmasını sağlar.

```rust
pub struct LimitOrderNonce {
    pub user_wallet: Pubkey,
    pub nonce_index: u8,             // user-chosen, 0..255
    pub order_nonce: u64,            // monotonic, incremented every time a new order is opened
    pub padding:     [u64; 4],
}
```

PDA seed: `[user_wallet.as_ref(), &[nonce_index]]`. Çoğu istemci `nonce_index = 0` kullanır ve `order_nonce`'nin kardinaliteyi taşımasına izin verir.

## `Permission` (kullanımdan kaldırıldı)

`Permission` hesabı [2026-10-22 yükseltmesinde](/tr/reference/changelog/2026-10-22-clmm-customizable-pool-v2) kaldırılmıştır. Daha önce `CreatePermissionedPool`'u kontrol ederdi; bu işlem artık izinsiz `CreateCustomizablePoolV2` olmuştur. Program artık bu hesapları okumaz veya kapatmaz ve `CreatePermissionPda` / `ClosePermissionPda` talimatları ortadan kalkmıştır. Yükseltmeden önce oluşturulan PDA'lar (`["permission", authority]`, 280 bayt) zincir üzerinde atıl veri olarak kalır; CLMM'ye ait hesapları taradığınızda bunları yoksayın.

## Anahtar hesapları türetme

```ts
import { PublicKey } from "@solana/web3.js";

const CLMM_PROGRAM_ID = new PublicKey(
  "CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK"
); // see reference/program-addresses

function i32ToBytes(n: number): Buffer {
  const b = Buffer.alloc(4);
  b.writeInt32BE(n);
  return b;
}

export function deriveClmmAccounts(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
) {
  const [poolState] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  // NOTE: pools created via CreateCustomizablePoolV2 append a non-zero u16
  // seed_index (LE) as a 5th seed — see deriveCustomizablePoolV2 below.
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  const [tickArrayBitmapExtension] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_tick_array_bitmap_extension"), poolState.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return { poolState, observation, tickArrayBitmapExtension };
}

export function deriveTickArray(
  pool: PublicKey,
  startTickIndex: number,
) {
  const [tickArray] = PublicKey.findProgramAddressSync(
    [Buffer.from("tick_array"), pool.toBuffer(), i32ToBytes(startTickIndex)],
    CLMM_PROGRAM_ID,
  );
  return tickArray;
}

export function deriveDynamicFeeConfig(index: number) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16BE(index);
  const [pda] = PublicKey.findProgramAddressSync(
    [Buffer.from("dynamic_fee_config"), idx],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveCustomizablePoolV2(
  ammConfig: PublicKey,
  token0Mint: PublicKey,           // must already be sorted
  token1Mint: PublicKey,
  seedIndex: number,               // non-zero u16
) {
  const idx = Buffer.alloc(2);
  idx.writeUInt16LE(seedIndex);    // little-endian, unlike the u16 seeds above
  const [pool] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool"), ammConfig.toBuffer(),
     token0Mint.toBuffer(), token1Mint.toBuffer(), idx],
    CLMM_PROGRAM_ID,
  );
  return pool;
}

export function deriveLimitOrderNonce(
  wallet: PublicKey,
  nonceIndex: number,
) {
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), Buffer.from([nonceIndex & 0xff])],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function deriveLimitOrder(
  wallet: PublicKey,
  nonceAccount: PublicKey,
  orderNonce: bigint,
) {
  const nonceBytes = Buffer.alloc(8);
  nonceBytes.writeBigUInt64BE(orderNonce);
  const [pda] = PublicKey.findProgramAddressSync(
    [wallet.toBuffer(), nonceAccount.toBuffer(), nonceBytes],
    CLMM_PROGRAM_ID,
  );
  return pda;
}

export function derivePersonalPosition(nftMint: PublicKey) {
  const [personalPosition] = PublicKey.findProgramAddressSync(
    [Buffer.from("position"), nftMint.toBuffer()],
    CLMM_PROGRAM_ID,
  );
  return personalPosition;
}
```

Tam seed dizgeleri her zaman zincir üzerindeki IDL ve [`reference/program-addresses`](/tr/reference/program-addresses) ile karşılaştırılmalıdır.
