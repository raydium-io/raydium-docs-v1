| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Yüksek riskli işlemler göndermeden önce bunları ilgili config hesabından doğrudan okuyun.

### Paylaşılan config / PDA kuralları

Birkaç Raydium programı, genel anahtarları sabit olan ve genel API'de listelenen **config hesaplarını** ortaya çıkarır. Sabit kodlamayı tercih etmek yerine API aramasını tercih edin:

```
# CPMM ücret konfigürasyonları (bir dizi {id, index, tradeFeeRate, ...} döndürür)
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM ücret konfigürasyonları
GET https://api-v3.raydium.io/main/clmm-config
```

CPMM'nin havuz oluşturma ücreti alıcısı, API aracılığıyla türetilmiş veya aranmış değil, sabit bir hesaptır: `raydium-cp-swap`'ın `lib.rs` içinde `create_pool_fee_reveiver::ID`, şu anda `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`. CPMM'nin `initialize` talimatı bunu tam adresle doğrular, bu nedenle test ettiğiniz herhangi bir kümede zaten var olması gerekir.

Varsayılan CPMM `AmmConfig` dizini `0` (standart %0,25 havuz) ücret parametreleri, referans için:

| Alan | Değer | Anlamı |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | işlem hacminin %0,25'i |
| `protocol_fee_rate` | `120000` | işlem ücretinin %12'si (hacim değil) protokole yönlendirilir |
| `fund_fee_rate` | `40000` | işlem ücretinin %4'ü fon multisig'e yönlendirilir |
| `creator_fee_rate` | `500` | işlem hacminin %0,05'i havuz oluşturucuya (isteğe bağlı) |

Bölünmelerin nasıl oluştuğunu [`products/cpmm/fees`](/tr/products/cpmm/fees) ve ürünler arası matrisi [`reference/fee-comparison`](/tr/reference/fee-comparison) adresinde görün.

### PDA tohumları

Aşağıdaki tohumlar **kanonik** ve hem SDK hem de zincir üstü CPI'lar tarafından kullanılır. Her zaman PDA'ları hesaplayın; türetilmiş adresleri sabit kodlamayın.

```ts
// CPMM — tüm tohumlar aksi belirtilmedikçe statik ASCII dizelerdir.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` karma işlemden önce **genel anahtar bayt sırasına göre sıralanır** (token0 < token1). Bunu yanlış yapmak, var olmayan bir havuz için geçerli bir PDA verir.

Eşdeğer CLMM tohumları aynı stili izler; bkz. [`products/clmm/accounts`](/tr/products/clmm/accounts).

## Bir adresi zincir üstünde nasıl doğrulayacağınız

1. **Solana Explorer.** Adresi [explorer.solana.com](https://explorer.solana.com) adresine yapıştırın ve `Program` olarak işaretlendiğini ve mevcut bir yükseltme yetkilendirmesine sahip olduğunu onaylayın. Mainnet-beta, Raydium'un yükseltme yetkilendirmesi tarafından imzalanan dağıtımları göstermelidir.
2. **CLI.** Dağıtım yuvası, BPF yükleyicisi, yükseltme yetkilendirmesi ve veri uzunluğunu incelemek için `solana program show <PROGRAM_ID> -u mainnet-beta` kullanın. Bunları runbook'unuza kaydedin.
3. **IDL eki.** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` ile zincir üstü IDL'yi sorgulayın. IDL'nin `address` alanı eşleşmelidir. Aynı IDL'ler [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) adresinde yansıtılır — buna güvenmeden önce zincir üstü IDL'yi repo'ya karşı diff edin.
4. **Config/yönetici yetkilendirmeleri.** CPMM/CLMM config hesapları için, `owner`/`protocol_owner` alanını okuyun ve [`security/admin-and-multisig`](/tr/security/admin-and-multisig) adresinde yayınlanan mevcut Raydium multisig'i ile eşleştiğini onaylayın.

Yukarıdaki dört kontrolden herhangi biri bu sayfayla uyuşmazsa, bu sayfayı yanlış olarak değerlendirin ve yeni kod yazmadan önce bir sorun açın.
