### Paylaşılan config / PDA kuralları

Birkaç Raydium programı, genel anahtarları sabit olan ve herkese açık API'de listelenen **config hesaplarını** ortaya koymaktadır. Sabit kodlamayı tercih etmek yerine API aramasını tercih edin:

```
# CPMM ücret konfigürasyonları ({id, index, tradeFeeRate, ...} dizisini döndürür)
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM ücret konfigürasyonları
GET https://api-v3.raydium.io/main/clmm-config
```

Varsayılan CPMM `AmmConfig` indeksi `0` (standart %0,25 havuzu) ücret parametreleri, referans için:

| Alan | Değer | Anlamı |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | işlem hacminin %0,25'i |
| `protocol_fee_rate` | `120000` | işlem ücretinin %12'si (hacim değil) protokole yönlendirilir |
| `fund_fee_rate` | `40000` | işlem ücretinin %4'ü fon multisig'e yönlendirilir |
| `creator_fee_rate` | `500` | işlem hacminin %0,05'i havuz oluşturucuya (isteğe bağlı) |

Bölünmelerin nasıl oluşturulduğunu [`products/cpmm/fees`](/tr/products/cpmm/fees) sayfasında ve ürünler arası matrisi [`reference/fee-comparison`](/tr/reference/fee-comparison) sayfasında görebilirsiniz.

### PDA tohumları

Aşağıdaki tohumlar **kanonik** olup SDK ve zincir üstü CPI'lar tarafından kullanılır. PDA'ları her zaman hesaplayın; türetilmiş adresleri sabit kodlamayın.

```ts
// CPMM — aksi belirtilmedikçe tüm tohumlar statik ASCII dizileridir.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` hash işleminden önce **genel anahtar bayt sırasına göre sıralanır** (token0 < token1). Bunu yanlış yapmak, var olmayan bir havuz için geçerli bir PDA verir.

Eşdeğer CLMM tohumları aynı stili takip eder; bkz. [`products/clmm/accounts`](/tr/products/clmm/accounts).

## Bir adresi zincir üstünde nasıl doğrulayacağınız

1. **Solana Explorer.** Adresi [explorer.solana.com](https://explorer.solana.com) içine yapıştırın ve `Program` olarak işaretlendiğini ve mevcut bir yükseltme yetkilisine sahip olduğunu onaylayın. Mainnet-beta, Raydium'un yükseltme yetkilileri tarafından imzalanan dağıtımları göstermelidir.
2. **CLI.** Dağıtım slotu, BPF yükleyicisi, yükseltme yetkilileri ve veri uzunluğunu incelemek için `solana program show <PROGRAM_ID> -u mainnet-beta` kullanın. Bunları runbook'unuza kaydedin.
3. **IDL eki.** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` ile zincir üstü IDL'yi sorgulayın. IDL'nin `address` alanı eşleşmelidir. Aynı IDL'ler [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) adresinde yansıtılır — buna güvenmeden önce zincir üstü IDL'yi repo ile karşılaştırın.
4. **Config/yönetici yetkileri.** CPMM/CLMM config hesapları için `owner`/`protocol_owner` alanını okuyun ve mevcut Raydium multisig'i [`security/admin-and-multisig`](/tr/security/admin-and-multisig) sayfasında yayınlananla eşleştiğini onaylayın.

Yukarıdaki dört kontrolden herhangi biri bu sayfayla uyuşmazsa, bu sayfayı yanlış olarak değerlendirin ve yeni kod yazmadan önce bir sorun açın.
