## 릴리스

<Update label="2026-08-31" description="LaunchLab: 플랫폼 곡선 규칙이 곡선 매개변수 화이트리스트를 대체합니다">
  출시 매개변수 제한이 `PlatformConfig`에서 개별 `PlatformCurveRule` 계정으로 이동합니다. 규칙은 19개의 출시 매개변수에 대해 최대 25개의 `(field, op, value)` 제약 조건을 가진 최대 10개의 검사 그룹을 보유하며, `Eq` / `Gte` / `Lte` / `Neq`를 지원합니다. 이를 통해 플랫폼은 값 범위, 대체 계층, 졸업 평가 상한선, 마이그레이션 하한선, 토큰 유형 게이팅 또는 날짜에 따라 전환되는 그룹을 표현할 수 있습니다. 이는 동등성만 지원하는 화이트리스트로는 불가능했습니다. `PlatformConfig`는 944바이트 크기를 유지합니다: `restrict_curve_param`, `curve_rule_manager`, 제거된 벡터의 길이 접두사가 패딩에서 제거됩니다. 디코더는 후행 `Vec<PlatformCurveParam>`을 제거해야 하고, 출시 빌더는 플래그가 켜져 있는 동안 규칙 PDA를 `remaining_accounts`에 추가해야 합니다. 2개의 명령어가 제거되고 4개가 추가되며, 2개의 `UpdatePlatformConfig` 변형이 추가되고, `6024`–`6030`이 추가됩니다. IDL 새로고침이 필요합니다. SDK는 2개의 순수 오프체인 검사를 제공하므로 생성자가 되돌려진 트랜잭션에서 규칙을 배울 필요가 없으며, 항목은 메인넷에서 플래그를 활성화하기 전에 데브넷 리허설을 문서화합니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-31-launchlab-platform-curve-rules)
</Update>

<Update label="2026-08-27" description="LaunchLab: 플랫폼이 민트 생성에서 출금 보류 권한을 보유합니다">
  `InitializeWithToken2022`는 이제 `PlatformConfig.transfer_fee_extension_auth`를 출시 `authority` PDA 대신 새 기본 민트의 `withdraw_withheld_authority`에 기록하므로, 플랫폼은 졸업을 기다리지 않고 본딩 곡선 단계 중에 보류된 이전 수수료를 수집할 수 있습니다. 프로그램 자체에는 출금 보류 명령어가 없습니다. `MigrateToCpswap`은 PDA가 여전히 보유하고 있을 때만 해당 권한을 재할당하므로 두 세대의 민트에 대해 졸업이 작동합니다. `transfer_fee_config_authority`는 여전히 졸업 시에만 이동하므로, 출시 중에 `transfer_fee_extension_auth`를 회전하면 두 권한이 다른 키에 남아 있게 됩니다. 계정 레이아웃, 명령어, 인수 또는 오류 코드는 변경되지 않았습니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority)
</Update>

<Update label="2026-08-26" description="LaunchLab: 플랫폼 수수료율 상한선이 500 bps로 인상됩니다">
  플랫폼 `fee_rate` 상한선이 이를 검증하는 두 경로 모두에서 `50000`(500 bps)으로 이동합니다. `CreatePlatformConfig`는 프로그램의 첫 릴리스 이후 `10000`(100 bps)으로 제한되었습니다. `UpdatePlatformConfig`는 2026-01-27 이후 `25000`(250 bps)으로 제한되었습니다. 이제 두 검사가 일치하므로 허용된 비율로 생성된 플랫폼도 해당 비율로 업데이트할 수 있습니다. 이는 모든 다른 필드를 다시 작성하면서 `fee_rate`를 다시 검증하는 `AllInfo` 대량 변형을 포함합니다. 두 경로는 여전히 다른 오류를 발생시킵니다 (생성 시 `InvalidInput`, 업데이트 시 `InvalidPlatformInfo`). 계정 레이아웃, 명령어 또는 오류 코드는 변경되지 않았으며, 기존 플랫폼이나 출시는 가격이 다시 책정되지 않습니다. `GlobalConfig.max_share_fee_rate`는 100 bps로 유지되며 거래당 추천 `share_fee_rate`만 제한합니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)
</Update>

<Update label="2026-08-24" description="LaunchLab: Token-2022 견적 민트">
  이제 출시를 Token-2022 민트로 견적할 수 있습니다. `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, 4개의 스왑 명령어, 모든 수수료 청구는 견적 프로그램 슬롯에서 두 토큰 프로그램 중 하나를 허용합니다. 더 이상 사용되지 않는 `Initialize`는 레거시 전용으로 유지됩니다. 스왑 슬리피지 경계는 이제 지불자가 실제로 지불하거나 받는 것과 비교되며, 견적 민트의 이전 수수료를 차감합니다. `PoolState.token_program_flag` bit1이 의미를 갖게 되므로, 전체 바이트를 `0`과 비교하는 디코더는 레거시 기본 민트를 Token-2022로 잘못 읽습니다. `MigrateToCpswap`은 두 토큰 프로그램 계정의 이름을 `token_program` / `token_program_2022`로 변경하고, `6023`은 `CalculateOverflow`에 재사용됩니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab: CPMM 전용 출시 및 플랫폼 구성 제어">
  새로운 출시 초기화는 이제 CPMM을 요구하는 반면 레거시 AMM v4 바운드 상태는 마이그레이션 가능하게 유지됩니다. 이 릴리스 이전에는 `creator_scale`이 생성자 소유 수수료 키를 생성했습니다. 업그레이드 후 실행된 CPMM 마이그레이션은 대신 `platform_scale + creator_scale`을 하나의 플랫폼 소유 수수료 키 공유로 통합합니다. 플랫폼은 또한 자체 `PlatformAllowConfig` PDA로 출시를 제한할 수 있으며, 마이그레이션 빌더는 두 CPMM 지원 민트 PDA를 추가해야 합니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM: 제한된 발급자 포지션 NFT 동결">
  새로운 CLMM 포지션 NFT 민트는 풀을 동결 권한으로 사용하지만, 토큰 계정은 기본적으로 동결되지 않은 상태로 유지됩니다. 동결은 `OpenPositionV2` 또는 `OpenPositionWithToken22Nft`에서만 발생하며, 기본 볼트 민트 중 하나의 동결 권한이 제한된 발급자 목록과 일치할 때입니다. 일치하는 포지션은 전송하거나 소유자를 변경할 수 없지만 여전히 유동성을 관리할 수 있습니다. 해당 `ClosePosition` 호출은 CLMM이 원자적으로 해제, 소각 및 종료할 수 있도록 풀을 추가해야 합니다. 기존 포지션은 변경되지 않습니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM: 무허가 생성자 수수료 수집">
  추가 `CollectCreatorFeePermissionless` 명령어를 통해 모든 지불자가 누적된 모든 생성자 수수료를 수집할 수 있으며, 수혜자와 두 토큰 목적지를 `PoolState.pool_creator` 및 생성자의 정규 ATA로 제한합니다. 원래 생성자 서명 경로는 변경되지 않습니다. `CreatePermissionPda`는 또한 전용 부여 권한을 허용하는 반면, `ClosePermissionPda`는 관리자 전용으로 유지됩니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM: 허가된 다중 풀 및 한도 주문 동결 계정 보호">
  두 개의 추가적이고 역호환 가능한 CLMM 프로그램 업데이트입니다. `CreatePermissionedPool`은 클라이언트 제공 0이 아닌 `seed_index`를 풀 PDA 시드에 통합하여, 화이트리스트된 운영자 (하나의 `Permission` PDA를 보유한)가 `(config, mint0, mint1)` 당 여러 풀을 생성할 수 있도록 합니다. 따라서 풀 ID는 더 이상 쌍에 대해 정규적이지 않습니다. 새로운 관리자 명령어 `CreatePermissionPda` / `ClosePermissionPda`는 해당 부여를 관리하고, `PoolState`는 `seed_index` 필드를 얻습니다 (패딩에서 조각내어짐, 크기 변경 없음). 별도로, `OpenLimitOrder`는 이제 출력 측 계정을 가져가고 입력 또는 출력 토큰 계정이 동결된 주문을 거부합니다 (`NotApproved`).

  [전체 항목 읽기 →](/ko/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4: OpenBook / Serum 의존성 제거">
  AMM v4는 오래된 OpenBook/Serum 의존성, 모든 주문서 CPI, 죽은 시장 조성 명령어를 제거합니다. `SwapBaseIn` / `SwapBaseOut`, `Deposit`, `Withdraw`는 레이아웃을 유지합니다 (제거된 시장 계정은 이제 무시되며 검증되지 않음). **하드 브레이킹** `WithdrawPnl` (17 → 10, 호환성 없음) 및 `SetParams` (계정 감소 + 번호 변경된 `param`). `Initialize`, `PreInitialize`, `MonitorStep`, `MigrateToOpenBook`, `WithdrawSrm`, `SimulateInfo`, `AdminCancelOrders`는 더 이상 호출할 수 없습니다. 온체인 계정 레이아웃 및 오류 코드는 안정적으로 유지됩니다. 스왑을 V2 진입점으로 마이그레이션하세요.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM: 죽은 OpenBook (시장) 코드 제거">
  Stable AMM은 오래된 OpenBook 시장 조성 계정 및 코드를 제거합니다. 더 작은 `SwapBaseIn` / `SwapBaseOut` (18 → 9), `Deposit` (14 → 12), `Withdraw` (21/22 → 12) 레이아웃 (이전 레이아웃은 여전히 호환됨). **하드 브레이킹** `WithdrawPnl` 변경 (16 → 10, 호환성 없음). 추천 수수료 폐지 및 단순화된 볼트 전용 풀 자산 공식입니다. 대부분의 다른 Stable 명령어는 더 이상 호출할 수 없습니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>

<Update label="2026-05-18" description="CLMM: 한도 주문, 단측 수수료, 동적 수수료">
  3가지 선택적이고 역호환 가능한 CLMM 기능: 1급 한도 주문 (`limit_order_admin` 정산 키퍼 포함), 단측 수수료 수집 (`CollectFeeOn`), 변동성 추적 동적 수수료입니다. `CreateCustomizablePool`, `PoolState` 재구성 (**인덱서 브레이킹 변경**), 새로운 `TickState` 필드, 11개의 새로운 오류 코드 (숫자 이동 포함), 일치하는 SDK / API 추가를 추가합니다.

  [전체 항목 읽기 →](/ko/reference/changelog/2026-05-18-clmm-limit-orders)
</Update>

## 문서 규칙

- **버전 관리**: 이 문서는 달력 기반 버전 관리 (YYYY-MM-DD)를 사용합니다. 각 업데이트는 새로운 항목 페이지를 추가하고 위의 타임라인에 새로운 행을 추가합니다.
- **릴리스당 하나의 페이지**: 모든 릴리스 요약은 `reference/changelog/` 아래의 자체 페이지에 있으므로 이 인덱스는 짧게 유지되고 각 항목은 독립적으로 링크 가능합니다.
- **검증 날짜**: 모든 항목은 온체인 / API 상태 및 프로그램 소스에 대해 마지막으로 교차 확인된 시기를 기록합니다. 명시되지 않은 경우 항목의 주요 날짜를 가정하세요.
- **주요 변경 사항**: 영향을 받는 페이지에서 상자 경고로 표시되고 항목에서 태그됩니다.
- **범위**: 이 변경 로그는 문서 세트 자체를 다룹니다. 프로토콜 자체의 역사적 타임라인은 [`introduction/history-and-milestones`](/ko/introduction/history-and-milestones)에 있으며 "Raydium에서 X가 언제 발생했는가"에 대한 진실의 원천입니다.
