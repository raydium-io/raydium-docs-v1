이 릴리스는 CPMM을 새로 초기화된 런칭의 유일한 졸업 대상으로 만듭니다. 또한 잠금 LP 권리를 받는 대상을 변경하고, `GlobalConfig` 선택 제어를 플랫폼 관리자에게 이동하며, CPMM 마이그레이션 CPI 입력을 확장합니다.

## 통합자를 위한 요약

- **새로운 런칭은 CPMM 전용입니다.** `Initialize`, `InitializeV2`, `InitializeWithToken2022`는 `migrate_type = 1`을 요구합니다. AMM v4로 구성된 새로운 런칭은 `MigrateTypeNotMatch`를 반환합니다.
- **레거시 AMM v4 상태는 계속 지원됩니다.** `MigrateToAmm`은 제거되지 않습니다. 저장된 마이그레이션 타입이 `0`인 기존 풀을 졸업시킬 수 있습니다.
- **크리에이터 잠금 LP는 이 업그레이드 후 플랫폼으로 이동합니다.** 이 릴리스 이전에는 `creator_scale`이 별도의 크리에이터 소유 Fee Key를 생성했습니다. 업그레이드 후 실행된 마이그레이션은 `platform_scale + creator_scale`을 하나의 플랫폼 소유 잠금 LP 지분으로 결합합니다. `burn_scale`은 소각됩니다.
- **크리에이터 수수료는 별도로 유지됩니다.** 본딩 곡선 크리에이터 수수료와 CPMM 크리에이터 수수료는 LP Fee Key 권리가 아닙니다. `platform_cp_creator`는 여전히 원래 런칭 크리에이터 또는 플랫폼이 선택한 주소가 CPMM 크리에이터 기록 소유자가 되는지를 결정합니다.
- **플랫폼이 자신의 설정 허용 목록을 관리합니다.** `PlatformConfig.restrict_global_config`와 `PlatformAllowConfig`는 글로벌 관리자 관리 `requires_platform_auth` / `PlatformGlobalAccess` 모델을 대체합니다.
- **CPMM 마이그레이션 빌더는 변경해야 합니다.** 업그레이드된 경로는 10개의 고정된 남은 계정을 요구하고 정렬된 두 민트에 대한 CPMM `support_mint` PDA를 추가합니다.
- **위임된 권한이 `GlobalConfig`를 생성할 수 있습니다.** 기존 설정을 업데이트할 수는 없습니다.

## 새로운 런칭 대 기존 상태 동작

CPMM 전용 확인은 풀 초기화 중에 실행됩니다. 기존 `PoolState` 계정을 다시 쓰지 않습니다. 기존 AMM v4 바운드 런칭은 저장된 마이그레이션 타입을 유지하고 유지된 레거시 마이그레이션 명령을 사용할 수 있습니다.

`amm_creator_fee_on`은 이제 CPMM 크리에이터 수수료 측면(`QuoteToken` 또는 `BothToken`)만 제어합니다. 클라이언트는 이를 사용하여 대상 프로그램을 추론해서는 안 됩니다.

## LP 소유권 변경

세 가지 스케일 필드는 `PlatformConfig`에 남아 있으며, 합계는 여전히 `1_000_000`과 같아야 합니다. 런타임 분배는 이제 다음과 같습니다:

```text
platform locked LP = floor(total LP × (platform_scale + creator_scale) / 1_000_000)
burned LP          = total LP − platform locked LP
```

이 릴리스 이전에는 LaunchLab이 `creator_scale`을 별도로 잠금하고 해당 Fee Key를 토큰 크리에이터에게 발행했습니다. 업그레이드 후 실행된 마이그레이션의 경우, 동일한 스케일이 플랫폼 지분에 추가됩니다. 결합된 지분이 0이 아니면 LaunchLab은 `platform_nft_wallet`에 대해 하나의 Fee Key를 생성하고 새로운 크리에이터 Fee Key를 생성하지 않습니다.

이 변경은 업그레이드 이전에 완료된 마이그레이션으로 생성된 Fee Key 또는 잠금 유동성 기록을 수정하지 않습니다. 업그레이드 이전에 생성되었지만 이후에 마이그레이션된 런칭은 `MigrateToCpswap`이 실행될 때 분할이 적용되므로 새로운 분배를 따릅니다.

계정 레이아웃이 유지되므로 인덱서는 계정 크기 마이그레이션이 필요하지 않지만, UI 및 회계 시스템은 마이그레이션 버전에 따라 `creator_scale`을 해석해야 합니다.

## 플랫폼 허용 목록 마이그레이션

`GlobalConfig.requires_platform_auth`는 제거되고 해당 바이트는 패딩으로 돌아갑니다. `PlatformConfig`는 `restrict_global_config`에 대해 하나의 패딩 바이트를 재사용하므로 두 계정 크기 모두 변경되지 않습니다.

`restrict_global_config = 1`일 때, 초기화는 다음에서 파생된 PDA를 포함해야 합니다:

```text
["platform_allow_config", platform_config, global_config]
```

플랫폼 관리자가 이러한 계정을 생성하고 닫습니다. 이전 `CreatePlatformGlobalAccess` 및 `ClosePlatformGlobalAccess` 명령은 제거되며, 이전 `PlatformGlobalAccess` PDA는 새로운 확인을 만족하지 않습니다. 자동 변환 경로는 없습니다.

## CPMM 마이그레이션 계정 변경

`MigrateToCpswap`은 이제 다음 0 기반 `remaining_accounts` 인덱스를 예상합니다:

| 인덱스 | 목적 |
|---|---|
| 0–4 | 플랫폼 Fee Key 소유자, 민트, ATA, 잠금 유동성 PDA, 메타데이터 |
| 5 | 원래 크리에이터 폴백 |
| 6 | CPMM 권한 PDA |
| 7 | 선택적 구성된 `platform_cp_creator` 계정 |
| 8–9 | 정렬된 mint0 및 mint1에 대한 CPMM `support_mint` PDA |

별도의 크리에이터 잠금 계정을 추가하거나 인덱스 8–9를 생략하는 이전 빌더는 업그레이드된 경로와 호환되지 않습니다. CPMM 프로그램 아래에서 `[b"support_mint", mint]`를 사용하여 두 support-mint 주소를 파생시킵니다.

## 오류 및 IDL 영향

코드 `6000`–`6021`은 안정적으로 유지됩니다. 이전 플랫폼 글로벌 액세스 변형은 제거됩니다. `6022`는 이제 `InvalidPlatformAllowConfig`를 의미하며, 이전 `6023`은 더 이상 존재하지 않습니다.

`PlatformAllowConfig` 명령을 구성하기 전에, 업데이트된 설정 필드를 디코딩하거나, 새로운 CPMM 마이그레이션 레이아웃을 구축하기 전에 LaunchLab IDL을 새로고침하세요.
