## Anchor 에러 코드 작동 방식

Anchor는 프로그램의 `ErrorCode` 열거형의 각 변형에 `6000`부터 시작하는 숫자 코드를 할당합니다. 실패한 트랜잭션은 다음을 표시합니다:

- **숫자 에러 코드** (예: `0x1771` = 6001) - 트랜잭션 로그에 표시됨
- **에러 이름** (예: `InvalidOwner`) - IDL에서 제공됨
- **`#[msg(...)]` 문자열** - Anchor가 `log_messages`에 출력함

통합자는 메시지 문자열이 아닌 **숫자 코드**로 매칭해야 합니다(문자열은 버전 업데이트 없이 다시 작성될 수 있습니다).

```ts
// 예: CPMM 슬리피지 에러를 감지하고 깔끔한 UX 메시지를 표시합니다.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

| 6044 | `InvalidDynamicFeeConfigParams` | Invalid dynamic fee config params | `CreateDynamicFeeConfig` / `UpdateDynamicFeeConfig`가 거부되었습니다. 또는 `CreateCustomizablePool`이 유효한 구성 없이 동적 수수료를 활성화했습니다. | 관리자 경로에서는 N/A. 사용자 경로에서는 "동적 수수료 구성이 유효하지 않습니다". |

| 6046 | `ZeroSqrtPrice` | sqrt_price_x64 must be greater than 0 | `CreateCustomizablePool`(또는 사용자 정의 가능한 초기 제곱근 가격을 허용하는 다른 경로)이 `sqrt_price_x64 == 0`으로 호출되었습니다. | "초기 가격은 0보다 커야 합니다." |
| 6047 | `ZeroLiquidity` | liquidity must be greater than 0 | 유동성 제공 경로가 `liquidity == 0`으로 호출되었고 보상 금액이 없습니다. | "유동성 금액은 0보다 커야 합니다." |
| 6048 | `MissingBaseFlag` | base_flag is required when liquidity is zero | 금액별 개방 포지션 경로가 `liquidity == 0`을 계산했고 호출자가 어느 쪽이 기본인지 명확히 하기 위해 `base_flag`를 제공하지 않았습니다. | "0이 아닌 유동성을 제공하거나 어느 토큰이 기본인지 지정하세요." |

| 6050 | `MissingTokenProgram2022` | Token-2022 program is required but not provided | 위와 동일하지만 SPL-Token-2022 프로그램 계정의 경우. | "내부: 누락된 Token-2022 프로그램 — 새로고침 후 다시 시도하세요." |

> **재번호 매기기에 대한 참고.** CLMM `ErrorCode` 열거형이 이 릴리스에서 재번호 매겨졌습니다: 5개의 레거시 변형(`LOK`, `ZeroMintAmount`, `InvalidLiquidity`, `TransactionTooOld`, `InvalidRewardDesiredAmount`)과 여러 오타(`Liquitity`, `enought`, `emissiones`)가 제거/수정되었고, 11개의 새로운 변형이 추가되었습니다. Anchor가 소스 순서로 에러를 번호 매기므로, `6000` 이상의 모든 코드는 사전 릴리스 빌드에 상대적으로 이동했습니다. 이전 버전에 대해 숫자 코드를 하드코딩한 클라이언트는 재매핑해야 합니다.

재생성 소스: [github.com/raydium-io/raydium-clmm — error.rs](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/error.rs).

## SDK 에러를 프로그램 에러로 매핑

공식 TypeScript SDK는 온체인 에러를 `SendTransactionError`로 래핑하고, Anchor 프로그램의 경우 `AnchorError`로 래핑합니다:

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

클라이언트 측에서 Anchor를 사용하지 않는 경우 트랜잭션 로그를 파싱하세요:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

패턴 `Error Number: (\d+)`은 Anchor 버전 전체에서 안정적이며 매칭하기에 안전합니다.

## 이 표 재생성

프로그램이 업그레이드되고 새로운 에러가 추가되면 소스에서 다시 추출하세요:

```bash
# 저장소를 복제하고 에러 열거형을 순서대로 grep합니다.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# 6000+++을 단조 증가하는 6000,6001,...로 바꿉니다. 위 표에 새 행을 추가합니다.
```

새로운 변형이 추가될 때마다 [`reference/changelog`](/ko/reference/changelog)를 업데이트하여 SDK를 업그레이드하는 통합자가 에러 핸들러를 새로고침해야 함을 알 수 있도록 하세요.
