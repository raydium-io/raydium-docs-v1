## 사전 요구사항

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

이 페이지의 모든 데모는 [`raydium-sdk-V2-demo/src/cpmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/cpmm)의 파일을 반영합니다. 각 섹션 옆에 GitHub 링크가 있습니다. 부트스트랩은 데모 저장소의 `config.ts.template` ([소스](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template))을 따릅니다:

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

`Raydium` 인스턴스는 SDK의 파사드입니다 — 아래의 모든 데모가 이를 사용합니다. `Raydium.load`는 기본적으로 토큰 목록을 로드하기 때문에 비동기입니다. 해당 페치를 건너뛰려면 `disableLoadToken: true`를 전달하세요. 가용성 기능 확인은 `disableFeatureCheck: false`를 전달하지 않는 한 이미 건너뜁니다. 수수료 구성은 `raydium.api.getCpmmConfigs()`를 통해 첫 사용 시 지연 로드됩니다.

## CPMM 풀 생성

소스: [`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (모든 풀 PDA를 한 번에 필요로 하면 내보낸 헬퍼는 `getCreatePoolKeys`입니다.
//  `getCpmmPdas`는 없습니다.)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. 수수료 구성을 선택합니다. index=0은 0.25% 계층입니다.
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. SDK가 Token-2022 확장을 처리할 수 있도록 민트 메타데이터를 가져옵니다.
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. 트랜잭션을 구성합니다.
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL (9자리 가정)
  mintBAmount:     new BN(   160_000_000),  // 160 USDC (SOL당 160)
  startTime:       new BN(0),               // 즉시 개시
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool created at", extInfo.address.poolId.toBase58());
console.log("Tx:", txId);
```

SDK가 조용히 처리하는 몇 가지 사항:

- PDA를 도출하기 전에 민트를 token0/token1 순서로 정렬합니다.
- 일회성 `create_pool_fee`를 `poolFeeAccount`에 지불합니다.
- 필요한 경우 호출자의 관련 토큰 계정을 생성합니다.
- 각 측면에 대해 올바른 토큰 프로그램 (SPL Token vs Token-2022)을 선택합니다.

확인 후 다음을 사용하여 라이브 풀 상태를 가져올 수 있습니다:

```ts
// getPoolInfoFromRpc는 위치 base58 문자열을 사용하며, PublicKey나 객체가 아닙니다.
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## 스왑 (기본 입력)

소스: [`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // base58 문자열

// 1. RPC에서 직접 현재 풀 상태를 로드합니다 (API에서 아님).
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // A → B 스왑
const amountIn   = new BN(100_000_000);                   // 0.1 SOL
const slippage   = 0.005;                                 // 0.5%

// 2. 로컬에서 견적을 받습니다. CurveCalculator는 온체인 수학을 반영하며,
//    양쪽의 Token-2022 전송 수수료를 포함합니다. 8개 인수 모두 필수입니다.
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult 필드는 inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount입니다.
// destinationAmountSwapped나 sourceAmountSwapped는 없습니다.

// 3. 구성 및 전송합니다. 여기서 `slippage`를 전달하는 것이 바운드를 적용합니다 —
//    수동 최소 출력 산술이 필요하지 않습니다.
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Swap tx:", txId);
```

참고: SDK는 **항상** `getPoolInfoFromRpc` 내에서 RPC에서 풀 상태를 다시 가져옵니다. 서명하려는 트랜잭션에 대해 `api-v3.raydium.io`에서 견적을 받지 마세요 — 한 블록 오래된 견적은 랜드 시간에 `ExceededSlippage`로 미끄러질 수 있습니다.

## 스왑 (기본 출력)

```ts
const amountOutWanted = new BN(15_000_000);        // 15 USDC
const slippage        = 0.005;

const baseIn = false; // false → mintB는 입력 측입니다
const swapResult = CurveCalculator.swapBaseOutput(
  amountOutWanted,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,

// swapResult.inputAmount는 필요한 입력입니다. sourceAmountSwapped는 없습니다.

const { execute } = await raydium.cpmm.swap({
  poolInfo,

  inputAmount: new BN(0),   // fixedOut일 때 미사용 — 금액은 swapResult에서 옵니다
  fixedOut:    true,
  swapResult,               // 필수이며, 목표 출력 금액을 전달합니다
  baseIn,
  slippage,
  txVersion:   TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

## 유동성 입금

소스: [`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity는 LP 금액이 아닌 INPUT 금액으로 구동됩니다.
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // 숫자가 아닌 Percent

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount는 mintA로 표시됩니다
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

SDK는 풀의 현재 준비금에서 쌍을 이루는 금액을 도출하고, 명령어의 `maximum_*` 인수에 대해 각 측을 슬리피지로 부풀리며, 필요한 경우 ATA 생성을 구성합니다. `raydium.cpmm.computePairAmount({ ... })`는 UI 미리보기를 원할 경우 동일한 숫자를 반환합니다.

## 프로토콜/펀드/크리에이터 수수료 수집

소스: [`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts), [`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

프로토콜 및 펀드 수집은 권한 게이트 상태로 유지됩니다. 크리에이터 수수료에는 두 가지 경로가 있습니다: 크리에이터 서명 `CollectCreatorFee`와 추가 `CollectCreatorFeePermissionless`로, 모든 지불자가 호출할 수 있지만 크리에이터의 정규 ATA로만 전송할 수 있습니다. `0.2.64-alpha`는 두 크리에이터 경로에 대한 모듈 수준 빌더를 제공합니다:

```ts
// 크리에이터 서명
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 권한 없음 — 모든 지불자; 수익은 크리에이터의 정규 ATA로 이동합니다
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 한 번에 여러 풀, 크리에이터 서명
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Warning>
  **두 크리에이터 명령어 모두 2026-09-13 프로그램 업그레이드에서 계정 목록을 변경했습니다.** 각각은 이제 `["creator_fee_share", creator, ammConfig]`에서 `creator_fee_share` PDA를 사용하며, 권한 없는 명령어는 `amm_config`도 사용합니다 — 둘 다 금고 전에 삽입됩니다. 업그레이드 이전 SDK 릴리스에 고정된 빌더는 이전 레이아웃을 내보내고 트랜잭션이 역직렬화에 실패합니다. 업그레이드된 프로그램에 대해 이러한 헬퍼를 사용하기 전에 설치한 버전이 새 계정을 전달하는지 확인하고, 이를 생성하는 경우 IDL을 새로 고칩니다.

  PDA를 전달하는 것은 생성된 적이 없는 경우에도 필수입니다 — 이를 도출하고 전달합니다. 프로그램은 계정이 비어 있을 때 `AmmConfig.creator_fee_share_rate`로 폴백합니다.
</Warning>

<Note>
  두 크리에이터 명령어는 **다른 판별자 및 계정 레이아웃을 가집니다** — 권한 없는 명령어는 크리에이터 서명자를 별도의 `payer`와 서명하지 않는 `creator`로 바꿉니다. 다른 명령어의 계정을 손으로 교환하는 대신 일치하는 빌더를 사용하세요.

  SDK에는 프로토콜 또는 펀드 수수료 빌더가 없습니다 (`makeCollectProtocolFeeInstruction`과 `makeCollectFundFeeInstruction`은 어떤 이름으로도 존재하지 않습니다) — 이들은 관리자 경로이며, `CreateCreatorFeeShare` / `CloseCreatorFeeShare`도 마찬가지로 빌더가 없습니다. 존재하는 낮은 수준의 명령어 빌더는 `collectCpFeeInstruction`, `makeCollectCreatorFeeInstruction` 및 `collectCreatorFeePermissionlessInInstruction`입니다.
</Note>

오프체인에서 `PoolState`에서 직접 발생한 수수료를 읽을 수 있습니다:

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // base58 문자열
console.log("Accrued protocol fee mintA:", pool.protocolFeesMintA.toString());
console.log("Accrued protocol fee mintB:", pool.protocolFeesMintB.toString());
// CpmmPoolInfoLayout 필드는 protocolFeesMintA/B, fundFeesMintA/B 및
// creatorFeesMintA/B입니다 — ...Token0/...Token1 필드는 없습니다.
//
// creatorFeesMintA/B는 *총* 발생입니다. 크리에이터는 수집 시간에 해결된
// 프로토콜 공유를 뺀 것을 받습니다. protocolFeesMintA/B는 해당 공유를 받으므로
// 스왑뿐만 아니라 크리에이터 수수료 수집에서도 증가합니다.
// products/cpmm/fees#protocol-share-of-the-creator-fee를 참조하세요.
```

## Rust CPI 스켈레톤

자신의 Anchor 프로그램에서 CPMM을 호출하려면 — 예를 들어, 예금자를 대신하여 스왑하는 금고 — CPI 컨텍스트는 다음과 같습니다. 계정 순서는 [`products/cpmm/instructions`](/ko/products/cpmm/instructions)를 따릅니다.

```rust
// Cargo.toml — 브랜치가 중요합니다: `master`는 여전히 anchor-lang 0.32.1을 고정합니다.
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "chore/upgrade-anchor", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // raydium-cp-swap이 고정하는 것과 일치해야 합니다
// anchor-spl       = "=1.0.2"
//
// `cpi` 기능이 필수입니다 — `raydium_cp_swap::cpi` 모듈은
// 이 기능 아래에서만 존재합니다. 이 크레이트는 products/clmm/code-demos의
// CLMM 샘플과 프로그램을 공유할 수 없으며, 이는 anchor-lang =0.32.1을 고정합니다.

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: CPMM 프로그램에서 검증됨
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: 링 버퍼
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0은 여기서 프로그램의 Pubkey를 사용하며, AccountInfo가 아닙니다.
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

CPI가 PDA로 서명하는 경우 (예: 예금자를 대신하여 금고를 관리), `CpiContext::new`를 `CpiContext::new_with_signer`로 교환하고 시드를 전달합니다.

## 일반적인 함정

지원 티켓을 열기 전의 짧은 체크리스트:

- **정렬된 민트.** 도출한 `poolState` PDA가 온체인 풀과 일치하지 않으면 민트 정렬을 잊었을 가능성이 높습니다.
- **오래된 API 견적.** `api-v3.raydium.io`의 준비금 값을 `CurveCalculator.swap`에 전달하지 마세요. RPC에서 가져옵니다.
- **잘못된 토큰 프로그램.** Token-2022 민트의 금고는 SPL Token이 아닌 Token-2022 프로그램이 소유합니다. 항상 풀의 `token_0_program` / `token_1_program` 필드를 사용하세요.
- **전송 수수료 민트에 대해 과소 표시된 슬리피지.** 풀의 어느 쪽이든 Token-2022 전송 수수료 민트인 경우, `minimum_amount_out`은 금고가 보내는 것이 아닌 사용자가 실제로 받는 것으로 표시되어야 합니다.
- **스왑에서 `NotApproved`.** `PoolState.status`를 확인하세요 — 관리자가 해당 풀에서 스왑을 일시 중지했을 수 있습니다. 상태 비트마스크는 [`products/cpmm/instructions`](/ko/products/cpmm/instructions)를 참조하세요.
