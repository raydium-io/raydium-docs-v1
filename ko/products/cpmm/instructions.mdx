## 명령어 요약

| 판별자 이름 | 서명자 | 수행 작업 |
|-------|-----------|--------------|
| `Initialize` | 풀 생성자 | 두 개의 민트와 `AmmConfig`에서 새로운 CPMM 풀을 생성합니다. 권한 없음; 누구나 호출할 수 있습니다. 새 풀에서 `enable_creator_fee = false`를 하드코딩합니다. `pool_state` 계정은 정규 PDA 또는 새로운 임의 키페어일 수 있습니다 (Initialize 계정 참고). |
| `InitializeWithPermission` | 지불자 + `Permission` PDA 보유자 | `Initialize`의 권한 있는 변형입니다. 호출자(`지불자`)는 자신의 공개키에서 파생된 `Permission` PDA를 소유해야 합니다. 풀 생성이 제한된 플랫폼에서 사용됩니다 (예: LaunchLab 졸업). 호출자가 `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`)을 고정할 수 있으며 새 풀에서 `enable_creator_fee = true`를 강제합니다. `pool_state`의 `creator` 필드는 지불자가 아닌 별도로 전달된 `creator` 계정으로 설정됩니다. `pool_state`에 대해 `Initialize`와 동일한 정규-PDA-또는-임의-키페어 유연성이 있습니다. |
| `Deposit` | LP | 두 토큰 모두에 유동성을 추가하고 LP 토큰을 받습니다. |
| `Withdraw` | LP | LP 토큰을 소각하고 기초 토큰을 비례적으로 받습니다. |
| `SwapBaseInput` | 스왑 실행자 | 정확한 입력 스왑 (`amount_in` 입력, ≥ `minimum_amount_out` 출력). |
| `SwapBaseOutput` | 스왑 실행자 | 정확한 출력 스왑 (≤ `maximum_amount_in` 입력, `amount_out` 출력). |
| `CollectProtocolFee` | `protocol_owner` (`AmmConfig`에서) | 볼트에서 누적된 프로토콜 수수료를 수집합니다. |
| `CollectFundFee` | `fund_owner` (`AmmConfig`에서) | 볼트에서 누적된 펀드 수수료를 수집합니다. |
| `CollectCreatorFee` | `pool_creator` | 누적된 생성자 수수료를 수집합니다 (생성자 수수료가 활성화된 경우). |
| `CollectCreatorFeePermissionless` | 모든 지불자 | 모든 누적된 생성자 수수료를 `pool_creator`의 정규 토큰 계정으로 수집합니다. 지불자는 누락된 수신자 ATA를 생성할 수 있지만 전송을 리디렉션할 수 없습니다. |
| `UpdatePoolStatus` | `admin` | 비트마스크를 통해 풀의 특정 작업을 일시 중지/재개합니다. |
| `UpdateAmmConfig` | `admin` | `AmmConfig`의 수수료율 또는 프로토콜/펀드 소유자를 변경합니다. |
| `CreateAmmConfig` | `admin` | 새로운 수수료 계층 (새 `AmmConfig` 계정)을 생성합니다. |
| `CreatePermissionPda` | `admin` 또는 위임된 권한-PDA 생성자 | 특정 권한이 `InitializeWithPermission`을 호출할 수 있도록 하는 `Permission` PDA를 발급합니다. |
| `ClosePermissionPda` | `admin` 또는 전담 권한-PDA 생성자 | 이전에 발급된 `Permission` PDA를 취소합니다. 2026-09 업그레이드 이후 전담 생성자 권한도 발급한 권한을 닫을 수 있습니다. 이전에는 관리자 전용이었습니다. |
| `CreateSupportMintAssociated` | `admin` 또는 전담 지원-민트 소유자 | 그렇지 않으면 확장 허용 목록에 실패할 Token-2022 민트를 등록하고 `SupportMintAssociated` PDA를 생성합니다. |
| `CloseSupportMintAssociated` | `admin` 또는 전담 지원-민트 소유자 | 민트의 등록을 제거합니다. |
| `CollectExcessLamports` | `admin` 또는 전담 수집-lamport 지갑 | CPMM 제어 볼트, LP 민트 및 PDA에서 임대 면제 최소값 이상의 lamport를 수집합니다. 2026-09에 추가됨. |

상태 비트마스크: 각 풀의 `status`는 `u8`이며, 비트 0 = 입금 비활성화, 비트 1 = 출금 비활성화, 비트 2 = 스왑 비활성화 (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` 프로그램에서). 명확한 비트는 작업이 허용됨을 의미하고, 설정된 비트는 일시 중지됨을 의미합니다. `UpdatePoolStatus`는 원시 `u8`을 가져와 기존 값을 덮어씁니다.

다음 섹션에서는 각각을 자세히 설명합니다. 계정 순서는 CPMM IDL을 따릅니다. SDK와 `raydium-cp-swap/programs/cp-swap/src/instructions`의 Rust 클라이언트가 이 순서와 일치합니다.

## `Initialize`

새로운 CPMM 풀을 생성합니다.

**인자**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix 타임스탬프; 이 시간 이전의 스왑은 거부됨
```

**계정** (W = 쓰기 가능, S = 서명자)

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 임대료를 지불합니다. `pool_state.pool_creator`로 기록됩니다. |
| 2 | `amm_config` |   |   | 선택된 수수료 계층. |
| 3 | `authority` |   |   | CPMM 글로벌 권한 PDA. |
| 4 | `pool_state` | W | S* | 여기서 `init`됩니다. **정규 PDA** `["pool", amm_config, token_0_mint, token_1_mint]` **또는** 새로운 임의 키페어 — 정규 PDA가 아닐 때, 프로그램은 `pool_state`가 서명하도록 요구합니다 (`require_eq!(pool_account_info.is_signer, true)`). 임의 키페어 경로는 생성자가 정규 PDA에 대한 프론트런 시도를 피할 수 있게 합니다. 다운스트림 PDA (`lp_mint`, `vaults`, `observation_state`)는 어느 쪽이든 `pool_state.key()`에서 파생됩니다. |
| 5 | `token_0_mint` |   |   | 정렬됨: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | 여기서 `init`됩니다. 권한이 `authority`로 설정됩니다. |
| 8 | `creator_token_0` | W |   | `init_amount_0`의 소스 ATA. |
| 9 | `creator_token_1` | W |   | `init_amount_1`의 소스 ATA. |
| 10 | `creator_lp_token` | W |   | LP의 목적지 (누락된 경우 생성됨). |
| 11 | `token_0_vault` | W |   | 여기서 `init`됩니다. `authority`가 소유합니다. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 생성자가 지불한 `create_pool_fee`의 목적지 ATA. |
| 14 | `observation_state` | W |   | 여기서 `init`됩니다. |
| 15 | `token_program` |   |   | SPL Token (LP 민트용). |
| 16 | `token_0_program` |   |   | SPL Token 또는 Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token 또는 Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state`는 임의 키페어 경로에서만 서명합니다. 정규-PDA 경로는 `pool_state` 서명 없이 실행됩니다.

**사전 조건**

- 민트가 정렬됨 (바이트 순서로 `token_0_mint < token_1_mint`).
- 어느 민트도 CPMM 허용 목록 외의 확장을 사용하지 않음 (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — [`products/cpmm/accounts`](/ko/products/cpmm/accounts#vaults-and-token-2022)를 참고하세요. `SupportMintAssociated` PDA (시드 `[b"support_mint", mint]`)가 있는 민트는 검사를 건너뜁니다. 2026-09 업그레이드가 하드코딩된 4개 민트 화이트리스트를 제거한 이후 해당 레지스트리가 유일한 우회입니다.
- `creator`는 각 ATA에서 최소 `init_amount_0`과 `init_amount_1`을 보유합니다.
- `amm_config.disable_create_pool == false`.

**사후 조건**

- `pool_state`는 `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`로 존재합니다.
- `LOCKED_LP` (`100` lamport의 LP 토큰)의 LP 스타터는 풀에 영구적으로 잠깁니다 — `pool_state.lp_supply`는 `liquidity − 100`을 기록하는 동안 `100` LP 단위는 순환 외부에 남아 풀이 완전히 소진되고 0으로 나누어지는 것을 방지합니다.
- `observation_state`가 초기화됩니다. `observation_index = 0`이고 `pool_id = pool_state.key()`.
- `create_pool_fee` lamport는 생성자에서 수신자로 전송되고 네이티브 SOL로 동기화됩니다 (wSOL ATA입니다).
- 풀의 상태 비트마스크는 `0` (입금/출금/스왑 모두 활성화).
- `enable_creator_fee = false`이고 `creator_fee_on = BothToken`. `Initialize`는 생성자 수수료 활성화를 지원하지 않습니다 — 해당 경로는 `InitializeWithPermission`입니다.
- `open_time`은 호출자가 `<= block_timestamp` 값을 전달한 경우 `block_timestamp + 1`로 범프됩니다. 스왑은 `open_time` 이전에 거부됩니다. 입금과 출금은 즉시 작동합니다.

**일반적인 오류** (전체 목록은 [`reference/error-codes`](/ko/reference/error-codes)에서)

- `InvalidInput` — 민트가 정렬되지 않았거나 동일한 민트.
- `NotSupportMint` — 차단된 Token-2022 확장.
- `ExceededSlippage` — 드물게; `init_amount_0/1`이 소수 자릿수 불일치로 인해 0 LP를 초래하는 경우.

## `Deposit`

풀에 비례하여 두 토큰 모두에 유동성을 추가합니다.

**인자**

```
lp_token_amount:   u64   // LP에 민트할 LP 토큰 수
maximum_token_0:   u64
maximum_token_1:   u64
```

**계정**

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**수학**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

`k`의 비례성에 변화 없음 — 볼트와 `lp_supply` 모두 동일한 계수로 확장됩니다.

**사후 조건**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (입력의 Token-2022 전송 수수료 순).
- `vault_1 += needed_token_1` (입력의 Token-2022 전송 수수료 순).

**일반적인 오류** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus` (입금이 일시 중지된 경우).

## `Withdraw`

LP 토큰을 소각하고 기초 토큰을 비례적으로 받습니다.

**인자**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**계정**

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(`Deposit`과 동일합니다. `lp_mint`는 LP 토큰이 소각되기 때문에 쓰기 가능합니다.)

**수학**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**사후 조건**

- `lp_supply -= lp_token_amount`.
- 볼트는 `out_token_0` / `out_token_1`을 전송합니다 (총액; 사용자는 Token-2022 전송 수수료 순을 받습니다).

## `SwapBaseInput`

정확한 입력 스왑.

**인자**

```
amount_in:            u64
minimum_amount_out:   u64
```

**계정**

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

순서는 **입력 → 출력**이며, 풀의 정규 `token_0 / token_1`이 아닌 사용자의 방향입니다. 프로그램은 민트를 일치시켜 어느 볼트가 어느 것인지 파악합니다.

**수학** — [`products/cpmm/math`](/ko/products/cpmm/math)를 참고하세요.

**사전 조건**

- `open_time <= now`.
- `pool_status`가 스왑을 허용합니다.
- 어느 민트도 이 권한에 대해 일시 중지되거나 동결되지 않았습니다.
- `amount_in > 0`.

**일반적인 오류**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — 거래가 0으로 반올림됩니다.
- `NotApproved` — 풀이 `UpdatePoolStatus`를 통해 스왑에 대해 일시 중지됨.
- `InvalidInput` — 민트가 풀의 볼트 민트 중 어느 것과도 일치하지 않습니다.

## `SwapBaseOutput`

정확한 출력 스왑.

**인자**

```
max_amount_in:  u64
amount_out:     u64
```

**계정** — `SwapBaseInput`과 동일합니다.

**수학** — 천장이 있는 역곡선, [`products/cpmm/math`](/ko/products/cpmm/math)를 참고하세요.

**일반적인 오류** — `ExceededSlippage` (`gross_in > max_amount_in`), `ZeroTradingTokens`, `InvalidInput`, `NotApproved`.

## `CollectProtocolFee`

볼트에서 프로토콜 목적지로 누적된 프로토콜 수수료를 수집합니다.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `owner` |   | S | `amm_config.protocol_owner`와 일치해야 합니다. |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**효과**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1
pool_state.protocol_fees_token0 = 0
pool_state.protocol_fees_token1 = 0
```

곡선의 유효 잔액에 변화 없음 (누적된 수수료는 이미 제외됨).

**일반적인 오류** — `NotApproved` (서명자가 `protocol_owner`가 아닌 경우).

## `CollectFundFee`

`CollectProtocolFee`와 동일한 형태이지만 `fund_owner`가 서명하고 `fund_fees_*` 카운터를 0으로 설정합니다.

## `CollectCreatorFee`

`pool_state.pool_creator`가 서명합니다. 전체 `creator_fees_token_0` 및 `creator_fees_token_1` 잔액을 생성자의 토큰 계정으로 전송한 다음 두 카운터를 0으로 설정합니다. 두 카운터가 모두 0일 때 `NoFeeCollect`를 반환합니다.

## `CollectCreatorFeePermissionless`

누구나 생성자 수수료 수집을 트리거할 수 있습니다. 명령어는 항상 전체 누적 잔액을 `pool_state.pool_creator`가 소유한 정규 관련 토큰 계정으로 전송합니다. 호출자는 다른 생성자나 목적지를 선택할 수 없습니다. ATA 중 하나가 누락된 경우 지불자가 생성 자금을 조달합니다.

원래 `CollectCreatorFee`는 호출 가능하게 유지되므로 기존 클라이언트는 호환성을 유지합니다.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 모든 서명자; 누락된 생성자 ATA에 자금을 조달합니다. |
| 2 | `creator` |   |   | `pool_state.pool_creator`와 같아야 합니다. 서명하지 않습니다. |
| 3 | `authority` |   |   | CPMM 글로벌 볼트 권한 PDA. |
| 4 | `pool_state` | W |   | 누적된 생성자 수수료 카운터를 보유합니다. |
| 5 | `token_0_vault` | W |   | 풀의 토큰 0 볼트와 일치해야 합니다. |
| 6 | `token_1_vault` | W |   | 풀의 토큰 1 볼트와 일치해야 합니다. |
| 7 | `vault_0_mint` |   |   | `token_0_vault.mint`와 일치해야 합니다. |
| 8 | `vault_1_mint` |   |   | `token_1_vault.mint`와 일치해야 합니다. |
| 9 | `creator_token_0` | W |   | `vault_0_mint`에 대한 생성자의 정규 ATA; 누락된 경우 생성됩니다. |
| 10 | `creator_token_1` | W |   | `vault_1_mint`에 대한 생성자의 정규 ATA; 누락된 경우 생성됩니다. |
| 11 | `token_0_program` |   |   | SPL Token 또는 Token-2022, 토큰 0과 일치. |
| 12 | `token_1_program` |   |   | SPL Token 또는 Token-2022, 토큰 1과 일치. |
| 13 | `associated_token_program` |   |   | 누락된 수신자 ATA를 생성합니다. |
| 14 | `system_program` |   |   | `payer`에서 계정 생성에 자금을 조달합니다. |

**효과**

- 풀 볼트에서 생성자 ATA로 `creator_fees_token_0` 및 `creator_fees_token_1`의 전부를 전송합니다.
- 두 생성자 수수료 카운터를 0으로 설정하고 `pool_state.recent_epoch`를 업데이트합니다.
- 두 카운터가 모두 0일 때 `NoFeeCollect`를 반환합니다.

## `UpdatePoolStatus`

풀의 개별 작업을 일시 중지하거나 재개합니다. `status` 필드는 비트마스크입니다:

| 비트 | 플래그 | 설정 시 효과 |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit`이 `NotApproved`로 거부됩니다. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw`가 거부됩니다. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput`이 거부됩니다. |

**인자**

```
status: u8      // 새로운 비트마스크
```

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `authority` |   | S | CPMM 프로그램의 관리자 키와 일치해야 합니다. |
| 2 | `pool_state` | W |   |

관리자 키는 CPMM 프로그램의 업그레이드 권한입니다 — 실제로는 Raydium 멀티시그입니다. [`security/admin-and-multisig`](/ko/security/admin-and-multisig)를 참고하세요.

## `CreateAmmConfig`

새로운 수수료 계층을 생성합니다.

**인자**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | 관리자. |
| 2 | `amm_config` | W |   | 여기서 `init`됩니다. |
| 3 | `system_program` |   |   |

**사전 조건**

- 동일한 `index`를 가진 기존 `AmmConfig`가 없습니다.
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`.

<Note>
  **2026-09에서 변경됨: 새 구성의 수수료 소유자는 더 이상 서명자에서 오지 않습니다.** `create_amm_config`는 이제 프로그램의 하드코딩된 `protocol_fee_owner::ID`를 `protocol_owner`에 기록하고 `fund_fee_owner::ID`를 `fund_owner`에 기록하며, 관리자 서명자의 키를 둘 다에 복사하는 대신입니다. 주소는 [`reference/program-addresses`](/ko/reference/program-addresses#cpmm-fee-owner-wallets)에 있습니다.

  결과: 새로 생성된 `AmmConfig`는 관리자 키가 아닌 전담 수수료 지갑에 의해 즉시 수집되며, 관리자는 먼저 필드를 회전하지 않고는 방금 생성한 구성에서 수집할 수 없습니다. **기존 `AmmConfig` 계정은 다시 작성되지 않습니다** — 저장된 내용이 여전히 관리하므로 항상 계정에서 `protocol_owner` / `fund_owner`를 읽으십시오. `UpdateAmmConfig` 매개변수 `3`과 `4`는 여전히 회전합니다.
</Note>

## `UpdateAmmConfig`

기존 `AmmConfig`의 수수료율 또는 소유권을 변경합니다. `param: u8` (업데이트할 필드의 판별자)과 `value: u64`를 가집니다. 매개변수당 값 의미론은 소스에 있습니다. 일반적으로:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (재해석으로 `Pubkey` 바이트 전달)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

변경 사항은 관리자가 서명하며 다음 스왑에서 이 `AmmConfig`에 바인딩된 **모든 풀**에 영향을 미칩니다. 마이그레이션 없음; 풀은 단순히 새 값을 읽습니다.

## `CollectExcessLamports`

CPMM이 제어하는 계정에서 임대 면제 최소값 이상의 lamport를 관리자가 수집합니다. 2026-09 업그레이드에서 추가되었으므로 프로토콜은 [SIMD-0437 임대 감소](/ko/solana-fundamentals/rent-and-reclaimable-rent)가 각 단계 이전에 생성된 계정에 남기는 초과 자금을 회수할 수 있습니다.

초과분만 이동합니다. 토큰 잔액, 계정 데이터, 소유자, 풀 상태 및 곡선은 변경되지 않으며, 명령어는 이미 최소값에 있는 계정에 대해 작동하지 않습니다 — 따라서 각 롤아웃 단계 후에 다시 실행하는 것이 안전합니다.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | 모든 수집된 lamport의 목적지. CPMM 프로그램 관리자 또는 전담 수집-lamport 지갑이어야 합니다 — [`reference/program-addresses`](/ko/reference/program-addresses#excess-lamports-collection-wallets)를 참고하세요. 다른 서명자는 `InvalidOwner`로 실패합니다. |
| 2 | `authority` |   |   | 시드 `[b"vault_and_lp_mint_auth_seed"]`의 CPMM 볼트-및-LP-민트 권한 PDA. 토큰 프로그램 CPI에 서명합니다. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. 둘 다 무조건 필요합니다. 프로그램은 소스 계정당 선택합니다. |
| 5.. | `remaining_accounts` | W |   | 수집할 `M` 소스 계정, 임의 개수, 임의 순서. |

**각 소스 계정이 처리되는 방식**

프로그램은 소스 계정의 `owner`에 따라 디스패치합니다:

| 소스 계정 소유자 | 처리 |
|---|---|
| SPL Token 또는 Token-2022, 비네이티브 토큰 계정 또는 민트 — 풀 볼트 및 LP 민트 | CPI `WithdrawExcessLamports` (토큰 프로그램 판별자 `38`), `authority`가 서명. |
| SPL Token 또는 Token-2022, **네이티브** (wSOL) 토큰 계정 | `WithdrawExcessLamports`는 네이티브 계정을 거부합니다. 프로그램은 `SyncNative`를 CPI하고, 래핑된 `amount`가 얼마나 증가했는지 측정하고, 정확히 그 델타에 대해 `UnwrapLamports` (판별자 `45`)를 수행한 다음, 래핑된 잔액이 사전 동기화 값과 같아야 합니다 — 그렇지 않으면 `LamportsCalculateError` (`6015`). SOL 측 풀 볼트는 따라서 전체 유동성을 유지합니다. |
| CPMM 프로그램 자체 — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | 프로그램은 계정을 `rent.minimum_balance(data_len)`까지 직접 차감합니다. |
| 다른 것 | **조용히 건너뜁니다.** 오류 없음, lamport 이동 없음. |

무제한 `remaining_accounts` 목록을 가지므로 트랜잭션 크기가 실제 제한입니다 — [`solana-fundamentals/rent-and-reclaimable-rent`](/ko/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction)에서 설명한 지갑 측 수집과 동일한 제약입니다.

**일반적인 오류** — `InvalidOwner` (`6001`, 잘못된 서명자), `LamportsCalculateError` (`6015`, wSOL 왕복이 0으로 순 정산되지 않음), 계정이 자신의 임대 최소값보다 적게 보유할 때 프로그램 소유 경로의 `InsufficientFunds`.

**SDK 빌더 없음.** `@raydium-io/raydium-sdk-v2`는 이 명령어에 대한 빌더를 제공하지 않으며, `raydium-sdk-V2-demo` 저장소도 제공하지 않습니다 — 관리자 경로입니다. [`solana-fundamentals/rent-and-reclaimable-rent`](/ko/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction)에서 지갑 측 수집이 토큰 프로그램 명령어에 대해 수행하는 방식처럼 수동으로 인코딩하세요.
