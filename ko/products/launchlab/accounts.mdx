## `PoolState`

런칭별 루트 상태. 아래 필드 이름은 온체인 Rust 구조체(`states/pool.rs`)와 일치합니다. 일부 값은 가독성을 위해 단순화되었으므로 정확한 메모리 레이아웃은 소스를 참조하세요.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus` 값 (Anchor IDL에서):

```
0 = Funding         — 매수/매도 수락; quote_reserve_target 이하
1 = Migrate         — quote_reserve_target 도달; MigrateTo* 대기 중
2 = Migrated        — MigrateTo* 이미 실행됨; 베스팅 시계 실행 중
```

통합자 대면 필드:

- **`status`** — 세 가지 값, 단조 (Funding → Migrate → Migrated). 읽기는 항상 안전하고 쓰기는 제한됩니다.
- **`real_base`**, **`real_quote`** — 현재 곡선 상태. `virtual_base` / `virtual_quote`와 함께 볼트에 접근하지 않고도 현물 가격을 계산하기에 충분합니다. [`bonding-curve`](/ko/products/launchlab/bonding-curve)를 참조하세요.
- **`total_base_sell`** vs `real_base` — UI를 위한 "졸업까지의 진행률" 비율.
- **`migrate_type`** — 새 초기화에는 `1` (`CPSWAP`)이 필요합니다. 저장된 `0`은 CPMM 전용 적용 이전에 생성된 기존 런칭에만 의미가 있습니다.
- **`amm_creator_fee_on`** — 졸업 후 CPMM 풀에서 `creator_fee_on = OnlyQuoteToken` (`0`) 또는 `BothToken` (`1`)을 선택합니다. 마이그레이션 대상을 선택하지 않습니다. [`creator-fees`](/ko/products/launchlab/creator-fees)를 참조하세요.
- **`token_program_flag`** — 부울이 아닌 비트필드입니다. Bit0은 기본 민트이고 bit1은 인용 민트이며, 각각 SPL Token의 경우 `0`, Token-2022의 경우 `1`이므로 바이트는 네 가지 값을 취합니다: `0` (둘 다 레거시), `1` (Token-2022 기본), `2` (Token-2022 인용), `3` (둘 다 Token-2022). `(token_program_flag >> bit) & 1`로 하나의 민트를 읽습니다. 전체 바이트를 `0`과 비교하여 기본 민트를 분류하면 `2`가 잘못된 프로그램으로 해석됩니다. Bit1은 Token-2022 인용 민트가 지원될 때까지 상수 `0`이었습니다.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — 세 개의 독립적인 수수료 카운터. 각각 자체 청구 명령이 있습니다. [`instructions`](/ko/products/launchlab/instructions)를 참조하세요.
- **`vesting_schedule`** — 모든 `PoolState`에 존재하지만 `total_locked_amount == 0`일 때 비활성화됩니다. 전체 수명 주기는 [`vesting`](/ko/products/launchlab/vesting)을 참조하세요.

## 권한 PDA

LaunchLab은 런칭별 시드 없이 모든 런칭에서 **단일** 권한 PDA를 사용합니다:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

그 단일 PDA는:

- 모든 런칭의 `base_vault` 및 `quote_vault`에 대한 권한입니다.
- 각 런칭의 `base_mint`에 대한 `mint_authority` (졸업 전).
- CPMM 졸업 CPI 및 기존 상태에 대한 레거시 AMM v4 졸업에 서명합니다.
- `ClaimVestedToken` 기본 볼트 이체에 서명합니다.
- Token-2022 기본 민트의 `TransferFeeConfig`에 대한 `transfer_fee_config_authority` (전체 졸업 전 단계) — 그리고 플랫폼이 `PlatformConfig.transfer_fee_extension_auth`를 설정하지 않은 경우에만 `withdraw_withheld_authority`도 포함됩니다.

`mint_authority`는 `MigrateToCpswap` 또는 레거시 `MigrateToAmm` 호출 직후 취소되므로 공급은 영구적으로 고정됩니다.

두 개의 추가 PDA가 수수료 볼트를 제어합니다:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

이들은 `ClaimCreatorFee` 및 `ClaimPlatformFeeFromVault` 중에 해당 수수료 볼트에서 이체할 때 서명합니다.

## 기본 민트

`Initialize`로 인라인으로 생성되며:

- `mint_authority = authority` (졸업 시 취소).
- `freeze_authority = None`.
- `supply = supply`, 전체가 `base_vault`로 민팅됨.
- `decimals`는 `Initialize`에서 크리에이터가 선택 (일반적으로 6).

전체 공급이 사전 민팅되므로 `base_mint.supply`는 런칭 기간 동안 상수입니다. 곡선 매수는 토큰을 `base_vault`에서 구매자로 이동하지만 `mint_to`를 호출하지 않습니다.

`Initialize` / `InitializeV2`는 SPL Token 기본 민트를 생성합니다. 전용 `InitializeWithToken2022` 명령어는 기본 민트가 Token-2022 민트(선택적 `TransferFeeConfig` 포함)가 되도록 합니다. 세 가지 초기화 경로 모두 CPMM 졸업이 필요합니다.

`InitializeWithToken2022`가 `TransferFeeConfig`를 첨부할 때, 민트는 `transfer_fee_config_authority = authority` 및 `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`로 생성되며, 플랫폼이 해당 필드를 설정하지 않은 경우 `authority`로 폴백됩니다. 두 권한 모두 졸업 시 플랫폼 키로 재할당되며, 철회 측은 PDA가 여전히 보유하고 있는 경우에만 재할당됩니다. [`platform-config`](/ko/products/launchlab/platform-config#token-2022-transfer-fee-authorities)를 참조하세요.

인용 민트는 기본 민트와 독립적이며 자체적으로 Token-2022 민트일 수 있습니다 — `InitializeV2` 및 `InitializeWithToken2022`는 인용 프로그램 슬롯에서 두 프로그램을 모두 수락합니다. 더 이상 사용되지 않는 `Initialize`는 그렇지 않습니다. 인용 프로그램 계정은 여전히 SPL Token으로 입력되므로 인용 민트가 Token-2022인 설정은 다른 두 가지를 통해서만 시작할 수 있습니다. 인용 민트는 LaunchLab에서 생성되지 않습니다. `GlobalConfig.quote_mint`가 지정하는 것입니다. [`global-config`](/ko/products/launchlab/global-config#token-2022-quote-mints) 및 [`reference/token-2022-support`](/ko/reference/token-2022-support#launchlab-quote-mints)를 참조하세요.

## 볼트

`base_vault` 및 `quote_vault` 모두 LaunchLab `authority` PDA가 소유한 토큰 계정이며, 각각 자신의 민트를 소유한 프로그램에서 생성됩니다 — 따라서 런칭은 레거시 기본 볼트와 Token-2022 인용 볼트를 가질 수 있거나 다른 조합을 가질 수 있습니다. `token_program_flag`는 어느 것이 어느 것인지 기록합니다. 주소는 `PoolState`에 저장되며 다음과 같이 파생될 수도 있습니다:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(프로덕션에서 파생에 의존하기 전에 소스의 `Initialize` 계정 구조에서 정확한 시드 접두사를 확인하세요.)

## 수수료 볼트

두 개의 PDA가 런칭 전체에서 수수료를 집계합니다:

- **크리에이터 수수료 볼트** — 시드 `[creator, quote_mint]`의 PDA. 동일한 인용 민트에서 동일한 크리에이터 수수료를 얻는 모든 런칭은 동일한 볼트로 흘러갑니다. 크리에이터는 `ClaimCreatorFee`를 통해 정산합니다.
- **플랫폼 수수료 볼트** — 시드 `[platform_config, quote_mint]`의 PDA. 동일한 플랫폼을 통해 라우팅되고 동일한 인용 민트를 사용하는 모든 런칭은 동일한 볼트로 흘러갑니다. 플랫폼의 `platform_fee_wallet`은 `ClaimPlatformFeeFromVault`를 통해 정산합니다. 또한 런칭별 정산 변형(`ClaimPlatformFee`)도 있으며, 이는 집계된 볼트를 거치지 않고 런칭의 `quote_vault`에서 직접 끌어옵니다.

둘 다 수수료를 누적하는 첫 번째 스왑에서 인용 민트를 소유한 프로그램에서 지연 생성됩니다. 레거시 및 Token-2022 인용 민트 모두에 대해 런칭을 실행하는 크리에이터 또는 플랫폼은 두 개의 서로 다른 레거시 민트에 대해 이미 했던 것처럼 민트당 하나의 볼트를 끝냅니다.

집계된 볼트 패턴은 높은 거래량의 크리에이터 또는 플랫폼이 많은 런칭에 걸쳐 수수료 누적의 임차료 비용을 분산할 수 있게 합니다.

## 인용 볼트 ↔ `real_quote`

`quote_vault.balance` 및 `PoolState.real_quote`는 동기화 상태를 유지해야 합니다. 세 개의 보류 중인 수수료 카운터(`quote_protocol_fee`, `platform_fee`, `migrate_fee`)의 합계만큼 드리프트할 수 있으며, 이들은 볼트에 있지만 수수료 카운터에 속하고 곡선 준비금에는 속하지 않습니다. 곡선 수학은 항상 `real_quote`를 사용하며 원시 볼트 잔액은 사용하지 않습니다.

졸업 전 불변식:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## 수명 주기 계정 전환

| 이벤트 | 상태 | `real_base` | `real_quote` | 졸업 후 풀 |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (또는 레거시 `MigrateToAmm`) | Funding → Migrate → Migrated | (고정) | (고정) | 생성됨; CPMM LP는 플랫폼 소유 잠금 LP 및 소각된 LP로 분할됨 |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | 모두 | — | — | 수수료 볼트 드레인 |
| `CreateVestingAccount` | Funding | — | — | `vesting_schedule.allocated_share_amount` 범프 |
| `ClaimVestedToken` | Migrated만 | — | — | `base_vault` 드레인 |
