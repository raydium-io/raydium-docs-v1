## 명령어 목록

| 런칭 생명주기 | `Initialize` / `InitializeV2` | 누구나 (생성자) — SPL Token 기본 민트; V2는 향후 CPMM 졸업을 위해 `amm_creator_fee_on` 기록. Token-2022 견적 민트만 V2에서 허용. |
| 런칭 생명주기 | `InitializeWithToken2022` | 누구나 (생성자) — Token-2022 기본 민트, 선택적 `TransferFeeConfig`; 어느 견적 토큰 프로그램이든 허용 |
| 거래 | `BuyExactIn` / `BuyExactOut` | 누구나 — 본딩 곡선에서 정확한 입력/출력 매수 |

| 졸업 | `MigrateToAmm` | 마이그레이션 지갑 — CPMM 전용 생성이 강제되기 전에 초기화된 풀을 위한 레거시 AMM v4 졸업. |
| 졸업 | `MigrateToCpswap` | 마이그레이션 지갑 — CPMM으로 졸업. 새로 초기화된 모든 런칭이 이 경로 사용. CPMM의 `InitializeWithPermission` 래핑. |
| 수수료 | `CollectFee` | 관리자 — 런칭에서 프로토콜 수수료 수거 |

| 수수료 | `ClaimCreatorFee` | 생성자 — 곡선 단계 중 누적된 생성자 수수료 청구 |
| 베스팅 | `CreateVestingAccount` | 생성자 — 수혜자에게 잠긴 토큰 할당, 졸업 후 해제 |
| 베스팅 | `CreatePlatformVestingAccount` | 플랫폼 관리자 — 플랫폼 측 수혜자에게 잠긴 토큰 할당 |
| 베스팅 | `ClaimVestedToken` | 수혜자 — 절벽 이후 해제된 토큰 청구 |
| 플랫폼 설정 | `CreatePlatformConfig` / `UpdatePlatformConfig` | 플랫폼 관리자 |
| 플랫폼 설정 | `CreatePlatformCurveRule` / `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` / `ClosePlatformCurveRule` | `PlatformConfig.curve_rule_manager` 또는 플랫폼 관리자 — 하나의 `GlobalConfig`에 대한 런칭 매개변수 규칙 관리 |
| 플랫폼 수수료 | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | 플랫폼 관리자 |
| 플랫폼 접근 | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 플랫폼 관리자 — 플랫폼이 제한을 활성화할 때 사용되는 `GlobalConfig` 허용 목록 유지 |

"ExactIn/ExactOut" 분할은 CPMM의 `SwapBaseInput` / `SwapBaseOutput`을 반영합니다 — 온체인에서는 약간 다른 반올림을 가진 별도의 명령어 판별자입니다.

**졸업 경로 선택.** 모든 새로운 `Initialize`, `InitializeV2`, `InitializeWithToken2022` 호출은 `migrate_type = 1` (`CPSWAP`)을 설정해야 합니다. 새로운 AMM v4 바운드 풀을 초기화하려는 시도는 `MigrateTypeNotMatch`를 반환합니다. `amm_creator_fee_on`은 결과 CPMM 생성자 수수료가 견적 토큰에 적용되는지 또는 두 토큰 모두에 적용되는지만 선택합니다; 대상 프로그램을 선택하지 않습니다.

`MigrateToAmm`은 이 제한 전에 `migrate_type = 0`으로 초기화된 기존 `PoolState`에 대해 호출 가능하게 유지됩니다. 이 릴리스는 기존 풀 상태를 다시 쓰거나 레거시 명령어를 제거하지 않습니다.

**견적 측 토큰 프로그램.** 견적 민트는 SPL Token 프로그램 또는 Token-2022 중 하나가 소유할 수 있습니다. 이를 건드리는 모든 명령어 — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, 4개의 거래 명령어, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee`, `ClaimPlatformFeeFromVault` — 견적 프로그램 계정 슬롯에서 소유 프로그램을 가져갑니다. 계정 위치는 변경되지 않았습니다; 허용되는 값만 변경되었습니다. 실제로 `GlobalConfig.quote_mint`를 소유하는 프로그램을 전달하세요. 기존 런칭의 경우 `PoolState.token_program_flag` bit1에서 읽을 수 있습니다 ([`accounts`](/ko/products/launchlab/accounts#poolstate) 참조) 또는 민트 계정의 소유자에서 읽을 수 있습니다.

더 이상 사용되지 않는 `Initialize`는 예외입니다: 견적 프로그램 계정은 여전히 SPL Token으로 입력되므로, 견적 민트가 Token-2022인 설정은 `InitializeV2` 또는 `InitializeWithToken2022`를 통해 시작해야 합니다.

`MigrateToCpswap`은 반대 방향의 다른 예외입니다 — 민트당 하나가 아니라 두 프로그램을 무조건 가져갑니다. 아래의 [마이그레이션 계정](#cpmm-migration-token-programs)을 참조하세요.

## `Initialize`

새로운 런칭을 생성합니다.

**인자**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // 또는 curve_type=1의 initial_virtual_quote_reserve
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // 인라인 name/symbol/uri; 프로그램이 Metaplex로 CPI
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**계정** (축약)

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 렌트 + 기본 민트 생성 비용 지불. |
| 2 | `launch_config` |   |   | 프로토콜 설정 바인딩. |
| 3 | `launch_state` | W |   | 새 계정. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | 신규 Keypair (또는 PDA) — 이 명령어가 초기화. |
| 6 | `base_vault` | W |   | `launch_authority`의 `base_mint`에 대한 ATA. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | `launch_authority`의 `quote_mint`에 대한 ATA. |
| 9 | `metadata` | W |   | Metaplex 메타데이터 PDA. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | 기본 민트용 SPL Token. `InitializeV2`와 `InitializeWithToken2022`는 어느 프로그램이든 될 수 있는 별도의 견적 프로그램 계정을 가져갑니다. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**사전 조건**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- 수수료 매개변수가 `launch_config.max_*_fee_rate` 검사를 통과합니다.
- `open_time ≥ now − slop` (SDK는 `≥ now` 강제; 프로그램은 약간의 역날짜 허용).
- `curve_type`이 인식됩니다.

**사후 조건**

- `base_mint`는 `supply = base_supply_max`, 모두 `base_vault`에 있습니다.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState`는 `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`으로 초기화됩니다.
- `quote_reserve_target`은 곡선 매개변수 + `base_supply_graduation` + `buy_numerator`에서 계산됩니다 (대략).
- `InitializeWithToken2022`의 경우 `TransferFeeConfig` 첨부: `transfer_fee_config_authority = launch_authority`, `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` (해당 필드가 설정된 경우), 그렇지 않으면 `launch_authority`. 인출 측은 플랫폼이 졸업 전에 보류된 수수료를 수거할 수 있도록 민트 생성 시 정확히 작성됩니다. [`platform-config`](/ko/products/launchlab/platform-config#token-2022-transfer-fee-authorities)를 참조하세요.

**일반적인 오류** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (정규 변형: `BuyExactIn`)

사용자가 고정 `quote_in`을 제공합니다; 곡선이 `base_out`을 계산합니다.

**인자**

```
quote_in:          u64
minimum_base_out:  u64
```

**계정**

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**사전 조건**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**효과**

1. `quote_in`을 `quote_in_after_fee`와 수수료 부분으로 분할합니다.
2. 사후 수수료 견적이 주어진 곡선에 대해 Newton 풀이로 `base_out`을 계산합니다.
3. `require(base_out ≥ minimum_base_out)` 그렇지 않으면 `ExceededSlippage` 되돌립니다.
4. `quote_in` 사용자 → 금고로 이동. `base_out` 금고 → 사용자로 이동.
5. `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)` 업데이트합니다.
6. 수수료 카운터 (`protocol_fees_quote`, `creator_fees_quote`) 업데이트합니다.
7. `state_data.num_buys += 1`.
8. 업데이트 후 `quote_reserve_real ≥ quote_reserve_target`이면, SDK는 일반적으로 같은 트랜잭션에서 `Graduate` ix를 연결합니다. 프로그램은 `Buy` 내에서 자동 졸업하지 않습니다 — 후속 `Graduate`가 필요합니다.

## `BuyExactOut`

사용자가 정확한 `base_out`을 지정합니다; 프로그램이 `quote_in`을 계산합니다.

**인자**

```
base_out:      u64
maximum_quote_in: u64
```

`BuyExactIn`과 동일한 계정. Newton 반복 대신 폐쇄형 이차 적분 (또는 curve_type 1의 경우 CPMM 역함수)을 사용합니다.

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy`의 미러. 사용자가 `base_in`을 곡선에 반환하고 `quote_out`을 받습니다. 수수료는 `quote_out`에서 공제되므로 사용자는 원본 통합 수익보다 적게 받습니다.

**사전 조건** —

- `user_base_ata.balance ≥ base_in`.
- 매도는 `base_sold`를 0 아래로 밀 수 없습니다 (위의 것과 중복, 회계가 일관성 있음).
- 런칭이 `Active`입니다.

**효과** — `Buy`와 대칭. `base_sold` 감소, `quote_reserve_real` 감소. 수수료는 여전히 누적됩니다.

### 견적 측 이전 수수료

견적 민트가 `TransferFeeConfig`를 가질 때, 금고가 이동하는 금액과 지불자가 청구되거나 신용되는 금액이 다르며, 슬리피지 한계는 지불자 측에 대해 확인됩니다. 확장 없는 견적 민트에서 아래의 모든 경우는 일반 레거시 민트와 동일합니다.

| 명령어 | 인자 | 확인 대상 |
|---|---|---|
| `BuyExactIn` | `amount_in` | 곡선은 `amount_in − transfer_fee(amount_in)`에서 가격 책정됩니다 — 금고에 도달하는 것. 전체 채우기는 정확히 `amount_in`을 청구합니다; 부분 채우기는 소비된 금고 금액과 그 역 수수료를 청구합니다. |
| `BuyExactOut` | `maximum_amount_in` | 금고 금액 **더하기** 역 이전 수수료 — 실제 청구. |
| `SellExactIn` | `minimum_amount_out` | 판매자가 민트가 수수료를 보류한 후 유지하는 것, 금고를 떠나는 총액이 아닙니다. |
| `SellExactOut` | `amount_out` | 정확히 전달됨. 곡선은 `amount_out` 더하기 역 이전 수수료를 목표로 합니다. |

견적에 대한 두 가지 결과:

- 민트가 수수료 없는 것처럼 계산된 한계는 거부됩니다. 수수료 없는 비용을 `maximum_amount_in`으로 또는 수수료 없는 수익을 `minimum_amount_out`으로 전달하면 `ExceededSlippage`로 되돌립니다.
- `real_quote`는 금고에 도달한 것만큼만 진행됩니다. 5% 견적 민트에서 `amount_in`의 `BuyExactIn`은 `real_quote`를 `amount_in × 0.95`로 이동합니다.

100% 수수료 견적 민트 (`10000` 기본 포인트)는 반전될 수 없으며 정확한 출력 경로에서 `CalculateOverflow`로 되돌립니다.

두 거래 측 민트도 일치하는 슬롯에 전달된 프로그램으로 제한되므로, 불일치하는 `base_token_program`은 이제 무시되는 대신 실패합니다. [`algorithms/token-2022-transfer-fees`](/ko/algorithms/token-2022-transfer-fees)에서 기본 수수료 수학을 참조하세요.

## `MigrateToAmm` / `MigrateToCpswap`

곡선이 `total_quote_fund_raising`에 도달하면 런칭을 거래 가능한 풀로 졸업합니다. 새 런칭은 CPMM 전용입니다. `MigrateToAmm`은 저장된 `migrate_type`이 `0`인 기존 풀을 위해 유지됩니다.

**서명자**

- `MigrateToAmm` — 바인딩 `GlobalConfig`에 기록된 `migrate_to_amm_wallet`.
- `MigrateToCpswap` — 바인딩 `GlobalConfig`에 기록된 `migrate_to_cpswap_wallet`.

이 지갑은 일반적으로 Raydium 운영 졸업 크랭크에 의해 보유됩니다; 실제로 졸업은 최종 매수를 트리거한 사람과 관계없이 임계값이 넘은 후 몇 초 내에 발생합니다.

**인자**

`MigrateToAmm`은 3개를 가져갑니다 (주로 프로그램이 AMM v4로 전달하는 OpenBook 시장 매개변수):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap`은 없습니다.

**효과 (둘 다 공통)**

1. `pool_state.status == Migrate` 확인 (즉, `quote_reserve_target`에 도달). 그렇지 않으면 `PoolMigrated` (상태가 이미 `Migrated`) 또는 `PoolFunding` (여전히 자금 조성 중)으로 되돌립니다.
2. `pool_state.migrate_type`이 명령어와 일치하는지 확인 (AMM의 경우 `0`, CPMM의 경우 `1`). 그렇지 않으면 `MigrateTypeNotMatch`로 되돌립니다.
3. 졸업 후 준비금 계산:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. 대상 프로그램 (`AMM v4 Initialize2` 또는 `CPMM InitializeWithPermission`)으로 CPI하여 해당 준비금으로 졸업 후 풀을 생성합니다.
5. 2026-08-17 업그레이드 후 실행된 CPMM 마이그레이션의 경우, `platform_scale + creator_scale`을 하나의 플랫폼 소유 잠긴 LP 공유로 결합하고 최대 하나의 Fee Key NFT를 `platform_nft_wallet`에 민트합니다. `burn_scale` 나머지를 소각합니다. 업그레이드 전에는 `creator_scale`이 별도로 잠겼고 그 Fee Key는 토큰 생성자에게 갔습니다. 완료된 과거 마이그레이션은 수정되지 않습니다. 레거시 AMM v4 졸업의 경우, LP 처분은 해당 명령어의 기존 흐름을 따릅니다.
6. `base_mint.mint_authority` 취소 (None으로 설정).
7. `pool_state.status = Migrated` 뒤집기, `vesting_schedule.start_time = block_time + cliff_period` 설정.

**Token-2022 이전 수수료 권한 이양** — 기본 민트가 `TransferFeeConfig`를 가진 Token-2022 민트 **이고** `PlatformConfig.transfer_fee_extension_auth`가 기본값이 아닐 때, 마이그레이션도 해당 확장의 권한을 플랫폼 키로 재할당합니다:

- `transfer_fee_config_authority`는 항상 재할당됩니다. 런칭 `authority` PDA는 전체 졸업 전 단계 동안 이를 보유하므로 항상 이동할 것이 있습니다.
- `WithheldWithdraw`는 **`authority` PDA가 여전히 이를 보유할 때만** 재할당됩니다. 2026-08-27 이후에 생성된 런칭은 이미 민트 생성 시 해당 권한에 `transfer_fee_extension_auth`를 가지고 있으므로 단계를 건너뜁니다. 가드는 마이그레이션이 해당 민트에서 되돌리는 것을 방지합니다 — PDA는 더 이상 보유하지 않는 권한을 포기할 수 없습니다.

마이그레이션 시 `transfer_fee_extension_auth`가 `Pubkey::default()`이면, 어느 권한도 이동하지 않으며 둘 다 `authority` PDA에 영구적으로 유지됩니다. [`platform-config`](/ko/products/launchlab/platform-config#token-2022-transfer-fee-authorities)를 참조하세요.

**사후 조건** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut`은 이 시점부터 `PoolMigrated`로 거부합니다. 결과 AMM 풀은 정규이며 다른 AMM v4 / CPMM 풀처럼 거래합니다.

**일반적인 오류** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### CPMM 마이그레이션 남은 계정

`MigrateToCpswap`을 구축하는 클라이언트는 이 고정 `remaining_accounts` 인덱스를 사용해야 합니다:

| 인덱스 | 계정 |
|---|---|
| 0–4 | 플랫폼 Fee Key 소유자, 민트, 토큰 계정, 잠긴 유동성 PDA, 메타데이터 계정 |
| 5 | 원본 런칭 생성자; `platform_cp_creator`가 설정되지 않았을 때 사용 |
| 6 | `[b"permission", launch_authority]`에서 파생된 CPMM 권한 PDA |
| 7 | 구성된 `platform_cp_creator`; 필드가 기본값이 아닐 때 사용 |
| 8 | 정렬된 `mint0`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint0]`에서 파생 |
| 9 | 정렬된 `mint1`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint1]`에서 파생 |

명령어는 업그레이드된 경로에서 최소 10개의 남은 계정이 필요합니다. 지원 민트 계정은 읽기 전용 CPI 입력입니다. 민트가 초기화된 지원 기록이 없을 때도 두 주소를 파생합니다. 여전히 생성자 잠금 계정을 추가하거나 인덱스 8–9를 생략하는 이전 빌더는 업데이트해야 합니다.

### CPMM 마이그레이션 토큰 프로그램

`MigrateToCpswap`은 두 토큰 프로그램을 무조건 가져가며 각 민트를 소유하는 프로그램을 자체적으로 파악합니다. 두 토큰 프로그램 계정의 이름이 그에 따라 변경되었습니다:

| 위치 | 계정 | 값 |
|---|---|---|
| 첫 번째 | `token_program` | 항상 레거시 SPL Token 프로그램 |
| 두 번째 | `token_program_2022` | 항상 Token-2022 프로그램 |

이들은 이전의 `base_token_program` (기본 민트를 소유한 프로그램) 및 `quote_token_program` (항상 레거시)을 대체합니다. 위치는 변경되지 않으므로 이는 레이아웃 변경이 아닌 값 변경입니다 — 하지만 두 값은 거의 반전되며, 이전 쌍을 계속 전달하는 빌더는 어느 민트든 Token-2022 민트가 되는 즉시 레거시 프로그램이 필요한 곳에 Token-2022를 공급합니다.

레거시 프로그램은 어느 민트도 사용하지 않을 때도 필요합니다. CPMM LP 민트와 잠긴 유동성 Fee Key NFT는 항상 이 프로그램에 있기 때문입니다.

## 플랫폼 `GlobalConfig` 허용 목록

`PlatformConfig.restrict_global_config`는 검사를 제어합니다:

- `0`: 플랫폼은 다른 방식으로 유효한 `GlobalConfig`를 수락합니다; 허용 계정이 필요하지 않습니다.
- `1`: `Initialize`, `InitializeV2`, `InitializeWithToken2022`는 일치하는 `PlatformAllowConfig`를 `remaining_accounts`의 어디든 포함해야 합니다.

플랫폼 관리자는 `CreatePlatformAllowConfig`와 `ClosePlatformAllowConfig`로 PDA를 생성하거나 닫습니다. 그 시드는 `[b"platform_allow_config", platform_config, global_config]`입니다. 이전 관리자 관리 `PlatformGlobalAccess` 명령어와 PDA는 폐기됩니다.

## 플랫폼 런칭 매개변수 규칙

4개의 명령어가 하나의 `PlatformCurveRule` 계정을 관리합니다. 4개 모두 `PlatformConfig.curve_rule_manager` 또는 플랫폼 관리자에 의해 서명됩니다 — 프로그램은 서명자에서 `PlatformConfig` PDA를 재파생하여 관리자를 수락하므로 별도의 계정이 이를 증명하지 않습니다. 둘 다 아닌 서명자는 `InvalidCurveRuleAuthority`를 반환합니다.

| 명령어 | 계정 | 인자 |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority` (서명자, mut), `platform_config`, `global_config`, `platform_curve_rule` (mut), `system_program` | 없음 |
| `UpdatePlatformCurveRule` | 동일한 5개 | `group_id: u16`, `constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | 동일한 5개 | `group_id: u16` |
| `ClosePlatformCurveRule` | 처음 4개 | 없음 |

`platform_curve_rule`은 `[b"platform_curve_rule", platform_config, global_config]`의 PDA입니다.

- **`Create`**는 그룹이 없는 계정을 할당합니다. 해당 상태는 아무것도 제한하지 않습니다.
- **`Update`**는 해당 `group_id`를 가진 그룹을 업서트하여, 존재하면 전체적으로 교체합니다. 계정 크기를 조정하므로 서명자는 증가한 렌트를 충전하고 감소한 렌트를 받습니다. 10번째를 넘는 새 그룹은 `CurveRuleGroupsExceeded`를 반환합니다; 25개 이상의 제약, 알 수 없는 필드 또는 연산자, 또는 한 그룹에서 동일한 `(field, op)` 쌍이 두 번 나타나면 `InvalidCurveRuleConstraint`를 반환합니다; 비상수 곱 설정에서 4개의 `TotalSellA` 파생 필드는 `CurveRuleFieldNotSupportedByCurve`를 반환합니다.
- **`Remove`**는 id로 하나의 그룹을 삭제하여 계정을 축소하고 차이를 환불합니다. 알 수 없는 id는 `CurveRuleGroupNotExist`를 반환합니다.
- **`Close`**는 전체 렌트를 서명자에게 반환합니다. 설정은 `restrict_curve_param`이 `1`로 유지되어도 제한되지 않습니다.

4개 모두 규칙이 강제되는지 여부를 변경하지 않습니다. 그것은 `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`이며, 플랫폼 관리자만 호출할 수 있습니다.

**런칭 경로에서.** `restrict_curve_param`이 `1`인 동안, `InitializeV2`와 `InitializeWithToken2022`는 `remaining_accounts`에 규칙 PDA를 요구합니다 — 존재하지 않을 때도 포함하여, 이를 생략하면 검사를 건너뛸 수 없습니다. 누락된 계정은 `NotEnoughRemainingAccounts`입니다; 어떤 그룹도 만족하지 않는 런칭은 `CurveParamNotMatchPlatformRule`입니다. 검사는 `GlobalConfig`의 자체 제한 전에 실행되며 이를 좁힐 수만 있습니다. 모델 및 플레이북: [`products/launchlab/curve-rules`](/ko/products/launchlab/curve-rules). 두 오류 모두 클라이언트 측에서 피할 수 있습니다 — SDK는 이 검사를 순수 함수로 미러링합니다. [전송 전 확인](/ko/products/launchlab/curve-rules#check-before-you-send)을 참조하세요.
