## 명령어 목록

|-------|-------------|-------------|

| 런칭 생명주기 | `Initialize` | **아무도 불가능 — 항상 `NotApproved`로 실패합니다.** 디스크리미네이터가 점유된 상태를 유지하고 IDL이 안정적으로 유지되도록 보존됩니다. `InitializeV2`를 사용하세요. |
| 런칭 생명주기 | `InitializeV2` | 누구나 (생성자) — SPL Token 기본 민트; 향후 CPMM 졸업을 위해 `amm_creator_fee_on`을 기록하고 Token-2022 견적 민트를 수락합니다. |
| 런칭 생명주기 | `InitializeWithToken2022` | 누구나 (생성자) — Token-2022 기본 민트, 선택적 `TransferFeeConfig`; 어느 견적 토큰 프로그램이든 수락합니다 |

| 졸업 | `MigrateToCpswap` | 마이그레이션 지갑 — CPMM으로 졸업합니다. 새로 초기화된 모든 런칭이 이 경로를 사용합니다. CPMM의 `InitializeWithPermission`을 래핑합니다. |

| 베스팅 | `CreateVestingAccount` | 생성자 — 수혜자에게 잠긴 토큰 할당, 졸업 후 잠금 해제 |
| 베스팅 | `CreatePlatformVestingAccount` | 플랫폼 관리자 — 플랫폼 측 수혜자에게 잠긴 토큰 할당 |

"ExactIn/ExactOut" 분할은 CPMM의 `SwapBaseInput` / `SwapBaseOutput`을 반영합니다 — 온체인에서는 약간 다른 반올림을 가진 별도의 명령어 디스크리미네이터입니다.

**졸업 경로 선택.** 모든 새로운 `InitializeV2` 및 `InitializeWithToken2022` 호출은 `migrate_type = 1` (`CPSWAP`)을 설정해야 합니다. 새로운 AMM v4 바운드 풀을 초기화하려는 모든 시도는 `MigrateTypeNotMatch`를 반환합니다. `amm_creator_fee_on`은 결과 CPMM 생성자 수수료가 견적 토큰에 적용되는지 또는 두 토큰 모두에 적용되는지만 선택합니다. 대상 프로그램을 선택하지 않습니다. 레거시 `Initialize`는 더 이상 런칭을 생성할 수 없습니다 (아래 참조).

`MigrateToAmm`은 이 제한이 강제되기 전에 `migrate_type = 0`으로 초기화된 기존 `PoolState`에 대해 호출 가능하게 유지됩니다. 릴리스는 기존 풀 상태를 다시 쓰거나 레거시 명령어를 제거하지 않습니다.

**견적 측 토큰 프로그램.** 견적 민트는 SPL Token 프로그램 또는 Token-2022 중 하나로 소유될 수 있습니다. 이를 건드리는 모든 명령어 — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, 네 가지 거래 명령어, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee`, `ClaimPlatformFeeFromVault` — 는 견적 프로그램 계정 슬롯에서 소유 프로그램을 받습니다. 계정 위치는 변경되지 않았습니다. 수락된 값만 변경되었습니다. 실제로 `GlobalConfig.quote_mint`를 소유하는 프로그램을 전달하세요. 기존 런칭의 경우 `PoolState.token_program_flag` bit1에서 읽을 수 있습니다 ([`accounts`](/ko/products/launchlab/accounts#poolstate) 참조) 또는 민트 계정의 소유자에서 읽을 수 있습니다.

더 이상 사용되지 않는 `Initialize`는 여기서 무관합니다: 견적 프로그램 계정은 여전히 SPL Token으로 입력되며, 2026-09 업그레이드 이후 명령어는 계정을 읽기 전에 실패합니다. `InitializeV2` 또는 `InitializeWithToken2022`를 통해 런칭하세요.

`MigrateToCpswap`은 반대 방향의 다른 예외입니다 — 민트당 하나가 아니라 **두 프로그램 모두**를 무조건 받습니다. 아래 [마이그레이션 계정](#cpmm-migration-token-programs)을 참조하세요.

## `Initialize`

<Warning>
  **2026-09 업그레이드 이후 효력 상실 — 이 명령어는 항상 실패합니다.** `initialize`의 핸들러는 이제 `Not supported. Please use initialize_v2 instruction`과 `NotApproved` (`6000`)를 기록하는 것뿐입니다. 판별자가 점유된 상태를 유지하고 IDL이 안정적인 형태를 유지하도록 순수하게 보존됩니다. (`Accounts` 구조체는 변경되지 않았으므로 Anchor의 생성된 검증이 먼저 실행되고, 트랜잭션은 어쨌든 되돌려집니다.)

  이전에는 클록에 의해 제어되었습니다. `get_upgrade_timestamp` 전환 후 3일까지는 작동했고 그 이후에는 실패했습니다. 이제 그 타임스탬프 헬퍼가 없으므로 실패는 무조건적입니다. 기존에 이를 통해 생성된 런칭은 영향을 받지 않으며, 저장된 `migrate_type`에 따라 `MigrateToAmm` 또는 `MigrateToCpswap`을 통해 정상적으로 거래되고 졸업합니다.

  아래의 인수와 계정 목록은 `InitializeV2`의 것입니다. 더 이상 사용되지 않는 `Initialize`는 동일한 순서로 동일한 18개 계정을 사용하고 처음 세 개의 인수만 사용합니다 — `amm_fee_on`이 없습니다 — 그리고 `quote_token_program` 슬롯은 `Interface<TokenInterface>` 대신 SPL Token으로 입력됩니다.
</Warning>

새로운 런칭을 생성합니다. `InitializeV2`는 더 이상 사용되지 않는 `Initialize`에 비해 `amm_fee_on` 인수만 추가합니다. 계정 **개수와 순서는 동일**하며, 유일한 계정 수준의 차이는 `quote_token_program`이 `Interface<TokenInterface>`로 입력되어 Token-2022 quote 민트가 허용된다는 것입니다.

**인수**

하나의 구조체가 아닌 네 개의 위치 인수입니다. (`InitializeWithToken2022`는 다섯 번째 `transfer_fee_extension_param: Option<TransferFeeExtensionParams>`를 추가합니다. 더 이상 사용되지 않는 `Initialize`는 `amm_fee_on`을 제거합니다.)

```rust
base_mint_param: MintParams {
    decimals: u8,                 // must equal the program's BASE_MINT_DECIMALS
    name:     String,
    symbol:   String,
    uri:      String,
}

curve_param: CurveParams {        // Borsh enum — one leading variant-tag byte
    Constant { data: ConstantCurve { supply: u64, total_base_sell: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Fixed    { data: FixedCurve    { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Linear   { data: LinearCurve   { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
}

vesting_param: VestingParams {
    total_locked_amount: u64,     // 0 requires cliff_period == unlock_period == 0
    cliff_period:        u64,     // seconds after fundraising ends
    unlock_period:       u64,     // seconds
}

amm_fee_on: AmmCreatorFeeOn       // 0 = QuoteToken, 1 = BothToken (CPMM migrations only)
```

변형은 `global_config.curve_type`과 일치해야 하거나 명령어가 `InputNotMatchCurveConfig` (`6003`)으로 되돌려집니다. `open_time`이 없고, `quote_mint` 인수가 없으며 (`global_config`에서 옵니다), `fees` 구조체가 없고 `post_graduation_lp_policy`가 없습니다 — LP 처리는 런칭별이 아닌 `PlatformConfig`에서 설정됩니다.

**계정** — 총 18개 (선언된 16개 + `#[event_cpi]` 추가 2개)

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 모든 렌트를 지불합니다. 생성자일 필요는 없습니다. |
| 2 | `creator` |   |   | `pool_state.creator`로 기록됩니다. 서명자가 아닙니다. |
| 3 | `global_config` |   |   | Quote 민트, 곡선 유형 및 모든 하한/상한을 제공합니다. |
| 4 | `platform_config` |   |   | 플랫폼 수수료율 및 LP 처리 정책을 제공합니다. |
| 5 | `authority` |   |   | PDA `["vault_auth_seed"]` — 모든 런칭에서 공유하는 하나의 글로벌 PDA입니다. |
| 6 | `pool_state` | W |   | 새 계정입니다. |
| 7 | `base_mint` | W | S | 새로운 키페어 — 이 명령어가 이를 초기화합니다. |
| 8 | `quote_mint` |   |   | `global_config.quote_mint`과 같아야 합니다. |
| 9 | `base_vault` | W |   | PDA `["pool_vault", pool_state, base_mint]`. |
| 10 | `quote_vault` | W |   | PDA `["pool_vault", pool_state, quote_mint]`. |
| 11 | `metadata_account` | W |   | Metaplex 메타데이터 PDA입니다. |
| 12 | `base_token_program` |   |   | `InitializeV2`의 경우 SPL Token, `InitializeWithToken2022`의 경우 Token-2022입니다. |
| 13 | `quote_token_program` |   |   | `quote_mint`를 소유하는 프로그램 — SPL Token 또는 Token-2022입니다. |
| 14 | `metadata_program` |   |   | Metaplex Token Metadata입니다. |
| 15 | `system_program` |   |   | |
| 16 | `rent_program` |   |   | Rent sysvar입니다. |
| 17 | `event_authority` |   |   | PDA `["__event_authority"]`. `#[event_cpi]`에 의해 추가됩니다. |
| 18 | `program` |   |   | LaunchLab 프로그램 ID. `#[event_cpi]`에 의해 추가됩니다. |

**전제 조건**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- 수수료 매개변수가 `launch_config.max_*_fee_rate` 검사를 통과합니다.
- `open_time ≥ now − slop` (SDK는 `≥ now`를 강제합니다. 프로그램은 약간의 역날짜를 허용합니다).
- `curve_type`이 인식됩니다.

**사후 조건**

- `base_mint`는 `supply = curve_param.supply`를 가지며, 모두 `base_vault`에 있습니다.
- 민트 권한은 **이 동일한 명령어에서 취소됩니다** (`set_authority(MintTokens, None)`) 공급이 민트된 직후 — 졸업 시점이 아닙니다. 따라서 base 민트는 영구적으로 고정 공급이며, 이후 명령어는 더 이상 민트할 수 없습니다.
- `PoolState`는 `status = Fund` (`0`), `real_a = 0`, `real_b = 0`으로 초기화됩니다.
- `total_fund_raising_b`는 `curve_param.total_quote_fund_raising`에서 직접 옵니다.
- `TransferFeeConfig`가 첨부된 `InitializeWithToken2022`의 경우: `transfer_fee_config_authority = launch_authority`, 그리고 `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` (해당 필드가 설정된 경우), 그렇지 않으면 `launch_authority`. 인출 측은 플랫폼이 졸업 전에 보류된 수수료를 수집할 수 있도록 민트 생성 시점에 기록됩니다. [`platform-config`](/ko/products/launchlab/platform-config#token-2022-transfer-fee-authorities)를 참조하세요.

**일반적인 오류** — `NotApproved` (`6000`, 더 이상 사용되지 않는 `Initialize`의 경우 무조건적), `InvalidInput` (`6002`, `GlobalConfig`의 공급/비율/자금 조성 하한 위반), `InputNotMatchCurveConfig` (`6003`, `curve_param` 변형이 `global_config.curve_type`과 일치하지 않음), `MigrateTypeNotMatch` (`6007`, `migrate_type != 1`), `MathOverflow` (`6008`), `VestingRatioTooHigh` (`6010`), `NoSupportExtension` (`6017`), `NotEnoughRemainingAccounts` (`6018`), `InvalidPlatformAllowConfig` (`6022`), `CurveParamNotMatchPlatformRule` (`6025`). 실패한 Anchor `address =` / `constraint =` 검사는 이러한 코드 중 하나가 아닌 2xxx 코드로 표시됩니다 — `InvalidQuoteMint`, `FeeRateTooHigh` 또는 `InvalidCurveParams` 중 어느 것도 프로그램의 오류 열거형에 존재하지 않습니다.

## `Buy` (정규 변형: `BuyExactIn`)

사용자가 고정 입력 금액을 제공하고, 곡선이 출력을 계산합니다.

**인수**

```
amount_in:           u64
minimum_amount_out:  u64
share_fee_rate:      u64   // referral fee on a 1_000_000 denominator; must be
                           // <= global_config.max_share_fee_rate. Pass 0 for no
                           // referral. Any non-zero value requires the share-fee
                           // receiver as remaining_accounts[0].
```

<Warning>
  네 가지 거래 명령어 모두 **세 개**의 인수를 사용하며, 두 개가 아닙니다. 두 개의 금액만으로 구성된 명령어는 8바이트가 부족하여 역직렬화에 실패합니다.
</Warning>

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 거래자입니다. |
| 2 | `authority` |   |   | PDA `["vault_auth_seed"]` — 런칭별 시드가 없는 하나의 글로벌 PDA입니다. |
| 3 | `global_config` |   |   | `address = pool_state.global_config`. |
| 4 | `platform_config` |   |   | `address = pool_state.platform_config`. |
| 5 | `pool_state` | W |   | |
| 6 | `user_base_token` | W |   | `token::mint = base_token_mint`. |
| 7 | `user_quote_token` | W |   | `token::mint = quote_token_mint`. |
| 8 | `base_vault` | W |   | `address = pool_state.base_vault`. |
| 9 | `quote_vault` | W |   | `address = pool_state.quote_vault`. |
| 10 | `base_token_mint` |   |   | |
| 11 | `quote_token_mint` |   |   | |
| 12 | `base_token_program` |   |   | base 민트를 소유하는 프로그램 — SPL Token 또는 Token-2022입니다. |
| 13 | `quote_token_program` |   |   | quote 민트를 소유하는 프로그램입니다. |
| 14 | `event_authority` |   |   | PDA `["__event_authority"]`. `#[event_cpi]`에 의해 추가됩니다. |
| 15 | `program` |   |   | LaunchLab 프로그램 ID. `#[event_cpi]`에 의해 추가됩니다. |

**남은 계정** — 수수료 배관, 정확한 순서로 읽음:

1. `share_fee_receiver` — **오직** `share_fee_rate > 0`일 때만.
2. `system_program` — 항상. `== System::id()` 확인, 그렇지 않으면 `InvalidInput`.
3. `platform_fee_vault` — PDA `[platform_config, quote_token_mint]`. 첫 사용 시 생성됩니다.
4. `creator_fee_vault` — PDA `[creator, quote_token_mint]`. 첫 사용 시 생성됩니다.

부족하면 `NotEnoughRemainingAccounts` (`6018`)를 반환합니다. `associated_token_program` 슬롯이 없으며, `system_program`은 선언된 계정이 아닌 *남은* 계정입니다.

**전제 조건**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**효과**

1. `quote_in`을 `quote_in_after_fee`와 수수료 부분으로 분할합니다.
2. 사후 수수료 quote에 대해 `base_out`에 대한 곡선을 Newton 풀이합니다.
3. `require(base_out ≥ minimum_base_out)` 그렇지 않으면 `ExceededSlippage`로 되돌립니다.
4. `quote_in` 사용자 → 금고로 이동합니다. `base_out` 금고 → 사용자로 이동합니다.
5. `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`를 업데이트합니다.
6. 수수료 카운터를 업데이트합니다 (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. 업데이트 후 `quote_reserve_real ≥ quote_reserve_target`이면, SDK는 일반적으로 동일한 트랜잭션에서 `Graduate` ix를 연결합니다. 프로그램은 `Buy` 내에서 자동 졸업하지 않습니다 — 후속 `Graduate`가 필요합니다.

## `BuyExactOut`

사용자가 정확한 `base_out`을 지정하고, 프로그램이 `quote_in`을 계산합니다.

**인수**

```
amount_out:         u64
maximum_amount_in:  u64
share_fee_rate:     u64   // as for BuyExactIn
```

`BuyExactIn`과 동일한 계정 및 동일한 남은 계정 계약입니다. Newton 반복 대신 폐쇄형 이차 적분 (또는 curve_type 1의 경우 CPMM 역함수)을 사용합니다.

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy`의 대칭 명령어입니다. 사용자가 `base_in`을 곡선에 반환하고 `quote_out`을 받습니다. 수수료는 `quote_out`에서 차감되므로 사용자는 원시 적분 수익보다 적게 받습니다.

**사전 조건** —

- `user_base_ata.balance ≥ base_in`.
- 판매로 인해 `base_sold`가 0 아래로 내려갈 수 없습니다 (회계가 일관성 있으면 위의 조건과 중복).
- Launch는 `Active` 상태입니다.

**효과** — `Buy`와 대칭입니다. `base_sold`는 감소하고, `quote_reserve_real`은 감소합니다. 수수료는 계속 누적됩니다.

### Quote 측 전송 수수료

Quote 민트가 `TransferFeeConfig`를 가지고 있으면, 볼트가 이동하는 금액과 지불자가 차감되거나 입금되는 금액이 다르며, 슬리피지 한계는 지불자 측에 대해 확인됩니다. 확장 기능이 없는 quote 민트에서는 아래의 모든 경우가 일반 레거시 민트와 동일합니다.

| 명령어 | 인자 | 확인 대상 |
|---|---|---|
| `BuyExactIn` | `amount_in` | 곡선은 `amount_in − transfer_fee(amount_in)` — 볼트에 도달하는 금액으로 가격이 책정됩니다. 완전 체결은 정확히 `amount_in`을 차감하고, 부분 체결은 소비된 볼트 금액과 그 역 수수료를 차감합니다. |
| `BuyExactOut` | `maximum_amount_in` | 볼트 금액 **더하기** 역 전송 수수료 — 실제 차감액. |
| `SellExactIn` | `minimum_amount_out` | 판매자가 민트가 수수료를 원천징수한 후 보유하는 금액, 볼트에서 나가는 총액이 아닙니다. |
| `SellExactOut` | `amount_out` | 정확히 전달됩니다. 곡선은 `amount_out` 더하기 역 전송 수수료를 목표로 합니다. |

견적 작성에 대한 두 가지 결과:

- 민트가 수수료 없는 것처럼 계산된 한계는 거부됩니다. 수수료 없는 비용을 `maximum_amount_in`으로 전달하거나, 수수료 없는 수익을 `minimum_amount_out`으로 전달하면 `ExceededSlippage`로 되돌립니다.
- `real_quote`는 볼트에 도달한 금액만큼만 증가합니다. 5% quote 민트에서 `amount_in`의 `BuyExactIn`은 `real_quote`를 `amount_in × 0.95`만큼 이동합니다.

100% 수수료 quote 민트 (`10000` 베이시스 포인트)는 반전될 수 없으며 정확한 출력 경로에서 `CalculateOverflow`로 되돌립니다.

두 거래 측 민트도 일치하는 슬롯에 전달된 프로그램으로 제한되므로, 일치하지 않는 `base_token_program`은 이제 무시되지 않고 실패합니다. 기본 수수료 수학은 [`algorithms/token-2022-transfer-fees`](/ko/algorithms/token-2022-transfer-fees)를 참조하세요.

### 거래 남은 계정

네 가지 거래 명령어 모두 `remaining_accounts`를 통해 수수료 배관을 다음 순서로 처리합니다:

| 인덱스 | 계정 | 조건 |
|---|---|---|
| 0 | `share_fee_receiver` | `share_fee_rate > 0`일 때만. 존재할 때 아래의 모든 인덱스를 하나씩 이동합니다. |
| 다음 | `system_program` | 항상. 수수료 볼트 생성에 자금을 제공합니다. |
| 다음 | `platform_fee_vault` | 항상. 시드 `[platform_config, quote_token_mint]`의 PDA, 처음 사용 시 생성됩니다. |
| 다음 | `creator_fee_vault` | 항상. 시드 `[creator, quote_token_mint]`의 PDA, 처음 사용 시 생성됩니다. |

<Note>
  **2026-09에서 변경됨: 마지막 세 개는 이제 무조건이며, `system_program`이 검증됩니다.** 이 릴리스 이전에는 프로그램이 `unix_timestamp >= get_upgrade_timestamp()`일 때만 읽었고, 그 시점 이전에는 플랫폼/크리에이터 수수료 분할을 완전히 건너뛰었습니다. 타임스탬프는 오래 지났으므로 메인넷의 동작은 실제로 변경되지 않았습니다 — 하지만 분기는 코드에서 제거되었고, 여전히 세 계정을 생략하는 빌더는 이제 항상 `NotEnoughRemainingAccounts` (`6018`)로 실패하며, 이전에는 컷오버 이후에만 실패했습니다. `system_program` 슬롯은 추가로 `System::id()`에 대해 검증되며, 다른 계정을 보유하면 `InvalidInput` (`6002`)을 반환합니다. 이전에는 해당 위치에서 모든 계정이 허용되었습니다.
</Note>

## `MigrateToAmm` / `MigrateToCpswap`

곡선이 `total_quote_fund_raising`에 도달한 후 런칭을 거래 가능한 풀로 졸업시킵니다. 새로운 런칭은 CPMM 전용입니다. `MigrateToAmm`은 저장된 `migrate_type`이 `0`인 기존 풀을 위해 유지됩니다.

**서명자**

- `MigrateToAmm` — 바인딩된 `GlobalConfig`에 기록된 `migrate_to_amm_wallet`.
- `MigrateToCpswap` — 바인딩된 `GlobalConfig`에 기록된 `migrate_to_cpswap_wallet`.

이 지갑들은 일반적으로 Raydium이 운영하는 졸업 크랭크에 의해 보유되며, 실제로는 누가 최종 구매를 트리거했는지와 관계없이 임계값을 넘은 후 몇 초 내에 졸업이 진행됩니다.

**인수**

둘 다 인수를 받지 않습니다.

<Warning>
  **주요 변경 사항 (마이그레이션 지갑만 해당, 2026-09).** `MigrateToAmm`은 세 개의 인수 — `base_lot_size`, `quote_lot_size`, `market_vault_signer_nonce` — **및 9개의 계정**을 모두 제거했습니다. 이제 명령 데이터는 단순한 판별자이므로, 이전 빌더는 17바이트의 예상치 못한 인수를 보내고 더 이상 정렬되지 않는 계정 목록을 제공합니다.

  이는 AMM v4의 자체 [OpenBook 제거](/ko/reference/changelog/2026-07-22-amm-v4-openbook-removal)를 따릅니다: AMM v4의 `Initialize2`는 더 이상 `market_program` 또는 `amm_open_orders`를 받지 않으므로, LaunchLab은 전달할 것이 남지 않았습니다. 프로그램은 또한 `initialize_openbook_market`을 CPI하지 않게 되었으며, 이는 세 개의 인수가 구성한 것입니다.

  제거된 계정: `openbook_program`, `request_queue`, `event_queue`, `bids`, `asks`, `market_vault_signer`, `market_base_vault`, `market_quote_vault`, 및 `amm_open_orders`. `market` 계정은 **위치에 남아** 있습니다 — AMM v4는 여전히 이를 참조 필드로 기록합니다 — 하지만 이제는 단순한 `#[account(mut)]`로 선언됩니다: 소유자, 주소 또는 시드 제약이 없습니다. 완전히 검증되지 않으며, AMM v4의 `Initialize2` CPI로 직접 전달되고, 프로그램은 더 이상 이를 초기화하지 않습니다. 마켓 계정이 실제로 초기화된 마켓이기를 원하는 호출자는 미리 직접 생성해야 합니다.

  남은 23개 계정 목록은 순서대로: `payer`, `base_mint`, `quote_mint`, `market`, `amm_program`, `amm_pool`, `amm_authority`, `amm_lp_mint`, `amm_base_vault`, `amm_quote_vault`, `amm_target_orders`, `amm_config`, `amm_create_fee_destination`, `authority`, `pool_state`, `global_config`, `base_vault`, `quote_vault`, `pool_lp_token`, `spl_token_program`, `associated_token_program`, `system_program`, `rent_program`.

  `MigrateToCpswap`은 영향을 받지 않습니다 — 인수가 없었습니다.
</Warning>

**효과 (둘 다 공통)**

1. `pool_state.status == Migrate` 확인 (즉, `quote_reserve_target`에 도달했음). 그렇지 않으면 `PoolMigrated` (상태가 이미 `Migrated`임) 또는 `PoolFunding` (여전히 펀딩 중)으로 되돌립니다.
2. `pool_state.migrate_type`이 명령과 일치하는지 확인 (AMM의 경우 `0`, CPMM의 경우 `1`). 그렇지 않으면 `MigrateTypeNotMatch`로 되돌립니다.
3. 졸업 후 리저브 계산:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. 대상 프로그램 (`AMM v4 Initialize2` 또는 `CPMM InitializeWithPermission`)으로 CPI하여 해당 리저브로 졸업 후 풀을 생성합니다.
5. 2026-08-17 업그레이드 이후 실행된 CPMM 마이그레이션의 경우, `platform_scale + creator_scale`을 하나의 플랫폼 소유 잠금 LP 공유로 결합하고 최대 하나의 Fee Key NFT를 `platform_nft_wallet`에 민트합니다. `burn_scale` 나머지를 소각합니다. 업그레이드 전에는 `creator_scale`이 별도로 잠금되었고 해당 Fee Key는 토큰 생성자에게 갔습니다. 완료된 과거 마이그레이션은 수정되지 않습니다. 레거시 AMM v4 졸업의 경우, LP 배치는 해당 명령의 기존 흐름을 따릅니다.
6. (민트 권한 단계 없음. `base_mint.mint_authority`는 런칭 생성 시 이미 `None`으로 설정되었습니다 — 아래 참고 참조.)
7. `pool_state.status = Migrated`로 전환하고, `vesting_schedule.start_time = block_time + cliff_period`를 설정합니다.

**Token-2022 전송 수수료 권한 이양** — 기본 민트가 `TransferFeeConfig`를 포함하는 Token-2022 민트이고 **`PlatformConfig.transfer_fee_extension_auth`가 기본값이 아닌 경우**, 마이그레이션은 또한 해당 확장의 권한을 플랫폼 키로 재할당합니다:

- `transfer_fee_config_authority`는 항상 재할당됩니다. 런칭 `authority` PDA는 졸업 전 단계 전체에서 이를 보유하므로 항상 이동할 것이 있습니다.
- `WithheldWithdraw`는 **`authority` PDA가 여전히 이를 보유할 때만** 재할당됩니다. 2026-08-27 이후에 생성된 런칭은 이미 민트 생성 시 해당 권한에 `transfer_fee_extension_auth`를 포함하므로 단계를 건너뜁니다. 가드는 마이그레이션이 해당 민트에서 되돌리지 않도록 하는 것입니다 — PDA는 더 이상 보유하지 않는 권한을 포기할 수 없습니다.

마이그레이션 시 `transfer_fee_extension_auth`가 `Pubkey::default()`인 경우, 어느 권한도 이동하지 않으며 둘 다 `authority` PDA에 영구적으로 남아 있습니다. [`platform-config`](/ko/products/launchlab/platform-config#token-2022-transfer-fee-authorities)를 참조하세요.

<Note>
  **기본 민트의 공급량은 졸업이 아닌 생성 시점부터 고정됩니다.** `InitializeV2`와 `InitializeWithToken2022`는 전체 공급량을 기본 금고에 민트한 다음 같은 명령에서 즉시 `MintTokens`를 취소하므로, `base_mint.mint_authority`는 런칭의 전체 수명 동안 `None`입니다. 마이그레이션은 이를 건드리지 않습니다. (이 페이지의 이전 버전은 취소를 졸업 시점에 배치했습니다. 그것은 잘못되었습니다.) 마이그레이션이 이동할 수 있는 유일한 권한은 아래에 설명된 Token-2022 전송 수수료 권한입니다.
</Note>

**사후 조건** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut`은 이 시점부터 `PoolMigrated`로 거부합니다. 결과 AMM 풀은 정규이며 다른 AMM v4 / CPMM 풀처럼 거래합니다.

**일반적인 오류** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### CPMM 마이그레이션 남은 계정

`MigrateToCpswap`을 구축하는 클라이언트는 다음 고정 `remaining_accounts` 인덱스를 사용해야 합니다:

| 인덱스 | 계정 |
|---|---|
| 0–4 | 플랫폼 Fee Key 소유자, 민트, 토큰 계정, 잠금 유동성 PDA, 및 메타데이터 계정 |
| 5 | 원래 런칭 생성자; `platform_cp_creator`가 설정되지 않았을 때 사용됨 |
| 6 | `[b"permission", launch_authority]`에서 파생된 CPMM 권한 PDA |
| 7 | 구성된 `platform_cp_creator`; 필드가 기본값이 아닐 때 사용됨 |
| 8 | 정렬된 `mint0`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint0]`에서 파생됨 |
| 9 | 정렬된 `mint1`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint1]`에서 파생됨 |

명령은 최소 10개의 남은 계정이 필요합니다. 지원 민트 계정은 읽기 전용 CPI 입력입니다. 민트가 초기화된 지원 레코드가 없을 때도 두 주소를 모두 파생시킵니다. 여전히 생성자 잠금 계정을 추가하거나 인덱스 8–9를 생략하는 이전 빌더는 업데이트해야 합니다.

<Note>
  **2026-09에서 변경됨.** 두 가지 정리로, 올바른 빌더는 변경되지 않습니다:

  - **권한이 있는 CPMM 경로가 이제 유일한 경로입니다.** `MigrateToCpswap`은 `unix_timestamp >= get_upgrade_timestamp()`를 기반으로 `InitializeCpSwap`과 `InitializeCpSwapWithPermission` 사이에서 선택하곤 했습니다. 타임스탬프 헬퍼와 레거시 CPI는 모두 사라졌으므로, 권한이 있는 경로 — 따라서 10개 계정 최소값 — 이 무조건 적용됩니다.
  - **세 개의 주소 제약이 계정 구조에서 명령 본문으로 이동했습니다.** `platform_config`, `base_vault`, 및 `quote_vault`는 여전히 `PoolState`에 저장된 값과 일치해야 하지만, 불일치는 이제 Anchor의 `address =` 제약이 아닌 `require_keys_eq!`로 발생합니다. 검사는 동등하지만, 오류 표면만 다릅니다 — 계정 이름 없이 Anchor의 일반 `RequireKeysEqViolated` (`2502`) 대신 `ConstraintAddress` (`2012`)를 받습니다. 이 세 계정에 대해 `2012`와 일치하는 오류 처리를 업데이트하세요.
</Note>

### CPMM 마이그레이션 토큰 프로그램

`MigrateToCpswap`은 두 토큰 프로그램을 무조건 받고 각 민트를 소유하는 프로그램을 스스로 파악합니다. 두 토큰 프로그램 계정의 이름이 변경되었습니다:

| 위치 | 계정 | 값 |
|---|---|---|
| 첫 번째 | `token_program` | 항상 레거시 SPL Token 프로그램 |
| 두 번째 | `token_program_2022` | 항상 Token-2022 프로그램 |

이들은 이전의 `base_token_program` (기본 민트를 소유한 프로그램이 무엇이든) 및 `quote_token_program` (항상 레거시)을 대체합니다. 위치는 변경되지 않으므로 이는 레이아웃 변경이 아닌 값 변경입니다 — 하지만 두 값은 거의 반전되며, 이전 쌍을 계속 전달하는 빌더는 어느 민트가 Token-2022 민트가 되는 즉시 레거시 프로그램이 필요한 곳에 Token-2022를 제공합니다.

CPMM LP 민트와 잠금 유동성 Fee Key NFT가 항상 레거시 프로그램에 있으므로 레거시 프로그램이 필요합니다.

## 플랫폼 `GlobalConfig` 허용 목록

`PlatformConfig.restrict_global_config`는 검사를 제어합니다:

- `0`: 플랫폼은 다른 방식으로 유효한 모든 `GlobalConfig`를 수락합니다; 허용 계정이 필요하지 않습니다.
- `1`: `Initialize`, `InitializeV2`, 및 `InitializeWithToken2022`는 `remaining_accounts`의 어디든 일치하는 `PlatformAllowConfig`를 포함해야 합니다.

플랫폼 관리자는 `CreatePlatformAllowConfig` 및 `ClosePlatformAllowConfig`로 PDA를 생성하거나 닫습니다. 시드는 `[b"platform_allow_config", platform_config, global_config]`입니다. 이전의 관리자 관리 `PlatformGlobalAccess` 명령 및 PDA는 폐기됩니다.

## 플랫폼 런칭 매개변수 규칙

4개의 명령이 하나의 `PlatformCurveRule` 계정을 관리합니다. 4개 모두 `PlatformConfig.curve_rule_manager` 또는 플랫폼 관리자에 의해 서명됩니다 — 프로그램은 서명자에서 `PlatformConfig` PDA를 재파생하여 관리자를 수락하므로 별도의 계정이 이를 증명하지 않습니다. 둘 다 아닌 서명자는 `InvalidCurveRuleAuthority`를 반환합니다.

| 명령 | 계정 | 인수 |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority` (서명자, mut), `platform_config`, `global_config`, `platform_curve_rule` (mut), `system_program` | 없음 |
| `UpdatePlatformCurveRule` | 동일한 5개 | `group_id: u16`, `constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | 동일한 5개 | `group_id: u16` |
| `ClosePlatformCurveRule` | 처음 4개 | 없음 |

`platform_curve_rule`은 `[b"platform_curve_rule", platform_config, global_config]`의 PDA입니다.

- **`Create`** 그룹이 없는 계정을 할당합니다. 해당 상태는 아무것도 제한하지 않습니다.
- **`Update`** 해당 `group_id`로 그룹을 업서트하여, 존재하면 전체적으로 교체합니다. 계정 크기를 조정하므로 서명자는 증가한 렌트를 충당하고 감소한 렌트를 돌려받습니다. 10번째를 넘는 새 그룹은 `CurveRuleGroupsExceeded`를 반환합니다; 25개 이상의 제약, 알 수 없는 필드 또는 연산자, 또는 한 그룹에서 동일한 `(field, op)` 쌍이 두 번 나타나면 `InvalidCurveRuleConstraint`를 반환합니다; 비상수 곱 구성에서 4개의 `TotalSellA` 파생 필드는 `CurveRuleFieldNotSupportedByCurve`를 반환합니다.
- **`Remove`** ID로 하나의 그룹을 삭제하여 계정을 축소하고 차이를 환불합니다. 알 수 없는 ID는 `CurveRuleGroupNotExist`를 반환합니다.
- **`Close`** 전체 렌트를 서명자에게 반환합니다. 그러면 `restrict_curve_param`이 `1`로 유지되더라도 구성이 제한되지 않습니다.

4개 모두 규칙이 적용되는지 여부를 변경하지 않습니다. 그것은 `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`이며, 플랫폼 관리자만 호출할 수 있습니다.

**런칭 경로에서.** `restrict_curve_param`이 `1`인 동안, `InitializeV2` 및 `InitializeWithToken2022`는 `remaining_accounts`에 규칙 PDA를 요구합니다 — 존재하지 않을 때도 포함하여, 이를 생략하면 검사를 건너뛸 수 없습니다. 누락된 계정은 `NotEnoughRemainingAccounts`입니다; 어떤 그룹도 만족하지 않는 런칭은 `CurveParamNotMatchPlatformRule`입니다. 검사는 `GlobalConfig`의 자체 제한 전에 실행되며 이를 좁힐 수만 있습니다. 모델 및 플레이북: [`products/launchlab/curve-rules`](/ko/products/launchlab/curve-rules). 두 오류 모두 클라이언트 측에서 피할 수 있습니다 — SDK는 이 검사를 순수 함수로 미러링합니다. [전송 전에 확인](/ko/products/launchlab/curve-rules#check-before-you-send)을 참조하세요.

## `CollectExcessLamports`

LaunchLab이 제어하는 계정의 렌트 면제 최소값 이상에 있는 램포트를 관리자가 회수합니다. 2026-09 업그레이드에서 추가되어 프로토콜이 [SIMD-0437 렌트 감소](/ko/solana-fundamentals/rent-and-reclaimable-rent)가 각 단계 전에 생성된 계정에 남기는 초과 자금을 회수할 수 있습니다.

초과분만 이동합니다. 토큰 잔액, 계정 데이터, 소유자, 곡선 상태 및 베스팅은 변경되지 않으며, 이미 최소값에 있는 계정에 대해서는 명령이 작동하지 않습니다 — 따라서 각 롤아웃 단계 후에 다시 실행하는 것이 안전합니다.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 설명 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | 모든 회수된 램포트의 목적지입니다. LaunchLab 프로그램 관리자 또는 전용 수집 램포트 지갑이어야 합니다 — [`reference/program-addresses`](/ko/reference/program-addresses#excess-lamports-collection-wallets)를 참조하세요. 다른 서명자는 `InvalidOwner`(`6001`)로 실패합니다. |
| 2 | `authority` |   |   | LaunchLab의 세 가지 볼트 권한 PDA 중 **하나**(아래 참조). 이 호출의 모든 토큰 계정에 대해 토큰 프로그램 CPI에 서명합니다. |
| 3 | `token_program` |   |   | SPL Token입니다. |
| 4 | `token_program_2022` |   |   | Token-2022입니다. 둘 다 무조건 필요하며, 프로그램이 소스 계정별로 선택합니다. |
| 5.. | `remaining_accounts` | W |   | 회수할 `M`개의 소스 계정, 임의의 개수, 임의의 순서입니다. |

**`authority` 선택**

계정은 확인 없이 전달되고 프로그램에 의해 해결되며, 프로그램은 LaunchLab의 세 가지 권한 PDA를 모두 다시 파생하고 일치시킵니다:

| 시드 | 소유 |
|---|---|
| `[b"vault_auth_seed"]` | 모든 런칭의 기본 및 쿼트 풀 볼트 |
| `[b"platform_fee_vault_auth_seed"]` | 모든 플랫폼 수수료 볼트 |
| `[b"creator_fee_vault_auth_seed"]` | 모든 크리에이터 수수료 볼트 |

세 가지 중 어느 것과도 일치하지 않는 키는 `InvalidOwner`(`6001`)로 전체 명령을 실패하게 합니다.

<Warning>
  **소스 계정을 권한별로 그룹화하세요.** 한 번의 호출은 하나의 `authority`를 전달하고, 토큰 프로그램은 계정의 실제 소유자가 서명하도록 요구합니다. 전달한 `authority`와 다른 세 가지 PDA 중 하나가 소유한 토큰 계정은 CPI를 실패하게 하고 전체 트랜잭션을 함께 가져갑니다. 풀 볼트, 플랫폼 수수료 볼트 및 크리에이터 수수료 볼트를 별도의 트랜잭션에서 회수하세요.

  프로그램 소유 PDA는 예외입니다 — 직접 차감되므로 모든 권한과 함께 탈 수 있습니다.
</Warning>

**각 소스 계정이 처리되는 방식**

| 소스 계정 소유자 | 처리 |
|---|---|
| SPL Token 또는 Token-2022, 비네이티브 토큰 계정 | CPI `WithdrawExcessLamports`(토큰 프로그램 판별자 `38`), `authority`로 서명됨. |
| SPL Token 또는 Token-2022, **네이티브**(wSOL) 토큰 계정 | `WithdrawExcessLamports`는 네이티브 계정을 거부합니다. 프로그램은 `SyncNative`를 CPI하고, 래핑된 `amount`가 얼마나 증가했는지 측정하고, 정확히 그 델타에 대해 `UnwrapLamports`(판별자 `45`)를 수행한 후, 래핑된 잔액이 사전 동기화 값과 같아야 합니다 — 그렇지 않으면 `LamportsCalculateError`(`6031`). SOL 인용 런칭은 따라서 전체 쿼트 준비금을 유지합니다. |
| LaunchLab 프로그램 자체 — `PoolState`, `GlobalConfig`, `PlatformConfig`, `VestingRecord`, `PlatformCurveRule`, `PlatformAllowConfig` | 프로그램은 계정을 `rent.minimum_balance(data_len)`까지 직접 차감합니다. |
| 다른 모든 것 | **조용히 건너뜁니다.** 오류 없음, 램포트 이동 없음. |

**기본 민트는 회수할 수 없습니다.** `InitializeV2`와 `InitializeWithToken2022`는 공급을 민트하는 동일한 명령에서 기본 민트의 `MintTokens`를 취소하므로, 어떤 키도 이에 대해 `WithdrawExcessLamports`에 서명할 수 없습니다 — 민트의 렌트는 영구적으로 그대로 유지됩니다.

**일반적인 오류** — `InvalidOwner`(`6001`, 잘못된 서명자 또는 세 가지 PDA 중 하나가 아닌 `authority`), `LamportsCalculateError`(`6031`, wSOL 왕복이 0으로 정산되지 않음), 계정이 자신의 렌트 최소값보다 적게 보유할 때 프로그램 소유 경로의 `InsufficientFunds`.

**SDK 빌더 없음.** `@raydium-io/raydium-sdk-v2`는 이 명령에 대한 빌더를 제공하지 않으며, `raydium-sdk-V2-demo` 저장소도 마찬가지입니다 — 이는 관리자 경로입니다. 수동으로 인코딩하세요, [`solana-fundamentals/rent-and-reclaimable-rent`](/ko/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction)의 지갑 측 회수가 토큰 프로그램 명령에 대해 수행하는 방식처럼.
