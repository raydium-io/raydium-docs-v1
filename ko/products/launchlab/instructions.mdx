## 명령어 목록

| 그룹 | 명령어 | 호출 가능자 |
|-------|-------------|-------------|
| 글로벌 설정 | `CreateConfig` / `UpdateConfig` | 프로그램 관리자; 위임된 create-config 권한도 `CreateConfig` 호출 가능 |
| 런칭 생명주기 | `Initialize` / `InitializeV2` | 누구나 (생성자) — SPL Token 런칭; V2는 향후 CPMM 졸업을 위해 `amm_creator_fee_on` 기록 |
| 런칭 생명주기 | `InitializeWithToken2022` | 누구나 (생성자) — Token-2022 런칭, 선택적 `TransferFeeConfig` |
| 거래 | `BuyExactIn` / `BuyExactOut` | 누구나 — 본딩 곡선에서 정확한 입력/출력 매수 |
| 거래 | `SellExactIn` / `SellExactOut` | 누구나 — 본딩 곡선에서 정확한 입력/출력 매도 |
| 졸업 | `MigrateToAmm` | 마이그레이션 지갑 — CPMM 전용 생성이 강제되기 전에 초기화된 풀을 위한 레거시 AMM v4 졸업 |
| 졸업 | `MigrateToCpswap` | 마이그레이션 지갑 — CPMM으로 졸업. 새로 초기화된 모든 런칭이 이 경로를 사용. CPMM의 `InitializeWithPermission` 래핑 |
| 수수료 | `CollectFee` | 관리자 — 런칭에서 프로토콜 수수료 수거 |
| 수수료 | `CollectMigrateFee` | 관리자 — 누적된 마이그레이션 수수료 수거 |
| 수수료 | `ClaimCreatorFee` | 생성자 — 곡선 단계 중 누적된 생성자 수수료 청구 |
| 베스팅 | `CreateVestingAccount` | 생성자 — 수혜자에게 잠긴 토큰 할당, 졸업 후 해제 |
| 베스팅 | `CreatePlatformVestingAccount` | 플랫폼 관리자 — 플랫폼 측 수혜자에게 잠긴 토큰 할당 |
| 베스팅 | `ClaimVestedToken` | 수혜자 — 클리프 후 해제된 토큰 청구 |
| 플랫폼 설정 | `CreatePlatformConfig` / `UpdatePlatformConfig` | 플랫폼 관리자 |
| 플랫폼 설정 | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | 플랫폼 관리자 — 허용된 곡선 형태의 플랫폼별 목록 관리 |
| 플랫폼 수수료 | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | 플랫폼 관리자 |
| 플랫폼 접근 | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 플랫폼 관리자 — 해당 플랫폼이 제한을 활성화할 때 사용되는 `GlobalConfig` 허용 목록 유지 |

"ExactIn/ExactOut" 분할은 CPMM의 `SwapBaseInput` / `SwapBaseOutput`을 반영합니다 — 온체인에서는 약간 다른 반올림을 가진 별도의 명령어 판별자입니다.

**졸업 경로 선택.** 모든 새로운 `Initialize`, `InitializeV2`, `InitializeWithToken2022` 호출은 `migrate_type = 1` (`CPSWAP`)을 설정해야 합니다. 새로운 AMM v4 바운드 풀을 초기화하려는 시도는 `MigrateTypeNotMatch`를 반환합니다. `amm_creator_fee_on`은 결과 CPMM 생성자 수수료가 인용 토큰에 적용되는지 또는 두 토큰 모두에 적용되는지만 선택합니다. 대상 프로그램을 선택하지 않습니다.

`MigrateToAmm`은 이 제한 전에 `migrate_type = 0`으로 초기화된 기존 `PoolState`에 대해 호출 가능하게 유지됩니다. 릴리스는 기존 풀 상태를 다시 쓰거나 레거시 명령어를 제거하지 않습니다.

## `Initialize`

새로운 런칭을 생성합니다.

**인자**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // 또는 curve_type=1의 경우 initial_virtual_quote_reserve
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // 인라인 name/symbol/uri; 프로그램이 Metaplex로 CPI
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**계정** (축약)

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 렌트 + 베이스 민트 생성 비용 지불. |
| 2 | `launch_config` |   |   | 프로토콜 설정 바인딩. |
| 3 | `launch_state` | W |   | 새 계정. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | 신규 Keypair (또는 PDA) — 이 명령어가 초기화. |
| 6 | `base_vault` | W |   | `launch_authority`의 `base_mint` ATA. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | `launch_authority`의 `quote_mint` ATA. |
| 9 | `metadata` | W |   | Metaplex 메타데이터 PDA. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token만. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**사전 조건**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- 수수료 매개변수가 `launch_config.max_*_fee_rate` 검사를 통과.
- `open_time ≥ now − slop` (SDK는 `≥ now` 강제; 프로그램은 약간의 백데이팅 허용).
- `curve_type`이 인식됨.

**사후 조건**

- `base_mint`는 `supply = base_supply_max`, 모두 `base_vault`에 있음.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState`는 `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`으로 초기화.
- `quote_reserve_target`은 곡선 매개변수 + `base_supply_graduation` + `buy_numerator`에서 계산 (대략).

**일반적인 오류** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (정규 변형: `BuyExactIn`)

사용자가 고정 `quote_in`을 제공하고, 곡선이 `base_out`을 계산합니다.

**인자**

```
quote_in:          u64
minimum_base_out:  u64
```

**계정**

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**사전 조건**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**효과**

1. `quote_in`을 `quote_in_after_fee`와 수수료 부분으로 분할.
2. 사후 수수료 인용에 대해 `base_out`을 위해 곡선을 Newton 풀이.
3. `require(base_out ≥ minimum_base_out)` 아니면 `ExceededSlippage`로 되돌림.
4. `quote_in` 사용자 → 금고로 이동. `base_out` 금고 → 사용자로 이동.
5. `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)` 업데이트.
6. 수수료 카운터 업데이트 (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. 업데이트 후 `quote_reserve_real ≥ quote_reserve_target`이면, SDK는 일반적으로 같은 트랜잭션에서 `Graduate` ix를 연결합니다. 프로그램은 `Buy` 내에서 자동 졸업하지 않습니다 — 후속 `Graduate`가 필요합니다.

## `BuyExactOut`

사용자가 정확한 `base_out`을 지정하고, 프로그램이 `quote_in`을 계산합니다.

**인자**

```
base_out:      u64
maximum_quote_in: u64
```

`BuyExactIn`과 동일한 계정. Newton 반복 대신 폐쇄형 이차 적분 (또는 curve_type 1의 경우 CPMM 역함수)을 사용합니다.

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy`의 미러. 사용자가 `base_in`을 곡선에 반환하고 `quote_out`을 받습니다. 수수료는 `quote_out`에서 공제되므로 사용자는 원본 통합 수익보다 적게 받습니다.

**사전 조건** —

- `user_base_ata.balance ≥ base_in`.
- 매도는 `base_sold`를 0 아래로 밀 수 없음 (회계가 일관성 있으면 위와 중복).
- 런칭이 `Active`.

**효과** — `Buy`와 대칭. `base_sold` 감소, `quote_reserve_real` 감소. 수수료는 여전히 누적됩니다.

## `MigrateToAmm` / `MigrateToCpswap`

곡선이 `total_quote_fund_raising`에 도달하면 런칭을 거래 가능한 풀로 졸업시킵니다. 새로운 런칭은 CPMM 전용입니다. `MigrateToAmm`은 저장된 `migrate_type`이 `0`인 기존 풀을 위해 유지됩니다.

**서명자**

- `MigrateToAmm` — 바인딩 `GlobalConfig`에 기록된 `migrate_to_amm_wallet`.
- `MigrateToCpswap` — 바인딩 `GlobalConfig`에 기록된 `migrate_to_cpswap_wallet`.

이 지갑은 일반적으로 Raydium 운영 졸업 크랭크에 의해 보유됩니다. 실제로 졸업은 최종 매수를 트리거한 사람과 관계없이 임계값이 넘은 후 몇 초 내에 발생합니다.

**인자**

`MigrateToAmm`은 3개를 취합니다 (주로 프로그램이 AMM v4로 전달하는 OpenBook 시장 매개변수):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap`은 없습니다.

**효과 (둘 다 공통)**

1. `pool_state.status == Migrate` 확인 (즉, `quote_reserve_target`에 도달). 아니면 `PoolMigrated` (상태가 이미 `Migrated`) 또는 `PoolFunding` (여전히 펀딩 중)으로 되돌림.
2. `pool_state.migrate_type`이 명령어와 일치하는지 확인 (`0` AMM, `1` CPMM). 아니면 `MigrateTypeNotMatch`로 되돌림.
3. 사후 졸업 준비금 계산:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. 대상 프로그램 (`AMM v4 Initialize2` 또는 `CPMM InitializeWithPermission`)으로 CPI하여 그 준비금으로 사후 졸업 풀 생성.
5. 2026-08-17 업그레이드 후 실행된 CPMM 마이그레이션의 경우, `platform_scale + creator_scale`을 하나의 플랫폼 소유 잠긴 LP 공유로 결합하고 최대 하나의 Fee Key NFT를 `platform_nft_wallet`에 민트. `burn_scale` 나머지 소각. 업그레이드 전에는 `creator_scale`이 별도로 잠겼고 그 Fee Key는 토큰 생성자에게 갔습니다. 완료된 과거 마이그레이션은 수정되지 않습니다. 레거시 AMM v4 졸업의 경우, LP 처분은 그 명령어의 기존 흐름을 따릅니다.
6. `base_mint.mint_authority` 취소 (None으로 설정).
7. `pool_state.status = Migrated` 뒤집기, `vesting_schedule.start_time = block_time + cliff_period` 설정.

**사후 조건** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut`은 이 시점부터 `PoolMigrated`로 거부합니다. 결과 AMM 풀은 정규이며 다른 AMM v4 / CPMM 풀처럼 거래합니다.

**일반적인 오류** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### CPMM 마이그레이션 남은 계정

`MigrateToCpswap`을 구축하는 클라이언트는 이 고정 `remaining_accounts` 인덱스를 사용해야 합니다:

| 인덱스 | 계정 |
|---|---|
| 0–4 | 플랫폼 Fee Key 소유자, 민트, 토큰 계정, 잠긴 유동성 PDA, 메타데이터 계정 |
| 5 | 원본 런칭 생성자; `platform_cp_creator`가 설정되지 않았을 때 사용 |
| 6 | `[b"permission", launch_authority]`에서 파생된 CPMM 권한 PDA |
| 7 | 구성된 `platform_cp_creator`; 필드가 기본값이 아닐 때 사용 |
| 8 | 정렬된 `mint0`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint0]`에서 파생 |
| 9 | 정렬된 `mint1`에 대한 CPMM 지원 민트 PDA, `[b"support_mint", mint1]`에서 파생 |

명령어는 업그레이드된 경로에서 최소 10개의 남은 계정이 필요합니다. 지원 민트 계정은 읽기 전용 CPI 입력입니다. 민트가 초기화된 지원 기록이 없을 때도 두 주소를 모두 파생시킵니다. 여전히 생성자 잠금 계정을 추가하거나 인덱스 8–9를 생략하는 이전 빌더는 업데이트해야 합니다.

## 플랫폼 `GlobalConfig` 허용 목록

`PlatformConfig.restrict_global_config`는 검사를 제어합니다:

- `0`: 플랫폼은 유효한 `GlobalConfig`를 수용합니다; 허용 계정이 필요하지 않습니다.
- `1`: `Initialize`, `InitializeV2`, `InitializeWithToken2022`는 `remaining_accounts` 어디든 일치하는 `PlatformAllowConfig`를 포함해야 합니다.

플랫폼 관리자는 `CreatePlatformAllowConfig`와 `ClosePlatformAllowConfig`로 PDA를 생성하거나 닫습니다. 그 시드는 `[b"platform_allow_config", platform_config, global_config]`입니다. 이전 관리자 관리 `PlatformGlobalAccess` 명령어와 PDA는 폐기됩니다.

## `CollectFee`

단일 런칭에서 프로토콜의 누적된 거래 수수료의 관리자 수거.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `protocol_fee_owner` |   | S | `global_config.protocol_fee_owner`와 같아야 함. |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`; 금고 이전에 서명. |
| 3 | `pool_state` | W |   | `quote_protocol_fee`를 0으로 변경하도록 변경. |
| 4 | `global_config` |   |   | 서명자의 진실 공급원. |
| 5 | `quote_vault` | W |   | `quote_protocol_fee`로 배수. |
| 6 | `recipient_token_account` | W |   | `protocol_fee_owner`의 `quote_mint` ATA. |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | SPL Token (인용 민트는 항상 SPL Token). |

**효과** — `pool_state.quote_protocol_fee`를 `quote_vault`에서 `recipient_token_account`로 이전한 후 카운터를 0으로. 첫 매수 후 언제든 호출 가능.

## `CollectMigrateFee`

졸업 시 누적된 마이그레이션 수수료의 관리자 수거. `CollectFee`와 동일한 계정 형태이지만 (`protocol_fee_owner` 대신) `migrate_fee_owner`를 서명자로 하고 `pool_state.migrate_fee`를 배수 카운터로.

## `ClaimCreatorFee`

생성자가 소유한 **모든 런칭**에서 동일한 인용 민트를 사용하는 누적된 생성자 수수료의 생성자별 수거. 풀별 수수료 금고가 아닌 생성자별 수수료 금고를 배수.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 풀 생성자. |
| 2 | `fee_vault_authority` |   |   | PDA `[b"creator_fee_vault_auth_seed"]`. |
| 3 | `creator_fee_vault` | W |   | 시드 `[creator, quote_mint]`의 PDA; 집계된 생성자 금고. |
| 4 | `recipient_token_account` | W |   | `init_if_needed`; `creator`의 `quote_mint` ATA. |
| 5 | `quote_mint` |   |   | |
| 6 | `token_program` |   |   | |

## `ClaimPlatformFee`

런칭의 인용 금고를 직접 배수하는 플랫폼별 수거. 집계된 플랫폼 금고를 거치지 않고 플랫폼이 특정 런칭 하나에 대한 슬라이스를 청구하려 할 때 사용합니다.

**인자** — 없음.

**계정**

| # | 이름 | W | S | 참고 |

| 1 | `platform_fee_wallet` | W | S | `platform_config.platform_fee_wallet`과 같아야 함. |

| 3 | `pool_state` | W |   | `pool_state.platform_fee`로 배수. |
| 4 | `platform_config` |   |   | 서명자의 진실 공급원. |
| 5 | `quote_vault` | W |   | 배수. |
| 6 | `recipient_token_account` | W |   | `init_if_needed`; `platform_fee_wallet`의 ATA. |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | |
| 9 | `system_program` |   |   | |
| 10 | `associated_token_program` |   |   | |

**효과** — `pool_state.platform_fee`를 `quote_vault`에서 `recipient_token_account`로 이전, 카운터를 0으로.
