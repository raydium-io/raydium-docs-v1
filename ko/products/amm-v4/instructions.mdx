SDK는 사용자 대면 명령어에 대한 빌더만 노출합니다. 유지보수 명령어는 일반적으로 Raydium 키퍼에 의해 호출됩니다.

**제거됨 / 더 이상 호출 불가** (클라이언트 빌더 삭제됨): `Initialize` (태그 0, `Initialize2` 사용), `MonitorStep` (2), `MigrateToOpenBook` (5), `WithdrawSrm` (8), `PreInitialize` (10, `Initialize2` 사용), `SimulateInfo` (12), `AdminCancelOrders` (13).

이러한 태그 중 하나를 포함하는 트랜잭션은 실패합니다. 프로그램은 명령어를 실행하지 않습니다. 이 일곱 개를 모두 처리할 오류 경로가 아닌 제거된 것으로 취급하세요.

## `Initialize2`

기존 OpenBook 마켓에 바인딩된 새로운 AMM v4 풀을 부트스트랩합니다.

**인자**

```
nonce:        u8
open_time:    u64
init_pc_amount:   u64
init_coin_amount: u64
```

**계정** (쓰기 가능 `W`, 서명자 `S`)

| # | 이름 | W | S | 참고 |
|---|------|---|---|------|
| 1 | `token_program` |   |   | `== spl_token::id()` 확인. |
| 2 | `associated_token_program` |   |   | 생성자의 LP ATA를 만드는 데 사용됩니다. |
| 3 | `system_program` |   |   | |
| 4 | `rent` |   |   | 여전히 `initialize_account` / `initialize_mint` CPI로 전달됩니다 — 빼지 마세요. |
| 5 | `amm` | W |   | `AmmInfo` PDA `[programId, market, "amm_associated_seed"]`; 여기서 생성됩니다. |
| 6 | `amm_authority` |   |   | PDA `["amm authority"]`; `nonce` 인수는 그 범프와 같아야 합니다. |
| 7 | `lp_mint` | W |   | PDA `[programId, market, "lp_mint_associated_seed"]`; 여기서 생성됩니다. |
| 8 | `coin_mint` |   |   | `pc_mint`와 달라야 합니다(`InvalidCoinMint`). |
| 9 | `pc_mint` |   |   | |
| 10 | `pool_coin_token_account` | W |   | PDA `[programId, market, "coin_vault_associated_seed"]`. |
| 11 | `pool_pc_token_account` | W |   | PDA `[programId, market, "pc_vault_associated_seed"]`. |
| 12 | `pool_target_orders_account` | W |   | PDA `[programId, market, "target_associated_seed"]`. |
| 13 | `amm_config` |   |   | 프로그램 수준 구성 PDA `["amm_config_account_seed"]`; 불일치 시 `InvalidConfigAccount`. |
| 14 | `create_fee_destination` | W |   | `config_feature::create_pool_fee_address`와 같아야 하며, 그렇지 않으면 `InvalidFee`. |
| 15 | `market` |   |   | 검증되지 않습니다 — 위의 모든 PDA에 대한 가변 시드로만 사용되며 참조 필드로 저장됩니다. |
| 16 | `user_wallet` | W | S | 생성자. Rent, 풀 생성 수수료, 초기 예치금을 지불합니다. |
| 17 | `user_token_coin` | W |   | |
| 18 | `user_token_pc` | W |   | |
| 19 | `user_token_lp` | W |   | 생성자의 LP ATA; 프로그램이 생성합니다. |

<Note>
  **수락되는 두 가지 레이아웃.** 위의 19개 계정 목록이 권장 레이아웃입니다. 하위 호환성을 위해
  프로그램은 21개 계정의 레거시 레이아웃도 읽으며, 이는 위치 7에 무시되는 `amm_open_orders`와
  위치 16에 무시되는 `market_program`을 삽입합니다 — 저장소 내 `initialize2` 명령어 빌더가
  여전히 내보내는 것이 바로 이것입니다. 그 외의 길이는 레거시 레이아웃에 대해 위치상으로
  파싱되어 실패합니다.
</Note>

**사후 조건**

- 생성자에게 발행되는 LP = `sqrt(init_coin_amount × init_pc_amount) − 10^coin_mint.decimals`. LP 소수 자릿수는 `coin_mint.decimals`와 같으므로 차감되는 양은 정확히 온전한 LP 토큰 한 개입니다. 이는 절대 발행되지 않으며 영구적으로 유통에서 제외됩니다. `sqrt(...)`가 그보다 작으면 명령어는 `InitLpAmountTooLess`로 복귀합니다.
- `AmmInfo.lp_amount`는 발행된 양이 **아니라** 전체 `sqrt(...)`를 저장합니다 — 따라서 `lp_mint.supply`는 `amm.lp_amount`보다 영구적으로 온전한 LP 토큰 한 개만큼 작습니다. 모든 비례 계산은 `amm.lp_amount`를 사용합니다.
- OpenBook 주문이 게시되지 않습니다 (주문서 그리드가 제거됨). `AmmInfo.market`은 슬롯 15에서 전달된 계정을 기록하지만, `AmmInfo.open_orders`와 `AmmInfo.market_program`은 둘 다 `Pubkey::default()`로 기록되며, `coin_lot_size` / `pc_lot_size` / `min_size`는 `0`으로 초기화됩니다. 레거시 21개 계정 레이아웃에서는 추가된 `amm_open_orders`와 `market_program` 계정이 읽힌 뒤 폐기됩니다.

**일반적인 오류** — `InvalidCoinMint` (coin과 pc 민트가 동일), `InvalidConfigAccount` (잘못된 `amm_config` PDA), `InvalidFee` (잘못된 풀 생성 수수료 목적지), `InvalidProgramAddress` (잘못된 `amm_authority` 또는 잘못된 `nonce`), `RepeatCreateAmm` (이 마켓에 이미 풀이 존재), `InitLpAmountTooLess`, `InvalidSupply` (초기 금액 중 하나가 `0`이거나 LP 민트에 이미 공급량이 있음), `AlreadyInUse`.

  `WrongAccountsNumber`로 복귀합니다.
</Warning>

더 이상 OpenBook에서 정산하는 단계가 없습니다 — 비례 수학은 금고 잔액을 직접 사용합니다.

## `SwapBaseIn`

정확한 입력 스왑. 항상 **AMM 경로** 스왑입니다 (OpenBook 매칭을 통해 라우팅하지 않음).

<Note>
  **새 코드에는 V2 변형을 사용하세요.** AMM v4의 OpenBook 의존성이 제거되었으므로 V1 진입점 (`SwapBaseIn`, `SwapBaseOut`)은 여전히 전체 17개 계정 목록 (또는 선택적 target-orders 계정 포함 18개)을 예상하지만 OpenBook/마켓 계정은 이제 **위치적으로 수락되고 무시됩니다**. 검증되지 않으며 CPI가 발행되지 않습니다. 잘못된 계정 *개수*를 전달하면 여전히 `WrongAccountsNumber`로 되돌아가지만 마켓 계정 *내용*은 더 이상 확인되지 않습니다. 새로운 통합은 [`SwapBaseInV2` / `SwapBaseOutV2`](#swapbaseinv2-/-swapbaseoutv2)를 사용해야 하며, 이는 훨씬 더 작은 계정 목록을 사용하고 오늘날의 정규 실행 경로를 나타냅니다. V1 형식은 완전성을 위해 그리고 기존 온체인 트랜잭션을 읽기 위해 여기에 문서화되어 있습니다.
</Note>

**인자**

```
amount_in:            u64
minimum_amount_out:   u64
```

**계정** (축약)

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `amm_open_orders` | W |   |
| 5 | `amm_target_orders` | W |   |
| 6 | `pool_coin_token_account` | W |   |
| 7 | `pool_pc_token_account` | W |   |
| 8 | `market_program` |   |   |
| 9 | `market` | W |   |
| 10 | `market_bids` | W |   |
| 11 | `market_asks` | W |   |
| 12 | `market_event_queue` | W |   |
| 13 | `market_coin_vault` | W |   |
| 14 | `market_pc_vault` | W |   |
| 15 | `market_vault_signer` |   |   |
| 16 | `user_source_token_account` | W |   |
| 17 | `user_dest_token_account` | W |   |
| 18 | `user_owner` |   | S |

**수학** — [`products/amm-v4/math`](/ko/products/amm-v4/math)를 참조하세요.

**사전 조건**

- `AmmStatus::from_u64(amm.status).swap_permission()`이 true입니다 — 즉, `status`가 `1`(`Initialized`), `6`(`SwapOnly`) 또는 `7`(`WaitingTrade`)입니다. `status`는 비트마스크가 아니라 열거형 값입니다. [`products/amm-v4/accounts`](/ko/products/amm-v4/accounts#status)를 참조하세요.
- `amm.state_data.pool_open_time <= now`.
- `amount_in > 0`.
- `user_source_token_account`는 최소 `amount_in`을 보유합니다.

**사후 조건**

- 사용자는 소스 토큰 `amount_in`을 잃고 대상 토큰 `amount_out ≥ minimum_amount_out`을 얻습니다.
- 스왑 수수료는 금고에 남아 불변식 `k`를 높입니다. `need_take_pnl_*` 카운터는 스왑에서 **건드려지지 않습니다** — 프로토콜 PnL은 다음 `Deposit`, `Withdraw` 또는 `WithdrawPnl`(`Processor::calc_take_pnl`)에서 `k` 델타로부터 다시 계산됩니다.
- 참고: `state_data.swap_*_in_amount` / `swap_*_out_amount` 분석 카운터는 **더 이상 업데이트되지 않습니다**. 값이 고정됩니다. 거래량 분석을 위해 거래 로그를 사용하세요.

**일반적인 오류** — `ExceededSlippage`, `InvalidInput`, `InvalidStatus`, `NotAllowed` (coin/pc mint 동일).

## `SwapBaseInV2` / `SwapBaseOutV2`

OpenBook 계정을 **완전히 건너뛰는** 변형 스왑 진입점 (태그 **16** / **17**). 수학은 V1 경로와 동일하지만 계정 목록은 AMM 측과 사용자만으로 축소됩니다. **8개 계정, `amm_open_orders`는 전달되지 않습니다**:

| # | 이름 | W | S |
|---|------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `pool_coin_token_account` | W |   |
| 5 | `pool_pc_token_account` | W |   |
| 6 | `user_source_token_account` | W |   |
| 7 | `user_dest_token_account` | W |   |
| 8 | `user_owner` |   | S |

풀 준비금은 이제 금고 잔액 (미결제 PnL 제외)이므로 견적 수학은 간단하고 v1 경로와 동일합니다. V2를 사용하여 계산을 절약하고 (이제 무시되는) 마켓 계정을 전달하지 않도록 하세요. Raydium 라우터는 AMM v4를 통해 라우팅할 때 항상 V2 형식을 사용합니다.

인자는 V1 형식과 동일합니다 (`SwapBaseInV2`의 경우 `amount_in / minimum_amount_out`; `SwapBaseOutV2`의 경우 `max_amount_in / amount_out`).

## `MonitorStep` 및 기타 제거된 명령어

<Warning>
  **제거됨 — 더 이상 호출 불가.** 2026-07 업그레이드 이후 `MonitorStep` (태그 2)이 프로그램에서 제거되었으며 호출되면 **되돌아갑니다** (`unimplemented!`). 클라이언트 빌더도 삭제되었습니다. `MigrateToOpenBook` (5), `WithdrawSrm` (8), `SimulateInfo` (12), `AdminCancelOrders` (13), 레거시 `Initialize` (0) / `PreInitialize` (10) 풀 생성 진입점도 동일하게 적용됩니다. `Initialize2`를 대신 사용하세요.
</Warning>

역사적으로 `MonitorStep`은 풀의 OpenBook 상호작용을 크랭크했습니다. 채워진 주문을 정산하고 (OpenBook CPI를 통해 마켓 금고에서 풀 금고로 수익 이동), 오래된 주문을 취소하고, `target_orders`와 `amm_open_orders` 사이의 간격을 좁히기 위해 새 주문을 게시했습니다. OpenBook 의존성이 제거되면서 크랭크할 것이 없어졌고 명령어가 제거되었습니다. 여전히 호출하는 키퍼나 통합은 호출을 제거해야 합니다.

**인자**

<Warning>

## `SetParams`

Raydium 멀티시그에서 호출하는 관리자 매개변수 변경. 인자는 `param: u8` 태그 + 페이로드입니다.

<Warning>
  **호환성 깨짐 (관리자만).** 계정 목록이 `[amm (W), admin (S)]`로만 축소되었습니다 (권한, open-orders, target-orders, 금고, 모든 마켓 계정이 제거됨). `param` 열거형이 **재번호 매기고 정리되었습니다**: `Status` = 0, `State` = 1, `Fees` = **2** (이전 9), `SetOpenTime` = **3** (이전 11). 모든 주문서 그리드 매개변수와 `AmmOwner`, `LastOrderDistance`, `UpdateOpenOrder`가 제거되었으며 `SetParamsInstruction` 구조체는 `new_pubkey`와 `last_order_distance`를 제거했습니다. 관리자 도구를 업데이트해야 합니다.
</Warning>

## `CreateConfigAccount` / `UpdateConfigAccount`

프로그램 수준 `AmmConfig` PDA (시드 `["amm_config_account_seed"]`)의 관리자 관리. 이 계정은 의미 있는 필드를 정확히 세 개 — `pnl_owner`, `cancel_owner`, `create_pool_fee` — 그리고 예약된 패딩 영역 두 개를 보유하며, 풀 생성 플래그는 없습니다. `UpdateConfigAccount`는 `param = 0`으로 `pnl_owner`, `param = 1`로 `cancel_owner`, `param = 2`로 `create_pool_fee`를 설정합니다.

<Note>
  **2026-09에서 변경되었으며 하위 호환성 유지.** `CreateConfigAccount`는 더 이상 rent sysvar를 읽지 않습니다. 계정 목록은 이제 **4개 계정**으로 5개에서 축소되었습니다:

  | # | 이름 | W | S |
  |---|------|---|---|
  | 1 | `admin` | W | S |
  | 2 | `amm_config` | W |   |
  | 3 | `pnl_owner` |   |   |
  | 4 | `system_program` |   |   |

  프로그램은 전달된 sysvar 계정을 역직렬화하는 대신 `Rent::get()`에서 rent 매개변수를 읽습니다. Solana 3.0 의존성 범프가 자연스럽게 만든 것입니다.

  제거된 계정은 목록의 **마지막**이었으며 핸들러는 길이 확인 없이 `next_account_info`를 통해 위치적으로 계정을 읽습니다. 따라서 여전히 이전 5개 계정 목록을 전달하는 기존 관리자 도구는 계속 작동합니다. 후행 rent 계정은 단순히 읽혀지지 않습니다. 편할 때 업데이트하세요. 긴급하지 않습니다. `UpdateConfigAccount`는 변경되지 않습니다.
</Note>

`Initialize2`는 위치 3에서 rent sysvar를 유지하며 여전히 **사용합니다**. 프로그램은 더 이상 `Rent::from_account_info`를 호출하지 않지만 풀의 금고와 LP mint를 생성하는 `spl_token::initialize_account` 및 `initialize_mint` CPI로 전달됩니다. 계정 목록에서 제거하지 마세요.

## `WithdrawExcessLamports`

프로그램이 제어하는 계정에서 rent 최소값 이상의 lamport를 수거하는 관리자 수거. 2026-09 업그레이드에서 추가되어 [SIMD-0437 rent 감소](/ko/solana-fundamentals/rent-and-reclaimable-rent)가 각 단계 전에 생성된 계정에 남기는 과다 자금을 복구합니다.

초과분만 이동합니다. 토큰 잔액, 계정 데이터, 소유자, 풀 상태는 변경되지 않으며 명령어는 이미 최소값에 있는 계정에서는 작동하지 않습니다. 따라서 반복적으로 그리고 각 롤아웃 단계 후에 다시 실행하는 것이 안전합니다.

**인자** — 없음. 페이로드는 단일 태그 바이트 `18`입니다.

**계정**

| # | 이름 | W | S | 참고 |
|---|------|---|---|------|
| 1 | `collect_lamports` | W | S | 모든 수거된 lamport의 대상. 클러스터의 collect-lamports 지갑과 같아야 합니다. [`reference/program-addresses`](/ko/reference/program-addresses#excess-lamports-collection-wallets)를 참조하세요. 다른 서명자는 `InvalidSignAccount`로 실패합니다. |
| 2 | `amm_authority` |   |   | 단일 AMM v4 권한 PDA, 프로그램에서 `["amm authority"]`로 고정 nonce 254로 재파생됩니다. 토큰 프로그램 CPI에 서명합니다. |
| 3 | `token_program` |   |   | **SPL Token.** `spl_token::id()`에 대해 확인됩니다. 잘못된 값은 `InvalidSplTokenProgram`으로 실패합니다. |
| 4.. | 소스 계정 | W |   | 수거할 `M`개 계정, 임의의 개수, 임의의 순서. |

**각 소스 계정 처리 방식**

프로그램은 소스 계정의 `owner`에 따라 디스패치합니다:

| 소스 계정 소유자 | 처리 |
|---|---|
| SPL Token, `data_len == 165` (토큰 계정), 비네이티브 | CPI `WithdrawExcessLamports` (토큰 프로그램 판별식 `38`), `amm_authority`로 서명. |
| SPL Token, `data_len == 165`, 네이티브 (wSOL) | `WithdrawExcessLamports`는 네이티브 계정에 사용할 수 없습니다. 프로그램은 `SyncNative`를 CPI하고, 래핑된 `amount`가 얼마나 증가했는지 측정하고, 정확히 그 델타에 대해 `UnwrapLamports` (판별식 `45`)를 수행한 다음 래핑된 잔액이 사전 동기화 값으로 돌아갔는지 확인합니다. 그렇지 않으면 `LamportsCalculateError`. 풀의 SOL 측 유동성은 따라서 절대 건드려지지 않습니다. |
| SPL Token, 다른 크기 (LP mint) | CPI `WithdrawExcessLamports`, `amm_authority`로 서명. |
| AMM v4 프로그램 자체 (`AmmInfo`, `TargetOrders`, `AmmConfig`) | 프로그램은 계정을 `rent.minimum_balance(data_len)`까지 직접 차감합니다. |
| 기타 | **조용히 건너뜁니다.** 오류 없음, lamport 이동 없음. |

**일반적인 오류** — `InvalidSignAccount` (잘못된 서명자), `InvalidSplTokenProgram` (슬롯 3의 잘못된 프로그램), `InvalidProgramAddress` (잘못된 `amm_authority`), `LamportsCalculateError` (사용자 정의 코드 `60`; wSOL 왕복이 0으로 정산되지 않음), 프로그램 소유 경로에서 계정이 자신의 rent 최소값보다 적게 보유할 때 `InsufficientFunds`.

**SDK 빌더 없음.** `@raydium-io/raydium-sdk-v2`는 이 명령어에 대한 빌더를 제공하지 않으며 `raydium-sdk-V2-demo` 저장소도 마찬가지입니다. 관리자 경로입니다. 수동으로 인코딩하세요. [`solana-fundamentals/rent-and-reclaimable-rent`](/ko/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction)의 지갑 측 수거가 토큰 프로그램 명령어에 대해 하는 방식처럼.
