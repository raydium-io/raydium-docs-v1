## 목록

AMM v4 풀은 생성 시 하나의 바인딩된 마켓을 `AmmInfo`에 기록합니다. 전체 구성은 다음과 같습니다:

| 카테고리 | 계정 | 소유자 | 역할 |
|----------|------|--------|------|
| 풀 | `AmmInfo` | AMM v4 프로그램 | 풀 상태: 누적된 수수료, 상태, 볼트 참조 (그리고 레거시 필드로서 마켓). |
| 풀 | `amm_authority` | AMM v4 프로그램 | 프로그램 소유 PDA로 볼트 이동에 서명합니다. 모든 AMM v4 풀에서 공유됩니다. |
| 풀 | `amm_open_orders` | OpenBook | 레거시 `OpenOrders` 참조. 더 이상 프로그램에서 읽거나 쓰지 않으며, v1 레이아웃에서 위치상으로만 전달됩니다. |
| 풀 | `amm_target_orders` | AMM v4 프로그램 | 레거시 타겟 주문 계정. 여전히 `WithdrawPnl`에서 참조되지만(계정 #10) 그리드는 더 이상 구축되지 않습니다. |
| 풀 | `pool_coin_token_account` | SPL Token | 풀의 코인 측 볼트 (`amm_authority`의 ATA). |
| 풀 | `pool_pc_token_account` | SPL Token | 풀의 pc 측 볼트. |
| 풀 | `lp_mint` | SPL Token | 대체 가능한 LP 민트. |
| 풀 | `pool_withdraw_queue` | AMM v4 프로그램 | 지연된 출금을 위한 레거시 큐; 길이 0으로 유지됩니다. |
| 풀 | `pool_temp_lp` | AMM v4 프로그램 | 보조 LP 계정. |
| 레거시 (OpenBook) | `serum_market` | OpenBook | 바인딩된 마켓. v1 레이아웃에서 전달되지만 더 이상 검증되거나 사용되지 않습니다. |
| 레거시 | `serum_bids`, `serum_asks` | OpenBook | 입찰/매도 큐. 무시됩니다. |
| 레거시 | `serum_event_queue` | OpenBook | 대기 중인 이벤트. 무시됩니다. |
| 레거시 | `serum_coin_vault`, `serum_pc_vault` | SPL Token | 마켓 수준 볼트. 무시됩니다. |
| 레거시 | `serum_vault_signer` | OpenBook | 마켓 수준 PDA. 무시됩니다. |

참고: "serum" 접두사는 하위 호환성을 위해 AMM v4의 IDL 및 필드 이름에 유지됩니다. 이 계정들은 OpenBook 제거 후 더 이상 기능하지 않습니다.

## `AmmInfo`

풀의 루트 상태 계정입니다. 풀과 OpenBook 참조를 인라인으로 포함하기 때문에 크기가 큽니다(약 752바이트).

```rust
// programs/amm/src/state.rs (축약; 필드 순서 / 이름은 IDL을 따름)
pub struct AmmInfo {
    pub status: u64,           // 비트마스크: 스왑/입금/출금/크랭크 활성화
    pub nonce:  u64,           // amm_authority 파생에 사용되는 범프
    pub order_num: u64,
    pub depth: u64,
    pub coin_decimals: u64,
    pub pc_decimals:   u64,
    pub state:         u64,    // 내부 상태 머신
    pub reset_flag:    u64,
    pub min_size:      u64,
    pub vol_max_cut_ratio: u64,
    pub amount_wave: u64,
    pub coin_lot_size: u64,    // 레거시 (OpenBook 로트 크기); 이제 0으로 초기화됨
    pub pc_lot_size:   u64,    // 레거시; 이제 0으로 초기화됨
    pub min_price_multiplier: u64,
    pub max_price_multiplier: u64,
    pub sys_decimal_value: u64,

    pub fees: Fees,            // 거래/프로토콜/펀드 수수료율
    pub state_data: StateData,

    // 풀 소유 계정:
    pub coin_vault: Pubkey,
    pub pc_vault:   Pubkey,
    pub coin_vault_mint: Pubkey,
    pub pc_vault_mint:   Pubkey,
    pub lp_mint:  Pubkey,
    pub open_orders: Pubkey,   // OpenBook의 풀 OpenOrders
    pub market: Pubkey,        // OpenBook 마켓
    pub market_program: Pubkey, // OpenBook 프로그램 ID
    pub target_orders: Pubkey,
    pub padding1: [u64; 8],     // 예약됨 — withdraw_queue / lp_vault 아님
    pub amm_owner: Pubkey,      // 관리자 (멀티시그)
    pub lp_amount: u64,         // 풀의 내부 LP 총액; 아래 참고 사항 참조
    pub client_order_id: u64,
    pub recent_epoch: u64,
    pub padding2: u64,
}

pub struct Fees {
    pub min_separate_numerator:   u64,     // 5
    pub min_separate_denominator: u64,     // 10_000
    pub trade_fee_numerator:      u64,     // 25  → OpenBook 통합에서 사용됨
    pub trade_fee_denominator:    u64,     // 10_000
    pub pnl_numerator:            u64,     // 12  → 스왑 수수료의 프로토콜 몫
    pub pnl_denominator:          u64,     // 100 → 따라서 12/100 = 수수료의 12%, = 거래량의 0.03%
    pub swap_fee_numerator:       u64,     // 25  → 0.25% 총 스왑 수수료
    pub swap_fee_denominator:     u64,     // 10_000
}

pub struct StateData {
    pub need_take_pnl_coin: u64,        // 여전히 업데이트됨 — 누적된 프로토콜 수수료 (코인 측)
    pub need_take_pnl_pc:   u64,        // 여전히 업데이트됨 — 누적된 프로토콜 수수료 (pc 측)
    pub total_pnl_pc:   u64,            // 더 이상 사용되지 않음 — 더 이상 업데이트되지 않음
    pub total_pnl_coin: u64,            // 더 이상 사용되지 않음 — 더 이상 업데이트되지 않음
    pub pool_open_time: u64,            // 여전히 사용됨 — 풀 개설 타임스탬프
    pub padding: [u64; 2],              // 예약됨
    pub orderbook_to_init_time: u64,    // 더 이상 사용되지 않음 — 더 이상 업데이트되지 않음
    pub swap_coin_in_amount: u128,      // 더 이상 사용되지 않음 — 거래량 카운터 동결됨
    pub swap_pc_out_amount:  u128,      // 더 이상 사용되지 않음
    pub swap_acc_pc_fee:    u64,        // 더 이상 사용되지 않음
    pub swap_pc_in_amount:  u128,       // 더 이상 사용되지 않음
    pub swap_coin_out_amount: u128,     // 더 이상 사용되지 않음
    pub swap_acc_coin_fee:  u64,        // 더 이상 사용되지 않음
}
```

<Note>
  구조체 **레이아웃은 변경되지 않았습니다**(바이트 호환), 따라서 기존 역직렬화기는 계속 작동하지만, OpenBook 제거 후 위에서 `더 이상 사용되지 않음`으로 표시된 필드는 **더 이상 쓰이지 않습니다** — `swap_*` 거래량 카운터는 마지막 값에서 동결됩니다. 거래량 분석을 위해서는 이 필드 대신 거래 로그를 사용하세요. `need_take_pnl_*`과 `pool_open_time`만 적극적으로 유지됩니다.
</Note>

통합자 대면 필드:

- **`coin_vault`**, **`pc_vault`** — 풀의 SPL Token 볼트. `coin`은 Serum/OpenBook 규칙에 따라 `token_0`(기본), `pc`는 `token_1`(인용)입니다.
- **`coin_decimals`**, **`pc_decimals`** — 민트와 일치합니다.
- **`open_orders`**, **`target_orders`**, **`market`** — 레거시 참조 필드. 여전히 `AmmInfo`에 있고 v1 명령어 레이아웃에서 위치상으로 전달되지만, 프로그램은 더 이상 읽거나 검증하지 않습니다. V2 스왑 진입점은 이들을 생략합니다.
- **`fees.swap_fee_numerator / swap_fee_denominator`** — 결합된 거래 수수료. 기본값 `25 / 10_000 = 0.25%`.
- **`status`** — 작업을 제어하는 단일 열거형 `u64` 상태이며 비트마스크가 **아닙니다**. `param = 0`(`Status`)과 함께 `SetParams`를 통해 관리자가 설정 가능합니다. 아래 [Status](#status)를 참조하세요.
- **`lp_amount`** — 풀의 내부 LP 총액. `lp_mint.supply`와 **같지 않습니다**: 정확히 온전한 LP 토큰 한 개(`10^coin_decimals` 기본 단위)만큼 더 큽니다. 그 양은 초기화 시 계산되지만 실제로 발행되지는 않기 때문입니다. 모든 비례 계산은 `lp_amount`를 사용하므로 당신도 이를 사용하세요.
- **`amm_owner`** — 생성 시 크리에이터가 아니라 프로그램에 하드코딩된 관리자 키에서 기록됩니다.
- **`state_data.need_take_pnl_*`** — 총 누적 수수료와 스윕된 금액 간의 차이. `TakePnl`이 이를 0으로 설정합니다.

## OpenBook 연결

<Note>
  **제거됨.** OpenBook / Serum 의존성이 프로그램에서 삭제되었습니다(2026-07 업그레이드). 이 섹션에서 설명하는 계정들은 더 이상 검증되거나 사용되지 않습니다. 이들은 `AmmInfo`의 참조 필드로, 그리고 레거시 v1 명령어 레이아웃의 위치 플레이스홀더로 남아 있습니다. **V2 스왑 진입점**을 사용하세요([`SwapBaseInV2` / `SwapBaseOutV2`](/ko/products/amm-v4/instructions)). 이들은 이 계정들을 전혀 사용하지 않습니다.
</Note>

레거시 **v1** `SwapBaseIn` / `SwapBaseOut`, `Deposit`, 또는 `Withdraw` 명령어를 호출할 때, 계정 **개수**는 여전히 이전 레이아웃과 일치해야 하지만(마켓 계정들이 역사적 위치를 차지), 그들의 **내용은 더 이상 확인되지 않습니다** — CPI가 이들에 대해 발행되지 않습니다. 새 코드는 이 계정들을 전혀 사용하지 않는 V2 스왑 변형을 사용해야 합니다.

```ts
const market = ...;  // OpenBook 마켓 PublicKey

// OpenBook이 마켓 계정에 노출하는 필드:
const marketDecoded = OpenBookMarket.decode(marketAccountData);
const {
  bids:           serumBids,
  asks:           serumAsks,
  eventQueue:     serumEventQueue,
  requestQueue:   serumRequestQueue,
  baseVault:      serumCoinVault,
  quoteVault:     serumPcVault,
  vaultSignerNonce,
} = marketDecoded;

const serumVaultSigner = PublicKey.createProgramAddressSync(
  [market.toBuffer(), u64ToBytes(vaultSignerNonce)],
  OPENBOOK_PROGRAM_ID,
);
```

AMM의 `amm_open_orders`는 OpenBook 소유 계정으로 이 마켓의 풀 한도 주문 상태를 보유합니다: 활성 주문, 정산된 잔액, 추천인 등. `amm_target_orders`는 AMM 측입니다: 프로그램이 현재 게시된 것과 저렴하게 비교하고 차이를 배치/취소할 수 있도록 AMM의 *의도된* 그리드(각 주문 슬롯의 가격/크기)를 보유합니다.

## 권한 PDA

전체 AMM v4 프로그램에 정확히 하나의 `amm_authority` PDA가 있습니다. 그 시드는 간단합니다(`["amm authority"]`), 그 범프는 모든 `AmmInfo`에 저장됩니다. 이 권한은 모든 AMM v4 풀의 모든 토큰 이동에 서명합니다.

```ts
const AMM_V4_PROGRAM_ID = new PublicKey(
  "675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8",
);
const [ammAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("amm authority")],
  AMM_V4_PROGRAM_ID,
);
```

두 번째의 풀 범위 권한은 없습니다: 이 하나의 PDA가 프로그램이 서명하는 모든 것을 담당합니다. 메인넷에서 그 범프는 `254`이며 모든 `AmmInfo`에 `nonce`로 미러링됩니다. `WithdrawExcessLamports`는 그 nonce를 하드코딩하여 이를 다시 파생합니다.

## 볼트

풀의 SPL Token 볼트는 `owner`가 `amm_authority`인 표준 토큰 계정입니다. ATA가 아닙니다 — 그들의 주소는 `Initialize2`에서 `[AMM_V4_PROGRAM_ID, market, "coin_vault_associated_seed"]` 및 `[AMM_V4_PROGRAM_ID, market, "pc_vault_associated_seed"]`로부터 파생된 PDA입니다. 민트는 시드가 아니며 `amm_id`도 시드가 아닙니다. 주소는 `AmmInfo`에 저장됩니다; 파생은 일회성 호기심입니다.

Token-2022는 **지원되지 않습니다**. 프로그램은 모든 볼트 이동에 대해 SPL Token의 프로그램 ID를 하드코딩합니다. AMM v4 풀을 Token-2022 민트에 바인딩하려고 시도하면 `Initialize2`에서 `InvalidSplTokenProgram`으로 실패합니다.

## LP 민트

권한이 `amm_authority`인 클래식 SPL Token 민트입니다. 총 공급량은 풀의 LP 소유권을 추적합니다; LP를 소각하면 두 볼트에서 비례적으로 토큰을 반환합니다.

상태 내 미러는 **존재합니다**: `AmmInfo.lp_amount`. 이는 민트의 공급량과 같지 않습니다 — 정확히 온전한 LP 토큰 한 개(`10^coin_decimals` 기본 단위)만큼 더 큽니다. 그 양은 초기화 시 계산되지만 실제로 발행되지는 않기 때문입니다. 프로그램의 모든 비례 계산은 `lp_amount`로 나누므로, 민트의 온체인 공급량 대신 이 필드를 사용하세요.

## 상태

`AmmInfo.status`는 단일 열거형 `u64` 상태이며 비트마스크가 **아닙니다**. 동등성으로 검사하세요 — `status & 1`을 검사하는 클라이언트는 모든 라이브 풀을 잘못 분류합니다. 정상 거래 상태가 비트 0이 설정된 `6`이기 때문입니다.

| 값 | `AmmStatus` | 스왑 | 예치 | 출금 |
|-------|-------------|------|---------|----------|
| 0 | `Uninitialized` | 불가 | 불가 | 불가 |
| 1 | `Initialized` | 가능 | 가능 | 가능 |
| 2 | `Disabled` | 불가 | 불가 | 불가 |
| 3 | `WithdrawOnly` | 불가 | 불가 | 가능 |
| 4 | `LiquidityOnly` | 불가 | 가능 | 가능 |
| 5 | `OrderBookOnly` | 불가 | 가능 | 가능 |
| 6 | `SwapOnly` | 가능 | 가능 | 가능 |
| 7 | `WaitingTrade` | `pool_open_time`이 지나면 가능 | 가능 | 가능 |

`Initialize2`는 `open_time`이 미래이면 `7`을, 그렇지 않으면 `6`을 기록합니다. `7` 상태의 풀은 `state_data.pool_open_time` 시점 이후의 첫 스왑에서 스스로 `6`으로 전환됩니다. `0..=7` 범위를 벗어난 값은 `AmmStatus::from_u64`를 패닉시킵니다.

Raydium 멀티시그는 `param = 0`(`Status`)과 함께 `SetParams`를 통해 상태를 설정하며 `1`–`7` 값만 허용됩니다. (`AdminCancelOrders`는 제거되었습니다.)

## 관찰 / 오라클

**AMM v4는 전용 관찰 계정이 없으며**, OpenBook 제거 이후로는 그것을 파생할 오더북 상태도 없습니다. 프로그램 지원이 있는 Raydium TWAP가 필요하면 CPMM 또는 CLMM을 사용하세요 — 둘 다 `ObservationState` 링 버퍼를 유지합니다. 그렇지 않으면 스왑 로그를 오프체인에서 인덱싱하세요.

## 처음부터 풀의 계정 파생

AMM v4의 풀 계정은 바인딩된 마켓을 키로 하는 일반 PDA입니다 — 시드 키쌍도 아니고 쌍별 PDA도 아닙니다. 그 모두가 `AMM_V4_PROGRAM_ID` 아래에서 동일한 3개 시드 형태 `[AMM_V4_PROGRAM_ID, market, <label>]`를 사용합니다:

| Account | `<label>` |
|---------|-----------|

```ts
const [ammId] = PublicKey.findProgramAddressSync(
  [
    AMM_V4_PROGRAM_ID.toBuffer(),
    marketPubkey.toBuffer(),
    Buffer.from("amm_associated_seed"),
  ],
  AMM_V4_PROGRAM_ID,

```

바인딩된 마켓이 유일한 가변 시드이며, 그래서 하나의 마켓이 정확히 하나의 AMM v4 풀에 매핑됩니다. SDK와 API는 이를 미리 계산합니다; `raydium-sdk-v2`의 `Liquidity.getAssociatedPoolKeys`를 참조하세요.

실제로, 통합자는 `GET https://api-v3.raydium.io/pools/info/ids?ids=<POOL_ID>`에서 또는 SDK에서 풀의 전체 계정 세트를 읽습니다. 손으로 파생하는 것은 거의 필요하지 않습니다.
