<Info>
  Raydium **不接受**任意的 Token-2022 铸币。CPMM 和 CLMM 都运行严格的**允许列表模式**：默认只有一小组扩展通过；其他所有扩展在池创建时被拒绝。每个程序通过一种机制接纳单个铸币——管理员管理的按铸币注册表 PDA。两个程序之前在各个位置都有硬编码的绕过机制；现在全部已删除。本页是关于强制执行内容和位置的单页参考，包含程序源代码的引用。
</Info>

## 程序级支持

| 程序 | Token-2022 基础/报价铸币？ | 模式 |
|---|---|---|
| **CPMM** | 是——受限 | 严格扩展允许列表 + 管理员按铸币注册表。其 4 个铸币静态白名单在 2026-09 升级中被移除。 |
| **CLMM** | 是——受限 | 严格扩展允许列表 + 管理员按铸币注册表。其 6 个铸币静态白名单和 Superstate 检测都在 2026 年 7 月被移除。 |
| **AMM v4** | 否 | 程序早于 Token-2022；两个铸币都必须是经典 SPL Token。 |
| **Stable AMM** | 否 | 与 AMM v4 相同的约束。 |
| **Farm v6** | 是，部分 | 奖励铸币可以是 Token-2022（受相同的允许列表约束，当农场包装 CPMM/CLMM LP 时）；用户质押 LP 铸币继承自包装的池。 |
| **LaunchLab** | 是——基础程序管理，报价不受限 | 基础铸币可以是 Token-2022，但仅通过专用的 `initialize_with_token_2022` 指令；程序本身使用 `MetadataPointer`（总是）和可选的 `TransferFeeConfig`（费率 ≤ 5%）创建铸币。具有任意扩展的预先存在的 Token-2022 铸币不能用作基础。**报价**铸币可以是管理员绑定到 `GlobalConfig` 的任何 Token-2022 铸币，无扩展检查——见[下文](#launchlab-报价铸币)。 |
| **Burn & Earn** | 镜像池程序 | 继承 CPMM / CLMM 限制。 |

允许列表检查位于：

- **CPMM**: [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs) 中的 `is_supported_mint`，从 `Initialize` 和 `InitializeWithPermission` 调用。
- **CLMM**: [`raydium-clmm/programs/amm/src/util/token.rs`](https://github.com/raydium-io/raydium-clmm/blob/master/programs/amm/src/util/token.rs) 中的 `is_supported_mint`，从 `CreatePool` 调用。
- **LaunchLab**: `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs` 中的 `initialize_with_token_2022`（源代码不公开）。

CPMM 或 CLMM 上**没有**交换时铸币检查——限制仅在池创建时触发。一旦池存在，交换只是信任铸币没有改变，这对 Token-2022 铸币状态的不可变部分是正确的。

## CLMM 头寸 NFT 冻结（受限发行者）

头寸 NFT 账户默认保持解冻。CLMM 仅在头寸使用 V2 开放路径**且**至少一个金库铸币的当前 `freeze_authority` 出现在硬编码的 `frozen_position_nft_authorities::IDS` 列表中时才冻结一个。该列表是替代 CLMM 早期 Superstate 令牌检测的内容，它携带旧启发式匹配的相同发行者权限。将池 PDA 设置为头寸 NFT 铸币的冻结权限本身不是冻结。这是头寸托管规则，不是池创建允许列表：

- 池可以已存在并保持可交换。
- 头寸 NFT 铸币使用 CLMM 池 PDA 作为其自己的冻结权限；底层发行者不控制头寸 NFT。
- `OpenPositionV2` 覆盖 Token-2022 池资产上的经典 SPL 头寸 NFT。`OpenPositionWithToken22Nft` 覆盖 Token-2022 头寸 NFT。
- `OpenPosition` V1 不检查金库铸币，无法服务由发货列表针对的 Token-2022 受限资产。
- 现有头寸保持不变。

冻结的头寸仍可由其所有者管理，但无法转移。`ClosePosition` 在客户端将池作为第一个剩余账户传递时原子地解冻和销毁。见[`products/clmm/ticks-and-positions`](/zh/products/clmm/ticks-and-positions#受限发行者头寸)。

## LaunchLab 报价铸币

LaunchLab 的两个铸币受限方式非常不同，不对称性很容易被忽视。

- **基础铸币**——LaunchLab 创建它。Token-2022 基础铸币仅通过 `initialize_with_token_2022` 可达，程序将仅附加 `MetadataPointer` 和（可选）`TransferFeeConfig`。任何其他内容返回 `NoSupportExtension`。预先存在的 Token-2022 铸币根本无法作为基础提供。当附加 `TransferFeeConfig` 时，铸币的 `transfer_fee_config_authority` 是启动权限 PDA 直到毕业，而其 `withdraw_withheld_authority` 是平台配置的 `transfer_fee_extension_auth`（从铸币创建开始）——launchpad 程序本身没有提取扣留指令。见[`products/launchlab/platform-config`](/zh/products/launchlab/platform-config#token-2022-转账费权限)。
- **报价铸币**——LaunchLab 不创建它也不筛选它。`CreateConfig` 接受给定的铸币账户，所以**报价端没有 `is_supported_mint` 等价物**。唯一的限制是管理员选择绑定到 `GlobalConfig` 的铸币。

这使得绑定 Token-2022 报价铸币成为高信任操作，原因与下面注册铸币相同：`TransferHook` 报价铸币会在每次买入、卖出和费用索赔时在每个以其报价的池中运行其钩子，`PermanentDelegate` 报价铸币会让委托人扫空这些池的报价金库。两者都不被程序阻止。

LaunchLab 一旦绑定报价铸币就正确处理的内容：

- 报价金库、两个费用金库和分享费接收者的令牌账户都在报价铸币自己的程序上创建。
- 报价端的 `TransferFeeConfig` 被计入所有四个交易指令，滑点界限针对支付者的净额而不是金库的总移动进行检查。见[`products/launchlab/instructions`](/zh/products/launchlab/instructions#报价端转账费)。
- `PoolState.token_program_flag` 记录两个铸币的程序——bit0 用于基础铸币，bit1 用于报价铸币。按位解码；字节不是布尔值。见[`products/launchlab/accounts`](/zh/products/launchlab/accounts#poolstate)。

已弃用的 `Initialize` 指令仍然采用仅限遗留的报价程序，所以具有 Token-2022 报价铸币的配置仅通过 `InitializeV2` 和 `InitializeWithToken2022` 可达。

## CPMM 和 CLMM 扩展允许列表

在下面涵盖的两个短路之后，程序迭代铸币的扩展，如果它携带**任何**不在这五个中的扩展，则拒绝铸币：

| 扩展 | 允许的原因 |
|---|---|
| `TransferFeeConfig` | 池数学减去入站费；Token-2022 程序处理出站费。见[`algorithms/token-2022-transfer-fees`](/zh/algorithms/token-2022-transfer-fees)。 |
| `MetadataPointer` | 装饰性——指向链上元数据。 |
| `TokenMetadata` | 装饰性——内联元数据。 |
| `InterestBearingConfig` | 池看到本金；UI 乘数仅是装饰，底层余额被保留。 |
| `ScaledUiAmount` | 与利息承载相同的形状——缩放因子仅适用于 UI 显示。 |

不在此列表中的任何内容——`TransferHook`、`NonTransferable`、`ConfidentialTransferMint`、`PermanentDelegate`、`MintCloseAuthority`、`DefaultAccountState`、`GroupPointer`、`GroupMemberPointer`、`MemberPointer`、`Pausable` 等——导致 `is_supported_mint` 返回 `false` 并且池创建恢复。

相关行（CPMM，CLMM 中形状相同）：

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

——[`cp-swap/src/utils/token.rs`](https://github.com/raydium-io/raydium-cp-swap/blob/master/programs/cp-swap/src/utils/token.rs)

## 绕过路径

不符合允许列表的 Token-2022 铸币仍然可以被接纳，通过每个程序中的一种机制。两个程序过去也携带硬编码的绕过机制；其中没有一个存活。

| 绕过 | CPMM | CLMM |
|---|---|---|
| 按铸币注册表 PDA | 是——唯一的绕过 | 是——唯一的绕过 |
| 静态 `MINT_WHITELIST` | 2026-09 移除（4 个地址） | 2026-07 移除（6 个地址） |
| Superstate 权限形状检测 | 从未有过 | 2026-07 移除 |

`is_supported_mint` 现在在两个程序中是逐字节相同的函数：遗留 SPL Token 铸币通过，具有注册表 PDA 的铸币通过，其他所有内容必须仅携带允许列表中的扩展。

## 唯一的绕过：按铸币注册表

两个程序都查询种子为 `[b"support_mint", mint]` 的 `SupportMintAssociated` PDA。如果该 PDA 对铸币存在，则无论其扩展集如何，铸币都被接纳。

每个程序都有自己的 PDA 副本（它们在不同的程序 ID 下派生）、自己的 `CreateSupportMintAssociated` / `CloseSupportMintAssociated` 对，以及自己的专用权限与共享管理员：

这四个密钥（CPMM 和 CLMM × 主网和开发网）列在[支持代币注册表权限](/zh/reference/program-addresses#support-mint-registry-authorities)下。

在两个程序中，指令接受 `crate::admin::ID` 或该程序的专用权限，并要求铸币由 Token-2022 拥有。效果：特定的 Token-2022 铸币可以选择加入池创建，无需程序升级——这就是为什么硬编码列表可以消失。

每个程序从它拥有的**每个**池创建路径查询注册表：CPMM 从 `Initialize` 和 `InitializeWithPermission`（后者是 LaunchLab 毕业使用的，所以注册的铸币也毕业和创建），CLMM 从 `CreatePool`、`CreateCustomizablePool` 和 `CreatePermissionedPool`。

## 移除的绕过

两个硬编码机制都已从部署的程序中删除。它们在这里仅被记录，因为针对较旧行为编写的集成可能仍然假设它们。

### 静态 `MINT_WHITELIST`——已移除

一个基础 58 铸币地址常量数组曾经在扩展迭代之前短路 `is_supported_mint`。CLMM 的包含六个地址，在 2026-07-24 删除；CPMM 的包含相同集合的前四个，在 [2026-09-09 升级](/zh/reference/changelog/2026-09-09-cpmm-anchor-1-and-excess-lamports)中删除。

| 曾在其中列入白名单 | 铸币 |
|---|---|
| CPMM 和 CLMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`, `Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`, `FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`, `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| 仅 CLMM | `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`, `AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

**已为这些铸币之一存在的池继续交易**——铸币检查仅在池创建时运行。现在为其中一个创建**新**池需要为其注册 PDA。

### Superstate 权限形状检测——已移除

CLMM 曾短暂通过权限形状而不是地址识别 Superstate 的令牌化资产：Token-2022 铸币，其 `freeze_authority` **和** 永久委托都等于 `superstate_allowlist::ID`，`DefaultAccountState` 设置为 `Frozen`，被接纳。这是一个启发式，所以任何具有相同形状的未来铸币都会被自动接纳。

它在 2026-07-31 与 `superstate_allowlist` 模块一起删除。替代它的更窄，服务于不同的目的：`frozen_position_nft_authorities::IDS`，它不接纳任何东西——它决定**头寸 NFT** 是否被冻结，并在[上面](#clmm-头寸-nft-冻结受限发行者)描述。旧启发式匹配的一个发行者权限是该列表中的一个条目。

## 绕过不豁免的内容

绕过跳过扩展允许列表，但程序仍然强制：

- 铸币由 `Token` 或 `Token-2022` 拥有。自定义令牌程序被上游拒绝。
- 池金库使用 Token-2022 池的正确 ATA 扩展创建（`ImmutableOwner` 等）。
- 所有转账都通过 `transfer_checked`——费用承载铸币在金库中着陆正确的金额。

稍后添加 `TransferHook` 的白名单或 PDA 注册铸币不会获得交换时检查；钩子会简单地在每次转账时运行，可能会破坏交换。因此，注册铸币是高信任操作。

## "被阻止"语义

当 `is_supported_mint` 返回 `false` 时，池创建以 `ErrorCode::NotSupportMint`（CPMM）/ `ErrorCode::NotSupportMint`（CLMM）恢复。见[`reference/error-codes`](/zh/reference/error-codes)了解数字代码。

现有池无法追溯地失败此检查——限制仅在创建时运行。铸币扩展对于 Raydium 拒绝的类别是不可变的（转账钩子、不可转移、机密转账无法在创建后添加），所以静态检查是充分的。

## 为什么每个被排除的扩展被排除

- **TransferHook**——在每次转账时调用自定义程序，具有任意 CU 消耗、任意失败条件，以及重新进入调用程序的能力。不存在安全沙箱。一些 DEX 维护钩子允许列表；Raydium 不。
- **NonTransferable**——`Transfer` 总是失败。池无法获得托管。
- **ConfidentialTransfer**——转账金额被加密；曲线无法为交换定价。
- **PermanentDelegate**——委托的持有者可以扫空任何令牌账户，包括池金库。仅通过注册铸币可接纳，这是受信任的发行者（例如受监管的稳定币）逐案例上线的方式。
- **MintCloseAuthority**——铸币可以关闭；现有池变得不可用。默认不允许。
- **DefaultAccountState (Frozen)**——池 ATA 会着陆在 `Frozen` 状态，需要按账户解冻。仅通过注册铸币可接纳，这假设发行者在注册时解冻机构账户。
- **Group/Member 指针**——不是主动有害，但未审查。默认不允许以保持表面狭窄。

## 转账费会计

对于携带 `TransferFeeConfig` 的铸币，每次交换、存款和提款移动的金额少于名义金额。涉及两个单独的数字，SDK 将它们分开：

- **池费**（LP + 协议 + 基金 + 创建者）来自曲线。`raydium.cpmm.computeSwapAmount({ ... })` 将其作为 `fee` 返回，以及 `amountIn`、`amountOut`、`minAmountOut`、`executionPrice`、`priceImpact` 和原始 `swapResult`。
- **Token-2022 转账费**来自铸币，不是池。它由 `@raydium-io/raydium-sdk-v2` 中的 `getTransferAmountFee` 助手计算，返回 `GetTransferAmountFee`：

```ts
export interface GetTransferAmountFee {
  amount: BN;                  // 实际移动的金额
  fee: BN | undefined;         // 由铸币扣留；当铸币没有 TransferFeeConfig 时未定义
  expirationTime: number | undefined;  // 在计划费用变更待处理时设置
}
```

存款和提款直接显示它：`computePairAmount` 返回 `inputAmountFee` 和 `anotherAmount` 作为 `GetTransferAmountFee` 值。

正确的 UI 显示：

- 输入金额**加上**其转账 `fee` 作为"你发送"
- 输出金额**减去**其转账 `fee` 作为"你接收"
- 池 `fee` 作为单独的行——它不是 Token-2022 费

显示仅 `amountIn → amountOut` 的幼稚 UI 低估了成本。将集群中的 `epochInfo` 传递到这些助手中，而不是缓存它；epoch 是选择铸币 `older` 和 `newer` 费用配置之间的内容。

### `maximumFee` 上限

Token-2022 转账费按转账上限。对于具有 10,000 令牌上限的 1% 铸币，100,000,000 令牌转账仅支付 10,000 费用。SDK 的 `computeSwapAmount` 应用上限；直接程序调用者必须复制它。

### Epoch 转换

铸币权限可以安排在下一个 epoch 激活的费率变更。在转换窗口期间，两个配置（`older`、`newer`）同时存在于铸币上，`TransferChecked` 按当前 epoch 选择。CPMM `SwapV2` 和 CLMM `SwapV2` 都在 `accounts` 中传递完整的铸币账户，所以程序读取正确的配置而无需额外查找。

如果你通过 Trade API 或 SDK 提前引用多个 epoch，执行费可能与引用费不同——由较旧配置的 `maximum_fee_basis_points` 限制。

## 利息承载和 ScaledUiAmount

池持有本金；"UI 金额"是本金乘以时间相关或管理员设置的缩放因子。交换数学在本金上运行：

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK 自动转换。直接 RPC 读者应将 `pool.token0Vault.amount` 视为本金。

## "Token-2022 池"定义

如果**任一**铸币具有 `programId == TokenzQdB...`，则池是 Token-2022 池。API 显示这个：

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

使用 `programId` 分派，使用 `hasTransferFee` 显示 UI 警告。

## SDK 助手

```ts
import { Raydium } from "@raydium-io/raydium-sdk-v2";
// TOKEN_2022_PROGRAM_ID is not re-exported by the Raydium SDK — import it from
// @solana/spl-token, as the SDK itself does.
import {
  TOKEN_2022_PROGRAM_ID,
  ExtensionType,
  getExtensionTypes,
  unpackMint,
} from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## 常见集成错误

- **仅预检程序 ID。** 铸币可以是 Token-2022 *且*不受支持。在允许池创建之前，针对允许列表遍历扩展列表，并检查铸币的注册表 PDA。
- **当铸币根本不被接受时信任 SDK 的报价。** 报价 API 不拒绝报价——池创建是恢复的。在在 UI 中公开池创建之前，离线确认 `is_supported_mint` 语义。
- **报价时不考虑转账费削减。** 具有 0.25% CPMM 池两侧 1% 转账费的铸币的有效费约为 2.25%，而不是 0.25%。使用 SDK 报价或 Trade API 报价——永远不要仅从池的费用等级手动计算费。
- **在 Token-2022 池上调用遗留 `Swap` 指令。** `Swap` 早于 Token-2022。每当任一铸币是 Token-2022 时使用 `SwapV2`。
- **自动列出新的 Token-2022 铸币。** 钱包和聚合器应在向用户显示铸币之前检查 `TransferHook` 和 `NonTransferable`；两者都对 Raydium 不利。
