<Info>
  Raydium **不接受**任意的 Token-2022 mint。CPMM 和 CLMM 都运行严格的**允许列表模式**：默认只有一小部分扩展通过；其他所有扩展在池创建时被拒绝。少数受信任的 mint 通过硬编码地址被允许；CLMM 还支持管理员管理的按 mint 注册表和运行时 Superstate 代币检测。本页是关于执行内容和位置的单页参考，包含程序源代码的文件和行号引用。

## 程序级支持

| 程序 | Token-2022 基础/报价 mint？ | 模式 |
|---|---|---|
| **CPMM** | 是 — 受限 | 严格扩展允许列表 + 4 个 mint 静态白名单。 |
| **CLMM** | 是 — 受限 | 严格扩展允许列表 + 6 个 mint 静态白名单 + 管理员按 mint 注册表 + Superstate 检测。 |
| **AMM v4** | 否 | 程序早于 Token-2022；两个 mint 都必须是经典 SPL Token。 |
| **Stable AMM** | 否 | 与 AMM v4 相同的约束。 |
| **Farm v6** | 是，部分 | 奖励 mint 可以是 Token-2022（受相同的允许列表约束，当农场包装 CPMM/CLMM LP 时）；用户质押 LP mint 继承自包装的池。 |
| **LaunchLab** | 是 — 基础程序管理，报价不受限 | 基础 mint 可以是 Token-2022，但仅通过专用的 `initialize_with_token_2022` 指令；程序本身使用 `MetadataPointer`（始终）和可选的 `TransferFeeConfig`（费率 ≤ 5%）创建 mint。具有任意扩展的预先存在的 Token-2022 mint 不能用作基础。**报价** mint 可以是管理员绑定到 `GlobalConfig` 的任何 Token-2022 mint，无扩展检查 — 见[下文](#launchlab-报价-mint)。 |
| **Burn & Earn** | 镜像池程序 | 继承 CPMM / CLMM 限制。 |

允许列表检查位于：

- **CPMM**：`is_supported_mint` 在 [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap)，从 `Initialize` 调用。
- **CLMM**：`is_supported_mint` 在 [`raydium-clmm/programs/amm/src/util/token.rs:280`](https://github.com/raydium-io/raydium-clmm)，从 `CreatePool` 调用。
- **LaunchLab**：`initialize_with_token_2022` 在 `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs`（源代码不公开）。

CPMM 或 CLMM 上**没有**交换时 mint 检查 — 限制仅在池创建时触发。一旦池存在，交换只是信任 mint 没有改变，这对 Token-2022 mint 状态的不可变部分是正确的。

## CLMM 头寸 NFT 冻结受限发行人

头寸 NFT 账户默认保持解冻。CLMM 仅在头寸使用 V2 开放路径**且**至少一个金库 mint 的当前 `freeze_authority` 与硬编码的受限发行人列表匹配时才冻结一个。初始列表包含 Superstate 检测路径下使用的相同权限。将池 PDA 设置为头寸 NFT mint 的冻结权限本身不是冻结。这是头寸托管规则，而不是另一个池创建允许列表：

- 池可以已存在并保持可交换。
- 头寸 NFT mint 使用 CLMM 池 PDA 作为其自己的冻结权限；底层发行人不控制头寸 NFT。
- `OpenPositionV2` 涵盖经典 SPL 头寸 NFT 超过 Token-2022 池资产。`OpenPositionWithToken22Nft` 涵盖 Token-2022 头寸 NFT。
- `OpenPosition` V1 不检查金库 mint，无法服务由发货列表针对的 Token-2022 受限资产。
- 现有头寸保持不变。

冻结的头寸仍可由其所有者管理，但无法转移。`ClosePosition` 在客户端将池作为第一个剩余账户传递时原子地解冻和销毁。见 [`products/clmm/ticks-and-positions`](/zh/products/clmm/ticks-and-positions#受限发行人头寸)。

## LaunchLab 报价 mint

LaunchLab 的两个 mint 受限方式非常不同，不对称性很容易被忽视。

- **基础 mint** — LaunchLab 创建它。Token-2022 基础 mint 仅通过 `initialize_with_token_2022` 可达，程序将仅附加 `MetadataPointer` 和（可选）`TransferFeeConfig`。任何其他内容返回 `NoSupportExtension`。预先存在的 Token-2022 mint 根本无法作为基础提供。
- **报价 mint** — LaunchLab 不创建它也不筛选它。`CreateConfig` 接受给定的 mint 账户，所以**报价端没有等效的 `is_supported_mint`**。唯一的限制是管理员选择绑定到 `GlobalConfig` 的 mint。

这使得绑定 Token-2022 报价 mint 成为高信任操作，理由与下面的 CPMM 和 CLMM 静态白名单相同：`TransferHook` 报价 mint 会在每个池中的每次买入、卖出和费用声明上运行其钩子，`PermanentDelegate` 报价 mint 会让委托人扫除这些池的报价金库。两者都不被程序阻止。

LaunchLab 一旦绑定报价 mint 正确处理的内容：

- 报价金库、两个费用金库和份额费用接收者的代币账户都在报价 mint 自己的程序上创建。
- 报价端的 `TransferFeeConfig` 被计入所有四个交易指令，滑点界限针对支付者的净额而不是金库的总移动进行检查。见 [`products/launchlab/instructions`](/zh/products/launchlab/instructions#报价端转账费用)。
- `PoolState.token_program_flag` 记录两个 mint 的程序 — 基础 mint 的 bit0，报价 mint 的 bit1。按位解码；字节不是布尔值。见 [`products/launchlab/accounts`](/zh/products/launchlab/accounts#poolstate)。

已弃用的 `Initialize` 指令仍然采用仅限遗留的报价程序，所以具有 Token-2022 报价 mint 的配置仅通过 `InitializeV2` 和 `InitializeWithToken2022` 可达。

## CPMM 和 CLMM 扩展允许列表

在静态白名单短路之后（下面涵盖），程序迭代 mint 的扩展，如果它携带**任何**不在这五个之外的扩展，则拒绝 mint：

| 扩展 | 允许的原因 |
|---|---|
| `TransferFeeConfig` | 池数学减去入站费用；Token-2022 程序处理出站费用。见 [`algorithms/token-2022-transfer-fees`](/zh/algorithms/token-2022-transfer-fees)。 |
| `MetadataPointer` | 装饰性 — 指向链上元数据。 |
| `TokenMetadata` | 装饰性 — 内联元数据。 |
| `InterestBearingConfig` | 池看到本金；UI 乘数仅是装饰，底层余额被保留。 |
| `ScaledUiAmount` | 与利息承载相同的形状 — 缩放因子仅适用于 UI 显示。 |

不在此列表中的任何内容 — `TransferHook`、`NonTransferable`、`ConfidentialTransferMint`、`PermanentDelegate`、`MintCloseAuthority`、`DefaultAccountState`、`GroupPointer`、`GroupMemberPointer`、`MemberPointer`、`Pausable` 等 — 导致 `is_supported_mint` 返回 `false` 并且池创建恢复。

相关行（CPMM，CLMM 中形状相同）：

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## 绕过路径

不符合允许列表的 Token-2022 mint 仍然可以通过三个显式绕过之一被允许。它们按顺序尝试，在扩展迭代运行之前。

### 1. 静态 mint 白名单

常量 `MINT_WHITELIST` base58 字符串数组在每个程序中硬编码。如果 mint 的地址匹配，函数立即返回 `true`，不执行扩展检查。

| 程序 | 白名单 mint |
|---|---|
| CPMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`、`Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`、`FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`、`2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM | 相同的四个，加上 `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`、`AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

这些地址被烘焙到程序中；更新列表需要通过 3/4 升级多签进行程序升级。

### 2. 按 mint 注册表 — 仅 CLMM

CLMM 还查询种子为 `[b"support_mint", mint]` 的 `SupportMintAssociated` PDA。如果该 PDA 对 mint 存在，无论其扩展集如何，它都被允许。

PDA 由 `CreateSupportMintAssociated` 创建（[`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)）。指令受限于两个签名者：

- `crate::admin::ID` — 标准 Raydium 管理员权限。
- `crate::create_support_mint_associated_owner::ID` — 为此目的的专用权限：`RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY`（主网），`rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5`（devnet）。

效果：CLMM 团队可以选择特定的 Token-2022 mint 进行池创建，无需程序升级。CPMM 没有等效项 — 其允许列表严格来自源代码。

### 3. Superstate 检测 — 仅 CLMM

CLMM 有第三条路径专门用于 Superstate 的代币化资产，它们使用 `ScaledUiConfig` 扩展，链接到 CLMM 程序的 `spl-token-2022` 版本无法解包。CLMM 不是升级依赖项，而是通过其权限形状检测 Superstate 代币：

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

如果**所有四个**都成立，mint 通过此分支：

- 其拥有程序是 Token-2022 程序。
- 其冻结权限等于 `superstate_allowlist::ID`。见 [`reference/program-addresses`](/zh/reference/program-addresses#clmm-受限发行人冻结权限) 获取主网-beta 和 devnet 值。
- 其 `DefaultAccountState` 扩展设置为 `Frozen`。
- 其永久委托也是 `superstate_allowlist::ID`。

这是启发式，不是注册表 — Superstate 发行的任何具有相同权限形状的未来 mint 将自动被允许。

## 绕过不豁免的内容

绕过跳过扩展允许列表，但程序仍然强制执行：

- mint 由 `Token` 或 `Token-2022` 拥有。自定义代币程序被上游拒绝。
- 池金库使用 Token-2022 池的正确 ATA 扩展创建（`ImmutableOwner` 等）。
- 所有转账都通过 `transfer_checked` — 费用承载 mint 在金库中着陆正确的金额。

白名单或 PDA 注册的 mint 如果稍后添加 `TransferHook` 不会获得交换时检查；钩子将简单地在每次转账上运行，可能会破坏交换。因此白名单是高信任操作。

## "被阻止"语义

当 `is_supported_mint` 返回 `false` 时，池创建恢复为 `ErrorCode::NotSupportMint`（CPMM）/ `ErrorCode::NotSupportMint`（CLMM）。见 [`reference/error-codes`](/zh/reference/error-codes) 获取数字代码。

现有池无法追溯地失败此检查 — 限制仅在创建时运行。Mint 扩展对于 Raydium 拒绝的类别是不可变的（转账钩子、不可转账、机密转账无法在创建后添加），所以静态检查是充分的。

## 为什么每个被排除的扩展被排除

- **TransferHook** — 在每次转账上调用自定义程序，具有任意 CU 消耗、任意失败条件和重新进入调用程序的能力。不存在安全沙箱。一些 DEX 维护钩子允许列表；Raydium 不。
- **NonTransferable** — `Transfer` 总是失败。池无法获得托管。
- **ConfidentialTransfer** — 转账金额被加密；曲线无法为交换定价。
- **PermanentDelegate** — 委托人的持有者可以扫除任何代币账户，包括池金库。仅通过受信任发行人的静态白名单允许（例如，受监管的稳定币）。
- **MintCloseAuthority** — mint 可以关闭；现有池变得不可用。默认不允许。
- **DefaultAccountState (Frozen)** — 池 ATA 会着陆在 `Frozen` 状态并需要按账户解冻。仅通过 Superstate 检测允许，假设发行人在注册时解冻机构账户。
- **Group/Member 指针** — 不是主动有害，但未审查。默认不允许以保持表面狭窄。

## 转账费用会计

对于携带 `TransferFeeConfig` 的 mint，每次交换、存款和提款移动的金额少于名义金额。SDK 显示计算的两个部分：

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

正确的 UI 显示：

- `amountIn + token2022FeeIn` 作为"你发送"
- `amountOut - token2022FeeOut` 作为"你接收"
- `feeAmount` 作为池费用（LP + 协议），与 Token-2022 转账费用分开

仅显示 `amountIn → amountOut` 的幼稚 UI 低估了成本。

### `maximumFee` 上限

Token-2022 转账费用按转账上限。对于 1% mint 和 10,000 代币上限，100,000,000 代币转账仅支付 10,000 费用。SDK 的 `computeSwapAmount` 应用上限；直接程序调用者必须复制它。

### 纪元转换

mint 权限可以安排在下一个纪元激活的费率变化。在转换窗口期间，两个配置（`older`、`newer`）同时存在于 mint 上，`TransferChecked` 按当前纪元选择。CPMM `SwapV2` 和 CLMM `SwapV2` 都在 `accounts` 中传递完整的 mint 账户，所以程序读取正确的配置而无需额外查找。

如果你通过 Trade API 或 SDK 提前超过一个纪元报价，执行费用可能与报价费用不同 — 由较旧配置的 `maximum_fee_basis_points` 限制。

## 利息承载和 ScaledUiAmount

池持有本金；"UI 金额"是本金乘以时间相关或管理员设置的缩放因子。交换数学在本金上运行：

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK 自动转换。直接 RPC 读者应将 `pool.token0Vault.amount` 视为本金。

## "Token-2022 池"定义

如果**任一** mint 有 `programId == TokenzQdB...`，池是 Token-2022 池。API 显示这个：

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }

```

使用 `programId` 分派，使用 `hasTransferFee` 显示 UI 警告。

## SDK 助手

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## 常见集成错误

- **仅预检查程序 ID。** mint 可以是 Token-2022 *且*不受支持。在允许池创建之前，针对允许列表（和静态白名单）遍历扩展列表。
- **当 mint 根本不被接受时信任 SDK 的报价。** 报价 API 不拒绝报价 — 池创建是恢复的。在 UI 中公开池创建之前，离线确认 `is_supported_mint` 语义。
- **报价时不考虑转账费用削减。** 0.25% CPMM 池两侧的 1% 转账费用 mint 的有效费用约为 2.25%，而不是 0.25%。使用 SDK 报价或 Trade API 报价 — 永远不要仅从池的费用等级手动计算费用。
- **在 Token-2022 池上调用遗留 `Swap` 指令。** `Swap` 早于 Token-2022。每当任一 mint 是 Token-2022 时使用 `SwapV2`。
- **自动列出新的 Token-2022 mint。** 钱包和聚合器应在向用户显示 mint 之前检查 `TransferHook` 和 `NonTransferable`；两者都对 Raydium 不利。
