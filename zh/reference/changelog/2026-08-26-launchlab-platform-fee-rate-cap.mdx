本次发布将平台费率上限提高至 500 bps。`PlatformConfig.fee_rate` 在两个地方进行验证——一次是在 `CreatePlatformConfig` 构建账户时，一次是在每个写入该字段的 `UpdatePlatformConfig` 变体中——现在两处都接受最高 `50000`。在程序的 `1/1_000_000` 费率分母中，这相当于每次毕业前买卖交易量的 5%。

在本次发布之前，这两个检查的值不一致：创建允许 100 bps，更新允许 250 bps。现在它们保持相同的值，因此平台创建时的费率与更新时的费率完全相同。

其他内容均未变化。没有账户增长或缩小，没有指令增加或删除账户，也没有错误代码移动。

## 集成者速览

- **平台费率上限在两条路径上都是 500 bps。** `CreatePlatformConfig` 和 `UpdatePlatformConfig` 都接受 `fee_rate` 最高 `50000`。
- **创建路径从 100 bps 提高。** `PlatformParams::check()` 自程序首次发布以来一直是 `<= 10000`。
- **更新路径从 250 bps 提高。** `update_platform_fee_rate` 之前是 `<= 25000`，本身在 2026-01-27 从 100 bps 提高过。
- **创建/更新不匹配问题已解决。** 之前在 250–500 bps 范围内创建的配置无法通过 `UpdatePlatformConfig` 调用，因为 `AllInfo` 在重写其他字段时会重新验证 `fee_rate`。现在两个检查一致，所以该编辑路径在任何允许的费率下都能工作。
- **`creator_fee_rate` 保持不变**，在两条路径上都是 `MAX_CREATOR_FEE_RATE = 5000`（50 bps）。
- **`GlobalConfig.max_share_fee_rate` 保持不变**，仍为 `10_000`（100 bps），从不限制平台费。它限制的是每笔交易的 `share_fee_rate` 推荐参数。本文档的早期版本说法不同；本次发布更正了这一点。
- **现有费率无变化。** 这些常数限制对 `fee_rate` 的写入，而非读取。链上已存在的每个 `PlatformConfig` 保持其当前费率，绑定到它的每次启动保持其当前费用。
- **无需刷新 IDL。** 没有布局、账户、参数或错误代码变化。

## 变更内容

```rust
// states/platform_config.rs — PlatformParams::check()，由 CreatePlatformConfig 运行
- require!(self.fee_rate <= 10000, ErrorCode::InvalidInput);
+ require!(self.fee_rate <= 50000, ErrorCode::InvalidInput);

// instructions/platform/update_platform_config.rs — update_platform_fee_rate
- require!(fee_rate <= 25000, ErrorCode::InvalidPlatformInfo);
+ require!(fee_rate <= 50000, ErrorCode::InvalidPlatformInfo);
```

LaunchLab 中的费率以 `1/1_000_000`（`RATE_DENOMINATOR_VALUE`）为单位，因此：

| 值 | 费率 | 基点 | 出现位置 |
|---|---|---|---|
| `10000` | 1% | 100 bps | 程序首次发布时的两个费率上限。也是当前 `GlobalConfig.max_share_fee_rate`，这是一个不同的、未变化的限制。 |
| `25000` | 2.5% | 250 bps | 2026-01-27 至本次发布之间的更新上限。已不再使用。 |
| `50000` | 5% | 500 bps | 本次发布后的两个上限。 |

## 两个检查的位置

上限由两个文件中的两个独立 `require!` 调用强制执行。它们现在保持相同的值，但仍然抛出不同的错误，因此错误处理需要识别两者：

| 路径 | 函数 | 违反时的错误 |
|---|---|---|
| `CreatePlatformConfig` | `PlatformParams::check()` | `InvalidInput`（`6002`） |
| `UpdatePlatformConfig::FeeRate` | `update_platform_fee_rate` | `InvalidPlatformInfo`（`6014`） |
| `UpdatePlatformConfig::AllInfo` | `update_platform_fee_rate` | `InvalidPlatformInfo`（`6014`） |

`AllInfo` 是批量更新变体：它在一次调用中重写钱包、品牌字符串、归属规模、NFT 分割、转账费权限、创建者费率和 `fee_rate`，对 `fee_rate` 运行与单字段变体相同的检查。在旧常数下，这使得 `AllInfo` 对在 250–500 bps 范围内创建的平台无法使用，即使编辑只涉及图像 URL。对齐两个常数消除了这个陷阱。

## 未变化的内容

- **费用计算和分配。** `platform_fee = amount_in × platform_config.fee_rate / 1_000_000` 是相同的公式，累积到相同的每平台金库，由相同的 `ClaimPlatformFee` 和 `ClaimPlatformFeeFromVault` 指令清扫。
- **现有平台和启动。** 常数限制写入，而非读取。没有存储的费率改变，所以没有实时启动重新定价。
- **`creator_fee_rate`。** 仍在两条路径上限制为 `MAX_CREATOR_FEE_RATE = 5000`（50 bps）。
- **`GlobalConfig.max_share_fee_rate`。** 仍为 `10_000`，仍仅限制四个交换指令上的 `share_fee_rate` 参数。
- **错误代码。** `6000`–`6023` 保持不变；本次发布未添加任何代码。
- **账户布局和 IDL。** 保持不变。

## 文档更正

两个页面将平台费率上限归因于 `GlobalConfig.max_share_fee_rate`。程序从未这样做过——它将 `max_share_fee_rate` 与 `share_fee_rate` 指令参数进行比较，仅在上面列出的两个函数中验证 `PlatformConfig.fee_rate`。本次发布更正了这些句子。推荐费上限本身在 100 bps 处保持不变，因此如果你将旧措辞理解为"平台费上限为 100 bps"，该数字对创建路径是正确的，直到本次发布，尽管原因不对。
