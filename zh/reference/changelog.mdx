## 版本发布

<Update label="2026-09-09" description="LaunchLab：Anchor 1.0、过量 lamports 恢复和过渡门的结束">
  LaunchLab 升级到 Agave `3.1.10` 上的 Anchor `1.0.2`，并停用了其过渡脚手架。已弃用的 `Initialize` 现在无条件地失败并返回 `NotApproved`。`MigrateToAmm` 对迁移钱包是**硬破坏性的**：所有三个参数和九个 OpenBook 账户都已移除，遵循 AMM v4 自身的 OpenBook 移除，程序不再通过 CPI 初始化市场。`get_upgrade_timestamp` 时钟门已删除，因此三个交易 `remaining_accounts` 现在是无条件必需的（`system_program` 槽现已验证），`MigrateToCpswap` 始终采用许可的 CPMM 路径，`InitializeWithToken2022` 移除了其 `amm_fee_on` 限制。新的管理员 `CollectExcessLamports` 返回 SIMD-0437 释放的租金——注意源账户必须按三个金库权限 PDA 中的哪一个拥有它们来分组。三个 `MigrateToCpswap` 地址约束移入指令体，将 `2012` 改为 `2502`。追加 `6031`。账户布局、交易指令或费用行为均未改变。

  [阅读完整条目 →](/zh/reference/changelog/2026-09-09-launchlab-anchor-1-and-excess-lamports)
</Update>

<Update label="2026-09-09" description="CPMM：Anchor 1.0、过量 lamports 恢复和固定费用所有者">
  CPMM 升级到 Agave `3.1.10` 上的 Anchor `1.0.2`，并添加了管理员 `CollectExcessLamports`，用于返回 SIMD-0437 从金库、LP 铸币和 PDA 释放的租金——包括包装的 SOL 金库，通过 `SyncNative` / `UnwrapLamports` 往返，保持包装余额不变。三个行为变化随之而来：`CreateAmmConfig` 现在写入硬编码的 `protocol_fee_owner` 和 `fund_fee_owner` 密钥而不是签名者（现有配置**不会**迁移——读取字段），硬编码的四地址 Token-2022 `MINT_WHITELIST` 已移除，因此 `SupportMintAssociated` 注册表 PDA 是唯一剩余的绕过方式，`ClosePermissionPda` 现在接受专用授权权限。追加 `6015`。用户面向的指令或账户布局均未改变。

  [阅读完整条目 →](/zh/reference/changelog/2026-09-09-cpmm-anchor-1-and-excess-lamports)
</Update>

<Update label="2026-09-09" description="AMM v4：Solana 3.0 依赖和过量 lamports 恢复">
  AMM v4 针对 `solana-program` `3.0.0`、`spl-token` `9.0.0`、`spl-associated-token-account` `8.0.0` 和新的 `solana-system-interface` crate 重新构建，并添加了仅限管理员的 `WithdrawExcessLamports`（标签 `18`），用于返回 SIMD-0437 释放的租金。每个交易者和 LP 面向的指令都保持其账户、参数和数学，发布中没有任何破坏性内容：`CreateConfigAccount` 停止读取其尾部租金 sysvar，但仍接受旧的五账户列表。`AmmError` 获得代码 `60`（从 `0` 而非 `6000` 开始编号）。

  [阅读完整条目 →](/zh/reference/changelog/2026-09-09-amm-v4-solana-3-and-excess-lamports)
</Update>

<Update label="2026-08-31" description="LaunchLab：平台曲线规则替代曲线参数白名单">
  启动参数限制从 `PlatformConfig` 移出到每个配置的 `PlatformCurveRule` 账户。规则最多可容纳 10 个检查组，每个组最多 25 个 `(field, op, value)` 约束，涵盖 19 个启动参数，支持 `Eq` / `Gte` / `Lte` / `Neq`——因此平台最终可以表达值范围、替代层级、毕业估值上限、迁移下限、代币类型门控或在日期上切换的组，这些都是仅支持相等性的白名单无法做到的。`PlatformConfig` 保持其 944 字节大小：`restrict_curve_param`、`curve_rule_manager` 和移除的 vec 的长度前缀都从填充中移出。解码器必须删除尾部的 `Vec<PlatformCurveParam>`，启动构建者必须在标志打开时将规则 PDA 追加到 `remaining_accounts`。移除两个指令，添加四个，添加两个 `UpdatePlatformConfig` 变体，追加 `6024`–`6030`。需要 IDL 刷新。SDK 提供两个纯链下检查，因此创建者永远不必从恢复的交易中学习规则，条目记录了在主网上启用标志前的 devnet 排练。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-31-launchlab-platform-curve-rules)
</Update>

<Update label="2026-08-27" description="LaunchLab：平台在铸币创建时持有提取扣留权限">
  `InitializeWithToken2022` 现在将 `PlatformConfig.transfer_fee_extension_auth` 写入新基础铸币的 `withdraw_withheld_authority` 而不是启动 `authority` PDA，因此平台可以在粘合曲线阶段扫除扣留的转账费用，而不是等待毕业——程序本身没有提取扣留指令。`MigrateToCpswap` 仅当 PDA 仍持有该权限时才重新分配该权限，这使毕业对两代铸币都有效。`transfer_fee_config_authority` 仍仅在毕业时移动，因此在启动中期轮换 `transfer_fee_extension_auth` 会无声地将两个权限留在不同的密钥上。账户布局、指令、参数或错误代码均未改变。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority)
</Update>

<Update label="2026-08-26" description="LaunchLab：平台费率上限提高到 500 bps">
  平台 `fee_rate` 上限在验证它的两条路径上都移至 `50000`（500 bps）。`CreatePlatformConfig` 自程序首次发布以来一直被限制在 `10000`（100 bps）；`UpdatePlatformConfig` 自 2026-01-27 以来被限制在 `25000`（250 bps）。两个检查现在一致，因此以任何允许的费率创建的平台也可以以该费率更新——包括通过 `AllInfo` 批量变体，它在重写每个其他字段时重新验证 `fee_rate`。两条路径仍然引发不同的错误（创建时为 `InvalidInput`，更新时为 `InvalidPlatformInfo`）。账户布局、指令或错误代码均未改变，现有平台或启动均未重新定价。`GlobalConfig.max_share_fee_rate` 保持在 100 bps，仅限制每笔交易的推荐 `share_fee_rate`。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)
</Update>

<Update label="2026-08-24" description="LaunchLab：Token-2022 报价铸币">
  启动现在可以用 Token-2022 铸币报价。`CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、四个交换指令和每个费用声明都在其报价程序槽中接受任一代币程序；已弃用的 `Initialize` 保持仅限旧版。交换滑点界限现在与支付者实际支付或接收的内容进行比较，扣除报价铸币的转账费用。`PoolState.token_program_flag` bit1 变得有意义，因此针对整个字节测试 `0` 的解码器会误读遗留基础铸币为 Token-2022。`MigrateToCpswap` 将其两个代币程序账户重命名为 `token_program` / `token_program_2022`，`6023` 被重用于 `CalculateOverflow`。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab：仅 CPMM 启动和平台配置控制">
  新启动初始化现在需要 CPMM，而遗留的 AMM v4 绑定状态保持可迁移。在此版本之前，`creator_scale` 生成创建者拥有的费用密钥；在升级后执行的 CPMM 迁移改为将 `platform_scale + creator_scale` 合并为一个平台拥有的费用密钥份额。平台也可以用自己的 `PlatformAllowConfig` PDA 限制启动，迁移构建者必须追加两个 CPMM 支持铸币 PDA。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM：受限发行者头寸 NFT 冻结">
  新的 CLMM 头寸 NFT 铸币使用其池作为冻结权限，但其代币账户默认保持解冻。冻结仅在 `OpenPositionV2` 或 `OpenPositionWithToken22Nft` 时发生，当任一底层金库铸币的冻结权限与受限发行者列表匹配时。匹配的头寸无法转移或更改所有者，但仍可管理流动性。其 `ClosePosition` 调用必须追加池，以便 CLMM 可以原子地解冻、销毁和关闭。现有头寸保持不变。

  [阅读完整条目 →](/zh/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

  [阅读完整条目 →](/zh/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)

<Update label="2026-07-30" description="CLMM：许可多池和限价单冻结账户保护">
  两个附加的、向后兼容的 CLMM 程序更新。`CreatePermissionedPool` 将客户端提供的非零 `seed_index` 折叠到池 PDA 种子中，让白名单操作者（持有 `Permission` PDA 的操作者）为每个 `(config, mint0, mint1)` 创建多个池——因此池 ID 不再是对的规范标识。新的管理员指令 `CreatePermissionPda` / `ClosePermissionPda` 管理这些授权，`PoolState` 获得 `seed_index` 字段（从填充中切割，大小不变）。另外，`OpenLimitOrder` 现在接受输出端账户并拒绝其输入或输出代币账户被冻结的订单（`NotApproved`）。

  [阅读完整条目 →](/zh/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>
