### 共享配置 / PDA 约定

多个 Raydium 程序公开**配置账户**，其公钥是稳定的并在公开 API 上列出。优先使用 API 查询而不是硬编码：

```
# CPMM 费用配置（返回 {id, index, tradeFeeRate, ...} 数组）
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM 费用配置
GET https://api-v3.raydium.io/main/clmm-config
```

CPMM 的池创建费接收者是固定账户，不是派生或通过 API 查询的：`create_pool_fee_reveiver::ID` 在 `raydium-cp-swap` 的 `lib.rs` 中，目前是 `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`。CPMM 的 `initialize` 指令通过精确地址验证它，所以它必须已经存在于你测试的任何集群上。

默认 CPMM `AmmConfig` 索引 `0`（标准 0.25% 池）费用参数，供参考：

| 字段 | 值 | 含义 |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 交易量的 0.25% |
| `protocol_fee_rate` | `120000` | 交易费的 12%（不是交易量）路由到协议 |
| `fund_fee_rate` | `40000` | 交易费的 4% 路由到基金多签 |
| `creator_fee_rate` | `500` | 交易量的 0.05% 给池创建者（可选） |

见 [`products/cpmm/fees`](/zh/products/cpmm/fees) 了解分割如何组成，以及 [`reference/fee-comparison`](/zh/reference/fee-comparison) 了解跨产品矩阵。

### PDA 种子

下面的种子是**规范的**，由 SDK 和链上 CPI 都使用。始终计算 PDA；不要硬编码派生地址。

```ts
// CPMM — 所有种子都是静态 ASCII 字符串，除非另有说明。
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` 在哈希前**按公钥字节顺序排序**（token0 < token1）。搞错这一点会为不存在的池产生有效的 PDA。

等效的 CLMM 种子遵循相同的风格；见 [`products/clmm/accounts`](/zh/products/clmm/accounts)。

## 如何在链上验证地址

1. **Solana Explorer。** 将地址粘贴到 [explorer.solana.com](https://explorer.solana.com) 并确认它标记为 `Program` 且具有当前升级权限。Mainnet-beta 应显示由 Raydium 升级权限签署的部署。
2. **CLI。** 使用 `solana program show <PROGRAM_ID> -u mainnet-beta` 检查部署槽、BPF 加载器、升级权限和数据长度。在你的运行手册中记录这些。
3. **IDL 附件。** 使用 `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` 查询链上 IDL。IDL 的 `address` 字段应该匹配。相同的 IDL 也镜像在 [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl)——在信任链上 IDL 前，将其与仓库进行对比。
4. **配置/管理员权限。** 对于 CPMM/CLMM 配置账户，读取 `owner`/`protocol_owner` 字段并确认它与 [`security/admin-and-multisig`](/zh/security/admin-and-multisig) 中发布的当前 Raydium 多签匹配。

如果上面的四项检查中的任何一项与本页不一致，将本页视为错误，在针对这些地址编写新代码前打开一个问题。
