## 上游依赖

### OpenBook（原 Serum）

- **角色**：中央限价订单簿。AMM v4 池最初是与 OpenBook 混合的——交换可以针对池的 AMM 曲线或匹配的 OpenBook 市场成交——但 **OpenBook 集成已被停用**。AMM v4 池不再在 OpenBook 上发布或维护订单。
- **影响范围**：历史上仅限 AMM v4 池；目前，Raydium 的任何产品都没有活跃的 OpenBook 依赖。
- **风险面**：之前，OpenBook 升级或故障可能影响 AMM v4 行为（2023 年 1 月发生过一次这样的事件）。现在集成已关闭，这种耦合被移除。CPMM 和 CLMM 从未有过 OpenBook 依赖。
- **状态**：OpenBook 继续在 Solana 上运行；Raydium 不依赖它进行任何当前的交换流量。现有 AMM v4 池引用的 OpenBook 市场账户作为不活跃状态保留在链上，以保持向后兼容性。

### Solana 运行时

- **角色**：所有 Raydium 程序的执行基础。
- **影响范围**：无处不在。Solana 的最终性时间（~1 秒）、计算预算限制（每笔交易 1.4M CU）和地址查找表都直接影响 Raydium 的用户体验。
- **状态**：Solana 定期升级；Raydium 跟踪验证者客户端版本（Agave、Firedancer），如果行为改变则进行调整。

### Token 程序（SPL Token 和 Token-2022）

- **角色**：所有 Raydium 池持有的 token 原语。
- **SPL Token**：遗留程序；适用于所有产品。
- **Token-2022**：启用扩展的程序；适用于 CPMM、CLMM、Farm v6，不适用于 AMM v4。
- **风险面**：扩展行为（转账费用、钩子等）可能影响池功能。参见 [`security/oracle-and-token-risks`](/zh/security/oracle-and-token-risks)。

## 下游集成

### Jupiter 和其他聚合器

- **角色**：在许多 Solana DEX（包括 Raydium）之间路由交易。
- **集成方式**：Jupiter 从 Raydium 的 REST API 和直接链上调用读取池状态，然后通过 Raydium SDK（有时直接）组合交换指令。
- **成交量占比**：大约 60% 的 Jupiter 成交量至少触及一次 Raydium 池。
- **集成者路径**：通用聚合器模式记录在 [`integration-guides/aggregator`](/zh/integration-guides/aggregator)。

### 钱包

- **角色**：让用户无需离开钱包即可交换、追踪 LP 头寸和参与农场。
- **集成方式**：
  - 交换：通过 Jupiter 或直接通过 Raydium SDK 路由。
  - 头寸显示：枚举用户的 ATA 和 NFT 持有，与 Raydium 的池列表交叉引用（[`integration-guides/wallet-integration`](/zh/integration-guides/wallet-integration)）。
  - 农场显示：调用 Raydium 的 `/positions/staking` 端点。
- **用户影响**：任何具有应用内交换的钱包可能通过 Raydium 路由，而你不会注意到。

### 借贷协议（Kamino、Marginfi、Drift）

- **角色**：需要预言机价格和清算执行场所的借贷协议。
- **集成方式**：使用 CLMM ObservationState TWAP 作为预言机；通过 Raydium 直接交换以进行清算抵押品转换。
- **风险**：如果借贷协议使用现货 Raydium 价格而不是 TWAP，可能被闪电贷风格的操纵利用（参见 [`security/attack-vectors`](/zh/security/attack-vectors)）。

### MEV 搜索者和套利者

- **角色**：保持 Raydium、Orca、Phoenix 和中心化交易所之间的价格一致。
- **对用户的影响**：大多数时间价格紧凑；对保护不足的交换进行三明治攻击。参见 [`integration-guides/routing-and-mev`](/zh/integration-guides/routing-and-mev)。

### 机器人（做市商、定投执行器、清算者）

- **角色**：提供流动性（在浅池上做 LP）、执行定时交易、平仓头寸。
- **集成路径**：通常使用 [`sdk-api/python-integration`](/zh/sdk-api/python-integration) 或 Rust CPI 包装器的 Python 或 Rust 机器人。

## 聚合成交量中的位置

截至 2026 年 4 月：

- Raydium 处理任何给定日期 Solana 范围内 DEX 成交量的约 35–45%。
- 当 memecoin 活动集中在 LaunchLab + 毕业池时，最高市场份额约 55%。
- 当大型机构流向 Phoenix（如果可用）时，低端约 25%。

这些数字波动；关键是 Raydium 可靠地是成交量排名前两位的场所之一。

## Token-2022 生态

Raydium 是最早原生支持 Token-2022 的主要 DEX 之一。含义：

- 具有转账费用的新 mint（例如，版税、费用到发行者 token）可以做 LP。
- 转账钩子 mint 可以存在（尽管有风险注意事项）。
- 不可转账和永久委托 mint 被阻止。

随着更多项目在 Token-2022 下启动——特别是使用受监管 mint 的"机构"群体——Raydium 的支持将其定位为该类流动性的场所。

## 前瞻性依赖

可能改变 Raydium 生态位置的关注项：

- **Solana 验证者多样化**：如果 Firedancer 实现主导地位，性能特征可能会改变。
- **跨链桥接**：Raydium 一直在研究扩展到其他 L1/L2。目前还没有部署。
- **Jito 的演进**：区块引擎和 DeFi 之间的持续集成可能改变 MEV 动态。
- **链上订单簿（Phoenix）**：持续成熟可能将一些类 AMM 流转向订单簿。
