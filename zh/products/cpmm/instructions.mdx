## 指令概览

| 判别器名称 | 谁签名 | 功能 |
|-------|-----------|--------------|
| `Initialize` | 池创建者 | 从两个 mint 和一个 `AmmConfig` 创建新的 CPMM 池。无需许可；任何人都可以调用。在新池上硬编码 `enable_creator_fee = false`。`pool_state` 账户可以是规范 PDA 或新的随机密钥对（见 Initialize 账户）。 |
| `InitializeWithPermission` | 支付者 + `Permission` PDA 持有者 | `Initialize` 的许可变体。调用者（`payer`）必须拥有从其自身公钥派生的 `Permission` PDA。由需要门控池创建的平台使用（如 LaunchLab 毕业）。让调用者固定 `creator_fee_on`（`BothToken` / `OnlyToken0` / `OnlyToken1`）并在新池上强制 `enable_creator_fee = true`。`pool_state` 上的 `creator` 字段设置为单独传递的 `creator` 账户，而非支付者。与 `Initialize` 相同的规范 PDA 或随机密钥对灵活性用于 `pool_state`。 |
| `Deposit` | LP | 添加两种代币的流动性；接收 LP 代币。 |
| `Withdraw` | LP | 销毁 LP 代币；按比例接收两种基础代币。 |
| `SwapBaseInput` | 交换者 | 精确输入交换（`amount_in` 输入，≥ `minimum_amount_out` 输出）。 |
| `SwapBaseOutput` | 交换者 | 精确输出交换（≤ `maximum_amount_in` 输入，`amount_out` 输出）。 |
| `CollectProtocolFee` | `protocol_owner`（来自 `AmmConfig`） | 从金库扫除累积的协议费用。 |
| `CollectFundFee` | `fund_owner`（来自 `AmmConfig`） | 从金库扫除累积的基金费用。 |
| `CollectCreatorFee` | `pool_creator` | 扫除累积的创建者费用（如果启用了创建者费用）。 |
| `CollectCreatorFeePermissionless` | 任何支付者 | 将所有累积的创建者费用扫除到 `pool_creator` 的规范代币账户。支付者可以创建缺失的接收者 ATA，但不能重定向转账。 |
| `UpdatePoolStatus` | `admin` | 通过位掩码暂停/恢复池上的特定操作。 |
| `UpdateAmmConfig` | `admin` | 更改费率或 `AmmConfig` 上的协议/基金所有者。 |
| `CreateAmmConfig` | `admin` | 创建新的费用等级（新 `AmmConfig` 账户）。 |
| `CreatePermissionPda` | `admin` 或委托的许可 PDA 创建者 | 铸造 `Permission` PDA，允许特定权限调用 `InitializeWithPermission`。 |
| `ClosePermissionPda` | `admin` 或专用许可 PDA 创建者 | 撤销之前颁发的 `Permission` PDA。自 2026-09 升级以来，专用创建者权限也可以关闭其颁发的授权；之前仅限管理员。 |
| `CreateSupportMintAssociated` | `admin` 或专用支持 mint 所有者 | 通过创建其 `SupportMintAssociated` PDA 来注册否则会失败扩展允许列表的 Token-2022 mint。 |
| `CloseSupportMintAssociated` | `admin` 或专用支持 mint 所有者 | 移除 mint 的注册。 |
| `CollectExcessLamports` | `admin` 或专用收集 lamport 钱包 | 从 CPMM 控制的金库、LP mint 和 PDA 扫除超过租金豁免最低值的 lamport。添加于 2026-09。 |

状态位掩码：每个池的 `status` 是一个 `u8`，其中位 0 = 禁用存款，位 1 = 禁用提取，位 2 = 禁用交换（程序中的 `PoolStatusBitIndex { Deposit, Withdraw, Swap }`）。清除位表示允许操作；设置位表示暂停。`UpdatePoolStatus` 接受原始 `u8` 并覆盖现有值。

后续部分详细介绍每一个。账户顺序遵循 CPMM IDL；SDK 和 `raydium-cp-swap/programs/cp-swap/src/instructions` 中的 Rust 客户端匹配此顺序。

## `Initialize`

创建新的 CPMM 池。

**参数**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix 时间戳；此前拒绝交换
```

**账户**（W = 可写，S = 签名者）

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 支付租金；记录为 `pool_state.pool_creator`。 |
| 2 | `amm_config` |   |   | 选定的费用等级。 |
| 3 | `authority` |   |   | CPMM 全局权限 PDA。 |
| 4 | `pool_state` | W | S* | 在此处 `init`。**要么**规范 PDA `["pool", amm_config, token_0_mint, token_1_mint]` **要么**新的随机密钥对——当不是规范 PDA 时，程序要求 `pool_state` 签名（`require_eq!(pool_account_info.is_signer, true)`）。随机密钥对路径让创建者躲避规范 PDA 上的抢先交易尝试。下游 PDA（`lp_mint`、`vaults`、`observation_state`）从 `pool_state.key()` 派生，无论哪种方式。 |
| 5 | `token_0_mint` |   |   | 排序：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | 在此处 `init`。权限设置为 `authority`。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` 的源 ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` 的源 ATA。 |
| 10 | `creator_lp_token` | W |   | LP 的目标（如缺失则创建）。 |
| 11 | `token_0_vault` | W |   | 在此处 `init`。由 `authority` 拥有。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 创建者支付的 `create_pool_fee` 的目标 ATA。 |
| 14 | `observation_state` | W |   | 在此处 `init`。 |
| 15 | `token_program` |   |   | SPL Token（用于 LP mint）。 |
| 16 | `token_0_program` |   |   | SPL Token 或 Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token 或 Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` 仅在随机密钥对路径上签名；规范 PDA 路径运行时不需要 `pool_state` 签名。

**前置条件**

- Mint 已排序（`token_0_mint < token_1_mint` 按字节顺序）。
- 两个 mint 都不使用 CPMM 允许列表外的扩展（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`）——见 [`products/cpmm/accounts`](/zh/products/cpmm/accounts#vaults-and-token-2022)。具有 `SupportMintAssociated` PDA（种子 `[b"support_mint", mint]`）的 mint 跳过检查；自 2026-09 升级移除硬编码四 mint 白名单以来，该注册表是唯一的绕过。
- `creator` 在各自的 ATA 中至少有 `init_amount_0` 和 `init_amount_1`。
- `amm_config.disable_create_pool == false`。

**后置条件**

- `pool_state` 存在，`lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`。
- `LOCKED_LP`（100 个 LP 代币的 lamport）的 LP 启动者永久锁定在池中——`pool_state.lp_supply` 记录 `liquidity − 100`，而 100 个 LP 单位保持在流通外，防止池被完全耗尽和除以零。
- `observation_state` 已初始化；`observation_index = 0` 和 `pool_id = pool_state.key()`。
- `create_pool_fee` lamport 从创建者转账到接收者并同步为原生 SOL（它是 wSOL ATA）。
- 池的状态位掩码为 `0`（存款/提取/交换全部启用）。
- `enable_creator_fee = false` 和 `creator_fee_on = BothToken`。`Initialize` **不**支持启用创建者费用——该路径是 `InitializeWithPermission`。
- 如果调用者传递的值 `<= block_timestamp`，`open_time` 会被提升到 `block_timestamp + 1`。交换在 `open_time` 前被拒绝；存款和提取立即生效。

**常见错误**（完整列表见 [`reference/error-codes`](/zh/reference/error-codes)）

- `InvalidInput` — mint 未排序或相同。
- `NotSupportMint` — 被阻止的 Token-2022 扩展。
- `ExceededSlippage` — 罕见；如果 `init_amount_0/1` 由于小数位数不匹配导致零 LP。

## `Deposit`

按池的比例添加两种代币的流动性。

**参数**

```
lp_token_amount:   u64   // 要铸造给 LP 的 LP 代币数量
maximum_token_0:   u64
maximum_token_1:   u64
```

**账户**

| # | 名称 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**数学**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

`k` 的比例性没有变化——两个金库和 `lp_supply` 按相同因子缩放。

**后置条件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（扣除输入上任何 Token-2022 转账费用）。
- `vault_1 += needed_token_1`（扣除输入上任何 Token-2022 转账费用）。

**常见错误** — `ExceededSlippage`、`ZeroTradingTokens`、如果存款被暂停则 `InvalidStatus`。

## `Withdraw`

销毁 LP 代币并按比例接收两种基础代币。

**参数**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**账户**

| # | 名称 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

（与 `Deposit` 相同；`lp_mint` 可写是因为 LP 代币被销毁。）

**数学**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**后置条件**

- `lp_supply -= lp_token_amount`。
- 金库发送 `out_token_0` / `out_token_1`（总额；用户接收扣除任何 Token-2022 转账费用的净额）。

## `SwapBaseInput`

精确输入交换。

**参数**

```
amount_in:            u64
minimum_amount_out:   u64
```

**账户**

| # | 名称 | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

顺序**输入 → 输出**由用户的方向决定，而非池的规范 `token_0 / token_1`。程序通过匹配 mint 来确定哪个金库是哪个。

**数学** — 见 [`products/cpmm/math`](/zh/products/cpmm/math)。

**前置条件**

- `open_time <= now`。
- `pool_status` 允许交换。
- 两个 mint 对此权限都未暂停或冻结。
- `amount_in > 0`。

**常见错误**

- `ExceededSlippage` — `amount_out < minimum_amount_out`。
- `ZeroTradingTokens` — 交易舍入为零。
- `NotApproved` — 池通过 `UpdatePoolStatus` 暂停交换。
- `InvalidInput` — mint 与池的任一金库 mint 都不匹配。

## `CollectFundFee`

与 `CollectProtocolFee` 形状相同，但由 `fund_owner` 签名并将 `fund_fees_*` 计数器清零。

## `CollectCreatorFee`

由 `pool_state.pool_creator` 签名。它将完整的 `creator_fees_token_0` 和 `creator_fees_token_1` 余额转账到创建者的代币账户，然后将两个计数器清零。当两个计数器都为零时返回 `NoFeeCollect`。

## `CollectCreatorFeePermissionless`

任何人都可以触发创建者费用收集。指令始终将完整的累积余额发送到由 `pool_state.pool_creator` 拥有的规范关联代币账户；调用者不能选择另一个创建者或目标。如果任一 ATA 缺失，支付者为其创建提供资金。

原始的 `CollectCreatorFee` 仍可调用，因此现有客户端保持兼容。

**参数** — 无。

**账户**

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 任何签名者；为缺失的创建者 ATA 提供资金。 |
| 2 | `creator` |   |   | 必须等于 `pool_state.pool_creator`；不签名。 |
| 3 | `authority` |   |   | CPMM 全局金库权限 PDA，种子为 `[b"vault_and_lp_mint_auth_seed"]`。它签名代币程序 CPI。 |
| 4 | `pool_state` | W |   | 持有累积创建者费用计数器。 |
| 5 | `token_0_vault` | W |   | 必须匹配池的代币 0 金库。 |
| 6 | `token_1_vault` | W |   | 必须匹配池的代币 1 金库。 |
| 7 | `vault_0_mint` |   |   | 必须匹配 `token_0_vault.mint`。 |
| 8 | `vault_1_mint` |   |   | 必须匹配 `token_1_vault.mint`。 |
| 9 | `creator_token_0` | W |   | 创建者的 `vault_0_mint` 规范 ATA；如缺失则创建。 |
| 10 | `creator_token_1` | W |   | 创建者的 `vault_1_mint` 规范 ATA；如缺失则创建。 |
| 11 | `token_0_program` |   |   | SPL Token 或 Token-2022，匹配代币 0。 |
| 12 | `token_1_program` |   |   | SPL Token 或 Token-2022，匹配代币 1。 |
| 13 | `associated_token_program` |   |   | 创建缺失的接收者 ATA。 |
| 14 | `system_program` |   |   | 从 `payer` 为账户创建提供资金。 |

**效果**

- 将所有 `creator_fees_token_0` 和 `creator_fees_token_1` 从池金库转账到创建者 ATA。
- 将两个创建者费用计数器清零并更新 `pool_state.recent_epoch`。
- 当两个计数器都为零时返回 `NoFeeCollect`。

## `UpdatePoolStatus`

暂停或恢复池上的单个操作。`status` 字段是一个位掩码：

| 位 | 标志 | 设置时的效果 |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` 以 `NotApproved` 拒绝。 |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` 拒绝。 |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` 拒绝。 |

**参数**

```
status: u8      // 新位掩码
```

**账户**

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `authority` |   | S | 必须匹配 CPMM 程序上的管理员密钥。 |
| 2 | `pool_state` | W |   |

管理员密钥是 CPMM 程序上的升级权限——实际上是 Raydium 多签。见 [`security/admin-and-multisig`](/zh/security/admin-and-multisig)。

## `CreateAmmConfig`

创建新的费用等级。

**参数**

```
index:             u16

fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**账户**

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | 管理员。 |
| 2 | `amm_config` | W |   | 在此处 `init`。 |
| 3 | `system_program` |   |   |

**前置条件**

- 不存在具有相同 `index` 的 `AmmConfig`。
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`。

<Note>
  **2026-09 中更改：新配置的费用所有者不再来自签名者。** `create_amm_config` 现在将程序的硬编码 `protocol_fee_owner::ID` 写入 `protocol_owner` 和 `fund_fee_owner::ID` 写入 `fund_owner`，而不是将管理员签名者的密钥复制到两者。地址在 [`reference/program-addresses`](/zh/reference/program-addresses#cpmm-fee-owner-wallets)。

  后果：新创建的 `AmmConfig` 立即由专用费用钱包扫除，而不是由管理员密钥，管理员不能在首次旋转字段之前从其刚创建的配置中收集。**现有 `AmmConfig` 账户不被重写** — 存储在其上的任何内容仍然管理，所以始终从账户读取 `protocol_owner` / `fund_owner` 而不是假设任一值。`UpdateAmmConfig` 参数 `3` 和 `4` 仍然旋转它们。
</Note>

## `UpdateAmmConfig`

更改现有 `AmmConfig` 上的费率或所有权。接受 `param: u8`（用于更新哪个字段的判别器）和 `value: u64`。每个参数的值语义在源代码中；常见的：

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner`（将 `Pubkey` 字节作为重新解释传递）
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

更改由管理员签名，影响**绑定到此 `AmmConfig` 的每个池**在下一次交换时。无迁移；池简单地读取新值。

## `CollectExcessLamports`

管理员扫除坐在 CPMM 控制的账户上租金豁免最低值之上的 lamport。在 2026-09 升级中添加，以便协议可以回收 [SIMD-0437 租金减少](/zh/solana-fundamentals/rent-and-reclaimable-rent) 在每个步骤之前创建的账户上留下的过度资金。

仅多余部分移动。代币余额、账户数据、所有者、池状态和曲线保持不变，指令对已在其最低值的账户是无操作——所以在每次推出步骤后重新运行是安全的。

**参数** — 无。

**账户**

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | 每个扫除 lamport 的目标。必须是 CPMM 程序管理员或专用收集 lamport 钱包——见 [`reference/program-addresses`](/zh/reference/program-addresses#excess-lamports-collection-wallets)。任何其他签名者以 `InvalidOwner` 失败。 |
| 2 | `authority` |   |   | CPMM 金库和 LP mint 权限 PDA，种子为 `[b"vault_and_lp_mint_auth_seed"]`。它签名代币程序 CPI。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。两者都无条件需要；程序按源账户选择。 |
| 5.. | `remaining_accounts` | W |   | `M` 个源账户要扫除，任意数量，任意顺序。 |

**每个源账户的处理方式**

程序根据源账户的 `owner` 分派：

| 源账户所有者 | 处理 |
|---|---|
| SPL Token 或 Token-2022，非原生代币账户或 mint — 池金库和 LP mint | CPI `WithdrawExcessLamports`（代币程序判别器 `38`），由 `authority` 签名。 |
| SPL Token 或 Token-2022，**原生**（wSOL）代币账户 | `WithdrawExcessLamports` 拒绝原生账户。程序 CPI `SyncNative`，测量包装 `amount` 增长了多少，`UnwrapLamports`（判别器 `45`）恰好那个增量，然后要求包装余额等于其预同步值——否则 `LamportsCalculateError`（`6015`）。因此 SOL 端池金库保持其完整流动性。 |
| CPMM 程序本身 — `PoolState`、`AmmConfig`、`ObservationState`、`Permission`、`SupportMintAssociated` | 程序直接将账户扣除到 `rent.minimum_balance(data_len)`。 |
| 其他任何东西 | **静默跳过。** 无错误，无 lamport 移动。 |

因为它接受无界的 `remaining_accounts` 列表，交易大小是真正的限制——与 [`solana-fundamentals/rent-and-reclaimable-rent`](/zh/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) 中描述的钱包端扫除相同的约束。

**常见错误** — `InvalidOwner`（`6001`，错误的签名者）、`LamportsCalculateError`（`6015`，wSOL 往返没有净为零）和来自程序拥有路径的 `InsufficientFunds`，当账户持有少于其自身租金最低值时。

**无 SDK 构建器。** `@raydium-io/raydium-sdk-v2` 不为此指令提供构建器，`raydium-sdk-V2-demo` 仓库也不——它是管理员路径。手动编码，就像 [`solana-fundamentals/rent-and-reclaimable-rent`](/zh/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) 中的钱包端扫除为代币程序指令所做的那样。
