## 前置条件

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

本页的每个示例都对应 [`raydium-sdk-V2-demo/src/cpmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/cpmm) 中的一个文件；GitHub 链接位于每个部分旁边。初始化遵循演示仓库的 `config.ts.template`（[源代码](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template)）：

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

`Raydium` 实例是 SDK 的门面——下面的每个示例都使用它。`Raydium.load` 是异步的，因为它默认加载代币列表；传递 `disableLoadToken: true` 可跳过该获取。可用性功能检查已被跳过，除非你传递 `disableFeatureCheck: false`。费用配置在首次使用时通过 `raydium.api.getCpmmConfigs()` 延迟获取。

## 创建 CPMM 池

源代码：[`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (如果你需要一次获取每个池的 PDA，导出的辅助函数是 `getCreatePoolKeys`。
//  没有 `getCpmmPdas`。)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. 选择费用配置。index=0 是 0.25% 层级。
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. 拉取 mint 元数据，以便 SDK 可以处理 Token-2022 扩展。
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. 构建交易。
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL（假设 9 位小数）
  mintBAmount:     new BN(   160_000_000),  // 160 USDC（按 160/SOL）
  startTime:       new BN(0),               // 立即开放
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("池创建于", extInfo.address.poolId.toBase58());
console.log("交易:", txId);
```

SDK 悄悄处理的几件事：

- 在推导 PDA 之前将 mint 排序为 token0/token1 顺序。
- 向 `poolFeeAccount` 支付一次性 `create_pool_fee`。
- 如果缺少，创建调用者的关联代币账户。
- 根据每一侧选择正确的代币程序（SPL Token 与 Token-2022）。

确认后，你可以使用以下方式获取实时池状态：

```ts
// getPoolInfoFromRpc 接受位置 base58 字符串，不是 PublicKey，也不是对象。
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## 交换（基础输入）

源代码：[`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // base58 字符串

// 1. 直接从 RPC 加载当前池状态（不从 API）。
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // 交换 A → B
const amountIn   = new BN(100_000_000);                   // 0.1 SOL
const slippage   = 0.005;                                 // 0.5%

// 2. 本地报价。CurveCalculator 镜像链上数学，包括
//    任一侧的 Token-2022 转账费。所有八个参数都是必需的。
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult 字段是 inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount。
// 没有 destinationAmountSwapped 或 sourceAmountSwapped。

// 3. 构建并发送。在这里传递 `slippage` 是应用边界的方式——
//    不需要手动最小输出算术。
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("交换交易:", txId);
```

注意：SDK **总是**在 `getPoolInfoFromRpc` 内从 RPC 重新获取池状态。不要从 `api-v3.raydium.io` 报价你即将签署的交易——一个落后一个区块的报价可能在着陆时滑入 `ExceededSlippage`。

## 交换（基础输出）

源代码：[`src/cpmm/swapBaseOut.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swapBaseOut.ts)

```ts
const amountOutWanted = new BN(15_000_000);        // 15 USDC
const slippage        = 0.005;

const baseIn = false; // false → mintB 是输入侧
const swapResult = CurveCalculator.swapBaseOutput(
  amountOutWanted,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult.inputAmount 是所需输入；没有 sourceAmountSwapped。

const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: new BN(0),   // 当 fixedOut 时未使用——金额来自 swapResult
  fixedOut:    true,
  swapResult,               // 必需，它携带目标输出金额
  baseIn,
  slippage,
  txVersion:   TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

## 存入流动性

源代码：[`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity 由输入金额驱动，不是 LP 金额。
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // 一个 Percent，不是数字

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount 以 mintA 计价
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

SDK 从池的当前储备推导配对金额，为指令的 `maximum_*` 参数将每一侧增加滑点，并在必要时构建 ATA 创建。`raydium.cpmm.computePairAmount({ ... })` 如果你想要它们用于 UI 预览，会返回相同的数字。

## 收取协议/基金/创建者费用

源代码：[`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts)、[`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

协议和基金收集仍然受权限限制。创建者费用有两条路径：创建者签署的 `CollectCreatorFee` 和加法 `CollectCreatorFeePermissionless`，任何支付者都可以调用，但只能转账到创建者的规范 ATA。`0.2.64-alpha` 为两个创建者路径提供模块级构建器：

```ts
// 创建者签署
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 无权限——任何支付者；收益进入创建者的规范 ATA
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 一次多个池，创建者签署
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Warning>
  **两个创建者指令在 2026-09-13 程序升级中改变了它们的账户列表。** 每个现在都在 `["creator_fee_share", creator, ammConfig]` 处获取 `creator_fee_share` PDA，无权限的那个也获取 `amm_config`——两者都插入在保险库之前。固定到升级前 SDK 版本的构建器发出旧布局，交易无法反序列化。在针对升级后的程序使用这些辅助函数之前，检查你安装的版本是否包含新账户，如果你从它生成客户端，请刷新 IDL。

  即使 PDA 从未被创建过，传递它也是强制性的——推导它并传递它；当账户为空时，程序回退到 `AmmConfig.creator_fee_share_rate`。
</Warning>

<Note>
  两个创建者指令有**不同的判别器和账户布局**——无权限的那个用单独的 `payer` 和非签署的 `creator` 替换创建者签署者。使用匹配的构建器，而不是在另一个上手动交换账户。

  SDK 中没有协议或基金费用构建器（`makeCollectProtocolFeeInstruction` 和 `makeCollectFundFeeInstruction` 在任何名称下都不存在）——那些是管理路径，`CreateCreatorFeeShare` / `CloseCreatorFeeShare` 也是，它们也没有构建器。**确实**存在的低级指令构建器是 `collectCpFeeInstruction`、`makeCollectCreatorFeeInstruction` 和 `collectCreatorFeePermissionlessInInstruction`。
</Note>

离链，你可以直接从 `PoolState` 读取应计费用：

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // base58 字符串
console.log("应计协议费 mintA:", pool.protocolFeesMintA.toString());
console.log("应计协议费 mintB:", pool.protocolFeesMintB.toString());
// CpmmPoolInfoLayout 字段是 protocolFeesMintA/B、fundFeesMintA/B 和
// creatorFeesMintA/B——没有 ...Token0/...Token1 字段。
//
// creatorFeesMintA/B 是*总*应计。创建者收到它减去在收集时解决的
// 协议份额；protocolFeesMintA/B 收到该份额，所以它也在创建者费用
// 收集时增长，不仅在交换时。
// 见 products/cpmm/fees#protocol-share-of-the-creator-fee。
```

## Rust CPI 框架

如果你想从自己的 Anchor 程序调用 CPMM——例如，一个代表其存款人进行交换的保险库——CPI 上下文看起来像这样。账户顺序遵循 [`products/cpmm/instructions`](/zh/products/cpmm/instructions)。

```rust
// Cargo.toml——分支很重要：`master` 仍然固定 anchor-lang 0.32.1。
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "chore/upgrade-anchor", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // 必须匹配 raydium-cp-swap 固定的内容
// anchor-spl       = "=1.0.2"
//
// `cpi` 功能是必需的——`raydium_cp_swap::cpi` 模块仅在
// 它下存在。注意此 crate 不能与 products/clmm/code-demos 中的 CLMM 示例
// 共享程序，后者固定 anchor-lang =0.32.1。

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: 由 CPMM 程序验证
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: 环形缓冲区
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0 在这里接受程序的 Pubkey，不是它的 AccountInfo。
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

如果你的 CPI 作为 PDA 签署（例如，你代表存款人管理保险库），将 `CpiContext::new` 交换为 `CpiContext::new_with_signer` 并传递你的种子。

## 常见陷阱

在开启支持工单之前的简短检查清单：

- **排序的 mint。** 如果你推导的 `poolState` PDA 与链上池不匹配，你可能忘记了排序 mint。
- **陈旧的 API 报价。** 永远不要将来自 `api-v3.raydium.io` 的储备值传递到 `CurveCalculator.swap`。从 RPC 获取。
- **错误的代币程序。** Token-2022 mint 的保险库由 Token-2022 程序拥有，不是 SPL Token。始终使用池的 `token_0_program` / `token_1_program` 字段。
- **转账费 mint 的滑点计价不足。** 如果池的任一侧是 Token-2022 转账费 mint，你的 `minimum_amount_out` 必须以用户实际收到的计价，而不是保险库发送的。
- **交换时 `NotApproved`。** 检查 `PoolState.status`——管理员可能已暂停该池上的交换。有关状态位掩码，见 [`products/cpmm/instructions`](/zh/products/cpmm/instructions)。
