<Info>
  LaunchLab 提供了一套精简的指令集：六个面向用户的调用加上少数管理员原语。SDK 包装了所有这些；本页为聚合器、监控工具和需要 CPI 的程序记录了原始接口。

  2026-09 程序升级在 Anchor 1.0.2 / Solana 3.1.10 上重建了 LaunchLab，并清除了三个过渡机制：已弃用的 `Initialize` 现在总是失败，`MigrateToAmm` 失去了它的三个参数和每个 OpenBook 账户，而 `get_upgrade_timestamp` 门控（使多个检查以时钟为条件）已消失。它还添加了一个管理员指令 `CollectExcessLamports`。参见 [2026-09-09 更新日志条目](/zh/reference/changelog/2026-09-09-launchlab-anchor-1-and-excess-lamports)。

## 指令清单

| 分组 | 指令 | 可调用者 |
|-------|-------------|-------------|
| 全局配置 | `CreateConfig` / `UpdateConfig` | 程序管理员；委托的创建配置权限也可以调用 `CreateConfig` |
| 启动生命周期 | `Initialize` | **无人 — 它总是以 `NotApproved` 失败。** 仅保留以保持判别器被占用且 IDL 保持稳定。使用 `InitializeV2`。 |
| 启动生命周期 | `InitializeV2` | 任何人（创建者）— SPL Token 基础代币；记录 `amm_creator_fee_on` 用于最终的 CPMM 毕业，并接受 Token-2022 报价代币。 |
| 启动生命周期 | `InitializeWithToken2022` | 任何人（创建者）— Token-2022 基础代币，可选 `TransferFeeConfig`；接受任一报价代币程序 |
| 交易 | `BuyExactIn` / `BuyExactOut` | 任何人 — 在联合曲线上精确输入/精确输出买入 |
| 交易 | `SellExactIn` / `SellExactOut` | 任何人 — 在联合曲线上精确输入/精确输出卖出 |
| 毕业 | `MigrateToAmm` | 迁移钱包 — 在强制执行仅 CPMM 创建之前初始化的池的遗留 AMM v4 毕业。自 2026-09 起不接受参数和 OpenBook 账户。 |
| 毕业 | `MigrateToCpswap` | 迁移钱包 — 毕业到 CPMM。所有新初始化的启动都使用此路径。包装 CPMM 上的 `InitializeWithPermission`。 |
| 费用 | `CollectFee` | 管理员 — 从启动中扫除协议费用 |
| 费用 | `CollectMigrateFee` | 管理员 — 扫除累积的迁移费用 |
| 费用 | `ClaimCreatorFee` | 创建者 — 在曲线阶段声称累积的创建者费用 |
| 归属 | `CreateVestingAccount` | 创建者 — 为受益人分配锁定代币，在毕业后解锁 |
| 归属 | `CreatePlatformVestingAccount` | 平台管理员 — 为平台端受益人分配锁定代币 |
| 归属 | `ClaimVestedToken` | 受益人 — 在悬崖期后声称解锁的代币 |
| 平台配置 | `CreatePlatformConfig` / `UpdatePlatformConfig` | 平台管理员 |
| 平台配置 | `CreatePlatformCurveRule` / `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` / `ClosePlatformCurveRule` | `PlatformConfig.curve_rule_manager` 或平台管理员 — 管理一个 `GlobalConfig` 的启动参数规则 |
| 平台费用 | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | 平台管理员 |
| 平台访问 | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 平台管理员 — 维护该平台启用限制时使用的 `GlobalConfig` 允许列表 |
| 租金 | `CollectExcessLamports` | 程序管理员或专用收集 lamports 钱包 — 从 LaunchLab 控制的金库和 PDA 中扫除超过租金豁免最低限额的 lamports。添加于 2026-09。 |

"ExactIn/ExactOut" 分割镜像 CPMM 的 `SwapBaseInput` / `SwapBaseOutput` — 在链上它们是具有略微不同舍入的单独指令判别器。

**毕业路径选择。** 每个新的 `InitializeV2` 和 `InitializeWithToken2022` 调用必须设置 `migrate_type = 1`（`CPSWAP`）。任何尝试初始化新的 AMM v4 绑定池都会返回 `MigrateTypeNotMatch`。`amm_creator_fee_on` 仅选择生成的 CPMM 创建者费用是否适用于报价代币或两个代币；它不选择目标程序。遗留的 `Initialize` 根本无法创建启动（见下文）。

`MigrateToAmm` 对于在此限制之前使用 `migrate_type = 0` 初始化的现有 `PoolState` 仍可调用。该版本不重写现有池状态或删除遗留指令。

**报价端代币程序。** 报价代币可由 SPL Token 程序或 Token-2022 拥有。每个接触它的指令 — `CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、所有四个交易指令、`CollectFee`、`CollectMigrateFee`、`ClaimCreatorFee`、`ClaimPlatformFee` 和 `ClaimPlatformFeeFromVault` — 在其报价程序账户槽中接受拥有程序。账户位置没有改变；只有接受的值改变了。传递实际拥有 `GlobalConfig.quote_mint` 的程序，你可以从现有启动的 `PoolState.token_program_flag` bit1 读取它（见 [`accounts`](/zh/products/launchlab/accounts#poolstate)）或从代币账户的所有者读取。

已弃用的 `Initialize` 在这里无关紧要：其报价程序账户仍然类型为 SPL Token，自 2026-09 升级以来该指令在读取任何账户之前失败。通过 `InitializeV2` 或 `InitializeWithToken2022` 启动。

`MigrateToCpswap` 是另一个例外，方向相反 — 它无条件地接受**两个**程序而不是每个代币一个。见下面的 [迁移账户](#cpmm-migration-token-programs)。

## `Initialize`

<Warning>
  **自 2026-09 升级以来实际上已删除 — 此指令总是失败。** `initialize` 的处理程序现在只是 `Not supported. Please use initialize_v2 instruction` 和 `NotApproved`（`6000`）的日志。它仅保留以保持其判别器被占用且 IDL 保持稳定形状。（`Accounts` 结构未改变，所以 Anchor 的生成验证仍然首先运行；无论如何交易都会还原。）

  以前它以时钟为门控：它在 `get_upgrade_timestamp` 切换后三天内有效，之后失败。该时间戳助手已消失，所以失败现在是无条件的。通过它创建的现有启动不受影响 — 它们根据存储的 `migrate_type` 通过 `MigrateToAmm` 或 `MigrateToCpswap` 正常交易和毕业。

  下面的参数和账户列表是 `InitializeV2` 的。已弃用的 `Initialize` 以相同顺序接受同样的 18 个账户，
  但只有前三个参数 —— 它没有 `amm_fee_on` —— 并且它的 `quote_token_program` 槽位被类型化为
  SPL Token，而不是 `Interface<TokenInterface>`。
</Warning>

创建新启动。相对已弃用的 `Initialize`，`InitializeV2` 只多了 `amm_fee_on` 参数；账户的**数量和顺序完全相同**，唯一的账户级差异是 `quote_token_program` 的类型为 `Interface<TokenInterface>`，因此可以接受 Token-2022 报价铸币。

**参数**

四个位置参数，而不是一个结构体。（`InitializeWithToken2022` 追加第五个参数 `transfer_fee_extension_param: Option<TransferFeeExtensionParams>`；已弃用的 `Initialize` 去掉了 `amm_fee_on`。）

```rust
base_mint_param: MintParams {
    decimals: u8,                 // must equal the program's BASE_MINT_DECIMALS
    name:     String,
    symbol:   String,
    uri:      String,
}

curve_param: CurveParams {        // Borsh enum — one leading variant-tag byte
    Constant { data: ConstantCurve { supply: u64, total_base_sell: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Fixed    { data: FixedCurve    { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
    Linear   { data: LinearCurve   { supply: u64,
                                     total_quote_fund_raising: u64, migrate_type: u8 } },
}

vesting_param: VestingParams {
    total_locked_amount: u64,     // 0 requires cliff_period == unlock_period == 0
    cliff_period:        u64,     // seconds after fundraising ends
    unlock_period:       u64,     // seconds
}

amm_fee_on: AmmCreatorFeeOn       // 0 = QuoteToken, 1 = BothToken (CPMM migrations only)
```

该变体必须与 `global_config.curve_type` 匹配，否则指令会以 `InputNotMatchCurveConfig`（`6003`）回滚。不存在 `open_time`，没有 `quote_mint` 参数（它来自 `global_config`），没有 `fees` 结构体，也没有 `post_graduation_lp_policy` —— LP 处置在 `PlatformConfig` 上设置，而不是按每个启动设置。

**账户** —— 共 18 个（16 个声明的，加上 `#[event_cpi]` 追加的两个）

| # | 名称 | W | S | 注释 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 支付所有租金。不必是创建者。 |
| 2 | `creator` |   |   | 记录为 `pool_state.creator`；不是签名者。 |
| 3 | `global_config` |   |   | 提供报价铸币、曲线类型以及每一个下限/上限。 |
| 4 | `platform_config` |   |   | 提供平台费率和 LP 处置策略。 |
| 5 | `authority` |   |   | PDA `["vault_auth_seed"]` —— 一个全局 PDA，被所有启动共享。 |
| 6 | `pool_state` | W |   | 新账户。 |
| 7 | `base_mint` | W | S | 新密钥对 —— 此指令初始化它。 |
| 8 | `quote_mint` |   |   | 必须等于 `global_config.quote_mint`。 |
| 9 | `base_vault` | W |   | PDA `["pool_vault", pool_state, base_mint]`。 |
| 10 | `quote_vault` | W |   | PDA `["pool_vault", pool_state, quote_mint]`。 |
| 11 | `metadata_account` | W |   | Metaplex 元数据 PDA。 |
| 12 | `base_token_program` |   |   | `InitializeV2` 用 SPL Token；`InitializeWithToken2022` 用 Token-2022。 |
| 13 | `quote_token_program` |   |   | 拥有 `quote_mint` 的程序 —— SPL Token 或 Token-2022。 |
| 14 | `metadata_program` |   |   | Metaplex Token Metadata。 |
| 15 | `system_program` |   |   | |
| 16 | `rent_program` |   |   | Rent sysvar。 |
| 17 | `event_authority` |   |   | PDA `["__event_authority"]`；由 `#[event_cpi]` 追加。 |
| 18 | `program` |   |   | LaunchLab 程序 id；由 `#[event_cpi]` 追加。 |

**前置条件**

- `quote_mint ∈ launch_config.allowed_quote_mints`。
- `base_supply_graduation ≤ base_supply_max`。
- 费用参数通过 `launch_config.max_*_fee_rate` 检查。
- `open_time ≥ now − slop`（SDK 强制 `≥ now`；程序容忍轻微回溯）。
- `curve_type` 被识别。

**后置条件**

- `base_mint` 有 `supply = curve_param.supply`，全部在 `base_vault` 中。
- 铸币权限在**同一条指令**中、供应量铸造完毕后立刻被**撤销**（`set_authority(MintTokens, None)`）—— 而不是在毕业时。因此基础铸币永久固定供应量，之后任何指令都无法再铸造。
- `PoolState` 初始化为 `status = Fund`（`0`）、`real_a = 0`、`real_b = 0`。
- `total_fund_raising_b` 直接来自 `curve_param.total_quote_fund_raising`。
- 对于带有 `TransferFeeConfig` 的 `InitializeWithToken2022`：`transfer_fee_config_authority = launch_authority`，当该字段被设置时 `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`，否则为 `launch_authority`。提取端在铸币创建时被写入，正是为了让平台可以在毕业前扫除扣留的费用。见 [`platform-config`](/zh/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

**常见错误** — `NotApproved`（`6000`，对已弃用的 `Initialize` 无条件触发）、`InvalidInput`（`6002`，违反了来自 `GlobalConfig` 的某个供应量／费率／募资下限）、`InputNotMatchCurveConfig`（`6003`，`curve_param` 变体与 `global_config.curve_type` 不匹配）、`MigrateTypeNotMatch`（`6007`，`migrate_type != 1`）、`MathOverflow`（`6008`）、`VestingRatioTooHigh`（`6010`）、`NoSupportExtension`（`6017`）、`NotEnoughRemainingAccounts`（`6018`）、`InvalidPlatformAllowConfig`（`6022`）、`CurveParamNotMatchPlatformRule`（`6025`）。Anchor 的 `address =` / `constraint =` 检查失败会表现为 2xxx 代码，而不是上述之一 —— 程序的错误枚举里并不存在 `InvalidQuoteMint`、`FeeRateTooHigh` 或 `InvalidCurveParams`。

## `Buy`（规范变体：`BuyExactIn`）

用户提供固定的输入数量；曲线计算输出。

**参数**

```
amount_in:           u64
minimum_amount_out:  u64
share_fee_rate:      u64   // referral fee on a 1_000_000 denominator; must be
                           // <= global_config.max_share_fee_rate. Pass 0 for no
                           // referral. Any non-zero value requires the share-fee
                           // receiver as remaining_accounts[0].
```

**账户**

| # | 名称 | W | S | 说明 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 交易者。 |
| 2 | `authority` |   |   | PDA `["vault_auth_seed"]` —— 一个全局 PDA，没有按启动的种子。 |
| 3 | `global_config` |   |   | `address = pool_state.global_config`。 |
| 4 | `platform_config` |   |   | `address = pool_state.platform_config`。 |
| 5 | `pool_state` | W |   | |
| 6 | `user_base_token` | W |   | `token::mint = base_token_mint`。 |
| 7 | `user_quote_token` | W |   | `token::mint = quote_token_mint`。 |
| 8 | `base_vault` | W |   | `address = pool_state.base_vault`。 |
| 9 | `quote_vault` | W |   | `address = pool_state.quote_vault`。 |
| 10 | `base_token_mint` |   |   | |
| 11 | `quote_token_mint` |   |   | |
| 12 | `base_token_program` |   |   | 拥有基础铸币的程序 —— SPL Token 或 Token-2022。 |
| 13 | `quote_token_program` |   |   | 拥有报价铸币的程序。 |
| 14 | `event_authority` |   |   | PDA `["__event_authority"]`；由 `#[event_cpi]` 追加。 |
| 15 | `program` |   |   | LaunchLab 程序 id；由 `#[event_cpi]` 追加。 |

**剩余账户** —— 费用管线，按这个确切顺序读取：

1. `share_fee_receiver` —— **仅**当 `share_fee_rate > 0` 时。
2. `system_program` —— 总是需要；会检查 `== System::id()`，否则报 `InvalidInput`。
3. `platform_fee_vault` —— PDA `[platform_config, quote_token_mint]`；首次使用时创建。
4. `creator_fee_vault` —— PDA `[creator, quote_token_mint]`；首次使用时创建。

数量不足会返回 `NotEnoughRemainingAccounts`（`6018`）。这里没有 `associated_token_program`
槽位，而 `system_program` 是一个*剩余*账户，而不是声明的账户。

**前置条件**

- `launch_state.status == Active`。
- `now ≥ open_time`。
- `user_quote_ata.balance ≥ quote_in`。
- `quote_in > 0`。

**效果**

1. 将 `quote_in` 分割为 `quote_in_after_fee` 和费用部分。
2. 牛顿求解曲线以获得给定后费用报价的 `base_out`。
3. `require(base_out ≥ minimum_base_out)` 否则还原 `ExceededSlippage`。
4. 移动 `quote_in` 用户 → 金库。移动 `base_out` 金库 → 用户。
5. 更新 `base_sold += base_out`、`quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`。
6. 更新费用计数器（`protocol_fees_quote`、`creator_fees_quote`）。
7. `state_data.num_buys += 1`。
8. 如果更新后 `quote_reserve_real ≥ quote_reserve_target`，SDK 通常在同一交易中链接 `Graduate` ix。程序不在 `Buy` 内自动毕业 — 需要后续的 `Graduate`。

## `BuyExactOut`

用户指定精确的 `base_out`；程序计算 `quote_in`。

**参数**

```
amount_out:         u64
maximum_amount_in:  u64
share_fee_rate:     u64   // as for BuyExactIn
```

与 `BuyExactIn` 相同的账户，以及相同的剩余账户约定。使用闭式二次积分（或 curve_type 1 的 CPMM 逆）而不是牛顿迭代。

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy` 的镜像。用户将 `base_in` 返回到曲线并接收 `quote_out`。费用从 `quote_out` 中扣除，所以用户收到的少于原始集成收益。

**前置条件** —

- `user_base_ata.balance ≥ base_in`。
- 卖出不能将 `base_sold` 推低于 0（给定会计一致，与上述冗余）。
- 启动是 `Active`。

**效果** — 对称于 `Buy`。`base_sold` 减少，`quote_reserve_real` 减少。费用仍然累积。

### 报价端转账费用

当报价代币携带 `TransferFeeConfig` 时，金库移动的金额和支付者被扣除或记入的金额不同，滑点界限针对支付者端进行检查。在没有扩展的报价代币上，下面的每种情况都与普通遗留代币相同。

| 指令 | 参数 | 检查对象 |
|---|---|---|
| `BuyExactIn` | `amount_in` | 曲线以 `amount_in − transfer_fee(amount_in)` 定价 — 到达金库的内容。完整填充精确扣除 `amount_in`；部分填充扣除消耗的金库金额加其逆费用。 |
| `BuyExactOut` | `maximum_amount_in` | 金库金额**加上**逆转账费用 — 真实扣除。 |
| `SellExactIn` | `minimum_amount_out` | 卖家在代币扣留其费用后保留的内容，而不是离开金库的总金额。 |
| `SellExactOut` | `amount_out` | 精确交付。曲线针对 `amount_out` 加逆转账费用。 |

报价的两个后果：

- 计算为代币无费用的界限被拒绝。将无费用成本作为 `maximum_amount_in` 传递，或将无费用收益作为 `minimum_amount_out` 传递，会以 `ExceededSlippage` 还原。
- `real_quote` 仅按到达金库的内容推进。5% 报价代币上的 `BuyExactIn` `amount_in` 将 `real_quote` 移动 `amount_in × 0.95`。

100% 费用报价代币（`10000` 基点）无法反演，在精确输出路径上以 `CalculateOverflow` 还原。

两个交易端代币也被限制为在其匹配槽中传递的程序，所以不匹配的 `base_token_program` 现在失败而不是被忽略。见 [`algorithms/token-2022-transfer-fees`](/zh/algorithms/token-2022-transfer-fees) 了解底层费用数学。

### 交易剩余账户

所有四个交易指令通过 `remaining_accounts` 按此顺序接受其费用管道：

| 索引 | 账户 | 何时 |
|---|---|---|
| 0 | `share_fee_receiver` | 仅当 `share_fee_rate > 0` 时。当存在时将下面的每个索引移动一个。 |
| next | `system_program` | 总是。为费用金库创建提供资金。 |
| next | `platform_fee_vault` | 总是。PDA 在种子 `[platform_config, quote_token_mint]`，首次使用时创建。 |
| next | `creator_fee_vault` | 总是。PDA 在种子 `[creator, quote_token_mint]`，首次使用时创建。 |

<Note>
  **在 2026-09 中改变：最后三个现在是无条件的，`system_program` 被验证。** 在此版本之前，程序仅在 `unix_timestamp >= get_upgrade_timestamp()` 时读取它们，并在该时刻之前完全跳过平台/创建者费用分割。时间戳已过去，所以主网上的行为实际上没有改变 — 但分支已从代码中消失，仍然省略三个账户的构建器现在总是以 `NotEnoughRemainingAccounts`（`6018`）失败，而不仅仅在切换后。`system_program` 槽另外针对 `System::id()` 进行检查，如果它持有其他任何内容则返回 `InvalidInput`（`6002`），而以前任何账户都在该位置被接受。
</Note>

## `MigrateToAmm` / `MigrateToCpswap`

一旦曲线达到 `total_quote_fund_raising`，将启动毕业到可交易的池中。新启动仅限 CPMM。`MigrateToAmm` 为存储的 `migrate_type` 为 `0` 的现有池保留。

**谁签署**

- `MigrateToAmm` — 绑定 `GlobalConfig` 上记录的 `migrate_to_amm_wallet`。
- `MigrateToCpswap` — 绑定 `GlobalConfig` 上记录的 `migrate_to_cpswap_wallet`。

这些钱包通常由 Raydium 运营的毕业 crank 持有；实际上毕业在阈值被越过后的几秒内进行，无论谁触发了最后的买入。

**参数**

都不接受任何。

<Warning>
  **破坏性变化（仅迁移钱包，2026-09）。** `MigrateToAmm` 删除了所有三个参数 — `base_lot_size`、`quote_lot_size`、`market_vault_signer_nonce` — **和九个账户**。其指令数据现在是裸判别器，所以旧构建器既发送 17 个意外参数字节，又提供不再对齐的账户列表。

  这遵循 AMM v4 自己的 [OpenBook 删除](/zh/reference/changelog/2026-07-22-amm-v4-openbook-removal)：AMM v4 的 `Initialize2` 不再接受 `market_program` 或 `amm_open_orders`，所以 LaunchLab 没有什么可转发的。程序也停止了 CPI-ing `initialize_openbook_market`，这是三个参数配置的内容。

  删除的账户：`openbook_program`、`request_queue`、`event_queue`、`bids`、`asks`、`market_vault_signer`、`market_base_vault`、`market_quote_vault` 和 `amm_open_orders`。`market` 账户**保留**在其位置 — AMM v4 仍将其记录为参考字段 — 但现在声明为裸 `#[account(mut)]`：无所有者、地址或种子约束。它完全未验证，直接转发到 AMM v4 的 `Initialize2` CPI，程序不再初始化它。想要市场账户成为真实初始化市场的调用者必须事先自己创建它。

  剩余的 23 账户列表按顺序为：`payer`、`base_mint`、`quote_mint`、`market`、`amm_program`、`amm_pool`、`amm_authority`、`amm_lp_mint`、`amm_base_vault`、`amm_quote_vault`、`amm_target_orders`、`amm_config`、`amm_create_fee_destination`、`authority`、`pool_state`、`global_config`、`base_vault`、`quote_vault`、`pool_lp_token`、`spl_token_program`、`associated_token_program`、`system_program`、`rent_program`。

  `MigrateToCpswap` 不受影响 — 它从未有过参数。
</Warning>

**效果（两者共同）**

1. 验证 `pool_state.status == Migrate`（即 `quote_reserve_target` 已达到）。否则以 `PoolMigrated`（状态已是 `Migrated`）或 `PoolFunding`（仍在融资）还原。
2. 验证 `pool_state.migrate_type` 匹配指令（AMM 为 `0`，CPMM 为 `1`）。否则以 `MigrateTypeNotMatch` 还原。
3. 计算毕业后的储备：
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI 到目标程序（`AMM v4 Initialize2` 或 `CPMM InitializeWithPermission`）使用这些储备创建毕业后的池。
5. 对于在 2026-08-17 升级后执行的 CPMM 迁移，将 `platform_scale + creator_scale` 合并为一个平台拥有的锁定 LP 份额，并最多向 `platform_nft_wallet` 铸造一个费用密钥 NFT。烧毁 `burn_scale` 余数。在升级之前，`creator_scale` 被单独锁定，其费用密钥去往代币创建者。已完成的历史迁移不被修改。对于遗留 AMM v4 毕业，LP 处置遵循该指令的现有流程。
6. （无代币权限步骤。`base_mint.mint_authority` 已在启动创建时设置为 `None` — 见下面的注释。）
7. 翻转 `pool_state.status = Migrated`，设置 `vesting_schedule.start_time = block_time + cliff_period`。

**Token-2022 转账费用权限交接** — 当基础代币是携带 `TransferFeeConfig` 的 Token-2022 代币**且** `PlatformConfig.transfer_fee_extension_auth` 非默认时，迁移也将该扩展的权限重新分配给平台密钥：

- `transfer_fee_config_authority` 总是被重新分配。启动 `authority` PDA 在整个毕业前阶段持有它，所以总有东西要移动。
- `WithheldWithdraw` 仅在 `authority` PDA 仍然持有它时被重新分配。从 2026-08-27 起创建的启动已经在代币创建时在该权限上携带 `transfer_fee_extension_auth`，所以该步骤被跳过。守卫是什么保持迁移不在这些代币上还原 — PDA 无法签署它不再持有的权限。

如果 `transfer_fee_extension_auth` 在迁移时是 `Pubkey::default()`，两个权限都不移动，两个都永久保留在 `authority` PDA。见 [`platform-config`](/zh/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

<Note>
  **基础代币的供应从创建时固定，而不是从毕业时。** `InitializeV2` 和 `InitializeWithToken2022` 将整个供应铸造到基础金库中，然后在同一指令中立即撤销 `MintTokens`，所以 `base_mint.mint_authority` 对启动的整个生命周期都是 `None`。迁移不接触它。（本页的早期版本将撤销放在毕业时；那是错误的。）迁移唯一可以移动的权限是下面描述的 Token-2022 转账费用权限。
</Note>

**后置条件** — 从此时起，`BuyExactIn`、`BuyExactOut`、`SellExactIn`、`SellExactOut` 将以 `PoolMigrated` 拒绝。生成的 AMM 池是规范的，交易就像任何其他 AMM v4 / CPMM 池一样。

**常见错误** — `PoolFunding`、`PoolMigrated`、`MigrateTypeNotMatch`、`InvalidCpSwapConfig`、`MathOverflow`。

### CPMM 迁移剩余账户

构建 `MigrateToCpswap` 的客户端必须使用这些固定的 `remaining_accounts` 索引：

| 索引 | 账户 |
|---|---|
| 0–4 | 平台费用密钥所有者、代币、代币账户、锁定流动性 PDA 和元数据账户 |
| 5 | 原始启动创建者；当 `platform_cp_creator` 未设置时使用 |
| 6 | 从 `[b"permission", launch_authority]` 派生的 CPMM 权限 PDA |
| 7 | 配置的 `platform_cp_creator`；当字段非默认时使用 |
| 8 | 排序 `mint0` 的 CPMM 支持代币 PDA，从 `[b"support_mint", mint0]` 派生 |
| 9 | 排序 `mint1` 的 CPMM 支持代币 PDA，从 `[b"support_mint", mint1]` 派生 |

指令至少需要十个剩余账户。支持代币账户是只读 CPI 输入。即使代币没有初始化的支持记录，也要派生两个地址。仍然附加创建者锁账户或省略索引 8–9 的旧构建器必须更新。

<Note>
  **在 2026-09 中改变。** 两个清理，都不改变正确的构建器：

  - **权限 CPMM 路径现在是唯一的路径。** `MigrateToCpswap` 曾经根据 `unix_timestamp >= get_upgrade_timestamp()` 在 `InitializeCpSwap` 和 `InitializeCpSwapWithPermission` 之间选择。时间戳助手和遗留 CPI 都消失了，所以权限路径 — 因此十账户最小值 — 无条件应用。
  - **三个地址约束从账户结构移到指令体中。** `platform_config`、`base_vault` 和 `quote_vault` 仍然需要匹配存储在 `PoolState` 上的值，但不匹配现在由 `require_keys_eq!` 而不是 Anchor 的 `address =` 约束引发。检查是等价的；只有错误表面不同 — 你得到 Anchor 的通用 `RequireKeysEqViolated`（`2502`）而不是 `ConstraintAddress`（`2012`），它被报告而没有账户名。更新任何匹配这三个账户的 `2012` 的错误处理。
</Note>

### CPMM 迁移代币程序

`MigrateToCpswap` 无条件地接受两个代币程序并自己计算出哪个拥有每个代币。其两个代币程序账户相应重命名：

| 位置 | 账户 | 值 |
|---|---|---|
| 第一个 | `token_program` | 总是遗留 SPL Token 程序 |
| 第二个 | `token_program_2022` | 总是 Token-2022 程序 |

它们替换了前面的 `base_token_program`（拥有基础代币的任何程序）和 `quote_token_program`（总是遗留）。位置没有改变，所以这是值变化而不是布局变化 — 但两个值几乎相反，保持传递旧对的构建器一旦任一代币是 Token-2022 代币就会在需要遗留程序的地方提供 Token-2022。

即使两个代币都不使用它，也需要遗留程序，因为 CPMM LP 代币和锁定流动性费用密钥 NFT 总是存在于它上面。

## 平台 `GlobalConfig` 允许列表

`PlatformConfig.restrict_global_config` 控制检查：

- `0`：平台接受任何其他有效的 `GlobalConfig`；不需要允许账户。
- `1`：`Initialize`、`InitializeV2` 和 `InitializeWithToken2022` 必须在 `remaining_accounts` 中的任何地方包含匹配的 `PlatformAllowConfig`。

平台管理员使用 `CreatePlatformAllowConfig` 和 `ClosePlatformAllowConfig` 创建或关闭 PDA。其种子是 `[b"platform_allow_config", platform_config, global_config]`。前面的管理员管理的 `PlatformGlobalAccess` 指令和 PDA 已停用。

## 平台启动参数规则

四个指令管理一个 `PlatformCurveRule` 账户。所有四个都由 `PlatformConfig.curve_rule_manager` 或平台管理员签署 — 程序通过从签署者重新派生 `PlatformConfig` PDA 来接受管理员，所以没有单独的账户证明它。既不是的签署者返回 `InvalidCurveRuleAuthority`。

| 指令 | 账户 | 参数 |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority`（签署者，mut）、`platform_config`、`global_config`、`platform_curve_rule`（mut）、`system_program` | 无 |
| `UpdatePlatformCurveRule` | 相同五个 | `group_id: u16`、`constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | 相同五个 | `group_id: u16` |
| `ClosePlatformCurveRule` | 前四个 | 无 |

`platform_curve_rule` 是 `[b"platform_curve_rule", platform_config, global_config]` 处的 PDA。

- **`Create`** 分配不持有任何组的账户。该状态不限制任何内容。
- **`Update`** 使用该 `group_id` 更新或插入组，如果存在则完全替换它。它调整账户大小以适应，所以签署者为其增长的租金补充，并接收其收缩的租金。超过第十个的新组返回 `CurveRuleGroupsExceeded`；超过 25 个约束、未知字段或运算符，或同一组中相同的 `(field, op)` 对两次返回 `InvalidCurveRuleConstraint`；非常数乘积配置上的四个 `TotalSellA` 派生字段返回 `CurveRuleFieldNotSupportedByCurve`。
- **`Remove`** 按 id 删除一个组，收缩账户并退款差额。未知 id 返回 `CurveRuleGroupNotExist`。
- **`Close`** 将整个租金返回给签署者。即使 `restrict_curve_param` 保持 `1`，配置也不再受限制。

四个都不改变规则是否被强制执行。那是 `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`，只有平台管理员可以调用。

**在启动路径上。** 当 `restrict_curve_param` 是 `1` 时，`InitializeV2` 和 `InitializeWithToken2022` 需要 `remaining_accounts` 中的规则 PDA — 包括当它不存在时，所以省略它无法跳过检查。缺少账户是 `NotEnoughRemainingAccounts`；满足无组的启动是 `CurveParamNotMatchPlatformRule`。检查在 `GlobalConfig` 自己的限制之前运行，只能缩小它们。模型和剧本：[`products/launchlab/curve-rules`](/zh/products/launchlab/curve-rules)。两个错误都可以客户端避免 — SDK 将此检查镜像为纯函数，见 [发送前检查](/zh/products/launchlab/curve-rules#check-before-you-send)。

## `CollectExcessLamports`

LaunchLab 控制的账户上超过租金豁免最低限额的 lamports 的管理员扫除。在 2026-09 升级中添加，以便协议可以回收 [SIMD-0437 租金减少](/zh/solana-fundamentals/rent-and-reclaimable-rent) 在每个步骤之前创建的账户上留下的过度资金。

只有超额移动。代币余额、账户数据、所有者、曲线状态和归属不受触及，指令对已在其最小值的账户是无操作 — 所以在每个推出步骤后重新运行是安全的。

**参数** — 无。

**账户**

| # | 名称 | W | S | 注释 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | 每个扫除 lamport 的目的地。必须是 LaunchLab 程序管理员或专用收集 lamports 钱包 — 见 [`reference/program-addresses`](/zh/reference/program-addresses#excess-lamports-collection-wallets)。任何其他签署者以 `InvalidOwner`（`6001`）失败。 |
| 2 | `authority` |   |   | **LaunchLab 三个金库权限 PDA 之一**（见下文）。为此调用中的每个代币账户签署代币程序 CPI。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。两个都无条件需要；程序按源账户选择。 |
| 5.. | `remaining_accounts` | W |   | `M` 个源账户要扫除，任何数量，任何顺序。 |

**选择 `authority`**

账户被无检查传递并由程序解析，程序重新派生 LaunchLab 的所有三个权限 PDA 并匹配：

| 种子 | 拥有 |
|---|---|
| `[b"vault_auth_seed"]` | 每个启动的基础和报价池金库 |
| `[b"platform_fee_vault_auth_seed"]` | 每个平台费用金库 |
| `[b"creator_fee_vault_auth_seed"]` | 每个创建者费用金库 |

不匹配三个中任何一个的密钥使整个指令以 `InvalidOwner`（`6001`）失败。

<Warning>
  **按权限分组你的源账户。** 一个调用携带一个 `authority`，代币程序需要账户的实际所有者签署。由与你传递的 `authority` 不同的三个 PDA 之一拥有的代币账户使 CPI 失败并将整个交易带走。在单独的交易中扫除池金库、平台费用金库和创建者费用金库。

  程序拥有的 PDA 是例外 — 它们被直接扣除，所以它们可以与任何权限一起进行。
</Warning>

**每个源账户如何处理**

| 源账户所有者 | 处理 |
|---|---|
| SPL Token 或 Token-2022，非本地代币账户 | CPI `WithdrawExcessLamports`（代币程序判别器 `38`），由 `authority` 签署。 |
| SPL Token 或 Token-2022，**本地**（wSOL）代币账户 | `WithdrawExcessLamports` 拒绝本地账户。程序 CPI `SyncNative`，测量包装 `amount` 增长了多少，`UnwrapLamports`（判别器 `45`）精确那个增量，然后需要包装余额等于其预同步值 — 否则 `LamportsCalculateError`（`6031`）。SOL 报价启动因此保留其完整报价储备。 |
| LaunchLab 程序本身 — `PoolState`、`GlobalConfig`、`PlatformConfig`、`VestingRecord`、`PlatformCurveRule`、`PlatformAllowConfig` | 程序直接扣除账户到 `rent.minimum_balance(data_len)`。 |
| 其他任何东西 | **静默跳过。** 无错误，无 lamports 移动。 |

**基础代币无法被扫除。** `InitializeV2` 和 `InitializeWithToken2022` 在铸造供应的同一指令中撤销基础代币上的 `MintTokens`，所以没有密钥可以为它签署 `WithdrawExcessLamports` — 代币的租金永久保留在原处。

**常见错误** — `InvalidOwner`（`6001`，错误的签署者或不是三个 PDA 之一的 `authority`）、`LamportsCalculateError`（`6031`，wSOL 往返没有净为零）和来自程序拥有路径的 `InsufficientFunds`，当账户持有少于其自己的租金最低限额时。

**无 SDK 构建器。** `@raydium-io/raydium-sdk-v2` 不为此指令提供构建器，`raydium-sdk-V2-demo` 仓库也不提供 — 它是管理员路径。手工编码，就像 [`solana-fundamentals/rent-and-reclaimable-rent`](/zh/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) 中的钱包端扫除对代币程序指令所做的那样。
