## 指令清单

| 分组 | 指令 | 可调用者 |
|-------|-------------|-------------|
| 全局配置 | `CreateConfig` / `UpdateConfig` | 程序管理员；委托的创建配置权限也可以调用 `CreateConfig` |
| 启动生命周期 | `Initialize` / `InitializeV2` | 任何人（创建者）— SPL Token 基础代币；V2 记录 `amm_creator_fee_on` 用于最终的 CPMM 毕业。仅 V2 接受 Token-2022 报价代币。 |
| 启动生命周期 | `InitializeWithToken2022` | 任何人（创建者）— Token-2022 基础代币，可选 `TransferFeeConfig`；接受任一报价代币程序 |
| 交易 | `BuyExactIn` / `BuyExactOut` | 任何人 — 在联合曲线上精确输入/精确输出买入 |
| 交易 | `SellExactIn` / `SellExactOut` | 任何人 — 在联合曲线上精确输入/精确输出卖出 |
| 毕业 | `MigrateToAmm` | 迁移钱包 — 针对在强制执行仅 CPMM 创建之前初始化的池的旧版 AMM v4 毕业。 |
| 毕业 | `MigrateToCpswap` | 迁移钱包 — 毕业到 CPMM。所有新初始化的启动都使用此路径。包装 CPMM 上的 `InitializeWithPermission`。 |
| 费用 | `CollectFee` | 管理员 — 从启动中扫除协议费用 |
| 费用 | `CollectMigrateFee` | 管理员 — 扫除累积的迁移费用 |
| 费用 | `ClaimCreatorFee` | 创建者 — 在曲线阶段声称累积的创建者费用 |
| 归属 | `CreateVestingAccount` | 创建者 — 为受益人分配锁定代币，毕业后解锁 |
| 归属 | `CreatePlatformVestingAccount` | 平台管理员 — 为平台端受益人分配锁定代币 |
| 归属 | `ClaimVestedToken` | 受益人 — 在悬崖期后声称解锁的代币 |
| 平台配置 | `CreatePlatformConfig` / `UpdatePlatformConfig` | 平台管理员 |
| 平台配置 | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | 平台管理员 — 管理每个平台允许的曲线形状列表 |
| 平台费用 | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | 平台管理员 |
| 平台访问 | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 平台管理员 — 维护该平台启用限制时使用的 `GlobalConfig` 允许列表 |

"ExactIn/ExactOut" 的分割镜像了 CPMM 的 `SwapBaseInput` / `SwapBaseOutput` — 在链上它们是具有略微不同舍入的单独指令判别器。

**毕业路径选择。** 每个新的 `Initialize`、`InitializeV2` 和 `InitializeWithToken2022` 调用必须设置 `migrate_type = 1`（`CPSWAP`）。任何尝试初始化新的 AMM v4 绑定池都会返回 `MigrateTypeNotMatch`。`amm_creator_fee_on` 仅选择生成的 CPMM 创建者费用是否适用于报价代币或两个代币；它不选择目标程序。

`MigrateToAmm` 对于在此限制之前使用 `migrate_type = 0` 初始化的现有 `PoolState` 仍然可调用。该版本不会重写现有池状态或删除旧版指令。

**报价端代币程序。** 报价代币可以由 SPL Token 程序或 Token-2022 拥有。每个接触它的指令 — `CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、所有四个交易指令、`CollectFee`、`CollectMigrateFee`、`ClaimCreatorFee`、`ClaimPlatformFee` 和 `ClaimPlatformFeeFromVault` — 在其报价程序账户槽中获取拥有程序。账户位置没有改变；只有接受的值改变了。传递实际拥有 `GlobalConfig.quote_mint` 的程序，你可以从现有启动的 `PoolState.token_program_flag` bit1 读取它（参见 [`accounts`](/zh/products/launchlab/accounts#poolstate)）或从代币账户的所有者读取。

已弃用的 `Initialize` 是例外：其报价程序账户仍然类型为 SPL Token，因此报价代币为 Token-2022 的配置必须通过 `InitializeV2` 或 `InitializeWithToken2022` 启动。

`MigrateToCpswap` 是另一个例外，方向相反 — 它无条件地获取**两个**程序而不是每个代币一个。参见下面的[迁移账户](#cpmm-migration-token-programs)。

## `Initialize`

创建新启动。

**参数**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // 或 curve_type=1 的 initial_virtual_quote_reserve
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // 内联名称/符号/uri；程序 CPI 到 Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**账户**（简化版）

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 支付租金 + 基础代币创建。 |
| 2 | `launch_config` |   |   | 协议配置绑定。 |
| 3 | `launch_state` | W |   | 新账户。 |
| 4 | `launch_authority` |   |   | PDA。 |
| 5 | `base_mint` | W | S | 新密钥对（或 PDA）— 此指令初始化它。 |
| 6 | `base_vault` | W |   | `launch_authority` 在 `base_mint` 上的 ATA。 |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | `launch_authority` 在 `quote_mint` 上的 ATA。 |
| 9 | `metadata` | W |   | Metaplex 元数据 PDA。 |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | 基础代币的 SPL Token。`InitializeV2` 和 `InitializeWithToken2022` 获取可能是任一程序的单独报价程序账户。 |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**前置条件**

- `quote_mint ∈ launch_config.allowed_quote_mints`。
- `base_supply_graduation ≤ base_supply_max`。
- 费用参数通过 `launch_config.max_*_fee_rate` 检查。
- `open_time ≥ now − slop`（SDK 强制 `≥ now`；程序容忍轻微回溯）。
- `curve_type` 被识别。

**后置条件**

- `base_mint` 有 `supply = base_supply_max`，全部在 `base_vault` 中。
- `base_mint.mint_authority = launch_authority`，`freeze_authority = None`。
- `LaunchState` 初始化为 `status = Active`、`base_sold = 0`、`quote_reserve_real = 0`。
- `quote_reserve_target` 从曲线参数 + `base_supply_graduation` + `buy_numerator` 计算（大约）。
- 对于附加了 `TransferFeeConfig` 的 `InitializeWithToken2022`：`transfer_fee_config_authority = launch_authority`，当该字段被设置时 `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`，否则 `launch_authority`。提取端在代币创建时写入，正是为了让平台可以在毕业前扫除扣留的费用。参见 [`platform-config`](/zh/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

**常见错误** — `InvalidQuoteMint`、`FeeRateTooHigh`、`InvalidCurveParams`、`MathOverflow`。

## `Buy`（规范变体：`BuyExactIn`）

用户提供固定的 `quote_in`；曲线计算 `base_out`。

**参数**

```
quote_in:          u64
minimum_base_out:  u64
```

**账户**

| # | 名称 | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**前置条件**

- `launch_state.status == Active`。
- `now ≥ open_time`。
- `user_quote_ata.balance ≥ quote_in`。
- `quote_in > 0`。

**效果**

1. 将 `quote_in` 分割为 `quote_in_after_fee` 和费用部分。
2. 牛顿求解曲线以获得给定后费用报价的 `base_out`。
3. `require(base_out ≥ minimum_base_out)` 否则恢复 `ExceededSlippage`。
4. 移动 `quote_in` 用户 → 金库。移动 `base_out` 金库 → 用户。
5. 更新 `base_sold += base_out`、`quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`。
6. 更新费用计数器（`protocol_fees_quote`、`creator_fees_quote`）。
7. `state_data.num_buys += 1`。
8. 如果更新后 `quote_reserve_real ≥ quote_reserve_target`，SDK 通常在同一交易中链接 `Graduate` ix。程序不会在 `Buy` 内自动毕业 — 需要后续的 `Graduate`。

## `BuyExactOut`

用户指定精确的 `base_out`；程序计算 `quote_in`。

**参数**

```
base_out:      u64
maximum_quote_in: u64
```

与 `BuyExactIn` 相同的账户。使用闭式二次积分（或 curve_type 1 的 CPMM 逆）而不是牛顿迭代。

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy` 的镜像。用户将 `base_in` 返回到曲线并接收 `quote_out`。费用从 `quote_out` 中扣除，因此用户收到的少于原始集成收益。

**前置条件** —

- `user_base_ata.balance ≥ base_in`。
- 卖出不能将 `base_sold` 推低于 0（给定会计一致，这是冗余的）。
- 启动是 `Active`。

**效果** — 对称于 `Buy`。`base_sold` 减少，`quote_reserve_real` 减少。费用仍然累积。

### 报价端转账费用

当报价代币携带 `TransferFeeConfig` 时，金库移动的金额和支付者被扣除或记入的金额不同，滑点界限针对支付者端进行检查。在没有扩展的报价代币上，下面的每种情况都与普通旧版代币相同。

| 指令 | 参数 | 检查对象 |
|---|---|---|
| `BuyExactIn` | `amount_in` | 曲线定价为 `amount_in − transfer_fee(amount_in)` — 到达金库的内容。完整填充精确扣除 `amount_in`；部分填充扣除消耗的金库金额加其逆费用。 |
| `BuyExactOut` | `maximum_amount_in` | 金库金额**加上**逆转账费用 — 真实扣除。 |
| `SellExactIn` | `minimum_amount_out` | 卖家在代币扣留其费用后保留的内容，而不是离开金库的总金额。 |
| `SellExactOut` | `amount_out` | 精确交付。曲线针对 `amount_out` 加逆转账费用。 |

报价的两个后果：

- 计算为好像代币无费用的界限被拒绝。将无费用成本作为 `maximum_amount_in` 传递，或将无费用收益作为 `minimum_amount_out` 传递，会以 `ExceededSlippage` 恢复。
- `real_quote` 仅按到达金库的内容推进。5% 报价代币上的 `BuyExactIn` 为 `amount_in` 移动 `real_quote` 为 `amount_in × 0.95`。

100% 费用报价代币（`10000` 基点）无法反演，在精确输出路径上以 `CalculateOverflow` 恢复。

两个交易端代币也被限制为其匹配槽中传递的程序，因此不匹配的 `base_token_program` 现在失败而不是被忽略。参见 [`algorithms/token-2022-transfer-fees`](/zh/algorithms/token-2022-transfer-fees) 了解底层费用数学。

## `MigrateToAmm` / `MigrateToCpswap`

一旦曲线达到 `total_quote_fund_raising`，将启动毕业到可交易的池。新启动仅限 CPMM。`MigrateToAmm` 为存储的 `migrate_type` 为 `0` 的现有池保留。

**谁签署**

- `MigrateToAmm` — 绑定 `GlobalConfig` 上记录的 `migrate_to_amm_wallet`。
- `MigrateToCpswap` — 绑定 `GlobalConfig` 上记录的 `migrate_to_cpswap_wallet`。

这些钱包通常由 Raydium 运营的毕业 crank 持有；实际上毕业在阈值被跨越后的几秒内进行，无论谁触发了最后的买入。

**参数**

`MigrateToAmm` 获取三个（主要是 OpenBook 市场参数，程序转发到 AMM v4）：

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` 不获取任何。

**效果（两者共同）**

1. 验证 `pool_state.status == Migrate`（即 `quote_reserve_target` 已被达到）。否则以 `PoolMigrated`（状态已是 `Migrated`）或 `PoolFunding`（仍在融资）恢复。
2. 验证 `pool_state.migrate_type` 匹配指令（AMM 为 `0`，CPMM 为 `1`）。否则以 `MigrateTypeNotMatch` 恢复。
3. 计算毕业后的储备：
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI 到目标程序（`AMM v4 Initialize2` 或 `CPMM InitializeWithPermission`）使用这些储备创建毕业后的池。
5. 对于在 2026-08-17 升级后执行的 CPMM 迁移，将 `platform_scale + creator_scale` 合并为一个平台拥有的锁定 LP 份额，并最多向 `platform_nft_wallet` 铸造一个费用密钥 NFT。燃烧 `burn_scale` 余数。在升级之前，`creator_scale` 被单独锁定，其费用密钥去往代币创建者。已完成的历史迁移不被修改。对于旧版 AMM v4 毕业，LP 处置遵循该指令的现有流程。
6. 撤销 `base_mint.mint_authority`（设置为 `None`）。
7. 翻转 `pool_state.status = Migrated`，设置 `vesting_schedule.start_time = block_time + cliff_period`。

**Token-2022 转账费用权限交接** — 当基础代币是携带 `TransferFeeConfig` 的 Token-2022 代币**且** `PlatformConfig.transfer_fee_extension_auth` 非默认时，迁移也将该扩展的权限重新分配给平台密钥：

- `transfer_fee_config_authority` 总是被重新分配。启动 `authority` PDA 在整个毕业前阶段持有它，所以总有东西要移动。
- `WithheldWithdraw` 仅当 `authority` PDA 仍然持有它时才被重新分配。从 2026-08-27 起创建的启动已经在代币创建时在该权限上携带 `transfer_fee_extension_auth`，所以该步骤被跳过。守卫是什么防止迁移在这些代币上恢复 — PDA 无法签署它不再持有的权限。

如果迁移时 `transfer_fee_extension_auth` 是 `Pubkey::default()`，两个权限都不移动，两个都永久留在 `authority` PDA。参见 [`platform-config`](/zh/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

**后置条件** — 从此点起，`BuyExactIn`、`BuyExactOut`、`SellExactIn`、`SellExactOut` 将以 `PoolMigrated` 拒绝。生成的 AMM 池是规范的，交易就像任何其他 AMM v4 / CPMM 池一样。

**常见错误** — `PoolFunding`、`PoolMigrated`、`MigrateTypeNotMatch`、`InvalidCpSwapConfig`、`MathOverflow`。

### CPMM 迁移剩余账户

构建 `MigrateToCpswap` 的客户端必须使用这些固定的 `remaining_accounts` 索引：

| 索引 | 账户 |
|---|---|
| 0–4 | 平台费用密钥所有者、代币、代币账户、锁定流动性 PDA 和元数据账户 |
| 5 | 原始启动创建者；当 `platform_cp_creator` 未设置时使用 |
| 6 | CPMM 权限 PDA 派生自 `[b"permission", launch_authority]` |
| 7 | 配置的 `platform_cp_creator`；当字段非默认时使用 |
| 8 | CPMM 支持代币 PDA 用于排序的 `mint0`，派生自 `[b"support_mint", mint0]` |
| 9 | CPMM 支持代币 PDA 用于排序的 `mint1`，派生自 `[b"support_mint", mint1]` |

指令在升级路径上需要至少十个剩余账户。支持代币账户是只读 CPI 输入。即使代币没有初始化的支持记录，也要派生两个地址。仍然附加创建者锁账户或省略索引 8–9 的旧版构建器必须更新。

### CPMM 迁移代币程序

`MigrateToCpswap` 无条件地获取两个代币程序，并自己计算出哪个程序拥有每个代币。其两个代币程序账户被相应地重命名：

| 位置 | 账户 | 值 |
|---|---|---|
| 第一个 | `token_program` | 总是旧版 SPL Token 程序 |
| 第二个 | `token_program_2022` | 总是 Token-2022 程序 |

它们替换了前面的 `base_token_program`（拥有基础代币的任何程序）和 `quote_token_program`（总是旧版）。位置没有改变，所以这是值改变而不是布局改变 — 但两个值几乎相反，保持传递其旧对的构建器一旦任一代币是 Token-2022 代币就会在需要旧版程序的地方提供 Token-2022。

即使两个代币都不使用它，旧版程序也是必需的，因为 CPMM LP 代币和锁定流动性费用密钥 NFT 总是在它上面。

## 平台 `GlobalConfig` 允许列表

`PlatformConfig.restrict_global_config` 控制检查：

- `0`：平台接受任何其他有效的 `GlobalConfig`；不需要允许账户。
- `1`：`Initialize`、`InitializeV2` 和 `InitializeWithToken2022` 必须在 `remaining_accounts` 中的任何地方包含匹配的 `PlatformAllowConfig`。

平台管理员使用 `CreatePlatformAllowConfig` 和 `ClosePlatformAllowConfig` 创建或关闭 PDA。其种子是 `[b"platform_allow_config", platform_config, global_config]`。前面的管理员管理的 `PlatformGlobalAccess` 指令和 PDA 已停用。

## `CollectFee`

协议在单个启动上累积的交易费用的管理员扫除。

**参数** — 无。

**账户**

| # | 名称 | W | S | 备注 |
|---|------|---|---|-------|
| 1 | `protocol_fee_owner` |   | S | 必须等于 `global_config.protocol_fee_owner`。 |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`；签署金库转账。 |
| 3 | `pool_state` | W |   | 变异为零 `quote_protocol_fee`。 |
| 4 | `global_config` |   |   | 签署者的真实来源。 |
| 5 | `quote_vault` | W |   | 由 `quote_protocol_fee` 排空。 |
| 6 | `recipient_token_account` | W |   | `protocol_fee_owner` 在 `quote_mint` 上的 ATA。 |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | 拥有报价代币的程序 — SPL Token 或 Token-2022。 |

**效果** — 从 `quote_vault` 转账 `pool_state.quote_protocol_fee` 到 `recipient_token_account`，然后将计数器清零。可在第一次买入后的任何时间调用。

## `CollectMigrateFee`

毕业时累积的迁移费用的管理员扫除。与 `CollectFee` 相同的账户形状，`migrate_fee_owner` 作为签署者（而不是 `protocol_fee_owner`）和 `pool_state.migrate_fee` 作为排空的计数器。

## `ClaimCreatorFee`

跨**创建者拥有的每个启动**使用相同报价代币的累积创建者费用的按创建者扫除。排空按创建者费用金库，而不是按池的。

**参数** — 无。

**账户**
