当 LaunchLab 代币迁移到 CPMM 时，资金池会铸造 LP 代币。在 2026-08-17 升级之前，`creatorScale` 为代币创建者单独锁定。对于升级后执行的迁移，`migrateCpLockNftScale` 仍然存储三个字段，其总和为 `1_000_000`，但运行时只产生两个目标。

## 有效分割

| 字段 | 更新后的行为 |
|---|---|
| `platformScale` | 包含在平台所有的锁定 LP 份额中。 |
| `creatorScale` | 升级前为创建者所有的费用密钥铸造。升级后，它包含在平台所有的锁定 LP 份额中。 |
| `burnScale` | 永久销毁。没有费用密钥代表此份额。 |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

当 `burnScale` 为零时，平台接收所有 LP 单位。当 `effectivePlatformScale` 为零时，所有 LP 被销毁，不创建平台费用密钥。

## 示例

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% 平台所有的锁定 LP，10% 销毁。
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// 在更新的程序下，这产生 100% 平台所有的锁定 LP。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% 销毁；无费用密钥。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## 与 CPMM 创建者费用的关系

规模字段仅控制 LP 所有权。它们不设置交换费率或标识 CPMM 创建者费用受益人。`cpConfigId` 选择 CPMM `AmmConfig`；`platformCpCreator` 决定 CPMM 资金池是记录原始启动创建者还是平台选定的地址。

## 更新分割

在更新平台之前：

- 确认三个值的总和恰好为 `1_000_000`。
- 将 `platformScale + creatorScale` 呈现为有效的平台份额。
- 不要基于 `creatorScale` 承诺创建者费用密钥。
- 保留升级前完成的迁移所显示的创建者费用密钥所有权；这些记录不会被重写。
- 在未来的启动使用更新的配置之前解释此更改。
