## 账户清单

| 账户 | 所有者 | 用途 |
|---------|-------|---------|
| [`GlobalConfig`](/zh/products/launchlab/global-config) | LaunchLab 程序 | 协议级规则：费用、供应下限、迁移钱包。每个 `(curve_type, index)` 一个。 |
| [`PlatformConfig`](/zh/products/launchlab/platform-config) | LaunchLab 程序 | 每平台覆盖层：品牌、平台费用、毕业时的 NFT 分割、曲线形状白名单。 |
| `PoolState` | LaunchLab 程序 | 每次启动的根状态：铸币、金库、曲线参数、销售计数器、费用计数器、归属计划、毕业状态。 |
| `authority` | LaunchLab 程序 | 单个 PDA，种子为 `[b"vault_auth_seed"]`，拥有所有启动的金库并签署毕业后 CPI。 |
| `base_vault` | SPL Token / Token-2022 | 每次启动的金库，持有未售出的基础代币。 |
| `quote_vault` | SPL Token / Token-2022 | 每次启动的金库，持有累积的报价代币。遵循拥有报价铸币的程序。 |
| [`VestingRecord`](/zh/products/launchlab/vesting) | LaunchLab 程序 | 每个受益人的悬崖 + 线性解锁记录。可选。 |
| `creator_fee_vault` | SPL Token / Token-2022 | 每个创建者 + 每个报价铸币的金库，持有应计创建者费用，由 `ClaimCreatorFee` 清空。遵循报价铸币的程序。 |
| `platform_fee_vault` | SPL Token / Token-2022 | 每个平台 + 每个报价铸币的金库，持有应计平台费用，由 `ClaimPlatformFeeFromVault` 清空。遵循报价铸币的程序。 |
| [`PlatformAllowConfig`](/zh/products/launchlab/platform-config) | LaunchLab 程序 | 可选的平台管理权限，用于一个 `(PlatformConfig, GlobalConfig)` 对。仅在平台启用限制时检查。 |
| （毕业后）`cpmm_pool_state` | CPMM 程序 | 由 `MigrateToCpswap` 为每次新启动创建的池。旧状态仍可引用 AMM v4 毕业。 |
| （毕业后）Fee Key NFT | LP-Lock 程序 | 在 2026-08-17 升级之前，平台和创建者规模可能产生单独的 Fee Key。之后执行的迁移将两个规模合并为一个平台 Fee Key。 |

SDK 的 `raydium.launchpad.getLaunchById` 返回 `PoolState` 加上一个标志，指示启动是否已毕业；如果已毕业，则包含迁移后的池 ID。

## `PoolState`

每次启动的根状态。下面的字段名称与链上 Rust 结构体（`states/pool.rs`）匹配；某些值为了可读性已简化——请查阅源代码了解确切的内存布局。

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus` 值（来自 Anchor IDL）：

```
0 = Funding         — 接受买入/卖出；低于 quote_reserve_target
1 = Migrate         — 达到 quote_reserve_target；等待 MigrateTo*
2 = Migrated        — MigrateTo* 已执行；归属时钟运行中
```

面向集成者的字段：

- **`status`** — 三个值，单调递增（Funding → Migrate → Migrated）。读取始终安全；写入受限。
- **`real_base`**、**`real_quote`** — 当前曲线状态。结合 `virtual_base` / `virtual_quote`，足以计算现货价格而无需接触金库。参阅 [`bonding-curve`](/zh/products/launchlab/bonding-curve)。
- **`total_base_sell`** vs `real_base` — UI 的"毕业进度"比率。
- **`migrate_type`** — 新初始化需要 `1`（`CPSWAP`）。存储的 `0` 仅对在 CPMM 唯一强制之前创建的现有启动有意义。
- **`amm_creator_fee_on`** — 在毕业后 CPMM 池上选择 `creator_fee_on = OnlyQuoteToken`（`0`）或 `BothToken`（`1`）。它不选择迁移目标。参阅 [`creator-fees`](/zh/products/launchlab/creator-fees)。
- **`token_program_flag`** — 位字段，不是布尔值。Bit0 是基础铸币，Bit1 是报价铸币，每个 `0` 表示 SPL Token，`1` 表示 Token-2022，所以字节取四个值：`0`（两个都是旧版）、`1`（Token-2022 基础）、`2`（Token-2022 报价）、`3`（两个都是 Token-2022）。用 `(token_program_flag >> bit) & 1` 读取一个铸币。将整个字节与 `0` 比较以分类基础铸币会将 `2` 解析为错误的程序。Bit1 在支持 Token-2022 报价铸币之前一直是常数 `0`。
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — 三个独立的费用计数器。每个都有自己的领取指令；参阅 [`instructions`](/zh/products/launchlab/instructions)。
- **`vesting_schedule`** — 存在于每个 `PoolState` 上，但当 `total_locked_amount == 0` 时不活跃。参阅 [`vesting`](/zh/products/launchlab/vesting) 了解完整生命周期。

## 权限 PDA

LaunchLab 在所有启动中使用**单个**权限 PDA，派生时不使用每次启动的种子：

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // see reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

该单个 PDA 是：

- 每次启动的 `base_vault` 和 `quote_vault` 上的权限。
- 每次启动的 `base_mint` 上的 `mint_authority`（毕业前）。
- CPMM 毕业 CPI 上的签署者，以及现有状态的旧版 AMM v4 毕业。
- `ClaimVestedToken` 从基础金库转出的签署者。

`mint_authority` 在 `MigrateToCpswap` 或旧版 `MigrateToAmm` 调用后立即被撤销，因此供应永久固定。

两个额外的 PDA 控制费用金库：

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

这些在 `ClaimCreatorFee` 和 `ClaimPlatformFeeFromVault` 期间签署相应费用金库的转出。

## 基础铸币

由 `Initialize` 内联创建，具有：

- `mint_authority = authority`（毕业时撤销）。
- `freeze_authority = None`。
- `supply = supply`，完全铸造到 `base_vault`。
- `decimals` 由创建者在 `Initialize` 时选择（通常为 6）。

因为完整供应是预先铸造的，`base_mint.supply` 在启动的整个生命周期中是常数。曲线买入将代币从 `base_vault` 移动到买方，但不调用 `mint_to`。

`Initialize` / `InitializeV2` 创建 SPL Token 基础铸币。专用的 `InitializeWithToken2022` 指令允许基础铸币是 Token-2022 铸币（带可选的 `TransferFeeConfig`）。所有三个初始化路径都需要 CPMM 毕业。

报价铸币独立于基础铸币，本身可能是 Token-2022 铸币——`InitializeV2` 和 `InitializeWithToken2022` 在其报价程序槽中接受任一程序。已弃用的 `Initialize` 不接受：其报价程序账户仍然类型为 SPL Token，因此报价铸币为 Token-2022 的配置只能通过其他两个启动。LaunchLab 从不创建报价铸币；它是 `GlobalConfig.quote_mint` 命名的任何东西。参阅 [`global-config`](/zh/products/launchlab/global-config#token-2022-quote-mints) 和 [`reference/token-2022-support`](/zh/reference/token-2022-support#launchlab-quote-mints)。

## 金库

`base_vault` 和 `quote_vault` 都是由 LaunchLab `authority` PDA 拥有的代币账户，每个都在拥有其自己铸币的程序上创建——因此启动可以有旧版基础金库和 Token-2022 报价金库，或任何其他组合。`token_program_flag` 记录哪个是哪个。地址存储在 `PoolState` 上，也可以派生：

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

（在生产中依赖派生之前，从源代码的 `Initialize` 账户结构验证确切的种子前缀。）

## 费用金库

两个 PDA 跨启动聚合费用：

- **创建者费用金库** — PDA，种子为 `[creator, quote_mint]`。每次启动在同一报价铸币上赚取相同创建者费用都流入同一金库。创建者通过 `ClaimCreatorFee` 清空它。
- **平台费用金库** — PDA，种子为 `[platform_config, quote_mint]`。通过同一平台路由且使用同一报价铸币的每次启动都流入同一金库。平台的 `platform_fee_wallet` 通过 `ClaimPlatformFeeFromVault` 清空它。还有一个每次启动的清空变体（`ClaimPlatformFee`），直接从启动的 `quote_vault` 拉取，不经过聚合金库。

两者都在第一次交换产生费用时在拥有报价铸币的程序上懒惰创建。针对旧版和 Token-2022 报价铸币运行启动的创建者或平台最终会为每个铸币获得一个金库，就像它已经为两个不同的旧版铸币所做的那样。

聚合金库模式是让高容量创建者或平台在许多启动中摊销费用累积的租金成本的原因。

## 报价金库 ↔ `real_quote`

`quote_vault.balance` 和 `PoolState.real_quote` 应该保持同步。它们最多可以漂移三个待处理费用计数器的总和（`quote_protocol_fee`、`platform_fee`、`migrate_fee`），这些计数器位于金库中但属于费用计数器而不是曲线储备。曲线数学始终使用 `real_quote`，从不使用原始金库余额。

毕业前不变量：

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## 生命周期账户转换

| 事件 | 状态 | `real_base` | `real_quote` | 毕业后池 |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap`（或旧版 `MigrateToAmm`） | Funding → Migrate → Migrated | （冻结） | （冻结） | 已创建；CPMM LP 分割为平台拥有的锁定 LP 和销毁 LP |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | 任何 | — | — | 清空费用金库 |
| `CreateVestingAccount` | Funding | — | — | 增加 `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | 仅 Migrated | — | — | 清空 `base_vault` |
