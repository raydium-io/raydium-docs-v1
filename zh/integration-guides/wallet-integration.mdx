## 检测 Raydium 头寸

### 经典 LP 代币（CPMM、AMM v4）

这些看起来像任何其他 SPL 代币：用户的 ATA 持有余额。钱包默认将其显示为另一个代币。要将其识别为 Raydium LP 头寸：

1. 枚举用户的代币账户：`connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`。
2. 对于每个 mint，检查 Raydium 的 mint 列表：`GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...`（每次调用最多批处理约 50 个 LP mint）。
3. 对于匹配的 mint，API 返回池引用。使用它来计算头寸的代币计价值：

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

同时显示 LP 余额和解包后的金额 — 用户以基础代币而非 LP 单位来思考。

### CLMM 头寸 NFT

CLMM 头寸是 NFT。每个头寸的 `PersonalPositionState` PDA 从 NFT mint 派生。要检测：

1. 枚举用户的 NFT。对于旧版 Metaplex NFT：将代币账户过滤为供应量为 1 且小数位为 0 的账户。
2. 对于每个 NFT mint，尝试派生 PersonalPositionState PDA：

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// 这是一个 Raydium CLMM 头寸 — 解码。
```

3. 使用 `raydium.clmm.getOwnerPositionInfo({ programId })` 枚举钱包的头寸，并在 `nftMint` 上匹配（没有 `getPositionInfo`）。每个条目给你：
   - `poolId` → 获取池以解析 mint
   - `tickLower`、`tickUpper` → 显示范围
   - `liquidity`、`tokensOwedA/B` → 计算头寸价值 + 待领费用
   - `rewardInfos` → 每个流的待领奖励

4. 对于在 Token-2022 下发行的头寸 NFT（`OpenPositionWithToken22Nft`），NFT mint 的程序是 Token-2022 而非 SPL Token。扫描时枚举两者。

### 农场质押

农场 v3 / v5 / v6 各有一个每用户账本 PDA。派生方式：

```ts
// 为用户的每个潜在农场交互尝试所有三个农场版本。
// 最便宜的方法：先询问 API，它已索引所有用户头寸。

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

对于偏好完全链上检测的钱包：通过使用精选的"可能"农场 ID 列表对用户进行哈希来迭代可能的 `UserLedger` PDA。穷举枚举所有农场 ID 不切实际（存在数千个）；使用 API。

## 计算头寸价值

### CPMM / AMM v4 LP

这三个模块**不**共享签名：`liquidity.getPoolInfoFromRpc` 接受 `{ poolId }`，而 `cpmm.getPoolInfoFromRpc` 和 `clmm.getPoolInfoFromRpc` 接受位置 base58 字符串。

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` 是一个 ApiV3Token，没有 `supply` 字段。从链上读取 LP mint 的
// 供应量，或使用池自己的镜像：
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

然后将每个乘以 mint 的美元价格（来自 `raydium.token` 或价格预言机）。

### CLMM 头寸

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // base58 字符串
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity 是异步的，接受 epochInfo + poolInfo + add，
// 并返回费用包装的金额。
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // 用于显示，无滑点
  add:        false,
});
// amountA.amount / amountB.amount 是 BN；.fee 是 Token-2022 转账费。

// 待领费用 — 单独显示为"未收取"
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// 待领奖励 — CLMM 池有 0–3 个奖励流。头寸的
// rewardInfos 条目仅为 { growthInsideLastX64, rewardAmountOwed }，所以
// mint 必须来自同一索引处的池的 rewardInfos。
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

渲染为：

- 流动性价值（当前价格）
- 未收取的费用
- 每个流的待领奖励
- 范围：`[tickLower_price, tickUpper_price]`，带有一个可视条显示当前价格是否在范围内

### 农场质押

```ts
// API 响应已包含待领奖励；直接使用。
const apr       = stakingFarm.apr;               // %，年化
const staked    = stakingFarm.stakedAmount;      // 质押 mint 的最小单位
const rewards   = stakingFarm.pendingRewards;    // { mint, amount } 数组
```

对于链上计算，镜像农场的会计：

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

确保在计算前使用懒更新公式刷新 `reward_per_share_x64`（经过时间 × 发放率 ÷ 总质押）。

## 交易模拟用于预览

在用户签名前，钱包通常预览余额变化。使用 `simulateTransaction`：

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// 解码每个返回账户的余额并与交易前余额进行比较。
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // 与交易前余额比较，显示 Δ
}
```

`accounts` 参数要求验证器为列出的地址返回模拟后的账户状态。比尝试仅从指令形状预测余额变化准确得多。

### 模拟陷阱

- **CLMM 交换需要有效的 tick 数组。** 如果用户的输入大小会跨越未初始化的 tick 数组，模拟会还原（与执行相同）。在 UI 中清楚地显示这一点。
- **优先费。** 模拟运行时不应用计算预算指令。对于会超过默认 200k CU 的大型交易，模拟失败但使用显式 CU 限制的实际执行成功。也在模拟的交易上设置 CU 限制。
- **新鲜区块哈希。** 模拟使用当前区块哈希；如果签名耗时 >60 秒，交易变为无效。如果用户犹豫，重新模拟。

## Token-2022 显示

Token-2022 程序下的代币应在钱包的代币列表中标记为此类，因为它们有不同的风险表面：

- **转账费 mint**：在余额旁显示当前 `transferFeeBasisPoints` 为"转账费：X%"。接收时警告 — 用户可能没有意识到他们会收到少于发送者发送的金额。
- **转账钩子 mint**：显示钩子程序 ID。恶意钩子可以阻止出站转账；用户应验证钩子是他们期望的。
- **不可转账 mint**：显示"不可转账"并禁用交换/发送。这些通常是灵魂绑定代币或凭证。
- **生息 mint**：从 `TokenAccount.amount` 派生的 UI 余额**不**反映应计利息。使用 `@solana/spl-token` 中的 `amountToUiAmount`（应用缩放因子）来获得显示值。

## 农场 APR 显示

向用户显示的 APR 应结合所有实时奖励流，转换为美元，并年化：

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // 跳过未运行的
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

显示为 `APR: X.Y%`。如果质押 mint 是 LP 代币，还计算基础 LP 的基础费用 APR 并将总和标记为"总 APR"或"APR + 费用"。
