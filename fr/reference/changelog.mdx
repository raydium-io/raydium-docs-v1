## Versions

<Update label="2026-07-30" description="CLMM : pools multi-permissionnés et garde de compte gelé pour ordres limites">
  Deux mises à jour additives et rétro-compatibles du programme CLMM. `CreatePermissionedPool` intègre un `seed_index` non-nul fourni par le client dans les seeds du PDA du pool, permettant à un opérateur autorisé (détenteur d'un PDA `Permission`) de créer plusieurs pools par `(config, mint0, mint1)` — ainsi un ID de pool n'est plus canonique pour une paire. Les nouvelles instructions d'administration `CreatePermissionPda` / `ClosePermissionPda` gèrent ces autorisations, et `PoolState` gagne un champ `seed_index` (prélevé sur le padding, pas de changement de taille). Séparément, `OpenLimitOrder` prend désormais les comptes du côté output et rejette les ordres dont le compte de token input ou output est gelé (`NotApproved`).

  [Lire l'entrée complète →](/fr/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4 : suppression de la dépendance OpenBook / Serum">
  AMM v4 supprime sa dépendance longtemps dormante à OpenBook/Serum, tous les CPI du carnet d'ordres, et les instructions de market-making mortes. `SwapBaseIn` / `SwapBaseOut`, `Deposit` et `Withdraw` conservent leurs layouts (les comptes de marché supprimés sont désormais ignorés, non validés) ; un `WithdrawPnl` **cassant** (17 → 10, pas de compatibilité) et `SetParams` (comptes réduits + `param` renuméroté) ; et `Initialize`, `PreInitialize`, `MonitorStep`, `MigrateToOpenBook`, `WithdrawSrm`, `SimulateInfo`, `AdminCancelOrders` ne sont plus appelables. Les layouts de comptes on-chain et les codes d'erreur restent stables ; migrez les swaps vers les points d'entrée V2.

  [Lire l'entrée complète →](/fr/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM : suppression du code OpenBook (marché) mort">

La plupart des autres instructions Stable ne sont plus appelables.

  [Lire l'entrée complète →](/fr/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)

## Conventions de documentation

- **Versioning** : cette documentation utilise un versioning basé sur le calendrier (YYYY-MM-DD). Chaque mise à jour ajoute une nouvelle page d'entrée et une nouvelle ligne en haut de la chronologie ci-dessus.
- **Une page par version** : chaque résumé de version vit sur sa propre page sous `reference/changelog/`, de sorte que cet index reste court et chaque entrée est indépendamment liée.
- **Date de vérification** : chaque entrée enregistre quand le contenu a été dernièrement recoupé par rapport à l'état on-chain / API et au code source du programme. Si non indiqué, supposez la date principale de l'entrée.
- **Changements cassants** : signalés dans un avertissement encadré sur les pages affectées et marqués dans l'entrée.
- **Couverture** : ce journal couvre l'ensemble de documentation lui-même. La chronologie historique du protocole vit dans [`introduction/history-and-milestones`](/fr/introduction/history-and-milestones) et est la source de vérité pour « quand X s'est-il produit sur Raydium ».
