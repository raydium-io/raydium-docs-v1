## Fonctionnement des codes d'erreur Anchor

Anchor assigne à chaque variante de l'énumération `ErrorCode` d'un programme un code numérique commençant à `6000`. Une transaction échouée affiche :

- **Code d'erreur numérique** (par ex. `0x1771` = 6001) dans les logs de la transaction.
- **Nom de l'erreur** (par ex. `InvalidOwner`) depuis l'IDL.
- **Chaîne `#[msg(...)]`** qu'Anchor a émise dans `log_messages`.

Les intégrateurs doivent faire correspondre le **code numérique**, pas la chaîne de message (la chaîne peut être reformulée sans augmenter une version).

```ts
// Exemple : détecter l'erreur de slippage CPMM et afficher un message UX propre.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

## Erreurs AMM v4, Farm v3 / v5 / v6, LaunchLab

Ces programmes sont documentés dans leurs chapitres respectifs (voir [`products/amm-v4/instructions`](/fr/products/amm-v4/instructions), [`products/farm-staking/instructions`](/fr/products/farm-staking/instructions), [`products/launchlab/instructions`](/fr/products/launchlab/instructions)). Les codes ci-dessous sont réservés par ces chapitres :

La version LaunchLab conserve les codes `6000`–`6021` inchangés. Elle supprime les anciennes erreurs d'accès global à la plateforme et assigne `6022` à la nouvelle erreur de validation du compte d'autorisation :

| Code | Nom | Signification |
|------|-----|---------------|
| 6018 | `NotEnoughRemainingAccounts` | Un compte restant requis est manquant. Cela inclut un `PlatformAllowConfig` requis et l'ensemble de comptes de migration CPMM étendu. |
| 6022 | `InvalidPlatformAllowConfig` | Le compte d'autorisation fourni n'encode pas la paire de plateforme et de configuration globale attendue. |

Les anciennes variantes `PlatformGlobalAccessDenied` (`6022`) et `InvalidPlatformGlobalAccess` (`6023`) sont supprimées. Ne décodez pas `6022` en utilisant l'IDL précédent.

## Mappage des erreurs SDK aux erreurs du programme

Le SDK TypeScript officiel enveloppe les erreurs on-chain dans `SendTransactionError` et, pour les programmes Anchor, `AnchorError` :

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspectez err.logs pour la ligne "custom program error: 0x...".
  }
}
```

Si vous n'utilisez pas le client Anchor, analysez les logs de la transaction :

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Le motif `Error Number: (\d+)` est stable entre les versions d'Anchor et sûr à faire correspondre.

## Régénération de ces tableaux

Lorsqu'un programme est mis à niveau et ajoute une nouvelle erreur, réextrayez de la source :

```bash
# Clonez et grep l'énumération d'erreur dans l'ordre.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Remplacez 6000+++ par 6000,6001,... en augmentant de manière monotone. Ajoutez les nouvelles lignes au tableau ci-dessus.
```

Mettez toujours à jour [`reference/changelog`](/fr/reference/changelog) lorsqu'une nouvelle variante est ajoutée, afin que les intégrateurs mettant à niveau le SDK sachent actualiser leurs gestionnaires d'erreurs.
