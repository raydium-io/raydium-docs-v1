## Fonctionnement des codes d'erreur Anchor

Anchor assigne à chaque variante de l'énumération `ErrorCode` d'un programme un code numérique commençant à `6000`. Une transaction échouée affiche :

- **Code d'erreur numérique** (ex. `0x1771` = 6001) dans les logs de la transaction.
- **Nom de l'erreur** (ex. `InvalidOwner`) depuis l'IDL.
- **Chaîne `#[msg(...)]`** qu'Anchor a émise dans `log_messages`.

Les intégrateurs doivent faire correspondre le **code numérique**, pas la chaîne de message (la chaîne peut être reformulée sans augmenter une version).

```ts
// Exemple : détecter l'erreur de slippage CPMM et afficher un message UX propre.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

### AMM v4 : `AmmError` n'est pas numéroté à la manière d'Anchor

AMM v4 est antérieur à Anchor. `AmmError` est une énumération `thiserror` simple avec `FromPrimitive`, convertie via `ProgramError::Custom(e as u32)`, donc ses codes commencent à **`0`**, pas `6000` — et, comme ceux d'Anchor, sont assignés par ordre source. La mise à niveau de 2026-09 ajoute une variante :

| Code | Variante | Chaîne `#[error]` | Cause |
|---|---|---|---|
| 60 | `LamportsCalculateError` | Lamports calculate error. | `WithdrawExcessLamports` a vidé un compte SOL enveloppé et l'aller-retour `SyncNative` → `UnwrapLamports` n'a pas laissé le solde du token enveloppé exactement où il a commencé. Chemin réservé à l'administrateur. |

Les codes `0`–`59` restent inchangés, rien ne se décale donc. Dans les journaux de transaction, cela s'affiche comme `custom program error: 0x3c`. Source de régénération : [github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs).

## Mappage des erreurs SDK aux erreurs de programme

Le SDK TypeScript officiel enveloppe les erreurs on-chain dans `SendTransactionError` et, pour les programmes Anchor, `AnchorError` :

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

Si vous n'utilisez pas Anchor côté client, analysez les journaux de transaction :

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Le motif `Error Number: (\d+)` est stable entre les versions d'Anchor et sûr à utiliser.

## Régénération de ces tableaux

Quand un programme est mis à niveau et ajoute une nouvelle erreur, réextrayez depuis la source :

```bash
# Clone and grep the error enum in order.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Replace 6000+++ with monotonically-increasing 6000,6001,... Append new rows to the table above.
```

Mettez toujours à jour [`reference/changelog`](/fr/reference/changelog) quand une nouvelle variante est ajoutée, afin que les intégrateurs mettant à niveau le SDK sachent rafraîchir leurs gestionnaires d'erreurs.
