## Configuration

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
```

```ts
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import BN from "bn.js";
import bs58 from "bs58";

const connection = new Connection(clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(bs58.decode(process.env.PRIVATE_KEY!));

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });

// REQUIS avant tout devis de pool Stable. initLayout() récupère la table de
// recherche ModelDataInfo on-chain dans raydium.liquidity.stableLayout.
await raydium.liquidity.initLayout();
```

<Warning>
  **`initLayout()` n'est pas optionnel pour les pools Stable.** `liquidity.computeAmountOut` se branche sur `poolInfo.version` : pour la version 4, elle utilise la formule à produit constant, et pour tout le reste, elle lit `this.stableLayout.stableModelData` et interpole la table de recherche. Ce cache est vide jusqu'à ce que `initLayout()` s'exécute, donc le devis d'un pool v5 sans lui produit des résultats incorrects plutôt qu'une erreur. C'est idempotent et peu coûteux — appelez-le une fois au démarrage.

  Les constructeurs de transactions (`swap`, `addLiquidity`, `removeLiquidity`) n'en ont pas besoin : ils se distribuent sur `pooltype.includes("StablePool")` et émettent des instructions `AmmV5*`, et les limites de montant que vous transmettez sont déjà calculées.
</Warning>

<Warning>
  **`liquidity.computeAmountIn` ne supporte pas les pools Stable.** Contrairement à `computeAmountOut`, il n'a pas de branche de version — il applique toujours l'inverse à produit constant, donc sur un pool v5, il retourne un `maxAmountIn` incorrect. Pour un swap à sortie exacte contre un pool Stable, inversez avec `getDxByDyBaseIn` vous-même (voir [Assistants de devis hors chaîne](#assistants-de-devis-hors-chaîne-stablets) ci-dessous) et transmettez le résultat à `swap` avec `fixedSide: "out"`.
</Warning>

## Identifier un pool Stable

Deux signaux équivalents sur `ApiV3PoolInfoStandardItem` :

```ts
const isStable =
  pool.version === 5 ||
  pool.pooltype.includes("StablePool"); // le SDK utilise cette vérification de chaîne en interne

// Alternativement, par ID de programme :
const STABLE_AMM_PROGRAM_ID = "5quBtoiQqxF9Jv6KYKctB59NT3gtJD2Y65kdnB1Uev3h";
const isStableByProgram = pool.programId === STABLE_AMM_PROGRAM_ID;
```

À la fois AMM v4 (`version: 4`, produit constant) et Stable AMM (`version: 5`) passent par la même API `LiquidityModule` sur le SDK. En interne, le module se distribue à :

- `InstructionType.AmmV4AddLiquidity` / `AmmV4RemoveLiquidity` pour les pools v4
- `InstructionType.AmmV5AddLiquidity` / `AmmV5RemoveLiquidity` pour les pools v5 (Stable)

Le `programId` du pool (retourné avec les clés du pool) indique au SDK quel programme appeler via CPI ; vous n'avez pas besoin de le coder en dur.

## Trouver un pool par paire de mints

```ts
import { PublicKey } from "@solana/web3.js";
import type { ApiV3PoolInfoStandardItem } from "@raydium-io/raydium-sdk-v2";

// Deux mints courants à utiliser comme exemple
const mintA = new PublicKey("Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB"); // USDT — voir reference/program-addresses
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// fetchPoolByMints retourne une enveloppe paginée : { count, data, hasNextPage }
const res = await raydium.api.fetchPoolByMints({
  mint1: mintA.toBase58(),
  mint2: mintB.toBase58(),
});

const stablePool = res.data.find(
  (p) => p.version === 5 || p.pooltype.includes("StablePool"),
) as ApiV3PoolInfoStandardItem | undefined;

if (!stablePool) {
  throw new Error("Aucun pool Stable n'existe pour cette paire de mints");
}

console.log("ID du pool Stable :", stablePool.id);
console.log("ID du programme du pool Stable :", stablePool.programId);
console.log("TVL :", stablePool.tvl);
```

Si la paire de mints a à la fois un pool v4 (produit constant) et un pool v5 (stable), la réponse inclut les deux — choisissez celui dont votre flux a besoin, ou transmettez-les au programme [AMM Routing](/fr/products/routing) et laissez-le choisir la meilleure route.

## Effectuer un swap via un pool Stable

Le flux `LiquidityModule.swap` a la même forme que pour les pools v4 — transmettez-lui simplement un objet pool v5. Deux détails sont faciles à se tromper : `computeAmountOut` a besoin des **réserves en direct** du pool greffées sur les infos du pool (l'élément API seul ne les porte pas), et son `slippage` est un **nombre** simple, pas un `Percent` :

```ts
import BN from "bn.js";

const amountIn = new BN(1_000_000); // 1 USDT (6 décimales), unités brutes

// Réserves en direct + statut. Sur mainnet, vous pouvez aussi prendre poolKeys de
// getAmmPoolKeys(poolId) et les réserves de getRpcPoolInfo(poolId).
const rpcData  = await raydium.liquidity.getRpcPoolInfo(stablePool.id);
const poolKeys = await raydium.liquidity.getAmmPoolKeys(stablePool.id);

const out = raydium.liquidity.computeAmountOut({
  poolInfo: {
    ...stablePool,
    baseReserve:  rpcData.baseReserve,
    quoteReserve: rpcData.quoteReserve,
    status:       rpcData.status.toNumber(),
    version:      5, // 5 = Stable ; la branche de courbe est sélectionnée sur ceci
  },
  amountIn,
  mintIn:  stablePool.mintA.address,
  mintOut: stablePool.mintB.address,
  slippage: 0.005, // nombre simple : 0.005 = 0.5% (plage 1 ~ 0.0001)
});

// amountOut / minAmountOut sont BN en unités brutes, pas TokenAmount.
console.log("Sortie attendue :", out.amountOut.toString());
console.log("Sortie minimale :", out.minAmountOut.toString());

// Construisez et signez la transaction de swap. `inputMint` est requis — sans lui, le
// SDK ne peut pas dire de quel côté du pool vous vendez.
const { transaction, execute } = await raydium.liquidity.swap({
  poolInfo:  stablePool,
  poolKeys,
  amountIn,
  amountOut: out.minAmountOut, // out.amountOut est la figure pré-slippage
  inputMint: stablePool.mintA.address,
  fixedSide: "in",
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Tx de swap Stable :", txId);
```

Le SDK lit le `programId` du pool à partir des clés du pool et se distribue dans le programme Stable AMM. Aucun argument `programId` spécial n'est nécessaire.

## Ajouter et retirer de la liquidité

`addLiquidity` et `removeLiquidity` fonctionnent de manière identique sur les pools v4 et v5 :

```ts
import { Percent, TokenAmount, toToken } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

const inputAmount = "100"; // 100 USDT, en unités humaines — computePairAmount prend une chaîne décimale

// Calculez le montant B correspondant que la courbe exige pour cette taille de A.
// Remarque : le slippage de computePairAmount EST un Percent (contrairement à celui de computeAmountOut).
const r = raydium.liquidity.computePairAmount({
  poolInfo: stablePool,
  amount:   inputAmount,
  baseIn:   true,
  slippage: new Percent(50, 10_000), // 0.5%
});

const { execute } = await raydium.liquidity.addLiquidity({
  poolInfo: stablePool,
  poolKeys,
  amountInA: new TokenAmount(
    toToken(stablePool.mintA),
    new Decimal(inputAmount).mul(10 ** stablePool.mintA.decimals).toFixed(0),
  ),
  amountInB: new TokenAmount(
    toToken(stablePool.mintB),
    new Decimal(r.maxAnotherAmount.toExact()).mul(10 ** stablePool.mintB.decimals).toFixed(0),
  ),
  otherAmountMin: r.minAnotherAmount,
  fixedSide:      "a",
  txVersion:      TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Tx d'ajout de liquidité :", txId);
```

En interne, le SDK émet `InstructionType.AmmV5AddLiquidity` parce que `pooltype.includes("StablePool")` est vrai. Le flux `removeLiquidity` correspondant est symétrique — transmettez `lpAmount` et les montants minimums que vous accepterez de chaque côté.

## Assistants de devis hors chaîne (stable.ts)

Pour les devis côté serveur ou le backtesting, le SDK expose les mathématiques de courbe stable sous-jacentes :

```ts
import {
  getStablePrice,
  getDxByDyBaseIn,
  getDyByDxBaseIn,
} from "@raydium-io/raydium-sdk-v2";

// Vous devez appeler initLayout() une fois avant d'utiliser ceux-ci (charge le
// PDA `ModelDataInfo` on-chain dans le cache StableLayout du SDK).
await raydium.liquidity.initLayout();

// initLayout() remplit l'instance StableLayout ; l'objet de données simples que
// les trois assistants ci-dessous attendent est son getter `stableModelData`, PAS l'instance.
const modelData = raydium.liquidity.stableLayout.stableModelData;

// Les réserves sont transmises comme des nombres simples en unités humaines (pas BN, pas unités brutes).
const coinReserve = 1_200_000; // réserve du côté coin du pool
const pcReserve   = 1_150_000; // réserve du côté pc du pool

// Prix au comptant aux réserves actuelles du pool. Le 4e argument est `baseCoin` :
// true retourne coin-par-pc, false retourne la réciproque.
const price = getStablePrice(modelData, coinReserve, pcReserve, true);
console.log("Prix au comptant :", price);

// Devis : étant donné dx en entrée, combien de dy en sortie (sans frais appliqués) ?
const dyOut = getDyByDxBaseIn(modelData, coinReserve, pcReserve, 1_000);

// Devis : étant donné la cible dy en sortie, combien de dx en entrée est nécessaire ?
const dxIn  = getDxByDyBaseIn(modelData, coinReserve, pcReserve, 1_000);
```

Ce sont des fonctions pures — pas de RPC, pas de signature. Le `ModelDataInfo` on-chain est récupéré une fois par `initLayout()` et mis en cache dans `raydium.liquidity.stableLayout`, lisible comme `.stableModelData`. `initStableModelLayout()` est idempotent : il ne re-récupère que si `validDataCount === 0`, donc appeler `initLayout()` à nouveau est gratuit. Transmettez les réserves actuelles (`x`, `y`) et les assistants calculent en recherchant binaire dans la table de recherche et en interpolant linéairement entre les deux lignes `DataElement` environnantes. Voir [`products/stable/math`](/fr/products/stable/math) pour l'algorithme sous-jacent.

## Routage via AMM Routing (multi-hop / meilleur prix)

Si vous ne voulez pas choisir un lieu vous-même, le programme [AMM Routing](/fr/products/routing) considérera chaque Raydium AMM (v4 / CPMM / CLMM / Stable) et routera via la combinaison la meilleure :

Le routeur est un pipeline de cinq appels plutôt qu'un seul `swap()`, et il est écrit en entier — avec le conseil de mise en cache qui le rend utilisable en production — sur [`products/routing/code-demos`](/fr/products/routing/code-demos). La forme est :

```ts
import { Router } from "@raydium-io/raydium-sdk-v2";

const poolData = await raydium.tradeV2.fetchRoutePoolBasicInfo(); // mettez ceci en cache
const routes   = raydium.tradeV2.getAllRoute({ inputMint: mintA, outputMint: mintB, ...poolData });
const ctx      = await raydium.tradeV2.fetchSwapRoutesData({ routes, inputMint: mintA, outputMint: mintB });
const quotes   = raydium.tradeV2.getAllRouteComputeAmountOut({ /* ...ctx, amount, slippage, ... */ });

const best = quotes[0]; // trié meilleur en premier
if (!best) throw new Error("aucune route de swap n'a été trouvée");

// Les entrées best.poolInfoList portent `version` — 5 marque un pool Stable dans le chemin.
console.log(best.routeType, best.poolInfoList.map((p) => p.version));

const poolKeys = await raydium.tradeV2.computePoolToPoolKeys({
  pools: best.poolInfoList,
  ammRpcData:  ctx.ammPoolsRpcInfo,
  clmmRpcData: ctx.clmmPoolsRpcInfo,
});

const { execute } = await raydium.tradeV2.swap({
  routeProgram: Router,
  swapInfo:     best,
  swapPoolKeys: poolKeys,
  ownerInfo:    { associatedOnly: true, checkCreateATAOwner: true },
  txVersion:    TxVersion.V0,
});

// tradeV2.swap peut retourner plusieurs transactions ; la première crée les ATA intermédiaires.
const { txIds } = await execute({ sequentially: true });
```

<Warning>
  Il n'y a pas de `raydium.tradeV2.fetchRoutes`, et `tradeV2.swap` n'accepte **pas** `inputMint` / `outputMint` / `slippage` — il prend un `swapInfo` déjà calculé de `getAllRouteComputeAmountOut`. Pour un **seul** pool connu, utilisez le constructeur de ce type de pool (`raydium.liquidity.swap` pour AMM v4 et Stable, `raydium.cpmm.swap`, `raydium.clmm.swap`) comme montré plus tôt sur cette page.
</Warning>

C'est le chemin recommandé pour les swappeurs et agrégateurs en production — vous n'avez jamais besoin de décider manuellement si un pool Stable existe ou s'il est le meilleur lieu aujourd'hui.

## Recommandations

1. **Pour les swaps des utilisateurs finaux**, préférez le flux de routage [`tradeV2`](/fr/products/routing). Il gère chaque type de pool Raydium, y compris Stable.
2. **Pour les opérations spécifiques au pool** (ajout/suppression de LP sur un pool Stable connu), utilisez directement `LiquidityModule` — il détecte automatiquement les pools v5.
3. **Pour les devis hors chaîne / analytique**, appelez `getStablePrice` / `getDyByDxBaseIn` / `getDxByDyBaseIn` après `initLayout()`. Pas de trafic RPC par devis après que les données du modèle soient mises en cache.
4. **Ne codez pas en dur les instructions `SwapBaseIn` brutes.** La [mise à jour du 2026-06-22](/fr/reference/changelog) a supprimé les comptes OpenBook morts, donc la nouvelle disposition de swap prend **9 comptes** (l'ancienne disposition de 18 comptes analyse toujours pour la compatibilité rétroactive). `Deposit` est maintenant 12 comptes (anciens 14 compatibles), `Withdraw` 12 (anciens 21/22 compatibles), et `WithdrawPnl` 10 sans **aucun** chemin de compatibilité. Les assistants pré-construits du SDK sélectionnent la disposition et l'ordre corrects pour vous ; rouler le vôtre est sujet aux erreurs. Voir [`products/stable/instructions`](/fr/products/stable/instructions) pour les tableaux de comptes complets.
