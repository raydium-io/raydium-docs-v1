## Le modèle de frais

Le Stable AMM réutilise la structure **`Fees`** d'AMM v4, mais pas les **chiffres** d'AMM v4. Les pools Stable appliquent des frais beaucoup plus bas, ce qui est attendu pour un pool conçu pour des actifs au prix similaire. Il n'existe qu'un seul palier de frais par pool (défini à l'initialisation) ; les pools ne peuvent pas être reconfigurés vers des paliers supérieurs.

| Champ | Valeur on-chain | Signification |
|-------|-----------------|---------------|
| `swap_fee_numerator / swap_fee_denominator` | `2 / 10_000` | **Frais bruts de trading : 0,02%** du volume d'entrée. C'est le seul frais réellement prélevé. |
| `trade_fee_numerator / trade_fee_denominator` | `0 / 10_000` | **Zéro.** Champ hérité autrefois utilisé pour la tarification des ordres OpenBook ; conservé pour la compatibilité de mise en page, n'est plus lu. |
| `pnl_numerator / pnl_denominator` | `12 / 100` | **Part du protocole dans les frais : 12%** — c'est-à-dire `0,02% × 12% = 0,0024%` du volume. |
| `min_separate_numerator / min_separate_denominator` | `4 / 10_000` | Seuil de séparation minimale utilisé lors de la division du PnL hors des frais bruts. |

<Note>
  Ce ne sont pas des « valeurs par défaut » — ce sont les valeurs sur **chaque** pool Stable actif sur mainnet. Les trois pools (USDT/USDC `2EXiumdi14E9b8Fy62QcA5Uh6WdHS2b38wtSxp72Mibj`, `9DTY3rv8xRa3CnoPoWJCMcQUSY7kUHZAoFKNsBhx8DDz`, `9f4FtV6ikxUZr8fAjKSGNPPnUHJEwi4jNk8d79twbyFf`) portent l'ensemble identique ci-dessus, et avec `SetParams` supprimé lors de la mise à jour du 2026-06-22, il n'existe plus aucune instruction capable de les modifier. Vérifié en décodant les champs `AmmInfo.fees` depuis les pools mainnet actifs.
</Note>

Il n'y a **pas de frais de fonds** et **pas de frais de créateur** — ce sont des inventions post-AMM v4 (CPMM/CLMM). Le Stable AMM est antérieur à cette convention.

## Comment la répartition est calculée

À chaque swap :

```
gross_fee = ceil(amount_in * (swap_fee_numerator / swap_fee_denominator))    // 0.02% of amount_in
pnl_portion = gross_fee * (pnl_numerator / pnl_denominator)                  // 12% of gross_fee
lp_portion = gross_fee − pnl_portion                                          // 88% of gross_fee
```

- **`lp_portion`** reste dans le coffre, augmente `k`, et bénéficie aux LP lors du retrait.
- **`pnl_portion`** incrémente `AmmInfo.out_put.need_take_pnl_coin` ou `need_take_pnl_pc` (selon le token d'entrée) et est collectée par `WithdrawPnl`.

Même **astuce de préservation d'invariant** que CPMM : le montant du PnL se trouve physiquement dans le coffre mais est soustrait des « réserves effectives » utilisées dans les mathématiques de la courbe, donc le retirer ne change pas le prix.

## PnL OpenBook (retiré)

Au début de sa vie, le pool postait également des ordres limites sur OpenBook ; lorsque ceux-ci étaient exécutés, il gagnait ou perdait le spread market-maker/taker, réglé lors de `MonitorStep`, et le résultat était suivi dans les compteurs `out_put.total_pnl_{coin,pc}`. **Ce chemin est dormant depuis des années** — le pool ne détient aucun ordre ouvert, donc le seul accrual de frais est la part du protocole de 0,0024% décrite ci-dessus. Les compteurs `total_pnl_*` restent dans la mise en page mais n'augmentent plus. La mise à jour du [2026-06-22](/fr/reference/changelog) a supprimé le code OpenBook restant (y compris `MonitorStep`). CPMM est devenu le défaut pour les nouveaux pools en partie à cause de cet ancien couplage à OpenBook ; le Stable AMM est indépendant du carnet d'ordres.

## Collecte

Le multisig Raydium (ou celui qui contrôle `amm_admin`) appelle `WithdrawPnl` pour collecter :

1. Transfère `need_take_pnl_coin` et `need_take_pnl_pc` des coffres vers les comptes désignés par l'admin.
2. Réinitialise les compteurs.

L'opération ne déplace pas la courbe. Les LP ne voient aucun changement de prix.

<Warning>
  `WithdrawPnl` a été modifié lors de la mise à jour du 2026-06-22 : il utilise désormais une **mise en page fixe de 10 comptes, réservée à l'admin, sans chemin de compatibilité** (les anciennes mises en page échouent avec des erreurs comme `InvalidTokenCoin`), et lorsque les fonds disponibles du pool sont insuffisants pour couvrir le PnL, il retourne `TakePnlError` directement au lieu de désactiver le pool. Voir [`products/stable/instructions`](/fr/products/stable/instructions#withdrawpnl).
</Warning>

## Rédemption des frais LP

Aucune instruction dédiée « collecter les frais ». Les frais LP s'accumulent dans les coffres, augmentant les réserves. Les LP les réalisent en brûlant des LP via `Withdraw`. La valeur d'un token LP augmente à mesure que les réserves augmentent.

## Visualisation : où vont \$10 000 de volume

Sur un `Swap` de \$10 000 lourd en USDC contre un pool Stable actif :

```
Gross trade fee (0.02%):       $2.0000
  LP share   (0.0176%):         $1.7600  → stays in pool, raises k
  PnL share  (0.0024%):         $0.2400  → need_take_pnl_pc, swept by WithdrawPnl
User receives (minus curve):  $9,998.00
```

Les mêmes \$10 000 via un pool AMM v4 coûtent \$25,00, et via un pool CPMM `index=0` \$25,00 — **12,5× plus**. Cet écart est le point du produit : les paires stables bougent très peu, donc les LP ont besoin de très peu de compensation pour le risque d'inventaire, et la courbe serrée plus les frais bas est ce qui garde les grands swaps stable-to-stable compétitifs.

## Notes pour les intégrateurs

- **Cotation :** Lisez toujours `AmmInfo` depuis la chaîne ; ne codez pas les frais en dur. Avec `SetParams` désormais supprimé, les paramètres de frais sur les pools existants sont effectivement fixes.
- **Ne supposez pas le taux d'AMM v4.** La structure `Fees` est partagée avec AMM v4, il est donc facile de copier `25 / 10_000` d'AMM v4 dans une cotation Stable. Les pools Stable appliquent `2 / 10_000`. Coter un pool Stable à 0,25% surestime les frais de 12,5×.
- **Courbe vs. frais :** L'application des frais est indépendante du fait que la courbe soit une formule (x·y=k dans AMM v4) ou une table de recherche (Stable). Les deux prélèvent les frais sur le montant d'entrée avant de toucher à la courbe.
- **Pas de récompenses :** Les pools Stable ne supportent pas les émissions de récompenses on-pool. Les fermes écosystème (Farm v3/v5/v6) gèrent le staking ailleurs.
