## Ce qui se trouve sur cette page

Les flux ci-dessous couvrent le cycle de vie pertinent pour l'intégrateur :

1. Configuration du compte — dépôt d'USDC et enregistrement du compte auprès d'Orderly.
2. Appels REST authentifiés — demande de signature pour le placement d'ordres, l'annulation et les requêtes de compte.
3. Trading — placement d'ordres au marché/limités, annulation, récupération des positions et des remplissages.
4. Données de marché — souscription au carnet d'ordres et au WebSocket de trading.
5. Retrait — initiation d'un retrait vers le portefeuille.

Ces extraits ciblent Node.js + TypeScript avec `@solana/web3.js` et `tweetnacl` pour la signature Ed25519. Ils sont des **points de départ** — la surface de l'API d'Orderly est large et change plus vite que cette page ; consultez toujours la documentation en direct d'Orderly avant de déployer du code en production.

## Configuration

```ts
import { Connection, Keypair, PublicKey, clusterApiUrl } from "@solana/web3.js";
import nacl from "tweetnacl";
import bs58 from "bs58";
import fs from "node:fs";

// 1. Portefeuille Solana — possède l'USDC, signe les transactions de dépôt/retrait.
const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

// 2. Clé de trading Orderly — paire de clés Ed25519 distincte utilisée pour signer les requêtes API.
//    PAS le portefeuille Solana. Générez une fois, gardez-la secrète, réutilisez-la entre les sessions.
const orderlyKey = nacl.sign.keyPair();   // ed25519
const orderlyPubB58 = "ed25519:" + bs58.encode(orderlyKey.publicKey);

// 3. URL de base d'Orderly. Raydium utilise l'hôte mainnet d'Orderly.
const ORDERLY_BASE = "https://api.orderly.org";
const BROKER_ID    = "raydium";   // Espace de noms du courtier Raydium sur Orderly
const CHAIN_ID     = "solana";    // pour l'enregistrement du compte inter-chaînes
```

La clé de trading Orderly n'est **pas** votre paire de clés de portefeuille. C'est une clé de signature de requête que vous enregistrez auprès de votre portefeuille lors de la première utilisation ; vous pouvez la faire tourner sans toucher aux fonds. Traitez-la comme une credential de session.

## Enregistrement du compte

Avant de placer des ordres, enregistrez le portefeuille auprès d'Orderly :

```ts
import { encodeUserSettlement } from "./eip712-helpers"; // consultez la documentation d'Orderly pour la charge utile exacte

// 1. Demandez un nonce d'enregistrement à Orderly.
const nonceResp = await fetch(`${ORDERLY_BASE}/v1/registration_nonce`).then(r => r.json());
const registrationNonce = nonceResp.data.registration_nonce;

// 2. Signez une charge utile d'enregistrement avec le portefeuille Solana (EIP-712-style sur Solana
//    est implémenté comme un message structuré ; le SDK d'Orderly fournit l'encodeur).
const payload = encodeUserSettlement({
  brokerId: BROKER_ID,
  chainId: CHAIN_ID,
  registrationNonce,
  timestamp: Date.now(),
});
const walletSig = nacl.sign.detached(Buffer.from(payload), owner.secretKey);

// 3. Enregistrez, en incluant la clé de trading Ed25519 d'Orderly.
const reg = await fetch(`${ORDERLY_BASE}/v1/register_account`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: payload,
    signature: bs58.encode(walletSig),
    userAddress: owner.publicKey.toBase58(),
    orderlyKey: orderlyPubB58,
  }),
}).then(r => r.json());

console.log("Account ID:", reg.data.account_id);
```

Les ID de compte sont déterministes par paire `(broker_id, wallet_address)` — l'enregistrement est idempotent. Si un portefeuille s'est déjà enregistré auprès du courtier Raydium, l'appel retourne le même ID de compte sans en créer un nouveau.

## Dépôt d'USDC

Les dépôts déplacent l'USDC du portefeuille ATA vers le coffre de règlement d'Orderly. Ce sont des transactions Solana on-chain :

```ts
// Construisez l'instruction de dépôt en utilisant le programme Solana d'Orderly (l'ID du programme du coffre est
// publié dans leur documentation ; récupérez-le dynamiquement plutôt que de le coder en dur).
const vaultProgramId = new PublicKey("<orderly_solana_vault_program_id>");

const depositIx = await buildOrderlyDepositIx({
  vaultProgramId,
  user: owner.publicKey,
  brokerId: BROKER_ID,
  amountUsdc: BigInt(100_000_000),    // 100 USDC (6 décimales)
});

const tx = new Transaction().add(depositIx);
const sig = await connection.sendTransaction(tx, [owner]);
await connection.confirmTransaction(sig, "confirmed");
console.log("Deposit tx:", sig);
```

Après environ 30 secondes, le relayeur d'Orderly indexe le dépôt et le solde s'affiche sous la marge libre du compte. Interrogez `/v1/client/holding` pour confirmer :

```ts
const holdingResp = await orderlyAuthGet("/v1/client/holding");
console.log("Balances:", holdingResp.data.holding);
```

(`orderlyAuthGet` est défini ci-dessous — chaque appel authentifié passe par lui.)

## Aide à la signature de requête

Chaque appel REST authentifié à Orderly porte une signature Ed25519 sur `(timestamp + method + path + body)` :

```ts
async function orderlyAuthRequest(
  method: "GET" | "POST" | "PUT" | "DELETE",
  path: string,
  body?: unknown,
): Promise<any> {
  const ts   = Date.now().toString();
  const json = body ? JSON.stringify(body) : "";
  const msg  = `${ts}${method}${path}${json}`;
  const sig  = nacl.sign.detached(Buffer.from(msg), orderlyKey.secretKey);

  const resp = await fetch(ORDERLY_BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json",
      "orderly-account-id":  /* l'account_id enregistré */ "",
      "orderly-key":         orderlyPubB58,
      "orderly-signature":   bs58.encode(sig),
      "orderly-timestamp":   ts,
    },
    body: json || undefined,
  });
  return resp.json();
}

const orderlyAuthGet  = (p: string)            => orderlyAuthRequest("GET",  p);
const orderlyAuthPost = (p: string, b: object) => orderlyAuthRequest("POST", p, b);
const orderlyAuthDel  = (p: string)            => orderlyAuthRequest("DELETE", p);
```

Protection contre la relecture : les requêtes avec un `timestamp` décalé de plus de 5 secondes par rapport à l'horloge du serveur sont rejetées. Synchronisez votre horloge (NTP) et évitez de signer les requêtes à l'avance.

## Placer un ordre au marché

```ts
const marketResp = await orderlyAuthPost("/v1/order", {
  symbol:        "PERP_SOL_USDC",
  order_type:    "MARKET",
  side:          "BUY",
  order_quantity: 1.0,        // 1 SOL de position
  reduce_only:    false,
});

if (marketResp.success) {
  console.log("Order ID:", marketResp.data.order_id);
} else {
  console.error("Reject:", marketResp.message);
}
```

Les ordres au marché s'exécutent immédiatement. La réponse retourne l'`order_id` résultant plus un statut. Les remplissages arrivent via le WebSocket (voir ci-dessous) ; la réponse REST elle-même ne bloque pas jusqu'à être complètement remplie.

## Placer un ordre limité avec Post-Only

```ts
const limitResp = await orderlyAuthPost("/v1/order", {
  symbol:         "PERP_SOL_USDC",
  order_type:     "LIMIT",
  side:           "SELL",
  order_quantity: 0.5,
  order_price:    140.50,
  // combinaisons de drapeaux :
  // post_only: true rend cet ordre réservé aux créateurs de marché — annulé s'il croiserait.
  // reduce_only / time_in_force sont indépendamment configurables.
  post_only:      true,
});
console.log(limitResp);
```

Pour `IOC` / `FOK`, définissez `time_in_force: "IOC"` ou `"FOK"`. Consultez [`products/perps/order-types`](/fr/products/perps/order-types) pour la sémantique de chaque drapeau.

## Annuler un ordre

```ts
// Par ID d'ordre
await orderlyAuthDel(`/v1/order?order_id=${orderId}&symbol=PERP_SOL_USDC`);

// Annuler TOUS les ordres sur un symbole
await orderlyAuthDel(`/v1/orders?symbol=PERP_SOL_USDC`);
```

Une annulation est reconnue de manière synchrone mais l'annulation réelle peut être en concurrence avec un remplissage. Réconciliez toujours en interrogeant `/v1/orders` ou en regardant le WebSocket — supposer qu'une annulation a réussi sans confirmation peut entraîner des positions dupliquées ou involontaires.

## Récupérer les positions ouvertes

```ts
const posResp = await orderlyAuthGet("/v1/positions");
for (const p of posResp.data.rows) {
  console.log(
    p.symbol,
    "size:",  p.position_qty,
    "entry:", p.average_open_price,
    "unrealized:", p.unsettled_pnl,
  );
}
```

Un `position_qty` négatif est une vente à découvert, positif est une position longue. `position_qty == 0` signifie que la position est fermée mais la ligne peut toujours s'afficher jusqu'au prochain nettoyage.

## Récupérer l'historique des remplissages

```ts
const fills = await orderlyAuthGet(
  "/v1/trades?symbol=PERP_SOL_USDC&start_t=" + (Date.now() - 86_400_000)
);
for (const t of fills.data.rows) {
  console.log(t.executed_timestamp, t.side, t.executed_quantity, "@", t.executed_price);
}
```

Les arguments de temps sont des timestamps Unix en millisecondes. La taille de page par défaut est 25 lignes ; utilisez les paramètres de requête `page` et `size` pour paginer.

## WebSocket : données de marché

```ts
import WebSocket from "ws";

const ws = new WebSocket(`wss://ws.orderly.org/ws/stream/${accountId}`);

ws.on("open", () => {
  // Données de marché publiques : deltas du carnet d'ordres + trades pour un symbole
  ws.send(JSON.stringify({ id: "ob1", topic: "orderbook@PERP_SOL_USDC" }));
  ws.send(JSON.stringify({ id: "tr1", topic: "trade@PERP_SOL_USDC" }));
});

ws.on("message", (raw) => {
  const msg = JSON.parse(raw.toString());
  if (msg.topic?.startsWith("orderbook@")) {
    // diff de profondeur : { bids: [[price, qty], ...], asks: [[price, qty], ...] }
    applyOrderbookDelta(msg.data);
  } else if (msg.topic?.startsWith("trade@")) {
    console.log("trade:", msg.data);
  }
});
```

Pour le flux **privé** (vos remplissages, mises à jour de position, changements de solde), le WebSocket doit être authentifié. Envoyez une charge utile `subscribe` signée de la même manière que les requêtes REST, limitée à votre ID de compte. La documentation d'Orderly a la forme exacte de la charge utile ; elle change occasionnellement, donc ne codez pas en dur un schéma particulier ici.

## Retrait d'USDC

```ts
// 1. Demandez un retrait.
const wRes = await orderlyAuthPost("/v1/withdraw_request", {
  token:  "USDC",
  chain_id: CHAIN_ID,
  amount: 50.0,                          // unités humaines
  receiver: owner.publicKey.toBase58(),
});

console.log("Withdrawal request id:", wRes.data.withdraw_id);
```

Orderly relaye le retrait on-chain vers l'adresse du destinataire. Il y a des frais de retrait fixes de **1 USDC** (consultez [`products/perps/fees`](/fr/products/perps/fees)). Le transfert on-chain se produit dans 1–2 minutes dans des conditions normales ; attendez-vous à plus long en cas de congestion.

## Pièges

- **Ne réutilisez pas la clé de trading entre les environnements.** Une seule clé de trading Orderly enregistrée auprès de votre portefeuille est associée à un compte mainnet Solana. Si vous avez également besoin de devnet ou de staging, générez une clé distincte pour chacun.
- **Synchronisation de l'horloge.** La tolérance de décalage d'horloge d'Orderly est serrée (±5s). Sur les services de longue durée, la dérive NTP finira par casser la signature. Resynchronisez périodiquement.
- **Reconnexions WebSocket.** Le WS public abandonne occasionnellement les connexions lors des mises à jour d'Orderly. Implémentez un backoff exponentiel et réabonnez-vous à la réouverture.
- **Limites de débit.** Les appels REST sont limités par taux par compte. Annulez en masse via `cancel_all` plutôt que de boucler `cancel`-par-id quand vous avez >5 ordres à annuler.
- **La direction de la position est implicite.** Un ordre `BUY` sur `PERP_SOL_USDC` ouvre ou prolonge une position longue ; un `SELL` ouvre ou prolonge une position courte — mais si vous êtes déjà long, un `SELL` *réduit* (et peut inverser) la position car Raydium Perps est en mode unidirectionnel. Vérifiez toujours la position actuelle avant de placer un ordre si la direction importe.
- **Le financement et les liquidations sont distincts du flux d'ordres.** Les paiements de financement et les liquidations s'affichent comme des flux d'événements distincts ; ce ne sont pas des « ordres ». Abonnez-vous aux sujets WS privés pertinents si vous avez besoin de les observer.
