## Outils principaux

### Solana CLI

L'interface de ligne de commande canonique pour interagir avec les clusters Solana — gestion des portefeuilles, appels RPC, déploiement de programmes.

Installation :

```bash
# La version contre laquelle les programmes Raydium sont construits et testés
sh -c "$(curl -sSfL https://release.anza.xyz/v3.1.10/install)"

# Ou suivre un canal au lieu d'une balise
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"
```

Vérification :

```bash
solana --version   # → solana-cli 3.1.10 (... client:Agave)
```

<Note>
  **L'hôte d'installation a changé.** `release.solana.com` appartenait à Solana Labs ; le client est maintenant maintenu par Anza sous le nom **Agave**, et les versions sont servies depuis `release.anza.xyz`. Le binaire de mise à jour automatique est `agave-install` (`solana-install` est conservé comme alias hérité), donc `agave-install update` et `agave-install init <version>` sont les orthographes actuelles. La documentation de Solana propose également un installateur en une seule commande qui récupère la CLI, Rust et Anchor ensemble :

  ```bash
  curl --proto '=https' --tlsv1.2 -sSfL https://solana-install.solana.workers.dev | bash
  ```

  Cet installateur suit sa propre idée du courant et peut vous remettre un Anchor différent de celui que les programmes Raydium épinglent — vérifiez `anchor --version` après.
</Note>

Configuration pour mainnet :

```bash
solana config set --url https://api.mainnet-beta.solana.com
solana config set --keypair ~/.config/solana/id.json
solana-keygen new                           # créer un portefeuille si vous n'en avez pas
solana address                              # votre clé publique
```

Pour les tests Raydium, vous voudrez presque toujours un portefeuille devnet financé :

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2                            # 2 SOL pour les tests
```

### SPL Token CLI

La CLI officielle pour les opérations SPL Token / Token-2022 — création de mints, frappe de jetons, transferts.

Installation (incluse avec Solana CLI) :

```bash
spl-token --version
```

Opérations courantes :

```bash
spl-token create-token                                  # créer un mint SPL Token
spl-token create-token --program-id TOKEN_2022 ...      # créer un mint Token-2022
spl-token create-account <MINT>                         # créer un ATA
spl-token mint <MINT> 1000                              # frapper 1000 jetons dans votre ATA
spl-token transfer <MINT> 100 <RECIPIENT>               # transférer 100
spl-token display <ACCOUNT_OR_MINT>                     # inspecter
```

### Anchor CLI

Nécessaire pour récupérer les IDLs Raydium, construire des clients et vérifier les programmes.

Installation :

```bash
cargo install --git https://github.com/solana-foundation/anchor avm --locked --force
avm install 1.0.2
avm use 1.0.2
anchor --version   # → anchor-cli 1.0.2
```

<Note>
  **Anchor a changé de dépôt et de version majeure.** Le dépôt canonique est maintenant `github.com/solana-foundation/anchor` (c'était `coral-xyz/anchor`), et Anchor 1.0 est la première ligne de version que les programmes Raydium utilisent — CPMM et LaunchLab épinglent tous deux `anchor-lang`/`anchor-spl` `=1.0.2` à partir de la mise à jour 2026-09-09, en montant de `0.32.1`. `avm` peut contenir plusieurs versions ; `avm use 1.0.2` est ce qui fait que `anchor build` reproduit les artefacts de Raydium. Anchor 1.1 et 1.2 existent et se construisent bien pour vos propres programmes, mais une caisse CPI compilée contre une version mineure `anchor-lang` différente de celle que le programme cible épingle ne se liera pas — voir [`sdk-api/rust-cpi`](/fr/sdk-api/rust-cpi).
</Note>

Opérations courantes :

```bash
anchor idl fetch <PROGRAM_ID> -o program.idl.json       # récupérer l'IDL on-chain
anchor idl init -f idl.json <PROGRAM_ID>                # télécharger un IDL
anchor build                                             # construire un programme à partir de la source
```

## Configuration TypeScript

Le chemin d'intégration principal pour Raydium.

### Paquets

```bash
npm install \
  @solana/web3.js \
  @solana/spl-token \
  @anchor-lang/core \
  @raydium-io/raydium-sdk-v2 \
  bn.js \
  decimal.js
```

Versions connues pour fonctionner ensemble en septembre 2026 :

| Paquet | Version | Remarque |
|---------|---------|------|
| `@solana/web3.js` | `^1.95` | L'API 1.x. `2.x` / `3.x` sont une surface API différente et incompatible ; le SDK Raydium cible 1.x. |
| `@solana/spl-token` | `^0.4.15` | 0.4.15 est ce qui expose `createUnwrapLamportsInstruction` — voir [reclaimable rent](/fr/solana-fundamentals/rent-and-reclaimable-rent). |
| `@anchor-lang/core` | `^1.0` | Le client TypeScript Anchor 1.x. |
| `@raydium-io/raydium-sdk-v2` | `0.2.64-alpha` | L'épingle que chaque démo de code dans ces documents utilise. |

<Note>
  **`@anchor-lang/core` est gelé ; le paquet est maintenant `@anchor-lang/core`.** `@anchor-lang/core` s'est arrêté à `0.32.1` quand Anchor a déménagé à la Solana Foundation. Anchor 1.x publie sous `@anchor-lang/core`, et les propres dépôts de programmes Raydium ont basculé leurs suites de tests vers celui-ci lors de la mise à jour 2026-09-09. Les imports que vous utilisez réellement sont inchangés — `import { Program, BN, AnchorProvider } from "@anchor-lang/core"` — donc la migration est un renommage de paquet plus une mise à jour du fichier de verrouillage.

  Deux remarques comportementales si vous passez de `0.3x` : `.accounts({...})` n'accepte maintenant que les comptes qu'Anchor ne peut pas résoudre lui-même, donc un constructeur qui passe l'ensemble complet doit appeler `.accountsPartial({...})` à la place ; et `@anchor-lang/core/dist/cjs/utils/token` est l'endroit où les aides telles que `ASSOCIATED_PROGRAM_ID` ont déménagé.
</Note>

### Script minimal

```ts
import { Connection, Keypair } from "@solana/web3.js";
import { Raydium } from "@raydium-io/raydium-sdk-v2";

const connection = new Connection("https://api.mainnet-beta.solana.com", "confirmed");
const owner      = Keypair.fromSecretKey(/* your key */);

const raydium = await Raydium.load({
  connection,
  owner,
  cluster:      "mainnet",
  disableFeatureCheck: true,
});

// `ids` est une liste séparée par des virgules, et l'appel retourne un tableau
const [poolInfo] = await raydium.api.fetchPoolById({ ids: "..." });
console.log(poolInfo);
```

Voir [`sdk-api/typescript-sdk`](/fr/sdk-api/typescript-sdk) pour la référence complète du SDK.

## Configuration Rust

Pour l'intégration CPI et les programmes on-chain.

### Chaîne d'outils

```bash
rustup install 1.91.0           # ce que les programmes Raydium épinglent
rustup default 1.91.0
rustup component add rustfmt clippy
agave-install init 3.1.10       # chaîne d'outils SBF incluse
```

Construisez les programmes avec `cargo build-sbf` (l'ancienne orthographe `cargo build-bpf` a disparu).

### Cargo.toml du programme pour une intégration CPI Raydium

```toml
# Intégration CPMM (Anchor 1.0)
[dependencies]
anchor-lang        = "=1.0.2"
anchor-spl         = "=1.0.2"
raydium-cp-swap    = { version = "0.2", features = ["cpi"] }
```

```toml
# Intégration CLMM — toujours Anchor 0.32, donc elle a besoin de sa propre caisse
[dependencies]
anchor-lang        = "=0.32.1"
anchor-spl         = "=0.32.1"
raydium-clmm       = { version = "0.1", features = ["cpi"] }
```

Épinglez `anchor-lang` et `anchor-spl` avec `=` à la version que le programme cible épingle. À partir de 2026-09, CPMM épingle `=1.0.2` et CLMM épingle toujours `=0.32.1`, donc **une seule caisse ne peut pas faire de CPI dans les deux** — voir [`sdk-api/rust-cpi`](/fr/sdk-api/rust-cpi#cargo-dependencies).

La fonctionnalité `"cpi"` importe le module `cpi` avec des aides CPI (donc vous pouvez `raydium_cp_swap::cpi::swap_base_input(...)`). Voir [`sdk-api/rust-cpi`](/fr/sdk-api/rust-cpi).

## Configuration Python

Chemin d'intégration secondaire — courant pour les développeurs de bots.

### Paquets

```bash
pip install solders solana anchorpy
```

Versions :

| Paquet | Nom PyPI | Version |
|---------|-----------|---------|
| `solders` | `solders` | ≥0.29 |
| solana-py | `solana` | ≥0.40 |
| `anchorpy` | `anchorpy` | ≥0.21 |

<Note>
  Deux pièges de nommage. Le client RPC est importé sous `solana` mais le projet s'appelle **solana-py** — `pip install solana-py` n'installe rien d'utile. Et il n'y a **pas de paquet `raydium-py` sur PyPI** : l'aide Raydium communautaire est un dépôt que vous clonez, [`AL-THE-BOT-FATHER/raydium_py`](https://github.com/AL-THE-BOT-FATHER/raydium_py), pas une distribution publiée. Les révisions antérieures de cette page listaient une ligne `pip install raydium-py` qui n'a jamais fonctionné.
</Note>

### Script minimal

```python
from solana.rpc.async_api import AsyncClient
from solders.keypair import Keypair
from anchorpy import Provider, Wallet, Program

async def main():
    conn = AsyncClient("https://api.mainnet-beta.solana.com")
    owner = Keypair()
    wallet = Wallet(owner)
    provider = Provider(conn, wallet)

    # Charger l'IDL et le programme
    with open("cpmm.idl.json") as f:
        idl = json.load(f)
    program = Program(idl, CPMM_PROGRAM_ID, provider)

    pool = await program.account["PoolState"].fetch(pool_id)
    print(pool)
```

## Points de terminaison RPC

Le RPC mainnet public (`api.mainnet-beta.solana.com`) est fortement limité en débit et s'étouffe sous toute charge. Pour une utilisation non triviale, obtenez un point de terminaison privé :

| Fournisseur | Remarques |
|----------|-------|
| Helius | Le plus populaire ; niveau gratuit généreux. |
| Triton | Entreprise ; tarification premium, stable. |
| QuickNode | Solide ; latence sub-par-seconde. |
| Votre propre nœud RPC | Coûte ~\$500/mois en matériel ; contrôle total. |

Configuration :

```ts
const connection = new Connection("https://mainnet.helius-rpc.com/?api-key=...");
```

Certaines opérations RPC nécessitent des capacités étendues :

- `getProgramAccounts` — les analyses sans restriction sont coûteuses ; certains fournisseurs les limitent ou facturent par analyse.
- `getPriorityFeeEstimate` — point de terminaison spécifique à Helius ; les autres ont des équivalents.
- `geyser` / diffusion WebSocket — nécessaire pour les bots à faible latence ; tous les fournisseurs ne l'exposent pas.

## Devnet et localnet

### Devnet

Le cluster de test public de Solana. Raydium a un déploiement devnet partiel :

- Certains pools CPMM existent pour les tests.
- AMM v4 a des pools devnet historiques.
- CLMM a quelques pools de démonstration.
- Farm v6 est déployé.

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2
```

Le SDK supporte devnet via `cluster: "devnet"` :

```ts
const raydium = await Raydium.load({ connection, owner, cluster: "devnet" });
```

**Mise en garde** : les pools devnet ont une liquidité mince et peuvent avoir un état obsolète. Ne comptez pas sur devnet pour la découverte de prix ; utilisez-le uniquement pour construire et tester les flux d'instructions.

### Localnet avec un état mainnet forké

Pour des tests réalistes, forkez l'état mainnet dans un validateur local :

```bash
solana-test-validator \
  --url https://api.mainnet-beta.solana.com \
  --clone CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C \
  --clone CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK \
  --clone <SOME_POOL_ID> \
  --clone <SOME_MINT_ID>
```

Cela clone l'état spécifique du programme/compte vers localhost, où vous pouvez effectuer des transactions librement. Idéal pour :

- Tester unitairement votre intégration CPI contre un vrai programme Raydium.
- Rejouer une transaction avec un paramètre modifié pour déboguer.
- Tester la charge avec de grands volumes synthétiques.

L'équipe Raydium utilise largement le localnet forké pour les tests de régression avant le déploiement mainnet.

## Hygiène de l'environnement

### Portefeuilles séparés par objectif

- **Portefeuille de développement** : contient SOL testnet, utilisé pour la construction.
- **Portefeuille de production** : contient du vrai SOL, utilisé uniquement pour les déploiements / soumissions multisig.
- **Portefeuille chaud pour les bots** : petit solde, permissions étroites.

Les clés ne doivent jamais être codées en dur. Utilisez des variables d'environnement ou des gestionnaires de secrets.

### Modèle `.env`

```
# .env (non commis)
SOLANA_RPC_URL=https://mainnet.helius-rpc.com/?api-key=...
WALLET_PATH=/Users/you/.config/solana/id.json
```

```ts
import { config } from "dotenv";
config();

const connection = new Connection(process.env.SOLANA_RPC_URL!);
```

### Épinglage des versions

Verrouillez toutes les dépendances de l'écosystème Solana. L'écosystème évolue rapidement ; une mise à jour de version mineure de `@solana/web3.js` a précédemment introduit des changements de rupture. Utilisez `package-lock.json` / `Cargo.lock` religieusement.
