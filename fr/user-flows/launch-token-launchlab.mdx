<Info>
  LaunchLab est le principal lieu de lancement de marché primaire de Raydium. Un projet dépose son approvisionnement en tokens dans une courbe de liaison ; les acheteurs échangent contre la courbe en utilisant SOL (ou un autre mint de cotation) ; lorsqu'un seuil de graduation est atteint, les actifs de la courbe migrent automatiquement vers un pool CPMM, et le token devient librement négociable. Cette page vous guide à travers l'ensemble du flux du côté du projet.
</Info>

## Ce dont vous avez besoin

- **Mint du token** — le token que vous souhaitez vendre. Doit être fraîchement créé avec :
  - L'approvisionnement complet créé dans votre portefeuille (pour que vous puissiez le déposer dans la courbe).
  - L'autorité de création révoquée avant le lancement (sinon le prix de la courbe peut être manipulé par de nouvelles créations).
- **Métadonnées** — nom, symbole, image, liens sociaux. Métadonnées Metaplex ou similaires.
- **Portefeuille** — ~1 SOL pour les frais de création + financement du coffre + frais de priorité (la graduation elle-même est payée par le graduateur, pas par vous).
- **Décisions sur** :
  - Type de courbe (quadratique vs CPMM à réserves virtuelles).
  - Seuil de graduation.
  - Politique de disposition des LP (Burn / Lock / ToCreator).
  - Prix initial et plafond.

## Choix de la courbe

LaunchLab supporte deux familles de courbes :

### Quadratique (`curve_type = 0`)

Le prix augmente quadratiquement avec l'approvisionnement vendu. Sensation classique de « lancement équitable » — les premiers acheteurs obtiennent un avantage de prix, les derniers acheteurs paient plus, le prix s'accélère régulièrement.

```
price(s) = a * s^2 + b * s + c
```

où `s` est l'approvisionnement vendu. Généralement `a > 0` (convexe). L'écart entre le prix initial et le prix de graduation est déterministe étant donné `a, b, c` et le plafond.

Idéal pour : lancements de nouveauté, mèmes, projets communautaires.

### CPMM à réserves virtuelles (`curve_type = 1`)

Émule un AMM à produit constant en utilisant des réserves *virtuelles* — la courbe se comporte comme un CPMM avec `x * y = k` mais le pool commence avec des tokens synthétiques qui ne sont jamais retirés.

```
price = virtual_quote_reserve / virtual_base_reserve
```

À mesure que les acheteurs achètent, `virtual_base_reserve` diminue et `virtual_quote_reserve` augmente — la courbe ressemble exactement à ce que le CPMM post-graduation ressemblera. Transition plus fluide.

Idéal pour : les lancements qui veulent une continuité de prix prévisible post-graduation.

## Présentation de l'interface utilisateur

Sur [raydium.io/launchpad/create](https://raydium.io/launchpad/create) :

1. **Token.** Collez l'adresse du mint. L'interface récupère les métadonnées et les affiche.
2. **Type de courbe.** Choisissez quadratique ou CPMM virtuel ; l'interface affiche un aperçu du graphique de prix pour chacun.
3. **Seuil de graduation.** Par défaut : la courbe se termine après que tout `total_base_supply` ait été vendu. Alternative : terminer à un `graduation_quote_amount` spécifique (par exemple 85 SOL).
4. **Mint de cotation.** SOL (par défaut), USDC, ou tout autre mint. SOL est standard.
5. **Politique de disposition des LP :**
   - **Burn** — tokens LP envoyés à une adresse inutilisable à la graduation. Le créateur ne peut pas retirer la liquidité ; les utilisateurs font confiance au pool pour toujours.
   - **Lock** — tokens LP envoyés à un séquestre verrouillé dans le temps pour `lock_duration`.
   - **ToCreator** — tokens LP envoyés au créateur. Plus flexible, moins minimisant la confiance.

   Les lancements les plus respectés utilisent Burn.

6. **Révision.** L'interface résume : plage de prix attendue, levée initiale si la courbe se vend, configuration CPMM de graduation.
7. **Signature.** Une transaction crée l'état de lancement + coffre de base + coffre de cotation, transfère `total_base_supply` de votre portefeuille au coffre de base.

## Présentation programmatique

La forme de la courbe, le mint de cotation, l'objectif de levée et la politique de disposition des LP ne sont **pas** des arguments — ils proviennent du `GlobalConfig` auquel vous vous liez et du `PlatformConfig` sous lequel votre lancement s'exécute. Ce que vous transmettez est l'identité du mint, la configuration à lier, et optionnellement un premier achat :

```ts
import {
  Raydium,
  TxVersion,
  LAUNCHPAD_PROGRAM,
  LaunchpadConfig,
  getPdaLaunchpadConfigId,
} from "@raydium-io/raydium-sdk-v2";
import { Keypair, PublicKey } from "@solana/web3.js";
import { NATIVE_MINT } from "@solana/spl-token";
import BN from "bn.js";

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });
const programId = LAUNCHPAD_PROGRAM;

// Vous générez la paire de clés du mint de base et signez avec elle.
const pair  = Keypair.generate();
const mintA = pair.publicKey;

// Liez une configuration : (mint de cotation, curve_type, index). C'est ce qui fixe la forme de la courbe,
// le mint de cotation et l'objectif de levée.
const configId   = getPdaLaunchpadConfigId(programId, NATIVE_MINT, 0, 0).publicKey;
const configData = await raydium.connection.getAccountInfo(configId);
const configInfo = LaunchpadConfig.decode(configData!.data);
const mintBInfo  = await raydium.token.getTokenInfo(configInfo.mintB);

const { execute, extInfo } = await raydium.launchpad.createLaunchpad({
  programId,
  mintA,
  decimals: 6,
  name:   "My New Token",
  symbol: "MYNEW",                    // 10 caractères ou moins
  uri:    "https://example.com/metadata.json",
  migrateType: "amm",                 // "amm" | "cpmm"

  configId,
  configInfo,
  mintBDecimals: mintBInfo.decimals,
  mintBProgram:  new PublicKey(mintBInfo.programId),

  createOnly: true,                   // true = créer le mint sans premier achat
  buyAmount:  new BN(1000),
  slippage:   new BN(100),            // 100 = 1%

  extraSigners: [pair],               // la paire de clés du mint de base doit signer
  txVersion: TxVersion.V0,
  computeBudgetConfig: { units: 400_000, microLamports: 50_000 },
});

// createLaunchpad retourne plusieurs transactions - exécutez-les dans l'ordre.
const { txIds } = await execute({ sequentially: true });
console.log("Pool ID:", extInfo.address.poolId.toBase58());
console.log("Base mint:", mintA.toBase58());
```

`raydium.api.fetchLaunchConfigs()` liste les configurations disponibles avec leur approvisionnement par défaut, montant de vente et objectif de levée, afin que vous puissiez montrer à l'utilisateur ce qu'une configuration donnée implique avant qu'il ne signe. Version complète annotée, incluant la variante Token-2022 : [`products/launchlab/code-demos`](/fr/products/launchlab/code-demos#create-a-launch).

## Suivi pré-graduation

Suivez l'activité via l'API :

LaunchLab a ses propres hôtes API, séparés de `api-v3.raydium.io` :

```ts
// Informations au niveau du mint, indexées par mint de base (séparées par des virgules pour un lot).
const r = await fetch(
  `https://launch-mint-v1.raydium.io/get/by/mints?ids=${mintA.toBase58()}`,
).then((r) => r.json());
console.log(r.data.rows[0]);

// Également disponible : /main/configs (liste de configuration) sur le même hôte, et
// https://launch-history-v1.raydium.io/kline et /trade pour le prix et les remplissages.
```

Ou lisez l'état on-chain directement. L'ID du pool est un PDA de `(programId, mintA, mintB)` :

```ts
import { getPdaLaunchpadPoolId, Curve } from "@raydium-io/raydium-sdk-v2";

const poolId = getPdaLaunchpadPoolId(programId, mintA, NATIVE_MINT).publicKey;
const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });

console.log({
  status:      poolInfo.status,
  baseSold:    poolInfo.realA.toString(),
  totalSellA:  poolInfo.totalSellA.toString(),
  quoteRaised: poolInfo.realB.toString(),
  raiseTarget: poolInfo.totalFundRaisingB.toString(),
});
```

La progression s'exprime mieux en termes de **prix** plutôt que comme une fraction de la levée, car la courbe est non-linéaire. Le dépôt de démonstration [`getFinishRate.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/getFinishRate.ts) le fait avec `Curve.getPrice`, `Curve.getPoolEndPriceReal` et `Curve.getPoolInitPriceByPool` :

```
finishRate = (currentPrice − initPrice) / (endPrice − initPrice)   // limité à 1
```

### Métriques à surveiller

- **Taux de vente** : pourcentage de base vendu. Le seuil de graduation est généralement à 80–100% vendu.
- **Prix actuel** : dérivé de la courbe au `baseSold` actuel.
- **Acheteurs uniques** : nombre de payeurs distincts via l'indexeur.
- **Ratio achat-vente** : les lancements précoces voient une forte pression d'achat qui ralentit.

Si le taux de vente est `<10%` après 24 heures, considérez si le marketing est adéquat. LaunchLab ne sauve pas les lancements sous-commercialisés.

## Graduation

La graduation est une transaction séparée, et elle n'est **pas** appelable par n'importe qui : `MigrateToCpswap` et le `MigrateToAmm` hérité exigent chacun que leur signataire corresponde à un portefeuille enregistré sur le `GlobalConfig` de liaison (`migrate_to_cpswap_wallet` / `migrate_to_amm_wallet`), et tout autre signataire obtient `InvalidOwner`. Il n'y a pas de prime. Ces portefeuilles sont gérés par le crank de graduation de Raydium, qui atterrit la migration en quelques secondes après le franchissement du seuil. Aucune action requise de votre part en tant que créateur au-delà de la configuration initiale.

### Ce que fait la graduation

1. Lit les soldes des coffres.
2. Ferme la courbe (plus d'achats/ventes contre elle).
3. Crée un nouveau pool CPMM avec les soldes des coffres comme liquidité initiale.
4. Crée des tokens LP initiaux en fonction des soldes des coffres.
5. Dispose des tokens LP selon la politique configurée (Burn / Lock / ToCreator).

Après la graduation, le pool CPMM est actif et les échanges se font via le routage normal de Raydium.

### Suivi de la graduation

Regardez `status` sur l'état du pool et basculez votre interface utilisateur quand il change :

```ts
const before = (await raydium.launchpad.getRpcPoolInfo({ poolId })).status;

setInterval(async () => {
  const p = await raydium.launchpad.getRpcPoolInfo({ poolId });
  if (p.status !== before) console.log("migrated - switch to the CPMM pool page");
}, 10_000);
```

L'adresse du pool gradué est le PDA CPMM pour `(cpswap config, token0, token1)`, vous pouvez donc la dériver plutôt que d'attendre qu'elle soit signalée. Pour un indexeur, abonnez-vous via gRPC au lieu de faire du polling — voir [`products/launchlab/code-demos`](/fr/products/launchlab/code-demos#watch-configs-and-pools-over-grpc).

Il n'y a pas de chemin de « graduation manuelle » pour un créateur ou un tiers. Si un lancement a franchi son seuil et n'a pas migré, c'est une question opérationnelle pour le portefeuille de migration, pas quelque chose que vous pouvez forcer depuis un client.

## Post-graduation

### Vérifier le pool CPMM

```ts
const pool = await raydium.cpmm.getPoolInfoFromRpc({ poolId: cpmmPoolId });
console.log("CPMM price:", pool.poolInfo.price);
console.log("CPMM TVL:  ", pool.poolInfo.tvl);
```

Le pool CPMM devrait avoir (approximativement) :

- Solde du token de base : `total_base_supply - baseSold` + reste de la courbe.
- Solde du token de cotation : `quoteRaised - graduationFee`.
- Prix : correspond au dernier prix de la courbe.

### Vérifier la disposition des LP

- **Burn** : l'approvisionnement du mint LP montre envoyé à 1nc1nerator11111111111111111111111111111111 ou similaire.
- **Lock** : tokens LP dans le PDA du séquestre avec timestamp de déverrouillage.
- **ToCreator** : tokens LP dans le portefeuille du créateur.

### Collecter les frais du créateur

Si vous avez configuré une part de frais du créateur, appelez périodiquement :

Le builder est `claimCreatorFee`, et il est indexé par le **mint de cotation** plutôt que par un lancement — un appel récupère vos frais de créateur accumulés dans ce mint :

```ts
import { NATIVE_MINT } from "@solana/spl-token";

await raydium.launchpad.claimCreatorFee({
  programId,
  mintB: NATIVE_MINT,      // le mint de cotation à réclamer
  txVersion: TxVersion.V0,
});
```

Utilisez `claimMultipleCreatorFee` pour regrouper les mints. Les frais s'accumulent à partir des échanges de courbe pré-graduation, et post-graduation à partir du chemin des frais du créateur du pool CPMM quand le `platform_cp_creator` de la plateforme vous laisse comme créateur du pool enregistré — voir [`products/launchlab/platform-config`](/fr/products/launchlab/platform-config).

## Liste de contrôle d'annonce

L'annonce post-graduation devrait inclure :

- [ ] Hash de la transaction de graduation.
- [ ] Nouvel ID du pool CPMM.
- [ ] Preuve de disposition des LP (tx burn / tx lock / portefeuille du créateur).
- [ ] ETA de couverture de l'agrégateur (les portefeuilles indexent généralement en 5 minutes).
- [ ] Vérification du contrat de token (correspondance de l'adresse du mint sur les canaux d'annonce).

## Pièges

### 1. Autorité de création non révoquée

Si `baseMint.mintAuthority` est toujours une clé que vous contrôlez, vous pouvez créer un nouvel approvisionnement et vendre dans votre propre courbe. Les lancements qui n'ont pas révoqué sont généralement signalés comme à haut risque ou non vérifiés par les agrégateurs et les sites de listing. Révoquez avant de lancer.

### 2. Mauvais paramètres de courbe

Les courbes quadratiques avec `a` trop élevé rendent les premiers tokens gratuits (prix ≈ 0) et les derniers tokens absurdes. Les courbes avec `a` trop bas rendent la courbe presque linéaire (perdent la sensation de « liaison »). Testez d'abord les paramètres sur devnet.

### 3. Seuil de graduation trop élevé

Si la graduation nécessite plus de capital que la demande réaliste, la courbe ne se gradue jamais et les acheteurs sont bloqués avec des tokens qu'ils ne peuvent vendre que contre la courbe (à des prix pires). Choisissez un seuil que vous pouvez réellement atteindre.

### 4. Escroqueries au mint de cotation

Si votre mint de cotation est un token personnalisé (pas SOL/USDC), les utilisateurs ne lui feront pas confiance. Restez avec SOL ou USDC pour la cotation.

### 5. Oublié de financer le coffre de base

Le SDK transfère `totalBaseSupply` de votre portefeuille à la création. Si votre portefeuille ne l'a pas, la tx revient. Confirmez le solde avant de signer.

### 6. Disposition des LP = Burn est irréversible

Une fois que les LP sont envoyés à 1nc1nerator, personne ne peut retirer la liquidité, *y compris vous*. C'est le point — minimisation de la confiance. Ne choisissez pas Burn si vous n'êtes pas sûr.

### 7. Niveau de frais CPMM post-graduation

Le pool gradué utilise la configuration CPMM par défaut de LaunchLab (0,25%). Si vous vouliez 1% ou 0,01%, vous devez créer un deuxième pool CPMM vous-même post-graduation et migrer la liquidité — maladroit et fragmentant. Acceptez la valeur par défaut, ou lancez via la création directe de CPMM au lieu de LaunchLab.
