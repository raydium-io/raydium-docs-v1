## IDL là gì

Các chương trình Anchor trên Solana công bố một tệp **IDL** (Interface Definition Language) mô tả các instruction, bố cục tài khoản, enum lỗi và schema struct của chúng. IDL là nguồn sự thật cho việc tạo mã client — TS SDK, crate CPI Rust và các client của bên thứ ba đều được tạo từ (hoặc viết tay dựa trên) nó.

Raydium công bố IDL cho CPMM, CLMM và LaunchLab. AMM v4, Stable AMM và Farm (v3 / v5 / v6) ra đời trước Anchor hoặc không được phân phối bằng Anchor — cấu trúc tài khoản của chúng được duy trì thủ công trong SDK.

## Nơi tìm chúng

IDL nằm trong một kho lưu trữ chuyên dụng:

```
https://github.com/raydium-io/raydium-idl
```

Các tệp chính xác:

| Chương trình | Tệp IDL |
|---------|----------|
| CPMM | [`raydium_cpmm/raydium_cp_swap.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_cpmm/raydium_cp_swap.json) |
| CLMM | [`raydium_clmm/raydium_clmm.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_clmm/raydium_clmm.json) |
| LaunchLab | [`raydium_launchpad/raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json) |
| AMM v4 | không có IDL chính thức — xem [`raydium-sdk-V2/src/raydium/liquidity/layout.ts`](https://github.com/raydium-io/raydium-sdk-V2/blob/master/src/raydium/liquidity/layout.ts) để xem bố cục viết tay |
| Stable AMM | không có IDL chính thức — bố cục trong SDK |
| Farm | không có IDL chính thức — bố cục trong SDK |

Các tệp IDL được phiên bản trong lịch sử git của kho lưu trữ; ghim vào một commit cụ thể nếu bạn cần tái tạo byte-for-byte.

IDL cũng có thể được kéo trực tiếp từ các chương trình được triển khai thông qua tính năng **on-chain IDL** của Anchor (nếu nhà xuất bản chương trình chọn tham gia):

```bash
anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet
```

CPMM, CLMM và LaunchLab đều có IDL on-chain. AMM v4, Stable AMM và Farm thì không (các chương trình trước Anchor).

## Tái tạo client TypeScript

Codegen của Anchor tạo ra một client được gõ từ IDL:

```bash
# Sử dụng CLI anchor
anchor build
anchor idl parse \
  --file target/idl/cpmm.json \
  --out target/types/cpmm.ts

# Hoặc với các trợ giúp TS `@anchor-lang/core` tại thời gian chạy:
```

```ts
import { Program, AnchorProvider } from "@anchor-lang/core";
// Kéo IDL trực tiếp từ kho raydium-idl (hoặc đưa nó vào dự án của bạn).
import cpmmIdl from "./idls/raydium_cp_swap.json";

const provider = new AnchorProvider(connection, wallet, {});
const program  = new Program(cpmmIdl as any, CPMM_PROGRAM_ID, provider);

// Các trình tạo phương thức được gõ tự động tạo:
await program.methods
  .swapBaseInput(new BN(amountIn), new BN(minAmountOut))
  .accounts({ ... })
  .rpc();
```

Hầu hết các nhà tích hợp **không** làm điều này — họ sử dụng trợ giúp `raydium.cpmm.swap(...)` cấp cao hơn, trợ giúp này bao bọc các phương thức Anchor cộng với tất cả công việc kế toán (tạo ATA, điều chỉnh phí chuyển, ngân sách tính toán, định tuyến chương trình Token-2022). Chỉ tái tạo khi bạn cần một lớp dưới SDK.

## Tái tạo client Rust (crate CPI)

Raydium công bố các crate Anchor cho các chương trình có IDL:

```toml
# Cargo.toml
[dependencies]
raydium_cp_swap = { git = "https://github.com/raydium-io/raydium-cp-swap", branch = "master", features = ["cpi"] }
raydium_amm_v3 = { git = "https://github.com/raydium-io/raydium-clmm",    branch = "master", features = ["cpi"] }
```

Tính năng `cpi` hiển thị các struct tài khoản `cpi::accounts::<Ix>` và các invoker `cpi::<ix>()` — các trình bao bọc CPI sẵn sàng sử dụng. Xem [`sdk-api/rust-cpi`](/vi/sdk-api/rust-cpi) để xem các mẫu sử dụng.

Nếu bạn thích tạo các ràng buộc mới:

```bash
# Từ IDL, sử dụng anchor-client
anchor idl parse \
  --file raydium_cpmm/raydium_cp_swap.json \
  --out src/generated/cpmm_bindings.rs
```

## Tái tạo client Python

Không có SDK Python chính thức của Raydium. Các trình tạo của bên thứ ba bao gồm:

- **`anchorpy`** — Cổng Python của client TypeScript của Anchor. Tạo các trình tạo phương thức được gõ từ IDL.
- **`solders`** — các nguyên thủy Solana cấp thấp (giao dịch, keypair, pubkey) trong các ràng buộc Rust; được sử dụng bên dưới `anchorpy`.

```bash
pip install anchorpy solders solana
```

```python
from anchorpy import Program, Provider
from solana.rpc.async_api import AsyncClient
from pathlib import Path
import json

idl = json.loads(Path("cpmm.json").read_text())
provider = Provider(AsyncClient("https://api.mainnet-beta.solana.com"), wallet)
program  = Program(idl, CPMM_PROGRAM_ID, provider)

await program.rpc["swap_base_input"](amount_in, min_amount_out, ctx=Context(accounts={...}))
```

Xem [`sdk-api/python-integration`](/vi/sdk-api/python-integration) để xem hướng dẫn đầy đủ hơn.

## Chính sách thay đổi IDL

Raydium tuân theo các quy tắc sau để đảm bảo tính ổn định của IDL:

1. **Các discriminator instruction không bao giờ thay đổi.** Thêm instruction mới mở rộng enum ở cuối; các discriminator hiện có vẫn ổn định.
2. **Bố cục struct tài khoản chỉ phát triển một cách bổ sung.** Các trường mới đi ở cuối, được đặt trước bằng một sự tăng kích thước trong schema on-chain. Các trường hiện có giữ nguyên offset của chúng.
3. **Mã enum lỗi chỉ được thêm vào.** Một mã lỗi hiện có luôn có nghĩa là điều tương tự.
4. **Các thay đổi phá vỡ được gửi trong các chương trình mới.** Khi cần thiết kế lại, nhóm triển khai một ID chương trình mới (ví dụ: CPMM như một chương trình mới thay vì nâng cấp AMM v4). Các pool cũ tiếp tục chạy trên chương trình cũ; các pool mới đi đến chương trình mới.

Chính sách này làm cho các client được tái tạo tương thích ngược: một client được tạo dựa trên IDL cũ hai phiên bản sẽ vẫn giải mã trạng thái hiện tại một cách chính xác (nó thấy các byte ở cuối thừa như phần đệm).

## Phải làm gì khi IDL thay đổi

1. **Cập nhật SDK.** `npm update @raydium-io/raydium-sdk-v2`.
2. **Tái tạo mã client của bạn** nếu bạn sử dụng Anchor codegen trực tiếp.
3. **So sánh bố cục tài khoản.** Các trường ở cuối của bố cục mới là điều duy nhất mã của bạn chưa thấy; xác nhận xem bạn có cần chúng hay không.
4. **Đừng giả định rằng các discriminator instruction cũ không hợp lệ.** Theo quy tắc 1, chúng vẫn hoạt động.
5. **Chạy lại các bài kiểm tra tích hợp** trên devnet trước khi triển khai đến mainnet.

## Khắc phục sự cố IDL

### Lỗi "Invalid discriminator"

Thường có nghĩa là một client được xây dựng dựa trên phiên bản N của IDL đang cố gắng gọi một instruction chỉ tồn tại trong phiên bản trước triển khai của chương trình. Kéo lại IDL từ chương trình trực tiếp:

```bash
anchor idl fetch <PROGRAM_ID>
```

### Lỗi giải mã tài khoản

Nếu `program.account.<Name>.fetch(pubkey)` ném ra lỗi "Invalid account discriminator", tài khoản được tạo bởi phiên bản chương trình trước đó và Anchor đang từ chối discriminator 8 byte của nó. Cách khắc phục là sử dụng trình phân tích bố cục thô từ SDK (`PoolInfoLayout.decode(accountData)`) không thực thi các discriminator Anchor.

### Instruction bị thiếu trong client được tạo

Codegen TS của Anchor chỉ tạo các phương thức cho các instruction có mục nhập IDL có `name` được phân tích cú pháp dưới dạng một định danh hợp lệ. Các instruction của Raydium đều thỏa mãn điều này, nhưng nếu bạn thấy sự không khớp, hãy kiểm tra xem tệp IDL có phải từ bản phát hành SDK hiện tại hay không.
