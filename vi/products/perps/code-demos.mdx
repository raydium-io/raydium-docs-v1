## Nội dung trang này

Các luồng dưới đây bao gồm vòng đời liên quan đến nhà tích hợp:

1. Thiết lập tài khoản — gửi USDC và đăng ký tài khoản với Orderly.
2. Các cuộc gọi REST được xác thực — yêu cầu ký để đặt lệnh, hủy lệnh và truy vấn tài khoản.
3. Giao dịch — đặt lệnh thị trường/giới hạn, hủy, lấy vị thế và lệnh điền.
4. Dữ liệu thị trường — đăng ký sổ lệnh và WebSocket giao dịch.
5. Rút tiền — bắt đầu rút tiền trở lại ví.

Các đoạn mã này nhắm mục tiêu Node.js + TypeScript với `@solana/web3.js` và `tweetnacl` để ký Ed25519. Chúng là **điểm khởi đầu** — bề mặt API của Orderly rộng lớn và thay đổi nhanh hơn trang này; luôn kiểm tra tài liệu trực tiếp của Orderly trước khi triển khai mã sản xuất.

## Thiết lập

```ts
import { Connection, Keypair, PublicKey, clusterApiUrl } from "@solana/web3.js";
import nacl from "tweetnacl";
import bs58 from "bs58";
import fs from "node:fs";

// 1. Ví Solana — sở hữu USDC, ký các giao dịch gửi/rút.
const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

// 2. Khóa giao dịch Orderly — cặp khóa Ed25519 riêng biệt được sử dụng để ký các yêu cầu API.
//    KHÔNG phải ví Solana. Tạo một lần, giữ bí mật, tái sử dụng trong các phiên.
const orderlyKey = nacl.sign.keyPair();   // ed25519
const orderlyPubB58 = "ed25519:" + bs58.encode(orderlyKey.publicKey);

// 3. URL cơ sở Orderly. Raydium sử dụng máy chủ mainnet của Orderly.
const ORDERLY_BASE = "https://api.orderly.org";
const BROKER_ID    = "raydium";   // Không gian tên broker của Raydium trên Orderly
const CHAIN_ID     = "solana";    // để đăng ký tài khoản xuyên chuỗi
```

Khóa giao dịch Orderly **không phải** là cặp khóa ví của bạn. Đó là một khóa ký yêu cầu mà bạn đăng ký với ví của mình khi sử dụng lần đầu; bạn có thể xoay nó mà không cần chạm vào quỹ. Coi nó như một thông tin xác thực phiên.

## Đăng ký tài khoản

Trước khi đặt bất kỳ lệnh nào, hãy đăng ký ví với Orderly:

```ts
import { encodeUserSettlement } from "./eip712-helpers"; // xem tài liệu Orderly để biết tải trọng chính xác

// 1. Yêu cầu nonce đăng ký từ Orderly.
const nonceResp = await fetch(`${ORDERLY_BASE}/v1/registration_nonce`).then(r => r.json());
const registrationNonce = nonceResp.data.registration_nonce;

// 2. Ký tải trọng đăng ký bằng ví Solana (EIP-712-style trên Solana
//    được triển khai dưới dạng một thông báo có cấu trúc; SDK của Orderly cung cấp bộ mã hóa).
const payload = encodeUserSettlement({
  brokerId: BROKER_ID,
  chainId: CHAIN_ID,
  registrationNonce,
  timestamp: Date.now(),
});
const walletSig = nacl.sign.detached(Buffer.from(payload), owner.secretKey);

// 3. Đăng ký, bao gồm khóa giao dịch Ed25519 của Orderly.
const reg = await fetch(`${ORDERLY_BASE}/v1/register_account`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: payload,
    signature: bs58.encode(walletSig),
    userAddress: owner.publicKey.toBase58(),
    orderlyKey: orderlyPubB58,
  }),
}).then(r => r.json());

console.log("Account ID:", reg.data.account_id);
```

ID tài khoản là xác định cho mỗi cặp `(broker_id, wallet_address)` — đăng ký là idempotent. Nếu ví đã đăng ký với broker của Raydium, cuộc gọi sẽ trả về cùng một ID tài khoản mà không tạo cái mới.

## Gửi USDC

Các khoản gửi di chuyển USDC từ ATA ví đến kho lưu trữ thanh toán của Orderly. Chúng là các giao dịch Solana trên chuỗi:

```ts
// Xây dựng ix gửi bằng chương trình Solana của Orderly (ID chương trình kho lưu trữ được
// công bố trong tài liệu của họ; kéo nó động thay vì mã hóa cứng).
const vaultProgramId = new PublicKey("<orderly_solana_vault_program_id>");

const depositIx = await buildOrderlyDepositIx({
  vaultProgramId,
  user: owner.publicKey,
  brokerId: BROKER_ID,
  amountUsdc: BigInt(100_000_000),    // 100 USDC (6 chữ số thập phân)
});

const tx = new Transaction().add(depositIx);
const sig = await connection.sendTransaction(tx, [owner]);
await connection.confirmTransaction(sig, "confirmed");
console.log("Deposit tx:", sig);
```

Sau ~30 giây, relayer của Orderly lập chỉ mục khoản gửi và số dư xuất hiện dưới lợi nhuận tự do của tài khoản. Truy vấn `/v1/client/holding` để xác nhận:

```ts
const holdingResp = await orderlyAuthGet("/v1/client/holding");
console.log("Balances:", holdingResp.data.holding);
```

(`orderlyAuthGet` được định nghĩa dưới đây — mọi cuộc gọi được xác thực đều đi qua nó.)

## Trợ giúp ký yêu cầu

Mọi cuộc gọi REST được xác thực tới Orderly đều mang chữ ký Ed25519 trên `(timestamp + method + path + body)`:

```ts
async function orderlyAuthRequest(
  method: "GET" | "POST" | "PUT" | "DELETE",
  path: string,
  body?: unknown,
): Promise<any> {
  const ts   = Date.now().toString();
  const json = body ? JSON.stringify(body) : "";
  const msg  = `${ts}${method}${path}${json}`;
  const sig  = nacl.sign.detached(Buffer.from(msg), orderlyKey.secretKey);

  const resp = await fetch(ORDERLY_BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json",
      "orderly-account-id":  /* tài khoản đã đăng ký account_id */ "",
      "orderly-key":         orderlyPubB58,
      "orderly-signature":   bs58.encode(sig),
      "orderly-timestamp":   ts,
    },
    body: json || undefined,
  });
  return resp.json();
}

const orderlyAuthGet  = (p: string)            => orderlyAuthRequest("GET",  p);
const orderlyAuthPost = (p: string, b: object) => orderlyAuthRequest("POST", p, b);
const orderlyAuthDel  = (p: string)            => orderlyAuthRequest("DELETE", p);
```

Bảo vệ phát lại: các yêu cầu có `timestamp` lệch hơn 5 giây so với đồng hồ máy chủ sẽ bị từ chối. Đồng bộ hóa đồng hồ của bạn (NTP) và tránh ký các yêu cầu trước.

## Đặt lệnh thị trường

```ts
const marketResp = await orderlyAuthPost("/v1/order", {
  symbol:        "PERP_SOL_USDC",
  order_type:    "MARKET",
  side:          "BUY",
  order_quantity: 1.0,        // 1 SOL vị thế
  reduce_only:    false,
});

if (marketResp.success) {
  console.log("Order ID:", marketResp.data.order_id);
} else {
  console.error("Reject:", marketResp.message);
}
```

Các lệnh thị trường được thực hiện ngay lập tức. Phản hồi trả về `order_id` kết quả cộng với trạng thái. Các lệnh điền đến qua WebSocket (xem dưới); phản hồi REST chính nó không chặn cho đến khi được điền đầy đủ.

## Đặt lệnh giới hạn với Post-Only

```ts
const limitResp = await orderlyAuthPost("/v1/order", {
  symbol:         "PERP_SOL_USDC",
  order_type:     "LIMIT",
  side:           "SELL",
  order_quantity: 0.5,
  order_price:    140.50,
  // kết hợp cờ:
  // post_only: true làm cho đây là lệnh chỉ maker — hủy nếu nó sẽ vượt qua.
  // reduce_only / time_in_force có thể được đặt độc lập.
  post_only:      true,
});
console.log(limitResp);
```

Đối với `IOC` / `FOK`, hãy đặt `time_in_force: "IOC"` hoặc `"FOK"`. Xem [`products/perps/order-types`](/vi/products/perps/order-types) để biết ngữ nghĩa của mỗi cờ.

## Hủy lệnh

```ts
// Theo ID lệnh
await orderlyAuthDel(`/v1/order?order_id=${orderId}&symbol=PERP_SOL_USDC`);

// Hủy TẤT CẢ lệnh trên một ký hiệu
await orderlyAuthDel(`/v1/orders?symbol=PERP_SOL_USDC`);
```

Hủy được xác nhận đồng bộ nhưng hủy thực tế có thể chạy đua với lệnh điền. Luôn điều hòa bằng cách thăm dò `/v1/orders` hoặc xem WebSocket — giả định hủy thành công mà không có xác nhận có thể dẫn đến vị thế trùng lặp hoặc không mong muốn.

## Lấy vị thế mở

```ts
const posResp = await orderlyAuthGet("/v1/positions");
for (const p of posResp.data.rows) {
  console.log(
    p.symbol,
    "size:",  p.position_qty,
    "entry:", p.average_open_price,
    "unrealized:", p.unsettled_pnl,
  );
}
```

`position_qty` âm là short, dương là long. `position_qty == 0` có nghĩa là vị thế đã đóng nhưng hàng có thể vẫn hiển thị cho đến lần dọn dẹp tiếp theo.

## Lấy lịch sử lệnh điền

```ts
const fills = await orderlyAuthGet(
  "/v1/trades?symbol=PERP_SOL_USDC&start_t=" + (Date.now() - 86_400_000)
);
for (const t of fills.data.rows) {
  console.log(t.executed_timestamp, t.side, t.executed_quantity, "@", t.executed_price);
}
```

Các đối số thời gian là dấu thời gian Unix tính bằng mili giây. Kích thước trang mặc định là 25 hàng; sử dụng các tham số truy vấn `page` và `size` để phân trang.

## WebSocket: dữ liệu thị trường

```ts
import WebSocket from "ws";

const ws = new WebSocket(`wss://ws.orderly.org/ws/stream/${accountId}`);

ws.on("open", () => {
  // Dữ liệu thị trường công khai: delta sổ lệnh + giao dịch cho một ký hiệu
  ws.send(JSON.stringify({ id: "ob1", topic: "orderbook@PERP_SOL_USDC" }));
  ws.send(JSON.stringify({ id: "tr1", topic: "trade@PERP_SOL_USDC" }));
});

ws.on("message", (raw) => {
  const msg = JSON.parse(raw.toString());
  if (msg.topic?.startsWith("orderbook@")) {
    // depth diff: { bids: [[price, qty], ...], asks: [[price, qty], ...] }
    applyOrderbookDelta(msg.data);
  } else if (msg.topic?.startsWith("trade@")) {
    console.log("trade:", msg.data);
  }
});
```

Đối với luồng **riêng tư** (các lệnh điền, cập nhật vị thế, thay đổi số dư của bạn), WebSocket phải được xác thực. Gửi tải trọng `subscribe` được ký theo cách tương tự như các yêu cầu REST, được phạm vi cho ID tài khoản của bạn. Tài liệu của Orderly có hình dạng tải trọng chính xác; nó thay đổi thỉnh thoảng, vì vậy đừng mã hóa cứng một lược đồ cụ thể ở đây.

## Rút USDC

```ts
// 1. Yêu cầu rút tiền.
const wRes = await orderlyAuthPost("/v1/withdraw_request", {
  token:  "USDC",
  chain_id: CHAIN_ID,
  amount: 50.0,                          // đơn vị con người
  receiver: owner.publicKey.toBase58(),
});

console.log("Withdrawal request id:", wRes.data.withdraw_id);
```

Orderly chuyển tiếp rút tiền trên chuỗi cho địa chỉ nhận. Có phí rút tiền cố định **1 USDC** (xem [`products/perps/fees`](/vi/products/perps/fees)). Chuyển giao trên chuỗi xảy ra trong vòng 1–2 phút trong điều kiện bình thường; mong đợi lâu hơn trong tình trạng tắc nghẽn.

## Những cạm bẫy

- **Đừng tái sử dụng khóa giao dịch trên các môi trường.** Một khóa giao dịch Orderly duy nhất được đăng ký với ví của bạn được liên kết với một tài khoản mainnet Solana. Nếu bạn cũng cần devnet hoặc staging, hãy tạo một khóa riêng cho mỗi khóa.
- **Đồng bộ hóa thời gian.** Dung sai lệch đồng hồ của Orderly rất chặt (±5s). Trên các dịch vụ chạy lâu dài, độ trôi NTP cuối cùng sẽ phá vỡ ký. Đồng bộ hóa lại định kỳ.
- **Kết nối lại WebSocket.** WS công khai thỉnh thoảng bỏ kết nối trong quá trình nâng cấp Orderly. Triển khai backoff theo cấp số nhân và đăng ký lại khi mở lại.
- **Giới hạn tốc độ.** Các cuộc gọi REST được giới hạn tốc độ theo cấp độ cho mỗi tài khoản. Hủy hàng loạt thông qua `cancel_all` thay vì vòng lặp `cancel`-by-id khi bạn có >5 lệnh để hủy.
- **Hướng vị thế là ngầm.** Lệnh `BUY` trên `PERP_SOL_USDC` mở hoặc mở rộng long; `SELL` mở hoặc mở rộng short — nhưng nếu bạn đã long, `SELL` *giảm* (và có thể lật) vị thế vì Raydium Perps ở chế độ một chiều. Luôn kiểm tra vị thế hiện tại trước khi đặt lệnh nếu hướng quan trọng.
- **Tài trợ và thanh lý tách biệt với luồng lệnh.** Các khoản thanh toán tài trợ và thanh lý xuất hiện dưới dạng các luồng sự kiện riêng biệt; chúng không phải là "lệnh". Đăng ký các chủ đề WS riêng tư liên quan nếu bạn cần quan sát chúng.
