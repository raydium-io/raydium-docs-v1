## Phát hiện vị trí Raydium

### LP token cổ điển (CPMM, AMM v4)

Chúng trông giống như bất kỳ SPL Token nào khác: ATA của người dùng nắm giữ một số dư. Ví hiển thị điều này như một token khác theo mặc định. Để tiết lộ nó như một vị trí Raydium:

1. Liệt kê các tài khoản token của người dùng: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Với mỗi mint, kiểm tra danh sách mint của Raydium: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (nhóm tối đa ~50 LP mint mỗi lần gọi).
3. Đối với các mint khớp, API trả về tham chiếu pool. Sử dụng nó để tính giá trị vị trí được biểu thị bằng token:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Hiển thị cả số dư LP và các số tiền được giải nén — người dùng suy nghĩ theo token cơ bản, không phải theo đơn vị LP.

### CLMM position NFT

Các vị trí CLMM là NFT. `PersonalPositionState` PDA của mỗi vị trí được lấy từ mint NFT. Để phát hiện:

1. Liệt kê các NFT của người dùng. Đối với NFT Metaplex cũ: lọc các tài khoản token có supply 1 và decimals 0.
2. Với mỗi NFT mint, hãy cố gắng lấy PersonalPositionState PDA:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Đây là vị trí CLMM của Raydium — giải mã.
```

3. Liệt kê các vị trí của ví bằng `raydium.clmm.getOwnerPositionInfo({ programId })` và khớp trên `nftMint` (không có `getPositionInfo`). Mỗi mục cung cấp cho bạn:
   - `poolId` → tìm nạp pool để giải quyết mint
   - `tickLower`, `tickUpper` → hiển thị phạm vi
   - `liquidity`, `tokensOwedA/B` → tính giá trị vị trí + phí chưa nhận
   - `rewardInfos` → phần thưởng chưa nhận mỗi luồng

4. Đối với position-NFT được phát hành theo Token-2022 (`OpenPositionWithToken22Nft`), chương trình mint NFT là Token-2022 thay vì SPL Token. Liệt kê cả hai khi quét.

### Farm stake

Farm v3 / v5 / v6 mỗi cái có một PDA sổ cái cho mỗi người dùng. Các lấy dẫn:

```ts
// Thử cả ba phiên bản farm cho mỗi tương tác farm tiềm năng của người dùng.
// Cách tiếp cận rẻ nhất: hỏi API trước, nó đã lập chỉ mục tất cả các vị trí người dùng.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Đối với các ví ưa thích phát hiện hoàn toàn trên chuỗi: lặp lại các PDA `UserLedger` có thể bằng cách băm người dùng với danh sách được quản lý "có khả năng" farm ID. Liệt kê tất cả farm ID một cách toàn diện là không thực tế (tồn tại hàng nghìn); sử dụng API.

## Tính giá trị vị trí

### CPMM / AMM v4 LP

Ba mô-đun **không** chia sẻ chữ ký: `liquidity.getPoolInfoFromRpc` lấy `{ poolId }`, trong khi `cpmm.getPoolInfoFromRpc` và `clmm.getPoolInfoFromRpc` lấy một chuỗi base58 vị trí.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` là ApiV3Token và không có trường `supply`. Đọc
// supply của LP mint từ chuỗi, hoặc sử dụng gương của pool:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Sau đó nhân mỗi cái với giá USD của mint (từ `raydium.token` hoặc một oracle giá).

### CLMM position

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // chuỗi base58
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity là async, lấy epochInfo + poolInfo + add,
// và trả về các số tiền được bao bọc phí.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // để hiển thị, không slippage
  add:        false,
});
// amountA.amount / amountB.amount là các BN; .fee là phí chuyển Token-2022.

// Phí chưa nhận — hiển thị riêng biệt dưới dạng "uncollected"
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Phần thưởng chưa nhận — một pool CLMM có 0–3 luồng phần thưởng. Các mục
// rewardInfos của vị trí chỉ là { growthInsideLastX64, rewardAmountOwed }, vì vậy
// mint phải đến từ rewardInfos của POOL ở cùng chỉ mục.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Hiển thị như:

- Giá trị thanh khoản (giá hiện tại)
- Phí chưa thu thập
- Phần thưởng chưa nhận mỗi luồng
- Phạm vi: `[tickLower_price, tickUpper_price]` với một thanh trực quan cho thấy liệu giá hiện tại có nằm trong phạm vi hay không

### Farm stake

```ts
// Phản hồi API đã bao gồm phần thưởng chưa nhận; sử dụng nó trực tiếp.
const apr       = stakingFarm.apr;               // %, hàng năm
const staked    = stakingFarm.stakedAmount;      // đơn vị nhỏ nhất của staking mint
const rewards   = stakingFarm.pendingRewards;    // mảng { mint, amount }
```

Để tính toán trên chuỗi, phản chiếu kế toán của farm:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Hãy chắc chắn làm mới `reward_per_share_x64` bằng công thức cập nhật lười trước khi tính toán (thời gian trôi qua × tỷ lệ phát hành ÷ tổng_staked).

## Mô phỏng giao dịch để xem trước

Trước khi người dùng ký, ví thường xem trước các thay đổi số dư. Sử dụng `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Giải mã số dư của mỗi tài khoản được trả về và so sánh với số dư trước tx.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // so sánh với số dư trước tx, hiển thị Δ
}
```

Tham số `accounts` yêu cầu trình xác thực trả về trạng thái tài khoản sau mô phỏng cho các địa chỉ được liệt kê. Chính xác hơn nhiều so với cố gắng dự đoán thay đổi số dư từ hình dạng hướng dẫn một mình.

### Các cạm bẫy mô phỏng

- **CLMM swap cần các mảng tick hợp lệ.** Nếu kích thước đầu vào của người dùng sẽ vượt qua một mảng tick chưa được khởi tạo, mô phỏng sẽ hoàn nguyên (giống như thực thi). Hiển thị điều này rõ ràng trong giao diện người dùng.
- **Phí ưu tiên.** Mô phỏng chạy mà không có các hướng dẫn ngân sách tính toán được áp dụng. Đối với một giao dịch lớn sẽ vượt quá 200k CU mặc định, mô phỏng không thành công nhưng thực thi thực tế với giới hạn CU rõ ràng thành công. Luôn đặt giới hạn CU trên tx được mô phỏng cũng vậy.
- **Blockhash tươi.** Mô phỏng sử dụng blockhash hiện tại; nếu ký kéo dài >60 giây, tx trở nên không hợp lệ. Mô phỏng lại nếu người dùng do dự.

## Hiển thị Token-2022

Các token theo chương trình Token-2022 nên được gắn nhãn như vậy trong danh sách token của ví, vì chúng có các bề mặt rủi ro khác nhau:

- **Transfer-fee mint**: hiển thị `transferFeeBasisPoints` hiện tại dưới dạng "Transfer fee: X%" bên cạnh số dư. Cảnh báo khi nhận — người dùng có thể không nhận ra rằng họ sẽ nhận được ít hơn những gì người gửi đã gửi.
- **Transfer-hook mint**: hiển thị ID chương trình hook. Một hook độc hại có thể chặn các chuyển khoản gửi đi; người dùng nên xác minh hook là cái họ mong đợi.
- **Non-transferable mint**: hiển thị "Non-transferable" và vô hiệu hóa swap/send. Đây thường là token soulbound hoặc thông tin xác thực.
- **Interest-bearing mint**: số dư giao diện người dùng được lấy từ `TokenAccount.amount` **không** phản ánh lãi suất tích lũy. Sử dụng `amountToUiAmount` từ `@solana/spl-token` (áp dụng hệ số tỷ lệ) cho giá trị được hiển thị.

## Hiển thị Farm APR

APR được hiển thị cho người dùng nên kết hợp tất cả các luồng phần thưởng trực tiếp, được chuyển đổi thành USD và hàng năm:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // bỏ qua không chạy
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

Hiển thị dưới dạng `APR: X.Y%`. Nếu staking mint là một LP token, cũng tính toán APR phí cơ sở LP cơ bản và gắn nhãn tổng dưới dạng "Total APR" hoặc "APR + fees".
