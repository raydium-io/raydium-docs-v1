## Anweisungsübersicht

| Diskriminator-Name | Wer signiert | Was es tut |
|-------|-----------|--------------|
| `Initialize` | Pool-Ersteller | Erstellt einen neuen CPMM-Pool aus zwei Mints und einer `AmmConfig`. Erlaubnisfrei; jeder kann es aufrufen. Hardcodiert `enable_creator_fee = false` im neuen Pool. Das `pool_state`-Konto kann entweder die kanonische PDA oder ein frischer zufälliger Keypair sein (siehe Initialize-Konten). |
| `InitializeWithPermission` | Zahler + Inhaber einer `Permission`-PDA | Berechtigte Variante von `Initialize`. Der Aufrufer (`payer`) muss eine `Permission`-PDA besitzen, die von seinem eigenen öffentlichen Schlüssel abgeleitet ist. Wird von Plattformen verwendet, die eine kontrollierte Pool-Erstellung benötigen (z. B. LaunchLab-Graduierungen). Ermöglicht dem Aufrufer, `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) festzulegen und erzwingt `enable_creator_fee = true` im neuen Pool. Das `creator`-Feld auf `pool_state` wird auf ein separat übergebenes `creator`-Konto gesetzt, nicht auf den Zahler. Gleiche kanonische-PDA-oder-zufälliger-Keypair-Flexibilität für `pool_state` wie `Initialize`. |
| `Deposit` | LP | Fügt Liquidität in beiden Token hinzu; erhält LP-Token. |
| `Withdraw` | LP | Verbrennt LP-Token; erhält beide zugrunde liegenden Token anteilsmäßig. |
| `SwapBaseInput` | Swapper | Exakte-Eingabe-Swap (`amount_in` rein, ≥ `minimum_amount_out` raus). |
| `SwapBaseOutput` | Swapper | Exakte-Ausgabe-Swap (≤ `maximum_amount_in` rein, `amount_out` raus). |
| `CollectProtocolFee` | `protocol_owner` (aus `AmmConfig`) | Sammelt aufgelaufene Protokollgebühren aus Vaults. |
| `CollectFundFee` | `fund_owner` (aus `AmmConfig`) | Sammelt aufgelaufene Fondsgebühren aus Vaults. |
| `CollectCreatorFee` | `pool_creator` | Sammelt aufgelaufene Ersteller-Gebühren (falls aktiviert). |
| `CollectCreatorFeePermissionless` | Beliebiger Zahler | Sammelt alle aufgelaufenen Ersteller-Gebühren auf die kanonischen Token-Konten des `pool_creator`. Der Zahler kann fehlende Empfänger-ATAs erstellen, kann aber die Überweisung nicht umleiten. |
| `UpdatePoolStatus` | `admin` | Pausiert / setzt spezifische Operationen auf einem Pool über eine Bitmaske fort. |
| `UpdateAmmConfig` | `admin` | Ändert Gebührensätze oder den Protokoll-/Fondsbesitzer auf einer `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Erstellt eine neue Gebührenstufe (neues `AmmConfig`-Konto). |
| `CreatePermissionPda` | `admin` oder delegierter Permission-PDA-Ersteller | Prägt eine `Permission`-PDA, die einer bestimmten Autorität erlaubt, `InitializeWithPermission` aufzurufen. |
| `ClosePermissionPda` | `admin` oder der dedizierte Permission-PDA-Ersteller | Widerruft eine zuvor ausgegebene `Permission`-PDA. Seit dem 2026-09-Upgrade kann die dedizierte Ersteller-Autorität auch einen von ihr ausgegebenen Zuschuss schließen; vorher war es nur Admin. |
| `CreateSupportMintAssociated` | `admin` oder der dedizierte Support-Mint-Besitzer | Registriert einen Token-2022-Mint, der sonst die Erweiterungs-Allowlist nicht bestehen würde, durch Erstellen seiner `SupportMintAssociated`-PDA. |
| `CloseSupportMintAssociated` | `admin` oder der dedizierte Support-Mint-Besitzer | Entfernt die Registrierung eines Mints. |
| `CollectExcessLamports` | `admin` oder das dedizierte Collect-Lamports-Wallet | Sammelt Lamports über dem Rent-Exempt-Minimum aus CPMM-kontrollierten Vaults, LP-Mints und PDAs. Hinzugefügt 2026-09. |

Status-Bitmaske: Der `status` jedes Pools ist ein `u8`, wobei Bit 0 = Deposit deaktiviert, Bit 1 = Withdraw deaktiviert, Bit 2 = Swap deaktiviert (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` im Programm). Ein gelöschtes Bit bedeutet, die Operation ist erlaubt; ein gesetztes Bit bedeutet, sie ist pausiert. `UpdatePoolStatus` nimmt ein rohes `u8` und überschreibt den vorhandenen Wert.

Die nächsten Abschnitte gehen durch jede im Detail. Die Kontoordnung folgt der CPMM-IDL; das SDK und der Rust-Client in `raydium-cp-swap/programs/cp-swap/src/instructions` entsprechen dieser Ordnung.

## `Initialize`

Erstellt einen neuen CPMM-Pool.

**Argumente**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix-Zeitstempel; Swaps werden davor abgelehnt
```

**Konten** (W = schreibbar, S = Unterzeichner)

| # | Name | W | S | Notizen |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Zahlt Miete; wird als `pool_state.pool_creator` aufgezeichnet. |
| 2 | `amm_config` |   |   | Die gewählte Gebührenstufe. |
| 3 | `authority` |   |   | CPMM-globale Autoritäts-PDA. |
| 4 | `pool_state` | W | S* | Wird hier `init`ialisiert. **Entweder** die kanonische PDA `["pool", amm_config, token_0_mint, token_1_mint]` **oder** ein frischer zufälliger Keypair — wenn nicht die kanonische PDA, verlangt das Programm, dass `pool_state` signiert (`require_eq!(pool_account_info.is_signer, true)`). Der zufällige-Keypair-Pfad ermöglicht es einem Ersteller, Front-Running-Versuche auf der kanonischen PDA zu vermeiden. Die nachgelagerten PDAs (`lp_mint`, `vaults`, `observation_state`) werden von `pool_state.key()` in jedem Fall abgeleitet. |
| 5 | `token_0_mint` |   |   | Sortiert: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | Wird hier `init`ialisiert. Autorität auf `authority` gesetzt. |
| 8 | `creator_token_0` | W |   | Quell-ATA für `init_amount_0`. |
| 9 | `creator_token_1` | W |   | Quell-ATA für `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | Ziel für LP (wird erstellt, falls fehlend). |
| 11 | `token_0_vault` | W |   | Wird hier `init`ialisiert. Besessen von `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Ziel-ATA für die `create_pool_fee`, die vom Ersteller gezahlt wird. |
| 14 | `observation_state` | W |   | Wird hier `init`ialisiert. |
| 15 | `token_program` |   |   | SPL Token (für LP-Mint). |
| 16 | `token_0_program` |   |   | SPL Token oder Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token oder Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` signiert nur auf dem zufälligen-Keypair-Pfad; der kanonische-PDA-Pfad läuft ohne `pool_state`-Signatur.

**Vorbedingungen**

- Mints sind sortiert (`token_0_mint < token_1_mint` nach Byte-Ordnung).
- Kein Mint verwendet eine Erweiterung außerhalb der CPMM-Allowlist (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — siehe [`products/cpmm/accounts`](/de/products/cpmm/accounts#vaults-and-token-2022). Ein Mint mit einer `SupportMintAssociated`-PDA (Seed `[b"support_mint", mint]`) überspringt die Prüfung; diese Registrierung ist die einzige Umgehung, seit das 2026-09-Upgrade die hardcodierte Vier-Mint-Whitelist entfernt hat.
- `creator` hat mindestens `init_amount_0` und `init_amount_1` in den jeweiligen ATAs.
- `amm_config.disable_create_pool == false`.

**Nachbedingungen**

- `pool_state` existiert mit `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- Der LP-Starter von `LOCKED_LP` (`100` Lamports von LP-Token) ist dauerhaft im Pool gesperrt — `pool_state.lp_supply` zeichnet `liquidity − 100` auf, während `100` LP-Einheiten außerhalb des Umlaufs bleiben, was verhindert, dass der Pool vollständig geleert wird und durch Null geteilt wird.
- `observation_state` wird initialisiert; `observation_index = 0` und `pool_id = pool_state.key()`.
- `create_pool_fee`-Lamports werden vom Ersteller zum Empfänger übertragen und als natives SOL synchronisiert (es ist eine wSOL-ATA).
- Die Status-Bitmaske des Pools ist `0` (Deposit / Withdraw / Swap alle aktiviert).
- `enable_creator_fee = false` und `creator_fee_on = BothToken`. `Initialize` unterstützt **nicht** das Aktivieren der Ersteller-Gebühr — dieser Pfad ist `InitializeWithPermission`.
- `open_time` wird auf `block_timestamp + 1` erhöht, wenn der Aufrufer einen Wert `<= block_timestamp` übergeben hat. Swaps werden vor `open_time` abgelehnt; Deposits und Withdrawals funktionieren sofort.

**Häufige Fehler** (vollständige Liste in [`reference/error-codes`](/de/reference/error-codes))

- `InvalidInput` — Mints unsortiert oder identisch.
- `NotSupportMint` — blockierte Token-2022-Erweiterung.
- `ExceededSlippage` — selten; wenn `init_amount_0/1` aufgrund von Dezimalstellen-Nichtübereinstimmung zu null LP führen.

## `Deposit`

Fügt Liquidität in beiden Token proportional zum Pool hinzu.

**Argumente**

```
lp_token_amount:   u64   // wie viele LP-Token an den LP geprägt werden
maximum_token_0:   u64
maximum_token_1:   u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Mathematik**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

Keine Änderung an der Proportionalität von `k` — beide Vaults und `lp_supply` skalieren um denselben Faktor.

**Nachbedingungen**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (netto von Token-2022-Transfergebühr auf Eingabe).
- `vault_1 += needed_token_1` (netto von Token-2022-Transfergebühr auf Eingabe).

**Häufige Fehler** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus` wenn Deposit pausiert ist.

**Argumente**

```

```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(Identisch mit `Deposit`; `lp_mint` ist schreibbar, weil die LP-Token verbrannt werden.)

**Mathematik**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)

require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**Nachbedingungen**

- `lp_supply -= lp_token_amount`.
- Vaults senden `out_token_0` / `out_token_1` (brutto; der Benutzer erhält netto von Token-2022-Transfergebühr).

- `ExceededSlippage` — `amount_out < minimum_amount_out`.

</Note>

## `UpdateAmmConfig`

Ändert Gebührensätze oder Besitz auf einer bestehenden `AmmConfig`. Nimmt einen `param: u8` (Diskriminator für welches Feld zu aktualisieren) und einen `value: u64`. Die Wert-Semantik pro Parameter sind in der Quelle; häufig:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (übergeben Sie `Pubkey`-Bytes als Reinterpretation)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

Änderungen werden vom Admin signiert und beeinflussen **jeden Pool, der an diese `AmmConfig` gebunden ist** beim nächsten Swap. Keine Migration; Pools lesen einfach die neuen Werte.

## `CollectExcessLamports`

Admin-Sammlung von Lamports, die über dem Rent-Exempt-Minimum auf Konten sitzen, die CPMM kontrolliert. Hinzugefügt im 2026-09-Upgrade, damit das Protokoll die Überfinanzierung zurückfordern kann, die die [SIMD-0437-Rent-Reduktion](/de/solana-fundamentals/rent-and-reclaimable-rent) auf Konten hinterlässt, die vor jedem Schritt erstellt wurden.

Nur der Überschuss bewegt sich. Token-Bilanzen, Kontodaten, Besitzer, Pool-Status und die Kurve bleiben unverändert, und die Anweisung ist ein No-Op gegen ein Konto, das bereits bei seinem Minimum ist — daher ist es sicher, nach jedem Rollout-Schritt erneut auszuführen.

**Argumente** — keine.

**Konten**

| # | Name | W | S | Notizen |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | Ziel für jeden gesammelten Lamport. Muss entweder der CPMM-Programm-Admin oder das dedizierte Collect-Lamports-Wallet sein — siehe [`reference/program-addresses`](/de/reference/program-addresses#excess-lamports-collection-wallets). Jeder andere Unterzeichner schlägt mit `InvalidOwner` fehl. |
| 2 | `authority` |   |   | Die CPMM-Vault- und LP-Mint-Autoritäts-PDA mit Seed `[b"vault_and_lp_mint_auth_seed"]`. Sie signiert die Token-Programm-CPIs. |
| 3 | `token_program` |   |   | SPL Token. |
| 4 | `token_program_2022` |   |   | Token-2022. Beide sind bedingungslos erforderlich; das Programm wählt pro Quellkonto. |
| 5.. | `remaining_accounts` | W |   | `M` Quellkonten zum Sammeln, beliebige Anzahl, beliebige Ordnung. |

**Wie jedes Quellkonto behandelt wird**

Das Programm verteilt basierend auf dem `owner` des Quellkontos:

| Quellkonto-Besitzer | Behandlung |
|---|---|
| SPL Token oder Token-2022, Nicht-Native-Token-Konto oder Mint — Pool-Vaults und LP-Mints | CPI `WithdrawExcessLamports` (Token-Programm-Diskriminator `38`), signiert von `authority`. |
| SPL Token oder Token-2022, **native** (wSOL) Token-Konto | `WithdrawExcessLamports` lehnt native Konten ab. Das Programm CPIs `SyncNative`, misst, wie viel der umhüllte `amount` wuchs, `UnwrapLamports` (Diskriminator `45`) für genau dieses Delta, dann verlangt, dass der umhüllte Saldo seinem Vor-Sync-Wert entspricht — sonst `LamportsCalculateError` (`6015`). Ein SOL-seitiger Pool-Vault behält daher seine volle Liquidität. |
| Das CPMM-Programm selbst — `PoolState`, `AmmConfig`, `ObservationState`, `Permission`, `SupportMintAssociated` | Das Programm belastet das Konto direkt auf `rent.minimum_balance(data_len)`. |
| Alles andere | **Stillschweigend übersprungen.** Kein Fehler, keine Lamports bewegt. |

Da es eine unbegrenzte `remaining_accounts`-Liste nimmt, ist die Transaktionsgröße die echte Grenze — die gleiche Einschränkung wie die Wallet-seitige Sammlung, die in [`solana-fundamentals/rent-and-reclaimable-rent`](/de/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) beschrieben ist.

**Häufige Fehler** — `InvalidOwner` (`6001`, falscher Unterzeichner), `LamportsCalculateError` (`6015`, die wSOL-Rundreise nettete nicht zu Null), und `InsufficientFunds` aus dem Programm-eigenen Pfad, wenn ein Konto weniger als sein eigenes Rent-Minimum hält.

**Kein SDK-Builder.** `@raydium-io/raydium-sdk-v2` liefert keinen Builder für diese Anweisung, und auch das `raydium-sdk-V2-demo`-Repo nicht — es ist ein Admin-Pfad. Codieren Sie es von Hand, wie die Wallet-seitige Sammlung in [`solana-fundamentals/rent-and-reclaimable-rent`](/de/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) für die Token-Programm-Anweisung.
