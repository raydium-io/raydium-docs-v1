## Zusammenfassung der Anweisungen

| Diskriminator-Name | Wer signiert | Was es tut |
|-------|-----------|--------------|
| `Initialize` | Pool-Ersteller | Erstellt einen neuen CPMM-Pool aus zwei Mints und einer `AmmConfig`. Erlaubnisfrei; jeder kann es aufrufen. Setzt `enable_creator_fee = false` auf dem neuen Pool fest. Das `pool_state`-Konto kann entweder die kanonische PDA oder ein neuer zufälliger Keypair sein (siehe Initialize-Konten). |
| `InitializeWithPermission` | Zahler + Inhaber einer `Permission`-PDA | Genehmigungspflichtige Variante von `Initialize`. Der Aufrufer (`payer`) muss eine `Permission`-PDA besitzen, die von seinem eigenen öffentlichen Schlüssel abgeleitet ist. Wird von Plattformen verwendet, die eine kontrollierte Pool-Erstellung benötigen (z. B. LaunchLab-Graduierungen). Ermöglicht dem Aufrufer, `creator_fee_on` (`BothToken` / `OnlyToken0` / `OnlyToken1`) festzulegen und erzwingt `enable_creator_fee = true` auf dem neuen Pool. Das `creator`-Feld auf `pool_state` wird auf ein separat übergebenes `creator`-Konto gesetzt, nicht auf den Zahler. Gleiche kanonische-PDA-oder-zufälliger-Keypair-Flexibilität für `pool_state` wie `Initialize`. |
| `Deposit` | LP | Fügt Liquidität in beiden Token hinzu; erhält LP-Token. |
| `Withdraw` | LP | Verbrennt LP-Token; erhält beide zugrunde liegenden Token anteilsmäßig. |
| `SwapBaseInput` | Swapper | Exakte-Eingabe-Swap (`amount_in` rein, ≥ `minimum_amount_out` raus). |
| `SwapBaseOutput` | Swapper | Exakte-Ausgabe-Swap (≤ `maximum_amount_in` rein, `amount_out` raus). |
| `CollectProtocolFee` | `protocol_owner` (aus `AmmConfig`) | Sammelt aufgelaufene Protokollgebühren aus Vaults. |
| `CollectFundFee` | `fund_owner` (aus `AmmConfig`) | Sammelt aufgelaufene Fondsgebühren aus Vaults. |
| `CollectCreatorFee` | `pool_creator` | Sammelt aufgelaufene Creator-Gebühren (falls Creator-Gebühr aktiviert war). |
| `CollectCreatorFeePermissionless` | Beliebiger Zahler | Sammelt alle aufgelaufenen Creator-Gebühren auf die kanonischen Token-Konten des `pool_creator`. Der Zahler kann fehlende Empfänger-ATAs erstellen, kann aber die Überweisung nicht umleiten. |
| `UpdatePoolStatus` | `admin` | Pausiert / setzt spezifische Operationen auf einem Pool über eine Bitmaske fort. |
| `UpdateAmmConfig` | `admin` | Ändert Gebührensätze oder den Protokoll-/Fondsbesitzer auf einer `AmmConfig`. |
| `CreateAmmConfig` | `admin` | Erstellt eine neue Gebührenstufe (neues `AmmConfig`-Konto). |
| `CreatePermissionPda` | `admin` oder delegierter Permission-PDA-Ersteller | Prägt eine `Permission`-PDA, die einer bestimmten Autorität erlaubt, `InitializeWithPermission` aufzurufen. |
| `ClosePermissionPda` | `admin` | Widerruft eine zuvor ausgegebene `Permission`-PDA. |

Status-Bitmaske: Der `status` jedes Pools ist ein `u8`, wobei Bit 0 = Deposit deaktiviert, Bit 1 = Withdraw deaktiviert, Bit 2 = Swap deaktiviert (`PoolStatusBitIndex { Deposit, Withdraw, Swap }` im Programm). Ein gelöschtes Bit bedeutet, dass die Operation erlaubt ist; ein gesetztes Bit bedeutet, dass sie pausiert ist. `UpdatePoolStatus` nimmt ein rohes `u8` und überschreibt den vorhandenen Wert.

Die nächsten Abschnitte gehen auf jede im Detail ein. Die Kontoordnung folgt der CPMM-IDL; das SDK und der Rust-Client in `raydium-cp-swap/programs/cp-swap/src/instructions` entsprechen dieser Ordnung.

## `Initialize`

Erstellt einen neuen CPMM-Pool.

**Argumente**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix-Zeitstempel; Swaps werden davor abgelehnt
```

**Konten** (W = schreibbar, S = Unterzeichner)

| # | Name | W | S | Notizen |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Zahlt Miete; wird als `pool_state.pool_creator` aufgezeichnet. |
| 2 | `amm_config` |   |   | Die gewählte Gebührenstufe. |
| 3 | `authority` |   |   | CPMM-globale Autorität-PDA. |
| 4 | `pool_state` | W | S* | Wird hier `init`ialisiert. **Entweder** die kanonische PDA `["pool", amm_config, token_0_mint, token_1_mint]` **oder** ein neuer zufälliger Keypair — wenn nicht die kanonische PDA, erfordert das Programm, dass `pool_state` signiert (`require_eq!(pool_account_info.is_signer, true)`). Der zufällige-Keypair-Pfad ermöglicht es einem Ersteller, Front-Running-Versuche auf der kanonischen PDA zu vermeiden. Die nachgelagerten PDAs (`lp_mint`, `vaults`, `observation_state`) werden in jedem Fall von `pool_state.key()` abgeleitet. |
| 5 | `token_0_mint` |   |   | Sortiert: `token_0_mint < token_1_mint`. |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | Wird hier `init`ialisiert. Autorität auf `authority` gesetzt. |
| 8 | `creator_token_0` | W |   | Quell-ATA für `init_amount_0`. |
| 9 | `creator_token_1` | W |   | Quell-ATA für `init_amount_1`. |
| 10 | `creator_lp_token` | W |   | Ziel für LP (wird erstellt, falls fehlend). |
| 11 | `token_0_vault` | W |   | Wird hier `init`ialisiert. Gehört `authority`. |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | Ziel-ATA für die `create_pool_fee`, die vom Ersteller gezahlt wird. |
| 14 | `observation_state` | W |   | Wird hier `init`ialisiert. |
| 15 | `token_program` |   |   | SPL Token (für LP-Mint). |
| 16 | `token_0_program` |   |   | SPL Token oder Token-2022. |
| 17 | `token_1_program` |   |   | SPL Token oder Token-2022. |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` signiert nur auf dem zufälligen-Keypair-Pfad; der kanonische-PDA-Pfad läuft ohne `pool_state`-Signatur.

**Vorbedingungen**

- Mints sind sortiert (`token_0_mint < token_1_mint` nach Byte-Ordnung).
- Kein Mint verwendet eine Erweiterung außerhalb der CPMM-Zulassungsliste (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) — siehe [`products/cpmm/accounts`](/de/products/cpmm/accounts#vaults-and-token-2022). Eine kleine Pro-Mint-Zulassungsliste im Programm umgeht die Überprüfung für Fall-für-Fall-Onboarding.
- `creator` hat mindestens `init_amount_0` und `init_amount_1` in den jeweiligen ATAs.
- `amm_config.disable_create_pool == false`.

**Nachbedingungen**

- `pool_state` existiert mit `lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`.
- Der LP-Starter von `LOCKED_LP` (`100` Lamports von LP-Token) wird dauerhaft im Pool gesperrt — `pool_state.lp_supply` zeichnet `liquidity − 100` auf, während `100` LP-Einheiten außerhalb des Umlaufs bleiben, was verhindert, dass der Pool vollständig geleert wird und durch Null geteilt wird.
- `observation_state` wird initialisiert; `observation_index = 0` und `pool_id = pool_state.key()`.
- `create_pool_fee` Lamports werden vom Ersteller zum Empfänger übertragen und als natives SOL synchronisiert (es ist eine wSOL-ATA).
- Die Status-Bitmaske des Pools ist `0` (Deposit / Withdraw / Swap alle aktiviert).
- `enable_creator_fee = false` und `creator_fee_on = BothToken`. `Initialize` unterstützt **nicht** das Aktivieren der Creator-Gebühr — dieser Pfad ist `InitializeWithPermission`.
- `open_time` wird auf `block_timestamp + 1` erhöht, wenn der Aufrufer einen Wert `<= block_timestamp` übergeben hat. Swaps werden vor `open_time` abgelehnt; Deposits und Withdrawals funktionieren sofort.

**Häufige Fehler** (vollständige Liste in [`reference/error-codes`](/de/reference/error-codes))

- `InvalidInput` — Mints unsortiert oder identisch.
- `NotSupportMint` — blockierte Token-2022-Erweiterung.
- `ExceededSlippage` — selten; wenn `init_amount_0/1` aufgrund von Dezimalstellen-Nichtübereinstimmung zu null LP führen.

## `Deposit`

Fügt Liquidität in beiden Token proportional zum Pool hinzu.

**Argumente**

```
lp_token_amount:   u64   // wie viele LP-Token an den LP geprägt werden
maximum_token_0:   u64
maximum_token_1:   u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**Mathematik**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

Keine Änderung an der Proportionalität von `k` — sowohl Vaults als auch `lp_supply` skalieren um denselben Faktor.

**Nachbedingungen**

- `lp_supply += lp_token_amount`.
- `vault_0 += needed_token_0` (netto von Token-2022-Transfergebühr auf Eingabe).
- `vault_1 += needed_token_1` (netto von Token-2022-Transfergebühr auf Eingabe).

**Häufige Fehler** — `ExceededSlippage`, `ZeroTradingTokens`, `InvalidStatus` wenn Deposit pausiert ist.

## `Withdraw`

Verbrennt LP-Token und erhält beide zugrunde liegenden Token anteilsmäßig.

**Argumente**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

(Identisch mit `Deposit`; `lp_mint` ist schreibbar, weil die LP-Token verbrannt werden.)

**Mathematik**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**Nachbedingungen**

- `lp_supply -= lp_token_amount`.
- Vaults senden `out_token_0` / `out_token_1` (brutto; der Benutzer erhält netto von Token-2022-Transfergebühr).

## `SwapBaseInput`

Exakte-Eingabe-Swap.

**Argumente**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

Die Ordnung **Eingabe → Ausgabe** folgt der Richtung des Benutzers, nicht der kanonischen `token_0 / token_1` des Pools. Das Programm ermittelt, welcher Vault welcher ist, indem es Mints abgleicht.

**Mathematik** — siehe [`products/cpmm/math`](/de/products/cpmm/math).

**Vorbedingungen**

- `open_time <= now`.
- `pool_status` erlaubt Swap.
- Kein Mint pausiert oder eingefroren für diese Autorität.
- `amount_in > 0`.

**Häufige Fehler**

- `ExceededSlippage` — `amount_out < minimum_amount_out`.
- `ZeroTradingTokens` — der Handel rundet auf Null.
- `NotApproved` — Pool ist für Swaps über `UpdatePoolStatus` pausiert.
- `InvalidInput` — Mints stimmen nicht mit einem der Pool-Vault-Mints überein.

## `SwapBaseOutput`

**Konten** — gleich wie `SwapBaseInput`.

## `CollectCreatorFee`

Signiert von `pool_state.pool_creator`. Es überträgt die vollständigen `creator_fees_token_0`- und `creator_fees_token_1`-Bilanzen auf die Token-Konten des Erstellers und setzt dann beide Zähler auf Null. Es gibt `NoFeeCollect` zurück, wenn beide Zähler Null sind.

## `CollectCreatorFeePermissionless`

Jeder kann die Creator-Gebührensammlung auslösen. Die Anweisung sendet immer die vollständigen aufgelaufenen Bilanzen an die kanonischen zugeordneten Token-Konten, die `pool_state.pool_creator` gehören; der Aufrufer kann keinen anderen Ersteller oder Ziel wählen. Wenn eine ATA fehlt, finanziert der Zahler ihre Erstellung.

Das ursprüngliche `CollectCreatorFee` bleibt aufrufbar, sodass bestehende Clients kompatibel bleiben.

**Argumente** — keine.

**Konten**

| # | Name | W | S | Notizen |
|---|------|---|---|-------|
| 1 | `payer` | W | S | Beliebiger Unterzeichner; finanziert fehlende Creator-ATAs. |
| 2 | `creator` |   |   | Muss `pool_state.pool_creator` entsprechen; signiert nicht. |
| 3 | `authority` |   |   | CPMM-globale Vault-Autorität-PDA. |
| 4 | `pool_state` | W |   | Hält die aufgelaufenen Creator-Gebühren-Zähler. |
| 5 | `token_0_vault` | W |   | Muss dem Pool-Token-0-Vault entsprechen. |
| 6 | `token_1_vault` | W |   | Muss dem Pool-Token-1-Vault entsprechen. |
| 7 | `vault_0_mint` |   |   | Muss `token_0_vault.mint` entsprechen. |
| 8 | `vault_1_mint` |   |   | Muss `token_1_vault.mint` entsprechen. |
| 9 | `creator_token_0` | W |   | Kanonische ATA des Erstellers für `vault_0_mint`; wird erstellt, falls fehlend. |
| 10 | `creator_token_1` | W |   | Kanonische ATA des Erstellers für `vault_1_mint`; wird erstellt, falls fehlend. |
| 11 | `token_0_program` |   |   | SPL Token oder Token-2022, passend zu Token 0. |
| 12 | `token_1_program` |   |   | SPL Token oder Token-2022, passend zu Token 1. |
| 13 | `associated_token_program` |   |   | Erstellt eine fehlende Empfänger-ATA. |
| 14 | `system_program` |   |   | Finanziert Kontoerstellung vom `payer`. |

**Effekt**

- Überträgt alle `creator_fees_token_0` und `creator_fees_token_1` aus den Pool-Vaults zu den Creator-ATAs.
- Setzt beide Creator-Gebühren-Zähler auf Null und aktualisiert `pool_state.recent_epoch`.
- Gibt `NoFeeCollect` zurück, wenn beide Zähler Null sind.

## `UpdatePoolStatus`

Pausiert oder setzt einzelne Operationen auf einem Pool fort. Das `status`-Feld ist eine Bitmaske:

| Bit | Flag | Effekt wenn gesetzt |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` lehnt mit `NotApproved` ab. |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` lehnt ab. |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` lehnen ab. |

**Argumente**

```
status: u8      // neue Bitmaske
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `authority` |   | S | Muss dem Admin-Schlüssel des CPMM-Programms entsprechen. |
| 2 | `pool_state` | W |   |

Der Admin-Schlüssel ist die Upgrade-Autorität des CPMM-Programms — in der Praxis das Raydium-Multisig. Siehe [`security/admin-and-multisig`](/de/security/admin-and-multisig).

## `UpdateAmmConfig`

Ändert Gebührensätze oder Eigentümerschaft auf einer existierenden `AmmConfig`. Nimmt einen `param: u8` (Diskriminator für welches Feld aktualisiert werden soll) und einen `value: u64`. Die Wert-Semantik pro Parameter sind in der Quelle; häufig:

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner` (übergeben Sie `Pubkey`-Bytes als Reinterpretation)
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

Änderungen werden vom Admin signiert und beeinflussen **jeden Pool, der an diese `AmmConfig` gebunden ist** beim nächsten Swap. Keine Migration; Pools lesen einfach die neuen Werte.
