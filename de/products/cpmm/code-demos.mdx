## Voraussetzungen

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

Jedes Demo auf dieser Seite spiegelt eine Datei in [`raydium-sdk-V2-demo/src/cpmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/cpmm); der GitHub-Link befindet sich neben jedem Abschnitt. Das Bootstrap folgt der `config.ts.template` des Demo-Repos ([Quelle](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template)):

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

Die `Raydium`-Instanz ist die Fassade des SDK — jedes Demo unten nutzt sie. `Raydium.load` ist asynchron, da es standardmäßig die Token-Liste lädt; übergeben Sie `disableLoadToken: true`, um diesen Abruf zu überspringen. Die Verfügbarkeitsprüfung ist bereits übersprungen, es sei denn, Sie übergeben `disableFeatureCheck: false`. Gebührenkonfigurationen werden bei der ersten Verwendung über `raydium.api.getCpmmConfigs()` lazy geladen.

## CPMM-Pool erstellen

Quelle: [`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (Wenn Sie alle Pool-PDAs auf einmal benötigen, ist der exportierte Helper `getCreatePoolKeys`.
//  Es gibt kein `getCpmmPdas`.)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. Wählen Sie eine Gebührenkonfiguration. index=0 ist die 0,25%-Stufe.
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. Rufen Sie Mint-Metadaten ab, damit das SDK Token-2022-Erweiterungen verarbeiten kann.
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. Erstellen Sie die Transaktion.
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL (angenommen 9 Dezimalstellen)
  mintBAmount:     new BN(   160_000_000),  // 160 USDC (bei 160/SOL)
  startTime:       new BN(0),               // sofort öffnen
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool erstellt unter", extInfo.address.poolId.toBase58());
console.log("Tx:", txId);
```

Ein paar Dinge, die das SDK stillschweigend übernimmt:

- Sortieren der Mints in token0/token1-Reihenfolge vor der PDA-Ableitung.
- Zahlen der einmaligen `create_pool_fee` an `poolFeeAccount`.
- Erstellen der zugehörigen Token-Konten des Aufrufers, falls fehlend.
- Auswahl des richtigen Token-Programms (SPL Token vs. Token-2022) pro Seite.

Nach der Bestätigung können Sie den Live-Pool-Status abrufen mit:

```ts
// getPoolInfoFromRpc nimmt einen positionalen Base58-String, keine PublicKey und kein Objekt.
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## Swap (Base-Input)

Quelle: [`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // Base58-String

// 1. Laden Sie den aktuellen Pool-Status direkt von einem RPC (nicht von der API).
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // Swap A → B
const amountIn   = new BN(100_000_000);                   // 0,1 SOL
const slippage   = 0.005;                                 // 0,5%

// 2. Zitieren Sie lokal. CurveCalculator spiegelt die On-Chain-Mathematik wider, einschließlich
//    Token-2022-Transfergebühren auf beiden Seiten. Alle acht Argumente sind erforderlich.
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult-Felder sind inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount.
// Es gibt kein destinationAmountSwapped oder sourceAmountSwapped.

// 3. Erstellen und senden. Das Übergeben von `slippage` hier ist das, was die Grenze anwendet —
//    keine manuelle Minimum-Out-Arithmetik ist erforderlich.
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Swap-Tx:", txId);
```

Hinweis: Das SDK ruft **immer** den Pool-Status von einem RPC innerhalb von `getPoolInfoFromRpc` ab. Zitieren Sie nicht von `api-v3.raydium.io` für eine Transaktion, die Sie gerade signieren werden — ein Zitat, das einen Block alt ist, kann bei der Landung in `ExceededSlippage` rutschen.

## Swap (Base-Output)

Quelle: [`src/cpmm/swapBaseOut.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swapBaseOut.ts)

```ts
const amountOutWanted = new BN(15_000_000);        // 15 USDC
const slippage        = 0.005;

const baseIn = false; // false → mintB ist die Eingabeseite
const swapResult = CurveCalculator.swapBaseOutput(
  amountOutWanted,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult.inputAmount ist die erforderliche Eingabe; es gibt kein sourceAmountSwapped.

const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: new BN(0),   // ungenutzt bei fixedOut — der Betrag kommt von swapResult
  fixedOut:    true,
  swapResult,               // erforderlich, und es trägt den Zielausgabebetrag
  baseIn,
  slippage,
  txVersion:   TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

## Liquidität einzahlen

Quelle: [`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity wird durch einen INPUT-Betrag angetrieben, nicht durch einen LP-Betrag.
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // ein Percent, keine Zahl

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount ist in mintA denominiert
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Das SDK leitet den gepaarten Betrag aus den aktuellen Reserven des Pools ab, erhöht jede Seite um den Slippage für die `maximum_*`-Argumente der Anweisung und erstellt die ATA-Erstellungen bei Bedarf. `raydium.cpmm.computePairAmount({ ... })` gibt die gleichen Zahlen zurück, wenn Sie sie für eine UI-Vorschau möchten.

## Protokoll-/Fonds-/Creator-Gebühren einziehen

Quelle: [`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts), [`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

Protokoll- und Fondseinzug bleiben behördengesteuert. Creator-Gebühren haben zwei Pfade: das von Creator signierte `CollectCreatorFee` und das additive `CollectCreatorFeePermissionless`, das jeder Zahler aufrufen kann, aber nur an die kanonischen ATAs des Creators übertragen kann. `0.2.64-alpha` liefert Builder auf Modulebene für beide Creator-Pfade:

```ts
// von Creator signiert
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// erlaubnisfrei — jeder Zahler; Erlöse gehen an die kanonischen ATAs des Creators
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// mehrere Pools auf einmal, von Creator signiert
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Note>
  Die beiden Creator-Anweisungen haben **unterschiedliche Diskriminatoren und Account-Layouts** — die
  erlaubnisfreie ersetzt die Creator-Signer-/`amm_config`-Positionen durch einen separaten `payer`
  und einen nicht signierenden `creator`. Verwenden Sie den passenden Builder, anstatt Konten auf dem
  anderen manuell auszutauschen.

  Es gibt keinen Protokoll- oder Fonds-Gebühren-Builder im SDK (`makeCollectProtocolFeeInstruction` und
  `makeCollectFundFeeInstruction` existieren unter keinem Namen) — das sind Admin-Pfade. Die
  Low-Level-Instruction-Builder, die *existieren*, sind `collectCpFeeInstruction`,
  `makeCollectCreatorFeeInstruction` und `collectCreatorFeePermissionlessInInstruction`.
</Note>

Off-Chain können Sie aufgelaufene Gebühren direkt aus `PoolState` lesen:

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // Base58-String
console.log("Aufgelaufene Protokollgebühr mintA:", pool.protocolFeesMintA.toString());
console.log("Aufgelaufene Protokollgebühr mintB:", pool.protocolFeesMintB.toString());
// Die CpmmPoolInfoLayout-Felder sind protocolFeesMintA/B, fundFeesMintA/B und
// creatorFeesMintA/B — es gibt keine ...Token0/...Token1-Felder.
```

## Rust-CPI-Skelett

Wenn Sie CPMM von Ihrem eigenen Anchor-Programm aus aufrufen möchten — zum Beispiel ein Vault, das im Namen seiner Einzahler Swaps durchführt — sieht der CPI-Kontext so aus. Die Account-Reihenfolge folgt [`products/cpmm/instructions`](/de/products/cpmm/instructions).

```rust
// Cargo.toml — der Branch ist wichtig: `master` pinnt immer noch anchor-lang 0.32.1.
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "chore/upgrade-anchor", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // muss mit dem übereinstimmen, das raydium-cp-swap pinnt
// anchor-spl       = "=1.0.2"
//
// Das `cpi`-Feature ist erforderlich — das Modul `raydium_cp_swap::cpi` existiert nur
// unter ihm. Beachten Sie, dass diese Crate kein Programm mit dem CLMM-Beispiel in
// products/clmm/code-demos teilen kann, das anchor-lang =0.32.1 pinnt.

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: validiert durch das CPMM-Programm
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: Ring-Buffer
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0 nimmt hier den Pubkey des Programms, nicht sein AccountInfo.
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

Wenn Ihr CPI als PDA signiert (z. B. verwalten Sie einen Vault im Namen von Einzahlern), tauschen Sie `CpiContext::new` gegen `CpiContext::new_with_signer` aus und übergeben Sie Ihre Seeds.

## Häufige Fallstricke

Eine kurze Checkliste, bevor Sie ein Support-Ticket öffnen:

- **Sortierte Mints.** Wenn Ihre abgeleitete `poolState`-PDA nicht mit dem On-Chain-Pool übereinstimmt, haben Sie wahrscheinlich vergessen, die Mints zu sortieren.
- **Veraltetes API-Zitat.** Übergeben Sie niemals einen Reservewert von `api-v3.raydium.io` an `CurveCalculator.swap`. Rufen Sie von einem RPC ab.
- **Falsches Token-Programm.** Ein Token-2022-Mint-Vault wird vom Token-2022-Programm besessen, nicht vom SPL-Token. Verwenden Sie immer die `token_0_program`-/`token_1_program`-Felder des Pools.
- **Slippage unter-denominiert für Transfer-Fee-Mints.** Wenn eine Seite des Pools ein Token-2022-Transfer-Fee-Mint ist, muss Ihr `minimum_amount_out` in dem denominiert sein, was der Benutzer tatsächlich erhält, nicht in dem, was der Vault sendet.
- **`NotApproved` bei einem Swap.** Überprüfen Sie `PoolState.status` — der Admin hat möglicherweise Swaps auf diesem Pool pausiert. Siehe [`products/cpmm/instructions`](/de/products/cpmm/instructions) für die Status-Bitmaske.
