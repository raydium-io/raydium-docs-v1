## Setup

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
```

```ts
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import BN from "bn.js";
import bs58 from "bs58";

const connection = new Connection(clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(bs58.decode(process.env.PRIVATE_KEY!));

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });

// ERFORDERLICH vor jeder Stable-Pool-Quotierung. initLayout() ruft die On-Chain-
// ModelDataInfo-Nachschlagetabelle in raydium.liquidity.stableLayout ab.
await raydium.liquidity.initLayout();
```

<Warning>
  **`initLayout()` ist für Stable Pools nicht optional.** `liquidity.computeAmountOut` verzweigt sich auf `poolInfo.version`: Für Version 4 wird die Konstant-Produkt-Formel verwendet, und für alles andere wird `this.stableLayout.stableModelData` gelesen und die Nachschlagetabelle interpoliert. Dieser Cache ist leer, bis `initLayout()` ausgeführt wird. Daher erzeugt die Quotierung eines v5-Pools ohne ihn Müll statt einen Fehler. Es ist idempotent und kostengünstig — rufen Sie es einmal beim Start auf.

  Die Transaktions-Builder (`swap`, `addLiquidity`, `removeLiquidity`) benötigen es nicht: Sie verzweigen sich auf `pooltype.includes("StablePool")` und geben `AmmV5*`-Anweisungen aus, und die Mengengrenzen, die Sie übergeben, sind bereits berechnet.
</Warning>

<Warning>
  **`liquidity.computeAmountIn` unterstützt Stable Pools nicht.** Im Gegensatz zu `computeAmountOut` hat es keine Versionsverzweigung — es wendet immer die Konstant-Produkt-Umkehrung an, daher gibt es auf einem v5-Pool ein falsches `maxAmountIn` zurück. Für einen Exact-Output-Swap gegen einen Stable Pool invertieren Sie selbst mit `getDxByDyBaseIn` (siehe [Off-Chain-Quote-Helfer](#off-chain-quote-helpers-stablets) unten) und übergeben Sie das Ergebnis an `swap` mit `fixedSide: "out"`.
</Warning>

## Einen Stable Pool identifizieren

Zwei äquivalente Signale auf `ApiV3PoolInfoStandardItem`:

```ts
const isStable =
  pool.version === 5 ||
  pool.pooltype.includes("StablePool"); // das SDK verwendet diese String-Prüfung intern

// Alternativ nach Programm-ID:
const STABLE_AMM_PROGRAM_ID = "5quBtoiQqxF9Jv6KYKctB59NT3gtJD2Y65kdnB1Uev3h";
const isStableByProgram = pool.programId === STABLE_AMM_PROGRAM_ID;
```

Sowohl AMM v4 (`version: 4`, Konstant-Produkt) als auch Stable AMM (`version: 5`) fließen durch die gleiche `LiquidityModule`-API im SDK. Intern verzweigt sich das Modul zu:

- `InstructionType.AmmV4AddLiquidity` / `AmmV4RemoveLiquidity` für v4-Pools
- `InstructionType.AmmV5AddLiquidity` / `AmmV5RemoveLiquidity` für v5 (Stable) Pools

Die `programId` des Pools (wird mit den Pool-Schlüsseln zurückgegeben) teilt dem SDK mit, in welches Programm es CPI durchführen soll; Sie müssen es nicht hardcodieren.

## Einen Pool nach Mint-Paar finden

```ts
import { PublicKey } from "@solana/web3.js";
import type { ApiV3PoolInfoStandardItem } from "@raydium-io/raydium-sdk-v2";

// Zwei häufige Mints als Beispiel
const mintA = new PublicKey("Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB"); // USDT — siehe reference/program-addresses
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// fetchPoolByMints gibt eine seitenweise Hülle zurück: { count, data, hasNextPage }
const res = await raydium.api.fetchPoolByMints({
  mint1: mintA.toBase58(),
  mint2: mintB.toBase58(),
});

const stablePool = res.data.find(
  (p) => p.version === 5 || p.pooltype.includes("StablePool"),
) as ApiV3PoolInfoStandardItem | undefined;

if (!stablePool) {
  throw new Error("Für dieses Mint-Paar existiert kein Stable Pool");
}

console.log("Stable Pool ID:", stablePool.id);
console.log("Stable Pool Programm-ID:", stablePool.programId);
console.log("TVL:", stablePool.tvl);
```

Wenn das Mint-Paar sowohl einen v4 (Konstant-Produkt) Pool als auch einen v5 (Stable) Pool hat, enthält die Antwort beide — wählen Sie den, den Ihr Flow benötigt, oder übergeben Sie sie an das [AMM Routing](/de/products/routing)-Programm und lassen Sie es die beste Route wählen.

## Durch einen Stable Pool swappen

Der `LiquidityModule.swap`-Flow hat die gleiche Form wie für v4-Pools — übergeben Sie einfach ein v5-Pool-Objekt. Zwei Details sind leicht zu übersehen: `computeAmountOut` benötigt die **Live-Reserven** des Pools, die auf die Pool-Info aufgepfropft sind (das API-Element allein trägt sie nicht), und sein `slippage` ist eine einfache **Zahl**, keine `Percent`:

```ts
import BN from "bn.js";

const amountIn = new BN(1_000_000); // 1 USDT (6 Dezimalstellen), Roheinheiten

// Live-Reserven + Status. Im Mainnet können Sie poolKeys auch von
// getAmmPoolKeys(poolId) und Reserven von getRpcPoolInfo(poolId) nehmen.
const rpcData  = await raydium.liquidity.getRpcPoolInfo(stablePool.id);
const poolKeys = await raydium.liquidity.getAmmPoolKeys(stablePool.id);

const out = raydium.liquidity.computeAmountOut({
  poolInfo: {
    ...stablePool,
    baseReserve:  rpcData.baseReserve,
    quoteReserve: rpcData.quoteReserve,
    status:       rpcData.status.toNumber(),
    version:      5, // 5 = Stable; die Curve-Verzweigung wird hierbei ausgewählt
  },
  amountIn,
  mintIn:  stablePool.mintA.address,
  mintOut: stablePool.mintB.address,
  slippage: 0.005, // einfache Zahl: 0.005 = 0,5% (Bereich 1 ~ 0.0001)
});

// amountOut / minAmountOut sind BN in Roheinheiten, nicht TokenAmount.
console.log("Erwartete Ausgabe:", out.amountOut.toString());
console.log("Minimale Ausgabe:", out.minAmountOut.toString());

// Bauen und signieren Sie die Swap-Transaktion. `inputMint` ist erforderlich — ohne ihn
// kann das SDK nicht erkennen, welche Seite des Pools Sie verkaufen.
const { transaction, execute } = await raydium.liquidity.swap({
  poolInfo:  stablePool,
  poolKeys,
  amountIn,
  amountOut: out.minAmountOut, // out.amountOut ist die Vor-Slippage-Zahl
  inputMint: stablePool.mintA.address,
  fixedSide: "in",
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Stable Swap Tx:", txId);
```

Das SDK liest die `programId` des Pools aus den Pool-Schlüsseln und verzweigt sich in das Stable-AMM-Programm. Es ist kein spezielles `programId`-Argument erforderlich.

## Liquidität hinzufügen und entfernen

`addLiquidity` und `removeLiquidity` funktionieren identisch über v4- und v5-Pools:

```ts
import { Percent, TokenAmount, toToken } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

const inputAmount = "100"; // 100 USDT, in menschlichen Einheiten — computePairAmount nimmt einen Dezimalstring

// Berechnen Sie die entsprechende B-Menge, die die Curve für diese Größe von A benötigt.
// Hinweis: computePairAmount's slippage IST ein Percent (im Gegensatz zu computeAmountOut's).
const r = raydium.liquidity.computePairAmount({
  poolInfo: stablePool,
  amount:   inputAmount,
  baseIn:   true,
  slippage: new Percent(50, 10_000), // 0,5%
});

const { execute } = await raydium.liquidity.addLiquidity({
  poolInfo: stablePool,
  poolKeys,
  amountInA: new TokenAmount(
    toToken(stablePool.mintA),
    new Decimal(inputAmount).mul(10 ** stablePool.mintA.decimals).toFixed(0),
  ),
  amountInB: new TokenAmount(
    toToken(stablePool.mintB),
    new Decimal(r.maxAnotherAmount.toExact()).mul(10 ** stablePool.mintB.decimals).toFixed(0),
  ),
  otherAmountMin: r.minAnotherAmount,
  fixedSide:      "a",
  txVersion:      TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Liquidität hinzufügen Tx:", txId);
```

Intern gibt das SDK `InstructionType.AmmV5AddLiquidity` aus, weil `pooltype.includes("StablePool")` wahr ist. Der entsprechende `removeLiquidity`-Flow ist symmetrisch — geben Sie `lpAmount` und die minimalen Mengen ein, die Sie auf jeder Seite akzeptieren.

## Off-Chain-Quote-Helfer (stable.ts)

Für serverseitige Quotierung oder Backtesting stellt das SDK die zugrunde liegende Stable-Curve-Mathematik bereit:

```ts
import {
  getStablePrice,
  getDxByDyBaseIn,
  getDyByDxBaseIn,
} from "@raydium-io/raydium-sdk-v2";

// Sie müssen initLayout() einmal vor der Verwendung dieser aufrufen (lädt die On-Chain-
// `ModelDataInfo` PDA in den StableLayout-Cache des SDK).
await raydium.liquidity.initLayout();

// initLayout() füllt die StableLayout-Instanz; das einfache Datenobjekt, das die
// drei Helfer unten erwarten, ist sein `stableModelData`-Getter, NICHT die Instanz.
const modelData = raydium.liquidity.stableLayout.stableModelData;

// Reserven werden als einfache Zahlen in menschlichen Einheiten übergeben (nicht BN, nicht Roheinheiten).
const coinReserve = 1_200_000; // Pool's Coin-Seite Reserve
const pcReserve   = 1_150_000; // Pool's PC-Seite Reserve

// Spot-Preis bei den aktuellen Reserven des Pools. Das 4. Argument ist `baseCoin`:
// true gibt Coin-pro-PC zurück, false gibt das Reziproke zurück.
const price = getStablePrice(modelData, coinReserve, pcReserve, true);
console.log("Spot-Preis:", price);

// Quotierung: Gegeben dx rein, wie viel dy raus (keine Gebühr angewendet)?
const dyOut = getDyByDxBaseIn(modelData, coinReserve, pcReserve, 1_000);

// Quotierung: Gegeben dy raus Ziel, wie viel dx rein ist erforderlich?
const dxIn  = getDxByDyBaseIn(modelData, coinReserve, pcReserve, 1_000);
```

Dies sind reine Funktionen — kein RPC, kein Signieren. Die On-Chain-`ModelDataInfo` wird einmal von `initLayout()` abgerufen und im `raydium.liquidity.stableLayout` zwischengespeichert, lesbar als `.stableModelData`. `initStableModelLayout()` ist idempotent: Es ruft nur ab, während `validDataCount === 0`, daher ist ein erneuter Aufruf von `initLayout()` kostenlos. Übergeben Sie aktuelle Reserven (`x`, `y`) und die Helfer berechnen durch binäre Suche in der Nachschlagetabelle und lineare Interpolation zwischen den zwei umgebenden `DataElement`-Zeilen. Siehe [`products/stable/math`](/de/products/stable/math) für den zugrunde liegenden Algorithmus.

## Routing durch AMM Routing (Multi-Hop / Best-Price)

Wenn Sie nicht selbst einen Veranstaltungsort wählen möchten, berücksichtigt das [AMM Routing](/de/products/routing)-Programm jeden Raydium-AMM (v4 / CPMM / CLMM / Stable) und leitet durch die beste Kombination:

Der Router ist eine Fünf-Aufruf-Pipeline statt eines einzelnen `swap()`, und er ist vollständig ausgeschrieben — mit dem Caching-Rat, der ihn in der Produktion nutzbar macht — auf [`products/routing/code-demos`](/de/products/routing/code-demos). Die Form ist:

```ts
import { Router } from "@raydium-io/raydium-sdk-v2";

const poolData = await raydium.tradeV2.fetchRoutePoolBasicInfo(); // cache this
const routes   = raydium.tradeV2.getAllRoute({ inputMint: mintA, outputMint: mintB, ...poolData });
const ctx      = await raydium.tradeV2.fetchSwapRoutesData({ routes, inputMint: mintA, outputMint: mintB });
const quotes   = raydium.tradeV2.getAllRouteComputeAmountOut({ /* ...ctx, amount, slippage, ... */ });

const best = quotes[0]; // sorted best-first
if (!best) throw new Error("no swap routes were found");

// best.poolInfoList Einträge tragen `version` — 5 markiert einen Stable Pool im Pfad.
console.log(best.routeType, best.poolInfoList.map((p) => p.version));

const poolKeys = await raydium.tradeV2.computePoolToPoolKeys({
  pools: best.poolInfoList,
  ammRpcData:  ctx.ammPoolsRpcInfo,
  clmmRpcData: ctx.clmmPoolsRpcInfo,
});

const { execute } = await raydium.tradeV2.swap({
  routeProgram: Router,
  swapInfo:     best,
  swapPoolKeys: poolKeys,
  ownerInfo:    { associatedOnly: true, checkCreateATAOwner: true },
  txVersion:    TxVersion.V0,
});

// tradeV2.swap kann mehrere Transaktionen zurückgeben; die erste erstellt zwischengeschaltete ATAs.
const { txIds } = await execute({ sequentially: true });
```

<Warning>
  Es gibt kein `raydium.tradeV2.fetchRoutes`, und `tradeV2.swap` akzeptiert **nicht** `inputMint` / `outputMint` / `slippage` — es nimmt ein bereits berechnetes `swapInfo` von `getAllRouteComputeAmountOut`. Für einen **einzelnen** bekannten Pool verwenden Sie den Builder dieses Pool-Typs (`raydium.liquidity.swap` für AMM v4 und Stable, `raydium.cpmm.swap`, `raydium.clmm.swap`) wie früher auf dieser Seite gezeigt.
</Warning>

Dies ist der empfohlene Pfad für Produktions-Swapper und Aggregatoren — Sie müssen nie manuell entscheiden, ob ein Stable Pool existiert oder ob er heute der bessere Veranstaltungsort ist.

## Empfehlungen

1. **Für End-User-Swaps** bevorzugen Sie den [`tradeV2`](/de/products/routing)-Routing-Flow. Er verarbeitet jeden Raydium-Pool-Typ einschließlich Stable.
2. **Für Pool-spezifische Operationen** (LP hinzufügen / entfernen auf einem bekannten Stable Pool) verwenden Sie das `LiquidityModule` direkt — es erkennt v5-Pools automatisch.
3. **Für Off-Chain-Quotierung / Analytik** rufen Sie `getStablePrice` / `getDyByDxBaseIn` / `getDxByDyBaseIn` nach `initLayout()` auf. Kein RPC-Verkehr pro Quotierung, nachdem die Modelldaten zwischengespeichert sind.
4. **Codieren Sie nicht manuell rohe `SwapBaseIn`-Anweisungen.** Das [2026-06-22-Upgrade](/de/reference/changelog) entfernte die toten OpenBook-Konten, daher benötigt das neue Swap-Layout **9 Konten** (das alte 18-Konto-Layout wird immer noch für Rückwärtskompatibilität geparst). `Deposit` ist jetzt 12 Konten (alte 14 kompatibel), `Withdraw` 12 (alte 21/22 kompatibel), und `WithdrawPnl` 10 mit **keinem** Kompatibilitätspfad. Die vordefinierten Helfer des SDK wählen das korrekte Layout und die Reihenfolge für Sie aus; das Rollen Ihrer eigenen ist fehleranfällig. Siehe [`products/stable/instructions`](/de/products/stable/instructions) für die vollständigen Kontotabellen.
