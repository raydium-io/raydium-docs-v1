## Setup

```ts
import { Connection, Keypair, PublicKey, clusterApiUrl } from "@solana/web3.js";
import nacl from "tweetnacl";
import bs58 from "bs58";
import fs from "node:fs";

// 1. Solana-Wallet — besitzt USDC, signiert Einzahlungs-/Abhebungstransaktionen.
const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

// 2. Orderly-Handelsschlüssel — separates Ed25519-Keypair zur Signierung von API-Anfragen.
//    NICHT die Solana-Wallet. Einmal generieren, geheim halten, über Sessions hinweg wiederverwenden.
const orderlyKey = nacl.sign.keyPair();   // ed25519
const orderlyPubB58 = "ed25519:" + bs58.encode(orderlyKey.publicKey);

// 3. Orderly-Basis-URL. Raydium verwendet Orderlys Mainnet-Host.
const ORDERLY_BASE = "https://api.orderly.org";
const BROKER_ID    = "raydium";   // Raydiums Broker-Namespace auf Orderly
const CHAIN_ID     = "solana";    // für Cross-Chain-Kontoregistrierung
```

Der Orderly-Handelsschlüssel ist **nicht** Ihr Wallet-Keypair. Es ist ein Schlüssel zur Anfragensignierung, den Sie bei der ersten Verwendung gegen Ihre Wallet registrieren; Sie können ihn rotieren, ohne Gelder zu berühren. Behandeln Sie ihn als Session-Anmeldedaten.

## Kontoregistrierung

Bevor Sie Orders platzieren, registrieren Sie die Wallet bei Orderly:

```ts
import { encodeUserSettlement } from "./eip712-helpers"; // siehe Orderly-Dokumentation für die genaue Payload

// 1. Fordern Sie einen Registrierungs-Nonce von Orderly an.
const nonceResp = await fetch(`${ORDERLY_BASE}/v1/registration_nonce`).then(r => r.json());
const registrationNonce = nonceResp.data.registration_nonce;

// 2. Signieren Sie eine Registrierungs-Payload mit der Solana-Wallet (EIP-712-ähnlich auf Solana
//    wird als strukturierte Nachricht implementiert; Orderlys SDK stellt den Encoder bereit).
const payload = encodeUserSettlement({
  brokerId: BROKER_ID,
  chainId: CHAIN_ID,
  registrationNonce,
  timestamp: Date.now(),
});
const walletSig = nacl.sign.detached(Buffer.from(payload), owner.secretKey);

// 3. Registrieren Sie sich, einschließlich des Orderly Ed25519-Handelsschlüssels.
const reg = await fetch(`${ORDERLY_BASE}/v1/register_account`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: payload,
    signature: bs58.encode(walletSig),
    userAddress: owner.publicKey.toBase58(),
    orderlyKey: orderlyPubB58,
  }),
}).then(r => r.json());

console.log("Account ID:", reg.data.account_id);
```

Account-IDs sind deterministisch pro `(broker_id, wallet_address)`-Paar — die Registrierung ist idempotent. Wenn eine Wallet bereits bei Raydiums Broker registriert ist, gibt der Aufruf dieselbe Account-ID zurück, ohne ein neues zu erstellen.

## USDC einzahlen

Einzahlungen verschieben USDC von der Wallet-ATA zum Settlement-Vault von Orderly. Sie sind On-Chain-Solana-Transaktionen:

```ts
// Erstellen Sie die Einzahlungs-Instruktion mit Orderlys Solana-Programm (Vault-Programm-ID ist
// in ihrer Dokumentation veröffentlicht; ziehen Sie sie dynamisch ab, anstatt sie hart zu codieren).
const vaultProgramId = new PublicKey("<orderly_solana_vault_program_id>");

const depositIx = await buildOrderlyDepositIx({
  vaultProgramId,
  user: owner.publicKey,
  brokerId: BROKER_ID,
  amountUsdc: BigInt(100_000_000),    // 100 USDC (6 Dezimalstellen)
});

const tx = new Transaction().add(depositIx);
const sig = await connection.sendTransaction(tx, [owner]);
await connection.confirmTransaction(sig, "confirmed");
console.log("Deposit tx:", sig);
```

Nach etwa 30 Sekunden indexiert Orderlys Relayer die Einzahlung und der Saldo wird unter der freien Marge des Kontos angezeigt. Fragen Sie `/v1/client/holding` ab, um zu bestätigen:

```ts
const holdingResp = await orderlyAuthGet("/v1/client/holding");
console.log("Balances:", holdingResp.data.holding);
```

(`orderlyAuthGet` ist unten definiert — jeder authentifizierte Aufruf läuft durch ihn.)

## Anfragensignatur-Hilfsfunktion

Jeder authentifizierte REST-Aufruf an Orderly trägt eine Ed25519-Signatur über `(timestamp + method + path + body)`:

```ts
async function orderlyAuthRequest(
  method: "GET" | "POST" | "PUT" | "DELETE",
  path: string,
  body?: unknown,
): Promise<any> {
  const ts   = Date.now().toString();
  const json = body ? JSON.stringify(body) : "";
  const msg  = `${ts}${method}${path}${json}`;
  const sig  = nacl.sign.detached(Buffer.from(msg), orderlyKey.secretKey);

  const resp = await fetch(ORDERLY_BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json",
      "orderly-account-id":  /* die registrierte account_id */ "",
      "orderly-key":         orderlyPubB58,
      "orderly-signature":   bs58.encode(sig),
      "orderly-timestamp":   ts,
    },
    body: json || undefined,
  });
  return resp.json();
}

const orderlyAuthGet  = (p: string)            => orderlyAuthRequest("GET",  p);
const orderlyAuthPost = (p: string, b: object) => orderlyAuthRequest("POST", p, b);
const orderlyAuthDel  = (p: string)            => orderlyAuthRequest("DELETE", p);
```

Replay-Schutz: Anfragen mit einem `timestamp`, der mehr als 5 Sekunden von der Serveruhr abweicht, werden abgelehnt. Synchronisieren Sie Ihre Uhr (NTP) und vermeiden Sie es, Anfragen im Voraus zu signieren.

## Market-Order platzieren

```ts
const marketResp = await orderlyAuthPost("/v1/order", {
  symbol:        "PERP_SOL_USDC",
  order_type:    "MARKET",
  side:          "BUY",
  order_quantity: 1.0,        // 1 SOL Position
  reduce_only:    false,
});

if (marketResp.success) {
  console.log("Order ID:", marketResp.data.order_id);
} else {
  console.error("Reject:", marketResp.message);
}
```

Market-Orders werden sofort ausgeführt. Die Antwort gibt die resultierende `order_id` plus einen Status zurück. Fills kommen über den WebSocket (siehe unten); die REST-Antwort selbst blockiert nicht, bis sie vollständig gefüllt ist.

## Limit-Order mit Post-Only platzieren

```ts
const limitResp = await orderlyAuthPost("/v1/order", {
  symbol:         "PERP_SOL_USDC",
  order_type:     "LIMIT",
  side:           "SELL",
  order_quantity: 0.5,
  order_price:    140.50,
  // Flag-Kombinationen:
  // post_only: true macht dies zu einer Maker-Only-Order — wird storniert, wenn sie kreuzen würde.
  // reduce_only / time_in_force sind unabhängig einstellbar.
  post_only:      true,
});
console.log(limitResp);
```

Für `IOC` / `FOK` setzen Sie `time_in_force: "IOC"` oder `"FOK"`. Siehe [`products/perps/order-types`](/de/products/perps/order-types) für die Semantik jedes Flags.

## Order stornieren

```ts
// Nach Order-ID
await orderlyAuthDel(`/v1/order?order_id=${orderId}&symbol=PERP_SOL_USDC`);

// Alle Orders auf einem Symbol stornieren
await orderlyAuthDel(`/v1/orders?symbol=PERP_SOL_USDC`);
```

Eine Stornierung wird synchron bestätigt, aber die tatsächliche Stornierung kann mit einem Fill konkurrieren. Gleichen Sie immer ab, indem Sie `/v1/orders` abfragen oder den WebSocket beobachten — das Annehmen einer erfolgreichen Stornierung ohne Bestätigung kann zu doppelten oder unbeabsichtigten Positionen führen.

## Offene Positionen abrufen

```ts
const posResp = await orderlyAuthGet("/v1/positions");
for (const p of posResp.data.rows) {
  console.log(
    p.symbol,
    "size:",  p.position_qty,
    "entry:", p.average_open_price,
    "unrealized:", p.unsettled_pnl,
  );
}
```

Eine negative `position_qty` ist ein Short, positiv ist ein Long. `position_qty == 0` bedeutet, dass die Position geschlossen ist, aber die Zeile kann bis zur nächsten Bereinigung bestehen bleiben.

## Fill-Verlauf abrufen

```ts
const fills = await orderlyAuthGet(
  "/v1/trades?symbol=PERP_SOL_USDC&start_t=" + (Date.now() - 86_400_000)
);
for (const t of fills.data.rows) {
  console.log(t.executed_timestamp, t.side, t.executed_quantity, "@", t.executed_price);
}
```

Zeitargumente sind Millisekunden-Unix-Zeitstempel. Die Standard-Seitengröße beträgt 25 Zeilen; verwenden Sie `page`- und `size`-Abfrageparameter zum Blättern.

## WebSocket: Marktdaten

```ts
import WebSocket from "ws";

const ws = new WebSocket(`wss://ws.orderly.org/ws/stream/${accountId}`);

ws.on("open", () => {
  // Öffentliche Marktdaten: Orderbuch-Deltas + Trades für ein Symbol
  ws.send(JSON.stringify({ id: "ob1", topic: "orderbook@PERP_SOL_USDC" }));
  ws.send(JSON.stringify({ id: "tr1", topic: "trade@PERP_SOL_USDC" }));
});

ws.on("message", (raw) => {
  const msg = JSON.parse(raw.toString());
  if (msg.topic?.startsWith("orderbook@")) {
    // Tiefendiff: { bids: [[price, qty], ...], asks: [[price, qty], ...] }
    applyOrderbookDelta(msg.data);
  } else if (msg.topic?.startsWith("trade@")) {
    console.log("trade:", msg.data);
  }
});
```

Für den **privaten** Stream (Ihre Fills, Positionsaktualisierungen, Saldoänderungen) muss der WebSocket authentifiziert werden. Senden Sie eine `subscribe`-Payload, die auf die gleiche Weise wie REST-Anfragen signiert ist, auf Ihre Account-ID beschränkt. Orderlys Dokumentation hat die genaue Payload-Form; sie ändert sich gelegentlich, daher codieren Sie hier kein bestimmtes Schema hart.

## USDC abheben

```ts
// 1. Fordern Sie eine Abhebung an.
const wRes = await orderlyAuthPost("/v1/withdraw_request", {
  token:  "USDC",
  chain_id: CHAIN_ID,
  amount: 50.0,                          // menschliche Einheiten
  receiver: owner.publicKey.toBase58(),
});

console.log("Withdrawal request id:", wRes.data.withdraw_id);
```

Orderly leitet die Abhebung On-Chain an die Empfängeradresse weiter. Es gibt eine pauschale **1 USDC**-Abhebungsgebühr (siehe [`products/perps/fees`](/de/products/perps/fees)). Die On-Chain-Überweisung erfolgt unter normalen Bedingungen innerhalb von 1–2 Minuten; rechnen Sie mit längeren Zeiten bei Überlastung.

## Fallstricke

- **Verwenden Sie den Handelsschlüssel nicht über Umgebungen hinweg erneut.** Ein einzelner Orderly-Handelsschlüssel, der gegen Ihre Wallet registriert ist, ist mit einem Solana-Mainnet-Konto verknüpft. Wenn Sie auch Devnet oder Staging benötigen, generieren Sie einen separaten Schlüssel für jeden.
- **Zeitsynchronisation.** Orderlys Toleranz für Uhrenabweichungen ist eng (±5s). Bei lange laufenden Services führt NTP-Drift schließlich zu Signierungsfehlern. Synchronisieren Sie regelmäßig neu.
- **WebSocket-Wiederverbindungen.** Der öffentliche WS lässt Verbindungen gelegentlich während Orderly-Upgrades fallen. Implementieren Sie exponentielles Backoff und abonnieren Sie bei Wiederöffnung erneut.
- **Ratenlimits.** REST-Aufrufe sind pro Konto Tier-Rate-limitiert. Verwenden Sie `cancel_all` für Massen-Stornierungen, anstatt `cancel`-by-id zu durchlaufen, wenn Sie >5 Orders stornieren müssen.
- **Positionsrichtung ist implizit.** Eine `BUY`-Order auf `PERP_SOL_USDC` öffnet oder erweitert einen Long; eine `SELL` öffnet oder erweitert einen Short — aber wenn Sie bereits long sind, *reduziert* eine `SELL` (und kann umkehren) die Position, da Raydium Perps im One-Way-Modus ist. Überprüfen Sie immer die aktuelle Position, bevor Sie eine Order platzieren, wenn die Richtung wichtig ist.
- **Finanzierung und Liquidationen sind getrennt vom Order-Flow.** Finanzierungszahlungen und Liquidationen erscheinen als separate Event-Streams; sie sind keine „Orders". Abonnieren Sie die relevanten privaten WS-Themen, wenn Sie sie beobachten müssen.
