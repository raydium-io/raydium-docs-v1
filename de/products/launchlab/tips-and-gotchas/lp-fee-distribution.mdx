Wenn ein LaunchLab-Token zu CPMM migriert, prägt der Pool LP-Token. Vor dem Upgrade vom 2026-08-17 wurde `creatorScale` separat für den Token-Creator gesperrt. Bei Migrationen nach dem Upgrade speichert `migrateCpLockNftScale` weiterhin drei Felder, die sich zu `1_000_000` addieren, aber die Runtime erzeugt nur zwei Ziele.

## Effektive Aufteilung

| Feld | Aktualisiertes Verhalten |
|---|---|
| `platformScale` | Enthalten im plattformeigenen gesperrten-LP-Anteil. |
| `creatorScale` | Vor dem Upgrade prägte es einen Creator-eigenen Fee Key. Nach dem Upgrade ist es im plattformeigenen gesperrten-LP-Anteil enthalten. |
| `burnScale` | Dauerhaft verbrannt. Kein Fee Key repräsentiert diesen Anteil. |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

Wenn `burnScale` null ist, erhält die Plattform alle LP-Einheiten. Wenn `effectivePlatformScale` null ist, wird alle LP verbrannt und es wird kein plattform-Fee Key erstellt.

## Beispiele

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% plattformeigene gesperrte LP, 10% verbrannt.
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// Unter dem aktualisierten Programm erzeugt dies 100% plattformeigene gesperrte LP.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% verbrannt; kein Fee Key.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## Beziehung zu CPMM-Creator-Gebühren

Die Scale-Felder steuern nur die LP-Eigentümerschaft. Sie legen keine Swap-Gebührensätze fest und identifizieren nicht den CPMM-Creator-Gebühren-Empfänger. `cpConfigId` wählt die CPMM `AmmConfig` aus; `platformCpCreator` bestimmt, ob der CPMM-Pool den ursprünglichen Launch-Creator oder eine von der Plattform ausgewählte Adresse aufzeichnet.

## Aktualisierung der Aufteilung

Vor der Aktualisierung einer Plattform:

- Bestätigen Sie, dass sich die drei Werte zu genau `1_000_000` addieren.
- Präsentieren Sie `platformScale + creatorScale` als den effektiven Plattformanteil.
- Versprechen Sie keinen Creator Fee Key basierend auf `creatorScale`.
- Bewahren Sie die Creator-Fee-Key-Eigentümerschaft, die durch Migrationen vor dem Upgrade angezeigt wird; diese Datensätze werden nicht umgeschrieben.
- Erklären Sie die Änderung, bevor zukünftige Launches die aktualisierte Konfiguration verwenden.
