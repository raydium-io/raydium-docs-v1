Das SDK `raydium.launchpad.getLaunchById` gibt `PoolState` plus ein Flag zurück, das anzeigt, ob der Launch abgeschlossen wurde; wenn ja, ist die Post-Migration-Pool-ID enthalten.

## `PoolState`

Der Pro-Launch-Root-State. Feldnamen unten entsprechen der On-Chain-Rust-Struktur (`states/pool.rs`); einige Werte sind zur Lesbarkeit vereinfacht — konsultieren Sie die Quelle für das exakte Memory-Layout.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

`PoolStatus`-Werte (aus dem Anchor IDL):

```
0 = Funding         — akzeptiert Käufe / Verkäufe; unter quote_reserve_target
1 = Migrate         — quote_reserve_target erreicht; wartet auf MigrateTo*
2 = Migrated        — MigrateTo* bereits ausgeführt; Vesting-Uhr läuft
```

Integrator-seitige Felder:

- **`status`** — drei Werte, monoton (Funding → Migrate → Migrated). Lesevorgänge immer sicher; Schreibvorgänge gated.
- **`real_base`**, **`real_quote`** — aktueller Curve-State. Kombiniert mit `virtual_base` / `virtual_quote` sind sie ausreichend, um den Spotpreis zu berechnen, ohne die Vaults zu berühren. Siehe [`bonding-curve`](/de/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — „Fortschritt zur Graduation"-Verhältnis für UIs.
- **`migrate_type`** — neue Initialisierung erfordert `1` (`CPSWAP`). Ein gespeichertes `0` bleibt nur für einen bestehenden Launch sinnvoll, der vor der CPMM-Only-Erzwingung erstellt wurde.
- **`amm_creator_fee_on`** — wählt `creator_fee_on = OnlyQuoteToken` (`0`) oder `BothToken` (`1`) auf dem Post-Graduation-CPMM-Pool. Es wählt nicht das Migrationsziel. Siehe [`creator-fees`](/de/products/launchlab/creator-fees).
- **`token_program_flag`** — ein Bitfeld, kein Boolean. Bit0 ist die Base-Mint und Bit1 ist die Quote-Mint, jeweils `0` für SPL Token und `1` für Token-2022, daher nimmt das Byte vier Werte an: `0` (beide Legacy), `1` (Token-2022 Base), `2` (Token-2022 Quote), `3` (beide Token-2022). Lesen Sie eine Mint mit `(token_program_flag >> bit) & 1`. Der Vergleich des gesamten Bytes gegen `0` zur Klassifizierung der Base-Mint löst `2` zum falschen Programm auf. Bit1 war konstant `0`, bis Token-2022-Quote-Mints unterstützt wurden.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — drei unabhängige Gebührenzähler. Jeder hat seine eigene Claim-Anweisung; siehe [`instructions`](/de/products/launchlab/instructions).
- **`vesting_schedule`** — vorhanden auf jedem `PoolState`, aber inaktiv, wenn `total_locked_amount == 0`. Siehe [`vesting`](/de/products/launchlab/vesting) für den vollständigen Lebenszyklus.

## Die Authority-PDA

LaunchLab verwendet eine **einzelne** Authority-PDA über alle Launches hinweg, abgeleitet ohne Pro-Launch-Seed:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // siehe reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Diese einzelne PDA ist:

- Die Authority auf jedem Launch's `base_vault` und `quote_vault`.
- Die `mint_authority` auf jeder Launch's `base_mint` (vor Graduation).
- Der Unterzeichner auf der CPMM-Graduation-CPI und auf Legacy-AMM-v4-Graduation für bestehenden State.
- Der Unterzeichner auf `ClaimVestedToken`-Transfers aus dem Base-Vault.
- Die `transfer_fee_config_authority` auf einer Token-2022-Base-Mint's `TransferFeeConfig`, für die gesamte Pre-Graduation-Phase — und ihre `withdraw_withheld_authority` auch, aber nur wenn die Platform `PlatformConfig.transfer_fee_extension_auth` nicht gesetzt hat.

Die `mint_authority` wird unmittelbar nach `MigrateToCpswap` oder einem Legacy-`MigrateToAmm`-Aufruf widerrufen, daher ist die Versorgung dauerhaft festgelegt.

Zwei zusätzliche PDAs gaten die Gebühren-Vaults:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Diese unterzeichnen den Transfer aus dem entsprechenden Gebühren-Vault während `ClaimCreatorFee` und `ClaimPlatformFeeFromVault`.

## Base-Mint

Erstellt inline durch `Initialize` mit:

- `mint_authority = authority` (widerrufen bei Graduation).
- `freeze_authority = None`.
- `supply = supply`, vollständig in `base_vault` geprägt.
- `decimals` vom Creator bei `Initialize` gewählt (üblicherweise 6).

Da die gesamte Versorgung vorgeprägt ist, ist `base_mint.supply` für die Lebensdauer des Launches konstant. Curve-Käufe verschieben Token von `base_vault` zum Käufer, rufen aber nicht `mint_to` auf.

`Initialize` / `InitializeV2` erstellen SPL-Token-Base-Mints. Die dedizierte `InitializeWithToken2022`-Anweisung ermöglicht es, dass die Base-Mint eine Token-2022-Mint ist (mit optionalem `TransferFeeConfig`). Alle drei Initialisierungspfade erfordern CPMM-Graduation.

Wenn `InitializeWithToken2022` einen `TransferFeeConfig` anhängt, wird die Mint mit `transfer_fee_config_authority = authority` und `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth` erstellt, fällt auf `authority` zurück, wenn die Platform dieses Feld nicht gesetzt hat. Beide Authorities werden bei Graduation zum Platform-Schlüssel neu zugewiesen, die Withdraw-Seite nur, wenn die PDA sie noch hält. Siehe [`platform-config`](/de/products/launchlab/platform-config#token-2022-transfer-fee-authorities).

Die Quote-Mint ist unabhängig von der Base-Mint und kann selbst eine Token-2022-Mint sein — `InitializeV2` und `InitializeWithToken2022` akzeptieren beide Programme in ihrem Quote-Programm-Slot. Das veraltete `Initialize` nicht: sein Quote-Programm-Konto ist immer noch auf SPL Token typisiert, daher kann eine Konfiguration, deren Quote-Mint Token-2022 ist, nur durch die anderen zwei gestartet werden. Die Quote-Mint wird nie von LaunchLab erstellt; sie ist, was `GlobalConfig.quote_mint` benennt. Siehe [`global-config`](/de/products/launchlab/global-config#token-2022-quote-mints) und [`reference/token-2022-support`](/de/reference/token-2022-support#launchlab-quote-mints).

## Vaults

Sowohl `base_vault` als auch `quote_vault` sind Token-Konten, die von der LaunchLab-`authority`-PDA besessen werden, jeweils auf dem Programm erstellt, das seine eigene Mint besitzt — daher kann ein Launch einen Legacy-Base-Vault und einen Token-2022-Quote-Vault haben, oder jede andere Kombination. `token_program_flag` zeichnet auf, welcher welcher ist. Adressen werden auf `PoolState` gespeichert und können auch abgeleitet werden:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Überprüfen Sie die genauen Seed-Präfixe aus der `Initialize`-Accounts-Struktur der Quelle, bevor Sie sich in der Produktion auf eine Ableitung verlassen.)

## Gebühren-Vaults

Zwei PDAs aggregieren Gebühren über Launches hinweg:

- **Creator-Gebühren-Vault** — PDA mit Seeds `[creator, quote_mint]`. Jeder Launch, der die gleichen Creator-Gebühren auf der gleichen Quote-Mint verdient, fließt in den gleichen Vault. Der Creator leert ihn über `ClaimCreatorFee`.
- **Platform-Gebühren-Vault** — PDA mit Seeds `[platform_config, quote_mint]`. Jeder Launch, der durch die gleiche Platform geleitet wird und die gleiche Quote-Mint verwendet, fließt in den gleichen Vault. Die `platform_fee_wallet` der Platform leert ihn über `ClaimPlatformFeeFromVault`. Es gibt auch eine Pro-Launch-Sweep-Variante (`ClaimPlatformFee`), die direkt aus dem Launch's `quote_vault` zieht, ohne durch den aggregierten Vault zu gehen.

Beide werden beim ersten Swap, der eine Gebühr anfallen lässt, auf dem Programm erstellt, das die Quote-Mint besitzt. Ein Creator oder eine Platform, die Launches gegen sowohl eine Legacy- als auch eine Token-2022-Quote-Mint durchführt, endet mit einem Vault pro Mint, wie es bereits für zwei verschiedene Legacy-Mints der Fall war.

Das aggregierte-Vault-Muster ermöglicht es einem High-Volume-Creator oder einer Platform, die Mietkosten der Gebührenakkumulation über viele Launches hinweg zu amortisieren.

## Quote-Vault ↔ `real_quote`

`quote_vault.balance` und `PoolState.real_quote` sollten synchron bleiben. Sie können um höchstens die Summe der drei ausstehenden Gebührenzähler (`quote_protocol_fee`, `platform_fee`, `migrate_fee`) abweichen, die im Vault sitzen, aber zu den Gebührenzählern und nicht zur Curve-Reserve gehören. Die Curve-Mathematik verwendet immer `real_quote`, nie den rohen Vault-Saldo.

Pre-Graduation-Invariante:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## Lebenszyklus-Kontoübergänge

| Ereignis | Status | `real_base` | `real_quote` | Post-Graduation-Pool |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (oder Legacy `MigrateToAmm`) | Funding → Migrate → Migrated | (eingefroren) | (eingefroren) | erstellt; CPMM LP wird in Platform-eigene gesperrte LP und verbrannte LP aufgeteilt |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | beliebig | — | — | leert einen Gebühren-Vault |
| `CreateVestingAccount` | Funding | — | — | erhöht `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Nur Migrated | — | — | leert `base_vault` |
