## Anweisungsbestand

| Gruppe | Anweisung | Aufrufbar durch |
|-------|-------------|-------------|
| Globale Konfiguration | `CreateConfig` / `UpdateConfig` | Programm-Admin; die delegierte Create-Config-Autorität kann auch `CreateConfig` aufrufen |
| Launch-Lebenszyklus | `Initialize` / `InitializeV2` | Jeder (Ersteller) — SPL Token Base-Mint; V2 zeichnet `amm_creator_fee_on` für die eventuelle CPMM-Graduierung auf. Nur V2 akzeptiert einen Token-2022-Quote-Mint. |
| Launch-Lebenszyklus | `InitializeWithToken2022` | Jeder (Ersteller) — Token-2022 Base-Mint, optionale `TransferFeeConfig`; akzeptiert beide Quote-Token-Programme |
| Handel | `BuyExactIn` / `BuyExactOut` | Jeder — exakte Eingabe / exakte Ausgabe Kauf auf der Bindungskurve |
| Handel | `SellExactIn` / `SellExactOut` | Jeder — exakte Eingabe / exakte Ausgabe Verkauf auf der Bindungskurve |
| Graduierung | `MigrateToAmm` | Migrations-Wallet — Legacy-AMM-v4-Graduierung für Pools, die vor der Durchsetzung der CPMM-only-Erstellung initialisiert wurden. |
| Graduierung | `MigrateToCpswap` | Migrations-Wallet — Graduierung zu CPMM. Alle neu initialisierten Launches verwenden diesen Pfad. Umhüllt `InitializeWithPermission` auf CPMM. |
| Gebühren | `CollectFee` | Admin — Protokollgebühren von einem Launch einziehen |
| Gebühren | `CollectMigrateFee` | Admin — angesammelte Migrationsgebühren einziehen |
| Gebühren | `ClaimCreatorFee` | Ersteller — angesammelte Ersteller-Gebühren während der Kurvenphase einfordern |
| Vesting | `CreateVestingAccount` | Ersteller — gesperrte Token einem Begünstigten zuordnen, nach Graduierung freigegeben |
| Vesting | `CreatePlatformVestingAccount` | Plattform-Admin — gesperrte Token Plattform-seitigen Begünstigten zuordnen |
| Vesting | `ClaimVestedToken` | Begünstigter — freigegeben Token nach der Cliff einfordern |
| Plattformkonfiguration | `CreatePlatformConfig` / `UpdatePlatformConfig` | Plattform-Admin |
| Plattformkonfiguration | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Plattform-Admin — verwalte die Pro-Plattform-Liste der zulässigen Kurvenformen |
| Plattformgebühren | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Plattform-Admin |
| Plattformzugriff | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Plattform-Admin — verwalte die `GlobalConfig`-Allowlist, die verwendet wird, wenn diese Plattform Einschränkung aktiviert |

Die „ExactIn/ExactOut"-Aufteilung spiegelt CPMMs `SwapBaseInput` / `SwapBaseOutput` — On-Chain sind sie separate Anweisungs-Diskriminatoren mit leicht unterschiedlichem Rounding.

**Graduierungspfad-Auswahl.** Jeder neue `Initialize`-, `InitializeV2`- und `InitializeWithToken2022`-Aufruf muss `migrate_type = 1` (`CPSWAP`) setzen. Jeder Versuch, einen neuen AMM-v4-gebundenen Pool zu initialisieren, gibt `MigrateTypeNotMatch` zurück. `amm_creator_fee_on` wählt nur, ob die resultierende CPMM-Ersteller-Gebühr auf den Quote-Token oder beide Token angewendet wird; es wählt nicht das Zielprogramm.

`MigrateToAmm` bleibt für einen bestehenden `PoolState` aufrufbar, der mit `migrate_type = 0` vor dieser Einschränkung initialisiert wurde. Die Veröffentlichung schreibt den bestehenden Pool-Status nicht um und entfernt die Legacy-Anweisung nicht.

**Quote-seitiges Token-Programm.** Der Quote-Mint kann entweder dem SPL Token-Programm oder Token-2022 gehören. Jede Anweisung, die ihn berührt — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, alle vier Handelsanweisungen, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee` und `ClaimPlatformFeeFromVault` — nimmt das besitzende Programm in seinem Quote-Programm-Kontoslot. Kontopositionen haben sich nicht geändert; nur der akzeptierte Wert hat sich geändert. Übergeben Sie das Programm, das tatsächlich `GlobalConfig.quote_mint` besitzt, das Sie aus `PoolState.token_program_flag` Bit1 für einen bestehenden Launch lesen können (siehe [`accounts`](/de/products/launchlab/accounts#poolstate)) oder andernfalls vom Mint-Konto-Besitzer.

Das veraltete `Initialize` ist die Ausnahme: sein Quote-Programm-Konto ist immer noch auf SPL Token typisiert, daher muss eine Konfiguration, deren Quote-Mint Token-2022 ist, durch `InitializeV2` oder `InitializeWithToken2022` gestartet werden.

`MigrateToCpswap` ist die andere Ausnahme, in die entgegengesetzte Richtung — es nimmt **beide** Programme bedingungslos statt eines pro Mint. Siehe [die Migrations-Konten unten](#cpmm-migrations-token-programme).

## `Initialize`

Erstelle einen neuen Launch.

**Argumente**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // oder initial_virtual_quote_reserve für curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // inline name/symbol/uri; Programm CPI zu Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Konten** (gekürzt)

| # | Name | W | S | Notizen |
|---|------|---|---|-------|
| 1 | `creator` | W | S | Zahlt Miete + Base-Mint-Erstellung. |
| 2 | `launch_config` |   |   | Protokoll-Konfigurationsbindung. |
| 3 | `launch_state` | W |   | Neues Konto. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Frischer Keypair (oder PDA) — diese Anweisung initialisiert ihn. |
| 6 | `base_vault` | W |   | ATA von `launch_authority` auf `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA von `launch_authority` auf `quote_mint`. |
| 9 | `metadata` | W |   | Metaplex-Metadaten-PDA. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token für den Base-Mint. `InitializeV2` und `InitializeWithToken2022` nehmen ein separates Quote-Programm-Konto, das entweder Programm sein kann. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Vorbedingungen**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Gebührenparameter bestehen `launch_config.max_*_fee_rate`-Prüfungen.
- `open_time ≥ now − slop` (SDK erzwingt `≥ now`; Programm toleriert leichte Rückdatierung).
- `curve_type` wird erkannt.

**Nachbedingungen**

- `base_mint` hat `supply = base_supply_max`, alles in `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` initialisiert mit `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` berechnet aus Kurvenparametern + `base_supply_graduation` + `buy_numerator` (ungefähr).

**Häufige Fehler** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (kanonische Variante: `BuyExactIn`)

Benutzer stellt einen festen `quote_in` bereit; die Kurve berechnet `base_out`.

**Argumente**

```
quote_in:          u64
minimum_base_out:  u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Vorbedingungen**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Effekt**

1. Teile `quote_in` in `quote_in_after_fee` und die Gebührenteile auf.
2. Newton-Löse die Kurve für `base_out` gegeben die Post-Gebühren-Quote.
3. `require(base_out ≥ minimum_base_out)` sonst revert `ExceededSlippage`.
4. Verschiebe `quote_in` Benutzer → Vault. Verschiebe `base_out` Vault → Benutzer.
5. Aktualisiere `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Aktualisiere Gebührenzähler (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Wenn `quote_reserve_real ≥ quote_reserve_target` nach der Aktualisierung, verkettete das SDK typischerweise eine `Graduate`-Anweisung in derselben Transaktion. Das Programm graduiert nicht automatisch innerhalb von `Buy` — eine nachfolgende `Graduate` ist erforderlich.

## `BuyExactOut`

Benutzer gibt den exakten `base_out` an; Programm berechnet `quote_in`.

**Argumente**

```
base_out:      u64
maximum_quote_in: u64
```

Gleiche Konten wie `BuyExactIn`. Verwendet das geschlossene Integral (oder CPMM-Inverse für curve_type 1) statt Newton-Iteration.

## `Sell` / `SellExactIn` / `SellExactOut`

Spiegelbild von `Buy`. Benutzer gibt `base_in` an die Kurve zurück und erhält `quote_out`. Die Gebühr wird von `quote_out` abgezogen, daher erhält der Benutzer weniger als die rohen integrierten Einnahmen.

**Vorbedingungen** —

- `user_base_ata.balance ≥ base_in`.
- Verkauf kann `base_sold` nicht unter 0 drücken (redundant mit dem obigen, wenn die Buchhaltung konsistent ist).
- Launch ist `Active`.

**Effekt** — symmetrisch zu `Buy`. `base_sold` sinkt, `quote_reserve_real` sinkt. Gebühren fallen weiterhin an.

### Quote-seitige Transfergebühren

Wenn der Quote-Mint eine `TransferFeeConfig` trägt, unterscheiden sich der Betrag, den der Vault bewegt, und der Betrag, um den der Zahler belastet oder gutgeschrieben wird, und die Slippage-Grenze wird gegen die Zahlerseite geprüft. Bei einem Quote-Mint ohne die Erweiterung ist jeder Fall unten identisch mit einem einfachen Legacy-Mint.

| Anweisung | Argument | Geprüft gegen |
|---|---|---|
| `BuyExactIn` | `amount_in` | Die Kurve wird auf `amount_in − transfer_fee(amount_in)` bepreist — was den Vault erreicht. Eine vollständige Füllung belastet genau `amount_in`; eine teilweise Füllung belastet den verbrauchten Vault-Betrag plus seine inverse Gebühr. |
| `BuyExactOut` | `maximum_amount_in` | Der Vault-Betrag **plus** die inverse Transfergebühr — die echte Belastung. |
| `SellExactIn` | `minimum_amount_out` | Was der Verkäufer behält, nachdem der Mint seine Gebühr einbehalten hat, nicht der Bruttobetrag, der den Vault verlässt. |
| `SellExactOut` | `amount_out` | Genau geliefert. Die Kurve zielt auf `amount_out` plus die inverse Transfergebühr. |

Zwei Konsequenzen für Quoting:

- Eine Grenze, die berechnet wird, als ob der Mint gebührenfrei wäre, wird abgelehnt. Übergabe der gebührenfreien Kosten als `maximum_amount_in` oder der gebührenfreien Einnahmen als `minimum_amount_out` reverts mit `ExceededSlippage`.
- `real_quote` rückt nur um das vor, was den Vault erreichte. Ein `BuyExactIn` von `amount_in` auf einem 5%-Quote-Mint bewegt `real_quote` um `amount_in × 0.95`.

Ein 100%-Gebühren-Quote-Mint (`10000` Basispunkte) kann nicht invertiert werden und reverts mit `CalculateOverflow` auf den Exact-Out-Pfaden.

Beide Handelsseiten-Mints sind auch auf das Programm beschränkt, das in ihrem passenden Slot übergeben wird, daher schlägt ein nicht übereinstimmender `base_token_program` jetzt fehl, statt ignoriert zu werden. Siehe [`algorithms/token-2022-transfer-fees`](/de/algorithms/token-2022-transfer-fees) für die zugrunde liegende Gebührenmathe.

## `MigrateToAmm` / `MigrateToCpswap`

Graduiere einen Launch in einen handelbaren Pool, sobald die Kurve `total_quote_fund_raising` erreicht hat. Neue Launches sind nur CPMM. `MigrateToAmm` wird für bestehende Pools beibehalten, deren gespeicherter `migrate_type` `0` ist.

**Wer unterzeichnet**

- `MigrateToAmm` — das `migrate_to_amm_wallet`, das auf der Bindungs-`GlobalConfig` aufgezeichnet ist.
- `MigrateToCpswap` — das `migrate_to_cpswap_wallet`, das auf der Bindungs-`GlobalConfig` aufgezeichnet ist.

Diese Wallets werden typischerweise vom Raydium-betriebenen Graduierungs-Crank gehalten; in der Praxis landet die Graduierung Sekunden, nachdem der Schwellenwert überschritten wird, unabhängig davon, wer den endgültigen Kauf ausgelöst hat.

**Argumente**

`MigrateToAmm` nimmt drei (hauptsächlich OpenBook-Marktparameter, die das Programm an AMM v4 weiterleitet):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` nimmt keine.

**Effekt (gemeinsam für beide)**

1. Verifiziere `pool_state.status == Migrate` (d.h. `quote_reserve_target` wurde erreicht). Sonst revert mit `PoolMigrated` (Status war bereits `Migrated`) oder `PoolFunding` (noch in Finanzierung).
2. Verifiziere `pool_state.migrate_type` stimmt mit der Anweisung überein (`0` für AMM, `1` für CPMM). Sonst revert mit `MigrateTypeNotMatch`.
3. Berechne die Post-Graduierungs-Reserven:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI in das Zielprogramm (`AMM v4 Initialize2` oder `CPMM InitializeWithPermission`) mit diesen Reserven, um den Post-Graduierungs-Pool zu erstellen.
5. Für CPMM-Migrationen, die nach dem 2026-08-17-Upgrade ausgeführt werden, kombiniere `platform_scale + creator_scale` in einen plattformgesammelten gesperrten LP-Anteil und präge höchstens einen Fee-Key-NFT zu `platform_nft_wallet`. Verbrenne den `burn_scale`-Rest. Vor dem Upgrade war `creator_scale` separat gesperrt und sein Fee-Key ging an den Token-Ersteller. Abgeschlossene historische Migrationen werden nicht geändert. Für Legacy-AMM-v4-Graduierung folgt die LP-Disposition dem bestehenden Fluss dieser Anweisung.
6. Widerrufe `base_mint.mint_authority` (setze auf `None`).
7. Kippe `pool_state.status = Migrated`, setze `vesting_schedule.start_time = block_time + cliff_period`.

**Nachbedingungen** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` werden von diesem Punkt an mit `PoolMigrated` ablehnen. Der resultierende AMM-Pool ist kanonisch und handelt wie jeder andere AMM-v4- / CPMM-Pool.

**Häufige Fehler** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### CPMM-Migrations-Restkonten

Clients, die `MigrateToCpswap` erstellen, müssen diese festen `remaining_accounts`-Indizes verwenden:

| Index | Konto |
|---|---|
| 0–4 | Fee-Key-Besitzer der Plattform, Mint, Token-Konto, gesperrte Liquiditäts-PDA und Metadaten-Konto |
| 5 | Ursprünglicher Launch-Ersteller; verwendet, wenn `platform_cp_creator` nicht gesetzt ist |
| 6 | CPMM-Berechtigungs-PDA abgeleitet von `[b"permission", launch_authority]` |
| 7 | Konfigurierter `platform_cp_creator`; verwendet, wenn das Feld nicht Standard ist |
| 8 | CPMM-Support-Mint-PDA für sortiertes `mint0`, abgeleitet von `[b"support_mint", mint0]` |
| 9 | CPMM-Support-Mint-PDA für sortiertes `mint1`, abgeleitet von `[b"support_mint", mint1]` |

Die Anweisung erfordert mindestens zehn Restkonten auf dem aktualisierten Pfad. Die Support-Mint-Konten sind schreibgeschützte CPI-Eingaben. Leite beide Adressen ab, auch wenn der Mint keinen initialisierten Support-Datensatz hat. Ältere Builder, die immer noch Creator-Lock-Konten anhängen oder Indizes 8–9 weglassen, müssen aktualisiert werden.

### CPMM-Migrations-Token-Programme

`MigrateToCpswap` nimmt beide Token-Programme bedingungslos und arbeitet heraus, welches Programm jeden Mint besitzt. Seine zwei Token-Programm-Konten wurden entsprechend umbenannt:

| Position | Konto | Wert |
|---|---|---|
| first | `token_program` | Immer das Legacy-SPL-Token-Programm |
| second | `token_program_2022` | Immer das Token-2022-Programm |

Sie ersetzen das frühere `base_token_program` (welches Programm auch den Base-Mint besaß) und `quote_token_program` (immer Legacy). Positionen sind unverändert, daher ist dies eine Wertänderung statt einer Layout-Änderung — aber die zwei Werte sind nahe beieinander invertiert, und ein Builder, der sein altes Paar weitergibt, wird Token-2022 liefern, wo das Legacy-Programm erforderlich ist, sobald einer der Mints ein Token-2022-Mint ist.

Das Legacy-Programm ist erforderlich, auch wenn keiner der Mints es verwendet, da der CPMM-LP-Mint und der gesperrte Liquiditäts-Fee-Key-NFT immer darauf leben.

## Plattform-`GlobalConfig`-Allowlist

`PlatformConfig.restrict_global_config` steuert die Prüfung:

- `0`: die Plattform akzeptiert jede ansonsten gültige `GlobalConfig`; kein Allow-Konto ist erforderlich.
- `1`: `Initialize`, `InitializeV2` und `InitializeWithToken2022` müssen die passende `PlatformAllowConfig` irgendwo in `remaining_accounts` enthalten.

Der Plattform-Admin erstellt oder schließt die PDA mit `CreatePlatformAllowConfig` und `ClosePlatformAllowConfig`. Seine Seeds sind `[b"platform_allow_config", platform_config, global_config]`. Die früheren Admin-verwalteten `PlatformGlobalAccess`-Anweisungen und PDA sind veraltet.
