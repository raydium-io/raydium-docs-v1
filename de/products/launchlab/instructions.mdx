## Anweisungsbestand

| Gruppe | Anweisung | Aufrufbar durch |
|-------|-----------|-----------------|
| Globale Konfiguration | `CreateConfig` / `UpdateConfig` | Programm-Admin; die delegierte Create-Config-Autorität kann auch `CreateConfig` aufrufen |
| Launch-Lebenszyklus | `Initialize` / `InitializeV2` | Jeder (Ersteller) — SPL Token Launches; V2 zeichnet `amm_creator_fee_on` für die eventuelle CPMM-Graduierung auf |
| Launch-Lebenszyklus | `InitializeWithToken2022` | Jeder (Ersteller) — Token-2022 Launch, optionale `TransferFeeConfig` |
| Handel | `BuyExactIn` / `BuyExactOut` | Jeder — exakte Eingabe / exakte Ausgabe Kauf auf der Bindungskurve |
| Handel | `SellExactIn` / `SellExactOut` | Jeder — exakte Eingabe / exakte Ausgabe Verkauf auf der Bindungskurve |
| Graduierung | `MigrateToAmm` | Migrations-Wallet — Legacy-AMM-v4-Graduierung für Pools, die vor der Durchsetzung der CPMM-only-Erstellung initialisiert wurden. |
| Graduierung | `MigrateToCpswap` | Migrations-Wallet — Graduierung zu CPMM. Alle neu initialisierten Launches verwenden diesen Pfad. Umhüllt `InitializeWithPermission` auf CPMM. |
| Gebühren | `CollectFee` | Admin — Protokollgebühren aus einem Launch einziehen |
| Gebühren | `CollectMigrateFee` | Admin — aufgelaufene Migrationsgebühren einziehen |
| Gebühren | `ClaimCreatorFee` | Ersteller — aufgelaufene Ersteller-Gebühren während der Kurvenphase einfordern |
| Vesting | `CreateVestingAccount` | Ersteller — gesperrte Token an einen Begünstigten zuordnen, entsperrt nach Graduierung |
| Vesting | `CreatePlatformVestingAccount` | Plattform-Admin — gesperrte Token an plattformseitige Begünstigte zuordnen |
| Vesting | `ClaimVestedToken` | Begünstigter — entsperrte Token nach der Cliff einfordern |
| Plattformkonfiguration | `CreatePlatformConfig` / `UpdatePlatformConfig` | Plattform-Admin |
| Plattformkonfiguration | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Plattform-Admin — verwalten Sie die pro-Plattform-Liste der zulässigen Kurvenformen |
| Plattformgebühren | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Plattform-Admin |
| Plattformzugriff | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Plattform-Admin — verwalten Sie die `GlobalConfig`-Allowlist, die verwendet wird, wenn diese Plattform die Einschränkung aktiviert |

Die Aufteilung „ExactIn/ExactOut" spiegelt CPMMs `SwapBaseInput` / `SwapBaseOutput` wider — on-chain sind sie separate Anweisungs-Diskriminatoren mit leicht unterschiedlichem Rounding.

**Graduierungspfad-Auswahl.** Jeder neue `Initialize`-, `InitializeV2`- und `InitializeWithToken2022`-Aufruf muss `migrate_type = 1` (`CPSWAP`) setzen. Jeder Versuch, einen neuen AMM-v4-gebundenen Pool zu initialisieren, gibt `MigrateTypeNotMatch` zurück. `amm_creator_fee_on` wählt nur aus, ob die resultierende CPMM-Ersteller-Gebühr auf das Quote-Token oder beide Token angewendet wird; es wählt nicht das Ziel-Programm aus.

`MigrateToAmm` bleibt für einen bestehenden `PoolState` aufrufbar, der mit `migrate_type = 0` vor dieser Einschränkung initialisiert wurde. Die Veröffentlichung schreibt den bestehenden Pool-Status nicht um und entfernt die Legacy-Anweisung nicht.

## `Initialize`

Erstellen Sie einen neuen Launch.

**Argumente**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // oder initial_virtual_quote_reserve für curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // inline name/symbol/uri; Programm CPIs zu Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Konten** (gekürzt)

| # | Name | W | S | Notizen |
|---|------|---|---|---------|
| 1 | `creator` | W | S | Zahlt Miete + Base-Mint-Erstellung. |
| 2 | `launch_config` |   |   | Protokoll-Konfigurationsbindung. |
| 3 | `launch_state` | W |   | Neues Konto. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Frisches Keypair (oder PDA) — diese Anweisung initialisiert es. |
| 6 | `base_vault` | W |   | ATA von `launch_authority` auf `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA von `launch_authority` auf `quote_mint`. |
| 9 | `metadata` | W |   | Metaplex-Metadaten-PDA. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | Nur SPL Token. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Vorbedingungen**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Gebührenparameter bestehen `launch_config.max_*_fee_rate`-Prüfungen.
- `open_time ≥ now − slop` (SDK erzwingt `≥ now`; Programm toleriert leichte Rückdatierung).
- `curve_type` wird erkannt.

**Nachbedingungen**

- `base_mint` hat `supply = base_supply_max`, alles in `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` initialisiert mit `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` berechnet aus Kurvenparametern + `base_supply_graduation` + `buy_numerator` (ungefähr).

**Häufige Fehler** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (kanonische Variante: `BuyExactIn`)

Benutzer stellt ein festes `quote_in` bereit; die Kurve berechnet `base_out`.

**Argumente**

```
quote_in:          u64
minimum_base_out:  u64
```

**Konten**

| # | Name | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Vorbedingungen**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Effekt**

1. Teilen Sie `quote_in` in `quote_in_after_fee` und die Gebührenteile auf.
2. Newton-Lösen Sie die Kurve für `base_out` gegeben das Post-Gebühren-Quote.
3. `require(base_out ≥ minimum_base_out)` sonst revert `ExceededSlippage`.
4. Verschieben Sie `quote_in` Benutzer → Vault. Verschieben Sie `base_out` Vault → Benutzer.
5. Aktualisieren Sie `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Aktualisieren Sie Gebührenzähler (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Wenn `quote_reserve_real ≥ quote_reserve_target` nach der Aktualisierung, verkettete das SDK typischerweise eine `Graduate`-Anweisung in derselben Transaktion. Das Programm graduiert nicht automatisch innerhalb von `Buy` — eine nachfolgende `Graduate` ist erforderlich.

## `BuyExactOut`

Benutzer gibt das exakte `base_out` an; Programm berechnet `quote_in`.

**Argumente**

```
base_out:      u64
maximum_quote_in: u64
```

Gleiche Konten wie `BuyExactIn`. Verwendet die geschlossene quadratische Integralform (oder CPMM-Inverse für curve_type 1) statt Newton-Iteration.

## `Sell` / `SellExactIn` / `SellExactOut`

Spiegelbild von `Buy`. Benutzer gibt `base_in` an die Kurve zurück und erhält `quote_out`. Die Gebühr wird von `quote_out` abgezogen, daher erhält der Benutzer weniger als die rohen integrierten Einnahmen.

**Vorbedingungen** —

- `user_base_ata.balance ≥ base_in`.
- Verkauf kann `base_sold` nicht unter 0 drücken (redundant mit dem obigen, wenn die Buchhaltung konsistent ist).
- Launch ist `Active`.

**Effekt** — symmetrisch zu `Buy`. `base_sold` sinkt, `quote_reserve_real` sinkt. Gebühren fallen weiterhin an.

## `MigrateToAmm` / `MigrateToCpswap`

Graduieren Sie einen Launch in einen handelbaren Pool, sobald die Kurve `total_quote_fund_raising` erreicht hat. Neue Launches sind nur CPMM. `MigrateToAmm` wird für bestehende Pools beibehalten, deren gespeicherter `migrate_type` `0` ist.

**Wer unterzeichnet**

- `MigrateToAmm` — das `migrate_to_amm_wallet`, das auf der Bindungs-`GlobalConfig` aufgezeichnet ist.
- `MigrateToCpswap` — das `migrate_to_cpswap_wallet`, das auf der Bindungs-`GlobalConfig` aufgezeichnet ist.

Diese Wallets werden typischerweise von der Raydium-betriebenen Graduierungs-Crank gehalten; in der Praxis landet die Graduierung Sekunden nach dem Überschreiten des Schwellwerts, unabhängig davon, wer den endgültigen Kauf ausgelöst hat.

**Argumente**

`MigrateToAmm` nimmt drei (hauptsächlich OpenBook-Marktparameter, die das Programm an AMM v4 weiterleitet):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` nimmt keine.

**Effekt (gemeinsam für beide)**

1. Überprüfen Sie `pool_state.status == Migrate` (d. h. `quote_reserve_target` wurde erreicht). Andernfalls revert mit `PoolMigrated` (Status war bereits `Migrated`) oder `PoolFunding` (noch in Finanzierung).
2. Überprüfen Sie, dass `pool_state.migrate_type` der Anweisung entspricht (`0` für AMM, `1` für CPMM). Andernfalls revert mit `MigrateTypeNotMatch`.
3. Berechnen Sie die Post-Graduierungs-Reserven:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI in das Ziel-Programm (`AMM v4 Initialize2` oder `CPMM InitializeWithPermission`) mit diesen Reserven, um den Post-Graduierungs-Pool zu erstellen.
5. Für CPMM-Migrationen, die nach dem 2026-08-17-Upgrade ausgeführt werden, kombinieren Sie `platform_scale + creator_scale` in einen plattformeigenen gesperrten LP-Anteil und prägen Sie höchstens einen Fee-Key-NFT zu `platform_nft_wallet`. Verbrennen Sie den `burn_scale`-Rest. Vor dem Upgrade war `creator_scale` separat gesperrt und sein Fee-Key ging an den Token-Ersteller. Abgeschlossene historische Migrationen werden nicht geändert. Für Legacy-AMM-v4-Graduierung folgt die LP-Disposition dem bestehenden Fluss dieser Anweisung.
6. Widerrufen Sie `base_mint.mint_authority` (setzen Sie auf `None`).
7. Kippen Sie `pool_state.status = Migrated`, setzen Sie `vesting_schedule.start_time = block_time + cliff_period`.

**Nachbedingungen** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` werden von diesem Punkt an mit `PoolMigrated` ablehnen. Der resultierende AMM-Pool ist kanonisch und handelt wie jeder andere AMM-v4- / CPMM-Pool.

**Häufige Fehler** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### CPMM-Migrations-Restkonten

Clients, die `MigrateToCpswap` erstellen, müssen diese festen `remaining_accounts`-Indizes verwenden:

| Index | Konto |
|---|---|
| 0–4 | Fee-Key-Eigentümer der Plattform, Mint, Token-Konto, gesperrte Liquiditäts-PDA und Metadaten-Konto |
| 5 | Ursprünglicher Launch-Ersteller; verwendet, wenn `platform_cp_creator` nicht gesetzt ist |
| 6 | CPMM-Berechtigungs-PDA abgeleitet von `[b"permission", launch_authority]` |
| 7 | Konfigurierter `platform_cp_creator`; verwendet, wenn das Feld nicht standardmäßig ist |
| 8 | CPMM-Support-Mint-PDA für sortiertes `mint0`, abgeleitet von `[b"support_mint", mint0]` |
| 9 | CPMM-Support-Mint-PDA für sortiertes `mint1`, abgeleitet von `[b"support_mint", mint1]` |

Die Anweisung erfordert mindestens zehn Restkonten auf dem aktualisierten Pfad. Die Support-Mint-Konten sind schreibgeschützte CPI-Eingaben. Leiten Sie beide Adressen ab, auch wenn der Mint keinen initialisierten Support-Datensatz hat. Ältere Builder, die immer noch Creator-Lock-Konten anhängen oder Indizes 8–9 weglassen, müssen aktualisiert werden.

## Plattform-`GlobalConfig`-Allowlist

`PlatformConfig.restrict_global_config` steuert die Prüfung:

- `0`: Die Plattform akzeptiert jede ansonsten gültige `GlobalConfig`; kein Allow-Konto ist erforderlich.
- `1`: `Initialize`, `InitializeV2` und `InitializeWithToken2022` müssen die passende `PlatformAllowConfig` irgendwo in `remaining_accounts` enthalten.

Der Plattform-Admin erstellt oder schließt die PDA mit `CreatePlatformAllowConfig` und `ClosePlatformAllowConfig`. Ihre Seeds sind `[b"platform_allow_config", platform_config, global_config]`. Die früheren Admin-verwalteten `PlatformGlobalAccess`-Anweisungen und PDA sind veraltet.

## `CollectFee`

Admin-Einzug der aufgelaufenen Handelsgebühren des Protokolls auf einem einzelnen Launch.

**Argumente** — keine.

**Konten**

| # | Name | W | S | Notizen |
|---|------|---|---|---------|
| 1 | `protocol_fee_owner` |   | S | Muss gleich `global_config.protocol_fee_owner` sein. |
| 2 | `authority` |   |   | PDA `[b"vault_auth_seed"]`; unterzeichnet die Vault-Übertragung. |
| 3 | `pool_state` | W |   | Mutiert, um `quote_protocol_fee` zu nullen. |
| 4 | `global_config` |   |   | Quelle der Wahrheit für den Unterzeichner. |
| 5 | `quote_vault` | W |   | Geleert durch `quote_protocol_fee`. |
| 6 | `recipient_token_account` | W |   | ATA von `protocol_fee_owner` auf `quote_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `token_program` |   |   | SPL Token (das Quote-Mint ist immer SPL Token). |

**Effekt** — Übertragen Sie `pool_state.quote_protocol_fee` von `quote_vault` zu `recipient_token_account`, dann nullen Sie den Zähler. Aufrufbar jederzeit nach dem ersten Kauf.

## `CollectMigrateFee`

Admin-Einzug der bei der Graduierung aufgelaufenen Migrationsgebühr. Gleiche Kontoform wie `CollectFee` mit `migrate_fee_owner` als Unterzeichner (statt `protocol_fee_owner`) und `pool_state.migrate_fee` als geleerten Zähler.

**Argumente** — keine.

**Konten**

| # | Name | W | S | Notizen |
|---|------|---|---|---------|

| 5 | `quote_mint` |   |   | |

**Effekt** — Übertragen Sie den gesamten Saldo von `creator_fee_vault` zu `recipient_token_account`. Revert mit einer Require-Größer-als-Null-Prüfung, wenn der Vault leer ist.
