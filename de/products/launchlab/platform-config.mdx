<Info>
  `PlatformConfig` ist die **Plattformebenen**-Überlagerung, die auf [`GlobalConfig`](/de/products/launchlab/global-config) aufsetzt. Während `GlobalConfig` die protokollweiten Regeln definiert („Handelsgebühr ist 1 %, Angebot muss mindestens 10 Mio. sein, nur dieses Wallet kann graduieren"), nutzt `PlatformConfig` jede Startplattform — pump.fun, Raydiums eigene UI, Drittanbieter-Launchpads — um ihre Gebühr hinzuzufügen, ihren Anteil am LP nach der Graduierung zu beanspruchen, einzuschränken, welche Startparameter ihre Starts wählen können, und ihr Branding (Name, Website, Bild) on-chain anzuzeigen.

## Was es ist

Ein `PlatformConfig`-Konto verwaltet fünf übergreifende Belange einer Plattform:

1. **Branding** — Name, Website, Bildlink, alle inline gespeichert, damit jeder Explorer oder Aggregator die Plattform anzeigen kann, die einen Token gestartet hat.
2. **Plattformgebühr** — eine zusätzliche Handelsgebühr (`fee_rate`) auf top der `trade_fee_rate` des Protokolls. Sammelt sich im `platform_fee_wallet` der Plattform an. Begrenzt auf 500 bps (`50000`) sowohl beim Erstellen als auch beim Aktualisieren, erhöht von 100 bps (`10000`) am 2026-08-26 — siehe [Gebührengrenzen](#gebührengrenzen).
3. **LP-Migrationszuteilung** — drei gespeicherte Ganzzahlen (`platform_scale`, `creator_scale`, `burn_scale`), die sich zu `1_000_000` addieren. Vor dem Upgrade vom 2026-08-17 erzeugte die Creator-Skala einen separaten Creator Fee Key. Migrationen, die nach dem Upgrade ausgeführt werden, kombinieren die ersten beiden in eine plattformeigene gesperrte LP-Zuteilung; der Rest wird verbrannt.
4. **Startparameter-Regeln** — eine optionale Einschränkung (`restrict_curve_param`), die einen Start dazu verpflichtet, das [`PlatformCurveRule`](/de/products/launchlab/curve-rules)-Konto der ausgewählten `GlobalConfig` zu erfüllen. Regeln unterstützen Wertbänder, alternative Stufen und Token-Typ-Gating; sie leben in eigenen Konten, nicht auf `PlatformConfig`.
5. **Global-Config-Allowlist** — eine optionale Einschränkung, die erfordert, dass eine plattformerstellte `PlatformAllowConfig` für die ausgewählte `GlobalConfig` vorhanden ist.

## Layout

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (denominator 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (denominator 10_000)

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // signs ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // receives the platform NFT slice at CPMM graduation
    pub platform_scale:              u64,               // share of LP minted to platform NFT
    pub creator_scale:               u64,               // creator share before upgrade; added to platform share afterward
    pub burn_scale:                  u64,               // share of LP burned permanently
    pub fee_rate:                    u64,               // platform's trade fee (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 padded with zeros
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig that the post-grad pool will bind to
    pub creator_fee_rate:            u64,               // creator-side fee taken pre-graduation
    pub transfer_fee_extension_auth: Pubkey,            // for Token-2022 launches: withdraw-withheld authority from mint creation, fee-config authority from graduation
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // platform's slice of total_locked_amount
    pub platform_cp_creator:         Pubkey,            // optional creator-of-record on the post-graduation CPMM pool
    pub restrict_global_config:      u8,                // 0 = unrestricted, 1 = require allow PDA
    pub restrict_curve_param:        u8,                // 0 = unrestricted, 1 = enforce the PlatformCurveRule
    pub curve_rule_manager:          Pubkey,            // hot wallet allowed to manage rule accounts
    pub padding:                     [u8; 78],
}
```

Das Konto ist eine feste Größe von 944 Bytes. Es enthielt ein nachfolgendes `Vec<PlatformCurveParam>` bis zum Release vom 2026-08-31, das Startparameter in [`PlatformCurveRule`](/de/products/launchlab/curve-rules)-Konten verschob; `restrict_curve_param`, `curve_rule_manager` und die 4 Bytes, die das Längenpräfix des Vektors belegten, kommen alle aus dem Padding, daher sind die Bytezahl und alle früheren Feldoffsets unverändert. Siehe [den Changelog-Eintrag](/de/reference/changelog/2026-08-31-launchlab-platform-curve-rules) für die erforderlichen Decoder-Änderungen.

`platform_scale + creator_scale + burn_scale` muss gleich `1_000_000` sein. Vor dem Upgrade vom 2026-08-17 war `creator_scale` separat gesperrt und sein Fee Key ging an den Token-Creator. Bei Migrationen, die nach dem Upgrade ausgeführt werden, wird es zu `platform_scale` addiert und seine gesperrten LP-Rechte gehen stattdessen an die Plattform. Beispielergebnisse unter der aktualisierten Logik:

- `(0, 100_000, 900_000)` — 90 % LP verbrannt, 10 % an die Plattform gesperrt.
- `(50_000, 100_000, 850_000)` — 85 % verbrannt, 15 % an die Plattform gesperrt.
- `(0, 0, 1_000_000)` — vollständig verbrannt, keine NFT-Prägungen. Strikte „keine Insider"-Starts.

## Branding-Felder

`name`, `web` und `img` sind Inline-Byte-Arrays, die mit Nullen bis zu ihren Größenkonstanten aufgefüllt sind. Um sie als Strings zu lesen, schneiden Sie bis zum ersten `\0`:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

Die Konstanten sind absichtlich großzügig (`name: 64`, `web: 256`, `img: 256`), damit Plattformen genug Metadaten für Explorer und Aggregatoren einbeziehen können, ohne Off-Chain-Speicher zu berühren. Alles, das diese Größen überschreitet, wird bei `CreatePlatformConfig` mit `InvalidInput` zurückgewiesen.

## Gebührenmechanik

Ein Swap auf einer Kurve, die an eine `PlatformConfig` gebunden ist, erhebt drei gestaffelte Gebühren:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` sammelt sich beim `protocol_fee_owner` des Protokolls an (beansprucht über `CollectFee`).
- `platform_fee` sammelt sich in einem plattformspezifischen Tresor an (beansprucht über `ClaimPlatformFee` oder `ClaimPlatformFeeFromVault`; siehe [`instructions`](/de/products/launchlab/instructions)).
- `creator_fee` sammelt sich in einem Creator-spezifischen Tresor an, der durch den öffentlichen Schlüssel des Creators + Quote-Mint gekennzeichnet ist (beansprucht über `ClaimCreatorFee`).

### Gebührengrenzen

Beide Sätze sind in `1/1_000_000` denominiert, daher ist `5000` 50 bps und `50000` 500 bps.

| Satz | Grenze | Erzwungen in |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` beim Erstellen — wird mit `InvalidInput` zurückgewiesen. `update_platform_fee_rate` bei jeder Update-Variante, die es berührt (`FeeRate` und `AllInfo`) — wird mit `InvalidPlatformInfo` zurückgewiesen. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` beim Erstellen und `update_creator_fee_rate` beim Update — beide werden mit `InvalidPlatformInfo` zurückgewiesen. |

Die zwei Erzwingungspunkte für `fee_rate` sind separate `require!`-Aufrufe in verschiedenen Dateien, daher tragen sie unterschiedliche Fehlercodes, aber sie wenden die gleiche Obergrenze an. Eine Plattform, die mit einem zulässigen Satz erstellt wurde, kann später bearbeitet werden, auch über die `AllInfo`-Bulk-Variante, die jedes Feld auf einmal umschreibt.

Beide `fee_rate`-Grenzen waren ursprünglich 100 bps (`10000`). Die Update-Grenze verschob sich am 2026-01-27 zu `25000` (250 bps); am 2026-08-26 verschoben sich beide zu `50000` (500 bps) — siehe [den Changelog-Eintrag](/de/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` begrenzt **nicht** einen der beiden Sätze. Es begrenzt das Pro-Transaktion-Argument `share_fee_rate`, das die vier Swap-Anweisungen annehmen — die Referral-Gebühr — und nichts anderes. Siehe [`global-config`](/de/products/launchlab/global-config#fees).

## Token-2022-Transfergebühren-Autoritäten

`transfer_fee_extension_auth` benennt den Plattformschlüssel, der am Ende die `TransferFeeConfig`-Autoritäten des Basis-Mints hält, wenn ein Start durch `InitializeWithToken2022` mit einer angehängten Transfergebühr erstellt wird. Die Erweiterung trägt zwei Autoritäten, und sie werden zu **verschiedenen Punkten im Start-Lebenszyklus** übergeben:

| Autorität | Inhaber bei Mint-Erstellung | Inhaber nach `MigrateToCpswap` |
|---|---|---|
| `withdraw_withheld_authority` — hebt die Gebühren ab, die Token-2022 auf Token-Konten einbehält | `transfer_fee_extension_auth`, direkt in den Mint geschrieben. Fällt auf die Launch-`authority`-PDA zurück, wenn das Feld `Pubkey::default()` ist. | Bereits der Plattformschlüssel, daher bewegt sich nichts. Migration weist ihn nur neu zu, wenn die `authority`-PDA ihn noch hält. |
| `transfer_fee_config_authority` — ändert den Gebührensatz und die maximale Gebühr | Immer die Launch-`authority`-PDA. | `transfer_fee_extension_auth`, vorausgesetzt, dieses Feld ist nicht Standard. |

Vor 2026-08-27 wurde der Mint mit der `authority`-PDA auf beiden Autoritäten erstellt, und beide verschoben sich bei der Graduierung zur Plattform. Das Programm stellt keine Withdraw-Withheld- oder Harvest-Anweisung bereit, daher waren während der Bonding-Curve-Phase einbehaltene Gebühren bis zur Graduierung des Starts unerreichbar. Das Schreiben der Withdraw-Seite bei der Mint-Erstellung macht sie ab dem ersten Trade beanspruchbar — siehe [den Changelog-Eintrag](/de/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority).

Zwei Konsequenzen, die es wert sind, geplant zu werden:

- **Stellen Sie das Feld vor dem Start ein, nicht danach.** Ein Start, der erstellt wird, während `transfer_fee_extension_auth` `Pubkey::default()` ist, setzt die `authority`-PDA auf die Withdraw-Seite. Das Feld später einzustellen funktioniert immer noch — die Graduierung findet die PDA an Ort und Stelle und übergibt die Autorität — aber nichts kann den einbehaltenen Saldo in der Zwischenzeit abheben.
- **Das Feld zwischen Start und Graduierung zu rotieren, teilt die beiden Autoritäten auf.** Ändern Sie `transfer_fee_extension_auth` zwischen der Erstellung eines Starts und seiner Graduierung, und die Withdraw-Withheld-Autorität des Mints bleibt bei dem Schlüssel, der bei der Erstellung konfiguriert wurde (die PDA hält ihn nicht mehr, daher überspringt die Migration diese Übergabe), während die Fee-Config-Autorität zum neuen Schlüssel geht. Rotieren Sie zwischen Starts, oder planen Sie, die beiden Schlüssel selbst durch Token-2022 direkt abzustimmen.

Eine Plattform, die das Feld für das ganze Leben eines Starts bei `Pubkey::default()` lässt, behält beide Autoritäten auf der `authority`-PDA dauerhaft: der Gebührensatz kann nie geändert werden und der einbehaltene Saldo kann nie abgehoben werden. Hängen Sie eine Transfergebühr an einen Start an, nur wenn die Plattform beabsichtigt, diese Schlüssel zu halten.

## NFT-Migrationszuteilung (nur CPMM)

Wenn ein Start zu CPMM graduiert, teilt die Migrationsanweisung die von `CPMM::InitializeWithPermission` geprägten LP-Token auf zwei Arten auf:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

Wenn `lp_to_platform` nicht null ist, wickelt das LP-Lock-Programm es in einen Fee Key NFT ein, der von `platform_nft_wallet` besessen wird. Dies ersetzt das Verhalten vor dem Upgrade, das separate Platform- und Creator-Fee-Keys erstellte. Fee Keys, die von vor dem Upgrade abgeschlossenen Migrationen erstellt wurden, bleiben unverändert. Dieses LP-Fee-Recht ist separat von CPMM-Creator-Gebühren, die von `platform_cp_creator` kontrolliert werden.

Der Burn-Anteil wird direkt verbrannt, daher kann kein Konto ihn abheben oder die LP-Gebühren beanspruchen, die dieser Anteil darstellt.

Bestehende Starts mit gespeichertem `migrate_type = 0` können immer noch den Legacy-AMM-v4-Pfad verwenden. Neue Initialisierung lehnt diesen Migrationstyp ab.

## Startparameter-Regeln

`restrict_curve_param` ist der Schalter. Bei `0` liest das Programm Regeln überhaupt nicht. Bei `1` muss jeder Start, der über diese Plattform geleitet wird, das [`PlatformCurveRule`](/de/products/launchlab/curve-rules)-Konto der ausgewählten `GlobalConfig` erfüllen, und der Start-Builder muss dieses Konto zu `remaining_accounts` hinzufügen.

```rust
pub restrict_curve_param: u8,   // 0 = unrestricted, 1 = enforce the rule of the used config
pub curve_rule_manager:   Pubkey, // may manage rule accounts; the platform admin always may too
```

Eine Regel ist ein Menü zulässiger Startformen: Einschränkungen innerhalb einer Prüfgruppe werden UND-verknüpft, Gruppen werden ODER-verknüpft, und jede Einschränkung ist ein `(field, op, value)`-Tripel, das `Eq`, `Gte`, `Lte` und `Neq` unterstützt. Das deckt Wertbänder, alternative Stufen, Graduierungs-Bewertungsgrenzen, Migrations-Untergrenze, Token-Typ-Gating und zeitlich begrenzte Gruppen ab — das vollständige Modell, die Feldtabelle und neun durchgearbeitete Playbooks sind in [`products/launchlab/curve-rules`](/de/products/launchlab/curve-rules).

Zwei Dinge gehören hier eher als auf diese Seite:

- **`curve_rule_manager` ist eine Delegation, keine Übertragung.** Stellen Sie es durch `UpdatePlatformConfig::CurveRuleManager` ein und dieses Wallet kann die Rule-Konten dieser Plattform erstellen, aktualisieren, entfernen und schließen, ohne den Admin-Schlüssel zu benötigen. Der Plattform-Admin behält die gleiche Macht parallel, daher stellt das Rotieren oder Löschen des Feldes die Kontrolle wieder her. `Pubkey::default()` bedeutet, dass nur der Admin Regeln verwalten kann. Es kann `restrict_curve_param` nicht umschalten, das ein Admin-Only-Aufruf bleibt.
- **Regeln werden auf top von `GlobalConfig` erzwungen, nie stattdessen.** Die Regelprüfung läuft vor den eigenen Grenzen der Config und kann sie nur einengen.

Dies ersetzt die frühere `curve_params: Vec<PlatformCurveParam>`-Whitelist, die nur auf exakte Gleichheit testen konnte, höchstens 10 Einträge über alle Configs hinweg hielt und das `PlatformConfig`-Konto selbst vergrößerte. Plattformen, die es nutzten, wurden vom Protokoll in einem einmaligen Pass migriert; das Legacy-Feld, seine zwei Anweisungen und `MAX_CURVE_PARAMS` sind weg.

## `PlatformAllowConfig` — eine Plattform einschränken

Jede Plattform entscheidet, ob sie einschränken möchte, welche `GlobalConfig`-Konten ihre Starts verwenden dürfen. Stellen Sie `restrict_global_config` mit `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)` ein.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

PDA-Seeds: `[b"platform_allow_config", platform_config, global_config]`.

Der Plattform-Admin erstellt oder schließt ein Konto pro zulässigem Paar über `CreatePlatformAllowConfig` und `ClosePlatformAllowConfig`. Wenn die Einschränkung `1` ist, durchsucht die Initialisierung `remaining_accounts` nach der erwarteten PDA und lehnt ein fehlendes Konto mit `NotEnoughRemainingAccounts` ab. Wenn die Einschränkung `0` ist, ist kein Allow-Konto erforderlich.

Das frühere vom Protokoll-Admin verwaltete `PlatformGlobalAccess`-Konto und seine Create/Close-Anweisungen sind veraltet. Bestehende `PlatformConfig`- und `GlobalConfig`-Größen ändern sich nicht, aber Decoder müssen das alte globale Flag durch das neue Plattform-Flag ersetzen. Alte Access-PDAs werden nicht durch die neue Prüfung verbraucht.

## Aktualisierungspfad

| Anweisung | Wer signiert | Was ändert sich |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | Plattform-Admin (einmalig) | Initialisiert das Konto mit `PlatformParams`. |
| `UpdatePlatformConfig` | Plattform-Admin | Generischer Dispatch, der durch einen `param: u8` gekennzeichnet ist; mutiert ein Feld pro Aufruf, oder jedes Feld auf einmal über `AllInfo`. Branding-Felder, Gebührensätze, Vesting-Wallet und die verschiedenen Wallets sind alle über dies einstellbar. Beide Gebührensätze werden bei jeder Variante, die sie berührt, gegen die Grenzen in [Gebührengrenzen](#gebührengrenzen) neu validiert. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Plattform-Admin | Fügen Sie eine zulässige `GlobalConfig` für diese Plattform hinzu oder entfernen Sie sie. |
| `CreatePlatformCurveRule` / `ClosePlatformCurveRule` | `curve_rule_manager` oder Plattform-Admin | Erstellen oder schließen Sie das Rule-Konto einer `GlobalConfig`. |
| `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` | `curve_rule_manager` oder Plattform-Admin | Fügen Sie eine Prüfgruppe hinzu, ersetzen Sie sie oder entfernen Sie sie. Das Konto wird in der Größe angepasst, daher folgt die Miete dem Inhalt. |
| `ClaimPlatformFee` | `platform_fee_wallet` | Leeren Sie die Pro-Pool-Plattformgebühr aus `PoolState.quote_vault`. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | Leeren Sie den Pro-Plattform-Gebühren-Tresor (PDA bei `[platform_config, quote_mint]`). |

Wallet-Rotationen (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) gehen alle durch `UpdatePlatformConfig`. Lesen Sie die `update_platform_config`-Dispatch-Tabelle des Quellcodes für die genauen `param`-Codes.

## Häufige Fallstricke

- **`restrict_curve_param` aktiviert, bevor der Builder aktualisiert wurde.** Während es `1` ist, muss die Rule-PDA bei jedem Start in `remaining_accounts` sein, auch für eine Config ohne Rule-Konto — ein fehlendes Konto ist `NotEnoughRemainingAccounts`, nicht ein Pass. Versenden Sie die Builder-Änderung zuerst, dann schalten Sie das Flag um.
- **`restrict_curve_param` aktiviert mit einer leeren Regel.** Eine Regel, die null Gruppen hält, oder eine Gruppe, die null Einschränkungen hält, erlaubt alles. Das Flag zu aktivieren ist nicht von selbst eine Einschränkung; schreiben Sie die Gruppen zuerst, überprüfen Sie sie mit [der SDK-Prüfung](/de/products/launchlab/curve-rules#check-before-you-send) und üben Sie die ganze Sequenz auf devnet.
- **NFT-Split-Rundung.** Die drei Skalen müssen sich genau zu `1_000_000` addieren. Off-by-One-Fehler bei `CreatePlatformConfig` werden zurückgewiesen; Off-by-One zur Laufzeit würde eine oder mehrere zusätzliche LP-Einheiten prägen oder verbrennen, was die strikte Gleichheitsprüfung verhindern soll.
- **Plattform-Vesting-Doppelzuweisung.** Wenn `platform_vesting_scale > 0`, muss die Plattform `CreatePlatformVestingAccount` einmal aufrufen, nachdem die Fundraising des Starts endet; wenn sie es vergisst, bleibt dieser Anteil unzugewiesen und inaktiv für immer (das `total_locked_amount`-Budget des Starts wird verbraucht, aber die Plattform beansprucht es nie).
- **`platform_cp_creator`-Mehrdeutigkeit.** Wenn auf `Pubkey::default()` gesetzt, wird der Start-Creator als `pool_creator` des Post-Graduierungs-CPMM-Pools aufgezeichnet; wenn auf einen echten Schlüssel gesetzt, wird dieser Schlüssel stattdessen aufgezeichnet. Dies bestimmt den Begünstigten von Post-Graduierungs-CPMM-Creator-Gebühren und wer den ursprünglichen `CPMM::CollectCreatorFee`-Pfad signieren kann. Der Pfad zur Permissionless-Erfassung zahlt immer noch die kanonischen ATAs dieses aufgezeichneten Schlüssels. Entscheiden Sie bei der Erstellung der Plattform-Config, welches Modell Sie möchten.
- **`transfer_fee_extension_auth` spät gesetzt oder rotiert.** Das Feld wird zweimal pro Token-2022-Start gelesen — einmal bei der Mint-Erstellung für `withdraw_withheld_authority`, einmal bei der Graduierung für `transfer_fee_config_authority` — daher lässt ein Wert, der sich zwischen diesen beiden Momenten ändert, die beiden Autoritäten auf verschiedenen Schlüsseln. Siehe [Token-2022-Transfergebühren-Autoritäten](#token-2022-transfergebühren-autoritäten).
- **Einschränkung ohne Allow-Konto.** Das Aktivieren von `restrict_global_config`, bevor die erforderliche `PlatformAllowConfig` erstellt wird, blockiert neue Starts, die diese Config auswählen.
