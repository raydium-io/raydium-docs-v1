<Info>
  `PlatformConfig` ist die **plattformspezifische** Ebene, die auf [`GlobalConfig`](/de/products/launchlab/global-config) aufsetzt. Während `GlobalConfig` die protokollweiten Regeln definiert („Handelsgebühr ist 1 %, Angebot muss mindestens 10 Mio. sein, nur dieses Wallet kann graduieren"), nutzt `PlatformConfig` jede Launch-Plattform — pump.fun, Raydiums eigene UI, Drittanbieter-Launchpads — um ihre Gebühr hinzuzufügen, ihren Anteil am LP nach der Graduierung zu beanspruchen, einzuschränken, welche Kurvenformen ihre Launches wählen können, und ihr Branding (Name, Website, Bild) on-chain anzuzeigen.
</Info>

## Was es ist

Ein `PlatformConfig`-Account verwaltet fünf übergreifende Belange einer Plattform:

1. **Branding** — Name, Website, Bildlink, alle inline gespeichert, damit jeder Explorer oder Aggregator die Plattform anzeigen kann, die einen Token gestartet hat.
2. **Plattformgebühr** — eine zusätzliche Handelsgebühr (`fee_rate`) auf top der `trade_fee_rate` des Protokolls. Sammelt sich im `platform_fee_wallet` der Plattform an. Begrenzt auf 500 bps (`50000`) sowohl beim Create als auch beim Update-Pfad, erhöht von 100 bps (`10000`) am 2026-08-26 — siehe [Gebührengrenzen](#gebührengrenzen).
3. **LP-Migrationszuteilung** — drei gespeicherte Ganzzahlen (`platform_scale`, `creator_scale`, `burn_scale`), die sich zu `1_000_000` addieren. Vor dem Upgrade vom 2026-08-17 erzeugte die Creator-Skala einen separaten Creator Fee Key. Migrationen, die nach dem Upgrade ausgeführt werden, kombinieren die ersten beiden zu einer plattformeigenen gesperrten LP-Zuteilung; der Rest wird verbrannt.
4. **Kurvenparameter-Whitelist** — ein `Vec<PlatformCurveParam>`, das genau auflistet, welche `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)`-Kombinationen auf dieser Plattform zulässig sind. Wenn der Vektor leer ist oder alle Einträge ungültig sind, ist **jede** Kombination zulässig; andernfalls müssen Launches genau einem Eintrag entsprechen.
5. **Global-Config-Allowlist** — eine optionale Einschränkung, die einen von der Plattform erstellten `PlatformAllowConfig` für die ausgewählte `GlobalConfig` erfordert.

```ts
    Buffer.from("platform_config"),

```

## Layout

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (denominator 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (denominator 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // signs ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // receives the platform NFT slice at CPMM graduation
    pub platform_scale:              u64,               // share of LP minted to platform NFT
    pub creator_scale:               u64,               // creator share before upgrade; added to platform share afterward
    pub burn_scale:                  u64,               // share of LP burned permanently
    pub fee_rate:                    u64,               // platform's trade fee (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 padded with zeros
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig that the post-grad pool will bind to
    pub creator_fee_rate:            u64,               // creator-side fee taken pre-graduation
    pub transfer_fee_extension_auth: Pubkey,            // for Token-2022 launches: who inherits transfer-fee authorities post-graduation
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // platform's slice of total_locked_amount
    pub platform_cp_creator:         Pubkey,            // optional creator-of-record on the post-graduation CPMM pool
    pub restrict_global_config:      u8,                // 0 = unrestricted, 1 = require allow PDA
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // whitelist of permitted curve shapes
}
```

`platform_scale + creator_scale + burn_scale` muss genau `1_000_000` ergeben. Vor dem Upgrade vom 2026-08-17 war `creator_scale` separat gesperrt und sein Fee Key ging an den Token-Creator. Bei Migrationen, die nach dem Upgrade ausgeführt werden, wird es zu `platform_scale` addiert und seine gesperrten LP-Rechte gehen stattdessen an die Plattform. Beispielergebnisse unter der aktualisierten Logik:

- `(0, 100_000, 900_000)` — 90 % LP verbrannt, 10 % gesperrt für die Plattform.
- `(50_000, 100_000, 850_000)` — 85 % verbrannt, 15 % gesperrt für die Plattform.
- `(0, 0, 1_000_000)` — vollständiger Burn, keine NFT-Prägungen. Strikte „keine Insider"-Launches.

## Branding-Felder

`name`, `web` und `img` sind Byte-Arrays inline, mit Nullen bis zu ihren Größenkonstanten aufgefüllt. Um sie als Strings zu lesen, schneiden Sie bis zur ersten `\0`:

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

Die Konstanten sind absichtlich großzügig (`name: 64`, `web: 256`, `img: 256`), damit Plattformen genug Metadaten für Explorer und Aggregatoren einbeziehen können, ohne Off-Chain-Speicher zu berühren. Alles, das diese Größen überschreitet, wird bei `CreatePlatformConfig` mit `InvalidInput` zurückgewiesen.

## Gebührenmechanik

Ein Swap auf einer Kurve, die an einen `PlatformConfig` gebunden ist, erhebt drei gestaffelte Gebühren:

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` sammelt sich beim `protocol_fee_owner` des Protokolls an (beansprucht via `CollectFee`).
- `platform_fee` sammelt sich in einem plattformspezifischen Vault an (beansprucht via `ClaimPlatformFee` oder `ClaimPlatformFeeFromVault`; siehe [`instructions`](/de/products/launchlab/instructions)).
- `creator_fee` sammelt sich in einem Creator-spezifischen Vault an, der durch den öffentlichen Schlüssel des Creators + Quote-Mint gekennzeichnet ist (beansprucht via `ClaimCreatorFee`).

### Gebührengrenzen

Beide Sätze sind in `1/1_000_000` denominiert, also ist `5000` 50 bps und `50000` 500 bps.

| Satz | Grenze | Erzwungen in |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` beim Create — wird mit `InvalidInput` zurückgewiesen. `update_platform_fee_rate` bei jedem Update-Variant, der es berührt (`FeeRate` und `AllInfo`) — wird mit `InvalidPlatformInfo` zurückgewiesen. |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` beim Create und `update_creator_fee_rate` beim Update — beide werden mit `InvalidPlatformInfo` zurückgewiesen. |

Die zwei Erzwingungspunkte für `fee_rate` sind separate `require!`-Aufrufe in verschiedenen Dateien, daher tragen sie unterschiedliche Fehlercodes, aber sie wenden die gleiche Obergrenze an. Eine Plattform, die mit einem zulässigen Satz erstellt wurde, kann später bearbeitet werden, auch durch den `AllInfo`-Bulk-Variant, der jedes Feld auf einmal umschreibt.

Beide `fee_rate`-Grenzen waren ursprünglich 100 bps (`10000`). Die Update-Grenze verschob sich am 2026-01-27 zu `25000` (250 bps); am 2026-08-26 verschoben sich beide zu `50000` (500 bps) — siehe [den Changelog-Eintrag](/de/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap).

`GlobalConfig.max_share_fee_rate` begrenzt **nicht** einen dieser Sätze. Es begrenzt das Pro-Transaktion-Argument `share_fee_rate`, das die vier Swap-Anweisungen annehmen — die Referral-Gebühr — und nichts anderes. Siehe [`global-config`](/de/products/launchlab/global-config#gebühren).

## NFT-Migrationszuteilung (nur CPMM)

Wenn ein Launch zu CPMM graduiert, teilt die Migrationsanweisung die LP-Token, die von `CPMM::InitializeWithPermission` geprägt werden, auf zwei Arten auf:

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

Wenn `lp_to_platform` ungleich Null ist, wickelt das LP-Lock-Programm es in einen Fee Key NFT ein, der von `platform_nft_wallet` besessen wird. Dies ersetzt das Verhalten vor dem Upgrade, das separate Platform- und Creator-Fee-Keys erstellte. Fee Keys, die von Migrationen erstellt wurden, die vor dem Upgrade abgeschlossen wurden, bleiben unverändert. Dieses LP-Gebührenrecht ist separat von CPMM-Creator-Gebühren, die von `platform_cp_creator` kontrolliert werden.

Der Burn-Anteil wird direkt verbrannt, daher kann kein Account ihn abheben oder die LP-Gebühren beanspruchen, die dieser Anteil darstellt.

Bestehende Launches mit gespeichertem `migrate_type = 0` können immer noch den Legacy-AMM-v4-Pfad verwenden. Neue Initialisierung lehnt diesen Migrationstyp ab.

## Kurvenparameter-Whitelist

`curve_params: Vec<PlatformCurveParam>` ist der Mechanismus der Plattform, um einzuschränken, welche Kurvenformen ihre Launches wählen können. Wenn der Vektor nicht leer ist und mindestens ein Eintrag gültig ist, erzwingt das Programm bei `Initialize`, dass die Parameter des Launches genau einem Eintrag entsprechen.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // ordinal within this platform's whitelist
    pub global_config:        Pubkey,       // which GlobalConfig this entry applies to
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // new launches require 1 = CPMM; u8::MAX = wildcard
    pub migrate_cpmm_fee_on:        u8,    // 0 = quote-only, 1 = both. u8::MAX = wildcard
    pub supply:                     u64,   // 0 = wildcard
    pub total_base_sell:            u64,   // 0 = wildcard
    pub total_quote_fund_raising:   u64,   // 0 = wildcard
    pub total_locked_amount:        u64,   // u64::MAX = wildcard
    pub cliff_period:               u64,   // u64::MAX = wildcard
    pub unlock_period:              u64,   // u64::MAX = wildcard
}
```

Jedes Feld hat einen Sentinel-Wert, der **Wildcard** bedeutet (jeder Wert passt): `u64::MAX` für die `u64`-Felder, `u8::MAX` für die `u8`-Felder, `0` für die Supply-/Sell-/Fundraising-Felder. Ein `BondingCurveParam` mit allen Sentinels ist „alles erlauben" — gleichbedeutend mit dem Verhalten einer leeren Whitelist.

Der Matching-Algorithmus bei `Initialize`:

1. Filtern Sie `curve_params` zu Einträgen, deren `global_config` der gewählten `GlobalConfig` des Launches entspricht.
2. Wenn die gefilterte Liste leer ist, erlauben Sie beliebige Parameter (die Plattform hat nichts für diese `GlobalConfig` auf die Whitelist gesetzt).
3. Wenn jeder Eintrag in der gefilterten Liste `all_is_invalid()` hat (jedes Feld ist der Wildcard), erlauben Sie beliebige Parameter.
4. Andernfalls iterieren Sie Einträge; für jeden Eintrag überprüfen Sie die Parameter des Launches gegen jedes Nicht-Wildcard-Feld. Wenn alle Nicht-Wildcard-Felder übereinstimmen, akzeptieren und zurückgeben.
5. Wenn kein Eintrag übereinstimmte, wird mit `InvalidInput` zurückgewiesen.

Dies ermöglicht es einer Plattform zu sagen „wir erlauben nur die Standard-1B-Supply-/800M-verkauft-/30k-USDC-Fundraising-/kein-Vesting-Form", indem sie einen einzelnen Eintrag mit konkreten Werten für diese vier Felder und Wildcards überall sonst schreibt. Oder eine strengere Plattform könnte drei oder vier diskrete Formen aufzählen, eine pro unterstützter Launch-Stufe.

`MAX_CURVE_PARAMS = 10` begrenzt die Whitelist-Größe.

## `PlatformAllowConfig` — Einschränkung einer Plattform

Jede Plattform entscheidet, ob sie einschränken möchte, welche `GlobalConfig`-Accounts ihre Launches verwenden dürfen. Setzen Sie `restrict_global_config` mit `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)`.

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

PDA-Seeds: `[b"platform_allow_config", platform_config, global_config]`.

Der Plattform-Admin erstellt oder schließt einen Account pro zulässigem Paar via `CreatePlatformAllowConfig` und `ClosePlatformAllowConfig`. Wenn die Einschränkung `1` ist, sucht die Initialisierung in `remaining_accounts` nach der erwarteten PDA und lehnt einen fehlenden Account mit `NotEnoughRemainingAccounts` ab. Wenn die Einschränkung `0` ist, ist kein Allow-Account erforderlich.

Der frühere von Protokoll-Admin verwaltete `PlatformGlobalAccess`-Account und seine Create/Close-Anweisungen sind veraltet. Bestehende `PlatformConfig`- und `GlobalConfig`-Größen ändern sich nicht, aber Decoder müssen das alte globale Flag durch das neue Plattform-Flag ersetzen. Alte Access-PDAs werden nicht durch die neue Überprüfung verbraucht.

## Update-Pfad

| Anweisung | Wer signiert | Was ändert sich |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | Plattform-Admin (einmalig) | Initialisiert den Account mit `PlatformParams`. |
| `UpdatePlatformConfig` | Plattform-Admin | Generischer Dispatch, der durch einen `param: u8` gekennzeichnet ist; mutiert ein Feld pro Aufruf, oder jedes Feld auf einmal via `AllInfo`. Branding-Felder, Gebührensätze, Vesting-Wallet und die verschiedenen Wallets sind alle durch dies einstellbar. Beide Gebührensätze werden bei jedem Variant, der sie berührt, gegen die Grenzen in [Gebührengrenzen](#gebührengrenzen) neu validiert. |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Plattform-Admin | Fügen Sie einen zulässigen `GlobalConfig` für diese Plattform hinzu oder entfernen Sie ihn. |
| `UpdatePlatformCurveParam` | Plattform-Admin | Fügen Sie einen `PlatformCurveParam`-Eintrag nach `(global_config, index)` hinzu oder ersetzen Sie ihn. |
| `RemovePlatformCurveParam` | Plattform-Admin | Löschen Sie einen Eintrag (setzen Sie ihn auf all-sentinel = wildcard). |
| `ClaimPlatformFee` | `platform_fee_wallet` | Leeren Sie die plattformspezifische Gebühr pro Pool aus `PoolState.quote_vault`. |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | Leeren Sie den plattformspezifischen Gebühren-Vault (PDA bei `[platform_config, quote_mint]`). |

Wallet-Rotationen (`platform_fee_wallet`, `platform_nft_wallet`, `platform_vesting_wallet`, `platform_cp_creator`, `transfer_fee_extension_auth`, `cpswap_config`) gehen alle durch `UpdatePlatformConfig`. Lesen Sie die Dispatch-Tabelle `update_platform_config` des Quellcodes für die genauen `param`-Codes.

## Häufige Fallstricke

- **Whitelist-Sentinels falsch gesetzt.** Ein `BondingCurveParam` mit `total_locked_amount = 0` ist **nicht** ein Wildcard — es passt zu Launches, die sich explizit gegen Vesting entscheiden. Der Wildcard für dieses Feld ist `u64::MAX`. Die gleiche Falle existiert für `cliff_period` und `unlock_period`. Verwenden Sie `clear()` (das das Programm bereitstellt), um Sentinels korrekt zu setzen.
- **NFT-Split-Rundung.** Die drei Skalen müssen sich zu genau `1_000_000` addieren. Off-by-One-Fehler bei `CreatePlatformConfig` werden zurückgewiesen; Off-by-One zur Laufzeit würde eine zusätzliche LP-Einheit prägen oder verbrennen, weshalb die strikte Gleichheitsprüfung vorhanden ist.
- **Plattform-Vesting-Doppelzuweisung.** Wenn `platform_vesting_scale > 0`, muss die Plattform `CreatePlatformVestingAccount` einmal aufrufen, nachdem die Fundraising des Launches endet; wenn sie es vergisst, bleibt dieser Anteil unzugewiesen und inaktiv für immer (das `total_locked_amount`-Budget des Launches wird verbraucht, aber die Plattform beansprucht es nie).
- **`platform_cp_creator`-Mehrdeutigkeit.** Wenn auf `Pubkey::default()` gesetzt, wird der Launch-Creator als `pool_creator` des Post-Graduierungs-CPMM-Pools aufgezeichnet; wenn auf einen echten Schlüssel gesetzt, wird dieser Schlüssel stattdessen aufgezeichnet. Dies bestimmt den Begünstigten von Post-Graduierungs-CPMM-Creator-Gebühren und wer den ursprünglichen `CPMM::CollectCreatorFee`-Pfad signieren kann. Der erlaubnislose Erfassungspfad zahlt immer noch die kanonischen ATAs dieses aufgezeichneten Schlüssels. Entscheiden Sie bei der Erstellung der Plattform-Config, welches Modell Sie möchten.
- **Einschränkung ohne Allow-Account.** Das Aktivieren von `restrict_global_config`, bevor Sie den erforderlichen `PlatformAllowConfig` erstellen, blockiert neue Launches, die diese Config auswählen.
