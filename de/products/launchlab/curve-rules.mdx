<Info>
  Eine **Kurvenregel** ist die Antwort einer Plattform auf die Frage „welche Starts bin ich bereit zu hosten?". [`GlobalConfig`](/de/products/launchlab/global-config) setzt die Protokoll-Untergrenze — mindestens 10M Supply, mindestens 20% der Supply auf der Kurve verkauft, und so weiter — und diese Untergrenzen sind absichtlich weit gefasst, damit jede Art von Plattform darunter passt. Eine Kurvenregel ist der Ort, an dem Sie diese auf die Form eingrenzen, die Ihr Produkt tatsächlich unterstützt.

  Regeln leben in ihrem eigenen `PlatformCurveRule`-Konto, eines pro (Plattform, [`GlobalConfig`](/de/products/launchlab/global-config))-Paar. Sie können nur das einengen, was die Config bereits erlaubt; eine Regel kann niemals eine Protokoll-Obergrenze aufheben.
</Info>

## Das mentale Modell

Drei Ebenen, von außen nach innen:

```
GlobalConfig       Protokoll-Untergrenze      "Supply >= 10M, Verkaufsquote >= 20%, ..."
  └─ PlatformCurveRule   Ihre Regel     "und auf meiner Plattform: eine dieser Formen"
       └─ Prüfgruppe    eine Form     "Supply = 1B UND Fundraising in [80, 90] SOL"
            └─ Constraint eine Prüfung    "(Supply, Eq, 1_000_000_000)"
```

Die zwei Verschachtelungsebenen machen dies ausdrucksstark:

- **Constraints innerhalb einer Gruppe werden UND-verknüpft.** Alle müssen erfüllt sein.
- **Gruppen innerhalb einer Regel werden ODER-verknüpft.** Ein Start ist erlaubt, sobald er eine einzelne Gruppe erfüllt.

Eine Gruppe ist also eine zulässige *Form*, und die Regel ist das Menü der Formen, die Sie anbieten. Eine Regel kann bis zu 10 Gruppen enthalten, und eine Gruppe bis zu 25 Constraints.

Zwei Grenzfälle sind es wert, sich zu merken:

| Zustand | Bedeutung |
|---|---|
| Kein Regelkonto oder eine Regel mit null Gruppen | Die Plattform schränkt die Startparameter für diese Config nicht ein. |
| Eine Gruppe mit null Constraints | Diese Gruppe passt zu jedem Start, daher erlaubt die gesamte Regel alles. |

Eine Regel tritt nur in Kraft, während `PlatformConfig.restrict_curve_param` auf `1` gesetzt ist. Bei `0` liest das Programm Regeln überhaupt nicht, was auch der Schalter ist, den Sie zum Ausrollen und Zurückrollen einer Regel verwenden.

## Constraints

Ein Constraint ist ein `(Feld, Operator, Wert)`-Tripel. Nichts anderes — keine Ausdrücke, keine Verschachtelung.

```rust
pub struct ParamConstraint {
    pub field: u8,    // welcher Startparameter, siehe die Tabelle unten
    pub op:    u8,    // 0 Eq, 1 Gte (min), 2 Lte (max), 3 Neq
    pub value: u128,
}
```

Ein **Bereich sind zwei Constraints** auf demselben Feld innerhalb einer Gruppe: ein `Gte` für die Untergrenze und ein `Lte` für die Obergrenze. Das gleiche `(Feld, Operator)`-Paar darf nicht zweimal in einer Gruppe vorkommen, was verhindert, dass Sie zwei widersprüchliche Mindestwerte schreiben.

### Felder

<Info>
  Feld-IDs sind dauerhaft. Neue Felder werden nur angehängt, daher ändert sich eine ID nie in ihrer Bedeutung, sobald ein Regelkonto sie enthält.
</Info>

| ID | Feld | Einheit | Hinweise |
|---|---|---|---|
| 0 | `CurveType` | Enum | 0 konstantes Produkt, 1 fester Preis, 2 linearer Preis |
| 1 | `MigrateType` | Enum | Neue Starts müssen ohnehin `1` (CPMM) sein |
| 2 | `MigrateCpmmFeeOn` | Enum | 0 nur Quote, 1 beide Token |
| 3 | `Supply` | Basiseinheiten | Die vollständige Token-Supply |
| 4 | `TotalSellA` | Basiseinheiten | Auf der Kurve verkauft. Nur Constant-Product-Configs — siehe [Kurventyp-Einschränkungen](#kurventyp-einschränkungen) |
| 5 | `TotalFundRaisingB` | Quote-Einheiten | Das Abschluss-Ziel |
| 6 | `TotalLockedAmount` | Basiseinheiten | Vesting-Budget |
| 7 | `CliffPeriod` | Sekunden | Wartezeit vor Entsperrung beginnt |
| 8 | `UnlockPeriod` | Sekunden | Entsperrdauer |
| 9 | `BaseTokenProgram` | Enum | 0 SPL Token, 1 Token-2022 |
| 10 | `TransferFeeEnabled` | Bool | 1 wenn die Basis-Mint `TransferFeeConfig` trägt |
| 11 | `TransferFeeBasisPoints` | 1/10 000 | 0 ohne die Erweiterung |
| 12 | `TransferFeeMaximumFee` | Basiseinheiten | 0 ohne die Erweiterung |
| 13 | `SellRateA` | 1/1 000 000 | Abgeleitet: `TotalSellA / Supply`. Nur Constant-Product |
| 14 | `LockRate` | 1/1 000 000 | Abgeleitet: `TotalLockedAmount / Supply` |
| 15 | `MigrateAmountA` | Basiseinheiten | Abgeleitet: `Supply − TotalSellA − TotalLockedAmount`. Nur Constant-Product |
| 16 | `MigrateRateA` | 1/1 000 000 | Abgeleitet: `MigrateAmountA / Supply`. Nur Constant-Product |
| 17 | `FundRaisingRateB` | 1/1 000 000 | Abgeleitet: `TotalFundRaisingB / Supply` |
| 18 | `UnixTimestamp` | Sekunden | Blockzeit des Starts |

Die abgeleiteten Felder sind diejenigen, die Regeln portierbar machen. Das Festlegen von `Supply` und `TotalFundRaisingB` auf exakte Zahlen fixiert eine Startform; das Einschränken von `FundRaisingRateB` fixiert die *Beziehung* zwischen ihnen und lässt einen Ersteller jede Supply wählen, die sie beibehält.

<Warning>
  Ratenfelder sind nur innerhalb einer `GlobalConfig` vergleichbar, da ihre Nenner von der Quote-Mint dieser Config und ihren Dezimalstellen abhängen. Das ist in der Praxis keine Einschränkung: eine Regel ist konstruktionsbedingt auf eine Config begrenzt.
</Warning>

## Die neun Playbooks

Jedes Playbook unten ist eine Regel. Constraints werden als `(Feld, Operator, Wert)` geschrieben.

### 1. Eine Standard-Stufe

Die einfachste Regel und das exakte Verhalten, das die eingestellte Kurvenparameter-Whitelist bot: eine Form, festgelegt.

| Gruppe | Constraints |
|---|---|
| 0 | `(Supply, Eq, 1_000_000_000e6)`, `(TotalSellA, Eq, 800_000_000e6)`, `(TotalFundRaisingB, Eq, 85e9)` |

Jeder Start, der in einem der drei abweicht, wird mit `CurveParamNotMatchPlatformRule` abgelehnt.

### 2. Ein Band statt einer Zahl

Der Grund, warum Bänder existieren: Ein Ersteller wählt ein Fundraising-Ziel, mit dem Sie sich wohlfühlen, ohne dass Sie jeden Wert aufzählen müssen.

| Gruppe | Constraints |
|---|---|
| 0 | `(Supply, Eq, 1_000_000_000e6)`, `(TotalFundRaisingB, Gte, 50e9)`, `(TotalFundRaisingB, Lte, 200e9)` |

Eine Gruppe, vier Constraints, und der Ersteller hat einen 50–200 SOL-Korridor. Unter der alten Whitelist brauchte dies einen Eintrag pro zulässigem Wert, und die Obergrenze von zehn Einträgen machte es unmöglich.

### 3. Stufen nebeneinander

Gruppen werden ODER-verknüpft, daher ist jede Stufe eine Gruppe.

| Gruppe | Constraints | Stufe |
|---|---|---|
| 0 | `(Supply, Eq, 1_000_000_000e6)`, `(TotalFundRaisingB, Eq, 85e9)` | Standard |
| 1 | `(Supply, Eq, 100_000_000e6)`, `(TotalFundRaisingB, Eq, 30e9)` | Klein |
| 2 | `(Supply, Eq, 10_000_000_000e6)`, `(TotalFundRaisingB, Gte, 500e9)` | Wal |

Die Reihenfolge ist wichtig für die Berechnung, nicht für die Semantik: Die Auswertung stoppt bei der ersten Gruppe, die passt, daher sollten Sie Ihre am häufigsten verwendete Stufe zuerst platzieren.

### 4. Ein Abschluss-Valuierungsband

`FundRaisingRateB` ist `TotalFundRaisingB / Supply` in Millionsten. Das Einschränken davon begrenzt, wie wertvoll ein Token unabhängig von der Supply, die der Ersteller wählte, abschließen kann.

| Gruppe | Constraints |
|---|---|
| 0 | `(FundRaisingRateB, Gte, 60_000)`, `(FundRaisingRateB, Lte, 120_000)` |

Mit einer 1e12 Supply und einer 9-dezimalen Quote-Mint sitzt `85e9 / 1e12 × 1e6 = 85_000` innerhalb dieses Bandes. Ein Ersteller, der die Supply verdoppelt, muss das Ziel ungefähr verdoppeln, um darin zu bleiben — das ist der Sinn. Zwei Constraints ersetzen, was sonst eine Tabelle von `(Supply, Ziel)`-Paaren wäre.

### 5. Eine Migrationsuntergrenze

`MigrateRateA` ist der Anteil der Supply, der beim Abschluss tatsächlich in den CPMM-Pool gelangt: `Supply − TotalSellA − TotalLockedAmount`, über Supply. Es ist die Tiefe des abgeschlossenen Pools und es ist der einzige Protokoll-Knopf ohne plattformseitiges Äquivalent vor Regeln.

| Gruppe | Constraints |
|---|---|
| 0 | `(MigrateRateA, Gte, 150_000)` |

Mindestens 15% der Supply erreichen den Pool. Ein Ersteller kann nicht 95% auf der Kurve verkaufen und ein flaches Buch hinterlassen.

<Note>
  Wenn die Parameter nicht aufgehen — ein gesperrter Betrag größer als das, was nach dem Kurvenverkauf übrig bleibt — kann der abgeleitete Wert nicht berechnet werden und das Constraint schlägt geschlossen fehl, daher wird der Start abgelehnt, anstatt stillschweigend erlaubt zu werden.
</Note>

### 6. Vesting, das Sie tatsächlich durchsetzen

`GlobalConfig.max_lock_rate` begrenzt Vesting von oben. Eine Regel kann eine Untergrenze darunter setzen und einen echten Cliff erfordern.

| Gruppe | Constraints |
|---|---|
| 0 | `(LockRate, Gte, 50_000)`, `(LockRate, Lte, 200_000)`, `(CliffPeriod, Gte, 2_592_000)` |

Zwischen 5% und 20% der Supply gesperrt, mit mindestens einem 30-Tage-Cliff. Nützlich für eine Plattform, deren Pitch „keine Instant-Unlock-Starts" ist.

### 7. Token-Typ-Gating

`BaseTokenProgram` und `TransferFeeEnabled` sind unabhängig, was wichtig ist: Eine Token-2022-Mint ohne `TransferFeeConfig` meldet `TransferFeeEnabled = 0` genau wie eine SPL Token-Mint.

| Absicht | Gruppe | Constraints |
|---|---|---|
| Nur SPL Token | 0 | `(BaseTokenProgram, Eq, 0)` |
| Nur Token-2022 | 0 | `(BaseTokenProgram, Eq, 1)` |
| Token-2022, keine Transfergebühr | 0 | `(BaseTokenProgram, Eq, 1)`, `(TransferFeeEnabled, Eq, 0)` |
| Keine Transfergebühr, beide Programme | 0 | `(TransferFeeEnabled, Eq, 0)` |

### 8. Eine bedingte Transfergebühr-Obergrenze

Es gibt keinen „if"-Operator, und keiner ist nötig — zwei Gruppen drücken die Bedingung aus.

| Gruppe | Constraints | Liest sich als |
|---|---|---|
| 0 | `(TransferFeeEnabled, Eq, 0)` | Keine Transfergebühr: in Ordnung |
| 1 | `(TransferFeeEnabled, Eq, 1)`, `(TransferFeeBasisPoints, Lte, 100)`, `(TransferFeeMaximumFee, Gte, 1_000)` | Mit einer Gebühr: höchstens 1%, und eine maximale Gebühr, die tatsächlich gesetzt ist |

Eine Null-Rate `TransferFeeConfig` rutscht nicht durch Gruppe 0: die Erweiterung ist vorhanden, daher ist `TransferFeeEnabled` `1` und nur Gruppe 1 kann sie akzeptieren.

### 9. Eine zeitlich begrenzte Promo, im Voraus geplant

`UnixTimestamp` ist die Blockzeit des Starts, daher kann eine Gruppe ihr eigenes Gültigkeitsfenster tragen. Sie schreiben beide Gruppen heute und der Wechsel passiert von selbst.

| Gruppe | Constraints | Fenster |
|---|---|---|
| 0 | `(UnixTimestamp, Lte, 1_767_225_600)`, `(TotalFundRaisingB, Gte, 30e9)` | Promo-Zeitraum: 30 SOL Minimum |
| 1 | `(UnixTimestamp, Gte, 1_767_225_601)`, `(TotalFundRaisingB, Gte, 80e9)` | Danach: 80 SOL Minimum |

An der Grenze ist keine Transaktion erforderlich. Die Kosten sind zwei Gruppenplätze statt eines.

## Kurventyp-Einschränkungen

Vier Felder lesen `TotalSellA`: `TotalSellA`, `SellRateA`, `MigrateAmountA` und `MigrateRateA`. Bei einer Constant-Product-Config liefert der Ersteller diese Zahl. Bei einer Fixed-Price- oder Linear-Price-Config leitet die Kurve sie stattdessen ab, und der Wert, den das Programm vergleicht, ist `0`, was jeden Start ablehnen würde.

Anstatt Sie eine Regel schreiben zu lassen, die Ihre eigene Config stillschweigend blockiert, weigert sich das Programm, diese vier Felder zum Schreibzeitpunkt bei einer Non-Constant-Product-Config zu akzeptieren, mit `CurveRuleFieldNotSupportedByCurve`. Nur Constant-Product-Configs existieren heute, daher werden Sie diesen Fehler in der Praxis nicht antreffen.

### Vor einem Start: Werden diese Parameter bestehen?

`checkLaunchAgainstCurveRule` spiegelt die Startzeit-Prüfung des Programms genau wider, einschließlich ihres Fail-Closed-Verhaltens. Führen Sie es in Ihrem Startformular aus und Sie können die Schaltfläche „Senden" mit einem Grund deaktivieren, anstatt den Ersteller für eine rückgängig gemachte Transaktion bezahlen zu lassen.

```ts
import {
  checkLaunchAgainstCurveRule,
  getPdaPlatformCurveRule,
  LaunchpadCurveRuleBaseTokenProgram,
  LaunchpadCurveRuleField,
  PlatformCurveRule,
} from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";

const platformConfig = await raydium.launchpad.getPlatformConfig(platformConfigId);

// bei 0 liest das Programm Regeln überhaupt nicht, daher gibt es nichts zu prüfen
if (platformConfig.restrictCurveParam !== 0) {
  const ruleId = getPdaPlatformCurveRule(programId, platformConfigId, configId).publicKey;
  const ruleAccount = await connection.getAccountInfo(ruleId);

  const result = checkLaunchAgainstCurveRule({
    // undefined wenn das Konto nicht existiert — die Plattform schrieb keine Regel für diese Config
    rule: ruleAccount === null ? undefined : PlatformCurveRule.decode(ruleAccount.data),
    context: {
      curveType: globalConfig.curveType,
      migrateType: 1,
      migrateCpmmFeeOn: 0,
      supply: new BN("1000000000000000"),
      totalSellA: new BN("793100000000000"),
      totalFundRaisingB: new BN("85000000000"),
      totalLockedAmount: new BN(0),
      cliffPeriod: new BN(0),
      unlockPeriod: new BN(0),
      baseTokenProgram: LaunchpadCurveRuleBaseTokenProgram.SplToken,
      // lassen Sie transferFee weg, wenn die Basis-Mint keine Transfergebühr-Erweiterung trägt
      unixTimestamp: new BN(Math.floor(Date.now() / 1000)),
    },
  });

  if (!result.ok) {
    // jede Gruppe lehnte den Start ab; jeder Eintrag listet alle fehlgeschlagenen Constraints dieser Gruppe auf
    for (const group of result.groupFailures) {
      for (const c of group.unsatisfied) {
        console.log(
          `Gruppe ${group.groupId}: ${LaunchpadCurveRuleField[c.field]} ist ${c.actual ?? "nicht berechenbar"},`,
          `Regel möchte Operator ${c.op} ${c.value.toString()}`,
        );
      }
    }
  }
}
```

Drei Dinge, die der Helfer reproduziert, anstatt sie zu approximieren:

- **Ein fehlendes Regelkonto und eine Regel ohne Gruppe bestehen beide.** Ebenso eine Gruppe ohne Constraints. Übergeben Sie `rule: undefined` für ein nicht existierendes Konto; behandeln Sie es nicht als Ablehnung.
- **Nicht berechenbare Werte schlagen geschlossen fehl.** Eine Null-Supply hat keine Raten, und ein gesperrter Betrag größer als das, was der Kurvenverkauf hinterlässt, hat keinen Migrationsbetrag. `actual` kommt als `undefined` zurück und das Constraint zählt als unerfüllt, genau wie On-Chain.
- **Alle fehlgeschlagenen Constraints werden gemeldet, nicht nur das erste.** Das Programm nimmt eine Abkürzung, weil es nur ein Urteil braucht; der Helfer sammelt alles, damit Ihr Formular jedes Problem auf einmal auflisten kann.

Das Einzige, das es nicht wissen kann, ist die Blockzeit, auf der Ihre Transaktion tatsächlich landen wird. Wenn eine Regel `UnixTimestamp` in der Nähe einer Grenze verwendet, behandeln Sie einen Pass als vorläufig.

### Vor dem Schreiben einer Regel: Ist diese Gruppe gültig?

`checkCurveRuleGroupWritable` spiegelt die Schreibzeit-Validierung von `UpdatePlatformCurveRule` wider — Constraint-IDs, die doppelte `(Feld, Operator)`-Regel, beide Zählgrenzen und die Kurventyp-Einschränkung. Führen Sie es in Ihrem Plattform-Admin-Tool aus, bevor Sie signieren.

```ts
import {
  checkCurveRuleGroupWritable,
  LaunchpadCurveRuleField,
  LaunchpadCurveRuleOp,
} from "@raydium-io/raydium-sdk-v2";

const constraints = [
  { field: LaunchpadCurveRuleField.Supply, op: LaunchpadCurveRuleOp.Eq, value: new BN("1000000000000000") },
  { field: LaunchpadCurveRuleField.TotalFundRaisingB, op: LaunchpadCurveRuleOp.Gte, value: new BN("50000000000") },
  { field: LaunchpadCurveRuleField.TotalFundRaisingB, op: LaunchpadCurveRuleOp.Lte, value: new BN("200000000000") },
];

const writable = checkCurveRuleGroupWritable({
  groupId: 0,
  constraints,
  curveType: globalConfig.curveType,
  // die IDs, die die Regel bereits hält, daher wird das Ersetzen einer Gruppe nicht mit dem Hinzufügen verwechselt
  existingGroupIds: existingRule?.groups.map((g) => g.groupId) ?? [],
});

// jeder Fehler trägt den Programm-Fehlercode, mit dem die Transaktion fehlgeschlagen wäre
if (!writable.ok) console.log(writable.errors);
```

<Note>
  Das Bestehen dieser Prüfung bedeutet, dass die Transaktion nicht wegen Fehlformation abgelehnt wird. Es sagt nichts darüber aus, ob die Regel das ist, was Sie gemeint haben — eine Gruppe kann perfekt gültig sein und trotzdem jeden Start ablehnen, den Ihre UI produzieren kann. Das ist der Grund für die Startseite-Prüfung oben: Nach dem Schreiben einer Gruppe führen Sie jede Form, die Ihr Produkt anbietet, durch `checkLaunchAgainstCurveRule` aus und bestätigen, dass jede immer noch eine Gruppe findet.
</Note>

### Testen Sie zuerst auf devnet

Das Aktivieren von `restrict_curve_param` auf mainnet ändert, was Ihre Ersteller tun können, sofort, für jeden Start. Üben Sie die gesamte Sequenz auf devnet, bevor Sie mainnet berühren:

1. Erstellen Sie eine Plattform-Config und eine Regel auf devnet, und schreiben Sie die gleichen Gruppen, die Sie ausliefern möchten.
2. Führen Sie jede Startform, die Ihre UI produzieren kann, durch `checkLaunchAgainstCurveRule` aus, und bestätigen Sie, dass die Urteile die sind, die Sie erwarten — sowohl die Formen, die bestehen sollten, als auch die Formen, die abgelehnt werden sollten.
3. Aktivieren Sie `restrict_curve_param`, dann starten Sie tatsächlich einen Token, der bestehen sollte, und einen, der abgelehnt werden sollte. Der zweite sollte mit `CurveParamNotMatchPlatformRule` (`6025`) fehlschlagen, nicht mit `NotEnoughRemainingAccounts` (`6018`) — letzteres bedeutet, dass Ihr Builder die Regel-PDA nicht anhängt und die Prüfung nicht wirklich ausgeübt wird.
4. Nur dann auf mainnet wiederholen, in der gleichen Reihenfolge.

Punkt 3 ist der, auf dem es sich lohnt zu bestehen. Der Off-Chain-Helfer und das On-Chain-Programm sind zwei Implementierungen der gleichen Regeln, und ein devnet-Start ist das, was beweist, dass sie für Ihre Regel übereinstimmen — einschließlich dass Ihr Start-Builder das Konto überhaupt anhängt.

## Eine Regel betreiben

### Der delegierte Manager

Das Bearbeiten von Regeln ist Routinearbeit; ein Plattform-Admin-Schlüssel ist normalerweise ein Multisig. `PlatformConfig.curve_rule_manager` existiert genau dafür: setzen Sie ihn einmal durch `UpdatePlatformConfig::CurveRuleManager`, und dieser Hot Wallet kann dann Regelkonten auf eigene Faust erstellen, aktualisieren, entfernen und schließen. Der Plattform-Admin behält die gleiche Macht parallel, daher ist ein verlorener Manager-Schlüssel wiederherstellbar — rotieren Sie ihn mit einem anderen Admin-Aufruf.

Umfang eines kompromittierten Manager-Schlüssels: Er kann Ihre Parameterregeln lockern oder löschen und die Miete eines Regelkontos zurückfordern. Er kann Gebühren-Wallets, Vesting, die CPMM-Config nicht berühren, kann `restrict_curve_param` nicht umschalten und kann eine `GlobalConfig`-Grenze nicht brechen. Behandeln Sie ihn als Konfigurationsschlüssel, nicht als Treasury-Schlüssel.

### Miete folgt dem Inhalt

Ein Regelkonto wird erstellt, das keine Gruppe hält, und wird bei jeder Änderung vergrößert, daher zahlen Sie für die Regeln, die Sie tatsächlich geschrieben haben. Das Entfernen einer Gruppe erstattet die Differenz an den Unterzeichner.

| Regelinhalt | Kontogröße | Miete |
|---|---|---|
| Leer (gerade erstellt) | 150 Bytes | ~0,0019 SOL |
| 1 Gruppe, 2 Constraints | 200 Bytes | ~0,0023 SOL |
| 3 Gruppen, 4 Constraints je | 408 Bytes | ~0,0037 SOL |
| 10 Gruppen, 25 Constraints je | 4 790 Bytes | ~0,034 SOL |

### Ausrollungsreihenfolge

1. Üben Sie die gesamte Sequenz auf devnet — siehe [Testen Sie zuerst auf devnet](#testen-sie-zuerst-auf-devnet).
2. Erstellen Sie das Regelkonto und schreiben Sie seine Gruppen. Noch nichts ändert sich — mit `restrict_curve_param` immer noch `0` liest das Programm sie nicht.
3. Prüfen Sie die Regel Off-Chain mit [`checkLaunchAgainstCurveRule`](#vor-einem-start-werden-diese-parameter-bestehen): für jede Startform, die Ihre UI produzieren kann, bestätigen Sie, dass eine Gruppe sie akzeptiert.
4. Setzen Sie `restrict_curve_param` auf `1`. Von diesem Moment an werden die Starts Ihrer Ersteller geprüft.
5. Zum Zurückrollen setzen Sie es auf `0` zurück. Das Regelkonto bleibt intakt.

<Warning>
  Ihr Start-Builder muss die Regel-PDA zu `remaining_accounts` anhängen, während `restrict_curve_param` `1` ist. Das Programm erfordert, dass das Konto vorhanden ist, auch wenn es noch nicht existiert, damit ein Ersteller die Prüfung nicht durch Auslassung überspringen kann — ein fehlendes Konto ist `NotEnoughRemainingAccounts`, kein Pass. Die Ableitung ist `[b"platform_curve_rule", platform_config, global_config]`.
</Warning>

## Kosten zum Startzeitpunkt

Die Prüfung läuft bei jedem Start, während sie aktiviert ist, daher ist ihre Rechenkosten eine Pro-Start-Steuer. Gemessen von Ende zu Ende — PDA-Ableitung, der `remaining_accounts`-Scan, Deserialisierung und Auswertung:

| Regelinhalt | Billige Felder | Abgeleitete Felder |
|---|---|---|
| Aktiviert, kein Regelkonto | 1 936 | — |
| 1 Gruppe, 2 Constraints | 2 576 | 2 926 |
| 3 Gruppen, 4 Constraints je | 3 624 | 5 724 |
| 10 Gruppen, 25 Constraints je | 24 344 | 68 094 |

„Billig" ist ein direktes Feldlesen wie `Supply`; „abgeleitet" ist ein berechnetes wie `MigrateRateA`, das etwa 223 CU pro Constraint kostet, gegenüber etwa 48. Selbst eine vollständig beladene Regel abgeleiteter Constraints bleibt unter einem Drittel des Standard-Budgets von 200 000 CU pro Anweisung, und eine realistische Drei-Gruppen-Regel liegt unter 6 000. Gruppen werden ausgewertet, bis eine passt, daher ist das Platzieren Ihrer häufigen Stufe zuerst kostenlose Einsparungen.
