<Info>
  `GlobalConfig` ist das **Konfigurationskonto auf Protokollebene**. Es kann viele davon geben — indiziert nach `(curve_type, index)` — und jeder Start wählt genau eines zum Zeitpunkt von `Initialize` aus. Die Werte auf der gewählten `GlobalConfig` werden dann zu harten Grenzen für die Parameter dieses Starts. Für plattformspezifische Anpassungen (Pro-Plattform-Gebührensatz, zulässige Kurvenfunktionen, NFT-Aufteilungen beim Abschluss) siehe [`products/launchlab/platform-config`](/de/products/launchlab/platform-config).
</Info>

## Was es ist

Eine `GlobalConfig` ist eine Singleton-pro-`(curve_type, index)` PDA, die die Protokoll-Regeln festlegt, die jeder Start befolgen muss:

- Die Art der zulässigen Bindungskurve (`curve_type`).
- Der Handelgebührensatz, den die Kurve bei jedem Kauf und Verkauf erhebt.
- Die beim Abschluss erhobene Migrationsgebühr.
- Untergrenzen für Angebot, Sperrquote, Verkaufsquote und Migrationsquote.
- Die Quote-Mint (typischerweise Wrapped SOL oder USDC) — das Asset, mit dem Benutzer kaufen.
- Vier Protokoll-Wallets: der Protokollgebühren-Eigentümer, der Migrationsgebühren-Eigentümer und die zwei Migrations-Kontroll-Wallets, die für CPMM und Legacy-AMM-v4-Abschluss beibehalten werden.

`GlobalConfig`-Konten können sowohl vom LaunchLab-Programm-Admin **als auch** von der delegierten Create-Config-Autorität erstellt **und aktualisiert** werden; jeder andere Unterzeichner erhält `InvalidOwner` (`6001`). Siehe [`reference/program-addresses`](/de/reference/program-addresses) für die kanonischen Autoritäten.

## Layout

```rust
// states/config.rs
pub const GLOBAL_CONFIG_SEED: &str = "global_config";

#[account]
pub struct GlobalConfig {
    pub epoch:                   u64,         // recent_epoch tracker
    pub curve_type:              u8,          // 0 = ConstantProduct, 1 = FixedPrice, 2 = LinearPrice
    pub index:                   u16,         // discriminator within a curve_type
    pub migrate_fee:             u64,         // SOL paid on graduation
    pub trade_fee_rate:          u64,         // 1/1_000_000 of volume
    pub max_share_fee_rate:      u64,         // 100 bps cap on the per-trade referral share fee
    pub min_base_supply:         u64,         // floor on Initialize supply (no decimals)
    pub max_lock_rate:           u64,         // ceiling on vesting locked / supply
    pub min_base_sell_rate:      u64,         // floor on base_supply_graduation / supply
    pub min_base_migrate_rate:   u64,         // floor on tokens that seed the post-graduation pool
    pub min_quote_fund_raising:  u64,         // floor on quote_reserve_target (with decimals)
    pub quote_mint:              Pubkey,
    pub protocol_fee_owner:      Pubkey,      // claims protocol fees via CollectFee
    pub migrate_fee_owner:       Pubkey,      // claims migration fees via CollectMigrateFee
    pub migrate_to_amm_wallet:   Pubkey,      // can sign MigrateToAmm
    pub migrate_to_cpswap_wallet:Pubkey,      // can sign MigrateToCpswap
    pub padding_alignment:       [u8; 8],
    pub padding:                 [u64; 15],
}
```

PDA-Ableitung:

```ts
const [globalConfig] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    Buffer.from(quoteMint.toBytes()),
    Buffer.from([curveType]),
    u16ToBytes(index),
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Überprüfen Sie die genaue Seed-Reihenfolge vom On-Chain-Konto vor dem Signieren — die `create_config`-Anweisung des Programms ist die Quelle der Wahrheit.)

## Feldsemanantik

### `curve_type` und `index`

Zusammen identifizieren diese eine `GlobalConfig` eindeutig. Es gibt eine `GlobalConfig` pro `(curve_type, index)`-Paar:

- `curve_type = 0` — Konstant-Produkt-Virtual-Reserve-Kurve. Standard und am häufigsten verwendet.
- `curve_type = 1` — Festpreis-Kurve.
- `curve_type = 2` — Linear-Preis-Kurve.

`index` ist ein `u16`, das dem Admin ermöglicht, mehrere Konfigurationen pro Kurventyp zu veröffentlichen (z. B. eine mit einer strengeren Gebühr, eine mit einer höheren Mindestquote-Erhöhung). Bei `Initialize` liefert der Start ein `(curve_type, index)`-Paar und das Programm lädt die entsprechende `GlobalConfig`.

### Gebühren

- `trade_fee_rate` — ausgedrückt in `1/1_000_000` des Handelsvolumens. Wird auf jeden Kauf und Verkauf auf der Kurve angewendet. Der `protocol_fee_owner` fordert seinen Anteil über `CollectFee` an.
- `migrate_fee` — eine Pauschalgebühr in Lamports (oder Quote-Einheiten, je nach Konfiguration), die einmalig beim Abschluss erhoben wird. Wird von `migrate_fee_owner` über `CollectMigrateFee` beansprucht.
- `max_share_fee_rate` — initialisiert auf `10_000` (100 bps). Begrenzt das `share_fee_rate`-**Argument**, das `BuyExactIn`, `BuyExactOut`, `SellExactIn` und `SellExactOut` akzeptieren — die Referral-Gebühr, die während des Handels direkt an den Share-Empfänger gezahlt wird. Es begrenzt **nicht** `PlatformConfig.fee_rate`; dieser Satz hat seine eigenen Obergrenzen, beschrieben in [`platform-config`](/de/products/launchlab/platform-config#rate-caps). `CreateConfig` erzwingt bei der Initialisierung `trade_fee_rate + max_share_fee_rate < RATE_DENOMINATOR_VALUE`. Auf dem Update-Pfad prüft nur `param = 6` (`max_share_fee_rate`) die Summe erneut; `param = 0` (`trade_fee_rate`) sichert lediglich `trade_fee_rate < RATE_DENOMINATOR_VALUE` zu, sodass das alleinige Erhöhen der Handelsgebühr das Paar über die kombinierte Grenze schieben kann. Setzen Sie sie in der Reihenfolge, die die Invariante erhält.

### Angebots- und Quoten-Untergrenzen

Diese Untergrenzen begrenzen, welche Kurvenform-Parameter ein Start bei `Initialize` wählen kann. Wenn die `CurveParams` des Erstellers eine davon verletzen, wird `Initialize` mit `InvalidInput` rückgängig gemacht.

- `min_base_supply` — das Minimum `supply` (ohne Dezimalstellen), das die Kurve deklarieren kann. Standard ist `10_000_000`.
- `max_lock_rate` — ausgedrückt in `1/1_000_000`; Standard `300_000` (30%). Begrenzt Vesting über `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `min_base_sell_rate` — ausgedrückt in `1/1_000_000`; Standard `200_000` (20%). Begrenzt `base_supply_graduation / supply` von unten.
- `min_base_migrate_rate` — ausgedrückt in `1/1_000_000`; Standard `200_000` (20%). Begrenzt die Anzahl der Token, die übrig bleiben, um den Post-Abschluss-Pool zu seeden.
- `min_quote_fund_raising` — Minimum `quote_reserve_target`, das ein Start deklarieren darf (mit Dezimalstellen). Standard ist `30_000_000_000` Einheiten der Quote-Mint.

### Quote-Mint und Protokoll-Wallets

- `quote_mint` — das Asset, mit dem Benutzer kaufen. Die meisten Starts verwenden Wrapped SOL (`So111…112`) oder USDC (`EPjF…Dt1v`). Eine `GlobalConfig` ist an eine Quote-Mint gebunden; Starts, die eine andere Quote benötigen, zielen auf ein anderes `(curve_type, index)` ab. Die Mint kann entweder vom SPL-Token-Programm oder Token-2022 gehört werden — siehe unten.
- `protocol_fee_owner` — Pubkey, die `CollectFee` signiert und die aufgelaufenen Protokollgebühren bei jedem Start, der an diese Konfiguration gebunden ist, beansprucht. Auf der Kette gespeichert; der Admin kann es über `UpdateConfig` rotieren.
- `migrate_fee_owner` — Pubkey, die `CollectMigrateFee` signiert.

#### Token-2022-Quote-Mints

`CreateConfig` akzeptiert eine Token-2022-`quote_mint`, und Pools, die an eine solche Konfiguration gebunden sind, tragen sie von Anfang bis Ende: der Quote-Vault, beide Fee-Vaults und das Token-Konto des Share-Fee-Empfängers werden alle auf Token-2022 erstellt, und die Swap-Anweisungen berücksichtigen eine `TransferFeeConfig` auf der Quote-Seite. `PoolState.token_program_flag` Bit1 zeichnet die Wahl pro Start auf.

Zwei Einschränkungen sind erwähnenswert, bevor Sie sich auf eine verlassen:

- **Das veraltete `Initialize` kann nicht dagegen starten.** Nur `InitializeV2` und `InitializeWithToken2022` akzeptieren ein Token-2022-Quote-Programm. Siehe [`instructions`](/de/products/launchlab/instructions#instruction-inventory).
- **Es wird keine Erweiterungs-Allowlist angewendet.** Im Gegensatz zu CPMM und CLMM prüft LaunchLab die Erweiterungen einer Quote-Mint nicht — `CreateConfig` nimmt die Mint wie gegeben, daher ist das einzige Gate die Admin-Diskretion darüber, welche Mints an eine Konfiguration gebunden werden. Die `NoSupportExtension`-Prüfung des Programms deckt nur Token-2022-Base-Mints ab, die LaunchLab selbst erstellt. Behandeln Sie das Binden einer als hochvertrauenswürdige Aktion; siehe [`reference/token-2022-support`](/de/reference/token-2022-support#launchlab-quote-mints).

### Migrations-Wallets

Die zwei gespeicherten Abschluss-Wallets erfordern unterschiedliche Unterzeichner:

- `migrate_to_amm_wallet` — signiert `MigrateToAmm` für einen bestehenden Legacy-Start, dessen gespeicherter `migrate_type = 0`.
- `migrate_to_cpswap_wallet` — signiert `MigrateToCpswap`. Jeder neu initialisierte Start verwendet diesen Pfad.

Diese werden typischerweise vom Raydium-betriebenen Abschluss-Crank gehalten, sodass der Abschluss kurz nach dem Erreichen des Schwellenwerts stattfindet, anstatt darauf zu warten, dass der Ersteller ihn aufruft.

### Plattformseitige Allowlists

`GlobalConfig` hat nicht mehr `requires_platform_auth`. Sein ehemaliges Byte ist Padding, daher ändert sich die Kontogröße nicht. Der Zugriff wird jetzt durch `PlatformConfig.restrict_global_config` und `PlatformAllowConfig`-Konten kontrolliert, die vom Admin dieser Plattform erstellt werden. Siehe [`platform-config`](/de/products/launchlab/platform-config).

## Standardwerte bei der Initialisierung

Wenn `CreateConfig` aufgerufen wird, initialisiert das Programm viele Felder mit hartcodierten Standardwerten:

```rust
self.max_share_fee_rate     = 10_000;                  // 100 bps (referral share fee)
self.min_base_supply        = 10_000_000;              // no decimals
self.max_lock_rate          = 300_000;                 // 30%
self.min_base_migrate_rate  = 200_000;                 // 20%
self.min_base_sell_rate     = 200_000;                 // 20%
self.min_quote_fund_raising = 30_000_000_000;
```

Der Admin setzt `curve_type`, `index`, `migrate_fee`, `trade_fee_rate`, `quote_mint` und die vier Wallet-Pubkeys explizit zum Erstellungszeitpunkt; nachfolgende Werte können über `UpdateConfig` angepasst werden.

## Wie ein Start eine `GlobalConfig` wählt

Bei `Initialize` übergibt der Ersteller:

- `(curve_type, index)`, um zu wählen, welche `GlobalConfig` PDA geladen werden soll.
- `CurveParams`, die die Kurvenform beschreiben (`supply`, `total_base_sell`, `total_quote_fund_raising`, `migrate_type`).
- `VestingParams`, die das gesperrte Angebot beschreiben.
- `MintParams` für die Base-Mint.

Das Programm erzwingt:

- `curve_type` stimmt mit `global_config.curve_type` überein.
- `supply >= global_config.min_base_supply`.
- `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `total_base_sell >= supply * min_base_sell_rate / 1_000_000`.
- `(supply − total_base_sell − total_locked_amount) >= supply * min_base_migrate_rate / 1_000_000` — d. h. genug Token übrig, um den Post-Abschluss-Pool zu seeden.
- `total_quote_fund_raising >= min_quote_fund_raising`.
- `migrate_type == 1` (`CPSWAP`).
- Wenn die ausgewählte Plattform `restrict_global_config == 1` hat, ist die entsprechende `PlatformAllowConfig` enthalten.

Nach `Initialize` speichert die `PoolState` des Starts die `global_config`-Pubkey direkt, daher ist die Bindung dauerhaft.

## Update-Pfad

`UpdateConfig` nimmt ein `(param: u8, value: u64)`-Paar und akzeptiert entweder den LaunchLab-Programm-Admin **oder** die delegierte Create-Config-Autorität als Unterzeichner — jeder andere Unterzeichner erhält `InvalidOwner` (`6001`). Jeder `param`-Wert wählt, welches Feld mutiert werden soll:

| `param` | Geändertes Feld | Neuer Wert kommt von | Validierung |
|---------|---------------|----------------------|------------|
| 0 | `trade_fee_rate` | `value` | `< 1_000_000` (per Assertion — eine Verletzung panickt statt einen Fehler zurückzugeben) |
| 1 | `protocol_fee_owner` | `remaining_accounts[0].key` | darf nicht der Default-Pubkey sein |
| 2 | `migrate_fee_owner` | `remaining_accounts[0].key` | darf nicht der Default-Pubkey sein |
| 3 | `migrate_to_amm_wallet` | `remaining_accounts[0].key` | darf nicht der Default-Pubkey sein |
| 4 | `migrate_to_cpswap_wallet` | `remaining_accounts[0].key` | darf nicht der Default-Pubkey sein |
| 5 | `migrate_fee` | `value` | keine |
| 6 | `max_share_fee_rate` | `value` | `< 1_000_000 − trade_fee_rate` |
| 7 | `min_base_supply` | `value` | `> 0` |
| 8 | `max_lock_rate` | `value` | `< 1_000_000` |
| 9 | `min_base_sell_rate` | `value` | `0 < v < 1_000_000` |
| 10 | `min_base_migrate_rate` | `value` | `0 < v < 1_000_000` |
| 11 | `min_quote_fund_raising` | `value` | `> 0` |

<Warning>
  Die vier Wallet-Rotationen sind gewöhnliche `param`-Werte im selben Dispatch — sie sind **keine**
  separate Argument-Form. Sie ignorieren `value` vollständig und lesen den neuen Key aus dem *ersten*
  `remaining_account`; wird dieses Konto weggelassen, panickt ein `unwrap()`. Jeder `param` über `11` gibt
  `InvalidInput` (`6002`) zurück.
</Warning>

Der ehemalige `UpdateConfig`-Selektor `12` für Plattformautorisierung ist entfernt. Plattform-Admins verwalten jetzt ihre eigenen Allowlists.

## Lesen einer `GlobalConfig` von einem Client

```ts
import { Raydium } from "@raydium-io/raydium-sdk-v2";

// Fetch by PDA derivation:
const [configPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    quoteMint.toBytes(),
    Buffer.from([curveType]),
    u16ToBytes(index),
  ],
  LAUNCHLAB_PROGRAM_ID,
);

// The SDK exposes the layout, not a getter — decode the account yourself:
import { LaunchpadConfig } from "@raydium-io/raydium-sdk-v2";
const info = await connection.getAccountInfo(configPda);
const config = LaunchpadConfig.decode(info!.data);
console.log(config.tradeFeeRate.toString(), config.minFundRaisingB.toString());
```

Beachten Sie, dass die Feldnamen des Layouts von den On-Chain-Rust-Namen abweichen: die Fundraising-Untergrenze dekodiert als `minFundRaisingB`, die Angebots-Untergrenze als `minSupplyA` und die Verkaufs-/Migrations-Ratenuntergrenzen als `minSellRateA` / `minMigrateRateA`.

Für eine UI, die alle verfügbaren Konfigurationen auflistet, fragen Sie den LaunchLab-API-Endpunkt ab, der sie spiegelt (`raydium.api.fetchLaunchConfigs()`); die On-Chain-Kontoanzahl ist klein (in der Praxis einstellig).
