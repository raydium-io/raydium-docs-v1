<Info>
  `GlobalConfig` ist das **Konfigurationskonto auf Protokollebene**. Es kann viele davon geben — indiziert nach `(curve_type, index)` — und jeder Start wählt genau eines zum Zeitpunkt von `Initialize` aus. Die Werte auf der gewählten `GlobalConfig` werden dann zu harten Grenzen für die Parameter dieses Starts. Für Anpassungen auf Plattformebene (Pro-Plattform-Gebührensatz, zulässige Kurvenfunktionen, NFT-Aufteilungen bei Graduierung) siehe [`products/launchlab/platform-config`](/de/products/launchlab/platform-config).
</Info>

## Was es ist

Eine `GlobalConfig` ist eine Singleton-PDA pro `(curve_type, index)`, die die Protokoll-Regeln festlegt, die jeder Start befolgen muss:

- Die Art der zulässigen Bindungskurve (`curve_type`).
- Der Handelsgebührensatz, den die Kurve bei jedem Kauf und Verkauf erhebt.
- Die bei Graduierung erhobene Migrationsgebühr.
- Untergrenzen für Angebot, Sperrquote, Verkaufsquote und Migrationsquote.
- Der Quote-Mint (typischerweise Wrapped SOL oder USDC) — das Asset, mit dem Benutzer kaufen.
- Vier Protokoll-Wallets: der Protokollgebühren-Eigentümer, der Migrationsgebühren-Eigentümer und die beiden Migrations-Kontroll-Wallets, die für CPMM und Legacy-AMM-v4-Graduierung beibehalten werden.

`GlobalConfig`-Konten können vom LaunchLab-Programm-Admin oder der delegierten Create-Config-Autorität erstellt werden. Nur der Admin aktualisiert bestehende Konfigurationen. Siehe [`reference/program-addresses`](/de/reference/program-addresses) für die kanonischen Autoritäten.

## Layout

```rust
// states/config.rs
pub const GLOBAL_CONFIG_SEED: &str = "global_config";

#[account]
pub struct GlobalConfig {
    pub epoch:                   u64,         // recent_epoch tracker
    pub curve_type:              u8,          // 0 = ConstantProduct, 1 = FixedPrice, 2 = LinearPrice
    pub index:                   u16,         // discriminator within a curve_type
    pub migrate_fee:             u64,         // SOL paid on graduation
    pub trade_fee_rate:          u64,         // 1/1_000_000 of volume
    pub max_share_fee_rate:      u64,         // 100 bps cap on platform share fee
    pub min_base_supply:         u64,         // floor on Initialize supply (no decimals)
    pub max_lock_rate:           u64,         // ceiling on vesting locked / supply
    pub min_base_sell_rate:      u64,         // floor on base_supply_graduation / supply
    pub min_base_migrate_rate:   u64,         // floor on tokens that seed the post-graduation pool
    pub min_quote_fund_raising:  u64,         // floor on quote_reserve_target (with decimals)
    pub quote_mint:              Pubkey,
    pub protocol_fee_owner:      Pubkey,      // claims protocol fees via CollectFee
    pub migrate_fee_owner:       Pubkey,      // claims migration fees via CollectMigrateFee
    pub migrate_to_amm_wallet:   Pubkey,      // can sign MigrateToAmm
    pub migrate_to_cpswap_wallet:Pubkey,      // can sign MigrateToCpswap
    pub padding_alignment:       [u8; 8],
    pub padding:                 [u64; 15],
}
```

PDA-Ableitung:

```ts
const [globalConfig] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    Buffer.from(quoteMint.toBytes()),
    Buffer.from([curveType]),

);
```

## Feldsemanantik

### `curve_type` und `index`

Zusammen identifizieren diese eine `GlobalConfig` eindeutig. Es gibt eine `GlobalConfig` pro `(curve_type, index)`-Paar:

- `curve_type = 0` — Konstant-Produkt-Virtual-Reserve-Kurve. Standard und am häufigsten verwendet.
- `curve_type = 1` — Festpreis-Kurve.
- `curve_type = 2` — Linear-Preis-Kurve.

`index` ist ein `u16`, das dem Admin ermöglicht, mehrere Konfigurationen pro Kurventyp zu veröffentlichen (z. B. eine mit niedrigerem Gebührensatz, eine mit höherem Mindest-Quote-Aufbringung). Bei `Initialize` gibt der Start ein `(curve_type, index)`-Paar an und das Programm lädt die entsprechende `GlobalConfig`.

### Gebühren

- `trade_fee_rate` — ausgedrückt in `1/1_000_000` des Handelsvolumens. Wird auf jeden Kauf und Verkauf auf der Kurve angewendet. Der `protocol_fee_owner` fordert seinen Anteil über `CollectFee` an.
- `migrate_fee` — eine Pauschalgebühr in Lamports (oder Quote-Einheiten, je nach Konfiguration), die einmalig bei Graduierung erhoben wird. Wird von `migrate_fee_owner` über `CollectMigrateFee` angefordert.
- `max_share_fee_rate` — initialisiert auf `10_000` (100 bps). Begrenzt den **Plattform**-Gebührensatz aus der bindenden `PlatformConfig` (siehe [`platform-config`](/de/products/launchlab/platform-config)). Das Programm erzwingt `trade_fee_rate + max_share_fee_rate < RATE_DENOMINATOR_VALUE`.

### Angebots- und Quoten-Untergrenzen

Diese Untergrenzen beschränken, welche Kurvenform-Parameter ein Start bei `Initialize` wählen kann. Wenn die `CurveParams` des Erstellers eine davon verletzen, wird `Initialize` mit `InvalidInput` zurückgewiesen.

- `min_base_supply` — das Minimum `supply` (ohne Dezimalstellen), das die Kurve deklarieren kann. Standard ist `10_000_000`.
- `max_lock_rate` — ausgedrückt in `1/1_000_000`; Standard `300_000` (30%). Begrenzt Vesting über `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `min_base_sell_rate` — ausgedrückt in `1/1_000_000`; Standard `200_000` (20%). Begrenzt `base_supply_graduation / supply` von unten.
- `min_base_migrate_rate` — ausgedrückt in `1/1_000_000`; Standard `200_000` (20%). Begrenzt die Anzahl der Token, die übrig bleiben, um den Post-Graduierungs-Pool zu seeden.
- `min_quote_fund_raising` — Minimum `quote_reserve_target`, das ein Start deklarieren darf (mit Dezimalstellen). Standard ist `30_000_000_000` Einheiten des Quote-Mints.

### Quote-Mint und Protokoll-Wallets

- `quote_mint` — das Asset, mit dem Benutzer kaufen. Die meisten Starts verwenden Wrapped SOL (`So111…112`) oder USDC (`EPjF…Dt1v`). Eine `GlobalConfig` ist an einen Quote-Mint gebunden; Starts, die einen anderen Quote-Mint benötigen, zielen auf ein anderes `(curve_type, index)` ab. Der Mint kann entweder vom SPL-Token-Programm oder Token-2022 gehört werden — siehe unten.
- `protocol_fee_owner` — Pubkey, der `CollectFee` signiert und die aufgelaufenen Protokollgebühren bei jedem Start, der an diese Konfiguration gebunden ist, anfordert. Wird On-Chain gespeichert; der Admin kann es über `UpdateConfig` rotieren.
- `migrate_fee_owner` — Pubkey, der `CollectMigrateFee` signiert.

#### Token-2022-Quote-Mints

`CreateConfig` akzeptiert einen Token-2022-`quote_mint`, und Pools, die an eine solche Konfiguration gebunden sind, tragen ihn von Anfang bis Ende: der Quote-Vault, beide Gebühren-Vaults und das Token-Konto des Share-Fee-Empfängers werden alle auf Token-2022 erstellt, und die Swap-Anweisungen berücksichtigen eine `TransferFeeConfig` auf der Quote-Seite. `PoolState.token_program_flag` Bit1 zeichnet die Wahl pro Start auf.

Zwei Einschränkungen sind wissenswert, bevor Sie sich auf eine verlassen:

- **Das veraltete `Initialize` kann nicht dagegen starten.** Nur `InitializeV2` und `InitializeWithToken2022` akzeptieren ein Token-2022-Quote-Programm. Siehe [`instructions`](/de/products/launchlab/instructions#instruction-inventory).
- **Es wird keine Extension-Allowlist angewendet.** Im Gegensatz zu CPMM und CLMM überprüft LaunchLab die Extensions eines Quote-Mints nicht — `CreateConfig` nimmt den Mint wie gegeben, daher ist das einzige Gate die Admin-Diskretion über welche Mints an eine Konfiguration gebunden werden. Die `NoSupportExtension`-Prüfung des Programms deckt nur Token-2022-Base-Mints ab, die LaunchLab selbst erstellt. Behandeln Sie das Binden eines als hochgradig vertrauenswürdige Aktion; siehe [`reference/token-2022-support`](/de/reference/token-2022-support#launchlab-quote-mints).

### Migrations-Wallets

Die zwei gespeicherten Graduierungs-Wallets erfordern unterschiedliche Unterzeichner:

- `migrate_to_amm_wallet` — signiert `MigrateToAmm` für einen bestehenden Legacy-Start, dessen gespeicherter `migrate_type = 0`.
- `migrate_to_cpswap_wallet` — signiert `MigrateToCpswap`. Jeder neu initialisierte Start verwendet diesen Pfad.

Diese werden typischerweise vom Raydium-betriebenen Graduierungs-Crank gehalten, sodass die Graduierung kurz nach dem Erreichen der Kurven-Schwelle stattfindet, anstatt auf den Aufruf des Erstellers zu warten.

### Plattform-seitige Allowlists

`GlobalConfig` hat nicht mehr `requires_platform_auth`. Sein ehemaliges Byte ist Padding, daher ändert sich die Kontogröße nicht. Der Zugriff wird jetzt durch `PlatformConfig.restrict_global_config` und `PlatformAllowConfig`-Konten kontrolliert, die vom Admin dieser Plattform erstellt werden. Siehe [`platform-config`](/de/products/launchlab/platform-config).

## Standardwerte bei Initialisierung

Wenn `CreateConfig` aufgerufen wird, initialisiert das Programm viele Felder mit hartcodierten Standardwerten:

```rust
self.max_share_fee_rate     = 10_000;                  // 100 bps
self.min_base_supply        = 10_000_000;              // no decimals
self.max_lock_rate          = 300_000;                 // 30%
self.min_base_migrate_rate  = 200_000;                 // 20%
self.min_base_sell_rate     = 200_000;                 // 20%
self.min_quote_fund_raising = 30_000_000_000;
```

Der Admin setzt `curve_type`, `index`, `migrate_fee`, `trade_fee_rate`, `quote_mint` und die vier Wallet-Pubkeys explizit zum Erstellungszeitpunkt; nachfolgende Werte können über `UpdateConfig` angepasst werden.

## Wie ein Start eine `GlobalConfig` wählt

Bei `Initialize` übergibt der Ersteller:

- `(curve_type, index)`, um zu wählen, welche `GlobalConfig`-PDA geladen werden soll.
- `CurveParams`, die die Kurvenform beschreiben (`supply`, `total_base_sell`, `total_quote_fund_raising`, `migrate_type`).
- `VestingParams`, die das gesperrte Angebot beschreiben.
- `MintParams` für den Base-Mint.

Das Programm erzwingt:

- `curve_type` stimmt mit `global_config.curve_type` überein.
- `supply >= global_config.min_base_supply`.
- `total_locked_amount <= supply * max_lock_rate / 1_000_000`.
- `total_base_sell >= supply * min_base_sell_rate / 1_000_000`.
- `(supply − total_base_sell − total_locked_amount) >= supply * min_base_migrate_rate / 1_000_000` — d. h. genug Token übrig, um den Post-Graduierungs-Pool zu seeden.
- `total_quote_fund_raising >= min_quote_fund_raising`.
- `migrate_type == 1` (`CPSWAP`).
- Wenn die ausgewählte Plattform `restrict_global_config == 1` hat, wird die entsprechende `PlatformAllowConfig` eingebunden.

Nach `Initialize` speichert die `PoolState` des Starts die `global_config`-Pubkey direkt, sodass die Bindung permanent ist.

## Update-Pfad

`UpdateConfig` ist nur für Admins und nimmt ein `(param: u8, value: u64)`-Paar. Jeder `param`-Wert wählt, welches Feld mutiert werden soll:

| `param` | Geändertes Feld |
|---------|---------------|
| 0 | `migrate_fee` |
| 1 | `trade_fee_rate` |
| 2 | `max_share_fee_rate` |
| 3 | `min_base_supply` |
| 4 | `max_lock_rate` |
| 5 | `min_base_sell_rate` |
| 6 | `min_base_migrate_rate` |
| 7 | `min_quote_fund_raising` |

Wallet-Rotationen (`protocol_fee_owner`, `migrate_fee_owner`, `migrate_to_amm_wallet`, `migrate_to_cpswap_wallet`) nehmen eine separate `Pubkey`-Argument-Form; überprüfen Sie die `update_config`-Quelle auf die genaue Dispatch-Tabelle, bevor Sie eine Admin-Transaktion zusammenstellen.

Der ehemalige `UpdateConfig`-Selektor `12` für Plattform-Autorisierung ist entfernt. Plattform-Admins verwalten jetzt ihre eigenen Allowlists.

## Lesen einer `GlobalConfig` von einem Client

```ts
import { Raydium } from "@raydium-io/raydium-sdk-v2";

// Fetch by PDA derivation:
const [configPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("global_config"),
    quoteMint.toBytes(),
    Buffer.from([curveType]),
    u16ToBytes(index),
  ],
  LAUNCHLAB_PROGRAM_ID,
);

const config = await raydium.launchpad.getGlobalConfig(configPda);
console.log(config.tradeFeeRate, config.minQuoteFundRaising);
```

Für eine UI, die alle verfügbaren Konfigurationen auflistet, durchlaufen Sie den `getAllGlobalConfigs`-Helper des SDK oder fragen Sie den LaunchLab-API-Endpunkt ab, der sie spiegelt; die On-Chain-Kontoanzahl ist klein (in der Praxis einstellig).
