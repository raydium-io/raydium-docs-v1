<Info>
  Eine **Plattform** in LaunchLab ist eine Drittanbieter-Launch-Umgebung, die auf Raydiums LaunchLab-Programm aufbaut. Plattformen können sich selbst branden, eigene Gebühren erheben und die Parameter nach der Bonding-Curve-Migration für jeden unter ihnen gestarteten Token konfigurieren – ohne ein separates On-Chain-Programm zu betreiben. Raydiums eigene Launch-UI ist nur eine Plattform unter vielen.
</Info>

## Warum Plattformen existieren

Raydium wollte, dass LaunchLab ein **gemeinsames Primitiv** ist, nicht ein einzelnes Markenprodukt. Das Platform-PDA-System ermöglicht es Ökosystemen, Tooling-Anbietern, Communities und Meme-Teams, kuratierte oder gebrandete Launch-Erfahrungen anzubieten, die alle im gleichen zugrunde liegenden LaunchLab-Bonding-Curve-Programm und CPMM-Pool nach der Migration abgewickelt werden.

Beispiele für Plattformen, die Sie in der Praxis sehen könnten:

- **Raydiums eigene LaunchLab-UI** unter raydium.io/launchlab – die Referenzimplementierung.
- **Partner-Launchpads** – Drittanbieter, die ihre eigene Platform PDA registriert haben, um die Launch-Erfahrung zu branden.
- **Nischen-Plattformen** – z. B. eine Community-spezifische Plattform, die nur Memecoins mit einem bestimmten Thema startet und eine benutzerdefinierte Gebührenaufteilung zur Finanzierung ihrer Schatzkammer nutzt.

Alle diese Token leben immer noch auf dem gleichen LaunchLab-Programm, wechseln zum gleichen CPMM-Programm und können von den gleichen Aggregatoren weitergeleitet werden.

## Die Platform PDA

Jede Plattform wird durch eine Platform PDA dargestellt, die im LaunchLab-Programm gespeichert ist. Die Felder umfassen:

| Feld | Beschreibung |
|---|---|
| `platform_key` | Seed / Identifikator für die Plattform, wird verwendet, um die Platform PDA abzuleiten. |
| `platform_fee_destination` | Konto, das den Anteil der Plattform an Handelsgebühren vor und nach der Migration erhält. |
| `platform_fee_bps` | Plattformgebührenanteil bei Swaps vor der Migration (variiert je nach Plattform). |
| `creator_fee_rate` | Creator-Gebührensatz während des Bonding-Curve-Handels. |
| `platform_scale`, `creator_scale`, `burn_scale` | Gespeicherte LP-Skalierungen. Vor dem Upgrade ging die Creator-Skalierung an einen Creator Fee Key. Bei Migrationen, die danach ausgeführt werden, kombinieren sich die ersten beiden zu einem gesperrten LP-Anteil der Plattform; `burn_scale` wird verbrannt. |
| `cp_config_id` | Falls das Migrationsziel CPMM ist, welche `AmmConfig` verwendet werden soll – wählt die Gebührenebene. |
| `restrict_global_config` | Ob Launches eine von der Plattform erstellte Allow-PDA für die ausgewählte `GlobalConfig` präsentieren müssen. |
| `name`, `description`, `image_url` | Anzeigende Metadaten, die von Wallets und UIs verwendet werden, die Plattform-Branding unterstützen. |
| `tokens_launched` | Zähler oder On-Chain-Index von Tokens, die unter dieser Plattform erstellt wurden. |

Genaue Feldnamen finden Sie in der LaunchLab IDL ([`sdk-api/anchor-idl`](/de/sdk-api/anchor-idl)). Die obige Tabelle ist eine beschreibende Übersicht.

## Was eine Plattform kontrollieren kann

**Gebührenerfassung:**

- **Plattformgebührenanteil** bei jedem Kauf/Verkauf vor der Migration.
- **Anteil nach der Migration** – vor dem Upgrade vom 14.08.2026 erzeugte die Creator-Skalierung einen separaten Creator Fee Key. Bei Migrationen, die danach ausgeführt werden, wird `platform_scale + creator_scale` zu einer von der Plattform verwalteten gesperrten LP-Position und `burn_scale` wird verbrannt.

**Migrationsziel:**

- **CPMM** mit einer `AmmConfig`, die über `cp_config_id` ausgewählt wird. Alle neu initialisierten Launches verwenden CPMM.
- **AMM v4** bleibt nur als Migrationspfad für bestehende Launch-States, die mit dem Legacy-Migrationstyp erstellt wurden.

**Benutzererfahrung:**

- **Branding-Metadaten**, die von der Raydium-App und jedem Wallet / Explorer verwendet werden, der LaunchLab-Token anzeigt.
- **Launch-Seiten-Anpassung** – Plattformen, die ihr eigenes Frontend hosten, können Token filtern, um nur ihre eigenen Plattform-Launches anzuzeigen.

## Was eine Plattform nicht kontrollieren kann

- **Bonding-Curve-Mathematik.** Die Kurvenform (logistisch, exponentiell usw.) ist Teil des LaunchLab-Programms selbst. Plattformen wählen aus den unterstützten Kurven; sie können keine beliebigen benutzerdefinierten Kurven hinzufügen.
- **Migrations-Schwellen-Logik.** Die Bedingung, die die Graduation zu CPMM auslöst, wird vom Programm erzwungen.
- **Kern-Sicherheit / Audit-Haltung.** Jede Plattform erbt die Audit-Historie von LaunchLab; eine böswillige Plattform kann diese nicht umgehen, indem sie das Programm ändert.

## Registrierung einer Plattform

Das LaunchLab-Programm stellt eine `create_platform`-Anweisung bereit (genaue Bezeichnung aus der IDL). Aufrufer übergeben:

- Den Seed, der die Platform PDA ableitet.
- Das Gebühren-Zielkonto.
- Gewünschte Gebühren in bps (unterliegen Programm-Level-Limits).
- Post-Migration-Konfiguration (CPMM `AmmConfig` ID, falls zutreffend).
- Branding-Metadaten.

Die Miete für die Platform PDA wird vom Ersteller bezahlt. Updates für Branding und einige Gebührenparameter sind nach der Erstellung durch die Autorität der Plattform zulässig; strukturelle Parameter (Migrationsziel-Programm) normalerweise nicht.

Siehe [`products/launchlab/instructions`](/de/products/launchlab/instructions) für die genaue Anweisungssignatur in der aktuellen LaunchLab IDL.

## Wirtschaftliche Interaktion

Ein einzelner Swap auf einer LaunchLab-Bonding-Curve verteilt Wert ungefähr so (genaue Verhältnisse werden von der Plattform festgelegt):

```
Käufer zahlt:                100 SOL
Protokollgebühr (LaunchLab): – kleiner %
Plattformgebühr:             – platform_fee_bps%
Creator-Gebühr (vor Migr.):  – creator_fee_bps% (falls aktiviert)
Rest (zur Kurve):            ~ Rest
```

Nach der Migration haben LP-Token zwei effektive Ziele:

```
LP-Token bei Graduation geprägt: 100%
  → Verbrannt:                      burnScale
  → Platform Fee Key:               platformScale + creatorScale
```

Der Platform Fee Key stellt einfordbare LP-Gebührenrechte dar, ohne die Möglichkeit, die gesperrte Liquidität abzuheben. Verbrannte LP haben keinen Fee-Key-Inhaber.

## Einschränkung von Global Configs

Ein Plattform-Admin kann `restrict_global_config = 1` setzen und eine `PlatformAllowConfig` pro akzeptierter `GlobalConfig` erstellen. Neue Launch-Transaktionen müssen dann die entsprechende Allow-PDA anhängen. Mit deaktivierter Einschränkung akzeptiert die Plattform jede Config, die die andere Validierung des Programms besteht.

## Hinweise für Integratoren

- **Tokens nach Plattform auflisten.** Verwenden Sie die API-Pool-Info / Mint-Endpunkte mit einem `platform`-Filter (falls unterstützt), um nur Tokens aufzulisten, die unter einer bestimmten Platform PDA gestartet wurden.
- **Branding-Anzeige.** Wenn Sie ein Wallet oder einen Explorer erstellen, der LaunchLab-Token anzeigt, ist das Lesen des Plattformnamens / der Bild-URL aus der Platform PDA eine viel bessere UX als die Anzeige von „LaunchLab" für jeden Token.
- **Gebühren-Mathematik.** Jedes Bonding-Curve-Angebot muss die Plattformgebühr zusätzlich zu den Protokoll- und Creator-Gebühren berücksichtigen. Die Quote-Helper des SDK tun dies automatisch, wenn die Platform PDA bereitgestellt wird.
