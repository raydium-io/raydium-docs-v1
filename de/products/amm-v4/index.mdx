## Was es ist

AMM v4 ist Raydiums Pool der ersten Generation. Es behält eine Konstantes-Produkt-Invariante (xy=k) bei. Der Pool war ursprünglich als **Hybrid-AMM** konzipiert: Neben der Kurve postete er ein Fibonacci-verteiltes Gitter von Limit-Orders auf einem gebundenen OpenBook-Markt, sodass die Pool-Liquidität für Order-Book-Taker sichtbar war. **Diese OpenBook-Integration wurde später aus dem Programm entfernt** (siehe Warnung oben); AMM v4 ist heute ein reines Konstantes-Produkt-AMM. On-Chain-`AmmInfo`-Accounts behalten ihre `market`- / `open_orders`-Referenzfelder für Layout-Kompatibilität, aber das Programm liest oder handelt nach ihnen nicht mehr.

Es ist immer noch das Produkt mit der höchsten Liquidität auf Raydium für viele Legacy-Paare, wird aber **nicht mehr für neue Pools empfohlen** — siehe [CPMM](/de/products/cpmm) für neue Deployments.

**Programm-ID:** siehe [reference/program-addresses](/de/reference/program-addresses).

**Token-2022:** nicht unterstützt. AMM v4-Pools akzeptieren nur klassische SPL-Token.

## Wann Sie dies lesen sollten

- Sie prüfen oder integrieren gegen bestehende AMM v4-Pools.
- Sie erstellen einen Router, der v4-Liquidität unterstützen muss.
- Sie planen eine Migration von v4 zu CPMM — siehe auch [user-flows/migrate-amm-v4-to-cpmm](/de/user-flows/migrate-amm-v4-to-cpmm).

Wenn Sie einen **neuen** Pool erstellen, lesen Sie stattdessen [CPMM](/de/products/cpmm).
