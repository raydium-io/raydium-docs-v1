## Kern-Tools

### Solana CLI

Die kanonische Befehlszeilenschnittstelle für die Interaktion mit Solana-Clustern — Wallet-Verwaltung, RPC-Aufrufe, Programm-Bereitstellung.

Installation:

```bash
# Die Version, gegen die die Raydium-Programme gebaut und getestet werden
sh -c "$(curl -sSfL https://release.anza.xyz/v3.1.10/install)"

# Oder verfolgen Sie einen Kanal statt eines Tags
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"
```

Überprüfung:

```bash
solana --version   # → solana-cli 3.1.10 (... client:Agave)
```

<Note>
  **Der Installations-Host hat sich geändert.** `release.solana.com` gehörte zu Solana Labs; der Client wird jetzt von Anza als **Agave** gepflegt, und Releases werden von `release.anza.xyz` bereitgestellt. Die Self-Update-Binärdatei ist `agave-install` (`solana-install` wird als Legacy-Alias beibehalten), daher sind `agave-install update` und `agave-install init <version>` die aktuellen Schreibweisen. Solanas eigene Dokumentation bietet auch ein One-Command-Installer, das die CLI, Rust und Anchor zusammen abruft:

  ```bash
  curl --proto '=https' --tlsv1.2 -sSfL https://solana-install.solana.workers.dev | bash
  ```

  Dieser Installer verfolgt seine eigene Vorstellung von aktuell und kann Ihnen einen anderen Anchor als den, den die Raydium-Programme festlegen, geben — überprüfen Sie danach `anchor --version`.
</Note>

Konfiguration für Mainnet:

```bash
solana config set --url https://api.mainnet-beta.solana.com
solana config set --keypair ~/.config/solana/id.json
solana-keygen new                           # Wallet erstellen, falls Sie noch keine haben
solana address                              # Ihr öffentlicher Schlüssel
```

Für Raydium-Tests benötigen Sie fast immer ein finanziertes Devnet-Wallet:

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2                            # 2 SOL zum Testen
```

### SPL Token CLI

Die offizielle CLI für SPL Token / Token-2022-Operationen — Erstellen von Mints, Prägen von Tokens, Übertragungen.

Installation (in Solana CLI enthalten):

```bash
spl-token --version
```

Häufige Operationen:

```bash
spl-token create-token                                  # SPL Token Mint erstellen
spl-token create-token --program-id TOKEN_2022 ...      # Token-2022 Mint erstellen
spl-token create-account <MINT>                         # ATA erstellen
spl-token mint <MINT> 1000                              # 1000 Tokens zu Ihrem ATA prägen
spl-token transfer <MINT> 100 <RECIPIENT>               # 100 übertragen
spl-token display <ACCOUNT_OR_MINT>                     # inspizieren
```

### Anchor CLI

Erforderlich zum Abrufen von Raydium IDLs, zum Erstellen von Clients und zum Überprüfen von Programmen.

Installation:

```bash
cargo install --git https://github.com/solana-foundation/anchor avm --locked --force
avm install 1.0.2
avm use 1.0.2
anchor --version   # → anchor-cli 1.0.2
```

<Note>
  **Anchor hat das Repository und die Hauptversion gewechselt.** Das kanonische Repository ist jetzt `github.com/solana-foundation/anchor` (es war `coral-xyz/anchor`), und Anchor 1.0 ist die erste Release-Linie, die die Raydium-Programme verwenden — CPMM und LaunchLab legen beide `anchor-lang`/`anchor-spl` `=1.0.2` ab dem Update vom 2026-09-09 fest, aufwärts von `0.32.1`. `avm` kann mehrere Versionen halten; `avm use 1.0.2` ist das, was `anchor build` dazu bringt, Raydiums Artefakte zu reproduzieren. Anchor 1.1 und 1.2 existieren und bauen sich gut für Ihre eigenen Programme, aber eine CPI-Crate, die gegen eine andere `anchor-lang`-Nebenversion als die, die das Ziel-Programm festlegt, kompiliert wurde, wird nicht verlinkt — siehe [`sdk-api/rust-cpi`](/de/sdk-api/rust-cpi).
</Note>

Häufige Operationen:

```bash
anchor idl fetch <PROGRAM_ID> -o program.idl.json       # On-Chain IDL abrufen
anchor idl init -f idl.json <PROGRAM_ID>                # IDL hochladen
anchor build                                             # Programm aus Quelle bauen
```

## TypeScript-Setup

Der primäre Integrationspfad für Raydium.

### Pakete

```bash
npm install \
  @solana/web3.js \
  @solana/spl-token \
  @anchor-lang/core \
  @raydium-io/raydium-sdk-v2 \
  bn.js \
  decimal.js
```

Versionen, die ab September 2026 zusammen funktionieren:

| Paket | Version | Hinweis |
|---------|---------|------|
| `@solana/web3.js` | `^1.95` | Die 1.x API. `2.x` / `3.x` sind eine andere, inkompatible API-Oberfläche; das Raydium SDK zielt auf 1.x ab. |
| `@solana/spl-token` | `^0.4.15` | 0.4.15 ist das, was `createUnwrapLamportsInstruction` verfügbar macht — siehe [reclaimable rent](/de/solana-fundamentals/rent-and-reclaimable-rent). |
| `@anchor-lang/core` | `^1.0` | Der Anchor 1.x TypeScript-Client. |
| `@raydium-io/raydium-sdk-v2` | `0.2.64-alpha` | Die Festlegung, die jede Code-Demo in dieser Dokumentation verwendet. |

<Note>
  **`@anchor-lang/core` ist eingefroren; das Paket ist jetzt `@anchor-lang/core`.** `@anchor-lang/core` stoppte bei `0.32.1`, als Anchor zur Solana Foundation wechselte. Anchor 1.x wird als `@anchor-lang/core` veröffentlicht, und Raydiums eigene Programm-Repositories wechselten ihre Test-Suites im Update vom 2026-09-09 dazu. Die Importe, die Sie tatsächlich verwenden, sind unverändert — `import { Program, BN, AnchorProvider } from "@anchor-lang/core"` — daher ist die Migration ein Paket-Umbenennung plus ein Lockfile-Update.

  Zwei Verhaltenshinweise, wenn Sie von `0.3x` wechseln: `.accounts({...})` akzeptiert jetzt nur noch Konten, die Anchor nicht selbst auflösen kann, daher sollte ein Builder, der den vollständigen Satz übergibt, stattdessen `.accountsPartial({...})` aufrufen; und `@anchor-lang/core/dist/cjs/utils/token` ist, wohin Helfer wie `ASSOCIATED_PROGRAM_ID` verschoben wurden.
</Note>

### Minimales Skript

```ts
import { Connection, Keypair } from "@solana/web3.js";
import { Raydium } from "@raydium-io/raydium-sdk-v2";

const connection = new Connection("https://api.mainnet-beta.solana.com", "confirmed");
const owner      = Keypair.fromSecretKey(/* your key */);

const raydium = await Raydium.load({
  connection,
  owner,
  cluster:      "mainnet",
  disableFeatureCheck: true,
});

// `ids` ist eine komma-getrennte Liste, und der Aufruf gibt ein Array zurück
const [poolInfo] = await raydium.api.fetchPoolById({ ids: "..." });
console.log(poolInfo);
```

Siehe [`sdk-api/typescript-sdk`](/de/sdk-api/typescript-sdk) für die vollständige SDK-Referenz.

## Rust-Setup

Für CPI-Integration und On-Chain-Programme.

### Toolchain

```bash
rustup install 1.91.0           # was die Raydium-Programme festlegen
rustup default 1.91.0
rustup component add rustfmt clippy
agave-install init 3.1.10       # SBF-Toolchain enthalten
```

Bauen Sie die Programme mit `cargo build-sbf` (die alte `cargo build-bpf`-Schreibweise ist weg).

### Program Cargo.toml für eine Raydium CPI-Integration

```toml
# CPMM-Integration (Anchor 1.0)
[dependencies]
anchor-lang        = "=1.0.2"
anchor-spl         = "=1.0.2"
raydium-cp-swap    = { version = "0.2", features = ["cpi"] }
```

```toml
# CLMM-Integration — immer noch Anchor 0.32, daher benötigt es seine eigene Crate
[dependencies]
anchor-lang        = "=0.32.1"
anchor-spl         = "=0.32.1"
raydium-clmm       = { version = "0.1", features = ["cpi"] }
```

Legen Sie `anchor-lang` und `anchor-spl` mit `=` auf die Version fest, die das Ziel-Programm festlegt. Ab 2026-09 legt CPMM `=1.0.2` fest und CLMM legt immer noch `=0.32.1` fest, daher **kann eine einzelne Crate nicht in beide CPI-Aufrufe durchführen** — siehe [`sdk-api/rust-cpi`](/de/sdk-api/rust-cpi#cargo-dependencies).

Das `"cpi"`-Feature importiert das `cpi`-Modul mit CPI-Helfern (damit Sie `raydium_cp_swap::cpi::swap_base_input(...)` aufrufen können). Siehe [`sdk-api/rust-cpi`](/de/sdk-api/rust-cpi).

## Python-Setup

Sekundärer Integrationspfad — häufig für Bot-Entwickler.

### Pakete

```bash
pip install solders solana anchorpy
```

Versionen:

| Paket | PyPI-Name | Version |
|---------|-----------|---------|
| `solders` | `solders` | ≥0.29 |
| solana-py | `solana` | ≥0.40 |
| `anchorpy` | `anchorpy` | ≥0.21 |

<Note>
  Zwei Benennungsfallen. Der RPC-Client wird als `solana` importiert, aber das Projekt heißt **solana-py** — `pip install solana-py` installiert nichts Nützliches. Und es gibt **kein `raydium-py`-Paket auf PyPI**: der Community-Raydium-Helfer ist ein Repository, das Sie klonen, [`AL-THE-BOT-FATHER/raydium_py`](https://github.com/AL-THE-BOT-FATHER/raydium_py), keine veröffentlichte Distribution. Frühere Versionen dieser Seite listeten eine `pip install raydium-py`-Zeile auf, die nie funktionierte.
</Note>

### Minimales Skript

```python
from solana.rpc.async_api import AsyncClient
from solders.keypair import Keypair
from anchorpy import Provider, Wallet, Program

async def main():
    conn = AsyncClient("https://api.mainnet-beta.solana.com")
    owner = Keypair()
    wallet = Wallet(owner)
    provider = Provider(conn, wallet)

    # IDL und Programm laden
    with open("cpmm.idl.json") as f:
        idl = json.load(f)
    program = Program(idl, CPMM_PROGRAM_ID, provider)

    pool = await program.account["PoolState"].fetch(pool_id)
    print(pool)
```

## RPC-Endpunkte

Öffentliches Mainnet RPC (`api.mainnet-beta.solana.com`) ist stark ratenbegrenzt und drosselt unter jeder Last. Für nicht-triviale Nutzung erhalten Sie einen privaten Endpunkt:

| Anbieter | Hinweise |
|----------|-------|
| Helius | Am beliebtesten; großzügiger kostenloser Tarif. |
| Triton | Enterprise; Premium-Preisgestaltung, stabil. |
| QuickNode | Solide; Sub-Sekunden-Latenz. |
| Eigener RPC-Knoten | Kostet ~\$500/Monat in Hardware; volle Kontrolle. |

Konfiguration:

```ts
const connection = new Connection("https://mainnet.helius-rpc.com/?api-key=...");
```

Einige RPC-Operationen benötigen erweiterte Funktionen:

- `getProgramAccounts` — uneingeschränkte Scans sind teuer; einige Anbieter sperren oder berechnen pro Scan.
- `getPriorityFeeEstimate` — Helius-spezifischer Endpunkt; andere haben Äquivalente.
- `geyser` / WebSocket-Streaming — erforderlich für Low-Latency-Bots; nicht alle Anbieter stellen es bereit.

## Devnet und Localnet

### Devnet

Solanas öffentlicher Test-Cluster. Raydium hat eine teilweise Devnet-Bereitstellung:

- Einige CPMM-Pools existieren zum Testen.
- AMM v4 hat historische Devnet-Pools.
- CLMM hat ein paar Demo-Pools.
- Farm v6 ist bereitgestellt.

```bash
solana config set --url https://api.devnet.solana.com
solana airdrop 2
```

Das SDK unterstützt Devnet über `cluster: "devnet"`:

```ts
const raydium = await Raydium.load({ connection, owner, cluster: "devnet" });
```

**Vorsicht**: Devnet-Pools haben dünne Liquidität und können veraltete Zustände haben. Verlassen Sie sich nicht auf Devnet für Preiserkennung; verwenden Sie es nur zum Erstellen und Testen von Anweisungsflüssen.

### Localnet mit gegabeltem Mainnet-Status

Für realistisches Testen, gabeln Sie Mainnet-Status in einen lokalen Validator:

```bash
solana-test-validator \
  --url https://api.mainnet-beta.solana.com \
  --clone CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C \
  --clone CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK \
  --clone <SOME_POOL_ID> \
  --clone <SOME_MINT_ID>
```

Dies klont spezifischen Programm-/Kontostatus zu Localhost, wo Sie frei transagieren können. Ideal für:

- Unit-Tests Ihrer CPI-Integration gegen ein echtes Raydium-Programm.
- Wiedergabe einer Transaktion mit einem geänderten Parameter zum Debuggen.
- Stress-Tests mit großen synthetischen Volumen.

Raydiums Team verwendet gegabeltes Localnet umfangreich für Regressionstests vor der Mainnet-Bereitstellung.

## Umgebungs-Hygiene

### Separate Wallets pro Zweck

- **Entwicklungs-Wallet**: hält Testnet SOL, wird zum Bauen verwendet.
- **Produktions-Wallet**: hält echte SOL, wird nur für Bereitstellungen / Multisig-Einreichungen verwendet.
- **Hot Wallet für Bots**: kleines Guthaben, enge Berechtigungen.

Schlüssel sollten niemals hartcodiert sein. Verwenden Sie Umgebungsvariablen oder Secret Manager.

### `.env`-Muster

```
# .env (nicht committed)
SOLANA_RPC_URL=https://mainnet.helius-rpc.com/?api-key=...
WALLET_PATH=/Users/you/.config/solana/id.json
```

```ts
import { config } from "dotenv";
config();

const connection = new Connection(process.env.SOLANA_RPC_URL!);
```

### Versions-Pinning

Sperren Sie alle Solana-Ökosystem-Abhängigkeiten. Das Ökosystem bewegt sich schnell; ein Minor-Version-Bump von `@solana/web3.js` hat zuvor Breaking Changes eingeführt. Verwenden Sie `package-lock.json` / `Cargo.lock` gewissenhaft.
