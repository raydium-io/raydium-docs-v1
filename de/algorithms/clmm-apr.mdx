<Info>
  Die **in der Raydium-Benutzeroberfläche angezeigte APR** für einen CLMM-Pool ist die realisierte Gebühren-APR der **in-Range-Liquidität** der letzten 24 Stunden, hochgerechnet auf ein Jahr. Sie ist nicht die APR, die *Ihre Position* verdient hätte – das hängt von Ihrem Bereich, Ihrer Zeit im Range und Ihrem Anteil an der Liquidität ab, die während des Handelsfensters aktiv war.
</Info>

## Die grundlegende Formel

Für einen CLMM-Pool wird die tägliche Gebühren-APR auf Raydium wie folgt berechnet:

```
apr_24h = (fees_24h / tvl_in_range_24h) · 365
```

Wobei:

- `fees_24h` die Summe der LP-seitigen Swap-Gebühren der letzten 24 Stunden (in USD) ist.
- `tvl_in_range_24h` der zeitgewichtete Durchschnittswert der USD-Liquidität ist, die während des Fensters **im Range** war.

Der Nenner unterscheidet CLMM-APR von CPMM-APR. CPMM verwendet die gesamte Pool-TVL, da jeder Dollar immer beiträgt. CLMM verwendet nur die im-Range-Teilmenge, da Dollar außerhalb des Ranges nichts verdienen.

## Ihre tatsächliche APR

Die Schlagzeilen-APR ist eine Statistik des Pools, nicht Ihrer Position. Ihre APR hängt von vier Multiplikatoren ab:

```
your_APR = headline_APR
         · (your_in_range_fraction / pool_in_range_fraction)     # Konzentrationsprämie
         · time_in_range                                          # Range-Disziplin
         · (1 − transfer_fee_haircut)                             # Token-2022-Steuer
         · compounding_factor                                     # bei Auto-Restaking
```

- **Konzentrationsprämie.** Wenn Ihr Bereich enger ist als der Pool-weite Durchschnitt, hat jeder aktive Tick mehr Ihrer Liquidität pro Dollar als der durchschnittliche LP. Enger = größere Prämie (und proportional größere IL-Verstärkung).
- **Zeit im Range.** Wenn Sie nur 40 % der Zeit im Range sind, multiplizieren Sie mit 0,40.
- **Gebühren-Haarschnitt.** Bei Token-2022-Mints mit Transfergebühren verliert jede Gebührenerfassung durch einen Transfer, der selbst Basispunkte kostet.
- **Compounding.** Wenn Sie `collectFee` wöchentlich einfordern und in denselben Bereich redeploy, beträgt die effektive APR etwa `(1 + daily_APR)^365 − 1`. Ohne Compounding ist sie linear.

### Durchgerechnetes Beispiel

Angenommen, ein SOL/USDC CLMM-Pool hat:

- 24h-Volumen: \$120M
- Gebührentier: 0,05% (LP-Anteil **84%** der Gebühren – jede Mainnet-CLMM `AmmConfig` hat `protocol_fee_rate = 12%` plus `fund_fee_rate = 4%`)
- Gesamt-TVL: \$40M
- In-Range-TVL: \$18M (45 % des Pools sind derzeit im Range)

```
fees_24h = 120M · 0.0005 · 0.84 = $50,400
apr_24h  = (50,400 / 18,000,000) · 365 = 102%
```

Die Raydium-Benutzeroberfläche zeigt **102 % APR** für den Pool an. (Dieses Beispiel verwendet einen tiefen, hochvolumigen Pool, um die Zahlen konkret zu halten; typische CLMM-Pools zeigen überall von 10 % bis 50 % APR, wobei Pools mit niedrigem Volumen deutlich unter 10 % liegen.)

Jetzt erwägen Sie, eine Position zu eröffnen:

- Ihr Bereich: eng genug, dass Sie die 2-fache durchschnittliche Konzentration haben.
- Erwartete Zeit im Range: 70 % (Sie werden wöchentlich überprüfen).
- Keine Token-2022-Gebühren. Kein Auto-Compounding.

```
your_APR ≈ 102% · 2 · 0.70 = 143%
```

Das ist eine Schätzung, keine Garantie. Das realisierte Volumen kann sich in einer Woche halbieren oder verdoppeln.

## Warum nachgelagerte APR ein verzögertes Signal ist

CLMM-APR bewegt sich **schnell** im Vergleich zu CPMM-APR, weil sich der In-Range-TVL-Nenner schnell bewegt:

- Ein großer Preissprung drückt Positionen aus dem Range, verkleinert den Nenner. Plötzlich sieht Ihre verbleibende In-Range-TVL „höher APR" aus – aber nur weil Konkurrenten gegangen sind, und typischerweise fällt auch das Volumen.
- Ein Pool, der ein neues ATH erreicht, kann vorübergehend 500–1000 % APR für eine Stunde anzeigen, da die meisten Positionen für niedrigere Preise kalibriert waren und nur wenige aggressive LPs im Range bleiben.
- Sobald sich der Markt beruhigt, gleichen LPs neu aus und APR kehrt zum Mittelwert zurück.

Faustregel:

- **Ignorieren Sie Sub-24h-APR.** Zu viel Rauschen.
- **Bevorzugen Sie 7d- und 30d-Fenster.** Raydium stellt beide über [`GET /pools/info/ids`](/de/sdk-api/rest-api) bereit – Felder `week.apr` und `month.apr`.
- **Backtesten Sie Ihren spezifischen Bereich** anhand historischer Volumen- und Preisdaten, bevor Sie bedeutendes Kapital einsetzen.

## Wie die Mathematik funktioniert (einzelner Tick-Schritt)

Innerhalb eines einzelnen Ticks verhält sich der CLMM wie ein CPMM auf die Menge der Liquidität `L`, die in diesem Tick aktiv ist. Gebühren sammeln sich in `fee_growth_global_X` und `fee_growth_global_Y` pro Liquiditätseinheit an. Für eine Position mit Liquidität `Lₚ`, die Tick-Bereiche `[i_lo, i_hi]` umfasst:

```
fees_earned_X = Lₚ · (fee_growth_inside_X(i_lo, i_hi, now) − fee_growth_inside_X(i_lo, i_hi, t_open))
fees_earned_Y = Lₚ · (fee_growth_inside_Y(i_lo, i_hi, now) − fee_growth_inside_Y(i_lo, i_hi, t_open))
```

Wobei `fee_growth_inside` das Gebührenwachstum unterhalb von `i_lo` und oberhalb von `i_hi` vom globalen Akkumulator subtrahiert. Details in [`algorithms/clmm-math`](/de/algorithms/clmm-math).

Um *erwartete* Gebühren über einen zukünftigen Zeitraum für einen prospektiven Bereich zu berechnen, schätzen Sie:

```
expected_fees_per_day = Σ_ticks_in_range (volume_at_tick · fee_rate · your_share_at_tick)
```

Raydiums SDK stellt `PoolUtils.estimateAprsForPriceRangeMultiplier` und `PoolUtils.estimateAprsForPriceRangeDelta` für diese Schätzung bereit.

## SDK-Hilfsmittel

```ts
import { Raydium, PoolUtils } from "@raydium-io/raydium-sdk-v2";

const raydium = await Raydium.load({ owner, connection });
// getPoolInfoFromRpc nimmt einen positionalen base58-String im CLMM-Modul.
const pool = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);

// Synchron, und es liest die Volumen-/Gebührenstatistiken aus poolInfo[aprType].
const apr = PoolUtils.estimateAprsForPriceRangeMultiplier({
  poolInfo: pool.poolInfo,
  aprType: "day",                 // "day" | "week" | "month"
  positionTickLowerIndex: -100,   // Ihr beabsichtigter Bereich
  positionTickUpperIndex:  100,
});

console.log(`Expected APR: ${apr.feeApr}% fee-only; rewards: ${apr.rewardsApr.join(", ")}`);
```

Das Hilfsmittel gibt `{ feeApr, rewardsApr[], apr }` zurück – `rewardsApr` ist pro Reward-Stream und `apr` ist die Gesamtsumme. Es gibt keine `raydium.clmm.estimatedApr`-Methode. `estimateAprsForPriceRangeDelta` ist die gleiche Berechnung, parametrisiert durch ein ± Delta um Spot statt expliziter Ticks.

## Wo Farm-APR passt

Raydium CLMM-Pools können Farm v6-Emissionen überlagert haben. Farm-Rewards werden in einem **Reward-Mint** (oft RAY oder ein Partner-Token) unabhängig von Swap-Gebühren gezahlt. Die Raydium-Benutzeroberfläche zeigt typischerweise:

```
Total APR = Fee APR + Farm APR [in $X, Y, Z Reward-Mints]
```

Farm-APR wird ähnlich berechnet, aber mit dem Reward-Emissionsplan und dem aktuellen Preis des Reward-Mints in USD. Im Gegensatz zu Gebühren-APR ist sie nicht volatilitätsabhängig – sie ist ein fester Plan.

Siehe [`products/farm-staking/overview`](/de/products/farm-staking/overview) für Farm-Emissionsmathematik.

## Häufige Fehler

- **„APR wird automatisch zusammengesetzt."** Nein. Gebühren müssen eingefordert werden – über eine Null-Liquiditäts-`DecreaseLiquidity`, da CLMM keine eigenständige Collect-Anweisung hat – dann manuell redeploy. Raydium setzt CLMM-Gebühren nicht automatisch zusammen.
- **„Meine APR = Schlagzeilen-APR."** Nur wenn Ihre Konzentration durchschnittlich ist, Ihre Zeit im Range 100 % beträgt und Sie mit der gleichen Häufigkeit zusammensetzen. Alle drei sind normalerweise falsch.
- **„Höheres Gebührentier = höhere APR."** Nur wenn das Volumen das höhere Gebühren überlebt. Bei 1 % kann ein Paar 50 % APR anbieten, aber 1/10 des Volumen tun; netto weniger als 0,25 % bei 120 % × 0,1 = 12 %.
- **„Out-of-Range-Positionen haben null Risiko."** Sie haben null Gebühreneinnahmen, aber vollständiges IL auf der bestehenden Token-Zusammensetzung – die Position ist jetzt „100 % von welcher Seite auch immer".
