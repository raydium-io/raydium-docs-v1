Alle Anchor-basierten Programme (CLMM, CPMM, LaunchLab, Lock) teilen sich einen einzigen hardcodierten Admin-`Pubkey` für Zugriffskontrolle auf Anweisungsebene zu Admin-Pfaden (wie `CreateAmmConfig` oder `UpdatePoolStatus`):

| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

Operationale Autoritäten auf Kontoebene (z. B. `protocol_owner`, `fund_owner` auf CPMM/CLMM `AmmConfig` oder die Migrations-Wallets auf LaunchLab `GlobalConfig`) werden On-Chain gespeichert und können sich vom Programm-Admin unterscheiden. Lesen Sie sie direkt aus dem relevanten Config-Konto, bevor Sie hochriskante Transaktionen senden.

### CLMM Restricted-Issuer Freeze Authorities

Wenn einer der Vault-Mints in einem CLMM-Pool eine der unten aufgeführten Freeze-Autoritäten hat, werden neue Positionen, die über einen V2-Pfad geöffnet werden, mit ihrem Position-NFT-Token-Konto eingefroren. ### Gemeinsame Config / PDA-Konventionen

Mehrere Raydium-Programme stellen **Config-Konten** bereit, deren öffentliche Schlüssel stabil sind und in der öffentlichen API aufgelistet sind. Bevorzugen Sie die API-Abfrage gegenüber dem Hardcoding:

```
# CPMM Fee Configs (gibt ein Array von {id, index, tradeFeeRate, ...} zurück)
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM Fee Configs
GET https://api-v3.raydium.io/main/clmm-config
```

Standard-CPMM `AmmConfig` Index `0` (Standard 0,25%-Pool) Fee-Parameter zur Referenz:

| Feld | Wert | Bedeutung |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 0,25% des Handelsvolumens |
| `protocol_fee_rate` | `120000` | 12% **der Handelsgebühr** (nicht des Volumens) an das Protokoll |
| `fund_fee_rate` | `40000` | 4% **der Handelsgebühr** an die Fund-Multisig |
| `creator_fee_rate` | `500` | 0,05% des Handelsvolumens an den Pool-Creator (optional) |

Siehe [`products/cpmm/fees`](/de/products/cpmm/fees) für die Zusammensetzung der Aufteilungen und [`reference/fee-comparison`](/de/reference/fee-comparison) für die produktübergreifende Matrix.

### PDA Seeds

Die unten aufgeführten Seeds sind **kanonisch** und werden sowohl vom SDK als auch von On-Chain-CPIs verwendet. Berechnen Sie PDAs immer; hardcodieren Sie abgeleitete Adressen nicht.

```ts
// CPMM — alle Seeds sind statische ASCII-Strings, sofern nicht anders angegeben.
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` werden **nach öffentlicher Schlüssel-Byte-Reihenfolge sortiert** (token0 < token1), bevor sie gehasht werden. Ein Fehler hier führt zu einem gültigen PDA für einen nicht existierenden Pool.

Die äquivalenten CLMM Seeds folgen dem gleichen Stil; siehe [`products/clmm/accounts`](/de/products/clmm/accounts).

## Wie man eine Adresse On-Chain überprüft

1. **Solana Explorer.** Fügen Sie die Adresse in [explorer.solana.com](https://explorer.solana.com) ein und bestätigen Sie, dass sie als `Program` mit einer aktuellen Upgrade-Autorität gekennzeichnet ist. Mainnet-beta sollte Deployments anzeigen, die von Raydiums Upgrade-Autorität signiert sind.
2. **CLI.** Verwenden Sie `solana program show <PROGRAM_ID> -u mainnet-beta`, um Deploy-Slot, BPF-Loader, Upgrade-Autorität und Datenlänge zu überprüfen. Notieren Sie diese in Ihrem Runbook.
3. **IDL-Anhang.** Fragen Sie die On-Chain-IDL mit `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` ab. Das Feld `address` der IDL sollte übereinstimmen. Die gleichen IDLs werden unter [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) gespiegelt – vergleichen Sie die On-Chain-IDL mit dem Repo, bevor Sie ihr vertrauen.
4. **Config/Admin-Autoritäten.** Für CPMM/CLMM Config-Konten lesen Sie das Feld `owner`/`protocol_owner` und bestätigen Sie, dass es mit der aktuellen Raydium-Multisig übereinstimmt, die in [`security/admin-and-multisig`](/de/security/admin-and-multisig) veröffentlicht ist.

Falls einer der vier oben genannten Checks mit dieser Seite nicht übereinstimmt, behandeln Sie diese Seite als fehlerhaft und öffnen Sie ein Issue, bevor Sie neuen Code gegen die Adressen schreiben.
