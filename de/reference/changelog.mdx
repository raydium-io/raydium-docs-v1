## Versionen

<Update label="2026-08-17" description="LaunchLab: CPMM-only Launches und Platform-Config-Steuerung">
  Die neue Launch-Initialisierung erfordert jetzt CPMM, während der Legacy-AMM-v4-gebundene Status migrierbar bleibt. Vor diesem Release erzeugte `creator_scale` einen Creator-eigenen Fee Key; CPMM-Migrationen nach dem Upgrade konsolidieren stattdessen `platform_scale + creator_scale` in einen einzigen Platform-eigenen Fee Key Share. Plattformen können Launches auch mit ihren eigenen `PlatformAllowConfig` PDAs einschränken, und Migration Builder müssen beide CPMM Support-Mint PDAs anhängen.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM: Restricted-Issuer Position NFT Freezing">
  Neue CLMM Position NFT Mints verwenden ihren Pool als Freeze Authority, aber ihre Token Accounts bleiben standardmäßig unfrozen. Freezing tritt nur bei `OpenPositionV2` oder `OpenPositionWithToken22Nft` auf, wenn die Freeze Authority einer der zugrunde liegenden Vault Mints der Restricted-Issuer-Liste entspricht. Eine übereinstimmende Position kann nicht transferiert oder den Besitzer wechseln, kann aber weiterhin Liquidität verwalten. Ihr `ClosePosition` Aufruf muss den Pool anhängen, damit CLMM atomar auftauen, brennen und schließen kann. Bestehende Positionen bleiben unverändert.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM: Permissionless Creator-Fee Collection">
  Eine additive `CollectCreatorFeePermissionless` Instruktion ermöglicht es jedem Zahler, alle aufgelaufenen Creator Fees zu sammeln, während der Begünstigte und beide Token-Ziele auf `PoolState.pool_creator` und die kanonischen ATAs des Creators beschränkt werden. Der ursprüngliche Creator-signierte Pfad bleibt unverändert. `CreatePermissionPda` akzeptiert auch eine dedizierte Grant Authority, während `ClosePermissionPda` nur Admin-Zugriff hat.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM: Permissioned Multi-Pools und Limit-Order Frozen-Account Guard">
  Zwei additive, rückwärtskompatible CLMM-Programm-Updates. `CreatePermissionedPool` integriert einen vom Client bereitgestellten nicht-null `seed_index` in die Pool PDA Seeds, wodurch ein whitelisteter Operator (einer, der eine `Permission` PDA hält) mehrere Pools pro `(config, mint0, mint1)` erstellen kann — so ist eine Pool ID nicht mehr kanonisch für ein Paar. Neue Admin-Instruktionen `CreatePermissionPda` / `ClosePermissionPda` verwalten diese Grants, und `PoolState` erhält ein `seed_index` Feld (aus Padding geschnitzt, keine Größenänderung). Separat nimmt `OpenLimitOrder` jetzt die Output-Side Accounts und lehnt Orders ab, deren Input- oder Output-Token Account gefroren ist (`NotApproved`).

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4: OpenBook / Serum Abhängigkeit entfernen">
  AMM v4 entfernt seine lange inaktive OpenBook/Serum-Abhängigkeit, alle Order-Book CPIs und die toten Market-Making-Instruktionen. `SwapBaseIn` / `SwapBaseOut`, `Deposit` und `Withdraw` behalten ihre Layouts (entfernte Market Accounts werden jetzt ignoriert, nicht validiert); ein **hart brechender** `WithdrawPnl` (17 → 10, keine Kompatibilität) und `SetParams` (reduzierte Accounts + renummerierter `param`); und `Initialize`, `PreInitialize`, `MonitorStep`, `MigrateToOpenBook`, `WithdrawSrm`, `SimulateInfo`, `AdminCancelOrders` sind nicht mehr aufrufbar. On-Chain Account Layouts und Error Codes bleiben stabil; migrieren Sie Swaps zu den V2 Entrypoints.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

<Update label="2026-06-22" description="Stable AMM: Toten OpenBook (Market) Code entfernen">
  Stable AMM entfernt seine lange inaktiven OpenBook Market-Making Accounts und Code. Kleinere `SwapBaseIn` / `SwapBaseOut` (18 → 9), `Deposit` (14 → 12) und `Withdraw` (21/22 → 12) Layouts (alte Layouts noch kompatibel); eine **hart brechende** `WithdrawPnl` Änderung (16 → 10, keine Kompatibilität); die Referral Fee ist veraltet; und eine vereinfachte Vault-only Pool-Asset-Formel. Die meisten anderen Stable Instruktionen sind nicht mehr aufrufbar.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>

<Update label="2026-05-18" description="CLMM: Limit Orders, Single-Sided Fee, Dynamic Fee">
  Drei Opt-in, rückwärtskompatible CLMM-Funktionen: First-Class Limit Orders (mit einem `limit_order_admin` Settle Keeper), Single-Sided Fee Collection (`CollectFeeOn`) und eine Volatilitäts-Tracking Dynamic Fee. Fügt `CreateCustomizablePool`, eine `PoolState` Umgestaltung (**Indexer Breaking Change**), neue `TickState` Felder, elf neue Error Codes (mit numerischer Verschiebung) und entsprechende SDK / API Ergänzungen hinzu.

  [Vollständigen Eintrag lesen →](/de/reference/changelog/2026-05-18-clmm-limit-orders)
</Update>

## Dokumentationskonventionen

- **Versionierung**: Diese Dokumentation verwendet kalenderbasierte Versionierung (YYYY-MM-DD). Jede Aktualisierung fügt eine neue Eintrag-Seite und eine neue Zeile oben in der Zeitleiste hinzu.
- **Eine Seite pro Version**: Jede Versions-Zusammenfassung befindet sich auf ihrer eigenen Seite unter `reference/changelog/`, sodass dieser Index kurz bleibt und jeder Eintrag unabhängig verlinkt werden kann.
- **Verifizierungsdatum**: Jeder Eintrag dokumentiert, wann der Inhalt zuletzt gegen On-Chain / API Status und die Programmquelle überprüft wurde. Falls nicht angegeben, gehen Sie vom Hauptdatum des Eintrags aus.
- **Breaking Changes**: Werden in einer Warnbox auf betroffenen Seiten hervorgehoben und im Eintrag gekennzeichnet.
- **Abdeckung**: Dieses Changelog behandelt die Dokumentation selbst. Die historische Zeitleiste des Protokolls selbst befindet sich in [`introduction/history-and-milestones`](/de/introduction/history-and-milestones) und ist die Quelle der Wahrheit für „wann ist X auf Raydium passiert".
