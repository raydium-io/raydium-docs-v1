## Wie Anchor-Fehlercodes funktionieren

Anchor weist jeder Variante eines Programms `ErrorCode`-Enum einen numerischen Code ab `6000` zu. Eine fehlgeschlagene Transaktion zeigt:

- **Numerischer Fehlercode** (z. B. `0x1771` = 6001) in den Transaktionsprotokollen.
- **Fehlername** (z. B. `InvalidOwner`) aus dem IDL.
- **`#[msg(...)]`-String**, den Anchor in `log_messages` ausgegeben hat.

Integratoren sollten auf dem **numerischen Code** abgleichen, nicht auf der Nachrichtenzeichenkette (die Zeichenkette kann umformuliert werden, ohne eine Version zu erhöhen).

```ts
// Beispiel: Erkennen Sie den CPMM-Slippage-Fehler und zeigen Sie eine saubere UX-Nachricht an.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

## SDK-Fehler zu Programmfehlern zuordnen

Das offizielle TypeScript SDK umhüllt On-Chain-Fehler in `SendTransactionError` und für Anchor-Programme in `AnchorError`:

```ts
import { AnchorError } from "@coral-xyz/anchor";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

Wenn Sie Anchor nicht auf der Client-Seite verwenden, analysieren Sie die Transaktionsprotokolle:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

Das Muster `Error Number: (\d+)` ist über Anchor-Versionen hinweg stabil und sicher zum Abgleichen.

## Diese Tabellen regenerieren

Wenn ein Programm aktualisiert wird und einen neuen Fehler hinzufügt, extrahieren Sie erneut aus der Quelle:

```bash
# Clone and grep the error enum in order.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Replace 6000+++ with monotonically-increasing 6000,6001,... Append new rows to the table above.
```

Aktualisieren Sie immer [`reference/changelog`](/de/reference/changelog), wenn eine neue Variante hinzugefügt wird, damit Integratoren, die das SDK aktualisieren, wissen, dass sie ihre Fehlerbehandler aktualisieren müssen.
