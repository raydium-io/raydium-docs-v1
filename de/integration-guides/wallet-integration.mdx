## Raydium-Positionen erkennen

### Klassische LP-Token (CPMM, AMM v4)

Diese sehen wie jeder andere SPL-Token aus: Das ATA des Benutzers hält einen Saldo. Eine Wallet zeigt dies standardmäßig einfach als einen weiteren Token an. Um es als Raydium-LP-Position zu offenbaren:

1. Zählen Sie die Token-Konten des Benutzers auf: `connection.getParsedTokenAccountsByOwner(user, { programId: TOKEN_PROGRAM_ID })`.
2. Überprüfen Sie für jede Mint die Raydium-Mint-Liste: `GET https://api-v3.raydium.io/pools/info/lps?lps=<LP_MINT>,...` (bis zu ~50 LP-Mints pro Aufruf zusammenfassen).
3. Für Mints, die übereinstimmen, gibt die API die Pool-Referenz zurück. Verwenden Sie sie, um den Token-denominierten Wert der Position zu berechnen:

```
token_a_owned = user_lp_balance * poolReserves.A / lpMint.supply
token_b_owned = user_lp_balance * poolReserves.B / lpMint.supply
usd_value     = token_a_owned * priceA_usd + token_b_owned * priceB_usd
```

Zeigen Sie sowohl den LP-Saldo als auch die unwrapped-Beträge an — Benutzer denken in zugrunde liegenden Token, nicht in LP-Einheiten.

### CLMM-Positions-NFTs

CLMM-Positionen sind NFTs. Die `PersonalPositionState` PDA jeder Position wird von der NFT-Mint abgeleitet. Zur Erkennung:

1. Zählen Sie die NFTs des Benutzers auf. Für Legacy-Metaplex-NFTs: Filtern Sie Token-Konten auf solche mit Supply 1 und Dezimalstellen 0.
2. Versuchen Sie für jede NFT-Mint, die PersonalPositionState PDA abzuleiten:

```ts
import { CLMM_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";

const [positionPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("position"), nftMint.toBuffer()],
  CLMM_PROGRAM_ID,
);

const accountInfo = await connection.getAccountInfo(positionPda);
if (!accountInfo || !accountInfo.owner.equals(CLMM_PROGRAM_ID)) return null;
// Es ist eine Raydium-CLMM-Position — dekodieren.
```

3. Zählen Sie die Positionen der Wallet mit `raydium.clmm.getOwnerPositionInfo({ programId })` auf und gleichen Sie `nftMint` ab (es gibt kein `getPositionInfo`). Jeder Eintrag gibt Ihnen:
   - `poolId` → Pool abrufen, um Mints aufzulösen
   - `tickLower`, `tickUpper` → Bereich anzeigen
   - `liquidity`, `tokensOwedA/B` → Positionswert + ausstehende Gebühren berechnen
   - `rewardInfos` → ausstehende Rewards pro Stream

4. Für Positions-NFTs, die unter Token-2022 ausgegeben wurden (`OpenPositionWithToken22Nft`), ist das Programm der NFT-Mint Token-2022 statt SPL Token. Zählen Sie beide auf, wenn Sie scannen.

### Farm-Stakes

Farm v3 / v5 / v6 haben jeweils eine Pro-Benutzer-Ledger-PDA. Ableitungen:

```ts
// Versuchen Sie alle drei Farm-Versionen für jede mögliche Farm-Interaktion des Benutzers.
// Günstigster Ansatz: Fragen Sie zuerst die API, die alle Benutzerpositionen indexiert hat.

const r = await fetch(
  `https://api-v3.raydium.io/positions/staking?wallet=${user.toBase58()}`
).then(r => r.json());

for (const s of r.data.stakings) {
  // s.farmId, s.stakedAmount, s.pendingRewards[], s.poolApr, ...
}
```

Für Wallets, die vollständige On-Chain-Erkennung bevorzugen: Iterieren Sie mögliche `UserLedger` PDAs, indem Sie den Benutzer mit einer kuratierten Liste „wahrscheinlicher" Farm-IDs hashen. Das vollständige Aufzählen aller Farm-IDs ist unpraktisch (es existieren Tausende); verwenden Sie die API.

## Positionswert berechnen

### CPMM / AMM v4 LP

Die drei Module teilen **keine** Signatur: `liquidity.getPoolInfoFromRpc` nimmt `{ poolId }`, während `cpmm.getPoolInfoFromRpc` und `clmm.getPoolInfoFromRpc` einen positionalen Base58-String nehmen.

```ts
// AMM v4
const { poolInfo, poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
// CPMM
// const { poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

// `poolInfo.lpMint` ist ein ApiV3Token und hat kein `supply`-Feld. Lesen Sie die
// Supply der LP-Mint von der Chain, oder verwenden Sie den eigenen Spiegel des Pools:
const lpSupply = BigInt(poolRpcData.lpAmount.toString());

const tokensA = BigInt(poolInfo.mintAmountA) * BigInt(userLpBalance) / lpSupply;
const tokensB = BigInt(poolInfo.mintAmountB) * BigInt(userLpBalance) / lpSupply;
```

Multiplizieren Sie dann jeden mit dem USD-Preis der Mint (von `raydium.token` oder einem Price-Oracle).

### CLMM-Position

```ts
const pool      = await raydium.clmm.getPoolInfoFromRpc(POOL_ID);   // base58 string
const positions = await raydium.clmm.getOwnerPositionInfo({
  programId: pool.poolInfo.programId,
});
const position  = positions.find((p) => p.poolId.toBase58() === pool.poolInfo.id)!;

// getAmountsFromLiquidity ist async, nimmt epochInfo + poolInfo + add,
// und gibt gebührenumhüllte Beträge zurück.
const { amountA, amountB } = await PoolUtils.getAmountsFromLiquidity({
  epochInfo:  await raydium.fetchEpochInfo(),
  poolInfo:   pool.poolInfo,
  tickLower:  position.tickLower,
  tickUpper:  position.tickUpper,
  liquidity:  position.liquidity,
  slippage:   0,      // für Anzeige, kein Slippage
  add:        false,
});
// amountA.amount / amountB.amount sind die BNs; .fee ist die Token-2022-Transfergebühr.

// Ausstehende Gebühren — separat als „nicht eingezogen" anzeigen
const fees = {
  A: position.tokenFeesOwedA,
  B: position.tokenFeesOwedB,
};

// Ausstehende Rewards — ein CLMM-Pool hat 0–3 Reward-Streams. Die rewardInfos-Einträge
// der Position sind nur { growthInsideLastX64, rewardAmountOwed }, daher muss die
// Mint aus den rewardInfos des POOLS beim gleichen Index kommen.
const rewards = position.rewardInfos.map((r, i) => ({
  mint:         pool.poolInfo.rewardDefaultInfos[i]?.mint,
  rewardAmount: r.rewardAmountOwed,
}));
```

Rendern Sie als:

- Liquiditätswert (aktueller Preis)
- Nicht eingezogene Gebühren
- Ausstehende Rewards pro Stream
- Bereich: `[tickLower_price, tickUpper_price]` mit einem visuellen Balken, der zeigt, ob der aktuelle Preis im Bereich liegt

### Farm-Stake

```ts
// Die API-Antwort enthält bereits ausstehende Rewards; verwenden Sie sie direkt.
const apr       = stakingFarm.apr;               // %, annualisiert
const staked    = stakingFarm.stakedAmount;      // kleinste Einheiten der Staking-Mint
const rewards   = stakingFarm.pendingRewards;    // Array von { mint, amount }
```

Für On-Chain-Berechnung spiegeln Sie die Farm-Buchhaltung:

```
pending_reward_i = user.deposited
                 * farm.reward_per_share_x64[i] / 2^64
                 - user.reward_debts[i]
```

Stellen Sie sicher, dass Sie `reward_per_share_x64` mit der Lazy-Update-Formel aktualisieren, bevor Sie berechnen (verstrichene Zeit × Emissionsrate ÷ total_staked).

## Transaktionssimulation für Vorschau

Bevor ein Benutzer signiert, zeigen Wallets normalerweise die Saldoänderungen in der Vorschau an. Verwenden Sie `simulateTransaction`:

```ts
const sim = await connection.simulateTransaction(tx, {
  sigVerify: false,
  commitment: "confirmed",
  accounts: {
    encoding: "base64",
    addresses: [userTokenAtaA, userTokenAtaB, userLpAta].map(a => a.toBase58()),
  },
});

// Dekodieren Sie den Saldo jedes zurückgegebenen Kontos und vergleichen Sie mit Pre-Tx-Salden.
for (const [i, acctData] of sim.value.accounts!.entries()) {
  const newBalance = decodeTokenAccount(acctData!.data[0]).amount;
  // mit Pre-Tx-Saldo vergleichen, Δ anzeigen
}
```

Der Parameter `accounts` fordert den Validator auf, den Post-Simulations-Kontostatus für aufgelistete Adressen zurückzugeben. Viel genauer als der Versuch, die Saldoänderung allein aus der Anweisungsform vorherzusagen.

### Simulations-Fallstricke

- **CLMM-Swaps benötigen gültige Tick-Arrays.** Wenn die Eingabegröße des Benutzers in ein nicht initialisiertes Tick-Array eindringen würde, wird die Simulation zurückgerollt (wie die Ausführung). Machen Sie dies deutlich in der UI.
- **Priority Fee.** Die Simulation läuft ohne die angewendeten Compute-Budget-Anweisungen. Für eine große Transaktion, die das Standard-200k CU überschreiten würde, schlägt die Simulation fehl, aber die tatsächliche Ausführung mit einem expliziten CU-Limit gelingt. Setzen Sie das CU-Limit auch auf der simulierten Tx.
- **Frischer Blockhash.** Die Simulation verwendet den aktuellen Blockhash; wenn das Signieren >60s dauert, wird die Tx ungültig. Simulieren Sie erneut, wenn der Benutzer zögert.

## Token-2022-Anzeige

Token unter dem Token-2022-Programm sollten in der Token-Liste der Wallet als solche gekennzeichnet werden, da sie unterschiedliche Risikoflächen haben:

- **Transfer-Fee-Mints**: Zeigen Sie die aktuellen `transferFeeBasisPoints` als „Transfer-Gebühr: X%" neben dem Saldo an. Warnen Sie beim Empfangen — Benutzer könnten nicht realisieren, dass sie weniger erhalten als der Absender gesendet hat.
- **Transfer-Hook-Mints**: Zeigen Sie die Hook-Programm-ID. Ein böswilliger Hook kann ausgehende Transfers blockieren; Benutzer sollten überprüfen, dass der Hook der erwartete ist.
- **Nicht übertragbare Mints**: Zeigen Sie „Nicht übertragbar" an und deaktivieren Sie Swap/Senden. Dies sind typischerweise Soulbound-Token oder Anmeldedaten.
- **Zinsgestaffelte Mints**: Der UI-Saldo, der von `TokenAccount.amount` abgeleitet ist, spiegelt **nicht** aufgelaufene Zinsen wider. Verwenden Sie `amountToUiAmount` von `@solana/spl-token` (das den Skalierungsfaktor anwendet) für den angezeigten Wert.

## Farm-APR-Anzeige

Der APR, der Benutzern angezeigt wird, sollte alle Live-Reward-Streams kombinieren, in USD umgerechnet und annualisiert:

```ts
let apr = 0;
for (const r of farm.rewardInfos) {
  if (r.rewardState !== 1) continue;   // nicht laufende überspringen
  const annualRewardTokens = Number(r.emissionPerSecond) * 86400 * 365 / 1e<decimals>;
  const annualRewardValue  = annualRewardTokens * priceUsd(r.rewardMint);
  const tvlValue           = Number(farm.totalStaked) * priceUsd(farm.stakingMint) / 1e<decimals>;
  apr += annualRewardValue / tvlValue;
}
```

Zeigen Sie als `APR: X.Y%` an. Wenn die Staking-Mint ein LP-Token ist, berechnen Sie auch den Basis-Gebühren-APR des zugrunde liegenden LP und kennzeichnen Sie die Summe als „Gesamt-APR" oder „APR + Gebühren".
