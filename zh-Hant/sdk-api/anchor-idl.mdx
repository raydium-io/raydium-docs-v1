## IDL 是什麼

Solana 上的 Anchor 程式會發佈 **IDL**（介面定義語言）檔案，描述其指令、帳戶配置、錯誤列舉和結構綱要。IDL 是客戶端程式碼產生的真實來源——TS SDK、Rust CPI crate 和第三方客戶端都是從它產生（或針對它手寫）的。

Raydium 為 CPMM、CLMM 和 LaunchLab 發佈 IDL。AMM v4、Stable AMM 和 Farm（v3 / v5 / v6）早於 Anchor 或以其他方式不是 Anchor 發佈的——它們的帳戶結構在 SDK 中手動維護。

## 在哪裡找到它們

IDL 位於專用儲存庫中：

```
https://github.com/raydium-io/raydium-idl
```

確切的檔案：

| 程式 | IDL 檔案 |
|---------|----------|
| CPMM | [`raydium_cpmm/raydium_cp_swap.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_cpmm/raydium_cp_swap.json) |
| CLMM | [`raydium_clmm/raydium_clmm.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_clmm/raydium_clmm.json) |
| LaunchLab | [`raydium_launchpad/raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json) |
| AMM v4 | 無官方 IDL——參見 [`raydium-sdk-V2/src/raydium/liquidity/layout.ts`](https://github.com/raydium-io/raydium-sdk-V2/blob/master/src/raydium/liquidity/layout.ts) 以取得手寫配置 |
| Stable AMM | 無官方 IDL——配置在 SDK 中 |
| Farm | 無官方 IDL——配置在 SDK 中 |

IDL 檔案在儲存庫的 git 歷史中進行版本控制；如果需要位元組對位元組的可重現性，請固定到特定提交。

IDL 也可以透過 Anchor 的**鏈上 IDL** 功能直接從已部署的程式中提取（如果程式發佈者選擇加入）：

```bash
anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet
```

CPMM、CLMM 和 LaunchLab 都有鏈上 IDL。AMM v4、Stable AMM 和 Farm 沒有（前 Anchor 程式）。

## 重新產生 TypeScript 客戶端

Anchor 的程式碼產生器從 IDL 產生類型化客戶端：

```bash
# 使用 anchor CLI
anchor build
anchor idl parse \
  --file target/idl/cpmm.json \
  --out target/types/cpmm.ts

# 或使用 `@anchor-lang/core` TS 幫助程式在執行時：
```

```ts
import { Program, AnchorProvider } from "@anchor-lang/core";
// 直接從 raydium-idl 儲存庫提取 IDL（或將其供應到你的專案中）。
import cpmmIdl from "./idls/raydium_cp_swap.json";

const provider = new AnchorProvider(connection, wallet, {});
const program  = new Program(cpmmIdl as any, CPMM_PROGRAM_ID, provider);

// 自動產生的類型化方法建構器：
await program.methods
  .swapBaseInput(new BN(amountIn), new BN(minAmountOut))
  .accounts({ ... })
  .rpc();
```

大多數整合者**不**這樣做——他們使用更高層級的 `raydium.cpmm.swap(...)` 幫助程式，它包裝了 Anchor 方法加上所有簿記（ATA 建立、轉帳費用調整、計算預算、Token-2022 程式路由）。只有在需要 SDK 下方的層時才重新產生。

## 重新產生 Rust 客戶端（CPI crate）

Raydium 為具有 IDL 的程式發佈 Anchor crate：

```toml
# Cargo.toml
[dependencies]
raydium_cp_swap = { git = "https://github.com/raydium-io/raydium-cp-swap", branch = "master", features = ["cpi"] }
raydium_amm_v3 = { git = "https://github.com/raydium-io/raydium-clmm",    branch = "master", features = ["cpi"] }
```

`cpi` 功能公開 `cpi::accounts::<Ix>` 帳戶結構和 `cpi::<ix>()` 呼叫器——現成的 CPI 包裝器。參見 [`sdk-api/rust-cpi`](/zh-Hant/sdk-api/rust-cpi) 以取得使用模式。

如果你偏好產生新的繫結：

```bash
# 從 IDL，使用 anchor-client
anchor idl parse \
  --file raydium_cpmm/raydium_cp_swap.json \
  --out src/generated/cpmm_bindings.rs
```

## 重新產生 Python 客戶端

沒有官方的 Raydium Python SDK。第三方產生器包括：

- **`anchorpy`** ——Anchor 的 TypeScript 客戶端的 Python 連接埠。從 IDL 產生類型化方法建構器。
- **`solders`** ——低層級 Solana 原始物件（交易、金鑰對、公鑰）在 Rust 繫結中；在 `anchorpy` 下方使用。

```bash
pip install anchorpy solders solana
```

```python
from anchorpy import Program, Provider
from solana.rpc.async_api import AsyncClient
from pathlib import Path
import json

idl = json.loads(Path("cpmm.json").read_text())
provider = Provider(AsyncClient("https://api.mainnet-beta.solana.com"), wallet)
program  = Program(idl, CPMM_PROGRAM_ID, provider)

await program.rpc["swap_base_input"](amount_in, min_amount_out, ctx=Context(accounts={...}))
```

參見 [`sdk-api/python-integration`](/zh-Hant/sdk-api/python-integration) 以取得更完整的逐步解說。

## IDL 變更政策

Raydium 遵循以下 IDL 穩定性規則：

1. **指令判別器永不改變。** 新增指令會在列舉末尾擴展；現有判別器保持穩定。
2. **帳戶結構配置只能加法演進。** 新欄位放在末尾，前面有鏈上綱要中的大小提升。現有欄位保持其偏移。
3. **錯誤列舉代碼是僅附加的。** 現有錯誤代碼始終意味著相同的事情。
4. **重大變更在新程式中發佈。** 當需要重新設計時，團隊部署新的程式 ID（例如 CPMM 作為新程式而不是升級 AMM v4）。舊池繼續在舊程式上執行；新池進入新程式。

此政策使重新產生的客戶端向後相容：針對兩個版本舊的 IDL 產生的客戶端仍將正確解碼當前狀態（它將額外的尾部位元組視為填充）。

## IDL 變更時該怎麼辦

1. **更新 SDK。** `npm update @raydium-io/raydium-sdk-v2`。
2. **重新產生你的客戶端程式碼**（如果你直接使用 Anchor 程式碼產生）。
3. **比較帳戶配置。** 新配置的尾部欄位是你的程式碼尚未看到的唯一內容；確認你是否需要它們。
4. **不要假設舊指令判別器無效。** 根據規則 1，它們仍然有效。
5. **在推出到主網之前，針對 devnet 重新執行整合測試**。

## IDL 故障排除

### 「無效判別器」錯誤

通常意味著針對 IDL 版本 N 建立的客戶端正在嘗試呼叫僅存在於程式的預部署版本中的指令。重新從實時程式中提取 IDL：

```bash
anchor idl fetch <PROGRAM_ID>
```

### 帳戶解碼失敗

如果 `program.account.<Name>.fetch(pubkey)` 拋出「無效帳戶判別器」，帳戶是由先前的程式版本建立的，Anchor 正在拒絕其 8 位元組判別器。修復方法是使用 SDK 中的原始配置解析器（`PoolInfoLayout.decode(accountData)`），它不強制執行 Anchor 判別器。

### 產生的客戶端中缺少指令

Anchor 的 TS 程式碼產生只為 IDL 項目產生方法，其 `name` 解析為有效識別碼。Raydium 的指令都滿足此條件，但如果你看到不匹配，請檢查 IDL 檔案是否來自當前 SDK 版本。
