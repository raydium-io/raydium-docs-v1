### 共用設定 / PDA 慣例

多個 Raydium 程式公開**設定帳戶**，其公開金鑰是穩定的，並列在公開 API 上。優先使用 API 查詢而不是硬編碼：

```
# CPMM 費用設定（返回 {id, index, tradeFeeRate, ...} 的陣列）
GET https://api-v3.raydium.io/main/cpmm-config

# CLMM 費用設定
GET https://api-v3.raydium.io/main/clmm-config
```

CPMM 的池建立費用接收者是固定帳戶，不是衍生或透過 API 查詢的：`raydium-cp-swap` 的 `lib.rs` 中的 `create_pool_fee_reveiver::ID`，目前為 `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`。CPMM 的 `initialize` 指令透過精確位址驗證它，所以它必須已經存在於你測試的任何叢集上。

預設 CPMM `AmmConfig` 索引 `0`（標準 0.25% 池）費用參數，供參考：

| 欄位 | 值 | 含義 |
|-------|-------|---------|
| `trade_fee_rate` | `2500` | 交易量的 0.25% |
| `protocol_fee_rate` | `120000` | 交易費的 12%（不是交易量）路由到協議 |
| `fund_fee_rate` | `40000` | 交易費的 4% 路由到基金多簽 |
| `creator_fee_rate` | `500` | 交易量的 0.05% 給池建立者（可選） |

見 [`products/cpmm/fees`](/zh-Hant/products/cpmm/fees) 了解分割如何組成，以及 [`reference/fee-comparison`](/zh-Hant/reference/fee-comparison) 了解跨產品矩陣。

### PDA 種子

下面的種子是**規範的**，由 SDK 和鏈上 CPI 都使用。始終計算 PDA；不要硬編碼衍生位址。

```ts
// CPMM — 所有種子都是靜態 ASCII 字串，除非另有說明。
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` 在雜湊前**按公開金鑰位元組順序排序**（token0 < token1）。搞錯這個會產生一個有效的 PDA，但對應不存在的池。

等效的 CLMM 種子遵循相同的風格；見 [`products/clmm/accounts`](/zh-Hant/products/clmm/accounts)。

## 如何在鏈上驗證位址

1. **Solana Explorer。** 將位址貼到 [explorer.solana.com](https://explorer.solana.com) 並確認它標記為 `Program` 且有當前升級授權。Mainnet-beta 應顯示由 Raydium 升級授權簽署的部署。
2. **CLI。** 使用 `solana program show <PROGRAM_ID> -u mainnet-beta` 檢查部署槽、BPF 載入器、升級授權和資料長度。在你的執行手冊中記錄這些。
3. **IDL 附件。** 使用 `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` 查詢鏈上 IDL。IDL 的 `address` 欄位應該匹配。相同的 IDL 也鏡像在 [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) — 在信任鏈上 IDL 前，將其與儲存庫進行比較。
4. **設定/管理員授權。** 對於 CPMM/CLMM 設定帳戶，讀取 `owner`/`protocol_owner` 欄位並確認它與 [`security/admin-and-multisig`](/zh-Hant/security/admin-and-multisig) 中發佈的當前 Raydium 多簽相符。

如果上面的四項檢查中的任何一項與本頁不符，將本頁視為錯誤，在針對位址編寫新程式碼前開啟一個議題。
