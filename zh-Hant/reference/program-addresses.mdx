### 共用管理員授權

每個 Raydium 程式（包括 AMM v4）都共用一個硬編碼的管理員 `Pubkey`，用於指令級別的管理路徑存取控制。在 AMM v4 中是 `config_feature::amm_owner::ID`（限制 `SetParams`、`CreateConfigAccount` 和 `UpdateConfigAccount`，並用作預設 `pnl_owner`），在 Anchor 程式（CLMM、CPMM、LaunchLab、Lock）中是 `admin::ID` — 限制 `CreateAmmConfig` 或 `UpdatePoolStatus` 等路徑：

| devnet | `DRayqG9RXYi8WHgWEmRQGrUWRWbhjYWYkCRJDd6JBBak` |

### PDA 種子

下面的種子是**規範的**，由 SDK 和鏈上 CPI 都使用。始終計算 PDA；不要硬編碼衍生位址。

```ts
// CPMM — 所有種子都是靜態 ASCII 字串，除非另有說明。
const [ammConfig]   = PublicKey.findProgramAddressSync(
  [Buffer.from("amm_config"), u16ToBytes(index)],
  CPMM_PROGRAM_ID,
);
const [authority]   = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_and_lp_mint_auth_seed")],
  CPMM_PROGRAM_ID,
);
const [poolState]   = PublicKey.findProgramAddressSync(
  [Buffer.from("pool"), ammConfig.toBuffer(), token0Mint.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [lpMint]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault0]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [vault1]      = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
  CPMM_PROGRAM_ID,
);
const [observation] = PublicKey.findProgramAddressSync(
  [Buffer.from("observation"), poolState.toBuffer()],
  CPMM_PROGRAM_ID,
);
```

`token0Mint` / `token1Mint` 在雜湊前**按公鑰位元組順序排序**（token0 < token1）。搞錯這個會為不存在的池產生有效的 PDA。

等效的 CLMM 種子遵循相同的風格；見 [`products/clmm/accounts`](/zh-Hant/products/clmm/accounts)。

## 如何在鏈上驗證位址

1. **Solana Explorer。** 將位址貼到 [explorer.solana.com](https://explorer.solana.com) 並確認它標記為 `Program` 且有目前的升級授權。Mainnet-beta 應顯示由 Raydium 升級授權簽署的部署。
2. **CLI。** 使用 `solana program show <PROGRAM_ID> -u mainnet-beta` 檢查部署槽、BPF 載入器、升級授權和資料長度。在你的執行手冊中記錄這些。
3. **IDL 附件。** `anchor idl fetch <PROGRAM_ID> --provider.cluster mainnet` 適用於 **CLMM、LaunchLab 和 Lock**，它們仍保留由程式本身擁有的舊版 `anchor:idl` 帳戶。它**不**適用於 CPMM：CPMM 的鏈上 IDL 在 2026-09 升級中移至程式元資料程式（`ProgM6JCCvbYkfKqJYHePx4xxSUSqJp7rh8Lyv7nk7S`），所以改為從那裡取得。AMM v4、Stable AMM 和 Farm 沒有鏈上 IDL。IDL 在 [github.com/raydium-io/raydium-idl](https://github.com/raydium-io/raydium-idl) 鏡像 — 在信任前針對儲存庫比較鏈上 IDL。
4. **設定/管理員授權。** 對於 CPMM/CLMM 設定帳戶，讀取 `owner`/`protocol_owner` 欄位並確認它與 [`security/admin-and-multisig`](/zh-Hant/security/admin-and-multisig) 中發佈的目前 Raydium 多簽相符。

如果上面的四項檢查中的任何一項與本頁不符，將本頁視為錯誤，在針對位址編寫新程式碼前開啟問題。
