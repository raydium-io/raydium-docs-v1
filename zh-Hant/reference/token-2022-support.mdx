## 程式層級支援

| 程式 | Token-2022 基礎/報價 mint？ | 模式 |
|---|---|---|
| **CPMM** | 是 — 受限 | 嚴格擴充功能允許清單 + 4 個 mint 靜態白名單。 |
| **CLMM** | 是 — 受限 | 嚴格擴充功能允許清單 + 6 個 mint 靜態白名單 + 管理員個別 mint 登記表 + Superstate 偵測。 |
| **AMM v4** | 否 | 程式早於 Token-2022；兩個 mint 都必須是經典 SPL Token。 |
| **Stable AMM** | 否 | 與 AMM v4 相同的限制。 |
| **Farm v6** | 是，部分 | 獎勵 mint 可以是 Token-2022（受限於相同的允許清單，當農場包裝 CPMM/CLMM LP 時）；使用者質押 LP mint 繼承自包裝的流動性池。 |
| **LaunchLab** | 是 — 基礎程式管理，報價不受限 | 基礎 mint 可以是 Token-2022，但只能透過專用的 `initialize_with_token_2022` 指令；程式本身使用 `MetadataPointer`（總是）和可選的 `TransferFeeConfig`（費率 ≤ 5%）建立 mint。具有任意擴充功能的預先存在 Token-2022 mint 無法用作基礎。**報價** mint 可以是管理員綁定到 `GlobalConfig` 的任何 Token-2022 mint，沒有擴充功能檢查 — 見[下方](#launchlab-報價-mint)。 |
| **Burn & Earn** | 鏡像流動性池程式 | 繼承 CPMM / CLMM 限制。 |

允許清單檢查位於：

- **CPMM**：`is_supported_mint` 在 [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap)，從 `Initialize` 呼叫。
- **CLMM**：`is_supported_mint` 在 [`raydium-clmm/programs/amm/src/util/token.rs:280`](https://github.com/raydium-io/raydium-clmm)，從 `CreatePool` 呼叫。
- **LaunchLab**：`initialize_with_token_2022` 在 `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs`（原始碼未公開）。

CPMM 或 CLMM 上**沒有**交換時間 mint 檢查 — 限制只在流動性池建立時觸發。一旦流動性池存在，交換只信任 mint 沒有改變，這對 Token-2022 mint 狀態的不可變部分是正確的。

## CLMM 位置 NFT 凍結受限發行者

位置 NFT 帳戶預設保持未凍結。CLMM 只在位置使用 V2 開放路徑**且**至少一個金庫 mint 的目前 `freeze_authority` 符合硬編碼受限發行者清單時才凍結一個。初始清單包含 Superstate 偵測路徑下方使用的相同授權。將流動性池 PDA 設定為位置 NFT mint 的凍結授權本身不是凍結。這是位置保管規則，不是另一個流動性池建立允許清單：

- 流動性池已經可以存在並保持可交換。
- 位置 NFT mint 使用 CLMM 流動性池 PDA 作為其自己的凍結授權；基礎發行者不控制位置 NFT。
- `OpenPositionV2` 涵蓋經典 SPL 位置 NFT 超過 Token-2022 流動性池資產。`OpenPositionWithToken22Nft` 涵蓋 Token-2022 位置 NFT。
- `OpenPosition` V1 不檢查金庫 mint，無法服務由已發送清單針對的 Token-2022 受限資產。
- 現有位置保持不變。

凍結的位置仍可由其所有者管理，但無法轉移。`ClosePosition` 在客戶端將流動性池作為第一個剩餘帳戶傳遞時自動解凍和燒毀。見 [`products/clmm/ticks-and-positions`](/zh-Hant/products/clmm/ticks-and-positions#受限發行者位置)。

## LaunchLab 報價 mint

LaunchLab 的兩個 mint 受限方式非常不同，不對稱性很容易被忽視。

- **基礎 mint** — LaunchLab 建立它。Token-2022 基礎 mint 只能透過 `initialize_with_token_2022` 到達，程式只會附加 `MetadataPointer` 和（可選）`TransferFeeConfig`。任何其他都返回 `NoSupportExtension`。預先存在的 Token-2022 mint 根本無法作為基礎提供。
- **報價 mint** — LaunchLab 不建立它也不篩選它。`CreateConfig` 接受給定的 mint 帳戶，所以**報價端沒有 `is_supported_mint` 等效項**。唯一的限制是管理員選擇綁定到 `GlobalConfig` 的 mint。

這使得綁定 Token-2022 報價 mint 成為高信任行動，理由與下方 CPMM 和 CLMM 靜態白名單相同：`TransferHook` 報價 mint 會在每次買入、賣出和費用索取時在每個以它報價的流動性池中執行其鉤子，而 `PermanentDelegate` 報價 mint 會讓委託人掃過這些流動性池的報價金庫。兩者都不被程式阻止。

LaunchLab 一旦報價 mint 被綁定就正確處理的：

- 報價金庫、兩個費用金庫和分享費用接收者的代幣帳戶都在報價 mint 自己的程式上建立。
- 報價端的 `TransferFeeConfig` 被計入所有四個交易指令中，滑點界限針對支付者的淨額而不是金庫的總移動進行檢查。見 [`products/launchlab/instructions`](/zh-Hant/products/launchlab/instructions#報價端轉帳費用)。
- `PoolState.token_program_flag` 記錄兩個 mint 的程式 — bit0 用於基礎 mint，bit1 用於報價 mint。按位解碼；位元組不是布林值。見 [`products/launchlab/accounts`](/zh-Hant/products/launchlab/accounts#poolstate)。

已棄用的 `Initialize` 指令仍然採用僅限舊版的報價程式，所以具有 Token-2022 報價 mint 的設定只能透過 `InitializeV2` 和 `InitializeWithToken2022` 到達。

## CPMM 和 CLMM 擴充功能允許清單

在靜態白名單短路（下方涵蓋）之後，程式迭代 mint 的擴充功能，如果它攜帶**任何**除了這五個以外的擴充功能，則拒絕 mint：

| 擴充功能 | 允許的原因 |
|---|---|
| `TransferFeeConfig` | 流動性池數學減去入站費用；Token-2022 程式處理出站費用。見 [`algorithms/token-2022-transfer-fees`](/zh-Hant/algorithms/token-2022-transfer-fees)。 |
| `MetadataPointer` | 裝飾性 — 指向鏈上中繼資料。 |
| `TokenMetadata` | 裝飾性 — 內聯中繼資料。 |
| `InterestBearingConfig` | 流動性池看到本金；UI 乘數僅是裝飾，基礎餘額被保留。 |
| `ScaledUiAmount` | 與計息相同的形狀 — 縮放因子僅適用於 UI 顯示。 |

不在此清單中的任何內容 — `TransferHook`、`NonTransferable`、`ConfidentialTransferMint`、`PermanentDelegate`、`MintCloseAuthority`、`DefaultAccountState`、`GroupPointer`、`GroupMemberPointer`、`MemberPointer`、`Pausable` 等 — 導致 `is_supported_mint` 返回 `false` 並且流動性池建立還原。

相關行（CPMM，CLMM 中形狀相同）：

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## 繞過路徑

不符合允許清單的 Token-2022 mint 仍然可以透過三個明確繞過之一被允許。它們按順序嘗試，在擴充功能迭代執行之前。

### 1. 靜態 mint 白名單

常數 `MINT_WHITELIST` 陣列的 base58 字串在每個程式中硬編碼。如果 mint 的位址符合，函式立即返回 `true`，不執行擴充功能檢查。

| 程式 | 白名單 mint |
|---|---|
| CPMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`、`Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`、`FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`、`2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM | 相同的四個，加上 `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`、`AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

這些位址被烤入程式中；更新清單需要透過 3/4 升級多簽進行程式升級。

### 2. 個別 mint 登記表 — 僅 CLMM

CLMM 另外查詢種子為 `[b"support_mint", mint]` 的 `SupportMintAssociated` PDA。如果該 PDA 對 mint 存在，無論其擴充功能集如何，它都被允許。

PDA 由 `CreateSupportMintAssociated` 建立（[`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)）。指令受限於兩個簽署者：

- `crate::admin::ID` — 標準 Raydium 管理員授權。
- `crate::create_support_mint_associated_owner::ID` — 為此目的的專用授權：`RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY`（主網）、`rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5`（開發網）。

效果：CLMM 團隊可以選擇特定的 Token-2022 mint 進行流動性池建立，無需程式升級。CPMM 沒有等效項 — 其允許清單嚴格來自原始碼。

### 3. Superstate 偵測 — 僅 CLMM

CLMM 有第三條路徑專門用於 Superstate 的代幣化資產，它們使用 `ScaledUiConfig` 擴充功能，連結到 CLMM 程式的 `spl-token-2022` 版本無法解包。CLMM 不是升級依賴項，而是透過其授權形狀偵測 Superstate 代幣：

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

如果**全部四個**成立，mint 通過此分支：

- 其擁有程式是 Token-2022 程式。
- 其凍結授權等於 `superstate_allowlist::ID`。見 [`reference/program-addresses`](/zh-Hant/reference/program-addresses#clmm-受限發行者凍結授權) 以取得主網測試版和開發網值。
- 其 `DefaultAccountState` 擴充功能設定為 `Frozen`。
- 其永久委託也是 `superstate_allowlist::ID`。

這是啟發式，不是登記表 — Superstate 發行的任何具有相同授權形狀的未來 mint 將自動被允許。

## 繞過不豁免的內容

繞過跳過擴充功能允許清單，但程式仍然強制執行：

- mint 由 `Token` 或 `Token-2022` 擁有。自訂代幣程式在上游被拒絕。
- 流動性池金庫使用 Token-2022 流動性池的正確 ATA 擴充功能建立（`ImmutableOwner` 等）。
- 所有轉帳都透過 `transfer_checked` — 費用承載 mint 在金庫中登陸正確金額。

白名單或 PDA 登記的 mint 稍後添加 `TransferHook` 不會獲得交換時間檢查；鉤子會在每次轉帳時簡單執行，可能會中斷交換。因此白名單是高信任行動。

## 「被阻止」語義

當 `is_supported_mint` 返回 `false` 時，流動性池建立還原為 `ErrorCode::NotSupportMint`（CPMM）/ `ErrorCode::NotSupportMint`（CLMM）。見 [`reference/error-codes`](/zh-Hant/reference/error-codes) 以取得數字代碼。

現有流動性池無法追溯性地失敗此檢查 — 限制只在建立時執行。Mint 擴充功能對於 Raydium 拒絕的類別是不可變的（轉帳鉤子、不可轉帳、機密轉帳無法在建立後添加），所以靜態檢查是充分的。

## 為什麼排除每個擴充功能

- **TransferHook** — 在每次轉帳時呼叫自訂程式，具有任意 CU 消耗、任意失敗條件和重新進入呼叫程式的能力。不存在安全沙箱。某些 DEX 維護鉤子允許清單；Raydium 不維護。
- **NonTransferable** — `Transfer` 總是失敗。流動性池無法取得保管。
- **ConfidentialTransfer** — 轉帳金額被加密；曲線無法為交換定價。
- **PermanentDelegate** — 委託人的持有者可以掃過任何代幣帳戶，包括流動性池金庫。僅透過受信任發行者的靜態白名單允許（例如，受監管的穩定幣）。
- **MintCloseAuthority** — mint 可以關閉；現有流動性池變得無法使用。預設不允許。
- **DefaultAccountState (Frozen)** — 流動性池 ATA 會登陸 `Frozen` 狀態並需要按帳戶解凍。僅透過 Superstate 偵測允許，假設發行者在註冊時解凍機構帳戶。
- **Group/Member 指標** — 不是主動有害，但未審查。預設不允許以保持表面狹窄。

## 轉帳費用會計

對於攜帶 `TransferFeeConfig` 的 mint，每次交換、存款和提款移動少於名義金額。SDK 表面計算的兩個部分：

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

正確的 UI 顯示：

- `amountIn + token2022FeeIn` 作為「你發送」
- `amountOut - token2022FeeOut` 作為「你接收」
- `feeAmount` 作為流動性池費用（LP + 協議），與 Token-2022 轉帳費用分開

只顯示 `amountIn → amountOut` 的天真 UI 低估了成本。

### `maximumFee` 上限

Token-2022 轉帳費用按轉帳上限。對於 1% mint 和 10,000 代幣上限，100,000,000 代幣轉帳只支付 10,000 費用。SDK 的 `computeSwapAmount` 應用上限；直接程式呼叫者必須複製它。

### 紀元轉換

mint 授權可以排程在下一個紀元激活的費率變更。在轉換視窗期間，兩個設定（`older`、`newer`）同時存在於 mint 上，`TransferChecked` 按目前紀元選擇。CPMM `SwapV2` 和 CLMM `SwapV2` 都在 `accounts` 中傳遞完整 mint 帳戶，所以程式讀取正確設定而無需額外查詢。

如果你透過交易 API 或 SDK 提前超過一個紀元報價，執行費用可能與報價費用不同 — 受舊設定的 `maximum_fee_basis_points` 限制。

## 計息和 ScaledUiAmount

流動性池持有本金；「UI 金額」是本金乘以時間相關或管理員設定的縮放因子。交換數學對本金進行操作：

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK 自動轉換。直接 RPC 讀取者應將 `pool.token0Vault.amount` 視為本金。

## 「Token-2022 流動性池」定義

如果**任一** mint 有 `programId == TokenzQdB...`，流動性池是 Token-2022 流動性池。API 表面這個：

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

使用 `programId` 分派，使用 `hasTransferFee` 表面 UI 警告。

## SDK 幫助程式

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## 常見整合錯誤

- **僅預檢程式 ID。** mint 可以是 Token-2022 *且*不支援。在允許流動性池建立之前，針對允許清單（和靜態白名單）檢查擴充功能清單。
- **當 mint 根本不被接受時信任 SDK 的報價。** 報價 API 不拒絕報價 — 流動性池建立是還原的。在你的 UI 中公開流動性池建立之前，確認 `is_supported_mint` 語義離線。
- **報價時沒有轉帳費用削減。** 1% 轉帳費用 mint 在 0.25% CPMM 流動性池的兩側有大約 2.25% 的有效費用，不是 0.25%。使用 SDK 報價或交易 API 報價 — 永遠不要僅從流動性池的費用層級手動計算費用。
- **在 Token-2022 流動性池上呼叫舊版 `Swap` 指令。** `Swap` 早於 Token-2022。每當任一 mint 是 Token-2022 時使用 `SwapV2`。
- **自動列出新的 Token-2022 mint。** 錢包和聚合器應在向使用者表面 mint 之前檢查 `TransferHook` 和 `NonTransferable`；兩者都對 Raydium 不利。
