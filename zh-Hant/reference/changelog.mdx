## 版本

<Update label="2026-08-31" description="LaunchLab：平台曲線規則取代曲線參數白名單">
  啟動參數限制從 `PlatformConfig` 移至各個 `PlatformCurveRule` 帳戶。規則最多可包含 10 個檢查群組，每個群組最多 25 個 `(field, op, value)` 約束條件，涵蓋 19 個啟動參數，支援 `Eq` / `Gte` / `Lte` / `Neq` 操作——因此平台終於可以表達數值範圍、替代層級、畢業估值上限、遷移下限、代幣類型閘道或按日期切換的群組，這些都是僅支援相等性的白名單無法做到的。`PlatformConfig` 保持 944 位元組大小：`restrict_curve_param`、`curve_rule_manager` 和移除的向量長度前綴都來自填充。解碼器必須移除尾部的 `Vec<PlatformCurveParam>`，啟動建構者必須在啟用旗標時將規則 PDA 附加到 `remaining_accounts`。移除了兩個指令，新增了四個，新增了兩個 `UpdatePlatformConfig` 變體，附加了 `6024`–`6030`。需要 IDL 重新整理。SDK 提供兩個純離鏈檢查，讓建構者無需從已還原的交易中學習規則，條目記錄了在主網啟用旗標前的開發網排練。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-31-launchlab-platform-curve-rules)
</Update>

<Update label="2026-08-27" description="LaunchLab：平台在鑄幣建立時持有提取預扣權限">
  `InitializeWithToken2022` 現在將 `PlatformConfig.transfer_fee_extension_auth` 寫入新基礎鑄幣的 `withdraw_withheld_authority`，而不是啟動 `authority` PDA，因此平台可以在結合曲線階段掃除預扣轉帳費用，而不是等待畢業——程式本身沒有提取預扣指令。`MigrateToCpswap` 僅在 PDA 仍持有該權限時才重新指派該權限，這使畢業對兩代鑄幣都有效。`transfer_fee_config_authority` 仍然僅在畢業時移動，因此在啟動中途輪換 `transfer_fee_extension_auth` 會無聲地將兩個權限留在不同的金鑰上。沒有帳戶配置、指令、引數或錯誤代碼變更。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority)
</Update>

<Update label="2026-08-26" description="LaunchLab：平台費率上限提高至 500 bps">
  平台 `fee_rate` 上限在驗證它的兩個路徑上都移至 `50000`（500 bps）。`CreatePlatformConfig` 自程式首次發佈以來一直被限制在 `10000`（100 bps）；`UpdatePlatformConfig` 自 2026-01-27 以來被限制在 `25000`（250 bps）。現在兩個檢查一致，因此以任何允許的費率建立的平台也可以以該費率更新——包括透過 `AllInfo` 批量變體，它在重寫每個其他欄位時重新驗證 `fee_rate`。兩個路徑仍然引發不同的錯誤（建立時為 `InvalidInput`，更新時為 `InvalidPlatformInfo`）。沒有帳戶配置、指令或錯誤代碼變更，現有平台或啟動都不會重新定價。`GlobalConfig.max_share_fee_rate` 保持在 100 bps，僅限制每筆交易的推薦 `share_fee_rate`。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)
</Update>

<Update label="2026-08-24" description="LaunchLab：Token-2022 報價鑄幣">
  啟動現在可以用 Token-2022 鑄幣報價。`CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、四個交換指令和每個費用聲明都在其報價程式槽中接受任一代幣程式；已棄用的 `Initialize` 保持僅限舊版。交換滑點邊界現在與支付者實際支付或接收的內容進行比較，扣除報價鑄幣的轉帳費用。`PoolState.token_program_flag` bit1 變得有意義，因此針對整個位元組測試 `0` 的解碼器會誤讀舊版基礎鑄幣為 Token-2022。`MigrateToCpswap` 將其兩個代幣程式帳戶重新命名為 `token_program` / `token_program_2022`，`6023` 被重新用於 `CalculateOverflow`。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab：僅限 CPMM 的啟動和平台設定控制">
  新啟動初始化現在需要 CPMM，而舊版 AMM v4 綁定狀態保持可遷移。在此版本之前，`creator_scale` 產生了建構者擁有的費用金鑰；在升級後執行的 CPMM 遷移改為將 `platform_scale + creator_scale` 合併為一個平台擁有的費用金鑰份額。平台也可以用自己的 `PlatformAllowConfig` PDA 限制啟動，遷移建構者必須附加兩個 CPMM 支援鑄幣 PDA。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM：受限發行人頭寸 NFT 凍結">
  新 CLMM 頭寸 NFT 鑄幣使用其池作為凍結權限，但其代幣帳戶預設保持未凍結。凍結僅在 `OpenPositionV2` 或 `OpenPositionWithToken22Nft` 時發生，當任一基礎保管庫鑄幣的凍結權限與受限發行人清單相符時。相符的頭寸無法轉移或更改擁有者，但仍可管理流動性。其 `ClosePosition` 呼叫必須附加池，以便 CLMM 可以原子地解凍、燒毀和關閉。現有頭寸保持不變。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM：無許可建構者費用收集">
  新增的 `CollectCreatorFeePermissionless` 指令讓任何支付者掃除所有累積的建構者費用，同時將受益人和兩個代幣目的地限制為 `PoolState.pool_creator` 和建構者的規範 ATA。原始建構者簽署路徑保持不變。`CreatePermissionPda` 也接受專用授予權限，而 `ClosePermissionPda` 保持僅限管理員。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM：許可多池和限價單凍結帳戶防護">
  兩個新增的、向後相容的 CLMM 程式更新。`CreatePermissionedPool` 將用戶端提供的非零 `seed_index` 摺疊到池 PDA 種子中，讓白名單操作者（持有 `Permission` PDA 的操作者）為每個 `(config, mint0, mint1)` 建立多個池——因此池 ID 不再是交易對的規範。新管理指令 `CreatePermissionPda` / `ClosePermissionPda` 管理這些授予，`PoolState` 獲得 `seed_index` 欄位（從填充中提取，大小不變）。另外，`OpenLimitOrder` 現在接受輸出端帳戶並拒絕其輸入或輸出代幣帳戶被凍結的訂單（`NotApproved`）。

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4：移除 OpenBook / Serum 依賴">

  [閱讀完整條目 →](/zh-Hant/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>
