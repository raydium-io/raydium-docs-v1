## 版本

<Update label="2026-08-26" description="LaunchLab：平台費率上限提高至 500 bps">
  平台 `fee_rate` 上限在兩條驗證路徑上都移至 `50000`（500 bps）。`CreatePlatformConfig` 自程式首次發布以來一直上限為 `10000`（100 bps）；`UpdatePlatformConfig` 自 2026-01-27 以來上限為 `25000`（250 bps）。現在兩個檢查一致，因此以任何允許的費率建立的平台也可以以相同費率更新——包括透過 `AllInfo` 批量變體，該變體在重寫其他每個欄位時重新驗證 `fee_rate`。兩條路徑仍會引發不同的錯誤（建立時為 `InvalidInput`，更新時為 `InvalidPlatformInfo`）。帳戶配置、指令或錯誤代碼均未變更，現有平台或啟動也未重新定價。`GlobalConfig.max_share_fee_rate` 保持在 100 bps，僅限制每筆交易的推薦 `share_fee_rate`。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)
</Update>

<Update label="2026-08-24" description="LaunchLab：Token-2022 報價鑄幣">
  啟動現在可以用 Token-2022 鑄幣進行報價。`CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、四個交換指令和每個費用領取都在其報價程式槽中接受任一代幣程式；已棄用的 `Initialize` 保持僅限舊版。交換滑點邊界現在與支付方實際支付或收到的金額進行比較，扣除報價鑄幣的轉帳費。`PoolState.token_program_flag` 位元 1 變得有意義，因此測試整個位元組是否為 `0` 的解碼器會誤讀舊版基礎鑄幣為 Token-2022。`MigrateToCpswap` 將其兩個代幣程式帳戶重新命名為 `token_program` / `token_program_2022`，`6023` 被重新用於 `CalculateOverflow`。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-08-24-launchlab-token2022-quote-mint)
</Update>

<Update label="2026-08-17" description="LaunchLab：僅限 CPMM 的啟動和平台設定控制">
  新的啟動初始化現在需要 CPMM，而舊版 AMM v4 綁定狀態保持可遷移。在此版本之前，`creator_scale` 產生了創作者擁有的費用金鑰；升級後執行的 CPMM 遷移會將 `platform_scale + creator_scale` 合併為一個平台擁有的費用金鑰份額。平台也可以使用自己的 `PlatformAllowConfig` PDA 限制啟動，遷移建構者必須附加兩個 CPMM 支援鑄幣 PDA。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-08-17-launchlab-cpmm-only-platform-config)
</Update>

<Update label="2026-08-17" description="CLMM：受限發行人頭寸 NFT 凍結">
  新的 CLMM 頭寸 NFT 鑄幣使用其池作為凍結權限，但其代幣帳戶預設保持未凍結。凍結僅在 `OpenPositionV2` 或 `OpenPositionWithToken22Nft` 時發生，當任一基礎保管庫鑄幣的凍結權限與受限發行人清單相符時。相符的頭寸無法轉帳或變更擁有者，但仍可管理流動性。其 `ClosePosition` 呼叫必須附加池，以便 CLMM 可以解凍、燒毀和關閉。現有頭寸保持不變。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-08-17-clmm-restricted-position-nft-freeze)
</Update>

<Update label="2026-08-17" description="CPMM：無許可創作者費用收集">
  附加的 `CollectCreatorFeePermissionless` 指令讓任何支付方掃除所有累積的創作者費用，同時將受益人和兩個代幣目的地限制為 `PoolState.pool_creator` 和創作者的規範 ATA。原始創作者簽署路徑保持不變。`CreatePermissionPda` 也接受專用授予權限，而 `ClosePermissionPda` 保持僅限管理員。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-08-17-cpmm-permissionless-creator-fee-collection)
</Update>

<Update label="2026-07-30" description="CLMM：許可多池和限價單凍結帳戶防護">
  兩個附加的、向後相容的 CLMM 程式更新。`CreatePermissionedPool` 將客戶端提供的非零 `seed_index` 折疊到池 PDA 種子中，讓白名單操作者（持有 `Permission` PDA 的操作者）為每個 `(config, mint0, mint1)` 建立多個池——因此池 ID 不再是交易對的規範。新的管理指令 `CreatePermissionPda` / `ClosePermissionPda` 管理這些授予，`PoolState` 獲得 `seed_index` 欄位（從填充中提取，無大小變更）。另外，`OpenLimitOrder` 現在接受輸出端帳戶並拒絕其輸入或輸出代幣帳戶被凍結的訂單（`NotApproved`）。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-07-30-clmm-permissioned-pools)
</Update>

<Update label="2026-07-22" description="AMM v4：移除 OpenBook / Serum 依賴">
  AMM v4 移除其長期休眠的 OpenBook/Serum 依賴、所有訂單簿 CPI 和已廢棄的造市指令。`SwapBaseIn` / `SwapBaseOut`、`Deposit` 和 `Withdraw` 保持其配置（移除的市場帳戶現在被忽略，不被驗證）；**硬性破壞性** `WithdrawPnl`（17 → 10，無相容性）和 `SetParams`（帳戶減少 + 重新編號 `param`）；`Initialize`、`PreInitialize`、`MonitorStep`、`MigrateToOpenBook`、`WithdrawSrm`、`SimulateInfo`、`AdminCancelOrders` 不再可呼叫。鏈上帳戶配置和錯誤代碼保持穩定；將交換遷移到 V2 進入點。

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-07-22-amm-v4-openbook-removal)
</Update>

  [閱讀完整項目 →](/zh-Hant/reference/changelog/2026-06-22-stable-amm-openbook-cleanup)
</Update>
