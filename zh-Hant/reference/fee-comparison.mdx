## 建立成本

部署池所需的一次性 SOL 成本。

| 產品 | 租金成本 | 建立費 | 典型總額 |
|---------|-----------|--------------|---------------|
| AMM v4 | ~0.15 SOL（多個帳戶） | 0.15 SOL | ~0.30 SOL |
| CPMM | ~0.04 SOL（池 + 金庫 + 觀察） | 0.15 SOL | ~0.19 SOL |
| CLMM | ~0.061 SOL（池 0.0116 + 觀察 0.0321 + tick-array-bitmap 擴展 0.0136 + 兩個金庫 0.0041） | 0 SOL | ~0.061 SOL，每個 tick 陣列再加 ~0.072 SOL |
| Farm v6 | ~0.02 SOL（農場狀態 + 獎勵金庫） | 0.1 SOL（反垃圾郵件） | ~0.12 SOL |
| LaunchLab 啟動 | ~0.015 SOL（結合曲線帳戶） | 0.1 SOL（LaunchLab 費） | ~0.115 SOL |

CLMM 的 tick 陣列**不是**由 `CreatePool` 建立的 — 每個 `TickArrayState` 為 10,240 位元組（約 0.072 SOL），由第一個觸及它的 `OpenPosition*` / `IncreaseLiquidity*` 延遲配置，費用由該呼叫者承擔。因此典型的第一個頭寸會在上表的池數字之上再加一到兩個 tick 陣列。

<Note>
  本頁的租金數字是以 `lamports_per_byte = 6,960`（SIMD-0437 之前的費率）計算的。
  [租金下調](/zh-Hant/solana-fundamentals/rent-and-reclaimable-rent)會分五個階段降低這個數字 —
  請呼叫 `getMinimumBalanceForRentExemption` 取得即時數字，而不要引用這些。
</Note>

大部分租金是可回收的 — 關閉頭寸或農場會返還 lamports。tick 陣列永遠不會被關閉，而 `AmmInfo` / `PoolState` 會無限期存在。

## 典型操作的網路費

這些是 Solana 基礎費 + 優先費，與 Raydium 協議費分開。

| 操作 | CU（實測） | 基礎費 | 優先費（10k µL/CU） | 總網路費 |
|-----------|-----|----------|---------------------------|---------------|
| CPMM `SwapBaseInput` | ~23,000 | 0.000005 SOL | 0.00000023 SOL | ~0.0000052 SOL |
| AMM v4 交換 | ~26,000 | 0.000005 SOL | 0.00000026 SOL | ~0.0000053 SOL |
| CLMM `Swap`（V1） | ~41,000 | 0.000005 SOL | 0.00000041 SOL | ~0.0000054 SOL |
| CLMM `SwapV2` | ~48,000 | 0.000005 SOL | 0.00000048 SOL | ~0.0000055 SOL |
| CLMM `IncreaseLiquidityV2` | ~36,000 | 0.000005 SOL | 0.00000036 SOL | ~0.0000054 SOL |
| CLMM `CollectProtocolFee` | ~16,000 | 0.000005 SOL | 0.00000016 SOL | ~0.0000052 SOL |

<Note>
  **這些是如何測量的。** 每個數字都是 Raydium 程式自身呼叫的
  `Program <id> consumed N of M compute units` 日誌行 — 因此它包含其內部的代幣程式 CPI，
  但不包含任何包裝該呼叫的聚合器或路由器。取樣自 **2026-09-09** 高交易量流動性池上的
  主網實際交易：CPMM `SwapBaseInput` 22,721–23,052（n=8）；AMM v4 交換
  25,215–26,002；CLMM `Swap` 37,148–44,721；CLMM `SwapV2` 43,838–52,887（n=6）。

  CLMM 交換成本會隨 tick 穿越次數增加，因此把 `SwapV2` 當作下限，並為波動性大的池預留餘裕。
  請實測你自己的路徑，而不要根據這張表編列預算 — 並注意一旦計入 ATA 建立、wSOL 包裝和
  compute-budget 指令，整筆交易的成本總是高於單獨的 Raydium 指令。
</Note>

優先費是 `ceil(compute_unit_price × compute_unit_limit / 1_000_000)` **lamports**，所以在 10,000 µLamports/CU 下，一筆 23,000 CU 的交易支付 230 lamports。在該 CU 價格下，每個簽名 5,000 lamports 的基礎費以超過一個數量級主導帳單；只有在單簽名 23,000 CU 的交易上大約超過 217,000 µLamports/CU 時，優先費才會超過它。優先費與 CU 價格呈線性關係；詳見 [`integration-guides/priority-fee-tuning`](/zh-Hant/integration-guides/priority-fee-tuning)。

## Token-2022 費用互動

當池的一側或雙方使用具有轉帳費的 Token-2022 時，有效費用會複合：

```
net input to pool   = amount_in × (1 − transfer_fee_in)
pool charges swap   = net × swap_fee_rate
net output to user  = out × (1 − transfer_fee_out)
```

範例：CPMM 0.25% 池，輸入側有 1% 轉帳費，輸出側有 0.5% 轉帳費。

```
amount_in        = 1000
net_to_pool      = 1000 × 0.99    = 990
pool swap fee    = 990 × 0.0025   = 2.475 (kept as LP fee)
amount_after_fee = 987.525
amount_out (AMM) = 987.525 × ratio, say 987.525 × 0.98 = 967.77
net_out_to_user  = 967.77 × 0.995 = 962.94
```

有效費用：**約 1.74%**，儘管名義上池費為 0.25% — 也就是 `1 − 0.99 × 0.9975 × 0.995`。上面的 `× 0.98` 是池的匯率（計價單位的變換），不是費用，所以不能算進費用堆疊：相對於 `1000 × 0.98 = 980` 的無費用輸出來衡量，損失同樣是 1.74%。

SDK 透過 `getComputeAmountOut` 計算有效費率 — 引用 Token-2022 池時務必使用它。

## 如何讀取鏈上當前值

### CPMM/CLMM AmmConfig

```ts
// The helper lives on the API client, not on the cpmm module.
const configs = await raydium.api.getCpmmConfigs();   // getClmmConfigs() for CLMM
console.log(configs[0]);
// Mainnet AmmConfig index 0, read 2026-09-09
// (D4FPEruKEHrG5TenZ2mpDGEfu1iUvTiqBxvpU8HLBvC2):
// {
//   id: "D4FPEruKEHrG5TenZ2mpDGEfu1iUvTiqBxvpU8HLBvC2",
//   tradeFeeRate:    2500,      //   2500 / 1_000_000 = 0.25% of volume
//   protocolFeeRate: 120000,    // 120000 / 1_000_000 = 12% OF THE TRADE FEE
//   fundFeeRate:     40000,     //  40000 / 1_000_000 =  4% of the trade fee
//   creatorFeeRate:  500,       //    500 / 1_000_000 = 0.05% of volume (opt-in)
//   createPoolFee:   "150000000",  // 0.15 SOL
//   protocolOwner:   "ProCXqRcXJjoUd1RNoo28bSizAA6EEqt9wURZYPDc5u",
//   fundOwner:       "FUNDduJTA7XcckKHKfAoEnnhuSud2JUCUZv6opWEjrBU",
//   ...
// }
```

請注意 `protocolFeeRate` 和 `fundFeeRate` 是**交易費**的比例，而不是交易量的比例 — 所以這裡的 12% 和 4% 在 0.25% 層級下意味著交易量的 0.03% 和 0.01%。

### AMM v4 池

```ts
// The fee numerators live on `poolRpcData` (the decoded AmmInfo), not on `poolInfo`,
// and they are named tradeFee*/swapFee*.
const { poolRpcData } = await raydium.liquidity.getPoolInfoFromRpc({ poolId: POOL_ID });
console.log(
  poolRpcData.tradeFeeNumerator.toString(),
  poolRpcData.tradeFeeDenominator.toString(),
);
// 25, 10000 → 0.25%
```

### Farm v6 獎勵費率

```ts
// Farm metadata comes from the API client, not the farm module — there is no
// raydium.farm.getFarmInfoFromRpc.
const farm = (await raydium.api.fetchFarmInfoById({ ids: farmId }))[0];
console.log(farm.rewardInfos);
// Per-reward: emissions rate, open/end time, reward mint
```
