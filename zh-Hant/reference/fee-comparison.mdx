## 建立成本

部署池支付的一次性 SOL 成本。

| 產品 | 租金成本 | 建立費 | 典型總計 |
|---------|-----------|--------------|---------------|
| AMM v4 | ~0.15 SOL（多個帳戶） | 0.15 SOL | ~0.30 SOL |
| CPMM | ~0.04 SOL（池 + 金庫 + 觀察） | 0.15 SOL | ~0.19 SOL |
| CLMM | ~0.061 SOL（池 0.0116 + 觀察 0.0321 + tick 陣列位圖擴展 0.0136 + 兩個金庫 0.0041） | 0 SOL | ~0.061 SOL，加上每個 tick 陣列 ~0.072 SOL |
| Farm v6 | ~0.02 SOL（農場狀態 + 獎勵金庫） | 0.1 SOL（反垃圾郵件） | ~0.12 SOL |
| LaunchLab 啟動 | ~0.015 SOL（結合曲線帳戶） | 0.1 SOL（LaunchLab 費） | ~0.115 SOL |

CLMM tick 陣列**不是**由 `CreatePool` 建立的 — 每個 `TickArrayState` 是 10,240 字節（~0.072 SOL），由首次觸及它的 `OpenPosition*` / `IncreaseLiquidity*` 懶惰分配，由該調用者承擔費用。因此，典型的首個頭寸在上述池數字基礎上額外添加一或兩個 tick 陣列。

<Note>
  本頁的租金數字以 `lamports_per_byte = 6,960` 計算，這是 SIMD-0437 前的費率。
  [租金減少](/zh-Hant/solana-fundamentals/rent-and-reclaimable-rent)分五步降低 — 調用 `getMinimumBalanceForRentExemption` 獲取實時數字，而不是引用這些。
</Note>

大部分租金可回收 — 關閉頭寸或農場會返回 lamports。Tick 陣列永遠不會關閉，`AmmInfo` / `PoolState` 無限期持續。

## 典型操作的網絡費

這些是 Solana 基礎費 + 優先費，與 Raydium 協議費分開。

| 操作 | CU（測量） | 基礎費 | 優先費（10k µL/CU） | 總網絡費 |
|-----------|-----|----------|---------------------------|---------------|
| CPMM `SwapBaseInput` | ~23,000 | 0.000005 SOL | 0.00000023 SOL | ~0.0000052 SOL |
| AMM v4 交換 | ~26,000 | 0.000005 SOL | 0.00000026 SOL | ~0.0000053 SOL |
| CLMM `Swap`（V1） | ~41,000 | 0.000005 SOL | 0.00000041 SOL | ~0.0000054 SOL |
| CLMM `SwapV2` | ~48,000 | 0.000005 SOL | 0.00000048 SOL | ~0.0000055 SOL |
| CLMM `IncreaseLiquidityV2` | ~36,000 | 0.000005 SOL | 0.00000036 SOL | ~0.0000054 SOL |
| CLMM `CollectProtocolFee` | ~16,000 | 0.000005 SOL | 0.00000016 SOL | ~0.0000052 SOL |

<Note>
  **這些是如何測量的。** 每個數字都是 Raydium 程序自身調用的 `Program <id> consumed N of M compute units` 日誌行 — 因此它包括其內部代幣程序 CPI，但排除任何聚合器或路由器包裝調用。從 **2026-09-09** 高交易量池的實時主網交易中採樣：CPMM `SwapBaseInput` 22,721–23,052（n=8）；AMM v4 交換 25,215–26,002；CLMM `Swap` 37,148–44,721；CLMM `SwapV2` 43,838–52,887（n=6）。

  CLMM 交換成本隨 tick 穿越而變化，因此將 `SwapV2` 視為下限，並為波動池預留餘量。測量你自己的路徑，而不是根據此表預算 — 並注意整個交易總是比 Raydium 指令單獨成本更多，一旦計入 ATA 建立、wSOL 包裝和計算預算指令。
</Note>

優先費是 `ceil(compute_unit_price × compute_unit_limit / 1_000_000)` **lamports**，因此在 10,000 µLamports/CU 時，23,000-CU 交易支付 230 lamports。在該 CU 價格下，5,000-lamport-per-signature 基礎費主導賬單超過一個數量級；優先費只有在單簽名 23,000-CU 交易上大約 217,000 µLamports/CU 以上時才會超過它。優先費與 CU 價格成線性關係；見 [`integration-guides/priority-fee-tuning`](/zh-Hant/integration-guides/priority-fee-tuning)。

## Token-2022 費用交互

當池的一側或兩側使用帶轉帳費的 Token-2022 時，有效費用複合：

```
net input to pool   = amount_in × (1 − transfer_fee_in)
pool charges swap   = net × swap_fee_rate
net output to user  = out × (1 − transfer_fee_out)
```

示例：CPMM 0.25% 池，輸入側有 1% 轉帳費，輸出側有 0.5% 轉帳費。

```
amount_in        = 1000
net_to_pool      = 1000 × 0.99    = 990
pool swap fee    = 990 × 0.0025   = 2.475 (kept as LP fee)
amount_after_fee = 987.525
amount_out (AMM) = 987.525 × ratio, say 987.525 × 0.98 = 967.77
net_out_to_user  = 967.77 × 0.995 = 962.94
```

有效費用：**~1.74%**，儘管名義上 0.25% 池費 — 即 `1 − 0.99 × 0.9975 × 0.995`。上面的 `× 0.98` 是池的匯率（面額變化），不是費用，因此不應計入費用堆棧：相對於無費用輸出 `1000 × 0.98 = 980`，損失相同為 1.74%。

SDK 通過 `getComputeAmountOut` 計算有效費率 — 在引用 Token-2022 池時始終使用它。

## Farm v6 獎勵成本模型

農場本身不收費 — 它們是獎勵分配。但它們需要 SOL 來運營：

| 成本 | 典型 |
|------|---------|
| 農場建立 | 0.1 SOL 反垃圾郵件 + ~0.02 SOL 租金 |
| 頂部獎勵金庫 | 只是代幣 + ~0.0005 SOL 交易費 |
| 回收未使用獎勵 | ~0.0005 SOL 交易費 |

農場還需要獎勵金庫中有足夠的 lamports 來覆蓋農場生命週期的租金；關閉會返回它們。

## 如何在鏈上讀取當前值

### CPMM/CLMM AmmConfig

```ts
// 助手位於 API 客戶端，不在 cpmm 模塊上。
const configs = await raydium.api.getCpmmConfigs();   // getClmmConfigs() for CLMM
console.log(configs[0]);
// Mainnet AmmConfig index 0, read 2026-09-09
// (D4FPEruKEHrG5TenZ2mpDGEfu1iUvTiqBxvpU8HLBvC2):
// {
//   id: "D4FPEruKEHrG5TenZ2mpDGEfu1iUvTiqBxvpU8HLBvC2",
//   tradeFeeRate:    2500,      //   2500 / 1_000_000 = 0.25% of volume
//   protocolFeeRate: 120000,    // 120000 / 1_000_000 = 12% OF THE TRADE FEE
//   fundFeeRate:     40000,     //  40000 / 1_000_000 =  4% of the trade fee
//   creatorFeeRate:  500,       //    500 / 1_000_000 = 0.05% of volume (opt-in)
//   createPoolFee:   "150000000",  // 0.15 SOL
//   protocolOwner:   "ProCXqRcXJjoUd1RNoo28bSizAA6EEqt9wURZYPDc5u",
//   fundOwner:       "FUNDduJTA7XcckKHKfAoEnnhuSud2JUCUZv6opWEjrBU",
//   ...
// }
```

注意 `protocolFeeRate` 和 `fundFeeRate` 是交易費的分數，不是交易量的分數 — 因此這裡的 12% 和 4% 在 0.25% 級別時表示交易量的 0.03% 和 0.01%。

CPMM 的 `AmmConfig` 攜帶此有效負載不一定表面的第四個費率：`creator_fee_share_rate`，協議的份額**的創建者費**，添加於 2026-09-19。它是累積創建者桶的分數，不是交易量的分數，也不是交易費的分數，它在收集創建者費時應用，而不是在交換時，每個創建者 `CreatorFeeShare` PDA 可以覆蓋它。從 `AmmConfig` 帳戶讀取它。詳見 [`products/cpmm/fees`](/zh-Hant/products/cpmm/fees#protocol-share-of-the-creator-fee)。
