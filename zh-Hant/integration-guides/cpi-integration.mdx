## CPI 何時是正確的工具

當交易需要與只有你的程式才能進行的其他鏈上狀態變更原子性地發生時，自訂程式就很有意義。常見的情況：

- **託管 / 限價單程式** — 使用者將一個 mint 存入你的託管，你的程式監視價格條件，當觸發時，你的程式原子性地透過 Raydium 交換並將結果記入使用者帳戶。
- **聚合器代理** — 單一指令將交換路由透過 Raydium 加上一個或多個其他 DEX，所有跳轉都在由你的程式擁有的單一滑點檢查下。
- **自動複利金庫** — 將 LP 或農場質押存入你的金庫，金庫按計畫收穫獎勵、重新供應流動性、發行份額代幣。
- **策略金庫** — 槓桿 LP 頭寸透過 CLMM 交換進行再平衡；清算人在一筆交易中關閉頭寸並交換抵押品。
- **具有自訂解鎖的代幣發行平台** — 你的程式持有解鎖代幣並按計畫釋放到 Raydium 池中。

如果你只想從鏈下程式碼發送交換，CPI 就太複雜了 — 使用 SDK。只有當與你自己的狀態的原子性是要求時，CPI 才值得這種複雜性。

## 組合模式

### 模式 1：薄代理

你的程式公開單一指令，驗證某些政策（例如白名單 mint 對、驗證使用者的費用折扣），然後轉發到 Raydium。

```
┌──────────────┐   user tx    ┌────────────────┐  CPI  ┌──────────┐
│ user         │─────────────▶│ your program   │──────▶│ Raydium  │
└──────────────┘              │  (validate)    │       │  (CPMM)  │
                              └────────────────┘       └──────────┘
```

狀態存在於使用者的 ATA 中。你的程式不擁有任何代幣。最小信任足跡。

### 模式 2：託管

你的程式擁有一個 PDA，持有使用者的輸入 mint。觸發時，PDA 簽署一個 CPI 到 Raydium 以交換其自己的餘額。

```
           deposit                   trigger
   user ───────────▶  PDA vault  ───────────────▶  Raydium swap
                     (your prog)                    (signed by PDA)
                                                            │
                                                            ▼
                                                    PDA vault (output mint)
                                                            │
                                                     withdraw ▼
                                                         user
```

關鍵細節：PDA 透過 `CpiContext::new_with_signer` 簽署。見 [簽署者種子](#pda-signer-seeds)。

### 模式 3：組合多跳

你的程式在一個指令中發出多個 CPI，在所有 CPI 中強制執行單一滑點界限。Raydium 交換指令各自有自己的 `minimum_amount_out`，但你將其設定為 0（或非常寬鬆的下限），並在最後一跳後自己強制執行嚴格的最終最小值。

```
instruction:
  CPI swap: tokenA → tokenB   (raydium, loose min)
  CPI swap: tokenB → tokenC   (raydium / third-party, loose min)
  CPI swap: tokenC → tokenD   (raydium, loose min)
  require(user.tokenD_ata.amount - pre_balance >= user_min_out)
```

這為整個路由提供了單一的還原門。只有在你信任每個跳轉都是滑點安全的情況下才使用此模式；否則，讓每個跳轉強制執行自己的最小值。

### 模式 4：金庫 / 策略

你的程式在 PDA 中持有 LP 代幣或農場質押。保管人（或使用者）呼叫 `compound()`，其中：

1. 從農場收穫獎勵。
2. 將獎勵交換為池代幣（CPI 進入 CPMM 或 CLMM）。
3. 將收益存回 LP（另一個 CPI）。
4. 質押新 LP（另一個 CPI）。

全部在一筆交易中進行，以便金庫的 NAV 原子性地移動。計算預算通常為 600k–1M CU；地址查詢表是必需的。

## 帳戶列表構造

呼叫程式的 `Accounts` 結構鏡像 Raydium 程式的帳戶順序，但大多數 Raydium 端帳戶是 `UncheckedAccount`，因為 Raydium 自己驗證它們。你只在*你*擁有的帳戶上新增約束：

```rust
use anchor_lang::prelude::*;
use anchor_spl::token::{Token, TokenAccount};

#[derive(Accounts)]
pub struct EscrowSwap<'info> {
    /// The escrow PDA; holds input mint and signs the CPI.
    #[account(
        mut,
        seeds = [b"escrow", user.key().as_ref()],
        bump = escrow.bump,
    )]
    pub escrow: Account<'info, Escrow>,

    #[account(mut)]
    pub user: Signer<'info>,

    // ----- Raydium-side accounts, mostly unchecked -----

    /// CHECK: validated by CPMM
    #[account(mut)] pub pool_state: UncheckedAccount<'info>,
    /// CHECK: validated by CPMM
    pub amm_config: UncheckedAccount<'info>,
    /// CHECK: validated by CPMM
    pub pool_authority: UncheckedAccount<'info>,
    #[account(mut)] pub input_vault:  Account<'info, TokenAccount>,
    #[account(mut)] pub output_vault: Account<'info, TokenAccount>,
    /// CHECK: validated by CPMM
    #[account(mut)] pub observation_state: UncheckedAccount<'info>,

    /// Escrow's input ATA — owned by the escrow PDA.
    #[account(
        mut,
        associated_token::mint = input_mint,
        associated_token::authority = escrow,
    )]
    pub escrow_input_ata: Account<'info, TokenAccount>,

    /// Escrow's output ATA.
    #[account(
        mut,
        associated_token::mint = output_mint,
        associated_token::authority = escrow,
    )]
    pub escrow_output_ata: Account<'info, TokenAccount>,

    pub input_mint:  Account<'info, anchor_spl::token::Mint>,
    pub output_mint: Account<'info, anchor_spl::token::Mint>,

    pub cpmm_program:       Program<'info, raydium_cp_swap::program::RaydiumCpSwap>,
    pub token_program:      Program<'info, Token>,
    pub token_program_2022: Program<'info, anchor_spl::token_2022::Token2022>,
}
```

不對稱性 — 對你的帳戶進行嚴格驗證，對 Raydium 的帳戶進行 `UncheckedAccount` — 不是懶惰。接收者驗證自己的；在呼叫者處雙重驗證只會燃燒 CU，並在 Raydium 發布新結構佈局欄位時冒著不同步的風險。

## CPI 呼叫本身

```rust
use raydium_cp_swap::cpi::{self, accounts::Swap as CpmmSwap};

pub fn escrow_swap(
    ctx: Context<EscrowSwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let user_key = ctx.accounts.user.key();
    let bump     = ctx.accounts.escrow.bump;
    let seeds: &[&[u8]] = &[b"escrow", user_key.as_ref(), &[bump]];
    let signer: &[&[&[u8]]] = &[seeds];

    let cpi_accounts = CpmmSwap {
        payer:                ctx.accounts.user.to_account_info(),
        authority:            ctx.accounts.escrow.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.escrow_input_ata.to_account_info(),
        output_token_account: ctx.accounts.escrow_output_ata.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.token_program.to_account_info(),
        output_token_program: ctx.accounts.token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };

    // Anchor 1.0 takes the program's Pubkey here, not its AccountInfo.
    let cpi_ctx = CpiContext::new_with_signer(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
        signer,
    );

    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)?;
    Ok(())
}
```

### PDA 簽署者種子

CPI 只有在作為 `authority` 傳遞的 PDA 與呼叫者聲稱的推導相符時才會成功。兩者必須同意：

1. 種子位元組序列（此處 `[b"escrow", user.key().as_ref()]`）。
2. bump。
3. 呼叫程式 ID（你的程式，不是 Raydium 的）。

Raydium 不在乎 authority 是誰 — 它只在乎 `authority` 簽名涵蓋交易且輸入 ATA 由該 authority 擁有。驗證發生在 `anchor_spl::token::transfer` 中：ATA 的 `authority` 欄位必須等於簽署者。

常見錯誤：將 `user` 作為 authority 傳遞（並從由託管 PDA 擁有的 `escrow_input_ata` 轉帳）。SPL Token 程式以 `owner mismatch` 拒絕。始終使 `authority` 欄位與 ATA 擁有者相符。

## 剩餘帳戶

幾個 Raydium 指令在固定帳戶之後採用可變長度的帳戶列表 — **剩餘帳戶**。

- **CLMM `SwapV2`**：1–8 個 `TickArrayState` 帳戶，用於交換可能遍歷的 tick 陣列，按交換方向。
- **Farm v6 `Deposit` / `Harvest` / `Withdraw`**：`(reward_vault, user_reward_ata)` 對，每個活躍獎勵槽一對。
- **Token-2022 轉帳掛鉤 mint**：轉帳掛鉤程式加上掛鉤需要的任何帳戶。

Anchor CPI 幫助程式不對剩餘帳戶進行型別檢查。將其傳遞：

```rust
let cpi_ctx = CpiContext::new_with_signer(program_id, accounts, signer)
    .with_remaining_accounts(ctx.remaining_accounts.to_vec());
```

**順序很重要。** 對於 CLMM：

```
remaining = [
    tick_array_in_direction_0,    // first one crossed
    tick_array_in_direction_1,
    ...,
]
```

對於 farm v6 收穫：

```
remaining = [
    reward_vault_0, user_reward_ata_0,
    reward_vault_1, user_reward_ata_1,
    // omit any slot whose reward_state is Uninitialized
]
```

你的呼叫程式必須將從客戶端接收的剩餘帳戶原封不動地傳遞。不要嘗試篩選或重新排序它們。

## 組合呼叫的計算預算

CPI 本身的呼叫框架成本約 1,500 CU；被呼叫者自己的 CU 使用堆疊在上面。每個 Raydium CPI 的粗略預算：

| 呼叫 | CU (SPL Token) | CU (Token-2022) |
|------|----------------|-----------------|
| CPMM swap_base_input | ~150,000 | ~200,000 |
| CLMM swap_v2 (single tick array) | ~180,000 | ~230,000 |
| CLMM swap_v2 (crosses 2 ticks) | ~220,000 | ~270,000 |
| Farm v6 deposit | ~120,000 | ~150,000 |
| Farm v6 harvest (per reward slot) | +30,000 | +40,000 |
| AMM v4 swap_base_in | ~140,000 | n/a |

為每個 CPI 框架新增約 1,500，為你自己程式的開銷新增約 20,000。執行 `harvest → swap A → swap B → deposit LP → stake LP` 的自動複利器輕鬆達到 700k CU。

始終設定明確的 `ComputeBudgetProgram::set_compute_unit_limit`：

```ts
import { ComputeBudgetProgram } from "@solana/web3.js";

const tx = new Transaction().add(
  ComputeBudgetProgram.setComputeUnitLimit({ units: 900_000 }),
  ComputeBudgetProgram.setComputeUnitPrice({ microLamports: priorityFeeMicroLamports }),
  yourInstruction,
);
```

預設的 200k CU 上限將在組合呼叫完成之前很久就無聲地耗盡。

## 錯誤傳播

Raydium 的程式返回具有穩定錯誤代碼的 Anchor 錯誤。你的呼叫程式將其視為 `Err(ProgramError::Custom(code))`。預設情況下冒泡：

```rust
cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)?;
```

或攔截特定代碼：

```rust
use raydium_cp_swap::error::ErrorCode as CpmmErr;

match cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out) {
    Ok(_) => {},
    Err(err) if is_err(err, CpmmErr::ExceededSlippage) => {
        // Your program might want to retry at a larger slippage, or unwind state.
        return err!(YourErr::PoolTooVolatile);
    }
    Err(err) => return Err(err),
}
```

錯誤代碼到含義的對應根據 IDL 政策是穩定的（[`sdk-api/anchor-idl`](/zh-Hant/sdk-api/anchor-idl)）；新代碼在末尾附加，現有代碼的含義永遠不會改變。

## 完整實作範例：限價單託管

流程：

1. **`open_order`** — 使用者將 `amount_in` 的 `input_mint` 存入託管 PDA；記錄目標 `min_amount_out` 和到期時間。
2. **`execute_order`** — 任何人（保管人）使用當前池帳戶呼叫。程式檢查當前報價 ≥ `min_amount_out`，然後 CPI Raydium 交換並將輸出保留在託管中。
3. **`claim`** — 使用者從託管中提取輸出 mint。

```rust
#[account]
pub struct LimitOrder {
    pub user:          Pubkey,
    pub input_mint:    Pubkey,
    pub output_mint:   Pubkey,
    pub amount_in:     u64,
    pub min_out:       u64,
    pub expiry_unix:   i64,
    pub state:         u8,    // 0 open, 1 filled, 2 cancelled, 3 expired
    pub bump:          u8,
}

#[program]
pub mod limit_orders {
    use super::*;

    pub fn execute_order(
        ctx: Context<ExecuteOrder>,
    ) -> Result<()> {
        let order = &ctx.accounts.order;
        require!(order.state == 0, OrderErr::NotOpen);
        require!(Clock::get()?.unix_timestamp < order.expiry_unix, OrderErr::Expired);

        let user_key = order.user;
        let seeds: &[&[u8]] = &[b"order", user_key.as_ref(), &[order.bump]];
        let signer: &[&[&[u8]]] = &[seeds];

        let pre_out_balance = ctx.accounts.escrow_output_ata.amount;

        let cpi_accounts = CpmmSwap {
            payer:                ctx.accounts.keeper.to_account_info(),
            authority:            ctx.accounts.order.to_account_info(),
            amm_config:           ctx.accounts.amm_config.to_account_info(),
            pool_state:           ctx.accounts.pool_state.to_account_info(),
            input_token_account:  ctx.accounts.escrow_input_ata.to_account_info(),
            output_token_account: ctx.accounts.escrow_output_ata.to_account_info(),
            input_vault:          ctx.accounts.input_vault.to_account_info(),
            output_vault:         ctx.accounts.output_vault.to_account_info(),
            input_token_program:  ctx.accounts.token_program.to_account_info(),
            output_token_program: ctx.accounts.token_program.to_account_info(),
            input_token_mint:     ctx.accounts.input_mint.to_account_info(),
            output_token_mint:    ctx.accounts.output_mint.to_account_info(),
            observation_state:    ctx.accounts.observation_state.to_account_info(),
        };

        let cpi_ctx = CpiContext::new_with_signer(
            *ctx.accounts.cpmm_program.key,
            cpi_accounts,
            signer,
        );

        // Let the escrow enforce the minimum — we trust Raydium's slippage, but we
        // also re-check our own post-swap delta in case a future change ever relaxes it.
        cpi::swap_base_input(cpi_ctx, order.amount_in, order.min_out)?;

        ctx.accounts.escrow_output_ata.reload()?;
        let delta = ctx.accounts.escrow_output_ata.amount
            .checked_sub(pre_out_balance)
            .ok_or(error!(OrderErr::AccountingError))?;
        require!(delta >= order.min_out, OrderErr::InsufficientOutput);

        let order = &mut ctx.accounts.order;
        order.state = 1;
        Ok(())
    }
}
```

保管人支付交易費（他們在其他地方獲得保管人費 — 未顯示）。託管 PDA 簽署 CPI。Raydium 端滑點檢查*和*託管自己的 delta 檢查都強制執行下限 — 雙重保險。

## 組合特有的陷阱

### 重入

Solana 沒有真正的重入 — CPI 不能在同一呼叫中回呼到發起程式。但你仍然可以將自己構建成邏輯重入：CPI 讀取你的狀態，然後你的程式再次讀取它，假設 CPI 沒有改變它。對於 Raydium，CPI 不會觸及你的狀態，所以這不如例如閃電貸上下文那樣令人擔憂。但如果你將 Raydium 與借貸協議組合，請注意。

### 帳戶可變性漂移

如果你的程式將帳戶作為 `mut` 傳遞，但 Raydium 期望它唯讀（或反之），執行時以 `InvalidAccountData` 拒絕呼叫。始終在 IDL 中檢查 Raydium 指令的預期可變性；`anchor_cp_swap::cpi::accounts::Swap` 透過其欄位型別強制執行。

### Token-2022 程式欄位

輸入和輸出 mint 可能在不同的代幣程式下 — 一個 SPL Token，一個 Token-2022。CPI 有單獨的 `input_token_program` 和 `output_token_program` 欄位是有原因的。始終檢查每個 mint 的 `owner` 欄位並將正確的程式路由到每個槽中。

### 版本化交易

執行 2+ 個 Raydium CPI 加上 ATA 建立的組合 tx 很少適合舊版（v0-without-LUT）交易。使用 V0 與地址查詢表；透過 `raydium.getRaydiumLutAddresses()` 拉取 Raydium 的公開 LUT。
