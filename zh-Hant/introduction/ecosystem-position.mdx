## 上游依賴

### OpenBook（前身為 Serum）

- **角色**：中央限價訂單簿。AMM v4 池原本是針對 OpenBook 的混合型——交換可以針對池的 AMM 曲線或匹配的 OpenBook 市場成交——但 **OpenBook 整合已被停用**。AMM v4 池不再在 OpenBook 上發佈或維護訂單。
- **相關之處**：歷史上僅適用於 AMM v4 池；今天，Raydium 的任何產品都沒有實時 OpenBook 依賴。
- **風險面**：以前，OpenBook 升級或中斷可能影響 AMM v4 行為（2023 年 1 月發生過一次這樣的事件）。現在整合已關閉，該耦合已移除。CPMM 和 CLMM 從未有過 OpenBook 依賴。
- **狀態**：OpenBook 繼續在 Solana 上運行；Raydium 不依賴它進行任何當前交換流量。現有 AMM v4 池引用的 OpenBook 市場帳戶保留在鏈上作為向後相容的惰性狀態。

### Solana 執行時

- **角色**：所有 Raydium 程式的執行基礎。
- **相關之處**：無處不在。Solana 的最終性時間（~1 秒）、計算預算限制（每筆交易 1.4M CU）和地址查詢表都直接影響 Raydium 使用者體驗。
- **狀態**：Solana 定期升級；Raydium 跟蹤驗證者客戶端版本（Agave、Firedancer），如果行為改變則進行調整。

### 代幣程式（SPL Token 和 Token-2022）

- **角色**：所有 Raydium 池持有的代幣基元。
- **SPL Token**：舊版程式；適用於所有產品。
- **Token-2022**：啟用擴展的程式；適用於 CPMM、CLMM、Farm v6，不適用於 AMM v4。
- **風險面**：擴展行為（轉帳費用、掛鉤等）可能影響池功能。參見 [`security/oracle-and-token-risks`](/zh-Hant/security/oracle-and-token-risks)。

## 下游整合

### Jupiter 和其他聚合器

- **角色**：在許多 Solana DEX（包括 Raydium）之間路由交易。
- **整合方式**：Jupiter 從 Raydium 的 REST API 和直接鏈上呼叫讀取池狀態，然後透過 Raydium SDK（有時直接）組合交換指令。
- **交易量份額**：大約 60% 的 Jupiter 交易量至少觸及 Raydium 池一次。
- **整合者路徑**：一般聚合器模式記錄在 [`integration-guides/aggregator`](/zh-Hant/integration-guides/aggregator)。

### 錢包

- **角色**：讓使用者交換、追蹤 LP 頭寸，以及參與農場，無需離開錢包。
- **整合方式**：
  - 交換：透過 Jupiter 或直接透過 Raydium SDK 路由。
  - 頭寸顯示：列舉使用者的 ATA 和 NFT 持有，與 Raydium 的池列表交叉參考（[`integration-guides/wallet-integration`](/zh-Hant/integration-guides/wallet-integration)）。
  - 農場顯示：呼叫 Raydium 的 `/positions/staking` 端點。
- **使用者影響**：任何具有應用內交換的錢包可能透過 Raydium 路由，而你不會注意到。

### 借貸協議（Kamino、Marginfi、Drift）

- **角色**：需要預言機價格和清算執行場所的借貸協議。
- **整合方式**：CLMM ObservationState TWAP 作為預言機；透過 Raydium 直接交換以進行清算抵押品轉換。
- **風險**：如果借貸協議使用現貨 Raydium 價格而不是 TWAP，它們可能被閃電貸風格的操縱所利用（參見 [`security/attack-vectors`](/zh-Hant/security/attack-vectors)）。

### MEV 搜尋者和套利者

- **角色**：保持 Raydium、Orca、Phoenix 和中心化交易所之間的價格一致。
- **對使用者的影響**：大多數時間價格緊湊；對保護較少的交換進行三明治攻擊。參見 [`integration-guides/routing-and-mev`](/zh-Hant/integration-guides/routing-and-mev)。

### 機器人（做市商、DCA 執行者、清算人）

- **角色**：提供流動性（在淺池上進行 LP）、執行排定的交易、平倉。
- **整合路徑**：通常是使用 [`sdk-api/python-integration`](/zh-Hant/sdk-api/python-integration) 或 Rust CPI 包裝器的 Python 或 Rust 機器人。

## 聚合交易量中的位置

截至 2026 年 4 月：

- Raydium 在任何給定日期處理 Solana 範圍內 DEX 交易量的約 35–45%。
- 當迷因幣活動集中在 LaunchLab + 畢業池時，最高市場份額約 55%。
- 在訂單簿驅動活動繁重的時期（大型機構流量在可用時流向 Phoenix），低端約 25%。

這些數字波動；要點是 Raydium 可靠地是交易量排名前兩位的場所之一。

## Token-2022 生態

Raydium 是首批原生支援 Token-2022 的主要 DEX 之一。含義：

- 具有轉帳費用的新鑄幣（例如，版稅、費用至發行者代幣）可以進行 LP。
- 轉帳掛鉤鑄幣可以存在（儘管有風險警告）。
- 不可轉讓和永久委託鑄幣被阻止。

隨著更多專案在 Token-2022 下啟動——特別是使用受監管鑄幣的「機構」群體——Raydium 的支援將其定位為該類流動性的場所。

## 前瞻性依賴

可能改變 Raydium 生態系統位置的監視項目：

- **Solana 驗證者多樣化**：如果 Firedancer 達到主導地位，效能特性可能會改變。
- **跨鏈橋接**：Raydium 一直在研究其他 L1/L2 的擴展。尚未部署。
- **Jito 的演進**：區塊引擎和 DeFi 之間的持續整合可能改變 MEV 動態。
- **鏈上訂單簿（Phoenix）**：持續成熟可能將某些 AMM 式流量轉移到訂單簿。
