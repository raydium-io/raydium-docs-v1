## 本頁內容

下方的流程涵蓋整合者相關的生命週期：

1. 帳戶設定 — 存入 USDC 並向 Orderly 註冊帳戶。
2. 已驗證的 REST 呼叫 — 請求簽署以進行訂單下單、取消和帳戶查詢。
3. 交易 — 下市場/限價單、取消、取得部位和成交。
4. 市場資料 — 訂閱訂單簿和交易 WebSocket。
5. 提領 — 啟動提領回錢包。

這些程式碼片段針對 Node.js + TypeScript，使用 `@solana/web3.js` 和 `tweetnacl` 進行 Ed25519 簽署。它們是**起點** — Orderly 的 API 表面很廣泛且變化速度比本頁快；在發佈生產程式碼之前，務必檢查 Orderly 的最新文件。

## 設定

```ts
import { Connection, Keypair, PublicKey, clusterApiUrl } from "@solana/web3.js";
import nacl from "tweetnacl";
import bs58 from "bs58";
import fs from "node:fs";

// 1. Solana 錢包 — 擁有 USDC，簽署存入/提領交易。
const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

// 2. Orderly 交易金鑰 — 用於簽署 API 請求的獨立 Ed25519 金鑰對。
//    不是 Solana 錢包。生成一次，保持機密，在各個工作階段中重複使用。
const orderlyKey = nacl.sign.keyPair();   // ed25519
const orderlyPubB58 = "ed25519:" + bs58.encode(orderlyKey.publicKey);

// 3. Orderly 基礎 URL。Raydium 使用 Orderly 的主網主機。
const ORDERLY_BASE = "https://api.orderly.org";
const BROKER_ID    = "raydium";   // Raydium 在 Orderly 上的代理命名空間
const CHAIN_ID     = "solana";    // 用於跨鏈帳戶註冊
```

Orderly 交易金鑰**不是**你的錢包金鑰對。它是一個請求簽署金鑰，你在首次使用時向錢包註冊；你可以在不觸及資金的情況下輪換它。將其視為工作階段憑證。

## 帳戶註冊

在下任何訂單之前，向 Orderly 註冊錢包：

```ts
import { encodeUserSettlement } from "./eip712-helpers"; // 查看 Orderly 文件以取得確切的承載

// 1. 從 Orderly 請求註冊 nonce。
const nonceResp = await fetch(`${ORDERLY_BASE}/v1/registration_nonce`).then(r => r.json());
const registrationNonce = nonceResp.data.registration_nonce;

// 2. 使用 Solana 錢包簽署註冊承載（Solana 上的 EIP-712 風格
//    實現為結構化訊息；Orderly 的 SDK 提供編碼器）。
const payload = encodeUserSettlement({
  brokerId: BROKER_ID,
  chainId: CHAIN_ID,
  registrationNonce,
  timestamp: Date.now(),
});
const walletSig = nacl.sign.detached(Buffer.from(payload), owner.secretKey);

// 3. 註冊，包括 Orderly Ed25519 交易金鑰。
const reg = await fetch(`${ORDERLY_BASE}/v1/register_account`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: payload,
    signature: bs58.encode(walletSig),
    userAddress: owner.publicKey.toBase58(),
    orderlyKey: orderlyPubB58,
  }),
}).then(r => r.json());

console.log("Account ID:", reg.data.account_id);
```

帳戶 ID 對於每個 `(broker_id, wallet_address)` 對都是確定性的 — 註冊是冪等的。如果錢包已經向 Raydium 的代理註冊，呼叫會返回相同的帳戶 ID，而不會建立新帳戶。

## 存入 USDC

存入會將 USDC 從錢包 ATA 移至 Orderly 的結算保管庫。它們是鏈上 Solana 交易：

```ts
// 使用 Orderly 的 Solana 程式建立存入指令（保管庫程式 ID 發佈在
// 他們的文件中；動態拉取而不是硬編碼）。
const vaultProgramId = new PublicKey("<orderly_solana_vault_program_id>");

const depositIx = await buildOrderlyDepositIx({
  vaultProgramId,
  user: owner.publicKey,
  brokerId: BROKER_ID,
  amountUsdc: BigInt(100_000_000),    // 100 USDC（6 位小數）
});

const tx = new Transaction().add(depositIx);
const sig = await connection.sendTransaction(tx, [owner]);
await connection.confirmTransaction(sig, "confirmed");
console.log("Deposit tx:", sig);
```

約 30 秒後，Orderly 的中繼器會索引存入，餘額會顯示在帳戶的可用保證金下。查詢 `/v1/client/holding` 以確認：

```ts
const holdingResp = await orderlyAuthGet("/v1/client/holding");
console.log("Balances:", holdingResp.data.holding);
```

（`orderlyAuthGet` 定義如下 — 每個已驗證的呼叫都通過它。）

## 請求簽署輔助函式

每個對 Orderly 的已驗證 REST 呼叫都帶有 Ed25519 簽署，簽署內容為 `(timestamp + method + path + body)`：

```ts
async function orderlyAuthRequest(
  method: "GET" | "POST" | "PUT" | "DELETE",
  path: string,
  body?: unknown,
): Promise<any> {
  const ts   = Date.now().toString();
  const json = body ? JSON.stringify(body) : "";
  const msg  = `${ts}${method}${path}${json}`;
  const sig  = nacl.sign.detached(Buffer.from(msg), orderlyKey.secretKey);

  const resp = await fetch(ORDERLY_BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json",
      "orderly-account-id":  /* 已註冊的 account_id */ "",
      "orderly-key":         orderlyPubB58,
      "orderly-signature":   bs58.encode(sig),
      "orderly-timestamp":   ts,
    },
    body: json || undefined,
  });
  return resp.json();
}

const orderlyAuthGet  = (p: string)            => orderlyAuthRequest("GET",  p);
const orderlyAuthPost = (p: string, b: object) => orderlyAuthRequest("POST", p, b);
const orderlyAuthDel  = (p: string)            => orderlyAuthRequest("DELETE", p);
```

重放保護：時間戳記與伺服器時鐘相差超過 5 秒的請求會被拒絕。同步你的時鐘（NTP）並避免提前簽署請求。

## 下市場單

```ts
const marketResp = await orderlyAuthPost("/v1/order", {
  symbol:        "PERP_SOL_USDC",
  order_type:    "MARKET",
  side:          "BUY",
  order_quantity: 1.0,        // 1 SOL 的部位
  reduce_only:    false,
});

if (marketResp.success) {
  console.log("Order ID:", marketResp.data.order_id);
} else {
  console.error("Reject:", marketResp.message);
}
```

市場單立即執行。回應返回結果的 `order_id` 加上狀態。成交通過 WebSocket 傳來（見下方）；REST 回應本身不會阻塞直到完全成交。

## 下限價單（Post-Only）

```ts
const limitResp = await orderlyAuthPost("/v1/order", {
  symbol:         "PERP_SOL_USDC",
  order_type:     "LIMIT",
  side:           "SELL",
  order_quantity: 0.5,
  order_price:    140.50,
  // 旗標組合：
  // post_only: true 使這成為只做市商的訂單 — 如果會穿過則取消。
  // reduce_only / time_in_force 可獨立設定。
  post_only:      true,
});
console.log(limitResp);
```

對於 `IOC` / `FOK`，設定 `time_in_force: "IOC"` 或 `"FOK"`。查看 [`products/perps/order-types`](/zh-Hant/products/perps/order-types) 以了解每個旗標的語義。

## 取消訂單

```ts
// 按訂單 ID
await orderlyAuthDel(`/v1/order?order_id=${orderId}&symbol=PERP_SOL_USDC`);

// 取消某個交易對上的所有訂單
await orderlyAuthDel(`/v1/orders?symbol=PERP_SOL_USDC`);
```

取消會同步確認，但實際取消可能與成交競爭。始終通過輪詢 `/v1/orders` 或監視 WebSocket 進行協調 — 假設取消成功而不確認可能導致重複或意外部位。

## 取得開放部位

```ts
const posResp = await orderlyAuthGet("/v1/positions");
for (const p of posResp.data.rows) {
  console.log(
    p.symbol,
    "size:",  p.position_qty,
    "entry:", p.average_open_price,
    "unrealized:", p.unsettled_pnl,
  );
}
```

負的 `position_qty` 是空頭，正的是多頭。`position_qty == 0` 表示部位已平倉，但該列可能會保留到下次清理。

## 取得成交歷史

```ts
const fills = await orderlyAuthGet(
  "/v1/trades?symbol=PERP_SOL_USDC&start_t=" + (Date.now() - 86_400_000)
);
for (const t of fills.data.rows) {
  console.log(t.executed_timestamp, t.side, t.executed_quantity, "@", t.executed_price);
}
```

時間引數是毫秒 Unix 時間戳記。預設頁面大小為 25 列；使用 `page` 和 `size` 查詢參數進行分頁。

## WebSocket：市場資料

```ts
import WebSocket from "ws";

const ws = new WebSocket(`wss://ws.orderly.org/ws/stream/${accountId}`);

ws.on("open", () => {
  // 公開市場資料：一個交易對的訂單簿增量 + 交易
  ws.send(JSON.stringify({ id: "ob1", topic: "orderbook@PERP_SOL_USDC" }));
  ws.send(JSON.stringify({ id: "tr1", topic: "trade@PERP_SOL_USDC" }));
});

ws.on("message", (raw) => {
  const msg = JSON.parse(raw.toString());
  if (msg.topic?.startsWith("orderbook@")) {
    // 深度增量：{ bids: [[price, qty], ...], asks: [[price, qty], ...] }
    applyOrderbookDelta(msg.data);
  } else if (msg.topic?.startsWith("trade@")) {
    console.log("trade:", msg.data);
  }
});
```

對於**私有**串流（你的成交、部位更新、餘額變化），WebSocket 必須經過驗證。發送一個簽署的 `subscribe` 承載，簽署方式與 REST 請求相同，範圍限於你的帳戶 ID。Orderly 的文件有確切的承載形狀；它偶爾會變化，所以不要在這裡硬編碼特定的架構。

## 提領 USDC

```ts
// 1. 請求提領。
const wRes = await orderlyAuthPost("/v1/withdraw_request", {
  token:  "USDC",
  chain_id: CHAIN_ID,
  amount: 50.0,                          // 人類單位
  receiver: owner.publicKey.toBase58(),
});

console.log("Withdrawal request id:", wRes.data.withdraw_id);
```

Orderly 將提領中繼到鏈上的接收者地址。有一筆固定的 **1 USDC** 提領費用（見 [`products/perps/fees`](/zh-Hant/products/perps/fees)）。鏈上轉帳在正常情況下在 1–2 分鐘內進行；在擁塞期間預期更長。

## 陷阱

- **不要在環境之間重複使用交易金鑰。** 針對你的錢包註冊的單個 Orderly 交易金鑰與一個 Solana 主網帳戶相關聯。如果你還需要 devnet 或 staging，為每個環境生成一個獨立的金鑰。
- **時間同步。** Orderly 的時鐘偏差容限很緊（±5 秒）。在長時間執行的服務上，NTP 漂移最終會破壞簽署。定期重新同步。
- **WebSocket 重新連接。** 公開 WS 在 Orderly 升級期間偶爾會斷開連接。實現指數退避並在重新開啟時重新訂閱。
- **速率限制。** REST 呼叫按帳戶進行分層速率限制。當你有超過 5 個訂單要取消時，通過 `cancel_all` 進行批量取消，而不是迴圈 `cancel`-by-id。
- **部位方向是隱含的。** 在 `PERP_SOL_USDC` 上的 `BUY` 訂單開啟或延伸多頭；`SELL` 開啟或延伸空頭 — 但如果你已經是多頭，`SELL` *減少*（並可能翻轉）部位，因為 Raydium Perps 是單向模式。在下訂單前始終檢查當前部位，如果方向很重要。
- **融資和清算與訂單流分開。** 融資支付和清算顯示為單獨的事件串流；它們不是「訂單」。如果你需要觀察它們，訂閱相關的私有 WS 主題。
