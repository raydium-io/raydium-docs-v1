## CPMM 資金池的六個帳戶

每個 CPMM 資金池完全由 CPMM 程式下的六個程式衍生地址（PDA）加上它引用的一個共享 `AmmConfig` 帳戶來描述。一旦你有了兩個 mint，就可以確定性地推導出所有內容，無需接觸網路。

| 帳戶 | 種子 | 擁有者 | 用途 |
|---------|---------|-------|---------|
| `authority` | `"vault_and_lp_mint_auth_seed"` | CPMM | 每次金庫移動和每次 LP mint/burn 的簽署者。在**所有** CPMM 資金池間共享。 |
| `poolState` | `"pool"`、`ammConfig`、`token0Mint`、`token1Mint` **或**任何簽署者提供的隨機金鑰對 | CPMM | 資金池的狀態結構——mint 對、金庫餘額、LP 供應量、費用累積、觀察指標。CPMM `Initialize` 指令接受從四個種子衍生的規範 PDA **或**由建立者簽署的任意金鑰對。隨機金鑰對路徑存在是為了防止搶先攻擊，其中對手監視記憶池並競速在合法建立者之前佔據規範 PDA。 |
| `lpMint` | `"pool_lp_mint"`、`poolState` | SPL Token | 資金池的 LP 代幣。供應量 = 未償 LP 總額。Mint 權限 = CPMM authority PDA。 |
| `vault0` | `"pool_vault"`、`poolState`、`token0Mint` | SPL Token / Token-2022 | 持有資金池的 token0 餘額。由 authority PDA 擁有。 |
| `vault1` | `"pool_vault"`、`poolState`、`token1Mint` | SPL Token / Token-2022 | 持有資金池的 token1 餘額。由 authority PDA 擁有。 |
| `observation` | `"observation"`、`poolState` | CPMM | 用於 TWAP 的價格樣本環形緩衝區。在每次交換時寫入。 |

以及共享配置：

| 帳戶 | 種子 | 擁有者 | 用途 |
|---------|---------|-------|---------|
| `ammConfig` | `"amm_config"`、`index: u16` | CPMM | 持有交易/協議/基金/建立者費率和管理員金鑰。每個「費用層級」一個。Poolstate 在建立時綁定到一個，之後無法更改。 |

## 僅從兩個 mint 推導資金池

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";

const CPMM_PROGRAM_ID = new PublicKey(
  "CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C"
); // mainnet — see reference/program-addresses

function u16ToBytes(n: number): Buffer {
  const b = Buffer.alloc(2);
  b.writeUInt16BE(n);
  return b;
}

// token0 < token1 by byte order. Getting this wrong yields a valid PDA
// that points at a nonexistent pool.
function sortMints(a: PublicKey, b: PublicKey): [PublicKey, PublicKey] {
  return Buffer.compare(a.toBuffer(), b.toBuffer()) < 0 ? [a, b] : [b, a];
}

export function deriveCpmmAccounts(
  mintA: PublicKey,
  mintB: PublicKey,
  ammConfigIndex = 0,
) {
  const [token0Mint, token1Mint] = sortMints(mintA, mintB);

  const [ammConfig] = PublicKey.findProgramAddressSync(
    [Buffer.from("amm_config"), u16ToBytes(ammConfigIndex)],
    CPMM_PROGRAM_ID,
  );
  const [authority] = PublicKey.findProgramAddressSync(
    [Buffer.from("vault_and_lp_mint_auth_seed")],
    CPMM_PROGRAM_ID,
  );
  const [poolState] = PublicKey.findProgramAddressSync(
    [
      Buffer.from("pool"),
      ammConfig.toBuffer(),
      token0Mint.toBuffer(),
      token1Mint.toBuffer(),
    ],
    CPMM_PROGRAM_ID,
  );
  const [lpMint] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_lp_mint"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault0] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token0Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [vault1] = PublicKey.findProgramAddressSync(
    [Buffer.from("pool_vault"), poolState.toBuffer(), token1Mint.toBuffer()],
    CPMM_PROGRAM_ID,
  );
  const [observation] = PublicKey.findProgramAddressSync(
    [Buffer.from("observation"), poolState.toBuffer()],
    CPMM_PROGRAM_ID,
  );

  return {
    ammConfig,
    authority,
    poolState,
    lpMint,
    token0Mint,
    token1Mint,
    vault0,
    vault1,
    observation,
  };
}
```

<Tip>
  **推導資金池 PDA 前務必排序 mint。** 種子按位元組順序雜湊兩個 mint，而非使用者順序。具有 `(A, B)` 和 `(B, A)` 的兩個資金池會在鏈上碰撞——排序是程式使映射規範化的方式。
</Tip>

<Note>
  **資金池 ID 並非總是規範 PDA。** `Initialize` 除了上述 PDA 外，還接受任意簽署者金鑰對作為 `pool_state`。如果傳遞的帳戶與規範 PDA 不符，程式要求它是簽署者——即建立者傳遞一個他們簽署的新金鑰對。這是搶先防禦：任何競速搶佔規範 PDA 的第三方都可以被合法建立者使用隨機金鑰對繞過。下游 PDA（`lpMint`、`vault0`、`vault1`、`observation`）仍從 `poolState.key()` 衍生，因此它們對於使用的任何地址都保持唯一。索引資金池時，始終從鏈上狀態發現資金池 ID（例如 CPMM 程式下的 `PoolState` 帳戶），而非推導規範 PDA——後者會遺漏隨機金鑰對資金池。
</Note>

## 帳戶佈局

完整的 Rust 定義位於 [`raydium-cp-swap`](https://github.com/raydium-io/raydium-cp-swap) 源碼中。下面的欄位是你在整合中會讀取的。

### `PoolState`

```rust
// programs/cp-swap/src/states/pool.rs
pub struct PoolState {
    pub amm_config: Pubkey,               // binds this pool to an AmmConfig
    pub pool_creator: Pubkey,             // who ran initialize
    pub token_0_vault: Pubkey,            // == vault0 PDA
    pub token_1_vault: Pubkey,            // == vault1 PDA

    pub lp_mint: Pubkey,
    pub token_0_mint: Pubkey,
    pub token_1_mint: Pubkey,

    pub token_0_program: Pubkey,          // SPL Token or Token-2022 program
    pub token_1_program: Pubkey,

    pub observation_key: Pubkey,          // == observation PDA
    pub auth_bump: u8,
    pub status: u8,                       // bitmask: deposit | withdraw | swap
    pub lp_mint_decimals: u8,
    pub mint_0_decimals: u8,
    pub mint_1_decimals: u8,

    pub lp_supply: u64,                   // mirrors lp_mint supply
    pub protocol_fees_token_0: u64,
    pub protocol_fees_token_1: u64,
    pub fund_fees_token_0: u64,
    pub fund_fees_token_1: u64,

    pub open_time: u64,                   // unix; swaps rejected before this
    pub recent_epoch: u64,

    // Creator-fee state (added after the original layout):
    pub creator_fee_on: u8,               // 0=BothToken, 1=OnlyToken0, 2=OnlyToken1
    pub enable_creator_fee: bool,
    pub padding1: [u8; 6],
    pub creator_fees_token_0: u64,
    pub creator_fees_token_1: u64,

    pub padding: [u64; 28],
}
```

實際要讀取的內容：

- **`lp_supply`** ——資金池對 LP mint 總供應量的內部鏡像。用於 LP 份額計算；該值應與 mint 的鏈上供應量相符，但從 `PoolState` 讀取可避免額外的帳戶提取。
- **`protocol_fees_token{0,1}`**、**`fund_fees_token{0,1}`** ——*累積*的未掃除費用。這些不影響交換定價；它們位於金庫中，直到呼叫 `CollectProtocolFee` / `CollectFundFee`。
- **`status`** ——控制是否允許 `Swap`、`Deposit`、`Withdraw` 的位元遮罩。由管理員透過 `UpdatePoolStatus` 更新。SDK 在建立交易前檢查此項；如果你直接進行 CPI，請自行檢查。
- **`token0_program` / `token1_program`** ——為每個金庫 CPI 的代幣程式。一個可以是經典 SPL Token，另一個是 Token-2022；它們是獨立的。
- **`open_time`** ——Unix 時間戳。此時間前的交換失敗。存款在 `open_time` 前被允許，以便資金池可以被初始化。
- **`creator_fee_on` / `enable_creator_fee`** ——共同控制此資金池是否啟用可選建立者費用以及從交換的哪一側收取。`enable_creator_fee == false` 完全清零建立者費用路徑。啟用時，`creator_fee_on` 選擇：`0` = 從交換輸入的任何代幣收取費用（`BothToken`）；`1` = 僅從 `token_0` 收取費用（跳過 `token_1 → token_0` 交換）；`2` = 僅從 `token_1` 收取費用。在資金池建立時透過 `InitializeWithPermission` 設定；之後無法更改。
- **`creator_fees_token_{0,1}`** ——累積的建立者費用，由 `CollectCreatorFee` 或 `CollectCreatorFeePermissionless` 掃除。兩條路徑都清零完整計數器；無許可路徑將收款人固定為 `pool_creator` 的規範 ATA。

### `AmmConfig`

```rust
pub struct AmmConfig {
    pub bump: u8,
    pub disable_create_pool: bool,
    pub index: u16,                       // matches the seed
    pub trade_fee_rate: u64,              // e.g., 2500 = 0.25%
    pub protocol_fee_rate: u64,           // fraction of trade fee to protocol
    pub fund_fee_rate: u64,               // fraction of trade fee to fund
    pub create_pool_fee: u64,             // paid once at init (in SOL or token)
    pub protocol_owner: Pubkey,           // can call CollectProtocolFee
    pub fund_owner: Pubkey,               // can call CollectFundFee
    pub creator_fee_rate: u64,            // optional pool-creator fee rate (1/1_000_000 of volume)
    pub padding: [u64; 15],
}
```

需要注意三件事：

1. **`trade_fee_rate` 和 `creator_fee_rate` 是交易量的分數**，兩者都以 `1/1_000_000` 單位計。`2500` 表示交易量的 0.25%。**`protocol_fee_rate` 和 `fund_fee_rate` 是*交易費用*的分數**（不是交易量），使用相同的 `1/1_000_000` 分母。建立者費用**不是**交易費用的分數——它是自己獨立的費率。完整算術在 [`products/cpmm/fees`](/zh-Hant/products/cpmm/fees)。
2. **`index` 是 `u16`**，所以種子雜湊使用 2 位元組大端序。位元組順序偏差一是常見的整合錯誤。
3. **`AmmConfig` 在資金池層級是不可變的。** 資金池在建立時指向一個 `AmmConfig`，之後永不切換。費用變更會傳播，因為資金池在每次交換時讀取配置——但資金池無法在費用層級間移動。

關於建立者費用的說明：**費率本身**（`creator_fee_rate`）位於 `AmmConfig` 上，在費用層級間共享。特定資金池是否實際收取它（`enable_creator_fee`）以及它在交換的哪一側（`creator_fee_on`）位於 `PoolState` 上。建立者費用**獨立於**交易費用——它是自己的費率，累積到自己的計數器（`creator_fees_token_{0,1}`），永不減少交易費用的 LP / 協議 / 基金份額。掃除透過 `CollectCreatorFee` 或目標受限的 `CollectCreatorFeePermissionless`。完整機制見 [`products/cpmm/fees`](/zh-Hant/products/cpmm/fees)。

### `Permission`

由 `InitializeWithPermission` 使用的小型存取控制帳戶。CPMM 程式支持許可資金池建立路徑，以便其他程式（例如 LaunchLab 在將代幣升級到 CPMM 時）可以證明他們有權針對給定 `AmmConfig` 建立資金池。

```rust
pub struct Permission {
    pub authority: Pubkey,    // who is allowed to call InitializeWithPermission
    pub padding: [u64; 8],
}
```

Permission PDA 由 CPMM 管理員或專用許可 PDA 建立者權限透過 `CreatePermissionPda` 建立。只有 CPMM 管理員可以透過 `ClosePermissionPda` 撤銷它。終端使用者不直接與此帳戶互動——它是跨程式流的管道。見 [`security/admin-and-multisig`](/zh-Hant/security/admin-and-multisig) 了解角色邊界，見 [`reference/program-addresses`](/zh-Hant/reference/program-addresses) 了解規範地址。

### 金庫和 Token-2022

`vault0` 和 `vault1` 由 CPMM authority PDA 擁有，其代幣程式擁有者（`token_program`）是 SPL Token 或 Token-2022，由 mint 的程式在資金池建立時決定。資金池透明地處理兩種情況——你在 `Swap` / `Deposit` / `Withdraw` 指令帳戶中為每一側傳遞正確的代幣程式 ID。

CPMM 在資金池建立時強制執行嚴格的**擴展允許清單**（`utils/token.rs` 中的 `is_supported_mint`）。Token-2022 mint 只有在它攜帶的**每個**擴展都在此清單上時，才能在 CPMM 資金池中使用：

- **`TransferFeeConfig`。** 由 mint 在每次轉移時應用。資金池在 `SwapBaseInput` 存款時位於接收方，在提款時位於發送方。程式計算登陸金庫的**淨**金額並相應設定曲線。見 [`algorithms/token-2022-transfer-fees`](/zh-Hant/algorithms/token-2022-transfer-fees)。
- **`MetadataPointer`** 和 **`TokenMetadata`。** 標準鏈上 mint 元資料。對交換數學無影響。
- **`InterestBearingConfig`。** Mint 的 UI 金額累積利息。金庫儲存原始金額；曲線僅在原始金額上運作。顯示 APR 的 UI 應呼叫 Token-2022 幫助程式來呈現 UI 金額。
- **`ScaledUiAmount`。** UI 顯示縮放擴展。與 `InterestBearingConfig` 相同的處理——曲線使用原始金額。

任何其他擴展——`PermanentDelegate`、`TransferHook`、`DefaultAccountState`、`NonTransferable`、`ConfidentialTransfer`、`Group`/`GroupMember`、`MintCloseAuthority` 等——導致 `Initialize` 以 `NotSupportMint` 拒絕。例外是程式中的小型硬編碼 **mint 白名單**（少數特定公鑰），它繞過擴展檢查；用於逐案例登錄特定 mint。

經過驗證的擴展清單和 mint 白名單位於 CP-Swap 源碼中的 `programs/cp-swap/src/utils/token.rs`，可能隨未來程式升級而變更。

### Observation

觀察帳戶是 `ObservationState` 項目的環形緩衝區，每個項目儲存 `block_timestamp` 和**累積價格**。在每次交換時，如果自上次以來經過足夠時間，程式會附加新觀察。TWAP 透過讀取兩個觀察並除以 `Δcumulative / Δtime` 計算。

```rust
// OBSERVATION_NUM is hardcoded in the program to 100.
pub const OBSERVATION_NUM: usize = 100;

pub struct Observation {
    pub block_timestamp:              u64,
    pub cumulative_token_0_price_x32: u128,   // Q32.32, top 64 bits left for overflow
    pub cumulative_token_1_price_x32: u128,
}

pub struct ObservationState {
    pub initialized:           bool,
    pub observation_index:     u16,                            // circular index
    pub pool_id:               Pubkey,
    pub observations:          [Observation; OBSERVATION_NUM], // 100 entries
    pub last_update_timestamp: u64,                            // timestamp of the most recent append
    pub padding:               [u64; 3],
}
```

環形緩衝區大小為**100 個觀察**。每個觀察 40 位元組，所以陣列單獨就是 4,000 位元組；完整 `ObservationState` PDA 在周圍欄位和判別器後約 4,100 位元組。

兩個消費者規則：

- **不要將單個觀察用作價格。** 它是*累積*，不是現貨價格。使用其中兩個計算 TWAP。
- **選擇至少相隔一個區塊的觀察。** 同一區塊內的交換可能不會產生新觀察；讀取連續的可能返回相同記錄。

更多數學見 [`products/clmm/accounts`](/zh-Hant/products/clmm/accounts)。

## 帳戶生命週期

| 事件 | 建立的帳戶 | 銷毀的帳戶 |
|-------|------------------|---------------------|
| `Initialize` | `poolState`、`lpMint`、`vault0`、`vault1`、`observation` | — |
| `Deposit` | —（可能建立使用者 LP ATA） | — |
| `Withdraw` | — | — |
| `Swap` | —（可能建立使用者目標 ATA） | — |
| `CollectProtocolFee` | — | — |
| `CollectFundFee` | — | — |
| `UpdatePoolStatus` | — | — |

CPMM 資金池及其 PDA **永不關閉**。即使在零流動性時，`poolState` 仍然存在。這是刻意的：稍後重新初始化相同資金池會保留其歷史觀察緩衝區，其 PDA 推導保持穩定。
