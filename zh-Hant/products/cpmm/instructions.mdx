## 指令摘要

| 判別器名稱 | 簽署者 | 功能 |
|-------|-----------|--------------|
| `Initialize` | 池創建者 | 從兩個鑄幣廠和一個 `AmmConfig` 建立新的 CPMM 池。無需許可；任何人都可以呼叫。在新池上硬編碼 `enable_creator_fee = false`。`pool_state` 帳戶可以是規範 PDA 或新的隨機金鑰對（見 Initialize 帳戶）。 |
| `InitializeWithPermission` | 支付者 + `Permission` PDA 持有者 | `Initialize` 的許可變體。呼叫者（`payer`）必須擁有從其自身公鑰衍生的 `Permission` PDA。由需要受限池創建的平台使用（例如 LaunchLab 畢業）。讓呼叫者固定 `creator_fee_on`（`BothToken` / `OnlyToken0` / `OnlyToken1`）並在新池上強制 `enable_creator_fee = true`。`pool_state` 上的 `creator` 欄位設定為單獨傳遞的 `creator` 帳戶，而非支付者。與 `Initialize` 相同的規範 PDA 或隨機金鑰對靈活性適用於 `pool_state`。 |
| `Deposit` | LP | 在兩個代幣中新增流動性；接收 LP 代幣。 |
| `Withdraw` | LP | 燒毀 LP 代幣；按比例接收兩個基礎代幣。 |
| `SwapBaseInput` | 交換者 | 精確輸入交換（`amount_in` 進入，≥ `minimum_amount_out` 輸出）。 |
| `SwapBaseOutput` | 交換者 | 精確輸出交換（≤ `maximum_amount_in` 進入，`amount_out` 輸出）。 |
| `CollectProtocolFee` | `protocol_owner`（來自 `AmmConfig`） | 從保管庫掃除累積的協議費用。 |
| `CollectFundFee` | `fund_owner`（來自 `AmmConfig`） | 從保管庫掃除累積的基金費用。 |
| `CollectCreatorFee` | `pool_creator` | 掃除累積的創建者費用（如果啟用了創建者費用）。 |
| `CollectCreatorFeePermissionless` | 任何支付者 | 將所有累積的創建者費用掃除到 `pool_creator` 的規範代幣帳戶。支付者可以建立遺漏的接收者 ATA，但無法重定向轉帳。 |
| `UpdatePoolStatus` | `admin` | 透過位元遮罩暫停/恢復池上的特定操作。 |
| `UpdateAmmConfig` | `admin` | 變更費率或 `AmmConfig` 上的協議/基金所有者。 |
| `CreateAmmConfig` | `admin` | 建立新的費用層級（新 `AmmConfig` 帳戶）。 |
| `CreatePermissionPda` | `admin` 或委派的許可 PDA 創建者 | 鑄造 `Permission` PDA，允許特定授權呼叫 `InitializeWithPermission`。 |
| `ClosePermissionPda` | `admin` 或專用許可 PDA 創建者 | 撤銷先前發行的 `Permission` PDA。自 2026-09 升級以來，專用創建者授權也可以關閉其發行的授權；之前僅限管理員。 |
| `CreateSupportMintAssociated` | `admin` 或專用支援鑄幣廠所有者 | 透過建立其 `SupportMintAssociated` PDA 來登記否則會失敗擴充功能允許清單的 Token-2022 鑄幣廠。 |
| `CloseSupportMintAssociated` | `admin` 或專用支援鑄幣廠所有者 | 移除鑄幣廠的登記。 |
| `CollectExcessLamports` | `admin` 或專用收集 lamports 錢包 | 從 CPMM 控制的保管庫、LP 鑄幣廠和 PDA 掃除超過租金豁免最低額的 lamports。新增於 2026-09。 |

狀態位元遮罩：每個池的 `status` 是一個 `u8`，其中位元 0 = 禁用存款，位元 1 = 禁用提取，位元 2 = 禁用交換（程式中的 `PoolStatusBitIndex { Deposit, Withdraw, Swap }`）。清除位元表示允許操作；設定位元表示已暫停。`UpdatePoolStatus` 取得原始 `u8` 並覆寫現有值。

下一節詳細介紹每一個。帳戶順序遵循 CPMM IDL；SDK 和 `raydium-cp-swap/programs/cp-swap/src/instructions` 中的 Rust 用戶端符合此順序。

## `Initialize`

建立新的 CPMM 池。

**參數**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix 時間戳；此前拒絕交換
```

**帳戶**（W = 可寫，S = 簽署者）

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 支付租金；記錄為 `pool_state.pool_creator`。 |
| 2 | `amm_config` |   |   | 選定的費用層級。 |
| 3 | `authority` |   |   | CPMM 全域授權 PDA。 |
| 4 | `pool_state` | W | S* | 在此 `init`。**要麼**是規範 PDA `["pool", amm_config, token_0_mint, token_1_mint]`，**要麼**是新的隨機金鑰對 — 當不是規範 PDA 時，程式要求 `pool_state` 簽署（`require_eq!(pool_account_info.is_signer, true)`）。隨機金鑰對路徑讓創建者躲避規範 PDA 上的搶先交易嘗試。下游 PDA（`lp_mint`、`vaults`、`observation_state`）無論如何都從 `pool_state.key()` 衍生。 |
| 5 | `token_0_mint` |   |   | 已排序：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | 在此 `init`。授權設定為 `authority`。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` 的來源 ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` 的來源 ATA。 |
| 10 | `creator_lp_token` | W |   | 建立者在 `lp_mint` 上的 ATA。`init`（不是 `init_if_needed`） — 它必須尚不存在，而且它也不可能存在，因為 `lp_mint` 是在同一條指令中建立的。 |
| 11 | `token_0_vault` | W |   | 在此 `init`。由 `authority` 擁有。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 創建者支付的 `create_pool_fee` 的目的地 ATA。 |
| 14 | `observation_state` | W |   | 在此 `init`。 |
| 15 | `token_program` |   |   | SPL Token（用於 LP 鑄幣廠）。 |
| 16 | `token_0_program` |   |   | SPL Token 或 Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token 或 Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` 僅在隨機金鑰對路徑上簽署；規範 PDA 路徑在沒有 `pool_state` 簽署的情況下執行。

**前置條件**

- 鑄幣廠已排序（按位元組順序 `token_0_mint < token_1_mint`）。
- 兩個鑄幣廠都不使用 CPMM 允許清單外的擴充功能（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`） — 見 [`products/cpmm/accounts`](/zh-Hant/products/cpmm/accounts#vaults-and-token-2022)。具有 `SupportMintAssociated` PDA（種子 `[b"support_mint", mint]`）的鑄幣廠會跳過擴充功能檢查 — **但你必須把該 PDA 附加到 `remaining_accounts`**。程式只掃描你傳入的帳戶，永遠不會自行載入該 PDA，因此只依賴該登記而不提供帳戶仍會以 `NotSupportMint`（`6007`）失敗。順序無關（比對是依金鑰進行）；為每個需要繞過的鑄幣廠傳入一筆。該登記是自 2026-09 升級移除硬編碼四鑄幣廠白名單以來唯一的繞過方式。
- `creator` 在各自的 ATA 中至少有 `init_amount_0` 和 `init_amount_1`。
- `amm_config.disable_create_pool == false`。

**後置條件**

- `pool_state.lp_supply = sqrt(init_amount_0 * init_amount_1)` — **完整**的平方根。建立者被鑄造 `lp_supply − 100`；那 100 個被鎖定的基礎單位計入 `lp_supply` 但從未鑄造。
- 因此在池的整個生命週期內 `lp_mint.supply == pool_state.lp_supply − 100`。所有 LP 份額計算（存入、提取）都除以 `lp_supply`，所以請使用該欄位，不要以鑄幣廠的鏈上供應量替代。若 `sqrt(...) < 100`，則以 `InitLpAmountTooLess` 還原。
- `observation_state` 已初始化；`observation_index = 0` 且 `pool_id = pool_state.key()`。
- `create_pool_fee` lamports 從創建者轉移到接收者並同步為原生 SOL（它是 wSOL ATA）。
- 池的狀態位元遮罩為 `0`（存款/提取/交換全部啟用）。
- `enable_creator_fee = false` 且 `creator_fee_on = BothToken`。`Initialize` **不**支援啟用創建者費用 — 該路徑是 `InitializeWithPermission`。
- 如果呼叫者傳遞的值 `<= block_timestamp`，`open_time` 會被提升到 `block_timestamp + 1`。交換在 `open_time` 前被拒絕；存款和提取立即進行。

**常見錯誤**（完整清單見 [`reference/error-codes`](/zh-Hant/reference/error-codes)）

- `InvalidInput` — 鑄幣廠未排序或相同。
- `NotSupportMint` — 被阻止的 Token-2022 擴充功能。
- `ExceededSlippage` — 罕見；如果 `init_amount_0/1` 因小數位數不匹配而導致零 LP。

## `Deposit`

按池的比例在兩個代幣中新增流動性。

**參數**

```
lp_token_amount:   u64   // 要鑄造給 LP 的 LP 代幣數量
maximum_token_0:   u64
maximum_token_1:   u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**數學**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

needed_token_0 = ceil(lp_token_amount * total_0 / lp_supply)
transfer_0     = needed_token_0 + inverse_transfer_fee(needed_token_0) // Token-2022
require(transfer_0 <= maximum_token_0, "ExceededSlippage")             // same for side 1
```

有兩個細節值得釘死：按比例的基準是**排除費用後**的金庫總額（`vault_amount_without_fee`，即原始餘額減去累積的協議、基金和建立者計數器），而不是原始金庫餘額；而滑點上限檢查的是付款人實際轉出的金額，也就是*加上* Token-2022 轉帳費用之後的金額，而不是金庫的毛額變動。

`k` 的比例性沒有變化 — 兩側的總額和 `lp_supply` 按相同因子縮放。

**後置條件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（扣除輸入上任何 Token-2022 轉帳費用）。
- `vault_1 += needed_token_1`（扣除輸入上任何 Token-2022 轉帳費用）。

**常見錯誤** — `ExceededSlippage`、`ZeroTradingTokens`、如果存款被暫停則 `InvalidStatus`。

## `Withdraw`

燒毀 LP 代幣並按比例接收兩個基礎代幣。

**參數**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |
| 14 | `memo_program` |   |   |

前 13 個帳戶與 `Deposit` 完全相同，而 `lp_mint` 可寫是因為 LP 代幣被燒毀。`Withdraw` 另外還取用第 14 個帳戶 `memo_program`（約束為 `address = memo::ID`） — `Deposit` 沒有。只有 13 個帳戶的 `Withdraw` 會在 Anchor 反序列化時失敗，因此 LP 無法退出。

**數學**

```
total_0 = vault_0 − protocol_fees_0 − fund_fees_0 − creator_fees_0    // same for side 1

out_token_0     = min(total_0, floor(lp_token_amount * total_0 / lp_supply))
receive_token_0 = out_token_0 − transfer_fee(out_token_0)             // Token-2022
require(receive_token_0 >= minimum_token_0, "ExceededSlippage")       // same for side 1

// As with Deposit: the base is the fee-excluded vault total, and the floor is
// checked against what the LP actually receives, after the transfer fee.
```

**後置條件**

- `lp_supply -= lp_token_amount`。
- 保管庫發送 `out_token_0` / `out_token_1`（總額；使用者接收扣除任何 Token-2022 轉帳費用的淨額）。

## `SwapBaseInput`

精確輸入交換。

**參數**

```
amount_in:            u64
minimum_amount_out:   u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `payer` |   | S |
| 2 | `authority` |   |   |
| 3 | `amm_config` |   |   |
| 4 | `pool_state` | W |   |
| 5 | `input_token_account` | W |   |
| 6 | `output_token_account` | W |   |
| 7 | `input_vault` | W |   |
| 8 | `output_vault` | W |   |
| 9 | `input_token_program` |   |   |
| 10 | `output_token_program` |   |   |
| 11 | `input_token_mint` |   |   |
| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

順序**輸入 → 輸出**由使用者的方向決定，而非池的規範 `token_0 / token_1`。程式透過匹配鑄幣廠來確定哪個保管庫是哪個。

**數學** — 見 [`products/cpmm/math`](/zh-Hant/products/cpmm/math)。

**前置條件**

- `open_time <= now`。
- `pool_status` 允許交換。
- 此授權的兩個鑄幣廠都未暫停或凍結。
- `amount_in > 0`。

**常見錯誤**

- `ExceededSlippage` — `amount_out < minimum_amount_out`。
- `ZeroTradingTokens` — 交易四捨五入為零。
- `NotApproved` — 池透過 `UpdatePoolStatus` 暫停交換。
- `InvalidInput` — 鑄幣廠不符合池的任一保管庫鑄幣廠。

## `CollectProtocolFee`

從保管庫掃除累積的協議費用到協議目的地。

**參數** — 無。

**帳戶**

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `owner` |   | S | 必須等於 `amm_config.protocol_owner` **或**程式硬編碼的管理員密鑰。 |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `amm_config` |   |   |
| 5 | `token_0_vault` | W |   |
| 6 | `token_1_vault` | W |   |
| 7 | `vault_0_mint` |   |   |
| 8 | `vault_1_mint` |   |   |
| 9 | `recipient_token_0_account` | W |   |
| 10 | `recipient_token_1_account` | W |   |
| 11 | `token_program` |   |   |
| 12 | `token_program_2022` |   |   |

**效果**

```
transfer pool_state.protocol_fees_token0 from vault_0 to recipient_0
transfer pool_state.protocol_fees_token1 from vault_1 to recipient_1

pool_state.protocol_fees_token1 = 0
```

**常見錯誤** — 如果簽署者既不是 `amm_config.protocol_owner` 也不是程式管理員，則為 `InvalidOwner`（`6001`）。（此路徑上沒有 `NotApproved`。）

## `CollectFundFee`

與 `CollectProtocolFee` 相同的形狀，但由 `amm_config.fund_owner` 簽署 — 或者同樣地，由程式管理員簽署 — 並將 `fund_fees_*` 計數器歸零。錯誤的簽署者同樣會得到 `InvalidOwner`。

## `CollectCreatorFee`

由 `pool_state.pool_creator` 簽署。它將完整的 `creator_fees_token_0` 和 `creator_fees_token_1` 餘額轉移到創建者的代幣帳戶，然後將兩個計數器歸零。當兩個計數器都為零時，它返回 `NoFeeCollect`。

## `CollectCreatorFeePermissionless`

任何人都可以觸發創建者費用收集。該指令始終將完整的累積餘額發送到由 `pool_state.pool_creator` 擁有的規範關聯代幣帳戶；呼叫者無法選擇另一個創建者或目的地。如果任一 ATA 遺漏，支付者資助其建立。

原始 `CollectCreatorFee` 仍可呼叫，因此現有用戶端保持相容。

**參數** — 無。

**帳戶**

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 任何簽署者；資助遺漏的創建者 ATA。 |
| 2 | `creator` |   |   | 必須等於 `pool_state.pool_creator`；不簽署。 |
| 3 | `authority` |   |   | CPMM 全域保管庫授權 PDA。 |
| 4 | `pool_state` | W |   | 保存累積的創建者費用計數器。 |
| 5 | `token_0_vault` | W |   | 必須符合池的代幣 0 保管庫。 |
| 6 | `token_1_vault` | W |   | 必須符合池的代幣 1 保管庫。 |
| 7 | `vault_0_mint` |   |   | 必須符合 `token_0_vault.mint`。 |
| 8 | `vault_1_mint` |   |   | 必須符合 `token_1_vault.mint`。 |
| 9 | `creator_token_0` | W |   | 創建者的 `vault_0_mint` 規範 ATA；如果遺漏則建立。 |
| 10 | `creator_token_1` | W |   | 創建者的 `vault_1_mint` 規範 ATA；如果遺漏則建立。 |
| 11 | `token_0_program` |   |   | SPL Token 或 Token-2022，符合代幣 0。 |
| 12 | `token_1_program` |   |   | SPL Token 或 Token-2022，符合代幣 1。 |
| 13 | `associated_token_program` |   |   | 建立遺漏的接收者 ATA。 |
| 14 | `system_program` |   |   | 從 `payer` 資助帳戶建立。 |

**效果**

- 將所有 `creator_fees_token_0` 和 `creator_fees_token_1` 從池保管庫轉移到創建者 ATA。
- 將兩個創建者費用計數器歸零並更新 `pool_state.recent_epoch`。
- 當兩個計數器都為零時返回 `NoFeeCollect`。

## `UpdatePoolStatus`

暫停或恢復池上的個別操作。`status` 欄位是位元遮罩：

| 位元 | 旗標 | 設定時的效果 |
|-----|------|-----------------|
| 0 | `DEPOSIT_DISABLED` | `Deposit` 以 `NotApproved` 拒絕。 |
| 1 | `WITHDRAW_DISABLED` | `Withdraw` 拒絕。 |
| 2 | `SWAP_DISABLED` | `SwapBaseInput` / `SwapBaseOutput` 拒絕。 |

**參數**

```
status: u8      // 新位元遮罩
```

**帳戶**

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `authority` |   | S | 必須符合 CPMM 程式上的管理員金鑰。 |
| 2 | `pool_state` | W |   |

管理員金鑰是**編譯進程式**的公鑰（`crate::admin::ID`），不是 BPF 升級授權 — 要更改它需要進行程式升級。其值見 [`reference/program-addresses`](/zh-Hant/reference/program-addresses)，持有者見 [`security/admin-and-multisig`](/zh-Hant/security/admin-and-multisig)。

## `CreateAmmConfig`

建立新的費用層級。

**參數**

```
index:             u16
trade_fee_rate:    u64
protocol_fee_rate: u64
fund_fee_rate:     u64
create_pool_fee:   u64
creator_fee_rate:  u64
```

**帳戶**

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `owner` | W | S | 管理員。 |
| 2 | `amm_config` | W |   | 在此 `init`。 |
| 3 | `system_program` |   |   |

**前置條件**

- 不存在具有相同 `index` 的 `AmmConfig`。
- `protocol_fee_rate + fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE`。

<Note>
  **2026-09 中變更：新配置的費用所有者不再來自簽署者。** `create_amm_config` 現在將程式的硬編碼 `protocol_fee_owner::ID` 寫入 `protocol_owner` 並將 `fund_fee_owner::ID` 寫入 `fund_owner`，而不是將管理員簽署者的金鑰複製到兩者。地址在 [`reference/program-addresses`](/zh-Hant/reference/program-addresses#cpmm-fee-owner-wallets)。

  後果：新建立的 `AmmConfig` 上的費用會進入專用的費用錢包，而不是管理員的錢包。管理員仍然是收取時可接受的*簽署者* — `CollectProtocolFee` / `CollectFundFee` 接受 `amm_config.protocol_owner` / `fund_owner` **或** `crate::admin::ID` — 因此不需要輪換任何東西就能清掃；改變的只是收益預設的去向。**現有 `AmmConfig` 帳戶不會被重寫** — 儲存在其上的任何內容仍然管理，因此始終從帳戶讀取 `protocol_owner` / `fund_owner` 而不是假設任一值。`UpdateAmmConfig` 參數 `3` 和 `4` 仍然可以輪換它們。
</Note>

## `UpdateAmmConfig`

變更現有 `AmmConfig` 上的費率或所有權。取得 `param: u8`（要更新哪個欄位）和 `value: u64`。完整的分派表：

- `param = 0` → `trade_fee_rate`（斷言 `trade_fee_rate + creator_fee_rate < 1_000_000`）
- `param = 1` → `protocol_fee_rate`（斷言 `≤ 1_000_000` 且 `+ fund_fee_rate ≤ 1_000_000`）
- `param = 2` → `fund_fee_rate`（斷言 `≤ 1_000_000` 且 `+ protocol_fee_rate ≤ 1_000_000`）
- `param = 3` → `protocol_owner`。新金鑰**不**在 `value` 中：請把它附加為 `remaining_accounts[0]`（唯讀即可）。它不得為預設公鑰，而省略該帳戶會在 `unwrap()` 上 panic。
- `param = 4` → `fund_owner`。與 `3` 相同的機制。
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`（任何非零 `value` 都會停用）
- `param = 7` → `creator_fee_rate`（斷言 `creator_fee_rate + trade_fee_rate < 1_000_000`）

任何其他 `param` 都會返回 `InvalidInput`。

變更由管理員簽署，影響**綁定到此 `AmmConfig` 的每個池**在下一次交換時。無遷移；池只是讀取新值。

## `CollectExcessLamports`

管理員掃除坐在 CPMM 控制的帳戶上租金豁免最低額之上的 lamports。在 2026-09 升級中新增，以便協議可以回收 [SIMD-0437 租金減少](/zh-Hant/solana-fundamentals/rent-and-reclaimable-rent) 在每個步驟之前建立的帳戶上留下的過度資金。

只有超額移動。代幣餘額、帳戶資料、所有者、池狀態和曲線保持不變，該指令對已在其最低值的帳戶是無操作 — 因此在每次推出步驟後重新執行是安全的。

**參數** — 無。

**帳戶**

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `collect_lamports_wallet` | W | S | 每個掃除 lamport 的目的地。必須是 CPMM 程式管理員或專用收集 lamports 錢包 — 見 [`reference/program-addresses`](/zh-Hant/reference/program-addresses#excess-lamports-collection-wallets)。任何其他簽署者以 `InvalidOwner` 失敗。 |
| 2 | `authority` |   |   | CPMM 保管庫和 LP 鑄幣廠授權 PDA，種子為 `[b"vault_and_lp_mint_auth_seed"]`。它簽署代幣程式 CPI。 |
| 3 | `token_program` |   |   | SPL Token。 |
| 4 | `token_program_2022` |   |   | Token-2022。兩者都無條件要求；程式按來源帳戶選擇。 |
| 5.. | `remaining_accounts` | W |   | `M` 個要掃除的來源帳戶，任意數量，任意順序。 |

**每個來源帳戶的處理方式**

程式根據來源帳戶的 `owner` 進行分派：

| 來源帳戶所有者 | 處理 |
|---|---|
| SPL Token 或 Token-2022，非原生代幣帳戶或鑄幣廠 — 池保管庫和 LP 鑄幣廠 | CPI `WithdrawExcessLamports`（代幣程式判別器 `38`），由 `authority` 簽署。 |
| SPL Token 或 Token-2022，**原生**（wSOL）代幣帳戶 | `WithdrawExcessLamports` 拒絕原生帳戶。程式 CPI `SyncNative`，測量包裝的 `amount` 增長了多少，`UnwrapLamports`（判別器 `45`）恰好是該增量，然後要求包裝的餘額等於其預同步值 — 否則 `LamportsCalculateError`（`6015`）。因此 SOL 端池保管庫保持其完整流動性。 |
| CPMM 程式本身 — `PoolState`、`AmmConfig`、`ObservationState`、`Permission`、`SupportMintAssociated` | 程式直接將帳戶扣除到 `rent.minimum_balance(data_len)`。 |
| 任何其他 | **無聲跳過。** 無錯誤，無 lamports 移動。 |

因為它取得無界的 `remaining_accounts` 清單，交易大小是真正的限制 — 與 [`solana-fundamentals/rent-and-reclaimable-rent`](/zh-Hant/solana-fundamentals/rent-and-reclaimable-rent#batching-how-many-fit-in-one-transaction) 中描述的錢包端掃除相同的約束。

**常見錯誤** — `InvalidOwner`（`6001`，簽署者錯誤）、`LamportsCalculateError`（`6015`，wSOL 往返未淨化為零）和來自程式擁有路徑的 `InsufficientFunds`，當帳戶持有少於其自身租金最低額時。

**無 SDK 建構器。** `@raydium-io/raydium-sdk-v2` 不提供此指令的建構器，`raydium-sdk-V2-demo` 儲存庫也不提供 — 它是管理員路徑。手動編碼，就像 [`solana-fundamentals/rent-and-reclaimable-rent`](/zh-Hant/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) 中的錢包端掃除對代幣程式指令所做的那樣。
