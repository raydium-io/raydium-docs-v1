## 指令總覽

| 判別器名稱 | 簽署者 | 功能 |
|-------|-----------|--------------|
| `Initialize` | 池創建者 | 從兩個代幣和一個 `AmmConfig` 建立新的 CPMM 池。無需許可；任何人都可以呼叫。在新池上硬編碼 `enable_creator_fee = false`。`pool_state` 帳戶可以是規範 PDA 或新的隨機金鑰對（見 Initialize 帳戶）。 |
| `InitializeWithPermission` | 支付者 + `Permission` PDA 持有者 | `Initialize` 的許可版本。呼叫者（支付者）必須擁有從其自身公鑰衍生的 `Permission` PDA。由需要閘控池建立的平台使用（例如 LaunchLab 畢業）。允許呼叫者固定 `creator_fee_on`（`BothToken` / `OnlyToken0` / `OnlyToken1`）並在新池上強制 `enable_creator_fee = true`。`pool_state` 上的 `creator` 欄位設定為單獨傳遞的 `creator` 帳戶，而非支付者。`pool_state` 的規範 PDA 或隨機金鑰對靈活性與 `Initialize` 相同。 |
| `Deposit` | LP | 在兩個代幣中新增流動性；接收 LP 代幣。 |
| `Withdraw` | LP | 銷毀 LP 代幣；按比例接收兩個基礎代幣。 |
| `SwapBaseInput` | 交換者 | 精確輸入交換（輸入 `amount_in`，輸出 ≥ `minimum_amount_out`）。 |
| `SwapBaseOutput` | 交換者 | 精確輸出交換（輸入 ≤ `maximum_amount_in`，輸出 `amount_out`）。 |
| `CollectProtocolFee` | `protocol_owner`（來自 `AmmConfig`） | 從金庫掃除累積的協議費用。 |
| `CollectFundFee` | `fund_owner`（來自 `AmmConfig`） | 從金庫掃除累積的基金費用。 |
| `CollectCreatorFee` | `pool_creator` | 掃除累積的創建者費用（如果啟用了創建者費用）。 |
| `CollectCreatorFeePermissionless` | 任何支付者 | 將所有累積的創建者費用掃除到 `pool_creator` 的規範代幣帳戶。支付者可以建立遺漏的接收者 ATA，但無法重定向轉帳。 |
| `UpdatePoolStatus` | `admin` | 透過位元遮罩暫停/恢復池上的特定操作。 |
| `UpdateAmmConfig` | `admin` | 變更費率或 `AmmConfig` 上的協議/基金擁有者。 |
| `CreateAmmConfig` | `admin` | 建立新的費用層級（新 `AmmConfig` 帳戶）。 |
| `CreatePermissionPda` | `admin` 或委派的許可 PDA 創建者 | 鑄造 `Permission` PDA，允許特定授權呼叫 `InitializeWithPermission`。 |
| `ClosePermissionPda` | `admin` | 撤銷先前發行的 `Permission` PDA。 |

狀態位元遮罩：每個池的 `status` 是一個 `u8`，其中位元 0 = 禁用存款、位元 1 = 禁用提取、位元 2 = 禁用交換（程式中的 `PoolStatusBitIndex { Deposit, Withdraw, Swap }`）。清除位元表示允許操作；設定位元表示已暫停。`UpdatePoolStatus` 接受原始 `u8` 並覆寫現有值。

下一節詳細介紹每一個。帳戶順序遵循 CPMM IDL；SDK 和 `raydium-cp-swap/programs/cp-swap/src/instructions` 中的 Rust 用戶端符合此順序。

## `Initialize`

建立新的 CPMM 池。

**參數**

```
init_amount_0: u64
init_amount_1: u64
open_time:     u64   // Unix 時間戳；此之前的交換被拒絕
```

**帳戶**（W = 可寫、S = 簽署者）

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 支付租金；記錄為 `pool_state.pool_creator`。 |
| 2 | `amm_config` |   |   | 選定的費用層級。 |
| 3 | `authority` |   |   | CPMM 全域授權 PDA。 |
| 4 | `pool_state` | W | S* | 在此初始化。**要麼**是規範 PDA `["pool", amm_config, token_0_mint, token_1_mint]`，**要麼**是新的隨機金鑰對——當不是規範 PDA 時，程式要求 `pool_state` 簽署（`require_eq!(pool_account_info.is_signer, true)`）。隨機金鑰對路徑讓創建者躲避規範 PDA 上的搶先交易嘗試。下游 PDA（`lp_mint`、`vaults`、`observation_state`）無論如何都從 `pool_state.key()` 衍生。 |
| 5 | `token_0_mint` |   |   | 已排序：`token_0_mint < token_1_mint`。 |
| 6 | `token_1_mint` |   |   | |
| 7 | `lp_mint` | W |   | 在此初始化。授權設定為 `authority`。 |
| 8 | `creator_token_0` | W |   | `init_amount_0` 的來源 ATA。 |
| 9 | `creator_token_1` | W |   | `init_amount_1` 的來源 ATA。 |
| 10 | `creator_lp_token` | W |   | LP 的目的地（如果遺漏則建立）。 |
| 11 | `token_0_vault` | W |   | 在此初始化。由 `authority` 擁有。 |
| 12 | `token_1_vault` | W |   | |
| 13 | `create_pool_fee` | W |   | 創建者支付的 `create_pool_fee` 的目的地 ATA。 |
| 14 | `observation_state` | W |   | 在此初始化。 |
| 15 | `token_program` |   |   | SPL Token（用於 LP 鑄造）。 |
| 16 | `token_0_program` |   |   | SPL Token 或 Token-2022。 |
| 17 | `token_1_program` |   |   | SPL Token 或 Token-2022。 |
| 18 | `associated_token_program` |   |   | |
| 19 | `system_program` |   |   | |
| 20 | `rent` |   |   | |

`*` `pool_state` 僅在隨機金鑰對路徑上簽署；規範 PDA 路徑在不簽署 `pool_state` 的情況下執行。

**前置條件**

- 代幣已排序（按位元組順序 `token_0_mint < token_1_mint`）。
- 兩個代幣都不使用 CPMM 允許清單外的擴展（`TransferFeeConfig`、`MetadataPointer`、`TokenMetadata`、`InterestBearingConfig`、`ScaledUiAmount`）——見 [`products/cpmm/accounts`](/zh-Hant/products/cpmm/accounts#vaults-and-token-2022)。程式內的小型每個代幣允許清單會繞過逐案上線的檢查。
- `creator` 在各自的 ATA 中至少有 `init_amount_0` 和 `init_amount_1`。
- `amm_config.disable_create_pool == false`。

**後置條件**

- `pool_state` 存在，`lp_supply = sqrt(init_amount_0 * init_amount_1) − LOCKED_LP`。
- `LOCKED_LP`（100 lamports LP 代幣）的 LP 啟動者永久鎖定在池中——`pool_state.lp_supply` 記錄 `liquidity − 100`，而 100 LP 單位保持在流通外，防止池被完全耗盡並除以零。
- `observation_state` 已初始化；`observation_index = 0` 和 `pool_id = pool_state.key()`。
- `create_pool_fee` lamports 從創建者轉帳到接收者並同步為原生 SOL（它是 wSOL ATA）。
- 池的狀態位元遮罩為 `0`（存款/提取/交換全部啟用）。
- `enable_creator_fee = false` 和 `creator_fee_on = BothToken`。`Initialize` **不**支援啟用創建者費用——該路徑是 `InitializeWithPermission`。
- 如果呼叫者傳遞的值 `<= block_timestamp`，`open_time` 會被提升到 `block_timestamp + 1`。交換在 `open_time` 之前被拒絕；存款和提取立即生效。

**常見錯誤**（完整清單見 [`reference/error-codes`](/zh-Hant/reference/error-codes)）

- `InvalidInput` — 代幣未排序或相同代幣。
- `NotSupportMint` — 被阻止的 Token-2022 擴展。
- `ExceededSlippage` — 罕見；如果 `init_amount_0/1` 因小數位數不匹配而導致零 LP。

## `Deposit`

按池的比例在兩個代幣中新增流動性。

**參數**

```
lp_token_amount:   u64   // 要鑄造給 LP 的 LP 代幣數量
maximum_token_0:   u64
maximum_token_1:   u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

**數學**

```
needed_token_0 = ceil(lp_token_amount * vault_0 / lp_supply)
needed_token_1 = ceil(lp_token_amount * vault_1 / lp_supply)
require(needed_token_0 <= maximum_token_0, "ExceededSlippage")
require(needed_token_1 <= maximum_token_1, "ExceededSlippage")
```

`k` 的比例性沒有變化——金庫和 `lp_supply` 按相同因子縮放。

**後置條件**

- `lp_supply += lp_token_amount`。
- `vault_0 += needed_token_0`（扣除輸入上任何 Token-2022 轉帳費用）。
- `vault_1 += needed_token_1`（扣除輸入上任何 Token-2022 轉帳費用）。

**常見錯誤** — `ExceededSlippage`、`ZeroTradingTokens`、如果存款被暫停則 `InvalidStatus`。

## `Withdraw`

銷毀 LP 代幣並按比例接收兩個基礎代幣。

**參數**

```
lp_token_amount:   u64
minimum_token_0:   u64
minimum_token_1:   u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `owner` |   | S |
| 2 | `authority` |   |   |
| 3 | `pool_state` | W |   |
| 4 | `owner_lp_token` | W |   |
| 5 | `token_0_account` | W |   |
| 6 | `token_1_account` | W |   |
| 7 | `token_0_vault` | W |   |
| 8 | `token_1_vault` | W |   |
| 9 | `token_program` |   |   |
| 10 | `token_program_2022` |   |   |
| 11 | `vault_0_mint` |   |   |
| 12 | `vault_1_mint` |   |   |
| 13 | `lp_mint` | W |   |

（與 `Deposit` 相同；`lp_mint` 可寫是因為 LP 代幣被銷毀。）

**數學**

```
out_token_0 = floor(lp_token_amount * vault_0 / lp_supply)
out_token_1 = floor(lp_token_amount * vault_1 / lp_supply)
require(out_token_0 >= minimum_token_0, "ExceededSlippage")
require(out_token_1 >= minimum_token_1, "ExceededSlippage")
```

**後置條件**

- `lp_supply -= lp_token_amount`。
- 金庫發送 `out_token_0` / `out_token_1`（總額；使用者接收扣除任何 Token-2022 轉帳費用的淨額）。

| 12 | `output_token_mint` |   |   |
| 13 | `observation_state` | W |   |

順序**輸入 → 輸出**由使用者的方向決定，而非池的規範 `token_0 / token_1`。程式透過匹配代幣來確定哪個金庫是哪個。

**數學** — 見 [`products/cpmm/math`](/zh-Hant/products/cpmm/math)。

**前置條件**

- `open_time <= now`。
- `pool_status` 允許交換。
- 此授權的兩個代幣都未暫停或凍結。
- `amount_in > 0`。

**常見錯誤**

- `ExceededSlippage` — `amount_out < minimum_amount_out`。
- `ZeroTradingTokens` — 交易四捨五入為零。
- `NotApproved` — 池透過 `UpdatePoolStatus` 暫停交換。
- `InvalidInput` — 代幣與池的任一金庫代幣不符。

## `CollectFundFee`

與 `CollectProtocolFee` 形狀相同，但由 `fund_owner` 簽署並將 `fund_fees_*` 計數器歸零。

## `CollectCreatorFee`

由 `pool_state.pool_creator` 簽署。它將完整的 `creator_fees_token_0` 和 `creator_fees_token_1` 餘額轉帳到創建者的代幣帳戶，然後將兩個計數器歸零。當兩個計數器都為零時，它返回 `NoFeeCollect`。

## `CollectCreatorFeePermissionless`

任何人都可以觸發創建者費用收集。指令始終將完整的累積餘額發送到由 `pool_state.pool_creator` 擁有的規範關聯代幣帳戶；呼叫者無法選擇另一個創建者或目的地。如果任一 ATA 遺漏，支付者資助其建立。

原始 `CollectCreatorFee` 仍可呼叫，因此現有用戶端保持相容。

**參數** — 無。

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `payer` | W | S | 任何簽署者；資助遺漏的創建者 ATA。 |
| 2 | `creator` |   |   | 必須等於 `pool_state.pool_creator`；不簽署。 |
| 3 | `authority` |   |   | CPMM 全域金庫授權 PDA。 |
| 4 | `pool_state` | W |   | 保存累積的創建者費用計數器。 |
| 5 | `token_0_vault` | W |   | 必須符合池的代幣 0 金庫。 |
| 6 | `token_1_vault` | W |   | 必須符合池的代幣 1 金庫。 |
| 7 | `vault_0_mint` |   |   | 必須符合 `token_0_vault.mint`。 |
| 8 | `vault_1_mint` |   |   | 必須符合 `token_1_vault.mint`。 |
| 9 | `creator_token_0` | W |   | 創建者的 `vault_0_mint` 規範 ATA；如果遺漏則建立。 |
| 10 | `creator_token_1` | W |   | 創建者的 `vault_1_mint` 規範 ATA；如果遺漏則建立。 |
| 11 | `token_0_program` |   |   | SPL Token 或 Token-2022，符合代幣 0。 |
| 12 | `token_1_program` |   |   | SPL Token 或 Token-2022，符合代幣 1。 |
| 13 | `associated_token_program` |   |   | 建立遺漏的接收者 ATA。 |
| 14 | `system_program` |   |   | 從 `payer` 資助帳戶建立。 |

- 當兩個計數器都為零時返回 `NoFeeCollect`。

管理員金鑰是 CPMM 程式上的升級授權——實際上是 Raydium 多簽。見 [`security/admin-and-multisig`](/zh-Hant/security/admin-and-multisig)。

## `UpdateAmmConfig`

變更現有 `AmmConfig` 上的費率或擁有權。接受 `param: u8`（用於更新哪個欄位的判別器）和 `value: u64`。每個參數的值語義在來源中；常見的有：

- `param = 0` → `trade_fee_rate`
- `param = 1` → `protocol_fee_rate`
- `param = 2` → `fund_fee_rate`
- `param = 3` → `new_protocol_owner`（將 `Pubkey` 位元組作為重新解釋傳遞）
- `param = 4` → `new_fund_owner`
- `param = 5` → `create_pool_fee`
- `param = 6` → `disable_create_pool`

變更由管理員簽署，並在下一次交換時影響**綁定到此 `AmmConfig` 的每個池**。無遷移；池只是讀取新值。
