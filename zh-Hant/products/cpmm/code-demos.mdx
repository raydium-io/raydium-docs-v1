## 前置需求

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token bn.js decimal.js
```

本頁的每個示例都對應 [`raydium-sdk-V2-demo/src/cpmm`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/cpmm) 中的一個檔案；GitHub 連結位於每個章節旁邊。初始化遵循示例倉庫的 `config.ts.template`（[來源](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template)）：

```ts
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
```

`Raydium` 實例是 SDK 的外觀 — 下面的每個示例都使用它。`Raydium.load` 是非同步的，因為它預設會載入代幣列表；傳遞 `disableLoadToken: true` 可跳過該提取。可用性功能檢查已預設跳過，除非你傳遞 `disableFeatureCheck: false`。費用配置會在首次使用時透過 `raydium.api.getCpmmConfigs()` 延遲取得。

## 建立 CPMM 流動性池

來源：[`src/cpmm/createCpmmPool.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/createCpmmPool.ts)

```ts
import { PublicKey } from "@solana/web3.js";
import BN from "bn.js";
import { CREATE_CPMM_POOL_PROGRAM, CREATE_CPMM_POOL_FEE_ACC }
  from "@raydium-io/raydium-sdk-v2";
// (If you need every pool PDA at once, the exported helper is `getCreatePoolKeys`.
//  There is no `getCpmmPdas`.)

const mintA = new PublicKey("So11111111111111111111111111111111111111112"); // wSOL
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// 1. 選擇費用配置。index=0 是 0.25% 級別。
const feeConfigs = await raydium.api.getCpmmConfigs();
const feeConfig  = feeConfigs.find((c) => c.index === 0)!;

// 2. 取得代幣元資料，以便 SDK 可以處理 Token-2022 擴展。
const mintAInfo = await raydium.token.getTokenInfo(mintA);
const mintBInfo = await raydium.token.getTokenInfo(mintB);

// 3. 建立交易。
const { execute, extInfo } = await raydium.cpmm.createPool({
  programId:       CREATE_CPMM_POOL_PROGRAM,
  poolFeeAccount:  CREATE_CPMM_POOL_FEE_ACC,
  mintA:           mintAInfo,
  mintB:           mintBInfo,
  mintAAmount:     new BN(1_000_000_000),   // 1 SOL（假設 9 位小數）
  mintBAmount:     new BN(   160_000_000),  // 160 USDC（按 160/SOL）
  startTime:       new BN(0),               // 立即開放
  feeConfig,
  associatedOnly:  false,
  ownerInfo:       { useSOLBalance: true },
  txVersion:       TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Pool created at", extInfo.address.poolId.toBase58());
console.log("Tx:", txId);
```

SDK 會自動處理以下幾點：

- 在推導 PDA 之前將代幣排序為 token0/token1 順序。
- 向 `poolFeeAccount` 支付一次性的 `create_pool_fee`。
- 如果缺少，建立呼叫者的關聯代幣帳戶。
- 根據每一側選擇正確的代幣程式（SPL Token 或 Token-2022）。

確認後，你可以使用以下方式取得即時流動性池狀態：

```ts
// getPoolInfoFromRpc takes a positional base58 string, not a PublicKey and not an object.
const { poolKeys, poolInfo, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(
  extInfo.address.poolId.toBase58(),
);
```

## 交換（基礎輸入）

來源：[`src/cpmm/swap.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swap.ts)

```ts
import { CurveCalculator, FeeOn } from "@raydium-io/raydium-sdk-v2";

const POOL_ID = "<POOL_ID>";   // base58 string

// 1. 直接從 RPC 載入目前的流動性池狀態（不是從 API）。
const { poolInfo, poolKeys, rpcData } = await raydium.cpmm.getPoolInfoFromRpc(POOL_ID);

const inputMint  = poolInfo.mintA.address;                // 交換 A → B
const amountIn   = new BN(100_000_000);                   // 0.1 SOL
const slippage   = 0.005;                                 // 0.5%

// 2. 在本地報價。CurveCalculator 鏡像鏈上數學，
//    包括任一側的 Token-2022 轉帳費用。全部八個參數都是必需的。
const baseIn = inputMint === poolInfo.mintA.address;
const swapResult = CurveCalculator.swapBaseInput(
  amountIn,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult fields are inputAmount / outputAmount / tradeFee / protocolFee /
// fundFee / creatorFee / newInputVaultAmount / newOutputVaultAmount.
// There is no destinationAmountSwapped or sourceAmountSwapped.

// 3. 建立並發送。在此傳遞 `slippage` 就是套用該邊界的方式 —
//    不需要手動計算最小輸出。
const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: amountIn,
  swapResult,
  slippage,
  baseIn,
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Swap tx:", txId);
```

注意：SDK **總是** 在 `getPoolInfoFromRpc` 內從 RPC 重新取得流動性池狀態。不要使用 `api-v3.raydium.io` 的報價來進行你即將簽署的交易 — 一個落後一個區塊的報價可能在著陸時滑入 `ExceededSlippage`。

## 交換（基礎輸出）

來源：[`src/cpmm/swapBaseOut.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/swapBaseOut.ts)

```ts
const amountOutWanted = new BN(15_000_000);        // 15 USDC
const slippage        = 0.005;

const baseIn = false; // false → mintB 是輸入側
const swapResult = CurveCalculator.swapBaseOutput(
  amountOutWanted,
  baseIn ? rpcData.baseReserve : rpcData.quoteReserve,
  baseIn ? rpcData.quoteReserve : rpcData.baseReserve,
  rpcData.configInfo!.tradeFeeRate,
  rpcData.configInfo!.creatorFeeRate,
  rpcData.configInfo!.protocolFeeRate,
  rpcData.configInfo!.fundFeeRate,
  rpcData.feeOn === FeeOn.BothToken || rpcData.feeOn === FeeOn.OnlyTokenB,
);
// swapResult.inputAmount is the required input; there is no sourceAmountSwapped.

const { execute } = await raydium.cpmm.swap({
  poolInfo,
  poolKeys,
  inputAmount: new BN(0),   // unused when fixedOut — the amount comes from swapResult
  fixedOut:    true,
  swapResult,               // required, and it carries the target output amount
  baseIn,
  slippage,
  txVersion:   TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

## 存入流動性

來源：[`src/cpmm/deposit.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/deposit.ts)

```ts
import { Percent } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

// addLiquidity 由「輸入」金額驅動，而不是 LP 金額。
const uiInputAmount = "0.0001";
const inputAmount = new BN(
  new Decimal(uiInputAmount).mul(10 ** poolInfo.mintA.decimals).toFixed(0),
);
const slippage = new Percent(1, 100);   // 是 Percent，不是 number

const { execute } = await raydium.cpmm.addLiquidity({
  poolInfo,
  poolKeys,
  inputAmount,
  baseIn: true,           // inputAmount is denominated in mintA
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

SDK 會從流動性池目前的儲備推導出配對金額，為指令的 `maximum_*` 參數將每一側依滑點膨脹，並在必要時建立 ATA。如果你想在 UI 預覽中使用這些數字，`raydium.cpmm.computePairAmount({ ... })` 會回傳相同的數值。

## 收取協議/基金/建立者費用

來源：[`src/cpmm/collectCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectCreatorFee.ts)、[`src/cpmm/collectAllCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/cpmm/collectAllCreatorFee.ts)

協議和基金收集仍受權限限制。建立者費用有兩條路徑：建立者簽署的 `CollectCreatorFee`，以及附加的 `CollectCreatorFeePermissionless`，任何支付者都可以呼叫，但只能轉帳到建立者的規範 ATA。`0.2.64-alpha` 為這兩條建立者路徑都提供了模組層級的建構器：

```ts
// creator-signed
const { execute } = await raydium.cpmm.collectCreatorFees({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// permissionless — 任何支付者；收益進入建立者的規範 ATA
const { execute } = await raydium.cpmm.collectCreatorFeesPermissionless({
  poolInfo,
  poolKeys,
  txVersion: TxVersion.V0,
});

// 一次處理多個流動性池，由建立者簽署
await raydium.cpmm.collectMultiCreatorFees({ poolInfoList, txVersion: TxVersion.V0 });
```

<Note>
  這兩個建立者指令有**不同的判別器和帳戶佈局** — 無許可的那個用單獨的 `payer` 和一個
  非簽署的 `creator` 取代了建立者簽署者 / `amm_config` 的位置。請使用相符的建構器，
  而不是在另一個上手動調換帳戶。

  SDK 中沒有協議費用或基金費用的建構器（`makeCollectProtocolFeeInstruction` 和
  `makeCollectFundFeeInstruction` 不以任何名稱存在） — 那些是管理員路徑。*確實*存在的
  低階指令建構器是 `collectCpFeeInstruction`、`makeCollectCreatorFeeInstruction` 和
  `collectCreatorFeePermissionlessInInstruction`。
</Note>

在鏈下，你可以直接從 `PoolState` 讀取應計費用：

```ts
const pool = await raydium.cpmm.getRpcPoolInfo(POOL_ID);   // base58 string
console.log("Accrued protocol fee mintA:", pool.protocolFeesMintA.toString());
console.log("Accrued protocol fee mintB:", pool.protocolFeesMintB.toString());
// The CpmmPoolInfoLayout fields are protocolFeesMintA/B, fundFeesMintA/B and
// creatorFeesMintA/B — there are no ...Token0/...Token1 fields.
```

## Rust CPI 骨架

如果你想從自己的 Anchor 程式呼叫 CPMM — 例如，一個代表其存款人進行交換的金庫 — CPI 上下文看起來像這樣。帳戶順序遵循 [`products/cpmm/instructions`](/zh-Hant/products/cpmm/instructions)。

```rust
// Cargo.toml — the branch matters: `master` still pins anchor-lang 0.32.1.
// raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap",
//                     branch = "chore/upgrade-anchor", features = ["cpi"] }
// anchor-lang      = "=1.0.2"   // 必須與 raydium-cp-swap 固定的版本相符
// anchor-spl       = "=1.0.2"
//
// The `cpi` feature is required — the `raydium_cp_swap::cpi` module only exists
// under it. Note this crate cannot share a program with the CLMM sample in
// products/clmm/code-demos, which pins anchor-lang =0.32.1.

use anchor_lang::prelude::*;
use anchor_spl::token_interface::{TokenAccount, TokenInterface, Mint};
use raydium_cp_swap::cpi::accounts::Swap;
use raydium_cp_swap::cpi;
use raydium_cp_swap::program::RaydiumCpSwap;

#[derive(Accounts)]
pub struct ProxySwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: 由 CPMM 程式驗證
    pub authority:     UncheckedAccount<'info>,
    /// CHECK:
    pub amm_config:    UncheckedAccount<'info>,
    #[account(mut)]
    /// CHECK:
    pub pool_state:    UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: InterfaceAccount<'info, TokenAccount>,

    #[account(mut)]
    pub input_vault:  InterfaceAccount<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: InterfaceAccount<'info, TokenAccount>,

    pub input_token_program:  Interface<'info, TokenInterface>,
    pub output_token_program: Interface<'info, TokenInterface>,

    pub input_token_mint:  InterfaceAccount<'info, Mint>,
    pub output_token_mint: InterfaceAccount<'info, Mint>,

    #[account(mut)]
    /// CHECK: 環形緩衝區
    pub observation_state: UncheckedAccount<'info>,

    pub cpmm_program: Program<'info, RaydiumCpSwap>,
}

pub fn proxy_swap_base_input(
    ctx: Context<ProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = Swap {
        payer:                ctx.accounts.payer.to_account_info(),
        authority:            ctx.accounts.authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.input_token_account.to_account_info(),
        output_token_account: ctx.accounts.output_token_account.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.input_token_program.to_account_info(),
        output_token_program: ctx.accounts.output_token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_token_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_token_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0 在此處採用程式的 Pubkey，而不是其 AccountInfo。
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );
    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)
}
```

如果你的 CPI 作為 PDA 簽署（例如，你代表存款人管理金庫），將 `CpiContext::new` 交換為 `CpiContext::new_with_signer` 並傳遞你的種子。

## 常見陷阱

開啟支援票證前的簡短檢查清單：

- **排序的代幣。** 如果你推導的 `poolState` PDA 與鏈上流動性池不符，你可能忘記了排序代幣。
- **過時的 API 報價。** 永遠不要將 `api-v3.raydium.io` 的儲備值傳遞到 `CurveCalculator.swap`。從 RPC 取得。
- **錯誤的代幣程式。** Token-2022 代幣的金庫由 Token-2022 程式擁有，而不是 SPL Token。始終使用流動性池的 `token_0_program` / `token_1_program` 欄位。
- **轉帳費用代幣的滑點未充分計價。** 如果流動性池的任一側是 Token-2022 轉帳費用代幣，你的 `minimum_amount_out` 必須以使用者實際收到的金額計價，而不是金庫發送的金額。
- **交換時出現 `NotApproved`。** 檢查 `PoolState.status` — 管理員可能已暫停該流動性池上的交換。請參閱 [`products/cpmm/instructions`](/zh-Hant/products/cpmm/instructions) 以了解狀態位元遮罩。
