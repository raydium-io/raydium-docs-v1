## 清單

AMM v4 池在建立時在 `AmmInfo` 上記錄一個綁定的市場。完整情況如下：

| 類別 | 帳戶 | 擁有者 | 角色 |
|----------|---------|-------|------|
| 池 | `AmmInfo` | AMM v4 程式 | 池狀態：累積費用、狀態、金庫參考（以及作為舊版欄位的市場）。 |
| 池 | `amm_authority` | AMM v4 程式 | 程式擁有的 PDA，簽署金庫移動。在所有 AMM v4 池中共享。 |
| 池 | `amm_open_orders` | OpenBook | 舊版 `OpenOrders` 參考。目前的程式從不建立或讀取它，而是在每個新池上寫入 `AmmInfo.open_orders = Pubkey::default()`；只有在移除 OpenBook 之前建立的池才帶有實際值。仍在 v1 佈局上按位置傳遞。 |
| 池 | `amm_target_orders` | AMM v4 程式 | 舊版目標訂單帳戶。仍由 `WithdrawPnl`（作為帳戶 #10）參考，但不構建網格。 |
| 池 | `pool_coin_token_account` | SPL Token | 池的幣側金庫（`amm_authority` 的 ATA）。 |
| 池 | `pool_pc_token_account` | SPL Token | 池的 pc 側金庫。 |
| 池 | `lp_mint` | SPL Token | 可互換的 LP 鑄幣。 |
| 舊版（OpenBook） | `serum_market` | OpenBook | 綁定的市場。在 v1 佈局上傳遞，但不再驗證或使用。 |
| 舊版 | `serum_bids`、`serum_asks` | OpenBook | 買價/賣價隊列。被忽略。 |
| 舊版 | `serum_event_queue` | OpenBook | 待處理事件。被忽略。 |
| 舊版 | `serum_coin_vault`、`serum_pc_vault` | SPL Token | 市場級金庫。被忽略。 |
| 舊版 | `serum_vault_signer` | OpenBook | 市場級 PDA。被忽略。 |

注意：為了向後相容性，「serum」前綴在 AMM v4 的 IDL 和欄位名稱中保留。OpenBook 移除後，這些帳戶不再有功能。

## `AmmInfo`

池的根狀態帳戶。大小（約 752 位元組），因為它內聯攜帶池和 OpenBook 參考。

```rust
// programs/amm/src/state.rs (簡化版；欄位順序/名稱遵循 IDL)
pub struct AmmInfo {
    pub status: u64,           // 位掩碼：啟用交換/存入/提取/執行
    pub nonce:  u64,           // 用於衍生 amm_authority 的 bump
    pub order_num: u64,
    pub depth: u64,
    pub coin_decimals: u64,
    pub pc_decimals:   u64,
    pub state:         u64,    // 內部狀態機
    pub reset_flag:    u64,
    pub min_size:      u64,
    pub vol_max_cut_ratio: u64,
    pub amount_wave: u64,
    pub coin_lot_size: u64,    // 舊版（OpenBook 批量大小）；現在初始化為 0
    pub pc_lot_size:   u64,    // 舊版；現在初始化為 0
    pub min_price_multiplier: u64,
    pub max_price_multiplier: u64,
    pub sys_decimal_value: u64,

    pub fees: Fees,            // 交易/協議/基金費率
    pub state_data: StateData,

    // 池擁有的帳戶：
    pub coin_vault: Pubkey,
    pub pc_vault:   Pubkey,
    pub coin_vault_mint: Pubkey,
    pub pc_vault_mint:   Pubkey,
    pub lp_mint:  Pubkey,
    pub open_orders: Pubkey,   // 池在 OpenBook 上的 OpenOrders
    pub market: Pubkey,        // OpenBook 市場
    pub market_program: Pubkey, // OpenBook 程式 ID
    pub target_orders: Pubkey,
    pub padding1: [u64; 8],     // 保留 — 不是 withdraw_queue / lp_vault
    pub amm_owner: Pubkey,      // 管理員（多簽）
    pub lp_amount: u64,         // 池的內部 LP 總量；見下方說明
    pub client_order_id: u64,
    pub recent_epoch: u64,
    pub padding2: u64,
}

pub struct Fees {
    pub min_separate_numerator:   u64,     // 5
    pub min_separate_denominator: u64,     // 10_000
    pub trade_fee_numerator:      u64,     // 25  → 由 OpenBook 整合使用
    pub trade_fee_denominator:    u64,     // 10_000
    pub pnl_numerator:            u64,     // 12  → 協議的交換費份額
    pub pnl_denominator:          u64,     // 100 → 所以 12/100 = 12% 的費用，= 0.03% 的交易量
    pub swap_fee_numerator:       u64,     // 25  → 0.25% 總交換費
    pub swap_fee_denominator:     u64,     // 10_000
}

pub struct StateData {
    pub need_take_pnl_coin: u64,        // 仍在更新 — 累積協議費（幣側）
    pub need_take_pnl_pc:   u64,        // 仍在更新 — 累積協議費（pc 側）
    pub total_pnl_pc:   u64,            // 已棄用 — 不再更新
    pub total_pnl_coin: u64,            // 已棄用 — 不再更新
    pub pool_open_time: u64,            // 仍在使用 — 池開放時間戳
    pub padding: [u64; 2],              // 保留
    pub orderbook_to_init_time: u64,    // 已棄用 — 不再更新
    pub swap_coin_in_amount: u128,      // 已棄用 — 交易量計數器凍結
    pub swap_pc_out_amount:  u128,      // 已棄用
    pub swap_acc_pc_fee:    u64,        // 已棄用
    pub swap_pc_in_amount:  u128,       // 已棄用
    pub swap_coin_out_amount: u128,     // 已棄用
    pub swap_acc_coin_fee:  u64,        // 已棄用
}
```

<Note>
  結構 **佈局未變**（位元組相容），所以現有的反序列化器繼續工作，但在 OpenBook 移除後，上面標記為 `已棄用` 的欄位 **不再被寫入** — `swap_*` 交易量計數器在其最後值處凍結。對於交易量分析，請使用交易日誌而不是這些欄位。只有 `need_take_pnl_*` 和 `pool_open_time` 被主動維護。
</Note>

面向整合者的欄位：

- **`coin_vault`**、**`pc_vault`** — 池的 SPL Token 金庫。根據 Serum/OpenBook 慣例，`coin` 是 `token_0`（基礎），`pc` 是 `token_1`（報價）。
- **`coin_decimals`**、**`pc_decimals`** — 與鑄幣相匹配。
- **`open_orders`**、**`target_orders`**、**`market`** — 舊版參考欄位。仍在 `AmmInfo` 上，仍在 v1 指令佈局上按位置傳遞，但程式不再讀取或驗證它們。V2 交換進入點省略了它們。
- **`fees.swap_fee_numerator / swap_fee_denominator`** — 合併的交易費。預設 `25 / 10_000 = 0.25%`。
- **`status`** — 單一的列舉 `u64` 狀態，用於控制操作，**不是**位掩碼。管理員可透過 `SetParams`（`param = 0`，即 `Status`）設定。見下方的 [Status](#status)。
- **`lp_amount`** — 池的內部 LP 總量。它**不等於** `lp_mint.supply`：它剛好高出一整個 LP 代幣（`10^coin_decimals` 個基礎單位），因為該數量在初始化時被計入但從未鑄造。程式中所有按比例的數學都使用 `lp_amount`，所以你也應該使用它。
- **`amm_owner`** — 在建立時從程式硬編碼的管理員密鑰寫入，而不是從建立者寫入。
- **`state_data.need_take_pnl_*`** — 累積總費用與已清掃費用之間的差值。`TakePnl` 將這些清零。

## OpenBook 接線

<Note>
  **已移除。** OpenBook / Serum 依賴已從程式中刪除（2026-07 升級）。本部分描述的帳戶不再被驗證或使用。它們作為 `AmmInfo` 上的參考欄位和舊版 v1 指令佈局上的位置佔位符保留。使用 **V2 交換進入點**（[`SwapBaseInV2` / `SwapBaseOutV2`](/zh-Hant/products/amm-v4/instructions)），它們完全跳過這些帳戶。
</Note>

當你呼叫舊版 **v1** `SwapBaseIn` / `SwapBaseOut`、`Deposit` 或 `Withdraw` 指令時，帳戶 **計數** 必須仍然符合舊佈局（市場帳戶佔據其歷史位置），但它們的 **內容不再被檢查** — 不會針對它們發出 CPI。新程式碼應使用 V2 交換變體，它們根本不接受這些帳戶。

```ts
const market = ...;  // OpenBook 市場 PublicKey

// OpenBook 在其市場帳戶上公開的欄位：
const marketDecoded = OpenBookMarket.decode(marketAccountData);
const {
  bids:           serumBids,
  asks:           serumAsks,
  eventQueue:     serumEventQueue,
  requestQueue:   serumRequestQueue,
  baseVault:      serumCoinVault,
  quoteVault:     serumPcVault,
  vaultSignerNonce,
} = marketDecoded;

const serumVaultSigner = PublicKey.createProgramAddressSync(
  [market.toBuffer(), u64ToBytes(vaultSignerNonce)],
  OPENBOOK_PROGRAM_ID,
);
```

AMM 的 `amm_open_orders` 是一個 OpenBook 擁有的帳戶，在此市場上持有池的限價訂單狀態：活躍訂單、已結算餘額、推薦人等。`amm_target_orders` 是 AMM 側：它持有 AMM 的 *預期* 網格（每個訂單槽的價格/大小），以便程式可以廉價地與當前發佈的內容進行比較，並放置/取消差值。

## 授權 PDA

整個 AMM v4 程式恰好有一個 `amm_authority` PDA。其種子很簡單（`["amm authority"]`），其 bump 存儲在每個 `AmmInfo` 上。此授權簽署所有 AMM v4 池的所有代幣移動。

```ts
const AMM_V4_PROGRAM_ID = new PublicKey(
  "675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8",
);
const [ammAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("amm authority")],
  AMM_V4_PROGRAM_ID,
);
```

沒有第二個以池為範圍的授權：這一個 PDA 涵蓋了程式所簽署的一切。它的 bump 在主網上是 `254`，並鏡像在每個 `AmmInfo` 的 `nonce` 上；`WithdrawExcessLamports` 會用硬編碼的該 nonce 重新衍生它。

## 金庫

池的 SPL Token 金庫是標準代幣帳戶，其 `owner` 是 `amm_authority`。不是 ATA — 它們的地址是在 `Initialize2` 時從 `[AMM_V4_PROGRAM_ID, market, "coin_vault_associated_seed"]` 和 `[AMM_V4_PROGRAM_ID, market, "pc_vault_associated_seed"]` 衍生的 PDA。鑄幣不是種子，`amm_id` 也不是。地址存儲在 `AmmInfo` 上；衍生是一次性的好奇心。

**不支援** Token-2022。程式為所有金庫移動硬編碼 SPL Token 的程式 ID。嘗試將 AMM v4 池綁定到 Token-2022 鑄幣，會在 `Initialize2` 時以 `InvalidSplTokenProgram` 失敗。

## LP 鑄幣

一個經典的 SPL Token 鑄幣，其授權是 `amm_authority`。總供應量追蹤 LP 對池的所有權；燃燒 LP 按比例從兩個金庫返回代幣。

狀態中**確實**有一個鏡像：`AmmInfo.lp_amount`。它不等於鑄幣的供應量 — 它剛好高出一整個 LP 代幣（`10^coin_decimals` 個基礎單位），因為該數量在初始化時被計入但從未鑄造。程式中每一項按比例的計算都除以 `lp_amount`，所以請使用該欄位，而不是鑄幣的鏈上供應量。

## 狀態

`AmmInfo.status` 是單一的列舉 `u64` 狀態，**不是**位掩碼。請用相等來測試它 — 用 `status & 1` 測試的客戶端會誤判每一個線上池，因為正常的交易狀態是 `6`，而它的第 0 位是 1。

| 值 | `AmmStatus` | 交換 | 存入 | 提取 |
|-------|-------------|------|---------|----------|
| 0 | `Uninitialized` | 否 | 否 | 否 |
| 1 | `Initialized` | 是 | 是 | 是 |
| 2 | `Disabled` | 否 | 否 | 否 |
| 3 | `WithdrawOnly` | 否 | 否 | 是 |
| 4 | `LiquidityOnly` | 否 | 是 | 是 |
| 5 | `OrderBookOnly` | 否 | 是 | 是 |
| 6 | `SwapOnly` | 是 | 是 | 是 |
| 7 | `WaitingTrade` | 是，一旦 `pool_open_time` 已過 | 是 | 是 |

`Initialize2` 在 `open_time` 位於未來時寫入 `7`，否則寫入 `6`；處於 `7` 的池會在 `state_data.pool_open_time` 當時或之後的第一次交換時把自己翻轉為 `6`。超出 `0..=7` 的值會讓 `AmmStatus::from_u64` panic。

Raydium 多簽透過 `SetParams`（`param = 0`，即 `Status`）設定該狀態；只接受 `1`–`7` 的值。（`AdminCancelOrders` 已被移除。）

## 觀察 / 預言機

**AMM v4 沒有專用的觀察帳戶**，而且自從移除 OpenBook 之後，也不再有可以從中衍生觀察資料的掛單簿狀態。如果你需要具有程式支援的 Raydium TWAP，請使用 CPMM 或 CLMM — 兩者都維護一個 `ObservationState` 環形緩衝區。否則，請在鏈下索引交換日誌。

## 從頭衍生池的帳戶

AMM v4 的池帳戶是以綁定市場為鍵的普通 PDA — 不是有種子的密鑰對，也不是每對一個的 PDA。它們每一個都在 `AMM_V4_PROGRAM_ID` 之下使用相同的三種子形狀 `[AMM_V4_PROGRAM_ID, market, <label>]`：

| Account | `<label>` |
|---------|-----------|
| `amm_id` (`AmmInfo`) | `"amm_associated_seed"` |
| `amm_target_orders` | `"target_associated_seed"` |
| `lp_mint` | `"lp_mint_associated_seed"` |
| `pool_coin_token_account` | `"coin_vault_associated_seed"` |
| `pool_pc_token_account` | `"pc_vault_associated_seed"` |

```ts
const [ammId] = PublicKey.findProgramAddressSync(
  [
    AMM_V4_PROGRAM_ID.toBuffer(),
    marketPubkey.toBuffer(),
    Buffer.from("amm_associated_seed"),
  ],
  AMM_V4_PROGRAM_ID,
);
```

綁定的市場是唯一可變的種子，這就是為什麼一個市場恰好對應一個 AMM v4 池。SDK 和 API 為你預先計算這些；請參閱 `raydium-sdk-v2` 的 `Liquidity.getAssociatedPoolKeys`。

實際上，整合者從 `GET https://api-v3.raydium.io/pools/info/ids?ids=<POOL_ID>` 或 SDK 讀取池的完整帳戶集。手動衍生很少需要。
