<Info>
  `PlatformConfig` 是位於 [`GlobalConfig`](/zh-Hant/products/launchlab/global-config) 之上的**平台層級**設定。`GlobalConfig` 定義協議級規則（「交易費為 1%、供應量至少 1000 萬、只有此錢包可以畢業」），而 `PlatformConfig` 則由各個啟動平台（pump.fun、Raydium 自有 UI、第三方啟動板）使用，以新增其費用、聲稱畢業後 LP 的份額、限制其啟動可選擇的曲線形狀，並在鏈上展示其品牌（名稱、網站、圖片）。
</Info>

## 概述

`PlatformConfig` 帳戶為平台管理五個跨領域的關注點：

1. **品牌** — 名稱、網站、圖片連結，全部內聯存儲，以便任何區塊瀏覽器或聚合器都能顯示啟動代幣的平台。
2. **平台費用** — 在協議 `trade_fee_rate` 之上的額外交易費用（`fee_rate`）。累積到平台的 `platform_fee_wallet`。上限為 500 bps（`50000`），在建立和更新路徑上均適用，從 2026-08-26 起從 100 bps（`10000`）提升 — 見[費率上限](#費率上限)。
3. **LP 遷移分配** — 三個存儲的整數（`platform_scale`、`creator_scale`、`burn_scale`），總和為 `1_000_000`。在 2026-08-17 升級前，創作者規模產生單獨的創作者費用密鑰。升級後執行的遷移將前兩者合併為一個平台擁有的鎖定 LP 份額；其餘部分被銷毀。
4. **曲線參數白名單** — 一個 `Vec<PlatformCurveParam>`，列出此平台允許的確切 `(supply, total_base_sell, total_quote_fund_raising, migrate_type, migrate_cpmm_fee_on, vesting_params...)` 組合。如果向量為空或所有條目無效，**任何**組合都被允許；否則啟動必須完全匹配其中一個條目。
5. **全局配置允許清單** — 一個可選限制，要求為選定的 `GlobalConfig` 建立平台建立的 `PlatformAllowConfig`。

PDA 推導：

```ts
const [platformConfigPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("platform_config"),
    platformAdmin.toBuffer(),       // 平台的擁有公鑰
  ],
  LAUNCHLAB_PROGRAM_ID,
);
```

（見源代碼中的 `create_platform_config` 以獲取規範種子列表。）

## 佈局

```rust
// states/platform_config.rs
pub const PLATFORM_CONFIG_SEED: &str = "platform_config";
pub const NAME_SIZE: usize = 64;
pub const WEB_SIZE:  usize = 256;
pub const IMG_SIZE:  usize = 256;
pub const MAX_CREATOR_FEE_RATE: u64 = 5000;       // 50 bps (分母 1_000_000)
pub const MAX_TRANSFER_FEE_RATE: u16 = 500;       // 5%   (分母 10_000)
pub const MAX_CURVE_PARAMS: usize = 10;

#[account]
pub struct PlatformConfig {
    pub epoch:                       u64,
    pub platform_fee_wallet:         Pubkey,            // 簽署 ClaimPlatformFee
    pub platform_nft_wallet:         Pubkey,            // 在 CPMM 畢業時接收平台 NFT 份額
    pub platform_scale:              u64,               // 鑄造給平台 NFT 的 LP 份額
    pub creator_scale:               u64,               // 升級前的創作者份額；升級後添加到平台份額
    pub burn_scale:                  u64,               // 永久銷毀的 LP 份額
    pub fee_rate:                    u64,               // 平台交易費 (1/1_000_000)
    pub name:                        [u8; 64],          // utf-8 用零填充
    pub web:                         [u8; 256],
    pub img:                         [u8; 256],
    pub cpswap_config:               Pubkey,            // CPMM AmmConfig，畢業後的池將綁定到此
    pub creator_fee_rate:            u64,               // 畢業前收取的創作者端費用
    pub transfer_fee_extension_auth: Pubkey,            // 針對 Token-2022 啟動：來自鑄造建立的提取保留權限、來自畢業的費用配置權限
    pub platform_vesting_wallet:     Pubkey,
    pub platform_vesting_scale:      u64,               // 平台在 total_locked_amount 中的份額
    pub platform_cp_creator:         Pubkey,            // 畢業後 CPMM 池上的可選創作者記錄
    pub restrict_global_config:      u8,                // 0 = 無限制，1 = 需要允許 PDA
    pub padding:                     [u8; 107],
    pub curve_params:                Vec<PlatformCurveParam>, // 允許的曲線形狀白名單
}
```

`platform_scale + creator_scale + burn_scale` 必須等於 `1_000_000`。在 2026-08-17 升級前，`creator_scale` 被單獨鎖定，其費用密鑰發送給代幣創作者。對於升級後執行的遷移，它被添加到 `platform_scale`，其鎖定 LP 權利轉到平台。更新邏輯下的示例結果：

- `(0, 100_000, 900_000)` — 90% LP 銷毀，10% 鎖定到平台。
- `(50_000, 100_000, 850_000)` — 85% 銷毀，15% 鎖定到平台。
- `(0, 0, 1_000_000)` — 完全銷毀，無 NFT 鑄造。嚴格的「無內部人士」啟動。

## 品牌欄位

`name`、`web` 和 `img` 是內聯位元組陣列，用零填充至其大小常數。要將其讀取為字符串，請切片至第一個 `\0`：

```ts
function readString(bytes: Uint8Array): string {
  const end = bytes.indexOf(0);
  return Buffer.from(end === -1 ? bytes : bytes.subarray(0, end)).toString("utf-8");
}
```

常數故意設置得很大（`name: 64`、`web: 256`、`img: 256`），以便平台可以包含足夠的元數據供區塊瀏覽器和聚合器使用，而無需觸及鏈外存儲。任何超過這些大小的內容都會在 `CreatePlatformConfig` 時以 `InvalidInput` 回退。

## 費用機制

綁定到 `PlatformConfig` 的曲線上的交換收取三層費用：

```
trade_fee     = amount_in × global_config.trade_fee_rate    / 1_000_000
platform_fee  = amount_in × platform_config.fee_rate        / 1_000_000
creator_fee   = amount_in × platform_config.creator_fee_rate / 1_000_000

amount_after_fee = amount_in − trade_fee − platform_fee − creator_fee
```

- `trade_fee` 累積到協議的 `protocol_fee_owner`（通過 `CollectFee` 聲稱）。
- `platform_fee` 累積到每個平台的保管庫（通過 `ClaimPlatformFee` 或 `ClaimPlatformFeeFromVault` 聲稱；見[`instructions`](/zh-Hant/products/launchlab/instructions)）。
- `creator_fee` 累積到由創作者公鑰 + 報價鑄造鍵入的每個創作者保管庫（通過 `ClaimCreatorFee` 聲稱）。

### 費率上限

兩個費率都以 `1/1_000_000` 計價，因此 `5000` 是 50 bps，`50000` 是 500 bps。

| 費率 | 上限 | 在以下位置強制執行 |
|---|---|---|
| `fee_rate` | `50000` (500 bps) | `PlatformParams::check()` 在建立時 — 以 `InvalidInput` 回退。`update_platform_fee_rate` 在每個涉及它的更新變體上（`FeeRate` 和 `AllInfo`） — 以 `InvalidPlatformInfo` 回退。 |
| `creator_fee_rate` | `MAX_CREATOR_FEE_RATE = 5000` (50 bps) | `create_platform_config` 在建立時和 `update_creator_fee_rate` 在更新時 — 兩者都以 `InvalidPlatformInfo` 回退。 |

`fee_rate` 的兩個強制執行點是不同檔案中的單獨 `require!` 呼叫，因此它們帶有不同的錯誤代碼，但它們應用相同的上限。在任何允許的費率下建立的平台可以稍後編輯，包括通過一次重寫每個欄位的 `AllInfo` 批量變體。

`fee_rate` 上限最初都是 100 bps（`10000`）。更新上限在 2026-01-27 移至 `25000`（250 bps）；在 2026-08-26 兩者都移至 `50000`（500 bps） — 見[變更日誌條目](/reference/changelog/2026-08-26-launchlab-platform-fee-rate-cap)。

`GlobalConfig.max_share_fee_rate` **不**限制任一費率。它限制四個交換指令採用的每筆交易 `share_fee_rate` 參數 — 推薦費用 — 僅此而已。見[`global-config`](/zh-Hant/products/launchlab/global-config#fees)。

## Token-2022 轉移費用權限

`transfer_fee_extension_auth` 命名平台密鑰，當通過 `InitializeWithToken2022` 建立啟動並附加轉移費用時，該密鑰最終將持有基礎鑄造的 `TransferFeeConfig` 權限。該擴展攜帶兩個權限，它們在啟動生命週期的**不同點**移交：

| 權限 | 鑄造建立時的持有者 | `MigrateToCpswap` 後的持有者 |
|---|---|---|
| `withdraw_withheld_authority` — 提取 Token-2022 在代幣帳戶上保留的費用 | `transfer_fee_extension_auth`，直接寫入鑄造。當欄位為 `Pubkey::default()` 時回退到啟動 `authority` PDA。 | 已是平台密鑰，因此無需移動。遷移僅在 `authority` PDA 仍持有它時才重新分配。 |
| `transfer_fee_config_authority` — 更改費率和最大費用 | 始終是啟動 `authority` PDA。 | `transfer_fee_extension_auth`，前提是該欄位非預設值。 |

在 2026-08-27 之前，鑄造是使用兩個權限上的 `authority` PDA 建立的，兩者都在畢業時移至平台。該程序不公開提取保留或收穫指令，因此在債券曲線階段保留的費用在啟動畢業前無法訪問。在鑄造建立時寫入提取端使其可從第一筆交易開始聲稱 — 見[變更日誌條目](/reference/changelog/2026-08-27-launchlab-token2022-withheld-authority)。

值得規劃的兩個後果：

- **在啟動前設置欄位，而不是之後。** 在 `transfer_fee_extension_auth` 為 `Pubkey::default()` 時建立的啟動將 `authority` PDA 放在提取端。稍後設置欄位仍然有效 — 畢業找到 PDA 並移交權限 — 但在此期間無法提取保留的餘額。
- **在啟動中旋轉欄位會分割兩個權限。** 在啟動建立和畢業之間更改 `transfer_fee_extension_auth`，鑄造的提取保留權限保留在建立時配置的密鑰（PDA 不再持有它，因此遷移跳過該移交），而費用配置權限轉到新密鑰。在啟動之間旋轉，或計劃通過 Token-2022 直接協調兩個密鑰。

將欄位保留在 `Pubkey::default()` 的平台在啟動的整個生命週期內將兩個權限永久保留在 `authority` PDA 上：費率永遠無法更改，保留的餘額永遠無法提取。只有在平台打算持有這些密鑰時才將轉移費用附加到啟動。

## NFT 遷移分配（僅限 CPMM）

當啟動畢業到 CPMM 時，遷移指令將 `CPMM::InitializeWithPermission` 鑄造的 LP 代幣分為兩種方式：

```
lp_to_platform = floor(lp_total × (platform_scale + creator_scale) / 1_000_000)
lp_to_burn     = lp_total − lp_to_platform
```

如果 `lp_to_platform` 非零，LP-Lock 程序將其包裝成一個由 `platform_nft_wallet` 擁有的費用密鑰 NFT。這替代了建立單獨平台和創作者費用密鑰的升級前行為。由升級前完成的遷移建立的費用密鑰保持不變。此 LP 費用權利與由 `platform_cp_creator` 控制的 CPMM 創作者費用分開。

銷毀份額直接被銷毀，因此沒有帳戶可以提取它或聲稱該份額代表的 LP 費用。

具有存儲 `migrate_type = 0` 的現有啟動仍可使用舊版 AMM v4 路徑。新初始化拒絕該遷移類型。

## 曲線參數白名單

`curve_params: Vec<PlatformCurveParam>` 是平台限制其啟動可選擇的曲線形狀的機制。如果向量非空且至少一個條目有效，程序在 `Initialize` 時強制啟動的參數完全匹配至少一個條目。

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct PlatformCurveParam {
    pub epoch:                u64,
    pub index:                u8,           // 此平台白名單中的序號
    pub global_config:        Pubkey,       // 此條目適用的 GlobalConfig
    pub bonding_curve_param:  BondingCurveParam,
    pub padding:              [u64; 50],
}

#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct BondingCurveParam {
    pub migrate_type:               u8,    // 新啟動需要 1 = CPMM；u8::MAX = 通配符
    pub migrate_cpmm_fee_on:        u8,    // 0 = 僅報價，1 = 兩者。u8::MAX = 通配符
    pub supply:                     u64,   // 0 = 通配符
    pub total_base_sell:            u64,   // 0 = 通配符
    pub total_quote_fund_raising:   u64,   // 0 = 通配符
    pub total_locked_amount:        u64,   // u64::MAX = 通配符
    pub cliff_period:               u64,   // u64::MAX = 通配符
    pub unlock_period:              u64,   // u64::MAX = 通配符
}
```

每個欄位都有一個哨兵值，表示**通配符**（任何值匹配）：`u64` 欄位為 `u64::MAX`，`u8` 欄位為 `u8::MAX`，供應/銷售/籌資欄位為 `0`。具有所有哨兵的 `BondingCurveParam` 是「允許任何東西」— 等同於空白名單行為。

`Initialize` 時的匹配算法：

1. 將 `curve_params` 篩選為 `global_config` 與啟動選擇的 `GlobalConfig` 匹配的條目。
2. 如果篩選列表為空，允許任何參數（平台未為此 `GlobalConfig` 白名單任何內容）。
3. 如果篩選列表中的每個條目都有 `all_is_invalid()`（每個欄位都是通配符），允許任何參數。
4. 否則迭代條目；對於每個條目，根據每個非通配符欄位檢查啟動的參數。如果所有非通配符欄位匹配，接受並返回。
5. 如果沒有條目匹配，以 `InvalidInput` 回退。

這讓平台可以說「我們只允許標準 1B 供應/800M 銷售/30k USDC 籌資/無質押形狀」，通過為這四個欄位寫入具體值並在其他地方使用通配符的單個條目。或者更嚴格的平台可能列舉三個或四個離散形狀，每個支持的啟動層級一個。

`MAX_CURVE_PARAMS = 10` 限制白名單大小。

## `PlatformAllowConfig` — 限制平台

每個平台決定是否限制其啟動可使用的 `GlobalConfig` 帳戶。使用 `UpdatePlatformConfig::RestrictGlobalConfig(0 | 1)` 設置 `restrict_global_config`。

```rust
pub const PLATFORM_ALLOW_CONFIG_SEED: &str = "platform_allow_config";

#[account]
pub struct PlatformAllowConfig {
    pub bump:            u8,
    pub platform_config: Pubkey,
    pub global_config:   Pubkey,
    pub padding:         [u64; 8],
}
```

PDA 種子：`[b"platform_allow_config", platform_config, global_config]`。

平台管理員通過 `CreatePlatformAllowConfig` 和 `ClosePlatformAllowConfig` 為每個允許的對建立或關閉一個帳戶。當限制為 `1` 時，初始化在 `remaining_accounts` 中搜索預期的 PDA，並以 `NotEnoughRemainingAccounts` 拒絕缺失帳戶。當限制為 `0` 時，不需要允許帳戶。

前協議管理員管理的 `PlatformGlobalAccess` 帳戶及其建立/關閉指令已停用。現有 `PlatformConfig` 和 `GlobalConfig` 大小不變，但解碼器必須用新平台標誌替換舊全局標誌。舊訪問 PDA 不被新檢查消費。

## 更新路徑

| 指令 | 誰簽署 | 更改內容 |
|-------------|-----------|--------------|
| `CreatePlatformConfig` | 平台管理員（一次性） | 使用 `PlatformParams` 初始化帳戶。 |
| `UpdatePlatformConfig` | 平台管理員 | 通用調度，由 `param: u8` 鍵入；每次呼叫改變一個欄位，或通過 `AllInfo` 一次改變每個欄位。品牌欄位、費率、質押錢包和各種錢包都可通過此設置。兩個費率在每個涉及它們的變體上都根據[費率上限](#費率上限)中的上限重新驗證。 |
| `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 平台管理員 | 為此平台添加或移除一個允許的 `GlobalConfig`。 |
| `UpdatePlatformCurveParam` | 平台管理員 | 按 `(global_config, index)` 添加或替換一個 `PlatformCurveParam` 條目。 |
| `RemovePlatformCurveParam` | 平台管理員 | 清除一個條目（將其設置為全哨兵 = 通配符）。 |
| `ClaimPlatformFee` | `platform_fee_wallet` | 從 `PoolState.quote_vault` 掃除每個池的平台費用。 |
| `ClaimPlatformFeeFromVault` | `platform_fee_wallet` | 掃除每個平台的費用保管庫（PDA 在 `[platform_config, quote_mint]`）。 |

錢包輪換（`platform_fee_wallet`、`platform_nft_wallet`、`platform_vesting_wallet`、`platform_cp_creator`、`transfer_fee_extension_auth`、`cpswap_config`）都通過 `UpdatePlatformConfig` 進行。閱讀源代碼的 `update_platform_config` 調度表以獲取確切的 `param` 代碼。

## 常見陷阱

- **白名單哨兵設置錯誤。** 具有 `total_locked_amount = 0` 的 `BondingCurveParam` **不是**通配符 — 它匹配明確選擇退出質押的啟動。該欄位的通配符是 `u64::MAX`。`cliff_period` 和 `unlock_period` 也存在相同陷阱。使用 `clear()`（程序公開）正確設置哨兵。
- **NFT 分配舍入。** 三個規模必須完全總和為 `1_000_000`。`CreatePlatformConfig` 時的差一錯誤會回退；運行時的差一會鑄造或銷毀一個額外的 LP 單位，這正是嚴格相等檢查的目的。
- **平台質押雙重配置。** 如果 `platform_vesting_scale > 0`，平台必須在啟動籌資結束後呼叫 `CreatePlatformVestingAccount` 一次；如果忘記，該份額保持未配置和休眠狀態（啟動的 `total_locked_amount` 預算被消費但平台永遠不聲稱）。
- **`platform_cp_creator` 歧義。** 當設置為 `Pubkey::default()` 時，啟動創作者被記錄為畢業後 CPMM 池的 `pool_creator`；當設置為真實密鑰時，該密鑰被記錄。這決定了畢業後 CPMM 創作者費用的受益人以及誰可以簽署原始 `CPMM::CollectCreatorFee` 路徑。無權限收集路徑仍向此記錄密鑰的規範 ATA 支付。在平台配置建立時決定你想要哪個模型。
- **`transfer_fee_extension_auth` 設置晚或旋轉。** 該欄位在每個 Token-2022 啟動中讀取兩次 — 一次在鑄造建立時用於 `withdraw_withheld_authority`，一次在畢業時用於 `transfer_fee_config_authority` — 因此在這兩個時刻之間更改的值將兩個權限留在不同的密鑰上。見[Token-2022 轉移費用權限](#token-2022-轉移費用權限)。
- **限制而無允許帳戶。** 在建立所需 `PlatformAllowConfig` 之前啟用 `restrict_global_config` 會阻止選擇該配置的新啟動。
