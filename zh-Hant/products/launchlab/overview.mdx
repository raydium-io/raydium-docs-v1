## LaunchLab 解決的問題

在 LaunchLab 推出之前，在 Raydium 上發行新代幣需要創建者預先為 AMM 池的兩側提供流動性——這意味著團隊必須自掏腰包提供報價端流動性（SOL 或 USDC）。這偏向於資金充足的項目，並以初始資本為門檻限制了發行平台的使用。

LaunchLab 用**結合曲線**取代了這個初始步驟：代幣部署在以報價幣種（通常是 SOL 或 USDC）定價的曲線上。買家通過向曲線發送報價幣來獲得代幣，程序根據曲線公式和當前供應量以確定的價格自動鑄造或釋放基礎代幣單位。無需預先提供流動性。

一旦曲線收集到足夠的報價幣來匹配真實 AMM 池的流動性公式，它就會**畢業**：程序在主網上創建一個 CPMM 池，以曲線的基礎儲備和報價儲備作為種子，從那時起交易轉移到 AMM。

## 生命週期

```
             ┌───────────────────────┐
creator  ──▶ │  Initialize (Launch)  │   ▸ mints the base token, funds the curve vaults,
             │                        │     sets curve params and graduation threshold
             └───────────┬────────────┘
                         │
                         ▼
             ┌───────────────────────┐       repeated N times
             │   Buy  /  Sell        │ ◀─── traders interact with the curve
             └───────────┬────────────┘
                         │ curve quote_reserve
                         │ crosses threshold
                         ▼
             ┌───────────────────────┐   ▸ snapshots curve state
             │      Graduate         │   ▸ deploys CPMM pool seeded with curve reserves
             │                        │   ▸ locks / burns remaining base supply per policy
             └───────────┬────────────┘
                         │
                         ▼
             ┌───────────────────────┐
             │   CPMM pool live      │   ▸ standard CPMM behavior going forward
             └───────────────────────┘
```

每次發行都會完全按照這個序列進行一次。`Buy` 和 `Sell` 是中間階段面向用戶的指令。一旦達到門檻，存儲在 `GlobalConfig` 上的遷移錢包會簽署 `MigrateToCpswap`。

## 兩個固定方

LaunchLab 狀態有兩個特殊帳戶：

- **基礎幣種** — 正在發行的代幣。其鑄造權限由 LaunchLab 程序持有，直到畢業；畢業後被撤銷。
- **報價幣種** — 抵押品。始終是主流幣種（SOL / USDC / RAY）。發行配置在 `Initialize` 時選擇一個；無法更改。

加上兩個金庫：

- **`base_vault`** — 持有已預先鑄造到曲線但尚未售出的基礎供應部分。隨著用戶購買而減少。
- **`quote_vault`** — 累積買家支付的報價幣。隨著用戶購買而增加。此餘額會與畢業門檻進行檢查。

## 定價模型

LaunchLab 支持多種曲線公式（見 [`bonding-curve`](/zh-Hant/products/launchlab/bonding-curve)）。最常見的是**二次**結合曲線，類似於 Pump.fun / Curve.fi / Bancor 系列：

```
price(s) = k × (s / S_max)²     (or similar — exact formula is curve-config dependent)
```

其中 `s` 是已售給用戶的基礎代幣數量，`S_max` 是曲線的最大供應量。每次購買時價格單調上升，每次出售時下降。因為程序精確計算 AMM 集成成本，任何規模的購買都會返回正確的集成金額；除了曲線的自然凸性外，沒有每筆交易的滑點。

## 畢業

當 `quote_vault.balance ≥ graduation_threshold` 時，發行畢業。門檻在 `Initialize` 時設置，通常選擇使得畢業時曲線的隱含價格與 AMM 池以收集的儲備開盤時的價格相匹配。具體來說：

```
threshold ≈ S_graduate × price(S_graduate) × f
```

其中 `S_graduate` 是已售出的基礎代幣數量，`price(S_graduate)` 是曲線在該點的邊際價格，`f` 是考慮費用線的小因子（1–2%）。

在畢業時：

1. 程序快照 `(base_vault_remaining, quote_vault)`。
2. 它使用這兩個儲備調用 CPMM `CreatePool` CPI，將初始 LP 鑄造到程序擁有的權限（通常根據政策燒毀/鎖定）。
3. 它撤銷基礎幣種的鑄造權限（因此永遠無法再鑄造更多基礎代幣）。
4. `LaunchState.status` 翻轉為 `Graduated`。

畢業後，`Buy` 和 `Sell` 被拒絕。交易繼續在生成的 CPMM 池上進行，該池與任何其他 Raydium CPMM 池無異。

## 費用

在曲線階段，每次 `Buy` 和 `Sell` 都會產生費用，分配給：

- **曲線 LP 端** — 增加曲線的隱含 `k`，使後來的買家受益（更緊的價格）。
- **協議** — 累積到 LaunchLab 管理員，通過 `CollectFees` 收集。
- **創建者** — 可選，在 `Initialize` 時可配置。某些發行將一部分作為創建者的持續收入流。

默認費率記錄在 [`bonding-curve`](/zh-Hant/products/launchlab/bonding-curve)。確切的分配存儲在 `LaunchState.fees` 上，每次發行可能不同。

畢業後的費用遵循池創建時的 CPMM 配置（通常是 `AmmConfig[0]`，0.25% 層級）。

## 畢業後誰持有 LP？

LaunchLab 使用平台的三個存儲的比例來產生兩個有效的 LP 目的地：

- **平台鎖定** — 對於 2026-08-17 升級後執行的遷移，`platform_scale + creator_scale` 通過 LP-Lock 鎖定，當此份額非零時，一個費用密鑰進入 `platform_nft_wallet`。升級前，`creator_scale` 產生單獨的創建者費用密鑰。
- **燒毀** — `burn_scale` 永久燒毀，沒有費用密鑰。

比例存儲在 `PlatformConfig` 上，必須總和為 `1_000_000`。升級僅改變未來遷移執行。它不改變早期遷移創建的創建者費用密鑰。

## 重要不變量

- **基礎幣種從創建時起無通脹。** 初始化指令在同一調用中鑄造完整供應並撤銷 `mint_authority`；`freeze_authority` 從未設置。
- **所有新發行都是 CPMM 專用。** `InitializeV2` 和 `InitializeWithToken2022` 需要 `migrate_type = CPSWAP`，自 2026-09 升級起，舊版 `Initialize` 完全失敗。現有舊版狀態仍可使用 `MigrateToAmm`。
- **曲線狀態在一個方向上是單調的。** `base_sold` 僅在 Buy 期間上升，`quote_vault` 僅在 Buy 期間上升（在 Sell 期間下降——對稱地減少 `base_sold`）。程序永遠不會讓曲線變為負數。
- **畢業是單向門檻。** 即使畢業後的交易將 AMM 池價格推回到畢業價格以下，發行也不會恢復到曲線。

## 何時使用 LaunchLab

<Note>
  本頁僅描述協議機制。此處任何內容都不構成財務、法律或投資建議。代幣發行涉及重大財務風險。在發行涉及公開融資的代幣之前，請諮詢適當的專業人士。
</Note>

- 你正在發行沒有先前市場的新代幣。
- 你希望市場決定開盤 CPMM 價格，而不是預先聲明。
- 你希望允許任何人——包括團隊本身——以相同的曲線決定價格購買，而不是以折扣價預分配給內部人士。

**不要**在以下情況使用 LaunchLab：

- 具有既定市場的現有代幣（直接在 CPMM 上使用 `CreatePool`）。
- 需要精確控制開盤 AMM 價格的發行（你可以通過仔細的曲線配置近似它，但機制仍然是曲線驅動的）。
- 需要 LaunchLab 不允許列表的 Token-2022 擴展的代幣（發行程序即使在 Token-2022 路徑上也拒絕 `TransferHook` 和 `PermanentDelegate` 等擴展）。
