當 LaunchLab 代幣遷移至 CPMM 時，資金池會鑄造 LP 代幣。在 2026-08-17 升級之前，`creatorScale` 會為代幣創作者單獨鎖定。對於升級後執行的遷移，`migrateCpLockNftScale` 仍然儲存三個欄位，其總和為 `1_000_000`，但執行時只產生兩個目的地。

## 有效分割

| 欄位 | 更新後的行為 |
|---|---|
| `platformScale` | 包含在平台所有的鎖定 LP 份額中。 |
| `creatorScale` | 升級前會鑄造創作者所有的費用金鑰。升級後，它包含在平台所有的鎖定 LP 份額中。 |
| `burnScale` | 永久銷毀。沒有費用金鑰代表此份額。 |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

當 `burnScale` 為零時，平台接收所有 LP 單位。當 `effectivePlatformScale` 為零時，所有 LP 都被銷毀，且不會建立平台費用金鑰。

## 範例

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% 平台所有的鎖定 LP，10% 銷毀。
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// 在更新的程式下，這會產生 100% 平台所有的鎖定 LP。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% 銷毀；無費用金鑰。
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## 與 CPMM 創作者費用的關係

規模欄位僅控制 LP 所有權。它們不設定交換費率或識別 CPMM 創作者費用受益人。`cpConfigId` 選擇 CPMM `AmmConfig`；`platformCpCreator` 決定 CPMM 資金池是否記錄原始啟動創作者或平台選定的地址。

## 更新分割

更新平台之前：

- 確認三個值的總和恰好為 `1_000_000`。
- 將 `platformScale + creatorScale` 呈現為有效的平台份額。
- 不要根據 `creatorScale` 承諾創作者費用金鑰。
- 保留升級前完成的遷移所顯示的創作者費用金鑰所有權；這些記錄不會被重寫。
- 在未來的啟動使用更新的設定之前，解釋此變更。
