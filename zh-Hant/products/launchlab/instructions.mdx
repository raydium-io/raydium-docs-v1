## 指令清單

| 群組 | 指令 | 可呼叫者 |
|-------|-------------|-------------|
| 全域設定 | `CreateConfig` / `UpdateConfig` | 程式管理員；委派的建立設定授權也可呼叫 `CreateConfig` |
| 啟動生命週期 | `Initialize` / `InitializeV2` | 任何人（建立者）— SPL Token 基礎代幣；V2 記錄 `amm_creator_fee_on` 以供最終 CPMM 畢業使用。僅 V2 接受 Token-2022 報價代幣。 |
| 啟動生命週期 | `InitializeWithToken2022` | 任何人（建立者）— Token-2022 基礎代幣，可選 `TransferFeeConfig`；接受任一報價代幣程式 |
| 交易 | `BuyExactIn` / `BuyExactOut` | 任何人 — 在結合曲線上進行精確輸入/精確輸出買入 |
| 交易 | `SellExactIn` / `SellExactOut` | 任何人 — 在結合曲線上進行精確輸入/精確輸出賣出 |
| 畢業 | `MigrateToAmm` | 遷移錢包 — 舊版 AMM v4 畢業，適用於在強制執行 CPMM 專用建立之前初始化的資金池。 |
| 畢業 | `MigrateToCpswap` | 遷移錢包 — 畢業至 CPMM。所有新初始化的啟動都使用此路徑。包裝 CPMM 上的 `InitializeWithPermission`。 |
| 費用 | `CollectFee` | 管理員 — 從啟動中清掃協議費用 |
| 費用 | `CollectMigrateFee` | 管理員 — 清掃累積的遷移費用 |
| 費用 | `ClaimCreatorFee` | 建立者 — 在曲線階段領取累積的建立者費用 |
| 歸屬 | `CreateVestingAccount` | 建立者 — 為受益人分配鎖定代幣，畢業後解鎖 |
| 歸屬 | `CreatePlatformVestingAccount` | 平台管理員 — 為平台端受益人分配鎖定代幣 |
| 歸屬 | `ClaimVestedToken` | 受益人 — 懸崖期後領取已解鎖的代幣 |
| 平台設定 | `CreatePlatformConfig` / `UpdatePlatformConfig` | 平台管理員 |
| 平台設定 | `CreatePlatformCurveRule` / `UpdatePlatformCurveRule` / `RemovePlatformCurveRule` / `ClosePlatformCurveRule` | `PlatformConfig.curve_rule_manager` 或平台管理員 — 管理一個 `GlobalConfig` 的啟動參數規則 |
| 平台費用 | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | 平台管理員 |
| 平台存取 | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | 平台管理員 — 維護該平台啟用限制時使用的 `GlobalConfig` 允許清單 |

「ExactIn/ExactOut」分割鏡像 CPMM 的 `SwapBaseInput` / `SwapBaseOutput` — 在鏈上它們是具有略微不同舍入的獨立指令判別器。

**畢業路徑選擇。** 每個新的 `Initialize`、`InitializeV2` 和 `InitializeWithToken2022` 呼叫必須設定 `migrate_type = 1`（`CPSWAP`）。任何嘗試初始化新的 AMM v4 綁定資金池都會返回 `MigrateTypeNotMatch`。`amm_creator_fee_on` 僅選擇結果 CPMM 建立者費用是否適用於報價代幣或兩個代幣；它不選擇目標程式。

`MigrateToAmm` 對於在此限制之前以 `migrate_type = 0` 初始化的現有 `PoolState` 仍可呼叫。此版本不會重寫現有資金池狀態或移除舊版指令。

**報價端代幣程式。** 報價代幣可由 SPL Token 程式或 Token-2022 擁有。每個涉及它的指令 — `CreateConfig`、`InitializeV2`、`InitializeWithToken2022`、所有四個交易指令、`CollectFee`、`CollectMigrateFee`、`ClaimCreatorFee`、`ClaimPlatformFee` 和 `ClaimPlatformFeeFromVault` — 在其報價程式帳戶槽中取得擁有程式。帳戶位置未改變；僅接受的值改變了。傳遞實際擁有 `GlobalConfig.quote_mint` 的程式，你可以從現有啟動的 `PoolState.token_program_flag` bit1 讀取（見[`accounts`](/zh-Hant/products/launchlab/accounts#poolstate)）或從代幣帳戶的擁有者讀取。

已棄用的 `Initialize` 是例外：其報價程式帳戶仍然被類型化為 SPL Token，因此報價代幣為 Token-2022 的設定必須透過 `InitializeV2` 或 `InitializeWithToken2022` 啟動。

`MigrateToCpswap` 是另一個例外，方向相反 — 它無條件地取得**兩個**程式，而不是每個代幣一個。見下面的[遷移帳戶](#cpmm-migration-token-programs)。

## `Initialize`

建立新的啟動。

**參數**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // 或 curve_type=1 的 initial_virtual_quote_reserve
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // 內聯名稱/符號/URI；程式 CPI 至 Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**帳戶**（簡化版）

| # | 名稱 | W | S | 備註 |
|---|------|---|---|-------|
| 1 | `creator` | W | S | 支付租金 + 基礎代幣建立。 |
| 2 | `launch_config` |   |   | 協議設定綁定。 |
| 3 | `launch_state` | W |   | 新帳戶。 |
| 4 | `launch_authority` |   |   | PDA。 |
| 5 | `base_mint` | W | S | 新鮮金鑰對（或 PDA）— 此指令初始化它。 |
| 6 | `base_vault` | W |   | `launch_authority` 在 `base_mint` 上的 ATA。 |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | `launch_authority` 在 `quote_mint` 上的 ATA。 |
| 9 | `metadata` | W |   | Metaplex 元資料 PDA。 |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | 基礎代幣的 SPL Token。`InitializeV2` 和 `InitializeWithToken2022` 取得可能是任一程式的單獨報價程式帳戶。 |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**前置條件**

- `quote_mint ∈ launch_config.allowed_quote_mints`。
- `base_supply_graduation ≤ base_supply_max`。
- 費用參數通過 `launch_config.max_*_fee_rate` 檢查。
- `open_time ≥ now − slop`（SDK 強制 `≥ now`；程式容許輕微回溯）。
- `curve_type` 被識別。

**後置條件**

- `base_mint` 有 `supply = base_supply_max`，全部在 `base_vault` 中。
- `base_mint.mint_authority = launch_authority`，`freeze_authority = None`。
- `LaunchState` 初始化為 `status = Active`、`base_sold = 0`、`quote_reserve_real = 0`。
- `quote_reserve_target` 從曲線參數 + `base_supply_graduation` + `buy_numerator` 計算（大約）。
- 對於附加 `TransferFeeConfig` 的 `InitializeWithToken2022`：`transfer_fee_config_authority = launch_authority`，且 `withdraw_withheld_authority = PlatformConfig.transfer_fee_extension_auth`（當該欄位被設定時），否則 `launch_authority`。提取端在代幣建立時寫入，正是為了讓平台可以在畢業前清掃扣留的費用。見[`platform-config`](/zh-Hant/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

**常見錯誤** — `InvalidQuoteMint`、`FeeRateTooHigh`、`InvalidCurveParams`、`MathOverflow`。

## `Buy`（規範變體：`BuyExactIn`）

使用者提供固定的 `quote_in`；曲線計算 `base_out`。

**參數**

```
quote_in:          u64
minimum_base_out:  u64
```

**帳戶**

| # | 名稱 | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**前置條件**

- `launch_state.status == Active`。
- `now ≥ open_time`。
- `user_quote_ata.balance ≥ quote_in`。
- `quote_in > 0`。

**效果**

1. 將 `quote_in` 分割為 `quote_in_after_fee` 和費用部分。
2. 牛頓求解曲線以獲得給定後費用報價的 `base_out`。
3. `require(base_out ≥ minimum_base_out)` 否則還原 `ExceededSlippage`。
4. 移動 `quote_in` 使用者 → 金庫。移動 `base_out` 金庫 → 使用者。
5. 更新 `base_sold += base_out`、`quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`。
6. 更新費用計數器（`protocol_fees_quote`、`creator_fees_quote`）。
7. `state_data.num_buys += 1`。
8. 如果更新後 `quote_reserve_real ≥ quote_reserve_target`，SDK 通常在同一交易中鏈接 `Graduate` ix。程式不在 `Buy` 內自動畢業 — 需要後續的 `Graduate`。

## `BuyExactOut`

使用者指定精確的 `base_out`；程式計算 `quote_in`。

**參數**

```
base_out:      u64
maximum_quote_in: u64
```

與 `BuyExactIn` 相同的帳戶。使用閉式二次積分（或 curve_type 1 的 CPMM 反函數）而不是牛頓迭代。

## `Sell` / `SellExactIn` / `SellExactOut`

`Buy` 的鏡像。使用者將 `base_in` 返回曲線並接收 `quote_out`。費用從 `quote_out` 中扣除，因此使用者收到的少於原始整合收益。

**前置條件** —

- `user_base_ata.balance ≥ base_in`。
- 賣出不能將 `base_sold` 推低於 0（考慮到會計一致性是冗餘的）。
- 啟動是 `Active`。

**效果** — 對稱於 `Buy`。`base_sold` 減少，`quote_reserve_real` 減少。費用仍然累積。

### 報價端轉帳費用

當報價代幣攜帶 `TransferFeeConfig` 時，金庫移動的金額和支付者被扣除或貸記的金額不同，滑點界限針對支付者端檢查。在沒有擴展的報價代幣上，下面的每個情況都與普通舊版代幣相同。

| 指令 | 參數 | 檢查對象 |
|---|---|---|
| `BuyExactIn` | `amount_in` | 曲線定價於 `amount_in − transfer_fee(amount_in)` — 到達金庫的金額。完整填充精確扣除 `amount_in`；部分填充扣除消耗的金庫金額加上其反向費用。 |
| `BuyExactOut` | `maximum_amount_in` | 金庫金額**加上**反向轉帳費用 — 實際扣除。 |
| `SellExactIn` | `minimum_amount_out` | 賣家在代幣扣留其費用後保留的金額，不是離開金庫的總金額。 |
| `SellExactOut` | `amount_out` | 精確交付。曲線目標 `amount_out` 加上反向轉帳費用。 |

報價的兩個後果：

- 計算為代幣無費用的界限被拒絕。傳遞無費用成本作為 `maximum_amount_in`，或無費用收益作為 `minimum_amount_out`，還原為 `ExceededSlippage`。
- `real_quote` 僅按到達金庫的金額推進。5% 報價代幣上的 `BuyExactIn` `amount_in` 移動 `real_quote` `amount_in × 0.95`。

100% 費用報價代幣（`10000` 基點）無法反轉，在精確輸出路徑上還原為 `CalculateOverflow`。

兩個交易端代幣也被限制為在其匹配槽中傳遞的程式，因此不匹配的 `base_token_program` 現在失敗而不是被忽略。見[`algorithms/token-2022-transfer-fees`](/zh-Hant/algorithms/token-2022-transfer-fees)以了解基礎費用數學。

## `MigrateToAmm` / `MigrateToCpswap`

一旦曲線達到 `total_quote_fund_raising`，將啟動畢業至可交易的資金池。新啟動僅限 CPMM。`MigrateToAmm` 為存儲 `migrate_type` 為 `0` 的現有資金池保留。

**誰簽署**

- `MigrateToAmm` — 綁定 `GlobalConfig` 上記錄的 `migrate_to_amm_wallet`。
- `MigrateToCpswap` — 綁定 `GlobalConfig` 上記錄的 `migrate_to_cpswap_wallet`。

這些錢包通常由 Raydium 運營的畢業 crank 持有；實際上畢業在閾值被超越後幾秒內進行，無論誰觸發最後的買入。

**參數**

`MigrateToAmm` 取三個（主要是 OpenBook 市場參數，程式轉發至 AMM v4）：

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` 不取任何。

**效果（兩者共同）**

1. 驗證 `pool_state.status == Migrate`（即 `quote_reserve_target` 已達到）。否則還原為 `PoolMigrated`（狀態已是 `Migrated`）或 `PoolFunding`（仍在籌資）。
2. 驗證 `pool_state.migrate_type` 匹配指令（AMM 為 `0`，CPMM 為 `1`）。否則還原為 `MigrateTypeNotMatch`。
3. 計算畢業後的儲備：
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI 至目標程式（`AMM v4 Initialize2` 或 `CPMM InitializeWithPermission`）以使用這些儲備建立畢業後資金池。
5. 對於在 2026-08-17 升級後執行的 CPMM 遷移，將 `platform_scale + creator_scale` 合併為一個平台擁有的鎖定 LP 份額，並最多向 `platform_nft_wallet` 鑄造一個費用金鑰 NFT。燒毀 `burn_scale` 餘額。在升級之前，`creator_scale` 被單獨鎖定，其費用金鑰去往代幣建立者。已完成的歷史遷移不被修改。對於舊版 AMM v4 畢業，LP 配置遵循該指令的現有流程。
6. 撤銷 `base_mint.mint_authority`（設定為 `None`）。
7. 翻轉 `pool_state.status = Migrated`，設定 `vesting_schedule.start_time = block_time + cliff_period`。

**Token-2022 轉帳費用授權移交** — 當基礎代幣是攜帶 `TransferFeeConfig` 的 Token-2022 代幣**且** `PlatformConfig.transfer_fee_extension_auth` 非預設時，遷移也將該擴展的授權重新分配給平台金鑰：

- `transfer_fee_config_authority` 總是被重新分配。啟動 `authority` PDA 在整個畢業前階段持有它，因此總有東西要移動。
- `WithheldWithdraw` **僅當 `authority` PDA 仍持有它時**才被重新分配。從 2026-08-27 起建立的啟動已經在代幣建立時在該授權上攜帶 `transfer_fee_extension_auth`，因此該步驟被跳過。守衛是防止遷移在這些代幣上還原的原因 — PDA 無法簽署它不再持有的授權。

如果 `transfer_fee_extension_auth` 在遷移時是 `Pubkey::default()`，兩個授權都不移動，兩者都永久留在 `authority` PDA。見[`platform-config`](/zh-Hant/products/launchlab/platform-config#token-2022-transfer-fee-authorities)。

**後置條件** — `BuyExactIn`、`BuyExactOut`、`SellExactIn`、`SellExactOut` 從此點起將以 `PoolMigrated` 拒絕。結果 AMM 資金池是規範的，交易如同任何其他 AMM v4 / CPMM 資金池。

**常見錯誤** — `PoolFunding`、`PoolMigrated`、`MigrateTypeNotMatch`、`InvalidCpSwapConfig`、`MathOverflow`。

### CPMM 遷移剩餘帳戶

建立 `MigrateToCpswap` 的客戶端必須使用這些固定的 `remaining_accounts` 索引：

| 索引 | 帳戶 |
|---|---|
| 0–4 | 平台費用金鑰擁有者、代幣、代幣帳戶、鎖定流動性 PDA 和元資料帳戶 |
| 5 | 原始啟動建立者；當 `platform_cp_creator` 未設定時使用 |
| 6 | 從 `[b"permission", launch_authority]` 衍生的 CPMM 權限 PDA |
| 7 | 已設定的 `platform_cp_creator`；當欄位非預設時使用 |
| 8 | 排序 `mint0` 的 CPMM 支援代幣 PDA，衍生自 `[b"support_mint", mint0]` |
| 9 | 排序 `mint1` 的 CPMM 支援代幣 PDA，衍生自 `[b"support_mint", mint1]` |

該指令在升級路徑上至少需要十個剩餘帳戶。支援代幣帳戶是唯讀 CPI 輸入。即使代幣沒有初始化的支援記錄，也要衍生兩個地址。仍然附加建立者鎖定帳戶或省略索引 8–9 的舊版建立者必須更新。

### CPMM 遷移代幣程式

`MigrateToCpswap` 無條件地取兩個代幣程式，並自己計算出哪個程式擁有每個代幣。其兩個代幣程式帳戶被相應地重新命名：

| 位置 | 帳戶 | 值 |
|---|---|---|
| 第一個 | `token_program` | 總是舊版 SPL Token 程式 |
| 第二個 | `token_program_2022` | 總是 Token-2022 程式 |

它們替換了前者的 `base_token_program`（無論哪個程式擁有基礎代幣）和 `quote_token_program`（總是舊版）。位置未改變，因此這是值變更而不是佈局變更 — 但兩個值幾乎相反，保持傳遞舊對的建立者一旦任一代幣是 Token-2022 代幣就會在需要舊版程式的地方提供 Token-2022。

舊版程式是必需的，即使兩個代幣都不使用它，因為 CPMM LP 代幣和鎖定流動性費用金鑰 NFT 總是存在於它上面。

## 平台 `GlobalConfig` 允許清單

`PlatformConfig.restrict_global_config` 控制檢查：

- `0`：平台接受任何其他有效的 `GlobalConfig`；不需要允許帳戶。
- `1`：`Initialize`、`InitializeV2` 和 `InitializeWithToken2022` 必須在 `remaining_accounts` 中的任何地方包含匹配的 `PlatformAllowConfig`。

平台管理員使用 `CreatePlatformAllowConfig` 和 `ClosePlatformAllowConfig` 建立或關閉 PDA。其種子是 `[b"platform_allow_config", platform_config, global_config]`。前者管理員管理的 `PlatformGlobalAccess` 指令和 PDA 已停用。

## 平台啟動參數規則

四個指令管理一個 `PlatformCurveRule` 帳戶。所有四個都由 `PlatformConfig.curve_rule_manager` 或平台管理員簽署 — 程式透過從簽署者重新衍生 `PlatformConfig` PDA 接受管理員，因此沒有單獨帳戶證明它。既不是的簽署者返回 `InvalidCurveRuleAuthority`。

| 指令 | 帳戶 | 參數 |
|---|---|---|
| `CreatePlatformCurveRule` | `curve_rule_authority`（簽署者，可變），`platform_config`，`global_config`，`platform_curve_rule`（可變），`system_program` | 無 |
| `UpdatePlatformCurveRule` | 相同五個 | `group_id: u16`，`constraints: Vec<ParamConstraint>` |
| `RemovePlatformCurveRule` | 相同五個 | `group_id: u16` |
| `ClosePlatformCurveRule` | 前四個 | 無 |

`platform_curve_rule` 是 `[b"platform_curve_rule", platform_config, global_config]` 處的 PDA。

- **`Create`** 分配不持有任何群組的帳戶。該狀態不限制任何東西。
- **`Update`** 使用該 `group_id` 更新插入群組，如果存在則完全替換它。它調整帳戶大小以適應，因此簽署者補充它增長的租金並收回它縮小的租金。超過第十個的新群組返回 `CurveRuleGroupsExceeded`；超過 25 個約束、未知欄位或運算子，或同一群組中相同的 `(field, op)` 對兩次返回 `InvalidCurveRuleConstraint`；非常數乘積設定上的四個 `TotalSellA` 衍生欄位返回 `CurveRuleFieldNotSupportedByCurve`。
- **`Remove`** 按 id 刪除一個群組，縮小帳戶並退款差額。未知 id 返回 `CurveRuleGroupNotExist`。
- **`Close`** 將整個租金返回給簽署者。即使 `restrict_curve_param` 保持 `1`，設定也不受限制。

四個都不改變規則是否被強制執行。那是 `UpdatePlatformConfig::RestrictCurveParam(0 | 1)`，僅平台管理員可呼叫。

**在啟動路徑上。** 當 `restrict_curve_param` 是 `1` 時，`InitializeV2` 和 `InitializeWithToken2022` 在 `remaining_accounts` 中需要規則 PDA — 包括當它不存在時，以便省略它無法跳過檢查。缺少帳戶是 `NotEnoughRemainingAccounts`；不滿足任何群組的啟動是 `CurveParamNotMatchPlatformRule`。檢查在 `GlobalConfig` 自己的限制之前執行，只能縮小它們。模型和劇本：[`products/launchlab/curve-rules`](/zh-Hant/products/launchlab/curve-rules)。兩個錯誤都可在客戶端避免 — SDK 將此檢查鏡像為純函數，見[發送前檢查](/zh-Hant/products/launchlab/curve-rules#check-before-you-send)。
