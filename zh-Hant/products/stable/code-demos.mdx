## 設定

```bash
npm install @raydium-io/raydium-sdk-v2 @solana/web3.js @solana/spl-token
```

```ts
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import { Connection, Keypair, clusterApiUrl } from "@solana/web3.js";
import BN from "bn.js";
import bs58 from "bs58";

const connection = new Connection(clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(bs58.decode(process.env.PRIVATE_KEY!));

const raydium = await Raydium.load({ connection, owner, cluster: "mainnet" });

// 在任何 Stable 池報價之前必須執行。initLayout() 會將鏈上
// ModelDataInfo 查詢表取入 raydium.liquidity.stableLayout。
await raydium.liquidity.initLayout();
```

<Warning>
  **`initLayout()` 對 Stable 池不是可選的。** `liquidity.computeAmountOut` 根據 `poolInfo.version` 分支：對於 version 4 使用常數乘積公式，對於其他版本則讀取 `this.stableLayout.stableModelData` 並插值查詢表。該快取在 `initLayout()` 執行前為空，因此在沒有它的情況下報價 v5 池會產生垃圾結果而不是錯誤。它是冪等的且成本低廉——在啟動時呼叫一次即可。

  交易*建構器*（`swap`、`addLiquidity`、`removeLiquidity`）不需要它：它們根據 `pooltype.includes("StablePool")` 分派並發出 `AmmV5*` 指令，你傳入的金額邊界已經計算過了。
</Warning>

<Warning>
  **`liquidity.computeAmountIn` 不支援 Stable 池。** 與 `computeAmountOut` 不同，它沒有版本分支——它總是應用常數乘積反演，因此在 v5 池上會返回錯誤的 `maxAmountIn`。對於針對 Stable 池的精確輸出交換，自己用 `getDxByDyBaseIn` 反演（參見下面的[鏈下報價輔助函式](#鏈下報價輔助函式stablets)），並將結果傳遞給 `swap`，設定 `fixedSide: "out"`。
</Warning>

## 識別 Stable 池

`ApiV3PoolInfoStandardItem` 上的兩個等效信號：

```ts
const isStable =
  pool.version === 5 ||
  pool.pooltype.includes("StablePool"); // SDK 內部使用此字串檢查

// 或者，按程式 ID：
const STABLE_AMM_PROGRAM_ID = "5quBtoiQqxF9Jv6KYKctB59NT3gtJD2Y65kdnB1Uev3h";
const isStableByProgram = pool.programId === STABLE_AMM_PROGRAM_ID;
```

AMM v4（`version: 4`、常數乘積）和 Stable AMM（`version: 5`）都透過 SDK 上相同的 `LiquidityModule` API 流動。在內部，模組分派到：

- `InstructionType.AmmV4AddLiquidity` / `AmmV4RemoveLiquidity` 用於 v4 池
- `InstructionType.AmmV5AddLiquidity` / `AmmV5RemoveLiquidity` 用於 v5（Stable）池

池的 `programId`（與池金鑰一起返回）告訴 SDK 要 CPI 進入哪個程式；你不需要硬編碼它。

## 按代幣對查找池

```ts
import { PublicKey } from "@solana/web3.js";
import type { ApiV3PoolInfoStandardItem } from "@raydium-io/raydium-sdk-v2";

// 兩個常見的代幣作為範例
const mintA = new PublicKey("Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB"); // USDT — 參見 reference/program-addresses
const mintB = new PublicKey("EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"); // USDC

// fetchPoolByMints 返回分頁信封：{ count, data, hasNextPage }
const res = await raydium.api.fetchPoolByMints({
  mint1: mintA.toBase58(),
  mint2: mintB.toBase58(),
});

const stablePool = res.data.find(
  (p) => p.version === 5 || p.pooltype.includes("StablePool"),
) as ApiV3PoolInfoStandardItem | undefined;

if (!stablePool) {
  throw new Error("No Stable pool exists for this mint pair");
}

console.log("Stable pool id:", stablePool.id);
console.log("Stable pool programId:", stablePool.programId);
console.log("TVL:", stablePool.tvl);
```

如果代幣對同時有 v4（常數乘積）池和 v5（穩定）池，回應包含兩者——選擇你的流程需要的那個，或將它們交給 [AMM 路由](/zh-Hant/products/routing)程式，讓它選擇最佳路由。

## 透過 Stable 池交換

`LiquidityModule.swap` 流程與 v4 池的形狀相同——只需將 v5 池物件交給它。有兩個細節容易出錯：`computeAmountOut` 需要池的**即時準備金**接合到池資訊上（API 項目本身不包含它們），其 `slippage` 是純**數字**，不是 `Percent`：

```ts
import BN from "bn.js";

const amountIn = new BN(1_000_000); // 1 USDT（6 位小數），原始單位

// 即時準備金 + 狀態。在主網上你也可以從
// getAmmPoolKeys(poolId) 取得 poolKeys，從 getRpcPoolInfo(poolId) 取得準備金。
const rpcData  = await raydium.liquidity.getRpcPoolInfo(stablePool.id);
const poolKeys = await raydium.liquidity.getAmmPoolKeys(stablePool.id);

const out = raydium.liquidity.computeAmountOut({
  poolInfo: {
    ...stablePool,
    baseReserve:  rpcData.baseReserve,
    quoteReserve: rpcData.quoteReserve,
    status:       rpcData.status.toNumber(),
    version:      5, // 5 = Stable；曲線分支根據此選擇
  },
  amountIn,
  mintIn:  stablePool.mintA.address,
  mintOut: stablePool.mintB.address,
  slippage: 0.005, // 純數字：0.005 = 0.5%（範圍 1 ~ 0.0001）
});

// amountOut / minAmountOut 是原始單位的 BN，不是 TokenAmount。
console.log("Expected out:", out.amountOut.toString());
console.log("Minimum out:", out.minAmountOut.toString());

// 建構並簽署交換交易。`inputMint` 是必需的——沒有它 SDK
// 無法判斷你在池的哪一側出售。
const { transaction, execute } = await raydium.liquidity.swap({
  poolInfo:  stablePool,
  poolKeys,
  amountIn,
  amountOut: out.minAmountOut, // out.amountOut 是滑點前的數字
  inputMint: stablePool.mintA.address,
  fixedSide: "in",
  txVersion: TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Stable swap tx:", txId);
```

SDK 從池金鑰讀取池的 `programId` 並分派進入 Stable AMM 程式。不需要特殊的 `programId` 引數。

## 新增和移除流動性

`addLiquidity` 和 `removeLiquidity` 在 v4 和 v5 池上的工作方式相同：

```ts
import { Percent, TokenAmount, toToken } from "@raydium-io/raydium-sdk-v2";
import Decimal from "decimal.js";

const inputAmount = "100"; // 100 USDT，以人類單位——computePairAmount 接受十進位字串

// 計算曲線對此大小 A 所需的匹配 B 金額。
// 注意：computePairAmount 的 slippage 是 Percent（與 computeAmountOut 的不同）。
const r = raydium.liquidity.computePairAmount({
  poolInfo: stablePool,
  amount:   inputAmount,
  baseIn:   true,
  slippage: new Percent(50, 10_000), // 0.5%
});

const { execute } = await raydium.liquidity.addLiquidity({
  poolInfo: stablePool,
  poolKeys,
  amountInA: new TokenAmount(
    toToken(stablePool.mintA),
    new Decimal(inputAmount).mul(10 ** stablePool.mintA.decimals).toFixed(0),
  ),
  amountInB: new TokenAmount(
    toToken(stablePool.mintB),
    new Decimal(r.maxAnotherAmount.toExact()).mul(10 ** stablePool.mintB.decimals).toFixed(0),
  ),
  otherAmountMin: r.minAnotherAmount,
  fixedSide:      "a",
  txVersion:      TxVersion.V0,
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Add-liquidity tx:", txId);
```

在內部，SDK 發出 `InstructionType.AmmV5AddLiquidity`，因為 `pooltype.includes("StablePool")` 為真。對應的 `removeLiquidity` 流程是對稱的——輸入 `lpAmount` 和你將接受的每一側的最小金額。

## 鏈下報價輔助函式（stable.ts）

對於伺服器端報價或回測，SDK 公開了底層穩定曲線數學：

```ts
import {
  getStablePrice,
  getDxByDyBaseIn,
  getDyByDxBaseIn,
} from "@raydium-io/raydium-sdk-v2";

// 在使用這些之前必須呼叫 initLayout() 一次（將鏈上
// `ModelDataInfo` PDA 載入 SDK 的 StableLayout 快取）。
await raydium.liquidity.initLayout();

// initLayout() 填充 StableLayout 實例；下面三個輔助函式
// 期望的純資料物件是其 `stableModelData` getter，不是實例。
const modelData = raydium.liquidity.stableLayout.stableModelData;

// 準備金以人類單位的純數字傳遞（不是 BN，不是原始單位）。
const coinReserve = 1_200_000; // 池的 coin 側準備金
const pcReserve   = 1_150_000; // 池的 pc 側準備金

// 池當前準備金處的現貨價格。第 4 個引數是 `baseCoin`：
// true 返回 coin-per-pc，false 返回倒數。
const price = getStablePrice(modelData, coinReserve, pcReserve, true);
console.log("Spot price:", price);

// 報價：給定 dx 輸入，輸出多少 dy（未應用費用）？
const dyOut = getDyByDxBaseIn(modelData, coinReserve, pcReserve, 1_000);

// 報價：給定 dy 輸出目標，需要多少 dx 輸入？
const dxIn  = getDxByDyBaseIn(modelData, coinReserve, pcReserve, 1_000);
```

這些是純函式——沒有 RPC，沒有簽署。鏈上 `ModelDataInfo` 由 `initLayout()` 取得一次並快取在 `raydium.liquidity.stableLayout` 內，可讀為 `.stableModelData`。`initStableModelLayout()` 是冪等的：它只在 `validDataCount === 0` 時重新取得，因此再次呼叫 `initLayout()` 是免費的。傳遞當前準備金（`x`、`y`），輔助函式透過二進位搜尋查詢表並在兩個相鄰 `DataElement` 列之間線性插值來計算。參見 [`products/stable/math`](/zh-Hant/products/stable/math) 瞭解底層演算法。

## 透過 AMM 路由進行路由（多跳 / 最佳價格）

如果你不想自己選擇場所，[AMM 路由](/zh-Hant/products/routing)程式將考慮每個 Raydium AMM（v4 / CPMM / CLMM / Stable）並透過最佳組合進行路由：

路由器是五呼叫管道而不是單個 `swap()`，它完整寫出——帶有使其在生產中可用的快取建議——在 [`products/routing/code-demos`](/zh-Hant/products/routing/code-demos)。形狀是：

```ts
import { Router } from "@raydium-io/raydium-sdk-v2";

const poolData = await raydium.tradeV2.fetchRoutePoolBasicInfo(); // 快取此項
const routes   = raydium.tradeV2.getAllRoute({ inputMint: mintA, outputMint: mintB, ...poolData });
const ctx      = await raydium.tradeV2.fetchSwapRoutesData({ routes, inputMint: mintA, outputMint: mintB });
const quotes   = raydium.tradeV2.getAllRouteComputeAmountOut({ /* ...ctx, amount, slippage, ... */ });

const best = quotes[0]; // 排序最佳優先
if (!best) throw new Error("no swap routes were found");

// best.poolInfoList 項目帶有 `version` — 5 標記路徑中的 Stable 池。
console.log(best.routeType, best.poolInfoList.map((p) => p.version));

const poolKeys = await raydium.tradeV2.computePoolToPoolKeys({
  pools: best.poolInfoList,
  ammRpcData:  ctx.ammPoolsRpcInfo,
  clmmRpcData: ctx.clmmPoolsRpcInfo,
});

const { execute } = await raydium.tradeV2.swap({
  routeProgram: Router,
  swapInfo:     best,
  swapPoolKeys: poolKeys,
  ownerInfo:    { associatedOnly: true, checkCreateATAOwner: true },
  txVersion:    TxVersion.V0,
});

// tradeV2.swap 可以返回多個交易；第一個建立中間 ATA。
const { txIds } = await execute({ sequentially: true });
```

<Warning>
  沒有 `raydium.tradeV2.fetchRoutes`，且 `tradeV2.swap` **不**接受 `inputMint` / `outputMint` / `slippage` — 它接受已計算的 `swapInfo` 來自 `getAllRouteComputeAmountOut`。對於**單個**已知池，使用該池類型自己的建構器（`raydium.liquidity.swap` 用於 AMM v4 和 Stable、`raydium.cpmm.swap`、`raydium.clmm.swap`），如本頁前面所示。
</Warning>

這是生產交換器和聚合器的推薦路徑——你永遠不需要手動決定 Stable 池是否存在或它今天是否是更好的場所。

## 建議

1. **對於終端使用者交換**，優先使用 [`tradeV2`](/zh-Hant/products/routing) 路由流程。它處理每個 Raydium 池類型，包括 Stable。
2. **對於池特定操作**（已知 Stable 池上的 LP 新增 / 移除），直接使用 `LiquidityModule` — 它自動偵測 v5 池。
3. **對於鏈下報價 / 分析**，在 `initLayout()` 後呼叫 `getStablePrice` / `getDyByDxBaseIn` / `getDxByDyBaseIn`。模型資料快取後每個報價無 RPC 流量。
4. **不要手工編碼原始 `SwapBaseIn` 指令。** [2026-06-22 升級](/zh-Hant/reference/changelog)移除了死 OpenBook 帳戶，因此新交換佈局採用**9 個帳戶**（舊 18 帳戶佈局仍向後相容解析）。`Deposit` 現在是 12 個帳戶（舊 14 相容），`Withdraw` 12 個（舊 21/22 相容），`WithdrawPnl` 10 個**沒有**相容路徑。SDK 的預建輔助函式為你選擇正確的佈局和順序；自己滾動容易出錯。參見 [`products/stable/instructions`](/zh-Hant/products/stable/instructions) 瞭解完整帳戶表。
