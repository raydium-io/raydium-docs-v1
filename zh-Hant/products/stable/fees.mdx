## 費用模型

Stable AMM 重用 AMM v4 的 **`Fees` 結構**，但不是 AMM v4 的**數字**。Stable 池收取的費用低得多，這正是你對一個為同價資產設計的池所預期的。每個流動性池只有一個費用等級（在初始化時設定）；池無法重新配置為更高的等級。

| 欄位 | 鏈上值 | 說明 |
|-------|----------------|---------|
| `swap_fee_numerator / swap_fee_denominator` | `2 / 10_000` | **總交易費：輸入交易量的 0.02%**。這是唯一實際收取的費用。 |
| `trade_fee_numerator / trade_fee_denominator` | `0 / 10_000` | **零。** 舊版欄位，原用於 OpenBook 訂單定價；為保持版面相容性而保留，不再被讀取。 |
| `pnl_numerator / pnl_denominator` | `12 / 100` | **協議的費用分配：12%** — 即交易量的 `0.02% × 12% = 0.0024%`。 |
| `min_separate_numerator / min_separate_denominator` | `4 / 10_000` | 從總費用中分離 PnL 時使用的最小分離門檻。 |

<Note>
  這些不是「預設值」 — 它們是**每一個**線上主網 Stable 池上的實際值。全部三個（USDT/USDC `2EXiumdi14E9b8Fy62QcA5Uh6WdHS2b38wtSxp72Mibj`、`9DTY3rv8xRa3CnoPoWJCMcQUSY7kUHZAoFKNsBhx8DDz`、`9f4FtV6ikxUZr8fAjKSGNPPnUHJEwi4jNk8d79twbyFf`）都帶有上述完全相同的一組值，而且在 2026-06-22 升級移除 `SetParams` 之後，已不再有任何指令可以改變它們。已透過從主網解碼 `AmmInfo.fees` 驗證。
</Note>

**沒有基金費**行，也**沒有創建者費**行 — 這些是 AMM v4 之後的發明（CPMM/CLMM）。Stable AMM 早於該慣例。

## 分配如何計算

每次交換時：

```
gross_fee = ceil(amount_in * (swap_fee_numerator / swap_fee_denominator))    // 0.02% of amount_in
pnl_portion = gross_fee * (pnl_numerator / pnl_denominator)                  // 12% of gross_fee
lp_portion = gross_fee − pnl_portion                                          // 88% of gross_fee
```

- **`lp_portion`** 留在金庫中，增加 `k`，並在贖回時使 LP 受益。
- **`pnl_portion`** 增加 `AmmInfo.out_put.need_take_pnl_coin` 或 `need_take_pnl_pc`（取決於輸入代幣），並由 `WithdrawPnl` 清掃。

與 CPMM 相同的**不變量保護技巧**：PnL 金額物理上位於金庫中，但從曲線數學中使用的「有效準備金」中扣除，因此移除它不會改變價格。

## OpenBook PnL（已停用）

在其早期，該池也在 OpenBook 上發佈限價訂單；當這些訂單成交時，它會賺取或損失做市商/接單者價差，在 `MonitorStep` 期間結算，並在 `out_put.total_pnl_{coin,pc}` 計數器中追蹤結果。**該路徑已休眠多年** — 該池沒有未平倉訂單，因此唯一的費用累積是上述 0.0024% 的協議分配。`total_pnl_*` 計數器仍在版面中，但不再增加。[2026-06-22 升級](/zh-Hant/reference/changelog)移除了剩餘的 OpenBook 代碼（包括 `MonitorStep`）。CPMM 成為新池的預設值，部分原因是這種與 OpenBook 的前期耦合；Stable AMM 與訂單簿無關。

## 收集

Raydium 多簽（或控制 `amm_admin` 的任何人）呼叫 `WithdrawPnl` 來清掃：

1. 將 `need_take_pnl_coin` 和 `need_take_pnl_pc` 從金庫轉移到管理員指定的帳戶。
2. 將計數器歸零。

該操作不會移動曲線。LP 看不到價格變化。

<Warning>
  `WithdrawPnl` 在 2026-06-22 升級中進行了更改：它現在使用**固定的 10 帳戶、僅限管理員的版面，沒有相容性路徑**（舊版本會因 `InvalidTokenCoin` 等錯誤而失敗），當池的可用資金不足以覆蓋 PnL 時，它直接返回 `TakePnlError` 而不是禁用池。請參閱 [`products/stable/instructions`](/zh-Hant/products/stable/instructions#withdrawpnl)。
</Warning>

## LP 費用贖回

沒有專用的「收集費用」指令。LP 費用在金庫中累積，增加準備金。LP 通過 `Withdraw` 燃燒 LP 來實現這些費用。LP 代幣的價值隨著準備金的增長而增長。

## 視覺化：\$10,000 交易量的去向

在針對線上 Stable 池、以 USDC 為主的 \$10,000 `Swap` 中：

```
總交易費 (0.02%)：              $2.0000
  LP 分配 (0.0176%)：            $1.7600  → 留在池中，提高 k
  PnL 分配 (0.0024%)：           $0.2400  → need_take_pnl_pc，由 WithdrawPnl 清掃
使用者收到（扣除曲線）：        $9,998.00
```

同樣的 \$10,000 通過 AMM v4 池要支付 \$25.00，通過 CPMM `index=0` 池也是 \$25.00 — **貴 12.5 倍**。這個差距正是該產品的重點：穩定幣對的價格變動非常小，因此 LP 對存貨風險只需要非常少的補償，而緊密的曲線加上低費用正是讓大額穩定幣間交換保持競爭力的原因。

## 整合者注意事項

- **報價：** 始終從鏈上讀取 `AmmInfo`；不要硬編碼費用。由於 `SetParams` 現已移除，現有池上的費用參數實際上是固定的。
- **不要假設 AMM v4 的費率。** `Fees` 結構與 AMM v4 共用，因此很容易把 AMM v4 的 `25 / 10_000` 複製到 Stable 的報價中。Stable 池收取的是 `2 / 10_000`。以 0.25% 為 Stable 池報價會把費用高估 12.5 倍。
- **曲線與費用：** 費用的套用與曲線是公式（AMM v4 中的 x·y=k）還是查詢表（Stable）無關。兩者都在觸及曲線之前從輸入金額中扣除費用。
- **無獎勵：** Stable 池不支持池上獎勵發放。生態系統農場（Farm v3/v5/v6）在其他地方處理質押。
