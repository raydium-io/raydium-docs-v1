<Info>
  Raydium 的每個程式都至少有一個特權角色——一個可以升級程式、建立新配置或提取協議費用的金鑰。最小化這些角色能做的事（並將它們放在有延遲的多簽後面）是防止管理員被破壞的主要防線。本頁列舉了這些角色以及它們在實踐中如何被保護。
</Info>

## 按程式分類的角色

### AMM v4

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| 池管理員 | 金庫多簽 (3/5) | 切換池狀態、更新現有池的費用 |

### CPMM

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| AmmConfig 管理員 | 金庫多簽 (3/5) | 建立新 AmmConfigs（費用層級）；切換現有的 |
| 建立池費用接收者 | 金庫多簽 (3/5) | 接收一次性建立池費用 |
| Permission-PDA 建立者 | 程式 `admin` **或** 專用的建立 permission-PDA 擁有者（主網和開發網上的值不同） | 呼叫 `CreatePermissionPda` 以授予權限給 `InitializeWithPermission`。專用擁有者無法呼叫 `ClosePermissionPda`；撤銷仍然只有管理員可以。 |

建立者費用收集不會引入特權角色。`CollectCreatorFeePermissionless` 接受任何支付者，將接收者擁有者限制為 `PoolState.pool_creator`，並將兩個目的地都限制為該建立者的規範 ATA。呼叫者可以資助遺漏的 ATA 並觸發掃描，但無法重定向費用。

### CLMM

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| AmmConfig 管理員 | 金庫多簽 (3/5) | 建立/修改 AmmConfigs |
| DynamicFeeConfig 管理員 | 金庫多簽 (3/5) | `CreateDynamicFeeConfig` / `UpdateDynamicFeeConfig` — 校準 `CreateCustomizablePool` 呼叫可能選擇的動態費用層級 |
| `permission_pda_admin` | 程式 `admin` **或** 專用的 `permission_pda_admin` 金鑰（主網和開發網上的值不同） | `CreatePermissionPda` / `ClosePermissionPda` — 授予或撤銷權限以呼叫 `CreatePermissionedPool`。授予是 `["permission", authority]` PDA 的存在；它**不**賦予任何池變更權力。 |
| `limit_order_admin`（程式範圍） | **鏈下操作熱錢包，不是多簽** | 代表擁有者結算和關閉限價單。保管人金鑰是單一程式範圍常數（主網和開發網上的值不同），通過 `signer == limit_order.owner \|\| signer == limit_order_admin::ID` 在 `SettleLimitOrder` / `CloseLimitOrder` 上檢查。輸出始終進入原始擁有者的 ATA；保管人無法重定向資金、修改訂單或開啟新訂單。 |

持有 `Permission` PDA 讓其權限可以呼叫 `CreatePermissionedPool` — 為已經有規範池的交易對建立額外池，每個都在不同的 `seed_index` 衍生地址。權限僅限於池建立：它無法移動資金、更改費用或觸及任何現有池。撤銷它（`ClosePermissionPda`）會阻止權限建立進一步的池，但保留已建立的池不變。

`limit_order_admin` 是一個刻意狹窄的操作角色。它的存在是為了讓鏈下保管人可以掃描已填充的訂單，而無需訂單擁有者必須在線。保管人金鑰是熱的（存在於保管人 VM 上）並獨立於上述多簽進行輪換。具體來說，保管人權限限於：

- `SettleLimitOrder` — 將訂單的已填充輸出推送到**擁有者的** ATA，以訂單的限價。
- `CloseLimitOrder` — 關閉完全結算的訂單帳戶以回收租金（租金進入訂單擁有者）。

它無法呼叫 `OpenLimitOrder`、`IncreaseLimitOrder`、`DecreaseLimitOrder`、變更任何池欄位或簽署任何其他指令——這些檢查由指令 `Accounts` 結構中的種子和 `has_one` 約束在鏈上強制執行。被破壞的保管人最多可能無法使用（訂單保持停放，直到擁有者自己結算它們）或按順序結算/關閉合法可填充的訂單；它無法將使用者資金移動到擁有者已授權的地方以外的任何地方。

### Farm v6

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| 農場建立者（每個農場） | 農場的建立者錢包 | 資助獎勵金庫、延長時程、回收未使用的獎勵 |

個別農場沒有協議管理員——每個農場的建立者只控制他們的農場，建立者的權力受限（無法沒收使用者質押、無法更改質押鑄幣）。

### LaunchLab

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| 程式管理員 | 共享 Raydium 管理員 | 建立和更新 `GlobalConfig` 帳戶；操作其他僅管理員路徑 |
| 委派配置建立者 | 專用叢集特定權限 | 建立新 `GlobalConfig`；無法更新現有配置 |
| 平台管理員 | 一個 `PlatformConfig` 的 PDA 種子權限 | 更新平台設定並建立或關閉該平台的 `PlatformAllowConfig` 帳戶 |
| 啟動建立者（每個啟動） | 啟動的建立者錢包 | 聲稱結合曲線建立者費用；僅當平台不覆蓋 `platform_cp_creator` 時才接收 CPMM 建立者費用權利 |

平台管理員允許清單是自限制的：它限制該平台下的啟動可能使用哪些 `GlobalConfig` 帳戶。它不授予對其他平台或現有啟動資金的權限。規範委派權限地址存在於 [`reference/program-addresses`](/zh-Hant/reference/program-addresses)。

## 程式升級權限

Raydium 的程式使用標準 Solana **BPF Loader v3** 升級機制。所有程式的升級權限是 3/4 Squads 多簽。

為什麼是 3/4：足夠的簽署者使得單一破壞不足以升級；足夠少以至於協調合法升級是可行的。四個權限是獨立的、氣隙冷設備簽署者，由核心團隊成員持有。順序簽署防止同一交易上的並行批准；交易帶有固定過期窗口。多簽操作定期與 **Solana 的 STRIDE 計畫（非對稱研究）** 合作審查。

### 移除升級權限

Raydium 尚未將任何程式的升級權限設定為空。協議在程式需要可升級的原則下運作（以修補錯誤、新增 Token-2022 等擴展、修復整合漂移）。權衡：使用者信任 3/4 多簽只會部署經過充分審查的升級。

對於想要不可變替代方案的使用者，較舊的 AMM v4 程式自上次審計以來一直很穩定；18 個月內零升級。該程式碼路徑實際上是凍結的，儘管權限仍然存在。

## AmmConfig 權限

每個新 AmmConfig 建立都受到許可——3/5 金庫多簽授權新費用層級和刻度間距。現有池通過 PDA 參考其 AmmConfig；池的費用層級是 AmmConfig 所說的任何內容。

**管理員可以更改現有 AmmConfig 嗎？** 是的，技術上可以。`updateAmmConfig` 可由管理員呼叫。在實踐中，避免對已部署 AmmConfigs 的修改，因為它會無聲地改變使用該配置的所有池的經濟學。協議政策是為任何更改建立新 AmmConfig 並進行遷移。

**管理員可以通過配置竊取協議費用嗎？** 不能——AmmConfig 包含費用參數，但不包含協議費用接收者；那是每個池的單獨不可變地址。

## 協議費用聲稱

掉期費用的一部分（通常是 25 bps 掉期費用的 3–12 bps，取決於配置）累積到協議費用金庫。多簽可以提取這些累積費用。使用者永遠不會看到他們的 LP 餘額因此改變——這是協議的預分配份額，不是 LP 資金。

## 農場建立者權限

Farms v6 給建立者權力：

- 資助獎勵金庫（新增更多代幣）。
- 延長時程（將結束時間推遲）。
- 在結束時間後呼叫 `withdrawReward` 以回收未使用的金庫餘額。

農場建立者**無法**：

- 提取質押的使用者 LP。
- 更改質押鑄幣。
- 追溯更改發放率（僅通過 `setRewards` 向前看）。
- 凍結使用者收穫。

惡意農場建立者最多可能資金不足金庫，使農場乾涸；使用者的本金質押始終是安全的。

## Squads 多簽配置

Raydium 為不同的風險表面運作兩個獨立的 Squads 多簽。兩者都可以通過 [Squads 協議](https://app.squads.so) UI 在鏈上檢查。

| 多簽 | 閾值 | 時間鎖 | 範圍 |
|------|------|--------|------|
| **程式升級** | **3/4** | **24 小時** | 部署 AMM v4、CPMM、CLMM、LaunchLab、Lock、AMM Routing、Stable Swap 和舊版 Farm/Staking 程式新程式位元組碼的唯一權限。在 [`app.squads.so/.../FytDr…ceZQK`](https://app.squads.so/squads/FytDrVzDybM1TwFQPGb8qaxZR7dBCzNeqT3vtQsceZQK/home) 檢視。 |
| **金庫** | **3/5** | 無 | 金庫資產、協議收入、營運費用。目前還持有 Raydium 的有限程式管理員權限（建立 AmmConfigs、掃描協議費用、配置池參數）。在 [`v3.squads.so/dashboard/RVha…dHdtYz09`](https://v3.squads.so/dashboard/RVhaWTdGUGNjTnVFdmdIWk1DTXB3dzJGZW44b0xXQlNKemRnQ3NYM0Rqd20=) 檢視。 |

升級多簽的操作屬性：

- **24 小時時間鎖**在任何交易上。今天批准的升級最早在 24 小時後執行，給使用者時間回應。
- **氣隙冷設備簽署。** 冷設備的網路卡被物理移除；它們只連接到硬體錢包並通過來自單獨熱設備的二維碼讀取交易資料。
- **順序簽署。** 只有在一個冷設備生成並簽署交易後，下一個冷設備才能開始其簽署過程——防止同一交易上的衝突或並行簽署。
- **交易過期。** 每個交易都帶有固定過期窗口，所以陳舊交易自動失效。
- **TOTP + 物理金鑰強制執行**在用於交易啟動和鏈上廣播的熱設備上。
- **公開交易隊列。** 任何人都可以在 Squads UI 上監控待處理升級。

金庫多簽沒有時間鎖——其範圍更窄，日常操作（建立 AmmConfigs、掃描費用）需要當天完成。金庫多簽也持有上述按程式表中列出的有限程式管理員權限；這是一個臨時安排，定期與專案的安全合作夥伴審查。

## 在鏈上驗證權限

驗證程式目前升級權限的最簡單方法：

```bash
solana program show <PROGRAM_ID>
```

輸出包括：

```
Program Id:          CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C
Owner:               BPFLoaderUpgradeab1e11111111111111111111111
ProgramData Address: <ProgramDataPDA>
Authority:           <EXPECTED_MULTISIG_ADDRESS>
Last Deployed In Slot: <slot>
Data Length: <n> bytes
```

如果 `Authority` 不是預期的 Squads 多簽地址，則出現問題。Raydium 在 [`reference/program-addresses`](/zh-Hant/reference/program-addresses) 上發佈預期的權限地址。

對於 AmmConfig / 池管理員角色，取得鏈上帳戶並解碼：

```ts
const config = await raydium.cpmm.getAmmConfig(configPda);
console.log("AmmConfig admin:", config.admin.toBase58());
// 預期：3/5 金庫多簽。
```

## 使用者端考慮

作為使用者/LP/整合者，你應該做什麼？

1. **在大額分配前檢查升級權限。** 確認它與記錄的多簽相符。
2. **監控多簽活動。** [Squads UI](https://v4.squads.so) 顯示待處理交易；計畫升級給你 24 小時來解除，如果你不同意更改。
3. **時間鎖感知的贖回策略。** 如果你運行自動複合器，確保你的解除路徑不需要正在更改的指令。
4. **不要假設程式不可變性。** 每個 Raydium 程式都可以升級；為此計畫。

## 整合者的陷阱

### 1. 快取權限地址

如果你在程式碼中硬編碼升級權限或管理員多簽地址，稍後它輪換，你的驗證失敗。在執行時從 [`reference/program-addresses`](/zh-Hant/reference/program-addresses) 取得或定期刷新。

### 2. 假設 AmmConfigs 穩定

新 AmmConfig 可以隨時建立。你的聚合器/路由器應定期重新取得完整配置清單（每小時可以）。

### 3. 農場建立者悲傷向量

如果你存入低聲譽農場，建立者可能會提前結束農場並回收獎勵金庫（假設沒有使用者質押）。一旦使用者質押，按比例權利由程式強制執行；回收只獲得理性結束後的剩餘。
