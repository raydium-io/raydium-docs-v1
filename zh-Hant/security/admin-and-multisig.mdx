<Info>
  Raydium 的每個程式都至少有一個特權角色——一個可以升級程式、建立新配置或提取協議費用的金鑰。最小化這些角色能做的事（並將它們放在有延遲的多簽後面）是防止管理員被破壞的主要防線。本頁列舉了這些角色以及它們在實踐中如何被保護。

### CLMM

| 角色 | 權限地址 | 能做什麼 |
|------|---------|---------|
| 程式升級 | Squads 多簽 (3/4) | 部署新程式位元組碼 |
| AmmConfig 管理員 | 金庫多簽 (3/5) | 建立/修改 AmmConfigs |
| DynamicFeeConfig 管理員 | 金庫多簽 (3/5) | `CreateDynamicFeeConfig` / `UpdateDynamicFeeConfig` — 校準動態費用層級，`CreateCustomizablePool` 呼叫可選擇加入 |
| `permission_pda_admin` | 程式 `admin` **或**專用 `permission_pda_admin` 金鑰（主網與開發網上的值不同） | `CreatePermissionPda` / `ClosePermissionPda` — 授予或撤銷權限呼叫 `CreatePermissionedPool` 的權利。授予就是存在 `["permission", authority]` PDA；它**不**賦予任何池變更權力。 |
| `limit_order_admin`（程式範圍） | **離線操作熱錢包，不是多簽** | 代表所有者結算和關閉限價單。保管人金鑰是單一程式範圍常數（主網與開發網上的值不同），透過 `signer == limit_order.owner \|\| signer == limit_order_admin::ID` 在 `SettleLimitOrder` / `CloseLimitOrder` 上檢查。輸出始終進入原始所有者的 ATA；保管人無法重定向資金、修改訂單或開啟新訂單。 |

持有 `Permission` PDA 的權限可以呼叫 `CreatePermissionedPool` — 為已有規範池的交易對建立額外池，每個都在不同的 `seed_index` 衍生地址。權限僅限於池建立：它無法移動資金、更改費用或觸及任何現有池。撤銷它（`ClosePermissionPda`）會阻止權限進一步建立池，但已建立的池保持不變。

`limit_order_admin` 是刻意設計的狹隘操作角色。它的存在使離線保管人可以掃除已成交訂單，而無需訂單所有者在線。保管人金鑰是熱的（存在於保管人 VM 上），並獨立於上述多簽進行輪換。具體來說，保管人權限限於：

- `SettleLimitOrder` — 將訂單的已成交輸出推送到**所有者的** ATA，按訂單限價。
- `CloseLimitOrder` — 關閉完全結算訂單的帳戶以回收租金（租金進入訂單所有者）。

它無法呼叫 `OpenLimitOrder`、`IncreaseLimitOrder`、`DecreaseLimitOrder`、變更任何池欄位或簽署任何其他指令——這些檢查由指令 `Accounts` 結構中的種子和 `has_one` 約束在鏈上強制執行。被破壞的保管人最多只能不可用（訂單保持停泊直到所有者自己結算它們）或按順序結算/關閉合法可成交的訂單；它無法將使用者資金移動到所有者已授權的地方以外的任何地方。

## 程式升級權限

Raydium 的程式使用標準 Solana **BPF Loader v3** 升級機制。所有程式的升級權限是 3/4 Squads 多簽。

為什麼是 3/4：足夠的簽署者使單一破壞不足以升級；足夠少使協調合法升級易於操作。四個權限是獨立的、氣隙冷設備簽署者，由核心團隊成員持有。順序簽署防止同一交易上的並行批准；交易帶有固定過期窗口。多簽操作定期與 **Solana 的 STRIDE 計畫（非對稱研究）** 合作審查。

### 移除升級權限

Raydium 尚未將任何程式的升級權限設為空。協議在程式需要可升級的原則下運作（以修補錯誤、新增 Token-2022 等擴展、修復整合漂移）。權衡：使用者信任 3/4 多簽只會部署經過充分審查的升級。

對於想要不可變替代方案的使用者，較舊的 AMM v4 程式自上次審計以來一直穩定；18 個月內零升級。該程式碼路徑實際上是凍結的，儘管權限仍然存在。

## AmmConfig 權限

每個新 AmmConfig 建立都受權限限制——3/5 金庫多簽授權新費用層級和刻度間距。現有池透過 PDA 參考其 AmmConfig；池的費用層級就是 AmmConfig 所說的。

**管理員可以更改現有 AmmConfig 嗎？** 是的，技術上可以。`updateAmmConfig` 可由管理員呼叫。實際上，對已部署 AmmConfigs 的修改被避免，因為它會無聲地改變使用該配置的所有池的經濟學。協議政策是為任何更改建立新 AmmConfig 並遷移。

**管理員可以透過配置竊取協議費用嗎？** 不能——AmmConfig 包含費用參數但不包含協議費用接收者；那是每個池的單獨不可變地址。

## 協議費用索賠

掉期費用的一部分（通常是 25 bps 掉期費用的 3–12 bps，取決於配置）累積到協議費用金庫。多簽可以提取這些累積費用。使用者永遠不會看到他們的 LP 餘額因此改變——這是協議的預先分配份額，不是 LP 資金。

## 農場建立者權限

Farms v6 給建立者權力：

- 資助獎勵金庫（新增更多代幣）。
- 延長時程（將結束時間推遲）。
- 在結束時間後呼叫 `withdrawReward` 以回收未使用金庫餘額。

農場建立者**無法**：

- 提取質押使用者 LP。
- 更改質押鑄幣。
- 追溯更改發放率（僅透過 `setRewards` 向前看）。
- 凍結使用者收穫。

惡意農場建立者最多只能資金不足金庫使農場乾涸；使用者的本金質押始終安全。

## Squads 多簽配置

Raydium 為不同風險表面運作兩個獨立的 Squads 多簽。兩者都可以透過 [Squads 協議](https://app.squads.so) UI 在鏈上檢查。

| 多簽 | 閾值 | 時間鎖 | 範圍 |
|------|------|--------|------|
| **程式升級** | **3/4** | **24 小時** | 部署 AMM v4、CPMM、CLMM、LaunchLab、Lock、AMM Routing、Stable Swap 和舊版 Farm/Staking 程式新程式位元組碼的唯一權限。檢視於 [`app.squads.so/.../FytDr…ceZQK`](https://app.squads.so/squads/FytDrVzDybM1TwFQPGb8qaxZR7dBCzNeqT3vtQsceZQK/home)。 |
| **金庫** | **3/5** | 無 | 金庫資產、協議收入、營運費用。目前也持有 Raydium 的有限程式管理員權限（建立 AmmConfigs、掃除協議費用、配置池參數）。檢視於 [`v3.squads.so/dashboard/RVha…dHdtYz09`](https://v3.squads.so/dashboard/RVhaWTdGUGNjTnVFdmdIWk1DTXB3dzJGZW44b0xXQlNKemRnQ3NYM0Rqd20=)。 |

升級多簽的操作屬性：

- **24 小時時間鎖**在任何交易上。今天批准的升級最早在 24 小時後執行，給使用者時間回應。
- **氣隙冷設備簽署。** 冷設備的網路卡被物理移除；它們只連接到硬體錢包並透過來自單獨熱設備的二維碼讀取交易資料。
- **順序簽署。** 只有在一個冷設備生成並簽署交易後，下一個冷設備才能開始其簽署過程——防止同一交易上的衝突或並行簽署。
- **交易過期。** 每筆交易都帶有固定過期窗口，因此陳舊交易自動失效。
- **TOTP + 物理金鑰強制**在用於交易啟動和鏈上廣播的熱設備上。
- **公開交易隊列。** 任何人都可以在 Squads UI 上監控待處理升級。

金庫多簽沒有時間鎖——其範圍更窄，日常操作（建立 AmmConfigs、掃除費用）需要當天完成。金庫多簽也持有上述按程式表中列出的有限程式管理員權限；這是臨時安排，定期與專案的安全合作夥伴審查。

## 在鏈上驗證權限

驗證程式目前升級權限的最簡單方法：

```bash
solana program show <PROGRAM_ID>
```

輸出包括：

```
Program Id:          CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C
Owner:               BPFLoaderUpgradeab1e11111111111111111111111
ProgramData Address: <ProgramDataPDA>
Authority:           <EXPECTED_MULTISIG_ADDRESS>
Last Deployed In Slot: <slot>
Data Length: <n> bytes
```

如果 `Authority` 不是預期的 Squads 多簽地址，則出現問題。Raydium 在 [`reference/program-addresses`](/zh-Hant/reference/program-addresses) 上發佈預期的權限地址。

對於 AmmConfig / 池管理員角色，取得鏈上帳戶並解碼：

```ts
const config = await raydium.cpmm.getAmmConfig(configPda);
console.log("AmmConfig admin:", config.admin.toBase58());
// Expected: 3/5 treasury multisig.
```

## 使用者端考慮

作為使用者/LP/整合者，你應該做什麼？

1. **在大額分配前檢查升級權限。** 確認它與文件化的多簽相符。
2. **監控多簽活動。** [Squads UI](https://v4.squads.so) 顯示待處理交易；計畫升級給你 24 小時來展開，如果你不同意更改。
3. **時間鎖感知的贖回策略。** 如果你運行自動複合器，確保你的展開路徑不需要被更改的指令。
4. **不要假設程式不可變性。** 每個 Raydium 程式都可以升級；為此計畫。

## 整合者的陷阱

### 1. 快取權限地址

如果你在程式碼中硬編碼升級權限或管理員多簽地址，稍後輪換時，你的驗證失敗。在執行時從 [`reference/program-addresses`](/zh-Hant/reference/program-addresses) 取得或定期刷新。

### 2. 假設 AmmConfigs 穩定

新 AmmConfig 可以隨時建立。你的聚合器/路由器應定期重新取得完整配置列表（每小時可以）。

### 3. 農場建立者悲傷向量

如果你存入低聲譽農場，建立者可以提前結束農場並回收獎勵金庫（假設沒有使用者質押）。一旦使用者質押，按比例權利由程式強制執行；回收只獲得理性結束後的剩餘。
