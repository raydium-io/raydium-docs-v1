<Info>
  CPI ("cross-program invocation") adalah mekanisme yang memungkinkan satu program Solana memanggil program lain. Sebagian besar program Raydium dilengkapi dengan crate wrapper CPI Anchor yang membuat call site terlihat seperti pemanggilan fungsi yang diketik, dengan struct akun yang memiliki nama field yang divalidasi dan helper `cpi::<ix>()`. Halaman ini mendokumentasikan pola umum sekali, kemudian perbedaan per-program. Untuk TypeScript yang dapat dijalankan, lihat halaman `code-demos` dari setiap bab produk.
</Info>

## Pola mana yang berlaku untuk program mana

| Program | Berbasis Anchor | Crate | Di mana |
|---|---|---|---|
| CPMM | Ya | `raydium-cp-swap` (repo publik; path Rust `use` adalah `raydium_cp_swap`) | [Pola umum](#the-general-anchor-cpi-pattern), contoh yang dikerjakan |
| CLMM | Ya | `raydium-clmm` (repo publik; path Rust `use` adalah `raydium_clmm`) | [Menerapkan pola: CLMM](#applying-the-pattern-clmm) |
| LaunchLab | Ya | nama crate tidak dikonfirmasi; sumber program ditutup, tetapi identifier metadata internal IDL on-chain adalah `raydium_launchpad`, nama teknis daripada nama produk (lihat peringatan di [Menerapkan pola: LaunchLab](#applying-the-pattern-launchlab)) | [Menerapkan pola: LaunchLab](#applying-the-pattern-launchlab) |
| Farm v6 | Tidak dikonfirmasi; tidak ada IDL publik atau sumber yang ditemukan (lihat peringatan di [Farm v6](#farm-v6)) | n/a | [Farm v6](#farm-v6) |
| AMM v4 | **Tidak**, mendahului Anchor tanpa crate CPI | tidak ada | [AMM v4](#amm-v4-manual-instruction-construction) |

Jika Anda mengintegrasikan CPMM, CLMM, atau LaunchLab, baca [pola umum](#the-general-anchor-cpi-pattern) terlebih dahulu, kemudian lompat ke bagian program Anda untuk daftar akun dan perbedaan apa pun. Farm v6 dan AMM v4 cukup berbeda sehingga layak membaca bagian mereka secara mandiri.

## Dependensi Cargo

```toml icon="file-code"
# Pilih SATU dari dua crate CPI Raydium per program — lihat peringatan di bawah.
[dependencies]
anchor-lang     = "=1.0.2"   # =0.32.1 jika Anda menargetkan raydium-clmm sebagai gantinya
anchor-spl      = "=1.0.2"   # =0.32.1 demikian pula
raydium-cp-swap = { git = "https://github.com/raydium-io/raydium-cp-swap", branch = "chore/upgrade-anchor", features = ["cpi"] }
# CATATAN: `master` raydium-cp-swap masih menyematkan anchor-lang 0.32.1. Pin `=1.0.2`
# di atas hanya diselesaikan terhadap cabang upgrade; jika Anda menargetkan `master`, gunakan =0.32.1
# dan API CpiContext 0.3x.
# raydium-clmm  = { git = "https://github.com/raydium-io/raydium-clmm",    branch = "master", features = ["cpi"] }
# LaunchLab: sumber program tidak tersedia untuk publik (lihat reference/program-addresses).
# Tidak ada dependensi git untuk ditunjuk. Hasilkan binding CPI dari IDL yang dipublikasikan
# sebagai gantinya. Lihat "Menerapkan pola: LaunchLab" di bawah.
# AMM v4 tidak memiliki crate CPI Anchor yang dipublikasikan; lihat bagiannya sendiri.
```

<Warning>
  **Kunci dependensi harus cocok dengan `[package] name` repo target dengan tepat, termasuk tanda hubung.** Cargo tidak memperlakukan `raydium_cp_swap` sebagai setara dengan `raydium-cp-swap` saat menyelesaikan dependensi *git*.
</Warning>

`branch = "master"` melacak sumber terbaru yang dipublikasikan; pin ke `rev = "<commit>"` spesifik jika Anda memerlukan build yang dapat direproduksi. Ini direkomendasikan setelah Anda melampaui prototyping, karena perubahan tata letak akun upstream di `master` akan memecahkan build Anda tanpa peringatan sebelumnya.

Flag fitur `cpi` membuat crate dikompilasi hanya ke permukaan CPI (struct akun + invoker) daripada program lengkap, sehingga binary Anda tetap kecil.

**`anchor-lang` / `anchor-spl` harus cocok dengan apa yang disematkan crate target**, dan per 2026-09 dua crate Raydium publik **tidak setuju**:

| Crate | Menyematkan `anchor-lang` / `anchor-spl` |
|---|---|
| `raydium-cp-swap` (`chore/upgrade-anchor`) | `=1.0.2` — dari [upgrade 2026-09-09](/id/reference/changelog/2026-09-09-cpmm-anchor-1-and-excess-lamports) |
| `raydium-cp-swap` (`master`) | `0.32.1`, caret-pinned — upgrade belum mendarat di `master` |
| `raydium-clmm` (`master`) | `=0.32.1` |

<Warning>
  **Anda tidak dapat bergantung pada kedua crate dari satu program sekarang.** Masing-masing menyematkan Anchor dengan `=`, jadi Cargo harus menautkan dua salinan Anchor yang tidak kompatibel ke satu binary, dan build gagal. Jika program Anda CPI ke dalam CPMM dan CLMM, Anda harus membaginya menjadi dua program, atau menghilangkan crate CPI yang diketik untuk salah satunya dan mengkodekan instruksi itu secara manual (pola yang ditunjukkan untuk [AMM v4](#amm-v4-manual-instruction-construction) berfungsi untuk program apa pun). Periksa kembali kedua file `Cargo.toml` sebelum memulai — ini diharapkan untuk diselesaikan ketika CLMM pindah ke Anchor 1.x.
</Warning>

<Warning>
  **Anchor 1.0 mengubah dua hal yang setiap call site CPI sentuh.** Jika Anda memindahkan integrasi yang berfungsi dari `0.3x`:

  - **`CpiContext::new` mengambil `Pubkey`, bukan `AccountInfo`.** `CpiContext::new(ctx.accounts.cpmm_program.to_account_info(), accts)` menjadi `CpiContext::new(*ctx.accounts.cpmm_program.key, accts)`. Sama untuk `new_with_signer`. Field struct sekarang `program_id: Pubkey`.
  - **`Context` memiliki satu lifetime, bukan empat.** `Context<'_, '_, 'info, 'info, MyProxySwap<'info>>` menjadi `Context<'info, MyProxySwap<'info>>`.

  Di sisi klien, `RequestBuilder::instructions()` dari `anchor-client` sekarang mengembalikan `Vec<Instruction>` daripada `Result<Vec<Instruction>>` (hilangkan `?`), dan `CommitmentConfig` pindah dari `solana-sdk` — ambil dari `anchor_client` sebagai gantinya. `spl-associated-token-account` 8.0 me-re-export helper-nya dari crate `spl-associated-token-account-interface` baru. `get_associated_token_address` dan `ID` masih dapat dijangkau di *root crate* (`spl_associated_token_account::{get_associated_token_address, ID}`), tetapi helper alamat sudah usang di sana — lebih suka bergantung pada `spl-associated-token-account-interface` secara langsung dan mengimpor `spl_associated_token_account_interface::address::get_associated_token_address` dan `spl_associated_token_account_interface::program::ID`. Perhatikan `::address` dan `::program` adalah modul dari crate *interface*; `spl_associated_token_account::address::…` tidak diselesaikan.
</Warning>

Untuk contoh CPI yang berfungsi yang menghubungkan struct akun end-to-end, lihat [`raydium-io/raydium-cpi-example`](https://github.com/raydium-io/raydium-cpi-example) (mencakup AMM v4, CPMM, dan CLMM). Cabang terbarunya adalah [`anchor-0.31.0`](https://github.com/raydium-io/raydium-cpi-example/tree/anchor-0.31.0) — belum ada cabang Anchor 1.x, jadi perlakukan repo itu sebagai referensi untuk **wiring struct akun**, bukan untuk pin versi yang halaman ini wajibkan.

## Pola CPI Anchor umum

Bagian ini berjalan melalui **CPMM** end-to-end sebagai contoh yang dikerjakan: struct `Accounts`, `CpiContext`, `cpi::<ix>()`. CLMM mengikuti bentuk yang identik, dengan daftar akun yang berbeda dan persyaratan remaining-accounts. LaunchLab mengikuti mekanika yang sama tetapi daftar akunnya membawa beberapa akun tanpa padanan CPMM/CLMM (`global_config`, `platform_config`, `event_authority`, `program`), jadi perlakukan sebagai *pola* yang sama, bukan *bentuk* yang sama. Lihat bagian masing-masing program daripada mengasumsikan daftar akun walkthrough ini ditransfer secara langsung.

### Konstruksi daftar akun

Setiap CPI Raydium memerlukan struct `Accounts` dalam program pemanggil. Field-nya adalah akun apa pun yang *instruksi Anda* butuhkan, dengan validator tingkat field; urutan deklarasi mereka tidak harus cocok dengan urutan akun instruksi Raydium sendiri, karena klien yang dihasilkan IDL Anda menangani mereka berdasarkan nama, bukan posisi:

```rust icon="rust"
use anchor_lang::prelude::*;
use anchor_spl::token::{Token, TokenAccount, Mint};

#[derive(Accounts)]
pub struct MyProxySwap<'info> {
    #[account(mut)]
    pub user: Signer<'info>,

    /// CHECK: divalidasi oleh CPMM
    #[account(mut)]
    pub pool_state: UncheckedAccount<'info>,

    /// CHECK: demikian pula
    pub amm_config: UncheckedAccount<'info>,

    /// CHECK: demikian pula
    pub pool_authority: UncheckedAccount<'info>,

    #[account(mut)]
    pub input_vault: Account<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: Account<'info, TokenAccount>,

    pub input_mint: Account<'info, Mint>,
    pub output_mint: Account<'info, Mint>,

    #[account(mut)]
    pub user_input_ata:  Account<'info, TokenAccount>,
    #[account(mut)]
    pub user_output_ata: Account<'info, TokenAccount>,

    /// Diketik sebagai `Program<RaydiumCpSwap>` daripada `UncheckedAccount`: akun ini
    /// adalah program yang dipanggil, bukan data milik Raydium, jadi wrapper `Program<T>`
    /// Anchor memeriksa alamatnya secara otomatis daripada meninggalkan pemeriksaan itu
    /// kepada callee.
    pub cpmm_program: Program<'info, raydium_cp_swap::program::RaydiumCpSwap>,
    pub token_program: Program<'info, Token>,
    /// CHECK: observation PDA
    #[account(mut)]
    pub observation_state: UncheckedAccount<'info>,
}
```

Sebagian besar akun sisi Raydium adalah `UncheckedAccount` karena callee (Raydium) memiliki validasi. Program pemanggil Anda hanya benar-benar memvalidasi akun yang *Anda* miliki, seperti ATA pengguna dan PDA Anda sendiri. Komentar doc `/// CHECK:` menekan peringatan Anchor tentang pemeriksaan yang hilang. Satu pengecualian sisi Raydium adalah `cpmm_program` itu sendiri: ini adalah program yang dipanggil daripada akun data yang Raydium validasi secara internal, jadi diketik `Program<T>` dan mendapat pemeriksaan alamat otomatis Anchor daripada `/// CHECK:` manual. Bentuk sebagian besar `UncheckedAccount` ini, di mana Raydium memvalidasi akunnya sendiri, sama untuk CLMM dan LaunchLab. Contoh ini mengasumsikan kedua mint adalah Token SPL klasik; jika salah satu sisi dapat berupa mint Token-2022, tambahkan field `token_program_2022: Program<'info, anchor_spl::token_2022::Token2022>` dan teruskan sebagai `input_token_program`/`output_token_program` sisi itu dalam panggilan CPI di bawah daripada `token_program`.

### Membangun panggilan CPI

Anchor menghasilkan satu helper per instruksi, bersama dengan struct akun CPI (`cpi::accounts::Swap`, dialias `CpmmSwap` di bawah). Tidak seperti struct `MyProxySwap` Anda di atas, nama field dan urutan ini diperbaiki oleh IDL `raydium-cp-swap` sendiri dan harus cocok dengan tepat:

```rust icon="rust"
use raydium_cp_swap::cpi::{self, accounts::Swap as CpmmSwap};

pub fn my_proxy_swap(
    ctx: Context<MyProxySwap>,
    amount_in: u64,
    minimum_amount_out: u64,
) -> Result<()> {
    let cpi_accounts = CpmmSwap {
        // `payer` adalah penanda ANDA — harus memiliki `input_token_account`.
        payer:                ctx.accounts.user.to_account_info(),
        // `authority` adalah PDA vault CPMM SENDIRI di seed [b"vault_and_lp_mint_auth_seed"],
        // yang CPMM tandatangani dengan dirinya sendiri. Melewatkan penanda Anda di sini
        // gagal constraint seed (`ConstraintSeeds`) sebelum transfer apa pun berjalan.
        authority:            ctx.accounts.pool_authority.to_account_info(),
        amm_config:           ctx.accounts.amm_config.to_account_info(),
        pool_state:           ctx.accounts.pool_state.to_account_info(),
        input_token_account:  ctx.accounts.user_input_ata.to_account_info(),
        output_token_account: ctx.accounts.user_output_ata.to_account_info(),
        input_vault:          ctx.accounts.input_vault.to_account_info(),
        output_vault:         ctx.accounts.output_vault.to_account_info(),
        input_token_program:  ctx.accounts.token_program.to_account_info(),
        output_token_program: ctx.accounts.token_program.to_account_info(),
        input_token_mint:     ctx.accounts.input_mint.to_account_info(),
        output_token_mint:    ctx.accounts.output_mint.to_account_info(),
        observation_state:    ctx.accounts.observation_state.to_account_info(),
    };
    // Anchor 1.0: argumen pertama adalah Pubkey program, bukan AccountInfo-nya.
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.cpmm_program.key,
        cpi_accounts,
    );

    cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)?;
    Ok(())
}
```

`cpi::swap_base_input` dihasilkan dari IDL; daftar argumennya mencerminkan daftar argumen instruksi Anchor. Setiap program Raydium berbasis Anchor yang dikonfirmasi (CPMM, CLMM, LaunchLab) menghasilkan helper `cpi::<ix>()` dengan cara yang sama, dengan nama fungsi cocok dengan nama instruksi dalam snake_case. Apakah ini meluas ke Farm v6 tidak dikonfirmasi; lihat bagiannya.

### Signer seeds (CPI yang ditandatangani PDA)

Ketika program Anda menandatangani CPI atas nama PDA (umum untuk vault, escrow, dll.), gunakan `CpiContext::new_with_signer`:

```rust icon="rust"
let bump         = ctx.accounts.my_authority_bump;
let signer_seeds: &[&[&[u8]]] = &[&[b"my_authority", &[bump]]];

let cpi_ctx = CpiContext::new_with_signer(
    *ctx.accounts.cpmm_program.key,
    cpi_accounts,
    signer_seeds,
);

cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out)?;
```

Signer seeds harus cocok dengan derivasi PDA. Untuk akun apa pun yang dilewatkan sebagai `authority` (atau peran penanda serupa), runtime Solana memeriksa bahwa PDA menandatangani melalui seed ini.

### Remaining accounts

Beberapa instruksi Raydium mengambil **remaining accounts**, daftar panjang variabel yang ditambahkan setelah akun tetap. Helper CPI Anchor tidak memeriksa tipe remaining accounts; teruskan melalui `.with_remaining_accounts(...)`:

```rust icon="rust"
let cpi_ctx = CpiContext::new(program_id, accounts)
    .with_remaining_accounts(ctx.remaining_accounts.to_vec());
```

Urutan selalu penting, karena program penerima mengulangi remaining accounts dalam urutan Anda teruskan. Dua urutan yang dikonfirmasi:

- **CLMM `SwapV2`**: [tick arrays](#applying-the-pattern-clmm), diurutkan secara directional.
- **Farm v6**: pasangan `(reward_vault, user_reward_ata)`, tetapi hanya dari aliran reward kedua ke depan; lihat [Farm v6](#farm-v6) untuk apa yang ditunjukkan decoding transaksi nyata.

## Menerapkan pola: CLMM

`SwapV2` mengikuti [pola umum](#the-general-anchor-cpi-pattern) di atas dengan daftar akun yang berbeda dan persyaratan remaining-accounts untuk tick arrays. Modul `#[program]` crate dinamai `raydium_clmm`, yang juga merupakan path Rust `use`-nya.

<Warning>
  **Struct akun CPI dinamai `SwapSingleV2`, bukan `SwapV2`.** `SwapV2` adalah nama instruksi on-chain.
</Warning>

```rust icon="rust"
use raydium_clmm::cpi::{self, accounts::SwapSingleV2 as ClmmSwap};

#[derive(Accounts)]
pub struct MyProxyClmmSwap<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: divalidasi oleh CLMM
    pub amm_config: UncheckedAccount<'info>,
    /// CHECK: demikian pula
    #[account(mut)]
    pub pool_state: UncheckedAccount<'info>,

    #[account(mut)]
    pub input_token_account: Account<'info, TokenAccount>,
    #[account(mut)]
    pub output_token_account: Account<'info, TokenAccount>,
    #[account(mut)]
    pub input_vault: Account<'info, TokenAccount>,
    #[account(mut)]
    pub output_vault: Account<'info, TokenAccount>,

    /// CHECK: observation PDA
    #[account(mut)]
    pub observation_state: UncheckedAccount<'info>,

    pub token_program: Program<'info, Token>,
    pub token_program_2022: Program<'info, anchor_spl::token_2022::Token2022>,
    /// CHECK: program memo SPL, diperlukan untuk beberapa path Token-2022
    pub memo_program: UncheckedAccount<'info>,

    pub input_vault_mint: Account<'info, Mint>,
    pub output_vault_mint: Account<'info, Mint>,

    /// Diketik sebagai `Program<T>` daripada `UncheckedAccount`, alasan yang sama dengan
    /// `cpmm_program` CPMM di pola umum di atas: ini adalah program yang dipanggil, dan
    /// `Program<T>` memeriksa alamatnya secara otomatis.
    pub clmm_program: Program<'info, raydium_clmm::program::RaydiumClmm>,
    // remaining_accounts: tick_array_bitmap_extension (jika walk membutuhkannya), kemudian
    // sebanyak akun tick_array yang diharapkan rentang harga swap span.
}
```

Hitung daftar tick-array dengan cara yang sama seperti SDK, melalui quote terhadap state pool saat ini, daripada menebak jumlah tetap; swap yang melampaui array yang Anda lewatkan kembali dengan `TickArrayNotFound` (lihat [`products/clmm/instructions`](/id/products/clmm/instructions) untuk tabel akun lengkap dan daftar error). Teruskan dalam arah price walk: array pertama dalam arah swap terlebih dahulu.

## Menerapkan pola: LaunchLab

LaunchLab berbasis Anchor dan IDL-dipublikasikan: [`raydium_launchpad/raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json) di repo `raydium-idl` publik. Identifier metadata internal IDL itu adalah `raydium_launchpad`, nama teknis untuk program yang mendasar, bukan nama alternatif untuk produk. Tidak seperti CPMM dan CLMM, bagaimanapun, **sumber program itu sendiri tidak tersedia untuk publik** (lihat [`reference/program-addresses`](/id/reference/program-addresses)). Tidak ada dependensi `git = "..."` untuk ditunjuk Cargo, dan tidak ada sumber untuk mengkonfirmasi apa path Rust `use` crate nyata.

Hasilkan binding dari IDL yang dipublikasikan menggunakan makro `declare_program!` Anchor. Simpan JSON IDL sebagai `idls/raydium_launchpad.json` di crate Anda (Cargo mencari direktori `idls/` relatif terhadap `CARGO_MANIFEST_DIR`), kemudian `declare_program!(raydium_launchpad);` menghasilkan struct `raydium_launchpad::cpi::accounts::<Ix>` dan fungsi `cpi::<ix>()` langsung dari IDL, tidak ada sumber program yang diperlukan. Nama struct akun yang dihasilkan selalu nama instruksi dalam PascalCase (`buy_exact_in` → `BuyExactIn`), dan nama field cocok dengan nama akun IDL dengan tepat, daftar akun yang sama sudah digunakan di `MyProxyBuy` di bawah.

Bentuk CPI mengikuti [pola umum](#the-general-anchor-cpi-pattern). Daftar akun dan argumen di bawah berasal dari instruksi `buy_exact_in` IDL on-chain, bukan dari `products/launchlab/instructions.mdx`:

```rust icon="rust"
use anchor_lang::prelude::*;
use anchor_spl::token::{Token, TokenAccount, Mint};
use raydium_launchpad::cpi::{self, accounts::BuyExactIn};

#[derive(Accounts)]
pub struct MyProxyBuy<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,

    /// CHECK: PDA, seeds = [b"vault_auth_seed"], divalidasi oleh program
    pub authority: UncheckedAccount<'info>,

    /// CHECK: divalidasi oleh program
    pub global_config: UncheckedAccount<'info>,
    /// CHECK: divalidasi oleh program
    pub platform_config: UncheckedAccount<'info>,

    /// CHECK: divalidasi oleh program
    #[account(mut)]
    pub pool_state: UncheckedAccount<'info>,

    #[account(mut)]
    pub user_base_token: Account<'info, TokenAccount>,
    #[account(mut)]
    pub user_quote_token: Account<'info, TokenAccount>,
    #[account(mut)]
    pub base_vault: Account<'info, TokenAccount>,
    #[account(mut)]
    pub quote_vault: Account<'info, TokenAccount>,

    pub base_token_mint: Account<'info, Mint>,
    pub quote_token_mint: Account<'info, Mint>,

    /// CHECK: token program mint base (Token SPL atau Token-2022, tergantung mint)
    pub base_token_program: UncheckedAccount<'info>,
    /// Diketik sebagai `Program<Token>` daripada `UncheckedAccount`: IDL memperbaiki ini ke
    /// Token SPL klasik secara khusus (tidak seperti base_token_program di atas), jadi
    /// pemeriksaan alamat bawaan Anchor pada `Program<Token>` cukup dengan sendirinya.
    pub quote_token_program: Program<'info, Token>,

    /// CHECK: PDA, seeds = [b"__event_authority"], diperlukan oleh pola emit_cpi! program
    pub event_authority: UncheckedAccount<'info>,
    /// CHECK: akun program itu sendiri, diperlukan bersama event_authority
    pub program: UncheckedAccount<'info>,
}

pub fn my_proxy_buy(
    ctx: Context<MyProxyBuy>,
    amount_in: u64,
    minimum_amount_out: u64,
    share_fee_rate: u64,
) -> Result<()> {
    let cpi_accounts = BuyExactIn {
        payer:               ctx.accounts.payer.to_account_info(),
        authority:           ctx.accounts.authority.to_account_info(),
        global_config:       ctx.accounts.global_config.to_account_info(),
        platform_config:     ctx.accounts.platform_config.to_account_info(),
        pool_state:          ctx.accounts.pool_state.to_account_info(),
        user_base_token:     ctx.accounts.user_base_token.to_account_info(),
        user_quote_token:    ctx.accounts.user_quote_token.to_account_info(),
        base_vault:          ctx.accounts.base_vault.to_account_info(),
        quote_vault:         ctx.accounts.quote_vault.to_account_info(),
        base_token_mint:     ctx.accounts.base_token_mint.to_account_info(),
        quote_token_mint:    ctx.accounts.quote_token_mint.to_account_info(),
        base_token_program:  ctx.accounts.base_token_program.to_account_info(),
        quote_token_program: ctx.accounts.quote_token_program.to_account_info(),
        event_authority:     ctx.accounts.event_authority.to_account_info(),
        program:             ctx.accounts.program.to_account_info(),
    };
    // `program` berlipat ganda sebagai target CPI di sini: akun LaunchLab sendiri adalah
    // salah satu akun yang diperlukan instruksinya (untuk pola emit_cpi!-nya) dan program
    // yang CpiContext::new panggil.
    let cpi_ctx = CpiContext::new(
        *ctx.accounts.program.key,
        cpi_accounts,
    );

    cpi::buy_exact_in(cpi_ctx, amount_in, minimum_amount_out, share_fee_rate)?;
    Ok(())
}
```

Pasca-kelulusan, program target adalah CPMM atau AMM v4 tergantung pada `pool_state.migrate_type`, yang `products/launchlab/accounts.mdx` katakan diatur pada waktu `Initialize`. Daftar akun CPI Anda harus disiapkan untuk salah satu, atau Anda perlu membaca `migrate_type` dari `PoolState` terlebih dahulu dan cabang.

## Propagasi error

Setiap program Raydium berbasis Anchor mengembalikan enum error-nya sendiri; Anchor membungkusnya, jadi program pemanggil Anda melihatnya sebagai `Err(ProgramError::Custom(code))`. Untuk menangani error spesifik:

```rust icon="rust"
use raydium_cp_swap::error::ErrorCode as CpmmErr;

match cpi::swap_base_input(cpi_ctx, amount_in, minimum_amount_out) {
    Ok(_) => Ok(()),
    Err(e) => {
        msg!("CPMM swap gagal: {:?}", e);
        // Re-raise, atau konversi ke tipe error Anda sendiri.
        Err(e)
    }
}
```

Tukar tipe error yang relevan untuk program yang Anda panggil (`raydium_clmm::error::ErrorCode` untuk CLMM, dan seterusnya). Nomor kode error stabil per kebijakan IDL ([`sdk-api/anchor-idl`](/id/sdk-api/anchor-idl#idl-change-policy)), jadi Anda dapat menguji terhadap kode spesifik dengan membandingkan nilai numerik. Tabel error lengkap: [CPMM](/id/reference/error-codes#cpmm-standard-amm-errors), [CLMM](/id/reference/error-codes#clmm-errors), [AMM v4, Farm v6, dan LaunchLab](/id/reference/error-codes#amm-v4-farm-v3-/-v5-/-v6-launchlab-errors).

## Compute budget dalam CPI yang dikomposisi

Setiap frame CPI memiliki overhead, dan konsumsi CU callee sendiri menumpuk di atas milik Anda, jadi transaksi yang memanggil Raydium dari dalam program Anda memerlukan compute budget eksplisit daripada mengandalkan default 200k CU.

<Note>
  **Diukur, bukan diestimasi.** `swap_base_input` CPMM di mainnet mengkonsumsi **~23.000 CU** dalam program CPMM itu sendiri — sampel 2026-09-09 di delapan swap langsung di pool volume tinggi (22.721–23.052), dibaca dari baris log `Program CPMMoo8… consumed N of M compute units`. Untuk perbandingan: swap AMM v4 ~26.000; `swap` CLMM ~41.000; `swap_v2` CLMM ~48.000 (43.838–52.887), naik dengan setiap tick crossing.

  Revisi sebelumnya dari halaman ini melaporkan ~47.700 CU untuk proxy-swap CPI. Angka itu adalah *seluruh transaksi* (`computeUnitsConsumed`), yang mencakup program pemanggil Anda sendiri, frame CPI dan setup ATA apa pun — bukan biaya callee. Keduanya berguna, tetapi mereka bukan angka yang sama, jadi bandingkan seperti dengan seperti. Ukur transaksi Anda sendiri daripada membudgetkan dari salah satu.
</Note>

CPI CLMM dan LaunchLab lebih mahal (CLMM khususnya berjalan tick arrays tambahan melalui `remaining_accounts`, menambah CU per array), tetapi hanya angka CPMM di atas yang merupakan nilai terukur. Selalu atur batas `ComputeBudgetProgram::set_compute_unit_limit(...)` eksplisit yang diukur dari pengukuran Anda sendiri, bukan angka yang disalin dari dokumentasi, karena batas CU default 200k akan diam-diam habis dan biaya per-instruksi bergeser saat program diupgrade.

## AMM v4: konstruksi Instruction manual

AMM v4 mendahului Anchor dan tidak memiliki crate CPI, menjadikannya satu-satunya program dalam doc ini yang tidak mengikuti pola umum di atas. Bangun `Instruction` dengan tangan:

```rust icon="rust"
use anchor_lang::prelude::*;
use anchor_lang::solana_program::program::invoke_signed;
use anchor_lang::solana_program::instruction::{Instruction, AccountMeta};

const AMM_V4_PROGRAM_ID: Pubkey = pubkey!("675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8");

// Discriminator SwapBaseIn adalah 9.
let mut data = vec![9u8];
data.extend_from_slice(&amount_in.to_le_bytes());
data.extend_from_slice(&minimum_amount_out.to_le_bytes());

let ix = Instruction {
    program_id: AMM_V4_PROGRAM_ID,
    accounts: vec![
        AccountMeta::new_readonly(token_program_id, false),
        AccountMeta::new(amm_id, false),
        AccountMeta::new_readonly(amm_authority, false),
        // ... akun yang tersisa per products/amm-v4/instructions ...
    ],
    data,
};
invoke_signed(&ix, &account_infos, signer_seeds)?;
```

Lihat [`products/amm-v4/code-demos`](/id/products/amm-v4/code-demos) untuk daftar akun lengkap.

## Farm v6

**Gunakan TS SDK jika itu pilihan untuk integrasi Anda.** `raydium.farm.deposit(...)` (lihat [`products/farm-staking/code-demos`](/id/products/farm-staking/code-demos)) dijalankan oleh demo nyata dan tidak bergantung pada apakah crate Anchor ada untuk program ini.

<Warning>
  **Farm v6 tidak menawarkan path CPI Anchor.** Tidak ada crate `raydium_farm_v6` di crates.io, tidak ada repo sumber publik, dan tidak ada IDL on-chain — program tidak memiliki akun `anchor:idl` legacy maupun entri dalam Program Metadata program (lihat [`sdk-api/anchor-idl`](/id/sdk-api/anchor-idl)). Perlakukan sebagai program non-Anchor dan bangun instruksinya dengan tangan, seperti di bawah.
</Warning>

**Jika Anda memerlukan Rust CPI bagaimanapun**, misalnya composing dari program on-chain lain, bangun `Instruction` dengan tangan, dengan cara yang sama seperti [AMM v4](#amm-v4-manual-instruction-construction): turunkan daftar akun nyata dan discriminator instruksi secara independen, misalnya dengan mendecode layout TypeScript SDK (`raydium-sdk-V2`'s farm module), mendecode transaksi nyata secara langsung (lihat di bawah), atau dump dan disassemble program yang di-deploy.

Untuk bentuk instruksi zero-argument yang konsisten dengan harvest atau claim call, urutan akun nyata adalah prefix tetap (`token_program`, akun state farm, PDA vault-authority, vault reward pertama PDA itu, PDA kedua, caller, dan ATA caller untuk mint reward pertama itu), diikuti oleh pasangan `(reward_vault_i, user_reward_ata_i)` dalam `remaining_accounts` untuk setiap aliran reward setelah yang pertama. Konvensi pairing adalah nyata, tetapi hanya dimulai pada aliran reward kedua: vault dan ATA aliran pertama adalah akun tetap, bukan berdekatan satu sama lain, dan bukan bagian dari `remaining_accounts` sama sekali.

## Menguji alur CPI

Dev lokal memerlukan program Raydium tersedia di test validator Anda. Tiga opsi:

1. **`anchor test` dengan program clone.** Menarik bytecode mainnet yang di-deploy ke validator lokal Anda; lihat [Cloning programs into a local validator](#cloning-programs-into-a-local-validator) di bawah untuk konfigurasi `Anchor.toml` dan dua hal yang membuat test pembuatan pool gagal secara khusus.
2. **Devnet.** Raydium men-deploy sebagian besar program ke devnet, tetapi di **program ID yang berbeda dari mainnet** untuk setiap program (CPMM, CLMM, AMM v4, Stable AMM, dan LaunchLab masing-masing memiliki alamat devnet yang berbeda; lihat tabel Devnet di [`reference/program-addresses`](/id/reference/program-addresses)). Farm v3/v5/v6 tidak dapat diandalkan dipublikasikan di devnet; API langsung (`https://api-v3-devnet.raydium.io/main/info`) memiliki gambaran saat ini. Jika Anda menggunakan konstanta `DEVNET_PROGRAM_ID` bundel `raydium_clmm` (atau setara untuk crate lain), jangan asumsikan ID mainnet juga berfungsi di devnet. Jalankan `anchor test --provider.cluster devnet` untuk mengenai kode langsung setelah Anda memiliki alamat yang tepat.
3. **Local deploy.** Clone repo Raydium (CPMM, CLMM; sumber LaunchLab tidak tersedia untuk opsi ini) dan `anchor deploy` ke validator lokal. Menambah overhead siklus test tetapi memungkinkan Anda memodifikasi callee untuk debugging.

Jalankan dengan `anchor test`, atau `anchor build` terlebih dahulu dan `anchor test --skip-build` setelahnya jika Anda mengulangi file test tanpa mengubah program.

### Cloning programs into a local validator

```toml icon="file-code"
[test]
# Default (5s) tidak cukup setelah Anda clone beberapa akun, karena masing-masing adalah
# putaran RPC mainnet sekuensial selama startup validator.
startup_wait = 60000

[test.validator]
url = "https://api.mainnet-beta.solana.com"

[[test.validator.clone]]
address = "CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK"  # CLMM

[[test.validator.clone]]
address = "CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C"  # CPMM

[[test.validator.clone]]
address = "LanMV9sAd7wArD4vJFi2qDdfnVhFxYSUg6eADduJ3uj"   # LaunchLab

[[test.validator.clone]]
address = "FarmqiPv5eAj3j1GMdMCMUGXqPUvmquZtMy86QH6rzhG"  # Farm v6
```

Ini berfungsi dengan program ID terlepas dari apakah sumber program publik, jadi LaunchLab clone dengan cara yang sama seperti CPMM dan CLMM meskipun sumbernya tidak tersedia. `reference/program-addresses` adalah sumber kebenaran untuk setiap alamat di sini.

<Warning>
  **Clone program tidak cukup jika test Anda juga *membuat* pool** (daripada swap terhadap yang sudah ada). Instruksi `initialize` CPMM memvalidasi akun `amm_config` dan `create_pool_fee`-nya terhadap data on-chain nyata, jadi Anda perlu clone itu juga, atau `initialize` gagal sama sekali. Untuk CPMM khususnya: clone tier biaya `AmmConfig` yang Anda inginkan (ambil alamatnya dari `GET https://api-v3.raydium.io/main/cpmm-config`, indeks 0 adalah tier 0,25%) dan [akun token penerima biaya](/id/reference/program-addresses#shared-config-/-pda-conventions), divalidasi dengan alamat tepat, bukan dibuat on-the-fly, jadi harus sudah ada.
</Warning>

<Warning>
  **Pool yang baru dibuat test Anda tidak dapat ditukar dalam sekejap.** `initialize` CPMM diam-diam menimpa `open_time` yang diminta yang tidak ketat di masa depan (`if open_time <= block_timestamp { open_time = block_timestamp + 1 }`), jadi bahkan `startTime: 0` ("buka segera," per SDK) meninggalkan celah nyata ≥1-detik sebelum pool menerima swap. Test yang membuat pool dan swap terhadapnya dengan penundaan nol akan mengenai [`NotApproved`](/id/reference/error-codes#cpmm-standard-amm-errors). `await` singkat (1–2s) antara pembuatan pool dan swap pertama sudah cukup. Ini spesifik untuk testing; manusia menjalankan dua perintah manual terpisah biasanya tidak akan memperhatikan, karena mengetik dan startup proses sudah makan lebih dari satu detik.
</Warning>
