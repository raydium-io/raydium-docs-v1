## Ringkasan satu paragraf

AMM v4 adalah program yang diluncurkan Raydium. Program ini mempertahankan invariant constant-product (`x · y = k`). Awalnya dirancang sebagai **AMM hybrid**: setiap pool berdiri di atas pasar limit-order-book OpenBook (dulunya Serum) dan mencerminkan sebagian dari kurvanya sebagai limit order di buku tersebut, sehingga pengguna dan agregator dapat swap langsung terhadap pool (jalur AMM) atau terhadap limit order yang dimiliki pool di OpenBook (jalur CLOB). **Ketergantungan OpenBook telah dihapus dari program** — pool tidak lagi memposting atau mempertahankan order di OpenBook, dan semua traffic swap saat ini mengalir melalui entrypoint swap V2 AMM-only. Token-2022 tidak didukung. AMM v4 **masih sepenuhnya operasional sebagai AMM constant-product** — setiap pool terus trading, fee masih terkumpul, LP masih mendapat keuntungan — tetapi UI dan SDK mengarahkan pembuatan pool baru ke [CPMM](/id/products/cpmm) karena CPMM lebih murah dan mendukung lebih banyak tipe mint.

## Sejarah hybrid (konteks)

Saat peluncuran, mendirikan pool bersama order book Serum berisiko memfragmentasi likuiditas. Desain hybrid menerbitkan kurva AMM ke buku sebagai limit order, sehingga router order-book melihat kedalaman pool secara gratis. Setelah OpenBook memisahkan diri dari Serum pada akhir 2022, program terus bekerja terhadap OpenBook dengan perubahan minimal. Seiring CPMM dan agregator on-chain berkembang, manfaat sisi orderbook memudar, dan integrasi OpenBook AMM v4 akhirnya dimatikan — kurva sekarang menjadi satu-satunya permukaan eksekusi pool.

## Apa yang AMM v4 berikan (yang CPMM tidak berikan)

- **Likuiditas dalam untuk pasangan legacy.** Pasangan utama (SOL-USDC, mSOL-USDC, dll.) dengan TVL AMM v4 besar tetap menjadi venue terdalam untuk trade tersebut.

(Secara historis, AMM v4 juga menawarkan visibilitas sisi orderbook melalui mekanisme hybrid OpenBook, tetapi jalur tersebut tidak lagi aktif. Setiap integrator yang sebelumnya merutekan melalui order OpenBook AMM harus sekarang merutekan langsung melalui entrypoint swap AMM.)

## Apa yang AMM v4 tidak berikan

- **Token-2022.** Tidak didukung. AMM v4 ditulis sebelum Token-2022 ada; tata letak akunnya mengasumsikan SPL Token klasik.
- **Jumlah akun rendah pada swap v1.** Tata letak `SwapBaseIn` / `SwapBaseOut` legacy masih membawa akun market OpenBook sebagai placeholder posisional (diterima tetapi tidak lagi divalidasi atau digunakan). Gunakan `SwapBaseInV2` / `SwapBaseOutV2` untuk menghilangkannya dan mengecilkan transaksi.
- **Penggunaan compute rendah.** Bahkan swap V2 lebih mahal daripada swap CPMM.
- **Alur pembuatan pool baru default.** Pool baru dibuat dengan `Initialize2` (entrypoint legacy `Initialize` / `PreInitialize` telah dihapus dan sekarang revert). UI Raydium, SDK, dan `api-v3.raydium.io` tidak lagi menampilkan tombol "buat pool AMM v4" — jalur default untuk pool baru adalah CPMM.

## Model mental

Pool AMM v4 hari ini adalah AMM constant-product `x · y = k`. Kedua vault sepenuhnya tersedia untuk kurva — tidak ada fraksi yang berkomitmen untuk order OpenBook, karena integrasi OpenBook telah dihapus. Operasi adalah **swap** (pengguna ↔ pool, melalui `SwapBaseInV2` / `SwapBaseOutV2`) dan **deposit** / **withdraw** (operasi LP). **Crank** lama (`MonitorStep`) telah dihapus dan sekarang revert jika dipanggil.

*Model mental historis (pra-deaktivasi):* sebagian dari setiap vault disimpan sebagai open-book order; penyelesaian order yang terisi terjadi selama operasi swap dan LP; swap yang dirutekan dapat terisi terhadap order OpenBook milik pool sendiri. Tidak ada dari ini yang beroperasi hari ini.

## Mengapa CPMM adalah default yang direkomendasikan

CPMM menghilangkan ketergantungan OpenBook. Trade-off-nya:

- Transaksi CPMM 2×–3× lebih murah dalam compute.
- CPMM mendukung mint Token-2022.
- Agregator sekarang mengintegrasikan CPMM langsung melalui Raydium SDK, sehingga manfaat visibilitas order-book sebagian besar tidak relevan.
- Risiko operasional: secara historis pemadaman atau jeda OpenBook dapat menurunkan pool AMM v4 (order basi). Dengan ketergantungan OpenBook sekarang dihapus dari program, coupling tersebut hilang — tetapi CPMM tetap menjadi default yang direkomendasikan dan lebih murah.

Lihat [`protocol-overview/versions-and-migration`](/id/protocol-overview/versions-and-migration) untuk panduan migrasi.

## Kapan AMM v4 adalah pilihan yang tepat

- Anda merutekan swap dan salah satu pool kandidat adalah pool AMM v4 dengan harga terbaik.
- Anda menyediakan atau mengelola likuiditas di pool AMM v4 yang ada — migrasi adalah pilihan, bukan keharusan; pool terus berfungsi sebagai AMM murni.
- Anda mempertahankan integrasi yang dibangun terhadap AMM v4 dan tidak memiliki alasan untuk bermigrasi.

(Visibilitas order-book di OpenBook tidak lagi menjadi alasan untuk memilih AMM v4 — integrasi tersebut sudah mati.)

Untuk pool constant-product yang baru, [CPMM](/id/products/cpmm) adalah default yang lebih sederhana.
