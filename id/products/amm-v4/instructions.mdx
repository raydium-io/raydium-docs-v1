## `Initialize2`

Bootstrap pool AMM v4 baru yang terikat ke pasar OpenBook yang ada.

**Argumen**


**Akun** (dapat ditulis `W`, penandatangan `S`)

| # | Nama | W | S | Catatan |
|---|------|---|---|---------|
| 1 | `token_program` |   |   | Diperiksa `== spl_token::id()`. |
| 2 | `associated_token_program` |   |   | Digunakan untuk membuat ATA LP kreator. |
| 3 | `system_program` |   |   | |
| 4 | `rent` |   |   | Masih diteruskan ke CPI `initialize_account` / `initialize_mint` — jangan dihilangkan. |
| 5 | `amm` | W |   | PDA `AmmInfo` `[programId, market, "amm_associated_seed"]`; dibuat di sini. |
| 6 | `amm_authority` |   |   | PDA `["amm authority"]`; argumen `nonce` harus sama dengan bump-nya. |
| 7 | `lp_mint` | W |   | PDA `[programId, market, "lp_mint_associated_seed"]`; dibuat di sini. |
| 8 | `coin_mint` |   |   | Harus berbeda dari `pc_mint` (`InvalidCoinMint`). |
| 9 | `pc_mint` |   |   | |
| 10 | `pool_coin_token_account` | W |   | PDA `[programId, market, "coin_vault_associated_seed"]`. |
| 11 | `pool_pc_token_account` | W |   | PDA `[programId, market, "pc_vault_associated_seed"]`. |
| 12 | `pool_target_orders_account` | W |   | PDA `[programId, market, "target_associated_seed"]`. |
| 13 | `amm_config` |   |   | PDA config tingkat program `["amm_config_account_seed"]`; `InvalidConfigAccount` jika tidak cocok. |
| 14 | `create_fee_destination` | W |   | Harus sama dengan `config_feature::create_pool_fee_address`; jika tidak, `InvalidFee`. |
| 15 | `market` |   |   | Tidak divalidasi — hanya dipakai sebagai seed variabel untuk setiap PDA di atas, dan disimpan sebagai bidang referensi. |
| 16 | `user_wallet` | W | S | Kreator. Membayar rent, biaya pembuatan pool, dan deposit awal. |
| 17 | `user_token_coin` | W |   | |
| 18 | `user_token_pc` | W |   | |
| 19 | `user_token_lp` | W |   | ATA LP kreator; dibuat oleh program. |

<Note>
  **Dua tata letak yang diterima.** Daftar 19-akun di atas adalah yang direkomendasikan. Untuk
  kompatibilitas mundur program juga membaca tata letak warisan 21-akun, yang menyisipkan
  `amm_open_orders` yang diabaikan pada posisi 7 dan `market_program` yang diabaikan pada posisi
  16 — inilah yang masih dipancarkan oleh instruction builder `initialize2` di dalam repo. Panjang
  lain apa pun akan diurai secara posisional terhadap tata letak warisan dan akan gagal.
</Note>

**Kondisi pasca**

- LP yang di-mint ke kreator = `sqrt(init_coin_amount × init_pc_amount) − 10^coin_mint.decimals`. Desimal LP sama dengan `coin_mint.decimals`, sehingga jumlah yang dikurangi tepat satu token LP utuh; jumlah itu tidak pernah di-mint dan permanen berada di luar sirkulasi. Jika `sqrt(...)` berada di bawah nilai itu, instruksi dibatalkan dengan `InitLpAmountTooLess`.
- `AmmInfo.lp_amount` menyimpan `sqrt(...)` penuh, **bukan** jumlah yang di-mint — sehingga `lp_mint.supply` permanen lebih rendah satu token LP utuh dibanding `amm.lp_amount`. Semua matematika pro-rata memakai `amm.lp_amount`.
- Tidak ada pesanan OpenBook yang diposting (grid order-book telah dihapus). `AmmInfo.market` mencatat akun yang dilewatkan pada slot 15, tetapi `AmmInfo.open_orders` dan `AmmInfo.market_program` keduanya ditulis sebagai `Pubkey::default()`, dan `coin_lot_size` / `pc_lot_size` / `min_size` diinisialisasi ke `0`. Pada tata letak warisan 21-akun, akun tambahan `amm_open_orders` dan `market_program` dibaca lalu dibuang.

**Kesalahan umum** — `InvalidCoinMint` (mint coin dan pc identik), `InvalidConfigAccount` (PDA `amm_config` salah), `InvalidFee` (tujuan biaya pembuatan pool salah), `InvalidProgramAddress` (`amm_authority` salah atau `nonce` salah), `RepeatCreateAmm` (pool sudah ada untuk pasar ini), `InitLpAmountTooLess`, `InvalidSupply` (salah satu jumlah init adalah `0`, atau LP mint sudah memiliki supply), `AlreadyInUse`.

## `SwapBaseIn`

Swap input-tepat. Selalu swap **jalur AMM** (tidak merutekan melalui pencocokan OpenBook).

<Note>
  **Gunakan varian V2 untuk kode baru.** Karena ketergantungan OpenBook AMM v4 telah dihapus, titik masuk V1 (`SwapBaseIn`, `SwapBaseOut`) masih mengharapkan daftar akun lengkap 17 (atau 18 dengan akun target-orders opsional), tetapi akun OpenBook/pasar sekarang **diterima secara posisional dan diabaikan** — mereka tidak divalidasi dan tidak ada CPI yang dikeluarkan. Melewatkan jumlah akun yang salah masih kembali dengan `WrongAccountsNumber`, tetapi *isi* akun pasar tidak lagi diperiksa. Integrasi baru harus menggunakan [`SwapBaseInV2` / `SwapBaseOutV2`](#swapbaseinv2-/-swapbaseoutv2), yang mengambil daftar akun yang jauh lebih kecil dan mewakili jalur eksekusi kanonik hari ini. Bentuk V1 didokumentasikan di sini untuk kelengkapan dan untuk membaca transaksi on-chain yang ada.
</Note>

**Argumen**

```
amount_in:            u64
minimum_amount_out:   u64
```

**Akun** (ringkas)

| # | Nama | W | S |
|---|------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `amm_open_orders` | W |   |
| 5 | `amm_target_orders` | W |   |
| 6 | `pool_coin_token_account` | W |   |
| 7 | `pool_pc_token_account` | W |   |
| 8 | `market_program` |   |   |
| 9 | `market` | W |   |
| 10 | `market_bids` | W |   |
| 11 | `market_asks` | W |   |
| 12 | `market_event_queue` | W |   |
| 13 | `market_coin_vault` | W |   |
| 14 | `market_pc_vault` | W |   |
| 15 | `market_vault_signer` |   |   |
| 16 | `user_source_token_account` | W |   |
| 17 | `user_dest_token_account` | W |   |
| 18 | `user_owner` |   | S |

**Matematika** — lihat [`products/amm-v4/math`](/id/products/amm-v4/math).

**Kondisi pra**

- `AmmStatus::from_u64(amm.status).swap_permission()` bernilai true — artinya, `status` adalah `1` (`Initialized`), `6` (`SwapOnly`) atau `7` (`WaitingTrade`). `status` adalah nilai enum, bukan bitmask; lihat [`products/amm-v4/accounts`](/id/products/amm-v4/accounts#status).
- `amm.state_data.pool_open_time <= now`.
- `amount_in > 0`.
- `user_source_token_account` memegang setidaknya `amount_in`.

**Kondisi pasca**

- Pengguna kehilangan `amount_in` dari token sumber, mendapatkan `amount_out ≥ minimum_amount_out` dari token tujuan.
- Biaya swap tetap berada di vault, menaikkan invariant `k`. Penghitung `need_take_pnl_*` **tidak** disentuh oleh swap — PnL protokol dihitung ulang dari delta `k` pada `Deposit`, `Withdraw` atau `WithdrawPnl` berikutnya (`Processor::calc_take_pnl`).
- Catatan: penghitung analitik `state_data.swap_*_in_amount` / `swap_*_out_amount` **tidak lagi diperbarui** — nilainya dibekukan. Gunakan log perdagangan untuk analitik volume.

**Kesalahan umum** — `ExceededSlippage`, `InvalidInput`, `InvalidStatus`, `NotAllowed` (mint coin/pc identik).

| # | Nama | W | S |
|---|------|---|---|
| 1 | `token_program` |   |   |
| 2 | `amm` | W |   |
| 3 | `amm_authority` |   |   |
| 4 | `pool_coin_token_account` | W |   |
| 5 | `pool_pc_token_account` | W |   |
| 6 | `user_source_token_account` | W |   |
| 7 | `user_dest_token_account` | W |   |

## `MonitorStep` dan instruksi dihapus lainnya

<Warning>
  **Dihapus — tidak lagi dapat dipanggil.** Sejak upgrade 2026-07, `MonitorStep` (tag 2) telah dihapus dari program dan sekarang **kembali** (`unimplemented!`) jika dipanggil. Builder klien juga dihapus. Hal yang sama berlaku untuk `MigrateToOpenBook` (5), `WithdrawSrm` (8), `SimulateInfo` (12), `AdminCancelOrders` (13), dan titik masuk pembuatan pool lama `Initialize` (0) / `PreInitialize` (10) — gunakan `Initialize2` sebagai gantinya.
</Warning>

Secara historis, `MonitorStep` menggerakkan interaksi OpenBook pool: ia menyelesaikan pesanan yang diisi (memindahkan hasil dari vault pasar ke vault pool melalui CPI OpenBook), membatalkan pesanan basi, dan memposting pesanan baru untuk menutup celah antara `target_orders` dan `amm_open_orders`. Dengan ketergantungan OpenBook dihapus, tidak ada yang perlu dikgerakkan dan instruksi hilang. Setiap keeper atau integrasi yang masih memanggilnya harus menghapus panggilan.

## `SetParams`

Perubahan parameter admin, dipanggil oleh multisig Raydium. Argumen adalah tag `param: u8` + payload.

<Warning>
  **Perubahan breaking (admin saja).** Daftar akun dikurangi menjadi hanya `[amm (W), admin (S)]` (otoritas, open-orders, target-orders, vault, dan semua akun pasar dihapus). ## `CreateConfigAccount` / `UpdateConfigAccount`

Manajemen admin PDA `AmmConfig` tingkat program (seed `["amm_config_account_seed"]`). Akun ini menyimpan tepat tiga bidang bermakna — `pnl_owner`, `cancel_owner` dan `create_pool_fee` — ditambah dua wilayah padding cadangan; tidak ada flag pembuatan pool. `UpdateConfigAccount` menetapkan `pnl_owner` dengan `param = 0`, `cancel_owner` dengan `param = 1`, dan `create_pool_fee` dengan `param = 2`.

<Note>
  **Berubah di 2026-09, dan kompatibel mundur.** `CreateConfigAccount` tidak lagi membaca rent sysvar. Daftar akun sekarang **4 akun**, turun dari 5:

  | # | Nama | W | S |
  |---|------|---|---|
  | 1 | `admin` | W | S |
  | 2 | `amm_config` | W |   |
  | 3 | `pnl_owner` |   |   |
  | 4 | `system_program` |   |   |

  Program membaca parameter sewa dari `Rent::get()` alih-alih mendeserialisasi akun sysvar yang dilewatkan — apa yang membuat bump ketergantungan Solana 3.0 alami.

  Akun yang dihapus adalah **terakhir** dalam daftar, dan handler membaca akun secara posisional melalui `next_account_info` tanpa pemeriksaan panjang. Alat admin yang ada yang masih melewatkan daftar 5-akun lama karena itu terus bekerja: akun sewa trailing tidak pernah dibaca. Perbarui ketika nyaman, bukan mendesak. `UpdateConfigAccount` tidak berubah.
</Note>

`Initialize2` menyimpan rent sysvar di posisi 3, dan masih **menggunakannya**: program berhenti memanggil `Rent::from_account_info` padanya, tetapi masih diteruskan ke CPI `spl_token::initialize_account` dan `initialize_mint` yang membuat vault dan LP mint pool. Jangan hapus dari daftar akun.

## `WithdrawExcessLamports`

Kumpulan admin lamport yang duduk di atas minimum bebas sewa pada akun yang dikendalikan program. Ditambahkan dalam upgrade 2026-09 untuk memulihkan over-funding yang [SIMD-0437 rent reduction](/id/solana-fundamentals/rent-and-reclaimable-rent) tinggalkan pada akun yang dibuat sebelum setiap langkah.

Ini hanya memindahkan kelebihan. Saldo token, data akun, pemilik, dan status pool tidak tersentuh, dan instruksi adalah no-op pada akun yang sudah di minimum — jadi aman untuk menjalankan berulang kali dan lagi setelah setiap langkah rollout.

**Argumen** — tidak ada. Payload adalah byte tag tunggal `18`.

**Akun**

| # | Nama | W | S | Catatan |
|---|------|---|---|---------|
| 1 | `collect_lamports` | W | S | Tujuan untuk setiap lamport yang dikumpulkan. Harus sama dengan dompet collect-lamports cluster — lihat [`reference/program-addresses`](/id/reference/program-addresses#excess-lamports-collection-wallets). Penandatangan lain gagal dengan `InvalidSignAccount`. |
| 2 | `amm_authority` |   |   | PDA otoritas AMM v4 tunggal, diturunkan ulang oleh program dari `["amm authority"]` dengan nonce tetap `254`. Ini menandatangani CPI program token. |
| 3 | `token_program` |   |   | **SPL Token.** Diperiksa terhadap `spl_token::id()`; nilai yang salah gagal dengan `InvalidSplTokenProgram`. |
| 4.. | akun sumber | W |   | `M` akun untuk dikumpulkan, jumlah berapa pun, urutan apa pun. |

**Bagaimana setiap akun sumber ditangani**

Program mengirim pada pemilik akun sumber:

| Pemilik akun sumber | Penanganan |
|---|---|
| SPL Token, `data_len == 165` (akun token), non-native | CPI `WithdrawExcessLamports` (diskriminan program token `38`), ditandatangani oleh `amm_authority`. |
| SPL Token, `data_len == 165`, native (wSOL) | `WithdrawExcessLamports` tidak dapat digunakan pada akun native. Program CPI `SyncNative`, mengukur berapa banyak `amount` yang dibungkus tumbuh, `UnwrapLamports` (diskriminan `45`) untuk delta yang tepat, kemudian menegaskan saldo yang dibungkus kembali ke nilai pra-sync — jika tidak `LamportsCalculateError`. Likuiditas sisi SOL pool karena itu tidak pernah disentuh. |
| SPL Token, ukuran lain apa pun (mint LP) | CPI `WithdrawExcessLamports`, ditandatangani oleh `amm_authority`. |
| Program AMM v4 itu sendiri (`AmmInfo`, `TargetOrders`, `AmmConfig`) | Program mendebit akun secara langsung ke `rent.minimum_balance(data_len)`. |
| Apa pun yang lain | **Dilewati diam-diam.** Tidak ada kesalahan, tidak ada lamport yang dipindahkan. |

**Kesalahan umum** — `InvalidSignAccount` (penandatangan salah), `InvalidSplTokenProgram` (program salah di slot 3), `InvalidProgramAddress` (`amm_authority` salah), `LamportsCalculateError` (kode kustom `60`; putaran wSOL tidak nol), dan `InsufficientFunds` dari jalur yang dikendalikan program ketika akun memegang kurang dari minimum sewa sendiri.

**Tidak ada builder SDK.** `@raydium-io/raydium-sdk-v2` tidak mengirimkan builder untuk instruksi ini, begitu juga repo `raydium-sdk-V2-demo` — ini adalah jalur admin. Enkode dengan tangan, cara yang dilakukan sweep sisi dompet di [`solana-fundamentals/rent-and-reclaimable-rent`](/id/solana-fundamentals/rent-and-reclaimable-rent#building-the-instruction) untuk instruksi program token.
