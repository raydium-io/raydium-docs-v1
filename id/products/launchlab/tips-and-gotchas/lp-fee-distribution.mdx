Ketika token LaunchLab bermigrasi ke CPMM, pool mencetak token LP. Sebelum upgrade 2026-08-14, `creatorScale` dikunci secara terpisah untuk kreator token. Untuk migrasi yang dijalankan setelah upgrade, `migrateCpLockNftScale` masih menyimpan tiga bidang yang berjumlah `1_000_000`, tetapi runtime hanya menghasilkan dua tujuan.

## Pembagian efektif

| Bidang | Perilaku yang Diperbarui |
|---|---|
| `platformScale` | Disertakan dalam bagian LP terkunci milik platform. |
| `creatorScale` | Sebelum upgrade, mencetak Fee Key milik kreator. Setelah upgrade, disertakan dalam bagian LP terkunci milik platform. |
| `burnScale` | Dibakar secara permanen. Tidak ada Fee Key yang mewakili bagian ini. |

```text
effectivePlatformScale = platformScale + creatorScale
platformLp = floor(totalLp × effectivePlatformScale / 1_000_000)
burnLp = totalLp − platformLp
```

Ketika `burnScale` adalah nol, platform menerima semua unit LP. Ketika `effectivePlatformScale` adalah nol, semua LP dibakar dan tidak ada Fee Key platform yang dibuat.

## Contoh

```ts
// @raydium-io/raydium-sdk-v2@0.2.42-alpha · mainnet-beta · verified 2026-08-13
// 90% LP terkunci milik platform, 10% dibakar.
migrateCpLockNftScale: {
  platformScale: new BN(400_000),
  creatorScale: new BN(500_000),
  burnScale: new BN(100_000),
}

// Di bawah program yang diperbarui, ini menghasilkan 100% LP terkunci milik platform.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(1_000_000),
  burnScale: new BN(0),
}

// 100% dibakar; tidak ada Fee Key.
migrateCpLockNftScale: {
  platformScale: new BN(0),
  creatorScale: new BN(0),
  burnScale: new BN(1_000_000),
}
```

## Hubungan dengan biaya kreator CPMM

Bidang skala hanya mengontrol kepemilikan LP. Mereka tidak menetapkan tarif biaya swap atau mengidentifikasi penerima biaya kreator CPMM. `cpConfigId` memilih CPMM `AmmConfig`; `platformCpCreator` menentukan apakah pool CPMM mencatat kreator peluncuran asli atau alamat yang dipilih platform.

## Memperbarui pembagian

Sebelum memperbarui platform:

- Konfirmasi ketiga nilai berjumlah tepat `1_000_000`.
- Sajikan `platformScale + creatorScale` sebagai bagian platform yang efektif.
- Jangan janjikan Fee Key kreator berdasarkan `creatorScale`.
- Pertahankan kepemilikan Fee Key kreator yang ditunjukkan oleh migrasi yang diselesaikan sebelum upgrade; catatan tersebut tidak ditulis ulang.
- Jelaskan perubahan sebelum peluncuran di masa depan menggunakan konfigurasi yang diperbarui.
