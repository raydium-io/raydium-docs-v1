SDK `raydium.launchpad.getLaunchById` mengembalikan `PoolState` ditambah flag yang menunjukkan apakah peluncuran telah lulus; jika ya, ID pool pasca-migrasi disertakan.

## `PoolState`

Status akar per-peluncuran. Nama field di bawah cocok dengan struct Rust on-chain (`states/pool.rs`); beberapa nilai disederhanakan untuk keterbacaan — konsultasikan sumber untuk tata letak memori yang tepat.

```rust
// states/pool.rs (abridged)
pub struct PoolState {
    pub epoch:                     u64,        // recent_epoch tracker
    pub auth_bump:                 u8,
    pub status:                    u8,         // PoolStatus enum
    pub base_decimals:             u8,
    pub quote_decimals:            u8,
    pub migrate_type:              u8,         // 0 = AMM v4, 1 = CPMM
    pub supply:                    u64,        // total base tokens (no decimals)
    pub total_base_sell:           u64,        // base supply allocated to the curve
    pub virtual_base:              u64,        // virtual-reserve seed
    pub virtual_quote:             u64,        // virtual-reserve seed
    pub real_base:                 u64,        // base sold so far
    pub real_quote:                u64,        // quote raised so far (excl. fees)
    pub total_quote_fund_raising:  u64,        // graduation threshold in quote

    pub quote_protocol_fee:        u64,        // accrued, pending CollectFee
    pub platform_fee:              u64,        // accrued, pending ClaimPlatformFee
    pub migrate_fee:               u64,        // accrued, pending CollectMigrateFee
    pub vesting_schedule:          VestingSchedule,

    pub global_config:             Pubkey,
    pub platform_config:           Pubkey,
    pub creator:                   Pubkey,
    pub base_mint:                 Pubkey,
    pub quote_mint:                Pubkey,
    pub base_vault:                Pubkey,
    pub quote_vault:               Pubkey,

    pub amm_creator_fee_on:        u8,         // 0 = QuoteToken, 1 = BothToken (CPMM-only)
    pub token_program_flag:        u8,         // bit0 = base mint, bit1 = quote mint; 0 = SPL Token, 1 = Token-2022
    pub padding:                   [u8; 54],
}

#[derive(Default, Debug, Clone)]
pub struct VestingSchedule {
    pub total_locked_amount:    u64,
    pub cliff_period:           u64,
    pub unlock_period:          u64,
    pub start_time:             u64,           // set at graduation
    pub allocated_share_amount: u64,           // running sum across VestingRecords
}
```

Nilai `PoolStatus` (dari IDL Anchor):

```
0 = Funding         — menerima pembelian / penjualan; di bawah quote_reserve_target
1 = Migrate         — quote_reserve_target tercapai; menunggu MigrateTo*
2 = Migrated        — MigrateTo* sudah dijalankan; jam vesting berjalan
```

Field yang menghadap integrator:

- **`status`** — tiga nilai, monoton (Funding → Migrate → Migrated). Pembacaan selalu aman; penulisan tergated.
- **`real_base`**, **`real_quote`** — status kurva saat ini. Dikombinasikan dengan `virtual_base` / `virtual_quote` mereka cukup untuk menghitung harga spot tanpa menyentuh vault. Lihat [`bonding-curve`](/id/products/launchlab/bonding-curve).
- **`total_base_sell`** vs `real_base` — rasio "kemajuan menuju kelulusan" untuk UI.
- **`migrate_type`** — inisialisasi baru memerlukan `1` (`CPSWAP`). `0` yang tersimpan tetap bermakna hanya untuk peluncuran yang ada yang dibuat sebelum penegakan CPMM-only.
- **`amm_creator_fee_on`** — memilih `creator_fee_on = OnlyQuoteToken` (`0`) atau `BothToken` (`1`) pada pool CPMM pasca-kelulusan. Ini tidak memilih target migrasi. Lihat [`creator-fees`](/id/products/launchlab/creator-fees).
- **`token_program_flag`** — bidang bit, bukan boolean. Bit0 adalah mint dasar dan bit1 adalah mint kutipan, masing-masing `0` untuk SPL Token dan `1` untuk Token-2022, jadi byte mengambil empat nilai: `0` (keduanya legacy), `1` (Token-2022 dasar), `2` (Token-2022 kutipan), `3` (keduanya Token-2022). Baca satu mint dengan `(token_program_flag >> bit) & 1`. Membandingkan seluruh byte terhadap `0` untuk mengklasifikasikan mint dasar menyelesaikan `2` ke program yang salah. Bit1 konstan `0` sampai mint kutipan Token-2022 didukung.
- **`quote_protocol_fee` / `platform_fee` / `migrate_fee`** — tiga penghitung biaya independen. Masing-masing memiliki instruksi klaim sendiri; lihat [`instructions`](/id/products/launchlab/instructions).
- **`vesting_schedule`** — hadir di setiap `PoolState` tetapi tidak aktif ketika `total_locked_amount == 0`. Lihat [`vesting`](/id/products/launchlab/vesting) untuk siklus hidup lengkap.

## PDA otoritas

LaunchLab menggunakan **satu** PDA otoritas di semua peluncuran, diturunkan tanpa seed per-peluncuran:

```ts
const LAUNCHLAB_PROGRAM_ID = new PublicKey("<LAUNCHLAB_ID>"); // lihat reference/program-addresses

const [authority, bump] = PublicKey.findProgramAddressSync(
  [Buffer.from("vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

PDA tunggal itu adalah:

- Otoritas pada `base_vault` dan `quote_vault` setiap peluncuran.
- `mint_authority` pada `base_mint` setiap peluncuran (pra-kelulusan).
- Penandatangan pada CPI kelulusan CPMM, dan pada kelulusan AMM v4 legacy untuk status yang ada.
- Penandatangan pada transfer `ClaimVestedToken` keluar dari vault dasar.

`mint_authority` dibatalkan segera setelah panggilan `MigrateToCpswap` atau `MigrateToAmm` legacy, sehingga pasokan tetap permanen.

Dua PDA tambahan membatasi vault biaya:

```ts
const [creatorFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("creator_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);

const [platformFeeVaultAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform_fee_vault_auth_seed")],
  LAUNCHLAB_PROGRAM_ID,
);
```

Ini menandatangani transfer keluar dari vault biaya yang sesuai selama `ClaimCreatorFee` dan `ClaimPlatformFeeFromVault`.

## Mint dasar

Dibuat inline oleh `Initialize` dengan:

- `mint_authority = authority` (dibatalkan saat kelulusan).
- `freeze_authority = None`.
- `supply = supply`, sepenuhnya dimint ke `base_vault`.
- `decimals` dipilih oleh kreator di `Initialize` (biasanya 6).

Karena pasokan penuh dimint sebelumnya, `base_mint.supply` konstan untuk kehidupan peluncuran. Pembelian kurva memindahkan token dari `base_vault` ke pembeli, tetapi tidak memanggil `mint_to`.

`Initialize` / `InitializeV2` membuat mint dasar SPL Token. Instruksi `InitializeWithToken2022` khusus memungkinkan mint dasar menjadi mint Token-2022 (dengan `TransferFeeConfig` opsional). Ketiga jalur inisialisasi memerlukan kelulusan CPMM.

Mint kutipan independen dari mint dasar dan mungkin sendiri mint Token-2022 — `InitializeV2` dan `InitializeWithToken2022` menerima program apa pun di slot program-kutipan mereka. `Initialize` yang sudah usang tidak: akun program-kutipan masih diketik ke SPL Token, jadi konfigurasi yang mint kutipannya adalah Token-2022 hanya dapat diluncurkan melalui dua yang lain. Mint kutipan tidak pernah dibuat oleh LaunchLab; itu apa pun yang dinamai `GlobalConfig.quote_mint`. Lihat [`global-config`](/id/products/launchlab/global-config#token-2022-quote-mints) dan [`reference/token-2022-support`](/id/reference/token-2022-support#launchlab-quote-mints).

## Vault

Baik `base_vault` maupun `quote_vault` adalah akun token yang dimiliki oleh PDA LaunchLab `authority`, masing-masing dibuat pada program yang memiliki mintnya sendiri — jadi peluncuran dapat memiliki vault dasar legacy dan vault kutipan Token-2022, atau kombinasi lainnya. `token_program_flag` mencatat mana yang mana. Alamat disimpan di `PoolState` dan juga dapat diturunkan:

```ts
const [baseVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), baseMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
const [quoteVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("pool_vault"), poolState.toBuffer(), quoteMint.toBuffer()],
  LAUNCHLAB_PROGRAM_ID,
);
```

(Verifikasi prefiks seed yang tepat dari struct akun `Initialize` sumber sebelum mengandalkan derivasi dalam produksi.)

## Vault biaya

Dua PDA mengagregasi biaya di semua peluncuran:

- **Vault biaya kreator** — PDA pada seed `[creator, quote_mint]`. Setiap peluncuran yang menghasilkan biaya kreator yang sama pada mint kutipan yang sama dituangkan ke vault yang sama. Kreator menyapunya melalui `ClaimCreatorFee`.
- **Vault biaya platform** — PDA pada seed `[platform_config, quote_mint]`. Setiap peluncuran yang dirutekan melalui platform yang sama yang menggunakan mint kutipan yang sama dituangkan ke vault yang sama. `platform_fee_wallet` platform menyapunya melalui `ClaimPlatformFeeFromVault`. Ada juga varian sapuan per-peluncuran (`ClaimPlatformFee`) yang menarik dari `quote_vault` peluncuran secara langsung tanpa melewati vault yang diagregasi.

Keduanya dibuat dengan malas pada swap pertama yang mengumpulkan biaya, pada program mana pun yang memiliki mint kutipan. Kreator atau platform yang menjalankan peluncuran terhadap mint kutipan legacy dan Token-2022 berakhir dengan satu vault per mint, seperti yang sudah dilakukan untuk dua mint legacy yang berbeda.

Pola vault yang diagregasi adalah apa yang memungkinkan kreator atau platform volume tinggi untuk mengamortisasi biaya sewa akumulasi biaya di banyak peluncuran.

## Quote vault ↔ `real_quote`

`quote_vault.balance` dan `PoolState.real_quote` harus tetap sinkron. Mereka dapat bergeser paling banyak jumlah dari tiga penghitung biaya yang tertunda (`quote_protocol_fee`, `platform_fee`, `migrate_fee`), yang duduk di vault tetapi milik penghitung biaya dan bukan cadangan kurva. Matematika kurva selalu menggunakan `real_quote`, tidak pernah saldo vault mentah.

Invarian pra-kelulusan:

```
quote_vault.balance ==
   real_quote
 + quote_protocol_fee
 + platform_fee
 + migrate_fee
```

## Transisi akun siklus hidup

| Acara | Status | `real_base` | `real_quote` | Pool pasca-kelulusan |
|-------|--------|-------------|--------------|----------------------|
| `Initialize` | Funding | 0 | 0 | — |
| `BuyExactIn` / `BuyExactOut` | Funding | `+base_out` | `+quote_in_after_fee` | — |
| `SellExactIn` / `SellExactOut` | Funding | `−base_in` | `−quote_out_before_fee` | — |
| `MigrateToCpswap` (atau `MigrateToAmm` legacy) | Funding → Migrate → Migrated | (beku) | (beku) | dibuat; LP CPMM dibagi menjadi LP terkunci milik platform dan LP yang dibakar |
| `ClaimCreatorFee` / `ClaimPlatformFee*` | apa pun | — | — | menguras vault biaya |
| `CreateVestingAccount` | Funding | — | — | menaikkan `vesting_schedule.allocated_share_amount` |
| `ClaimVestedToken` | Migrated only | — | — | menguras `base_vault` |
