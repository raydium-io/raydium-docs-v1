## Inventaris instruksi

| Grup | Instruksi | Dapat dipanggil oleh |
|-------|-----------|---------------------|
| Konfigurasi global | `CreateConfig` / `UpdateConfig` | Admin program; otoritas create-config yang didelegasikan juga dapat memanggil `CreateConfig` |
| Siklus peluncuran | `Initialize` / `InitializeV2` | Siapa saja (pembuat) — basis mint SPL Token; V2 mencatat `amm_creator_fee_on` untuk kelulusan CPMM yang akan datang. Hanya V2 yang menerima quote mint Token-2022. |
| Siklus peluncuran | `InitializeWithToken2022` | Siapa saja (pembuat) — basis mint Token-2022, opsional `TransferFeeConfig`; menerima program token quote apa pun |
| Perdagangan | `BuyExactIn` / `BuyExactOut` | Siapa saja — pembelian input-tepat / output-tepat pada kurva ikatan |
| Perdagangan | `SellExactIn` / `SellExactOut` | Siapa saja — penjualan input-tepat / output-tepat pada kurva ikatan |
| Kelulusan | `MigrateToAmm` | Dompet migrasi — kelulusan AMM v4 warisan untuk pool yang diinisialisasi sebelum pembuatan CPMM-only diterapkan. |
| Kelulusan | `MigrateToCpswap` | Dompet migrasi — lulus ke CPMM. Semua peluncuran yang baru diinisialisasi menggunakan jalur ini. Membungkus `InitializeWithPermission` pada CPMM. |
| Biaya | `CollectFee` | Admin — sapu biaya protokol dari peluncuran |
| Biaya | `CollectMigrateFee` | Admin — sapu biaya migrasi yang terkumpul |
| Biaya | `ClaimCreatorFee` | Pembuat — klaim biaya pembuat yang terkumpul selama fase kurva |
| Vesting | `CreateVestingAccount` | Pembuat — alokasikan token terkunci ke penerima manfaat, dibuka setelah kelulusan |
| Vesting | `CreatePlatformVestingAccount` | Admin platform — alokasikan token terkunci ke penerima manfaat sisi platform |
| Vesting | `ClaimVestedToken` | Penerima manfaat — klaim token yang tidak terkunci setelah tebing |
| Konfigurasi platform | `CreatePlatformConfig` / `UpdatePlatformConfig` | Admin platform |
| Konfigurasi platform | `UpdatePlatformCurveParam` / `RemovePlatformCurveParam` | Admin platform — kelola daftar per-platform bentuk kurva yang diizinkan |
| Biaya platform | `ClaimPlatformFee` / `ClaimPlatformFeeFromVault` | Admin platform |
| Akses platform | `CreatePlatformAllowConfig` / `ClosePlatformAllowConfig` | Admin platform — pertahankan daftar izin `GlobalConfig` yang digunakan ketika platform itu mengaktifkan pembatasan |

Pemisahan "ExactIn/ExactOut" mencerminkan `SwapBaseInput` / `SwapBaseOutput` CPMM — di rantai mereka adalah diskriminator instruksi terpisah dengan pembulatan yang sedikit berbeda.

**Pemilihan jalur kelulusan.** Setiap panggilan `Initialize`, `InitializeV2`, dan `InitializeWithToken2022` yang baru harus menetapkan `migrate_type = 1` (`CPSWAP`). Setiap upaya untuk menginisialisasi pool yang terikat AMM v4 baru mengembalikan `MigrateTypeNotMatch`. `amm_creator_fee_on` hanya memilih apakah biaya pembuat CPMM yang dihasilkan berlaku untuk token quote atau kedua token; itu tidak memilih program target.

`MigrateToAmm` tetap dapat dipanggil untuk `PoolState` yang ada yang diinisialisasi dengan `migrate_type = 0` sebelum pembatasan ini. Rilis tidak menulis ulang status pool yang ada atau menghapus instruksi warisan.

**Program token sisi quote.** Mint quote dapat dimiliki oleh program SPL Token atau Token-2022. Setiap instruksi yang menyentuhnya — `CreateConfig`, `InitializeV2`, `InitializeWithToken2022`, keempat instruksi perdagangan, `CollectFee`, `CollectMigrateFee`, `ClaimCreatorFee`, `ClaimPlatformFee`, dan `ClaimPlatformFeeFromVault` — mengambil program pemilik di slot akun quote-program-nya. Posisi akun tidak berubah; hanya nilai yang diterima yang berubah. Lewatkan program yang benar-benar memiliki `GlobalConfig.quote_mint`, yang dapat Anda baca dari bit1 `PoolState.token_program_flag` untuk peluncuran yang ada (lihat [`accounts`](/id/products/launchlab/accounts#poolstate)) atau dari pemilik akun mint sebaliknya.

`Initialize` yang sudah usang adalah pengecualian: akun quote-program-nya masih diketik ke SPL Token, jadi konfigurasi yang quote mint-nya adalah Token-2022 harus diluncurkan melalui `InitializeV2` atau `InitializeWithToken2022`.

`MigrateToCpswap` adalah pengecualian lainnya, dalam arah yang berlawanan — ia mengambil **kedua** program tanpa syarat daripada satu per mint. Lihat [akun migrasi di bawah](#cpmm-migration-token-programs).

## `Initialize`

Buat peluncuran baru.

**Argumen**

```
launch_params: {
    curve_type:                 u8,
    base_supply_max:            u64,
    base_supply_graduation:     u64,
    k:                          u128,              // atau initial_virtual_quote_reserve untuk curve_type=1
    open_time:                  u64,
    quote_mint:                 Pubkey,
    base_token_metadata: {                         // nama/simbol/uri inline; program CPI ke Metaplex
        name:   String,
        symbol: String,
        uri:    String,
    },
    fees: {
        buy_numerator:   u64,
        buy_denominator: u64,
        sell_numerator:  u64,
        sell_denominator: u64,
        lp_share:        u64,
        creator_share:   u64,
        protocol_share:  u64,
        total_share:     u64,
    },
    post_graduation_lp_policy:  u8,                // 0 = Burn, 1 = Lock, 2 = ToCreator
}
```

**Akun** (ringkas)

| # | Nama | W | S | Catatan |
|---|------|---|---|---------|
| 1 | `creator` | W | S | Membayar sewa + pembuatan mint dasar. |
| 2 | `launch_config` |   |   | Pengikatan konfigurasi protokol. |
| 3 | `launch_state` | W |   | Akun baru. |
| 4 | `launch_authority` |   |   | PDA. |
| 5 | `base_mint` | W | S | Keypair Segar (atau PDA) — instruksi ini menginisialisasinya. |
| 6 | `base_vault` | W |   | ATA dari `launch_authority` pada `base_mint`. |
| 7 | `quote_mint` |   |   | |
| 8 | `quote_vault` | W |   | ATA dari `launch_authority` pada `quote_mint`. |
| 9 | `metadata` | W |   | PDA metadata Metaplex. |
| 10 | `metaplex_program` |   |   | |
| 11 | `token_program` |   |   | SPL Token untuk mint dasar. `InitializeV2` dan `InitializeWithToken2022` mengambil akun quote-program terpisah yang mungkin program apa pun. |
| 12 | `system_program` |   |   | |
| 13 | `rent` |   |   | |

**Kondisi awal**

- `quote_mint ∈ launch_config.allowed_quote_mints`.
- `base_supply_graduation ≤ base_supply_max`.
- Parameter biaya lulus pemeriksaan `launch_config.max_*_fee_rate`.
- `open_time ≥ now − slop` (SDK memberlakukan `≥ now`; program mentoleransi backdating ringan).
- `curve_type` dikenali.

**Kondisi akhir**

- `base_mint` memiliki `supply = base_supply_max`, semuanya di `base_vault`.
- `base_mint.mint_authority = launch_authority`, `freeze_authority = None`.
- `LaunchState` diinisialisasi dengan `status = Active`, `base_sold = 0`, `quote_reserve_real = 0`.
- `quote_reserve_target` dihitung dari parameter kurva + `base_supply_graduation` + `buy_numerator` (kira-kira).

**Kesalahan umum** — `InvalidQuoteMint`, `FeeRateTooHigh`, `InvalidCurveParams`, `MathOverflow`.

## `Buy` (varian kanonik: `BuyExactIn`)

Pengguna menyediakan `quote_in` tetap; kurva menghitung `base_out`.

**Argumen**

```
quote_in:          u64
minimum_base_out:  u64
```

**Akun**

| # | Nama | W | S |
|---|------|---|---|
| 1 | `user` | W | S |
| 2 | `launch_state` | W |   |
| 3 | `launch_authority` |   |   |
| 4 | `base_vault` | W |   |
| 5 | `quote_vault` | W |   |
| 6 | `user_base_ata` | W |   |
| 7 | `user_quote_ata` | W |   |
| 8 | `base_mint` |   |   |
| 9 | `quote_mint` |   |   |
| 10 | `token_program` |   |   |
| 11 | `associated_token_program` |   |   |
| 12 | `system_program` |   |   |

**Kondisi awal**

- `launch_state.status == Active`.
- `now ≥ open_time`.
- `user_quote_ata.balance ≥ quote_in`.
- `quote_in > 0`.

**Efek**

1. Pisahkan `quote_in` menjadi `quote_in_after_fee` dan bagian biaya.
2. Newton-selesaikan kurva untuk `base_out` yang diberikan quote pasca-biaya.
3. `require(base_out ≥ minimum_base_out)` jika tidak balik `ExceededSlippage`.
4. Pindahkan `quote_in` pengguna → vault. Pindahkan `base_out` vault → pengguna.
5. Perbarui `base_sold += base_out`, `quote_reserve_real += quote_in_after_fee × (lp_share / total_share)`.
6. Perbarui penghitung biaya (`protocol_fees_quote`, `creator_fees_quote`).
7. `state_data.num_buys += 1`.
8. Jika `quote_reserve_real ≥ quote_reserve_target` setelah pembaruan, SDK biasanya merantai instruksi `Graduate` dalam transaksi yang sama. Program tidak auto-graduate di dalam `Buy` — `Graduate` berikutnya diperlukan.

## `BuyExactOut`

Pengguna menentukan `base_out` yang tepat; program menghitung `quote_in`.

**Argumen**

```
base_out:      u64
maximum_quote_in: u64
```

Akun yang sama seperti `BuyExactIn`. Menggunakan integral kuadrat bentuk tertutup (atau CPMM terbalik, untuk curve_type 1) daripada iterasi Newton.

## `Sell` / `SellExactIn` / `SellExactOut`

Cerminan dari `Buy`. Pengguna mengembalikan `base_in` ke kurva dan menerima `quote_out`. Biaya dikurangkan dari `quote_out`, jadi pengguna menerima lebih sedikit daripada hasil terintegrasi mentah.

**Kondisi awal** —

- `user_base_ata.balance ≥ base_in`.
- Penjualan tidak dapat mendorong `base_sold` di bawah 0 (berlebihan dengan di atas mengingat akuntansi konsisten).
- Peluncuran adalah `Active`.

**Efek** — simetris dengan `Buy`. `base_sold` berkurang, `quote_reserve_real` berkurang. Biaya masih terkumpul.

### Biaya transfer sisi quote

Ketika mint quote membawa `TransferFeeConfig`, jumlah yang dipindahkan vault dan jumlah yang didebit atau dikreditkan pembayar berbeda, dan batas slippage diperiksa terhadap sisi pembayar. Pada mint quote tanpa ekstensi setiap kasus di bawah identik dengan mint warisan biasa.

| Instruksi | Argumen | Diperiksa terhadap |
|---|---|---|
| `BuyExactIn` | `amount_in` | Kurva dihargai pada `amount_in − transfer_fee(amount_in)` — apa yang mencapai vault. Pengisian penuh mendebit tepat `amount_in`; pengisian sebagian mendebit jumlah vault yang dikonsumsi ditambah biaya terbaliknya. |
| `BuyExactOut` | `maximum_amount_in` | Jumlah vault **ditambah** biaya transfer terbalik — debit nyata. |
| `SellExactIn` | `minimum_amount_out` | Apa yang disimpan penjual setelah mint menahan biayanya, bukan jumlah kotor yang meninggalkan vault. |
| `SellExactOut` | `amount_out` | Disampaikan dengan tepat. Kurva menargetkan `amount_out` ditambah biaya transfer terbalik. |

Dua konsekuensi untuk penawaran:

- Batas yang dihitung seolah-olah mint bebas biaya ditolak. Melewatkan biaya bebas sebagai `maximum_amount_in`, atau hasil bebas biaya sebagai `minimum_amount_out`, kembali dengan `ExceededSlippage`.
- `real_quote` maju hanya dengan apa yang mencapai vault. `BuyExactIn` dari `amount_in` pada mint quote 5% memindahkan `real_quote` sebesar `amount_in × 0.95`.

Mint quote 100%-biaya (`10000` basis poin) tidak dapat dibalik dan kembali dengan `CalculateOverflow` pada jalur exact-out.

Kedua mint sisi perdagangan juga dibatasi pada program yang dilewatkan di slot pencocokan mereka, jadi `base_token_program` yang tidak cocok sekarang gagal daripada diabaikan. Lihat [`algorithms/token-2022-transfer-fees`](/id/algorithms/token-2022-transfer-fees) untuk matematika biaya yang mendasar.

## `MigrateToAmm` / `MigrateToCpswap`

Lulus peluncuran ke pool yang dapat diperdagangkan setelah kurva mencapai `total_quote_fund_raising`. Peluncuran baru hanya CPMM. `MigrateToAmm` dipertahankan untuk pool yang ada yang `migrate_type` tersimpannya adalah `0`.

**Siapa yang menandatangani**

- `MigrateToAmm` — `migrate_to_amm_wallet` yang dicatat pada `GlobalConfig` pengikatan.
- `MigrateToCpswap` — `migrate_to_cpswap_wallet` yang dicatat pada `GlobalConfig` pengikatan.

Dompet ini biasanya dipegang oleh crank kelulusan yang dioperasikan Raydium; dalam praktik kelulusan mendarat beberapa detik setelah ambang batas terlampaui, terlepas dari siapa yang memicu pembelian terakhir.

**Argumen**

`MigrateToAmm` mengambil tiga (terutama parameter pasar OpenBook yang program teruskan ke AMM v4):

```
base_lot_size:               u64
quote_lot_size:              u64
market_vault_signer_nonce:   u8
```

`MigrateToCpswap` tidak mengambil apa pun.

**Efek (umum untuk keduanya)**

1. Verifikasi `pool_state.status == Migrate` (yaitu, `quote_reserve_target` telah tercapai). Jika tidak balik dengan `PoolMigrated` (status sudah `Migrated`) atau `PoolFunding` (masih dalam pendanaan).
2. Verifikasi `pool_state.migrate_type` cocok dengan instruksi (`0` untuk AMM, `1` untuk CPMM). Jika tidak balik dengan `MigrateTypeNotMatch`.
3. Hitung cadangan pasca-kelulusan:
   - `base_amount_out = base_vault.amount − vesting_schedule.total_locked_amount`
   - `quote_amount_out = quote_vault.amount − quote_protocol_fee − migrate_fee − platform_fee`
4. CPI ke program target (`AMM v4 Initialize2` atau `CPMM InitializeWithPermission`) dengan cadangan tersebut untuk membuat pool pasca-kelulusan.
5. Untuk migrasi CPMM yang dieksekusi setelah upgrade 2026-08-17, gabungkan `platform_scale + creator_scale` menjadi satu saham LP terkunci milik platform dan mint paling banyak satu NFT Fee Key ke `platform_nft_wallet`. Bakar sisa `burn_scale`. Sebelum upgrade, `creator_scale` dikunci secara terpisah dan Fee Key-nya pergi ke pembuat token. Migrasi historis yang selesai tidak dimodifikasi. Untuk kelulusan AMM v4 warisan, disposisi LP mengikuti aliran yang ada dari instruksi itu.
6. Cabut `base_mint.mint_authority` (atur ke `None`).
7. Balik `pool_state.status = Migrated`, atur `vesting_schedule.start_time = block_time + cliff_period`.

**Kondisi akhir** — `BuyExactIn`, `BuyExactOut`, `SellExactIn`, `SellExactOut` akan menolak dari titik ini dengan `PoolMigrated`. Pool AMM yang dihasilkan adalah kanonik dan berdagang seperti pool AMM v4 / CPMM lainnya.

**Kesalahan umum** — `PoolFunding`, `PoolMigrated`, `MigrateTypeNotMatch`, `InvalidCpSwapConfig`, `MathOverflow`.

### Akun sisa migrasi CPMM

Klien yang membangun `MigrateToCpswap` harus menggunakan indeks `remaining_accounts` tetap ini:

| Indeks | Akun |
|---|---|
| 0–4 | Pemilik Fee Key platform, mint, akun token, PDA likuiditas terkunci, dan akun metadata |
| 5 | Pembuat peluncuran asli; digunakan ketika `platform_cp_creator` tidak diatur |
| 6 | PDA izin CPMM yang diturunkan dari `[b"permission", launch_authority]` |
| 7 | `platform_cp_creator` yang dikonfigurasi; digunakan ketika bidang tidak default |
| 8 | PDA support-mint CPMM untuk `mint0` yang diurutkan, diturunkan dari `[b"support_mint", mint0]` |
| 9 | PDA support-mint CPMM untuk `mint1` yang diurutkan, diturunkan dari `[b"support_mint", mint1]` |

Instruksi memerlukan setidaknya sepuluh akun sisa pada jalur yang ditingkatkan. Akun support-mint adalah input CPI read-only. Turunkan kedua alamat bahkan ketika mint tidak memiliki catatan dukungan yang diinisialisasi. Pembangun yang lebih lama yang masih menambahkan akun creator-lock atau menghilangkan indeks 8–9 harus diperbarui.

### Program token migrasi CPMM

`MigrateToCpswap` mengambil kedua program token tanpa syarat dan mengetahui program mana yang memiliki setiap mint. Dua akun token-program-nya dinamai ulang sesuai:

| Posisi | Akun | Nilai |
|---|---|---|
| pertama | `token_program` | Selalu program SPL Token warisan |
| kedua | `token_program_2022` | Selalu program Token-2022 |

Mereka menggantikan `base_token_program` (program apa pun yang memiliki mint dasar) dan `quote_token_program` (selalu warisan) sebelumnya. Posisi tidak berubah, jadi ini adalah perubahan nilai daripada perubahan tata letak — tetapi dua nilai hampir terbalik, dan pembangun yang terus melewatkan pasangan lamanya akan memasok Token-2022 di mana program warisan diperlukan segera setelah mint apa pun adalah mint Token-2022.

Program warisan diperlukan bahkan ketika tidak ada mint yang menggunakannya, karena mint LP CPMM dan NFT Fee Key likuiditas terkunci selalu tinggal di atasnya.

## Daftar izin `GlobalConfig` platform

`PlatformConfig.restrict_global_config` mengontrol pemeriksaan:

- `0`: platform menerima `GlobalConfig` yang valid; tidak ada akun izin yang diperlukan.
- `1`: `Initialize`, `InitializeV2`, dan `InitializeWithToken2022` harus menyertakan `PlatformAllowConfig` yang cocok di mana saja di `remaining_accounts`.

Admin platform membuat atau menutup PDA dengan `CreatePlatformAllowConfig` dan `ClosePlatformAllowConfig`. Bijinya adalah `[b"platform_allow_config", platform_config, global_config]`. Instruksi `PlatformGlobalAccess` yang dikelola admin sebelumnya dan PDA pensiun.
