## Apa yang ada di halaman ini

Alur di bawah mencakup siklus hidup yang relevan bagi integrator:

1. Penyiapan akun — setor USDC dan daftarkan akun dengan Orderly.
2. Panggilan REST terautentikasi — minta penandatanganan untuk penempatan pesanan, pembatalan, dan kueri akun.
3. Perdagangan — menempatkan pesanan pasar/limit, pembatalan, pengambilan posisi dan pengisian.
4. Data pasar — berlangganan orderbook dan WebSocket perdagangan.
5. Penarikan — memulai penarikan kembali ke dompet.

Cuplikan ini menargetkan Node.js + TypeScript dengan `@solana/web3.js` dan `tweetnacl` untuk penandatanganan Ed25519. Ini adalah **titik awal** — permukaan API Orderly luas dan berubah lebih cepat dari halaman ini; selalu periksa dokumentasi live Orderly sebelum mengirim kode produksi.

## Penyiapan

```ts
import { Connection, Keypair, PublicKey, clusterApiUrl } from "@solana/web3.js";
import nacl from "tweetnacl";
import bs58 from "bs58";
import fs from "node:fs";

// 1. Dompet Solana — memiliki USDC, menandatangani transaksi deposit/penarikan.
const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);

// 2. Kunci perdagangan Orderly — keypair Ed25519 terpisah yang digunakan untuk menandatangani permintaan API.
//    BUKAN dompet Solana. Buat sekali, jaga kerahasiaan, gunakan kembali di seluruh sesi.
const orderlyKey = nacl.sign.keyPair();   // ed25519
const orderlyPubB58 = "ed25519:" + bs58.encode(orderlyKey.publicKey);

// 3. URL dasar Orderly. Raydium menggunakan host mainnet Orderly.
const ORDERLY_BASE = "https://api.orderly.org";
const BROKER_ID    = "raydium";   // Namespace broker Raydium di Orderly
const CHAIN_ID     = "solana";    // untuk pendaftaran akun lintas rantai
```

Kunci perdagangan Orderly **bukan** keypair dompet Anda. Ini adalah kunci penandatanganan permintaan yang Anda daftarkan terhadap dompet Anda pada penggunaan pertama; Anda dapat merotasinya tanpa menyentuh dana. Perlakukan sebagai kredensial sesi.

## Pendaftaran akun

Sebelum menempatkan pesanan apa pun, daftarkan dompet dengan Orderly:

```ts
import { encodeUserSettlement } from "./eip712-helpers"; // lihat dokumentasi Orderly untuk payload yang tepat

// 1. Minta nonce pendaftaran dari Orderly.
const nonceResp = await fetch(`${ORDERLY_BASE}/v1/registration_nonce`).then(r => r.json());
const registrationNonce = nonceResp.data.registration_nonce;

// 2. Tandatangani payload pendaftaran dengan dompet Solana (EIP-712-style di Solana
//    diimplementasikan sebagai pesan terstruktur; SDK Orderly menyediakan encoder).
const payload = encodeUserSettlement({
  brokerId: BROKER_ID,
  chainId: CHAIN_ID,
  registrationNonce,
  timestamp: Date.now(),
});
const walletSig = nacl.sign.detached(Buffer.from(payload), owner.secretKey);

// 3. Daftarkan, termasuk kunci perdagangan Ed25519 Orderly.
const reg = await fetch(`${ORDERLY_BASE}/v1/register_account`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: payload,
    signature: bs58.encode(walletSig),
    userAddress: owner.publicKey.toBase58(),
    orderlyKey: orderlyPubB58,
  }),
}).then(r => r.json());

console.log("Account ID:", reg.data.account_id);
```

ID akun bersifat deterministik per pasangan `(broker_id, wallet_address)` — pendaftaran bersifat idempoten. Jika dompet telah terdaftar dengan broker Raydium, panggilan mengembalikan ID akun yang sama tanpa membuat yang baru.

## Setor USDC

Deposit memindahkan USDC dari ATA dompet ke vault penyelesaian Orderly. Ini adalah transaksi Solana on-chain:

```ts
// Bangun ix deposit menggunakan program Solana Orderly (ID program vault dipublikasikan
// dalam dokumentasi mereka; tarik secara dinamis daripada hard-coding).
const vaultProgramId = new PublicKey("<orderly_solana_vault_program_id>");

const depositIx = await buildOrderlyDepositIx({
  vaultProgramId,
  user: owner.publicKey,
  brokerId: BROKER_ID,
  amountUsdc: BigInt(100_000_000),    // 100 USDC (6 desimal)
});

const tx = new Transaction().add(depositIx);
const sig = await connection.sendTransaction(tx, [owner]);
await connection.confirmTransaction(sig, "confirmed");
console.log("Deposit tx:", sig);
```

Setelah ~30 detik, relayer Orderly mengindeks deposit dan saldo muncul di bawah margin bebas akun. Kueri `/v1/client/holding` untuk mengonfirmasi:

```ts
const holdingResp = await orderlyAuthGet("/v1/client/holding");
console.log("Balances:", holdingResp.data.holding);
```

(`orderlyAuthGet` didefinisikan di bawah — setiap panggilan terautentikasi melewatinya.)

## Pembantu penandatanganan permintaan

Setiap panggilan REST terautentikasi ke Orderly membawa tanda tangan Ed25519 atas `(timestamp + method + path + body)`:

```ts
async function orderlyAuthRequest(
  method: "GET" | "POST" | "PUT" | "DELETE",
  path: string,
  body?: unknown,
): Promise<any> {
  const ts   = Date.now().toString();
  const json = body ? JSON.stringify(body) : "";
  const msg  = `${ts}${method}${path}${json}`;
  const sig  = nacl.sign.detached(Buffer.from(msg), orderlyKey.secretKey);

  const resp = await fetch(ORDERLY_BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json",
      "orderly-account-id":  /* ID akun terdaftar */ "",
      "orderly-key":         orderlyPubB58,
      "orderly-signature":   bs58.encode(sig),
      "orderly-timestamp":   ts,
    },
    body: json || undefined,
  });
  return resp.json();
}

const orderlyAuthGet  = (p: string)            => orderlyAuthRequest("GET",  p);
const orderlyAuthPost = (p: string, b: object) => orderlyAuthRequest("POST", p, b);
const orderlyAuthDel  = (p: string)            => orderlyAuthRequest("DELETE", p);
```

Perlindungan replay: permintaan dengan `timestamp` lebih dari 5 detik dari jam server ditolak. Sinkronkan jam Anda (NTP) dan hindari penandatanganan permintaan sebelumnya.

## Tempatkan pesanan pasar

```ts
const marketResp = await orderlyAuthPost("/v1/order", {
  symbol:        "PERP_SOL_USDC",
  order_type:    "MARKET",
  side:          "BUY",
  order_quantity: 1.0,        // 1 SOL posisi
  reduce_only:    false,
});

if (marketResp.success) {
  console.log("Order ID:", marketResp.data.order_id);
} else {
  console.error("Reject:", marketResp.message);
}
```

Pesanan pasar dieksekusi segera. Respons mengembalikan `order_id` yang dihasilkan plus status. Pengisian datang melalui WebSocket (lihat di bawah); respons REST itu sendiri tidak memblokir sampai sepenuhnya terisi.

## Tempatkan pesanan limit dengan Post-Only

```ts
const limitResp = await orderlyAuthPost("/v1/order", {
  symbol:         "PERP_SOL_USDC",
  order_type:     "LIMIT",
  side:           "SELL",
  order_quantity: 0.5,
  order_price:    140.50,
  // kombinasi flag:
  // post_only: true membuat ini pesanan maker-only — dibatalkan jika akan melintasi.
  // reduce_only / time_in_force dapat diatur secara independen.
  post_only:      true,
});
console.log(limitResp);
```

Untuk `IOC` / `FOK`, atur `time_in_force: "IOC"` atau `"FOK"`. Lihat [`products/perps/order-types`](/id/products/perps/order-types) untuk semantik setiap flag.

## Batalkan pesanan

```ts
// Berdasarkan ID pesanan
await orderlyAuthDel(`/v1/order?order_id=${orderId}&symbol=PERP_SOL_USDC`);

// Batalkan SEMUA pesanan pada simbol
await orderlyAuthDel(`/v1/orders?symbol=PERP_SOL_USDC`);
```

Pembatalan diakui secara sinkron tetapi pembatalan aktual mungkin bersaing dengan pengisian. Selalu rekonsiliasi dengan polling `/v1/orders` atau menonton WebSocket — mengasumsikan pembatalan berhasil tanpa konfirmasi dapat menyebabkan posisi duplikat atau tidak diinginkan.

## Ambil posisi terbuka

```ts
const posResp = await orderlyAuthGet("/v1/positions");
for (const p of posResp.data.rows) {
  console.log(
    p.symbol,
    "size:",  p.position_qty,
    "entry:", p.average_open_price,
    "unrealized:", p.unsettled_pnl,
  );
}
```

`position_qty` negatif adalah short, positif adalah long. `position_qty == 0` berarti posisi ditutup tetapi baris mungkin masih muncul sampai pembersihan berikutnya.

## Ambil riwayat pengisian

```ts
const fills = await orderlyAuthGet(
  "/v1/trades?symbol=PERP_SOL_USDC&start_t=" + (Date.now() - 86_400_000)
);
for (const t of fills.data.rows) {
  console.log(t.executed_timestamp, t.side, t.executed_quantity, "@", t.executed_price);
}
```

Argumen waktu adalah timestamp Unix milidetik. Ukuran halaman default adalah 25 baris; gunakan parameter kueri `page` dan `size` untuk paginate.

## WebSocket: data pasar

```ts
import WebSocket from "ws";

const ws = new WebSocket(`wss://ws.orderly.org/ws/stream/${accountId}`);

ws.on("open", () => {
  // Data pasar publik: delta orderbook + perdagangan untuk satu simbol
  ws.send(JSON.stringify({ id: "ob1", topic: "orderbook@PERP_SOL_USDC" }));
  ws.send(JSON.stringify({ id: "tr1", topic: "trade@PERP_SOL_USDC" }));
});

ws.on("message", (raw) => {
  const msg = JSON.parse(raw.toString());
  if (msg.topic?.startsWith("orderbook@")) {
    // depth diff: { bids: [[price, qty], ...], asks: [[price, qty], ...] }
    applyOrderbookDelta(msg.data);
  } else if (msg.topic?.startsWith("trade@")) {
    console.log("trade:", msg.data);
  }
});
```

Untuk stream **privat** (pengisian Anda, pembaruan posisi, perubahan saldo), WebSocket harus terautentikasi. Kirim payload `subscribe` yang ditandatangani dengan cara yang sama seperti permintaan REST, dibatasi pada ID akun Anda. Dokumentasi Orderly memiliki bentuk payload yang tepat; itu berubah sesekali, jadi jangan hard-code skema tertentu di sini.

## Tarik USDC

```ts
// 1. Minta penarikan.
const wRes = await orderlyAuthPost("/v1/withdraw_request", {
  token:  "USDC",
  chain_id: CHAIN_ID,
  amount: 50.0,                          // unit manusia
  receiver: owner.publicKey.toBase58(),
});

console.log("Withdrawal request id:", wRes.data.withdraw_id);
```

Orderly menyampaikan penarikan on-chain ke alamat penerima. Ada biaya penarikan datar **1 USDC** (lihat [`products/perps/fees`](/id/products/perps/fees)). Transfer on-chain terjadi dalam 1–2 menit dalam kondisi normal; harapkan lebih lama selama kemacetan.

## Jebakan

- **Jangan gunakan kembali kunci perdagangan di seluruh lingkungan.** Satu kunci perdagangan Orderly terdaftar terhadap dompet Anda terkait dengan satu akun mainnet Solana. Jika Anda juga memerlukan devnet atau staging, buat kunci terpisah untuk masing-masing.
- **Sinkronisasi waktu.** Toleransi skew jam Orderly ketat (±5s). Pada layanan berjalan lama, drift NTP pada akhirnya akan memecahkan penandatanganan. Sinkronkan ulang secara berkala.
- **Reconnect WebSocket.** WS publik sesekali menjatuhkan koneksi selama upgrade Orderly. Implementasikan backoff eksponensial dan berlangganan ulang saat dibuka kembali.
- **Batas laju.** Panggilan REST dibatasi laju tier per akun. Pembatalan massal melalui `cancel_all` daripada loop `cancel`-by-id ketika Anda memiliki >5 pesanan untuk dibatalkan.
- **Arah posisi bersifat implisit.** Pesanan `BUY` pada `PERP_SOL_USDC` membuka atau memperpanjang long; `SELL` membuka atau memperpanjang short — tetapi jika Anda sudah long, `SELL` *mengurangi* (dan mungkin membalik) posisi karena Raydium Perps adalah mode satu arah. Selalu periksa posisi saat ini sebelum menempatkan pesanan jika arah penting.
- **Pendanaan dan likuidasi terpisah dari alur pesanan.** Pembayaran pendanaan dan likuidasi muncul sebagai stream acara terpisah; mereka bukan "pesanan". Berlangganan topik WS privat yang relevan jika Anda perlu mengamatinya.
