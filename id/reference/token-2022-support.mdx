Raydium **tidak** menerima mint Token-2022 sembarangan. CPMM dan CLMM keduanya menjalankan mode **daftar izin ketat**: hanya serangkaian kecil ekstensi yang lolos secara default; semuanya ditolak saat pembuatan pool. Segelintir mint terpercaya diterima melalui alamat yang dikodekan; CLMM juga mendukung registri per-mint yang dikelola admin dan deteksi token Superstate saat runtime. Halaman ini adalah referensi satu halaman untuk apa yang diterapkan dan di mana, dengan kutipan file-dan-baris ke sumber program.

## Dukungan tingkat program

| Program | Mint base/quote Token-2022? | Mode |
|---|---|---|
| **CPMM** | Ya — terbatas | Daftar izin ekstensi ketat + whitelist statis 4-mint. |
| **CLMM** | Ya — terbatas | Daftar izin ekstensi ketat + whitelist statis 6-mint + registri per-mint admin + deteksi Superstate. |
| **AMM v4** | Tidak | Program mendahului Token-2022; kedua mint harus SPL Token klasik. |
| **Stable AMM** | Tidak | Batasan yang sama dengan AMM v4. |
| **Farm v6** | Ya, sebagian | Mint reward dapat berupa Token-2022 (tunduk pada daftar izin yang sama ketika farm membungkus LP CPMM/CLMM); mint LP stake pengguna mewarisi dari pool yang dibungkus. |
| **LaunchLab** | Ya — base dikelola program, quote tanpa gating | Mint base dapat berupa Token-2022, tetapi hanya melalui instruksi `initialize_with_token_2022` khusus; program itu sendiri membuat mint dengan `MetadataPointer` (selalu) dan secara opsional `TransferFeeConfig` (rate ≤ 5%). Mint Token-2022 yang sudah ada dengan ekstensi sembarangan tidak dapat digunakan sebagai base. Mint **quote** dapat berupa mint Token-2022 apa pun yang diikat admin ke `GlobalConfig`, tanpa pemeriksaan ekstensi — lihat [di bawah](#launchlab-quote-mints). |
| **Burn & Earn** | Mencerminkan program pool | Mewarisi gating CPMM / CLMM. |

Pemeriksaan daftar izin berada di:

- **CPMM**: `is_supported_mint` di [`raydium-cp-swap/programs/cp-swap/src/utils/token.rs:178`](https://github.com/raydium-io/raydium-cp-swap), dipanggil dari `Initialize`.
- **CLMM**: `is_supported_mint` di [`raydium-clmm/programs/amm/src/util/token.rs:280`](https://github.com/raydium-io/raydium-clmm), dipanggil dari `CreatePool`.
- **LaunchLab**: `initialize_with_token_2022` di `raydium-launchpad/programs/launchpad/src/instructions/initialize_with_token_2022.rs` (sumber tidak tersedia untuk publik).

**Tidak ada** pemeriksaan mint saat swap pada CPMM atau CLMM — gating hanya terjadi saat pembuatan pool. Setelah pool ada, swap hanya mempercayai bahwa mint tidak berubah, yang benar untuk bagian immutable dari state mint Token-2022.

## Pembekuan NFT posisi CLMM untuk penerbit terbatas

Akun NFT posisi tetap tidak beku secara default. CLMM membekukan satu hanya ketika posisi menggunakan jalur open V2 **dan** setidaknya satu mint vault saat ini memiliki `freeze_authority` yang cocok dengan daftar penerbit terbatas yang dikodekan. Daftar awal berisi otoritas yang sama yang digunakan oleh jalur deteksi Superstate di bawah. Menetapkan pool PDA sebagai freeze authority mint NFT posisi bukan pembekuan itu sendiri. Ini adalah aturan penjagaan posisi, bukan daftar izin pembuatan pool lain:

- Pool sudah dapat ada dan tetap dapat ditukar.
- Mint NFT posisi menggunakan CLMM pool PDA sebagai freeze authority-nya sendiri; penerbit yang mendasar tidak mengendalikan NFT posisi.
- `OpenPositionV2` mencakup NFT posisi SPL klasik atas aset pool Token-2022. `OpenPositionWithToken22Nft` mencakup NFT posisi Token-2022.
- `OpenPosition` V1 tidak memeriksa mint vault dan tidak dapat melayani aset Token-2022 terbatas yang ditargetkan oleh daftar yang dikirim.
- Posisi yang ada tidak berubah.

Posisi yang beku tetap dapat dikelola oleh pemiliknya tetapi tidak dapat ditransfer. `ClosePosition` mencairkan dan membakar secara atomik ketika klien melewatkan pool sebagai akun sisa pertama. Lihat [`products/clmm/ticks-and-positions`](/id/products/clmm/ticks-and-positions#restricted-issuer-positions).

## Mint quote LaunchLab

Dua mint LaunchLab dibatasi sangat berbeda, dan asimetrinya mudah terlewatkan.

- **Mint base** — LaunchLab membuatnya. Mint base Token-2022 hanya dapat dicapai melalui `initialize_with_token_2022`, dan program hanya akan melampirkan `MetadataPointer` dan (opsional) `TransferFeeConfig`. Apa pun yang lain mengembalikan `NoSupportExtension`. Mint Token-2022 yang sudah ada tidak dapat disuplai sebagai base sama sekali.
- **Mint quote** — LaunchLab tidak membuatnya dan tidak menyaringnya. `CreateConfig` menerima akun mint sebagaimana diberikan, jadi **tidak ada ekuivalen `is_supported_mint` di sisi quote**. Satu-satunya gating adalah mint mana yang dipilih admin untuk diikat ke `GlobalConfig`.

Itu membuat pengikatan mint quote Token-2022 menjadi tindakan kepercayaan tinggi, dengan alasan yang sama dengan daftar whitelist statis CPMM dan CLMM di bawah: mint quote `TransferHook` akan menjalankan hook-nya pada setiap pembelian, penjualan, dan klaim biaya di setiap pool yang dikutip di dalamnya, dan mint quote `PermanentDelegate` akan membiarkan delegasi menyapu vault quote pool tersebut. Tidak satupun yang diblokir oleh program.

Yang LaunchLab tangani dengan benar setelah mint quote diikat:

- Vault quote, kedua vault biaya, dan akun token penerima share-fee dibuat di program mint quote sendiri.
- `TransferFeeConfig` di sisi quote diperhitungkan dalam keempat instruksi perdagangan, dan batas slippage diperiksa terhadap jumlah bersih pembayar daripada pergerakan vault kotor. Lihat [`products/launchlab/instructions`](/id/products/launchlab/instructions#quote-side-transfer-fees).
- `PoolState.token_program_flag` mencatat program kedua mint — bit0 untuk mint base, bit1 untuk mint quote. Dekode per bit; byte bukan boolean. Lihat [`products/launchlab/accounts`](/id/products/launchlab/accounts#poolstate).

Instruksi `Initialize` yang sudah usang masih mengambil program quote legacy-only, jadi config dengan mint quote Token-2022 hanya dapat dicapai melalui `InitializeV2` dan `InitializeWithToken2022`.

## Daftar izin ekstensi CPMM dan CLMM

Setelah shortcut whitelist statis (dibahas di bawah), program mengulangi ekstensi mint dan menolak mint jika membawa **ekstensi apa pun** selain lima ini:

| Ekstensi | Alasan diizinkan |
|---|---|
| `TransferFeeConfig` | Matematika pool mengurangi biaya inbound; program Token-2022 menangani biaya outbound. Lihat [`algorithms/token-2022-transfer-fees`](/id/algorithms/token-2022-transfer-fees). |
| `MetadataPointer` | Dekoratif — menunjuk ke metadata on-chain. |
| `TokenMetadata` | Dekoratif — metadata inline. |
| `InterestBearingConfig` | Pool melihat jumlah pokok; pengganda UI hanya dekorator dan saldo yang mendasar dipertahankan. |
| `ScaledUiAmount` | Bentuk yang sama dengan interest-bearing — faktor skala hanya berlaku untuk tampilan UI. |

Apa pun yang tidak dalam daftar ini — `TransferHook`, `NonTransferable`, `ConfidentialTransferMint`, `PermanentDelegate`, `MintCloseAuthority`, `DefaultAccountState`, `GroupPointer`, `GroupMemberPointer`, `MemberPointer`, `Pausable`, dll. — menyebabkan `is_supported_mint` mengembalikan `false` dan pembuatan pool kembali.

Baris yang relevan (CPMM, bentuk identik di CLMM):

```rust
for e in extensions {
    if e != ExtensionType::TransferFeeConfig
        && e != ExtensionType::MetadataPointer
        && e != ExtensionType::TokenMetadata
        && e != ExtensionType::InterestBearingConfig
        && e != ExtensionType::ScaledUiAmount
    {
        return Ok(false);
    }
}
Ok(true)
```

— [`cp-swap/src/utils/token.rs:190–200`](https://github.com/raydium-io/raydium-cp-swap)

## Jalur bypass

Mint Token-2022 yang tidak sesuai dengan daftar izin masih dapat diterima melalui salah satu dari tiga bypass eksplisit. Mereka dicoba secara berurutan, sebelum iterasi ekstensi berjalan.

### 1. Whitelist mint statis

Array konstanta `MINT_WHITELIST` dari string base58 dikodekan dalam setiap program. Jika alamat mint cocok, fungsi mengembalikan `true` segera dan tidak ada pemeriksaan ekstensi yang dilakukan.

| Program | Mint yang di-whitelist |
|---|---|
| CPMM | `HVbpJAQGNpkgBaYBZQBR1t7yFdvaYVp2vCQQfKKEN4tM`, `Crn4x1Y2HUKko7ox2EZMT6N2t2ZyH7eKtwkBGVnhEq1g`, `FrBfWJ4qE5sCzKm3k3JaAtqZcXUh4LvJygDeketsrsH4`, `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| CLMM | Keempat yang sama, ditambah `DAUcJBg4jSpVoEzASxYzdqHMUN8vuTpQyG2TvDcCHfZg`, `AUSD1jCcCyPLybk1YnvPWsHQSrZ46dxwoMniN4N2UEB9` |

Alamat ini dipanggang ke dalam program; memperbarui daftar memerlukan upgrade program melalui multisig upgrade 3/4.

### 2. Registri per-mint — CLMM saja

CLMM juga berkonsultasi dengan PDA `SupportMintAssociated` di seed `[b"support_mint", mint]`. Jika PDA itu ada untuk mint, itu diterima terlepas dari set ekstensinya.

PDA dibuat oleh `CreateSupportMintAssociated` ([`admin/create_support_mint_associated.rs`](https://github.com/raydium-io/raydium-clmm)). Instruksi dibatasi untuk dua penandatangan:

- `crate::admin::ID` — otoritas admin Raydium standar.
- `crate::create_support_mint_associated_owner::ID` — otoritas khusus untuk tujuan ini: `RayVyjyJQz9vAi126A4sGexKnSU1XeZaHTRcM1mZMPY` (mainnet), `rayf3nEbb3bnfN6RDGFpqPbjc5uUa3tRUzu6UVYrRx5` (devnet).

Efek: tim CLMM dapat memilih mint Token-2022 tertentu untuk pembuatan pool tanpa upgrade program. CPMM tidak memiliki ekuivalen — daftar izinnya ketat dikodekan sumber.

### 3. Deteksi Superstate — CLMM saja

CLMM memiliki jalur ketiga khusus untuk aset tokenisasi Superstate, yang menggunakan ekstensi `ScaledUiConfig` yang versi `spl-token-2022` yang ditautkan ke program CLMM tidak dapat membuka. Daripada upgrade dependensi, CLMM mendeteksi token Superstate berdasarkan bentuk otoritasnya:

```rust
superstate_allowlist::ID == freeze_authority
    && *mint_account_info.owner == spl_token_2022::ID
    && default_account_state_freeze
    && maybe_permanent_delegate
```

— [`raydium-clmm/programs/amm/src/util/token.rs:485`](https://github.com/raydium-io/raydium-clmm)

Mint melewati cabang ini jika **keempat** berlaku:

- Program pemiliknya adalah program Token-2022.
- Freeze authority-nya sama dengan `superstate_allowlist::ID`. Lihat [`reference/program-addresses`](/id/reference/program-addresses#clmm-restricted-issuer-freeze-authorities) untuk nilai mainnet-beta dan devnet.
- Ekstensi `DefaultAccountState`-nya diatur ke `Frozen`.
- Permanent delegate-nya juga `superstate_allowlist::ID`.

Ini adalah heuristik, bukan registri — mint apa pun di masa depan yang Superstate keluarkan dengan bentuk otoritas yang sama akan diterima secara otomatis.

## Apa yang bypass tidak waivkan

Bypass melewati daftar izin ekstensi, tetapi program masih menerapkan:

- Mint dimiliki oleh `Token` atau `Token-2022`. Program token kustom ditolak upstream.
- Vault pool dibuat dengan ekstensi ATA yang tepat untuk pool Token-2022 (`ImmutableOwner`, dll.).
- Semua transfer melalui `transfer_checked` — mint yang membawa biaya mendarat jumlah yang tepat di vault.

Mint yang di-whitelist atau terdaftar PDA yang, misalnya, menambahkan `TransferHook` nanti tidak mendapatkan pemeriksaan swap-time; hook hanya akan berjalan pada setiap transfer dan dapat membuat swap tidak berfungsi. Whitelisting oleh karena itu adalah tindakan kepercayaan tinggi.

## Semantik "Blocked"

Ketika `is_supported_mint` mengembalikan `false`, pembuatan pool kembali dengan `ErrorCode::NotSupportMint` (CPMM) / `ErrorCode::NotSupportMint` (CLMM). Lihat [`reference/error-codes`](/id/reference/error-codes) untuk kode numerik.

Pool yang ada tidak dapat secara retroaktif gagal pemeriksaan ini — gating hanya berjalan saat pembuatan. Ekstensi mint tidak dapat diubah untuk kategori yang Raydium tolak (transfer hook, non-transferable, confidential transfer tidak dapat ditambahkan pasca-pembuatan), jadi pemeriksaan statis sudah cukup.

## Mengapa setiap ekstensi yang dikecualikan dikecualikan

- **TransferHook** — memanggil program kustom pada setiap transfer, dengan konsumsi CU sembarangan, kondisi kegagalan sembarangan, dan kemampuan untuk memasuki kembali program yang memanggil. Tidak ada sandbox yang aman. Beberapa DEX mempertahankan daftar izin hook; Raydium tidak.
- **NonTransferable** — `Transfer` selalu gagal. Pool tidak dapat mengambil alih.
- **ConfidentialTransfer** — jumlah transfer dienkripsi; kurva tidak dapat menentukan harga swap.
- **PermanentDelegate** — pemegang delegasi dapat menyapu akun token apa pun, termasuk vault pool. Diizinkan hanya melalui whitelist statis untuk penerbit terpercaya (misalnya, stablecoin yang diatur).
- **MintCloseAuthority** — mint dapat ditutup; pool yang ada menjadi tidak dapat digunakan. Dilarang secara default.
- **DefaultAccountState (Frozen)** — ATA pool akan mendarat di status `Frozen` dan memerlukan pencairan per akun. Diizinkan hanya melalui deteksi Superstate, yang mengasumsikan penerbit mencairkan akun institusional saat pendaftaran.
- **Group/Member pointers** — tidak secara aktif berbahaya, tetapi tidak ditinjau. Dilarang secara default untuk menjaga permukaan tetap sempit.

## Akuntansi biaya transfer

Untuk mint yang membawa `TransferFeeConfig`, setiap swap, deposit, dan withdraw memindahkan lebih sedikit dari jumlah nominal. SDK menampilkan kedua bagian dari perhitungan:

```ts
const { amountIn, amountOut, feeAmount, token2022FeeIn, token2022FeeOut } =
  await raydium.cpmm.computeSwapAmount({ ... });
```

UI yang benar menunjukkan:

- `amountIn + token2022FeeIn` sebagai "Anda kirim"
- `amountOut - token2022FeeOut` sebagai "Anda terima"
- `feeAmount` sebagai biaya pool (LP + protokol), yang terpisah dari biaya transfer Token-2022

UI naif yang hanya menunjukkan `amountIn → amountOut` meremehkan biaya.

### Batas `maximumFee`

Biaya transfer Token-2022 dibatasi per transfer. Untuk mint 1% dengan batas 10.000 token, transfer 100.000.000 token hanya membayar 10.000 dalam biaya. `computeSwapAmount` SDK menerapkan batas; pemanggil program langsung harus mereplikanya.

### Transisi epoch

Otoritas mint dapat menjadwalkan perubahan tingkat biaya yang diaktifkan pada epoch berikutnya. Selama jendela transisi, dua config (`older`, `newer`) hidup di mint sekaligus dan `TransferChecked` memilih berdasarkan epoch saat ini. CPMM `SwapV2` dan CLMM `SwapV2` keduanya melewatkan akun mint lengkap di `accounts`, jadi program membaca config yang tepat tanpa pencarian tambahan.

Jika Anda mengutip lebih dari satu epoch sebelumnya melalui Trade API atau SDK, biaya yang dieksekusi dapat berbeda dari biaya yang dikutip — dibatasi oleh `maximum_fee_basis_points` config yang lebih lama.

## Interest-bearing dan ScaledUiAmount

Pool memegang jumlah pokok; "jumlah UI" adalah pokok dikalikan dengan faktor skala yang bergantung waktu atau yang ditetapkan admin. Matematika swap beroperasi pada pokok:

```
principal_in = ui_amount_in / ui_multiplier(now)
```

SDK mengonversi secara otomatis. Pembaca RPC langsung harus memperlakukan `pool.token0Vault.amount` sebagai pokok.

## Definisi "pool Token-2022"

Pool adalah pool Token-2022 jika **salah satu** mint memiliki `programId == TokenzQdB...`. API menampilkan ini:

```
GET /pools/info/ids?ids=<POOL_ID>
```

```json
{
  "data": [{
    "mintA": { "programId": "TokenzQdB...", "hasTransferFee": true, ... },
    "mintB": { "programId": "Tokenkeg...", ... }
  }]
}
```

Gunakan `programId` untuk dispatch, dan `hasTransferFee` untuk menampilkan peringatan UI.

## Pembantu SDK

```ts
import { Raydium, TOKEN_2022_PROGRAM_ID } from "@raydium-io/raydium-sdk-v2";
import { ExtensionType, getExtensionTypes, unpackMint } from "@solana/spl-token";

const raydium = await Raydium.load({ owner, connection });

const acct = await connection.getAccountInfo(mintPubkey);
if (!acct) throw new Error("mint not found");
const mint = unpackMint(mintPubkey, acct, acct.owner);

if (acct.owner.equals(TOKEN_2022_PROGRAM_ID)) {
  const extensions = getExtensionTypes(mint.tlvData);
  const accepted = new Set([
    ExtensionType.TransferFeeConfig,
    ExtensionType.MetadataPointer,
    ExtensionType.TokenMetadata,
    ExtensionType.InterestBearingConfig,
    ExtensionType.ScaledUiAmount,
  ]);
  const rejecting = extensions.filter(e => !accepted.has(e));
  if (rejecting.length) {
    console.warn("Pool creation will revert unless this mint is whitelisted:", rejecting);
  }
}
```

## Kesalahan integrasi umum

- **Pre-flighting hanya ID program.** Mint dapat berupa Token-2022 *dan* tidak didukung. Jalan daftar ekstensi terhadap daftar izin (dan whitelist statis) sebelum memungkinkan pembuatan pool.
- **Mempercayai kutipan SDK ketika mint tidak diterima sama sekali.** API kutipan tidak menolak untuk mengutip — pembuatan pool adalah yang kembali. Konfirmasi semantik `is_supported_mint` off-chain sebelum mengekspos pembuatan pool di UI Anda.
- **Mengutip tanpa potongan biaya transfer.** Mint biaya transfer 1% di kedua sisi pool CPMM 0,25% memiliki biaya efektif sekitar 2,25%, bukan 0,25%. Gunakan kutipan SDK atau kutipan Trade API — jangan pernah hitung biaya secara manual dari tingkat biaya pool saja.
- **Memanggil instruksi `Swap` legacy pada pool Token-2022.** `Swap` mendahului Token-2022. Gunakan `SwapV2` kapan pun salah satu mint adalah Token-2022.
- **Auto-listing mint Token-2022 baru.** Dompet dan agregator harus memeriksa `TransferHook` dan `NonTransferable` sebelum menampilkan mint kepada pengguna; keduanya tidak ramah Raydium.

## Pekerjaan masa depan

Item roadmap ekosistem Solana dan protokol yang akan mengubah matriks ini:

- Program transfer-hook yang di-whitelist di level Solana (konvensi ekosistem berkembang).
- AMM yang kompatibel dengan confidential-transfer (tahap penelitian).
- Registri per-mint CPMM yang lebih luas (paritas dengan CLMM).
- Upgrade dependensi sehingga dekoding `ScaledUiConfig` CLMM berfungsi tanpa heuristik Superstate.

Halaman ini akan diperbarui ketika ada yang mendarat.
