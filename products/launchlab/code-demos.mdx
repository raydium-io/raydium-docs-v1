## Setup

Demos here mirror files in [`raydium-sdk-V2-demo/src/launchpad`](https://github.com/raydium-io/raydium-sdk-V2-demo/tree/master/src/launchpad). Bootstrap follows the demo repo's [`config.ts.template`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/config.ts.template):

```ts
import { Connection, Keypair, clusterApiUrl, PublicKey } from "@solana/web3.js";
import { Raydium, TxVersion } from "@raydium-io/raydium-sdk-v2";
import BN from "bn.js";
import fs from "node:fs";

const connection = new Connection(process.env.RPC_URL ?? clusterApiUrl("mainnet-beta"));
const owner = Keypair.fromSecretKey(
  new Uint8Array(JSON.parse(fs.readFileSync(process.env.KEYPAIR!, "utf8"))),
);
const raydium = await Raydium.load({
  owner,
  connection,
  cluster: "mainnet",
  disableFeatureCheck: true,
  blockhashCommitment: "finalized",
});
export const txVersion = TxVersion.V0;
```

## Create a launch

Source: [`src/launchpad/createMint.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/createMint.ts) (and [`createBonkMintApi.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/createBonkMintApi.ts) for the API-driven Bonk variant)

```ts
import { Keypair, PublicKey } from "@solana/web3.js";
import { NATIVE_MINT } from "@solana/spl-token";
import {
  LAUNCHPAD_PROGRAM,
  LaunchpadConfig,
  getPdaLaunchpadConfigId,
} from "@raydium-io/raydium-sdk-v2";

const programId = LAUNCHPAD_PROGRAM;

// The base mint is a fresh keypair you pass in as an extra signer.
const pair  = Keypair.generate();
const mintA = pair.publicKey;

// Resolve the GlobalConfig you are launching under (quote mint, curve type, index).
const configId   = getPdaLaunchpadConfigId(programId, NATIVE_MINT, 0, 0).publicKey;
const configData = await raydium.connection.getAccountInfo(configId);
const configInfo = LaunchpadConfig.decode(configData!.data);

const { execute, extInfo } = await raydium.launchpad.createLaunchpad({
  programId,
  mintA,
  decimals: 6,
  name:   "Example Token",
  symbol: "EXMPL",
  uri:    "https://example.com/metadata.json",

  configId,
  configInfo,                       // optional; the SDK refetches from configId if omitted
  migrateType: "cpmm",              // new launches must graduate to CPMM
  extraSigners: [pair],

  createOnly: true,                 // false = create and land the creator's first buy together
  buyAmount:  new BN(1_000),        // only meaningful when createOnly is false
  slippage:   new BN(100),          // 1%

  // Curve shape — omit to inherit LaunchpadPoolInitParam defaults:
  // supply:            new BN("1000000000000000"),
  // totalSellA:        new BN("793100000000000"),
  // totalFundRaisingB: new BN("85000000000"),   // 85 SOL when mintB is WSOL

  // Vesting — omit for none:
  // totalLockedAmount: new BN(0),
  // cliffPeriod:       new BN(0),               // seconds
  // unlockPeriod:      new BN(0),               // seconds

  txVersion: TxVersion.V0,
});

const sentInfo = await execute({ sequentially: true });
console.log("Pool:", extInfo);
```

Notes:

- Curve parameters are `supply` / `totalSellA` / `totalFundRaisingB`, not a scale factor. Which of them the program reads depends on `GlobalConfig.curve_type` — the `Fixed` and `Linear` curves derive `totalSellA` themselves. See [`bonding-curve`](/products/launchlab/bonding-curve).
- There is **no fee argument**. Trade fees come from the `GlobalConfig` you bind to and from `PlatformConfig`; the post-graduation LP split comes from the platform's `platform_scale` / `creator_scale` / `burn_scale`. See [`platform-config`](/products/launchlab/platform-config).
- `platformId` defaults to the Raydium platform. Pass your own to route platform fees to your wallets — see [`createPlatform.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/createPlatform.ts).
- Creation can span more than one transaction, which is why the demo executes with `{ sequentially: true }`.

## Fetch launch state

Source: [`src/launchpad/poolInfo.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/poolInfo.ts)

The pool address is a PDA of the two mints, so you can derive it rather than store it:

```ts
import {
  Curve,
  LaunchpadConfig,
  LaunchpadPool,
  getPdaLaunchpadPoolId,
} from "@raydium-io/raydium-sdk-v2";

const poolId = getPdaLaunchpadPoolId(programId, mintA, NATIVE_MINT).publicKey;

// Either decode the accounts yourself...
const acc  = await raydium.connection.getAccountInfo(poolId);
const info = LaunchpadPool.decode(acc!.data);

const cfg        = await raydium.connection.getAccountInfo(info.configId);
const configInfo = LaunchpadConfig.decode(cfg!.data);

// ...or let the SDK do both in one call:
const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });

console.log("status:", ["Funding", "Migrate", "Migrated"][poolInfo.status]);
console.log("raised:", poolInfo.realB.toString(), "/", poolInfo.totalFundRaisingB.toString());
console.log("price:", Curve.getPrice({
  poolInfo,
  curveType: poolInfo.configInfo.curveType,
  decimalA:  poolInfo.mintDecimalsA,
  decimalB:  poolInfo.mintDecimalsB,
}).toString());
```

`getRpcPoolInfo` returns the decoded launch state plus its `configInfo`; `getRpcPoolsInfo` does the same for a batch. For a graduation-progress percentage, use the price-ratio helper in [`getFinishRate.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/getFinishRate.ts) rather than a raw reserve ratio — the ratio is not linear in progress for every curve type.

## Buy — exact quote in

Source: [`src/launchpad/buy.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/buy.ts)

Quote off-chain with `Curve`, then send with `buyToken`:

```ts
import { Curve, PlatformConfig } from "@raydium-io/raydium-sdk-v2";

const inAmount = new BN(1).mul(new BN(10).pow(new BN(9)));   // 1 SOL
const slippage = new BN(100);                                // 1%

const poolInfo     = await raydium.launchpad.getRpcPoolInfo({ poolId });
const platformData = await raydium.connection.getAccountInfo(poolInfo.platformId);
const platformInfo = PlatformConfig.decode(platformData!.data);

const mintInfo = await raydium.token.getTokenInfo(mintA);

const res = Curve.buyExactIn({
  poolInfo,
  amountB:         inAmount,
  protocolFeeRate: poolInfo.configInfo.tradeFeeRate,
  platformFeeRate: platformInfo.feeRate,
  creatorFeeRate:  platformInfo.creatorFeeRate,
  curveType:       poolInfo.configInfo.curveType,
  shareFeeRate:    new BN(0),
  transferFeeConfigA: undefined,   // set for a Token-2022 base mint carrying TransferFeeConfig
  slot: await raydium.connection.getSlot(),
});
console.log("expected out:", res.amountA.amount.sub(res.amountA.fee ?? new BN(0)).toString());

const { execute, extInfo } = await raydium.launchpad.buyToken({
  programId,
  mintA,
  mintAProgram: new PublicKey(mintInfo.programId),
  mintB:        poolInfo.mintB,
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,
  buyAmount: inAmount,
  slippage,
  txVersion: TxVersion.V0,
  // shareFeeReceiver, shareFeeRate,   // optional referral fee; see below
});

const { txId } = await execute({ sendAndConfirm: true });
console.log("Buy tx:", txId, "expected receive:", extInfo.decimalOutAmount.toString());
```

`Curve.buyExactIn` is the client-side mirror of the on-chain curve solver for the pool's `curveType`. Pass the same fee rates the program will use, or the preview and the fill will disagree.

**Referral fee.** `shareFeeRate` is a real instruction argument, not an SDK convenience: it is paid out of the trade to `shareFeeReceiver`. It must not exceed `poolInfo.configInfo.maxShareFeeRate`, and passing a non-zero rate without a receiver has nowhere to send the fee. Include it in the `Curve` preview too, or your quote will be optimistic by exactly that rate.

## Buy — exact base out

```ts
const { execute } = await raydium.launchpad.buyTokenExactOut({
  programId,
  mintA,
  mintB: poolInfo.mintB,
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,
  outAmount:    new BN(1_000_000).mul(new BN(10).pow(new BN(6))),  // 1M base
  maxBuyAmount: new BN(2).mul(new BN(10).pow(new BN(9))),          // cap at 2 SOL
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Useful for "buy exactly X tokens" UIs. Reverts with `ExceededSlippage` if the curve has moved enough that the quote requirement now exceeds `maxBuyAmount`.

## Sell

Source: [`src/launchpad/sell.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/sell.ts)

```ts
const sellAmount = new BN(500_000).mul(new BN(10).pow(new BN(6)));  // 0.5M base

const res = Curve.sellExactIn({
  poolInfo,
  amountA:         sellAmount,
  protocolFeeRate: poolInfo.configInfo.tradeFeeRate,
  platformFeeRate: platformInfo.feeRate,
  creatorFeeRate:  platformInfo.creatorFeeRate,
  curveType:       poolInfo.configInfo.curveType,
  shareFeeRate:    new BN(0),
  transferFeeConfigA: undefined,
  slot: await raydium.connection.getSlot(),
});
console.log("expected out:", res.amountB.toString());

const { execute } = await raydium.launchpad.sellToken({
  programId,
  mintA,
  mintAProgram: new PublicKey(mintInfo.programId),
  mintB:        poolInfo.mintB,
  poolInfo,
  configInfo:      poolInfo.configInfo,
  platformFeeRate: platformInfo.feeRate,
  sellAmount,
  slippage,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

The sell path is the mirror of the buy path: the base and quote reserves both decrease, and the fee is taken out of the quote leg so the seller keeps less than the raw integrated proceeds. There is also `sellTokenExactOut` for "receive exactly X SOL" flows.

## Graduation is not something you call

<Warning>
  There is no `Graduate` instruction and the SDK exposes no graduation method. Anything you may have seen describing an `autoGraduate` flag, a graduation bounty, or a permissionless `graduate()` race does not exist in this program.
</Warning>

What actually happens is two separate events:

1. **The curve closes inside the buy.** When a `BuyExactIn` / `BuyExactOut` pushes the quote reserve to the fundraising target, that same instruction flips the launch's `status` from `Funding` (`0`) to `Migrate` (`1`) and emits a `TradeEvent` carrying the new status. From that point every trade instruction reverts. No extra transaction is involved, and no bot can front-run this — it is part of the buy itself.
2. **The CPMM pool is created by a permissioned crank.** `MigrateToCpswap` must be signed by `GlobalConfig.migrate_to_cpswap_wallet` (legacy AMM v4 launches: `migrate_to_amm_wallet`). Those wallets are operated by Raydium. Your client cannot call it, and there is no bounty to claim. It flips `status` to `Migrated` (`2`).

So an integrator's job is to **observe**, not to trigger:

```ts
async function watch(poolId: PublicKey) {
  for (;;) {
    const poolInfo = await raydium.launchpad.getRpcPoolInfo({ poolId });

    console.log(
      `status=${["Funding", "Migrate", "Migrated"][poolInfo.status]}`,
      `raised=${poolInfo.realB.toString()}/${poolInfo.totalFundRaisingB.toString()}`,
    );

    if (poolInfo.status === 2) {
      // Post-graduation CPMM pool: derive it from the mint pair.
      console.log("Migrated — the CPMM pool for this mint pair is now live.");
      break;
    }
    await new Promise((r) => setTimeout(r, 10_000));
  }
}
```

Budget for a real gap between status `1` and status `2`: the pool is untradeable on both venues in between. A UI that treats `Migrate` as "graduated, go trade the CPMM pool" will send users to a pool that does not exist yet.

## Collect creator fees

Source: [`src/launchpad/claimCreatorFee.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/claimCreatorFee.ts) (single quote mint) and [`collectAllCreatorFees.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/launchpad/collectAllCreatorFees.ts) (batched)

```ts
const { execute } = await raydium.launchpad.claimCreatorFee({
  programId,
  mintB: NATIVE_MINT,           // the quote mint whose creator vault you are draining
  // mintBProgram: TOKEN_PROGRAM_ID or TOKEN_2022_PROGRAM_ID,
  txVersion: TxVersion.V0,
});

await execute({ sendAndConfirm: true });
```

Creator fees accrue into a per-creator, per-quote-mint vault PDA rather than per launch, so the call takes a quote mint, not a pool. It drains everything the signer has accrued on that mint across all of their launches. Callable pre- or post-graduation; use `claimMultipleCreatorFee` to sweep several quote mints at once.

## Watch configs and pools over gRPC

Source: [`src/grpc/launchpadPoolInfo.ts`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/grpc/launchpadPoolInfo.ts)

Subscribes to the LaunchLab program over Yellowstone gRPC and logs every `GlobalConfig` and `PoolState` update with each mint's token program. Two `datasize` filters on one `accounts` subscription separate the two account types, so a single stream covers both.

The demo is the shortest correct reference for classifying a launch's mints, which the [Token-2022 quote-mint release](/reference/changelog/2026-08-24-launchlab-token2022-quote-mint) makes necessary:

- **Pools** are classified straight from `PoolState.token_program_flag`, decoding bit0 for the base mint and bit1 for the quote mint with no mint fetch at all. Testing the whole byte against `0` — which was sufficient while quote mints were legacy-only — misreads a legacy base mint as Token-2022 whenever the quote mint is Token-2022.
- **Configs** cannot be classified that way: a `GlobalConfig` stores its quote mint's address and no program flag, so the demo reads the mint account's owner once and caches it per mint.

It also cross-checks the two against each other, which is a useful assertion to keep in your own indexer. Note that `create` versus `update` is inferred from the demo's own caches, seeded at startup from `getProgramAccounts`; with that seeding disabled, read "create" as "first seen on this stream".

gRPC access is not part of the public RPC surface — see the demo repo's [`src/grpc/README.md`](https://github.com/raydium-io/raydium-sdk-V2-demo/blob/master/src/grpc/README.md).

## Rust CPI

Calling LaunchLab from your own program means building the instructions by hand — there is no CPI crate to depend on the way there is for CPMM and CLMM. Take the discriminators and account order from [`raydium_launchpad.json`](https://github.com/raydium-io/raydium-idl/blob/master/raydium_launchpad/raydium_launchpad.json), keep the `event_authority` / `program` pair Anchor appends, and append the remaining accounts listed in [`instructions`](/products/launchlab/instructions#the-four-trade-instructions). See [`sdk-api/rust-cpi`](/sdk-api/rust-cpi) for the general pattern.

## Pitfalls

- **Treating fees as launch parameters.** They are not. There is no fee argument on any create call; the rates live on `GlobalConfig` and `PlatformConfig`. To change them you bind to a different config or run your own platform.
- **Using the wrong quote mint.** A `GlobalConfig` fixes exactly one `quote_mint`, and the pool PDA is derived from the mint pair. To launch against a different quote asset you need the config for that asset — derive it with `getPdaLaunchpadConfigId(programId, quoteMint, curveType, index)` and confirm the account exists before building the transaction.
- **Metadata size.** Long `uri` strings push the Metaplex CPI over the budget. Keep `uri` under ~200 chars — most CDN-hosted JSON metadata fits easily.
- **Assuming you can trigger or race graduation.** You cannot, in either direction: the curve closes inside the threshold-crossing buy, and only Raydium's migration wallet can create the CPMM pool. Treat `status` as something to poll, and handle the `Migrate` window where the token trades nowhere.
- **Forgetting the `event_cpi` accounts.** Every LaunchLab instruction ends with `event_authority` and `program`. Hand-built instructions that stop at `quote_token_program` fail account resolution, which surfaces as an opaque error rather than a named one.
